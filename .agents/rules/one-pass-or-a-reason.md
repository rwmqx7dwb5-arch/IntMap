# IntMap — 一発で決める。繰り返しは失敗が実在したときだけ (One pass, or a reason)

> **恒久指示（#R768）。** 利用者:「**一発で全部決めるようにするのを恒久方針に。失敗したら
> フォールバックするのはいいけど、数回やるのが当たり前は怖すぎ。**」／追補:「**AI モデルが決定権を
> もっていて、なにをやるか決めるというのはそれでいい。コード側で変に縛ったりするのは嫌。
> ハーネスとして、性能向上につながるならいいけど、縛るのはやめてほしい。**」
> `AGENTS.md` §3 の 11 がここを指す。正本はここ。実測は `DEV-NOTES.md` #R768。

## 1. 縛るのはハーネスであって、Atlas ではない

**禁じるのは、Atlas に同じ手をもう一度やらせてしまう機構のほう。** 何を何回呼ぶかは Atlas が決める。

- 禁じない: 1 ターンに複数回モデルを呼ぶこと（1 手進めるごとに次を訊くのは仕様）
- 禁じない: Atlas が必要と判断して同じ道具をもう一度呼ぶこと
- **禁じる: 一度やったことを「まだやっていない」と機構が伝えること**
- **禁じる: 観測できなかったことを「失敗した」と機構が伝えること**

⚠ **手本は既にある。** `js/atlas-turn-results.js` の `callKey` と `js/atlas-agent.js` の `doneCalls` は
同じ呼び出しを**拒否せず、同じ答えを返して「もう済んでいる」と述べる**（コメント自身が
「IT IS NOT A CAP, AND NOT A REFUSAL (CONSTITUTION.md §5)」と書いている）。足すものは全部この形。

## 2. 繰り返しは症状である。原因は必ずこの 3 つ

1. **観測器が嘘をついた** — 成功を失敗と報告した。#R736 は成功した描画を毎回 `not_rendered` と呼び、
   21 手・10分29秒が再試行に消えた。#R742 は **207 操作中 52 件（25%）**。#R768 は合成されていない
   ページで `no_change` を 7 回返した。
2. **結果が持ち帰られなかった** — 実行はされたが、次の手を決めるモデルに届いていない。
3. **操作が冪等でない** — 二度目が一度目と違う結果になる。

⇒ **直すのはこの 3 つであって、上限ではない。**

## 3. ⚠⚠⚠ 上限を下げて塞いではならない

手数の上限は**暴走を止める最後の柵**であって繰り返しへの対処ではない（`CONSTITUTION.md` §5）。
下げると**繰り返しは残ったまま、正しい仕事が先に死ぬ**——#R768 実測で、上限に殺されたのは
繰り返しではなく**成果物のほう**だった（座標を取った直後に切れ、距離を 1 つも出せずに終了）。

## 4. 着手前の 3 問（1 つでも「いいえ」なら、まだ直っていない）

- 成功したとき、**成功したと報告される**か（観測器は塗った当人に訊いているか）。
- 実行した結果は、**次の手を決めるモデルに届く**か。
- 同じ引数でもう一度呼ばれたとき、**「もう済んでいる」と述べられる**か
  （黙って捨てるのでも、黙って再実行するのでもなく）。

## 5. 繰り返してよい唯一の場合

**実在した失敗のあとの再試行。** ただし次を満たすこと。

- 失敗が**観測された事実**であること（例外・上流の 5xx・上流が明示した拒否）。
  ⚠ **「確認できなかった」は失敗ではなく観測できなかったである。** この 2 つに同じ答えを返さない。
- 再試行が**前回と違うこと**をすること。
- 回数が記録に残ること。

## 6. 測れない方針は守られない

門は **`npm run check:atlasrepeat`**（`scripts/atlas-repeat.mjs`）。
⚠ **測るのは「操作の回数」ではなく「同じ操作の二度目」と、その原因。**
手数そのものを門にすると、それは §3 が禁じた上限をテストの形で作ることになる。
