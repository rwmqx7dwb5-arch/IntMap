News events

The queue is what the machine is least sure about: two or more articles with the lowest cluster confidence, and anything no operator has reviewed. Tick two events and press Merge, or tick articles inside one event and press Split / Reassign. Every action is reversible from the Operator log.

Client errors

One row per distinct defect, newest first. Count is every occurrence reported since it was first seen; release, page and browser are from the latest one. Nothing here identifies a reader: no IP, user, query string or typed text is stored. Rows are deleted 30 days after they were last seen.

Usage

Anonymous daily counts only — no IP, user, session, User-Agent or time finer than the day is stored, and nothing is counted from a browser with Do Not Track / Global Privacy Control or with the setting off. Days are UTC. Layers and features count page loads in which they were used; Atlas counts questions.

Growth

Anonymous daily counts (UTC) from IntMap's own counters — see «Usage» for what is and is not stored. Each arrival is counted from what the page saw when the map opened: an entry door, a referring host and up to three utm tags are separate counters, so the rows of one table do not add up to the visits. The change is against the period of the same length just before.

Campaign link

A link to one of IntMap's pages with utm tags, counted in the tables above once a visitor opens the map with it. Tags are stored lower-case, 1–40 of a–z 0–9 . _ - (anything else is not stored at all). A landing page (an example, About, For teachers) does not run the counter itself: its tags are counted when the visitor goes on to the map from it.
