## R520 — **昔の国名ラベルは、国ごとではなく「島ごと」に作られていた**

> 「歴史表示の国名ラベルが、1国家につき何十個も出る。原因は、歴史国名ラベルを『国ごとの代表点』ではなく、
> 国境ポリゴンそのものから生成していること。」

外部の指摘がそのまま当たっていた。`js/time-borders.js` の `imtb-lbl` / `imtb-lbl2` は
`source:'imtb-src'` — **国境を描くための Polygon / MultiPolygon** — を `symbol-placement:'point'` で
ラベル化していた。maplibre-gl の symbol bucket（`node_modules/maplibre-gl/dist/…-worker-dev.js`,
`addFeature`）は、Polygon をこう答える:

```js
else if (feature.type === 'Polygon') {
    for (const polygon of classifyRings(feature.geometry, 0)) {
        const poi = findPoleOfInaccessibility(polygon, 16);
        addSymbolAtAnchor(subdividedLine, new Anchor(poi.x, poi.y, 0));
    }
}
```

**外環ひとつにつき1個。** つまりラベル候補の数は、国の数ではなく**島の数**である。

### 実測（この app が実際に配っているデータ）

`data/cshapes.js` は 1886–2019 の**全年**を答える側で、報告された年（1900 前後）もここから来る:

| 年 | features（国） | outer rings（ラベル候補） | 比 |
|---|---|---|---|
| 1900-07-01 | 151 | **1,583** | 10.5× |
| 1914-07-01 | 150 | **1,642** | 10.9× |
| 1938-07-01 | 173 | **1,671** | 9.7× |

内訳の上位は Canada 268・Indonesia 136・Russia 146・Chile 124・Alaska 95。報告の当事者は
**Japan 30・Korea 7・China 21**（1900-07-01）。1886 より前を答える aourednik のスナップショットも同じ形で、
world_1900 は 166 名が 516 環に、world_1938 の «Empire of Japan» だけで 62 環に分かれている。

⚠ **これは衝突判定の不具合ではない。** `text-allow-overlap` は立っておらず、2層は
`_same != 1` / `_same == 1` で排他になっている。衝突判定が見るのは**すでに作られた候補**だけなので、
`text-padding` を広げる対処は「作ってはいけなかった候補」を隠すだけで、**ついでに本物の国も隠す**。
壊れているのは候補を作る前である。

⚠⚠ **その形は既存の門を全部通っていた。** `tests/r309-checks.test.mjs` は2層の宣言を
`ofm-country` と鍵ごとに突き合わせて一致していたし、`tests/r410.spec.js` は**描かれた文字**を読んで
正しかった。どちらも真だった——**同じ文字を40回描くレイヤーについて**。候補の数を数えていたものが
どこにも無かった。

### 直し方 — 現代の国名ラベルが最初からそうである形

`ofm-country` の文字はベクタタイルの `place` レイヤ（`class=country`）＝**点**データから来る。
era 側にも同じものを与える:

- **`imtb-lbl-src`**（新設・GeoJSON の点ソース）。`imtb-lbl` / `imtb-lbl2` はこれを読む。
- **`_labelFC(fc)`** が `imtb-src` の中身から **1 identity＝1 Point** を作る。まとめる鍵は `NAME` で、
  これはこのモジュールが他の全部で使っている同一性（`featureAt` / `geomFor` / `resolveHist` / `tagSame`）。
  点は**代表地物の properties をそのまま持つ**ので、`_same`（どちらの層が描くか）・
  `_locName` / `_modName`（何と書くか）・`NAME`（クリックが何を開くか）は 1 バイトも変わらない。
- **アンカーは最大の部分の pole of inaccessibility**（本州・チリ本土）。MapLibre が環ごとに計算していた
  のと**同じ量**なので、その国の1つのラベルは「いちばん大きい島に出ていたラベル」の位置に出る。
  動いたのではなく、余りが作られなくなった。
- `_corrected` の地物（`_mergeTibet` / `_mergeEastPrussia` が後継国へ改名して `_modName:''` にしたもの）は
  除く。もともとラベルが空である。
- **`imtb-src` は一切変えていない。** 国境・クリック対象の fill・Compare の塗り・`resolveHist` の
  ジオメトリはそのままで、**出典表記もこちらが持ち続ける**（同じ2つのデータで、`imtb-line` は
  ラベルが出ている間つねに画面にある）。

⚠ **境界を書くたびに、名前も書く。** 2つのソースは1つの状態である。`setSourceData('imtb-src'` は
5か所（`apply()` の2経路・`clear()`・#R410 の遅れて届く身元の貼り直し・#R126/#R140 の `styledata` 再構築）
にあり、どれか1つが名前を書き忘れると**その経路だけ前の年の国名が残る**。検査は総数を比べない
（`_pushLbl` は宣言そのものが1個数えられてしまい、呼び出しを1つ落としても総数は足りる）——
**書き込み1か所ずつ**、直後の文で点も書いているかを見る。

⚠ **費用は1回だけ払う。** 極を解くのは 150 か国で 107 ms（Node 実測）。`_csGeomOf` は CShapes の
レコードごとに geometry オブジェクトを**1つだけ**作って memo しているので、アンカーを `WeakMap` に
**その geometry で**覚えると、10年ぶんの移動で1国につき1回しか解かない。加えて 600 点を超える環は
間引く（107 → 59 ms・最大の国で極が 0.4° 動く）。⚠ **間引いた環は別の多角形**なので、答えを**実物の
多角形で検証し、陸から外れていたら正確に解き直す**——ラベルは近似でよいが、海に出てはいけない。

### ⚠⚠⚠ 直したあとに、二つ出てきた

**① 候補が1つということは、機会が1つということ。** 重複が消えた瞬間、1916 のヨーロッパで
«German Empire» が**丸ごと消えた**。ドイツの pole of inaccessibility はカッセルの近くで、そこは
`ofm-city` の «Frankfurt am Main» が取っている。以前は環ごとに候補があったので、最良の位置が塞がれて
いても別の島の写しが置かれていた——**あの茂みは、同時に冗長性でもあった。** 3つの部分を持つ国は名前を
保ち、1つしかない国は最初から保てなかったことになる。
戻すのではなく、MapLibre 自身の仕組みで置き場所だけを増やす: **`text-variable-anchor`**（＋
`text-radial-offset` 0.65 と、これに必須の `text-justify:'auto'`）。**シンボルは1つのまま、置ける場所が
5つ**になる。実測 1916 / center [8,48] z4.2 で、描かれた国が **14 → 17**（Germany・Greece・Montenegro が
戻り、重複は 0 のまま）。⚠ `ofm-country` にこれは要らないし付いてもいない——あちらのアンカーは OSM の
`place`（人が空いている所に置いた点）で、こちらは**国境から計算した点**であり、他に何が描かれているかを
知らない。

**② 点に「ポリゴンの properties オブジェクトそのもの」を持たせると、この source は書けなくなる。**
これは 40 分かけて計器で追い込んだ。症状は「`imtb-src` は «Austria-Hungary» に更新されたのに、
era ラベルは tag 前の名前を描き続ける」。`_pushLbl` は**呼ばれていて、151 件を組み立てていて**、
それでも `GeoJSONSource.setData` に届いていなかった（`setData` を包んで実測）。
真因は `js/geo-command-log.js` の `_sourceHolds`——source が今持っているものと渡されたものを比べ、
**変わらない書き込みを飛ばす**。その関数自身のコメントがこう書いている:

> a caller that keeps ONE object and edits it in place can still say so — but it has to say so;
> nothing infers it, because **an object that was mutated is the same object**.

`tagSame` は身元が遅れて届いたとき properties を**その場で**書き換える（#R410）。参照を共有していると、
**source が持っている側も同じ瞬間に変わる**ので deep-equal になり、書き込みが飛び、タイルは再解析されない。
`imtb-src` が助かっているのは毎回**まったく同じオブジェクト**を渡していて、`_sourceHolds` の規則①が
「同一性は等値の証明にならない」と拒むから。⇒ `Object.assign({}, …)` で写しにする。写しなら本当の変化は
本当の差になり、**変わっていない年はちゃんと飛ばされる**（それがこの比較の存在理由でもある）。

⚠ この2つはどちらも「直したあとで」しか現れない。**#R410 の spec が両方を捕まえた**——
片方は「1916 の国名が5つとも描かれていること」、もう片方は「描かれている tag が source の tag と
一致すること」という、この2年前に書かれた条件で。

| 年・カメラ | before | after |
|---|---|---|
| 1916 / center [8,48] z4.2 | 17 ラベル・13 か国（France ×2・Italy ×2・Spain ×2・Greece ×2） | 17 ラベル・**17 か国**・重複 0（variable anchor 無しだと 14 か国） |
| 1939 / center [8,48] z4.2 | 22 ラベル（France ×2・Spain ×2・Greece ×2） | 21 ラベル・重複 0 |
| 1900 / center [133,36] z4.2 | China ×3・Japan ×3 | 各1・重複 0 |
| 同 z5.0 / 5.5 / 6.0 / 6.8 | Japan ×3 / ×2 / ×2 / ×2 | すべて重複 0 |

⚠ 1916 の before と after は**同じ 17 個**で、中身が違う。重複が場所を取っていたぶん、
**4 か国が衝突判定で置けなくなっていた**。

⚠ ズームを上げて代表点が画面外に出ると、その国の名前は出ない。これは `ofm-country` と**同じ**挙動で、
「昔の国名ラベルの見た目や挙動も今の国名ラベルと完全に同じに」（#R309）が求めていたものである。

### 起動費用 — `eager.brotli` の天井を 5.9 kB 上げた（理由）

`npm run check:perf` は「起動時に必ず落ちてくるバイト数」に**下がる一方のラチェット**をかけている。
このラウンドは `js/time-borders.js`（eager の `main` チャンク）に pole of inaccessibility の実装を
足したので、**brotli で約 1.7 kB** 増えた。⚠ **落ちたのはその 1.7 kB だけのせいではない**——
eager の天井は #R494 / #R495 以来書き戻されておらず、#R511 も #R515 も #R518 も「許容内
（`max(天井×0.005, 2048B)`）」で通してきた。#R518 が通った時点で残りは **1.3 kB** で、このラウンドが
それを食い切って **240 バイト**はみ出した。

**理由**: この 1.7 kB は「1国＝1ラベル」を成立させている当のアルゴリズムで、時間旅行を始めた瞬間に
要る（遅延させると、境界が出てから名前が遅れて出る）。⇒ `tests/perf-baseline.json` の
**`eager.brotli` の 1 行だけを手で** 1,155,124 → 1,161,140 に上げた。
⚠ `--update` は使っていない——あれは**全項目を書き戻す**ので、#R518 が残した async の増分まで
黙って承認済みにしてしまう。`raw` と `gzip` は許容内なので**天井のまま**（次に足す側が、自分のぶんに
ついて同じ説明をすることになる）。

### 検査

- **`tests/r520-checks.test.mjs`**（`test:checks` に登録済み）。⚠ **綴りを読む検査ではない**——
  出荷される `js/time-borders.js` から `_labelFC` とその補助関数を `vm` に**取り出して評価し**、
  本物の CShapes スナップショットに当てる。① 1国につき1点・1国も落ちない・**独立に書いた
  point-in-polygon で**全アンカーが自国の陸にある、② レンダラが使っていた per-ring 規則を**隣で走らせて**
  1,583 と 151 を並べる（差が消えたら検査が何も測っていないと言って落ちる）、③ 2層がポリゴン源を
  読まないこと・書き込み1か所ずつの追随・`clear()` が両方を空にすること・アンカーが本当に
  キャッシュされていること（同じ geometry の2回目が 1/8 未満）。
  加えて④ 点が properties の**写し**を持つこと（ポリゴン側を mutate しても、既に渡した点は動かない／
  作り直せば新しい値を読む）、⑤ 1つになった候補が**脇へ寄れる**こと。
  **9つの変異（欠陥そのものの復元を含む）を入れて全部赤になることを確認済み。**
- **`tests/r410.spec.js`** に `test.step` を1つ追加。すでに起動して 1916 のヨーロッパに居る page で、
  `queryRenderedFeatures` が返す **PLACED** なラベルに同じ国名が二度出ないことを見る。
  ⚠ **舞台は既に払ってある**ので試験予算は増えない（`check:testbudget` は全体が上限ちょうど）。
