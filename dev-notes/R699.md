## R699 — **散文の中の数の主張を、手書きの区切り文字の集合で拾っていた**

〈#R696 の続き。セッション開始の配線を正本 1 つにしたうえで、#R696 が見つけた見落としを構造で直す〉

### 1. ⚠⚠⚠ 集合の外にある文は、誤りとも正しいとも判定されていなかった

`scripts/doc-facts.mjs` の `edge-count` は、文書が述べる Edge Function の本数をこう拾っていた:

```
Edge Functions?  ·  「は を — – - : ： （ (」のどれか  ·  数  ·  「本」
```

#R696 の実測では `docs/README.md` が実体より 1 つ少ない数を書いており、**門は緑だった**。
名詞と数のあいだにあるのは「の名簿（」で、**「の」は集合から意図的に外されていた**
——「… の 1 本」が部分を指す言い方だからで、その判断自体は正しい。
問題は、集合の外にある文が**誤りとも正しいとも判定されず、そもそも見られなかった**ことである。
そして報告は、たまたま集合に合った文だけについて「7 件すべて 17」と言っていた。

**同じ数を今日戻しても、旧い針は緑のままだった**（実測）。
これは #R694 が `_shared/` の門から取り出した形と同じで、あちらは **260 文字の窓**が
「いくつ抜けを見逃すか」を決めていた。**どちらも針の性質が規則の被覆に漏れ出している**——
片方は本文の長さ、片方は文字の一覧。

### 2. 問いを逆にする——数量を全部見つけて、それが何を数えているかを訊く

`scripts/doc-claims.mjs`。主題の助数詞を持つ数量を**全部**見つけ、そこから
**名詞修飾連鎖を左に歩いて**、その数量が数えている名詞に着く。

| 文 | 連鎖 | 判定 |
|---|---|---|
| 「Edge Functions は **17本**」 | 間に名詞 0・「は」で接続 | 総数の主張 |
| 「Edge Function の名簿（17 本の名前」 | 間に「名簿」・「の」で接続 | **総数の主張**（#R696 の 1 件） |
| 「公開 relay 4 本」 | `relay` に着いて止まる | 主題の話ではない |
| 「Edge Function の 1 本」 | 間に名詞 0・「の」 | **部分**（そのうちの 1 本） |
| 「**Edge Function 1 本**（…）」 | 間に名詞 0・接続も無い | **個体**（1 本がこれをする） |

実測、同じ 44 文書で **7 件 → 9 件・偽陽性 0**。

### 3. ⚠⚠⚠ 既定の向きが要点だった

旧い集合は**包含**の一覧で、名指されなかったものは不可視だった。
新しいのは**除外**の一覧で、**連鎖が主題に着いた数量は全部検査される**——
名前の付いた類（部分・個体）に落ちたときだけ免除され、**その類も数えて報告される**。

これが本体である。**「食い違いが無かった」と「1 件も見ていなかった」を、旧い規則は
区別できなかった。** 同じ欠陥が他にもあり、`node scripts/doc-facts.mjs` の緑の行に数が
1 つも入っていない規則が **10 本**あった（一覧は門の出力から読む。`docs/TESTING.md`）。

### 4. ⚠⚠ 見出しが話すのは、自分の名詞を持たず行頭に立つ数量だけ

「⚠ **17本**すべてを…宣言する」は名詞に着かない——読者と同じで、上の見出し §6.2 に寄りかかる。
そこで「見出しが主題を名乗る節の中の、連鎖が失敗した数量」を主張として拾ってみたところ、
**`Architecture.md` §6.2 の中だけで 11 件が偽の主張になった**（「socket は同時に1本だけ」
「鍵1本あたり3接続で、4本」「共有するのは13本」…＝真 2 件に対し偽 11 件）。
**自分の名詞を持つ数量は、すでに主題を見つけている。** 見出しが話してよいのは、
**hops が空で・接続も無く・行頭に立つ**数量だけ——実測でそこまで絞って偽陽性 0。

### 5. ⚠⚠ 規則の名簿を片側から導出すると、静かに欠ける

`tests/r274-checks` ① は「走らなかった規則は落ちようがない」を測る唯一の検査で、
規則の一覧を**この門自身の `ok('…')` から導出**している（#R403 が手書きの 12 本を置き換えた）。
ところが **`fail()` しかしない規則はそこに現れない**——`scan` と `sql-path` の 2 本が、
その検査の**外**にいた。**一覧を 2 つある側の片方から導出するのは、区切り集合と同じ形**
（答えが、見た場所の広さに縛られる）。母集合は `fail(` ∪ `ok(` にし、2 本に `ok()` を足した。

### 6. ⚠ 規則を説明する文書が、その規則の欠陥を逐語で引用すると自分で赤くなる

`docs/TESTING.md` に #R696 の文を**そのまま**書いたら、新しい歩きがそれを主張として拾い、
`check:docs` が落ちた。`scripts/doc-facts.mjs` のヘッダが警告している自己命中そのもので、
**直ったことの実地の証明**でもある（旧い針はこの引用も見なかった）。文は部品から組み立てて書く。

### 7. ⚠ セッション開始の hook が、最後まで手書きの写しだった

`.claude/settings.json` の `hooks.SessionStart` と `.codex/hooks.json` が同じ起動コマンドを
別々に持っており、**片方の製品にだけ hook を足せる状態**だった——#R696 が直した
「メモリの正本が 2 つあった」のと同じ形が、配線の側に残っていた。
正本は `.agents/session-start.json` 1 つになり、`scripts/agent-sync.mjs` が両方を描く
（`npm run check:agents` が照合）。**どの製品に配るかは各コマンドの `products`、
配らない理由は `why`。** 実際の非対称は 1 つだけ: Claude Code は `MEMORY.md` を自分で読むので、
メモリの hook は Codex にしか要らない——**「両方に要る事実」と「両方が hook を要る」は別**である。

### 7.5 ⚠⚠⚠ 同じ形を他の 12 規則で数えたら、4 件は**いま嘘だった**

門が緑のまま、読者はこう読んでいた:

| 文書 | 書いてあった | 実体 |
|---|---|---|
| `PRODUCT.md` | 「130 の能力すべてに届く」「130 能力」 | 138 |
| `docs/FILES.md` | 「125 能力 ×」 | 138 |
| `docs/FILES.md` | 「実測 core 6 本 / deep 59 本」 | core 7 / deep 105 |

`capability-count` は「\*\*N 能力\*\*」「N 能力ぶん」「N 本の schema」という**装飾に固定した 3 つの形**
だったので、**「の」が 1 つ挟まるか、アスタリスクが無いか**、それだけで見えなくなっていた。
`deep-tier-size` は英語の「spec files」を数えており、**同じ事実が日本語で書かれていた 5 か所目**が
規則の外にいた（規則自身のコメントは「4 か所のうち 3 か所がずれた」と書いてある）。

⚠⚠⚠ **ただし一般解は「助数詞に結べ」ではない——`alerts` でそれを実測した。**
「能力」「都市」「リング」「名前」は**主題が 1 つしか無い**助数詞なので結んでよい。
「か国」「フィード」は違う: 全部拾ったら **1 回の実行で 59 件の正しい文が失敗になった**
（放射線レイヤーの国数・インターネット健全性の国数・ニュースのフィード数——全部正しく、
全部 alerts の話ではない）。**汎用の助数詞は、主題も届いていないと使えない。**

⚠⚠ **そして 1 本の針は、捕まえた数を比較していなかった。**
`(\d+) countries over (\w+) feeds` は両方取って `[1]` しか読まないので、
「47 countries over **thirteen** feeds」は**フィードが何本になっても緑**だった。
**見ることと判定することは別**で、その差がこの回の主題そのもの——未使用の捕獲群 1 つぶん。

### 7.6 ⚠⚠⚠ 事実の値を針のリテラルに埋めると、その値は誰も検査していない

`capability-count` の 6 本目の針は 「撤去済み **1** を除く (N)」 で、**撤去済みの件数が
パターンに焼き込まれていた**（比較されていなかった）。#R590 がレジストリを 137→138 に上げた
同じコミットで本文を「撤去済み **137** を除く」に書き換え、**その瞬間に針が外れて規則が無言に**
なった。以後 4 件が未検査のまま出荷されていた:

| 文書 | 書いてあった | 実体 |
|---|---|---|
| `Architecture.md` ×2 | 「撤去済み 137 を除く 136」 | 撤去済み 1・到達可能 137 |
| `DECISIONS.md` ×2 | 「130 のうち撤去済み 137 を除く 136」 | レジストリ 138 |

しかも `docs/FILES.md` は 2 ファイル隣で「到達可能 137」と**正しく**書いており、
**2 文書が同じ数について別の答えを出していた**。規則は「10 stated size(s)」と印字していたが、
この 4 件はその 10 に入っていない。

⚠⚠⚠ **これは 7.5 の捕獲群の 1 段手前である。** あちらは**捕まえた数を読まなかった**。
こちらは**捕まえてすらいなかった**。どちらも「針に書いた数は、検査されている数ではない」。

### 7.7 ⚠⚠⚠ 1 件も当たらない針は、緑を出す

`languages` の針は 「対応 UI 言語は(\\d+)つ」——**半角空白が必須**。
`Architecture.md` §2 は「**対応UI言語は9つ**」と空白無しで書いている。
**全 44 文書で 0 件**。`if (archN && …)` が無言で飛ばすので、
**言語数を `js/locales/` に結びつける規則は、何も検査していなかった。**
日本語の中のラテン語の前後を空けるかどうかは**書き手が文ごとに決める体裁**であって、
パターンの一部にできるものではない（#R694 の「体裁の制約が検査から漏れ出す」形）。
⚠ **無言のスキップがもう半分**——「正本が述べていない」と「正本が正しく述べている」が
同じ緑の行になっていた。§2 はこの数の正本なので、**黙ったら赤**にした。

### 7.8 ⚠⚠ #R694 は自分の教訓の半分を残していた

#R694 は `edge-shared` から 260 文字の窓を外した。だが批判した当の文——
**11 本を読み上げながら、どの文書についても何も証明していない門**——は、
**0 件監査した実行でも印字できるまま**だった（`ok()` が無条件）。
監査した目録の数を数えて印字し、**0 なら赤**にした。
### 8. 残っている穴（書き留めたうえで残す）

- **裸の英語の数詞**。`docs/SECURITY-ARCHITECTURE.md` §5 は「There are seventeen Edge Functions,
  and this table used to list two.」で始まる。**総数の主張と、その文書自身の履歴が 1 文の中にある。**
  節の広さでも段落の広さでも測ったが、前者を拾えるまで広げると**後者が失敗になる**。
- **歩きが知らない接続詞**。連結の語彙はまだ手書きの集合である。ただし**その端から外れたことが
  見えるようになった**——他のどの名詞も名乗らず、主題と同じ行にある数量は `unlinked` として
  返り、他の主張と同じように検査される（文書群にある主題と無関係な約 460 の数量に紛れない）。
