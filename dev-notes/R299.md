## R299 — **「ごっそり抜け落ちる」を上流のファイルに訊いたら、そのファイルは履歴ではなく現況の表だった**

依頼は6主題。いちばん重い1件は、上流の JSON を**1回開いて数えれば**答えが出るところにあった。

### ① 日本の警報の 26% が、種別ごとの行を捨てていたせいで消えていた

> 発令されているのに、ごっそり都道府県単位でもれ落ちていたりする。

`https://www.jma.go.jp/bosai/warning/data/r8/map.json` を実際に取って数えた:

| 測ったもの | 値 |
|---|---|
| 行数 | **287** |
| 発表官署の数 | **58** |
| **(官署 × `dataTypeCode`) の組ごとの行数** | **min 1 / max 1** |

つまりこれは**速報の履歴ではなく、現況の表**である。`dataTypeCode` は災害の系統で、1つの官署が

```
VPWW55 → コード 03,10       (大雨・洪水系)      VPWW58 → 15          (風)
VPWW56 → コード 09,29,49    (土砂災害系)        VPWW59 → 16          (波浪)
VPWW57 → コード 48          (高潮)              VPWW61 → 14,20,21    (雷・濃霧・乾燥)
```

をそれぞれ**独立に**出し、各行はその系統について、その官署の**全 class20 を「発表なし」まで含めて**列挙する。
前橋地方気象台の4行を並べると一目で分かる——

| 種別 | 発表時刻 | 発表中の市町村 |
|---|---|---|
| VPWW56（土砂） | 08-22 03:37 | **2** |
| VPWW55（大雨） | 08-21 22:44 | 0 |
| **VPWW61（雷）** | 08-21 04:58 | **35** |
| VPWW58（風） | 08-12 00:16 | 0 |

#R269 の「官署ごとの最新1件」は、群馬について **VPWW56（2件）を残して VPWW61（35件）を捨てていた**。

**このモジュール自身の処理**（`JMA_CODE` の表・class10→class20 の展開込み）を実データに通した実測:

| | 残る行 | 塗られる市町村 |
|---|---|---|
| 旧（官署ごと） | 58 | **601** |
| 新（官署 × 種別） | 287 | **812** |

**+211、発表中の 26.0%。** そして損失は薄く広がらず、**県単位で全滅**していた——
**千葉県 54/54・東京都 53/53・熊本県 46/46・山梨県 27/27・石川県 19/19**。
「ごっそり都道府県単位で」は比喩ではなかった。

⚠ **古い行を捨ててはならない。** 再発表されていない系統は「その系統は変わっていない」という意味である。

「全系統が新しいか」ではない——静かな系統こそ正当に古い。

### ② 「発令されているのに、灰色になっている場所がある」

国全体の灰色は**「読んだ。何も出ていない」**という主張である。`washTier` の最後の行は

```js
return quietSet[c]?2:1;
```

で、`quietSet` は `QUIET_UNIT_Z`（=3）未満では**常に空**（#R290 が測った通り、世界ズームで区分ごとに描くのは
5,445 地物・6.1 MB を払って同じ絵を作る）、そして単位索引が届くまでの数秒も空である。
その2つの窓で、**警報を描いている国の全面に灰色が敷かれ、その上に警報色が乗っていた**。
主張そのものが偽——警報が出ている国について「何も出ていない」は言えない。

→ **何かを描いている国は wash しない**（`quietSet[c]||drawnISO[c]`）。
これは #R270 ⑧ が既に書いていた規則（「区域を描く国は国全体で wash しない」）が、
`quietSet` の空く窓に届いていなかっただけである。⚠ 世界ズームでは発令中の国が透明になる——
それは「読んだ。何かが出ている。ただしこのズームでは**どこで無いか**は言えない」という、
この地図が本当に知っていることと一致する。

### ③ 二度塗りが1件だけ残っていた——同じ形どうしで点判定が外れる

本番実測（z8・青森、6 px 刻み 19,418 点）: 1点あたりの地物数は **1 が 99.55%・2 が 0.45%・3以上は 0**。
#R298 追記の「1点に4回・5回」は解消している。**ただし本物の二度塗りが 1 件**——
**上北郡野辺地町**が同じソースに **norm 1**（気象庁「Dense fog」・`#f2e700`）と **norm 0**（発表なし・`#dcdce0`）の
**両方**で入っており、`fill-opacity` 0.38 が二度掛かって実効 α は **0.616**。

理由は `coveredByWarning` の2つの点判定が、**同じ形どうしでは外れうる**ことだった:

- `jpShape()` は `UNITS['JPN']` と**同じ索引**から**新しい** MultiPolygon を作るので、`===` は偽。
- 野辺地町は**湾を抱く**ので、**自分の重心が自分の外（海）にある**。だから「単位の中心が警報の中にあるか」は、
  その単位そのものに描かれた警報について**偽**になる。

→ **輪郭で先に訊く**。同じ国で bbox が小数4桁まで一致すれば同じ単位である（`dedupeSameShape` が
同じ判断に既に使っている基準）。日本・中国・台湾・MeteoAlarm の名前解決——**この地図自身の単位の上に
警報を置く国すべて**が同じ穴を踏みうる。

### ⑤ 「いま発表されている警報」は、一覧でも警報でもなかった

中身は**国の一覧**（1国1行・上限16か国）である。依頼は2つ:

- **IntMap 独自分類で「危険」以上のものがある国だけ**——しきい値は `HOT_MIN`（=3＝`NORM_NAME(3)` の「危険」）
  1か所にだけ書く。見出し・空のときの1行・絞り込みが別々の数を言わないため。
- **ふさわしい名称に改名**——**「危険以上の警報が出ている国」**。一覧でないものを「いま発表されている警報」と
  呼ぶのは、この層が何度も払ってきた偽の見出しである。

⚠ **空のときの文も変えた。** 「接続中のいずれの機関にも、現在発表中のものはありません」は、絞り込みが入った
いま**偽の文**である（下位の階級は出ていて地図に描かれうる）。→「いま『危険』以上に達している国はありません」。

本番実測で出ていた16か国のうち、**Severe（norm 2）だったポーランド 339・オーストリア 115・カナダ 112 が落ち**、
Danger 以上の 13 か国が残る（ローカルで確認済み）。

そして凡例の下の長文2本（120字級）を**1行**にした。残したのは主張だけ——
①「IntMap 独自の換算である」＋「同じ段でも危険度は同じではない」、②「色は各機関自身のもの」。
どちらの機関がどの配色かは**タップ1つ先**（`legendFor`）にあり、そこが答える場所である。**9言語**。

### ⑥ 風——「同じ絵に着くまで」を短くした（絵は1ミリも変えていない）

1. **`keepFrame` が同じ変数の<b>別時刻</b>まで捨てていた** → 「1時間進めて戻す」が必ず再ダウンロード。
   置き換えるのは**同じ鍵で、新しい帯が古い帯を覆うもの**だけにし、あとは予算 24e6 の LRU に任せる。
   帯なら **7〜21 時刻**が手元に残る＝再生で通った時刻の往復が**通信ゼロ**。
2. **追い越された読み込みが、最後まで通信してから捨てられていた** → `serial()` の順番が回った時点で世代を見て
   **1バイトも読まずに**戻る。スライダーを 20 コマ引きずると **20回 → 1回**。
   ⚠ 戻り値を falsy にしない——`js/weather.js` はそれを「取得失敗」と読んで再試行3段とトーストに入る。
3. **`widen()` が時刻を変えるたび地球（13,199,360 標本 ≈ 18 MB）を読み直していた** →
   **静止 900 ms ごとに1段ずつ**広げ、時刻が変われば段はやり直し。⚠ 段は幅ではなく**標本数**で切る——
   ECMWF は reduced Gaussian で行の点数 ∝ cos φ なので、「半幅2倍」は世界ズームで地球の **86.6%** を掴み、
   段を挟むと合計が**増える**。静止し続けた読み手のバイト数は #R297 の2読と同じで、減るのは**まだ動かしている**
   読み手の分。
4. `lift()` が idle ごとに `getStyle()`（スタイル全体のシリアライズ）を呼んでいた → メモ化し `styledata` で捨てる。

⚠ **粗い領域への切り替えは採らなかった。** `ecmwf_ifs025`（0.25°・標本 1/6.4）は実在するが、
`valid_times` が **3時間刻み（49本）**で、`ecmwf_ifs` の **1時間刻み（109本）**と軸が違う。
使えば**時刻がずれる**——「品質を保ったまま」に反するので捨てた。

本番の「前」の数字（比較用）: 起動から粒子 **2.9〜6.9 s**・色面 **10.1 s**・1トグルで **27.8 MiB**
（うち `.om` 16.4 MiB）、1コマ変更で **3.41 MiB / 6.36 s**。

### ⑦ 経路パネル——本番で測ったら、辺は掴めて角だけ掴めなかった

#R298 追記の drag/resize は**本番に届いている**（実測: ヘッダを掴んで [414,74]→[534,134]、`data-detent` は
null＝指紋が消えた）。残っていたのは**角**である:

| 掴む場所 | hover の cursor | 結果 |
|---|---|---|
| E / S / W / N の辺 | `ew-` / `ns-resize` | 効く |
| **SE 角 inset 1〜5 px** | **付かない** | **0 px** |

原因は当たり判定ではなく、**ポインタがそもそも届いていない**こと——`border-radius:18px` は**当たり判定も切る**ので、

`M` を上げても直らない——足りない画素は**要素の外**にあるので、要素に付けた listener には原理的に見えない。

⚠ **角だけ**（`d.length===2`）——辺まで document で取ると、パネルの縁 9 px に落ちたクリックを全部奪う。
⚠ **z 最上位の窓が勝つ**（`bringToFront` が保つ順序）。
ローカルで**押して**確認: 角の内側 2 px から **384×590 → 466×652**。

先に記帳して、**466×652 → 45 → 466×652 ちょうど**。

**上半分が下半分を潰していた。** 本番実測、`.rtp-body` は `scrollHeight` **1,619 px** のうち **267 px** しか

**下だけを縮める**。→ 上に `max-height`、下に `min-height`、各部品を1段小さく。
⚠ **デスクトップだけ**（`@media (min-width:768px)`）。携帯の 44 px の標的は 1 px も触らない。

#### ⑫ 「THE CAMERA DOES NOT MOVE」と書いた行の1文前で、カメラが動いていた

`_onLineClick` の上に #R299 はこう書いた——**「⚠ THE CAMERA DOES NOT MOVE.
`open({reveal:true, keepView:true})` skips the re-frame」**。本番実測、z10.91 で線をタップすると:

| | 値 |
|---|---|
| Δlng | **+0.001934°**（東へ約 2.7 px） |
| Δlat | **−0.002779°**（南へ約 4.7 px） |
| Δzoom | **−0.0359**（尺度 −2.5%） |

2回の独立実行で**同一の差分**。そしてジェスチャは move → down → 60 ms → up で**間に移動が無く**、
かつ **zoom が変わっている**——合成ドラッグではない。

⚠ **コメントが名指しした機構は本当に無実だった。** `open({keepView:true})` はパネル自身の再フレームを
確かに飛ばす。動かしていたのは**同じ関数がその1文前に呼ぶ `selectAlt`** で、

```js
_drawAlts(sel,setId)  →  _paint(feats, fc.length?fc:null, 15)   // fc = 選択中の候補の全座標
_paint(feats,fitCoords,…)  →  if(fitCoords&&!_noFit) camera.fitBounds(…)
```

#R291 の規則「**新しい経路集合だけが、1回だけ fit する**」は、`_lastPaint.fit=null` によって
**スタイル差し替えの再描画にしか効いていなかった**。選択には一度も効いていない——つまり **7ラウンドのあいだ、
候補を選ぶたびにカメラが飛んでいた**（地図の線からでも、パネルのカードからでも）。

→ 選択は `repaint()` が既に使っている `_noFit` で**貼り直すだけ**にする。
⚠ `selectStep` は**意図して飛ぶ**ので触らない——「その手順へ飛ぶ」が「1つの手順を訊く」の意味である。

**教訓**: 検査した機構の名前を書いた注記は、**検査しなかったほうの機構については何も言っていない**。

#### ⑬ 「開いている」と「見えている」は別の状態だった

`_revealPanel()` は `if(UI.isOpen()) return;` で早期に戻る。**最小化したパネルは `openState` が真**なので、
本番実測: 線をタップすると `sel 0 → 1`、`.rtp-min` は**そのまま**、高さ **46 px**——
読めない帯の中で経路が選ばれていた。

→ `isOpen()` から「もうやることは無い」と**推測する**のをやめて `open({reveal:true,keepView:true})` を
**呼ぶ**（`open()` は冪等で、`rtp-min` を外すのは `reveal` フラグである）。

⚠ **そのぶん `open()` が再入可能になった**ので、「開くときにだけ起きるべき2つ」を守った——
**フォーカスの戻り先**（`focusReturn`）と**「出発地」欄へ入るカーソル**。
地図をタップするたびに読み手の手からフォーカスを奪うのは、再入可能になった `open()` がやる
典型的な静かな破壊である。

#### ⑭ 同じ事実を述べた3ファイルのうち、1つが4ラウンド古かった

`js/map-ui.js` と `js/routing.js` はどちらも「**Tools 行の2度押しはパネルを閉じるだけで経路は残る**」と
書いていた。本番実測: 2度押しで `hasRoute()` は false、`imroute-*` は**全レイヤー 0 地物**。
#R296 の「経路機能を閉じても地図に経路が残り続けるのをやめろ」が**閉じる＝消す**に反転させて以来そうであり、
Tools 行も同じ `close()` を通る。**振る舞いが指示で、文のほうが写しだった。**

#### ⑯ 追記2 — 欧州でただ1点「何も塗られていない」場所があり、原因は上流の一般化だった

「何も発令されていないのに、灰色に塗られていない場所がある」の最後の1件。z9 で 0.005° の格子を撃つと:

| 測ったもの | 値 |
|---|---|
| `wp-alert-fill` が 0 件の点 | **323**（bbox **12.95 km × 9.48 km**） |
| z11 で同じ格子 | **同じ 323 点・同じ bbox**（＝タイル簡略化ではない） |
| 同じ箱の他の点 | **1,146 点が `ITA:Lazio/n1` ちょうど1件** |

「透明なのか斜線なのか何も無いのか」は、**塗りの式を読んで**決めた——ITA の `feature-state.wpAlert` は **2** で、
`wp-alert-choro` の `match` では**既定の完全透明**、`wp-alert-hatch` の `case` では**不透明度 0**。
画素でも確かめた（穴の中は素の基図、外だけ G が下がる＝`#ffd200` を 0.38 で載せた計算値と一致）。

**幾何を直読みすると**（`queryRenderedFeatures` ではなく）、ローマ中心は **Lazio の外側リングの中**であり、
**同時に Lazio の穴の中**だった。イタリアの 22 地物のうち穴を持つのは Lazio だけ。

その穴は**バチカン市国**で、**20M の一般化が 0.44 km² → 73.93 km²＝168 倍**に膨らませ、歴史地区を飲んでいた。

| ファイル | バチカンの穴 | ローマ中心 |
|---|---|---|
| `NUTS_RG_20M_…_LEVL_2`（本番が読む） | **73.93 km²** | **穴の中** |
| `NUTS_RG_03M_…_LEVL_2` | 1.66 km² | 穴の外 |
| `NUTS_RG_01M_…_LEVL_2` | 0.50 km² | 穴の外 |

⚠ **IntMap は改変していない**——本番の地物の穴リングは、Eurostat のファイルのそれと **9桁一致**。
⚠ そして公開コレクション **3,384 地物・穴 94 本**のうち、**中に何も入っていない穴はこの1本だけ**である
（他は全部、中に別の単位が入っている——それが穴の正しい使われ方）。

**なぜイタリアだけか。** #R297 が作った細かい段は **LEVL_3 だけ**で、MeteoAlarm が**州＝NUTS-2** で
発表するのは**イタリアだけ**。他国の単位は LEVL_3 を通るので 03M が届いた時点で**自然に治る**——
**同じ穴は 20M の LEVL_3 にもある**のに症状が出ないのはそのためで、だから欠陥がイタリアの形をしていた。

→ **細かい段が両方の階級を取る**（03M LEVL_2 は **3.97 MB**・`bndJSON` でキャッシュ・
`UNIT_HIRES_Z` を越えたときだけ）。⚠ **床は 20M のまま**——#R297 が測って断った通り。

**本番で確認した**（同じ格子・同じ z9）:

| 測ったもの | 修正前 | 修正後 |
|---|---|---|
| `wp-alert-fill` が 0 件の点 | **323** | **7** |
| その bbox | 12.95 km × 9.48 km | `[12.45, 41.90, 12.46, 41.91]` |
| ローマ中心 | 0 件 | **1 件**（`ITA:Lazio / norm 1`） |
| Lazio の穴の面積 | 74.42 km² | **1.6746 km²** |

⚠ **残った 7 点はバチカン市国そのもの**（03M の穴リングに対する point-in-ring で全点が中、
ローマ中心は外、バチカン中心は中）。**NUTS の単位でも MeteoAlarm の区域でもない主権国家**なので、
そこが塗られないのは欠陥ではない。
取得も確認: `NUTS_RG_03M_…_LEVL_2` **4,160,790 B = 3.97 MiB** で 200、**床の 20M 2本も消えていない**。
床の内訳（z2・258 地物）は **透明 65 / 灰 88 / 斜線 105** で、形は修正前（57/86/91）と同じ。
Berlin・Paris・Madrid・Warsaw・Milan・Naples はいずれも 1 件。

⚠⚠ **そして直りは「即時」ではない。** ローマへ寄ってからの時系列: **t=21.6 s** はまだ 20M で 0 件、
**t=32.9 s** に索引が 03M へ替わり、**t=43.1 s** に描画ソースの再 publish が届いて 1 件になる。
**一発サンプリングでこの主張を測ると偽陰性が出る**（実際、45 秒後に一度だけ測ったランが 0 件を返した
——それはソース差し替え中の一過性の窓で、ローマ固有ではない）。

**教訓**: 「地図に穴がある」と言われたら、**塗りの式を読んで「透明」と「未塗装」を分け**、
そのうえで**幾何を直読みして穴のリングを探す**。そして**穴が正当かどうかは「中に何か入っているか」で決まる**。
