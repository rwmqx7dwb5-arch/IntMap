## R440 — **「同梱している」と言っていた数は、書いた行数ではなく読んだ行数だった**

**#R432 の調査で見つかった別件。** `data/volcano-detail.json.gz` が実際に持つ噴火行は **11,043**
（VEI 付き **8,402**）。しかし現行文書4本と**出荷される6言語の文字列**は **11,089**（**8,418**）と
述べていた。**差は 46 行。**

### 1. 数はどこから来たか

`scripts/build-volcanoes.mjs` は GVP の WFS を3つ読む。噴火の feature type
`Smithsonian_VOTW_Holocene_Eruptions` は **11,089 行**を返し、その全部が `hist`（火山番号 → 行）に
入る。ところが `detail[vn] = {…}` を書くのは **`V.features` のループの中だけ**——つまり
**完新世火山カタログ（1,214 座）に項目がある火山だけ**が書かれる。

それでも完了行はこう印字していた:

```
wrote data/volcano-detail.json.gz — ${E.features.length} eruptions (${veiKnown} with VEI)
```

**`E.features.length` は上流の応答の長さであって、書いたファイルの中身ではない。**
14 か所の写しは、すべてこの 1 行から出ている。

### 2. 落ちる 46 行の正体（上流で実測した）

WFS の噴火 11,089 行を取り直して火山番号をカタログと突き合わせた:

| | 行 | うち VEI 付き |
|---|---:|---:|
| 上流が返す | 11,089 | 8,418 |
| カタログに居る火山の分（＝同梱） | **11,043** | **8,402** |
| 落ちる | 46 | 16 |

落ちる 46 行は **24 の火山番号**に属する——Vulsini、Tacora、Ollagüe、San Pedro-San Pablo（10 行）、
Igwisi Hills、Muria、Feni、Mariveles など。**どれも完新世「火山」カタログに項目が無い**ので、
カードを掛ける先が存在しない。**落ちるのは正しい。** 正しくなかったのは「同梱している」と言ったこと。

⚠ カタログの 1,214 座のうち、噴火の行を1つ以上持つのは **891 座**。

### 3. なぜ門が2つとも見えなかったか

- **`tests/r353-checks ②`** は行を実際に数えていたが、比較していたのは
  `eruptions > 10000` / `withVei > 7000` という**下限**だった。11,043 でも 11,089 でも 10,001 でも通る。
  **唯一その位置に居た検査が、閾値だったせいで何も測っていなかった。**
- **`⑧`**（#R353 が「件数をプロースに書くな」のために作った門）は
  `src.replace(/\/\*[\s\S]*?\*\//g, '')` で**ブロックコメントを剥がしてから**針を当てる。
  **この数が書かれた js の4か所は全部ブロックコメントだった**（`js/beta-overlays.js`・
  `js/volcano-intel.js` ×2・`js/lazy-modules.js`）。そのうえ針は座数（`1,215` / `1,214`）だけで、
  走査対象は3ファイル——**6言語の `js/locales/pages.*.js` はそもそも開いていない。**

⚠ **#R353 は `docs/VOLCANO-INTELLIGENCE.md` §2 でこう宣言している**——
「**件数はどこにもハードコードしない**——凡例も文書検査もテストも**ファイルから読む**」。
座数についてはその3つを全部作った。**そして同じラウンドで、噴火の件数を14か所に書き写した。**
宣言は、当の数には一度も適用されていなかった。

### 4. 直したもの

**出荷される文字列（9言語）** — 数を落とした。凡例と違い `sources.html` は 551 kB の gz を
「何行あるか」のために取りに行けないし、**同じ文が座数について既にそうしている**
（「完新世カタログ全件を結合キー付きで持ち」）。同じ形にした——
「そのカタログに載る火山について GVP が記録している噴火のすべて（VEI と日付）」。
⚠ **de / es / ru は #R353 の書き換えを一度も受けておらず、1文の旧文言のままだった**
（前後の項目は3言語とも長文に更新済み）。9言語ぶんの本文を入れた。

**ビルド** — `V.features` のループが**書いた行を数える**。完了行は書いた数を印字し、
**落とした数とその理由も印字する**。

```
wrote data/volcano-detail.json.gz — 11,043 eruptions (8,402 with VEI), 538 kB gzipped
  of the 11,089 rows GVP published (8,418 with VEI); 46 were dropped, belonging to
  24 volcano numbers the Holocene catalog does not list
```

**ファイルが自分の大きさを持つ** — `eruptions` / `eruptionsWithVei` を top-level に（**+25 B**）。
下流はどこも数えなくてよく、`②` が記載と実体の一致を要求する。

**`②` から floor を全部外した** — 代わりに3つの等式:
① 記載（`DETAIL.eruptions`）＝歩いた行数、② `Σ layer.q`（9,911）＝確認済み行数、
③ **`y`（Last_Eruption_Year）を持つ 848 座は必ず噴火行を持つ**。
⚠ ①②は**0 でも自己整合する**——「上流が空で返した」を捕まえられるのは③だけ。
`y` は**火山**の feature type から来るので、噴火の feature type とは独立。

**`⑭`（新）** — 数を**ファイルから引き**、**コメントを剥がさず** js 4本を掃き、
`js/locales/pages.*.js` を**ディレクトリから列挙して**全言語の «Smithsonian GVP» 欄を読む。
4桁以上の数を禁じる（半径の 5 / 10 / 30 / 100 km は3桁までなので当たらない）。

**`npm run check:docs` に `volcano-eruptions`（規則30）** — gz を開いて行を数え直し、
現行文書が述べる数と突き合わせる。
⚠ **最初の版は「噴火語の 24 文字以内にある3桁区切りの数」で、正しい文を4つ誤検出した**——
`E3WebApp_Eruptions1960` の行（2,248）、**火山の座数**を数える見出し（1,214）、そして
**2つの数を対比するために書いた自分の説明文**（11,043 と 11,089 が並ぶ）。
**近さは主張ではない。** 主張は「N 件の噴火履歴」「噴火履歴N件」「N eruptions」という
**数え方の句**なので、そちらを照合するようにした。句が変われば逃げられるので、
**3文書には名指しで「書いてあること」も要求する**——黙るのも赤。

**コメント4か所** — 数を消して、何が在るかを言うようにした。

⚠ **その `⑮` 自身が、最初は並行実行で偽の赤を出した。** 3つの変異は `withTreeLock` の中に入れて
いたが、**その前後の「素の木で緑であること」を読む2行がロックの外に居た**——`npm test` 中は
他のファイルの変異が生きている瞬間があるので、「volcano-eruptions is already red on the
committed tree」で落ちる。`tests/helpers/gate-lock.mjs` の見出しが **#R280 の実測としてこれを
名指ししている**（「A READER THAT REQUIRES A PRISTINE TREE IS ALSO A PARTY TO THE LOCK」）。
**素の木を読むだけの行も、ロックを取る側である。** 2行それぞれを独立の hold に入れて解決
（ホールドはテスト全体ではなく変異ごとに取る——#R403 が同じ理由で 264 s を測っている）。

⚠ **ラウンド番号は R436 → R440 に取り直した**（rebase 中に origin/main が 3 コミット進み、
R438 / R439 が別の open PR に取られていた）。R440 が **DEV-NOTES の最新**になるので、
`index.html` のビルドスタンプ **2箇所**（`__imBuild` と `INTMAP_BUILD`）も上げる
（`tests/r264 ⑧` と `tests/r301 ⑦` が CI で赤くして教えてくれた——隙間番号なら触らない側）。

⚠ **9言語の査読で、de の1本だけ意味がずれていた**——`die Vulkankarte` は en の「volcano **card**」
ではなく「火山**地図**」と読める複合語で、地図アプリの出典ページでは実在するレイヤーを指してしまう。
`pages.de.js` の `-karte` 複合語は `Basiskarte`／`Warnkarte`／`Regionskarte`… と**全部「地図」**で、
カードの意味で使われている語は `Infokarten`（Wikipedia の行）だけだった ⇒ `die Vulkan-Infokarte`。
**新規に訳を入れた3言語のうち、es は既存の作法にそのまま乗っていて修正ゼロ**——
英語原文が同一の兄弟3行（`CRUST1.0` / `USGS Slab2` / `Bird (2003) PB2002`）と突き合わせると、
その言語がその文をどう書くかは**測れる**（de は `Mit der App ausgeliefert`、ru は
`Поставляется с приложением` が兄弟3行の書き方だった）。ru はもう1つ、受動形動詞 `собираемые` の
行為者に**造格**が要るのにラテン文字のファイル名は格を担えない ⇒ `собираемые скриптом scripts/…`。
