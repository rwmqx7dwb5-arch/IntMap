## R533 — **正しいロゴは最初からリポジトリの中にあり、一覧だけが消えたホストを見ていた**

〈#R529 の本番検証の副産物として報告された 3 系統——`logo.clearbit.com` の名前解決失敗 189 件・
`t{0..3}.gstatic.com/faviconV2` の 404 15 件・Yahoo/corsproxy/allorigins の株価失敗〉

### 切り分け（2026-09-07 実測）

**① `logo.clearbit.com` は消えている。** 8.8.8.8 / 1.1.1.1 / 9.9.9.9 のすべてが `clearbit.com` の
**SOA だけ**を返し、A も CNAME も無い（apex の `clearbit.com` は 18.138.148.131 で生きている——
消えたのは `logo.` だけ）。上流の記録も一致する: HubSpot が買収後に統合し、**deprecation 2025-03-18 →
shutdown 2025-12-08**。#R514（`map-tiles.open-meteo.com`）と同じ形で、こちらは**規約でも Referer でも
鍵でもなく、単に無い**。

**② gstatic の 404 は退行ではなく正常動作だった。** リポジトリに `faviconV2` という綴りは 1 件も無い。
実測すると `https://www.google.com/s2/favicons?domain=…&sz=64` が **301 で `t{N}.gstatic.com/faviconV2`
へ転送される**——つまり観測された 15 件は、ロゴも favicon も持たない企業がモノグラムへ落ちる過程その
ものだった。⚠ **計器に映った 2 つのホストは、コードの中では 1 本の段だった。**

**③ 株価は 3 段とも同時に落ちていた。** 直 Yahoo は 200 を返すが **ACAO を返さない**（ブラウザには
CORS エラーに見える）・`corsproxy.io` は 403・`api.allorigins.win` は 522。

### ⚠⚠⚠ 直しかたは「別のロゴ屋を探す」ではなかった

**このリポジトリは既に正しいロゴを持っていた。** `scripts/companies/build.mjs` は前からビルド時に
**Wikidata の P154（logo image）**を引き、`https://commons.wikimedia.org/wiki/Special:FilePath/<file>`
を各プロフィールへ書いている（**533 社中 435 社**）。企業アトラスのパネル（`js/company-panel.js`）は
**最初からそれを描いていた**。

一覧だけがそれを見られなかった理由は 1 つ——**ロゴが `profiles/<id>.json` にしか無く、そのファイルは
「企業を開いたとき」にしか取りに行かない**から。だから一覧は自分用のロゴ経路を持ち、その 1 段目が
死んだホストを指したまま、**同じ企業の正しいロゴが同じリポジトリの中にあることを知らずに**、
表示のたびに 189 回失敗していた。

⇒ **`data/companies/index.json` の各行に `lg` を足す**（`profile.identity.logo` **そのもの**を入れる
ので、URL の組み立ては `build.mjs` の 1 か所のままで、index と profile は原理的にずれない）。
`js/company-data.js` に `logoFor(key, domain)`（`data/companies/` の唯一の読み口が持つ）。
新しい段は **Commons（同梱・ビルド時解決）→ Google favicon（Commons に無い企業のみ）→ モノグラム**。
⚠ **index が届くまでは推測の URL を出さずモノグラムを描く**——「失敗すると分かっている要求」は
フォールバックではなく雑音である、というのが今回撤去したものの正体だから。

⚠⚠⚠ **これは新しい発見ではなかった。** #R353 の本番検証が既に「`logo.clearbit.com` が到達不能
（96 リクエスト）」と書き、そのラウンドの退行ではないとして**そのまま残していた**。96 が 189 になった
だけで、**観測を赤に変える門が無かった**のが本当の欠陥。

### ⚠⚠⚠ 公開プロキシは濡れ衣で、上流はずっと 400 を返していた

株価を共有の `js/proxy-fetch.js` へ寄せる作業の途中で、**Yahoo 自身が 400 を返していた**ことが分かった:

```
Number of symbols needs to be less than or equal to 20
```

`js/companies.js` は **`const B=40`** で束ねていた（実測: 20 は 200・24 は 400）。つまり
**バッチの株価取得は 1 回も成功しておらず**、毎回 1 銘柄ずつの chart フォールバック（約 150 リクエスト）に
落ちていた。#R353 が「ライブ株価の最初の数手は必ず失敗する」と書いてプロキシのせいにしていたものの
実体はこれで、**プロキシは上流が既に拒否した要求を運んでいただけ**だった。
⇒ `SPARK_MAX_SYMBOLS=20`（**由来・失効条件・正本を上流の文言そのもので**書いた）。同じ数を
`quotes-relay` も持つので、`tests/r533-checks ⑧` が両者の一致を測る。

### 変更

- **新 Edge Function `quotes-relay`（15 本目）** — Yahoo の keyless `v8/finance/spark` / `chart` を
  サーバ側で取って ACAO を付けて返す。`_shared/relay-guard.js` の締切・バイト上限・content-type・
  総称エラー。**2 エンドポイントとそのパラメータの allow-list** で、通るのはティッカーだけ。
  ⚠ **最初の版は spark を 502 にしていた**——`{"spark":{"result":…}}` を期待したが、query1 は今
  **平たい `{TK:{symbol,close,…}}`** を返す（`js/companies.js` は元から両方読める）。
  **呼び出し元より狭い受理は、良い答えを障害に変える。**
- **`js/companies.js` の私有ラダーを撤去**し `HOST.fetchViaProxy(u,{as:'json'})` へ。`direct` は
  **意図的に付けない**（Yahoo は ACAO を返さないので成功し得ず、#R464 の実測どおり CORS 拒否は
  往復ぶん待たされる＝ロゴと同じ「失敗が確定した段」）。
- **`js/proxy-fetch.js` の自前 relay 判定を表にした。** `news.google.com` 1 件の regex だったものが、
  2 つ目の呼び出し元を「特例」にするのではなく `OWN_RELAYS` になった。
  ⚠ **2 人目の利用者は特例ではなく、1 人目も特例ではなかったという証拠である。**
- 出典・利用規約・プライバシー（9 言語）を実態へ。Clearbit の名前は消え、Wikidata（選定）／
  Wikimedia Commons（配信）／Google favicon（フォールバック）の役割の違いと、
  **Commons はビルド時解決なので閲覧時に「誰を見ているか」が漏れない**ことを書いた。

### 門（⚠ 綴りではなく「答えるか」を訊く）

- `tests/prod-smoke.spec.js` に 2 本。1 本目は **配信された JS から第三者ホストを発見して**、
  1 つずつ名前解決と応答を確かめる（⚠ **ホスト名を試験に書かない**——書いた一覧は来週足される
  ホストについて何も言わない。#R529）。2 本目は配信された `index.json` が Commons のロゴを
  実際に積んでいることと、その 1 枚が**この origin から**200 で読めることを測る。
- `tests/r533-checks.test.mjs` 9 本。`allowed()` は**読まずに評価**する（#R505）。
- ⚠ **`tests/r147.spec.js #3` は綴りを固定していたので、1 段目を消した瞬間に無意味になっていた**
  （`step0clearbit` が構造上 0 になり、緑のまま何も測らない＝#R488 の形）。#R147 が本当に買った
  不変量——**解決済みの行は再描画で `<img>` を出し直さない**——に書き換えた。

**残っている問題**: Commons にロゴが無い 98 社（533 中）は Google favicon かモノグラムのまま。
`t*.gstatic.com` の 404 はその正常な通過点であって、消すには上流（Wikidata）にロゴが増えるのを待つか、
別の出典を足す判断が要る。
