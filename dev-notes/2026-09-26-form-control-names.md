## 何が起きていたか（本番実測、2026-09-26）

- **1280 px・レイヤー 9 個**で、DOM のフォーム部品 932 個のうち **87 個に accessible name が無かった**
  （range 49・select 27・date 8・color / file / time 各 1）。代表はレイヤーの不透明度スライダで、隣に
  「Opacity」と書いてあっても部品と結ばれていなかった。
- **375×812** で、凡例カード（例: Live cameras）の左上を地図切替の `#bm-square`（canvas）が、右端を
  `#m-fab-tools` / `#m-fab-stack` が覆っていた（`elementFromPoint` で確認）。

## ローカルでの再現と前後の数

新しい spec（`tests/form-control-names.spec.js`）を、変更前の木（`HEAD` を `git archive` して build）と
変更後の木の両方に当てた。

| | 変更前 | 変更後 |
|---|---|---|
| ① 各レイヤー系統を1枚ずつ点けた DOM の部品（308〜309 個）のうち名前の無いもの | **51** | **0** |
| ② 375×812 で凡例 3 枚を開き、四隅と中心を `elementFromPoint` で訊いたとき他の物に覆われていた点 | **8**（`#bm-square` の canvas に 5 点・他の凡例に 3 点） | **0** |

全レイヤー（174 個）を点けた探索では、変更前は 450 個中 202 個が無名だった（その状態は検査には使わない
——下の「検査の設計」）。

## 名前: 何が原因で、どう直したか

**原因は1種類**——部品を作る関数が、自分が知っている意味（隣の語・レイヤー名）を部品に渡していなかった。
Atlas の命名掃引（`js/atlas-controls.js` `_uiNameSweep()`）が後から拾う部品もあったが、掃引は
`atlas-controls` が読み込まれて 3.5 秒後から 20 秒おきに走る補助で、読み込み前・掃引の間・掃引が知らない
クラスの部品は名前が無いままだった。**直したのは作る側**で、掃引には触っていない。

- 隣に語があるもの: 語と部品を結ぶ。`<label for>`（設定の 17 行・衛星パネル・ケッペンの期間・モデルの
  時刻と単位）、語と部品を `<label style="display:contents">` で包む（凡例の不透明度行 3 か所・等高線の
  細かさ・NATO / EU / 歴史国境の年・フィルタ・カタログ・土地被覆 / 年降水量 / 世界銀行の年・期間・人口年・
  業界）——`display:contents` なので行の flex 配置は変わらない。
- 包む `<label>` の中に `‹` ボタンがある行（日付欄）では `<label>` がボタンを名指すので、
  `aria-labelledby` で語を参照する（GIBS の日付・`_dateBoxHTML`）。
- 語が画面に無いもの: 作る側が知っている意味から名付ける。レイヤー行の不透明度スライダと日付欄は、
  自分の語（翻訳キー付き `aria-label`、`data-i18n-aria`）と行のレイヤー名 `#lyrname-<id>` を
  `aria-labelledby` の自己参照で**参照**する——言語が変わると画面の文字と同じ経路で名前が変わる。
  レーダーの時刻・潮汐の日時・選挙・信号・並べ替え・フィルタ条件・ファイル選択も同じ。
- Chronos は語を持つ要素（時刻の基準・タブ）を `aria-labelledby` で指し、スライダは**今のタブ**を名前に
  する（`applyMode` が付け替える）。

新しい文字列は en + jp だけ（憲法 §7）。既存の英語キーと日本語が食い違う組（`Opacity`→「透明度」、
`Signal` / `Signal source`）は衝突監査が落としたので、既存の訳に合わせるか別の語にした。

## 重なり: 何が原因で、どう直したか

原因は2つあった。

1. **置き場が地図の上の部品を知らなかった。** 携帯の凡例は `top:64px; left:6px` に固定で、幅の上限
   `calc(100vw - 20px)` は内容だけを縛っていた（padding と枠の 22 px ぶん画面の右端を越えた）。地名検索の丸・
   地図切替・丸ボタン列は、それぞれ `max(12px, safe-area + 4px)` を写した別々の数で置かれていた。
   ⇒ 携帯ブロックの `:root` に部品の寸法（`--m-edge` `--m-fab` `--m-bm` `--m-chrome-top` `--m-bm-top`）を
   1 か所にまとめ、4 つの部品はそれを読む。凡例の置き場 `--m-legend-top`（左の列の下端＋8 px）と
   `--m-legend-right`（右の列の幅＋8 px）は**そこから導出**する。特定のカードの座標は1つも書いていない。
2. **積み上げが効いていなかった。** 携帯の CSS が凡例の `top` / `left` を `!important` にしていたので、
   `tileLegends()` が書いた位置（64 / 118 / 172 px）は全部上書きされ、3 枚が同じ場所に重なっていた。
   ⇒ `!important` を外し、`tileLegends()` の携帯の起点と右端を上の 2 トークンから読む（`@property` で長さ
   として登録してあるので、解決済みの px が1回のスタイル読み出しで返る。CSS の無い偽 DOM では従来の
   64 px）。さらに、ケッペンの凡例は `flex` で表示されるため積み上げの母集合（`display==='block'`）から
   漏れ、他の凡例が同じ起点から積まれてその上に乗っていた——携帯では同じ置き場の一員として数える
   （デスクトップの全高の置き場は変えない）。

## 検査の設計

- ① の母集合は DOM から発見し、名前の一覧は書かない。点けるレイヤーも**Layers 欄から発見**し、チェック
  ボックス id の系統（`dl-` `dl-ec-` `bx-` `gx-` `wp-dl-` `fac-dl-` `beta-dl-` …＝作るモジュール）ごとに
  最初の1枚を点ける。⚠ 全 174 枚を同時に点ける形は実測で捨てた——ページの主スレッドが塞がり、2 worker の
  実行では検査自身の `evaluate` が 240 秒返らなかった。25 枚ずつ点けて消す形も、累積で同じになった。
- 名前は、**描画されている部品はブラウザの accessibility tree（CDP `Accessibility.getFullAXTree`）**に
  訊く。描画されていない部品（閉じたパネル）は tree から外れて名前が無いので、accname の手順
  （`aria-labelledby` → `aria-label` → `<label>` → `title` → `placeholder`）を当て、**その規則が描画
  されている部品すべてでブラウザと一致すること**も同じ検査で測る。⚠ Playwright の
  `toHaveAccessibleName` は `placeholder` を名前として数えず Chromium と食い違ったので、判定には使って
  いない。
- ② は角丸の半径だけ内側に入った四隅と中心を訊く（角丸の外は最初からカードではない）。
- 所要は ① と ② で直列 25 秒。

## 開いたときにだけ作られるツールのパネル

レイヤーの凡例と同じ流儀（部品を作る場所で名付ける）で、ツールのパネルも直した。

- **③ の母集合は実体から発見する。** アプリの中でツールの一覧を述べている場所は2つある——Layers の
  Tools 欄（`.lst-toolbody`：`js/map-ui.js` のツール登録表から作られる行と、各モジュールが自分のボタンを
  足す実物の `#layer-tools`）と、携帯の tools sheet（`#tools-sheet [data-proxy]`：地図ツールバーの実ボタンの
  名簿）。見えている入口を全部集めると **23 個**（経路・写真の撮影地点・シミュレーター 9 種・比較・相関・
  地図データの読み込み・Data & analysis・Playground・プリセット保存・グリッド・計測・描画・3D 体積・半径・
  スクリーンショット）。1 つずつ押し、部品の数が落ち着くのを待って DOM の全部品を読み、閉じてから次へ行く。
- **前後**: 変更前 **17 個**が無名（地震 2・パンデミック 1・ドローン 3・Data & analysis 3・描画 1・3D 体積 2・
  半径 5）、変更後 **0**。
- 生成元: 地震の事例一覧と速度（`js/seismic.js`）・パンデミックの設定スライダを作る 1 つの helper
  （`js/playground.js`、語とスライダを `<label>` で包む）・ドローン（`js/drone-nav.js`）・Data & analysis
  （`js/gis-panel.js`：処理の選択・入力の選択・`paramControl` の全型・条件行・表のセル編集・列の道具・
  塗り分け・書き出し形式・バンド・標本の格子）・描画の解像度（`js/map-tools.js`）・3D 体積と半径
  （`js/tool-panel.js`）。
- ③ の入口から一度では開かない物も、同じ規則で生成元を直した: 新規監視（`js/monitors.js`：既にあった
  `<label>` に `for`）・フライトシムの開始地点（`js/flight-sim.js`）・夜空の日時と速度（`js/night-sky.js`）・
  Atlas の放射性物質カードの核種と放出量（`js/atlas-console.js`）。津波の 2 つの select は最初から
  `<label>` の中にあり、名前を持っていた。
- ③ は直列 57 秒（spec 全体で 80 秒、`tests/durations.json`）。

## 残っていること

- 監視・フライトシム・夜空・Atlas の放射性物質カードは、Tools の入口を1回押しただけでは開かない
  （2 段目の操作やログイン・Atlas の回答が要る）ので、③ の母集合には入っていない。生成元は直した。
- 関連 spec の同時実行で `tests/r384.spec.js`（ケーブル凡例の注記）・`tests/r466.spec.js`（モデル一覧の
  読み込み時刻）・`tests/r186.spec.js` が落ちたが、前 2 本は**変更前の build でも同じ組み合わせで同じく
  落ち**、3 本とも単独では緑だった。
