## R529 — **手で書かれた一覧を守るために、番人が3つ積み上がっていた**

外部調査「IntMap：軽微な修正でコードが増え続ける問題の調査報告」の**優先1**だけを実装した回。
依頼は「テスト実行対象の手動一覧と、それを維持する周辺の仕組みに対象を限定する」で、
**総行数の削減は目的にしていない**。

### 何がそこにあったか

`package.json` の `scripts["test:checks"]` は **292 本のパスを手で名指しする 7,893 バイトの 1 行**だった。
そしてその一覧の上に、番人が 3 つ積み上がっていた。**3 つとも、実際に起きた事故から書かれている**:

| ラウンド | 何を見つけたか |
|---|---|
| #R301 | 一覧から漏れたファイルは**走らない**＝弱い検査ではなく検査ではない。`tests/r210` と `tests/r211` は書かれてから一度も実行されておらず、走らせたら r211 の 12 本中 5 本が赤（最古は 90 ラウンド前の #R212 で壊れていた） |
| #R385 | 一覧を**一覧自身と**照合していなかった。`new Set(listed)` が最初の 1 手だったので多重度が消え、`tests/r356-checks.test.mjs` が 22 ラウンド二重に走り続けた |
| #R390 | 「テストか」を**名前**だけで決めていたので、規約より古い `tests/security-logic.mjs`（31 本・#R138）は要求の外にあり、3 ラウンド走らないまま**リポジトリの全ゲートが緑**だった |

⚠ **どれも本物の発見で、どれも「そもそも存在しなくてよかった一覧」についての発見だった。**
`node --test` は自分でテストファイルを見つけられる。

### 置き換えと、その前に測ったこと

```
test:checks = node --test "tests/**/*.test.mjs"
```

⚠ **撤去の前に、発見される集合が旧一覧と同じであることを実測した**（報告書が「一度だけ明示的に比較する」と
指定した工程）。改名を反映したうえで **292 = 292・どちらの向きにも差分ゼロ**。
比較表そのものは恒久的な台帳にしていない——この 1 行が記録である。

### ⚠⚠⚠ Node 20 と Node 24 で `node --test` の引数解釈が非互換だった

| | ディレクトリ引数 | glob |
|---|---|---|
| Node 20 | **再帰探索する**（公式ドキュメントの記述） | 非対応 |
| Node 24.18.0（実測） | **モジュールとして解決を試みて `MODULE_NOT_FOUND`** | 対応 |

`.nvmrc` は `24`、CI の 8 か所は `node-version-file: .nvmrc` を読む。しかし `engines` は `">=20"` で、
**この呼び出しが動かないバージョンを許す宣言**になっていた。`.nvmrc` に合わせて `">=24"` にし、
`docs/TESTING.md` の「Node.js ≥ 20」も直した。`tests/r529 ③` が engines と `.nvmrc` の一致と、
下限が glob を持つ版であることを測る（値を書き写さず、両方から読んで比べる）。

### #R390 の半分だけは、一覧が消えても残る

runner が「テストファイルか」を決めるのは**名前**である。だから `tests/` の `.mjs` が `node:test` を
import していても、`*.test.mjs` でなければ **runner からは見えず、一度も走らないまま永久に緑**になる。
これは一覧とは無関係な、発見機構そのものの性質。

- 唯一の例外だった `tests/security-logic.mjs` を **`tests/security-logic.test.mjs` に改名**し、
  命名規則から例外を消した（＝#R390 が必要とした「ソースを読む」特例の**原因**を消した）
- `check:static` が、**一覧ではなくディスク**にこの不変条件を訊く（12 行）。
  合成違反 `tests/zz-probe-not-named.mjs` を置いて赤くなること・外して緑に戻ることを実測

### 残した判断

- **script 名 `test:checks` は変えない。** `tests/r407-checks` と `doc-facts` の `ci-gates` 規則が
  「CI がこのゲートに到達しているか」をこの名前で見ている。名前を変える理由が今回は無い
- **`js/world-packs.js` と `tests/r211-checks.test.mjs` のヘッダにある #R301 の経緯は残した。**
  「一覧から漏れていた」は起きた事実であって、機構が消えても嘘にならない
- **報告書そのものを恒久指示にしていない。** `AGENTS.md` にも `CLAUDE.md` にも 1 行も足していない
  （報告書 §9 の明示要求）

### 検証

`tests/r529-checks.test.mjs`（3 本）。①一覧が戻ってきていないこと（`package.json` の**全** script を走査）、
②**中身が `node:test` を宣言しているファイルは、script が実際に持っているパターンで漏れなく発見される**
（パターンは script から読み出す。⚠ 除外されるべき helper／fixture／corpus が**空でない**ことも測る——
空の母集合に対する部分集合判定は、何も見ずに通る #R521）、③engines と `.nvmrc`。
**3 本とも変異で赤くなることを実測**（①パスを1本戻す ②見えない名前のテストを置く ③下限を 20 に戻す）。
