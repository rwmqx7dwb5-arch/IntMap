## R385 — **一覧が同じ行を2回名指していても、門は22ラウンド緑だった**

依頼はこうだった。「`package.json` の `test:checks` に `tests/r356-checks.test.mjs` が**2回**ある
（`r339` と `r340` の間に1回、末尾近くにもう1回）。並行ラウンドの merge の副産物だろう。片方を消して、
`package.json` が JSON として妥当なままであることと `npm run check:static` が緑であることを確かめて。
ついでに、`scripts/check-test-list.mjs` が**欠落／余分**だけでなく**重複**も弾くべきかを見てほしい
——これを捕まえられなかったので。足すなら、緑になる前に赤くなるところを見せて。」

### 1. 消すものは無かった——そして、誰も直していなかった

着手時の実測（`origin/main` = `dc8a77d`）: `test:checks` のトークン **196件・相異なるもの196件・重複0**。
`tests/r356-checks.test.mjs` は **1回しか**現れない。

在ったのは確かである。`package.json` を触った直近60コミットを1つずつ復元して数えた:

| コミット | ラウンド | 重複 |
|---|---|---|
| `4dd14d1` | R355 | 無し |
| **`bff4c91`** | **R356** | **`tests/r356-checks.test.mjs` ×2** |
| `030ee91` / `6e9daed` / `bc6a33e` / `ed058ca` | R370 / R375 / R376 / R377 | 同上 |
| **`214d433`** | **R379** | **無し** |

⚠⚠⚠ **消えたのは、誰かが見つけたからではない。** `214d433` の `package.json` の diff は
**1行の入れ替え**で、`tests/r379-checks.test.mjs` を足しながら**末尾側の写しを落としている**。
R379 の DEV-NOTES の項にも commit message にも、重複への言及は**一言も無い**。

これは細かい話ではなく、この作業の理由そのものである。あの literal は **197トークンの1行**で、
**毎ラウンド、並行セッションの rebase 衝突解決が書き換える場所**である（#R350 / #R378 /
#R381 / #R384 がいずれも番号の取り直しと同じ1行の衝突を記録している）。
重複は**誰も決めないまま入り、誰も決めないまま出ていった**。
**「もう直っている」は「もう起こらない」ではない。**

したがってこのラウンドは `package.json` の一覧から**1バイトも消していない**。消すものが無い。
足したのは、次に入ったときに止めるものだけである。

### 2. 門が見られなかった理由は、実装の粗ではなく質問の形

`scripts/check-test-list.mjs` (#R301) は一覧と `tests/` を**両方向**で突き合わせる。

- ディスクに在って一覧に無い → 赤（**走らない検査は、弱い検査ではなく検査ではない**）
- 一覧に在ってディスクに無い → 赤（`node --test` はその1本で node の段を丸ごと落とす）

⚠⚠⚠ **そのどちらも、同じ正しいことを2回言う一覧に完全に満たされる。**
しかも見えない理由は構造的で、関数の**最初の一手**が `new Set(listed)` だった——
**多重度は、2つの質問が始まる前に捨てられている。** 22ラウンド緑だったのは見落としではなく、
**訊いていない質問には答えられない**というだけのことである。

同じ形は #R318 / #R323 / #R345 が繰り返し記録している。**「検査が緑」は「対象が正しい」ではなく
「検査した性質が成り立っている」**でしかない。

### 3. 第3の方向——一覧を、自分自身と突き合わせる

`checkTestList()` に `kind:'duplicate'` を足した。ディスクとの照合の**前**に置いてある
（`listedSet` を作った時点で証拠が消えるので、そこより前でなければならない）。

- **1つの繰り返しにつき1件**、余分な写し1つにつき1件ではない。メッセージは**回数を持つ**
  ——ファイル名だけ渡された読み手は、197トークンの1行を自分で数えることになる。
- **`tests/` の全トークンを数える。** `*.test.mjs` に限らない——`tests/security-logic.mjs` は
  `IS_NODE_TEST` に当たらないが、2回書けば2回走るのは同じである。
- `scripts/static-checks.mjs` は返ってきた問題を**すべて** `err()` に流すので、
  新しい `kind` は**それだけで門を落とす**（警告ではない）。

⚠ **重複は正しさの欠陥ではない。** ファイルは走り、2回とも通る。値段は2つある——
毎回の CI がその1本を2度払うことと、**一覧が自分の大きさを偽ること**。
`scripts/doc-facts.mjs` はこの literal のトークンを数えて `docs/TESTING.md` の
「N Node test files」と突き合わせており、**両側が同じ重複を数えていた**ので22ラウンド一致し続け、
文書は1つ多い数を述べていた。**片方がもう片方から導かれている2つの文書の一致は、裏付けではない。**

### 4. 赤くなるところを先に見せた

`tests/r385-checks.test.mjs`（8件・`test:checks` に登録済み）。

| 段 | 実装前 | 実装後 |
|---|---|---|
| ① 実物の一覧に繰り返しが無い | 緑 | 緑 |
| ② 繰り返しを報告する（回数つき） | **赤** | 緑 |
| ③ 3つの写しは「3」と言う1件（余分2件ではない） | **赤** | 緑 |
| ④ 無いところに作らない／3方向を同時に報告する | **赤** | 緑 |
| ⑤ `checkTestListHere()` ——門が実際に通る入口 | **赤** | 緑 |
| ⑥ 返った問題は全部 `err()` になる | 緑 | 緑 |
| ⑦ `docs/TESTING.md` の数は**相異なる**ファイル数 | 緑 | 緑 |
| ⑧ この検査自身が一覧に、ちょうど1回 | **赤** | 緑 |

門そのものも実測した。**歴史上の重複を `package.json` に差し戻すと**
`node scripts/static-checks.mjs` は **exit 1**、
`✗ [node-tests] package.json "test:checks" names tests/r356-checks.test.mjs 2 times — it is
executed 2 times on every run, and the entry count that docs/TESTING.md is checked against is
1 too high`。戻すと **exit 0**。

⑤ は使い捨ての repository（`mkdtemp`）を作って `checkTestListHere()` に渡す。
**同じ repository から写しを1つ消すと黙る**ことも見ている——さもないと ⑤ が測っているのは
「2ファイルの repository について何か文句がある」でしかない（#R386 の「理由のない緑」）。

### 5. やらなかったこと

⚠ **並び順は直していない。** この一覧は元から昇順ではない——`r197` は `r200` の後、
`r370` は `r340` の前、`tests/security-logic.mjs` は途中に在り、`r378` は `r381` の後にある。
頼まれたのは重複であって整列ではなく、197トークンの1行を並べ替えれば
**現に走っている全並行セッションの rebase と衝突する**。**門も昇順を要求しない。**

⚠ **ビルドスタンプは触っていない**（`index.html` は `R388` のまま）。このラウンドは
番号の**隙間**（R385）を取っているので、`tests/r301-checks.test.mjs` ⑦ が要求する
「2つのスタンプは同じラウンドを名指し、それは DEV-NOTES が持つ最新のラウンドである」は
そのまま成り立つ（#R378 の作法）。
