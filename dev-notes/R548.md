## R548 — **「1行」の定義が2つあって、どのファイルでも一致し、1つだけで14行ずれた**

> 利用者報告:
> 「`scripts/i18n-dead-key-codemod.mjs` が `js/locales/ui.zh-hans.js` で crash する。
> `scripts/zh-hans.mjs` を最後の checkout 以降に走らせていると必ず。」
>
> ```
> scripts/i18n-dead-key-codemod.mjs:74
>     const before = lines0[a - 1].slice(0, pr.loc.start.column);
> TypeError: Cannot read properties of undefined (reading 'slice')
> ```
>
> 「`scripts/i18n-apply-inline.mjs` は最後にその生成器を呼ぶので、
> 『新しい鍵を入れてから死んだ鍵を掃く』という通常の順序が **必ず** これに当たる。
> clean checkout からしか動かない。」

### ① 欠陥は「改行が混ざっていること」ではなく、**「1行」の定義が2つあったこと**

codemod はファイル全体の区切りを1つに決めて分割し、その配列を **acorn が数えた行番号で引いていた**。

```js
const nl = src.includes('\r\n') ? '\r\n' : '\n';   /* …ファイル全体についての推測 */
const lines0 = src.split(nl);                       /* 6,272 要素 */
lines0[pr.loc.start.line - 1].slice(…)              /* acorn は 6,286 行を数えていた */
```

**実測（`js/locales/ui.zh-hans.js` を、修正前の生成器が書いたとおりに組み直して計測）**:

| | 値 |
|---|---|
| acorn の行数 | **6,286** |
| `src.split('\r\n').length`（旧規則） | **6,272** |
| `splitLines(src).length`（新規則） | **6,286** |
| ずれの手前で最初に当たる property | 6,273 行目 `"Fine tuning"` |
| 旧規則でそれを引いた結果 | **`TypeError: Cannot read properties of undefined (reading 'slice')`** ＝ 報告と一字一句同じ |

⚠⚠⚠ **crash より悪いのは、ずれの手前にある 6,272 行ぶんの property**である。そこでは
`lines0[a-1]` は **undefined にならず、14 行離れた別の行を返す**。codemod はその行の見た目
（`before.trim()===''` と `after` の形）だけで「この property は1行まるごと消してよいか」を決めるので、
**間違った行を根拠に行を消す**。しかも codemod 自身の安全弁

```js
if (lines1.length !== lines0.length) throw new Error('line count moved — a range spanned a newline');
```

は**両方を同じ壊れた規則で数えている**ので、この状態を通す。

### ② 混在を作っていたのは `.gitattributes` と、2つの文字列の連結

`scripts/zh-hans.mjs` は、**自分のソースにあるテンプレートリテラル**（`HEAD`）を、
**別ファイルから切り出した本文**の前に貼っていた。

```js
return HEAD.split('UI STRINGS').join(job.what)… + body;   /* ← LF のヘッダ + CRLF の本文 */
```

- `.gitattributes` は `*.mjs text eol=lf` を宣言している → `scripts/zh-hans.mjs` は**純 LF**（実測 LF 317 / CRLF 0）→ `HEAD` は LF
- `js/` については何も宣言していない → `core.autocrlf=true` に委ねられる → `js/locales/ui.zh.js` は**純 CRLF**（実測 CRLF 6,281）

**だから出力は「LF 14 行 ＋ CRLF 6,271 行」になる。**
⚠⚠⚠ **Linux では両方 LF なので、CI はこれを一度も見ていない。**
壊れているのは「生成器を走らせた瞬間から、次の checkout までの窓」だけで、しかも
**生成したマシンの上だけ**。`zh-hans.mjs --check` は比較の前に CR を全部落とすので、**そこにも映らない**。

### ③ 直し（2段）

**(1) 分割をパーサに合わせる。** ECMAScript の LineTerminatorSequence は `<LF> <CR> <CR><LF> <LS> <PS>`
で、acorn の `loc.line` はちょうどその集合で進む。**同じ集合で分割すれば、両者は定義上ずれない。**

⚠ **正本は新設しなかった。** 改行コードについてのこのリポジトリの答えは **#R283 が `scripts/eol.mjs`**
に置いてある（`lf` / `readLF` / `sameText`、82 ファイルが import）。そこへ
`splitLines` / `joinLines` / `eolHistogram` / `dominantEol` / `normaliseEol` を足した。
一度 `scripts/source-lines.mjs` として書いたが、**同じ事実に正本が2つある状態**になるので畳んだ。

⚠ **各行は自分の終端子を持って運ばれる**（`{ text, eol }`、`joinLines(splitLines(s)) === s`）。
「全部 LF に正規化する」でも crash は消えるが、それは**2行消すために 6,285 行を打ち直した diff**を
次の読み手に渡すことになる。codemod は読んだファイルを書き戻す道具なので、**触っていない行の句読点を
変えてはならない。**

**(2) 生成器は、自分が足すヘッダだけを本文に合わせて句読する。**

```js
return normaliseEol(head, dominantEol(body)) + body;
```

⚠ **出力全体を正規化しない。** 本文は source のバイトそのもので、この script にそれを打ち直す権限は無い。
実際 `js/locales/pages.zh-hant.js` は**別のツールが残した迷子の lone CR** を1つ持っており、
全体正規化はそれを**自分の diff に取り込んで洗浄**してしまう（1行増える）。
守るべき性質は「**derivation は、source が使っていない終端子を1つも持ち込まない**」——これが
`tests/r548-checks.test.mjs ③` が測っているもの。

⚠ 副次的な確認: 修正後は**生成器の出力がチェックアウトとバイト一致**する
（`node scripts/zh-hans.mjs` を走らせても `git status` が空）。修正前は、走らせるだけで
`ui.zh-hans.js` と `pages.zh-hans.js` の2本が dirty になっていた。

### ④ 1件ではなく形——全数調査して4か所

| file:line | 何をしていたか | 混在で何が起きるか |
|---|---|---|
| `scripts/i18n-dead-key-codemod.mjs` | 検出した区切りで `split` し、`loc.line` で添字 | **crash ＋ 手前の行の silent corruption** |
| `scripts/i18n-append-inline.mjs` | 同じ三項式で、**足す行**の区切りを決める | crash しない。**静かに**間違った終端子を書く（LF のファイルに CRLF が1本でもあれば、新しい行は全部 CRLF） |
| `scripts/i18n-pages-apply.mjs` | LF のヘッダを CRLF の本文に貼る | **混在ファイルを新規に作る**（新言語の `pages.<tag>.js`） |
| `scripts/i18n-pages-audit.mjs --template` | 同上 | 同上 |

全数調査の結果:

- `includes('\r\n') ? … : …` の三項式は、リポジトリ全体で**ちょうど2件**（上の1・2番目）。同等形は0件
- `loc.start.line` / `loc.end.line` は **51 か所**にあるが、**自前 split の配列添字にしているのは1件だけ**。
  残り 50 か所は行番号を報告文字列に埋めるだけ
- ⚠⚠ **`split('\n')` 142 件は直していない——実測で acorn と1行もずれないから。**
  LF で割ると、CRLF のファイルでも行数は acorn と一致する（各行末に `\r` が残るだけ）。
  壊れるのは「**検出した区切りで split する**」形だけで、`split('\n')` はその形ではない。
  末尾アンカー（`$/` / `endsWith`）で行内容を見る 7 件も個別に確認して全部安全

### ⑤ 検査は4本とも**出荷コードを走らせる**（`tests/r548-checks.test.mjs`）

| | 何を測るか | どう測るか |
|---|---|---|
| ① | `splitLines()` が acorn と同じ行数を数える | 合成9種（LF/CRLF/**混在**/lone CR/`\r`+CRLF/LS・PS/終端子なし/空/末尾空行）＋ **`js/locales/` の実ファイル19本**。往復が**バイト一致**することも |
| ② | codemod が混在ファイルで落ちない | `cutDeadRows()` を **import して実行**。死んだ行が消え・生きた行が残り・**ヘッダは LF のまま・本文は CRLF のまま** |
| ③ | 生成器が source に無い終端子を持ち込まない | `build()` を **import して実行**（CRLF の合成 source を temp に書いて渡す） |
| ④ | `i18n-append-inline` が多数派で句読する | 実スクリプトを **コマンドとして実行**（temp のロケールに対して） |

⚠ ①②③ は **旧規則が同じ入力で失敗すること**も同時に主張する。そうでないと
「検査が通った」が「検査がもう区別できない」を意味しうる。

⚠⚠ **変異試験を実測**——4つの欠陥を1つずつ戻し、毎回**それを名指す検査が赤**になることを確認:

| 戻した欠陥 | 赤になった検査 |
|---|---|
| `splitLines` を LF だけで割る | ① ② ③ |
| codemod がファイル全体の区切りを1つ決める | ② |
| ヘッダを本文にそのまま貼る | ③ |
| `includes('\r\n')` で足す行を句読する | ④ |

⚠ `scripts/i18n-dead-key-codemod.mjs` と `scripts/zh-hans.mjs` は、検査から `import` できるように
**コマンド部分を `IS_MAIN` の内側へ移した**（前者は import しただけで corpus 全体を audit し、
後者は import しただけで生成物2本を書き直していた）。`tests/r335-checks.test.mjs` の
「zh-hans は import してはならない」という注記は、その理由の片方が消えたので更新した。

### ⑥ 今回直していない、実測した1件（**報告のみ**）

`js/locales/pages.*.js` **9本すべてが、迷子の lone CR を1つずつ持っている**（`",\r\r\n"` の形）。

- これがあるために **git はこの9本を binary (`-text`) として扱う**ので、`core.autocrlf` の正規化を
  受けず、**CRLF が index にそのまま入っている**（他のロケールは index では LF）
- 結果として **acorn はこれらを `split('\n')` より1行多く数える**——今回直した crash とまったく同じ形。
  現時点でこの9本を acorn の行番号で添字している箇所は**無い**ので実害は出ていない
- 出所は `i18n-pages-apply` / `i18n-pages-audit` の書き戻し（`split('\n')` した行を `'\r\n'` で
  結合すると `",\r" + "\r\n"` になる）と整合するが、どのラウンドで入ったかは特定できなかった

直すと **9本が binary→text に変わって index が LF へ正規化される**＝ 5,400 行ぶんの diff になり、
`check:perf` / `check:assets` の予算（余白がほぼ無い）にも触れる。**今回の依頼の範囲外**なので、
別ラウンドとして提案する。
