## R779 — 送信はできても、回答に到達していなかった（#R773 の 2 つ目の退行）

〈production verification。#R777 で `ReferenceError` は消え、利用者の吹き出しも出るようになったが、
**Atlas の返事の位置に例外の文字列が出ていた**〉

```
atl-b u :: 東京はどこ？
atl-b a :: Cannot read properties of null (reading 'concat')
```

`VFRAMES.urls()` は **フレームが 1 枚も無いとき null を返す**（`js/atlas-view-capture.js`）。
これは省略ではなく契約で、`js/ai-core.js` は「画像が無い」と「空の画像一覧を送る」を別の道として
扱う。#R773 はそこに `.concat(_atlRecallImgs)` を足した——**`inspect` を一度も通っていない普通の
初回送信**は毎回 `null.concat` で死に、`ai-proxy` への POST は 1 本も出なかった。添付の有無に依らない。

### ⚠⚠ #R777 の spec は緑のままこれを通した

あの spec が測ったのは「送信が run() に到達し、吹き出しを作ること」。**未ログインのターンは
モデル呼び出しの手前で返る**ので、壊れていた 1 行は一度も評価されていない。
⇒ 「送信が吹き出しを作る」と「ターンがモデル呼び出しまで組み上がる」は**別の主張**だった。

### 直しと検査

呼び手に `_atlTurnImgs(frames, recalled)` を置き、**空なら null のまま**返す。
`tests/r779-atlas-turn-images-checks.test.mjs` は 2 つを別々に測る:
① **契約そのもの** — `makeViewCapture` を実際に作って `urls()` が空のとき null を返すこと
② **受け止め** — 呼び手の式を**ソースから取り出して走らせる**（綴りを読むのではなく評価する）
③ `VFRAMES.urls().concat` がどこにも無いこと
⚠ 壊した状態で赤・直した状態で緑を実測した。
⚠ **契約は関数の隣（`urls()` の直上）に書いた**——呼び手の側にだけ書いた注意書きは、
次の呼び手には届かない。
