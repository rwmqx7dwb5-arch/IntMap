## R279 — **統合分析の回答が、毎回「自分は統合分析です」と名乗ってから始まっていた**

> 「いちいち Atlas の回答に、「🧭 統合分析」ってつけなくていいです」

`analyze`（統合分析）の返答は、組み立ての**一番最初の行**でこう始まっていた。

```js
let html='<div style="font-weight:600;margin:2px 0 5px;">🧭 '+L('Integrated analysis','統合分析',…)+'</div>';
html+='<div style="font-size:14px;line-height:1.68;">'+mdMini(String(txt).trim())+'</div>';
```

条件は無い。**統合分析の回答は、例外なく全部この見出しから始まっていた**——そして中身は
どの回答でも同じ3語だった。読み手はその見出しを読む前から、自分が Atlas に統合分析を
頼んだことを知っている。**返答そのものが統合分析なのに、それを言い直す1行**が毎回
先頭にあった、というのがこの指摘の内容で、そのとおりだった。

見出しを削った。本文（`mdMini` が描くモデルの散文）が回答の先頭になる。出典カード・
地図への地点反映・暫定評価の注記など、その後ろにあるものは**一切変えていない**。

### 消したのはこの1つだけ

同じファイルには、同じ形の見出しが他にもある——カスタム評価レイヤー（🧮）、関連指標（🔗）、
複数地点の最短順路。**それらは別の機能の見出しで、指摘の対象ではない**ので触っていない。
`tests/r279 ④` がその3つを名指しで検査する＝**削除が広がったらここが赤くなる**。

### 検査が自分のコメントに当たる（14回目）

この修正を説明するソースコメントは、**削除した見出しの語をそのまま引用している**。
生のファイルを `'統合分析'` で探す検査を書けば、直した理由を書いた文そのものに当たって
落ちる。`tests/r279` は `js/atlas-console.js` から**コメントを剥がしてから**読む。

さらに `tests/r279 ①` は、**古い形を持った架空のソース**を組み立てて同じ判定関数に
かけ、そちらでは「翻訳された見出しで始まっている」と判定されることを先に確かめる。
緑が「見て、無かった」であって「何も見ていない」ではないことの証明
（#R274 ③ と同じ作り）。

### 判定は文字列ではなく「形」

検査が見るのは `let html=` と本文の描画呼び出しの**間に何があるか**であって、
`font-size:14px` という具体的な値ではない。div の見た目を将来変えても、
見出しを足し直したときだけ赤くなる。

### 残したもの

`ui.fr.js` / `ui.ko.js` / `ui.zh.js` / `ui.zh-hans.js` には `"Integrated analysis"` の
訳語が残っている。これらは**未使用の辞書項目**になったが、同じ表には実測 **158 件**の
未使用項目が既にあり（`ui.fr.js` の 3,981 件中）、この1件だけを消して回るのは
今回の指示の範囲ではない。i18n ゲートは未使用項目を欠陥として数えない（数えるのは
逆方向——**宣言されていない鍵**）ので、緑のままである。
