## R273 — **GDACS を消したから「未対応」を描く必要が生まれた／日本は市町村／各国の階級を1つの尺度に押し込まない**

> 「気象警報は、日本では気象庁の塗分けに対応させろ。また、市町村単位で塗り分けろ。まだ対応していない国は、
>   灰色斜線で、発令されていないだけの地域は灰色に。」
> 「警報レイヤー、日本以外でも区分単位、発令単位ごとに色分けしろ。…対応国も増やせ。更新が遅すぎる。
>   リアルタイムにと言っている。ソースは一国一ソース。…GDACSを完全に撤廃しろ。」
> 「一番根本的なのは、今のレイヤーが『警報を理解するUI』ではなく『取得した警報データを全部描画するUI』に
>   なっていること。初期状態では地図を見ただけで **どこで / 何が / どれほど危険か / 情報は新鮮か** の4つが
>   分かるべき。」

十項目の指摘は**同じ欠陥を十の側から見たもの**だった——レイヤーが「読み手が警報地図に訊くこと」ではなく
「取得できたもの」を描いていた。だからこのラウンドは**4つの問いを骨格にして組み直し**、既存の機能は
どれか1つの問いの下に置き直している。

### ⚠⚠⚠ GDACS を撤廃したから、「未対応」を描く義務が生まれた

「GDACSを完全に撤廃しろ。」——撤廃そのものは削除で済む。**問題は、撤廃すると何も見えなくなる国が
出ること**で、それは「警報が出ていない国」と**区別がつかない**。利用者の指摘⑤がまさにそれだった。

→ **国は3状態を持ち、3つの見え方を持つ**。

| 状態 | 見え方 |
|---|---|
| この国のフィードに接続していない | **灰色の斜線**（`fill-pattern`・`wp-alert-hatch`） |
| フィードはあり、いま何も出ていない | **灰色**（気象庁自身の「発表なし」 `#c8c8cb`） |
| 発令中 | その階級の色（発令単位の形で） |

実測、`countryGeo` の **206 か国が斜線**、47 か国が接続済み。タップすると斜線の国は
「IntMap はこの国の警報機関に接続していないため、この地図はこの国について何も述べていません——
『発表されていない』という意味ではありません」と**文章で**言う。

### ⚠⚠⚠ 日本は市町村で塗る — 幾何は気象庁が「1区域1ファイル」でしか配っていない

気象庁は class10（一次細分区域・153）と class20（市町村・1,805）で発令している。#R271 は class10 に
したが、指示は**市町村**。ところが実測:

    …/bosai/common/const/geojson/class10s.json   200 · 153件 · ACAO *
    …/bosai/common/const/geojson/class15s.json   200 · 385件 · ACAO *
    …/bosai/common/const/geojson/class20s.json   **404**

気象庁自身の警報ページは `common/const/geojson/class20s/<コード>.json` を**1区域1ファイル**で読む
（`class20relm.json` が索引）。60秒周期のレイヤーが 1,800 リクエストを撃つわけにはいかない。

→ **国土交通省 国土数値情報（行政区域）N03** を使う。1,897件・629 KB（gzip）で ACAO *、
`N03_007` が **JIS X 0402** のコード。**class20 コードの上5桁がその JIS コード**で、実測 1,805 のうち
**1,774 が直接一致**。残る31は さいたま市・千葉市・横浜市北部/南部 … ＝**政令指定都市**で、`PP100` に
対して区は `PP101…PP199` なので**区の合併**が市になる。⚠ **合併に使った区のコードを返させる**こと——
返さないと、その区が「発表なし」の灰色として**後から**同じソースに積まれ、いま塗った警報の**上に**描かれる。

実測 **1,479 / 1,490 配置**、灰色の市町村 416。class10 は fallback として残り、パネルはどちらが
画面に出ているかを `jmaUnit` から言う。

### ⚠⚠⚠ 「単位で描く」か「国を薄く塗る」かは排他 — 4回目の「発令されてない箇所が塗られている」

#R271 は薄塗りの意味を「**位置を特定できなかった区域**」に狭めた。正しい狭め方だったが、
**描画済みの国にも重ねていた**。市町村にした瞬間これが見えた——実測、日本は 1,490 のうち **11** しか
置けなかった区域が無いのに、その 11 のために**日本全土**が着色された。

→ **`washTier` は `!drawnISO[c]` を要求する。** 1つでも単位が描けた国は薄塗りしない。
置けなかった数は `placedLine()` が**言葉で**印字し、その国のタップも同じ数を出す。

### ⚠⚠⚠ 各国の階級を1つの3色に押し込むのは、危険な主張

> 「JMA、NWS、MeteoAlarm、CMAなどは警報制度そのものが違います。『赤だからフランスと日本で同程度の危険』と
>   読めてしまいます。共通3段階へ正規化するなら、IntMap独自換算であることを明示する必要があります。」
> →（訊いた答え）「塗りの色を、各国の公式配色に忠実に塗るモードと、IntMap換算の世界共通塗りモードを
>   切り替えられるように。」

**既定は各機関の公式配色**。値は選ばずに**読み出した**——気象庁のページの stylesheet が持つ
`.contents-level20 #f2e700` / `-level30 #ff2800` / `-level40 #aa00aa` / `-level50 #0c000c` /
`.contents-missing #c8c8cb`。中国は気象局の四色予警信号、その他は CAP の黄/橙/赤（MeteoAlarm・DWD・
MET Norway・NWS・ECCC・INMET・BoM・PAGASA・HKO・CWA が**実際にそれで出している**）。

**IntMap換算**は別モードで、**どの機関の配色とも1色も共有しない**4段階。パネルが
「各機関の階級を IntMap が独自にこの4段階へ換算したものです。同じ段でも国どうしの危険度が等しいという
意味ではありません——制度そのものが違います」と書く。

⚠ 地物は `colA`（公式）と `colN`（換算）を**両方**持つので、切替は**再取得ではなく `setPaint` 1回**。

### ⚠⚠⚠ severity しか描いていない警報地図は、情報が足りない

> 「赤いフランスを見ても、暴風・大雨・洪水・高温・雷・雪 のどれなのか分かりません。」
> →「警報種別は、その区間に文字で表示。（小さい場合はイニシャル表記など。）」

区域は**災害名そのもの**を持ち、同じ区域に複数出ていれば `+N`（最高階級1色が捨てていた情報）。

⚠ **`text-field` に `['step',['zoom'],['get','hzs'],5,['get','hz']]` は書けない。**
MapLibre が style 時に `this.expression.evaluate is not a function` を投げ、**ページごと落ちた**（実測）。
`minzoom`/`maxzoom` は式ではなくレイヤーの属性なので、**同じ規則を書き間違えられない場所に書く**
——z5 未満のレイヤーが短縮形、以上のレイヤーが正式名。

⚠ **頭字語は短縮形ではない。** 最初の実装は先頭文字を採り、実測でイタリアとギリシャの上に
`MTW+4` `GHT+6` が並んだ——読み手に鍵の無い符号。**階級を言う語を落として災害の語を残す**
（`Moderate thunderstorm warning` → `Thunderstorm`。階級は色がもう言っている）。

### ⚠⚠ 31.1h と 2min が同じ緑だった

#R269 は「到達可能」と「まだ動いている」を分けた。利用者は**その次の段**を指した——INMET の 31.1h と
PAGASA の 0 min が同じ緑。→ **Fresh（≤6h）/ Delayed（≤48h）/ Stale / Error** の4段階。
⚠ これは**フィードについての語**であって危険度ではない。発表するものが無い機関は「静か」であって
「故障」ではない、とパネルが自分で書く。

### ⚠⚠ パネルが「どのAPIから何件取ったか」を説明していた

→ 先頭は **「いま発表されている警報」**：国×災害でまとめ、〈色・国・災害・階級・区域数〉で並べる。
**取得先の一覧は畳んで**「ソースの状態」に、置けなかった区域の診断はさらにその下へ。
数字は**全ソースで「区域数」に統一**（従来は 111 発令区域 / 5,070 件 / 81 か国 と単位がばらばらで、
5,070 だけが異常に大きく見えていた）。出典の注記は**一文**（従来は18か国を名指しする段落）。

### ⚠⚠ 「透明度選択をつけろ」に専用ボタンを作ったのは間違いだった

> 「いや透明度選択、元の共通のスライダーをなんで変えどんねん。余計なボタン作るな。」

このアプリの凡例は**全部** `_registerLayerOpacity` の共通スライダーを持っている。必要だったのは
**この層の既定値を宣言する**ことだけ（`plates` が 0.30、`worldcover` が 1 を宣言しているのと同じ場所）。
→ 追加した段組みコントロールと `_setLayerOpacityById` は撤去し、`opacities['wpalerts']=0.38` だけ残した。
「色が濃すぎて地図を殺している」への答えは、**濃さの既定**と、塗りを透かしても残る**輪郭線と文字**。

### ⚠⚠ U+2715 はこのアプリのどのフォントも持っていない

> 「複数のポップアップで、×の形がおかしくなっている。改悪をするな。元に戻せ。」
> 「なにか形がおかしい×をやめろと言っている。明らかに×の形が変な感じ。」

実測、`measureText` 16px:

    U+2715   Inter 13.07 · Noto Sans JP 13.07 · system-ui 13.07 · sans-serif 13.07 · Arial 13.07
    U+00D7   Inter 10.59 · Noto Sans JP 16.00 · system-ui 10.95 · sans-serif 16.00 · Arial  9.34

**全ファミリで同一の送り幅は、どのファミリも持っていない証拠**——全部が記号フォントに落ち、
アプリの他のどの字とも違う太さ・大きさ・ベースラインで、OS ごとに別の形になる。そして
**アプリは両方を使っていた**：U+2715 が **46ファイル 177箇所**、U+00D7 の button が十数個。
#R270 が検索欄2つだけ SVG に替えたのは、その混在の直近の形だった。

→ **U+00D7 ひとつ**に統一（`window.IntMapClearGlyph()` が1つの定義）。tests/r273 ⑨ が js/ と css/ の
全ファイルを掃く。⚠ **この注記は2つの符号位置を「名前で」書いている**——文字で書くとその掃除機が
自分のコメントに当たる（**12回目**の形）。

### 追記 — 本番検証で１件: 不透明度スライダーは「答え」の方も薄くしていた

本番に出してからレイヤーをオンにして測ったところ、`wp-alert-line` の `line-opacity` が **0.38**。

このラウンドの設計は「**面はもっと薄くして、重大度は境界線やパターンでも表現した方がいい**」という指摘への
答えとして、**階級を輪郭線に持たせていた**。ところが `_applyGenericOpacity` はチェックボックスが宣言した層を
**種類を問わず**暗くする（fill なら `fill-opacity`、line なら `line-opacity`）ので、**面を透かしたときに残るはずの
ものが一緒に薄くなっていた**。文字は `_opacityOpaqueText` で守っていたのに、線にはその仕組みがないことを見落としていた。

→ **スライダーに渡すのは `wp-alert-fill` と国の2層だけ**。輪郭線と災害名は自分の不透明度を保つ
（#R205 が「名前は薄塗りの一部ではない」とプレート名について書いたのと同じ規則）。

⚠ **その注記を `makePanel('wp-alert-panel', …)` の引数の中に書いたら tests/r212 ② が落ちた。**
あの検査は `makePanel\('…'` から **560文字の窓**で呼び出しを拾い、「五つのファミリーが全部行 id を渡しているか」を
見ているので、引数の中の長いコメントが**閉じ括弧を窓の外へ押し出す**と、そのファミリーが**存在しないことになる**。
実測、`found 4`。**注記は呼び出しの外へ**（パターンを賢くするのではなく入力を変える——#R267 の `codeOnly()` と同じ答え）。
