## R292 — **ウィジェット基盤の全面改修——そして計測して最初に出てきたのは「既定のボードは5枚ではなく1枚だった」**

「IntMapのウィジェット機能を、Appleのウィジェットと比較して判明した不足点をすべて反映し、単なる
『Apple風カード一覧』ではなく、IntMapの地理・時間・災害・ニュース・データ機能を短時間で把握・操作できる、
本格的なウィジェット基盤へ作り直してください。」（27節の仕様）

### ⚠⚠⚠ 着手前の計測で、直す前から壊れていたものが出た

指示どおり**変更前に実測**した。ウィジェットの保存を消して起動すると：

```
window.IntMapWidgets2._active()      →  ["clock"]
localStorage.intmap_widgets_def21    →  null
localStorage.intmap_widgets3         →  null
```

既定のボードは**自分のソースにも `Architecture.md` にもそれを作ったラウンドの記録にも**
「Clock · FX · Featured layer · Random country · On this day」と書いてある。実際に出ていたのは
**1枚**で、**何も保存されず**、**毎回同じ失敗を繰り返していた**。

原因は4行の中にあった。種まきのループが `DEF_FX` を読み、その `const` は**同じクロージャの196行下**に
宣言されていた——`'fx'` の反復で **TDZ の `ReferenceError`**。そして `try{ … }catch(_){}` が
**その throw と一緒に、次の2行（フラグの `setItem` と `save()`）も飲んだ**。

⚠ **catch が飲むのは throw だけではない。throw のあとの文も飲む。** 計器は全部緑だった——
例外はコンソールに出ず、ボードは「時計1枚が既定」に見え、誰も5枚を数えていなかった。

**構造的な答え**：既定の設定値を**関数**（`defaultConfig(context)`）にした。カードが作られる瞬間に
評価されるので、**ファイルのどこに書いたかに依存できない**。`tests/r292 ⑱` が
「`DEF_*` 表は、それを読む `defaultConfig` より前に宣言されている」ことを行位置で検査する。

### ⚠⚠⚠ 同じ問いを何度も聞いていた——測ってから直した

変更前、4枚（map-weather ×2・crypto・crypto-cap）を置いて **8秒**観測：

```
api.coingecko.com/api/v3/simple/price   ×7
api.coingecko.com/api/v3/global         ×7
api.open-meteo.com/v1/forecast          ×2   （同じ座標に2回）
```

原因は2つあり、掛け算になる。`render()` が **`refreshAll()` で終わっていた**ので、
言語イベント・設定を開く・追加・削除・再表示——**再描画のたびに全カードを再取得**していた。
そして**仕事の単位がカードだった**ので、同じ問いを持つ2枚は互いを知らない。

→ **仕事の単位を `requestKey` にした**。実測、天気カード3枚（S/M/L・うち1枚は `weather.here`）で
**キーは1つ・要求は1回**。⚠ 座標は**2桁に丸めて鍵にする**（≈1.1 km、モデルより細かい）——
生の float なら「同じ町の現在地と地図中心」が別の鍵になる。
そして**描画と取得は別の行為**になったので、再描画は1件も要求を出さない。

### ⚠⚠ 検証中に、この基盤自身の欠陥が2つ出た（どちらも「静かに何もしない」形）

1. **最初の描画がDOMに入る前に走り、捨てられていた。** `buildCard()` が購読すると、
   スケジューラもティッカーも**手持ちを即座に返す**——が、その瞬間カードはまだ親に append されて
   おらず、`paint()` の `isConnected` ガードが正しく落とす。**その1回きりの塗りを捨てたあと、
   データが永久に来ないカード（非表示のボード・オフライン・ホストが塞がれている）は
   空の箱のまま**だった。スケルトンでも状態の文でもなく、**何も無い**。
   → `render()` が**append のあとに**全カードを塗る。
2. **非表示のボードがティッカーの購読を持ち続けていた。** タブを開くとボードは隠れるが、
   カードは購読したままで、**誰も見ていない時計のために 1 Hz のタイマーが回り続けていた**。
   ⚠ **「隠れていたら早期 return」を2か所に足しても、タイマーは回ったままになる。**
   → 隠すときに**解放する**（`LAY.release()`）。「非表示のボードは何もしない」が
   コールバック側の心がけではなく**構成上の事実**になる。実測 購読 0・タイマー停止。

### 主な設計判断

- **S / M / L は論理サイズで、情報そのものが変わる。** `tests/r292 ⑦` が定義ごとに3つの
  レンダラ本文を**文字列として比較**し、同じものを渡していたら落ちる（＝CSS だけの差を禁じる）。
  実測 天気カードは S/M/L で本文の要素数 **8 / 40 / 96**。
  列数は**ウィンドウではなく盤面の実測幅**から（`ResizeObserver`）——同じセッションで
  サイドバーの1列と Workspace の広い面の両方に正しく答えるため。
  ⚠ `grid-auto-flow:dense` は**使わない**：DOM を動かさずに見た目だけ並べ替えるので、
  キーボードの並べ替えと読み上げ順が視覚順と食い違う。
- **状態は12個あり、全部が理由を文で述べる。** 旧ボードの状態は実質3つで、うち2つは
  **句読点**だった（`···` と `—`）。読み手は「今日は何も無い」「上限に達した」「ホストが落ちている」を
  区別できず、**5分前に答えを持っていたカードもそれを捨てて `—` を出していた**。
  ⚠ **失敗しても前回成功した値は消さない**——値を保つ状態は `WC.keepsValue()` 1か所で定義する。
- **DOM は `WC.el()` だけが作る。** `innerHTML` へ至る経路が**存在しない**ので、外部文字列が
  マークアップになりようがない（`tests/r292 ③`）。URL は**スキームの許可制**。
- **プレビューは実レンダラで描き、通信も権限要求もしない。** プレビュー用の context は
  位置状態を `prompt` に**固定**してあるので、`WC.resolvePoint` が端末の測位を返せない
  ＝「プレビューが許可ダイアログを出さない」が**構成上**の事実になる。実データはキャッシュに
  あるときだけ使い、無ければ**見本と明示して**描く。実測 ギャラリーを開いて外部要求 **0**。
- **Smart Stack は乱数ではない。** `(stack, context)` の純関数で、同じ入力に同じ答えを返す
  （`tests/r292 ⑫` が梯子の順序を実際に**実行して**検査する）。差が小さいときは前面を動かさず
  （`MARGIN` / `SETTLE`）、重大警報だけは即座に前へ出る（`URGENT`）。
- **IntMap 固有の9枚は、既存の subsystem を読むだけ。** そのために足した読み取り専用の口は3つ：
  `IntMapWorld.alertsQuery()`（地図が塗るのと**同じ正規化済みの `feats`**）・
  `IntMapRouting.summary()`（読み手が見ている代替経路から導出）・
  `IntMapWidgetBriefStore.remember()`（Atlas が**渡してくる**側）。
  ⚠ **カードが2つ目の真実を作らない。** 作れば必ず片方が古くなる。
- **Atlas ブリーフィングのカードは AI を呼ばない。** 更新方針は `manual`、ローダ無し
  ——**スケジューラがこのカードを動かす経路が存在しない**（`tests/r292 ⑧`）。
- **CSS が JS から出た。** 旧ボードは ~14 KB のスタイルシートを文字列連結で作って `<head>` に
  足していた。⚠ **テンプレートリテラルの中の CSS は、バッククォート1つでサイトが白紙になる**
  （`CONSTITUTION.md` §2）。今は `css/intmap.css` の1節（`--widget-*` トークン）で、
  `prefers-reduced-motion` / `prefers-reduced-transparency` / `forced-colors` / `pointer:coarse`
  に答える。**通常状態のカードに外側の影は付けない**（内側のガラス縁だけ・#R186/#R188）。

### 移行——1バイトも落とさない

`intmap_widgets3` は**読むだけで、消さない**。それが世代バックアップそのもので、v4 が壊れたときの
復元元になる。移行は**何度実行しても同じ結果**になるよう、インスタンス ID を旧 `u` から取り、
`createdAt` を**位置から**導く（`Date.now()` を使わない）。実測、7件の v3 から
順序・`u`・FX の base/quote（2インスタンス別々に）・Countdown の title/date・World clock の tz・
Holiday の cc がすべて保存され、知らない型 1 件だけが落ちた。2回目の移行は**バイト単位で同一**。

⚠ **既定のボードは「何も保存されていないボード」にだけ種をまく。** 旧コードのフラグは
「**既存の利用者にも新しい既定を出す**」意図だったが、そのフラグは一度も立ったことがない
（上の TDZ のため）ので、**その読み方で通った利用者は1人もいない**。今それを復活させると、
自分で整えたボードに5枚が降ってくる——頼まれていない変更（`CLAUDE.md` §3.2）。

### 言語

新しい英語文字列 **454 件**。de / ru / es は位置引数で、fr / ko / zh / zh-hans は
`inline` 表への追記（`scripts/i18n-append-inline.mjs`・zh-hans は `scripts/zh-hans.mjs` が生成）。
⚠ **「英語と同じ」を24件出した**ので1件ずつ読み直した——`Chronos` と `ISO 8601` は**固有名**なので
`L(…)` から外し（表に入れれば規格名を翻訳できてしまう）、`Digital`/`Analog`/`Ring`/`Coins`/`Neutral`/
`Decimal` は**実際に違う語がある**ので直し、`Format`/`analog`/`lunar`/`Winter`/`metal`/`aurora`/
`monitor`/`24 h`/`Hexadecimal` は**その言語で本当に同じ語**なので、根拠を書いて
`scripts/i18n-positional-audit.mjs` の `SAME_AS_EN` に足した。
