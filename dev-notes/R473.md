## R473 — **「既存機能は絶対に削らない」を、利用者が「確認を取れば削ってよい」に変えた**

利用者の方針転換。コードの不具合ではないので、直したものは無い——**規程そのものを書き換えた回**である。

### 1. 何が変わったか

指示は3文だった。

> 既存機能の削減的再編、削除、に関する制限を緩和してください。必要と判断すれば、私に確認をとれば、
> 削除や縮小も積極的に行ってよい。特に Atlas は AI であるため、加算による問題の複雑化には注意するように。
> ……ただし、これまで通り、勝手に削除や縮小をすることのないように。
> ……実装は削ってよい。Atlas の到達可能な能力・回答品質は削るな。

つまり**3つの状態がある**——「勝手に削る」は今までどおり禁止、「提案して確認を得て削る」は
**新しく許可**、「必要なのに提案しない」は**もはや安全側ではない**。旧規程は3つ目を美徳として
書いていた（`CONSTITUTION.md` §0 の 3「削除・縮小を絶対に行わない」／迷ったら消さない）。

**確認の時期**も規則にした。作業を提案のために止めると、1つの依頼が何往復にもなる（`CLAUDE.md`
§3 の 8 が禁じている形）。⇒ **今回の依頼と不可分なとき**——削らなければ依頼が正しく直らないとき
——だけその場で訊き、それ以外は**依頼を完遂してから**最終報告の中で提案する。

⚠ **手順の側にも同じ段を置いた**——ラウンドの手順書（`/intmap-round` の §8 最終報告）に、
「作業中に気づいた削減候補は、依頼を止めずに完遂してから、この報告の中で提案する」を足した。
#R403 の教訓がそのまま効く: **セッションが実際に読むのは手順書のほう**で、標準指示だけを直すと
その段は一度も実行されない。

**名指しで「消さない」と書いてあった個別項目**（Cesium・ニュースの決定論フォールバック・停止中の
記事経路・撤去済み Area Monitors の基盤・`DEV-NOTES` の不削除）も、利用者の指示で**手続きの対象に
含めた**。各項目に書かれた理由は消していない——**提案のときに検討する材料**として、そのまま残る。

### 2. Atlas だけが別扱いである理由と、その境界

Atlas は「機能の集まり」ではなく**1つの判断者**なので、他の機能と同じ扱いにできない。

- **足す側の危険**: 症状1つに機構を1つ足す積み重ねが、Atlas では**そのまま回答品質の劣化**になる。
  互いに矛盾する門が増え、どれが効いたのか誰にも言えなくなる（`DECISIONS.md` が既に持っている
  「68 か所の意味判定は、どれも実在の不具合への対処として足され、**互いに矛盾しながら蓄積した**」）。
- **削る側の危険**: 実装を削ると、削ったつもりのない**能力**が消える。カタログに無い操作は
  プランナーにとって存在しないので、**消えたことは沈黙として現れる**（#R397 の形）。

⇒ 境界を利用者の言葉どおりに引いた——**実装は削ってよい。到達可能な能力と回答品質は削らない。**
統合（重複した機構・二重の正本・到達しない分岐を1本にする）は歓迎で、**能力を1本も減らさずに
行う**。減るならそれは統合ではなく機能削減であり、§0 の 3 の確認が要る。能力の集合を数えるのは
`npm run check:capabilities` と `npm run check:catalog`——**主張ではなく門がある**。

### 3. 3か所に書いてあるので、門を足した

方針は3つの文書に、3つの声で書いてある——`CONSTITUTION.md`（何を守るか）・`CLAUDE.md`（どう働くか）・
`PRODUCT.md`（§2.1 守ること）。⚠ **この形は、この repository が最もよく壊してきた形である**
（#R403 の gate-lists、#R399 の本数、`backup-shell` の launcher——どれも「1つを直して2つを忘れた」）。

そして**ここでは両方の古さが事故になる**:

| 片方だけが古いと | セッションはこう振る舞う |
|---|---|
| 旧い禁止だけを読む | いま望まれている削減を**提案せずに**終わる |
| 許可だけを読み、確認の段が落ちている | **訊かずに消す**（取り返しがつかない） |

⇒ `scripts/doc-facts.mjs` に `shrink-policy` を足した（`npm run check:docs`・`npm test` に内包）。
**検査するのは文言ではなく形**である——各文書が「既存機能」を語る **700 字の窓**の中に、
①削除・縮小の語 ②確認・承認という条件 ③勝手にやらないという禁止 が揃っているか。
Atlas の但し書きは**正本を1つに決めた**（`CONSTITUTION.md` §5）ので、他の2文書には
**その名前が窓の中にあること**だけを要求する（同じ文を3枚に写せば、いつか片方だけが古くなる）。

⚠ **否定の needle は1つも使っていない。** この規則が「退役した言い回しを探す」形だったら、
それを説明する `docs/TESTING.md` の行自身が引っかかる（同じ自己捕獲がこの repository で
13 回起きている）。**在るべきものを数える形**なら、説明はいくらでも書ける。

`tests/r473-checks.test.mjs`（6本）は、**壊して赤を見る**:

- ② 3文書それぞれから「確認・承認」を窓の中だけ消す → 赤（許可だけが残った文書を作らない）
- ③ 「勝手・承認の無い・承認されるまで」を消す → 赤（**ブレーキの無い許可は許可証**）
- ④ `CONSTITUTION.md` から「一体」／「到達（可能な能力）」を消す → 赤
- ⑤ 他の2文書から正本の名前を消す → 赤
- ⑥ 錨（`既存機能`）ごと綴りを変える → **赤**。⚠ **文が消えたせいで緑**は #R385 の形で、
  この検査自身が最も陥りやすい失敗である

⚠ 変異は**窓の中だけ**に効かせている。ファイル全体から「確認」を消すような変異は、通っても
何も証明しない（規則が読んでいるのはその窓だから）。

### 4. 変えていないもの

- **アプリのコードは1行も変えていない。** 変えたのは方針・文書・門だけ。
- **「勝手にやらない」は1文字も緩めていない。** 緩めたのは「提案してよいか」であって
  「実行してよいか」ではない。
- **Atlas の全権（`CONSTITUTION.md` §5）**——制限を増やす方向・例外を増やす方向へ持っていっては
  ならない、はそのまま。今回足した一体条項は**その下に並ぶ**（削ってよいのは実装であって、
  Atlas に許される範囲ではない）。
- **個別項目に書かれた理由**（Cesium を残す理由・決定論フォールバックを残す理由…）は残してある。
  対象になったのは「提案できないこと」であって、「理由」ではない。
