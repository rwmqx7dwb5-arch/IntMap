## R571 — **5 回の正しい書き込みが、1 回の正しい書き込みより悪かった**

> #R567（世界遺産レイヤー）の production verification で実測。

### 症状

本番で言語を **2 回目**に切り替えると、UI は追従するのに**地図に描かれた世界遺産の名前が
前の言語のまま**残る。ja → en → ja と往復すると、UI は日本語なのにラベルは英語のまま。

### 全部正しかった。最後の 1 手だけが届いていなかった

| 見たもの | 値 |
|---|---|
| `__imWhsLayer.locale()` | 新しい言語 |
| `__imWhsLayer.fc()` の feature 名 | 新しい言語 |
| style の `sources["whs-src"].data` | 新しい言語 |
| `queryRenderedFeatures` / `querySourceFeatures` | **古い言語** |

66 秒のポーリングでも、`triggerRepaint()` でも、別大陸へ飛んで戻ってタイルを作り直させても変わらない。
**同じデータで手動 `getSource("whs-src").setData(__imWhsLayer.fc())` を 1 回**呼ぶと 4 秒で切り替わった。

つまり**ペイロードは一度も間違っていない**。間違っていたのは**回数**だった——`setData` を包んで数えると、
言語変更 1 回につき **`setSourceData` が同じ tick に 5 回**呼ばれていた:

1. `intmap-lang` のリスナが FeatureCollection を組み直して書く
2. 行ラベルの relabel が style を動かし、`styledata` が発火する
3. 基図の自己修復が `whsEnsure()` → 書く
4. その自己修復が `whsLoad()` を呼ぶ（#R567 でエンジン切替に耐えるよう足した）
5. `whsLoad()` の早期 return がまた書く

MapLibre の geojson worker はこの連射を越えられず、持っていたタイルを持ち続ける。

### ⚠⚠⚠ 直しは「呼ぶ回数を減らす」ではない

5 か所のどれかを黙らせるのは間違いである——**4 つの経路はどれも source を更新したいと言う資格があり**、
どれか 1 つを消せば、その経路だけが更新されない層に戻る（#R567 の自己修復はまさにそれを直したもの）。
**どの経路も知らないのは「同じ tick に他の誰かが同じことを頼むかどうか」だけ**である。

したがって全員が `whsPush()` に頼み、**書くのはそこだけ**にした:

- **1 tick 分の依頼を 1 回の書き込みにまとめる**（`Promise.resolve().then(…)` で 1 回だけ予約する）
- **直前に書いたのと同じ collection なら書かない**。`whsBuild()` は毎回**新しい object** を作るので、
  同一性で訊けば「本物の作り直し」と「同じものの再依頼」が正しく分かれる
- ⚠ **`addSource` は書いた記憶を捨てる。** 新しい source はこのモジュールが書いたものを 1 つも
  持っていないので、忘れないと**基図切替の初回の書き込みが飛ばされて層が空になる**

### 検査は綴りではなく構造を測る（4 本・全部変異で赤を確認）

| | 測っているもの | 変異 |
|---|---|---|
| ① | `whs-src` に書く場所は **1 か所か**（acorn で数える） | 2 か所目を戻す → 赤 |
| ② | その書き込みは**コールバックの中か**（＝ 1 tick が 1 回になるか） | 遅延を外す → 赤 |
| ③ | **同一性で repeat を弾いて、書いたものを記録するか** | ガードを外す → 赤 |
| ④ | `addSource` の手前で**記憶を捨てるか** | 1 行消す → 赤 |

⚠ ソースは `codeOnly()` を通してから読む——この直しの説明が、消した呼び出しを綴っているので、
生の grep は**説明のほうに「はい」と答える**（`docs/TESTING.md` の 9 件目）。
