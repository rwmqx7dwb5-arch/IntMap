## R432 — **状態のはしごは、この地図が描けない火山を名指していた**（イエローストーンが火山レイヤーに1点も無かった）

**依頼**: `tests/r353-live.spec.js` の «R353-live ① status ladder» が deep tier で決定論的に落ちている
（`joined.unplaced === 0` のはずが **6**）。その 6 座は何か、どちらが正しいか（カタログを補うのか、
地物を持たない座を索引に入れないのか）、spec の settle ループに `usgsMon` が要るか。

### 再現と切り分け

`IM_TIER=deep npx playwright test tests/r353-live.spec.js` で **2 passed / 1 failed**、`unplaced: 6`。
⚠ **`IM_TIER=deep` が要る**——素の `npx playwright test` は `testIgnore` に食われて「0 tests」で緑に見える。

上流 5 本を node から直接叩いて切り分け（**全部 HTTP 200・非空**＝上流不調ではない）:

| エンドポイント | HTTP | 行数 |
|---|---|---:|
| `hans-public/api/volcano/getElevatedVolcanoes` | 200 | 5 |
| `hans-public/api/volcano/getMonitoredVolcanoes` | 200 | 70 |
| `hans-public/api/notice/getVonasWithinLastYear` | 200 | 92 |
| `jma.go.jp/bosai/volcano/data/warning.json` | 200 | 14 |

### 6 鍵の正体——2 種類あり、依頼が想定した「5 座」に**入っていない 6 件目**があった

`getMonitoredVolcanoes` の 70 行のうち **7 行**が同梱カタログに地物を持たず、うち 2 行が
`vnum: null` で 1 鍵に潰れるので **6 鍵**になる。

| 鍵 | 中身 | GVP は持っているか |
|---|---|---|
| **0** | «Alaskan Volcanoes» (AVO) と «Cascade Range» (CVO)、どちらも `vnum: null` | **火山ではない**——観測所全体の速報。`+null` が 0 になっていた |
| 311370 | Isanotski Peaks | **更新世カタログにある** |
| 311161 | Korovin (AVO ak171) | **どちらのカタログにも無い**——GVP 311160 «Atka Volcanic Complex» の北側の火口 |
| 323180 | Coso Volcanic Field | **更新世カタログにある** |
| 323822 | Long Valley | **更新世カタログにある** |
| 325010 | **Yellowstone** | **更新世カタログにある** |

GVP の WFS を両方（完新世 1,214・更新世 1,452）取って照合した結果である。
Korovin は更新世にも無く、GVP 311160 の `Geological_Summary` が名前を書いている。
AVO の速報本文の座標 52°22′54″N 174°09′55″W は **311160 の点から 5.9 km**。

### 症状は「テストが赤い」ではない

`js/beta-overlays.js` の `volcApplyStatus` は、ランクを **`volcFC` の地物に書き込んでから**
`setSourceData` する（paint 式は関数を呼べないので #R353 からこの形）。**地物が無ければ書き込む先が無い**
——USGS が毎日公表している 5 座のレベルを、この地図は**毎セッション取得してから捨てていた**。
イエローストーンは専用の観測所（YVO）を持つのに、**火山レイヤーに1点も出ていなかった。**

### 直した方向——除外ではなく、カタログを補う

`CONSTITUTION.md` §5 が「報告された不具合を条件文・除外リストで塞ぐな」と言う。
ここでの正しい向きは明白で、**観測機関が現在の警戒レベルを公表している火山は火山地図に出るべきもの**である。

1. **同梱カタログ = GVP 完新世の全件 ＋ 観測機関が語っている座のうち完新世一覧に無いもの。**
   `scripts/build-volcanoes.mjs` が `getMonitoredVolcanoes` をビルド時に読み、完新世に無い番号を
   `Smithsonian_VOTW_Pleistocene_Volcanoes` から引いて足す。**手で並べた一覧は無い。**
   GVP がどちらにも持たない番号が出たら `throw` してビルドを止める。
2. **`vnum` を持たない行は鍵を作らない。** `usgsVnum(r)` が非数値・非正を `null` にし、
   `statusIndex` / `usgsFor` / `usgsMonitors` が全部これを通る。
3. **`USGS_TO_GVP = { 311161: 311160 }`。** `JMA_TO_GVP` と同じ形の結合表。
   ⚠ **ビルドはこの表を `js/volcano-intel.js` から読み出す**——2 つ目の写しを持たせない。
4. **1 つの GVP 番号に複数の USGS 行が落ちたら、いちばん重い行が答え**（同着なら新しいほう）。
   AVO は Atka を 2 単位（ak17 / ak171）で監視しているので、先に来た行を返す実装のままだと
   **GREEN の複合火山の陰に ORANGE の火口が隠れうる**——寄せることで初めて生まれる欠陥を同時に閉じた。

**再ビルドの差分は追加分だけ**だった: 既存 1,214 件は **1 件も変わらず**、`built` と新しい
`holocene` キーと 4 件の追加のみ。詳細ファイルの語彙も `epoch` が
`["Holocene"]` → `["Holocene","Pleistocene"]` だけ。層 303,079→304,130 B、詳細 551,330→552,386 B。

⚠ **更新世の feature type は完新世の 19 項目のうち 9 項目しか出さない**（最終噴火年・主要岩石・
構造区分・収録根拠・写真が無く、噴火一覧も人口レイヤーも完新世限定）。**無い項目は推測せず null**。
そのぶんカードの文言が 1 つ嘘になっていた——「日付のある噴火が1件も無い」ときの注記が
**「完新世カタログには別の証拠にもとづいて収録されています」と言い切っていた**ので、
地質時代で分岐させ、更新世の座には「完新世に入ってからの噴火の記録が無く、観測機関がレベルを
公表しているのでこの地図にいる」と言わせた（9 言語）。

### 名前から事実を外した（#R353 と同じ理由）

- レイヤー見出し `Volcanoes (GVP Holocene)` → `Volcanoes (Smithsonian GVP)`
- レイヤー一覧の行 `Volcanoes — full Holocene catalog` → `Volcanoes — the Smithsonian GVP catalog`
- Atlas の「見つからない」応答 `…is in the Holocene catalog.` → `…is in the Smithsonian GVP catalog this map carries.`
- 凡例の出典行は **`features.length` と `holocene` を両方ファイルから読んで**構成を述べる
  （`{h} Holocene volcanoes + {m} older ones an observatory watches`。プレースホルダー1本・#R355）

#R353 は「全1,215座」を行の見出しから外した。**名前に書いた事実は自分を検査できない**というのは
件数だけの話ではなく、**「完新世」という語も同じ**だった。

### 点を1つ足すと、別の答えが誤りになりうる

USGS のハザード域サービスが出す 7 区域のうち **「Long Valley Volcanic Region」** は、
#R353 が **Mono-Inyo Craters (323120)** に結んでいた——`js/volcano-layers.js` の注記いわく
「その完新世項目は GVP では Mono-Inyo Craters である」。**GVP 自身の Long Valley (323822) が
このカタログに無かったから**である。

それが入った以上、区域を片方の点だけに結んだままにすると、**もう片方のカードが
「機械可読なハザード域は公表されていない」と述べる**——USGS が**まさにその名前で**公表している
区域について。ポリゴンはカルデラと Mono-Inyo の連なりの両方を覆っているので、
`HAZ_TO_GVP` の値を **番号の配列** にして両方に結んだ。**既存の結びは1つも外していない**
（加算的な変更）。`tests/r353-checks ⑤` の突き合わせも配列を展開して全部の番号を検査する。
### 262 バイトで天井を越えた——`atlas-console` の余白は 8 バイトしか残っていなかった

CI の `Static checks` が `check:perf` で落ちた: `async chunk "atlas-console" grew:`
`826.8 kB > ceiling 822.4 kB`。**実測して切り分けた**——このチャンクに入る私のファイルは 2 本
（`js/atlas-catalog-text.js` の SYS 本文と `js/atlas-controls.js` の「見つからない」応答）だけで、
その 2 本だけを `origin/main` の版に戻してビルドし直すと **846,334 B**、戻さないと **846,596 B**。

| | バイト |
|---|---:|
| 記録されていた天井 | 842,131 |
| 許容線（×1.005） | 846,342 |
| `origin/main` だけ | **846,334**（許容線まで **8 バイト**） |

⚠ **越えさせたのは私の 262 バイトだが、余白を使い切っていたのは main のほうだった。**

「1,214 of them」「in the Holocene catalog」という偽になった記述を直すために伸びた**もので、
天井のために短くすると元の欠陥に戻る。`atlas-console` は**遅延チャンク**（起動費用ではない）なので、
`tests/perf-baseline.json` の `async.chunks["atlas-console"]` を実測値 846,596 に上げた。
⚠ **`--update` は使っていない**——それは EAGER の +4.2 kB（main 由来・このラウンドで誰も説明していない）
まで一緒に記録してしまう。**上げたのは測った 1 行だけ。**
### 検査（`tests/r432-checks.test.mjs`・7 本）

① 同梱ファイルが構成を持ち、層の `holocene` と詳細の `epoch` が一致する（**片方をもう片方から導出**）／
② 足された座は実在の GVP 記録で、供給源の無い項目が**全部 null**（推測が無い）／
③・③b **`node:vm` で js/volcano-intel.js を起動**し、`fetch` に USGS 実測の行形（`vnum: null` 2 行・
Korovin・Atka・Yellowstone）を食わせて `statusIndex()` に訊く。**綴り検査では `+null` という
型強制は見えない**／④ ビルドがフィードから導出し、対応表を 1 つしか持たず、置けない番号で止まる／
⑤ 上記の settle ループ／⑥ 出荷文字列がもうカタログを「完新世」と呼ばず、カードが地質時代で分岐する。

**5 通りの変異で全部赤**を実測（`usgsVnum` の `null` 番兵を外す→③③b、最重要行の選択を先頭行に戻す→③b、
spec のループを 4 本に戻す→⑤、`holocene` キーを消す→①、足した座に最終噴火年を捏造→②）。
