## R499 — **同じ形が、あと5か所あった。そして本当に重かったのは、失敗した取得が「取得した」に数えられていなかったこと**

依頼は前回（#R498）の診断レポートを添えた「コード変更も含め、根本的・構造的に徹底的に解決して」だった。
レポートが名指した残件は正しかった。**そして、レポートが「断定できない」と書いていた警報レイヤーの中に、
はるかに大きなものが1つあった。**

### 0. まず計器に「誰が訊いたか」を言わせた（`--attribute`）

#R498 が足した `rect/move` は仕事をしていた——9.59 → 7.47。だが**残りの 7.47 が誰のものかは、
MapLibre のソースを読んで判断していた**。ラッパは呼び出しを数えるが呼び出し元を数えない。
そしてこの枝では `pan-alerts-city` が **rect/move 901.63** を出していて、その 901 が誰のものかは
どんな読み方でも分からない。

`scripts/mobile-trace.mjs --attribute` は、touch 相のあいだ `getBoundingClientRect` /
`getComputedStyle` の**呼び出しごとにページ側のスタックを3フレーム**取り、多い順に印字する。
⚠ **既定は off で、off のままでなければならない**——`new Error().stack` は測っている呼び出しより
はるかに高いので、`--attribute` 実行の `lat` / `busy` / `fps` は**計器自身の数字**である。
移せるのは**回数だけ**で、印字にそう書いてある。

⚠ **最初の版は全件を計器自身に帰属させた。** スキップ規則を「`__imSite` や `getBoundingClientRect`
という語を含む行」にしたが、スタックの最初の行はその矢印関数 `site` 自身で、どちらの語も含まない。
6,674 件すべてが 1 か所と報告された。**規則は「名前の一覧」ではなく「URL を持つか」**——ラッパの
フレームは注入された `<anonymous>` に居て URL を持たず、アプリのフレームは必ず持つ。

実測（Chromium・390×844・DPR 3・CPU 等倍）:

| 相 | rect/move | 内訳 |
|---|---|---|
| `pan-touch` | 7.47 | **252/254 が MapLibre の `DOM.getScale`**（`touchPos` → `getBoundingClientRect` ＋ `offsetWidth/Height`）／IntMap 由来は **1** |
| `pinch-touch` | 7.83 | 280/282 が同じ MapLibre の1行／IntMap 由来は **1** |
| `pan-alerts-city` | 365〜902 | **6,090 / 6,224 が `js/data-layers.js` の `tileLegends()` の1行**、そこへ `panel.open()` から2経路（`_registerLayerOpacity` の末尾と `panel.open` 自身の `_tileLegends()`）で**各 3,045 回** |

⇒ **#R498 の修正は保っている**（アプリが指の経路で DOM に訊く回数は 1）。**残りはレンダラのもの**で、
`getBoundingClientRect` はレイアウトが汚れていなければ安い——だから直すべきは「自分の書き込み」だった。
そして `pan-alerts-city` の 98 % は入力経路の話ですらなく、**凡例の置き場所を決める関数**だった。

### 1. 指の座標を地図の座標に直す場所が、5つとも自分で測っていた

どれも同じ形である。

```
const r = canvas.getBoundingClientRect();          // ← ポインタイベントごとに
unproject([touch.clientX - r.left, touch.clientY - r.top]);
```

- `js/wheel-zoom.js` の**感度ピンチ**（`touchmove` ごとに矩形 ＋ `camera.easeTo`。120 Hz の
  デジタイザなら**表示 1 フレームにつきカメラ更新2回**で片方は捨てる。`passive:false` なので
  ブラウザ自身のスクロール判断もそのぶん待つ）
- `js/map-tools.js` の `touchLL`（作図ストロークの touch イベントごと）
- `js/volume3d.js` の `_ll` と `onMove`/`onTouchMove`（**1 移動につき同じ要素を2回**）
- `js/tool-panel.js` の `place()`（指ではなく**カメラのフレームごと**。しかも
  「読む → `getComputedStyle` → `maxHeight` を書く → **メニュー自身を測る**（＝いま強制した）→
  `left`/`top` を書く」という #R498 のクロスヘアと同じサンドイッチ）
- `js/map-tooltip.js` の `positionTooltip`（#R311 が**地図の**大きさをポインタ経路から外し、
  **ツールチップ自身の** `offsetWidth`/`offsetHeight` を残した。呼び出し側 37 か所が同じ行で
  `el.style.display='block'` を無条件に書くので、その読みは全部**強制**同期レイアウトだった）

⚠ **答えは「各所が気を付けてキャッシュする」ではない。** #R498 が測ったとおり、**任意の最適化は
採用されない**——`setMapTooltipHTML` は 11 ラウンド在って 8 ファイル中 1 つしか使っていなかった。
だからキャッシュは **`js/runtime.js` の第5の登録簿 `box(el)`** に置いた。フレームループの隣、
「1フレームでレイアウトは1回だけ標本化する」ためだけに在るファイルの中である。

無効化するもの: 要素自身の ResizeObserver ／ `resize` `orientationchange` `scroll` ／
visualViewport の同2つ ／ **そして `pointerdown` と `touchstart`**。
⚠ **最後の1つがこれを「用心深い」から「厳密」に変える**——ジェスチャは down 無しに始まらないので、
**1ストロークは必ず1回の実測から始まり、その間ずっと使い回される**。#R498 が長押しについて手で
書いた規則を、全員に対して機械が守る。測るのは無効化のあと**最初に訊かれたとき1回**なので、
誰も訊かないリサイズは 0 円。

ピンチは加えて**フレームに合流**する（`touchmove` は目標ズームと中点を控えるだけ、`easeTo` は
`RT.frame()` が1フレームに1回）。⚠ **`touchend` で控えが残っていれば必ず流す**ので、描かれなかった
フレームの値でジェスチャが終わることはない。⚠ この経路は**感度が既定でないときだけ**動く——
だから 11 ラウンド生き残った（既定ではレンダラ自身のピンチが引き受ける）。

ツールチップの表示は 1 か所が決める（`window.showMapTooltip` / `hideMapTooltip`、8ファイル・37か所を
変換）。大きさは **markup が変わったときだけ**測り直す（`setMapTooltipHTML` が知っている）。
⚠ 書き込みの番人は**覚えた写しではなくインライン宣言そのもの**と比べる——`el.style.left` を読むのは
CSSOM の読みでレイアウトを要求しないし、写しは他所が同じ箱に書いた瞬間に嘘になる。

### 2. 細いポインタを「も」持っている携帯が、デスクトップの予算を取っていた

`_imPhoneClass()` は `(pointer:coarse) && !(any-pointer:fine)` だった。第2項はタッチ対応の
**ノート PC** を外すために書かれているが、それは第1項が既に外している（主ポインタがマウスだから）。
実際に外れていたのは **細いポインタも持っている携帯**——S Pen を抜いた Galaxy、Bluetooth マウスを
繋いだ端末。**それらは携帯の GPU のままデスクトップの予算**（フル DPR・MSAA・canvas 8192²・
@2x タイル＝1枚あたり4倍の画素・毎フレームのマーカー遮蔽・DEM キャッシュ 560）**を払っていた。**

述語は3項になった。3項目は `Math.min(screen.width, screen.height) <= 500`——**幅ではなく端末の画面、
その短いほう**なので向きで答えが変わらない（#R232 が選んだ形）。⚠ **追加しかしない**: 既に true の
端末を false にすることはできない（タブレットも Surface も従来どおり）。

### 3. ⚠⚠⚠ 失敗した取得が「取得した」に数えられていなかった

`--attribute` が名指した 3,045 × 2 回の `tileLegends()` は `panel.open()` から来ていた。
**8秒の指1回のパンで、警報パネルが 3,045 回描き直されていた。**誰もそれを頼んでいない。

両方の輪番（MeteoAlarm と WMO SWIC）は**成功した読み取りだけが書く時計**で順番を決める。
それは #R277 が意図して書いたことで、理由も書いてある——
「`maAt` は読み取りが**完了したとき**だけ書く。パネルが出す**データの古さ**だからで、
楽観的に書けば停滞が隠れる」。**`maAt` については正しい。**
見落とされていたのは、**同じ時計が「もう一度訊く時か」にも答えていた**ことと、
一度も答えたことのない国には**時計が無い**ことである（`maNext` の絞り込みは `!maAt[k]` で通り、
`cold`（`!maData[k]`）は年齢で絞られてすらいない）。

だから取得が**失敗**すると——リレーの障害、429、トンネルの中の携帯——何も動かず、
そのバッチ自身の終了処理が `pumpMA()` をもう一度呼ぶ。次の呼び出しは**同じ国**を返し、同じように
失敗し、**輪はマイクロタスクの速さで回り続ける**。しかも `.catch` はどれも `showPanel()` で終わる
ので、1周ごとに**パネル全体の再描画と全凡例の再配置**が付く。携帯ではそれが主スレッドの全部で、
**接続が悪いほど速く回る**。

→ **試行を成功とは別に時刻する。** `maAt` / `swicAt` は意味を1文字も変えない（パネルが出す古さ）。
バッチを**発行した**ときに書く第2の時計が「もう訊く時か」に答え、失敗が続くあいだ後退する
（2 s → 6 s → 20 s → 60 s）。答えた瞬間に後退は消える。
障害の費用は「国あたり・後退の段あたり 1 回」になり、イベントループが詰め込める限りではなくなった。

同じ答えの後半として、`panel.open()` は **同じ本文・同じレイヤー id・同じ名前なら、不透明度の再登録と `tileLegends()` を飛ばす**（#R311 がツールチップに置いた番人と同じもの）。`hide()` と、閉じられたパネルの `claim()` が鍵を捨てる。
⚠⚠ **本文の書き直しは飛ばさない。** 早期 return は厳密に良く見えて**そうではない**——`wireControls` はハンドラを `addEventListener` で付けており、それが一度も漏れなかった唯一の理由は`b.innerHTML=` が毎回ボタンを作り直していたからである。同じノードを返せば、**自動再描画のたびに click リスナーが積み上がる**。飛ばすのは、フレームを食っていた2つの呼び出しだけにする。

### 4. 凡例の並べ方が、置いてから測っていた

`tileLegends()` の3つの枝はどれも1つのループで「置く → 測る」をしていた:

```
el.style.top = …; el.style.bottom='auto'; el.style.left=…; el.style.right='auto';
top += el.getBoundingClientRect().height + 8;      ← 上の4つの書き込みが強制した
```

N 枚で N 回の強制同期レイアウト、そして**この関数は 31 か所から呼ばれる**。
**高さを全部先に読んでから**位置を書けば、1回のレイアウト確定で済む。書き込みは番人付きなので、
**何も変わらない呼び出しは何も書かず**、次の呼び出しの読みも安いままになる。
⚠ **算術は一字も変えていない**——30/64/140 の原点、+10/+8/+10 の間隔、`data-grow-down` の規則、
`gdKey`。高さは同じ高さで、少し早く取っただけである。

### 6. 検査（`tests/r499-checks.test.mjs`・20 本）

⚠ **走らせられるものは全部走らせる**。`js/runtime.js` と `js/wheel-zoom.js` は**モジュールとして
import** し、`js/map-tooltip.js` は vm で実行し、`place()` / `touchLL` / `_box` / `_imPhoneClass` /
`tileLegends` / `maNext` / `pumpMA` は**ソースから切り出して** vm で走らせ、
レイアウトの問いを**数える**偽の DOM に当てる。

⑨ は読みと書きの**順序**を記録して `/^r+w+$/` を要求する——回数ではなく順序だけが、強制レイアウトと
安いレイアウトを区別する。⑩ は**答えない feed** に対して輪番を回し、30 か国が全滅しても
発行されるバッチが **5 本**（＝6 か国 × 5）で止まることを要求する。
⚠⚠ **「データを持っているか」は間違った問いである**——後退を解除する条件に最初そう書いた。
**一度成功した国は、今日の取得が落ちても昨日の答えを持っている**ので、それでは後退が全部消え、
`MIN_AGE_MS` の切れた**暖まった国のぶんだけ同じ輪に戻る**。この読み取りが届いたかを言えるのは
**成功の時計が動いたか**だけなので、バッチ発行時のスナップショットと比べる（⑩ の2本目が測る）。
⚠ **その rig の feed には上限がある**。#R499 以前のソースに当てると輪は止まらないので、
上限が無ければ**テストは落ちるのではなく固まる**——走らせられない反証は反証ではない（#R498）。

⚠ **反証を測った**: 変更前のソースに差し替えて **16 本が赤**（当時 17 本）。緑のまま残った1本は
「感度が既定ならこの経路は動かない」＝**前後どちらでも成り立つべき不変条件**。
