〈依頼〉 発注書 2026-11-27 の「このターンで完了していないもの: マッピングして」（成功したのに出る）と「成功したのに回答を撤回して、成功して、を繰り返す」、
および監査 2 本が再現した 8 件（実行キーの小文字化・子の結果の版違い再利用・Web リンクの取り違え・取り込み件数・依頼変更・未達の消失・実行順・長い資料）。

## 原因（`one-pass-or-a-reason` の 3 分類で）

**① 観測器の誤報**（1・2 の原因）。2 か所あった。

- `js/atlas-goal-verify.js` `recordOf` は **`ok === false` を `status` より先に見て**、`unobserved`（実行したが効果を観測できなかった）と `partial`（一部は置いた）を
  **FAILED と書いて**独立した読み手へ渡していた。読み手は「失敗したから請求は満たされていない」と所見を返し、Atlas は描かれている地図をもう一度描き、また読まれ……
  が繰り返された。最後に所見が残れば「完了していないもの: マッピングして」（`need` は読み手が依頼の言葉で書く）。
- `js/atlas-agent.js` の完了判定 `unmetOf` は `produced` だけを見ていたが、出力の門（`made`）は **`ranBy`（実行したが見えなかった）も「作った」とみなす**。
  門が通した回答を、同じ関数が「地図は未完了」と報告していた（同じ規則の 2 実装が食い違った形）。`ranBy` を引数で受け取り門と同じ規則にした。

**② 結果が届かない**（8・10）。

- 8: 検証が無応答（null）のとき `goalUnmet = list || []` が**確認済みの不足を消していた**。無応答は解消ではない——前回の所見を保持し、解消を観測した読み手だけが消せる。
- 10: `read_step` の範囲読みは `fresh` を数えず、先頭・中間・末尾の 3 回を「すでにある答えを 2 回続けて求めた」とみなして停止していた。**新しい範囲は進展**。
  子への入力は `slice(0, 12000)` で黙って切られていた。版（バイト列のダイジェスト）・件数・列を添えた**マニフェスト**に変え、全体は `input:<task>` で保持し範囲で読める。
  読めない側（サーバーの実行器）には「N 文字しか見せていない・全体と見なすな」と述べる。

**③ 非冪等・同一性**（3・4・5・9）。

- 3: `stable()` が文字列を一律 `norm`（小文字化）していた。**言葉の形をした文字列だけ**畳み、`= ( ) { } / _ …` などを含むものは原文のまま。引数名の一覧ではなく値の形で判定する。
- 4: 子の再開記録は契約キー（入力を ID で指す）だけで照合していた。記録に**実際に受け取った入力のダイジェスト**を持たせ、入力を持つ子は受け取った後に照合する。
  古い記録（ダイジェスト無し）は入力を持つ子を答えない。
- 5: 親の再利用が `open A` を門に届けず、門の「現在のページ」が B のままだった。ref を `l1@<page>` にして**ページ名を ref 自身に載せ**、クリックは名指されたページの状態へ戻ってから行う。
- 9: 取得が task_id 順で、親の適用が逆順になり、**実行前に**適用済みの印を付けていた。`deps` を保ち依存順（終了時刻・名前で同順位を解く）にし、
  印は**観測後**にだけ付ける。先行が効かなければ後続は走らせず理由を返す。

## 取り込み件数（6）

`GeoJSONUpload.handle` の `n` は addFC の**地図レイヤー通し番号**で、これを「行数」として読んでいた。`features`（読んだ件数）・`layer`・`registered` を足し、
GIS 登録が無いときは `not_registered`（描いたが分析用データセットは無い）を失敗として返す。

## 依頼の版（7）——ここまでで、ここから先

ジョブ実行器は、各タスクの開始時の amend 数を **`requestVersion`** として結果に書き（完了 3 経路）、最終報告は依頼変更より前に作られた結果に
「変更前（version v / latest・変更内容）」と印を付ける。**何が引き継げるか（港湾データは共通・名古屋の分析は不要）は判断であり、機械は決めない。**
計画者は印とふれ込みを得た。**影響を受けるタスクだけの再計画（新しい契約の発行）はこの変更では実装していない**（`atlas_job_amend` は新タスクを足せない）。
ページ側の委譲（`makeDelegation`）の依頼変更は未着手。
