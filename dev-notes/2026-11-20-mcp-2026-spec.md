## 2. 決めたこと

- **新旧は訊いて決める**（`ensureInit`）。初回は `server/discover`。結果→新方式、400+`-32022`→挙げられた版次第、400/404/405/-32601/非 JSON→`initialize`。**401・タイムアウト・CORS・リレー失敗は判定に使わない**（誤って「旧サーバ」と決めると、認証の問題が握手の失敗に化ける）。版文字列だけ変える案は、新方式のサーバが旧方式の `initialize` を持たないので動かない。
- **新方式の機能は実装し、読めなかったものは載せない**: 一覧の `ttlMs`、`resultType:'task'` のポーリング（`tasks/get`）と継続・取消、`input_required` の表出と再送、401 の `WWW-Authenticate` の報告、各結果の来歴。`tasks/get` の完了結果は `result` に入る形と想定した（`tasks/result` が廃止されたため）——**schema を読んだら照合する**（tolerant parser で `task` の入れ子も受ける）。
- **MRTR は利用者のもの**: `input_required` はモデルへ「利用者に訊け・代わりに答えるな・秘密を埋めるな」として返し、クライアントは自分では答えない。宣言する elicitation は form のみ。
- **取消は書き込み**: `taskAction:'cancel'` は `mcp.act`（毎回確認）だけ。`get` は `mcp.call` でも通る（読むだけ）。
- **外部ツールの副作用管理**: `effects.jobSafe` ＝利用者が読み取り専用と宣言したものだけ。サーバの `readOnlyHint`/`idempotentHint` は `hint` に出すだけで判断に使わない（利益を受ける側の申告）。
- **取得結果の保存**: 新しい保存庫は作らなかった。結果は従来の `meta.external`（`read_result` が運ぶ）に載り、そこへ `provenance`（server・tool・protocol・fetchedAt・taskId）を足した。localStorage に外部サーバの結果を永続化すると、利用者の私的なサーバの出力が端末に残り、信頼できない文字列を再読み込みで再び運ぶことになるため。
- **ジョブからの呼び出し（#1294）**: #1294 のサーバ側 runner は `worker` 型だけを走らせ、`capability` 型は `kind_unsupported`。しかも MCP サーバの登録は利用者のブラウザの localStorage にあり、Edge から見えない。**だからジョブへの配線は作っていない**（作ると呼び手のない死んだ橋になる）。代わりに、ジョブが将来使う判定（`jobSafe`）と、長い呼び出しを「再開できる形」（task id）で返す性質を整えた。サーバ側登録が出来たとき、`createMcpClient({fetchImpl, storage})` は純粋なファクトリなので Deno でもそのまま使える。
- **サーバ側の公開範囲**: 世界グラフの読み RPC は find/near/subgraph の 3 本が全部で、GIS は既に出ている。足したのは `intmap_capabilities`（tool の宣言から**導く**自己説明。効果と「出していないもの・その理由」）だけ。**書き込み系は足さない**——鍵の持ち主を行為者とする同一性・鍵ごとの scope・人の確認が、この扉にはまだ無い。代わりに全 tool が `_meta["io.intmap/effects"]` を宣言し、無い／`writes` が false でない tool を検査が落とす（書き込みを足す判断が来たとき、検査が先に止める）。`outputSchema`・`destructiveHint:false` も付けた（仕様: `outputSchema` があれば `structuredContent` は適合しなければならない）。
- **Tasks・Apps・elicitation をサーバ側で出さない理由**: 全 tool が 20 秒以内に終わるので Tasks に返す物が無い。Apps は §1 のとおり仕様を読めていない。サーバはクライアントに何も訊かない。
- **未実装として残す**: OAuth 2.1（保護リソースメタデータの検出・PKCE・Client ID Metadata Documents）。サーバの認証は従来の IntMap 鍵のまま。クライアントは 401 の `resource_metadata` を**報告する**だけで、トークンの取得は利用者が行う。`subscriptions/listen`（`listChanged` 通知）。
