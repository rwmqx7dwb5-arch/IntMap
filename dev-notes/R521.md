## R521 — **綴りは身元ではなかった**

**依頼**〈外部監査〉:「高知市が『コーチン』と表示された。**高知だけの個別修正では不十分**で、これは Chronos の
歴史都市名システム全体にある『都市名をIDとして扱っていること』と『重複検査用データが重複を事前に消していること』
の複合バグ。608都市すべてを再監査し、runtime を `name-only` から `name + spatial identity` へ変更し、
validator を ambiguity-preserving source に切り替え、`unproven` と waiver の仕様も強化して、
Kochi / Kirov / Linden を control case にした回帰テストまで足すこと。」

### 何が起きていたか

`js/hist-cities.js` は `ofm-city` の `text-field` を `match` で包み、**タイル自身の名前が記録のキーと一致したら
era 名に差し替える**。それが全部だった。式の中に「どの Kochi か」を言えるものが1つも無いので、
**記録の千を超える綴りと同じ名前を持つ都市は、地球上のどこにあっても射程**だった。

| 記録の行 | 巻き添えになる都市 | 距離 |
|---|---|---|
| `kochi`（ケーララ州・～1996 Cochin） | **高知市**（`name:en=Kochi`） | 6,900 km |
| `kirov-vyatka`（キーロフ州・～1934 Vyatka） | **カルーガ州の Kirov**（39,319人・`place=town`） | 900 km |
| `linden-gy`（ガイアナ・～1969 Mackenzie） | **Linden, New Jersey**（42,021人・`place=town`） | 4,000 km |

### そして、それを止めるはずのゲートは、答えを先に消した file に訊いていた

#R427 の規則そのものは正しい——「2万人以上の別の集落が同じ綴りを持ってはならない」。
間違っていたのは**訊く相手**で、`data/gazetteer-world.json.gz` は `js/newsgeo.js` のために作られている:

```js
rows.sort((a, b) => b.pop - a.pop);
if (seenName.has(key)) return false;          // the more populous homonym already won
```

⚠⚠⚠ **一意性を証明させられていた相手に、一意性が先に課されていた。** 皿の無い秤は必ず 0 を指す。
カルーガ州の Kirov も New Jersey の Linden も、**より人口の多い同名都市に枠を取られて**この file に入っていない。
高知市はさらに二重に不可視で、GeoNames の `name` が `Kōchi`（マクロン付き）である一方、
`alternateNamesV2` の絞り込み 18 言語に**英語が入っていない**（`js/newsgeo.js` が字句解析できる言語だけ、
という正しい理由で）。

### 直し方 — 身元を「綴り」から「綴り＋位置」へ

各行が**ガード半径** `g`（メートル）を持ち、`match` の各分岐が定数ではなく `case` になる:

```
['match', ['coalesce', ['get','name:en'], ''],
   'Kochi', ['case', ['<=', ['distance', {type:'Point', coordinates:[76.2673, 9.9312]}], 20000],
                     'Cochin',
                     ['var', 'imhcLocal']],   ← 半径外は元のラベルへ落ちる
   … , ['var','imhcLocal']]
```

- ⚠ **落ちる先は `let` で1回だけ束ねる。** 分岐ごとに書き下すと base 式がキーの数だけ複製される。
- ⚠ **`distance` は symbol のレイアウト計算（worker）で評価される**——`performSymbolLayout` は
  `evaluationFeature.geometry = loadGeometry(feature)` を入れてから `text-field` を評価するので、
  MapLibre の Distance 式が要求する geometry と canonical tile の両方が揃っている。
  揃わない場合の戻り値は **NaN** で、`['<=', NaN, r]` は false ＝ **壊れ方の向きは「歴史名が出ない」側**。
- ⚠ **半径は書かない。導出する。** `scripts/build-hist-cities.mjs` が、同じ綴りを**自分の名前として**持つ
  最も近い集落までの距離の**半分**（上限 20 km・下限 6 km）を与える。だから
  **自分の同名都市に届く半径を持てる行は構造的に存在しない**。611 行中 600 行が上限、
  5 行が同名の集落に合わせて狭まる（アルマヴィル 4.1・トルクメンバシ 6.7・イーニン 8.5・
  アボヴャン 12.8・ホルビウカ 14.6 km）。⚠ **下限 6 km は「誰も実測していない行が受け取る既定値」**で、
  自分の差を実測した行は `{ measured: { km, on, why } }` を書いて下回れる（後述）。

### 証拠を作り直した

`data/histcities-homonyms.json.gz`（`scripts/build-histcities-homonyms.mjs`・30 kB）＝
GeoNames **cities500** のうち、記録が使う綴りに `name` / `asciiname` / 無タグの `alternatenames` の
いずれかで一致する**すべての集落**。⚠ **人口ソートも重複排除もストップワードも文字数下限も curated 差分もかけない。**
曖昧なものは曖昧なまま残すのが、この問いに必要な性質。cities1000 ではなく cities500 なのは、
`ofm-city` のフィルタが `class in [city, town]` ＝ **人口の下限を1つも持たない**から。

同じ file が、座標に初めて意味を与えた。ガードは**行の座標**を中心に張るので、座標が 26 km ずれていれば
**era 名は静かに出なくなる**。旧ゲートの「40 km 以内」では全部合格していた **4 件の座標誤り**が出た:

| 行 | 旧座標 | 実際 | ずれ |
|---|---|---|---|
| `sorokyne`（ソロキネ／旧クラスノドン） | 39.3803 | 39.7332 | **26.1 km** |
| `kwadukuza`（クワドゥクザ／旧スタンガー） | 31.0519 | 31.2895 | **23.0 km** |
| `kunming`（昆明） | 102.8329, 24.8801（呈貢） | 102.7183, 25.0389 | **21.1 km** |
| `kariega`（カリエガ／旧アイテンハーヘ） | 25.5728 | 25.4007 | **15.9 km** |

GeoNames cities500 がそもそも持っていない 6 行（ヌナブトの4集落・山陽小野田市・金策）は
`{ unlisted: '…理由…' }` を**文で**書く。⚠ 旧ビルドはこれを `unproven++` と数えて**そのまま出荷していた**
（実測 279 キー）。数えるだけの数字は誰も読まない。

### `!` を廃止し、毎回試される主張に替えた

旧 `!` は「このキーについての**あらゆる**指摘を無条件に飛ばす」印で、9 行 10 キーに付いていた。
そのうち 6 件（サントドミンゴ・ラティーナ・コンスタンツァ・コロリョフ・キロフスク・イストラ・
スヴェトロゴルスク・ポジーリシク）は**距離が答える**ので消えた。残るのは**半径では分けられない双子都市**だけ:

| 行 | 相手 | 距離 |
|---|---|---|
| `valga`（エストニア） | Valka（ラトビア） | 1.2 km |
| `guben`（ドイツ） | Gubin（ポーランド） | 0.9 km |
| `komarno`（スロヴァキア） | Komárom（ハンガリー）×2キー | 2.4 km |
| `artashat`（アルメニア） | Verin Artashat | 6.1 km |

これらは `{ key, place, cc, why }` の **waiver** になった。⚠ **ビルドが毎回主張を検証する**——
「その綴りは相手の**別名欄にしかない**」が waiver の内容なので、GeoNames が相手の `name` / `asciiname` に
昇格させたら waiver は真でなくなり**ビルドが落ちる**。逆に、指摘が消えた waiver も落ちる（死んだ免除を残さない）。

### 実機で測った（ガードは両側から決まる）

半径は「同名都市を外に出せるだけ小さく」かつ「自分のラベルを中に入れられるだけ大きく」なければならない。
後者は**タイルの `place` ノードと記録の座標の差**で決まるので、本番同等のビルドを立てて
実際の OpenFreeMap タイルに対して測った:

| 行 | ガード | タイルのノードまでの実測差 | 余裕 |
|---|---|---|---|
| `armavir-am` | 4.1 km | 0.09 km | 4.01 km |
| `turkmenbashy` | 6.7 km | 3.73 km | 2.97 km |
| `yining` | 8.5 km | 4.09 km | 4.41 km |
| `abovyan` | 12.7 km | 0.54 km | 12.16 km |
| `holubivka` | 14.6 km | 0.50 km | 14.10 km |
| `tokyo` | 20 km | **6.68 km**（実測の最大） | 13.32 km |
| `kochi`（ケーララ） | 20 km | 4.78 km | 15.22 km |
| `volgograd` | 20 km | 0.11 km | 19.89 km |

⚠ **最大 6.68 km（東京）**。下限 6 km の行は余裕が一桁 km しかないので、**信用ではなく実測で確かめる**。
狭まった 5 行は全部この表に入っている。

そして、直したことそのものを実機で見た（1950 年・`ofm-city`）:
**高知市 → 「Kochi」**（`name:en=Kochi` を持つ本物のタイルで）、**ケーララのコチ → 「Cochin」**。

### 検査

⚠⚠⚠ **旧 ④ は綴りを固定していた**——`byLocal.push(base)`・`['match', ['coalesce', ['get', 'name:en']` …
その正規表現は**全部生き残ったまま緑**で、その間ずっと高知市はコーチンだった（[[intmap-r488-lessons]] と同じ形）。
新しい ④ は**組み上がった式を歩き**、全 1,400 分岐が `case` + `distance` + `var` の落とし先を持つことを見る。

⚠⚠ **`distance` は geometry が無いと NaN を返す。** だから `{ properties }` だけで評価する検査は、
**「歴史名が1つも出ない」を「全部正常」と読む**。`tileFeature()` が symbol worker と同じ形
（タイル座標の点 geometry ＋ canonical tile id）を組み、z3（`ofm-city` の minzoom・量子化が最も粗い）と
z14 の両方で確かめる。

- **⑩ control cases**: 高知市・カルーガ州 Kirov・New Jersey Linden が**それぞれ自分の名前のまま**。
  ついでにコロリョフ（1938–1995 の**もう1つの**カリーニングラード・1,200 km 離れ）も。
- **⑪ 全行 × 全綴りの全数**: ⚠ **1つ目の主張は「証拠が空でないこと」**——
  高知市・カルーガ州 Kirov・New Jersey Linden が index に**居ることを先に要求**する。
  #R427 の穴は規則ではなく証拠にあったので、同じ穴を掘り直していないことを最初に言わせる。
  そのうえで、どの行のガードの中にも「その行の都市でない集落」が入らないこと（国が違えば `alt` 一致のみ）。
- `--audit` が全行 × 13 列の表を出す（`SAFE_UNIQUE` / `SAFE_SPATIAL` / `SAFE_NARROWED` /
  `WAIVED_ALT_ONLY` / `UNLISTED`）。

### #R427 が落とした 3 行を戻した（608 → 611 都市・685 → 688 の歴史名）

**「その副産物も正常化して」。** #R427 は「綴りで分けられない」ことを理由に 3 行を捨てていた。
理由は今回失効したので、3 行とも戻した。⚠ **どれも実機のタイルで確かめてから入れた**——
`js/hist-cities.js` を vm で走らせ、組み上がった式を**本物の OpenFreeMap タイルの地物**に対して
評価する（extent は bucket と同じ 8192 に正規化し、`class in [city, town]` も自分で掛ける）:

| 行 | 年 | 実タイル | 出た名前 | 同名の他人 | 他人に出た名前 |
|---|---|---|---|---|---|
| `zelenogorsk-terijoki` | 1900 | `name:en=Zelenogorsk` @29.707,60.197 | **Terijoki** | クラスノヤルスク地方（3,679 km） | Zelenogorsk |
| `armavir-am` | 1950 | `name:en=Armavir` @44.039,40.156 | **Hoktemberyan** | クラスノダール地方（589 km） | Armavir |
| `kadoma-zw` | 1970 | `name:en=Kadoma` @29.913,-18.337 | **Gatooma** | 門真市（10,000 km） | Kadoma |

⚠⚠⚠ **アルマヴィルだけ、旧い記録が知らなかったものが出てきた**——ロシアのアルマヴィルは 589 km で
距離が答えるが、**8.2 km 南にもう一つのアルマヴィル**（古代都市の址の村・3,428 人）がある。
導出されるガードは 4.1 km で、**この回で決めたばかりの下限 6 km を下回る**。

⇒ **下限を「誰も実測していない行が受け取る既定値」に格下げした。** 6 km は他の行の最悪値
（東京の 6.68 km）から来た数で、**自分の差を実測した行にそれを当てるのは、証拠を既定値で否定すること**。
`{ measured: { km, on, why } }` を書いた行は下回れる（ビルドはガードが実測値の 3 倍以上あることを要求し、
実測を持たない行が下回れば従来どおり落ちる）。
⚠ **2 km の硬い下限だけはどの実測でも越えられない**——`ofm-city` の minzoom 3 では
タイル自身の量子化が ±0.61 km（extent 4096・1 単位 1.22 km）あり、それ以下の半径は丸めが決める。
アルマヴィルの実測は **町のノードが記録座標から 0.09 km・村のノードが 7.97 km**（2026-09-07）。
村は `class=village` ＝ `ofm-city` が**そもそも描かない**が、それは GeoNames から毎回検証できない
主張なので、**ガードの根拠にはしていない**（コメントに事実として残しただけ）。

⚠ **ホクテンベリアンの span を 1991 で切ったのは、資料が割れているから。**
サルダラパト→ホクテンベリアンは 1935 年 3 月 2 日で en/ru が一致する。戻る側は
en.wikipedia が 1995 年 11 月 7 日（州制改革）、ru.wikipedia が 1992 年、ja.wikipedia が
「独立の 2 年後」と**三通り**。最も遅い年を採ると、三つのうち二つが「アルマヴィル」と呼ぶ年に
「ホクテンベリアン」と印字することになる。だから**全部が一致する最後の年**で止め、1992–1995 は
元のラベルへ落とす——**ガードが失敗する向きと同じで、この記録が失敗してよい唯一の向き**。

### やらなかったこと

- **キーの field provenance**（`{en:[…], local:[…]}`）は入れていない。身元が空間になった今、
  `name:en` のキーが `name` に当たっても無害で、逆に分けると**当たるべき一致を落とす**
  （多くの都市は `name` にラテン文字の綴りを持つ）。監査自身が「provenance だけで一意性を保証してはならない」
  と書いており、安全上の利得がゼロで 611 行の書き換えになる。
- **`iso_a2` による絞り込み**も入れていない。OpenMapTiles の標準では `iso_a2` は `class=country` にしか無い。
