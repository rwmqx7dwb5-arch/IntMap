## R690 — **1850 年より前の国境は、上流にずっと日付つきであった——窓だけが 1850 で切られていた**

〈「1850 年より前の国境を、スナップショットから日単位の記録へ」〉

### 1. ⚠⚠⚠ 上流は 19 世紀のデータセットではなかった。窓がそうだっただけである

OpenHistoricalMap が publish する `admin_level=2` の boundary relation は **3,985 件**。
そのうち **2,101 件（53%）が 1850 年より前に終わる**。#R518 が切った窓の下に、上流の半分以上が
あった。その帯を答えていたのは `data/hist-eras.js` のスナップショット 53 枚で、
**西暦 1000 年より下は 100 年刻み**、その上でも 30〜70 年刻み。1750 年の読者は 1715 年の世界を、
1600 年の読者は 1 世紀ぶん動かない 1 フレームを見ていた。

束は **1689–1885** になった。記録 **494 → 1411 件**、窓の中の変化日 **216 → 881 件**。
神聖ローマ帝国もグレートブリテン王国もヴェネツィア共和国もムガル帝国も清もオスマン帝国も、
そして**ポーランド・リトアニアの 3 回の分割が 3 つの別々の日付つき記録として**入っている。

### 2. ⚠⚠⚠ 下限は選んだ年ではなく導出された年で、その導出規則は実測に 2 度否定された

「上流が持っている限り下げる」は誤りである。OHM の深い側は薄い——**西暦 100 年で 13 政体・
全陸地の 6%**、1500 年で 25%、1650 年で 56%。**日付が正確な散らばりは、粗くても世界全体を覆う
スナップショットより悪い世界である。**

だから問いは「これは世界か」であり、それを**測れるものに訊いた**。2 回外した:

- **① 「その年を挟むスナップショットと同じだけの陸地を覆うこと」** ⇒ 下限 **1882**。
  **#R518 が出荷済みの窓ごと壊す答え**だった。原因はスナップショット側にある——
  `world_1815` は **18,845 deg²＝地球の陸地より 3 割多い**。植民地の重複主張を二重に数えているからで、
  **それで作った尺度は「世界の広さ」ではなく「その時代がどれだけ争われていたか」を測っている。**
- **② 「スナップショットの中央値」** も同じ汚染を継ぐ（重複が最も多いのが植民地の世紀そのもの）。

⇒ 尺度は**隣の記録 `data/cshapes.js` に訊く**。同じ種類の記録（主権国家・日単位・重なり無しで
地球を敷き詰める）で、**この束が引き継ぐ相手**でもある。実測 **12,895〜14,660 deg²**、
バーはその最小から CShapes 自身のばらつき 1 つ分を引いた **11,131**。

**1688 年は 9,371 deg²、1689 年は 11,314 deg²。** 記録の被覆は階段状（1650 年代 7,500・
1670 年代 9,000・1684 年 9,396）で、**バーはその 9,396 と 11,314 のあいだの 1,900 deg² の空白に落ちる**
——1 年ぶんの雑音では床が動かない。導出値は束の `window[0]` が正本で、
`js/time-borders.js` の `HB_MIN` はその**写し**にすぎない（`go()` が 13 MB の束を注入するかどうかを
束を読む前に決めなければならないから、そこにだけ綴りがある）。両者の一致は
`tests/r690-histborders-deep-checks.test.mjs ③` が押さえる。

### 3. ⚠⚠⚠ member の role を見ていなかったことが、窓を広げた瞬間に危険になる

relation member **8,782 件のうち 8,769 件が `subarea`**——行政区画であって、この境界の一部ではない。
#R518 は**すべての** relation member に再帰し、`inner` でない way を**すべて**輪郭に入れていた。
それが露見しなかったのは、506 件のダウンロードが 8,536 参照のうち **1,054 件しか解決しなかった**から
である。2,607 件へ広げれば数千件が解決し、**全区画の輪郭が親の輪郭に黙って溶接される。**

⇒ way は `outer` / `inner` / role 無しだけ、relation member は **role 無しの 12 件だけ**。
その 12 件は南部連合（11）と Sarawak（1）で、**自前の way を 1 本も持たない 3 件の全幾何**である。
`label` 489 件・`admin_centre` 271 件も輪郭から外れた。

⚠ #R518 が名指した 6 政体（南部連合・両シチリア・教皇領・プロイセン・ハノーファー・
ロシア領アメリカ）は全部そのまま残っている——**既存の形は壊れていない。**

### 4. ⚠⚠ キャッシュの鍵・許容幅・`Date.UTC`

- **キャッシュの鍵を relation id にした。** #R518 はバッチ先頭の id で鍵を付けていたので、
  id の一覧が変われば **196 ファイルすべてが到達不能**になり、約 2.1 GB を再取得するところだった
  （#R669 が位置で鍵を付けて 3.4 GB を迷子にしている）。既存のバッチは捨てずに移行する。
- **許容幅は掃いて「据え置いた」。** 0.008° 18.14 MB / 0.012° 13.28 / 0.015° 11.13 / 0.020° 8.82 で、
  **どれも 1,411 件を保つ**ので #R530 の規則（何も失わない最も粗い段）なら 0.020° で 4.46 MB 安くなる。
  それが効かないのは**引き継ぎ**があるから——読者は 1885→1886 を **1 日ずつ**跨げるので、そこで
  1885 年の海岸線だけが目に見えて粗くなる。**2 つの記録は 1 つのものとして読まれるのだから、
  同じ尺度で簡略化する。**
- **`Date.UTC` をビルドから除いた**（y<100 で y+1900。#R602 が同じ形を 4 か所で踏んでいる）。
  「翌日」は proleptic Gregorian の素の算術になった。

### 5. ⚠ 閉じられない残余を 3 つ、明記した

1. 上流から**ずれた**ファイルは門を通る（再生成にはネットワークが要る）。両側の検査が名指す
   政体の一覧で狭めている。
2. **「なぜ 1689 より下ではないのか」はオフラインで検算できない**——束には床を越えた記録しか
   入っていないから。オフラインで測れるのは床が**上から**きついこと（窓のどの年もバーを越える）と、
   ビルドが床を**読まずに計算する**こと。
3. **OHM の紀元前表記は混在している。** `Roman Empire -0027` は歴史年（紀元前 27 年）、
   `Uruk culture -3999` は天文年（紀元前 4000 年）。データからは区別できないので**書かれたまま読み、
   例外を発明しない**（`.agents/rules/no-ad-hoc-hardcoding.md`）。導出された床ははるかに上なので
   **出荷物には影響しない**——記録するのは**上流がそうだから**であって、束がそうだからではない。
