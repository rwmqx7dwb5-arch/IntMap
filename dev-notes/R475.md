## R475 — **毎晩の警報になっていたのは、誰も操縦していない数字だった**（そして次のラウンドが偶然それを直した）

依頼は「`tests/r318-atlas.spec.js` の `expect(r.caps).toBe(126)` が 127 で落ちる。#R433 の形なので
数字を上げずに導出しろ。ついでに deep tier に他の失敗が無いか見ろ」。

### 1. ⚠⚠⚠ 報告された症状は、今日の `main` では再現しない——**それが問題の核心だった**

`origin/main` (7821b33) を worktree に出してビルドし、`IM_TIER=all npx playwright test
tests/r318-atlas.spec.js --workers=1` を実測: **13 passed**。R406 ① は緑で、`caps` は **126**。

依頼が名指した `sim.slopeAspect` は `js/atlas-capabilities.js` にも `js/atlas-schemas.js` にも無い。
残っているのは `js/sims.js` の墓碑コメント1行だけ——**#R469 がこのラウンドの2つ前に消していた。**

`js/atlas-capabilities.js` をそれを触った commit ごとに読み込んで `makeAtlasCapabilities({}).all().length`
を数えた実測:

| commit | ラウンド | 何をした | 件数 | R406 ① |
|---|---|---|---|---|
| `fa924f6` | #R413 | — | **126** | 緑（#R406 が数字を書いた日） |
| `616e549` | #R439 | `layers.isobars` を**足した** | **127** | **赤・毎晩** |
| `30d1a7c` | #R469 | `sim.slopeAspect` を**消した** | **126** | **緑に戻った** |

⚠⚠⚠ **どちらも正しい製品作業で、どちらのラウンドもこのファイルを開いていない。**
そして2つ目は**警報を偶然修理した**。**開いていないラウンドによって赤くなり、開いていない
ラウンドによって緑に戻る判定は、自分の名前が言っていることを測っていない。**
罠は消えていない——次に能力が1つ増えた晩にまた赤くなる。

### 2. 直し方は「数」ではなく「id」

R406 ① が本当に主張しているのは **「registry がビルドを丸ごと渡った」**。だからそう訊く——
`js/atlas-capabilities.js` が宣言する id の集合と、ビルド済みアプリの `IntMapCapabilities.all()`
が答える id の集合を突き合わせる（`tests/helpers/atlas-registry.mjs` の `declaredCapabilityIds()`）。

- **件数より強い**——id が1つ入れ替わっても長さは同じで、数では見つからない。
- **古くならない**——能力を足しても消しても両辺が同時に動く。
- **2本目の一覧を作らない**（#R318 の主旨）。モジュールを **import して訊く**のであって、
  リテラルを正規表現で読まない（#R469 が「リテラルへの正規表現は綴りへの検査」で検査12本を
  一度に落としている。`tests/helpers/layer-groups.mjs` と同じ形）。

⚠ `js/atlas-capabilities.js` は DOM を要らない素の factory なので、node 側で `window` を
作らずにそのまま import できる（実測）。テストのワーカーにグローバルを1つも足さない。

### 3. ⚠⚠ 門は、落とした行より広くする（`tests/r475-checks.test.mjs`）

**このラウンドが生き延びた理由は、前のラウンドが1行しか見なかったこと**である——#R433 は
**同じファイルの3つ下**にある R406 ② を直し、① をそのまま置いていった。

so ② は**リポジトリの全テスト**を掃く。registry を名指すファイル（`IntMapCapabilities` /
`makeAtlasCapabilities` / `atlas-capabilities` / `atlas-registry` を綴るファイル）だけを対象に、
`.all()` の**件数と整数リテラルの等号**を探す。実装は idiom を書かれたとおりに読む——
まず「どの名前が件数（`caps: C.all().length`）または一覧（`const all = CAPS.all()`）を持つか」を
集め、次にその名前が整数と等号で結ばれているかを見る。**出荷されていた行では両者は6行離れていた**
ので、近接 grep では1件も見つからない。

⚠ **上限・下限は対象にしない。** `tests/r406-checks ④` の `assert.ok(all.length >= 126)` は
「registry は縮んではならない」という**意図的なラチェット**で、能力を足しても壊れない。
罠は**等号**のほう——それを満たし続けられるものは何も無い。境界はそこに引いてある
（該当行にその旨を注記した）。

⚠ **発火することを実測している**（#R465）。出荷されていた `tests/r318-atlas.spec.js` を
そのまま走査器に渡すと `["expect(r.caps).toBe(126)"]` を返し、修正後は `[]` を返す。
inline 形・node 形も含めて3通りで赤を確認し、ラチェット形が**緑のまま**であることも確認した。

⚠⚠ **検査の見本は組み立ててあって、書いてはいない**（#R345 の一歩先）。`codeOnly` が剥がすのは
コメントであって**文字列リテラルではない**ので、罠をそのまま綴った初版は**自分自身を告発して
落ちた**（実測）。見本は断片から連結するので、このファイルの本文にはどこにも現れない。
