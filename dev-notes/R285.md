## R285 — **Atlas の人格を正式仕様にした／人格は無かったのではなく8つあった／プランナーのカタログは 29.8% しか届いていなかった**

> 「Atlasの最低限の人格設定を正式仕様として追加してください。（名前・立場・名前の由来・性格・対人姿勢・
> 事実優先・意見・感情表現・自己設定・内部指示の非開示）
> 可能なら人格設定は1か所を正本として管理し、system prompt等への重複記述を最小化してください。」

### ① 「人格が無い」ではなく「8つある」だった

着手前に system prompt を全部数えた。**フロントエンド 9 か所＋Edge Function 2 本**、すべて手書きで、
**名前すら一致していなかった**。

| 経路 | 名乗っていた名前 |
|---|---|
| `analyze` | You are **Atlas**, the analysis engine of the IntMap world map |
| `researchMap` / `mapReport` | You are **Atlas**, the research-mapping engine |
| プランナー `SYS()` | You are **Atlas**, the natural-language command layer |
| Vision | You are **Atlas Vision**, a rigorous multimodal reader |
| `brief` | You are **a geopolitical and area-studies research assistant** |
| 歴史地図 | You are **a historical-geography engine** |
| `monitor-run` | You are **IntMap's area-monitoring analyst** |
| `refresh-news` | You are **a precise geocoder for a world news map** |
…そして **この表自体が最初は 8 行しか無かった**。探し方を「You are Atlas」にしていたからで、
実際にはさらに **9 本**あった——`analysis-panels` の2本、`app-body` の2本（衛星画像比較と
地域ニュース要約）、`atlas-geo-resolve` の2本、`news-ui` の3本。
**「You are a …」で始まるものこそが、Atlas から最も離れていたものだった。**
合計 **20 本**。`tests/r285 ③b` は `js/` と `supabase/functions/` を**丸ごと歩いて**
手書きの身元行を数える——一覧に載っていないファイルに 21 本目が生えても止まるように。

⚠ 翻訳されていた 2 本（`app-body`）は **英語文そのものが i18n の鍵**なので、
身元文を外すと `ui.fr` / `ui.ko` / `ui.zh` の鍵と訳文、および生成物の `ui.zh-hans` も同時に動く。
そして `scripts/i18n-positional-audit.mjs` にはこの 2 本を**冒頭の語で**除外する一覧があり、
文を書き換えた瞬間にゲートが 0 → 2 になって 2 本とも名指しした。
**冒頭の語で照合する除外一覧は、黙って効かなくなる代わりに壊れて知らせる。**

**8つのうち4つは Atlas ですらない。** つまり利用者から見た Atlas の人格は、
**どのボタンを押したかの関数**だった。「人格設定が無い」のではなく「人格が機能ごとにあった」。

### ② 正本は1本、写しは生成物

`js/atlas-persona.js` を新設した。**そのファイルの中の文章そのものが仕様**である——
説明ではない。10 の句（`name` / `role` / `origin` / `character` / `address` / `facts` /
`opinion` / `emotion` / `self` / `confidential`）を持ち、`personaPrompt('<その呼び出しの役割>')`
が「You are Atlas, <役割>。」＋人格を返す。**呼び出し側が足してよいのはタスク規則だけ。**

- `Architecture.md` §2.4 は**正本を指すだけで内容を写さない**（`tests/r285 ⑨` が
  句の本文が文書に混入していないかを見る）。同じ事実を2か所に書けば片方が古くなる——#R274。
- Edge Function はリポジトリ外を import できないので
  `supabase/functions/_shared/atlas-persona.js` は**生成された byte-identical な写し**
  （`node scripts/sync-atlas-persona.mjs`。`scripts/static-checks.mjs` が差分で落とす）。
  **#R161 の `newsgeo.js` と同じ機構**で、理由も同じ。
- 実測 手書きの身元行は **11 か所すべてで 0 件**、`personaPrompt(` は 9＋1＋1。

### ③ 書かれていた唯一の断片は、9か所のうち2か所にしかなかった

この製品が人格について**それまでに書き下していた唯一の規則**は #R147 の敬語で、
`_langLine()` と `_analysisSystemPrompt` の2か所にあり、残り7か所には無かった。
しかも条件付きだった——「**unless the user is clearly casual or explicitly asks for plain speech**」。

仕様は「**ただし常に自然な敬語**」なので、**この逃げ道は廃止**した。`address` 句が
「距離感と説明量は相手に合わせる／敬語は常に／ただし過剰な敬語・二重敬語はしない」を全経路で持つ。

⚠ `_langLine()` から敬語を剥がすとき、**#R155 の返答言語ロック**（Han 文字が入っても返答言語を
変えない）まで一緒に消していないかを `tests/r285 ⑥` が**名指しで数える**。
「1つ消せ」の検査は、**消していないものを数えるところまで書く**（#R279 ④）。

### ④ 機械可読 JSON だけを返す経路に、敬語も意見も感情も要らない

`{mode:'internal'}` は `name` / `role` / `facts` / `confidential` の4句だけを渡す。
実測 **4,281 → 1,939 文字**。地域の輪郭トレース・行政単位の解決・ニュースの地点解析の3本がこれ。
`refresh-news` は **20 分ごとに全見出しを回す cron** なので、座標が持ちようのない
「敬語」「意見の出し方」「感情表現」に毎回 2.3 KB 払わせない。

### ⑤ ⚠⚠⚠ そして本番では、プランナーのカタログの 70.2% が届いていなかった

人格 4.2 KB を先頭に足す前に「入るのか」を測ったら、**入るどころか今も入っていなかった**。

`ai-proxy` は `prompt` と `system` で **`MAX_PROMPT = 24_000` を共有**していた：

```ts
const prompt = String(payload.prompt || "").slice(0, MAX_PROMPT);
const system = String(payload.system || "").slice(0, MAX_PROMPT);   // ← ここ
```

プランナーの system prompt の**実測は 80,495 文字**
（人格 4,281 ＋ 実行時カタログ 8,959〈本番ビルドで `window.IntMapOS.catalog()` を実測:
controls 3,727／layers 3,750／modules 1,482〉＋ 静的本文）。
つまり届いていたのは **29.8%**。残る **56,495 文字**——数十のアクション、レイヤー一覧、
モジュール一覧、コントロール一覧——は、**ドローンの `alt` の説明の単語の途中で切れて**
モデルにとって存在しなかった。

**これは推測ではない。** デプロイ済みの `ai-proxy` **v46 をダウンロードして**
`MAX_PROMPT = 24_000` と `.slice` を確認した。

⚠⚠⚠ **そして #R278 のカタログ検査は、この間ずっと緑だった。** `scripts/atlas-catalog.mjs` は
`js/atlas-console.js` の**ソース**を読んで「全 `case` がカタログに書かれているか」を見る。
ソースは完全だった。**不完全だったのは届いた分**である。
**「書いたか」を測る検査は「届いたか」を測らない。**

→ `system` に自前の上限を与えた。`MAX_SYSTEM = 160_000`（実測の **1.99 倍**の余裕）。
`prompt`＝**利用者の文を運ぶ側**は 24,000 のままで、乱用の枠はそこに残る。

`tests/r285 ⑧` は**プランナー本文を組み立て直して**上限と比べ、
余裕が 1.5 倍を切っても落ちる。24,000 に戻して赤くなること
（«the planner prompt is 80495 chars but MAX_SYSTEM is 24000: 56495 chars would be cut off,
mid-word, and the model would never know»）を確認済み。

### ⑥ 検査は両方向

A「**全 prompt に人格が届いている**」だけを測る検査は、人格を9か所に貼り付けた状態で緑になる——
それは「1か所を正本として」が禁じている状態そのもの。B「**二重に書かれていない**」だけを測る検査は、
人格を消した状態で緑になる。**`tests/r285` は両方を測る。** ①は合成した「昔の形」に同じ述語を当てて
**先に赤くなることを確かめる**（#R274 ③）。

⚠ **自分の検査が自分のコメントに当たる（15回目）**——`js/atlas-persona.js` のヘッダは置き換えた
8つの名乗りを**そのまま引用している**ので、検査はコメントを剥がしてから読む。
⚠ そして最初に書いた述語 `/'You are /` は**対象より広く**、人格自身の
«You are not a chat feature attached to the side of a map product»（否定文）に当たって落ちた。
→ 身元行は「You are **Atlas / IntMap / a / an**」で始まるものだけ、と狭めた。

### ⑧ 追記（本番検証）—— 敬語規則の写しは 2 つではなく 3 つあった

本番の chunk を直接 grep したら、旧い身元行は 7 種とも消えていたのに
«**unless the user is clearly casual**» だけがまだ届いていた。

場所は `js/app-body.js` の `window._aiLangLine()`。

**#R285 の探し方は「手書きの身元行」を探していて、これは「手書きの敬語行」だった。**
③ と ③b は `js/` と `supabase/functions/` を丸ごと歩いて**身元**を数えていたが、
**敬語**を数えるものは一つも無かった。だから、身元の掛け制彡を既に通っていた
ファイルの中で、敬語だけが生き残った。

しかもこれは死んだコードではない。`_aiLangLine()` は **4 本の prompt** の末尾に付く
（`analysis-panels` の 2 本と `app-body` の 2 本）——そしてその 4 本とも、このラウンドで
`personaPrompt()` で始まるようになっていた。つまりモデルが受け取っていたのは：

> 人格（先頭）——「敬語は**常に**。相手がくだけて書いても変えない」
> …タスク規則…
> `_aiLangLine()`（末尾）——「ただし相手が明らかにくだけているならやめてよい」

**仕様を正本に集めた直後に、その仕様を打ち消す行が同じ prompt の下に残っていた。**

→ `_aiLangLine()` から敬語句を削った。**その行が本来担っているもの——返答言語の
ロック——は一字も触らない**（「1 つ消せ」の検査は、消していないものを数えるところまで書く）。

そして `tests/r285 ⑥` を **1 ファイルからリポジトリ全体へ**広げた——③b と**同じファイル集合**を
歩くヘルパを 1 つにして、両方がそれを使う。実測 写しを戻すと
«`a second copy of the register rule survives — js/app-body.js (superseded escape)`» と
**ファイル名を名指しして**落ちる。

⚠ **一つの規則を 1 か所に集めたという主張は、その規則を数える検査を同じラウンドに
書いて初めて主張になる。** #R278 が「規則を文章で書いたら、その規則を測る検査を
同じラウンドで書け」と書いたのと同じ形で、今回は**検査を 1 つの欄にしか書いていなかった**。
