## R680 — **25.8 MB が、何の不変条件にも守られていなかった——歴史的行政区分の束 2 本に門を付ける**

> 「歴史的な行政区分の束 2 本にゲートを足す」

### 1. ⚠⚠⚠ 門が無かったのではなく、宣言すらされていなかった

歴史的な境界の束は 5 本ある。#R679 の全数調査が測ったとおり、そのうち 3 本＋`border-coast` には
門があり、**大きいほうの 2 本だけに無かった**:

| 束 | サイズ | 門（#R680 の前） |
|---|---|---|
| `data/hist-borders.js` | 5.3 MB | `npm run check:histborders` |
| `data/hist-eras.js` | 10.6 MB | `npm run check:histeras` |
| `data/hist-kuni.js` | 1.8 MB | `npm run check:kuni` |
| `data/border-coast.js` | 165 kB | `npm run check:bordercoast` |
| **`data/hist-admin1.js`** | **10.3 MB** | **無し** |
| **`data/hist-admin2.js`** | **15.5 MB** | **無し** |

`scripts/build-hist-admin1.mjs` に `--check` は 1 件も無く、`package.json` にも
`.github/workflows/ci.yml` にも該当するステップが無かった。**地図は第1級・第2級の線もラベルも、
クリックの答えも被覆の件数もここから作る。**

⚠ **これは #R381 と #R628 の 3 度目の形で、前 2 回より 1 段深い。** #R381 は
`scripts/build-wars.mjs` が `--check` を持ちながら**呼び出し元を持たなかった**話、#R628 は
`check:bordercoast` が宣言され両方の指示表に載りながら**誰にも呼ばれていなかった**話。今回は
**`--check` そのものが無い**ので、`gate-callers` にも `gate-lists` にも `ci-gates` にも
見えなかった——**3 つの規則はどれも「宣言された門」を母集合にしているから**である。
⚠ 母集合の外にあるものは、その母集合を見る規則には原理的に見えない（#R628 の `fonts/README.md`
と同じ形。「除外されていない」と「見られている」は別物）。

### 2. ⚠ 再導出はしない、と書く

ビルドは OHM の `admin_level` 3–6 の抽出そのもの（28,211 relation・再開した 1 回の実測で Overpass
**3.4 GB**）を消費する。CI はそれを持てない。`check:histborders` / `check:histeras` が同じ理由で
同じ判断をしているので、**同じ形にした**——測るのは**コミットされたバイトの不変条件**で、
**残余（上流から乖離した束でも通る）は `docs/TESTING.md` に含みではなく明示で**書いた。

### 3. ⚠⚠⚠ 層の一覧を書かない

`data/hist-admin<N>.js` という綴りが 2 つのことを決めている——global が `__HISTADM<N>` であること
と、その層が `admin_level` 2N+1・2N+2 であること。#R604 の事故（`--global` を渡し忘れて
`data/hist-admin2.js` が `window.__HISTADM1=` を名乗り、**読み込んだ瞬間に第1級の記録を置き換えた**）
は、まさにこの規約が破られたときに起きた。だから門は**ディレクトリを読む**:
手で 2 本並べた一覧は、第3層が足された日に黙ってそれを飛ばす
（`.agents/rules/no-ad-hoc-hardcoding.md` §2 の 4）。
`tests/r680-histadmin-gate-checks ⑪` が、**壊れた `data/hist-admin3.js` を置いて門が気づくこと**を測る。

### 4. ⚠⚠⚠ 「全 feat が英語名を持つ」は、実測で偽だった

着手時の見立てには「全 feat が英語名を持つこと」があった。測ると:

```
names.en を持つ    第1級 3,116 / 4,820      第2級  1,482 / 22,708
どの言語でも無い    第1級     1              第2級      2
```

英語名は**そもそも過半に無い**ので、門にできない。門にできるのは「どの言語でも名前が無い」ほうで、
それが **3 件**（OHM relation 2698257・2735085・2735454）。ここに 2 つの誤答がある——
**3 つの id を門に書けば**それは事例ごとの記述（`.agents/rules/no-ad-hoc-hardcoding.md` が禁じる）、
**何も測らなければ**次の再ビルドが 400 件出荷しても緑になる（#R669 の形＝ビルドが認識できなかった
ものを黙って落とす）。⇒ **下向きにしか動かない天井**にした:

```js
const NAMELESS_MAX = 3;   // 観測 2026-09-11 / 失効: builder が拒むか上流が名づけた日 / 正本: この行
```

`scripts/test-budget.mjs` と同じ作法である。**由来の書けない定数は 1 つも置いていない**——
世紀ごとの単位数のような「上流の事情で動く数」は**性質**に置き換えた（下記）。

### 5. 測っているもの

- 各ファイルが**自分の名前が示す global だけ**を名乗ること（#R604。`tests/r604-checks ⑦` は
  出荷物の側から見ているが、**名前を選ぶのは build なので build の門も見る**）
- `v` / `src`（上流名と **CC0**）／`built`（ISO 日付）／`since` / `tolerance`
- **名前が要求する層**と、ファイルが `levels` として**宣言する**層が一致すること
- 全リングが 4 点以上・**閉じる**・地球上にある（|lat|≤90, |lon|≤180）
- ring index がすべて解決し、**プールのどのリングもどこかの単位から参照されている**こと
  （参照されないリングは、誰も描かないのに配られているバイトである）
- span が `start <= end`（両端を含む・cshapes と同じ規約）で `since` より前に終わらない／月日が暦の中にある
- 名前の言語キーが build の読む 9 つの中にある／**U+FFFD が 1 つも無い**（`check:histeras` と同じ理由）
- 全単位が**一意の OHM relation id** を持つ（列 10 はクリックの精度そのもの・#R669）
- ⚠ **どの世紀にも在force の単位があること。** `check:histborders` が 36 年の窓を 1 年ずつ測るのと
  同じ問いを、暦全体が相手なので世紀で訊く。**件数の下限は置かない**（実測 2026-09-11: 第1級は
  1 年 73・1500 年 398・1900 年 656、第2級は 1 年 17・1900 年 4,181——どれも上流の事情で動く数）。

### 6. ⚠ 既にある門の仕事は繰り返さない（正本を決める）

- `data/hist-kuni.js` がこの束の持つ単位を名乗らないこと（＝二重に描かない）。**正本は `check:kuni`**
  ——判断が行われる導出側で測っている。ここでは 1 行も繰り返していない。
- 各リングの「国境／海岸線の写し」の印。**正本は `check:bordercoast`**（全リングを再導出できる）。
  ここに残したのは、それが安く言えない O(1) の半分だけ——`data/border-coast.js` が**この本数の
  リングに対して**作られていること。⚠ **束だけを焼き直すと、印は黙って別のポリゴンの説明になる**
  （印はリング番号で引くから）。

### 7. ⚠ 恒久指示の余白は 16 バイトだった

`.agents/rules/execution-strategy.md` は毎セッション読み込まれるので **6,144 バイトの天井**があり
（`tests/r295-checks ⑥`・**下向きにしか動かない数**）、着手時の残りは **16 バイト**。新しい行は約 57。
**天井は上げず、同じファイルの中で払った**——表の 3 つのラベルから意味を持たない語を落とし
（「`js/` の**ファイル**を足した」「**その**生成物」「紀元前**を含む**」）、2 行上で
`npm run check:docs` を綴り直すのをやめた（その名前は表の行が既に持っている）。6,128 → **6,134**。

### 8. ⚠ 検査は綴りを固定せず、壊して門が鳴るかを測る

`tests/r680-histadmin-gate-checks.test.mjs`（11 本）は門の主張を**書き写さない**——#R488 の形
（綴りを固定した検査は、死んだ規則を緑のまま残す）を避けるため、**壊して鳴るか**を測る。
門は自分のパスから ROOT を導くので、**一時ディレクトリに小さな束を置けばそれが root になる**:
だから「参照されないリング」も「世紀の穴」も「第3層の発見」も、25.8 MB を触らずにミリ秒で証明できる。
⚠ ② は**壊していない合成の世界が通ること**を測る——これが無いと、以下の 9 本は「変異を捕まえた」
のではなく「一時 root が壊れていた」ので落ちているかもしれない（#R585 の形）。

### 9. 残っているもの（提案）

**名前を 1 つも持たない 3 件は、まだ出荷されている。** 構造的な直しは `absorb()` が
**名前の無い記録を出さない**ことで、そうすれば天井は 0 になる。**このラウンドではやっていない**——
実行には 25.8 MB の再ビルド＝ OHM の全抽出が要り、依頼された作業（門を足す）の外側だからである。
次に この束を焼くラウンドで、同じ 1 回のパスに入れるのが安い。
