## R776 — 同じ名前の 2 つの「Atlasに聞く」が、違う着き方をしていた

〈利用者の指摘:「News の details から Ask Atlas を押しても、単にタブが切り替わるだけなのは
不親切だと思いませんか？」／確認したうえでの指示:「1に。自由送信もできるように、」
（＝記事を名指した案内＋質問チップ。ただし入力欄は自由のまま、自動送信はしない）〉

### 1. 実測 — 押したあと何が起きていたか

`js/article-reader.js` の `askAtlasAboutReading()` は `IntMapAtlas.call('open')` の 1 行だった。
読む面（記事 reader と出来事の詳細が**共有する** `.nrp-bar`）の「Ask Atlas」は、Atlas を開いて
**それだけ**。着いた先は汎用の導入文で、見出しを目の前にしていた読み手は、その見出しを
**打ち直さないと何も訊けない**。

⚠⚠⚠ **主題は最初から渡っていた。** `window._imReader` は #R430 から見出し・媒体・時刻・座標・
場所・本文を運び、`_selectionState()` がそれを読み、`js/atlas-state.js` が「この記事 / この出来事 /
それ / 詳しく・背景・なぜ」をそこへ写像する——つまり Atlas は**最初から答えられた**。
欠けていたのは情報ではなく、**到着の瞬間にそう名乗るもの**だった
（[[intmap-records-with-no-reader]] と同じ形の、宛先だけが無い記録）。

⚠⚠ **同じラベルの 2 つ目のボタンは、ちゃんと着いていた。** 地図の右クリック「Ask Atlas」
（`askHere`）は #R392 以来、点を名指した見出しと**その点の周りで測った** 3 つの起点を出す。
2 つが違ったのは方針の差ではなく、**到着が `askHere` の中に書かれていたから**である。

### 2. 直したもの

- **`js/atlas-reading.js`（新設）** に **`arrive(headHtml, note, qs)`** を置き、**askHere もこれを呼ぶ**。
  到着の吹き出し（見出し＋説明＋チップ＋チップの配線＋入力欄へのフォーカス）はこれ 1 か所。
  ⚠⚠⚠ **最初はカーネルの中に書いて、5 本の検査を赤にした**——`js/atlas-console.js` は shrink-only の
  行数天井（4,908・`tests/r318` ⑨b）の**1 行下**に座っていて、+57 行で 4,964 になった。天井の脇に
  書いてある規則は「**機能が出ていくのであって、天井が上がるのではない**」なので、`js/atlas-gloss.js`
  や `js/atlas-msg-tools.js` と同じ形で module へ出した（import と組み立てはどちらも**既存の行に
  足す**——カーネルには 1 行の余白も無い）。結果 4,904 行＝ `origin/main` の 4,907 より**3 行少ない**。
  ⚠ 検査 ③ は `class="atl-here-q"` の**出現回数が 1** であることを測る——2 か所になった日が、
  次に誰かが写した日である。
- **`askReading()`**（公開 API）。`open()` を先に済ませ、`window._imReader` を読み、
  見出し／媒体・日付・場所の 1 行／`loc` をピン（`_herePoint` / `_lastPlace`）に据える。
  ⚠ **flyTo はしない**——読み手はまだ読んでいる。押された理由は地図を動かすことではない。
  ⚠ 何も読んでいなければ `false` を返すが `open()` は済んでいる＝**呼び手に第 2 の筋書きを
  持たせない**（[[intmap-contract-reached-only-from-one-side]]）。
- **`readingStarters(rd)`** — チップは**その 1 件が実際に持っているもの**から導く。場所が無い
  記事に場所の問いを出さず、`kind==='event'` なら出典の一致を訊き、本文が無ければ周辺を訊く。
  ⚠ **固定の 3 文にしない**（#R392 が `askHere` から外したのと同じ理由）。
- `window._imReader` の書き手**全員**に `kind`（`'article'` / `'event'`）を足し、
  `_selectionState()` の `o.article` がそれを運ぶ。⚠ 書き手は 3 か所ある
  （[[intmap-object-built-twice-and-hidden-class]]）——検査 ⑤ は一覧を持たず、`window._imReader = {`
  を**発見して**数え、見つけた全部に `kind` を要求する。4 つ目が足された日に測られる。
- **自動送信はしない。** 利用者の「自由送信もできるように」はこの点で、チップは起点であって
  唯一の出口ではない。`_arrive` が最後にするのは送信ではなく**入力欄へのフォーカス**。

### 3. 検証

`tests/r776-reader-atlas-arrival-checks.test.mjs` 5 本。⚠ ①② は `readingStarters` の**ソースを
取り出して実際に評価する**（#R505: ソースを読む検査は決定を見られない）——主題ごとにチップが
違うこと、場所を持たない記事に `{p}` も地名も漏れないこと、**どの言語でも** `{p}` が埋まること
（`.replace()` を英語の文だけに当てる書き方なら、残り 8 言語に `{p}` が残る）。

本番同等のローカル build（1280×860）で実際に押した: News →「Details (2 sources)」→「Ask Atlas」
⇒ Atlas が «Hong Kong Follows Fed With First Rate Hike in Over Three Years» / «Reuters +1 ·
2026-09-17 · Federal Reserve Board» / 3 チップ（背景・場所を地図に・出典の一致）で開き、
入力欄は空のまま。続けて地図の右クリック → Actions → Ask Atlas ⇒ 📍 36.784, -77.387 と
点の 3 チップ。**同じ builder で 2 つとも正しく描かれ、6 つのチップすべてに配線があった。**
