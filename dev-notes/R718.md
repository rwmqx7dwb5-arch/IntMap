## R718 — 門の判定がプラットフォームに依存し、どちらの判定も本物だった

〈利用者報告: `npm run check:agents`（`scripts/agent-sync.mjs` の `doc-size`）が Windows と CI で
違う判定を出す〉

### 1. ⚠⚠⚠ 緑の CI が、切り落とされた規程を隠していた

**実測 2026-09-14（`origin/main` = `ea7664a1`）:**

| 見ている側 | `AGENTS.md` のバイト数 | 天井 32,768 に対して |
|---|---|---|
| CI（Linux・LF） | 32,718（改行 465 本） | **余白 50 で緑** |
| このマシン（CRLF・**Codex が実際に開くファイル**） | **33,183** | **415 バイト超過** |

超過して落ちていたのは **§12（本ファイル自体の保守）の末尾**——つまり
**「この文書が長くなったときに何をすべきか」を書いた節が、長すぎることによって消えていた。**

`.gitattributes` が LF に固定しているのは **Linux で実行・解析される拡張子だけ**
（`*.sh` `*.sql` `*.mjs` `*.yml` `*.yaml` `*.toml`）。**`*.md` はそこに無い**ので
`core.autocrlf` が決め、同じコミットが 2 つのサイズになる。
**どちらの判定も、自分の走っている環境については正しかった。**

### 2. ⚠⚠⚠ #R283 の正規化は、ここでは誤答である

`scripts/eol.mjs` は「検査の主題は**内容**であって、改行はチェックアウトの性質だから」
正規化する（#R283）。**この門はその例外**で、理由は 1 つ:

> **この門の主題はチェックアウトのバイトそのものである。**
> Codex はファイルシステムが渡したバイトを数え、復帰文字はその 1 つ。

`lf()` を当てれば判定は**可搬になるのではなく、誰も訊いていない問い**
（「別の保存の仕方なら入るか」）に答えるようになり、このマシンの読者は §12 を失ったままになる。

⇒ **正規化もせず、走っている環境も信じない。** 測るのは**適合するチェックアウトが作りうる最悪値**
＝ `LF のバイト数 + 改行の本数`。中身から導出されるので **Linux でも Windows でも同じ数**で、
**どの読者が見るバイト数より小さくなることが無い**。

実装は `scripts/eol.mjs` の `crlfBytes`——**新しいモジュールを作らず、例外を規則の真横に置いた**。
#R283 の理由でその文書に来た読者が、両方向を一度に読む。

**規則を否定形で:**
**復帰文字が主題の手前の雑音なら正規化する。主題が「読み手に何バイト渡るか」なら数える。**

### 3. 余白は、数を上げずに §11.3 を移して回収した

`AGENTS.md` §12 が要求しているとおり（「足す前に正本を疑う」）、
**§11.3「スクリプトが守っていること」（3,578 バイト）を
[`docs/AGENT-SETUP.md`](docs/AGENT-SETUP.md) §10 へ移し**、`AGENTS.md` には 1 行の案内だけを残した。
**マシン・製品固有の詳細を持つのはその文書**であり、#R628 が Edge Function の名簿を
同じ理由で同じ場所へ移した前例がある。

**余白 −415 → +2,805 バイト**（最悪値 29,963 / 32,768）。

### 4. ⚠⚠ 節が動くと、その節を守っていた検査の**母集合**も動く

`tests/r260-checks.test.mjs` ② は約 30 の条項が
`AGENTS.md + scripts/backup-usb.ps1` に在ることを主張しており、
**そのうち 13 が §11.3 に住んでいた**（④ の「同期方向」「USB を作業元にしない」も同じ）。

#R260 が確立したのは「各条項が**書かれている**」ことであって
「`AGENTS.md` に書かれている」ことではない。⇒ **母集合を「手順を運ぶ文書の集合」に述べ直し**、
移った先の文書を足した。⚠ **条項を消して通すことだけは禁じる**——
それは #R260 が捕まえるために作られた無言の喪失そのもので、**着地先を見るまで移動と区別がつかない**。
だから `AGENTS.md` §11.3 が**移った先を名指していること**も同じ検査が主張する
（名指さない「移動」は、誰も開かない場所への削除と同じ）。
⚠⚠ **そして母集合を追わなければならない検査は 1 本ではなかった。** 段 3（`npm test`）で
`tests/r282-checks` (5) が落ちた——**§11 のどこかで USB ミラーを「原本が merge 後の状態か」で
ゲートしていること**を主張する検査で、その文は §11.3 の中に住んでいた。
#R280 のコメントが「**節は番号ではなく主題で引く**」と明示しているとおり、守られていたのは
**節の場所ではなく順序という事実**である。

⇒ **検査を緩めず、事実を正しい節へ置いた**: 「原本を先に最新化し `master-sync.mjs --check` が
exit 0 を返してから走らせる」は**いつ走らせるかの話**なので `AGENTS.md` §11.2（＝スクリプトを
起動する節）に置き、移設先 §10 からは同じ指示を削って §11.2 を指すだけにした。
**2 か所に同じ順序を書かない**（§9）。

⚠ **教訓は §4 と同じ形で、1 段深い**: 節を移したら
「**その節の文字列に依存している検査**」を全部探す。`r260` は依頼で名指されていたので見つけたが、
`r282` (5) は**全件テストが見つけた**——段 3 を省いていたら、緑の PR で着地していた。

### 5. 検査（`tests/r718-agents-doc-size-checks.test.mjs` 6 本）

- ① 同じ文の LF 綴りと CRLF 綴りが**同じ数**になる（非 ASCII を含む）
- ② **正規化していない**——改行 1 本につき 1 バイト増える
- ③ 実測された `ea7664a1` の形（LF 32,718・改行 465）が **33,183 と判定され落第する**
- ④ 門が**実際にその数を印字する**（`scripts/agent-sync.mjs` を**走らせて**読む。#R505）
- ⑤ 天井 32,768 が 3 文書で述べられており、失敗文が「数を上げるな」と言い続けている
- ⑥ 不変条件の正本が 1 つ（`AGENT-SETUP.md` §10）で、`AGENTS.md` §11.3 は**写しを持たない**

⚠ **④ の変異は Linux でしか見えない。** CRLF のチェックアウトでは
「ディスク上のバイト」と「最悪値」は**定義により同じ数**なので、原理的に区別できない。
**実測で確かめた**: `AGENTS.md` を LF に打ち直して（＝ Linux のチェックアウト）
門を戻すと緑、`bytes = disk` に変異させると**赤**。
**バグが緑だった走者と、検査が赤くなる走者は同じである。**
