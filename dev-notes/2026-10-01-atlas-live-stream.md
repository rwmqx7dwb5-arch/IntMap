〈依頼〉「求めるのは修正ではなく革命・改革。整形ではなく造形」（全面委任）。主題: Atlas を「考え終わってから一度に出す」ものから「読み・描き・答えるのが見える」ものへ。ai-proxy から provider（OpenAI Responses・Anthropic・Gemini）のストリームを SSE で中継する（台帳と上限の数え方を壊さない）／文章を流しながら描き、各道具呼び出しの開始と完了を地図の上で同時に見せる／中断・再接続・途中失敗で観測器が嘘をつかない／体感の待ち時間（最初の文字・最初の描画）を前後で測る／Edge Function を本番へ配備／文書と記録。

## 0. 測った

**構造（コードから）**
- `#R723` の実測: 6 操作のターンが 57.2 秒、うち操作は 13.6 秒。残り約 43 秒はモデルの往復で、読者が見ていたのは「考え中」の 1 語。
- ストリームの実装は 0 本: `js/ai-core.js` は `r.json()`、ai-proxy は提供元に 1 つの完成した本文を頼み、**`_shared/relay-guard.js` の `fetchBounded` は本文を全部読んでから** Response を返していた（期限を本文の最後のバイトまで効かせるため・#R801）。
- 読者が読む文は厳格な JSON（`FINAL_SCHEMA`）の `final_text` の中にあり、全体を parse するまで出せない。⇒ **読者が見る最初の文字は、そのターンが最後に作るものだった**。
- 一方で `FINAL_SCHEMA` は `#R663` 以来 `turn` → `answer_mode` → `final_text` の順に生成される。**文が答えか途中の一言かは、文より先に分かる**——ストリームで読むための宣言がすでにあった。

**本番・前（旧クライアント、2026-10-01、ログイン済みの Claude 用アカウント、外部計測器）**

計測器はページの DOM だけを見る（新旧で同じ定義）。`firstVisible`＝Atlas が書いた最初の文字（泡の文・作業一覧の「途中の一言」・考え中の行の詳細）、`firstOpDone`＝最初に終わった操作の行、`end`＝ターンの完了。旧クライアントでは回答は最後に一度に描かれるので `firstVisible = firstAnswer = end`。

## 1. 作ったもの

**サーバ（ai-proxy）**
- `stream: true`（protocol 2 の `atlas_turn` だけ）を受けると、提供元にもストリームで頼み、`text/event-stream` で `open` → プレビュー（`think` / `text` / `call` / `search` / `reset`）→ **`done` 1 つ**を返す。`done` は `{status, body}` で、**同じ要求をストリームなしで送った応答そのもの**。
- 応答部（提供元呼び出し〜払い戻し）は `answer(sink) → {status, body}` という値を返す関数になった。素の要求は `json(body, status)`、ストリームは `done` で同じ値を送る——**2 つが違う答えを返す余地が無い**。
- **提供元の本文は 2 回読む**（新 `_shared/ai-stream.js`）: 届く間はプレビュー、届き切ったら**非ストリームの終点が返す本文へ畳み戻して**既存の解析器へ。OpenAI は終端イベントが本文そのもの、Anthropic は部品から組み直し（tool_use の引数・citations・usage を合成）、Gemini は同種の part を連結。ストリーム用の第 2 の解析器は書いていない。
- `fetchBounded` / `readCapped` / `providerFetch` に `onChunk`（2xx の本文を読むそばから渡す観測者）を足しただけで、期限・バイト上限・返す Response は不変。
- ストリームの中で提供元が述べた失敗（`response.failed`・Anthropic `error`・Gemini error chunk）は HTTP の失敗と同じ `classifyGemini` が分類し、**それまでに課金されていた使用量**（`partial`）を meter に載せる。終端の無いまま切れたら `provider_unavailable`。
- **推論の要約**（OpenAI `reasoning.summary:"auto"`）はストリームのときだけ頼む。拒まれたら（組織の検証が要る）400 の梯子の**最初の段**でそれだけ外し、isolate が覚えて次からは頼まない。Gemini は `includeThoughts`（`thought` part は今までどおり答えから除く）。
- 無言の間は 15 秒ごとに SSE コメント。読者が切断しても書き込みが止まるだけで、提供元の呼び出し・使用量の記録・精算／払い戻しは最後まで行う（`EdgeRuntime.waitUntil`）。

**ページ**
- `js/ai-core.js` `aiReadStream`: SSE を読み、プレビューを呼び出し側へ、`done` を Response に戻して**従来の行に渡す**（401・2 つの 429・型付きエラー・protocol 2 の検査は同じ行が読む）。`done` の前に切れたら**同じターン鍵で 1 回だけストリームなしで**頼み直す（観測された失敗のあと・違う頼み方。読者の枠は二重に消費されない）。停止は頼み直さない。
- 新 `js/atlas-live.js`: 返答の JSON を届いた順に読む小さな走査器（深さ・文字列・エスケープ——`\u` が 2 つの差分に割れても——を跨いで保持し、トップレベルの文字列値を**書かれている最中に**出す）。`turn:"continuing"` や同じ返答の中の関数呼び出しが見えたら文は**作業一覧の「途中の一言」行**へ、そうでなければ**泡の下書き**へ（キャレット付き）。推論の要約の見出し → 「次: …」を考え中の行の詳細へ。
- **地図の上の HUD**: いま走っている操作と ✓／✗。行は実行器の `started` からしか開かない（プレビューは地図に何も置かない）。位置は**実測で決めた**——最初の版は上中央で、スクリーンショットでは検索バー・エンジン切替・凡例の下に隠れて輪だけが見えていた。デスクトップは下中央（左下は座標、右下は Chronos）、携帯は Atlas のシートが下を覆うので上端。
- `js/atlas-progress.js` に `detail` / `say` / `sayText`。「途中の一言」行は歩数に数えない。
- 実行器の終端イベントが `produced` を運ぶ（最初の描画の時刻を測るため）。
- `window.IntMapAtlasDebug.latency()`: ターンごとに依頼からの ms で `firstVisible` / `firstThought` / `firstAnswer` / `firstCall` / `firstOp` / `firstDraw` / `answer` / `end`。

**変えていないもの**
- `js/atlas-agent.js`（ループ）は無変更——**ストリームを知らない**。プレビューで何かを決める経路を作らないため（検査が守る）。
- 台帳の順: 消費は本文の前、精算は `done` の前、失敗は払い戻し。上限（`TURN_MAX_CALLS`・`MAX_FN_TOOLS`・期限・プランの枠）は 1 つも動かしていない（`CONSTITUTION.md` §5）。
- 観測器（`OBSERVERS`）は実行された操作だけを判定する。ストリームの何も観測器に届かない。

## 2. 中断・再接続・途中失敗で、誰も嘘をつかない

| 起きたこと | サーバ | ページ |
|---|---|---|
| 提供元がストリーム中に失敗 | 分類して払い戻し、課金済みの使用量を記録、`done` は 503 | 型付きのエラー。下書きは消える（答えではなかった） |
| 提供元への再要求（梯子・空応答・Web 期限） | 何か見せたあとなら `reset` | 見せたものを取り下げる |
| `done` の前に接続が切れた | 最後まで走って精算 | 1 回だけストリームなしで頼み直す（`streamRetried`） |
| 読者が停止 | 最後まで走って精算 | 下書きは**未完と明示して**残る（破線・キャレット無し）、答えとしては記録しない |
| 関数の名前だけ届いた | — | 「次: …」と言うだけ。行・HUD は実行器が開く |

## 3. 採らなかった案

- **引数が揃った呼び出しの先行実行**: ストリームが後で失敗すると、モデルが一度も受け取らない結果が地図に残る（「誰の手か」を観測器が言えない操作）。OpenAI の出力順は推論 → 文 → 呼び出しで、呼び出しは末尾にまとまって届くので縮む時間も小さい。
- **ストリーム専用の解析器**: 呼び出し item・使用量・失敗の分類・梯子が 2 系統になり、どちらが効いたのか言えなくなる。畳み戻して既存の 1 本に渡す。
