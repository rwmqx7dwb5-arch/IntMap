## 0. 再現した（直す前に測った数）

- **地名検索**: 「Kyoto」で京都市と京都駅がどちらも「Kyoto, Kyoto Prefecture, Japan」。Photon のラベルは

  ラベルは「Kyoto, Kyoto Prefecture, Japan」と「Kyōto, Kyoto, Kyoto Prefecture, Japan」（名前と等しい市を
  落とすかどうかだけの差）。2026-09-27 に 3 提供者の応答を取り直し、Photon が `district`（Minami Ward /
  Shimogyo Ward）・`locality`、Open-Meteo が `admin2〜4` を返すことを確かめた。
- **コントラスト**: 1280×800・ライトで選択中の Satellite / Globe は `rgb(0,122,255)` 12 px / 500 を白の上
  ＝ **4.02:1**。画面に出ているアクセント色の文字はこの 2 つだけ（全要素を走査）。
- **フォーカス**: Tab で `#search-input` に来たとき、欄自身は `outline:none`、ピルは 0.15 s の遷移のあと
  1 px の枠色＋3 px・18 % の光輪（白の上で 1.2:1）。並べ替えの `select` は `outline:none` で、`:focus` の
  1 px の枠色だけ。⚠ 最初の計測は遷移の途中を読んでいた（ピルの影が `0 0 0 0` と出た）——遷移を待つか
  `getAnimations().finish()` してから読むこと。
- **placeholder**: 初回訪問（右のレイヤーパネルが自分で開く）の 1280×800 で、ピル 203 px・欄 105 px に
  「Search any place on Earth...」185 px。試験の既定の保存状態は `lsrOpen:false` なので、そのままでは
  欄 282 px で**再現しない**——初回訪問の状態を明示して初めて見えた。
- **帰属表示**: 375×812 で `© Esri` のリンクは 17.6×12.0 px、ピルは 23.0 px。リンクの中心から 24×24 の
  四隅を `elementFromPoint` に訊くと 0/4。

## 1. 直したもの

1. **検索の行の 2 行目（`.ms-kind`）**: `js/search-geocode.js` の `_paint` が、行ごとに既に計算している
   `placeClass` を `js/place-framing.js` の新しい `classNames()` で名前にして添える。名前は `PLACE_ZOOM` の
   全キーに en＋jp（`pickArgs` の呼び出しなので i18n の監査が数える）。**名前はその分類が入れているもの
   全体を述べる**——`station` は railway=* 全部なので「Station / railway」、`landmark` は tourism=* を含む
   ので「Tourism / landmark」（ホテルを「名所」と呼ばない）。同じ種別で名前が畳むと同じになる行が他にも
   あるときだけ、提供者の行政の連なり（`raw.within`：Photon は county・city・district・locality、
   Open-Meteo は admin2〜4、粗い順）からラベルに無く相手に無い最初の地名を足す。到着のたびにカード全体を
   塗り直す（相方が後から来る）。束ね方（`_sameFeature`）は変えていない。
   ⚠ 英語の鍵の衝突が 3 つ出た（「City」＝都市・「Municipality」＝所在地・「Museum」＝博物館が既存）。
   City は既存の「都市」に合わせ、残り 2 つは別の英語（「Municipality / commune」「Museum / gallery」）にした。
2. **アクセント**: ライトの `--primary-color` を `#007aff` → `#0071e3`（同じ色相、ΔE00 4.6。白に対して
   アクセント文字でも白文字でも 4.70:1）。アクセントを文字色にする CSS の規則 43 本と、白文字のアクセント
   塗りは全部このトークンを読むので、1 か所で全部が変わる。ダークは据え置き（`#0a84ff` は `#1c1c1e` に
   4.66:1、ダークの選択中セグメントは `#111` on `#fff`）。
3. **フォーカス**: テーマ定義の直後に `:where(…):focus-visible{ outline:2px solid var(--focus-ring) !important;
   outline-offset:2px }` を 1 つ。`!important` は基底に書かれた `outline:none`（特異度 (0,4,1) まで）に勝つため、
   offset は非 `!important`・一覧は `:where()` なので、自前のリングを持つ部品は offset を保つ。
   枠の無い欄を持つ検索ピル（`.search-bar`・`.map-search`）は欄にリングを描かず、ピルの `:focus-within` が
   1 px の枠＋1 px の輪で 2 px のアクセントの縁を描く。`--focus-ring` はアクセントで、カードに対して
   ライト 4.70:1・ダーク 4.66:1（非テキストの基準 3:1）。
4. **placeholder**: `js/mobile-ui.js` のピルの見張りの隣に、欄の実幅と計算済みフォントで文を測る見張りを 1 つ。
   `js/i18n.js` が書いた全文が入らなければ「Search places」／「地名を検索」。それでも入らなければ
   `text-overflow:ellipsis`。言語の切り替えは `MutationObserver` で受ける。ピルを広げる（操作部品の下に
   潜る。#R25/#R484）・2 段目に落とす（#R122 が止めるよう頼まれた）はどちらも取らなかった。
5. **帰属表示**: 携帯の `.map-credit a::after` に文字中心の `max(100%,24px)` 四方の透明な当たり判定。
   ピルは `overflow:visible` に（切り取られた箱は当たり判定も切り取られる）。見た目のリンクは 17.6×12.0 px の
   まま、四隅と上下辺の中点が 6/6 で当たる。

## 3. 直さなかったもの・残っているもの

- ⚠ **Chromium はマウスで押した `<select>` も `:focus-visible` とみなす**（実測：同じ操作でボタンは
  fv=false、select は fv=true）。文字を打つ欄と同じ扱いで、Firefox と Safari はそうしない。この規則は
  ブラウザの判断に従うので、Chromium で並べ替えの select をクリックするとリングが出る。消すには
  「最後の入力がポインタだった」をページが覚える小さな JS が要る。文字を打つ欄も同じ理由で
  クリックでリングが出る（検索ピルは以前からクリックで縁が出ていた）。**判断: 標準の挙動として受け入れ、
  JS は足さない。** `#0071e3` への変更も受け入れられた（その後 §4 で `#0069db` へ）。
- ~~ダークで白文字のアクセント塗りは 3.65:1~~ → §4 で直した。
- ~~ライトの灰色の面の上のアクセント文字 4.31 / 4.20:1~~ → §4 で直した。
- 利用者が設定で選ぶアクセント（オレンジなど）はその値のまま使う（範囲外・記録のみ）。
- JS の中で `color:var(--primary-color)` を書く約 110 か所もトークンを読むので値の変更は届いている。
- GeoNames の AIRH（ヘリポート）・PRK（公園）は `placeClass` が答えないので 2 行目を書かない（種別を
  名乗れない行に種別を書かない）。

## 4. 続き: アクセントの役を 2 つのトークンに分けた（文字 `--primary-color`／面 `--primary-fill`）

〈依頼〉残ったコントラストの 2 件を、トークンの役割を分けて直す。

- **測った**: ダークで白文字を載せるアクセントの面は `#0a84ff` で 3.65:1。暗いカードの上の文字として 4.5:1 を
  超えるには相対輝度 0.228 以上、白文字を載せて 4.5:1 には 0.183 以下が要り、**1 つの値では両立しない**。
  ライトの灰色の面は、アクセント文字の規則ごとに「その規則か、その状態（:hover・.has・.on …）の元の規則」の
  背景をスタイルシートから読んで洗った: `--input-bg` の上に `.stats-filter-btn.has`（常時の状態）と
  `:hover` 5 つ（`.stats-sort-dir`・`.stats-filter-btn`・`.co-detail-btn`・`.rad-act`・`.ntl-bstep-b`・
  `.compose-img-btn`）。主要な 5 画面（既定・News・Info・Countries・設定）を実画面で走査したときは、
  出ていたアクセント文字（切替 2 つ・ニュースの出典名 27）は全部白い面の上だった。
- **直した**:
  1. `--primary-fill` を新設。ライトは `var(--primary-color)`、ダークは
     `color-mix(in srgb, var(--primary-color) 85%, #000)`（既定で `#0970d9`、白文字 4.85:1、`#0a84ff` から
     ΔE00 8.2）。混ぜて導くので利用者の選んだアクセントも面では色相を保つ。
  2. **アクセントで背景を塗る箇所を全部 `--primary-fill` へ**: CSS 90・JS のインライン style と style 代入
     （`b.style.background=act?'var(--primary-color)':…` の形を含む）32 ファイル・index.html 1——189 か所。
     同じ規則／同じ 1 行の style で枠を同じアクセントにしていたものは枠も面に揃えた（ダークで 1 px 明るい縁が
     出ないように）。ライトでは値が同じなので見た目は変わらない。
  3. ライトの `--primary-color` を `#0071e3` → **`#0069db`**（同じ色相。白 5.19:1・`#f5f5f7` 4.77:1・
     `#f2f2f2` 4.64:1、白文字の面としても 5.19:1）。**ΔE00 は `#0071e3` から 3.0、元の `#007aff` から 7.4。**
     `#006bdc`（ΔE00 2.3）でも `#f2f2f2` は 4.53:1 を超えるが、余白が 0.03 しかないので 1 段濃くした。
- **検査**: `tests/ui-a11y-polish-checks.test.mjs` に ⑥（js/・css/・index.html 全体で、背景を文字用の
  トークンで塗る箇所が 0 件／白文字の面が両テーマで 4.5:1 以上）と ⑦（アクセント文字が載る灰色の面を
  規則から見つけ、`--bg-color` と合わせて全部 4.5:1 以上。色は `color-mix`・`rgba` の合成まで計算する）を足した。
  **直す前（wip commit の木を `git archive` で展開）に ⑥⑦ が赤**（⑥ は 180 余りの箇所を列挙）、後に 12 件全部緑。
  ③④ も合成した実際の色で測るように書き直した。
- **残っているもの**: アクセントで**薄く色づけた**面の上のアクセント文字は灰色の面ではないので ⑦ の範囲外にした。
  `.ev-badge.first`（`rgba(0,122,255,0.14)` の上、10 px 太字）はライト 4.33:1・ダーク 4.03:1、
  `.mon-evchip`（`#0a84ff` 固定の文字を同じ色の 10 % の上）はライト 3.23:1。どちらも色が直書きで
  トークンを読んでいない。直すなら色づけの面を `color-mix` でトークンから導き、濃さを測って決める。

## 5. 淡く色づけた面の上の文字（統合時に追加）

§4 が範囲外として記録した 2 つ——`.ev-badge.first`（初報バッジ。ライト 4.33:1・ダーク 4.03:1）と
`.mon-evchip`（証拠チップ。ライト 3.23:1）——は、どちらも色を直書き（`rgba(0,122,255,…)`・`#0a84ff`）していた。
アクセントから導くトークンを 2 つ足した: `--primary-tint`（アクセントの 12 %）と `--primary-on-tint`
（アクセントを本文色へ 25 % 寄せた文字色）。両テーマで、カード・ページ背景・パネルの上の全てで 5.1:1 以上
（ライト 6.02 / 5.56 / 5.11、ダーク 5.46 / 7.05 / 5.95）。文字色を本文色へ寄せるので、利用者が選んだ
アクセントでも同じ向きに強くなる。検査 ⑧ がトークンの使用と比を両テーマ・2 面で述べる。
