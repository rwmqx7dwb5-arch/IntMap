〈依頼〉 deep tier の r169 を調べた別の作業の観測: `js/auth-ui.js` の認証イベントから呼ばれる `startNews()` が、ニュースタブを開いた約 3.3 秒後に一覧を最初の 30 件へ描き直す。起動直後に読み進めた位置と、`appendNewsBatch()` で進んだ `renderedCount` が失われる。

## 0. 再現（修正前、2026-10-01、このマシン・hermetic の Playwright）

- 75 件をキャッシュに入れて起動 → `#btn-news` → 底までスクロールして 2 つ目の束（60 件）→ 本物の supabase-js `SIGNED_OUT`（`window.sb.auth.signOut()`）。
- **前: 60 件・見ていたカード #18 → 後: 30 件。** フィードを空にする書き込みに stack を取ると、1 回の `SIGNED_OUT` で **2 回**（12 ms 差）: 認証リスナーの直接の `HOST.startNews()` と、続く `HOST.renderUI()` の News 分岐の `startNews()`。
- 未ログインでも起動時に `INITIAL_SESSION` が来る（この環境では約 260 ms、タブを開く前）。deep tier の「開いて約 3.3 秒後」は同じ経路が遅い機械で後ろへずれたもの——ここでは時刻に依らず本物の認証イベントで再現した。

## 1. 原因

認証状態が変えうるのは★の状態（`HOST.bookmarks`／出来事の保存）と、Saved スコープの中身（`loadFavorites()` がゲストの★をアカウントへ合流させる）。**News スコープの一覧そのもの（項目と順）は変わらない。** それでも `startNews()` は呼ばれるたびに無条件で `feed.innerHTML=''; renderedCount=0` として最初の束だけを描いていた——呼び手が何であれ、描き直しを「リセット」として実装していた。

## 2. 直したもの

- `js/news-feed.js` `startNews()`: 描き直す前に**画面のカードが今の絞り込み結果の先頭 N 件そのものか**を確かめ（DOM の子が `newsFiltered[0..N)._cardEl` と一致し、個数が `renderedCount` と一致）、新しい結果の先頭 N 件が**同じ項目・同じ順**（同一性は★と同じ: 出来事は `publicId`、記事は `link`）なら、N 件まで描いて**見ていたカードを同じオフセットへ戻す**。先頭が変わった一覧（新しい検索・カテゴリ・先頭の新着）は従来どおり先頭から。
- カードは作り直す（DOM をそのまま残す「もう済んでいる」形は採らなかった）。カードの文面は言語・日付書式・★の状態にも依り、それを「変わりうるもの」の一覧で持つと、カードが設定を 1 つ多く読んだ日から誤る（`.agents/rules/no-ad-hoc-hardcoding.md` §2-4）。同じ入力での 2 回目は読者から見て何も変えない（冪等）。
- `js/auth-ui.js`: 認証リスナーの直接の `startNews()` を外した。`renderUI()` の News/Saved 分岐が必ず呼ぶので、1 回の認証イベントで 2 度描いていた（`.agents/rules/one-pass-or-a-reason.md`）。
- 修正後の実測（同じ手順）: **60 件のまま・見ていたカード #18 がオフセット −36 px のまま**、フィードを空にする書き込みは 1 回。

## 3. 検査

- `tests/news-list-keeps-position-checks.test.mjs`（新規・7 件）: 本物の `startNews()` を小さなレイアウト模型（固定高のカード・clamp される `scrollTop`）で評価。変異（位置を戻す 1 行を無効化）で 3 件が赤になることを確かめた。
- `tests/r169.spec.js` #3b（既存 spec に 1 本）: #3 の 45 件の状態で本物の `SIGNED_OUT` を起こし、45 件と見ていたカード・オフセットが残ること。変異で `Expected 45 / Received 30` を確かめた。spec ファイルは増やしていない（`check:testbudget`）。

## 4. 残したもの（今回の依頼の外）

- 3 分ごとの背景取得（`fetchData({background:true})`）が**先頭に新着を持ってきた**ときは、一覧の先頭が変わるので従来どおり先頭へ戻る。読んでいる項目の同一性で位置を合わせることはできるが、「読者が問いを変えた（検索・カテゴリ）」と「背景で中身が増えた」を `startNews()` は区別できないので、呼び手の意図を渡す変更になる。提案として残す。
- 読む面（`#news-reader-pane`）が開いていて一覧が隠れている間の認証イベントは、深さは残るが位置は測れない（隠れた要素は矩形を持たない）ので、`scrollTop` の値だけを戻す。
- 認証リスナーは `renderUI()` の前に `loadCommunity()` も直接呼んでおり、Community タブでは `renderUI()` がもう一度呼ぶ——同じ形の二重呼び出し。今回は触っていない。

## 5. 追記 — main の CI で #3b が赤（run 36783323529）。誤っていたのは spec の観測で、製品ではなかった

- **観測**: PR では緑、merge 後の main の push（Linux・Browser rest 2/2）で 1 回目も再試行も赤。1 回目「the reader is on the same card」**Expected #25 / Received #30**、再試行「at the same offset」51 px。件数 45 は通っていた。
- **再現**（このマシン、CDP `Emulation.setCPUThrottlingRate` 4・`--workers=4 --repeat-each=5`）: **5/5 赤**。`before` は**毎回 #25**、`after` は #30・#32・#33・#34。
- **原因**: spec が読者を置く `f.scrollTop += …` は位置への書き込みではない。フィードは `.content-area`（`scroll-behavior:smooth`）なので、#3 が残した #25 から目標の #34 への**飛行を始めるだけ**で、`before` はその出発点を読んでいた（同じ罠を #3 のコメントが自分で書いている）。`after` は認証イベントの描き直しが走った瞬間の飛行の途中。出発点と途中の点を比べても描き直しの検査にならない。
- **製品側の切り分け**: 落ち着いた位置（`behavior:'instant'` で #21・オフセット 12 px）から同じ ×4 で本物の `SIGNED_OUT` を起こすと、描き直しの前後で `scrollTop` 2151・先頭カード #21 が変わらず、scroll イベントも 0（3 回）。`startNews()` は空にする・満たす・戻すを 1 タスクで行い、その間にレイアウトが無いので位置は動かない。カードに画像は無く（`appendNewsBatch` の出力。画像は読む面の `nrp-hero` だけ）、描き直しの後に高さが変わる入力も観測されなかったので、ResizeObserver による追従は足していない（根拠の無い機構になる）。
- **直したもの**（`tests/r169.spec.js` #3b のみ）: 読者を `scrollTo({…, behavior:'instant'})` で #34 に置き、`before` が #34 であることを先に確かめる。待ちは時間（変異後 300 ms・5 秒の逃げ道）ではなく**描き直しそのもの**——MutationObserver の最初の通知で解決し、描き直しが起きなければ赤（以前は 5 秒後に描き直されていない一覧を自分と比べて緑になりえた）。
- **修正後**: ×4・`--workers=4 --repeat-each=6` で r169 全 12 本 **72/72 緑**、×6・`--workers=8 --repeat-each=8` で **96/96 緑**。変異（`_restorePlace` の呼び出しを外す）で #3b は **Expected #34 / Received #25** と赤になることを確かめた。`tests/news-list-keeps-position-checks.test.mjs` 7/7 緑（変更なし）。
- **残したもの（今回の依頼の外）**: 読者自身のスムーズスクロールが**飛行中**に描き直しが来ると、Chromium は飛行を止める（×4 の実測で、出発直後なら #21 のまま、途中なら途中の位置で止まる）。`startNews()` は止まった瞬間の位置を正しく保つが、飛行の続きは失われる。原因は一覧を空にして満たし直すこと自体（戻す書き込みを「差分が 0.5 px 未満なら書かない・書くなら instant」にした試作でも、書き込み 0 回のまま飛行は止まった。試作は根拠が無いので採らず元に戻した）、直すにはカードをその場で置き換える形へ `startNews()`／`appendNewsBatch()` を変える必要がある。提案として残す。
