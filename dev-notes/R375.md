## R375 — **国は正しく同定されていた。表のほうが、5年ぶん幾何より小さかった**

依頼は本番で実測された 1 件——「Atlas のスターターチップが、シンガポールでは国別プールではなく世界プールの
4 文（「日本・ドイツ・インドを比較」など）になる」。

### 1. 報告そのものが、真因を1段まで絞っていた

#R392 の本番検証は、この報告について**普通なら真っ先に疑う2つを、先に潰してあった**——

- 本番ページ内で出荷アルゴリズムを走らせて `codeAtPoint(103.85,1.29)` → **`'SGP'`**、`(103.82,1.35)` → **`'SGP'`**。
  **国の同定は成功している。**
- z=11 も z=13 も `js/atlas-examples.js` の `z>=2.5` の床を越えている。**ズーム床でもない。**
- それでもチップは世界プールで、しかも **`redrawn=true`**。**「古いチップが残っている」でもない。**

残るのは `exFacts()` の中の 2 行だけだった。

```js
const st = near ? countryStats[near] : null;
const nm = st ? cName(st) : null;        →  usePlace = !!(f && f.st && f.name)
```

`near` は `'SGP'` なので、**`countryStats['SGP']` が無いか `cName` が空を返すか**の二択。検証者はここで止まって
いる——`countryStats` はモジュールスコープで `window` に無く、ブラウザから中身を測れないからで、これは
正しい停止だった。

### 2. 真因は #R195 で、その根拠の文が真因そのものだった

`js/countries-ui.js` の履歴を引くと、`if(!s) return;` を入れたのは **#R195（`01d1821`）** の 1 コミット。
それ以前の読み込み順は

```
10 m を取る → 失敗したら 50 m → 失敗したら 110 m      （粗い側は「落ちたときの代役」）
```

で、表は常に 10 m から作られていた。#R195 はこれを反転した——**4,335 KB が 2,024 ms から始まり、既定の起動
では 1 ピクセルも描かれない**という正しい実測にもとづいて、「**属性**は 110 m から作り、**幾何**だけを idle
後に 10 m へ差し替える」に。その根拠はファイルの中にこう書いてある:

> The attributes are identical at every Natural Earth scale.

⚠⚠⚠ **これは「地物について」真で、「ファイルについて」偽である。** 今回 CDN の実物を数えた:

| ファイル | features | 導出できるコード |
|---|---|---|
| `ne_110m_admin_0_countries.geojson` | 177 | **177** |
| `ne_50m_admin_0_countries.geojson` | 242 | 240 |
| `ne_10m_admin_0_countries.geojson` | 258 | **252** |

**75 コードが細かいファイルにしか無い。** そしてアップグレードは

```js
best.forEach((v,code)=>{ const s=HOST.countryStats[code]; if(!s) return;   /* ← 純粋な enrichment */
  s.area=…; s.density=…; s.bbox=…; });
HOST.countryGeo=hi; window.countryGeo=hi;                                  /* ← 幾何だけが 252 に */
```

——**表は 177 のまま、幾何だけが 252 になる。** その瞬間から `codeAtPoint` は表に無いコードを答え始める。
起動直後（粗いファイルだけの間）は両者が**一致している**ので、食い違いは「idle 後に開く窓」だった。

### 3. 落ちていたのはチップだけではない（25 か所）

`countryStats[…]` のブラケット参照は js/ 全体で 100 行あり、**キーが幾何由来のもの**を数えると 25 行:

choropleth の値読み・ホバーツールチップ・`applyChoro` の**塗り値**（`js/data-layers.js`）、NATO と EU の
ホバーカード、`applyRimland`、データセンター詳細カード（`js/datacenters.js`）、時代境界の解決
（`js/time-borders.js`）、ニュースの国名フォールバック（`js/news-context.js`）、シルエットクイズ
（`js/analysis-edu.js`）、Atlas の 5 経路、そして `resolveCountryId` 自身（`js/app-body.js`——**表に在る
候補しか受理しない**ので、この欠陥を増幅する）。

⚠ **全員が「未知のコードは飛ばす」と書かれている**（`if(!s) return` / `continue` / `if(cs)`）。だから
**どの計器も何も報告しない。** 5 年間、誰も気づかなかった理由はこれで説明がつく。

さらに `js/news-context.js` は**索引を `countryGeo` から作り、名前を `countryStats` から引く**ので、この 75
については表示名が英語の `NAME_EN` に落ちていた。

### 4. 75 の内訳——「1 件直して終わり」にできる形ではなかった

| Natural Earth TYPE | 件数 | 例 |
|---|---|---|
| **Sovereign country** | **29** | SGP MLT MCO VAT BHR MDV MUS AND LIE SMR CPV COM SYC STP …＋小島嶼国 15 |
| Dependency | 26 | AIA ASM BMU COK CYM FRO GUM PYF SGS SHN SPM TCA UMI VGB VIR WLF … |
| Country（自治領） | 9 | ABW ALA CUW GGY **HKG** IMN JEY **MAC** SXM |
| Indeterminate | 8 | BJN BRT CNM KAS PGA SCR SER SPI |
| Disputed / Lease | 3 | GIB IOT USG |

モナコも同じ 75 に入っている（報告では「幾何側で `codeAtPoint` が `null`」として別扱いだったが、**仮に
同定できていても表に行が無い**ので、いずれにせよ世界プールに落ちていた）。

### 5. 直し方——`if(!s) return;` を消すのではなく、行を作る場所を1つにした

`countryStats` に**行を作る**箇所はリポジトリ全体で `js/countries-ui.js` の 1 か所しか無い（他はすべて
`if(!s)` で不在を飛ばす enrich）。**そこを逃したコードは、後続のどの pass も救わない。**

- 行の構築を **`_mkStat(f, code, area)` 1 本**に抽出し、**110 m の初期ループと 10 m のアップグレードの両方が
  これを呼ぶ**。どちらのファイルが供給したコードでも、同じ記録が同じ手順で作られる——**2 つの pass が
  二度と離れられない。**
- アップグレードは、行が無ければ **`return` せず作る**。在れば**従来どおり in-place で enrich**する
  （#R195 の ⚠ が書いているとおり、PPP・指標補完・時代機械が後から書き込んでいるので、まるごと差し替えると
  それを捨てる）。
- ⚠ **遅れて生まれた行は、先に走り終えた読み手に渡さないと永久に半端になる。** `_mergePPP` は
  `Object.keys(countryStats)` を **1 度**歩くだけで、`countryDataPromise`（＝粗いファイル）に鎖でつながれて
  いる。しかも **30 日の localStorage キャッシュ**から供給されるので、放っておくと**次のタブでも次の週でも、
  同じ粗い表に対して再生される**。payload を保持する **`reapplyPPP()`** を host contract に足し、行を足した
  ときだけ再生する（**merge の 2 本目の写しは作らない**）。Countries タブはデスクトップの既定なので
  （#R170）、開いていれば同時に描き直す。

⚠ **4 つの読み込み経路すべてで不変条件が成り立つことを確かめた**——(1) 110 m → 10 m アップグレード（本件・
75 件を作る）／(2) 110 m が落ちて 50 m → 10 m（**同じループなので 12 件を作る**）／(3) 両方落ちて 10 m を直接
（`coarse=false` でアップグレードは走らず、表も幾何も 252）／(4) アップグレードの取得が失敗（`countryGeo` は
粗いまま・表も粗いまま）。**幾何が動くときは表も同じ pass で動く**か、**どちらも動かない**かのどちらかになった。

⚠ **`exFacts` に `sov` ガードを足さなかった。** 新たに `sov:false` になるのは Indeterminate な 8 件だが、
**ノルウェーは今日すでに `sov:false`**（Natural Earth の `FCLASS_TLC` の癖）で、#R337 はそれと知って
ノルウェーのチップを書いている。ガードを足せば、直すのと引き換えに #R337 を壊していた。

### 6. 検査——「シンガポールが動く」ではなく、不変条件を、出荷ローダで

`tests/r375-checks.test.mjs`。⚠ **`countryStats` と `countryGeo` の両方を含むテストは、この時点で
リポジトリに 1 本も無かった**（最も近い `tests/r195-checks ⑧` は「まるごと差し替えるな」の検査で、
**むしろ「行を作らない」現状を固定する側に効いていた**）。

主張するのは **`countryGeo` の全 id が `countryStats` に行を持つ**こと——**国名も件数も Natural Earth の
縮尺も出てこない**、スケールフリーな不変条件。測り方は、`js/countries-ui.js` を **`new Function` で実際に
評価して出荷のローダを走らせ**、粗いコレクションと細かいコレクションを食わせる（＝欠陥が存在する唯一の
条件）。再実装を検査しているのではない。

10 本: ①不変条件／②報告された経路そのもの（`usePlace` が真になる）／③遅れて作られた行は起動時の行と
**フィールド集合が完全に一致**し、`CAPITAL`/`CURRENCY`/`GDP`/`HDI`/`LANGS` を実際に読んでいる／④#R23 の
`sov:false` は保たれる／⑤既存行は**同一オブジェクトのまま**で、後から書かれた値が生き残り、幾何由来の
フィールドだけが更新される／⑥#R15 の最大面積勝ち／⑦行を足したときだけ PPP を再生する／⑧⑨Ⓔ ソース側
（`codeOnly()` 経由——#R345）。

⚠ **欠陥を戻して赤くなることを確認した。** `if(!s){…}` を `if(!s) return;` に戻すと **10 本中 6 本が赤**。
緑のままの 4 本は、この変更が**壊していない**契約を主張しているもの（#R195 の in-place enrich、#R15、
host hook）で、そこが緑なのは正しい。

### 7. 残っている、この欠陥ではないもの

- モナコの `codeAtPoint` が `null` を返す件は**幾何側の別件**（`js/atlas-console.js` の `codeAtPoint` は
  `countryGeo.features` の**線形走査で最初に当たった地物**を返し、索引も最小 bbox のタイブレークも持たない。
  `js/app-body.js:2305` / `js/countries-ui.js:307` の turf 版は最小 bbox を選ぶので**挙動が違う**）。
  表の行はこのラウンドで生えたので、同定さえ通れば正しく答える。
- `package.json` の `test:checks` に `tests/r356-checks.test.mjs` が **2 回**入っている（並行ラウンドの
  マージ由来）。無害だが重複。
