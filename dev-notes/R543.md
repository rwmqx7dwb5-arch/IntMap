## R543 — **回答が見せられるのは地図だけで、数字はずっと文章のままだった**

依頼は「Atlas の出力で足りないものは？」という問いから始まり、答えたうちの
**画像に関わらないもの**を実装せよ、というものだった。

### 何がそこにあったか

#R511 は地図を「回答の**形式**」にした——Atlas が `answer_mode` で宣言し、宣言したのに描いていなければ
コードが差し戻す。**数字にはそれが起きていなかった。**

| | 地図 | 数字 |
|---|---|---|
| 回答の形式として宣言できるか | できる（`"map"` / `"mixed"`） | **できない** |
| 宣言を守らせる門 | ある（`map_not_drawn`） | **無い** |
| 返答の中に置く経路 | `map.compose` | **`js/atlas-sims.js` の弾道プロファイル 1 本だけ** |
| 能力表の `produces` 列 | `map` 66 件 | `chart` **0 件** |

値を出す能力（`data.rank` / `data.ratio` / `data.relate` / `data.query` /
`data.compareStats` / `data.timeSeries` …）は大量にあるのに、**それが絵になるのは 3 つのパネルの
どれかがたまたま開いたときだけ**だった。

### ⚠⚠⚠ 直しかたの中心は、チャートではなく門のほう

素直に足すなら「chart 用のフラグ」と「chart 用の差し戻し」を、地図用のそれの**隣に**置くことになる。
`CONSTITUTION.md` §5 がその積み重ねを名指しで禁じている——**「症状 1 つに機構を 1 つ足す積み重ねは、
Atlas ではそのまま回答品質の劣化になる（互いに矛盾する門が増え、どれが効いたのか誰にも言えなくなる）」。**

そこで実測から入った。`changedMap` を押している場所は 1 行しかない:

```js
if (ok && out.status === 'completed' && Array.isArray(out.produced) && out.produced.indexOf('map') >= 0) out.changedMap = true;
```

**`'map'` という文字列 1 つの直書きが、「地図だけが宣言を守らせられる出力」の正体だった。**
レジストリの `produces` 列は最初から一般形（`map,explanation` / `panel` / `camera` …）で、
この行がその**残りを捨てていた**だけである。⇒ `producedModes` として列をそのまま渡す。

結果、足したものは**門ではなく語彙**になった:

| `answer_mode` | 満たすもの | 差し戻しの型 |
|---|---|---|
| `"text"` | （何も要らない） | — |
| `"map"` | `map` | `map_not_drawn`（#R511 の綴りのまま） |
| `"chart"` | `chart` | `chart_not_drawn` |
| `"mixed"` | `map` **または** `chart` | `output_not_produced` |

⚠ **`"mixed"` は広がりであって狭まりではない**——#R511 が受理していた組み合わせは 1 つも拒まれない。
`tests/r543 ⑧` が両方向（`producedModes` 経由と、呼び出し元が自前の `execute` で立てる
`changedMap` 経由）で実測する。`gateBounces++` が**ファイル全体で 1 か所**であることを ⑨ が測る。

### レンダラ — 拒むことが仕事

`js/atlas-chart.js`（`chart.compose` / tool 名 `chart` / CORE の 9 本目）。
line・bar・scatter・**timeline** を **HTML 文字列**で返す。

- ⚠ **出所 (`source`) を宣言しないグラフは拒む。** グラフは主張が取り得る**最も信じられやすい形**なので、
  根拠を必ず伴わせる（`.agents/rules/no-ad-hoc-hardcoding.md` §2.2 を画素に適用——**コードの仕事は
  判断することではなく、根拠のないものを拒むこと**）。
- ⚠ **線と散布は実点 3・棒は名前つき 2・年表は日付つき 2 件**を下回れば、薄く描かずに**拒んで理由を返す**。
  数は `js/widget-render.js` が §2.6 として既に持っていたもので、理由も同じ——**「1 つの値から作った
  sparkline は、証拠の形をした装飾である」。**
- 目盛りは 1/2/**2.5**/5×10^k の nice-number。⚠ **`js/` にある唯一の目盛り生成器**で、既存 5 実装は
  どれも端点を 2〜4 個置くだけだった（2.5 が要るのは、無いと 0–100 が 4 区間を求めて 2 区間しか得ないから）。
- 数の整形は `Intl` のみ。色は `--chart-cat-1..10` の CSS 変数だけを書き、**この層は色を 1 つも
  知らない**＝ダークモードは token の入れ替えで済む。

### ⚠⚠⚠ `isFinite(+v)` は「これは数か」ではない

最初の `clean()` は `!isFinite(+p.y)` で欠損を弾いたつもりだった。**弾けていない。**
`+null` も `+''` も `+false` も `+[]` も **0 であり、有限**である。

つまり**報告されなかった値が「実測 0」として棒になり**、caption は「0 件落とした」と言う——このファイルの
ヘッダが名指しで禁じている〈計器が全部緑のままグラフが嘘をつく〉形そのものが、ヘッダの下で起きていた。
自分で書いた `tests/r543 ③` が捕まえた。⇒ **変換の前に不在を判定する。**

### ⚠⚠ 観測子は「描いたと言っているか」を訊かない

グラフは地図に何も置かないので `paintNow()` は前後で同じ数を返し、`paint` 観測子なら**全てのグラフを
`not_rendered`** と呼ぶ。かといって「レンダラが ok と言った」を根拠にすると、`js/atlas-capabilities.js` 自身が
禁じている〈legacy(raw) を唯一の証拠にしない〉になる。

⇒ 描いた点・棒・出来事に **`data-mark` を刻み**、`chart` 観測子が**返答へ渡る HTML の中の印を数えて**
レンダラの申告と突き合わせる。**空の図を `ok` で返せば `partial / not_rendered`**（描かなかった塗りに
`paint` が下すのと同じ評決）。⚠ 印を class ではなく**属性**にしたのは #R488——CSS の綴りを固定した検査は、
その規則が何にも当たらなくなっても緑のままだった。

### ⚠⚠ 翻訳の鍵を連結で組むと、計器に穴が見えないまま 4 言語が英語で出続ける

`L()` の第 1 引数（英語原文）は、fr / ko / zh-Hant / zh-Hans では**完全一致の鍵として inline 表を引く**。
ところが最初の実装は拒否理由 4 本と caption 1 本を**文字列連結**で組んでいた:

```js
L('a ' + kind + ' needs at least ' + MIN_TREND + ' real points; ' + all.length + ' arrived', …)
```

これは**どの表とも一致しない**ので、その 4 言語では永久に英語のままになる。しかも監査は**リテラルしか**
抽出できないため、**穴が計器に見えない**（母数が 5,560 のまま増えず、欠落として数えられない）。
⇒ リポジトリ既存の作法（`{n}` プレースホルダ ＋ `.split('{n}').join(v)`）へ 5 か所を静的鍵化。
直したあと母数が **5,560 → 5,565** に増えた＝**5 本が初めて計測対象になった**ことがそのまま証拠になる。

### ⚠⚠⚠ node の検査は `window` を持たないので、整形の**フォールバック**を測っていた

aria ラベルは、目の見えない読者にとっては**図そのもの**である。その x 範囲に軸用の `notation:'compact'` を
使っていたので、本番では **2000 と 2020 が両方「2K」**になり、**範囲を持たない範囲**を読み上げていた。

⚠ **この欠陥を、ここまでのどの検査も見られなかった。** node には `window.IntMapWidgetCore` が無く、
`num()` が自分の catch に落ちて `String(v)` を返していたからで、**整形についての主張はすべて
出荷されない経路を測っていた**（#R505 が Edge Function で踏んだのと同じ形が、今度はアクセシビリティの戸口から）。
⇒ 軸は compact のまま（数ミリしかない）、**読み上げる文には実数**。検査は本物の整形器を差し込んでから測り、
**綴りではなく性質**を主張する（「百万の目盛りは 4 文字以下」——en-GB は `1m`・en-US は `1M` で、
どちらかを固定した検査は欠陥が無いのに別ロケールで落ちる）。

⚠ 併せて `長條圖`（台湾）は字形変換だけでは `长条图` になり大陸の標準語にならないので、
`scripts/zh-hans.mjs` の語彙表に `['長條圖', '條形圖']` を 1 行足した（`条形图` になる）。
**全字が共通字なので変換層からは見えない**——そのファイル自身が例に挙げているまさにその形。
### ⚠⚠ ついでに見つかったもの: カタログ配列に穴があった

`js/atlas-catalog-text.js` の gloss ブロックと compose ブロックの間に **`},,`（二重カンマ）**があり、
配列に**穴**（elision）ができていた。`length` は 46、実在は 45。`Architecture.md` はその 46 を写していた。

**見つけられなかった理由が本題である。** これを見るはずの検査は `scripts/atlas-capability-audit.mjs` ⑭ の
「空のブロックは無いか」で、それが `docs.blocks().forEach(...)` と書かれていた——**`forEach` は配列の穴を
訪問しない。** 空のブロックを探す検査が、唯一の空のブロックだけを構造的に見られなかった。
⇒ 添字ループにし、**穴そのものを失敗として報告する**（`tests/r543 ⑪` が数ではなく構造を測る）。

### 二つめ: 回答が描かれた「視点」は、どのスナップショットにも入っていなかった

同じ問いへの答えの 2 つめは「5 つ前の回答まで遡っても、それが何を見せていたのか分からない」だった。
**調べたら、半分は既にあった。** #R118/#R122/#R125 が返答ごとの重ね描きスナップショットと、それを
描き直すチップ（「地図に表示中」）を持っていて、クローン層による独立共存まで実装済みである。

⚠ **入っていなかったのは「視点」のほう**——カメラの位置、基図、投影、点いていたレイヤー、
そして**時計**。チップを点け直すと、図形は読者が**その後移動した先**に、**その後動かした年**の上に
描き直される。IntMap の主題は大半が歴史なので、**1950 年についての回答の図形が 2026 年の基図に
乗るのは「その回答の地図」ではなく、その幾何を着た別の主張**である。

⇒ `js/atlas-answer-view.js`。撮るのは `IntMapAtlasState.snapshot` **そのもの**——#R397 から
camera / time / activeLayers を読んでいる観測器で、私有の読み手を作れば状態ブロックと食い違い始める。
この観測器に無かった片割れ（**適用器**）だけを足した。

⚠⚠ **レイヤーは点けるだけで、消さない。** カメラ・時計・基図・投影は単一の値で、読者がそれを
頼んでいて、同じ操作子で戻せる——正確に戻す。**レイヤーは違う**: その回答のあとに読者が点けた
ものを消すのは、**画面に何も出ないまま読者の作業を壊す**ことで、しかもカメラと違って「何が起きたか」も
「どう戻すか」も見えない。だから点けるだけにし、**その回答に無かったのに今点いているものを
`extraLayers` として報告する**——呼び出し元が「同一の視点だ」と言い張らずに済むように。
ボタンの表示は「戻しました（後から追加の N レイヤーはそのまま）」になる。

⚠ ボタンは `.atl-msgt`（バブルの**兄弟**）に置いた。本文の中に置くと `_atlCompose` が
次のツール呼び出しで本文を組み直したときに消える（#R492）。`js/atlas-console.js` に足したのは
**既存 1 行の中の撮影 1 か所だけ**で、行は 1 本も増えていない（天井が 0 なので増やせない）。

### ⚠⚠ 「位置を固定した検査」に二度当たり、二度目は既に直っていた

全件テストで 1 本だけ赤くなった: `tests/r495-checks.test.mjs` の

```js
assert.match(read('src/main.js'), /'atlasQuery'\]/, 'the one list of every factory the program has');
```

この正規表現が訊いているのは「`atlasQuery` が一覧に**居るか**」ではなく**「配列の最後の要素か」**である。
このラウンドが後ろに 2 件足しただけで赤くなった——`atlasQuery` の配線は 1 バイトも変わっていないのに。

⚠ **これは #R488（CSS の綴りを固定した検査）・#R429（1 ファイルに向けた検査）と同じ形**で、
`.agents/rules/no-ad-hoc-hardcoding.md` §5 の表が名指ししているもの。所属を訊く形に書き換え、
**通ることではなく効くことを実測した**（`atlasQuery` を一覧から外した合成違反で赤くなることを
確認してから戻した）。

⚠⚠ **そして rebase したら、#R527 が同じ行を同じ考え方で先に直していた**——
`/const LAZY_FACTORIES = \[[^\]]*'atlasQuery'/`。あちらも「新しい lazy factory を後ろに足したら
赤くなった」から直しており、**同じ一行が 2 ラウンド続けて同じ理由で人を止めた**。衝突は向こうの版を
採って解いた（先に着いたほうが正本）。記録に残す価値があるのは修正ではなく**再発したという事実**で、
「位置を固定した検査」はこのリポジトリで**実際に繰り返し起きている**形だということ。
### 予算をどう動かしたか（起動費用は 1 バイトも緩めていない）

`tests/perf-baseline.json` で動かしたのは **async 側の 2 つと、新しい chunk 2 本の記録**だけ。

| 項目 | baseline | 実測 | 差 |
|---|---:|---:|---:|
| `async.gzip` | 3,178,421 | **3,196,572** | +18,151 |
| `async.chunks["atlas-console"]` | 1,001,341 | **1,010,543** | +9,202 |
| `async.chunks["atlas-chart"]` | — | **10,777** | 新規 |
| `async.chunks["atlas-answer-view"]` | — | **2,599** | 新規 |

atlas-console の +9,202 は、この能力 1 本が要求する文——catalogue のブロック、CORE ツールの説明、
差し戻しの注記——と、図の CSS である。⚠ `--update` は使っていない: **22 項目全部を書き戻す**ので、
起動費用のラチェットまで一緒に緩む。

⚠⚠ **触っていないもの: `eager.*` の 7 項目すべてと `async.raw` / `dist.*`。**
`modules` も `requests` も**完全一致のまま動いていない**——レンダラも視点復元も**遅延ロード**なので、
新モジュール 2 本は起動グラフに 1 本も入っていない。CSS を `css/intmap.css` ではなく
`js/atlas-styles.js` に置いたので `cssRaw` もほぼ動かない。
**読者全員が毎回払う数字は 1 つも緩めていない。**

⚠ **この数字は 3 回書き直した。** 最初に測ったときは 5 項目が赤く、そのうち約 7 割は本ラウンドの増分では
なく **baseline が 2 ラウンド分古かったぶんの drift** だった（当時の最終更新は #R520 で、#R519・#R529 が
baseline 未更新のまま merge されていた）。#R527／#R530／#R533／#R534／#R536／#R538／#R540 の上に載せ直す
たびに赤い項目は入れ替わり、最後に残ったのが上の 2 つである。**古い baseline の上で測った数字を、その
ラウンドの費用として読んではいけない**——ラチェットは「誰の増分か」を区別しないので、記録する側が区別する。
