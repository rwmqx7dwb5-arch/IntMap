## R582 — **扉の名前は書いてあったが、中身が一つも書いていなかった**

> 「エンゲルス空軍基地からナッシュビルまでICBM」
> → 「エンゲルス空軍基地からナッシュビルへのICBM発射・飛翔経路・到達時間・照準など、攻撃を実行できる
> 具体的な計画には協力できません。代わりに……」
> 「ha?」 → ほぼ同じ拒否内容を再度説明。
>
> （あわせて設計改善の調査報告書 1 本。以下 §5 に、報告書のどの主張を採り、どれを実測で退けたかを書く。）

### ① 頼まれたものは実在する。しかも Atlas 以外からは触れない

`sim.ballistic` は実在の能力である。`js/atlas-sims.js` が Bate/Mueller/White の地対地弾道解を解き
（`ballisticSolve`）、Allen–Eggers の大気抵抗で着弾速度を出し、地球の自転で地上航跡を曲げ（Coriolis）、
必要なら MaRV の終末機動と 4 段の爆風リング（`cbrt(Y)` スケール）を描く。19 機種の射程と威力の表を持つ。
`js/atlas-catalog-text.js:77` はこれを **「BALLISTIC MISSILE SIMULATION (real physics — use THIS for any
ballistic/ICBM/弾道ミサイル request)」** と書き、例として「モスクワからワシントンへ弾道ミサイル」を挙げている。

そして**この能力には、製品のどこにも UI の入口が無い**。`js/map-ui.js` の `SIM_TOOLS` は
Layers ▸ Tools に出る正式な入口の一覧で、10 本のシミュレータを並べていて、弾道は入っていない。
`IntMapOS.register('sim.ballistic', …)` はリポジトリに 0 件。`index.html` にも `js/locales/*` にも
ICBM／弾道の文字列は無い。⚠ **つまり Atlas に頼むことが、この機能への唯一の到達経路である。**
Atlas が断れば、その機能は読者にとって存在しない。

### ② 決める時点で、Atlas はそれを見ていなかった

`SYS()` が毎ターン送るのは persona（`js/atlas-persona.js`）＋ policy の 5 節（`js/atlas-policy.js`）＋
返答形式 ＋ **道具 11 本**である。中核 9 本は `map_view` / `highlight` / `compose_map` / `chart` /
`set_layer` / `research` / `my_location` / `look_at_map` / `ask_user`。残りは `find_capability` と
`run_capability` の 2 本。

レジストリは 135 能力を持つ。**そのうち 11 が名前で示され、120 余は 1 文で代表されていた**——
`find_capability` の説明文「Search everything IntMap can do.」。

⚠⚠⚠ **それは扉の名前であって、中身の一覧ではない。** 存在を知らない能力のために扉は開かれない。
Atlas が「検索してみよう」と決める**前**に下す判断は、すべて**道具が 9 本しかない IntMap** についての
判断になる。そのアプリから見れば「エンゲルス空軍基地からナッシュビルまでICBM」は、地図と図と調査しか
できない道具立てに向けられた、実在の空軍基地と実在の都市についての一文でしかない。

⚠ **この形はこのファイルが前に一度記録している。** `js/atlas-capabilities.js` の #R413 の注記は
「`find_capability` が 121 能力への唯一の扉になったので、得点 0 の綴りは**存在しない能力**になる——
しかも扉は黙って閉じるのではなく『IntMap may not have this』と**答える**」と書いていた。あれは
**扉が正しく開くか**の話だった。残っていたのは、**扉を叩くと決めるための材料**である。

### ③ 直したのは到達であって、方針ではない

`js/atlas-capabilities.js` に `index()` を足した。レジストリ（`order` の表そのもの）から導出し、
撤去済みを除いた全能力の **ID だけ**をカテゴリ別に並べる。`SYS()` が `_capIndex()` 経由で毎ターン載せる。

```
sim: sim.lineOfSight, sim.radiation, sim.flightSim, sim.rfCoverage, sim.sunPosition, sim.terrainWater,
     sim.earthquake, sim.sunHours, sim.nightSky, sim.space, sim.tsunami, sim.ballistic, sim.flyAnimate.
```

**2,504 バイト**（134 能力・撤去済み `system.monitor` は除く）。説明文 81,951 バイトは `find_capability`
の裏に置いたままで、#R406 が測った「『ありがとう』に 41,178 文字」は戻していない。ID は
`run_capability` がそのまま取る文字列なので、索引 → schema → 実行が一本の線でつながる。

⚠ **索引は導出であって一覧ではない。** 能力を 1 本足せば次のターンから索引に載る。手で並べた一覧は
次に足されたものを黙って落とす（`.agents/rules/no-ad-hoc-hardcoding.md` §2.4、およびこのファイル自身の
冒頭「A list that a human must remember to update is a list that will be wrong」）。

⚠⚠⚠ **`js/atlas-policy.js` には 1 文も足していない。** §② は #R147 から
「never judge by keyword … 4 軸で測れ … TRANSFORM it and EXECUTE … full refusal is the LAST resort」と
言っている。**その指示は間違っていなかったし、破られてもいなかった**——存在を知らされていない道具に
対しては、変換して実行しようがない。`CONSTITUTION.md` §5 は Atlas を制限・例外の増える方向へ動かすことを
禁じており、この件の欠陥は**到達**だったので、直したのも到達だけである。

### ④ 検査は、報告された 1 件ではなく性質を測る

`tests/r582-checks.test.mjs`（6 本）。

① 索引が名指す集合が、レジストリの非撤去集合と**一致する**——期待値はレジストリから導出し、
テストに書き下さない（書き下せば 2 つ目の正本になり、次に能力を足したラウンドで古くなる）。
② 撤去済みは載せない（`system.monitor` は `FEATURE_WITHDRAWN` を返す扉なので、案内すれば嘘になる）。
③ **「Atlas に見えるシミュレータの数」＝「IntMap が持つシミュレータの数」**。報告時点は **0/13** だった。
⚠ 「`sim.ballistic` が文字列に含まれるか」では書かない——それは報告された 1 件についての検査で、
#R488 が示したとおり綴りを固定した検査は経路が死んでも緑のままになる。
④ `SYS()` が索引を**実際に連結しているか**を acorn の構文木で訊く。`_capIndex` を定義したまま
連結を外しても grep は通る（実際に変異させて確認: ④ だけが赤になる）。
⑤ 索引が説明文に戻らない予算（1,500 < n < 8,000 バイト）。
⑥ **policy が節を増やしていないこと**、および policy の本文が武器の名前を含まないこと——
将来のラウンドが拒否の報告に文を 1 つ足して答えようとしたら、ここで落ちる。

変異試験: 索引の連結を外すと ④ が赤、`index()` から 1 カテゴリを落とすと ①③ が赤。

### ⑤ 報告書のうち、実測で退けたもの

添えられた調査報告書は 28 節あり、主因を **「現在のUI状態がLLMにとって事実になっていない」** と
名指していた。**IntMap については誤りである。**

- `js/atlas-state.js` は 18 セクション（`camera` / `selection` / `pinnedPoint` / `deviceLocation` /
  `viewport` / `time` / `activeLayers` / `panels` / `objects` / `routing` / `simulations` / `comparison` /
  `settings` / `pendingOperations` / `capabilityAvailability` / `alerts` / `monitors` / `workspace`）を
  **構造化スナップショットとして**持ち、`renderPrompt()` が毎ターン `[CURRENT MAP STATE]` として送っている。
  これは #R318 で、報告書が指摘するのとまったく同じ理由（手書きの文章に各機能の状態を都度足す方式は、
  足し忘れた subsystem が invisible になる）で作られている。
- 報告書が前提にしていた**「利用者は ICBM シミュレーション画面を開いて操作していた」という状況も
  成立しない**——§① のとおりその画面は存在しない。
- **Policy Gate（FULL / REDUCED / BLOCK）は作っていない。** 利用者の判断を仰いだうえで
  `CONSTITUTION.md` §5 を優先した（「Atlas に制限を増やす方向・例外を増やす方向へ持っていってはならない」
  「症状1つに機構を1つ足す積み重ねは、Atlas ではそのまま回答品質の劣化になる」）。
- **repair mode も入れていない。** 「は？／ha?／what?／違う」の綴りの一覧は
  `.agents/rules/no-ad-hoc-hardcoding.md` §1 が禁じる「埋め込み一覧」そのものであり、さらに IntMap の
  ループは毎ターン状態から**再計画**していて、凍結された意図分類という機構が存在しない。
  2 ターン目が同じ答えになったのは、**1 ターン目と同じ材料しか無かったから**である。索引は 2 ターン目にも載る。
- `tool_choice` の強制（報告書 §8）は経路が違う。Atlas の道具は provider の native function calling では
  なく JSON エンベロープで運ばれており（`js/atlas-console.js` の `TURN_SCHEMA`）、`ai-proxy` が
  `tool_choice` を渡すのは hosted web search に対してだけである。
- 名前空間（報告書 §10）は既にある——能力 ID は `sim.ballistic` / `map.compose` のように
  `<領域>.<動詞>` で、レジストリがそれを正本にしている。

⚠ 報告書のうち**採ったのは 1 点だけ**である: 「Atlas に何が見えているかを、決める前に与えよ」。
それが実測で残った唯一の欠陥だった。
