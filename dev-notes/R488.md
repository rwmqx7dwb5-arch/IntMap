## R488 — **開閉タブは「残った」のではない。隣に居ろと書いた規則が、隣を見失った**

報告は一文だった。

> 左サイドバーの開閉タブが残り続けてしまっている。

### 実測（本番 build R485・1280×720）

```
#sidebar.className                       "sidebar collapsed"
#btn-toggle-sidebar getBoundingClientRect  x=400  right=422   ← --sidebar-w のまま
#map-container.parentElement.className     "map-column"
document.querySelector('.sidebar.collapsed ~ .map-container')   → null
.chev の transform                        matrix(0.707, 0.707, …) ＝ rotate(45deg)（開いた向きのまま）
```

サイドバーは閉じているのに、取っ手だけが**地図の真ん中に居残っていた**。
山形も「閉じる」を指したままだった。

### 原因は #R485 が**正しく**足した wrapper

#R485 は、帰属表示に「どのオーバーレイの包含ブロックも届かない行」を与えるために
`#map-container` を `.map-column` で包んだ。**その判断は正しい**（credit は実測で
全ての点が覆われていた）。壊れたのは、包まれた側を**兄弟結合子で名指していた** 6 本である。

```
.sidebar.collapsed ~ .map-container …          ← #map-container が #sidebar の直接の兄弟であることの主張
```

`.map-column` が間に入った瞬間、この主張は偽になり、6 本は**1 要素も選ばなくなった**。

| 失われた規則 | 見えた症状 |
|---|---|
| `.btn-toggle-sidebar{ left:0 }` | 取っ手が x=400 に居残る（報告された症状） |
| `.chev{ transform:rotate(-135deg) }` | 山形が「閉じる」を指したまま |
| `.coord-readout{ left:16px }` | フロスト時、座標読み取りが無いサイドバーぶん右に |
| `.data-legend` / `.koppen-legend{ left:24px }` | 同上（凡例2種） |
| `.country-info{ left:24px }` | 同上（国情報パネル） |

⚠ **6 本すべてが同じ 1 文で死んでいる。** 症状が 1 つしか報告されていないのは、
残り 5 本がフロストガラス設定の中だけの話だからで、直っていなかった数は 6 である。

### ⚠⚠⚠ `npm test` はこの間ずっと緑だった

`tests/r252 ⑥` は、この規則をこう固定していた。

```js
assert.match(css, /\.sidebar\.collapsed ~ \.map-container \.btn-toggle-sidebar \{ left:0; \}/, …)
```

**この行は最後まで通っていた。** 綴りは 1 バイトも変わっていないからである。
**「その CSS が在る」と「その CSS がこの要素に当たる」は別の主張**で、前者しか見ていない検査は
後者について何も言えない。同じ形は既に 3 回書かれている——#R435（当たらない CSS は綴りとしては
完全に健在）、#R455（レイヤーの箱に入っている ≠ 地図に在る）、#R485（可視か ≠ 最前面か）。
**今回は選択子の側で再発した。**

### 直し方は「経路を書き直す」ではなく「経路を名乗るのをやめる」

```
.operation-room:has(> .sidebar.collapsed) .map-container .btn-toggle-sidebar { left:0; }
```

述べているのは**状態**（この操作室のサイドバーは畳まれている）であって、
`#map-container` が何層目に居るかではない。次に誰かが層を挟んでも生き残る。

⚠ **適用範囲は 1 ミリも広げていない。** ws-mode では `js/workspace.js` が `#map-container` を
`<body>` 直下のウィンドウへ持ち出すので、`.operation-room` の中に居ない——**以前
`#sidebar` の兄弟でなくなっていたのと同じ理由で、今も当たらない**。
（そこでは `#btn-toggle-sidebar` 自身が `display:none` でもある。）
`body:has(.sidebar.collapsed)` にしなかったのはこのため——`<body>` を起点にすると
ws-mode の HUD にまで新しく当たり始める。

### 門は綴りを読まない

`tests/r159.spec.js` の `R488`（**新しい spec ファイルは作っていない**——同じ起動・同じ視野・
同じ classic/solid モードで既にこのサイドバーを開閉している spec に足した。
`scripts/test-budget.mjs` の言う「積み増しではなく統合」）。

- **ⓐ 取っ手を実際に測る。** 開いていれば `--sidebar-w`、閉じていれば 0。
  山形は回転行列の第1項の**符号**で見る（`rotate(45deg)` は +0.707、`rotate(-135deg)` は −0.707）。
- **ⓑ collapsed について語る規則が、1 本も空振りしていないことを要求する。**
  CSSOM を歩いて `selectorText` に `.sidebar.collapsed` を含む規則を全部集め、
  `document.querySelectorAll(sel).length === 0` のものがあれば落ちる。
  ⚠ **綴りに依存しない**ので、**正しい書き換えでは落ちず、次の wrapper では落ちる。**
  （3 本はフロスト限定なので、判定の間だけ `body.sidebar-glass` を付けて外す。）

⚠ **発火を実測した。** 選択子を #R485 時点へ戻して同じ検査を走らせると:

```
Error: shut: the handle came back to the window edge instead of staying behind at x=400
  Expected: < 2
  Received:   400
```

報告された症状そのものが、数値で出る。`:has` 版では 3 passed。

`tests/r252 ⑥` の綴りの検査は**残した**（そこから導かれている地震パネルの逃げ幅の根拠が
この数値なので）。ただし**何を証明していないか**をその場に書いた——嘘の綴りを直すのではなく、
**足りない主張を別の場所に足す**のが正しい（#R458）。
