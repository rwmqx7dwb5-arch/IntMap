## R424 — **閉じた集合が、入力についての推測だった**

報告は本番（日本語・1916年）のスクリーンショット付きだった。

```
  歴史の行   イギリス領インド帝国 / South Asia / Calcutta / New Delhi
             大日本帝国 / East Asia / Tokyo
  現代の行   北アメリカ … / ヨーロッパ …          ← 同じ一覧の、同じ位置
```

国名は #R410 が直していて正しい。**国名の下のサブ行の region だけ**が、歴史の行では英語のままだった。

### 原因——表の中身ではなく、表が覆っている語彙

`js/countries-ui.js` の `_regionName()` は #R251 が足したもので、鍵は **Natural Earth の CONTINENT**、
つまり7大陸である。7つで足りるという判断は、`s.region` の**産地が1つ**だという前提の上に立っていた。
産地は1つではない。

| 産地 | 語彙 |
|---|---|
| Natural Earth `CONTINENT`（`js/countries-ui.js` の `_mkStat`） | 7大陸 ＋ `Seven seas (open ocean)` |
| `js/history.js` の `STATES`（`agg()` が `region:S.region` をそのまま載せる） | `Eurasia` / `Middle East` / `South Asia` / `Southeast Asia` / `East Asia` |

2つ目の語彙は**大陸を1つも含まない**。そして表に無い鍵に当たると `_regionName()` は
`return r`——引数をそのまま返す。9言語すべてで生の英語が出る。

### ⚠⚠⚠ どの計器も、これを見られない

`tests/r251-langs.spec.js` は #R251 が「形を持たない計器」として書いたもので、画面を歩いて
**「この文字列は英語で出ている——IntMap はその訳を持っているか？」**と訊く。持っていれば欠陥。
つまり **IntMap が訳を1つも持っていない語には、構造的に沈黙する**。`South Asia` の訳はどの表にも
無かったので、この計器は1度も鳴らなかった。

**閉じた集合が入力についての推測であるとき、外れ方は必ず無音になる。**「訳が足りない」は測れるが、
「訳を持つべき語が表に無い」は、表を語彙と突き合わせない限り誰も測っていない。

### ⚠⚠⚠ 報告されていない2件目が、同じ穴から出ていた

同じ理由で現代側にも生きた英語が1行あった。**Natural Earth には8つ目の `CONTINENT` 値がある。**
実測 2026-08-25、`loadCountryData()` が取りに行く3つの縮尺すべてを数えた:

| file | features | 7大陸の外 |
|---|---|---|
| `ne_110m_admin_0_countries.geojson` | 177 | `Seven seas (open ocean)` × 1 — **ATF**（フランス領南方・南極地域） |
| `ne_50m_admin_0_countries.geojson` | 242 | 同 × 8 — SGS / IOT / SHN / SYC / MUS / MDV / ATF / HMD |
| `ne_10m_admin_0_countries.geojson` | 258 | 同 × 9 — 上に Clipperton (FRA) |

**既定の起動が読むのは `ne_110m`** で、ATF は `sov:true` なので `renderStats` の絞り込み
（`s.nameEn && !s._histHidden && s.sov!==false`）を通る＝**一覧に出る行**である。つまり報告は
「歴史の行だけ」と書いていたが、欠陥は歴史の行だけのものではなかった。

⚠ 逆に、`enrichCountry()` の `if(!s.region && c.region) s.region=c.region;`（restcountries の
`Americas` / `Antarctic`）は**表に足していない**。同じ実測で **CONTINENT が空の feature は
3縮尺とも 0 件**——この枝は届かない。届かない値を表に入れるのは、覆っているという主張を薄めるだけ。

### 首都は、測ってから据え置いた

依頼が「決める前に現代の行が実際に何をしているか測れ」と書いていた。測った:
**現代の行は `CAPITAL[code]`（«Washington, D.C.»「Tokyo」）、歴史の行は `_STINFO`（«Tokyo»
«Calcutta / New Delhi»）。どちらも英語のまま出る。** #R251 の「首都は地名なので残す」は歴史の行でも
成立していて、**不整合なのは region だけ**だった。`tests/r424.spec.js` は「region が変わり、
**capital は1バイトも変わらない**」を両方の行について言う。

### 同じ欄のもう1つの面（範囲の外だったので、訊いてから入れた）

`s.region` を描く場所は2つある。報告された一覧のサブ行（`js/countries-ui.js` の `subline`）と、
行をダブルクリックして開く**国詳細カードの Region 行**である。後者は
`[HOST.t('statRegion'),(s.region||'—')+…]` で生に出しており、**9言語すべてで «Europe / Western Europe»**
と読めていた——#R251 は一覧だけを通していた。報告された範囲の外なので `CLAUDE.md` §3.2 に従って
確認し、「サブ行＋詳細カードの region」で実施した。`subregion`（Natural Earth の約24語彙）は
今回は英語のまま据え置き。

### 直したもの

- `js/countries-ui.js` — `_REGIONS` に **6鍵**（`Seven seas (open ocean)` ＋ 歴史の5語彙）。
  各行は `pickArgs()` の5引数（en/jp/de/ru/es）で、fr/ko/zh/zh-Hans は inline 表が引く。
- `js/countries-ui.js` — 詳細カードの Region 行を `_regionName(s.region)` へ。
- `js/locales/ui.{fr,ko,zh}.js` — 6語 × 3言語を `scripts/i18n-append-inline.mjs` で**挿入**
  （`build-ui-zh.mjs` の再生成フローは #R235 が実測したとおり lossy なので使わない）。
  `ui.zh-hans.js` は `node scripts/zh-hans.mjs` の生成物。
- `scripts/i18n-positional-audit.mjs` — `SAME_AS_EN.es` に `Eurasia` を1行。**スペイン語でも
  «Eurasia»**（RAE）で、同時に足した他の4語は全部異なる（Oriente Medio / Asia del Sur /
  Sudeste Asiático / Asia Oriental）——だからこれは「引数の書き忘れ」ではなく「語についての主張」。

### 検査

`tests/r424-checks.test.mjs`（5本・**5通りの変異で全部赤を実測**）:

| | 何を訊くか |
|---|---|
| ① | `js/history.js` が宣言する `region:` の literal 全部が `_REGIONS` の鍵か（acorn で木から読む） |
| ② | Natural Earth の8値が全部鍵か |
| ③ | 各値が5引数の `L(…)` 呼び出しで、第0引数が鍵そのものか |
| ④ | **`js/lang-registry.js` と4本の inline 表を実行して**、9言語ぶん `pick()` に解決させる |
| ⑤ | 一覧のサブ行と詳細カードが両方 `_regionName` を通り、生の `s.region` がどこにも無いか |

④ が要点である。「表に行がある」は形であり、形を照合する計器は #R251 以降ずっとこの欠陥の上を素通りしていた。
④ は**アプリ自身の解決器に訊く**ので、`inline` の綴り違い・`normalise` の解決順・引数の位置ずれが
どれも同じ1つの質問で落ちる。同じ実行で「英語と同じ」になるのは3組だけで、それぞれ1言語についての
主張として書いてある（es `Asia`・es `Eurasia`・fr `Europe`）。

`tests/r424.spec.js`（core tier・1テスト・1起動）は 1916 の画面を読む。**2通りの変異で赤**、
しかも失敗文が報告そのものになる:

```
  Error: 歴史の行のサブ行が英語のまま: 「East Asia / Tokyo」 — 同じ一覧の現代の行は「北アメリカ / Washington, D.C.」
  Error: カードの Region 行が英語のまま: 「East Asia」
```

⚠ **画面で読むのは9言語のうち2つ**（英語と、報告された日本語）で、これは値切りではなく**支払い**である。
残る7言語は④が答える——ブラウザの予算を1秒も使わずに。

⚠ **待つ述語は答えを待たない。**「東アジア が出るまで」を待つと、欠陥のあるビルドは30秒の沈黙のあと
述語の名前だけを残して落ちる。待つのは「その言語になった」「一覧がその言語で描き直された」
（並び順ラベルは keyed なので registry に訊ける）「2つの行が在る」——どれも壊れたビルドでも真になる。

⚠ **言語ピルは画面に出ていない**（設定パネルの中）。Playwright の `click` は «hidden» のまま20秒待って
落ちる（実測）。押すのは DOM の `click`——`tests/r251-langs.spec.js` と同じ入口。

⚠ **`app.page` は worker 内で共有される。** `resetPage()` は言語も時計も戻さないので、戻すのは
この spec の責任である。

### 試験予算——天井は2つとも測った額だけ動いた

`core 30 → 35`・`total 4,600 → 4,610`。core の6ファイルのうち5本は always-on で動いておらず、
6本目が `currentRoundSpec()`＝1916へ移動して言語を切り替えてから読む spec になった。
`tests/r416.spec.js` はその規則で gate を出る（1ラウンド前に `tests/r405.spec.js` が出たのと同じ）ので、
**#R428 がそれを 5 秒に測り直した分も、この round が使える余りではない**。

⚠ **校正は先に試して、捨てた。** 同じ batch・同じ条件（直列・1 worker・server 起動済み・
worker-scoped page・reporter の test body 時間・**worker の先頭ではない**ので起動費を二重に払わない）:

| spec | 実測 | 記録された entry | この spec を何秒と言うか |
|---|---|---|---|
| `tests/r416.spec.js` | 1,888 / 1,734 ms | 3（#R428 が 5 に測り直した） | 12–17 |
| `tests/r405.spec.js` | 3,764 / 2,972 ms | 7 | 12–17 |
| `tests/r209.spec.js` | 22,743 / 20,942 ms | 10 | 4 |
| `tests/r424.spec.js` | **7,592 / 7,219 ms** | — | — |

#R322 の規則——**機械と食い違う表から、この round は節約を取らない**——は両方向に効く。
どれからも取らず、直接の実測に #R416 自身の余裕率（2,360 ms → 3）をかけて **10** を入れた。

### 番号とスタンプ

⚠ **R424 は隙間番号である。** 着手時の空きは R423 だったが、同じ瞬間に2セッションが同じ番号を取り、
push 時点の `origin/main` は **R429** まで進んでいた。**最新ラウンド番号ではないので
`window.__imBuild` / `window.INTMAP_BUILD` は触っていない**（一度 R424 へ下げてしまい、戻した）。
