## R663 — **「まず確認します」で終わったターンは、電文が「途中である」と言えない形だったから終われた**

> #R582 の production verification。ログイン済みの本番で `window.fetch` を hook し、ai-proxy へ実際に
> 送られた body を読んだ。

### 1. ⚠⚠⚠ 索引は届いていた。能力は認識されていた。それでも 1 本も呼ばれなかった

「東北沖でM9の地震が起きたときの津波の伝播をシミュレーションして見せて」に対する実測:

| 測ったもの | 値 |
|---|---|
| system prompt | 22,378 字・`WHAT INTMAP CAN DO` を含み `sim.ballistic` もある |
| model 呼び出し | **1 回** |
| tool_calls | **0 件** |
| `window.IntMapTsunami` | **undefined** |
| 地図の source | **0 本** |

返ってきた文は 「…津波の伝播をシミュレーションします。**まず、利用可能な津波シミュレーション機能の設定を
確認します。**」。**能力の存在は文の中で名指されている。** つまり #R582 の索引は届いており、
「見えていなかったから呼ばれなかった」という診断はここでは成り立たない。**呼ぶと言って、呼ばずに終えている。**

### 2. ⚠⚠⚠ 電文の 2 つの形が、その返答を「正しい返答」にしていた

**① `final_text` が strict json_schema の先頭のプロパティだった。**
strict な `json_schema` は**プロパティ順に生成される**。並びは `final_text` → `answer_mode` → `tool_calls`
だったので、**どの手でも、読者に見せる文を書き終えてから `tool_calls` に到達していた。**
そこに着いたときには、既に「一続きの返答」として組み立てた文に commit している。

**② ターンの終わりが「省略」で表現されていた。**
`tool_calls` が空ならターンは終わる——**モデルが出せる最も安い出力が「終わり」の合図**だった。
そして `final_text` は**毎手 required** なので、「これから動く」という意図を置ける場所は
**読者に見える文しか無かった**。「途中である」と「終わった」は、電文の上では同じバイト列である。

### 3. 直したのは、その 2 つの形そのもの

```
{"turn":"final"|"continuing","tool_calls":[…],"answer_mode":…,"final_text":string}
```

- **並びが決める順になった**——「この返答は**何か**」→「**何をするか**」→「**何と言うか**」。
  schema がプロパティ順に生成される以上、これは飾りではなく**機械的な仕組み**である。
- **`turn` は Atlas が宣言する。** `"final"` は「`final_text` が完成した回答でターンはここで終わる」、
  `"continuing"` は「まだ回答ではなく、続きは `tool_calls` にある」。
  `"continuing"` と言いながら `tool_calls` が空の final は、**何も続いていないという機械の記録**と
  矛盾するので `no_calls_issued` として返る。
- **同じ門である。** #R511（`answer_mode` × 描かれたか）と #R543（出力の集合）が既に持っている
  「宣言 × 記録」の検査に条件が 1 つ増えただけで、`gateBounces++` も `trace.outputGate++` も
  **ファイル内に 1 か所のまま**（`tests/r543 ⑨` が数えている）。予算も注記の形も共通。
- **`"continuing"` と宣言された手の文は、読者の回答にならない。** 報告された画面で
  「まず確認します」が**回答として表示された**のは、どの手の非空テキストもターンの答えになっていたから。
  ⚠ ただし、その手が結局ターンを終えたとき（差し戻しが上限に達したとき）は受理側で取り戻す——
  **空の吹き出しを出す経路を作らない。**

### 4. ⚠ 足していないもの（`CONSTITUTION.md` §5）

- **`turn` は必須ではない。** `TURN_SCHEMA.required` は `["final_text"]` のまま。宣言しないモデルは
  従来と 1 バイトも変わらず動き、**以前できた返答で今できなくなったものは 1 つも無い。**
- **`js/atlas-policy.js` は 1 文字も変えていない**（5 節のまま）。電文の話は REPLY FORMAT の仕事。
- **文面を読む規則を 1 つも足していない。** 「まず」「確認します」「I will now」——この種の綴りの一覧が
  この回の禁じ手であり（`.agents/rules/no-ad-hoc-hardcoding.md` §1）、検査は綴りを列挙する代わりに
  **`js/atlas-agent.js` が正規表現を 1 つも持たないこと**を測る。ループにとって
  「まず確認します」と「フランスの首都はパリです」は同じバイト列で、両者を分けるのは**Atlas 自身の宣言**だけ。

### 4b. ⚠⚠⚠ 直したら次の壁が見えた——**理由の無い失敗**（同じ回で直した）

①を入れて本番同等のローカルビルドで測り直したら、Atlas は narration をやめて
`find_capability` → `run_capability('sim.tsunami')` を**呼んだ**。そして 8 回連続で失敗した。
返っていたのは毎回これだけ:

```json
{"ok":false,"capability":"sim.tsunami","status":"failed","error":"failed"}
```

**`failed` という単語しか無い。** dispatch の case は
「⚠ 震源はどこですか（地名または経緯度）。」と**理由を書いていた**——ただし
`R(false, warn(…))` の HTML の中に、つまり**読者にだけ**。
`js/atlas-toolsurface.js` は #R413 以来 `res.error` を読んでいるが、
`_runOne` が返すオブジェクトに**その項が一度も存在しなかった**ので、
**すべての失敗が同じ 1 単語**になっていた。理由の無い失敗を渡された Atlas にできるのは
**推測**だけで、実際 `place` の綴りと `magnitude`/`mw` を入れ替えながら 7 回やり直し、
手数の予算を使い切って終わった。

直しは 1 か所——`mechanical()` が、**IntMap が既に書いた文**を text として読む
（`<template>` は inert なので何も読み込まず・実行せず・描かない）。
**個別の case に `message:` を 1 つも足していない**（`.agents/rules/no-ad-hoc-hardcoding.md` §2）。
実測（同じ文・ローカル本番ビルド・ログイン済み）:

```json
{"ok":false,"error":"failed","message":"⚠ 震源はどこですか（地名または経緯度）。"}
```

### 4c. ⚠ まだ残っている 2 つ（**この回では直していない。次の回に提案する**）

同じ 1 文を最後まで通すには、あと 2 つある。**どちらも実測してある。**

1. **拒否が「渡されていない」と「解決できなかった」を区別しない。**
   `geocode('東北沖')` は解決できない（#R515 の名前一致の床が、当たっていない候補を正しく捨てる）。
   ところが返る文は「震源はどこですか（**地名**または経緯度）」——**渡した地名が悪い**とは
   言っていないので、Atlas は地名を言い換えて何度も試す。⚠ **これは 1 か所の話ではない**——
   dispatch の `geocode(` は **50 呼び出し・39 case**、うち **32 case が場所不定で拒否**し、
   **2 つの状態を別の文言で区別している case は 0**。共有ヘルパも無く、`geocode()` 自身は
   `null` を返すだけで**何を問い合わせたかも、なぜ外したかも返さない**。
   ⇒ **正しい直しは 39 か所の個別対応ではなく、`geocode()` に「外した」を語らせること。**

2. **`sim.tsunami` は座標があっても Atlas の経路からは走らない**（活性化との競合）。
   `IntMapTsunami.open()` は `IntMapRuntime.activate()` へ委譲しながら**同期で `true` を返す**。
   dispatch はその直後に `setHours` → `run` → `showMaximum` → `showContours` → `play` を並べる。
   実測（`open({lng:141,lat:37,…,run:false})` の**直後**に `state()` を採る）:

   | いつ | `open` | `epi` |
   |---|---|---|
   | 直後 | **false** | **前回の [143, 38.3]** |
   | 2.5 秒後 | true | [141, 37] |

   つまり `run()` は**まだ活性化していないモジュール**に届き、`build()` は `epi` が無いので
   `lastErr='no epicenter'` で戻る。2.5 秒待ってから `run()` を呼ぶと**同じ引数で走る**
   （`pct:10`・`sim` あり・`err:null`）。`open()` に `run:false` を渡す理由自体は正しい
   （#R204: scope は solve の前に決まらなければならない）ので、直すべきは**活性化を待たずに
   次の呼び出しを並べていること**。

### 5. ⚠ ICBM の拒否は、この回の対象ではない

同じ報告に含まれていた「エンゲルス空軍基地からナッシュビルまでICBM」の拒否は、実測では
**索引が届いたうえで model が 1 回で拒否している**＝ provider（GPT-5.6 Terra）自身の挙動であって、
IntMap 側の門ではない。利用者の明示指示により、**語の言い換えや provider のフィルタ回避は行わない。**
