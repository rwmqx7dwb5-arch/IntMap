## ニュース履歴を本番に届かせるのに要った 4 つの修正(#1291 の後)

#1291 を入れた後、定期の取り込みが 2026-11-24 08:40 UTC から `news_ingest_runs` に何も残さなくなっていた(履歴が 0 行だったのは、書く段まで run が届いていなかったため)。原因は 4 つが重なっていた(詳細と測定は `dev-notes/2026-11-24-news-archive-cpu.md`):

1. 履歴の書き写しが毎 run 直近 72 時間の全出来事を組み直していた(#1395・#1397)。
2. `locate` が 12 batch を順に待って約 143 秒を使い、無通信 150 秒の上限に当たった(#1401: 並列 4・予算 140 秒)。
3. 1 つの worker に段を重ねるとメモリを手放さず `WORKER_RESOURCE_LIMIT`(546)。段ごとに 4 本の job に分けた(#1403)。
4. 観測の穴: 遡りの結果が応答にしか出ていなかった。`notes` に出すようにした。

修正後、4 本の job(:00 fetch・:04 locate+embed・:08 assign+link+entities・:16 prune)がそれぞれ run の記録を残すことを確認した。
