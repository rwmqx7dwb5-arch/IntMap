## R344 — **警報レイヤーの全数監査——描けない図形を「置けた」と数え、変わっていない地物を毎回まるごと送り直していた**

依頼は一文だった——「警報レイヤーを徹底的に監査し、まだ余地のある場所を探して徹底的につぶして。高速化もして。」

監査は**計器から**始めた。本番と同じビルドを立て、レイヤーを点けて 70〜240 秒回し、
⑴ CPU プロファイル ⑵ Chrome のタイムライン ⑶ `queryRenderedFeatures` による点ごとの塗り検査
⑷ 公開されたコレクションそのものの読み出し、の4つで測った。出てきたものを順に書く。

### ① 座標を1つも持たない図形は「図形」ではない

公開されたコレクションを読み出すと、**27 地物の `geometry` が `{"type":"Polygon","coordinates":[]}`** だった。
全部が台湾である。上流を数えると原因が出た——この地図が郷鎮市区を引いている 1982 年のファイル
（g0v/twgeojson `legacy/twTown1982.json`）は、**378 件のうち 19 件を座標ゼロで出荷している**:

```
台北市中正區 · 台南市中西區 · 台南市安平區(海) · 台南市南區(海) · 台中縣清水鎮(海) · 台中市中區 ·
基隆市中正區(海) · 基隆市中山區(海) · 基隆市仁愛區(海) · 基隆市仁愛區 · 高雄市新興區 ·
高雄市前金區 · 高雄市鹽埕區 · 高雄市鼓山區(海) · 高雄市前鎮區(海) · 高雄市小港區(海) ·
連江縣東引鄉 · 連江縣莒光鄉 · 澎湖縣七美鄉
```

`twTownGeo()` の篩は `if(!n||!f.geometry) return;` ——**「在るか」しか訊いていない**。空の座標配列を持つ
Polygon は在るので索引に入り、`shapeOf` がそれを答えとして返し、`unitFeature` がそれを地物にした。

実測した被害は「見えない」ではなく、**それより悪い**:

- 発令中の警報 **8 件**がその形に乗っていた。うち **5 件は大雨の rank 3**（＝赤）。
- `PLACED['TWN']` は**置けたほうに数えていた**（350/396）。
- したがって `UNPL['TWN']` は上がらない。**「ここで何かが起きている。ただしどこかはこの地図には言えない」**
  と言うためだけに存在する国 1 枚の薄塗り（#R271）が、**一度も呼ばれなかった**。
- `dedupeSameShape`（#R298 追記）はこの 27 件を素通りさせていた。`geomBox` がそういう図形に **null** を返し、
  この関数は `if(!bb) return;` で降りるからである——**述語はもとから在り、誰も訊いていなかった**。

修正は**述語に名前を付けて、図形が入ってくる扉に置くこと**である。

```js
const shaped=(g)=>(g&&geomBox(g))?g:null;
```

扉は3つある——**境界索引**（`twTownGeo`）・**単位の一覧**（`setUnits`）・**地物の生成**（`unitFeature`）。
⚠ **直したのは述語であって台湾ではない。** どの国のどの境界データが同じことをしても、もう通らない。

実測: 空の図形 **27 → 0**、公開コレクションの重複鍵 **warn 7 / quiet 18 → どちらも 0**、
`PLACED['TWN']` は **331/396** と正直になった（65 件は名前が索引に無いもので、これは以前からの数である）。

### ② 変わっていない地物まで、毎回まるごとシリアライズし直していた

本番ビルドの CPU プロファイル（70 秒・レイヤーを点けたまま・他は何も触らない）で、第一位は自分のコードではなかった。

| | 自時間 |
|---|---:|
| MapLibre `serialize`（`xs`） | **5,910 ms** |
| その手前の `sendAsync` | **5,594 ms** |
| **合計（`wp-alert` のアップロード 26 回ぶん）** | **11,504 ms** |
| このレイヤー自身で最も高い関数（`_bboxKey`） | 634 ms |

そのときの積荷は **13.3 MB・5,163 地物・455,886 頂点**である。`setData` には
**「今動いたのはこの3件だけだ」と言う方法が無い**ので、警報が1件届くたびに惑星ぜんぶを歩き直す。

#R290 と #R297 は「**何も言っていない**アップロード」をすでに消していた（内容の署名・1.5 秒の窓）。
残っていたのは**本当に違うもの**で、その違いは 5,000 のうち数十である。

MapLibre 5 には `GeoJSONSource.updateData({add,remove})` がある——**差分だけを worker へ送り、
差分が触れるタイルだけを貼り直す**。要求は一つ、**全地物が一意な id を持つこと**。

契約は `setSourceData(id, data, opts)` の**3引数目**に足した:

- 丸ごと書くとき、caller は `{diffable:true}` で「この積荷は同定できる」と言う。
- 以後は `{diff:{add,remove}}` を**完全なコレクションと一緒に**渡す。
- ⚠ **`data` は常に真実**。差分できないエンジン（Cesium アダプタは `opts` を見ない）・スタイル再読込・
  id の衝突・`updateData` の throw——どれでも**丸ごと書き**に落ちて、絵は同じになる。

実測（**孤立**した合成ソース 5,000 多角形 × 88 頂点 ＝ 17.9 MB、フィードも他レイヤーも無し、
1プロセスの中で 24 回ずつ交互に）:

| メインスレッド ms | 丸ごと | `{add,remove}` |
|---|---:|---:|
| serialize + post | 2,206 | **832** |
| `xs` だけ | 711 | **239** |
| MapLibre 全体 | 3,215 | **1,279** |
| GC | 623 | **173** |

アプリ本体では、世界ズームで冷たい状態から 90 秒:
**丸ごと 28 回 → 丸ごと 3 回 ＋ 差分 25 回**（＝シリアライザに渡す地物の約 1/10）。

⚠⚠⚠ **facade が第3引数を落としていた。**

```js
layers:{ … setSourceData:(id,d)=>A().setSourceData(id,d), … }
```

引数が2つしかないので、**#R322 が足した `opts.revision`**（「同じオブジェクトを使い回している」と
caller が宣言するための契約）は**アプリのどこからも到達できなかった**。今も誰も revision を渡していない
——だから気づかれなかった。**使われていなかったのではなく、到達不能だった。**

⚠⚠ **「差分で送っているつもり」と「差分で送っている」は別**である。アダプタが実際にどちらを呼んだかを
census が数える（`diffed`）。これは `CMD.on` に**ゲートされていない**——1回のソース更新につき整数の加算
1つで、**計器を切ったまま読めることにこそ意味がある**。

### ③ 「警報の顔ぶれが変わったか」を、配列の同一性で訊いていた

`_qCache`・`warnIndex`・`warnedISOs` の3つは、どれも `_xxxOf===feats` で自分の答えを記憶していた。
`feats` は publish のたびに `concat` で作り直される——**フィードが何も新しいことを言わなくても、毎回別の
オブジェクトになる**。したがって3つとも「1回の publish の中」でしか当たらない。

そして `quietFeatures()` は **publish あたり 1 回**しか呼ばれない。つまり、`warnMeeting` を4千の単位に
走らせ、その後ろの多角形差分を全部引き連れるあの memo は、**書かれた日から一度もキャッシュを返していない**。

→ 版を**内容**にした。発令中の各図形の**国と輪郭**を publish あたり1パスでハッシュし、変わったときだけ
`featsVer` を進める（`geomKey` が輪郭の鍵を図形に焼いているので、パスは手元にある値の文字列処理だけ）。

### ④ 一国の警報が1件変わると、地球上の全単位を作り直していた

単位の灰色は `単位 − ∪(その単位に重なる<b>その国自身</b>の警報)` である——`warnIndex` は国ごとに束ねられ、
`warnMeeting` は他国の行を見ない（#R298）。にもかかわらず、ドイツの警報が1件届くと日本の 1,490 市町村が
再計算されていた。

→ memo を**国ごと**にした。鍵は ⑴ その国の発令中の輪郭の指紋（索引が鍵を綴るついでに畳み込む）
⑵ 単位索引の版（**長さではなく版**——同じ数の細かい索引に置き換わる経路が3つある）⑶ clipper の有無。

実測 **isoHit 1,102 / isoMiss 92** ＝ **92 % の国別再構築が消えた**。
⚠ カウンタ（`quietCut` ほか）も国ごとに持って足し戻す。そうしないと「今回作り直した国」だけの数になり、
#R305 と #R307 が測った意味を失う。

### ⑤ 同じ図形の同じ鍵を、何度も綴り直していた

`_bboxKey` は、この層が単位と警報を比べるときの**同一性そのもの**である——`sameOutline`・`unitBoxes`・
`warnMeeting`・`isNeighbourUnit`・`subtractWarnings`・斜線の引き算。すべての単位を、すべての候補に対して、
publish のたびに。実測 **0.63 秒 / 70 秒** で、プロファイル中の**第一者最大**だった。しかも答えは毎回同じで、
`geomBox` はその図形の箱を**すでに覚えている**（`__abb`）。

→ `geomKey(g)` が鍵をその隣に焼く（`__bk`）。実測、上位30から消えた。

### ⑥ 満杯のテーブルを空にしていた／入力が変わったことは出力が変わったことではない

- `subtractWarnings` の `_diff` は満杯で **`clear()`** していた。このテーブルこそが2回目以降の差分を無料に
  するもので、(単位 × 警報) の組は上限より多い——日本だけで 1,490 市町村ある。**満ちる → 空にする →
  全単位がもう一度 clipper を払う**、という形で、世界を描くほど起きやすくなる。
  ⚠ **実測では今は起きていない**（1,300 前後で天井 3,000 に届かない）。それでも形として直し、
  **古い 1/4 を捨てる**ようにした。`diffEvict` が計器に出る。
- `rebuildHatchCut` の鍵はコレクション全体の署名を含むので、警報が1件どこかに落ちるだけで走り直す。
  だが**切り抜きはほとんど毎回同じ**——どの国が斜線かは、コレクションよりずっとゆっくりしか変わらない。
  → **出力の署名**を持ち、変わったときだけ貼る。
- `drawnCount` は国ごとにコレクション全体を走査し、`feedCount` がそれをその配信元の全ての国について呼ぶ
  （258 × 3,000 を配信元ごとに）。実測 0.28 秒 → **publish あたり1パスの表**。
- `hazardKey` は同じ機関の同じ文言に **27 本の正規表現**を当て直していた → 文言で記憶する。

### ⚠⚠⚠ 見つからなかったものも書いておく

このマシンでは、レイヤーを点けるとメインスレッドの空き時間が **69 % → 0.8 %** に落ちる（対照実験:
レイヤーを消したまま同じ時間回すと長タスクは 91 秒中 12.1 秒、点けると 101 秒中 88.7 秒）。
その差の正体は、この監査では**分解できなかった**。

- Chrome のタイムラインを**スレッドごと**に集計すると、落ち着いた 30 秒の窓で
  `CrRendererMain` の `RunTask` **29,154 ms** のうち **`Commit` が 24,609 ms**、GPU プロセスは **24,503 ms**。
  JS は全部合わせて 5 秒しかない。
- **警報の5レイヤーを全部隠しても長タスクは 15.1 → 14.5 秒にしか動かない**——つまり**描いていること**が
  原因ではない。
- headless の Chromium は合成とラスタの経路が実機と違う（コンソールに `GPU stall due to ReadPixels` が出る）。
  **測れないものを測ったことにはしない。**

だから上に書いた数字は、**どのブラウザでも同じもの**だけである——何を組み立てたか、レンダラに何を渡したか、
その**個数**。時間の数字は「同じ機械で交互に測った差」としてのみ載せた。
