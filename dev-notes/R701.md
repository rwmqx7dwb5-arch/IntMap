## R701 — **門の針が「日本語と英語」でできていたので、出荷している 9 言語のうち 7 言語は最初から外にいた**

〈`scripts/doc-facts.mjs` の `histb-count` 規則を、出荷している 9 言語すべてに届かせる〉

`data/hist-borders.js` の大きさ——1689–1885 の窓が何件の記録と何件の変化日を持つか——は、
`Architecture.md`・`PRODUCT.md`・`docs/TESTING.md`・束を読むコード・**9 言語の出典ページ**が
それぞれ散文で述べている。#R500 の発見（機械が持つ数を散文が写した箇所は必ず離れる）に対して
`histb-count` が置かれていた。

### 1. ⚠⚠⚠ 針が見ていたのは 8 件。立っていた主張は 30 件だった

#R699 の実測（44 文書 ＋ 規則自身の source list）:

| | 件数 |
|---|---|
| 針が見ていた主張 | **8** |
| 実際に立っていた主張 | **30** |
| **規則の外にあった** | **22** |

22 件のうち **14 件**は、de / es / fr / ru / ko / zh-Hant / zh-Hans が述べる**同じ 2 つの数**である。

- ru 「**1 411** записей … **881** различная дата изменений」
- fr 「**1 411** enregistrements … **881** dates de transition distinctes」

単位語が `件の記録` / `records` / `件の変化日` / `transition dates` の **4 つ＝ en と ja の綴り**
でできていたので、残り 7 言語はどれも届かない。**全計器は緑だった**——一致しなかった文に対する
既定が「沈黙」だからである。

### 2. ⚠⚠⚠ 7 言語ぶんの単位語を足すのが、修正ではなく欠陥のほうだった

手で 9 言語ぶんの名詞を並べた表は、`.agents/rules/no-ad-hoc-hardcoding.md` が禁じているものそのもの:
訳が言い換えられた日に静かに外れ、**10 番目の言語は初日から外にいる。**

代わりに使えるものが上流の構造にあった。**9 枚の出典ページは 1 つの文とその 8 つの翻訳で、
鍵は英語の原文**（`sourceUse['OpenHistoricalMap (CC0 1.0)']`）。だから**言語に依存しない性質**が
成り立つ:

> **正本が述べる数は、どの翻訳も述べている。**

これは 2 つの数ではなく**その段落の数を全部**守る——1411・881・13.3 MB・3,985・2,101・53%・
164–216・1689・1850。そして**ドイツ語・ロシア語・韓国語の単語を 1 つも必要としない。**
実測: **56 × 8 = 448 の主張、欠落 0。**

⚠⚠ **等しさではなく包含で、向きは選んだのではなく測った。** 翻訳は英語が語で書いた数を数字で
書くことがあるので（ja 「9 言語」＝ *nine languages*、「3 回の分割」＝ *three partitions*）、
翻訳のほうが**多い**: ja 65・ko 59・zh 57 対 正本 56。**できないのは落とすことだけ。**

⚠ 名簿も書かずに**ディスクから発見**し、出荷言語数と照合する。書き出せば**同じ 9 つの 3 つ目の
綴り**になり、2 つについて間違う——このアプリの日本語のページは `pages.ja.js` で言語コードは
`jp`、繁体字は `pages.zh-hant.js` でコードは `zh`（#R588）。

### 3. ⚠⚠⚠ 数の帰属先は行ではなく文で、それを直した瞬間に 2 つの古い数が出た

行は**組版の産物**であって意味の単位ではない。記録を名指す行の**次の行**にその数がある文がある。
スコープを「行 **または** 文のうち、記録を名指す最小のもの」に変えると 4 件増え、そのうち 2 件は
**#R690 が窓を広げて以来ずっと古かった**:

```
js/time-borders.js  (#R518 の段落)
  scripts/build-hist-borders.mjs writes
  494 records, 216 transition dates inside the window, …     ← #R518 の数・現在形
  … 11 行下 …
  The bundle now runs to 1689: 1,411 records, 881 transition dates, …   ← 現在の数
```

同じファイルの中に同じ事実の写しが 2 つあり、片方が古い。`AGENTS.md` §9 のとおり**正本を 1 つに
決めて古い写しを消した**（#R690 の段落が持つ）。⚠ この場所は #R690 自身のヘッダが
「導入した回に既に 2 つ古かった」と書いている当のファイルである。

⚠⚠ **段落はスコープではない。測ってから棄却した**——段落スコープは per-instant の計数
（`1860-06-15 210 features`）と他の記録の大きさ（aourednik の 236・hist-admin1 の 5,315）を拾い、
**偽 11 件**。#R694 の「固定幅の窓は長さであって関連性ではない」が、隣の規則で同じ形を取った。

### 4. ⚠⚠⚠ 桁区切りを直さずに広げることはできなかった

旧い針は `(\d{2,5})\s*<単位>` なので、**桁区切り付きの「1,411」を 411 と読む**
（#R689 が `hist-cities` で直した形）。緑だったのは**区切り付きの文がすべて偶然スコープの外**
だったからで、**区切り除去を同じ変更に入れなければ、広げた瞬間に偽の赤が出た。**
読み手は 1 つにし、`1,411` / `1.411` / `1 411`（U+00A0・U+202F 含む）を同じ数として読み、
**数の途中から始まらない**ように lookbehind を付けた。検査は**両向き**に測る——`2,411` で落ちる
だけでなく、**`411` でも落ちる**（後者が旧い針が黙って通していた読み方そのもの）。

### 5. ⚠⚠ `features` は単位に入れない——測って棄却した

`Architecture.md` の QID 行をはじめ 8 か所が、同じ数を `feature` で述べている。入れれば届く。
**入れなかった。**

| 構成 | 主張 | うち偽 |
|---|---|---|
| `records` / `件の記録` / `transition dates` / `件の変化日` | **12** | **0** |
| ＋ `features` | 22 | **3** |

**この repo のどの束も features の列**なので、その語は**どの記録の話かを言わない**。偽の 3 件は
aourednik のオーバーレイを数えている文（141）と per-year の探針（210・167）。
**狼少年の門は、次に出会ったセッションが緩める。**22 件で 3 偽より 12 件で 0 偽を採る。

残余は**数えて** `docs/TESTING.md` に明記した（正本はそこ・ここに写さない）——単一言語の
carrier に立っている主張は **26 件で、この規則が読むのは 10 件**。残り 16 件の理由は 3 つに分かれ、
**どれも「表に語が足りない」ではない**（8 件が `feature`・7 件が主語を**前の文**に持つ・
1 件は表の列にある裸の数）。⚠ これを閉じるのは表への追記ではなく、
**名詞ではなく数量の文法的な役を読む機構**——別の仕組みの仕事である
（#R699 の `doc-claims.mjs` がその方向）。

### 6. ⚠ 母集合も手書きをやめた／自分の検査ファイルが門に報告された

規則は `js/time-borders.js` と `scripts/build-hist-borders.mjs` を**名指して**いた——#R399 の欠陥
（台帳は、一覧が見に行くのを忘れた場所ではいくらでも腐る）。git が追跡する全ファイルを掃き、
生成物（`data/` `dist/`）と変更履歴（`DEV-NOTES*`。**過去に真だった数を正しく保持している**）
だけを除く。それで `docs/TESTING.md` の対が入った。

⚠⚠⚠ **その結果、自分の検査ファイルが門に報告された。** 変異表に「誤った数 ＋ 単位語」を
1 つのリテラルで書いた行が、主張として読まれた。**単位語は部品から組み立てる**
（`docs/TESTING.md` がこの罠を記録して **14 回目**。`scripts/doc-facts.mjs` のヘッダが同じ理由で
同じことをしている）。

### 7. 検査

`tests/r701-histb-count-lang-independent-checks.test.mjs`（**13 件・全緑**・木のロックを握って
`--rule=` で回す）:

| | 測っているもの |
|---|---|
| ① | ru の出典ページが正本の数を 1 つ落とすと落ちる（**ロシア語の単語を 1 つも使わずに**） |
| ② | de / fr / ko / zh-Hant も**同じ 1 つの性質**で守られている |
| ③ | 桁区切りを丸ごと読む——**両向き**（`2,411` も `411` も落ちる） |
| ④ | 記録の名前が**前の行**にある主張が検査されている（先に「行スコープでは見えない」ことを測ってから変異する） |
| ⑤ | 出典ページの名簿はディスクから発見され、**出荷言語数と照合される** |
| ⑥ | 翻訳側で**鍵**が消えると落ち、数の不一致とは**別の文**で報告される |
| ⑦ | `Architecture.md` が数を述べなくなると落ちる（正本の沈黙も失敗） |
| ⑧ | **広げても偽陽性が 1 件も出ていない**（木が緑・`--rule=` の綴り間違いは緑にならない） |

`histb-count` の完了行: **10 の主張 × 5 carrier ＋ 8 つの翻訳にまたがる 448 の数**
（before: 8 の主張）。

### 8. ⚠ 気づいたが直していないもの（提案）

`js/locales/pages.zh-hans.js` だけ、他の 8 枚が持つ 1 行の bootstrap
（`window.IntMapPageI18N = window.IntMapPageI18N || {…}`）を持っていない。そのファイルだけを
評価した読み手は `TypeError` になる。この規則の読み込み器は**自分でレジストリを渡す**ようにした
ので門としては影響が無いが、**アプリ内で簡体字の読者が出典ダイアログを開く経路**が同じ形なら
実害がある。1 行の追加だが今回の依頼の外なので**変更していない**（`AGENTS.md` §3 の 2）。
