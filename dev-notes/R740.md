### 1. ⚠⚠⚠ 地図は、同じ画面が表示している指標で色を塗れなかった

`drawChoro()` は `METRICS[metricKey]` しか読まない。平均寿命とネット利用率は **`XMET`** にある。
つまり**鍵が正しくても拒否される**。しかも同じ瞬間、Countries タブは **`Life expectancy`** という見出しの
列に 84.0 / 80.8 / 54.6 を印字していた。**店が自分の棚にある品を「無い」と答えていた**（#R733 と同じ形）。

そのうえ拒否文が**代わりの候補を1つも言わない**ので、模型に残る手は綴りを替えることだけになる。
7 回替えれば 1 ターンの予算は尽きる。⇒ **拒否は、実行可能な次の一手を含んでいなければ無限ループである。**

さらに 3 つ目——プロンプトの `/* 37 */` は有効な鍵を**手で並べて**いた:

```
Valid metric KEY values ONLY: pop, density, area, gdp, gdppc, hdi, dem, milSpend, milSpendGDP, tfr.
If a needed metric is not in this list, do NOT invent it
```

`lifeExp` と `internet` が**無い**。一方すぐ上の `/* 02 */` は「rank/mapMetric と同じ鍵（＋ lifeExp, internet）」
と書いていた。**1 つのプロンプトが同じ問いに 2 つの答えを持ち、どちらも実装と違っていた。**

⇒ 直したのは 3 か所ではなく、**1 つの事実**:

- `_metSpec()` が**唯一の解決器**になり、`drawChoro` / `rank` / `ratio` / `relate` / `value` / `explore` が
  全部そこを通る。`METRICS[...]` を直接引く経路は消えた。
- 解決は**その指標レコードが自分で名乗っている名前**（`LA(...)` の 5 言語のラベル＋現在の言語で描画した形）
  で行う。手書きの別名表（`VMET`/`XVMET`）は「寿命」「一人当たりgdp」のような**ラベルではない口語**のためだけに残る。
  ⇒ 指標を 1 つ足せば、その日から 9 言語で引ける。
- 「不明な指標」の文言は `_unknownMetric()` **1 か所**になり、**数え上げた有効鍵を必ず添える**。
- カタログの一覧は `metricList()` で**実装から数え上げて**渡す。`/* 02 */` の「（＋ lifeExp, internet）」は消した
  ——数えた一覧に既に入っている。

⚠ **一覧を書き写した時点で、それは実装と離れる。** `.agents/rules/no-ad-hoc-hardcoding.md` §2-4。

### 2. ⚠⚠⚠ 「評価できなかった条件」と「そもそも訊いていない条件」を、同じ扱いにしていた

`js/atlas-query.js` は、解決できない列名を `unapplied` に積んで**注記だけして答えを出して**いた。
本番の実測はその帰結そのもの——**10,971 件のうち先頭 200 件**が、`161 Earthquakes` という見出しの下に並び、
中身は M0.55 のカリフォルニアの微震だった。**正しくラベルされた、完全に間違った答え。**

2 つの原因:

1. `columnFor()` は **id の完全一致**しか見ない。列は `mag` で、模型が書いたのは `magnitude`。
2. `earthquakes` の行は最初から `time` を持っているのに、**それを宣言する列が無かった**。

直し方:

- **列は、その列が自分で名乗っている名前で引く**（`byDeclaredName`）。`col()` の第3引数の `LA(...)` が
  その列の名前の全部で、正規化して**完全一致 → 唯一の部分一致**の順で当てる。2 つ以上に当たる語は引かない
  ——`elevation` が 2 列に当たるとき当てずっぽうで選ぶのは、**無い列より悪い**（間違った数に条件が掛かる）。
- **`time` 列を宣言した**（種別 `date`）。⚠ ISO 文字列は辞書順が時刻順と一致する**ように見える**が、
  読者と模型が書くのは `2026-09-10` という**短い**文字列で、行が持つ `2026-09-10T04:00:00.000Z` より
  辞書順で**前**になる。だからその日 1 日分が丸ごと落ちる。両辺を `Date.parse` で瞬間に直してから比べる。
- **解決できない列を名指した条件は、問い合わせ全体を拒否する**（`{ok:false, error:'unknown-column'}`）。
  拒否は**その表が実際に持つ列 id を全部挙げる**（§1 と同じ理由）。
  ⚠ **拒否は計画を 1 つも走らせる前**に行う——後で拒否しても、捨てる答えのためにネットワーク列の代金は払っている。
- ⚠ **同じ判断は 3 か所にあった。** `where` だけ直すと、`near` の結合先の条件と `spatial` の対象の条件は
  今までどおり `.filter(c => c._col)` で**黙って消える**。読者から見れば同じ嘘（「2km以内で人口10万以上の港」と
  訊いて、人口の条件だけ無かったことになった表が返る）。⇒ `planFor()` が 1 つ答え、3 か所が同じものに訊く。
- カタログが**提示する列一覧**と、拒否が**案内する列一覧**は同じ関数（`tableColumnIds`）が作る。
  違う一覧を返すなら、その案内は動かない助言である。

### 3. ⚠⚠ 送信ボタンが「Atlas パネルを閉じる」と名乗っていた

本番の DOM で測った: `[data-imname]` が 441 件、そのうち **13 件が自分の `title` と食い違う `aria-label`** を
持っていた。全部 `close: …` である。

| 要素 | 本当の意味（title） | 名乗っていた名前 |
|---|---|---|
| `.atl-go` | **Send**（質問を送る） | `close: atlas panel` |
| `.atl-map-toggle` | Show / hide on the map | `close: atlas panel` |
| `.atl-jump` | Jump to latest | `close: atlas panel` |
| `.alc-x` | Hide | `close: layer active section` |
| `.accent-sw` ×9 | Default / Indigo / Purple / … | `close: accent picker` |

原因は 1 つの guard:

```js
const t2=(b.textContent||'').replace(/\s+/g,'');
if(t2&&!/^[××✖xX]$/.test(t2)) return;
```

⚠ **`t2 &&` が付いているので、テキストを 1 文字も持たない要素（中身が SVG のボタン）は「× である」と
確かめられないまま close として命名される。**「× であることを確かめる」ための条件が、
**× を 1 文字も持たないものだけを通していた。**

これは読み上げの問題にとどまらない——**Atlas は `aria-label` を handle にして `findControl` で UI を引く**ので、
「Atlas パネルを閉じて」という指示が**送信ボタンを押しうる**。

⇒ 掃引の判定を事実に付け直した: ① `title` があればそれが**その要素自身の名前**なので採る
② `title` が無く、テキスト全体が close グリフ**そのもの**のときだけ `close: <host>`
③ どちらでもない（アイコンだけ）なら**何も書かない**。
⚠ **誤った名前は、名前が無いことより悪い。** 名前が無いことは `IntMapUIAudit.run()` が `unnamed` として
正直に数える。

### 4. 表が 1 文字ずつ改行されていた

`<div style="overflow-x:auto;"><table style="…width:100%;">` は、**はみ出さずに縮む**。
幅 365px の Atlas パネルに 6 列が入り、`#` と `Name` のヘッダに `white-space:nowrap` が無いので、
本番の `NAME` は **N / A / M / E** と縦 1 文字ずつになった（表の高さ **8,153 px**）。
⇒ 表を `width:auto; min-width:100%` にし、`#` と `Name` にも nowrap。包む `div` は既に横スクロールするので、
**縮まずにスクロールする**。`.atl-md-table` にも同じ形があったので同じく直した。

### 5b. ⚠⚠⚠ 成功した仕事を「何も起きなかった」と報告すると、Atlas は同じ仕事を予算が尽きるまで繰り返す

同じ日にもう 5 本訊いた。**そのうち 4 本が `repeated_calls` か `step_budget` で死に、死因は全部これだった。**

| 訊いたこと | `lastPlan()` が記録したもの |
|---|---|
| 渋谷駅から徒歩30分で行ける範囲を地図に出して。面積も。 | `isochrone [ok]` → **`not_rendered` ×5** → `reset [ok]` ／ 16 ステップ・1m09s・`step_budget` |
| ヨーロッパの気温をGFSで、等圧線も、風のパーティクルも | `flyTo "ヨーロッパ" [no_change]` ×2・`flyTo "Europe" [no_change]` ×2 → `flyTo [ok]` ／ 7 ステップ・92s・`repeated_calls` |
| 東京駅から京都駅まで電車で | `directions "transit" [ok]` を**5 回** ／ `repeated_calls`・5 候補のカードが**2 枚**出た |
| 旧ソ連の国を全部ハイライトして GDP 順に | `highlight [failed]` → `highlight [ok]`。**失敗の告知（「いずれの識別子も境界データに一致させられませんでした」＋14か国のISO3）が、成功した「15か国を描画しました」の真上に残った** |

⚠ **到達圏は1回目で正しく描かれ、画面にずっと出ていた。** カメラも最初からヨーロッパを映していた。
⚠ **副産物**: 同じポリゴンが 5 枚重なり、`fill-opacity:0.18` が実効 6 割を超えて下の地図が読めなくなった。

原因は 2 つの判定で、どちらも同じ誤りを持っている（`js/atlas-capabilities.js`）:

```js
/* paint   */ if (changed(before, after)) …ok…; return { code:'not_rendered' };
/* camera  */ if (wantsMove && !changed(before, after)) return { code:'no_change' };
```

**どちらも「何かが動いたか」を訊いていて、「訊かれたものが地図の上にあるか」を訊いていない。**
カメラの方はコメントで不変条件を明言していた——「one that asked for movement is complete only when
the camera really is somewhere else」。**読者が頼んだのは移動ではなく状態である。**

⚠ **このファイルは同じ形を既に 2 回直している**（#R551 → `research.historicalMap` → `factions`）。
到達圏で 3 件目、カメラで 4 件目。再発する理由は、判定が見られる面が `paintNow()` に**手で並んでいる**
ことで、`im-iso-src`（到達圏）はその一覧に無かった。
⚠ **一覧に足すだけでは直らない。** 足しても「1回目は動いたから ok、2回目は動かないから not_rendered」が
残る。欠陥の本体は一覧の漏れではなく、**同一の再実行を失敗と呼ぶ判定**のほうである。
⇒ 到達圏は自分の面（`im-iso-src`）を読む専用の判定を持ち、**同じ到達圏の描き直しも「描かれている」**。
カメラは、既にその行き先を映しているなら**失敗ではないコード**で完了とする（`clear` が
`already_clear` で先にやっていた形）。
⇒ カメラの直しは 2 段だった。① 判定を「移動したか」から「**名指された視界になっているか**」へ。
② それでも**地名の座標は判定器に 1 バイトも届かない**（`case 'flyTo'` が解決した行き先をモジュール私有の
`_setLast` に入れて散文だけを返していた）ので、**動かした側が宣言する**——`R()` の第3引数の `meta.dest` に、
**カメラへ実際に渡した行き先**（点、`flyToBox` が成功したときだけ箱）を載せる。`case 'flyTo'` の
**成功する 4 分岐すべて**が載せ、失敗は載せない。
⚠ **判定器は宣言を読むが信じない**——申告された行き先を実際の視界と突き合わせるので、飛んでいない場所を
申告した dispatch は通らない。⚠ 検査は**出荷している `case 'flyTo'` を切り出して評価**し、
「申告した行き先＝カメラに渡した行き先」を 5 分岐について照合したうえで、**6 本目の分岐が足されたら赤くなる**
戸口調査を末尾に置いた（綴りは固定していない）。

### 6. 残したもの（直していない。次の回へ）

- ⚠⚠⚠ **何もしなかったターンが「完了しました。」で通った。**
  「ラゴス発のパンデミックを R0=2.5 でシミュレーションして。100か国目に到達するのは何日目？」に対し、
  `lastPlan()` は `steps: 0` / `calls: []` / `produced: '-'` / `mapDrawn: false` / `stopped: 'answered'`。
  読者に出たのは **「完了しました。」の一行だけ**で、シミュレーションは走らず、日数も答えていない。
  ⚠ 能力自体はある（`sim.pandemic` ／ カタログの `{"type":"playground","mode":"pandemic"}`）。
  ⇒ 問題は 2 つ。① その能力に届かなかったこと ② **IntMap が「何も生まなかったターンの『完了しました』」を
  完全な回答として受け取ったこと**。②は §5b/§5c と同じ家族（IntMap が読者に対して事実でないことを述べる）
  だが、「中身の無い一行」を一般に見分ける規則はまだ書けていない——**書けていないと書いておく**。
- ⚠⚠⚠ **1914 年のオスマン帝国は、同梱の歴史境界記録が本物の輪郭を持っている**
  （実測: 時計を 1914-06-01 にすると `IntMapTimeBorders.currentFC()` は 150 件を返し、その中に
  `Ottoman Empire` があり、`geomForCode('OTT')` は形を返す）。**それでも Atlas は AI トレースを描いた**
  ——1 手に 1m25s かけて。カタログは highlight の対象を **「ISO 3166-1 alpha-3」**と定義しており、
  オスマン帝国に ISO3 は無い。だから規則に忠実な模型ほど `query` に落ち、`query` は AI トレースへ行く。
  ⇒ **画面を描いている記録に訊く道**（過去の年では、その記録が公表している名前が対象として有効であること）を
  作るのが次の仕事。[[intmap-history-is-verified-as-history]] の範囲なので、年を名指した検証を伴う。
- 同じ回、**コンスタンティノープル／スミルナ／アレッポが 3 件とも解決できなかった**（歴史地名の記録を
