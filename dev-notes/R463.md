## R463 — **ドットは文末かもしれない、を無条件に信じていた**（Atlas の返信が URL と座標を壊す）

報告はスクリーンショット1枚。Atlas の返答の中で

```
地図中心付近の49.

10°N・19.54°E
```

と座標が2段落に割れ、出典リンクは

```
https://liptovska-mara.

eu/?utm_source=openai
```

となって、青くなっていたのは `https://liptovska-mara.` だけだった。

### 何が起きていたか

`js/atlas-reply.js` は返答テキストを HTML にする唯一の場所で、そこに**文分割器が2つ**ある。

| どれ | 何のため | 何で切るか |
|---|---|---|
| `_atlStanza` の `SENT` | 230字を超える一続きの段落を**約2文ごと**に区切って余白を作る（#R154） | `[.!?。！？…]` |
| `_dedupText` の `dedupLine` | そっくり繰り返された文を落とす（#R137） | `[.!?。！？]` |

どちらも「ドットは文末候補」を無条件に適用する。だから

- `liptovska-mara.slovakian-mountains.eu` は**3つの文**に見え、
- `21.6` / `49.10` / `19.54` は**2つの文**に見える。

`_atlStanza` は切った文を2つずつ束ねて `\n\n` で繋ぎ直すので、**束の境目が URL や小数の内部に落ちる**。
そのあとに走る markdown リンクの規則（`\[…\]\((https?:[^)\s]{4,300})\)`）も裸 URL の規則も
**URL に空白を許さない**ので、リンクは成立しなくなり、裸 URL 化だけが最初のドットまでを拾う。
スクリーンショットの「そこだけ青い」はこれ。

修正前のこの枝で、報告と同じ形の306字の段落を実際に通した結果:

```
湛水面積はおよそ21.\n\n6平方キロメートル、…地図中心付近の49. 10°N・19.\n\n54°Eに広がっています。
href="https://liptovska-mara."
```

⚠ **報告されなかった側のほうが悪い。** `dedupLine` はトークンを `''` で繋ぎ直すので**位置はずれない**——
代わりに**繰り返されたトークンを消す**。同じ URL が1つの返信に2回出ると、2本目の
`slovakian-mountains.` と `eu/tourism/index.` は1本目で既に見た文なので落ち、残りが繋がって

```
1本目 href="https://liptovska-mara.slovakian-mountains.eu/tourism/index.html"
2本目 href="https://liptovska-mara.html"
```

になる。**生きていて、普通のリンクに見えて、まったく別の宛先。** 壊れて見えるリンクは報告されるが、
こちらは報告されようがない。

### 直し方（閾値でも「賢い文末判定」でもない）

前後の文字からドットの意味を当てにいくと、略語・ホスト名・バージョン番号を1つずつ特例で足し続ける
ことになり、いつまでも取りこぼす。そうではなく、**散文でありえない範囲**——markdown リンク、URL、
メールアドレス、**裸のホスト名とファイル名**、小数と桁区切りの数——を、**どちらの分割器が文字列を見るより前に** placeholder へ
退避し、直後に戻す。切れない場所を切らないよう教えるのではなく、**切る対象からそもそも外す**。

```js
const _ATL_ATOM=/!?\[[^\]\n]{0,200}\]\([^)\s]{1,400}\)|(?:https?:\/\/|www\.)[^\s<>"']+|…|\d+(?:[.,]\d+)+/g;
```

placeholder は PUA `U+E010`/`U+E011`。`mdMini` 自身がコード・数式・表に使う `U+E000`/`U+E001` とは
**意図的に別**にしてある（`_atlStanza` が走る時点で、その2つは既に文字列の中にいる）。

⚠ **報告された形（完全な URL）を直しても、アプリが実際に一番よく出す形は直っていなかった。**
`js/atlas-answer-render.js` は構造化回答に `stripModelUrls()` を掛け、リンクを**ホスト名だけの平文**に
潰してから `mdMini` に渡す。つまり Atlas の出典として画面に最も多く出る文字列は `https://…` ではなく
`reuters.com` で、これは scheme も `www.` も持たないので最初の版の退避には掛からなかった。実測:

```
一次情報の要約は reuters.\n\ncom に、続報の詳細は apnews. com にまとまっています。
```

⇒ **裸のホスト名とファイル名も退避する。ただし TLD は小文字に限る**——限らないと、空白を欠いた英文
`the end.Next one` を1語として抱え込み、本物の文の境目を消してしまう。
⚠ **略語（`U.S.` / `e.g.`）はここに入れない。** あれは散文で、意味を当てにいくのがこの設計の拒否して
いる当て推量そのものだから、**今までどおり切れる**。直したのは「URL を壊すな」であって
「文末を賢く当てろ」ではない。

**他は1バイトも動かさない**ように置いた:

- 230 の門は**退避前の本物の段落**を測る（退避した文字列で測ると、URL の長い返信だけ整形されなくなる）
- dedup の鍵は**戻したトークン**から作る（退避したままだと鍵が短くなり、`MIN=15` を割って重複が残る）

これを主張ではなく実測にした。HEAD の `js/atlas-reply.js` と新版を**同じプロセスに両方 import** し、
見出しあり／箇条書き／番号付き／表／数式／コード／引用／太字行／重複文／短文／空／`null` の17ケースを
流して、`_atlStanza` と `mdMini` の出力が**全件バイト一致**することを確認してから commit した。

### テスト

`tests/r463-checks.test.mjs`（`test:checks` に登録）。**綴りを読むのではなく本物を実行する**——
`makeAtlasReply` を node で組み立て、実際に HTML を描かせて anchor を数える（#R447）。

| | 何を主張するか | HEAD で |
|---|---|---|
| ① | 報告された段落: 小数3つが残り、anchor は**1本**で href は**URL 全体** | 赤 |
| ② | 同じ URL が2回でも、2本目が**別の宛先**にならない | 赤 |
| ③ | 整形自体は変わらない（長い散文は今も区切られ、`##` 返信は不変、#R137 の重複除去も生きている） | **緑**（＝「直す」が「止める」になっていないことの見張り） |
| ④ | placeholder が HTML に1つも漏れない・コード／数式のトークンは今までどおり戻る・メールアドレスと `www.` ホストも切られない | 赤 |
| ⑤ | **2つの分割器が両方とも**退避後の文字列を読む（片方だけ直した将来の編集をここで落とす） | 赤 |

⚠ `⑤` があるのは、同じ規則の写しが3本あって3本目だけ直らなかったことが過去にあるから（#R447）。
ここでは写しは2本で、**両方に同じ検査を向けてある**。
