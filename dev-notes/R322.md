依頼は「R311後の未完課題集中・第2次性能改善」で、**「さらに何でもlazy化すること」ではない**と明記されていた。
7つの主題（MapLibre への重複命令・巨大 side-effect module の分離・IntMapRuntime lifecycle の接続・

それぞれ「まず測れ、測ってから決めろ」という形で書かれていた。**測った結果、7つのうち2つは「やらない」が答えだった。**

### ⚠⚠⚠ ② 「同じ命令を繰り返す無駄」は本当にあった。ただし**安い**

`js/geo-engine.js` のアダプタに、5つの命令の**回数を数える計器**を入れた（`attempted` / `sent` /
`same`＝レンダラが既に同じ値を持っていた / `absent`）。フェーズは**宣言する**——`setPaint` の中から
「なぜ呼ばれたか」は分からないので、`node scripts/frame-profile.mjs --commands` が起動・pan・zoom・
レイヤー欄・ホバー・Chronos・言語・テーマを実際に駆動して、その都度ラベルを立てる。
⚠ **駆動できなかったフェーズは 0 ではなく `(NOT DRIVEN)` と出す**——最初の実行で `language` が
0 件だったのは、言語 `<select>` の値が `jp` なのに `'ja'` を代入していて**変更イベントが起きていなかった**から。
**「測って 0」と「測っていない」を同じ 0 で書くと、後者が前者として読まれる。**

### ⚠⚠⚠ ③ だから ON にしたのは5つのうち1つだけで、決めたのは MapLibre のソース

`node_modules/maplibre-gl/dist/maplibre-gl-dev.js` を読むと:

```
Style.setPaintProperty   :60727   if (deepEqual(layer.getPaintProperty(name), value)) return;
Style.setLayoutProperty  :60701   if (deepEqual(layer.getLayoutProperty(name), value)) return;
Style.setFilter          :60672   if (deepEqual(layer.filter, filter)) return;
GeoJSONSource.setData    :48755   （比較が一つも無い）
```

**3つはレンダラ自身が既に同値を捨てている。** その手前にもう1つ比較を置いても、レンダラの仕事は
1つも減らない——実測でも `cmp` の増加が `call` の減少とほぼ相殺している（paint: 2.5→2.0 ms）。
`setData` にだけ比較が無く、毎回コレクション全体が worker へ渡って**再パースされる**。
⇒ **`sourceData` だけ ON、他の4つは数えるだけ。** `filter` / `featureState` は**どのシナリオでも0回**
呼ばれないので、そもそもキャッシュを作る対象が無い。
⚠ この判断は `tests/r322-checks ①` が**両方のファイルを読んで**固定している——MapLibre 側が
`setData` に比較を足したら、あるいは `setPaintProperty` から比較を外したら、その検査が赤くなって
どちらが変わったかを言う。

**省略の安全は2つの規則が作っている**（`_sourceHolds`。レンダラが今持っている payload との deep-equal で、
何も保持しないので陳腐化しない）:
1. **同一オブジェクトは根拠にならない**——呼び出し側がその場で書き換えたかもしれないので必ず適用する。
2. **比較には作業量の上限がある**——上限内に等しいと**証明できなかった**ものは適用する。
「終わらなかった」を「等しい」として扱わないのが、大きなコレクションで安全側に倒れる仕組み。

### ⚠⚠⚠ ⑥ `runtime.dispose()` は「二度と開けない」という意味だった

`js/runtime.js` のライフサイクル（`define`/`load`/`activate`/`suspend`/`dispose`）は #R234 から
**呼び出し元が1つも無かった**。接続してみて、2つの欠陥が出た:

1. `dispose()` の最後が `CAPS.delete(name)` で、**定義ごと消していた**。次の `activate` は
   「no such capability」で拒否される——**閉じたら二度と開けない機能**を作る動詞になっていた。
   ⇒ 定義は残し、`state='disposed'` にして `c.p`（load のメモ）だけ落とす。次の activate は
   `def.load` からやり直す。
2. 掃除が `READ`/`WRITE`/`ONCE`/`TIMERS` だけで **`IDLE` を見ていなかった**。しかも最後の行で
   `SUSPENDED.delete(name)` するので、**dispose 済み capability の idle タスクは skip すらされず、
   たった今解放した資源に対して走る**。

⚠ **どちらも「検査を書いてから実装を直した」**——`tests/r322-checks ⑤⑥` を **origin/main の
`js/runtime.js` に当てて、両方が赤くなることを確認した**（「the definition must survive dispose」
「the idle queue was not swept」）。緑になる検査は、何も主張していないかもしれない。

接続したのは3つで、**それぞれ違う種類の資源を持つもの**を選んだ:

| capability | activate | suspend（速い再開のために残す） | dispose（返す） |
|---|---|---|---|
| `wx.wind` | 風レイヤー ON | OFF。**WebGL レンダラは残す** | `js/wx-wind.js` の `dispose()`＝tex2・FBO2・VBO2・program2 を削除 |
| `sim.tsunami` | 津波パネル | 閉じる（ジョブは abort、スレッドは残す） | worker を terminate、モデルとパネル DOM を破棄 |
| `sat.live` | 実時間衛星 ON | OFF（interval・3リスナー・詳細パネル。**カタログは残す**） | カタログ・導出位置・レイヤー・軌道を破棄 |

⚠ **`js/wx-wind.js` の `dispose()` は #R276 から存在して、一度も呼ばれたことがなかった**——
`js/weather.js` に "dispose" の文字が無い。風を一度でも点ければ、GL オブジェクトはタブの寿命ぶん生きる。
⚠ **公開の口は register を通し、定義側は内部関数を名指す**（`API.open = openPublic` / `def.activate = open`）。
同じ関数にすると activate が open を呼び、open が activate を呼ぶ。
⚠ **worker を返す動詞と、worker が墜ちた経路は別物**——`dispose()` は**在庫のジョブを必ず決着させてから**
terminate する（terminate されたスレッドを待つ promise は永久に解決しない）。津波側は `null` で解決
（`abort` と同じ答え）、衛星タイル側は **reject**（タイルの promise は絵を約束していて、`null` は
「絵が無い」を絵の位置に置くことになる）。`onerror` 側は `tried` を戻さない——墜ちた worker を輪で作り直さない。

**10サイクル開閉の実測**（`node scripts/frame-profile.mjs --lifecycle --cycles 10`）:
3つとも後半のヒープ傾きは 0〜0.57 MB/cycle、DOM ノードと timer と camera 購読は 0、
**dispose 後の再 activate は3つとも `active`**。`sat.live` は dispose でヒープ 222.04→188.92 MB、
レイヤー 69→63。
⚠ **`sat.live` だけ listener が毎サイクル +4 に見えた**が、`addEventListener` を包んで発生源を記録したら
**2サイクルで 75 件すべてが MapLibre 自身の `AbortSignal`**（`triggerRepaint` の中）で、
うち 72 件が除去済み。**IntMap のコードが足すリスナーは0件。** サンプリングの瞬間に飛んでいる
フレーム要求の数を見ていた。
