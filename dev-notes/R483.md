## R483 — **★は3年ぶんの機能で、それを見る場所だけが無かった**

依頼は3つ。①「基本表示の、カスタムにしたときに出てくる選択肢は、もっと縦方向をコンパクトに。」
②「基本表示のあとに、お気に入りにしているレイヤーがある場合のみ、お気に入りレイヤーカテゴリを
ほかとおなじように作り、出すように。」③「Atlasのユーザー送信メッセージの吹き出しを、
フロストガラスの質感に。」

### ② の前提が、実は欠落そのものだった

「お気に入りにしているレイヤーがある場合のみ」という言い方は、**お気に入りが既に在ること**を
前提にしている。実際に在った——`window.imLayerFavs`・`intmap_settings.layerFavs` への保存・
アカウント同期・★の注入（`js/layer-favs.js`、#R200）まで全部生きている。

⚠⚠⚠ **無かったのは「一覧を描く面」ではなく、その面への到達路である。**
一覧（`#layer-fav-section` のチップ帯）は `index.html` に在るが、置き場が `#layer-dropdown`
——**永久 `display:none` のレジストリ**の中で、しかも `css/intmap.css` がタイルモードでは
`display:none !important` で明示的に消している。デスクトップのタイル閲覧面にも、携帯シートの
タイルモードにも、**星を付けた結果を見る場所が1つも無かった**。
「星は付くのに、付けた星がどこにも出ない」——機能の欠落ではなく、面の欠落。

### 棚は「移動」ではなく「2枚目」

⚠⚠⚠ お気に入りの行を自分のカテゴリから**動かして**棚に集める実装は、この repository が
既に一度払っている形である。`reorganizeLayerPanel` の `order.push` は要素を**移動**させるので、
誰も引き取らない行はベータへ落ちる（#R271 で 🕒 タイムゾーンが実際にそこへ出た）。
**複製なら**レイヤーは自分のカテゴリに残り、件数バッジも「その他N件」も分類について嘘をつかない。

⚠⚠⚠ **ただし複製を作った瞬間、#R469 が書いた門が壊れる。**
`open()` / `mountInto()` は「描かれたタイル数 ≠ `rowsFromDropdown().length`」でグリッド全体を
組み直す——#R72 の「layersをクリックしたときの反応が非常に遅い」に対して書かれた安い経路である。
複製が数に入ると**両者は永久に一致せず、パネルは正しいまま開くたびに全部組み直される**。
これは**見た目には何も起きない**壊れ方で、#R469 が3択の行について実測した当のものだ。
⇒ 複製は `data-fav="1"` を持ち、**門4本すべて**が `.lst-tile[data-lid]:not([data-fav="1"])` を数える。
**1本でも漏れたら同じ症状になる**ので、`tests/r483-checks` ② は4本を数えて全部に `:not()` を要求する。
実測（ブラウザ）: 閉じて開き直したとき `.lst-root` が**同じ要素のまま**＝建て直していない。

⚠⚠ **1枚のレイヤーに2枚のタイルがあるなら、状態を配る側は複数形でなければならない。**
チェックボックスの `change` を受けるリスナは `const tile=h.querySelector(sel)` ＝**単数**で、
2枚目は古い `.on` のまま残る（「レイヤーのオンオフが地図上と一致していない」＝#R72 の報告の形）。
`querySelectorAll(...).forEach` へ。実測: `dl-climate` を棚から押して、両方のタイルが
`checked` に追従（t+0 / t+100 / t+600 / t+2100 の4点で一致）。
同じ理由で★も `data-key` を持ち、棚から星を外すとカテゴリ側の金色も消える（実測）。

⚠⚠ **「ある場合のみ出す」を分岐で書かない。**
`filterTiles` は可視タイル0のグリッドと**その見出し**を既に隠す。同じ `display` を2つの機構で
決めるのは #R469 が名指しで警告した欠陥なので、棚は常に組み立てて、空なら既存の機構に消させる。
実測: 星0で見出しもグリッドも `display:none` / 星2で `grid` ＋ 見出しに件数バッジ 2。

⚠⚠ **★を書き換える口は2つある。**
タイルの `.lst-star`（`js/map-ui.js`）と classic 行の `.lyr-star`（`js/layer-favs.js`）で、
どちらも `window.imLayerFavs` を直接触る。片方だけが知らせれば、もう片方から星を付けたときに
棚が更新されない。⇒ **両方**が `intmap-layerfavs` を撃ち、タイル閲覧側が購読する。
`js/layer-favs.js` は `js/map-ui.js` を import しない——**契約はストア、イベントは「動いた」の合図**。
実測: classic 行の★から棚が 1→2。
⚠ `IntMapHiddenLayerRows`（`cb-countries` / `dl-contours`）はタイルを持たないので棚にも出ない
——実測でそのとおりになった（★は付き、classic のチップには出る）。

名前は既存の i18n キー `favLayers` から引く。**9言語すべてに既に訳がある**ので、
新しい文字列は1つも増えていない。実測: 言語を jp に切り替えると見出しが「お気に入りレイヤー」に
なり、位置は基本表示の直後のまま。

### ① 共有された寸法を、片方の都合で縮めてはならない

⚠⚠⚠ 素直に `.lst-tile.lst-row` を縮めると通ってしまうが、それは間違いである。
`.lst-sw`（42×26・つまみ 20px・移動 16px）は `js/map-ui.js` 自身のコメントが
「ウィジェット群の `.wgt-sw` と**同じ1つの物**」と宣言しているスイッチで、base を縮めると
**依頼と無関係なウィジェット側のスイッチが黙って一緒に縮む**。
⇒ 縮むのは `.lst-basic`（カスタムで出る11行）だけ。3択のモード行は 46px のままで、
結果として**主選択（3択）と副選択（11行）の階層**になる——これは依頼の言葉どおりでもある
（「カスタムにしたときに出てくる選択肢」）。

小さいほうのスイッチは**同じ 3px の余白を保った小さい実例**（34×21・つまみ 15px・移動 13px
＝ 34−3−15−3）。`tests/r483-checks` ① はその算術を検算し、同時に base の 42×26/20/16 が
1バイトも動いていないことを確かめる。

⚠ 行間は grid の `gap` なので子ごとに変えられない。**隣り合う `.lst-basic` の間だけ**を
負の `margin-top` で詰める（先頭の1行は「カスタム」との境界なので 6px のまま）。

実測（デスクトップの右サイドバーと携帯シートの両方）: 選択肢 34px×11・行間 4px、
モード行 46px×3、スイッチ 34×21。1行あたり 52px → 38px。

### ③ 白い文字は、下地が不透明でなくなった瞬間に読めなくなる

⚠⚠⚠ 吹き出しは `#fff` on `--atlas-grad`（不透明なアクセント掃引）だった。
実測の最悪コントラストは**紫の端で 3.52:1**。ここをガラス（0.55 相当のアルファ）にして
白を残すと **2.2:1** まで落ち、白が生き残る不透明度（〜0.9）は**もはやガラスではない**。
⇒ 塗りを `--atlas-glass`（アクセント主導の低アルファ掃引）に、文字を `--text-main` に。
**文字色はついでの調整ではなく、ガラスを可能にしている当のものである。**
実測（light/dark × 白い地図/黒い地図 × 3ストップ ＝ 12通り）: **最悪 5.48:1**・最良 13.66:1
——**全組み合わせで改善**。

⚠⚠ **同じ理由で、吹き出しの中で白を前提にしていたものを取り残さない。**
ファイルチップは `rgba(255,255,255,0.16)` の地に `#fff` で、**白地に白**になるところだった。
画像行も `background:none` だけでは**写真の周りにガラス板**が残る（`border` と
`backdrop-filter` も剥がす）。

⚠⚠ **入れ子の blur はデスクトップではほぼ無効である。**
吹き出しは既に blur を持つ `#atlas-panel` の内側にあり、その背後は合成済みの滑らかな面なので、
子に `backdrop-filter` を足してもぼかす対象がほとんど無い。それでも書くのは、
**携帯タブでは親の blur が `none !important` で、そこでは本当に地図が背後に在る**から。
デスクトップで frost に見えているのは、透過・ヘアラインの縁・inset の艶のほうである。
——このことをコメントに書いた（書かないと次の人が「効いていない」と判断して剥がす）。

⚠⚠ **`css/intmap.css` に350ラウンド立っていた1文が、この変更で嘘になった。**
「選択中の Atlas タブ＝**ユーザー吹き出しと同じ塗り**」（#R130/#R132）。タブは押された感を出す
不透明なコントロール、吹き出しは半透明な面で、**同じアクセントを追うが同じ塗りではない**。
写しを残すと次の人が再統合するので、その場で書き換えた。
`--atlas-glass` は `--atlas-grad` の**再定義ではなく2本目のトークン**で、タブは無傷。
⚠ トークンは light と dark の**両方**で定義する（片方だけだと、そのテーマで `var()` が空になり
縁も影も黙って消える）。`tests/r483-checks` ④ が両ブロックを見る。

⚠⚠ **20 バイト足しただけで、他ラウンドの検査が「製品が壊れた」と名乗った。**
`tests/r408-checks` ⑥c は `function open(` から**固定 2,500 バイト**を切り出し、その中に
`IntMapLayerPreviews.kick(sb)` があることを要求していた。#R483 が open() 内の1行に
`:not([data-fav="1"])` の **20 バイト**を足した結果:

| | `kick(sb)` の終端 | 予算 2,500 |
|---|---|---|
| R482 (LF＝CI) | 2,471 | 余白 29 |
| R482 (CRLF＝作業コピー) | 2,492 | 余白 8 |
| **R483 (LF)** | **2,491** | **余白 9** |
| **R483 (CRLF)** | **2,512** | **12 バイト超過＝赤** |

⚠ **窓は本体ではなく、改行コードとコメント量に依存する近似だった。**
`.gitattributes` は `js/*.js` に `eol=lf` を課していないので、**同じ commit が手元で 2,512・
CI で 2,491** になる（窓の中に改行が 21 行）。CI は緑のまま通ってしまう＝
**#R478 と同じ形（開いていないところで動く判定は、そのラウンドでは測られていない）**。
しかも報告文は「サイドバーを開いたら kick する」＝**製品が壊れたと名乗る**。
⇒ 窓を**次の関数宣言まで**（`function close(` の直前）に変えた。改行コードに依らず、
育っても切れない。実測: as-on-disk / LF / CRLF の3通りで本体 4,323〜4,361 バイト・判定は同一。
⚠ **緩めたのではなく、正確にした**——旧 2,500 は open() の実体 4,361 バイトの **57%** しか
見ておらず、否定アサーション（`_onScreen(sb)` を足すな）は**残り 43% に対して無力だった**。
新しい窓では open() 全体に効く。

### このラウンドで踏んだ、コードの外のもの

⚠ **生の NUL バイトを1つ混入させかけた。** `FAV_SEC` の値を `'\0favs'` のつもりで
**バイトそのもの**として書いてしまい、`git ls-files --eol` が `js/map-ui.js` を
**`w/-text`（バイナリ）**と判定した。結果は ⓐ CRLF 正規化が効かず CI(Linux) がこのファイルだけ
CRLF で checkout（`\n` を要求する正規表現が踏む #R283/#R274 の地雷）、ⓑ diff が 2,504 行の
全文置換でレビュー不能、ⓒ `git grep` が `Binary file … matches` を返す＝**このファイルが
文字列検索から落ちる**。⚠ `check:static`（acorn パース）は **NUL が JS 文字列リテラルとして
合法なので通る**。⇒ `'__favs'`。意図（言語変更に耐える固定キー）は同じまま。

⚠⚠ **build stamp は「自分のラウンド」ではなく「DEV-NOTES に載っている最大のラウンド番号」を名乗る。**
`tests/r207 ⑬` / `r264 ⑦` / `r301 ⑦` は DEV-NOTES の `## R<n>` 見出しの **Math.max** と
`window.__imBuild` / `window.INTMAP_BUILD` を突き合わせる。#R174 が書いた「毎ラウンド上げる」は
**番号が単調に増えている間だけ**正しく、番号を先に取って後から merge するこの運用では
**追い越されることがある**——**R484・R485 が R483 より先に merge された**ので、R483 であるこのラウンドが
スタンプを R483 に下げると**3本が同時に赤くなる**（実測）。⇒ スタンプは R485 のままで、
`index.html` はこのコミットで**1バイトも変えていない**。

⚠ **ラウンドの途中で R480・R482・R484・R485 が merge された。** 4度 rebase して取り込み、`package.json` の
`test:checks` の衝突は毎回**片方を選ばず両方を足した**（263 → 268）。`docs/TESTING.md` の本数も
同じコミットで 268 へ。
⚠ `tests/perf-baseline.json` の `eager.cssRaw` は **R480 が既に 326,601 → 328,887 へ動かしていた**
ので、rebase 前に測った超過は R480 のぶんだった。**このラウンドの CSS 増は実測 +0.5 kB**
（トークン4本×2テーマ。コメントは minifier が全部落とすので値だけが乗る）で、
rebase 後は `perf-budget: within budget`。**天井は動かしていない。**
