## R356 — **変数はモデルごとに違う、という一つの実測が設計を決めた**

依頼は「IntMap の気象機能を Windy 級へ引き上げろ」で、その第一段は
**「複数予報モデルの切替・比較」**である。

このラウンドが最初にやったのは実装ではなく**実地確認**だった。現行の風・気温レイヤーが
読んでいる `map-tiles.open-meteo.com` を叩いてみると、**同じ URL 規則・同じ Range Read で
58 モデル分の空間データが公開されていた**（SDK 同梱の 64 domain のうち live 58／404 が 6）。
ファイル規則はモデル非依存で、ECMWF 9 km・ECMWF 0.25°・GFS 0.13°・ICON・ICON-D2 の
どれに対しても 206 Partial Content が返る。

**つまり「地図を描くために地点 API を数千回叩く」必要はどこにも無い。** 依頼が §4.3 で
禁じている構造を避ける道が、すでに使っているホストの中に実在していた。

---

### 実測が設計を決めた三つの事実

**① 変数はモデルごとに全く違う。**

| domain | 変数 | 気圧面 | 段数 | 予報期間 |
|---|---|---|---|---|
| `ecmwf_ifs`（現行・9 km） | 35 | **0** | 109 | 6 d |
| `ncep_gfs013`（13 km） | 29 | **0** | 209 | **16 d** |
| `dwd_icon`（13 km） | 123 | 18 | 93 | 5 d |

**ECMWF IFS HRES に気圧面は1つも無く、GFS 0.13° に `pressure_msl` も `cape` も
`dew_point_2m` も無い。** そして `.om` は存在しない変数を読んでも例外を投げない——
何も返らないだけである。だから「同じ変数で別のモデルを読む」を無条件に許せば、
**9 レイヤーのうち 4 つがモデル切替の瞬間に黙って空になる**。これは #R276 が
`ec-sst` で 9 ラウンド払った欠陥と同じ形で、材料だけが違う。

⇒ 「このモデルでこれを見せてよいか」は**共通部分**であって宣言ではない。
`js/wx-models.js` の `availability()` が
**「提供の可否 × ライブ metadata × カバー範囲 × 変数 × 時刻」**を突き合わせ、
`no_such_variable` / `no_such_level` / `outside_coverage` / `no_metadata` /
`outside_forecast_window` のいずれかの**理由**を返す。ピッカーはその選択肢を
`disabled` にし、`setModel` は理由付きで拒否する。**どちらか片方では足りない**
——ピッカーは metadata が届く前に組まれることがあり、共有リンクはピッカーを通らない。

**② レンダラ SDK の `getColorScale()` は、知らない変数に気温のスケールを返す。**

実装は `lookup(v) ?? settings.temperature` で終わっている。null でも例外でもなく、
**単位ごと気温の表**が返る。58 domain が公開する live 変数 857 に対して測ると、
**212 がその分岐に落ち、うち 52 は気温ではない**——PM2.5・PM10・オゾン・二酸化窒素・
二酸化硫黄・一酸化炭素・ダスト・エアロゾル光学的厚さ・海流の u/v・海面高度・降雪・
天気コード・うねり方向の2つ。**PM2.5 の凡例に °C と出ても、何ひとつ落ちない。**

⇒ 「存在しない変数」を1つ問い合わせて、その答えと同じものが返るかを比べれば、
フォールバック分岐に落ちたことを**厳密に**判定できる（推測ではなく分岐そのもの）。
`tests/r356-checks.test.mjs ⑧` は、SDK のバージョンを固定した実測 fixture に対して
**「出荷レイヤーがこの分岐に落ちるのは、そのレイヤー自身が `kind:'temp'` と
言っているときだけ」**を要求する。今日の 8 レイヤーは 2 温度層がフォールバックで
6 層が自前——ぴたりと一致する。

**③ 軸は index ではなく瞬間である。**

ECMWF は 1 時間刻み 109 段、GFS は 209 段で 16 日、ICON は 93 段。index 30 は
どれでも別の時刻である。だからモデル切替は**画面に出ている有効時刻に最も近い段**へ
移る（fixture 実測でずれ ≤1.5 時間）。これは #R276 が「新しい run は index ではなく
壁時計の瞬間を保つ」と決めたのと同じ規則で、**モデル交代は同じ出来事の歩幅が
大きい版**にすぎない。

### 構造

**`js/wx-models.js`（新設）が「どのモデルが存在するか」の正本。**
宣言するのは提供の可否・表示名・公称解像度・出典機関・ライセンス・役割**だけ**。
格子・カバー範囲・変数・気圧面・予報期間は SDK の domain 表と各モデル自身の
`latest.json` から**導出する**。手書きの変数表は上流が1つ足した日から間違いになり、
しかも**黙って**間違う。

**`js/wx-ecmwf.js` は `createModel(cfg)` になった。** 1,757 行（rebase 後 1,992 行）の
モジュールスコープの状態を、モデルごとのインスタンスに閉じた。
変換は**機械的に行い、行の保存を検査した**——元の行のうち**消えたのは意図した 5 行だけ**
（`BASE` / `META_URL` / `DOMAIN` / `window.IntMapECMWF =` / `MODEL:` の行）。

⚠ **`window.IntMapECMWF` は写しではなく、既定モデルのインスタンスそのもの。**
12 ファイル 64 呼び出しが名指ししているので、ファサードを作れば状態が二重になる。
`CONSTITUTION` §2.2 が禁じているのはまさにそれである。

⚠ **ページに1つしか無いものは factory の外に残した**——SDK・`om://` の登録・
開いたファイルのプール（`READER_MAX` は**ページ全体**の予算であってモデルごとではない）・
32 MB のブロックキャッシュ・色の ramp（1,041 段と 2,341 段。モデルごとに作り直せば
同じものを 400 kB ぶん余計に持つ）・スタイルレイヤーの索引・`Intl` の memo。

⚠ **本体を再インデントしていない。** 1,300 行を関数で包んで全部 2 スペース動かせば、
コメントが仕様の一部で 17 のテストファイルが実測値を部分文字列で引用しているコードに
対して、**誰にもレビューできない空白差分**になる。入れ子は本物、インデントは従来どおり。

**`js/weather.js` は 3 状態を持つ。**

```
requested (state.model)  利用者が選んだもの   … <select> が表示する
loading                  いま組み立て中のもの … null なら何も飛んでいない
displayed                実際に塗られているもの … ⚠ 利用者に見せる文言は全部ここから
```

`displayed` への代入は**コード全体で1か所**（`commit()`）、呼ばれるのは
**新スロットの不透明度を上げ、旧スロットを落とすのと同じターン**。
要求から凡例を作れば、読み込みの数秒間ずっと「画面に無いもの」を説明することになる。

### rebase が作った、どちらも正しい半分どうしの衝突

作業中に origin/main が R325 と R333 を取り込んだ。#R325 はラスタ源に
`omRasterUrl`（`tile_size` 付き）を与えており、本ラウンドはレイヤーごとにモデルを
与えていた。**自動マージは競合を報告せず通った**——そして

```js
GE().layers.addSource(sid,{type:'raster',url:EC().omRasterUrl(cfg.variable), …})
```

という行が残った。`cfg` がスコープにあるのに `EC()`（既定モデル）である。
**GFS を選んだレイヤーが、色だけ ECMWF のファイルから描く**。凡例も地点値も
粒子も GFS を指しているのに、である。これは
「地図、粒子、凡例、地点値が同じ表示状態を参照」が禁じる唯一の状態そのもので、
**git がそれを競合と呼ぶ理由は無い**（両方の半分が、それぞれ単独では正しい）。

⇒ rebase のあとは、**自分が触った関数を1つずつ読み直す**。差分の competing hunk
だけを見るのでは足りない。

### 検査

`tests/r356-checks.test.mjs` **12 本**。fixture は捕獲した**実データ**
（`tests/fixtures/om-models/` の 6 モデル ＋ SDK の色スケール実測）で、
手作りの形ではない——手作りなら「テストを書いた人が期待した変数」が入っていて、
このラウンドが唯一仮定してはいけないものがそれである。

既存の 11 の assertion が `EC()` というリテラルを pin していた。**閾値を緩めず、
答えが引っ越した先を読む**形に追随させた。1 本（`R276 ⑦`）だけは追随ではなく
**主張が変わっている**ので、両方の半分を別々の行にして**強くした**：
「どのモデルも持っていない変数の行は消える」＋「持っていないモデルはそのレイヤーに
選べない」。前者だけでは、モデルを選んで空の地図を見ることができてしまう。

### 起動コストを 1 モジュールぶん上げた——その理由

`npm run check:perf` は eager を**両方向のラチェット**で見ており、`eager.modules` は
**個数**なので許容幅がゼロである。実測:

```
                      measured      ceiling(前)      Δ
  eager raw          4378.3 kB      4367.6 kB     +10.7 kB   （許容 21.8 kB）
  eager gzip         1459.6 kB      1455.8 kB      +3.8 kB   （許容  7.3 kB）
  eager brotli       1111.9 kB      1108.8 kB      +3.1 kB   （許容  5.5 kB）
  eager requests             6              6           0
  eager modules            279            278          +1   ← 許容 0 で FAIL
```

増えた 1 本は **`js/wx-models.js`** で、これは **eager でなければならない**。
`js/wx-ecmwf.js` は読み込み時に `window.IntMapECMWF = model(null)` を評価し、
**12 ファイル 64 呼び出しがそのオブジェクトが同期的に存在することを前提にしている**。
レジストリを遅延させれば、それらが全部 `undefined` を見る。

バイトのほうは 3 行とも許容の内側で通ったが、**ラチェットなので `--update` は 4 行すべてを
新しい実測値へ動かす**。⚠ **brotli の残り余裕は 2.5 kB しか無かった**——次のラウンドが
eager に何かを足すときは、まずここを見ること。

⚠ **`requests` は 6 のまま**である（§19.4 の「eager request 数：増加なし」）。
新しいモジュールは既存の main チャンクに入っており、**起動時の往復は 1 回も増えていない**。

**そしてもう一つの予算——`appShell` の行数——は、1 行も使わずに済ませた。**
`tests/r168 #8` の天井は **8,000 行未満**で、rebase 後の上流は **7,999 行**、つまり**余裕ゼロ**。
最初は `src/main.js` に `import '../js/wx-models.js';` を足していて、それだけで 8,001 行になった。

⚠ **「天井を上げる」ではなく「そこに置く理由が本当にあるか」を問い直した。** 答えは
**無かった**——`src/main.js` に import 行を置く意味は「読み込み順を entry が決める」ことだが、
**この依存は順序の都合ではない**。`js/wx-ecmwf.js` はレジストリ無しにインスタンスを 1 つも
作れないのだから、依存は**エンジン自身のもの**である。so `import './wx-models.js';` は
`js/wx-ecmwf.js` の中にある。`js/wx-ecmwf.js` は appShell に入らないので**行は無料**で、
しかも import は巻き上げられるので**順序の保証は entry に頼るより強い**。

⚠ 予算に押されて出た答えのほうが、押される前の答えより正しかった。

### 9言語の掃引で出た、このラウンドとは別の2件

**① 出典ページの1文が、55 ラウンド 3 言語で欠けていた。**
`sources.html` の Open-Meteo の項を全 9 言語で書き直そうとしたところ、
**de / ru / es にはその一文が最初から存在しなかった**。`grep -c ECMWF` は
en / ja / zh-Hant / fr / ko が 1、**de / ru / es が 0**。#R276 がこの文を足したとき
5 言語にしか入れておらず、**鍵は 9 言語すべてにあるので i18n 監査は 417/417・
100% のまま**だった。

これは #R313 が測ったのと同じ形である——**ゲートは「テンプレートが 9 言語あるか」を
見ており、「その値が同じ事実を述べているか」は見ていない**。1 つの鍵の値の中に
複数の文があるとき、片方の文だけが欠けても被覆は 100% を保つ。3 言語は今回
**差し替えではなく新規追加**になった。

**② `printf 'é'` はロケール依存で、壊れた文字を UTF-8 のふりをして書く。**
フランス語の `météo` を shell の `printf` 経由で JSON に書いたところ、ファイルには
**U+FFFD が 2 つ**入った。ターミナル表示だけの問題に見えたが、
`[...s].map(c=>c.charCodeAt(0))` で読むと本当に 65533 だった——**表示の artifact と
本物の破損は、目では区別できない**。9 言語ぶんの locale を全部走査して
U+FFFD が 0 件であることを確かめてから先へ進んだ。⚠ **非 ASCII を含む翻訳を
shell 経由で書かない**（このリポジトリの `scripts/i18n-append-*.mjs` は JSON を
node が読むので、JSON ファイル自体を node かエディタで書けば通る）。
