## R585 — **実測放射線のレイヤー：欧州の集約は使えず、原発の一覧は12件の手書きで、その1つは130km ずれていた**

〈利用者「放射線レイヤーを追加して。実測放射線。これは今ある放射性プルーム「シミュレーション」と別物。
EURDEPには欧州約5,000観測所の毎時γ線量率があります。最大35日前まで閲覧可能です。
原発 → 実測線量 → 風 → IntMap放射性物質拡散simulation が一続きになる。」
出典の選定は「任せる。最終的なグラフィックが統一的であればいい」、
時間軸は「各出典が実際に持つ深さまで遡る」、原発は「IAEA PRIS + OSM/Wikidata で実在の台帳を作る」で確認済み〉

### 1. ⚠⚠⚠ 名指しされた出典が、技術的にもライセンス的にも閉じていた

EURDEP を**実際に叩いて**確かめた（2026-09-09）。**推測ではない。**

- **値を返す公開経路は 1 本しかなく、それが落ちている。** `redata.jrc.ec.europa.eu/gis/` の OGC WPS
  （`PointGDRv4` / `HexBinGDRv4`・GeoJSON 出力）は**全変種で 503**。同ホストの `/oss/` `/chart/` は
  200 を返すので、**WPS だけが死んでいる**。
- 生きているのは ①観測局レジストリ（Atom・**6,259 局・値は 1 つも無い**）②`/api/dates`（時刻だけ）
  ③局別の**チャート PNG**。`?format=json` を付けても**同じ PNG が返る**。
- ⚠ **その PNG の中身が 2024 年 5 月で止まっている**（Atom の `updated` も全局 2024-05-06）。
  「毎時・最大35日」という前提そのものが、公開側では既に成り立っていない。
- **35 日遡れる Advanced は CAPTCHA の内側**、本体は EU Login の内側。
- ライセンス（同意画面の原文）: 「All data that is exchanged via EURDEP are subject to copyright of
  the original data provider and cannot be used for other purposes, including scientific research,
  without their prior written agreement.」

### 2. ⚠⚠⚠ 取れてしまう迂回路があり、その「使ってはいけない理由」を上流自身が書いていた

ドイツ BfS のオープンデータ WFS には **`opendata:eurdep_latestValue`** が実在する——
**3,633 局・44 か国・µSv/h・座標つき・CORS `*`・鍵不要**。叩けば 200 で返る。
**1 行も使っていない。** 理由は BfS の利用条件の中にある:

> Daten von Drittanbietern stehen unter der jeweiligen Lizenz des Datenanbieters.
> （第三者提供のデータは、当該提供者のライセンスに従う。）

つまり BfS 自身の DL-DE/BY-2.0 は**この層に及ばない**。**取得できることは、表示してよいことではない。**
これは道徳の話ではなく検査になっている——`tests/r585-checks.test.mjs` ④ が、**出荷ツリー
（`js/` `src/` `supabase/functions/`）のコードに EURDEP のホストを指す URL が 1 本も無い**ことを測る。
⚠ **コメントは剥がしてから測る**——理由を書いた文が、理由を守る検査に落とされてはならない。

### 3. 代わりに使ったもの — 6 網・7,172 局（本番実測）

再配布が**明示的に許されている**ものだけ。一覧の正本は
`supabase/functions/_shared/radiation-sources.js`（各 provider が id・出典表記・ライセンス・上流の
単位・量・遡行日数・CORS の要否を**自分で宣言**し、コードは宣言に従う。`switch(country)` は無い）。

deploy 済みの本番関数を叩いた実測（`?mode=latest`・4.8 s・1,187,709 B・`x-intmap-rows: 7323`）:

| id | read | 局 | 量 | ライセンス |
|---|---|---|---|---|
| de-bfs | true | 1,582 | H\*(10) | DL-DE/BY-2.0 |
| jp-nra | true | 5,340 | ambient-gamma | 政府標準利用規約 2.0 |
| fi-stuk | true | 239 | H\*(10) | CC BY 4.0 |

⚠ **上流について、依頼に書いてあった表が 3 か所間違っていた**（実測が正しい）:
`ua-seb` の現在値 API は存在せず data.gov.ua にあるのは **604,935,935 バイトの ZIP 1 本**で、
`saveecobot.com/api/radiation` は **401 No API key**（座標だけの台帳は線量図にならないので**入れていない**）。
`us-epa` の唯一の無鍵経路は**局×年に 1 本の CSV**で **140 リクエスト・67.3 MB・102 秒**。
`fi-stuk` は 241 ではなく **239 局**。

⚠ **`us-epa` は「名前で」外していない——要求数の予算で外れる**（`MAX_UPSTREAM_REQUESTS`）。
`reason:'chunked'` と名乗り、`&provider=&chunk=N`（28 回）で到達できる。
**クライアントは地図を描いた後に背景で 28 個を追いかける**——空のアメリカを世界の放射線地図に
置いたままにすると、**空白の国は「安全な国」と読まれる**から。

### 4. 統一グラフィック＝「クライアントに出典ごとの分岐を持ち込ませない」

上流は µSv/h・nSv/h・µGy/h をばらばらに使う。**正規化はサーバー側で 1 回だけ**（`toNanoSvH`）。
⚠ **知らない単位は例外を投げる。黙って 0 にしない。**
各レコードは**上流が名乗った量**を保持するので、ポップアップは「何を測った値か」を言える——
**単位を揃えたことは、同じものを測っていることではない。**

⚠ **`stations` と `reference` は別の配列**。後者は「期間の平均」（今は RIVM の 2011 年年平均 151 局。
RIVM 自身が「実測値表示は工事中、最新は EURDEP を見よ」と告知している）。
**2011 年の平均を毎時の値と同じ色の尺度に載せると、地図が誰も測っていないことを言い出す。**
だから reference は**時計がその期間に入ったときだけ**描き、それ以外は凡例が
「ほかに N 局が期間平均を公表している」と言う——これは他の全出典と同じ規則である。

⚠ **「検出器の下限未満」は「ゼロ」ではない。** 実測 **720/7,172 行**。0 と印字すれば
**その機器に不可能な主張**を地図に載せることになり、捨てれば稼働中の観測局が消える。
`b:1` を持たせ、ポップアップは `< 19.9 nSv/h` と「この検出器の測定下限未満」を出す。

### 5. 色の尺度は、各網が自分で公表している行動閾値に留めた

50/100（自然の地殻放射線の帯・実測: RIVM 151 局の年平均が 56.0–116.0、BfS 稼働 1,582 局が 47–226 nSv/h）、
**200**（RIVM が公表する自動警報の閾値）、**1,000**（スイス NADAM が自網について公表する警報閾値。
⚠ **NADAM のデータは使っていない**——オープンライセンスが無い。公表された事実として引用しただけ）、
**2,000**（RIVM が公表する安全地域への通報閾値）。
**取得した集合の分布から作らない**——それだと 1 時間ごとに世界の色が変わり、2 枚のスクリーンショットが
比較できなくなる。`tests/r585-checks.test.mjs` ① が**モジュールを実際に評価して得た RAMP** と
`docs/RADIATION.md` の由来表を突き合わせる。

⚠ **測定と模型は色を共有してはならない。** 検査 ② が、`js/radiation-layer.js` の RAMP と
`js/sims.js` の `ZONES` に**共通の色が 1 つも無い**ことを測る（`ZONES` は写さず**ファイルから読む**）。
変異試験で赤を確認。

⚠ **凡例と Atlas が必ず言うこと**: 50–200 nSv/h はほぼ全世界で通常の自然放射線量／
**降雨だけでラドン子孫核種が洗い落とされて最大 3 倍**（BfS の記述）／大半は未検証データ／
だから 1 局が高いこと、近くの複数局が同時に高いことは**放出の証拠にならない**（近い局は同じ天気を共有する）。
⚠ **BfS は利用条件の中で「事実に即した提示」を明文で求めている。** これは体裁ではない。

### 6. ⚠⚠⚠ 鎖の第 1 段が存在しなかった——12 件の手書きで、1 つは 130.8 km ずれていた

「原発 → 実測線量 → 風 → 拡散」の第 1 段は、`js/sims.js` の**正規表現 12 件と手打ちの座標**だった。
`.agents/rules/no-ad-hoc-hardcoding.md` §1 が最初に名指す形で、**予測どおりの 2 つの壊れ方**をしていた:

1. **13 件目で黙って外れる。** 世界の他の約 630 の原子力施設は、汎用ジオコーダに落ちるだけ。
2. **間違っていて、誰にも分からない。** **Bushehr は 52.23°E と書かれていたが、実際の炉は
   50.887°E（Wikidata）／50.885°E（OSM）——130.8 km ずれていた。** 2 つの出典は互いに一致し、
   **手書きの数字とだけ食い違う。**
3. さらに `ohi|大飯|takahama|高浜|川内原発|hamaoka|浜岡` が**1 行に束ねられ、6 つ全部に大飯の座標**を
   返していた。**浜岡は大飯から約 300 km ある。**

⇒ `data/npp.json`（**638 サイト**・305,170 B）を `scripts/build-npp-registry.mjs` が
**Wikidata（CC0）から生成**する。座標の無い 231 件は同梱しない（地図に置けない）。
IAEA PRIS に機械可読な経路は**無い**（実測: `/PRIS/` 以下は全パスが同一の SPA を返し、
`www.iaea.org/PRIS/` は Cloudflare で 403。**Wikidata に PRIS 識別子プロパティも存在しない**）。
OSM は座標の無い 270 件のうち**2 件しか知らなかった**（0.7%）ので、2 件のために同梱データ全体へ
ODbL の share-alike を背負わせない判断をした（`sources[]` と `src` は残してあるので、後から足すのは追加）。

### 7. 名前の照合は表ではなく**尺度**にした（#R515 の再演を避ける）

正規化（各言語の「原子力発電所／原発／nuclear power plant／АЭС…」を剥がす）＋
**文字 bigram の Dice 係数**で採点し、**床（0.55）を下回れば拒む**。
⚠ **拒否が本体である**——床を 0 にする変異試験で ⑦ が赤になることを確認済み。

⚠ **旧表が引けた綴りを引けなくするのは能力の縮小**なので、実測して直した。46 綴りから抽出した
**37 の literal** を新しい照合器に通し、**最初は 30/37**。原因は表ではなく**構造**にあった:

- **長音符と中黒は転写の選択であって名前の一部ではない**（「マヤーク」＝「マヤク」、
  「ラ・アーグ」＝「ラアーグ」）⇒ 正規化で落とす。**書記体系についての規則**であって 4 件の特例ではない。
- **前方一致は独立した証拠**（「запор」は人が Запорожская を打ち始めた形。中間の部分一致は偶然）
  ⇒ 前方一致に専用の段を置く。これが無いと「запор」は自分の原発に **0.509** で床を割る。
- **証拠として数える文字数は書記体系で違う。** 漢字 2 字は英字 4 字ぶんの情報を持つ——
  「福島」は県を名指すが «fu» は何も名指さない。**固定の下限は、ラテン文字についての規則が
  名前についての規則のふりをしている**もの。⇒ CJK を含む問い合わせは下限 2。
- **上流に無い名前は上流で直す。** 「чорнобиль」は**ウクライナ語**——
  **その施設が建っている国の言語での名前は「おまけの言語」ではなく、その施設の名前そのものである。**
  ⇒ 取得言語を「UI の 9 言語 ∪ **その国の公用語**」に広げた。国と言語の対応表は**書いていない**——
  `P17 → P37 → P424` を SPARQL で辿る（実測 66 か国・78 コード）。自国語で名乗れる施設 **569/631 = 90.2%**。

**最終 36/37。** 失ったのは **`kyshtym` 1 件**で、これは**上流に無い**——Kyshtym は 1957 年の事故と
町の名前であって、Wikidata が Mayak の名前として持っていない。⚠ **表に書き足して直さない**
（それが #R515 で禁じた行為そのもの）。汎用ジオコーダは町として解決するので、
`js/atlas-console.js` の梯子は今も近傍に着地する。

⚠ **曖昧さは「一致」でも「不一致」でもない。** 「福島原発」は第一と第二を等しく名指す。
順序で黙って 1 つ返すのは #R515 に手順を足しただけなので、**近接した同点は `ambiguous` として名乗り**、
Atlas の返答が「その名前は {o} にも一致します。この実行では {u} を使いました」と言う。

### 8. 鎖を 1 つの回答にした

`IntMapRadiationObs.near(lat,lon,km)` と Atlas の `data.radiationNear` が「その地点の周りで
**いま実際に読まれている値**」を返す。拡散シミュレーションの返答にも
「📟 いま放出源の近くで実測されている値」が**モデルの数字とは別の段落として**付く。
⚠ **測定と仮説を 1 つの段落に混ぜない**——それが `docs/RADIATION.md` の唯一の禁止事項。

本番実測の裏取り: 最も高い 6 局が**すべて福島第一（37.42, 141.03）の数 km 以内**——
大熊町・双葉町・小入野・乙沢。**データが本物で、正しく地理参照されている**という強い証拠。

### 9. 途中で見つけて直した、今回の主題ではない欠陥

- ⚠⚠⚠ **`wbgetentities` は `languages` も上限 50**（`highlimit 500` は権限が要る）。88 言語を一度に
  投げると **HTTP 200 ＋ `error` オブジェクト**が返り、`entities` が無いので**空の台帳（212 B）が
  黙って出荷された**。⇒ 言語もページングし、**API の `error` は throw する**。
- ⚠⚠ **`tests/security-logic.test.mjs` の `FUNCTIONS` が手書きの配列**で、**その配列自身のコメントが
  欠陥を説明していた**——「a function missing from it is a function nothing in this file inspects」。
  ⇒ ディスクから発見する。⚠ **そうすると既存の検査 `assert.deepEqual(dirs, FUNCTIONS)` が
  トートロジーになる**（両辺が同じディスク由来）ので、比較先を **`config.toml` の宣言**へ付け替えた
  ——独立した 2 つの側が残る唯一の関係。変異試験（宣言を 1 つ改名）で赤を確認。
- ⚠⚠ **`Number("")` も `Number(null)` も 0 で有限**なので、欠損値が「実測 0 nSv/h」になり、
  `""` が緯度として通っていた（#R543 の形）。強制変換を 1 本に統合。
- ⚠ **最初の重複除去の変異試験が緑のまま生き残った**——fixture が偶然 distinct 3 局だったから。
  **619 回繰り返す局を含む実バイトに差し替えて赤を確認**（#R548・#R552 と同じ形：
  実物より都合のよい fixture は、その欠陥を原理的に見られない）。
- ⚠ **繁体字と簡体字で用語が別だった。** 台湾は `等效劑量率`、大陸は `剂量当量率`。
  `scripts/zh-hans.mjs` の WORDS に **1 行**（`['等效劑量率','劑量當量率']`）足して、
  **それぞれの読者にそれぞれの標準語**が出るようにした。⚠ 鍵は `周圍…率` ではなく**裸の語**にする
  ——修飾語が句の内側に入る（`周圍γ等效劑量率`）ので、長い鍵は黙って外れる。
