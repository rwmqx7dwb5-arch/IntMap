## R686 — **上流が名前を 1 つしか持っていないとき、9 言語は「訳す」のではなく「照合する」仕事になる**

> 「IntMap で、**1850 年より前の歴史的な国名を 9 言語にする**作業をしてください。」

`data/hist-eras.js`（#R679 で同梱した 53 枚・紀元前 17 枚）は 10,212 の feature を名前つきで描き、
その名前は **全部 `{en:…}` の 1 つだけ**だった。だから日本語の読者が紀元前 323 年へ行くと
「Empire of Alexander」、1500 年で「Kalmar Union」。隣の 1850–1885 の記録は #R224 から 9 言語を
持っている（OHM が `name:xx` を持つから）。**上流の違いがそのまま読者の言語の違いになっていた。**

⚠ **`npm run check:i18n` はこれを緑のまま通す。** あれが監査するのは app 自身の文字列表で、
これはデータである。**気づく仕組みが 1 つも無かった。**

### 1. ⚠⚠⚠ 設計の前に上流を測って、天井が 100% でないことを先に確定させた

| 測ったもの | 実測（2026-09-11） |
|---|---|
| 名前つき feature | 10,212 |
| **distinct な綴り** | **3,028**（`Australian aboriginal hunter-gatherers` は 36 枚に出る） |
| 上流の `wikipedia` 欄を持つ feature | **21 件・13 の綴り＝0.4%** |
| 英語版 Wikipedia の題名で素直に引いて当たる綴り | 1,335（44.1%） |
| **そのうち Wikimedia の曖昧さ回避ページ** | **353** |

**訳す単位は feature ではなく名前**なので、対象は 10,212 ではなく 3,028。そして
**繋ぐ識別子は無い**——0.4% では join できない。綴りしか入口が無い。

⚠ そして残りの多くは**政体名ですらない**。上流は名指す政体が無いところに**英語の説明文**を書く:
`Australian aboriginal hunter-gatherers`・`Savanna hunter-gatherers`・`Plain bison hunters`・
`West African cereal farmers`、それに自前の綴り間違い（`Khoiasan`・`Plateau fichers`）。
**どの言語のどの出典にも存在しない。** 1 人の製図者の英語の文だからである。
だから**この回の天井は 100% ではなく、そう書いた**。埋まらないところは英語のままにする——
#R679 が地名で立てた規約であり、`js/time-borders.js` が 1850–1885 に対して既にしている扱い。

### 2. ⚠⚠⚠ #R515 の再演を 3 回、実測で止めた

#R515 は `geocode()` が `limit=1` の先頭を無検証で採ったせいで港を取り違えた回で、
規則は**尺度**でなければならない、が結論だった。ここでも同じ穴が 3 回あいた。

**① 順位を使わない。** `wbsearchentities` は順位をつけて返す。それを使えば #R515 と同じ行為に
なるので、問い合わせは **`rdfs:label` / `skos:altLabel` の英語での等値**にした——順序無しで
**その綴りを持つ項目を全部**返す。`Ainu` は **9 件**返る。**綴りは問いであって答えではない。**

**② 座標に許容幅を置くのをやめた。** 最初は 20°、次に「その行の形の大きさから導いた幅」。
2 つ目のほうが悪い:

```
Montana → Q22060885   モンタナ（ニュージャージー州）
```

地図が `Montana` で描く形は大陸の 5 分の 1 あるので、そこから導いた幅は**次の大洋まで届く**。
⇒ **述べられた座標は、地図がその名前で描く形の「中」に無ければ拒む。** 幅は無い。

**③ 期間の許容幅は固定値にできない。** 記録の分解能が一定ではないからである——
1492 年の周りは `1400 · 1492 · 1500 · 1530` で数十年、紀元前は `123000 BC · 10000 BC` で
**11 万 3 千年**。固定の 400 年は深い側で無意味に厳しく、浅い側で緩すぎた:

```
Cheyenne → Q39042   シャイアン（ワイオミング州・1867 年創設）   1492 年の feature に対して 375 年差
Erie / Tonkawa / Ponca                                         同じ形
```

**いずれもその民族の領域の中に立つ、その民族にちなんだ近代の町**である。だから空間の検査は
「一致」と言う。**分けられるのは時計だけで、しかも記録自身の分解能で訊いたときだけ。**
⇒ `timeSlack(row, years)` ＝ その行の前後のスナップショットまでの間隔。

### 3. ⚠⚠⚠ 一番多かった誤りは「言語」だった

最初の版が採った 751 件の **P31 の最頻値は `Q34770`（言語）で 146 件**。

```
Burmese       → ビルマ語        Hän           → 汗語
Siuslaw       → サイウスロー語   Northern Pomo → 北波莫語
```

上流が描いているのは**民族**で、Wikidata でその英語名を持つ項目は**その民族にちなんだ言語**
であることがとても多い。**領域の地図に「ビルマ語」と出るところだった。**

⇒ 直し方は QID の一覧ではない（次の 1 件のために編集する一覧は
`.agents/rules/no-ad-hoc-hardcoding.md` が禁じているもの）。**根を 2 つ名指し、その下に何が
あるかは Wikidata に `wdt:P279*` で訊く**:

| 根 | それが言うこと |
|---|---|
| `Q17442446` Wikimedia internal item | 曖昧さ回避・一覧記事・カテゴリ・テンプレート |
| `Q34770` language | 言語は場所ではない（話者の国を持っていても） |

実測: 候補クラス 2,102 のうち **37 が該当**し、その 37 が**候補 250 件**を落とした。

### 4. ⚠⚠ 括弧つきのラベルは、Wikidata が曖昧さ回避をしている印である

```
Montana (新澤西州)   Blackfoot (Montana)   아이누 (동음이의)
```

地図のラベルには括弧の中身を運ぶ場所が無い。**その言語の文字列だけ落とす**（実測 18 件）——
行は残り、括弧の無い名前を書いた言語はそのまま出て、どれも書かなかったら英語が立つ。

### 5. ⚠⚠⚠ 手書きの名前表が何に答えるのかを、8 ラウンド誰も測れなかった

`js/time-borders.js` は英語名を**認識して**訳す表を 4 つ持つ——`IntMapHistStates.STATES` 19・
`_VANISHED` 8・`_ERA_LOC` 242・`_COLONIZER` 26——が、全部 `_eraLocName` の閉包の中にあり、
**「3,028 のうち何件に答えるのか」を訊く扉が無かった**（#R575 の数理が DOM の閉包にあった話、
#R673 の「固定引数のせいで規則が一度も測られなかった」話と同じ帽子）。

⇒ **node で `js/time-borders.js` を実体化する足場**（`scripts/histeras/time-borders.mjs`）を作り、
`eraLocName` を公開 API に足して**評価した**。答え:

```
jp 250   ru 250   de 195   es 204   fr 107   ko 107   zh 107   zh-hans 107   （/ 3,028）
```

⚠ **fr・ko・zh・zh-hans が半分以下なのは、その 4 言語が `LA(...)` の位置引数 5 つの外**にあり、
inline 表を英語鍵で引くから。**束はこの 250 件を書かない**——書けば同じ判断が 2 か所になり、
`tagSame` は `_i18n` を先に読むので**手書きのほうが静かに到達不能になる**（#R536）。
`tests/r686-histeras-names-checks.test.mjs ⑨` が言語ごとに交わりゼロを測る。

### 7. ⚠ 残っている既知の誤りを隠さない

**「その民族にちなんだ、その領域の中に立つ、Wikidata に創設年が無い近代の集落」は分けられない。**
座標は形の中にあり、時計は何も言わないからである。実害の多くは音写が同じで気づかれない
（`Cheyenne → シャイアン` はどちらの意味でもそう書く）が、**`Nazca` は「ナスカ市」として通っている**。
これは綴りで繋いだことの天井であって、次の 1 件を一覧に足して消すものではない。

### 9. ⚠⚠⚠ CI で 6 本落ちた——**名前の車線の失敗が、地図の車線を道連れにしていた**

ローカルの `npm test` は緑だったのに、CI の `Regression 2/3` が 6 本落ちた。全部
`tests/r682-hist-eras-note-checks.test.mjs`（**このラウンドが触っていないファイル**）で、
全部**同じ例外**:

```
ReferenceError: fetch is not defined
    at erNames (evalmachine.<anonymous>:494:7)
    at evalmachine.<anonymous>:503:18      ← erLoad の .then(d=>erNames()…)
```

`erNames()` の `fetch(...)` は **同期的に投げうる**（#R682 の検査は `fetch` を持たない vm で
このモジュールを評価する。stub は意図的に inert・#R585）。その同期例外が、**era の階層全体が
await している `_erP` を reject させた**——名前が読めないだけのはずが、**地図が出なくなる**。
自分で「⚠ AND IT IS NOT A PRECONDITION」とコメントに書いた当のものが、実装で成り立って
いなかった。⇒ `fetch(...)` を `try/catch` で包み、失敗を「名前の車線が空」へ降格させる。

⚠ **ローカルが緑だったのは環境差ではない**——`tests/r682-…` は**このブランチを切ったあとに
main へ入った**ので、rebase するまで手元に存在しなかった。rebase 後に同じ変異を入れると、
手元でも 13 本落ちる（実測）。

⚠⚠ **そして、この退行を自分のラウンドの門にしようとして失敗し、その検査を捨てた。**
`scripts/histeras/time-borders.mjs` の足場に「`fetch` の無い文脈」を足して同じことを測ろうと
したが、**try/catch を外しても緑のままだった**（この足場は `_go()` が別の経路で FC を得る）。
**落ちない検査は無いより悪い**（#R488）ので、緑の飾りを出荷せずに削った。守っているのは
#R682 の 7 本で、それは「巻き添え」ではなく **`erLoad` が reject しないこと**をたしかに測っている。
