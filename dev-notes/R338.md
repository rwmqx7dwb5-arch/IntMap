## R338 — **原本の同期と USB バックアップを毎ラウンド塞いでいたもの**

`CLAUDE.md` §5 の最終工程（原本を `origin/main` へ早送りする）と §11 の USB バックアップが、
**並行セッションが 1 つでもプレビューを持っている限り、毎ラウンド止まっていた。**

### 何が起きていたか

`.claude/launch.json` はラウンドごとのプレビュー設定である。中身はこういうものだ:

```json
{ "name": "intmap-preview-r330",
  "runtimeArgs": ["scripts/serve.mjs", "--root",
    "C:/Users/gyuuk/AppData/Local/Temp/intmap-worktrees/wt-r330-.../dist", "--port", "4330"] }
```

**このマシンの、この worktree にしか意味のない絶対パス**である。他のマシンでも、他のセッションでも
使えない。それでも**追跡対象**だったので、次の連鎖が起きた:

1. Browser の preview ツールは **原本の** `.claude/launch.json` へ書く（名前でキャッシュする・#R289）。
2. 原本の作業ツリーが dirty になる。
3. `git merge --ff-only` が「ローカルの変更が上書きされる」と**拒否する**。
4. `CLAUDE.md` §6 は他セッションの未コミット変更に触ることを禁じているので、**その拒否は正しい**。
   commit することも、stash することも、捨てることもできない。
5. 原本が古いままなので、`scripts/backup-usb.ps1` が `skipped master-not-synced` で止まる。

**実測（#R334 の終了処理）**: 同時に **19 セッション**が走っており、原本は **3 コミット遅れ**、
USB バックアップは skip。#R320 も**同じ連鎖を測って記録していた**——
しかし記録したのは「正しく拒否している」という観察までで、**原因は残った**。
「拒否が正しい」ことと「塞がれ続けてよい」ことは別である。

### 直し方

**追跡をやめた。** `.gitignore` に入れて `git rm --cached`。それだけ。

- 書き込みは今までどおり（`worktree.mjs new` が 1 件足し、preview ツールが原本へ絶対エントリを書く）。
- 読み出しも今までどおり——`scripts/worktree.mjs` の `claimedRounds()` は**原本の**このファイルから
  `intmap-preview-r(\d+)` を拾って**使用済みラウンド番号**を導いている。追跡をやめてもファイルは在る。
- ⚠ ただし**新しい clone にはこのファイルが無くなる**ので、`worktree.mjs` が無ければ作るようにした。
  これが無いと、fresh clone の最初のラウンドが「launch.json を更新できなかった」と警告して終わる。

### ⚠ 検査を狭めた理由

最初に書いた ① は「`.claude/` の追跡ファイルに `C:\Users\…` が出てきたら落とす」だった。
これは **`.claude/agents/intmap-implementer.md`** に当たって落ちる——
あのファイルは**散文の中で作業ディレクトリの例として**そのパスを引用しているだけで、
誰の merge も塞がない。

⇒ **危ないのは「絶対パスが書いてある」ことではなく、「毎セッションがそのファイルを機械的に
書き換える」ことである。** 見る対象を `.json`（＝ツールが書くもの）に絞った。

### 門が本当に落ちることを確かめた

`git add -f .claude/launch.json` で追跡へ戻すと **4 件中 2 件が赤**（① 追跡されていない・
② 無視されている）。`git rm --cached` で戻すと **4/4 緑**。

### 触ったもの

`.gitignore`（理由つきの節）／`scripts/worktree.mjs`（無ければ作る・古くなった注記）／
`CLAUDE.md` §2 ローカルプレビュー／`.claude/skills/intmap-round/SKILL.md`／
`docs/FILES.md`／`scripts/master-sync.mjs` と `tests/r282-checks.test.mjs` の注記
（**どちらも `.claude/launch.json` を「毎セッションが編集する追跡ファイル」の定番例として
本文に書いていた**——その例は消えたが、両者が測っている不変条件は変わらない）。
