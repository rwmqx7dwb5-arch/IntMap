## R441 — **同じ経路が2回並んだのは、唯一の重複判定が「描画済み HTML の文字列比較」だったから**

報告はスクリーンショット1枚と1行だった。「経路を聞いたらいくつも出てきてしまう。6つぐらい出てきた。
おかしいバグ。」

写っていたのは、**1つの質問に対する1つの返信**の中身である。

```
利用者: ここから大阪駅まで電車で行きたい。
Atlas : 現在地から大阪駅まで、電車のみの経路を検索します。
        現在地 (35.133, 136.934)
        5件の候補 — タップで地図に表示
        ① 05:56–07:28  1時間32分・2回乗換 …（カード5枚）
        公共交通の経路検索（Transitous／MOTIS）— 時刻表ベース（…）。
        5件の候補 — タップで地図に表示
        ① 05:56–07:28  1時間32分・2回乗換 …（カード5枚）
```

発時刻も着時刻も乗換回数も、✓ の付いたカードまで同じものが2度。読者にとっては「候補が10件出た」
であり、実際には**同じ5件が2回**である。

### 繰り返していたのは操作で、判定が読んでいたのは描画だった

1つのターンが同じ道具を何度走らせるかは Atlas が決める（`CONSTITUTION.md` §5。ループは
`js/atlas-agent.js` で 8 手・32 呼び出しまで許している）。**決めてよくないのは、走らせた回数が
そのまま読者に見える回数になること**で、`js/atlas-console.js` の `_atlCompose` にはそのための門が
2つあった。

| 門 | 何を見ていたか | 経路に効いたか |
|---|---|---|
| `_atlGoalKey` | **目的**。ただし回答系14型以外には `''`（＝無条件に全部残す）を返す | ✗ `directions` は対象外 |
| `seen[h]` | **描画済み HTML の文字列** | ✗ 1バイト違う |

2つ目が経路に効かない理由は `js/routing.js` にある。計算した経路セットは1つずつ新しい id を持ち
（`_rsNew()` ＝ `'rs' + (++_rsSeq)`）、`js/routing-cards.js` がそれを**カード1枚ずつの `data-rset`** に
書く。これは #R291 が入れた正しい仕組みで——10 返信前の Atlas メッセージのカードを叩いても
「最後に計算されたやつの i 番目」ではなく**そのメッセージ自身のセットの i 番目**が選ばれる——
その結果、**同じ旅程を2回計算した2つの断片は、その1か所だけが違う**。`rs1` と `rs2`。
だから文字列比較は一度も発火せず、2つとも積まれた。

**門は描画を読んでいて、繰り返していたのは操作だった。**

### `js/atlas-turn-results.js` — 目的の名前を2通りに増やした

判定を `js/atlas-console.js` から出して、DOM も network も global も持たない1本のモジュールにした
（#R419 と同じ理由: `js/atlas-console.js` は縮む一方の行数上限を持つ。実測 4,908 → **4,902 行**）。

- **回答の族**（`analyze` / `research` / `mapReport` …）は #R159 のまま。主題ごとに最良を1つ、
  **同点なら先に書いたもの**が残る——修復は得点で勝って失敗を置き換える。
- **同じ操作の繰り返し**は、action の型と引数から作った同一性で1つに畳み、**同点なら後のもの**が
  残る。理由は非対称ではない: **アプリが持っているのは最後の実行**で、地図が描いている経路も、
  叩けるカードも、そちらだから。⚠ **失敗した再実行が成功を押しのけることは無い**（得点で負ける）。

⚠ **引数の一致だけでは足りない。** `my_location` が座標を返したあとのステップは、同じ旅程を
「ここから」ではなく `35.1330,136.9340` で頼みうる。**言葉が違うだけで同じ操作**なので、経路の
case が**自分が解決した端点と mode** を `meta.resultKey` として名乗り、同一性はそちらを優先する。
座標は約 11 m に丸める——ジオコーダの揺れより粗く、隣の駅より細かい。

⚠ **Atlas からは何も取り上げていない。** ループの上限も、呼び出しの拒否も、「2回目は無駄だ」という
判断も足していない。**変わったのは読者に何回見せるかだけ**である。

### 測ったこと

- `tests/r441-checks.test.mjs`（10本）が**出荷するモジュールそのもの**を回す。**6通りの変異で全部赤**
  ——旧挙動へ戻す／`resultKey` を無視する／操作でも同点は先勝ちにする／回答でも同点は後勝ちにする／
  空の引数を数える／道路側の `return` から identity を落とす。
- `tests/r318-atlas.spec.js` に browser の証拠を1本相乗りさせた（新しい spec ファイルは worker を
  1つ買う——#R423）。**ビルドされたバンドル・実物の dispatch・実物の経路カード**を通し、
  ルータだけを差し替えて同じ旅程を2つの綴りで2回走らせる。修正あり ＝ `.rt-alts` が **1つ**
  （`rsR441x2`・カード5枚）、`keep()` を欠陥版に戻す ＝ **2つ**。
- ⚠ **判っていないことが1つある。** 本番でその turn が経路の道具を何回呼んだかは
  `window.IntMapAtlasDebug.lastPlan()` に残るが、それを読むには読者としてログインが要る。
  ここで直したのは**返信の組み立て**であって、Atlas が2回頼んだ理由ではない。

### ⚠ 相乗り先が赤いと、足した検査は「走らなかった」で緑と見分けがつかない

`tests/r318-atlas.spec.js` は `test.describe.configure({mode:'serial'})` である。相乗りさせた直後の
実行は **1 failed / 9 passed / 3 did not run** で、**その3本の中に、いま足した検査がいた。**
落ちていたのは `R406 ②` で、#R413 が製品から**意図して外した**上限（`MAX_FIND = 8`）を
テストのほうがまだ主張していた——deep tier ＝ nightly 専用なので、merge から丸一日
誰の PR も落ちていない。

ここで一度直した。そして **push 直前の `git fetch` で、#R433 が同じ欠陥を先に、より広く
直していた**——数を書き直すだけでなく、`tests/r413-checks` に**「`matches` の件数を数値リテラルで
縛る assert を禁じる」門**まで足している。**こちらの修正は捨てて向こうを取った**（#R402 と同じ形。
同じ欠陥を同じ方向で2人が直したときに残すべきなのは、門まで広げたほうである）。

残ったのは、直し方ではなく**順番のほう**の教訓である:
**赤いファイルに新しい検査を足しても、それは走っていない。**
