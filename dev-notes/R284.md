### ① 斜線は「未対応」の見た目なのに、対応国が読まれるまでの間ずっとそれを着ていた

`washTier(iso)` は国の見え方を決める。#R275 は「まだ読んでいない国に『発表なし』の灰色を塗るな」を直し、
#R277 は「取得に失敗した国にも塗るな」を直した——**どちらも正しい**。ただし**代わりに何を塗ったか**が問題で、
両方とも `return 0`＝**斜線**だった。斜線は `wp-alert-hatch` の `fill-pattern` で、意味は
「**この地図はこの国に対応していない**」ただ一つである。

**実測**（ビルド済みページ・1280×800・レイヤーON）:

| 時点 | 斜線 | うち**対応している**国 |
|---|---|---|
| t+45 s | 134 | **22**（WMO 登録簿の輪番中 15・MeteoAlarm 5 ほか） |
| 定常 | 113 | **1**（北マケドニア——`feeds.meteoalarm.org` が `upstream_error` を返し続ける） |

つまり主張は3つ（未対応／発表なし／発令中）なのに、**状態は4つ**あった。4つ目は
「対応しているが、まだ読めていない／読めなかった」で、これは**主張ではない**。

→ `washTier` は `readState(iso)!=='ok'` のとき **−1** を返す。−1 は塗り式の既定値
（`['to-number',['feature-state','wpAlert'],-1]`）そのものなので、斜線（`==0`）にも薄塗り（`>0`）にも
当たらない——**何も描かれず、地の図がそのまま見える**。1行も塗り式を変えずに4状態目ができた。
タップしたカードの見本も**斜線ではなく破線の空枠**にし、「順番待ち」と「取得できませんでした」を
**別の文言**で言う（それまでは両方「未取得」だった）。

**実測、修正後: 対応国の斜線は 0。**

### ② 「漏れが多すぎる」の原因は、形の索引が「今の天気」でできていたこと

#R277 は形を4段のはしごで探すようにし、2段目に「**その機関自身が WMO 登録簿に出している形**」を置いた。
これは正しかったが、`?swicgeo=<mid>` が返すのは**その機関にいま出ている区域**なので、
**その機関が静かな日には索引が空になる**。

**実測**（同じ分）: 墺 112 形・波 126・西 86・斯 54 が返る一方、**葡 0・モルドバ 0・洪 0・伊 0・白 0**。
その結果 **モルドバ 0/42・ポルトガル 1/18・ハンガリー 0/7**——**機関が発表しているのに国が真っ白**だった。

4つ直した。

1. **索引はためる。** 後から来た形は**併合**であって置き換えではない（`swicGeoBy[iso]` を作り直さない）。
2. **空で返った機関は聞き直す。** それまでは `swicGeoAsked[iso]=true` で**永久に**打ち切っていた。
3. **天気に依存しない行政界を5段目に足した**——geoBoundaries gbOpen の ADM1 → ADM2。
   IPMA は**県 (distrito)**、モルドバの機関は**地区 (raion)** で発令していて、どちらも NUTS に存在しない。
   ⚠ **これは「第2の警報ソース」ではない**——形だけで、何が発令されているかは今もその国のフィードが答える
   （NUTS・Natural Earth・国土数値情報と同じ立場）。
   ⚠ **①〜④が答えられなかった区域にだけ**効かせる。実測、希と白は**既存の段のほうが良い**（希 10/16 対 3/16）。
   ⚠ `raw.githubusercontent.com` は Git-LFS の**ポインタ**（実測 131 バイト・`version https://git-lfs…`）を
   返し、`github.com/…/raw/…` は CORS ヘッダを返さない。**`media.githubusercontent.com/media/…` だけ**が
   実体を `Access-Control-Allow-Origin: *` で返す（実測、葡 595 KB・373 ms）。
4. **ハンガリーは NUTS-2 を英語名で呼ぶ。** 「Southern Great Plain」に対し Eurostat が持つのは
   `NAME_LATN = Dél-Alföld` だけなので、**どの段にも一致しなかった**（0/7＝国ごと白）。NUTS 索引は
   `NUTS_ID` でも引けるので、標準英語名を ID の**別名**として登録した（形は今も Eurostat のもの）。

**実測（同じビルド・同じ手順）: 2,737 / 2,923 → 2,877 / 2,961**（欠落 **186 → 84**）。
モルドバ 0→32、ポルトガル 1→17、リトアニア 7→10、伊 18→19。

### ③ 「対応国も増やせ」——NWS は既にグアムに警報を描いていて、国の側だけが「未対応」と言っていた

`FEEDS` は ISO3 → フィード名の表で、`USA:'nws'` の1行しかなかった。だが **NWS の管轄は合衆国の国境ではない**。

**実測**（`api.weather.gov/alerts/active`、この分）: UGC の州コードに **GU・MP・PW・FM** が実際に含まれていた
——グアム予報事務所はマリアナ・パラオ・ミクロネシア連邦・マーシャル諸島に、サンフアンはプエルトリコと
米領ヴァージン諸島に、パゴパゴは米領サモアに発令する。**警報ポリゴンは既に描かれていて**、その同じ島に
国の層が「未対応」の斜線を塗っていた。

→ `ALSO = { nws:[…8 か国・地域…] }`。⚠ **既に自分のフィードを持つ国は上書きしない**（一国一ソース）。
⚠ ISO の一覧は `tests/r284 ②` が検査する。**対応 140 → 148**（対応外 252 → 104）。

WMO 登録簿の外にはもう増やせない: 実測、加盟 198 機関のうち「CAP 実装 Completed」は **139** で
この地図は**その全部**を読んでおり、対応外の国で加盟しているものは**58 機関すべてが Development / Not started**、
全球スキャンに1件も現れない。

### ④ 「更新が遅すぎる」（4回目）は、定常ではなく出だしだった

定常の一周は relay のエッジキャッシュ 60 秒の**床にもう乗っている**（実測、最古の国は 38〜78 秒で振れる。
それより速く聞いても同じバイトが返るだけ）。床に乗っていなかったのは**最初の1分**である。

**実測**、レイヤーを入れて 45 秒: MeteoAlarm **30/35**・WMO 登録簿 **78/93**——世界の4分の1が白いまま、
読み手はそれを見ていた。まだ一度も読んでいない国は**キャッシュを消費しない**（キャッシュされたものが無い）
ので、3枠は正しい**定常**の速さで、正しくない**出だし**の速さだった。

→ 未読が残っている間だけ **6 枠**（`COLD_CALLS`）で走り、一周したら 3 枠に戻る。
**実測、45 秒で 35/35・93/93、未読 26 → 1。** バーストは国の数で上限が決まるので**1セッションに1回**しか起きない。

### ⑤ 「警報名は設定言語で書け」——表に無い語は数えられる

**実測**（MeteoAlarm 35 機関 ＋ WMO 登録簿の全加盟機関、同じ分）: 異なる event 文字列 **163** のうち
分類できなかったのは **7**。うち2つは仕様どおり（「Yellow Warning」＝階級だけで災害を名乗っていない、
「Other dangers」＝同じ）。残る5つは本物の穴だった:

| 機関の言葉 | 実体 |
|---|---|
| Red Flag Warning | NWS の**林野火災**（「fire」も「weather」も入っていない） |
| Meteorological risk of geological disaster | CMA の**土砂災害**（中文の `地质灾害` は表にあったが英語が無かった） |
| Strong convection | CMA の**雷**（`强对流` は表にあった） |
| Moderate rissagas warning | バレアレスの**気象津波**（rissaga には他の言語の名前が無い） |
| Small Craft Advisory | NWS の**海上**警報 |

### ⑥ ECMWF の凡例は「家族名の1枚」に全部積まれていた

**実測**（1280×800・ECMWF 3 レイヤー ON）: `#data-legend-ecmwf` 1枚に `<h4>ECMWF weather</h4>` と
3本の帯が縦に積まれて **354 px**。**どの帯がどのレイヤーのものかはどこにも書かれていない。**
そして幅の狭い画面では `ensureLegendMinimize` が floating な凡例を自動的に畳み、
**`<h4>` 以外の子を全部 `display:none` にする**ので、箱は**「ECMWF 気象」という2語だけ**になる。
つまり「凡例名が ECMWF気象になっている」「凡例がない」「凡例が連結してしまう」は**同じ1枚の箱の3つの面**だった。

→ ECMWF レイヤーの凡例は、他のレイヤーの凡例と同じもの——**自分の箱**（`data-legend-ec-<id>`）で、
題は**そのレイヤー自身の名前**、中身はそのレイヤーの帯・目盛・単位・説明だけ。畳んでも残るのは
**そのレイヤーの本当の名前**になる。予報時刻は**どのレイヤーの鍵でもない操作**なので、自分の箱
（「ECMWF 予報時刻」）に住み、ECMWF レイヤーが1つでも出ていれば出る。
⚠ 並べるのは既存のタイラーで、**id の接頭辞**で拾う（1つの要素を名指しすると、次にレイヤーが増えた日に古くなる）。

### ⑦ Wind(animated) が段彩だったのは、SDK の配色表が補間しないから

出荷されている `@openmeteo/weather-map-layer` の色決定は2種類しかなく、**どちらも最近傍の抽選**である:

```
case "rgba":       colors[floor((v − min) / step)]
case "breakpoint": colors[binarySearch(breakpoints, v)]
```

`WINDY_WIND` は 17 個の停留点なので、**惑星全体が 17 本の平らな帯**で塗られていた。
一方 `legend()` が作る CSS `linear-gradient` は**補間される**——つまり
**凡例だけが滑らかで、地図が階段**という、#R270 の「色は名前と一緒に旅する」がちょうど裏返った状態だった。

→ `rampFrom(WIND_ANCHORS, 0.1)` が**同じ17色**を 0.1 m/s 刻みへ**再標本化**する（601 段）。
停留点の値はそのまま自分の色に着地する（バケットの色は下端の色）ので「**色はそのまま**」は近似ではなく厳密、
あいだは sRGB で線形。**データは一切変わらない**——同じファイル・同じ 9 km 標本・同じ風速。
変わったのは**色の分解能**だけで、17 段から 601 段になった。

**実測**: 隣り合う段の最大チャネル差 **4/255**（見える閾値の下）。ビルド済みページで大西洋上の走査線を読むと、
風の ramp に乗った 51 画素のうち **46 画素**が**17 色の表では作れない色**だった。
⚠ 601 段の帯をそのまま CSS に書くと 24 kB になるので、`legend()` は**描画用の停止点だけ**を 64 以下に間引く
（`stops`——呼び出し側が読む数値——は完全なまま）。

### ⑧ 「点滅する」と「未来や過去に変えたときの読み込みが異常に遅い」は同じ1行だった

`<input type="range">` は**ドラッグの1画素ごと**に `input` を発火する。そのハンドラは
`E.setIndex(+sl.value)` → `emit('time')` で、受け手は:

```
if(ev.type==='time'){ if(renderer) renderer.setField(null); load(…); }   ← 粒子を消す
activeLayers().forEach(cfg=>{ removeLayer(cfg); … addLayer(cfg) … });    ← 層を作り直す
```

つまり1回のドラッグで**アニメーションが数十回消えて戻り**（＝報告された点滅）、
**26 MB の場の読み込みが数十本**1本の直列キューに積まれた——**読み手が指を止めた時刻は行列の最後**で、
その手前には誰も見ない9枚が並ぶ。作業が遅かったのではなく、**すでに用済みの絵のための作業**だった。

→ 軸のイベントを2つに分けた:

| イベント | いつ | 何をする |
|---|---|---|
| `index` | **即時** | 時刻の文字と目盛だけ。指の下で時計が動く |
| `time` | 軸が `COALESCE_MS` 静止してから**1回** | 取得を伴う本番。層の入れ替えと場の読み込み |

ボタンと `step()` は `{now:true}` で即時に撃つ（クリックは掃引ではない）。
そして **`renderer.setField(null)` を消した**——粒子が読む場は**それが作られた時のフレームを閉じ込めた
クロージャ**なので、新しい時刻が着地するまで**古い時刻のまま正しく動き続ける**のが正しい。
ラスタ側も「消してから足す」をやめ、**2つのスロット**を交互に使って新しい時刻を不透明度 0 で隣に組み立て、
地図が落ち着いてから古いほうを落とす（アニメーション風の色面が以前からやっていたこと）。

**実測**: 12 段のドラッグで `index` **12 回**・`time` **1 回**、着地は正しく +12。
その間に採った 22 フレーム**すべて**で粒子は描画を続けていた（最小 1,513 セグメント）。

### ⑨ 再生ボタンと「次へ」が同じ字だった

**実測**、5つのボタンは `⏮ ◀ ▶ ▶ ⦿`——**再生と「次へ」は文字通り同じ文字**で、「戻る」と「再生」は
同じ三角の鏡像だった。加えて絵文字／Miscellaneous Technical の字は 10.5 px で読み手の OS 任せに描かれる。

→ **描いた SVG 5 種**: 最初へ（棒＋三角）／1つ戻る（**二重**三角）／再生（**単一**三角）／
一時停止（2本の棒）／1つ進む（**二重**三角）。そして「現在」は**言葉**にした（`⦿` を「now」と読む人はいない）。
風の凡例の操作盤も**同じ宣言**（`IC`）を読む——1つの時計の2つの見え方が、どちらが再生かで食い違えない。
