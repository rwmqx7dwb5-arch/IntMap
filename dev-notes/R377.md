## R377 — **視点は機体にあった。動いていたのは、その下の地面のほうだった**

報告はこうだった。「deep tier の `tests/r173.spec.js`「コックピットに本物の世界があり、視点は機体にある」が
clean `origin/main` で落ちる。低高度の脚で `|eyeAlt − alt| = 247.8`、許容は 120。**許容値を広げるな。根本原因を直せ。**」

「視点は機体にある」は #R95/#R96 以来の恒久的な不変条件なので、まず疑うべきはカメラだった。
**カメラは無実だった。**

### 1. 何が起きているかを、フレームごとに測った

低高度の脚を 0.4 秒ごとに読むと、**すべての値が凍っていた**——`performance.now()` だけが進み、
`alt`・`vs`・`V`・`pitch`・`zoom`・`eyeAlt` は 5 秒間 1 ビットも動かない。飛行シムのループが止まっている。

止まった理由は接地だった。テストの降下は `S.alt = (S._terrF || 0) + 250` ——「**地面の 250 m 上**」——だが、
実測したその瞬間の `_terrF` は **−394 m** で、目標は **−144 m**、つまり**海面下**。機体は水中へ降ろされ、
地面が 0 m に戻った瞬間に接地し、`showResult()` が `paused = true` にしてループを止めた。
以後カメラは最後のフレームのまま凍り、テストのスクリプトだけが `st.alt` を書き続ける。
**その差が 248 m だった。** カメラは、生きている間ずっと機体にいた。

### 2. なぜ地面が海面下 400 m にあったのか

出発点 **138.66°E 35.05°N は駿河湾の上**である。AWS terrarium DEM をこちらで復号して確かめた:

| ズーム | 138.66°E 35.05°N の標高 | 富士山頂（138.73, 35.36）|
|---|---|---|
| z8 | **−1,045 m** | — |
| z10 | **−994 m** | — |
| z12 / z15 | **0 m**（rgb 128,0,0 ＝ 海）| **3,699 / 3,709 m** |

低ズームの terrarium は**水深**を持ち、z12 以上は陸だけのデータで水面を 0 m とする。どちらも正しい。
#R152 はこれを見越して**海面フロア**を書いた——外洋の上では物理の地面は海面（0 m）で、
海面下の**陸**（死海・干拓地）だけが本当の負の標高を保つ。その判別は `window.countryGeo` への
点‐多角形判定で、内側なら陸・外側なら海。

**その判定が「陸」を返していた。** ページに同じ点を今の `countryGeo` で訊くと `false`（＝海）が返るのに、
シムの `st._overOcean` は `false`（＝陸）のまま——**二つが食い違っていた**。

### 3. 原因: キャッシュが、それを計算した元データを記録していなかった

`js/countries-ui.js` は起動時にまず **Natural Earth 110 m** を取り、**10 m** が届いたら
`window.countryGeo` を**差し替える**（#R195 の注記いわく起動の 4〜10 秒後）。
`js/flight-sim.js` の `_fsOceanCache`（約 0.25° セルごとの陸/海の答え）と `_fsBBox`（地物ごとの外接矩形）は、
**最初の物理フレームの時点の外形**から作られ、差し替えを知る手段を持っていなかった。

二つの縮尺は、粗いファイルが解像できない湾のすべてで食い違う。両方をこちらでダウンロードして測った:

| 外形 | 地物数 | 138.66°E 35.05°N |
|---|---|---|
| `ne_110m_admin_0_countries` | 177 | **Japan（陸）** |
| `ne_10m_admin_0_countries` | 258 | **OCEAN（海）** |

飛行の実測トレース（1.5 秒ごと）が、そのまま経過を写している:

```
S0  ocean:false  terrF:0      nFeat:0     ← countryGeo 未到着（未知は陸・キャッシュしない）
S1  ocean:false  terrF:-34.6  nFeat:177   ← 110 m 到着。「陸」を確定してキャッシュ
S3  ocean:false  terrF:-169.1 nFeat:177   ← 地面が水深へ滑り落ちていく
S5  ocean:false  terrF:-316.1 nFeat:177
PAUSED ocean:false terrF:-368  nFeat:258  ← 10 m は届いた。キャッシュは古いまま
```

`_terrF` は #R117 の**速度制限つき追従**なので、一気に −994 へは行かない——だから
「テストがいつ降下を始めたか」で目標が海面の上にも下にも来る。**閾値の競争**である。

### 4. 直したこと

キャッシュに**それを計算した外形**を持たせ、外形が変わったら両方を捨てる。1 呼び出しあたり
参照の同一比較 1 回で、点‐多角形の掃引は従来どおりセルごとに 1 回だけ。

```js
let _fsOceanCache=Object.create(null), _fsBBox=null, _fsGeoSrc=null;
function _fsGeoSame(cg){ if(cg===_fsGeoSrc) return true; _fsGeoSrc=cg; _fsOceanCache=Object.create(null); _fsBBox=null; return false; }
```

`_isOpenOcean()` は**キャッシュを読む前に**これを通る（後ろに置いたら、古い答えに当たってから捨てることになる）。

修正後の同じトレース: `TARGET 250`（**−144 ではなく**）・`ocean:true`・`terrF:0`・
`alt 298.0` に対し `eyeAlt 297.9`、**差 0.1 m**（許容 120）。

### 5. 直っていないと言うべきこと

- **bisect は正直に諦めた。** 落ちる／落ちないでは分けられない——tip での再現率は **2 回中 1 回**で、
  GOOD 判定が信用できない。もっと細かい物差し（起動 12 秒後の `_terrF`）も試したが、
  **old `4f3ef256` が −64、tip が −60**——同じ tip が別の run では **−368** を出しているので、
  この量は commit ではなく **DEM タイルが届く順番**を測っている。分かっているのは端点だけ:
  最後に緑だった nightly の commit（`4f3ef256`）はこのマシンで **4/4 緑**、tip は **1/2 赤**。
  つまり**閾値が動いた**のであって、**欠陥を入れたラウンドは無い**。
  この穴は #R152 がこのキャッシュを書いた日からここにある。60 commit のどれが競争を
  数百ミリ秒ずらしたかを名指しするには、1 commit あたり 10 回以上走らせる必要がある。
  **直し方はそれを知らなくても同じ**——競争そのものを消す——ので、そこで止めた。
- **nightly deep tier は、保持されている 15 夜すべてが赤か中断**（#R304 の再来）。
  ただし r173 のこの test 自体は 8/21 の run では**通っている**——赤の原因は別の spec で、
  このラウンドはそれらを見ていない。
- `queryTerrainElevation()` が**カメラの覆うタイルの最大ズーム**から答えるので、
  z12〜z15 が読み込まれていても z10 の水深を返すことがある（実測 `lastTerr −994` ＝ z10 の値）。
  これは MapLibre の仕様どおりで、#R152 のフロアはまさにそれを見越して書かれている。**触っていない。**

### 6. 検査

**振る舞いの側は `tests/r173.spec.js` のコックピット test の中に足した**——**新しい spec ファイルは作っていない**。
理由は測ったもので、手抜きではない: `scripts/test-budget.mjs` の `TOTAL_BUDGET_S` は
**合計と 1 秒の差も無い 4,808**（#R347 が「この後どんな spec でも 1 本足せば超える」と書いたとおり）で、
足すには**測った上で他所を下げる**しかない。この台帳が「まだ請求していない stale-high」と名指ししている
`tests/r192.spec.js`（66 s）を実測したら **4 本で 4.5 分**——**stale-LOW** だった。**下げられる先が無い。**
一方 r173 のコックピット test は**このラウンドの水域の上を、すでに飛んでいる**。追加の boot も追加の飛行も
要らないので、実測でも **52.0 s**（修正前の 52〜55 s と区別がつかない）。

- `tests/r173.spec.js`（deep・コックピット test の末尾）— **合成の海岸線**で両方向に訊くので、
  Natural Earth が届くかどうかにも、どちらの縮尺が競争に勝ったかにも依存しない。
  ① 与えられた外形の内側では「陸」、② 点を含まない外形に差し替わった瞬間に「海」、
  ③ その答えは飾りではない——`_terrF` を −900 に押し込んでも #R152 のフロアが海面へ戻す。
  ⚠ **赤も緑も実測した**（同じ木・同じ台本、`js/flight-sim.js` だけ入れ替え）:

  | | 修正前 | 修正後 |
  |---|---|---|
  | ① 点を含む外形 → 陸 | `false` ✓ | `false` ✓ |
  | ② 点を含まない外形 → 海 | **`false`** ✗ | **`true`** ✓ |
  | ③ `_terrF` を −900 にした後 | **`−799`** ✗ | **`0`** ✓ |
  | 報告された表明 `\|eyeAlt − alt\|` | **248.65**（許容 120）✗ | **0.1** ✓ |

- `tests/r356-checks.test.mjs`（Node・3 本・門の中）— ㋐ 番人はキャッシュを読む**前に**走る、
  ㋑ 番人は隣で宣言された**すべての**キャッシュを捨てる（宣言から導く。ここに一覧を書かない）、
  ㋒ ファイル内で `window.countryGeo` を読むのはその 2 か所だけ。
  ⚠ **3 本とも自分の赤を連れている**（#R345）——同じ述語を、欠陥を戻した写しに当て、
  拒否できなければ失敗する。散文に当たっている検査は、ここで落ちる。
