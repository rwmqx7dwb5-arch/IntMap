## R489 — **回答が名指した14の州は、次のターンには「文字列」しか残っていなかった**

依頼は2通の報告だった。前半は **「主因は、前の回答で得た地名が、構造化された地理データとして次のターンへ
引き継がれていないことです」**、後半は **「1回の依頼に対して少なくとも4回の独立した『調査＋地図化』を
連続実行しています」**。**同じ1つの機構の話**である——調査結果からピン／ハイライトへの受け渡しが、
最初から最後まで**文字列**だったこと。

### ① ターンを越えたのは、26文字だった

`js/atlas-turn-continuity.js` の `actionLabel` が、1ターンが次へ残す**唯一**の記録である。

```
actLabel(a) = a.type + ' "' + (a.name||a.place||a.country||…).slice(0,26) + '"'
```

回答が14の州を名指し、その各々について国も kind も座標も知っていた。そして次のターンへ渡ったのは
`analyze "…"` の26文字だった。だから「マッピングして」を受けたターンは、同じ14州を**自分の文章から
取り直し**、国コードも kind も識別子も持たない日本語の文字列として、1件ずつこの梯子を降りた——

```
「ベルゴロド州」 → highlight → 境界に解決できず → 英訳して再試行 → ロシアへ flyTo
                → 1州ずつ Web 照合 → 再試行 → 「実在しない」
```

`js/atlas-geo-ledger.js` が、1度解決した地点を **種別・国コード・正規名・stableId・座標・
その回答の中での役割** として会話のあいだ保持する。`contextLines()` が次のターンのプロンプトへ
`[RESOLVED PLACES]` として**識別子ごと**渡す。⚠ **地点の「形」は `js/atlas-geo-object.js`（#R397）の
ものをそのまま使う**——provenance も一緒に受け取るので、代表点が「その地点」へ昇格することはない。
⚠ **何も決めない**（CONSTITUTION.md §5）: 覚えて返すだけで、地図に何を出すかは Atlas が決める。

### ② 探しに行っていた境界は、リポジトリの中にあった

`data/admin1-world.json.gz` は **#R290 から同梱されている**。4,515 ユニット・247 か国・2.38 MB gzip。
しかも**名前が一緒に入っている**——

```
RUS :: Belgorod|Belgorodskaya Oblast|Белгородская область|RU-BEL|RU.BL|Belgorodskaya Oblast'|BL
```

読んでいたのは `js/world-packs.js` の警報レイヤーだけで、**Atlas からは到達できなかった**。
`js/atlas-admin1.js` を `resolveHlTarget` の**ネットワークより前の段**に置いた。実測——

```
14州 + 「Белгородская область」 + 「RU-BEL」 + Krasnodar Krai + Republic of Tatarstan
  → 18 hit / 0 miss / 名前ごとの通信 0 件（索引の読み込みはセッション1回）
```

⚠ **当たらなければ null を返して従来の梯子へ譲る**——「大阪湾」「Blue Banana」「（台帳が空のときの）
ベルゴロド州」はここでは答えない。今まで解決していたものは 1 つも経路が変わらない。

### ③ 「実在しない」は嘘だった

`ベルゴロド州` を Nominatim へ投げると、最上位候補は**ベルゴロド市**である。fail-closed の境界検査は
「市は州の輪郭ではない」と**正しく**弾いた。表示していた文だけが間違っていた——

```
旧: 「見つかりません: ベルゴロド州」 / 「その要求の識別子はいずれも実在の国境に解決できませんでした」
新: 「境界データを解決できませんでした: …」 / 「いずれの識別子も、IntMapが保持する境界データに
     一致させられませんでした（場所自体は実在する可能性があります）」
```

⚠ **世界のせいにする文は、次のターンを要らない再検証へ送り出す。** 実際そうなっていた。

同名2ユニットの決め手も直した。Natural Earth は Moskovskaya（州）と Moskva（市）の**両方**に
alias「Moscow」を持つので、**綴りでは分けられない**。分けられるのは**問い合わせが何を求めたか**である——
`州 / oblast / область / province / 도 / provincia…` を含む問いは**面積の大きい方**を採る。

```
Moscow Oblast → RU-MOW / Moskovskaya      Moscow → RU-MOS / Moskva
```

### ④ 1秒1件の床を持っていたのは、7ファイル中1つだけだった

`nominatim.openstreetmap.org` を呼ぶファイルは 7 つあり、公開ポリシーの「1秒1リクエスト」を守っていたのは
`js/routing-geocode.js`（#R298）**だけ**だった。残りは素の `fetch` である。⚠ **私有の床は床ではない**
——2つのモジュールがそれぞれ「1秒1件」を自分に許すと、相手には2件届く。`js/nominatim-gate.js` が
**counter を1つ**持ち、7ファイル 11 か所すべてがそこから枠を取る。

- `reserve({drop:true})` ＝ 打鍵経路。窓が埋まっていれば**捨てる**（#R298 の測定のまま）。
- `wait()` ＝ 一括経路。14件は**並ぶ**——13件を捨てるのが報告された失敗だから。

⚠ **取得はしない**。締切（`js/fetch-deadline.js`）も header も解析も呼び出し側のまま。

### ⑤ 同じ調査を、1ターンに4回

`js/atlas-turn-results.js` は #R441 から重複を畳んでいる——**描画時に**。その時点で 4 回ぶんの
Web 検索・モデル呼び出し・ジオコードは**すべて支払い済み**で、しかも 4 つは互いに**違う結論**だった
（時間窓を誰も固定していなかったので、それぞれが別の瞬間に別の範囲を検索した）。

`callKey(name, args)` を **実行前**に引くようにした（`js/atlas-agent.js`）。

⚠⚠⚠ **上限ではない。** CONSTITUTION.md §5 と #R413 の恒久指示（「Atlas に制限・例外を増やすな」）の
とおり、呼び出し回数の予算も plan も 1 つも変えず、拒否もしない。**同じ呼び出しには、先の成功した結果を
そのまま返し**、「これは今このターンで自分が出した答えである」と添えるだけ。**失敗は覚えない**——
再試行が正しいのは、まさにその場合だから。（利用者への確認で、上限を入れる案ではなくこちらが選ばれた。）

時間窓そのものも、台帳が**質問ごとに1度**固定して持つ（`setWindow`）。次の検索はそれを渡される。

### ⑥ ピンは、自分が何であるかを言えなかった

`addPin(lng,lat)` が作るマーカーは `{id,lng,lat,elev}` で、ポップアップは `📍 Pin #3` と出る。
`pin` action も `place` しか取らない。だから「着弾地点を説明付きでピンして」に対応できる action が
**存在せず**、Atlas は `analyze → 素のピン → analyze → ピン` と**説明を第2の調査で作り直して**いた。

`pin` が `title` / `description` / `date` / `source` / `url` / `country` / `confidence` を取り、
`addPin(lng,lat,meta)` がそれを持ち、ポップアップが出す。⚠ すべて `IntMapSafe.html` / `IntMapSafe.url`
経由（#R272 SEC）。⚠ `meta` は任意で、既存の呼び出し元（右クリックメニュー・検索カード）は 1 バイトも
変わらない。⚠ **`country` は飾りではない**——「オクチャブリスキー」単体は成功し得ない問い合わせで、
記録に残っていたのはまさにそれが失敗する様子だった。

### ⑦ 1ターンに2回描くと、1回目が消えていた

描画経路はどれも `clearHl()` / `clearPolyHl()` / `clearPois()` で始まる。**新しい依頼には正しい**。
**1つの依頼が14州を14アクションで描く**ときには誤りで、各アクションは成功を報告し、地図には
**最後の1つ**しか残っていなかった。**同じ run に属するあいだは足す**。

⚠⚠ **「同じ run か」は action に押した印で決める**（`runActions` が `a.__paintRun` を押す）。
最初は `_curTurn` を見ていたが、それは `run()` でしか進まないので **`runDirect` を2回押すと
1つの依頼に見えて積み上がった**。次に `_runGen` にしたが、**`IntMapOS.dispatch` の素の呼び出し**
（診断用の扉であり、`tests/r157.spec.js` が通る扉）はどちらの counter も進めないので、やはり
積み上がる——**browser 半分がそれを1件の失敗として捕まえた**（`poly.n` が 1 のはずのところ 2）。
印なら**寿命の管理が要らず**（`runActions` の早期 return が何本あっても消し忘れが無い）、
**印の無い action は必ず置き換える**。
⚠ #R143 の世代トークンは「**古い**非同期描画が**新しい**ものを上書きする」話で、そこは 1 行も変えていない。
⚠ **Atlas から何も取り上げていない**——上限も拒否も無い。地図が、返信が既に主張していた状態になっただけ。

### 起動費用（`npm run check:perf` の ratchet を意図的に1段上げた）

`js/nominatim-gate.js` は **eager** で読む必要がある——`js/routing.js` / `js/river-course.js` /
`js/search-geocode.js` / `js/routing-geocode.js` は**トップレベル宣言を持てない**（tests/r175 #4）ので
`window.IntMapNominatimGate` 経由で届き、Atlas が読み込まれる前に検索が走り得るから。

```
eager modules   282 → 283          eager raw  4419.6 → 4431.9 kB   （gzip +3.8 kB / brotli +2.3 kB）
async chunk "atlas-console"  837.5 → 849.3 kB   （台帳と ADM1 索引はこの chunk に入る）
```

⚠ **これは「上限を上げて通した」のではなく、増えた理由を述べて ratchet を進めたもの**。
床が下がれば天井も下がる（#R195 の規則）ので、`--update` は縮んだ項目も一緒に書き戻している
（`async raw −160.7 kB` / `dist.assets −146.1 kB`）。
⚠ **アプリシェルの行数予算（tests/r168 #8・8,050）は上げていない。** `src/main.js` と
`js/app-body.js` への追記を**既存行に畳んで** 8,049 に収めた。
