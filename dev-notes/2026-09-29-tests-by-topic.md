〈依頼〉「IntMap、様々な側面から監査し、すべてやりきって。全部任せる。求めるのは修正ではなく改革」——構造監査（`2026-09-29-structural-audit-reform.md` §5）が承認待ちとして残した「ラウンド単位の検査 633 本を主題単位へ統合し、綴りを読む検査を挙動の検査へ」を利用者が承認した。

## 0. 測った

- `tests/` 直下の `r<N>` 名の検査は 633 本（node 検査 521・spec 112）、155,835 行・10.6 MB。1 つの主題（例: `js/geodesy.js`）を守る検査が 35 本のファイルに散り、どれが何を守るかをファイル名から引けなかった。
- 主対象（読む・import するファイル）を機械で数えてクラスタに分け、12 の領域に割った（Atlas×2・測地/GIS・災害シミュ・歴史・画面・レイヤー・その他×2・工程と文書・ニュース/天気・エンジン/バックエンド/データ）。
- 統合から外したもの: 並行 PR が書き換え中だった r192/r201/r530/r564/r668/r333、`scripts/doc-facts.mjs` が中身を読む r285、`ci.yml` が名指す r783-format-compat、spec 112 本（node 検査とは性質が違う）。

## 1. やったこと

- **512 本 → 312 本**（＋共通補助 `tests/helpers/geo-shared.mjs`・`tests/helpers/layer-locale-tables.mjs`）。名前は `tests/<主題>-checks.test.mjs`。各 test の題名は元のまま、先頭に由来のラウンド札 `#R<N>` を付けた——**題名の集合を機械で照合し、元 5,011 件のうち欠けたのは、中身が完全に重なっていた 17 件の畳み込みだけ**（それぞれ、残した側に経緯を移した）。
- **綴りを読む検査 249 件を、対象を実際に評価する形へ**（`import`・`vm`・acorn で関数を取り出して呼ぶ・記録用の地図やエンジンに通す）。置き換えたものはすべて、変異を入れて赤くなることを確かめた。変異は**作業ツリーに書かず**、`fs.readFileSync` の差し替えと ESM の load hook でメモリ上に入れた（同じ作業ツリーで他の担当が検査を走らせていたので——ディスクに書く変異が他の検査を一時的に赤くした実測がある）。
- **評価できないものは綴りのまま残し、理由を 1 行で書いた**（型: DOM・レンダラの中のクロージャ／CSS・マークアップ／Deno の Edge Function・SQL／「2 つ目が無い」のようにソースの形そのものが主張であるもの）。
- **隔離**: 別プロセスだったものを 1 ファイルにすると、グローバル（`window` 等）の書き換えが次の検査に漏れる。各元ファイルをブロックに閉じ、グローバルを差し替える検査は test の中で準備と後始末をする（`isolate()`）。モジュールの読み込み時にグローバルを置くものは別ファイルに分けた。`--test-randomize` で順序依存が無いことを確かめた。
- **継ぎ目**: 他の検査ファイルをパスで読む箇所（`gate-parity-and-shards` の変異対象・`r200` が読む `r165` 等）を新しいパスへ、または「その回の題名を持つファイルを中身で探す」形へ。`scripts/round-names.mjs` の `LEGACY_NUMBERED_COUNT` 631→121・`LEGACY_NUMBERED_MAX_ROUND` 808→783。`.github/checks-cost.json` は旧ファイルの CI 実測秒を行き先の test 数で按分して導出した（`measured` 欄にそう書いた。CI で再計測するまでの値）。現状仕様の文書 19 本の 284 か所と、コード中のコメント 649 か所の旧パスを新しいパスへ。`docs/TESTING.md` に置き場所の正本（「Where a regression check lives」）を足した。

## 2. 置き換えの過程で見つかったもの

- **製品の欠陥 2 件（別 PR で直した）**: Atlas の操作で対象が複数一致したとき「入力を求める」はずが「失敗」と報告されていた（`2026-09-29-atlas-ambiguous-is-not-failure.md`、#811）。GIS の時間の宣言が拒否コードの宣言表を通らなかった（`2026-09-29-gis-refusals-declared.md`、#812）。どちらも**綴りの検査が「その行が在ること」だけを見ていたので緑だった**。
- **検査の穴 3 件（この PR で塞いだ）**: R204 ⑥ は `REF` で計算し直していて、出荷値の元である `SUB_REF` の変更を捕まえられなかった。R577 ⑧ は片方のモデルが wave の役割を失っても緑だった。統合で評価する形にした R299 ⑥ は、fixture の時間軸が 4 時間しかなく**毎時 30 分以降は必ず赤**になっていた（時計を 40 分にずらして旧版が赤・修正版が緑を確認）。
- **見つけたが直していないもの（提案に回す）**: `js/locales/ui.{fr,ko,zh,zh-hans}.js` に、同じキーを 1 つのオブジェクトの中で 2 回宣言している箇所が 18（後の値が黙って勝つ）。#R274 ① が錠なしで `doc-facts --check` を走らせ、他の検査の変異中の木を読みうる。

## 3. 否定した見立て

- 「ファイルを機械的に連結すればよい」——別プロセスだった隔離が崩れ、グローバルの漏れで 12 件（GIS）・10 件（Atlas）が赤になった。ブロックに閉じ、後始末を test に入れて初めて緑になった。
- 「担当ごとの単独実行秒を台帳に入れる」——別マシン・別負荷の単位で、CI の値と混ぜると shard の釣り合いがずれる。CI 実測の按分にした。

## 4. 残したもの

- spec 112 本と、上の除外 8 本は `r<N>` の名前のまま（`LEGACY_NUMBERED_COUNT` が下向きにだけ動いて数える）。
- 領域の接頭辞で分けたため、主題が近いファイルが複数ある（`terrain-water` が 3 本、`hazard-other-*` の 24 本など）。次の段で主題ごとに合流させられる。

## 5. 検証

- `check:static`（round-name を含む）・`check:docs`（named-path 1,969 件すべて実在）・`check:agents`・`check:testbudget`・`checks-shards --check` は緑。
- `npm run test:checks` 全件 1 回: 5,710 件中 5,705 件が緑、5 件が赤。**5 件とも単独で走らせると緑**（`--test-concurrency=1`）。共通の原因は統合前からある形: `#R717 ①` は錠を取って `js/` に探針ファイル（`js/__r717-*.js`）を書くが、`js/` や文書を走査する側（R236・#R585 ④・#R700 ⑤・R241 ①・#R274 ①）は錠を取らないので、同時に走るとそれを拾う。**錠は書く側だけが取っても、読む側が取らなければ隔離にならない**——次に直すべき構造として残す。
