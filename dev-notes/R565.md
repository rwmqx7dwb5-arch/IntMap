## R565 — **インターネットの健康状態を、供給者を1つも名指さない土台として足した**

> 「Internet Health → Internet outages → BGP anomalies → Routing visibility → Network reachability
> みたいなレイヤーを作れます。」「理想はすべてを多角的に統合し統一的、網羅的基盤にすること。」

### 実装ではなく、規約が設計を決めた

着手前に 12 の候補を**本番オリジン `https://rwmqx7dwb5-arch.github.io` から実際に `fetch` して**
測った。鍵なしでブラウザから届いたのは 5 つだけで、そのうち出典と条件を書けるのは 3 つだった。

**⚠ Cloudflare Radar は、トークンがあってもブラウザからは原理的に届かない。**
トークン無しで 200 を返す公開エンドポイント `/client/v4/ips` にも `access-control-allow-origin` が
無く、preflight も未実装（400／405）だった。つまり**欠けているのは認可ではなくヘッダ**で、
トークンはヘッダを足さない。OONI は CORS が `*.ooni.org` / `*.ooni.io` のホワイトリスト
（Origin を振って確認: `https://explorer.ooni.org.evil.com` は拒否されるので、正しくアンカーされている）。
**BGPView は `bgpview.io` に A/AAAA レコードが無く、ホストごと消えていた**（#R514 と同じ形）。

そして RIPE の規約は「RIPEstat のデータを再パッケージ・再配布してはならない」と明示している。
中継すれば触れうる。**読者のブラウザが読み、当方は 1 バイトも保存しない**なら触れない。

⇒ だから **Edge Function を 1 つも作らず、同梱データも増やしていない**。そして供給者は
コードの分岐ではなく **`PROVIDERS` の 1 エントリ**にした——「使えるかどうか」は実装の問題ではなく
鍵とライセンスの問題で、**それはこのファイルが変わらないまま変わる**（`.agents/rules/no-ad-hoc-hardcoding.md`）。
Cloudflare を後から足すのは、エントリ 1 つと中継 1 つであって、このファイルの書き換えではない。

### ⚠⚠⚠ 打ち間違いと「障害ゼロの地球」が、上流では同じ応答になる

実測: `/v2/outages/alerts?entityType=nonsense` は **HTTP 200・`error: null`・`data: []`**。
これは障害が 1 件も無い世界の応答と**3 フィールドとも同一**である。

#R536（段の条件を「解決器が存在するか」で分けたら本番で下の段が死んだ）と #R514（上流の不在が
計器では 5 通りの別名になった）と同じ形なので、対策も同じ形にした——**範囲は `/entities/query` が
その範囲の実体を返したときにだけ使う**。実体が 0 件の `entityType` は存在しない。
そのときレイヤーは `unsupported_scope` と言い、**測っていない「異常なし」を描かない**。
供給者ごとの「最後に何をしたか」は `report()` の答えに同梱する——
**誰が測ったかを言わない障害の答えは、答えではない**（#R499・#R504）。

### ⚠⚠⚠ 書いた検査が、書いたコードのバグを 1 件捕まえた

`deficit(value, base)` は上流の `value` と `historyValue` から「その回線自身の直近の通常水準からの
低下率」を出す。最初の実装は `const v = +value, b = +base; if (!isFinite(v) …)` だった。

**`+null` は 0 で、`isFinite(0)` は真である。** つまり `value` が欠けた読み取りは
`1 - 0/b = 1` ＝ **100% 遮断**として、色の最も濃い端で塗られていた。上流が数値を何も言っていない
国が、全断として描かれるということ。#R543 の「`isFinite(+v)` は『数か』を訊いていない」が
そのまま再演していた。⇒ **coercion を「した後で調べる」のではなく「する前に拒む」**。

### ⚠ 信号の一覧を 1 つも書かなかった

IODA は独立した複数の計器（BGP 可視性・/24 の能動計測・ネットワーク望遠鏡・Google のトラフィック）
を持つが、**その名前は応答の `datasource` として届く**ので、凡例の選択肢はそこから組み立てる
（`js/shakemap.js` が USGS の製品から指標一覧・色・刻みを読むのと同じ形）。
検査 ⑦ は 2 方向から測る——**聞いたこともない計器名が凡例に出ること**と、
**ファイルが既知の計器名を 1 つも綴っていないこと**。

同じ理由で、**原因（政府命令・ケーブル切断・停電）はこのレイヤーが答えない**。
それを分類して API で返すのは Cloudflare だけで、上のとおり届かない。
原因の対応表をコードに埋め込むのは `.agents/rules/no-ad-hoc-hardcoding.md` が禁じているので、
**原因は Atlas がウェブに訊く**（同ファイル §2 の「判断が要るなら、判断できるものに訊く」）。

### ⚠ 結合できなかった 41 件は、穴ではない

IODA の地方エンティティを `data/admin1-world.json.gz`（#R290 で同梱・4,515 単位）に結合した実測は
**1,999 件中 1,958 件＝97.9%**。外れた 41 件は Anguilla の集落、Åland の自治体、
`[Invalid Region (54)]` のような欠番——**そもそも第一次行政区画ではないもの**である。
だから最も近いポリゴンに寄せず、**拒んで数え、凡例に出す**（#R531 の形）。

⚠ 結合には**新しい読み込み器を作っていない**。`js/atlas-admin1.js` の `resolveMany()` に訊く
——同じファイルを開く 3 つ目の読み手は、3 つ目の意見だからである。
⚠ IODA 自身の `/v2/topo/region` は使っていない（gzip 14 MB・展開 36.8 MB）。
