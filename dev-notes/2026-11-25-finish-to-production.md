---
title: 与えられた仕事は本番検証まで完遂する——「次の作業の着手時に回す」工程を廃止
date: 2026-11-25
---

〈経緯〉利用者の指示(2026-11-25):「与えられた仕事は完遂するように変更して」。直前の並列 25 セッションでは、PR は全部 main に入った一方、本番検証・deploy 後の設定・USB は各セッションが「次の作業の着手時」に回して閉じており、起動時の通知にも本番未到達で検証の記録がない PR(#1398・#1404・#1405)が残っていた。次の作業が来ない限り、その工程は誰にも実行されない。

〈変えたもの〉`AGENTS.md` §5.1・§11.2 と `.agents/skills/intmap-round/SKILL.md` §6・§7。工程は「PR → MERGED → main の CI 緑・本番公開 → 本番検証(受領証)→ 原本の最新化 → USB → done」を 1 つの作業の中で終える。merge 後に main の CI を待つのも作業のうち(background 実行・ポーリングしない)。deploy・秘密の設定・初回の取り込みなど merge 後にしかできない手順も、その回で行う。ユーザーにしかできないものだけを AGENTS.md §7 に従い 1 回の依頼にまとめる。

〈変えなかったもの〉PR が MERGED になるまで閉じない規則、CI 赤・conflict の直し方、`worktree.mjs` と `master-sync.mjs` の仕組み、USB スクリプトの不変条件。能力や検査は 1 つも減らしていない(文言だけ)。

〈効果の測り方〉次に起動時の `worktree.mjs status` が述べる「本番未到達・本番検証の記録なし」が、完了報告のたびに 0 に戻っているか。
