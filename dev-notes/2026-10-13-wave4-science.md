## 0. 決めた理由と、測ったこと（着手前、2026-10-13）

- **既にあったもの**（第 1〜3 波の記録）: 地震レイヤー・ShakeMap・この場所の地震の記録（`quake-history`、**確率は出さない**と明言）・
  地震波／津波のシミュレータ・火山灰の「いま噴火したら」・放射拡散と福島の答え合わせ・今週の地球。
- **無かったもの**: 大地震のあと誰もが訊く「**まだ来るのか、どのくらいの大きさが**」に答える面。地震の記録は「推定しない」を貫いており、
  確率を出す計器は IntMap のどこにも無い（`grep -i aftershock|omori|reasenberg` は説明文に 3 か所のみ）。
- **公式の予測は少数の地震にしか無い**: 2026 年の M6 以上 106 件のうち USGS の `oaf` 製品（余震予測）を持つのは 11 件（ComCat を
  `producttype=oaf` で数えた）。日本の気象庁は大地震の後に見通しを発表するが、世界のほとんどの地震には数値の見通しが無い。
- **手法と係数は公開されている**: USGS の運用コード OpenSHA OAF（github.com/opensha/opensha-oaf、**CC0**）が、Page ほか（2016, BSSA 106:2290,
  doi:10.1785/0120160073 を Crossref で確認）の区分ごとの一般パラメータ・時間変化する検知限界・García ほか（2012, BSSA 102:185）の全球区分の
  0.05° 表（`TectonicRegimeTable.dat`、658 kB）をそのまま配っている。上流の 3 ファイルの最終変更は 2021-05-15。
- ⇒ **Reasenberg & Jones（1989）の余震予測を、USGS のコードと同じ規則で、カタログ上のどの M5 以上の地震にも出す**。ベイズ結合で p・c を
  固定し a だけを更新するのは USGS の `RJ_AftershockModel_Bayesian` の読みどおり（`setup_model` が両モデルの最尤 p・c を固定して a の PDF の積を取る）。

## 1. 作ったもの

- **`js/aftershock-core.js`**（純粋）: 区分 `regimeAt`（カリフォルニアの 5 区域をメルカトル平面の多角形で先に、無ければ García の格子の最近傍）・
  検知限界 `completenessAt` / `mcAt`（max(magCat, F·Mm − G − H·log10 t)）・余震域 `zoneOf`（Wells & Coppersmith 1994 の破壊長を
  OAF の範囲で切り、本震と M≥magCentroid の余震の球面重心）・`kIntegral`（検知限界が一定の部分は解析的、直後の部分は対数時間の Simpson）・
  `posterior`（OAF の a の格子・正規事前分布 σ(M)²=σ0²+σ1²/10^max(M,6)）・`mixture`（事後分布上のポアソン混合の「少なくとも 1 回」と
  2.5/50/97.5% 点。ポアソン CDF は正則化不完全ガンマ）・`forecast`（USGS と同じ 1 日／1 週／1 暦月／1 暦年）・`run`（答え合わせ `check` を
  含む）・USGS の `oaf` 製品の読み・`?as=`・`forAtlas`。
- **`js/aftershock.js`**（遅延 `aftershock`）: カード——最上部に「公式の予測ではない・各国の機関（日本では気象庁）に従う・確率は円全体」、
  見通しの時点、見出し（今後 1 週間の M6 以上の確率と、本震と同規模以上が「およそ N 回に 1 回」）、4 期間 × 5 規模の表（確率と回数の範囲）、
  累積余震と予想される減り方（95% の帯）の図、根拠（区分・一般パラメータ・使った余震の数と事後分布・余震域・検知限界・最大余震）、
  USGS 自身の予測（あれば、合算しない）、「この見通しはどれくらい当たる？」（下の §2）。地図に余震域の破線円・余震（見通しの時点より後は白抜き）・本震。
  **マスタークロックが見通しの時点**——過去の地震のあとに合わせると、その時点までの余震で出せた見通しと、終わった期間の実際の回数（95% の範囲の
  内・下・上。カタログが漏れなく記録する規模だけ）。ライブの時計がライブのまま進むだけでは計算し直さない（毎分の読み直しをしない）。
- **扉**: 地震ポップアップの「余震の見通し」（M5 以上）・地震の記録で選んだ地震・Tools ▾ の行（最近 30 日の M5.5 以上から選ぶ）・
  `?as=<ComCat ID>`・命令 `aftershock.open`・Atlas `sim.aftershocks`（`eventId`／`place`／`at`、doc は `more-features` の at 560）。
- **束**: `data/aftershock-regimes.json.gz`（55 kB。`scripts/build-aftershock-regimes.mjs` が上流の 1 コミットに固定して 3 ファイルを無加工で写す。
  上流の表が述べる区分ごとの格子点数と、復号した連長の合計が一致しなければ書かない）。
- **手法のページ** `science.html#aftershock`（en / ja）: 式・事前分布・余震域・検知限界・ベイズ更新・答え合わせ・実績・限界。
- **出典・通信**: `js/reference-data.js` に OpenSHA OAF（CC0）の行。プライバシー §4（en / jp）と `scripts/outbound-hosts.json` の USGS の行に
  「余震の見通しはその地震自体の位置と余震域の半径を送る。場所を名指したときは整数度に丸める（`nearUrl` は地震の記録と同じ規則を import して使う）」を
  足し、`LEGAL_DATE` を 2026-10-13 に。新しい外部ホストは無い（USGS の `forecast.json` も earthquake.usgs.gov、CORS `*` を実測）。

- **共有窓口**（check:surface）: 新しい窓口 `window.IntMapAftershock`（遅延モジュールの公開名。地震の記録の `IntMapQuakeHistory` と同じ形）と、
  その読み（`js/wb-layers.js` の扉・`js/atlas-cap-sim.js`・`js/map-ui.js` の Tools 行）、カードが読む `IntMapLazy`・`IntMapOS`・`IntMapSafe`・
  `IntMapDevice`・`__setDetent`・`IntMapQuakeHistory`（「この場所の地震の記録」へ渡す）を、地震の記録のカードと同じ形で足した——基準を `--update`。

## 2. 実績（2026-10-13 測定・`data/aftershock-hindcast.json`）

`scripts/build-aftershock-hindcast.mjs` が、2015-01-01〜2025-01-01 の M7 以上**全部**（137 件。規則で選び、外れたものも落とさない）について
本震の 1 日後に見通しを出し、その後の実際と比べた。モデルには何も合わせていない。

| 期間 | M5+ 少なくとも1回: 予想の平均 / 実際 | M6+ | M7+ | M5+ の回数が 95% の範囲に入った割合（下 / 上に外れ） |
|---|---|---|---|---|
| 1 日 | 46.3% / 38.0% | 12.7% / 8.8% | 1.7% / 0.0% | 96%（1 / 4） |
| 1 週間 | 68.5% / 56.2% | 27.4% / 19.7% | 5.2% / 0.0% | 91%（9 / 4） |
| 1 か月 | 78.6% / 71.5% | 37.1% / 24.8% | 8.6% / 1.5% | 85%（18 / 2） |
| 1 年 | 87.9% / 83.9% | 50.3% / 41.6% | 14.7% / 2.9% | 77%（26 / 6） |

- **このモデルは高めに出る**。大きな規模と長い期間ほど強い。一因と考えられるのは、p を一般値に固定したまま a だけを学ぶこと
  （実際の系列の減衰が速いと長い期間で過大になる）と、1 日目に大きな余震が続いた系列で a が大きく学ばれること（トルコ 2023 は 1 日目に
  M7.5 を含み、a の事後平均 −1.91 は事前 −2.29 より大きい）。どちらも検証はしていない見立て。**合わせ込みはしない**——カード・手法のページ・Atlas の
  doc がそのまま述べ、大きな値を「上振れ気味の見積もり」と読ませる。
- 個別（本震の 1 日後）: 熊本 2016 M7.0（SZ-INLBACK）1 週間の M5+ 予想 4 [1–10]・実際 2。能登 2024 M7.5 は 7 [2–15]・実際 2。
  トルコ 2023 M7.8 は 16 [8–25]・実際 6（下に外れ）。リッジクレスト 2019 M7.1（CAL-HYDROTHERMAL・M3 まで検証可）は 1 日の M3+ 予想 102 [80–126]・実際 55。

- `tests/wave4-science-checks.test.mjs`（node・10 件・約 3 秒・ネットワーク無し）: ① 区分表の復号が上流の格子点数と一致し、名指す区分が地質と
  合う（太平洋＝安定海洋・オーストラリア中央＝安定大陸・ハワイ／アイスランド＝ホットスポット・東京／チリ＝沈み込み帯・カリフォルニアは区域が先）
  ② 事前分布が USGS の式 ③ K が総当たりの積分と一致（直後の不完全な時間を含む）④ **事前分布から a を引いて模擬した系列で、M3+ の 95% 範囲が
  92.5〜97.5% を覆い、M6+ の「少なくとも 1 回」の予想と頻度が 5 ポイント以内**（ベイズの仕組みそのものの較正）⑤ 実際の ComCat の 3 系列
  （`tests/fixtures/aftershock-sequences.json`＝ビルダと同じ要求の答え）が同梱の実績の行に再計算で一致し、実績の集計が行から導ける
  ⑥ USGS の実際の `forecast.json`（パナマ 2026 M7.7）を書かれたとおりに読む ⑦ 地震の位置はそのまま・名指した場所は丸めて送る・リンク
  ⑦b Atlas の要約の但し書きと M5 未満の拒否 ⑧ 扉・能力・手法のページ（en / ja、式 4 本以上と限界）⑧b Atlas の entry（science・scenario が
  自分の schema の引数を名指す・doc が割当の at・en + jp）。
- **外すと落ちることを確かめた**: 事前分布の項を消す → ②⑤、97.5% 点を 90% にする → ④⑤、格子の緯度を反転 → ①⑤、答え合わせの
  検知限界の条件を外す → ⑤。

- **ブラウザでの確認**（build 済みの dist・USGS を fixture で応答・他の外部は遮断、Playwright 1 起動 16 秒）: 時計を熊本の本震の 1 日後に置いて
  Atlas `IntMapOS.execute('sim.aftershocks', { eventId })` が completed、カードに 5 行の表と終わった期間の答え合わせ、地図に余震域・余震・本震
  （描画数を地図から数える）、「この見通しはどれくらい当たる？」で 3 行の実績、「いまの時点にする」で答え合わせが消える、命令
  `aftershock.open` の空呼び出しで最近の M5.5 以上だけの一覧。この確認で見つけて直した欠陥 2 つ: 一覧を読んだ後にカードを描き直していなかった
  （「読んでいます…」のまま）／実際に 0 件の割合が「<0.1%」と出ていた。spec は試験時間の天井（`TOTAL_BUDGET_S`）に入れず木から外した
  （地震の記録の spec と同じ判断）。

## 4. 残したこと

- ETAS（USGS の現行）は実装していない。R&J の一般パラメータ版が USGS の公開した全球の規則であり、ETAS の全球一般パラメータは
  同じ形で公開されていない（OAF の `oetas` は系列ごとの当てはめ）。USGS 自身の ETAS の予測がある地震では並べて示す。
- 「この見通しはどれくらい当たる？」の実績は 1 日後に出した見通しの 1 本だけ。1 時間後・1 週間後に出した場合の実績は未測定。
