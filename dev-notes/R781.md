## R781 — 製品名が訳されていた。名前が名前であることを、誰も述べていなかった

〈利用者「Atlas が『インターマップ』と言ってしまう問題を解決して」。添えられた画面では、日本語で
「あなたは誰？内部のモデルは？」と訊かれた Atlas が「インタラクティブな世界地図『インターマップ』の
下で…」と自己紹介していた〉

### 1. 何が誤っていたのか（モデルの判断ではない）

`git grep -e インターマップ -e イントマップ -e 인트맵` は**追跡されたファイルで 0 件**。画面のどこにも
その名前は出ていない（`index.html` の `<title>` は `IntMap — Explore the world. Ask the map.`）。
つまりモデルは**どこかから写したのではなく、英語らしく見える語を日本語に訳した**——それは
普通の振る舞いである。

人格の正本 `js/atlas-persona.js` の `name` 節は、**Atlas 自身の名前**について
「どの言語でも、どのパネルでも、唯一の名前」と述べている。**製品の名前については一言もない。**
⇒ 欠けていたのは情報ではなく、**その文字列が翻訳の対象ではないという性質**だった。

### 2. カタカナの 1 綴りを禁じる修正はしない

「インターマップ」を名指して禁じれば、この 1 件は消える。しかしハングル・キリル文字・漢字は
**自分の綴りを発明する自由をそのまま持つ**——`.agents/rules/no-ad-hoc-hardcoding.md` §1 が禁じる
「症状ごとの特例」そのもの。⇒ 足したのは性質を述べる 1 節（`wordmark`）:

- `IntMap` は**文字列そのものが名前**で、各言語が訳して置き換える英語句ではない
- **訳語・音写・展開形を持たない**——かな・ハングル・漢字のいずれでも書かない。
  `Int` が何かの略だとして綴り開くこともしない
- 日本語・韓国語・ロシア語・中国語の文の中でも**ラテン文字でそのまま**書く
  （利用者が別の書き方をしていても）。何であるかは**名前の代わりにではなく、名前と並べて**述べる
- 画面に出ている各部の名前も同じ——**インターフェースが見せている語**を使う

### 3. `internal` モードにも入れた

`internal` は「出力が機械可読な JSON だけ」の安い経路で、敬語・意見・感情の節を払わない。
⚠ **しかし訳文を作る経路は internal である**（`js/news-ui.js` の記事翻訳）。固有名が別の文字体系に
書き換わる失敗が起きるのはまさにそこなので、`name` と一緒に運ぶ。**名前は register でも感情でもなく、
どちらのモードでも同じ 1 文で足りる。**

### 4. 検査（`tests/r781-atlas-wordmark-checks.test.mjs`）

- ① **綴りをテストに書かない。** `index.html` の `<title>` から製品名を読み出し、
  **UI が見せている文字列と人格が述べる文字列の一致**を測る（改名すれば両方が一緒に動く）。
  大文字小文字も固定する（`intmap` / `INTMAP` も訳語と同じく別の綴り）
- ② **性質が述べられていること**——節が列挙していない文字体系でも効くこと。
  併せて「代わりに何をするか」が書かれていること（禁止だけの節は従えない）
- ③ **prose を書くモードが 1 つも漏れていないこと**——`order` と `internal` の両方に在り、
  かつ**実際に組んだプロンプト**の両方に文字列として現れること
- ④ Edge Function 側の写しを **import して評価**し、サーバの 3 プロンプト
  （`monitor-run` / `refresh-news` / `news-ingest`）が受け取る節そのものを測る。
  `check:static` の**バイト差分は理由を述べない**ので、節の水準で読めるようにした
