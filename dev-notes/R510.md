## R510 — **「APIキーが必要です」と出るレイヤーは、機能ではなく前提条件だった**

> 「船舶レイヤーは、APIキーが必要ですと出てくるので、没にしてましたが、ちゃんと実装したい。
> あなたの側でできることはすべてやって。私に操作が必要なことがあるならやる」

### 1. 出ていた。そしてそれが設計だった

BYOK——利用者ひとりずつが aisstream.io の無料キーを取得して設定に貼り、取るまで地図は
**何も描かずプロンプトを出す**。これは #R341 が航空機で潰したのと同じ構造である:

- **上流負荷が利用者数に比例する**（ブラウザが1つずつ WebSocket を張る）
- **資格情報を取りに行った人にしか、機能が存在しない**

⇒ `supabase/functions/ais-feed`（**14本目**）。鍵はこの関数の環境変数の中にしか無く、
共有スナップショットを全利用者へ配る。

⚠ **BYOK の経路は取り上げていない**（`AGENTS.md` §3.1）。自分の鍵を持つ利用者は**今までどおり**
ブラウザから直接 aisstream を張る——ライブの WebSocket はどんなスナップショットより新しく、
その鍵はその人のもので、その人のブラウザにしか保存されない。
**変えたのは「鍵が無いとき何が起きるか」だけ**である。

### 2. ⚠⚠ 無料・鍵不要・全球の AIS は存在しない

| provider | 範囲 | 鍵 | ライセンス |
|---|---|---|---|
| **Digitraffic / Fintraffic** | バルト海・フィンランド海域 | **不要**（登録も不要） | CC BY 4.0 |
| **aisstream.io** | **全球** | 要 | 規約に従う |

実測（2026-08-31）: Digitraffic は位置 **890 件**・静的情報 **854 件**を2リクエストで返し、
`access-control-allow-origin: *` を送る。**鍵が無い日でもレイヤーが空にならない**のはこれのおかげ。
⚠ gzip を受け入れない要求には **406**、`Digitraffic-User` ヘッダで名乗ることを求める（どちらも文書化
された要件）。⚠ **喫水はデシメートル**で来る（AIS もカードもメートル）。
⚠ AISHub はデータを提供する人に配り（adsb.lol の re-api と同じ形・#R504）、商用トラッカーは売っている。
**他所の私的な端点を回り込んで取ることはしない。**

### 3. ⚠⚠⚠ WebSocket は「1回の呼び出しの中で」開いて閉じる

素朴な設計は「関数が裏でストリームを開きっぱなしにする」だが、**それは本番で1バイトも集めない**——
`EdgeRuntime.waitUntil` に渡した Promise は**応答をまたいで生きない**（#R341 が航空機で実測し、
そこに設計を賭けていた）。⇒ `?refresh=1` の中で**開く → 数秒吸う → 閉じる**（既定4秒・最大20秒）。
aisstream 自身が鍵1本あたり同時接続3本までと言っているので、十分内側である。

### 4. ⚠⚠⚠ 鍵が違うときの見え方は、繋がらないときと同じ

```
open | sent | error | close:1006      ← フレームは1つも来ない
```

**エラーメッセージが無い。** だから外からは「aisstream が落ちている」と「この鍵を拒否している」が
**区別できない**。⇒ **わざと無効な鍵を入れた手元のマシンで同じ形を再現**し、本番と一致することを
確かめてから、`x-intmap-note` に socket の顛末を出した:
`start | open:rs1:klen<N>:kshape<alnum|other> | sent | ...`

⚠ **鍵の長さと形は出すが、鍵は出さない。** それが実際に問題を解いた事実だった——保存されていた秘密は
**79 文字で英数字以外を含み**、aisstream が発行する形ではなかった（値に別のものが混ざっていた）。
資格情報のダイジェストでは何も分からず、資格情報そのものは応答にもログにもヘッダにも出してはならない。

⚠ **秘密は trim する。** シェルやダッシュボードを通った値には、ついてきた空白がついてくる。
末尾に改行が1つ入った資格情報を持つハンドシェイクは**何も言われずに拒否**され、
それは「鍵が違う」と見分けがつかない。

### 5. ⚠⚠ Storage は 400 を返す。404 ではない

存在しない bucket への PUT は **HTTP 400 + `NoSuchBucket`**。404 だけを見る再試行は**一度も発火せず**、
最初のスナップショットが黙って永続しない。⚠ そして bucket の `allowed_mime_types` には **json を入れた**
——航空側は octet-stream しか許しておらず、#R504 の正直な `application/json` は 415 で拒否され、
**書き込みだけが毎回失敗して他は全部正常に見えた**（#R505）。2つの事実は別ファイルに住むので、
`tests/r510` ② が migration と関数を突き合わせる。

### 6. ⚠ リレー経路にはズームの下限が無い——しかし全球をそのまま運ばない

下限は「視野購読は全球を1つのブラウザに流せない」から在るもので、リレーは既に全球を持っている。
⚠ そして従来の `moveend` ハンドラの `else` 枝は `shipsData` を**空にする**——リレー経路でそれが走ると
**地図をドラッグするたびに世界が消える**。鍵が無いときはそのハンドラの**最初の 1 行だけ**を通る。

⚠⚠ **8/31 の版は「世界は同じバイト列だからパンは何も要求しない」と書いて、全球の JSON を 30 秒ごとに
丸ごと運んでいた。** 実測（本番・9/6）: **797 隻で gzip 後 52,185 バイト＝1 隻あたり約 65 バイト**。
バルト海だけならそれで済むが、鍵が通って全球（数万隻）になった瞬間に**携帯へ 30 秒ごとに数 MB** になる——
鍵が一度も通らなかったので、その設計は一度も試されていなかった。⇒ 関数に **`view` チャンネル
（`?bbox=w,s,e,n`・西>東で日付変更線）** を足し、ブラウザは**見ている範囲＋35% の余白**を訊いて、
**視野がその箱を出たときだけ訊き直す**（余白の内側のパンは 0 リクエスト。ズーム 2 未満は視野が世界）。

### 7. ⚠⚠⚠ 温かい isolate は一度 build したら二度と更新しなかった

8/31 の handler は「強制・何も持っていない・何も持たず古い」の 3 条件でしか `refresh()` を呼ばず、
ブラウザは `refresh=1` を送らず、船舶用の掃引もない。⇒ **一度 build した isolate はその寿命のあいだ
同じバイト列を返し続ける**。本番実測（9/6）: `?meta=1` が `refreshes:0, hydrated:624,
ageMs:494,298,922`（**5.7 日前**のスナップショットを hydrate して即答）→ 次の呼び出しで build →
以後 `x-intmap-age-ms` が伸びるだけ。**温かいサーバーで止まる「ライブ」**。
⇒ TTL（30 秒）を過ぎた呼び出しが**1 回分の更新を待つ**（`refreshOnce`・同時の呼び出しは `INFLIGHT` で
1 つを共有。aisstream は鍵 1 本あたり同時 3 接続で、4 本目は**鍵が違うときと同じ顔**で断られる）。
「古いものを返して裏で更新」は**応答の後に走る仕事が無い**ので選べない（#R341）。

### 8. ⚠⚠ `x-intmap-coverage` は「設定されている provider」を名乗っていた

8/31 の版は `digitraffic+aisstream` を、**aisstream が 0 隻でも**返していた（鍵が拒否されていても）。
被覆の主張が「空の太平洋」を海についての事実に見せる（§25.2）。⇒ **直近の更新で実際に答えた provider と
隻数**（`digitraffic:891`）を返し、スナップショットにも provider 別の隻数 `p` を同梱して、hydrate
しただけの isolate も同じことを言える。

### 9. ⚠⚠ この作業は 8/31 に書かれ、9/6 まで 1 コミットも無かった

8/31 のセッションは関数を**本番に deploy し**（`supabase functions list` に `ais-feed` がある）、
DEV-NOTES に「本番実測 834 隻」まで書いて、**worktree `wt-r509-r507-ships-relay` に 34 ファイルの変更
＋新規 4 ファイルを未コミットのまま**終わっていた（branch の先端は R506 のまま）。だから利用者は
9/6 になってもトーストを見ていた——**サーバーは出荷済み、ブラウザは出荷前**。
今回はその worktree に**触らず**（`AGENTS.md` §6）、差分を R510 の worktree へ写して現在の main
（R507・R508・衛星カタログ更新 11 件）に載せ直し、番号を R509 → R510 に改番した
（`scripts/worktree.mjs status` の空き番号は R510 で、`feat/r509-…` は死んだ branch として残っている）。

### 10. 本番実測（9/6・この回の変更前）

```
x-intmap-count: 795        x-intmap-coverage: digitraffic+aisstream     ← 8/31 の版（設定を名乗る）
x-intmap-note: digitraffic=891,aisstream=0[start|open:rs1:klen79:kshapeother|sent|error:Unexpected EOF|close:0:]
```

**aisstream の鍵は 9/6 も 79 文字・英数字以外を含む形のまま**（8/31 07:46 に設定されたもの）。
手元の Node で**わざと無効な鍵**を使うと `open → sent → error → close 1006・フレーム 0` で本番と同じ形
（`tests` ではなく scratchpad で実測）。**これは利用者にしか直せない**（秘密の入力）。
直るまで、鍵無しの利用者に出る船は**バルト海の Digitraffic 分だけ**である。

### 検査

`tests/r510-checks.test.mjs` 11 本。①は **#R505 の「module 本体を評価する」門を14本目にも通す**。
②は migration と関数の content-type を突き合わせる。③は**鍵が応答に出ないこと**。
④⑤は**取り上げていないこと**と、リレー経路が視野購読の `else` 枝を通らず **bbox を訊くこと**。
⑨⑩⑪は**関数を実際に走らせる**——`Deno.serve` に渡された handler を捕まえ、上流（Digitraffic・
aisstream の WebSocket・Storage）だけを stub して `Request` を投げる: 箱の内側だけが返る／日付変更線を
またぐ箱／被覆は答えた provider だけ／TTL を過ぎた温かい isolate が自分で更新する。
`tests/r510.spec.js` はブラウザで**鍵無しでレイヤーを点けてもトーストが出ず、`ais-feed` に bbox 付きで
訊き、`stream.aisstream.io` には繋がない**ことを見る。
