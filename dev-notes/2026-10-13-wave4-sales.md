〈依頼〉第 4 波の営業担当（学校・報道・企業・自治体。問い合わせから導入まで）。「組織が導入を決められるための、実際に動く道具を。既にあるものと重複しない」。
料金・契約・Stripe には触れていない。外部への送信はしていない。DB の変更は無い（割り当てられた migration 時刻・pgTAP 番号は使っていない）。

## 0. なぜこれを選んだか（測ったこと）

既にあるもの（第 1〜3 波）: 組織向けの紹介 3 ページ・相談フォームとコンソール（パイプライン）・単元対応表と A4 1 枚・印刷用ワークシート・
埋め込みと埋め込み API・引用タブ・セキュリティのページ（何をどこへ送るか）・アプリ内の「このページの通信」と「IntMap のいま」。

欠けていたのは、**導入を決める側の最後の問い**——「うちの端末・うちのフィルターで動くか、情報担当に何を許可してもらえばよいか」——に答える道具だった。

| 何 | 着手前 |
|---|---|
| 学校向けページの情報担当チェックリスト | 「サイトと、地図・データ・フォントの読み込み先を許可してください（プライバシーポリシーに記載）」「WebGL」——散文。実際に試す手段は無い |
| 接続先ごとの「代表の 1 回の要求」 | `scripts/outbound-hosts.json` の `probe` に 113 件。読むのは毎晩の `upstream-liveness`（GitHub の走者から）だけ＝**提供元が生きているか**は分かるが、**学校のネットワークから届くか**は誰も測れない |
| 地図の描画に要るもの | maplibre-gl 6.13 は `contextType` を `'webgl2'` に限る（`src/ui/map.ts`）。学校向けページは「WebGL」とだけ書く |
| 初回表示が使う接続先 | `index.html` の `preconnect`（#R192「何かを描く前に必ず要る」）——宣言はあるが、読者向けには出ていない |

相談フォームに来る「動きますか？」に、運営者は推測でしか答えられなかった。⇒ 1 つの大きな道具として作る。

## 1. 作ったもの

- **`readiness.html` / `ja/readiness.html`**（`scripts/org-pages.mjs` が生成・`ORG_NAV` の `{ bar: false }`＝全ページの足元から）。
  - **ページそのものが許可リスト**: 113 の接続先を 3 層——地図を開くのに必要なもの（`index.html` の preconnect に当たる 7 件）・IntMap の基盤（1 件）・
    データレイヤー（105 件）——の表にし、用途（`what`/`whatJp`）を添える。スクリプト無しでも読め、印刷でき、「一覧をコピー」でフィルターに貼れる。
  - **「診断を始める」を押すと**（読み込みでは走らない——全接続先に問い合わせるのは読者が決めること）、この端末で:
    描画文脈（`webgl2`）・GPU かソフトウェア描画か（`failIfMajorPerformanceCaveat` だけで拒まれる＝ソフトウェア）・Web Worker・オフラインのコピー・設定の保存、
    そして各接続先へ **`no-cors` の GET を 1 回ずつ**（16 本並行・20 秒で締切）。行ごとに「到達 · N ms／到達できず／20 秒以内に応答なし」。
  - **到達できなかった接続先は昨夜の確認と結ぶ**（`data/service-status.json`、`js/service-status.js` の `upstreamFor`）: 昨夜は応答していた＝**このネットワークで遮断**
    （許可が必要）、昨夜も無応答＝**提供元の不調**（許可を頼まない）、読めない＝不明（どちらのせいにもしない）。
  - 判定: 描画できない／最初に要る接続先がこのネットワークで届かない → 「このままでは地図が正しく表示されません」、基盤かレイヤーが届かない → 「一部が使えません」、全部 → 「使えます」。
  - 結果を**コピー・テキストで保存・「結果を添えて相談する」**（`contact.html?attach=readiness`——このタブの `sessionStorage` に置いた結果を `js/org-page.js` が
    空のメッセージ欄へ、欄の `maxlength` に収めて入れ、そう告げる。送るのは本人）。IntMap には何も送らない。
  - 「この診断で分からないこと」をページが書く（遮断画面を返すフィルターは到達に見える／1 台・1 回／利用中に決まる接続先は含まない／昨夜の確認とは何か）。
- **`js/readiness-check.js`**（規則）: `MAP_CONTEXT`・`PROBE_TIMEOUT_MS`・`PROBE_CONCURRENCY`・`firstViewHosts`・`probeRows`（層は内部の `tierOf`）・`probeAll`（1 回ずつは内部の `probeOne`）・
  `deviceReport`・`assess`。**ページの生成器・ページ・Atlas の 3 者が同じ関数で層を分け、同じ判定を下す。**
- **`js/readiness-page.js`**（ページの動き。素のまま配るモジュール。語を持たない——語はページの `data-live`／`data-report`／`data-tiers`）。
- **Atlas `system.readiness`**（`at` 800）: 「学校のネットワークで使える？」「フィルターで何を許可すればいい？」に、読者の端末で同じ診断を走らせて答え、
  届かなかった接続先と昨夜の状態を述べ、診断ページへ結ぶ。`scope:"essential"` は最初の表示と基盤だけ（数秒）。届かない接続先は**発見であって操作の失敗ではない**ので
  `ok` で返す（`.agents/rules/one-pass-or-a-reason.md` §2 の 1——失敗として返すと同じ診断を繰り返させる）。
- **入口**: 学校向けページの「情報担当の方へのチェックリスト」の下にボタン、A4 1 枚の「アドレス」欄に 1 行、全ページの足元（`landing.mjs` が `ORG_NAV` から）、sitemap。
- **営業の手引き**: `docs/sales/README.md` §2 と §3b（「動くか」を訊かれたら推測で答えずこのページを送る・結果の読み方）、`faq.md` に 1 行。

## 2. 構造として直したもの

- **数は持ち主から**: 描画文脈は maplibre-gl の `ContextType` 宣言と、締切・同時数は `upstream-liveness` の `TIMEOUT_MS`・`CONCURRENCY` と、検査が等しさを測る
  （写しが黙ってずれない）。最初の表示の接続先は `index.html` の preconnect、基盤は `src/vendor.js`、接続先と要求は台帳の `probe`——どれも手で並べていない。
- **台帳の `probe` をブラウザへ**: `deriveConnectionLedger`（`scripts/outbound-hosts.mjs`）が要求する行の `probe` を `data/connection-ledger.json` に運ぶ
  （40 kB → 50 kB。読むのは「このページの通信」と診断だけで、どちらも開いたときに取る）。Atlas はアプリ内でこれを読み、ページの生成器は同じ導出から表を書く。
- **素のまま配るページの import 漏れ（実在した欠陥）**: `js/service-status.js` は `js/bus.js`（とその `js/mobile-sheet.js`）を import するが、`vite.config.js` の
  `STATIC_ASSETS` に無かった——**出典のページ（`sources.html`）が `import('./service-status.js')` しても dist では 404 で落ち、「昨夜応答しなかった提供元」を一度も
  言えていなかった**（`.catch` で黙る）。2 つを足し、`tests/wave4-sales-checks.test.mjs` ⑤ が `STATIC_ASSETS` の全モジュールの import グラフ（静的と文字列の動的
  import）をたどって「配られないモジュールに届く」を拒む（2 つを外すと赤になることを確かめた）。
- **ポリシー**: 診断ページだけ `connect-src 'self' https:`。接続先が自分の別ホストへ転送した要求をページのポリシーが拒むと「このネットワークで遮断」と誤報するため
  （観測器が嘘をつく形）。基盤の住所はポリシーに書かない（`TALKS` の規則のまま）。

## 3. 判断

- **1 回の `no-cors` 要求が言えること**を正直に分けた: 応答の中身は読めないので「到達」は「何かが答えた」。遮断画面を代わりに返すフィルターは見分けられない——ページに書いた。
  「到達できず」（ブラウザが応答を返さなかった＝観測された失敗）と「時間内に応答なし」（時計が尽きた）は別の語にし、再試行しない（その時点の写真）。
- **自動で走らせない**: 113 の第三者に端末の IP が届く操作を、ページを開いただけで始めない。
- **結果を IntMap へ送る経路を作らなかった**（DB も Edge Function も足していない）: 相談に添えるかは本人が決め、届くのは既存の相談の本文としてだけ。
