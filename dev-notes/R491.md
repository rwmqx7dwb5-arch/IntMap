## R491 — **回答は「読むもの」でもあるのに、読んでいる途中で止まる経路しか無かった**

依頼は機能の可否だった——**「Atlas内の回答文を選択して、右クリックしたらミニポップアップがでて、
その言葉の辞書的解説がAI生成されるという機能は実装できますか？」**

できる。回答の吹き出しは選択可能なままだし（`.atl-b.a` に `user-select:none` は掛かっていない）、
`contextmenu` を握り潰しているのは地図だけ（`js/mobile-ui.js` の #R231 の swallow は `#map` 限定）。
`getSelection` は `js/` 全体に1件も無かったので、経路そのものは新規である。

**難しかったのは実装ではなく、費用のほうだった。**

### ① 「1日10回」の枠に載せると、機能の目的そのものが成り立たない

読んでいる途中で気になった語を叩く機能が、1タップで質問1回を消費すると、**3語調べた時点で
その日の Atlas が終わる**（`AI_FREE_DAILY = 10`）。これは「使えるかどうか」の話ではなく、
**「読みながら引く」という目的が成立するかどうか**の話である。

⚠ **枠を 20 に上げるのは答えではない。** 同じ壁が少し先に立つだけで、**質問とグロスが
互いを塞ぐ**という構造は 1 バイトも変わらない。だから**別のレーン**を与えた。

| | 質問（既存） | 用語グロス（#R491） |
|---|---|---|
| 表 | `public.ai_usage` ＋ `ai_turns` | `public.ai_gloss_usage` |
| RPC | `consume_ai_turn` / `refund_ai_turn` | `consume_ai_gloss` / `refund_ai_gloss` |
| 上限 | free 10 / plus 50 / pro 200 | free 60 / plus 300 / pro 1,000 |
| 単位 | **1 user turn**（#R318） | 1 カード ＝ 1 回 |
| 入力 | 画像可・web 検索可・prompt 24,000 | **テキストのみ**・web 不可・prompt 8,000 |

**両方向に独立**である。グロスを使い切っても質問はできるし、質問を使い切っても語句は引ける。

### ② レーンは「まだ誰も読んでいない本文についての自己申告」である

⚠ **どちらの枠で払うかは、本文を parse する前に決まる。** ai-proxy は枠切れの呼び出しの本文を
読まないために**消費を先に**やる——#R318 が turn 鍵を body ではなくヘッダに置いたのと同じ理由で、
`task` は body にあるから消費の時点では読めない。だからレーンもヘッダにするしかない。

```
x-intmap-lane: gloss     ← 消費の前に読める（＝どのカウンタを引くかを決められる）
{ "task": "gloss", … }   ← 消費の後に読める（＝そのヘッダが本当だったかを確かめられる）
```

**照合しなければ、これは「安いカウンタで `atlas_turn` を買う」ドアである。** 本文を読んだ直後に
`isGloss !== (task === "gloss")` を**両方向で**見て、食い違えば**払い戻してから** 400 `bad_lane`
を返す。逆向き（`task:"gloss"` をレーン無しで送る）も同じく拒否する——そちらを通すと、
このレーンが防ぐために存在する当のもの（質問枠でグロスを払う）が起きる。
安いレーンは画像も hosted web search も受け付けず、prompt 上限も別に持つ。

### ③ 応答が `used` を名乗ってはならない理由

`js/ai-core.js` は、受け取った応答に `used` があれば**無条件に**質問カウンタの写しへ書く
（#R447 の「サーバーが送った数以外を書かない」の裏返しで、**送られた数は書く**）。
グロスの残数をその名前で返すと、10 回の日に **「残り 58 / 60」** と表示される。
だからグロスの応答は `used`/`limit` を**含めず**、`glossUsed` / `glossLimit` を名乗る。
写しも別（`aiGlossLeft()`）で、入口も別である——`askAIGloss` は `aiQuotaBlocked()` を**呼ばない**。
呼べば「質問を10回したのでグロスが止まる」という、このレーンが存在する理由そのものが起きる。

### ④ 文脈は、turn 履歴ではなく画面から採る

カードが辞書に勝てるのは **「この文での意味」の欄だけ**である。1番目の欄（一般的な語義）は
ブラウザの辞書でも出る。同じ `Georgia` が国なのか米国の州なのかは、**語ではなく段落**が決める。

その段落は**すでに描画されている**——吹き出しがその回答を、直前の吹き出しがその質問を持っている。
だから `js/atlas-gloss.js` は turn 履歴にも envelope にも証拠レジストリにも触らない。CTX は
`{L, esc, chat, ask}` の4つで、どれも状態ではない。

⚠ **長い回答は、語句の「周り」を切り出す。** 先頭から 1,400 字で切ると、終盤の語句が属する段落——
つまり「この文での意味」に答えられる唯一の段落——が落ちる。しかも**画面には何も出ない**（カードが
少し曖昧になるだけ）。`tests/r491-checks ③` は、前から切る実装を落とす。
文の切り出しでは `。` も文末記号に入れてある（入れないと日本語の回答は端から端まで1文になり、
「文」の上限が「段落」の上限に退化する）。

### ⑤ 同じ語×同じ回答は1回しか訊かない

キャッシュ鍵は **(言語, 吹き出し, 語句)**。次の回答の同じ語は**別の問い**なので訊き直す——
答えが段落に依存する、というのがこの機能の趣旨だからである。

### ⑥ 経路は2つ、カードは1つ

- **読者**: 回答文を選択 → **右クリック**（タッチは長押し → 「解説」のピル）
- **Atlas**: `{"type":"gloss","term":str}` ＝ 能力 `reader.gloss`

⚠ **選択 UI からしか届かない能力を作らない**（`CONSTITUTION.md`／Atlas は操作卓）。
dispatch の `case`・catalog のブロック・registry の行・schema の4か所すべてに入っている
（`check:catalog` と `check:capabilities` の22検査が通る）。

### ⑧ 天井は上げない——**上げないために、どこに何を置くかが決まった**

⚠ **`js/atlas-console.js` は 4,909 行で、天井は「4,910 未満」——余白は 0 行である**
（`tests/r318` ⑨b・`tests/r419` ⑨d）。#R199 の規則は「機能は**外へ出る**、天井は上がらない」なので、
新しい subject が入るときに置ける場所は、**既にある行の上**しかない。

| 要るもの | どこに置いたか |
|---|---|
| `import { makeAtlasGloss }` | `makeMsgTools` の import 行の**続き** |
| `const GLOSS = makeAtlasGloss(…)` | `makeMsgTools(…)` を作っている行の**続き** |
| `GLOSS.wire(panel)` | `chatEl=…; inEl=…;` の行の**続き** |
| `case 'gloss':` | **1行必要**（カタログの門は `^ {8}case '` を読む）。その1行は、`dispatch(` の開き行と自分の `switch` を**1行に繋いで**払った——同じ1文の2行だったので |

dispatch の中身（引数の検査・カード起動・3種の返答）は**モジュール側**（`GLOSS.dispatch(a)`）にある。
⚠ 同じ理由で `js/app-body.js` も **1行**しか増えていない（`tests/r168` #8 が index.html ＋ src/main.js ＋
app-body を 8,050 行未満で束ねている。8,048 → 8,049）。そのために `aiGlossLeft` を HOST から外し、
**残数は `askAIGloss` の応答が持って帰る**ようにした——2つ目の窓口を作るより素直で、
「質問カウンタを見ない」という不変条件も 1 か所で済む。

⚠ **`js/ai-core.js` が返す名前の集合＝`js/app-body.js` が転送する集合**（`tests/r169` #2 の shim 契約）。
だから内部だけで使う `aiFetchGlossUsage` / `aiGlossLimitMsg` / `aiGlossLeft` は**返さない**。

⚠ **`\u0000` を区切りに書いたら、生の NUL がファイルに入った**（#R483 が測ったのと同じ罠——
検査は通り、`grep` が「Binary file matches」と言い出す）。鍵の 3 欄のうち先頭 2 つに空白は入らないので、
区切りは空白で足りる。
