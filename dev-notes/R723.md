## R723 — Atlas は自分の作業を 3 通りに記録していて、読者には 1 語しか出していなかった

〈「Atlasの回答中に、なにをいまAtlasがやってるのかみえずらいから、ChatGPTやClaudeのような、
作業中のことがよく見えるUIに。」〉

### 1. ⚠⚠⚠ 足りなかったのは情報ではなく、情報の**宛先**だった

ターンが走っているあいだ、Atlas は自分が何をしているかを**3 か所に**書いていた。

| 記録 | 中身 | 読み手 |
|---|---|---|
| `js/atlas-executor.js` の `API.on(fn)` | 1 操作につき 10 段（`planned` → `validating` → `started` → `progress` → `completed` / `partial` / `failed` / `cancelled` / `superseded`）。能力 id・ターン・source を運ぶ | **0**（`IntMapOS.on(` は grep 0 件） |
| `js/atlas-agent.js` の `opts.onStep({step, calls})` | 「Atlas はいまこの N 本を呼ぶと決めた」を知る**唯一の場所** | `_atlasDbg.steps` ＝ **開発用の診断オブジェクト** |
| `js/atlas-state.js` の `recordOperation` | 引数・status・produced・**所要 ms** | ターン台帳（プロンプト側） |

読者に出ていたのは `.atl-stage` の **1 語**で、段が進むたびに**自分を上書き**していた。
**6 段のターンは 1 語ずつしか見えず、済んだ 5 段は画面に 1 文字も残らない。**

### 2. ⚠⚠⚠ その 1 語は、4 回に 3 回以上まちがっていた（実測）

どの語を出すかを決めていたのは `_STAGE_OF(a)` ——legacy の `type` を 30 ほど並べ、
それ以外は全部 `return 'think'` にする**綴りの一覧**である。`js/atlas-capabilities.js` の 138 行に
照らして数えた:

```
capabilities 138 · _STAGE_OF が名指し 29 · 黙って「考え中」 109
例: data.weather / settings.language / map.choropleth / layers.opacity / research.askHere …
```

**薄い指標ではなく、5 件に 4 件が誤った指標だった。**しかも読者には「本当に考えている」と
「一覧に載っていない」を区別する手段が無い。⇒ 言葉は**その能力自身の `category`**（レジストリの
4 列目）から導く。⚠ **言葉そのものは IntMap が書く散文で、何からも導けない**——導いているのは
**鍵の集合**で、`tests/r723-atlas-progress-ui-checks.test.mjs` ② が「レジストリが使う category に
言葉が無ければ落ちる」を測る。109 件が 1 件ずつ戻ってくることはもう無い。

### 3. ⚠⚠⚠ 道具 1 本目から先は、指標も**取り消しの印**も無かった

`runActions` は道具 1 本ごとに `_atlCompose(ai)` で終わる。それは `ai.innerHTML` を**代入**する。
`.atl-stage` は #R313 以来**2 つの仕事**を持っている——シマーの語であり、同時に
「まだ作業中の泡」を探す走査（`js/atlas-console.js` と `js/atlas-turn-continuity.js` の
`markCancelled`）が見る**印**である。したがって道具 1 本目のあと:

- 指標はターンの残り全部で**消えている**（どれだけ長く走っても）
- 取り消しは**止めるべき返答を見つけられない**

**どちらも無言で壊れていた。** `setStage` は「`.atl-stage` があるときだけ動く」という番をしていて、
その番が見ているのが**消された当の class** だったから——失敗が no-op に見える。
⇒ `js/atlas-progress.js` の `live()` が compose の直後に印を戻し、`done()` が**ターンの終わりに外す**。
⚠ **戻すだけでは足りない**: 再武装は「回答を描いた compose」にも掛かるので、外さないと
**届いた回答の下で「考え中」が回り続ける**。語と印が同じ 1 要素であることの両側である。

### 4. 置いたもの

返答の泡の**兄弟**として `.atl-trace` を置く（`insertAdjacentElement`。#R298 の per-message ツールバーと
同じ理由＝`innerHTML` の代入で消えない）。**行は事象が開く**ので、この経路が名前を知らない能力も現れる
——`_STAGE_OF` との違いはそこで、あちらの知識は一覧だった。回答が着いたら「N ステップ · X 秒」の
1 行に畳み、**読者はそれを開き直せる**。

⚠ **ターンの進み方は 1 つも変わっていない。** 購読して、足して、書き戻さない。
能力は 1 本も減らしていない（`CONSTITUTION.md` §5）。

### 5. 出口を数えず、「生きている一覧は 1 つ」を守る

ターンは abort でも supersede でも throw でも終わる。**出口を全部数え上げて `done()` を呼ぶのは
lifecycle** であり、lifecycle は #R623（持ち替えのたびに破れた錠）と #R667（1 つの `null` が 2 つの
意味）がそれぞれ間違えた形である。⇒ 不変条件は「どの出口も done を呼ぶ」ではなく
**「生きている一覧は常に 1 つ」**で、**返答が 1 つ増える 1 か所**（`open()`）が守る。

### 5b. ⚠⚠⚠ 本番のターンを実測したら、一覧が**時間の 4 分の 1 しか説明していなかった**

最初に通した本物のターン（大阪と札幌の気温を比べて地図に出す）は **57.2 秒**で、一覧に出た 6 行の
合計は **13.6 秒**。残りの **43 秒は 8 回の planner 往復**で、一覧はそのどれについても何も言って
いなかった——**ターンの時間の大半を占める部分に行が無い**。

理由は hook の向きである。`onStep` は**モデルが答えたあと**に鳴るので、待ちを**閉じる**ことしか
できない。**始まったことを知っているのは、モデルを呼ぶ当の関数だけ**（`js/atlas-console.js` の
`_model`）。⇒ そこで 1 行開ける。⚠ 締めの 1 手は agent 自身が `final: true` と**宣言している**ので、
その行だけ「回答を作成中」にする——こちらで文面を見て推測しない。

⚠ **ただし 2 つの呼び出し側が同じ待ちを指す**（返答を開くときと、最初のモデル呼び出し）。
`phase()` を**同じ段については冪等**にした——そうしないと本物の行の上に **0.0s の行**が並び、
読者は**一覧自身の帳簿を、Atlas がやった仕事として数える**ことになる。

再実測（同じ問い）: **7 ステップ・35.7 秒**で、行の合計は 5.1 + 5.5 + 1.1 + 1.1 + 9.0 + 1.9 + 12.1
= **35.8 秒** ＝ ターン全体。⚠ **連続する「考え中」2 行は誤りではない**——あいだで `find_capability`
（能力ではなく agent 自身の道具なので実行器の事象を出さない）が走っている。**まとめると、その隙間を
消してしまう。**

### 5c. perf の baseline は、このラウンドより前から遅れていた

`check:perf` が `atlas-console` の async chunk 超過で落ちた（+10.1 kB ＝ 新モジュールと CSS、
および 4 言語ぶんの訳）。`--update` で baseline を書き戻したが、**同じ更新に自分のものでない差分が
入っている**ので明記する: `tests/perf-baseline.json` の前回更新は **#R711** で、それ以降
**data/ を触ったラウンドが 5 本**ある（#R716・#R717・#R719 と衛星カタログの更新 2 本）。
DEPLOY は ceiling-only なので落ちずに通っていた。⇒ `dist.data` の **+404 kB** はそれらのもので、
このラウンドのものではない。

### 6. 場所は「天井を上げない」が決めた

`js/atlas-console.js` は縮むだけの天井（tests/r318 ⓑ・4,910 行）に対して **4,909 行**、余白 0 だった。
⇒ **出ていく主題は、置き換えられる当のもの**にした: 旧 indicator の 15 行が 12 行になり、
import 1 行が入って **4,907 行**。天井も **4,908 へ下げた**（#R199 の規則——天井は床を追って下がる）。
⚠ import は**行頭に単独で**置く（`scripts/js-reachability.mjs` は行頭で走査するので、
共有行の 2 つ目は「誰も import していない」と読まれる）。

⚠ **#R313 の検査 ⑧ が読む母集合も一緒に動かした。** `js/atlas-console.js` だけを読ませておくと、
シマー・印・番のどれもが**削除によって緑**になる（「見つからない、ゆえに違反していない」）。
述べているのは**指標についての事実**でファイルについての事実ではないので、母集合は 2 ファイルになる。

### 7. 検査は、書いた直後に**変異で鳴るか**確かめた——1 本が生き延びた

7 つの変異（行を上書きする／category の言葉を 1 つ落とす／fallback を「考え中」にする／
`live()` を無効化する／`done()` の撤去をやめる／次の返答で前を閉じない／綴りの一覧を戻す）。
**「どの能力も『考え中』と名乗らない」だけが緑のまま生き延びた**——レジストリの全 category に
言葉がある以上、その主張は fallback に**到達しない**＝空虚だった。⇒ 登録外の id で
**直接** fallback に訊く 2 行を足し、再度の変異（「考え中」にする／空文字にする）で両方鳴った。

### 8. 全件テストが見つけた 2 件——どちらも「検査が綴りを握っていた」形

**(a) `tests/r156-checks.test.mjs` #5 は、自分のコメントが警告している形そのものだった。**
そのコメントは #R540 について **「連結を対象に書かれた検査は、性質ではなく欠陥を固定していた」**
と述べたうえで、次の行で **画像ルーティングの 1 行をバイト単位で固定する正規表現**を書いていた
（``const aiv=bubble('a',stageDots('read'))`` ごと）。⇒ 作業一覧を開くために泡を包んだだけで、
**ルーティングは 1 バイトも変わっていないのにルーティングの検査が落ちた**。
⇒ 述べ直した: 画像の枝が**存在して return すること**／その中で `_atlVisionTurn` に
`imgs, gen, _atts` を渡していること／それが **`AGENT.runTurn` より前**にあること の 3 つ。

**(b) `tests/r175-checks.test.mjs` ③ が新モジュールの死んだ export を 2 つ捕まえた。**
`TRACE_PHASES` は使われていたがモジュール直下、`TRACE_CATEGORIES` は**どこからも読まれていない**。
後者は `CATEGORY_WORD` が既に持っている鍵の**2 つ目の一覧**——つまり**このラウンドが取り除いている当の
二重の正本を、それを取り除くファイルの中に書いていた**。⇒ 消した（鍵は `categoryWords()` が表から読む）。
前者はそれを使う関数と同じ場所＝ファクトリの中へ移した。

⚠ **これ以外の 16 件の赤は退行ではない**——`check:docs` の 1 件（§ の `js/` 本数、直した）と、
それを前提にするメタテスト 9 件、並行実行とツリーロックの競合 4 + 2 件。
切り分けは単独実行で再現しないことによる（`git stash` は全 worktree 共有なので使っていない）。
