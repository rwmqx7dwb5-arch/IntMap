### ① 同じ形が `js/analysis-correlate.js` に 2 か所あった

#R536 のあと `js/` 300 ファイルを構文解析して同型を数え上げた（if/else-if 連鎖 1,301 本・
`else if` 条件 754 本）。**解決器の連鎖で同じ形は #R536 の 1 件だけ**だったが、
**読み込み器**に同じ形が 2 か所あった。

```js
/* ensureCountriesSrc — 残差マップが使う */
if(GE().layers.hasSource('countries')){ cb(); return; }
if(typeof loadCountryData==='function'){ loadCountryData().then(…); return; }
cb();   // ← 到達不能

/* open — 相関ウィンドウを開く */
if(window.countryGeo && Object.keys(countryStats||{}).length) go();
else if(typeof loadCountryData==='function'){ …「読み込み中」…; loadCountryData().then(go); }
else go();   // ← 到達不能
```

`loadCountryData` は `js/app-body.js` が `get loadCountryData(){ return loadCountryData; }` として
**巻き上げられた関数宣言**の上に置いているので、`typeof …==='function'` は**常に真**。
最後の腕は書かれた日から到達しない。**そして連鎖には reject の腕が 1 つも無い。**

`residualMap()` は `hide()` でダイアログを**先に**閉じるので、読み込みが失敗すると
**利用者は地図を頼み、ダイアログが閉じ、そして何も起きない**——描画も、再試行も、失敗表示も、
コンソール出力も無い。`open()` のほうは「読み込み中」の表示のまま**永久に止まる**。

⇒ 「ローダが無い」「投げた」「promise を返さなかった」「reject した」を**1 つの falsy に畳む**
`requestCountryData()` にした。`js/atlas-map-compose.js` の `fromLedger()` が「台帳が無い」と
「その名前が無い」を同じ `null` に畳んでいるのと同じ形である。**存在検査は「呼ぶかどうか」の中だけ**に
残り、呼び出し側は**得たもの**で分岐する。`open()` が待っているのは promise ではなく**データ**なので、
条件も `haveCountryData()` にした（解決したが何も無い場合も、reject と同じだけ正直に答える）。

新しい文字列は足していない——残差マップが既に持っていた
「国データを取得できませんでした。再度お試しください。」を `loadFailMsg()` として共有した。

### ② 「正確に特定できませんでした」は、4 つの別々のことに対して印字されていた

`_pinReplyPlaces` が `verdict:'unplaced'` を積むのは 4 か所ある:

| 積む場所 | 実際に起きたこと |
|---|---|
| 最後の段まで落ちて解決できなかった | **その名前について本当に分からなかった** |
| `newPins.length>=14` | **我々のピン上限** |
| `(Date.now()-pin0)>=PINPASS_BUDGET_MS` | **我々の制限時間** |
| ジオコーダが投げた／`reason==='network'` | **照会が応答しなかった** |

1 つの文で 4 つを名指すと、**後ろ 3 つは地名への濡れ衣**になる——「大阪府は特定できません」ではなく
「今回はもう照会しないと決めた」なのに、読み手には前者としか読めない。

⇒ verdict が `reason` を運ぶ（`unplacedBy: {not_found, budget, infra}`）。注記は**原因ごとに 1 行**。
⚠ **`unplaced` は全件を持ったまま**なので、既に読んでいる呼び出し側から見た形は変わらない。
⚠ `unplacedBy` を持たない古い verdict は、**従来 4 つ全部に使っていた文**へ落ちる（後方互換）。

新文言 2 本を **9 言語**へ（`check:i18n` は 5652/5654 → **5654/5654**）。
⚠ インラインの表は `js/lang-registry.js` ではなく **各ロケールファイルの `inline:`** が持っている。
⚠ `js/locales/ui.zh-hans.js` は生成物なので `node scripts/zh-hans.mjs` で作った。

### ③ 台帳の絞り込みの鍵は、どの呼び出し側も持っていない鍵だった

`resolve(name, opts)` は `kind` と `countryCode` を読んでいた。ところが

- `js/atlas-verify.js` は `countryCode: it.countryCode` を渡すが、その `it` を作る mapper は
  `name/country/kind/summary/lng/lat/provenance/src` しか写さない ⇒ **常に `undefined`**
- `js/atlas-console.js:3088` は `countryName` を渡すが、`resolve()` は**その名前を読まない**

つまり**絞り込めるはずの呼び出し側が 2 つとも、届かない鍵を渡していた**。
⇒ **呼び出し側が実際に持っているもの**を読む: `resolve()` に `countryName` を足し、ピン監査は
`{kind: it.kind, countryName: it.country}` を渡す。エンティティは `record()` が `countryName` を
保存しているので、読めば済む話だった。**呼び出し側が供給できない国コードを発明しても、
死んだ鍵が移動するだけ**である。

⚠ **これは「同名 2 件を選び分ける」機能ではない。** 国コードを持たない同名 2 件は、この台帳では
**同一のエンティティ**である（同一性＝名前＋種別＋国コード。綴りが身元ではないという #R521 と同じ話）。
この鍵がするのは「**違う国の話に、持っている 1 件を答えない**」ことで、
その結果ジオコーダへ落ち、`Springfield, New Zealand` として照会される。

### 起動費用 — 天井は動かしていない（一度は動かしかけた、その記録）

`check:perf` は**素で緑**。`tests/perf-baseline.json` は `origin/main` と 1 バイトも違わない。

⚠ **一度は落ちていて、移植しかけた。** #R543 を土台にしていた間、`async.raw` が 9,618.7 kB
（天井 9,568.4 kB）、chunk `ui.ko` が 389.0 kB（天井 386.9 kB）で落ちていた。`origin/main` 単体を
同じマシンで build して同じ baseline に当てたところ、**超過 50.3 kB のうち 46.7 kB は #R543 自身の
build が既に出していた分**で（内訳のほぼ全部が `index` チャンクの +50.1 kB。許容幅 47.84 kB の
**内側 1.1 kB** に収まっていたので #R543 は緑だった）、**この回の増分は +3.6 kB** だった。

そこで `perf-budget --update` は使わず（**15 項目を書き戻す**ので `index` の +50.1 kB を黙って
飲むことになる。#R500 の教訓）、**落ちた 2 項目だけを移植**した。
**その後 #R546 が baseline を記録し直したので、その移植は不要になり、取り消した。**

⚠ **記録として残す理由**: 「天井に当たった」ときに最初に確かめるべきなのは**自分の増分**ではなく
**土台がすでにどれだけ食っているか**である。ここでは 93% が自分のものではなかった。
⇒ `git archive origin/main` を別の場所に展開して**同じマシンで build し、同じ baseline に当てる**。
これをやらずに `--update` を打つと、他人のドリフトを自分の記録として飲む。

### ⚠ 3 例目が見つかった（この回では直していない）

`js/countries-ui.js:822` の `renderStats` に同じ形の 3 例目がある。`loadCountryData` は
**fetch に失敗しても resolve する**一方 `countryDataLoaded` は false のままなので、
キャッシュ済みの解決済み promise を通して**自分を無限に呼び直し、main thread が約 2 秒で固まる**（実測）。
今回の spec の fixture が「ダウンロードを塞ぐ」ではなく「ローダの seam で reject させる」形なのは
これが理由である。
