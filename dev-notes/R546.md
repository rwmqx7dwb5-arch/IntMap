## R546 — **USGS ShakeMap: 「マグニチュード」ではなく、土地の上で実際に起きたこと**

**依頼**: 「USGS ShakeMap を IntMap にマッピングできる？」——配信形式（等値線 JSON / CoverageJSON /
`grid.xml`）と、既存の人口・施設レイヤーとの重ね合わせまで含めた提案として。

### 1. 何が足りていなかったか（実測）

ライブの地震レイヤー `eq-pt`（`js/wb-layers.js`）は 1 イベント 1 円を描き、クリックすると
**M・地名・現地時刻の 3 行**を出していた。それは**カタログ**——点・規模・深さ——であって、
規模は**震源の性質**である。誰がどれだけ揺れたかは何も言っていない。
**都市の真下 11 km の M6.0 と、600 km 沖の M6.0 は、この地図では同じ円**だった。

ShakeMap はその反対側にある: USGS が観測記録・体感報告（DYFI）・地盤条件・距離減衰から作る
**地震動の場**で、しかも**地理データとして配られている**（誰もが貼る JPEG だけではない）。

### 2. 約 90 個のファイルのどれを使い、なぜ `grid.xml` を使わないか

**1923〜2026 の 6 イベントで実測**（関東 `iscgem906183`／東北 `official20110311054624120_30`／
Napa `nc72282711`／トルコ `us6000jllz`／アラスカ `us7000tdvt`／ワシントン `uw714095342`）:

| ファイル | 中身 | 大きさ | 6 件での存在 |
|---|---|---|---|
| `download/cont_<指標>.json` | GeoJSON の MultiLineString 等値線。**各 feature が `value`・`units`・`color`・`weight` を持つ** | 7〜110 kB | **6/6**（1923 年の Atlas 項目にもある） |
| `download/coverage_<指標>_low_res.covjson` | 同じ場の**正則格子**（例 115×93） | 40〜120 kB | 6/6 |
| `download/grid.xml` | 全解像度の格子 | **10.2 MB（Napa）〜28.4 MB（トルコ）** | 6/6・**使わない** |

⇒ **等値線で描き、格子で答える。** 格子があるので「この都市は何を感じたか」は**引き算ではなく参照**になる。
`grid.xml` は同じ場を 250 倍のバイトで運ぶだけなので使わない。

⚠ `earthquake.usgs.gov` はこれらのファイルに `access-control-allow-origin: *` と
`cache-control: max-age=315360000` を返す（実測）。**中継も Edge Function も要らない**——
カタログを直に読んでいる `js/wb-layers.js` と同じ経路である。

### 3. ⚠⚠⚠ 素朴に書いたら「−0.65 g の揺れ」と印字していた

**等値線ファイルと格子は単位を共有していない。** `cont_pga.json` は `units:"pctg"`、
`cont_pgv.json` は `"cms"` と書くのに、同じ 2 指標の covjson は
`unit.symbol.value = "ln(g)"` / `"ln(cm/s)"` と宣言する——**格子は自然対数を持っている**
（Napa の格子の最大は **−0.650**、`exp` して 0.52 g）。MMI だけが例外で、**尺度なので単位を持たない**。

⇒ 数値は必ず `_toContourUnit` を通す。それは **covjson が自分で宣言した記号**を読み、
**その記号が名指す変換だけ**を戻す。**知らない記号は推測せず `ok:false` を返す**——
間違ったラベルの下に生の数を出すより、答えないほうが正しい。

### 4. 色表も指標の一覧も、この app は 1 つも持っていない

- **指標の一覧は製品のファイル名から数え上げる**（`cont_<stem>.json` / `coverage_<stem>_<res>.covjson`）。
  この app に `'mmi'` や `'pga'` という**書かれた一覧は無い**。表示名も上流のもの（`MMI` =
  Modified Mercalli Intensity・`SA(0.3)` = 0.3-second Spectral Acceleration）。
- **色は等値線の各 feature が持っている**（`color`）。
- **面を塗るかどうかも上流が決める**: covjson に `preferredPalette` を持つ指標だけを塗る。
  実測で持っているのは **MMI だけ**なので、PGA・PGV・SA は自動的に「線だけ」になる。
  ⚠ そして **`state().painted` が「線だけ」と「面もある」を区別する**——#R534 の形（ON と OFF が
  同じ 1 文になる状態）を作らないため、凡例もその 2 つを別の文で言う。
- ⚠ **面の消え際も上流の数**: 上流が引いた**最も低い等値線**（6 件すべてで MMI 2.5）より下は塗らない。
  USGS 自身の intensity JPEG は矩形を塗り切るが、世界地図の上では**角のある色板**に見える。
  等値線が 1 本も無いときだけ `preferredPalette` 先頭の白の連なりを「何も無い」と読む。

### 5. ⚠⚠ 画像は Mercator へ再標本化しなければならない

CoverageJSON の格子は**緯度に線形**。maplibre の `image` source は **4 隅を Web Mercator に写す**。
そのまま渡すと全ての行が赤道側へずれる。**合成場で実測**（緯度 20–60°・401 行）: 段の位置は
Mercator で 155.6 行目、緯度線形だと 213.3 行目——**58 行**。`js/seismic.js:1265` が `mY`/`latOfY`
を持っているのは同じ理由だが、あちらはシミュレータの中なので、こちらは自分で持つ。

### 6. 誰が、どれだけの揺れの中にいたか

`action:"exposure"` は**震度の格子を、地名辞典（GeoNames cities1000・147,924 件）の各都市で標本化**して、
「MMI いくつ以上だった都市の数と、その都市の人口」を返す。範囲外の都市は数えない。
⚠ **これは人口ラスタではない**。等値線の内側にいる全員ではなく**名前のある都市の人口**であり、
その但し書き（`basis` と 9 言語の `basisNote()`）は**数と一緒に必ず出る**。Atlas のカタログ本文も
「その言葉で言え」と指示している。

### 7. 収まらなかったので、収まる場所へ置いた

`js/atlas-console.js` は**余白 0 行**（4,909 行・天井 `< 4,910`・`tests/r318` ⓑ）。
dispatch の `case` は **#R511 の compose の行に相乗りさせ**、能力の本体（引数の解釈・イベントの解決・
結果の HTML）は `js/shakemap.js` に置いた。`js/lazy-modules.js` の 3 か所（グローバル名・動的 import・
mount）も **app-shell の合計行数予算**（余白 1 行）に触れないよう既存行に相乗りさせている。

### 8. ⚠⚠ 自分で書いた 1 行の i18n ヘルパが、9 言語を計器から隠した

最初 `const L = function(){ return _LT.arr(LA.apply(null, arguments)); };` と書いた。読みやすいし、
9 言語は全部その場に書いてある。**それでも `scripts/i18n-pair-audit.mjs` は 16 タプルすべてを
「隣接データスロットとして持たれた翻訳の組」として報告した**——あの計器はタプルを、
**渡された識別子**（`IntMapLang.pickArgs()` / `.pick()` / `.t` に直接束ねられた名前）で見つけるから。

これは `Architecture.md` §10.1 が **1 ファイルに、1 つの理由でだけ**与えている免除
（`js/reference-data.js` の 143 件は「どの言語でも画面に出ていない」ことを AST で確かめたうえでの免除）
の中に、**理由の無い 16 件を紛れ込ませる**ということだった。⇒ 呼び出し側を `_LT.arr(LA(…))` に戻し、
**なぜラッパを書かないのか**をファイルの先頭に書いた。穴は 143 のまま。

### 9. 試験

`tests/r546-checks.test.mjs` **12 本**。**出荷モジュールを stub window で評価する**（#R505 の形——
ソースを読んで綴りを固定する検査は、守っているものが死んでも緑のままになる。#R488/#R533）。
実物の USGS 製品を `tests/fixtures/shakemap-napa.json` に置いた（nc72282711・2014 South Napa M6.0・
3 つの ShakeMap 製品とその全ファイル一覧・MMI と PGA の等値線・MMI の低解像度 covjson・
PGA covjson の parameter ブロック。public domain）。

① `preferredWeight` で製品を選ぶ（**配列を逆にしても同じ製品**——今の feed が偶然その順なだけ）／
② 指標の一覧は製品から数え上げ、**格子を持たないバイト等長の別名は畳まれ**、開くのは震度／
③ `ln(g)` は %g に戻り、**知らない記号は拒まれ**、MMI は素通り／
④ 実物の Napa の場を標本化（ナパ 7.2・SF 3.5・サクラメント 3.4）、**範囲外は 0 ではなく null**／
⑤ **画素で測る Mercator**——段が Mercator の行に落ちること、かつ緯度線形の行と 4 行以上違うこと
（違わなければこの検査は何も証明しない）／
⑥ 最も低い等値線より下は塗られない（実物では**淡くなる**ことと、下端では**完全に透明**であることの両方）／
⑦ **色表を配っている指標だけが面を持つ**（MMI は `painted:true`、PGA は `false`）・指標を切り替えても
前の面が線の下に残らない・`close()` は何も残さない／
⑧ 凡例の色は**ファイルの色そのもの**／
⑨ exposure は格子が閾値以上と言う都市だけを数え、**範囲外の都市は決して数えない**／
⑩ 遅延であること（eager の一覧に無い・`IntMapLazy` から届く）／
⑪ 能力の `lazy` 列と観測器の source 名が、**モジュールが実際に作るもの**を指していること／
⑫ **`image` source に渡す定義の鍵が `url`・`coordinates`・`type` の 3 つだけ**であること（§9b）。

### 9b. ⚠⚠ ブラウザで測って初めて出た欠陥——`image` source に 1 つ多い鍵

ブラウザ（Playwright・実データ）で通したら、**等値線は描かれ、凡例も指標ボタン 6 つも出て、
`open:true`・`valueAt` は 7.24 を返すのに、震度の面だけが無かった**（`painted:false`）。

原因は `addSource` に渡した **`attribution: 'USGS ShakeMap'`**。style spec の `image` source が
取るのは **`url` と `coordinates` の 2 つだけ**で、余分な鍵は maplibre の source 検証に弾かれる。
描画経路は防御的に書いてあるので、**その例外は誰にも見えないところで飲まれた**——
地図には「等値線だけの ShakeMap」というもっともらしい状態が残る。
（同じ鍵を GeoJSON source に渡すのは正しく、出典はそちらが運んでいる。）

⚠ **stub のレンダラはどんな鍵でも受け取るので、検査は「定義の形」を測る**——
`tests/r546-checks` ⑫ が `Object.keys(定義)` を `['coordinates','type','url']` と突き合わせる。

### 9c. 遅延モジュールを 1 本足すと、台帳は 5 つある

`npm test` で 5 本落ちた。4 本は同じ 1 つの事実の別の言い方で、**新しい遅延モジュールが
`js/lazy-modules.js` にしか登録されていなかった**こと（`tests/r209` ③・`r304` ②・`r400` ①・`r408` ④）。
⇒ `src/main.js` の `LAZY_FACTORIES` と `tests/r209.spec.js` の MEMBER 表に 1 件ずつ。
⚠ どちらも**既存行に相乗り**させた（`src/main.js` は app-shell 6 本の合計行数予算の中にある）。
⚠ **この検査の存在をこちらの検査が知らなかった**——`tests/r546-checks` ⑩ は最初
「`src/main.js` に `shakeMap` という綴りが出てはならない」と書いていた。**それは正しい登録を
欠陥と呼ぶ検査**である（同じファイルが起動時の一覧 `MODULE_FACTORIES` と遅延の台帳
`LAZY_FACTORIES` の**両方**を持っている）。⇒ 2 つの一覧を別々に読み、**前者に無く後者にある**ことを測る形へ。

**5 本目は検査のほうが間違っていた。** `tests/r397` ② は「paint 観測器が数える source id は、
どこかのファイルが実際に作っているか」を訊く、正しい問いを持つ検査である。しかしその訊き方が
2 つとも #R488／#R533 の形だった:

- **creators が手書きの 5 ファイル一覧**だったので、6 番目のファイルが作った source は
  「誰も作っていない」と読まれる。
- 一致条件が **`addSource('<id>'` というリテラルの綴り**だったので、source 名を定数に持つファイル
  （`const SRC_LN = 'shk-cont-src'; … addSource(SRC_LN`）は**原理的に見えない**。

⇒ **緩めるのではなく広げた**: creators を `js/` から**ディスクで発見**し、単純代入の文字列定数を
**解決してから**問う。実測 discovered 40 本以上。⚠ 書き換えたので**変異させて赤を見た**
（`paintNow()` の id を 1 つ架空のものに変えると 22 pass / 1 fail、戻すと 23 pass）——
このファイル自身が冒頭で要求している作法である。
⚠ **広げた掃引は、緩む方向にも広がりうる。** 定数の解決は**宣言の初期化だけ**を見て**先勝ち**にし
（後の無関係な代入が、誰も作っていない id を発明できないように）、`removeSource` は
**「作った」の証拠にしない**（壊すだけのファイルがある）。実測 147 source id を発見。

**`check:perf`**: 落ちたのは locale の async chunk 4 本だけで、各 +2.4〜3.6 kB＝**今回足した
18 鍵ぶん**。⚠ `--update` は 15 項目を書き戻すので、**動いた 9 項目だけを移植**した
（`ui.{fr,ko,zh,zh-hans}`・新 chunk `shakemap` 19.6 kB・`async.raw`/`async.gzip`・
`dist.total`/`dist.assets`）。**起動費用は動いていない**——`requests 6` と `modules 285` は完全一致、
EAGER は raw +4.0 kB で許容幅の内なので、ラチェットの締まった側をそのまま残した。
