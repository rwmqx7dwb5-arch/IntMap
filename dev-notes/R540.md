## R540 — **添付できる種類が少なかったのは、判定が「75 個の拡張子の一覧」だったから**

利用者の依頼は 1 行、「**Atlasに添付できるファイルの種類が少なすぎる**」。

### 何が起きていたか

添付の入口は 3 つ（＋ボタン・貼り付け・パネルへのドロップ）あって、どれも `_atlAddFiles` に集まり、
「これは何か」を決めていたのは **`js/atlas-attach.js` の `atlFileKind` ただ 1 つ**だった。その中身は:

```js
const TEXT_EXT=/\.(txt|text|md|markdown|rst|csv|tsv|json|…|dockerfile|makefile)$/i;   // 75 個
if(/^image\//.test(ty)) return 'image';
if(/^text\//.test(ty)||ty==='application/json'||…||TEXT_EXT.test(nm)) return 'text';
return 'other';
```

⚠⚠⚠ **一覧に無いものは全部 `other`＝拒否**だった。PDF も、Word も Excel も PowerPoint も、
アーカイブも。そして `.adoc` `.org` `.wkt` `.f90` `.editorconfig` `LICENSE` のように、
**中身は完全にテキストなのに誰も一覧に書かなかった**ものも全部。
`.agents/rules/no-ad-hoc-hardcoding.md` §1 が名指ししている形そのもの——**実体から導ける埋め込み一覧**で、
苦情が来るたびに 1 行ずつ伸ばす以外に育て方が無い。

⚠⚠⚠ **そして逆向きにも壊れていた。** `image/*` は**前方一致**なので iPhone の既定である HEIC も
「画像」と判定される。ところが `compressImage` は `img.onerror` で **元の data URL をそのまま
resolve** し、`_atlAddFiles` の `/^data:image\//` はそれを通し、ai-proxy の
`IMAGE_MIME = {png, jpeg, webp, gif}` が `if (!part) continue;` で捨てる。
**トーストは出ない。**利用者から見ると、写真を添えたのに Atlas がそれについて何も言わない。

### 直し方——名前を見ない

`ATL_FILE.read(file, {encodeImage})` が、順に**ファイルそのもの**に訊く:

1. **PDF か** — `%PDF-` 署名。⚠ 先頭バイトとは限らない（ISO 32000-1 §7.5.2 が先行バイトを許し、
   スキャナは実際に出す）ので先頭 1 kB を走査する。
2. **旧 Office か** — OLE2 署名 `D0 CF 11 E0 A1 B1 1A E1`。読めないので**そう言って断る**。
3. **コンテナか** — ZIP/gzip 署名。**中の部品**が何を持つかで docx / xlsx / pptx / odf / kmz /
   一般 zip を決める（`word/document.xml` があるか、`xl/workbook.xml` があるか…）。
   中央ディレクトリを歩き、`DecompressionStream('deflate-raw')` で展開する。Zip64 も読む。
4. **画像か** — **エンコーダに渡してみる。** png/jpeg/webp/gif の data URL が返れば画像、
   返らなければ画像ではない。⚠ **これが HEIC の無言消失に対する構造的な答え**で、
   「描けたかどうか」以外に信用できる判定は無い。
5. **テキストか** — バイト列を復号する。BOM → UTF-8（fatal）→ WHATWG のレガシー符号化を
   **誤復号の少ない順**に。⚠ 許容的なもの（gb18030・windows-1252）を**最後**に置く:
   どちらもほぼ全てのバイト列を受け入れるので、先に置くと必ず本来の符号化に勝ってしまう。

どれでもなければ**理由つきで断る**（`media` / `legacy-office` / `image-undecodable` / `binary`）。
一覧を読み上げる「添付できるのは画像とテキスト系ファイルのみです」は消えた。

⚠ SVG は絵でも文書でもあるので、**ラスタ化に失敗したらソースをテキストとして渡す**。

### xlsx は「値の列」ではなく「表」として出す

`<row>` の `<c r="C1">` を `r` 属性から列番号に直して並べ直し、TSV にする。
⚠ **空のセルを詰めると、数字がどの列にあったかが消える**——表計算はそれしか持っていない。
共有文字列（`sharedStrings.xml`）とシート名（`workbook.xml` ＋ `_rels`）も辿る。

### そして、届いていた分も切られていた

⚠⚠⚠ #R158 は添付テキストを `[ATTACHED FILE …]` として **`prompt` に連結**していた。
ai-proxy は `prompt` を `MAX_PROMPT = 24_000` で `.slice()` する。クライアントは
**1 ファイル 60,000 字 × 4 本**を積む。つまり**添付の中身は、利用者にもモデルにも何も言わずに
捨てられていた**。#R285 で `system` に起きたのと同じ形で、解も同じ——**自分の枠を持たせる**:

| チャネル | サーバ側の枠 |
|---|---|
| `files`（抽出済みテキスト） | `MAX_FILES` 8 / `MAX_FILE_TEXT` 120,000 / `MAX_FILES_TEXT` 400,000 |
| `docs`（provider が直接読む文書） | `MAX_DOCS` 4 / `MAX_DOC_BYTES` 8 MB / `MAX_DOCS_BYTES` 12 MB |

3 provider すべてに通した（Anthropic `type:"document"` / OpenAI `input_file` /
Gemini `inline_data`）。**どれが動くかは secret `AI_PROVIDER` が決める**ので、1 つだけに
配線したら secret が変わった日に消える。添付テキストの前置きは `filesBlock()` **1 か所**で作る。

⚠⚠ **上限はクライアントとサーバの両方にある。** クライアントは**理由を出すために**、サーバは
**クライアントを信じないために**。2 か所にあるのは正しく、**2 つの数が離れるのが間違い**なので、
tests/r540 ④ が `ATL_FILE.LIMITS` と ai-proxy の定数を**等しいこと**で照合する（#R504）。

### CI が見つけた1件 — 一度だけの置換は、消したはずの記号を組み直す

CodeQL (`js/incomplete-multi-character-sanitization`, high×2) が `xmlText` を指した。
`<<!--x-->!--y-->` は内側のコメントが消えると**外側の半分どうしが閉じてまたコメントになる**し、
`<scr<b>ipt>` は `<b>` が消えると `<script>` に戻る。⚠ **この出力はモデルへ渡す平文であって
HTML には入らない**ので攻撃経路は無いが、指摘している形は正しい——1 回の `.replace()` は
「markup を消す」ではなく「markup をだいたい消す」で、**.docx の読者は文書が言っていることを
受け取るべきで、組み直った断片を受け取るべきではない**。⇒ 不動点まで回す（各パスは必ず
短くなるか変化なしで終わるので停止する。上限 64 は病的な部品が回り続けないための柵）。
⚠ **entity は最後に解く**ので、`&lt;!--` と書いてある文書はその通り `<!--` を返す——それは
markup ではなく本文である。tests/r540 ②b2 は**生の markup** を食わせて測る。

### 起動費用の天井を2項目だけ上げた

`npm run check:perf` が超えたのは 2 項目だけで、上げたのもそれだけ（`--update` は 22 項目を
書き戻すので、他所で測った値を持ち込まないよう落ちた項目だけを手で移した）:

| 項目 | 旧 | 新 | 増分 | 許容幅 |
|---|---|---|---|---|
| async chunk `atlas-console` | 989,899 B | 1,001,341 B | **+11.2 kB** | 4.8 kB |
| async chunk `ui.ko` | 394,153 B | 396,204 B | **+2,051 B** | 2,048 B |

⚠ **この予算が守っているのは起動費用で、そこは動いていない**——`eager.raw` +1.0 kB /
`eager.gzip` +0.4 kB（許容 7.6 kB）/ `requests` と `modules` は**完全一致で不動**。
増えたのは **Atlas を開いたときに初めて読み込まれる非同期チャンク**で、その実体は
`js/atlas-attach.js` の判定器（ZIP リーダ・OOXML/ODF の抽出・文字コード判定）である。
⚠ `ui.ko` は **10 個の訳語で 2,051 B**——許容幅 2,048 B を **3 バイト**超えた。同じ 10 行で
fr は +1,990 B・zh は +1,797 B で**どちらも通っている**。つまりこれは「韓国語だけが太った」
のではなく、**4 つのうち 1 つだけが門の上に出た**という話で、天井を上げる以外に直しようが無い
（訳を削れば §3.5 の 9 言語対応が崩れる）。
⚠ **測り直しは #R538 まで取り込んだ後の値である**——分岐点で測った超過は自分の費用とは限らない。

### 残した問題 — 1ターンの中で文書は毎回送り直される

Atlas のターンは 1 回の質問に対してモデルを複数回呼ぶ（サーバ側の `TURN_MAX_CALLS` は 12）。API は
ステートレスなので、**文書はその全ての呼び出しに載る**。「この PDF を要約して」のような質問は
1〜2 回で終わるが、道具を何段も使う質問に 8 MB の PDF を添えると、その分だけ上りが増える。
⚠ **これを「最初の 1 回だけ送る」で塞ぐと、2 手目以降のモデルは文書を持っていない**——`CONSTITUTION.md` §5 が
禁じている「到達できる能力と回答品質を削る」ほうに倒れる。暴走を止める柵は `TURN_MAX_CALLS` と
`MAX_DOCS_BYTES` の側にあるので、正しさを採ってこのままにした。

### 文字コード

⚠ `atlReadText` は `FileReader.readAsText`＝**UTF-8 前提**だったので、日本語の表計算が既定で
書き出す **Shift_JIS の CSV は文字化けしてモデルに届いていた**。拡張子の一覧を通っていたので、
「対応している」と見える状態のまま壊れていた。

### 旧い検査が守っていたもの

- `tests/r158 #4` は `ok('export function atlFileKind(f){')`——**壊れた実装について真**だった綴り検査。
- `tests/r149 #9` は `compressImage(f,2000,0.9)` の**引数名**を固定していた。
- `tests/r493 ②e` は `_agentPrompt(req,q)+_fileBlock` という**連結そのもの**を固定していた。

3 本とも**性質は保ったまま**書き直し、`tests/r540-checks.test.mjs` を新設して
**本物のバイト列で評価する**（テスト内で実際の ZIP 中央ディレクトリを組み立て、実際の Shift_JIS を
食わせ、エンコーダが `null` を返す場合を実際に通す）。#R505 の「ソースを読む検査は走らせる検査の
代わりにならない」を、この主題にも当てた。

### 法務文面

⚠ 添付は AI プロバイダへ送られる。#R149 以来**画像は既に送られていたのに、方針は「入力したテキスト」
としか言っていなかった**。今回 PDF と文書のテキストが加わって差はさらに大きくなったので、
`js/legal-text.js` の Privacy §4 を EN / JA 両方で直し、`LEGAL_DATE` を進めた
