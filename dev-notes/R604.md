## R604 — **「解像度が低い」も「coverage がくそ」も上流の話ではなく、束の作り方の話だった**

〈利用者: 「ふざけんじゃねーよ。歴史的地方区分の境界線のcoverageがくそ。全時代、全地域で完璧に網羅しろ。線の解像度も低すぎる。」（画面は 1850 年の日本、令制国が破線で出ているところ）〉

#R564 はこの同じ苦情の一つ前の版に「薄いのは上流である」と答えた。その結論は**測った 1 年（1900）については正しく、それ以外については確かめていなかった**。今回まず測り直したところ、二つの苦情はどちらも**上流ではなく、こちらの束の作り方**だった。

### ① 解像度は、ビルドの許容値だった

`scripts/build-hist-admin1.mjs` は Douglas–Peucker 0.02°（≒2.2 km）で間引き、座標を3桁（≒110 m）に丸める。世界ぶんの多角形ファイルを「パースできる大きさ」に収めるための値である。

実測 2026-09-10、OHM の Overpass に対して:

| | 上流 | 出荷していた束 |
|---|---|---|
| 伊豆国（relation 2687374）の頂点数 | **2,800** | **29** |
| 周長 | 787 km | — |
| 平均頂点間隔 | 281 m | — |

**束は解像度を1つしか持てない。地図は20持つ。** どの許容値を選んでも、片方のズームで粗すぎるか、もう片方でファイルが大きすぎるかのどちらかになる。だから許容値は動かさず、**線の供給元を替えた**。

OpenHistoricalMap は同じレコードを**ベクタタイル**でも配信している——`https://vtiles.openhistoricalmap.org/maps/ohm/{z}/{x}/{y}.pbf`、TileJSON は `maps/ohm.json`（z0–20・CC0）、`land_ohm_lines` の admin 線は `start_decdate` / `end_decdate` を**数値で**持つ。したがって:

- 境界はそのズームの**ネイティブ形状**で描かれる（`imta-vt-line` / `imta2-vt-line`）。
- **時代の移動は再取得ではなく `setFilter` 1回**。1つのタイルキャッシュが 2,000 年ぶんを賄う。
- 海に出ないのは**上流自身の `maritime` 属性**で落とすから。現代の `ref-admin1` / `ref-admin2` が持っているのと**同じ句**で、#R564 が Natural Earth に対して導出していた判断（`data/border-coast.js`）が、これで1か所になった。

⚠ **束は消していないし、死んでもいない。** タイルが届かない読者のための**予備の線**であり（切り替えは「タイルを要求した」ではなく **`queryRenderedFeatures` が実際に描いていると答えた**ときに初めて行う。#R565 の「数は地図から取る」）、**9言語のラベル**であり（タイルは `name` を1つしか持たない）、**クリックの答え**（`geomAt`）であり、`coverage()` が数えるものである。

### ② 「全時代」も、ビルドの引数だった

束は `--since 1850` で焼かれていた。この絞り込みは「**1850 年より前に終わった単位を1つも入れない**」という意味なので、それ以前の世紀は原理的に空だった。そして時計の下限（`js/chronos.js` の `YMIN`）自体が 1850 だった。

両方を動かした。下限は**西暦 1 年**、束は `--since 1` で焼き直し:

| | 以前 | いま |
|---|---|---|
| 第1級（admin_level 3–4） | 3,049 件 | **4,679 件** |
| 第2級（5–6） | 16,236 件 | **22,711 件** |

在force 件数（第1級・その年の6月15日）: 西暦1年 **64**・1000年 **113**・1500年 **393**・1800年 **411**。**以前はこの4つがすべて 0 だった。**

⚠ **上流にある薄さは、埋めずに言う。** z5 の 160 タイルを掃引した実測（在force の `admin_level`≥3 セグメント本数／それが乗っていたタイル数）は、西暦1年 936／14・1000年 1,195／12・1500年 3,712／23・1700年 7,157／29・1900年 8,341／66。**古い世紀ほど記録は地理的に偏る。**「全時代に届く」と「全地域を埋める」は別のことで、後者は上流の空白そのものだから、埋めれば `CONSTITUTION.md` の禁じる偽物になる。凡例（9言語）はそれを述べる。

### ③ ⚠⚠⚠ `Date.UTC(1, …)` は 1901 年である

ECMA-262 は `Date.UTC` の第1引数に**2桁年規則**を適用する。`Date.UTC(1,0,1)` は 1901-01-01、`Date.UTC(50,…)` は 1950 年。

つまり `YMIN = 1` と書き換えただけの実装は、`IntMapTime.min === 1` を満たしたまま**地図を 1901 年へ連れて行き、ラベルだけが「1年」と言う**。カーネル内の瞬間の生成を全部 `atUTC()`（`setUTCFullYear` を使う。この規則は適用されない）に通した。

⚠ 検査（`tests/r573-checks` ①）は**定数を読まない**。`setYear(1)` を呼んで**帰ってきた年**を読む。ソースを読む検査はこの欠陥を見られない（#R505）。

### ④ ⚠⚠⚠ 10 進年の規約は、推測ではなく実測で決めた

タイルの日付比較は `*_decdate`（10進年）に対して行う。規約を推論で決める代わりに、160 枚の z5 タイルを復号し、`*_date` 文字列と `*_decdate` 数値を**両方**持つ **103,093 件**に候補を当てた:

| 候補 | 平均絶対誤差 |
|---|---|
| 年 + (通日 − 0.5)/その年の長さ　←**これ** | 2.06e-6（浮動小数の丸めだけ） |
| 年 + (通日 − 1)/その年の長さ | 1.37e-3（**＝半日**） |
| 年 + 通日/その年の長さ | 1.37e-3 |
| 年 + (通日 − 1)/365.25 | 1.49e-3 |

**その日の中点である。** 最初に書いた実装は「1日の始まり」で、これは**その単位が発足したその日の `start_decdate` を下回る**——つまり **4,679 単位すべてが、自分が生まれた当日だけ描かれず、廃止された翌日にはまだ描かれていた**。半日は丸め誤差ではない。

⚠ **年になり得ない `*_decdate` が 106,173 件中 3,080 件ある**（|v| が 1 未満のものが 1,573 件、残りは 1e151〜1e222）。素直に `>= t` へ掛けると、そのレコードは**すべての時代から消える**。上流の問題なのか値の型付けの artefact なのかはこちらからは判じられないが、**扱いは同じで、しかもその 3,080 件のための特例ではない**——「年の範囲の外にある値は日付ではなく、**日付が無い**」という規則にした。端が無いことは「いま始まる」でも「決して始まらない」でもなく、**その端を制約しない**ことである。

### ⑤ ⚠⚠⚠ 算術を DOM のクロージャから出した（#R570 の教訓）

上の3つ——どの年で比べるか（`decYear`）・どの境界を描くか（`ohmFilter`）・読者がどの年を頼んだか（`rail`）——はどれも純粋な算術で、どれも**少し間違うと地図が一世紀ぶん自信を持って間違う**種類のものである。そして書き始めた場所は、地図と言語表とスライダーが無ければ評価できないファクトリの中だった。#R570 が同じ形で 6 件の P0 を出している。

`js/hist-scale.js` に出した。DOM も地図も時計も言語も触らない。

⚠ **式と述語が離れないことを測る。** `ohmFilter()` は描画器が読む式、`inForce()` は検査が読む述語。片方だけ直すと地図とテストが別のことを言い始め、**しかも両方緑になる**（#R536/#R515 の形）。`tests/r573-checks` ④ は式を**実際に評価して** 720 通りのレコード × 12 の瞬間で突き合わせる。

### ⑥ 下限を 1 にすると、年スライダーが壊れる

1年=1目盛りのレールは、全長の **91%** を 1850 年より前に使い、**1850–現在を末尾 8.7%** に押し込む。実測でこのパネルの軌道は 340 px なので、**176 年が 30 px ＝ 1 px あたり 6 年**、それも地図が最も多くを持っている区間で。

**到達範囲を伸ばすことで、すでにあった精度を奪ってはならない。** スライダーは 0〜1000 の**位置**を運び、年は位置の**区分線形関数**になった。折れ点（1500 で 25%・1850 で 50%）は好みではなく、上の z5 掃引が示す**記録密度の変わり目**である（失効条件も `js/hist-scale.js` に書いた）。⚠ 目盛りも `.ntl-scale`（flex の均等配置＝区分線形の軸では「1500」が軌道の中央に立つ）から、**Time タブが #R337 で既に作っていた位置指定の定規**（`#ntl-ticks`）へ移した。そのファイルのコメントが最初から言っていたこと——「位置は値から**計算**しなければならない」——が、そのまま今回の要件だった。

### ⑦ ビルドで踏んだ2つ

⚠ **22,807 関係で V8 の 4 GB を使い切って落ちた**（`Ineffective mark-compacts near heap limit`。18 分ぶんの取得のあとで）。原因は「全惑星の生 geometry を `Map` に溜めてから簡略化する」形で、これは**上流の大きさに縛られていて、こちらの必要には縛られていない**。`--max-old-space-size` を上げるのは、次に上流が育つたびに誰かが上げ直す数なので、**バッチごとに簡略化して生を捨てる**形にした。ディスクキャッシュは無傷なので、落ちた 18 分は失われていない。

⚠ **`--global` を渡し忘れると、`data/hist-admin2.js` の中身が `window.__HISTADM1=` になる。** 読み込みは成功し、エラーも警告も出ず、`js/time-admin1.js` が第2層を注入した瞬間に**第1級の記録が第2級に置き換わる**。実測で 15 MB の、**自分についての主張が全部正しく、名前だけ間違ったファイル**ができた。既定を**出力ファイル名から導く**ようにし、`--global` は規約の外の出力のための上書きとして残した。⚠ ビルドを直しただけでは足りない（次に誰かが上書きできる）ので、**出荷物の側でも** `tests/r573-checks` ⑦ が「各束は自分のファイル名が示す global だけを名乗る」ことを測る。

### ⑧ 「時計の下限は 1850」と述べていた場所

下限が動いた以上、それを引用していた文はすべて偽になる。火山の凡例（9言語）・Atlas のカタログ文2か所・`js/beta-overlays.js` のコメント3か所・`js/atlas-console.js` のコメント・`docs/VOLCANO-INTELLIGENCE.md`・`Architecture.md`。⚠ 直し方は「1850 を 1 に書き換える」ではない——**火山の記録は時計に切られなくなった**のだから、凡例は「時計は1850年まで」ではなく「記録は時計よりさらに古くまで遡る」と言う（**数を1つも含まないので、次に下限が動いても嘘にならない**）。`js/atlas-console.js` の年の拒否メッセージは #R380 から既に `IntMapTime.min` を読んでいたので、実装は無変更でそのまま正しい。

### ⑨ 綴りを固定していた検査

`tests/r349-checks` ① は `const YMIN = 1850` の**数字**を読んでいた。R349 の主張は「その数が 1850 であること」ではなく「**下限は1つで、全員がそれを読むこと**」だったので、数を読むのをやめ、性質（下限が存在し、暦にある年で、R349 が約束した 1850 には少なくとも届く）を読むようにした。`tests/smoke.spec.js` の「1850 へドラッグできる」は、**位置レールの上で 1850 を意味する位置**へドラッグして年が 1850 になることを読む。

### ③b ⚠⚠⚠ 同じ罠を4か所で踏んだ——そして「直した」と書いたコメントの隣で3か所が生きていた

③ を直したとき、`js/chronos.js` には「この規則は `setUTCFullYear` を通す」というコメントまで添えた。
それでも次の3か所は `Date.UTC` のままだった。順に、**見つけたのは全部テストである**。

| # | 場所 | 症状 | 見つけたもの |
|---|---|---|---|
| 1 | `js/chronos.js` の `atUTC` | 年1が1901になる | 自分（実装時） |
| 2 | `js/news-timeline.js` の `floorMs()` | 日付入力の下限が1901 | `tests/smoke.spec.js` R378 ① |
| 3 | `js/news-timeline.js` の `zInstant()` | 「0019」と打つと**1919年**になる | 同 ①（下限を直したあと） |
| 4 | `js/news-timeline.js` の `tzOffMs()` | `min` 属性が **1901** を名乗り続けた | ブラウザでの実測（`floorMs` は正しかったのに） |

4 が一番たちが悪い。`tzOffMs` は「その時間帯での壁時計」を `Intl.DateTimeFormat` から取り出して
**`Date.UTC` で瞬間に戻す**。年1の瞬間について書式化器は「1」と答え、`Date.UTC` はそれを 1901 に戻すので、
**求まるオフセットが +1900 年**になっていた。つまり `floorMs()` は正しい値を返しているのに、
それを表示用に整形する経路が 1901 を作っていた——**正しい値と、正しく見えないという2つの事実**が
同時に成り立っていて、ソースを読む検査ではどちらも見えない。

⇒ 規則の持ち主を `js/hist-scale.js` の `utcAt()` **1つ**にし、4か所すべてがそれを読む。
`tests/r604-checks` ⑧ が持ち主を**評価**し、`tests/smoke.spec.js` R378 ① が**入力欄が最終的に持つ
`min` 属性**を読む（ソースではなく結果を読むので、5か所目が現れても見える）。

⚠ **そして #R378 の主張そのものが変わった。** 「打ちかけの年（0019）は下限に丸める」という規則は、
1900年より前が**違法だった**から意味があった。下限が1年になると 0019 は**合法な要求**なので、
丸めは起きない——代わりに #R378 が同時に入れた 320 ms のデバウンスが、途中の値が時計に届くのを止める。
検査は「下限に丸まる」ではなく「**19年は19年を意味する**」を測るようになった（直す前は 1919 年だった）。

### ⑧b ⚠⚠⚠ 下限を下げたことで、国境レイヤーが 1500 年に「ウィーン会議の地図」を描いていた

1500 年のヨーロッパをスクリーンショットで見て気づいた。ラベルが **Prussia・Austrian Empire・
Republic of Kraków・Kingdom of Sardinia**——1500 年の政体ではない。

`js/time-borders.js` の `nearest()` は「1500 以下のスナップショットが無い」ので**持っている中で最も古い
1815 を返す**設計で、それは下限が 1850 だった間は起こり得なかった。**下限を下げた私の変更が、
この経路を初めて到達可能にした。**

原因は一覧のほうだった。`YEARS` は 12 個で 1815 から始まっていたが、**上流が公開しているのは 36 枚で、
西暦 100 年から**ある（2026-09-10 実測。GitHub のディレクトリを読んだ）。24 枚全部を取得して確かめた——
全部あり、全部同じ形（204〜1,946 features）。既存のコメントの「1815 と 1880 しか無い」は嘘ではなく、
**1850–1885 という窓についてだけ**の話で、誰もそれ以外を訊いていなかった。

⇒ 系列を 36 枚に広げた。誤差は「最大 1,700 年」から**その系列自身の粒度**（1000 年以前は 100 年刻み、
以降は 1279/1492/1530/1715/1783 のように上流が細かく持つ年もあり最大およそ 50 年）になった。
西暦 1〜99 年は最古の 1 枚が答える。

### ⑨b 検査が1本まるごと走っていなかった

`tests/r380-checks.test.mjs` は先頭で `/const YMIN\s*=\s*(\d{4})\s*;/` を `.exec()` していた。
`const YMIN=1;` は4桁ではないので `null` になり、**import 時に TypeError で落ちて、そのファイルの
検査が1件も走らなくなった**。しかもそれは「時計の到達範囲を語る全ての文が、カーネルの下限と一致するか」
を9言語で掃引する検査で、**まさにこのラウンドが取り締まられるべき対象**だった。

直したら 3 件の本物が出た: 起動時カードの「1850年まで遡って表示」（9言語）・出典ページの
historical-basemaps の項目（「1815 と 1880 の2枚」＝上の⑧b で古くなった）・Maddison の下限が
時計の下限と同じ数であることを要求する assertion（もう同じではない。各出典は自分の範囲を持つ、
というのが `js/chronos.js` の元からの契約）。

⚠ **そして検査の「正の半分」が充足不能になっていた。** 「4桁の年で書かれた reach-claim が8件以上ある」
——下限が1年になると、正しい文は4桁の年を持てない（`{y}` プレースホルダか、その言語の紀年表記になる）。
つまり**そのラウンドは何を書いても自分の検査を通せない**。数えるものを「4桁の年」から
「reach を語る文」に変えた。

### ⑩b 起動費用と配信量が動いた——測った分だけ、理由つきで

`npm run check:perf` は**ビルドが要る**のでローカルの `npm test` には入っておらず、CI の Static checks
で初めて落ちた。3項目が天井を越えていて、3つとも意図したものである。

| 項目 | 以前 | いま | 差 | 理由 |
|---|---|---|---|---|
| eager.modules | 291 | **292** | +1 | `js/hist-scale.js` は時計とパネルの両方が起動時に読むので eager |
| eager.raw | 4,556.7 kB | 4,562.6 kB | +5.8 kB | 同上（gzip +2.2 kB / brotli +2.2 kB） |
| dist.data | 176,217 kB | **183,692 kB** | +7,475 kB | 束の全時代焼き直し（第1級 +2.7 MB・第2級 +4.9 MB） |

⚠ **eager が増えるのは、この gate が最も嫌う向きである**（#R311 の ratchet）。それでも +1 module を
受け入れたのは、算術を DOM のクロージャの外に出すこと自体が今回の目的の一つだからで（#R570）、
中身は 4 kB の純関数しかない。⚠ **配信量の +7.5 MB は起動費用ではない**——`data/hist-admin*.js` は
idle で取りに行き、電話と Data Saver では取りに行かず、第2級は z6 を越えるまで取りに行かない
（`tests/r530-checks` ⑫ がその3つを測っている）。増えたのは**そこにある記録の量**であって、
読者が起動時に払うものではない。

### 5. ⚠⚠⚠ #R586 のシャードは、一度も効いていなかった

同じ回に入れた CI の分割も、同じ形で壊れていた。**`--test-shard` は、グロブより後ろに置くと
黙って無視される**（エラーも警告も出ず exit 0）。実測（Node 24.18）:

```
node --test --test-shard=1/3 "tests/r5*-checks.test.mjs"   → 155 tests
node --test "tests/r5*-checks.test.mjs" --test-shard=1/3   → 441 tests   （＝分割なし）
node --test "tests/r5*-checks.test.mjs"                    → 441 tests
```

`npm run … --` は**後ろに足すことしかできない**ので、そこからはフラグを前に出せない。
結果、**3 台のランナーが全部同じ全量を走らせ、名前に入っているシャード番号は飾りだった**
（#R586 の実測: 3 本とも 459〜599 秒）。

⚠ **そして #R586 の検査②は、それが見えないように書かれていた**——
「ステップに `--test-shard=…` と**書いてあるか**」を測っており、「**効いているか**」を測って
いなかった。#R585 の凡例と同じ形が、同じセッションの中でもう一度起きている。

⇒ 直しは 2 つ:

1. **`scripts/test-checks.mjs`** がグロブを持ち、余分な引数を**その前に**置く。
   `package.json` の `test:checks` はそこへ委譲するので、**ファイル集合の正本は 1 つのまま**。
2. 検査②は**走らせて数える**——使い捨ての 6 ファイルを一時ディレクトリに作り、出荷している
   ランナー経由で `1/2` と `2/2` を実行し、**二つの半分が重ならず、合わせて全体になる**ことを測る。
   ⚠ 本物のスイート（3,510 テスト）を 3 回シャードして確かめると 30 分かかり、しかも
   **その事実はどのファイルかに依存しない**。

⚠ 途中で 2 つ踏んだ:
**`stdio:'inherit'` のランナーでも親が pipe なら出力は取れる**（取れないと思い込むと計器を捨てる）。
そして **`NODE_TEST_CONTEXT` を子に渡してはならない**——入れ子の `node --test` がそれを見ると
**v8 直列化の子プロトコル**に切り替わり、プローブは何も読めず「計器が盲目」と報告する。
正常に動いているランナーの上で。
