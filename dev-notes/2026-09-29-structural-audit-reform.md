この記録は**総括**である。各改革の実測・判断・検査はそれぞれの記録にあり、ここには書き写さない。

## 0. 監査した側面と、見つかった最大の形

9 つの側面を読み取り専用の調査役に並列で渡し、結論（file:line と件数）だけを受け取った。

| 側面 | 最大の発見 |
|---|---|
| セキュリティ | 実行時に第三者 CDN から SRI なしで `<script>` を挿入／AI 呼び出しにプロジェクト全体の日次上限が無い（口座を増やせば請求に上限が無い）／コミュニティ投稿の著者名と時刻をクライアントが自由に書ける／公開バケットが匿名で一覧できる |
| 信頼性 | 期限の無い `fetch()` が 161 本。Open-Meteo の共有クライアントが期限なしで同じ URL を束ね、1 本止まると同じ URL の全員がセッション中待つ／空の catch 5,603 |
| アーキテクチャ | window 経由の結合が import の 33 倍／HTML エスケープの独自実装 48 か所（`"` を変換しないもの 5）／大円距離 36・色補間 5・日付整形の重複 |
| 開発プロセス | `npm test` のゲート一覧が手書きで、CI が走らせる 31 個のうち 8 個を持たない／node 回帰の 3 shard が 11 分・8.5 分・4 分と偏る／#R795 で撤去したはずの行数天井が `<=` の綴りで 5 本残る |
| アクセシビリティ | キーボードで届かない操作 37／フォーカストラップを持つダイアログは 1 つだけ／設定モーダルの Esc はコメントにしか無い／「モーダルが開いているか」の一覧が 2 か所で中身が違う |
| 性能 | デスクトップの全セッションが、歴史機能に触れなくても起動直後に約 55 MB の歴史データを先読みして main thread で parse する（註は「5.5 MB」のまま、実物は 12.96 MB） |
| Atlas | `system.control` は confirm=none のまま任意のボタンを押せ、外部内容を読んだターンに公開投稿・フィードバック送信・アカウント操作まで届く／操作一覧がメール欄の placeholder（利用者のメールアドレス）をモデルに渡す／現行でないモデル ID が 5 関数に散在 |
| データ統治 | 同梱 72 データセットのうち定期更新は 1／鮮度 `unknown` 129／出典表と実行時ホストを突き合わせる門が無い |
| 前回分と nightly | 前回 3 本は本番で OK（受領証済み）／nightly は 8 夜連続で赤、最新の赤は本物の退行（下の §2） |

⇒ **最も多かった形は「同じ判断が複数の場所にあり、片方だけが正しい」**（海底ケーブルの取得順が本体とサムネイルで逆、エスケープ 48 本、ゲート一覧 2 本、モーダル判定 2 本、モデル ID 5 本、提供元呼び出しの私的コピー 3 本）。直し方は毎回同じ: **正本を 1 つにし、写しは正本を読む。増えたら落ちる門を付ける。**

## 2. nightly の赤は本物の退行だった——期限が自分の凍結を数えていた

`tests/restored-layer-before-style.spec.js:147` を repeat 5 で再現し、計器を付けた。重い復元でメインスレッドが
3.8〜30 秒止まる間に RainViewer は 0.2〜2.9 秒で答えていたが、`setTimeout(6000)` 1 本の期限はスレッドが戻った
瞬間に応答より先に発火し、レーダーの行を外していた。**観測器が成功を失敗と報告する形**
（`.agents/rules/one-pass-or-a-reason.md` §2 ①）で、今回の取得層も同じ時計に載るので時計そのものを直した
（詳細と検査は fetch-deadline-layer の記録 §1b）。retry 側の赤は CI 2 コアでの CPU 飢餓（環境要因）。

## 3. 毎セッションの読み込み量

`AGENTS.md` §1 は `Architecture.md`・`PRODUCT.md`・`DECISIONS.md` を読めと書くが、3 本で約 880 KB、
`Architecture.md` だけで約 20 万トークンあり、文字どおりには守れない（守れない規則は守られない）。
「主題の節を見出しで引いて読み、読んだ節を最終報告に書く」に改めた。`check:agents` の天井内。

## 4. 否定された見立て

- 「3 つの builder（deepsky・smallbodies・spacecraft）が `res.ok` を見ずに 404/503 のページを書く」——読むと
  3 本とも本文を JSON として解析し形を確かめてから使い、失敗は再試行ののち `null`。書かない。直すものは無かった。
- 「pmtiles を npm 依存にして同梱する」——呼び出し元が 1 つも無い死んだ読み込み器だった（R13 で撤去済み）。
- 「天気 SDK を同梱する」——GPL-2.0 で、R314 が同梱しないと決めている。判断を保ち、SRI で固定した。
- 「CI の赤（#799 の Regression 3/3）は shard の並び替えによる環境要因」——本物だった（計時ファイルを
  リポジトリ直下に置いたこと、gate-callers 規則の弱体化）。

## 5. 承認が要るので実施していないもの（最終報告で提案）

削除・縮小・挙動の変更を伴うもの。一覧と理由は最終報告にある。主なもの: 起動直後の約 55 MB の先読みを
時代 UI の最初の利用に結びつける／呼ばれない `loadPMTiles`・`index.gemini-backup.ts`・読み手 0 の window 名 67・
役目を終えた script 2 本の撤去／`user-scalable=no` の解除／投稿画像の DB 側の CHECK／外部内容の印をターンを
またいで運ぶ（確認が増える）／ラウンド単位の検査 633 本を主題単位へ統合し、綴りを読む検査を挙動の検査へ。
