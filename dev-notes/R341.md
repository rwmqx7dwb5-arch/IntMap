## R341 — **航空レイヤーは「遅い」のではなく死んでいた**

依頼は「航空レイヤーを全面再設計し、全球・数万機・即時描画の航空プラットフォームへ置き換えよ」。
調べ始めて最初に分かったのは、**それが速度の問題ではない**ということだった。

### 1. 本番の実測（改修前）

```
GET https://api.airplanes.live/v2/point/50.040/8.570/250
→ HTTP 403   Cloudflare   Access-Control-Allow-Origin: なし
```

CORS ヘッダが無いので、ブラウザ側では `fetch` が reject する。つまり
`js/data-layers.js` の `if(!r.ok)` は**一度も評価されていない**——全部 `catch` に落ちていた。

| シナリオ | 観測 | airplanes.live へのリクエスト | 描画された機体 | コンソールエラー |
|---|---|---|---|---|
| 既定カメラ (z1.7) | 60 s | 1 | 0 | 8 |
| z8 | 90 s | 11 | 0（合成のみ） | 30 |
| z4 | 200 s | 72 | 0（合成のみ） | **153** |

掃引が全滅すると `genSyntheticPlanes()` が **270 機**を作る。それが実データでないことは数えられる:

| 検査 | 結果 |
|---|---|
| ICAO24 が 16 進数として妥当（`^[0-9a-f]{6}$`） | **0 / 38**（`6TEB8M` `V8KCZO` `1P76KQ`——F より後の英字を含む） |
| 登録記号が非空 | 0 / 38 |
| 機種が非空 | 0 / 38 |
| スコークが非空 | 0 / 38 |
| 昇降率がちょうど 0 | **38 / 38** |

⚠ **そして詳細カードには、合成である旨が1語も無かった。** 出典行は `airplanes.live · ADS-B`、
受信欄は「Last seen 11 s ago」。合成であると告げるのは**ホバーのツールチップだけ**だった。

**根本原因は上限でもアイコンの重さでもない。** 利用者ごとのブラウザが局所検索 API を
最大 128 回叩いて全球を再構成する構造——**上流負荷が利用者数に比例する構造**——そのものだった。

### 3. 測って初めて分かった3つ

**(a) adsb.lol のバースト予算は約4リクエストで、間隔を空けても増えない**

| 間隔 | 成功 | 429 |
|---|---|---|
| 2000 ms | 4/10 | 6 |
| 1500 ms | 4/10 | 6 |
| 1000 ms | 4/10 | 6 |

成功数が間隔で動かない＝**毎秒あたりの上限ではなく、ゆっくり回復する持ち分**。
980 タイルの全球格子はこの provider では到達できない。だから world チャンネルは
**viewport が既に支払ったタイルの合併**として育ち、`coveragePct` がそう言う。
「そこに機体がいない」と「まだ訊いていない」を同じ絵にしないための数字。

**(b) Edge Function の isolate メモリはキャッシュではない**

同じ viewport を3回、TTL 15 秒:

```
call 1  200  7,140 B  5.64 s   x-intmap-age-ms: 2
call 2  200  7,140 B  5.76 s   x-intmap-age-ms: 1
call 3  200  7,089 B  6.39 s   x-intmap-age-ms: 1
```

**毎回 age が 1 ms** ＝毎回作り直している。上流リクエストは利用者数に比例したままで、
**構造をブラウザからサーバーへ移しただけ**になっていた。⇒ スナップショットを Storage へ。

**(c) `EdgeRuntime.waitUntil` の Promise は応答をまたいで生き残らなかった**

world を6回続けて叩いても **27 機・0/980 タイルのまま**、書き込みも 0。
⚠ **背景仕事に依存する設計は、単発の試験では全部正しく見えて、本番では一度も前に進まない。**

### 4. `upstream_unreachable` は、このファイルの文字列リテラルだった

`?ch=view` と `?ch=world` が 502 `{"error":"upstream_unreachable"}` を返し続けた。
`?meta=1` だけが動いていたので、しばらく上流の到達性を疑った。実際は:

```js
ATTRIBUTION.adsblol = "adsb.lol — ODbL 1.0"
                              ↑ U+2014 (8212)
```

HTTP ヘッダ値は **ByteString**——255 を超える文字は入らない。Deno は `Response` の構築で
`TypeError` を投げ、外側の catch が `relayFail()` に渡し、呼び出し側は
**ネットワーク障害だと告げられた**。`?meta=1` が生き残ったのは**そのヘッダを立てないから**で、
それがそのまま「fetch の問題だ」という誤診の材料になっていた。

⇒ **1つの文字列を直すのではなく、ヘッダ値を全部 ASCII に正規化した**（`hdr()`）。
次にダッシュやアクセントや CJK を含む出典行が来ても、エンドポイントは落ちない。

### 5. 描画

- **1機＝1頂点、1 draw call。** 1フレームあたりバッファ束縛7回・uniform 6個・`drawArrays` 1回。
- **進行方向はフラグメントシェーダが `gl_PointCoord` を回して**出す。テクスチャアトラスは無い。
- **publish の間、CPU は機体を1つも触らない。** 位置は頂点シェーダが速度から外挿する。
- **バッファは転送される（コピーされない）。**
- ⚠ **外挿は3秒で頭打ち**（衛星の4秒ではない）。航空機は旋回し、水平飛行に移り、着陸する。
  頭打ちを過ぎたら glyph は**その場で止まる**——**行っていない場所へ滑らかに線を引くのは、
  止まっている機影より悪い答え**だから。
- ⚠ **ズームが決めるのは大きさと細かさだけになった。** 旧実装は z2 未満で `planesData=[]` にし、
  本番では z1 で「Zoom in to load live aircraft」が**270 機が描かれている最中に**出ていた。

### 6. Cesium: `alignedAxis` は使えなかった

Cesium 1.143 の `BillboardCollectionVS` は

```
angle += sign(-x) * acos(sign(y) * (y*y) / (x*x + y*y))
```

＝ **`acos(cos²θ)`** を計算している（正しくは `acos(cosθ)`）。東西南北の4方向でだけ正確で、
間は最大 **15.79°** ずれる（10°→14.11 / 30°→41.41 / **45°→60.00** / 60°→75.52）。
16 度ずれる機首方位は交通表示として嘘なので、**画面角を CPU で厳密に出して `rotation` に渡し、
`alignedAxis` は ZERO のまま**にした。

### 7. 「無い」と「ゼロ」

IMAV/1 は `AC_ALT_VALID` を別のビットに持つ。落ちていれば高度は `NaN` にデコードされ、
**0 ft にはならない**。旧実装はこれを混同していて、高度を報告しない機体を海面高度として
3D の地面に置いていた。フィルタも同じ規則で、**高度不明の機体は高度フィルタを通らない**
（NaN を 0 と読むと「1万 ft 以下」に全部入ってしまう）。

### 8. 出典

`airplanes.live · ADS-B` はリテラルで書かれていて、**合成データの下にもそれが出ていた**。
既定 provider の adsb.lol は **ODbL 1.0＝出典表記が義務**。⇒ 名前は
`x-intmap-attribution` ヘッダで運び、`_planeSourceLine()` が表示する。

⚠ 途中で `IntMapSafe.escape()` と書いた。**この関数は存在しない**（正しくは `.html()`）ので、
catch に落ちて**出典が黙って消える**形だった。ODbL 違反が「例外を握りつぶす1行」の姿で現れる。

### 9. やらなかったこと・残っている制約

- **全球の高頻度な被覆は、無料の provider では成立しない。** OpenSky は `/states/all` 1回で
  **6,838 機 / 900 kB / 2.7 s**（実測）だが、利用規約が**運用利用に事前の書面合意**を求めている。
  アダプタは完成しており、`OPENSKY_AGREEMENT=1` で主経路へ昇格する。
- **便情報（定刻・実績・遅延・欠航・飛行計画）は無料経路に無い。** だから**作っていない**——
  `PROVIDER_FIELDS` は全 provider について `route:false` / `schedule:false` を宣言し、
  `tests/r341-checks ⑧` がそれを検査する。
- **旧経路は1文字も変えずに残した**（`?aviation=v1`）。§28 Phase G の巻き戻し期間のため。
  `js/data-layers.js` の約 1,320 行が航空のまま残っており、それが shell の天井を
  7,950 → 8,000 に上げた分の**次のラウンドが払える借り**。

| 経路 | 応答 |
