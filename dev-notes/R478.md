### ⚠⚠⚠ 門を「棚のキーの集合」から導出した初版は、落ちた当の行を捕まえられなかった

最初に書いた門は、禁止する集合を `GROUPS` のキー（18個）から導出していた。ここに 18 個を書き
並べればそれこそが「二度目の写し」になるので、導出そのものは正しい。**正しくなかったのは、
それが落ちた行を含まないことだった。**

出荷版（`origin/main` 08676e1）の `tests/r439.spec.js` を走査した実測:


`lyrGrpOthers` は `GROUPS` に**無い**。「その他 (beta)」は棚ではなく、`reorganizeLayerPanel` の
safety sweep がどの棚にも引き取られなかった行のために作る**見出し**である（#R271 の 🕒 タイムゾーンが
実際にそこへ落ちた経路）。だから集合に入らず、**赤くなった 149 行目だけが門を抜けた。**

### ⚠⚠ 綴らずに済む口を先に用意する——`BETA_KEY`

綴りを禁じるだけでは、`|| 'lyrGrpOthers'` と書きたい正当な検査の行き場が無くなる。そこで
`tests/helpers/layer-groups.mjs`（#R469 が「リテラルを**値として**評価する」ために作った モジュール）に
**`BETA_KEY`** を足した——`reorganizeLayerPanel` の sweep が `setAttribute('data-i18n', …)` で
実際に書いている見出しを、**分類と同じファイルから**読む。

```js
expect(under['dl-' + id], …).toBe(where(id) || BETA_KEY);
```

⚠ **`|| BETA_KEY` は分類の写しではない。** 「どの棚にも無い行はベータへ掃き出される」という
sweep についての1つの事実であり、`tests/r478-checks` ③ が
「`BETA_KEY` は `GROUPS` のキーではない」ことを毎 push 確かめている。

### ⚠ この spec が主張すべきは「どの棚か」ではない

棚を決めるのは分類（`GROUPS`）で、それを動かせるのは読者の指示だけである（#R273）。
spec が主張すべきなのは、**描かれたパネルが宣言どおりに行を並べているか**——`order.push` は要素を
**移動**させるので、2つのリストに載った id は最後の1つでしか描かれず、どのリストにも載らない行は
ベータへ落ちる。それは DOM にしか訊けない問いで、まさにこの spec の持ち場である。

宣言の側（「4行は気候・気象の棚にいる」）は `tests/r439-checks` ⑨ が id を名指しで、毎 push 見ている。
そして **#R439 自身の主張＝名指しの4行が「ベータを出た」こと**は、棚の名前を綴らずに残した:

```js
expect(under['dl-' + id], …).not.toBe(BETA_KEY);
```

`ec-wind`（今も誰も名指ししていない行）も同じ導出でパネル側から見るようにしたので、#R273 の規則は
**両側に証人がいる**——名指しされた行と、されなかった行。
