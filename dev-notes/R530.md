## R530 — **地方区分の境界は、時計を一行も読んでいなかった**

> 「国境線だけでなく地方区分の境界もChronosに完全対応させるように。完全対応。」

### 何が起きていたか（実測）

`ref-admin1`（js/app-body.js・OpenFreeMap のベクタタイル `boundary` 層・admin_level 3〜4・**既定 ON**）は
**Chronos を 1 行も読んでいなかった**。`window._applyBorders` はこの id を知らないので、時計を 1900 年へ
送ると——

- 国境は `borders-only-line` が隠れ、CShapes の 1900 年（`imtb-line`）が描かれ、
- 国名は `ofm-country` が隠れ、当時の国名（`imtb-lbl`）が描かれ、
- 州名は `ofm-admin1` が隠れ（#R198/#R103 が正しくそうしていた）、
- **州境だけが、2026 年のまま、紫の破線で残った。**

⚠ **ラベル側が正しかったことが、この欠陥を「意図的な表示」に見せていた。** 名前が消えて境界だけが残る画面は
壊れて見えない。そして `git grep ref-admin1 tests/` は **0 件**——この層には node 検査もブラウザ spec も
一本も無く、可視性は正しく `'visible'` だったので、**綴りや旗を読む検査を書いても緑になっていた**。

### 直しかた — 国境の規則を、そのまま区分に適用する

新しい `js/time-admin1.js` は `js/time-borders.js` の双子で、同じ時計・同じ 45 ms のデバウンス・
**#R421 と同型の日単位エポック索引**（record の開始日と、終了日の翌日）を持つ。

| 時計 | `ref-admin1`（現代・ベクタタイル） | `imta-line`（当時） | `imta-lbl`（当時の名前） |
|---|---|---|---|
| Now | `cb-admin1` に従う | 出さない | 出さない |
| 過去 | **隠す** | `cb-admin1` に従う | `cb-names` に従う |

- ⚠ **1 つの機能に 1 つのスイッチ、しかも両方向。** #R94g の原則そのままで、#R94l の例外（旅行中は
  toggle に関わらず歴史国境を出す）は**採らない**。国境側にその例外があるのは「旅行が地図を国境の無い
  状態にしてはいけない」からで、区分を切っても国境線と海岸線は残るから、ここでは読者の意思を尊重するほうが正しい。
- ⚠ **名前は `cb-names`、線は `cb-admin1`。** 現代側の `ofm-admin1`（地名表示）と `ref-admin1`（州・県境）が
  既にそう分かれている（#R198：県名は地名である）。旅行がスイッチを切り直してはならない。
- ⚠ **`js/place-labels.js` の「旅行中は隠す」判定を 2 つに割った。** 国名は `IntMapTimeBorders.active()`、
  区分名は `IntMapTimeAdmin1.active()`。国境側は CShapes の最終年（2019）を超えると現代の国境へ戻るが、
  **区分の記録は今日まで続く**ので、1 つの旗のままだと 2020〜2025 年で現代の県名と当時の区分名が
  同じ点に二重に出る。
- ⚠ **レイヤー監査の表は両方の id を持つ**（`'cb-admin1':['ref-admin1','imta-line']`）。`painted()` は
  「どれか 1 つでも見えているか」を訊くので、現代側だけを列挙すると**正しく旅行中の地図を『checked なのに
  空』と誤診して、数秒ごとにチェックボックスを off→on する**。

### ⚠⚠⚠ 束の到着を待って隠していたら、コールド初回だけ間欠で落ちた

最初の実装は `active` を `go()` の先頭で true にし、実際に隠すのは 6.55 MB の
`data/hist-admin1.js` が届いて `apply()` が走ってからだった。**実測 3 回中 1 回、しかも必ずコールドな
1 回目だけ**、1900 年の上に現代の州境が 4 本残ったまま `tests/r530.spec.js` ① が落ちた。窓は
`load()` そのもので、ウォームなページでは数ミリ秒なので見えない。

直しかたは待ち時間の延長ではなく**規則**である——**時計が過去に入った瞬間、今日の州境は間違いだと
分かっている。それは代わりを描く用意ができているかどうかとは無関係。** 一瞬なにも描かないのは正しく、
間違ったものを描くのは正しくない。だから旅行の開始は Chronos の購読者の中で**同期的に**宣言する。

双子のモジュールが 1 組の作法で読めるようにしてある。

⚠ **簡略化は当て推量ではなく、国境側の束に対する値付けとして測った**：

| 許容 / 座標桁 | raw | brotli |
|---|---|---|
| 0.008° / 4 桁 | 15.46 MB | 1.54 MB |
| 0.015° / 3 桁 | 8.33 MB | — |
| **0.020° / 3 桁（出荷）** | **6.55 MB** | **0.67 MB** |

`data/cshapes.js` が 5.33 MB / 0.38 MB。#R192 が測ったとおりこの大きさの束は主に**メインスレッドの
パース**で払うので、決め手にしたのは raw 側。0.02° は、より粗い段が落とす 13 件を全部残す最小の段。

### ⚠⚠ 被覆は部分的で、埋めない

在force 件数の実測：**1850=543 / 1870=638 / 1900=642 / 1914=689 / 1938=676 / 1950=690 / 1990=726 / 2020=747**。
現代の第 1 級行政区分は約 4,596 件なので、**過去の日付では多くの国に区分線が引かれない**。

埋める手は 2 つあり、どちらも `CONSTITUTION.md` の「偽物・ハリボテ禁止」で禁じられている——
**現代の区分を過去の日付に描く**（これが今回直した欠陥そのもの）ことと、**現代の区分をその時代の国境で
切り抜く**（誰も測っていない境界に、線の権威を与える）こと。

代わりに**言う**。`IntMapTimeAdmin1.coverage()` がその日付の在force 件数を返し、`note()` が 9 言語の
一文を返して「州・県境」のレイヤー行の `title` に出る——**線が無い国は「区分が無かった」のではなく
「記録がまだ無い」**。Now に戻ると消えるので、古い日付についての一文が残ることはない。
⚠ 位置引数の順は **en, jp, de, ru, es, zh-Hant, zh-Hans, fr, ko**（`IntMapLang.index()` の実測）。
最初は自然な en/ja/de/ru/es/fr/ko/zh/zh 順で書いていて、**繁体字の読者にフランス語を渡していた**（#R502 の形）。
かつ `pickArgs()` は選ばない——渡された配列をそのまま返す計測用の器なので、`pick(getLang).arr(...)` で
解決しないと**9 言語が一度に画面へ出る**（実測した）。

### 起動費用（#R311 のゲートが求める「理由」）

eager が **+21.3 kB raw / +7.5 kB gzip / +5.8 kB brotli / +1 module** 増えた（実測。`tests/perf-baseline.json`
の 6 項目だけを手で書き戻した——⚠ `--update` は全項目を書き戻すので使わない）。⚠ **`modules` は完全一致を
求める項目**なので、eager のモジュールが 1 本増えた時点で旧天井では必ず赤になる。増えたのは
`js/time-admin1.js` を `src/main.js` が静的に import しているためで、**遅延にはできない**——遅延にすると「過去の日付では今日の州境は間違い」という
規則がモジュールの到着まで効かず、上で直した窓が桁違いに広がって戻ってくる。**6.55 MB のデータ自体は
バンドルに入っていない**（idle で `<script>` 挿入、携帯と Data Saver / 2G では先読みすらしない。
`data/cshapes.js` の #R192/#R201 と同じ規則）。`dist.data` の +6.76 MB はその同梱データ 1 本ぶん。
`tests/perf-baseline.json` は**名指しされた 6 項目だけ**手で書き戻した（`--update` は全項目を書き戻すので使わない）。

### 検査

- `tests/r530-checks.test.mjs`（15 本）— 束を **vm で実際に評価**して形と日付の粒度を見る／エポックが
  年に丸まっていないこと／切替盤の 2 つのゲート式／`_wireRef` が決定を切替盤へ返すこと／2 つの時計を

- `tests/r530.spec.js`（1 本）— **描かれているかを訊く**（`queryRenderedFeatures`）。可視性フラグを読む
  検査は、欠陥のあるビルドでも `'visible'` が正しかったので緑になる。現在→1900→スイッチ両方向→Now を
  **1 回の時間旅行**から読む（4 本に割ると束の解決を 4 回待って 59.8 s だった）。
### ⚠⚠⚠ 同じ出典が、同じリポジトリの中で2つの違うライセンスを名乗っていた

このラウンドの直前に merge された #R518 が、1850–1885 の**国境**のために同じ
**OpenHistoricalMap** を同梱しており、それを **ODbL 1.0** と表記していた。こちらは
**CC0 1.0** と書いた。出典ページに同じ組織が矛盾する2行で並ぶことになるので、放置できなかった。

**実測して確かめた（2026-09-07）**——`openhistoricalmap.org/copyright` の meta description は
「created by people like you and **dedicated to the public domain**」、Overpass API の応答本文は
「The data is made available under **CC0**」。⇒ **CC0 が正しく、ODbL は誤り。**

⚠ **1行に統合した。** `js/reference-data.js` の 2 行を `OpenHistoricalMap (CC0 1.0)` の 1 行にし、
9 言語の説明文も**訳し直さずに**（既にその言語で書かれていた2つの文を連結して）1 項目にまとめた。
`data/hist-borders.js` の `src`、`scripts/build-hist-borders.mjs`、地図の attribution
（`js/time-borders.js`）、`Architecture.md` / `docs/FILES.md` / `docs/MAP-LAYERS.md` も直した。
⚠ 各言語の末尾にあった `© OpenHistoricalMap contributors, ODbL 1.0.` は**削除**した——CC0 は
パブリックドメイン献呈なので `©` の主張自体が成り立たず、統合後の本文に既にその言語のライセンス文がある。

⚠ **そして、それを守っていたはずの検査は何も守っていなかった。** `tests/r518-checks` ⑤ の
licence line は `/ODbL 1\.0\./.test(s)` を**ファイル全体**に対して掛けており、どの `pages.*.js` も
OpenStreetMap と mledoze の行で ODbL を含むので、**OHM について一度も何も言っていなかった**
（OHM の行にライセンス表記が1文字も無くても緑だった）。**項目そのものを取り出して訊く**形に直した。

### ⚠⚠ 切替盤は app-shell に置けなかった（余白は1行だった）

最初は `window._applyAdmin1` を `js/app-body.js` に書いた。それで **app-shell 6本
（`index.html` / `src/main.js` / `src/vendor.js` / `js/app-body.js` / `js/geo-engine.js` /
`js/lazy-modules.js`）の合計が 8,049 → 8,099 行**になり、天井 8,050 を 50 行超えた
（`tests/r168-checks` #8。⚠ **同じ数の写しを `r350` ⑨c と `r479` ⑧ も持っている**ので、
上げるなら3か所とも上げることになる。#R465 が記録したとおり、この tripwire は
「自分の変更を通すために天井を上げる」ことを捕まえるためにある）。

**天井は上げず、切替盤を `js/time-admin1.js` へ移した。** 筋としてもそちらが正しい——
区分を描くモジュールが「どちらの組を画面に出すか」の規則を持つ。shell に残ったのは
**双子を作る1行に相乗りした生成**と、`_wireRef` の中の**1行の呼び戻し**だけで、
結果は **8,049 行＝HEAD と同じ**。⚠ `src/main.js` の import も既存の行に相乗りさせた。

⚠ **書き戻しで改行コードを壊しかけた。** `js/app-body.js` は HEAD が LF、このラウンドで
足した行が LF、しかし行単位で読み書きするスクリプトが全体を CRLF で書き戻し、`git diff` が
399 行の全面変更になった。`.gitattributes` は `*.mjs` などを `eol=lf` に固定しており、
`src/main.js` には**行の途中に裸の CR が1つ**ある（#R408 が「ON THIS LINE for the shell budget」と
書いた行）。`split(/
?
/)` はそれを分割しないが、書き戻しの改行統一が壊す。
**バイトを戻して LF に統一したうえで、差分が実際に触った行だけであることを確認した。**

### テスト予算 — 天井を実測ぶんだけ動かした（`scripts/test-budget.mjs` の作法どおり台帳にも書く）

**core 28 → 35、total 4,639 → 4,648（+9）。** この欠陥はレンダラの中でしか見えない——`ref-admin1` の
`visibility` は間違っている間ずっと正しく `'visible'` だったので、**Node の検査で区別できるものが 1 つも無い**。

⚠ **まず spec で払った。** 最初は 4 テスト（現在／1900／スイッチ／復帰）で、どれも時計を動かすので
**6.5 MB の束の解決を 4 回待って 59.8 s** だった。4 つの主張は同じ 1 回の時間旅行から読めるので 1 本に畳み、
固定 `settle()` を全部「その主張が立つ条件」の待ちに置き換えた（#R399）。静穏なマシンで 4 回連続
**6.6 / 7.0 / 8.1 / 7.5 s** ＝上限 8.05 s、切り上げて entry **9**。
⚠ **ばらつきを書き残す**: 同じ spec を負荷のかかった時間帯に測ると **11.3〜19.0 s**（wall 43〜59 s）だった。
entry は #R455 の作法どおり「静穏時の連続バッチの上限」を採っており、マシンの都合である外れ値は採らない。
⚠ **他所から節約は取っていない**（#R322/#R455）——同じバッチで常設 5 本も測り直したが、
`tests/smoke.spec.js` は entry 8 に対して実測 77 s で、**この表は過小申告側**である。過小申告する表から
節約を取るのは算数であって節約ではない。
⚠ **core は 6 本ではなく 7 本だった。** #R494 が `BUDGET_S = 28` を導いた式に `tests/r510.spec.js` が
入っていない——entry がちょうど 1 なので `!(d[n] > CORE_MAX_S)` を通る。常設の床は 25 ではなく **26**。

- `tests/r198-checks.test.mjs` ②b は綴り `id==='ofm-country'||id==='ofm-admin1'` を固定していた。
  規則は生きていて綴りだけが変わった形（#R488）なので、**不変条件を訊く形に書き換えた**——決定が
  `ofm-admin1` を名指していること、両者が旅行の旗で切れること、そしてその旗が**それぞれ別の時計**であること。
