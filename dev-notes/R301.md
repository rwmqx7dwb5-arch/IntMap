依頼は「`tests/r210` と `tests/r211` が `test:checks` の一覧に無い。走らせて、落ちているものを仕分けて、
同じ穴が二度と開かないようにしろ」。

**赤**で、しかも誰も見ていない。r260 ⑥ が守れるのは**その穴を意識していた作者のラウンドだけ**で、
r210 も r211 もそのあとに書かれている。

### ② 5 件のうち 4 件は「後の指示が削った綴り」を固定していた

r211 のファイル冒頭に、r211 自身がこう書いている——

**全部、関係へ書き直した。** 数や綴りを書いていたものは、盤上から**導出する**形にした——

* fetch の門は 4 本の throw の文言ではなく、**`fetch(` の呼び出し全部を掃いて** status を見ているか訊く

* 「消えたはずのもの」は**名指しで不在**を要求する（歩きが復活したら落ちる）

### ③ 残る 1 件は本物の欠陥で、**サーバ障害を地面についての測定結果として印字していた**

`js/world-packs.js` の作物レイヤーのセル取得だけが、**このファイルで唯一 `r.ok` を見ていない fetch**
だった。

```js
const r=await fetch(GAEZ+'/identify?…');
const j=await r.json();
const v=j&&j.value;
if(v==null||v==='NoData'){ stat(… 'no cultivation recorded in this cell' …); return; }
```

GAEZ が落ちると `j.value` は `null` になり、次の行が**「このセルには栽培の記録がありません」**と言う。
⚠ 「黙る」のではなく、**嘘の測定値を出す**。#R183 が名付けた「無検査の応答は静かな `—`」の、もう一段
悪い形である。ArcGIS は障害を **HTTP status** でも **200 + エラー本文**でも返すので、両方訊く。
throw は既存の `catch` に落ち、**何も言わない**（間違ったことを言うよりよい）。

この欠陥が見えなかった理由はひとつ——**#R183 のルールをこのファイルについて表明している検査が、
一度も走っていなかったから。**

### ④ 同じ穴が二度と開かないようにする

`scripts/check-test-list.mjs` が `test:checks` の一覧と `tests/` の中身を**両方向**で照合する。

* 盤上の `*.test.mjs` で一覧に無いもの → 落ちる（**今回の形**）
* 一覧にあって盤上に無いもの → 落ちる（改名・削除で**ノード段が丸ごと死ぬ**形）
* fixture・コーパス・共有ヘルパ（`*.test.mjs` でない `.mjs`）は**要求しない**

⚠ **この番人は `test:checks` の中にいない。** 一覧の番人が一覧の項目だったら、一覧から外した瞬間に
番人も消える——それが防ごうとしている失敗そのものである。`scripts/static-checks.mjs`（＝
`npm run check:static`、`npm test` と `test:seq` の両方が通る別の門）から走る。

⚠ そして**検査は実行して確かめる**。`check-test-list.mjs` は入力に対して純粋なので、`tests/r301 ③` が
**わざと壊したリポジトリ**を渡して両方向の失敗を実際に出させる。#R298 の「呼び出しが書かれているか」を
訊いて緑だった検査の教訓——**書いてあることは、走ることではない**。

### ⑤ 自分の検査が自分のコメントに当たるのを、書く前に避けた

`tests/r301 ⑤` の素直な書き方は「r211 はもう `collectPond(` を含まない」だが、**書き直した r211 は
その綴りを 6 つとも名指ししている**——固定をやめた理由の説明と、「復活していないこと」の表明の中で。
この形（自分の検査が自分の散文に当たる）はこのプロジェクトで **20 回以上**起きている。
⑤ は否定形をやめ、**置き換えた側の形**だけを肯定形で訊く（盤上を読む構文はリテラルでは満たせない）。

* `js/world-packs.js` の**ファイル先頭コメント**は「警報レイヤーは 2 か国を対象とする」と書いているが、
  実際の `FEEDS` は **12 の国営フィード**＋MeteoAlarm＋WMO SWIC である。**今回は触っていない**——

* `tests/r210` は 6/6 通ったので**変更していない**。一覧に足しただけ。
* ⚠⚠ **`npm test` はこのマシンで既に赤い。このラウンドのせいではない**とことを測って確かめた。
  `scripts/test-parallel.mjs` はノード半分とブラウザ半分を**同時に**走らせるので、
  ノード側の 1,700 件超が CPU を埋めている間に `webServer`（`npm run build && serve`）が
  `playwright.config.js` の **180 秒**を超える——`Error: Timed out waiting 180000ms from config.webServer`。

  | 測ったもの | ノード半分 | ブラウザ半分 |
  |---|---|---|
  | 清潔な `origin/main`（796ec5aを別 worktree へ）の `npm test` | **1,727 pass / 0 fail** | **FAIL** — 同じ webServer タイムアウト |
  | この branch の `npm test` | **1,752 pass / 0 fail** | FAIL — 同じ |
  | この branch でブラウザ半分を**単独**で（`node scripts/run-tests.mjs`） | — | **76 passed / exit 0** |

  差分の **+25** は r210（6）＋r211（12）＋r301（7）と**一致**する。
  ⚠ **CI はこの形では走らない**——`.github/workflows/ci.yml` は `check:static` と `test:checks` を
  1 つの job で、ブラウザは別の matrix job で shard して実行するので、**同時実行自体が存在しない**。
  つまりこれはこのマシンのローカルの問題であって、門の問題ではない。
  **直していない**：`webServer.timeout` を上げるのも半分を逐次にするのも、依頼の範囲外の
  テスト基盤の変更だから（`CLAUDE.md` §3.2）。**測定だけをここに残す。**
