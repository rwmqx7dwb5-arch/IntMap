〈依頼〉gis-result-handoff の本番検証（3 回目・main 2491b55・atlas-jobs v35）。

**測った。**
- **アフリカのジョブ。** Atlas が組んだのは、能力タスク 4 段（filter → convexHull → aggregate count / aggregate sum）。前段は `data.gis` の `"inputs":["africa"]` にだけ書き、どの契約の `inputs` も空だった。そのため依存が無く、4 段が同じ秒に始まり、後の 3 段は前段の出力を引けずに断られた。1 段目の出力は正しかった（51 件、POP_EST 合計 1,306,370,215.3 は正解と一致、出典あり、`output` あり）。
- **日本のジョブ。** worker 1 件が `data.gis` を道具として呼び、正しく 3 件・48,775,000 を `findings` に返した。ところが `jobFacts` は `findings` を件数に変えていたので、Atlas は「保存結果に数値が無い」と言ってページで集計し直した。監査が指摘した「要約・件数・出典に変換し、構造化した中身を持ち帰らない」の残り。

**直したこと。**
- **データを受け取る引数を能力が宣言する。** サーバの twin が `datasetArgs`（`data.gis` は `["inputs"]`）を持ち、lane が `datasetSlots(id)` で渡す。`planJob` は、宣言された引数に書かれた同じ一覧の仕事の id を依存にする（`deps` と契約の `inputs` に足す）。
  - ページでデータセット id を書くのと同じ扱い。
  - 宣言されていない引数は読まないので、絞り込みの値が偶然仕事の id と同じでも参照にならない。
  - 関数の `create` と `revise` の両方で渡す。
- **findings の中身を持ち帰る。** `jobFacts` は findings を中身（主張・出典・抜粋）のまま持ち、`jobText` が 1 件ずつ述べる。要約も 600 字で切らない（保存されている 1,500 字まで）。

**検査。** `tests/gis-result-handoff-checks.test.mjs` に、本番で組まれたそのままの 4 段を足した。本物の GIS で、依存の順に走り、件数と合計が正しく、出典が最後まで残る。絞り込みの値が仕事の id と同じでも依存にならないことも確かめる。findings が `jobText` に出るテストも足した。

**範囲外（別件として残す）。**
- 地図に戻すとき、Atlas が元データの座標を使わず地名から位置を探して置き、京都が約 60 km ずれた。
- 確認カードを押す前に書かれた答えが「まだ開始されていません」のまま残る。
- worker の道具の答えが 6,000 字で切れ、続きを読む手段が無い。
