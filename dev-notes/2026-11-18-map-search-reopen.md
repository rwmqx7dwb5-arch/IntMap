〈依頼〉#1195 の本番検証（build 1be2049、1152×720 と 960×640・両パネル開）で再現した 3 件。① Escape で畳んだ後（文字を残した状態）、検索ボタンのクリックでも Enter でも欄が開かない（`.ms-shut` が残り欄 45px のまま、Shift+Tab でだけ開く）。② その状態で候補 12 件が幅 44px の一覧に出て横にあふれる（scrollWidth 83 > clientWidth 33）。③ その一覧を Escape で閉じると左パネルも閉じる（sidebar x 0 → −400）。

## 0. 原因

- ①② 検索ボタンの押下は「欄が空なら欄を開く、文字があれば検索する」だった。畳んだ欄に文字が残っていると検索に回り、欄にフォーカスが入らないので `.ms-shut` が外れず、検索の結果が畳んだ欄の幅の一覧に出た。#1195 は「文字を残して畳む」を足したが、そこから戻る道を確かめていなかった。
- ③ Escape の処理が入力欄にしか付いておらず、フォーカスがボタンにあるときの Escape（候補を閉じる）は検索の中で答えられないまま文書へ上がり、「Esc で左サイドバーを開閉」が受け取った。

## 1. 直したこと（`js/app-body.js` wireMapSearch・`css/intmap.css`）

- **畳んでいるかは描かれた欄に訊く**（入力部の幅が 0）。畳んだ欄へのボタン押下（クリックも Enter も同じ click）は、文字の有無にかかわらず欄を開く（フォーカスが `.ms-shut` を外す）。検索は開いた欄の Enter・ボタンで行う。
- **畳んだ欄は候補一覧を出さない**（狭い形の畳んだ状態に `display:none !important`）。遅れて答える検索（ネットワークの地名検索）が畳んだボタンの下に一覧を開くこともない。一覧は欄が開くと戻る。
- **検索の中の Escape は検索のもの。** 入力欄ではなく検索の枠（`.map-search`）全体に capture で 1 つ付け、どこで押されても聞く: 一覧が開いていれば閉じる → 次の押下で（畳む段なら）欄を畳んでボタンへ。検索の中で押された Escape は、閉じるものが無くても（畳んだボタンの上でも）押下を「答えた」（`preventDefault`）とし、#1195 で足した「答え済みの Escape は左サイドバーを開閉しない」が効く（spec ⑨ が最初の版で検出: 畳んだボタン上の Escape が左パネルを閉じ、枠が広がって欄が開いていた）。capture なので、入力欄の listbox が一覧を閉じる前に状態を読み、1 回の押下が 1 つのことだけをする。

## 2. 検査

`tests/map-chrome-layout.spec.js` ⑨: 1152×720 と 960×640（両パネル開）で、畳んだ状態 → ボタンで開く → 「Tokyo」と打つ（候補が一覧に収まる）→ Escape（一覧だけ閉じる）→ Escape（畳む・文字は残る・キャレットはボタン）→ 700ms 待つ（遅い答えでも一覧は出ない）→ ボタンで開き直す（文字は残る）→ Escape×2 で畳む → Enter で開き直す。各段で欄の幅・一覧・キャレット・文字・**左パネルが開いたまま**かを測る。
