## R406 — **`セーヌ川の長さは・` は質問ではなかった。1文字の句読点が、意味を決めていた**

> 依頼: 「これは『セーヌ川の長さは・』だけを直す不具合修正ではない。……今回の目的は、Atlas の判断を
> さらに別の規則で囲うことではなく、蓄積した意味判断レイヤーを整理・撤去し、Atlas を IntMap 全体の
> 主体的な知能・操作レイヤーへ戻すことである。」

### 0. 報告された1文字と、その下にあったもの

`js/atlas-planner.js:94`、`_requestProfile` の1行がこうだった:

```js
const wantExpl=(/[?？]|どう|どんな|なに|何|なぜ|…/i.test(q))||temporalMode!=='unspecified';
```

疑問符の文字クラスは **`[?？]` の2文字だけ**（U+003F と U+FF1F）。実測——本物の
`makeAtlasPlanner` を node で読み込み、`live:true` で:

```
"セーヌ川の長さは・" -> outputs:{explanation:false, map:false, …}   goalSpec.completionRules = []
"セーヌ川の長さは？" -> outputs:{explanation:true,  map:false, …}   completionRules = [explanation-produced]
```

`・`(U+30FB)・`。`・`｡`・`⁇`・`﹖` はどれも入っていない。**`・` を文字クラスに足すのが、この
ラウンドが明示的に禁じられた修正**である——欠陥は句読点ではなく、**正規表現が文の意味を決めて
いること**だから。

そして「質問か」を訊く検出器は**2つ**あり、`js/atlas-console.js` の `INFO` も同じ `[?？]\s*$` を
持っていた。**同じ字面の弱点を2か所が共有していて、片方が落ちればもう片方も落ちる。**

### 2. 何をしたか

**撤去した**（規則で包み直すのではなく、主題ごと消した）:

- `js/atlas-planner.js` を**削除**（568行）——request profile・意図の門・plan 書き換え・
  repair 指示・goal 判定・カタログ選別・呼ばれない依存グラフ実行。
- `localPlan()` を**削除**（251行・154 正規表現・90 分岐）。利用者の指示は「完全撤去」。
- SYS() の固定散文6段落・カタログ 64,250 文字・レイヤー名 170・コントロール一覧。
- `_atlCompose` の**件数警告**（「実行できなかった操作が N 件あります」）と、
  失敗時に回答を伏せる規則（`say` が**実行前に**書かれていたから必要だった規則で、その前提が消えた）。
- 「answer だけの計画を情報質問なら analyze へ差し替える」ライブ出典オーバーライド。

**入れた**:

- `js/atlas-agent.js` — **ターンのループ**。1手ごとに Atlas が「最終回答」か「tool 呼び出し」を
  選び、**機械的な結果**を受けて次を選ぶ。コードが見るのは**ツールの実在・引数の型・必須引数・
  回数の上限**だけ。**tool 呼び出し0件が正式な完了**で、最終文は**結果を読んだあと**に書かれる。
- `js/atlas-toolsurface.js` — 中核7ツール ＋ `find_capability`（全126を検索して上位8件を
  schema 付きで返す）／`run_capability`（ID指定）。**到達範囲は全126のまま、送る量だけが減る。**
- `js/atlas-schemas.js` — **126能力ぶんの引数 schema**。綴りは dispatch が実際に読む名前から
  機械抽出（宣言した229プロパティすべてが dispatch に読まれていることを照合済み）。
- `supabase/functions/ai-proxy/index.ts` に `atlas_turn`（`JSON_TASKS` に入れたので**全 provider**で
  envelope が効く。`atlas_plan` は**残した**——GitHub Pages のキャッシュを持つ読者が居る間の互換）。

### 3. 実装中に出た欠陥（自分のもの）

⚠⚠⚠ **`type` を引数に混ぜられると別の case へ流れた。** `actionFor` が
`Object.assign({type: cap.legacy}, args)` と**先に** `type` を置いていたため、モデルが `args` に
`type` を入れると、**schema を通ったツールとは別の dispatch case が動く**。`type` を**最後に**
代入して塞ぎ、`tests/r406-turn ⑧b` が両経路（core tool と `run_capability`）で赤を見る。

⚠⚠⚠ **削除した名前を1つ呼び残していた。** `updateWctx` が `_rpExtractYear` を呼んでおり、
**それが `try{…}catch(_){}` の中**だった——例外は飲まれ、`historicalMap` の年が会話に引き継がれなく
なるという**沈黙の機能低下**になるところだった。`scripts/static-checks.mjs` の `split-scope` だけが
捕まえた（自由識別子だったから）。⇒ 決定的な構文解析（4桁の西暦）として `_eraYear` に inline し、
**自分の検査の `GONE` 一覧に `_rpExtractYear`/`_rpGeoKind` を足した**（最初の版はそこが抜けていた）。

⚠⚠ **自分の検査が自分のソースに当たった（20回目）。** 「`atlas-planner` を誰も import していない」
の検査が、**その検査自身の `exists('js/atlas-planner.js')` の行**に一致していた。⇒ 綴りではなく
**実際の読み込み**（`from`/`import(`/`read(`）だけを見る形にし、実 import を足して赤を実測。

⚠⚠⚠ **`npx deno check` が共有 node_modules を作り直した。** Edge Function を型検査しようとして
`npx --yes deno@1.46 check supabase/functions/ai-proxy/index.ts` を実行したところ、Deno が
`package.json` を見つけて**node_modules を Deno のレイアウトで入れ直した**——原本の
`node_modules` は全 worktree が junction している共有物なので、影響は**このマシンの全セッション**:

- `.bin/*.cmd` 18本が `@deno run -A npm:vite@6.4.3/vite %*` に書き換わり、`deno` は未インストール
  ⇒ `npm run build` / `npx playwright` / `npm test` のブラウザ半分が**全滅**。
- lock 外の版へドリフト（cesium 1.143.0→**1.144.0**、@playwright/test 1.61.1→1.62.1）
  ⇒ `check:perf` が「cesium chunk が +76,733 B」で赤。**R406 は Cesium を1行も触っていない。**
- 追跡外・gitignore 外の `deno.lock` が生成され、**`git add -A` なら commit されるところだった**。

⇒ `npm ci` で復旧（cesium 1.143.0・shim 復元・`.deno` ストア消滅を実測）、`deno.lock` を削除、
`check:perf` は復旧後に緑。**教訓は「deno を使うな」ではなく、`package.json` のある木で
別のパッケージマネージャを走らせると node_modules を奪われる**、そしてそれが**共有物**だということ。

### 5. 残っている問題

- **ネイティブ tool calling は使っていない。** ai-proxy は3分岐とも `tools` にホスト型 web 検索しか
  積まず、`function_call` を読む行が**1行も無い**（返ってきても空テキスト→502）。依頼が許した
  「最小 Envelope」（`final_text` / `tool_calls`）を採った。`arguments` は**文字列**で運ぶ——
  OpenAI の strict json_schema は「properties の無い object」を表現できず、素の object にすると
  `strictJsonSchema()` が null を返して**schema 全体が json_object へ落ちる**（`tests/r406-turn ⑭` が
  この規則を再現して守る）。
- `atlas_plan` はサーバの allowlist に残してある（キャッシュされた旧バンドル対策）。次のラウンドで
  外してよい。
- 引数ゼロの21能力は schema に `type` を1個だけ宣言して legacy 名の enum に固定している
  （レジストリ列1の写し）。drift を捕まえる1行の門を足す余地がある。
