〈依頼〉第3報告の公開 Web GIS・非構造化原図の取得、地理座標への変換、検証を一般化する。

## 実装

軽量閲覧とレンダリング済みページが、URL が実際に現れた経路を地理資産候補とともに返す。ファイル取得の
既存の入口に原図の検査・抽出を追加し、取得済みのバイト列を参照で受け渡す。PDF.js とブラウザの
画像デコーダは原図の処理時にだけ読む。投影変換、ポリゴン化、検証、地上面積とレジストリは既存 GIS を使う。
原図の作業時に限って Atlas が GIS の遅延入口とその既存レジストリを読むため、グローバル読み取りが各 1 増える。

## 検証

未収録の入力で URL と実体の区別、非平行な座標変換、検証点の誤差、凡例の曖昧さ、同一取得の再利用を検査する。
ブラウザでは原図のベクター線と画像化した面を回復し、既知の参照面との比較と分析用 ID の受け渡しを検査する。

公開資料での再現では [ロシア科学アカデミーの原ページ](https://da.ruslang.ru/map/m103) が HTML の
ファイル一覧を返さなかった。宣言された外部スクリプトの静的な調査から
[方言群の GeoJSON](https://da.ruslang.ru/static/data/dialect_groups.json) に到達し、HTTP 200 と
FeatureCollection 25 地物を確認した。URL やデータの同梱はなく、同形式の未知の公開ページに同じ処理を使う。

PDF.js のコンパイルをアプリと一緒に行った最初のビルドでは、Oxc のクラス用ヘルパー 7 本が
起動グラフに移り、同じ環境で測った main の 933 モジュールが 940 に増えた。PDF.js 本体をワーカーと同じ
配布済み ES モジュールとして PDF を開くときに読み込み、PDF のコードとヘルパーを起動時の依存関係から外す。
配信資産の増分は PDF.js 本体とワーカーを含めて記録した。Atlas の実行チャンクは取得の分岐と戻り値の
接続が増え、ビルドで計測した上限を付けた。原図の読み取り・座標変換と画素分類・線の抽出は、結果の来歴に
各カーネル版を記録する。

ブラウザー検査は既存のログイン済み Atlas ページを共有する。SVG の穴付き面と線、PDF の曲線、
PNG の凡例見本画素、参照面の IoU と次の GIS 演算を同じページで確かめる。
原図固有の拒否は Atlas 側に日英の文を持たせ、GIS パネルには届かないことを検査の契約にも明記した。

修正後は main と機能ブランチの起動グラフともに 933 モジュール。非同期 JS は 16,187,124 B、
Atlas 実行チャンクは 1,198,947 B、遅延取得する PDF.js 本体・ワーカーは合計 1,746,199 B と測った。
