〈依頼〉右サイドバー（レイヤー一覧）を開いた状態でブラウザのズームを大きくすると、地図上部の検索バーと下部の Chronos が崩れる。以前から何度も右サイドバー開閉時のボタン類の問題があった——直すなら根本的に。合意: 地図の列を唯一の基準にして作り直す。上下の帯へ移すのは最狭の段だけ。

## 0. 測った（変更前・ビルドした本体・ズームは CSS ビューポートの幅として再現）

| 状態 | 観測 |
|---|---|
| 1152×720（1440 画面の 125 %）・左フロスト開・右開 | 検索欄 436–1138 px、右パネルは 852 から。`elementFromPoint`（検索ボタン中央）＝レイヤー一覧のタイル |
| 同・左は不透明（地図の横）・右開 | 同じ。Chronos は 293 px から＝左パネル（0–400）の下 |
| 1440×900・左フロスト開・右閉 | 検索欄 721–1119 とスタック 1115– が 4 px 重なる |

原因は構造: 浮かぶ部品はそれぞれ**地図キャンバス全体**を基準に置かれ、乗っているパネルを 1 つずつ避けていた——右パネルは `body.lsr-open … right:calc(var(--lsr-w) + …)` が 4 部品ぶん、左のフロストは検索の中央寄せ 2 規則と座標表示 2 規則、さらに検索は JS（`js/mobile-ui.js` の #R21〜#R252 の監視）が両パネルとスタックの行を測って `--ms-left`／`--ms-right` を `position:fixed` の欄に書いていた。その監視の「上の行に収まらないなら全幅で下へ」の分岐が右パネルの幅を引かずに右端を決めたのが今回の絵。ズーム・パネル幅・言語のどれかが変わるたびに、規則の知らない場合が生まれる形だった。

## 1. 直した構造

- **`.map-frame`（index.html）＝見えている地図。** 検索・右上スタック・ツールパネル・衛星パネル・座標表示・Chronos をこの中へ移した。枠の左端はフロストの左パネルが地図に乗っている間だけ `--sidebar-w`、右端はレイヤーパネルが開いている間だけ `--lsr-w`。**パネルを知る規則はこの 2 つだけ**。枠はサイズコンテナで、ズーム・窓の幅・パネルの開閉は全部「枠の幅が変わった」になる。
- **上段はグリッド**（`.map-frame-top`。コンテナクエリはコンテナ自身を塗れないので、型を切り替える格子を枠の子にした）。スタックの列は内容幅を下回らないので、検索は構造上スタックに潜れない。
- **普段の幅では何も動かさない**（追加条件・利用者確認済み）。検索の置き方は旧来の 2 つをそのまま再現した: 中央（地図の中央・398px＝380 の欄＋自分の余白と枠・上は端の余白 `--chrome-edge`）と、レーン（左ハンドル +14px〜スタック −14px の中央・最大 380px・上 14px）。旧監視は右パネルの幅を引かない「地図全体の中央」で衝突を判定していたため、右パネルが開いていると 約 1800px 未満の全幅でレーンを選んでいた——その見た目を規則として残した（右パネルが開いている間はレーン）。もう 1 つの切替は枠 1205px＝2×(端 6＋スタック 383＋半幅 199＋14)。383 は取り込んだ main（dcd32a0c・「More tools」が加わった後）のビルドで 1440×900 の英語のスタックを実測した値。コンパクト段は 640px 未満（レーンが 200px を切る幅）。Chronos と座標表示は、基準規則の `right/bottom/left:6px` が相対位置として二重に効いて 6px ずれていたのを、行が余白を持つ形で打ち消した。Chronos の幅は旧来の 560px＋自分の余白と枠 8px＝568px。年のレールの幅は旧来の `clamp(220px,30vw,360px)` のまま、行が足りないときだけ縮む。
- **基準との一致を数値で測る**: `origin/main`（最終は dcd32a0c）を別の作業場でビルドし、`tests/helpers/map-chrome.js` の同じ計測器で 1440×900・1280×800 × 右パネル開閉 × 明暗の 8 状態を採って `tests/map-chrome-layout-baseline.json` に置いた。新しい側の同じ 8 状態は検索・スタック・表示行・ツール行・方位磁針・現在地・Chronos の全部が 1px 以内で一致（差が出たのは右パネル開の検索の x が 0.3px——旧監視は錨を整数に丸めていた）。撮影も前後で同一。
- **下端は 1 行**（`.map-frame-bottom`）: 左に座標表示、右に Chronos。並ばない幅では `wrap-reverse` で Chronos が 1 段上へ。
- **狭い枠は形を変える**（コンテナクエリ）: 560px 未満で検索はボタンに畳む（空のまま押すと欄が開く・文字がある間は開いたまま）、2 つの表示ピルは新しい `#btn-view-menu` のメニューへ、Tools／Share は字を落とす（title が名前を持つ）、閉じた Chronos は副題を落として 1 行。360px 未満ではツールの行を縦にし、開いた検索は上段を全部使ってスタックを 1 段下げる。帯は作らなかった（縦に積むだけで足りた）。
- 年のレール（`thinPeek`）は窓の `resize` でしか印を間引き直さなかった。幅はもう枠のものなので、レール自身の `ResizeObserver` にした。
- 検索ボタンの「空なら欄にカーソル」は携帯だけだった。畳んだ欄はボタンだけなので、全端末で同じ規則にした。

### 実装中に測って直した 2 点

- **コンテナクエリはコンテナ自身を塗らない。** 最初は狭い段で `.map-frame` の列定義を差し替えていたが、規則は空振りし、畳んだ検索ボタンが列いっぱい（212px）に伸びていた。列定義は 1 つのまま、段ごとに変えるのは中の部品の置き方（`justify-self`・`grid-column`）だけにした。
- **欄を開く条件を `:focus-within` にすると、開くボタンが押せない。** 押し下げでボタンにフォーカスが移った瞬間に欄が開いてボタンが動き、離す位置がずれてクリックが成立しなかった（spec ⑥ が最狭の段で検出：フォーカスは `#ms-btn` のまま）。「文字がある・またはボタン以外にフォーカスがある」ときだけ開く。

## 2. 消したものと、引き継いだもの（substance-over-form）

| 消したもの | 何が同じだけ働いているか |
|---|---|
| `body.lsr-open:not(.ws-mode)` の `.map-controls-top`／`#tool-panel`／`#sat-controller`／`.news-timeline` の `right:calc(var(--lsr-w)+…)` と `transition:right` | 枠の右端 `right:var(--lsr-w)` と枠自身の `left`/`right` の遷移 |
| 検索の中央寄せ 2 規則（`--sidebar-w`／`--lsr-w` からの計算）・`min-width:170px`・`max-width:calc(100% - 330px)` | 上段グリッドの中央列（最大 380px）＋コンパクト段 |
| `body.ms-narrow`（fixed 配置）・`body.ms-hide` と、それを書く `js/mobile-ui.js` の監視（約 110 行） | グリッド（重ならない）・枠の端（パネルの下へ行かない）・コンパクト段（潰れない）・枠の遷移（スライドに追従） |
| `body.sidebar-glass .coord-readout{left:calc(var(--sidebar-w)+12px)}` と折り畳み時の 12px | 枠の左端＋下端の行（隅から 6px。Chronos と同じ余白） |
| `const mob=` と「携帯だけ」の空押し条件 | 全端末で同じ空押し規則 |

到達経路は減っていない: 5 つの表示ボタンは id もハンドラも同じ（Atlas・ショートカット・テストは直接押す）。携帯（≤768px）は枠が `display:contents` なので、シートへの貸し出し（`rememberHome`）を含め以前のまま。ワークスペースモードはコンパクト段を当てず、`js/workspace.js` の固定配置がそのまま効く。

⚠ **枠は z-index を持たない。** 最初は枠に z-index を与えていたが、それで枠が重なりの文脈になり、前面印（`.im-front`、front-mark-outer-context の規則で「競う場所」まで上る）が枠に付いて枠ごと 2650 へ上がり、Chronos の年のレールが経路パネルの「Clear route」を覆った（smoke R291 ⑤ が検出）。サイズコンテナ自体は重なりの文脈も固定配置の基準箱も作らない（Chromium で実測）ので、z-index を外せば各部品は以前と同じ自分の z で外の要素と並ぶ。`map-a11y-structure.spec` ⑥ に「印は枠に付かない」を足した。

## 3. 検査

- 新 `tests/map-chrome-layout.spec.js`: 1440 画面の 100/125/150 %、1920 画面の 200 % × 左パネル（閉／横／フロスト）× 右パネル（閉／開）× 明暗で、①枠と窓からはみ出さない ②開いたパネルと交差しない ③検索とスタックの各行・Chronos が交差しない ④各操作の中央の `elementFromPoint` がその操作。⑤ 1440 の 200 %（720×450）は携帯レイアウト ⑥ 畳んだ形でも同じ操作に届く。 ⑦ 普段の幅（1440×900・1280×800 × 右パネル開閉 × 明暗）で全部品の矩形が変更前の基準と 1px 以内で一致。
- 監視 JS を前提にしていた検査を、守っていた欠陥のほうで言い直した: `chrome-overlap-checks`（#R484）・`shell-compass-controls-checks`（#R480 ⑤）・`shell-map-input-checks`（#R252 ⑥）・`shell-css-surface-checks`（#R309 ⑤）・`sidebar-layout-checks`（#R160 B5）・`map-a11y-structure.spec`（⑤ は狭い枠＝コンパクト段で、⑥ は印が枠に付かない）。`z-layers-baseline.json` は `--update`。
- 監視処理を消したので `js/mobile-ui.js` は `intmap-sidebar-resize` を聞かなくなった——`js/bus.js` の名簿の pending から外した（`event-bus-checks` ③）。`window.IntMapDevice` の読み 2 か所が減った分は `global-surface` の基準を `--update`。
- **起動時の CSS が約 2.5 kB 増えた**（変更前の main のビルド 303,379 → 305,860 バイト、`check:perf` の `eager.cssRaw` の天井を `--update`）。増えたのは狭い枠の段（検索を畳む・表示メニュー・字を落とす・最狭の縦積み）と、中央とレーンの 2 型を再現する格子の規則。旧規則（右パネル回避 4 本・中央寄せ 2 本・`ms-narrow`/`ms-hide`）は消し、レーンの列定義は変数 1 つに、ワークスペースモードはコンテナ指定自体を外して各規則の前置きを省いた——それでも残るのは新しい能力そのものの分。

## 4. 残したこと

- データ凡例（`js/data-layers.js` が JS で置く）と国情報カード（`.country-info`）は、まだフロストの左パネルを個別に避けている（`--sidebar-w` + 24px）。同じ形の欠陥なので、枠の左下へ入れるのが次の一歩。
- 枠 640／360px の段は英語のスタック幅の実測（1440×900 で 383px）から決めた。幅の広い言語では段の中で検索が細くなるだけで、重なりはグリッドが防ぐ。
