## R383 — **発令された、は、発令中ではない——ヨーロッパの 84% は誰も受けていない警報で塗られ、米国の 96.9% は描かれていなかった**

依頼は一文——「警報レイヤーを実際の発表との整合性中心に徹底的に監査し、まだ余地のある場所を探して徹底的に
つぶして。過不足なく正確で最新の情報を掲載できているか監査して。高速化もして。」

**「過不足」を数えたら、両方が同時に、しかも大きく出ていた。**

| | 監査前（本番実測・同じ分） | 監査後（実測） |
|---|---:|---:|
| MeteoAlarm が提供した区域 | 1,158 | — |
| **そのうち実際に発令中** | **183 (15.8%)** | — |
| この地図がヨーロッパで塗っていた区域 | **1,015** | **155** |
| 米国 `PLACED.USA`（置けた/発表された） | **[11, 135]** | **[403, 403]** |
| この地図が世界で塗っていた区域 | 1,811 | 2,207 |

---

### 1. MeteoAlarm は「発令記録の流れ」であって「発令中の一覧」ではない

`feeds.meteoalarm.org` の到達できた 34 加盟国を同じ分に全部読んだ実測——

```
緑（awareness 1）以外の電文        2,990
    すでに期限切れ (expires < now)  2,546
    まだ発効していない (onset > now)   327
    発令中                            117
```

区域に畳むと **1,158 → 183（過剰塗り 84.2%）**。国ごとでは

```
オーストリア 116 → 0     （781 件すべてが 5 日前 2026-08-18 に失効した雷雨警報）
ポーランド   319 → 1      スイス 107 → 0      チェコ 25 → 0      ギリシャ 16 → 0
イスラエル    33 → 2      ラトビア 43 → 12    フランス 96 → 15   スペイン 147 → 37
```

**原因は 1 行の不在で、しかもそれはこのリレー自身の中で唯一の例外だった。**
`supabase/functions/alerts-relay/index.ts` の要約器は 4 本あり、`summariseCAP`・`summarisePAGASA`・
`summariseSWIC` は**どれも `expires < now` を落としている**。`summariseMeteoAlarm` だけが有効期間を
一度も見ていなかった——つまり**この地図でいちばん多くのフィードを持つ地域が、いちばん真実から遠かった**。

→ 判定を **`forceState(info, sent, now)` 1 本**にし、3 本の要約器がこれを呼ぶ
（WMO 登録簿は CAP の `<info>` ではなく WFS の行なので自前の `expires` 判定のまま）。

- ⚠ **fail-open**。`expires` も `onset` も無い電文は**落とさない**——時計を出さなくなったフィードが
  地図を黙って空にしてはならない（実測、34 加盟国で `noExpires` は **0**。これは経路ではなく防具）。
- ⚠ **黙って切らない**。`expired` / `upcoming` / `upcomingAreas` が要約と一緒に返り、
  国別の凡例が言葉で印字する（`notInForceLine`）。#R320 の規則——**黙って切った一覧は完全な一覧に見える**。
- ⚠ **「これから発効」は警報ではないが、沈黙でもない**。MeteoAlarm 自身のサイトには「明日」のタブがある。
  この地図の時制は 1 つで、JMA・NWS・ECCC・CMA と共有している（どれも**いま有効なものだけ**を公表する）。
  ヨーロッパだけ別の時計で塗るのは #R288 と #R298 が二度払った形なので、**塗らないが、数えて名前で出す**。

### 2. 米国の警報は、その 96.9% が「形を持たない発表」だった

`api.weather.gov/alerts/active` の実測: **発令中 127 件のうち幾何を持つのは 4 件**。残る 123 件は
UGC の予報区コードで発令され `geometry: null` で配信される——Extreme Heat Warning 6・Heat Advisory 14・
Gale Warning 11・Air Quality Alert 9・Small Craft Advisory 68・Fire Weather Watch 3・Red Flag Warning 1。
同じ分の本番実測 **`PLACED.USA = [11, 135]`**。

#R302 はこれを **201/281（71.5%）**で測り、「置けなかったものを置けたと数えていた」ほうを直して
「⚠ THIS DOES NOT DRAW THEM. Turning a UGC code into a shape needs the NWS zone index」と書いた。
数え方は正しくなり、**割合はその後 96.9% まで上がっていた**——緑のフィード灯の下で、米国は事実上
「地図の無い国」だった。

→ **形は NOAA 自身が公開している予報区レイヤーから引く**（`nws_reference_map`：
8 公共予報区 4,080・9 火災気象予報区 3,603・5 沿岸海域 569・6 沖合 130・2 郡 3,284）。

- ⚠ **これは索引であって第2の意見ではない**。Eurostat NUTS・国土数値情報・DataV・同梱の世界 ADM1 と
  同じ扱いで、**何が発令されているか・その階級・その文言は `api.weather.gov` だけ**が決める。
  「ソースは一国一ソース」は保たれる——同じ機関の、同じ区域についての、その機関自身の作図である。
- ⚠ **実測は出荷コードそのものを実サービスに当てて取った**（#R317 の作法）。
  発令中の **339 の区域コードが 339/339 解決・4.0 秒・幾何 572,659 B・32,078 頂点**。
- ⚠ **種別が鍵の一部**。火災予報区と公共予報区は UGC の名前空間を共有する（どちらも `state_zone='AK317'`
  に答える）ので、`/zones/fire/` と `/zones/forecast/` を区別しない索引は
  **Red Flag Warning に公共予報区の輪郭を渡す**。
- ⚠ **素の `geocode.UGC` は代替であって2つ目の登録ではない**。火災気象の電文は同じ区域を
  `affectedZones` と `geocode.UGC` の**両方**で名乗るので、UGC を無条件に足すと `f:` の隣に `z:` の鍵ができ、
  **同じ地面を2度主張**する。実測、110 件中 **10 件**が「登録簿に無い区域」として現れていた
  （CAZ280/281・ORZ621-623・ORZ670-672・IDZ423/426——`api.weather.gov` はそれらを `fire/…` と呼ぶ）。
- ⚠ **簡略化は宣言する**。`maxAllowableOffset` 0.004°（≈440 m、この地図自身の世界 ADM1 索引 0.01° より細かい）。
  実測、116 区域で **1,099,442 B → 80,503 B**。
- ⚠ **冷えた索引は駆ける**（#R284 と同じ形）。1 バッチ 110 に対し発令中の区域は実測 339 なので、
  ティック待ちにすると米国が描き終わるまで数分かかる。バッチは**連鎖**し、待つのは**失敗した掃引だけ**。
- ⚠ **答えは保存する**。予報区の境界は年 2 回程度しか改定されないので、他のあらゆる境界集合と同じく
  Cache API に置く（`intmap-nwszone-v1`・180 日）。

**描かれていることの実測**（`queryRenderedFeatures`・キャンバス 880×720・16 px 格子・2,184 点）:
z3.4 の北米で **警報色の点 192、うち 115 が NWS の予報区ポリゴン**。z4 のヨーロッパで 175（MeteoAlarm 128）。

### 3. 台湾: 1 つの名前の下に 4 つの機関、1 つの階級の下に 4 つの帯

「CWA (Taiwan), via NCDR」と名乗っていたフィードの電文の発令者は、実測で

```
農業部農村發展及水土保持署 ×31   中央氣象署 ×17   交通部公路局 ×10   高雄市政府 ×1
```

の 4 者だった。#R352 が名指しした欠陥——**間違った出典を名乗るのは、名乗らないより悪い**——そのもの。
水土保持署は台湾の**土石流警戒の正規の発表機関**なのでここに属するが、公路局の **道路封閉** は
`Extreme` で塗られ、高雄市の **開放臨時停車** は `<areaDesc>` が**小学校名**（`苓雅區福東國小`）の
「区域」を **45 件**作っていた。

そして **`xmlOne(cap,'event')` は文書中の最初の `<event>`** で、**`xmlAll(cap,'area')` は全部の `<area>`**
——2 つ目以降の `<info>` に属する区域まで、**最初の帯の階級と有効期間**で塗っていた。実測（降雨）:

| | 監査前 | 監査後 |
|---|---:|---:|
| 紅色 / Extreme | **286** | 125 |
| 橙色 / Severe | 0 | 108 |
| 黃色 / Moderate | 0 | 53 |

後者が中央氣象署の発表そのものである。多言語の電文では**同じ区域が言語ごとに 2 回**数えられており、
`areaTotal` は **694 → 386** になった。

→ **`<info>` ブロックを仕事の単位にする**。そして**何が警報かは CAP 自身の語彙で決める**——
`<category>` が `Met`/`Geo`/`Fire`/`Env`/`Health` でなければ警報ではなく（実測 Geo 253・Met 59・**Transport 15**）、
`severity: Unknown`＝**発令者が階級を付けなかった**ものは色にできない（実測 1 件）。
台湾の機関名を書き並べた表ではないので、**増える日に嘘にならない**（#R271）。
件数（`notHazard` / `ungraded` / `senders` / `indexTotal`）はすべて要約に載る。
出典名は集約体を名乗り、**行ごとに実際の発令機関**（`by`）が付いて、カードはそれで束ねる。

### 4. 鮮度の計器が読んでいたのは、リレー自身の時計だった

#R269 が `FEED_AT` を作った理由は「**止まったフィードは、失敗したフィードではない**」（83 日間 200 と
正しい JSON を返し続けた JMA のエンドポイント）。ところが MeteoAlarm と WMO 登録簿には
**リレーがフィードを読んだ時刻（`fetchedAt`）**が渡っていた＝常に「いま」。本番実測
**`feedAgeH.meteoalarm = 0`**、その裏で

```
ルクセンブルク 104 h   ベルギー 94 h   英国 82 h   キプロス 78 h   アイルランド 66 h
```

なにも発表していなかった。→ リレーが **`newest`**（その加盟国の CAP `sent` の最大）を返し、
`seenAt` はそれだけを読む。実測、監査後 `meteoalarm 0.63 h` / `swic 8.13 h`（＝ **delayed**）/
`pagasa 11.13 h`（＝ **delayed**）。⚠ **空のフィードは時計を出さない**ので `seenAt` は空文字を無視する
——「発表がない」は「取得できていない」ではない。

### 5. ドイツの Bundesland のために、10 秒ごとにもう 1 本 HTTP を投げていた

`loadDWD` は WFS と並行して `dwd.de/DWD/warnungen/warnapp/json/warnings.json` を取り、
`st[String(p.WARNCELLID||'')]` で引いていた。実測、WFS の項目名は **`GC_WARNCELLID`** で、
素の `WARNCELLID` を持つ地物は 1 つも無い——つまり毎行 `st['undefined']`、**州は一度も解決せず**、
タップカードは郡名を 2 回印字していた。そして同じ応答が **`GC_STATE`**（実測 `"MV"`）を持っている。

→ 1 応答・1 真実。ブラウザの実測で `www.dwd.de` への要求は **21 → 0**（`maps.dwd.de` は 19 のまま）。

### 6. 黙って切った一覧は、完全な一覧に見える

リレーの `AREA_CAP` は区域一覧を 400 件で切るのに、アプリは分母に `areas.length`（＝**切った後**）を
数えていた。実測、台湾は `areaTotal` 694 に対して読み手に「**286 / 400**」と印字されていた。
→ 分母は `areaTotal`（MeteoAlarm・WMO 登録簿・CAP の 3 か所）。

**そして「ページ」は「フィード」ではない。** 同じ形が 2 か所に残っていた——カナダは `limit=500` で
読むのにコレクションは `numberMatched` を返し（実測 238）、中国は 2 ページ × 1,000 行で読むのに
CMA 自身は `count` を返す（実測 1,202）。**どちらも今日は上限に届いていない**——それこそが、
黙った切り落としが隠れている状態である。⇒ 分母は**大きいほうの数**。

### 7. 速くなったところ

- **DWD**: 更新のたびの HTTP が 1 本減る（実測 21 → 0／セッション。10 秒ティック）。
- **MeteoAlarm**: 貼り直すコレクションから **約 860 地物**が消えた。実測、監査後の
  `warn/meteoalarm` は **155 地物 / 22,467 頂点**（145 頂点/地物）なので、その平均で見て
  **およそ 12.5 万頂点**が毎回のシリアライズから外れる。#R344 が測ったこの層の最大の費用は
  「1 つのコレクションを何回貼り直すか × その大きさ」なので、ここが直接効く。
- **NWS**: 逆に **393 地物 / 33,623 頂点**が加わる（＝この層が初めて米国を描くための費用）。
  差し引きでコレクションは軽くなり、しかも**描いている警報は増えている**。
- 予報区の索引は Cache API に残るので、**2 回目以降の訪問は 1 リクエストも払わない**。

### 8. 検査（`tests/r380-checks.test.mjs`・6 本）

⚠ **赤にできることを確かめた**——9 つの変異を 1 つずつ入れて、**9 つとも赤**（#R347 の規則）:
MeteoAlarm の絞り込みを外す／`forceState` の期限判定を殺す／予報区の鍵から種別を落とす／
`fetchedAt` を戻す／DWD に存在しない項目を読ませる／道路封閉を通す／切った一覧を分母に戻す／
UGC を無条件に足す／冷えた索引の連鎖を止める。

① は **`forceState` を出荷ファイルから取り出して実行**する（fail-open の 3 ケースを含む）。
② は WHERE 句の**エスケープを実行**して確かめる（`"AR074'); DROP--"` → `'AR074DROP'`）。

### 9. 触っていないもの・残っている問題

- **CMA**（`nmc.cn/rest/findAlarm`）は**有効期限を公表しない**。実測、返る 1,202 件はすべて 24 時間以内
  （0–6 h 309・6–12 h 486・12–24 h 205）で、上流自身が「直近」の一覧として運用している。
  **推測で切らない**——切れば実際に発令中の信号を消しうる。
- **香港 (HKO)** は今も `PLACED.HKG=[0,1]` で、幾何を持たず**国全体の薄塗り**で答える。
  発令単位が領域そのものなので嘘ではないが、輪郭を描けば種別ラベルとタップの当たり判定が付く。
- **台湾の CAP 索引**は 2,102 エントリ中 252 件が対象機関で、リレーはその**新しい 90 件**を読む
  （`capTotal` / `capRead` / `indexTotal` が要約に載る）。実測、その 90 件の中に既に
  **期限切れの `<info>` が 224 件**あるので、その先はほぼ失効分だが、**上限であることに変わりはない**。
- **`AREA_CAP` は 400 のまま**。監査後は MeteoAlarm 側が最大 147 まで下がり、台湾も 386 なので
  いま切っているものは無い（分母は `areaTotal` なので、切れた日には読み手に見える）。
