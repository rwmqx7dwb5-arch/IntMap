## R694 — **`_shared/` の名簿を見る 3 つの門が、そろって綴りを測っていた**

〈「supabase/functions/_shared/ の名簿をめぐる 3 つの門が『綴り』を測っていて『事実』を測っていない。
#R690 でぶつかったので構造として直してほしい」＋ 4 件の実測〉

### 0. 報告された 4 件は 4 件とも再現した

`supabase/functions/_shared/` は **11 本**（atlas-persona, aviation-codec, aviation-model,
news-cluster, news-geo-prompt, news-ingest, newsgeo, radiation-sources, relay-guard,
volcano-parse, who-don-extract）。`docs/FILES.md` §3.12 は **9 本**しか挙げていなかった
（radiation-sources.js と who-don-extract.js が無い）。

### 1. ⚠⚠⚠ 門は 11 本を読み上げながら、9 本の文書を通していた

`scripts/doc-facts.mjs` の `edge-shared` の出力は、9 本の版でもこうだった:

```
✓ edge-shared: _shared/ holds 11: atlas-persona.js, … , who-don-extract.js
```

**11 本を正しく数え上げ、名前を全部印字したうえで、9 本しか書いていない文書を通している。**
原因は照合の側ではなく**読み取りの側**にあった:

```js
const win = body.slice(at.index, at.index + 260);      // 260 文字の窓
const group = win.match(/（([^）]*)）/) || win.match(/\(([^)]*)\)/);
if (!group) continue;                                   // ← 名簿ごと素通り
```

台帳は名簿を 3 行に折り返しており、閉じ括弧は **~290 文字目**。窓に入らないので `group` は
`null` になり、`continue` が名簿を丸ごと捨てる。**同じ名簿を 8 本に削ると閉じが窓の内側に
戻ってきて、即座に赤くなる**——つまり**見逃す件数を決めていたのは、抜けの数ではなく本文の長さ**
だった。長い名簿ほど見なくなる検査である。

⇒ 目録は**閉じ括弧まで無制限に読む**（長さは関連性の証拠ではない）。**閉じない括弧は
`continue` ではなく `fail`**——「読めなかった」を「問題なし」として出さない。

### 2. ⚠⚠⚠ 「3 本未満は目録ではない」は、抜く数によって効いたり効かなかったりする

同じ規則に `if (names.length < 3) continue` があった。11 本から 9 本抜けば残り 2 本で見逃し、
10 本から 9 本抜けば残り 1 本でやはり見逃す。**件数は目録の条件ではない。**

条件は**言及がディレクトリについてか、その中の 1 本についてか**である。閾値を外した最初の版は
`Architecture.md` の

> `_shared/newsgeo.js`（＝ブラウザの `js/newsgeo.js` と1バイト同一）

を「10 本を omit した名簿」と報告した。これは**1 本について真の文**であって目録ではない。
⇒ 言及は `_shared/` の**直後にファイル名が続かないもの**だけを取る。

### 3. ⚠⚠⚠ 体裁の制約が検査から漏れ出していた

`scripts/arch-files-check.mjs` は §3.1 以下の**行頭の `名前.js`** を無差別に js/ のモジュール
宣言と読み、そうでないものを**手書きの控除表 3 つ**で引いていた——`src/` の実体、`scripts/` の
実体、そして `^(sw|admin|vite\.config|playwright[.a-z]*|_.*)\.js$`。

結果、§3.12（`supabase/`）の名簿を折り返して行頭を `radiation-sources.js` にしただけで
**正しい文書の上で赤**になる。名簿は「たまたま js/ にも同名がある 5 つ」でしか改行できなかった。

⇒ **§3.x の見出しがバッククォートで名乗るディレクトリが、その段の主語である。**
台帳が既に持っていた構造で、`### 3.4 \`js/\` — 地図の表面` と
`### 3.12 \`supabase/\` / \`docs/\` / …` は自分が何の話かを宣言している。
`js/` を名乗る段の中だけを読むと、**控除表は 3 つとも要らなくなり、答えは変わらない**
（284 記述 / 284 実在・欠落 0・幽霊 0）。逆向きも締まった——js/ のモジュールを
`supabase/` の段に書いても「記述した」ことにならない。

### 4. ⚠⚠⚠ 正しい追記が CI を赤くしていた

`tests/r399-checks` ① は名簿の綴りそのものを変異の錨にしていた:

```js
from: 'news-cluster.js / news-geo-prompt.js / news-ingest.js / volcano-parse.js）',
```

名簿に 2 本足せば、その並びはもう文書に無い。`assert.ok(re.test(original))` が落ちる。
**錨が測っていたのは「名簿が正しいか」ではなく「名簿が去年と同じ字で書いてあるか」だった**
（#R488／#R530 の形）。

⇒ **壊し方で書く**——実体の `_shared/` を読み、その文書の名簿から**1 本落とす**。何が並んで
いるかは実体から来るので、正しい追記では錨が外れない。落とすのは**末尾の 1 本**（窓で切って
いた実装が最初に失う位置）。

実測: **12 本目を足して 3 文書を正しく更新すると、`check:docs`・`check:archfiles`・`r399 ①`・
新しい検査が 4 つとも緑**。これが報告された欠陥の直接の反証である。

### 5. ⚠⚠ 規則を出したのは、測れるようにするため

`doc-facts.mjs` は 1 回 **7.5 秒**。「全部の名前を、全部の名簿から 1 本ずつ落とす」掃引
（11 名 × 3 文書 = 33 回）はそれ越しだと **4 分**になり、**だから今まで書かれなかった**。
判断を `scripts/shared-roster.mjs` へ出すと同じ掃引が**数ミリ秒**で、`doc-facts` も検査も
**同じ関数**を使うので規則は 1 つのまま（規則を書き写すと規則が 2 つになる——
`.agents/rules/no-ad-hoc-hardcoding.md` §2.3、#R575 の形）。

### 6. 検査

`tests/r694-shared-roster-facts-checks.test.mjs`（7 本・**1.6 秒**）:
① `_shared/` の**どの 1 本**を**どの名簿**から落としても名指して落ちる（名簿を書いている文書は
**名簿そのものから発見**する——手で並べた一覧は次の文書を黙って落とす）／② **長さは判定に
関与しない**（閉じが 260 文字より外にある名簿でも鳴る。窓が戻ってきたら赤）／③ 閉じない括弧は
失敗であって素通りではない／④ ファイル 1 本への言及は目録ではない・hedge は据え置き、**かつ
hedge を外せば同じ文が鳴る**（「hedge があるから緑」と「見ていないから緑」は同じ緑に見える）／
⑤ 名簿は**11 本のどの名前でも改行できる**（報告された欠陥そのもの）／⑥ arch-files は本物の欠陥
では依然として赤い（緩めて通したのではない）／⑦ js/ のモジュールを `supabase/` の段に書いても
記述したことにならない。

### 7. ついでに直した数と、直さなかった構造

実体と離れていた数を 3 つ直した——台帳の回帰検査 `262本`→**349**、spec `100本`→**114**、
`Architecture.md` の js/ `269 本`→**284**（最初の 2 つはこの回が 1 本足すことで動く数でもある）。
⚠ **これらは門を持たないので、また離れる。** #R500 の「機械が持つ数を散文が写した箇所は必ず
離れる」がそのまま当てはまるが、門を 1 本足すのは今回の依頼の外なので**最終報告で提案した**。
