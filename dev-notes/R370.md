## R370 — **1つの英語キーが5つの意味を運んでいた**

報告は「`js/locales/ui.{fr,ko,zh,zh-hans}.js` の `inline:` 表は英語原文をキーにするので、異なる意味の
3か所が同じ行を共有している」だった。3か所ではなく **10か所・5つの意味**で、同じ形が **192 キー**あった。

### なぜ4言語だけが壊れるのか——非対称は設計そのものにある

`js/lang-registry.js` の `pick()`:

```js
var i = idx[code];
if (i > 0 && i < n) { var v = arguments[i]; if (v != null && v !== '') return v; }  // en/ja/de/ru/es
if (i !== 0) { var t = inline[code]; if (t) { var s = t[arguments[0]]; … } }        // fr/ko/zh-Hant/zh-Hans
```

en / ja / de / ru / es は **その call site が書いた引数**を読む。fr / ko / zh-Hant / zh-Hans は
`inline[code][arguments[0]]` ＝ **英語原文1つにつき1行**を読む。

> **位置の5言語は衝突しようがなく、inline の4言語は衝突を避けようがない。**

`'Clear'` の 10 か所:

| 日本語 | サイト | 意味 |
|---|---|---|
| 快晴 | `js/widget-defs-data.js:82` | WMO code 0（天気） |
| 清浄 | `js/data-layers.js:502` | エアロゾル凡例の下端 |
| 消去 | `js/map-tools.js` `js/seismic.js` `js/sims.js` `js/viewshed.js` | 消す |
| クリア | `js/companies-ui.js` `js/company-panel.js` `js/countries-ui.js` | フィルタ解除 |
| 解除 | `js/app-body.js:1410` | 範囲指定の解除 |

行は fr「Effacer」/ ko「지우기」/ zh「清除」＝**消去**。つまり**天気ウィジェットは快晴を「消せ」と表示し、
大気の凡例は「清浄」を「消去」と書いていた**——4言語で。

⚠ **どの計器も 100% を表示し続けていた。** `i18n-report.mjs` は「その英語キーの行は在るか」を数え、
在った。`i18n-positional-audit.mjs` は「引数は5つ揃っているか」を数え、揃っていた。
**「行がある」は「その行が正しい」ではない**というのが、既存のどの面にも無かった問いだった。

### 判定は日本語の位置引数

引数1は日本語で、**サイトごとに書かれている**。同じ英語で日本語が違うなら、書いた人は別のものを
訳している。辞書が要らない唯一の真の信号。

⚠ **これは過大に拾う。**「比較」「比較する」「国を比較」はフランス語では `Comparer` 1語で、
1行で足りる。だから所見は「違う」ではなく「**違い、かつ1行では足りない**」であり、それを分けられるのは
読む人だけ。**192 件すべてを1件ずつサイトで読んだ**結果が、28 件の改名と 176 件の benign 判定（rebase で R356 が `unavailable` を1件持ち込み、同じ基準で読んで benign ＝ **177**）。

### 直し方——外れ値の側に固有の英語キーを与える

⚠⚠⚠ **`arguments[0]` は参照キーであると同時に英語の表示文字列**である。だから新しいキーは
**英語として正しく読めなければならない**（内部識別子ではない）。

⚠⚠ **足す前に探す。** `Clear sky` は `js/weather.js:1585` に**同じ日本語「快晴」で既に存在し、
4言語の行も揃っていた**。`Source term` も `js/atlas-console.js:2223` と `js/sims.js:230` に
**同じ「放出量」で既にあった**。この2件は**行を1つも足さずに**解決した。

⚠⚠ **de/ru/es が既に別の語を出しているなら、それが「英語キーのほうが間違っている」証拠。**
`L('High','最高','Max','Макс','Máx')` — 5言語のうち3言語が既に「最大」と言っていて、
fr/ko/zh だけが「高い」と言っていた。英語キーを `Max` / `Min` に寄せた。
（副作用: de 引数が英語と同一になるので `SAME_AS_EN.de` に `Max` / `Min` を追加。
ドイツ語の Maximum / Minimum の略はまさにその3文字。）

⚠⚠ **衝突相手が去ると、残った側の行が間違いとして残る。** `Day` の ko 行は「경과」＝経過、
zh は「天數」＝日数だった——これは**去っていった「経過日」のための訳**で、残る「今日の進捗」には合わない。
`Day` / `Week` / `watch` / `points` / `Emergency` の5キーは、**残った意味に合わせて行を訳し直した**。

⚠⚠⚠ **そして残った側が1サイトになると、衝突の計器からは見えなくなる。**
`Emergency` は「救急（病院）」と「緊急（警報の最高階級）」の2つで、行は**病院の救急**だった。
救急を `Emergency room` へ移した結果、**警報の最高階級だけが残り、その行は「Urgences / 응급 / 急診」**
＝病院の科の名前のままになった。**1サイトは衝突ではない**ので新しいゲートは黙る。
これは resolve 表（fr/ko/zh の実際の解決結果を並べたもの）を読んで初めて見つかった——
**「衝突を消したか」ではなく「読者は何を見るか」で確かめる**必要がある。

### 衝突ではなかった3件

- `js/world-packs.js:1296` — 日本語の引数が**英語の単語 `'Moderate'`** だった ⇒ `中程度`
- `js/world-packs.js:1294` — `'Extreme（最も深刻）'` と英語混じり ⇒ `極端（最も深刻）`
- `js/monitors.js:83` — 全ての非英語引数が `''` だった。⚠ **これは死んだコードだった**——
  `rel` は宣言されているだけで**一度も呼ばれていない**（同ファイルに残る `rel` は `rel="noopener"` の属性）。
  空の訳は**一度も描画されていない**ので、訳す対象が無い ⇒ 削除した。
  ⚠ その隣でロシア語が**数字を1つも持たない「мин назад」**を出していたので、そこは直した。

### 第17の面——`scripts/i18n-key-collision-audit.mjs`

`#R239` の規則どおり、**新しい問いは新しい独立した計器ではなく `i18n-audit.mjs` の1行**にする。
どの呼び出しが翻訳呼び出しかは `scripts/i18n-helpers.mjs` が**リポジトリ全体で1回だけ**解決したものを
import する（#R251 の教訓——ファイル単位で答えると他モジュール越しのヘルパが視野の外に出る）。

⚠⚠ **許可リストは両方向に落ちる。** `PAIR_CEILING` や `scripts/test-budget.mjs` と同じで、
**衝突しなくなった項目を残すと、そこが本物の衝突の隠れ場所になる**。benign の最後の重複サイトを
消すことは、ここの1行を消す費用を伴う——その1行が「消えた」という記録になる。

⚠⚠ **緑は効く証拠ではないので、両方向で赤にして確かめた。**
① 新しい衝突を入れる（`Clean air` を別の日本語で再利用）⇒ 赤。
② 許可リストの項目を衝突しなくする（`Thunderstorm` の片方の日本語を揃える）⇒
`no longer collide … "Thunderstorm"` と名指しで赤。どちらも戻して緑。

### 残っている問題

- `js/monitors.js` の `_fmtWhen()` は相対時刻の英語キーを**連結で作っている**
  （`Math.round(diff/60)+' min ago'`）。**動的なキーは inline 表に存在しえない**ので、
  fr / ko / zh-Hant / zh-Hans はこの関数の中では英語のままになる。今回の範囲外——
  直すには `{n}` を持つ1つのキーに畳む必要がある。
- 同じ理由で、`ML('ago', …)` 型の**前置詞になる言語**（de「vor」・fr「il y a」・es「hace」）は
  後置の語順では正しく組めない。上と同じ1つの修正で一緒に解ける。
