## R409 — **両大戦を2つのレイヤーに割り、凡例に自分の時計を持たせた**（そして記録に「画面に出せない行」を作れなくした）

依頼は3つ。**「World Wars layer をもっと充実させろ。また、凡例内にタイムスライダーをつけろ。
また、WW1とWW2でレイヤーを分けろ。」** 充実の方向は利用者が4つとも選び、再生については
**「付ける。Chronosは動かすな。」**、期間外の挙動は**「ONにしたら開戦日へ時計を移す」**と指定した。

### 1. 着手前に測ったもの — 依頼の前提を全部当たる

`intmap-scout` 2体に UI の全配線とデータパイプラインを走らせた。実測で分かったこと:

- **events 221 件のうち 179 件（81%）が `kind` を持たない。** 種別は実質2値で、しかも
  **その綴りは `js/war-layer.js` の MapLibre `match` 式の中にしか存在しなかった**——記録の側に
  語彙が無いので、綴りを間違えた行は静かに陸戦として描かれる。
- **収容所・ジェノサイドは0件。会談は1件だけ**（カサブランカ）。空襲（Blitz・ドレスデン・広島・
  長崎・バトル・オブ・ブリテン）は**10件すべて `kind` 無し**＝陸戦扱い。
- **`data/wars.json` の `src`（出典文字列）を読むコードがリポジトリに1件も無い。** 画面のクレジットは
  `js/war-layer.js` に**手で書かれた別の文字列**で、CShapes は名乗るが記録は名乗らない。
  出典ページ（`js/reference-data.js` / `pages.*.js`）にも記録そのものの項目が無かった。
- ⚠⚠⚠ **サラエヴォ事件（1914-06-28）は出荷されているのに一生画面に出ない。** 層は `from`〜`to`
  の間しか大戦を描かず、その日付は `from` の**30日前**だった。
  **出荷されている行と、存在しない行は、画面の上で見分けがつかない。**
- **お気に入りに留めると「wars」という生 id がチップに出る**（`js/layer-favs.js` は
  `span[data-i18n]` か `span.ec-lbl` から名前を読み、無ければ id にフォールバックする）。
- **Atlas から日ごとの記録に到達する道が無かった。** `LAYER_ALIASES` に war 系の別名は0件で、
  「第二次世界大戦」は `js/atlas-sims.js` の**近似の `historicalMap`** に振られていた。

### 2. レイヤーを2つに割った

行は **`dl-ww1` と `dl-ww2`**（どちらも既定 OFF・分類は「政治・統治」）。`js/war-layer.js` は
**1つの工場・大戦ごとに1インスタンス**（`makeWar()`）で、source と layer は `ww1-` / `ww2-` を
接頭辞に持つ。**共有するのは算術だけ**——`data/wars.json`・CShapes の表・リングのキャッシュは
1回だけ読む。**インスタンスは自分の行が ON になったときに初めて生まれる**（実測: WW2 だけを
点けたセッションに `ww1-src` は存在しない）。

⚠ **旧 `dl-wars` は3つの扉から入ってくる。** レイヤー欄（`js/data-layers.js` の分類表）・
**共有 URL**（`js/map-ui.js`）・**セッション復元**（`js/session-tabs.js` の `RETIRED` 表）。
共有 URL の復元ループは id を `getElementById` で解決し、**そのあと「望まれていないレイヤー」を
全部閉じる**——古いリンクは「war レイヤーが開かない」だけでなく「**利用者はそれを望んでいない**」
と読まれる。`RETIRED` はそれまで**改名だけ**の1対1表で、今回が初めての**分割**なので、値が
リストでもよいようにした（既存の5件は1バイトも変えていない）。IntMapOS の `wars.toggle` /
`wars.show` も残し、`wars.show` は**日付が入るほうの大戦**を開く。

### 3. 凡例の中の時計と、Chronos を動かさないこと

凡例に**輸送ボタン（最初の日／1日戻る／再生・一時停止／1日進む／時計に合わせる）・日スライダー・
日付の直接入力・再生の刻み（1日／5日／15日）**を入れた。部品は **`window.IntMapWxPlayer` の
`b` と `IC`**——気象レイヤーの再生ボタンと**同じ宣言**なので `.data-legend .ecl-b` の CSS が
そのまま効き、**プレイヤーの CSS を1行も足していない**（写しが4つになるのが繰り返しの形）。

⚠⚠⚠ **再生が主時計を進めると、100 ミリ秒ごとにニュース・国境・昼夜境界・全統計が動く。**
だから凡例側の操作は Chronos を**読むだけ**にした。`js/war-layer.js` が `IntMapTime.set` を
呼ぶのは**ただ1か所、`toggle()` の中の種まきだけ**（`tests/r409-checks ③` が「書き込みは
ちょうど1回で、スライダーにも輸送にも再生ループにも無い」を測る）。`js/chronos.js` は
**自分では時を刻まない**ので、「Chronos に追従する」がスライダーと喧嘩することは構造上ない。
実測: 再生で層の日付が 1943-07-05 → 1943-08-14 と進むあいだ、主時計は 1939-09-01 のまま。

⚠⚠⚠ **分割が、それまで存在しなかった場合を作った。** 層が1つのときは「Chronos に追従する」に
間違った答えが無い。2つになると **1916年の時計は WW1 の中にあり WW2 の外にある**——そして
`setDate` は期間へ clamp するので、素直に追従させると **WW2 は 1939-09-01 へ飛び、再生も止まる**。
その日付は WW2 について何も語っていない。⇒ **時計が自分の期間の外に出た層は、自分が見せていた
日をそのまま持つ**（実測: 両方 ON で時計を 1917-04-06 に動かすと WW1 だけが追従する）。

⚠⚠ **制御は1回だけ組み、以後は中身だけ書き換える。最初の版はそうしていなかった。**
range は1ドラッグの間に何十回も `input` を出す。毎回 `innerHTML` を張り替えると
**指がつかんでいる要素が2フレームの間に差し替わり**、スライダーは1px で手を離す。
文章の側（`.war-info`）だけを毎フレーム書き換え、制御は `syncControls()` が値だけ更新する。
⚠ `_tileLegends()`（地図上の全凡例の再配置）は**再生中に呼ばない**——毎秒9回やる仕事ではない。

### 4. 画面で測って初めて分かった3件

⚠⚠ **凡例が 900 px の窓の上端を突き抜けていた。** 1943年7月のある日は戦線が4本あり、それぞれ
注記を持ち、作戦の一覧が続く。`.data-legend` は**下端で留まる**ので、画面から落ちたのは見出しと、
**このラウンドが足した制御の全部**だった。⇒ 変わる側（`.war-info`）に高さの上限を付けた。

⚠⚠⚠ **電話では逆のことが起きていた。** 狭い画面では `js/data-layers.js` が凡例を**最小化して
開く**——そしてその最小化は、箱の子要素を**1回だけ**歩いて `display:none` を書く。この層の本体は
`_registerLayerOpacity` が返ったあとに append されるので**その走査に入らない**。結果、箱は
`legend-collapsed` を持ったまま全文を表示し（実測 **1,095 px / 844 px の画面**、地図は消えた——
`CONSTITUTION` §4 が禁じている）、しかも共有プレイヤーの CSS が `.legend-collapsed .ecl-player`
を隠すので**輸送が丸ごと不可視**だった。**症状は2つ、原因は1つ、直しは1行**
（`.legend-collapsed .war-leg{display:none}`）。⚠ 枠組みの高さ上限は壊れていない——クラスが
外れた瞬間に 253.2 px（30dvh）に戻ることを実測した。最初に書いた原因（CSS 変数が空）は**誤り**で、
測って否定した。

⚠⚠⚠ **作戦の点が丸ごと描かれていないのに、その名前だけが地図に出ていた。** `ensure()` は
3か所から呼ばれ、`load()` を待つのは `toggle()` だけ。取得中に基図が入れ替わると `data === null`
のまま全レイヤーを組み、色式が `['match', ['get','kind'], '#ffffff']`＝**ケースの無い `match`**
になって MapLibre が拒否する。エンジンの facade が不正な `add` を握り潰すので **5本中4本だけが
入り**、以後 `ensure()` は source があるので早期 return——**そのセッションのあいだ点は永久に
出ない**。実測: `layers.has('ww1-evt') === false`、面も線もラベルも描かれ、作戦名の下に丸が無い。
⇒ **記録が来るまで組まない**（`ensure()` が `!data` で拒否）＋**退避の述語を `canBuild()` に**
（「スタイルが用意できた」だけでなく「記録が届いた」も見る）＋色式が退化しないように。
`tests/smoke.spec.js` が**点が描かれていること**を、ラベルとは別に訊くようになった。

### 5. 記録の側（`scripts/wars/` → `data/wars.json`）

- **種別の語彙 `KINDS` を `scripts/wars/lang.mjs` に1か所だけ置き、そのまま出荷した。** 9種
  （`battle` / `naval` / `air` / `siege` / `landing` / `political` / `conference` / `atrocity` /
  `uprising`）。色と9言語名を持ち、層は**出荷された表から**円の色と凡例を作る。⚠ **色を層に
  書くのをやめた**——記録と地図が食い違える場所を1つ消した。語彙外の綴りは検査⑧が拒否する。
- **数値 `str`（投入兵力）／ `cas`（死傷・捕虜）**。整数、または出典が割れているときは `[低, 高]`。
  **いずれも「一般に引用される両軍合計」**で、ポップアップがそう明記する（検査⑨が形と上限を見る）。
  円の半径は `cas` から作った `mag`（0〜3）で決まり、**数値の無い作戦は基準の大きさで描いて隠さない**。
- ⚠⚠⚠ **層が描く窓を `span` にした**（ビルドが `from`/`to` と記録の両端から**導出**する）。
  これで「出荷されているのに到達できない行」が構造的に作れなくなった。外へは最大 120 日（検査⑩）。
- ⚠⚠⚠ **検査⑪ — 線が去ったあと何が残るかを言う責任。** 1年以上どの戦線にも切られない期間で
  `control` だけが国の色を決めているなら、**その期間の内側の control 照合を1つ以上**要求する。
  該当は16件で、15件は単に書かれていなかっただけ、**1件がフランス**だった。
- **各大戦が自分の照合表 `checks` を持てるようにした**（2つのラウンドが同じ配列を編集しなくて済む）。
- **出典を1本にした。** 層の attribution も凡例の最終行も `data.src` を読む。手書きの写しは消し、
  出典ページ（`js/reference-data.js` ＋ `pages.*.js` 9言語）に**記録そのものの行を足した**。

### 7. 実測した副産物（このラウンドの外・別件として起票した）

⚠ **タイムマシンを 1939 → 1916 と戻すと、地図のラベルが 1939 のままになる。** 1916年の地図に

### 追記（本番検証）— **本番検証が、全ゲート緑のまま2つ見つけた**

merge・deploy のあと `intmap-prod-verifier` を本番（`d382913`）に当てた。ビルド印・2本の行・
既定 OFF・`ww1-src` が作られないこと・スライダーと再生が主時計を動かさないこと・9種の種別・
195/313 件の作戦・兵力と死傷の表示——**測ったものはすべて主張どおり**だった。そのうえで、
**ローカルのどのゲートも捉えていなかった欠陥が2つ**出た。どちらも #R409 が持ち込んだものである。

### 1. 作戦の点をクリックすると、その下の国のカードが開く

`GE().events.onLayer('click', …)` は **「最前面が勝つ」ではない**——`js/geo-engine.js` の素の
`m.on(event, layer, cb)` である。だから1クリックで `onEvent`（作戦）と `onArea`（国）の**両方**が
走り、**後から `show()` したほうが相手のポップアップを `remove()` する**。

実測（本番・クルスク 1943-07-05・点の実座標をクリック）:

```
クリック前:  queryRenderedFeatures(点, {layers:['ww2-evt']}) = 1
クリック後:  .plc-popup = 「Russia (Soviet Union) / 1943-07-05 / Allies」
             .war-pop-k 無し · .war-pop-n 0件 · <a> 0件（Wikipedia リンク無し）
MutationObserver: 1クリックにつき ポップアップ要素の挿入が 2件
```

⚠ **作戦の点はほとんどが支配域の上にある。** したがって、このラウンドが足した
「種別・投入兵力・死傷・Wikipedia」のカードは、**下に塗りの無い海戦以外、事実上すべて到達不能**
だった（マタパン岬沖海戦のカードは正しく開いた——それが海の上だから）。

答えはエンジンに既にあった。**#R210 が `claimClick` / `clickClaimed` をこのために作っており**
（「地図上の他のものをクリックした際は、その下にある地名ラベルを同時にクリックした判定になる」）、
`js/war-layer.js` は**一度も使っていなかった**（grep 0件）。claim は **DOM イベントの同一性**なので
古びず、しかも**2つのリスナがどちらの順で走っても作戦が勝つ**。

### 2. 凡例が 900px の窓の上端から外へ出ていた

箱は 579px。**単独で開く試験では 1080px にも 900px にも収まる。** だが本番は
**海底ケーブルの凡例（193px）を既定で開いており**、凡例は下端から上へ積む。

| 窓の高さ | `#data-legend-ww2` の y | 高さ | 切れる量 |
|---|---|---|---|
| 1080 | 156 | 581 | 0 |
| **900** | **−22** | 579 | **22 px** |
| **768** | **−98** | 523 | **98 px** |

親の `#map-container` は `overflow-y:hidden` なので、**上へ出た分はスクロールでも出せない**——
落ちたのは閉じる×・題名・不透明度行、つまり箱を閉じる手段そのものだった。
⇒ 上限を viewport 相対にし、**別の凡例1枚とこの箱自身の制御 ~200px の分を引く**。
実測 900 → **501px**、768 → **369px**。

⚠ **残りは隠さずに書いた。** 大戦2つ＋3枚目の凡例は、まだ 900px を越える。これは
`.data-legend` に**デスクトップの高さ上限がそもそも無い**という枠組みの性質で（モバイルには
#R215 からある）、背の高い凡例が3枚あれば何でも起きる。このラウンドが負っていたのは
**自分ひとりで溢れる層でないこと**であって、枠組みを作り直すことではない。

### なぜローカルで捕まらなかったか

- **クリックの経路を突く検査が1本も無かった。** 面・線・点・ラベルが「描かれているか」は測って
  いたが、「**クリックしたら何が開くか**」は測っていなかった。⇒ `tests/smoke.spec.js` が
  クルスクの点をクリックし、**作戦のカードが開くこと**（種別があり Wikipedia リンクがあること）を
  測るようになった。
- **凡例の高さは「単独で開く」試験しか無かった。** 本番の既定は凡例が1枚開いている状態である。
  ⇒ `tests/r409-checks ⑱` が、上限が**viewport 相対で、かつ別の凡例の分を引いている**ことを測る。

⚠ **未コミットのまま変異テストをして、`git checkout` で自分の修正を2度消した。** 変異させて赤を
見る手順は正しいが、**その前に commit する**。
⚠ **絶対日付を書いた表明は、その前後のブロックの順序を測っていた。** smoke のスライダー検査が
`'1942-02-03'` を固定で持っていたので、クリック検査を上に足した瞬間に**測っている内容と無関係な
理由で**赤くなった。⇒ 「動かした日数ぶんだけ動く」という**相対の表明**に直した。
