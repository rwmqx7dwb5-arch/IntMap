## R399 — **番人が見ていたのは「手書きの2文書の、最初の1文」だった**

報告は小さい。`docs/FILES.md` §3.12 が `supabase/` の欄で **「⚠ Edge Function は全11本をここに宣言する」**
と **「Edge Functions（9本。§6.2）」** と書き、`functions/_shared/` の中身を5本だけ並べていた。

ディスクを数えた:

| 訊いたもの | 実測 |
|---|---|
| `supabase/functions/*/`（`_shared` を除く） | **12** |
| `supabase/config.toml` の `[functions.*]` | **12**（一致） |
| `supabase/functions/_shared/*.js` | **8** |
| `supabase/migrations/*.sql` | 13（`docs/FILES.md` の記載と一致） |
| `supabase/tests/*_test.sql` | 7（同上） |

数が古いのは症状で、`FILES.md` だけの話でもなかった。**`scripts/doc-facts.mjs` の規則2は、この在庫を
既に照合していた**——だから `CLAUDE.md` は正しかった、というのが依頼の見立てだったが、**そこが違った。**

### 黙っていた理由は3つあり、3つとも「見ていなかった」

```js
for (const f of ['CLAUDE.md', 'Architecture.md']) {          // ①
  const claimed = body.match(/Edge Functions?…\*\*?(\d+)\s*(?:本|函数)/);   // ②③
```

**① 走査する文書名が手書きの2件だった。** `docs/FILES.md` は一度も入っていない。だから台帳の数は
自由に腐ることができた。同じ理由で `SECURITY.md`（「eight」）と `docs/SECURITY-ARCHITECTURE.md`
（「ELEVEN」「all eleven」）は**一度も開かれていない**。

**② needle がリテラルの `*` を必須にしていた。** `\*\*?` は「`*` 1個＋任意の2個目」であって
「`*` 0〜2個」ではない。`CLAUDE.md` の書き方は `**Edge Functions は 12 本**`——**アスタリスクは名詞の
前**にあるので、needle は名詞の**後ろ**でそれを探して常に空を掴んでいた。`claimed` は毎回 null。
**CLAUDE.md の本数は一度も検査されていない。** 合っていたのは、同じブロックの
「全部の名前がバッククォート付きで出てくるか」という**別の**検査が効いていたからで、
**発火しない検査は、通った検査と見分けがつかない。**

**③ `.match()` は最初の1件しか返さない。** `Architecture.md` は §6.2 の見出しで正しい数を名乗る。
そこで満足するので、**§10.1 の2つ目の主張が永久に見えなかった**:

```
4. **Edge Functions を10本デプロイする**（…）：
   for f in ai-proxy delete-account; do …            # 2本
   for f in refresh-news … volcano-feed; do …        # 10本  ← 合わせて12本
```

散文は10と言い、**その真下の一覧は既に12本を回していた。** 一覧を伸ばした人が数を直さず、
番人はそこを見ていなかった。

### 直したもの

規則2を**全現行文書・全出現・数字と英単語の両方**へ広げ、`edge-count`（在庫の数）と
`edge-shared`（`_shared/` の一覧）に分けた。手書きで残した文書名は**正本の `Architecture.md` 1件だけ**で、
しかも「**書いていなければ落ちる**」側に置いてある——needle が読めない形へ書き換えられて黙るのが、
この回で塞いでいる当のものだから。ほかの文書の契約は「**書くなら合っていること**」で、
だから数を書かずに §6.2 へリンクする自由が残る。

`_shared/` は関数ではないので在庫の分母に入らない。**完全を装う一覧**——括弧に囲まれた3本以上の
`.js`——だけを縛り、`など` / `etc.` と断っている一覧は見逃す（`Architecture.md` §6.2 の散文は3本＋
`など` で、あれは嘘ではない）。`CLAUDE.md` の一覧は括弧の形に直した——読める形にしないと縛れない。

**拡張した門を当てたら、報告の3件を含めて10件が落ちた**（6文書）:

| 文書 | 言っていたこと | 実体 |
|---|---|---|
| `docs/FILES.md` | 全11本 / 9本 / `_shared/` 5本 | 12 / 12 / 8 |
| `Architecture.md` §10.1 | 10本デプロイする | 12 |
| `SECURITY.md` | eight Edge Functions | twelve |
| `docs/SECURITY-ARCHITECTURE.md` §5 | ELEVEN / all eleven / `_shared/` 7本 | twelve / all twelve / 8 |
| `CLAUDE.md` §5.1 | `_shared/` 7本（atlas-persona 欠） | 8 |
| `docs/NEWS-EVENTS.md` §12.1 | news-ingest は「9 本目」 | 宙に浮いた序数。落とした |

**数を直しただけなら、6文書のうち5文書は次のラウンドでまた古びる。**

### needle が壊れる向きは両方ある

⚠ **節番号を数と読みかけた。** `### 6.2 Edge Functions` の `6.2` が「2本ある」と読まれ、
**正本が自分を間違いだと報告した。** `(?<![\d.§#])` で塞いだ——節番号・`§`・`#R` は
**住所であって数量ではない。**

⚠ **逆向きも壊せる。** `docs/NEWS-EVENTS.md` §12.1 の「**Edge Function 1 本**（`…/news-ingest/`）」は
**「1本がこれをする」**であって「1本しか無い」ではない。名詞と数字が**助詞なしで隣り合う**形は
在庫の主張として読まない。`の` と `が` を区切りに入れていないのも同じ理由で、
「Edge Function **の** 1 本」は部分の格である。読んでしまう needle は、**正しい文の上で赤を出す。**

### 門を退行させて、検査が赤くなることを実測した

`tests/r399-checks.test.mjs`（①変異4種＋②正本の沈黙＋③逆向き＋④走査の形）。緑を見て終わりにせず、
**門のほうを2通りに壊して、検査が落ちることを確かめた**:

| 門をこう戻すと | 検査は |
|---|---|
| 走査を手書きの2文書に戻す | **① と ④ が RED** |
| `matchAll` を `match`（最初の1件）に戻す | **① と ② が RED** |
| どちらも戻さない（本来の実装） | **4/4 GREEN** |

**変異させて赤を見るまで、検査は完成していない**（#R392 と同じ形）。

⚠ **自分の変更が自分の門に捕まった。** 検査ファイルを1本足したので `docs/TESTING.md` の
`**N Node test files**` が 200 → 201 になり、`node-tests` 規則が即座に落とした。これは正しい動作で、
**この回が直しているのと同じ仕組みが、同じ回のうちに働いた**。

⚠ **残**: `Architecture.md` §15.5 は「検査する事実の一覧は `docs/TESTING.md` の『文書の検査』節が正本」
と書いているが、**その節は存在しない**——規則の表は `DEV-NOTES.md` の履歴の中にしか無い。今回は
触った規則の分だけ `docs/TESTING.md` に節を足した。全規則の表を現行文書へ起こすのは別の仕事。
