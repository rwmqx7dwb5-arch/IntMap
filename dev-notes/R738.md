## R738 — 属性を持つデータになる（第 5 項が丸ごと）と、誰も渡していなかった中止ボタン

〈利用者の指摘（#R729 を読んだもの）のうち、#R732 と #R735 が済ませた 6 項を除いた残り——
**第 5 項（Shapefile / GeoPackage・統計表の結合・計算列・列の型と単位・属性の編集と取り消し）**と、
`docs/GIS-CORE.md` §6 が「やらないこと」として申告していたもののうち構造で直せるもの。
残したものは §11 に、なぜ残したかと一緒に書いた〉

### 1. ⚠⚠⚠ 3 つの拒否は、正直な断りから「読めるものを読んでいない」に変わっていた

`js/geo-import.js` は 3 つのものを断っていた。書かれた時点ではどれも正しい断りである
（読み手が無いときに「対応していない形式です」と言うより、**何であるかを名指す**ほうが良い）。
問題は、断りが**そのまま残っていた**ことのほうである。

- **ZIP の中の `.shp`** — 「Shapefile はまだ対応していません」。⇒ `js/gis-shapefile.js`。
- **GeoPackage** — `js/` に綴りが 1 つも無かった。⇒ `js/gis-geopackage.js`。
- **座標を持たない表** — `no-coordinate-columns` で**取り込みごと**断っていた。⇒ `format:'table'`。

3 つ目が一番重い。利用者が求めたのは「行政界＋市区町村コード付き CSV → 統計値を結合」で、
**その結合の右側がレジストリに入る経路が無かった**。左側（境界）は入るのに、右側（数の表）は
入口で断られる——だから結合の op を書いても入力が存在しない。

⚠ **拒否を実装に変えるときの作法**（#R732 の教訓）: `tests/r576-checks` ③⑨ は「統計表は拒否される」
「Shapefile は名前で断られる」を測っていた。**消さずに、主張のほうを測り直した**——③ は
**「1 行も座標を与えられていない」**（元の拒否が守っていた危険は「1 行 1 ピンでギニア湾に落ちる」
ことであって、「表が読めること」ではない）、⑨ は**「shapefile の読み手が答え、何が壊れているかを
名指した」**。⚠ 検査を消すだけにすると、それは**見るのをやめた回**になる。

### 1b. Shapefile と GeoPackage で、静かに壊れる場所

- ⚠ **環の向きが、外と穴を分ける唯一の区別である。** 「parts が 2 つ以上なら 2 つ目以降は穴」と
  読むと、**飛び地が穴になる**（島嶼を持つ自治体が全部そうなる）。符号付き面積で読む。
- ⚠ **Z を座標の第 3 成分に入れない。** `js/geodesy.js` の `sanitizeFeatures` が第 3 成分を畳むので
  登録に届かない（#R735 が同じ実測で GPX の標高を隣へ移している）。`_z` に並行配列で運ぶ。
- ⚠ **`.dbf` の値は文字列のまま返す。** 型づけは `IntMapData.typeColumn` の仕事で、**2 か所に
  型づけ規則を持つと必ず離れる**（`docs/GIS-CORE.md` §1.1）。例外は `D` 型（`YYYYMMDD`）だけ——
  そのまま渡すと `20200304` が**数**になり、日付の列が数値列として集計される。
- ⚠ **GeoPackage は SQLite なので、オーバーフローページの鎖を実装しないと大きな幾何が黙って
  切れる。** 3,000 頂点の幾何が鎖をまたぐ fixture を検査が持ち、鎖を無視する変異でそこだけが赤くなる
  ことを確かめた。⚠ 依存は 1 つも足していない（sql.js は入れていない。**読むだけなら仕様どおりに
  読める**）。
- ⚠ **どちらも「表が複数あったら黙って 1 つ目を選ぶ」をしない。** どれを読むかは読者が決めることで、
  黙って選ぶのはこのリポジトリが繰り返し記録している欠陥の形である。

### 2. ⚠⚠⚠ `.prj` が、2 ラウンド呼び出し元の無かった規則の最初の客になった

`js/gis-crs.js` の `define()`——「読者が持参した WKT または proj 文字列」——は #R732 で作られ、
**`js/` と `tests/` を通じて呼び出し元が 0 件**だった。規則は在り、**渡せる経路が無かった**
（memory「完成した配線が通電しているかは、配線を描く門からは見えない」）。

Shapefile の `.prj` がその文字列である。⚠ **変換の前に、コードが既知かどうかに関わらず登録する**
——`EPSG:6675`（JGD2000 平面直角座標系）のような国の座標系は proj4 の内蔵表が知らないが、
**ファイル自身が定義を持っている**。ファイル自身の申告を優先するのは、GeoJSON の `crs` メンバが
既に受けている扱いと同じ規則である。

⚠ **AUTHORITY を述べない `.prj` に EPSG 番号を発明しない。** `PRJ:<基底名>` という
**定義そのものの名前**で登録する。`sourceCrs` は「そのファイルが何であったか」を述べる欄なので、
そこに推測を入れると `docs/GIS-CORE.md` §1 の「`null` は名乗っていないであって 4326 ではない」が
崩れる。

### 3. ⚠⚠⚠ `join` が結ぶのは識別子であって数ではない

この層の他の比較は全部 `asNumber` を通る——**量を比べているから**である。結合が比べるのは
**符号**で、両者は**まさに問題になるセルで別の答えを返す**:

> `"01100"`（札幌市中央区）と `"1100"` は、**1 つの数で 2 つの場所**である。

#R735 が「十進の記法に無意味な先頭ゼロは無いので、それが付いているセルは識別子を綴ったもの」を
入れたのはこの土台のためで、ここがその読み手である。数として比べれば、札幌市中央区の統計が
**隣の自治体に付く**——そして出来上がるのは**完全に見える表**で、どこにも誤りが無い。

⚠ **一致した件数・しなかった件数・相手を見つけなかった鍵の実例を、答えとして返す。**
同じ市区町村コードを違う綴りで書いた 2 ファイルは、**構造的には完璧で情報の無い結合**を作る。
読者がそれに気づく方法は、「何行が相手を見つけたか」を告げられること以外に無い。

⚠ **同じ鍵が右側に 2 度あれば拒む**（`duplicates:'first'` と述べれば通る）。黙って 1 つ選ぶことも、
黙って行を増やすことも、**読者が見ていないデータで行数が決まる**ことを意味する。
⚠ **列名がぶつかれば拒む**（`prefix` が読者の答え）。上書きは画面に出ているデータを壊し、
ここで改名すれば**誰も知らない名前**を発明することになる。

### 4. ⚠⚠ 式は解釈されるのであって評価されない

`js/gis-expr.js` は自前のトークナイザと再帰下降パーサで、**`eval` も `new Function` も使わない**
（CSP のためだけではない——読者の打った文字列が任意のコードになる経路を作らない）。

- ⚠ **空は 0 ではなく伝播する。** `1 + null` は `null`。0 にすると、埋まっていない列を平均した
  読者が**小さすぎる答えを黙って受け取る**（このリポジトリが繰り返し記録している「少し小さい数」）。
  欠損を 0 として扱いたい読者には `coalesce(x,0)` が在る＝**読者が述べる**。
- ⚠ **先頭ゼロのセルは算術に入らない。** そしてその規則を**写さない**——`IntMapData` に訊く。
  写せば、パネルでは比較できて式ではできない列ができる。
- ⚠ **`'a' + 1` は連結ではなく `expr-type`。** 黙って連結すると、数の列と文字の列を足した結果が
  「動く」ので、読者はその列を合計しようとして初めて気づく。連結は `concat` が在る。
- ⚠ **式が名指す列はデータセットに対して検査する**（`filter` の条件と同じ規則）。綴り違いを
  「null の列」で答えると、**何も描かれない地図とエラーの無い画面**になる。

### 5. ⚠⚠⚠ 属性の編集で本体になるのは、何を拒むかである

`js/gis-datasets.js` に `editValues` / `addField` / `removeField` / `renameField` / `undo` / `redo` が
入った。実装として難しいところは無い。**難しいのは、読者が当然できると思う操作のうち、黙って
破壊的なものを断ること**である。

- **op の出力は編集しない**（`edit-would-contradict-recipe`）。その記録の地物は**自分のレシピが
  出すもの**であり、編集すると `setParams` の再計算が**読者の編集を黙って消す**。
  同時に「結果を保存しないのはレシピがあれば再生できるから」（§4）も偽になる。
- **下流のある列は消さない・改名しない**（`field-has-dependents`）。その列を読んでいるレシピが
  再実行できなくなり、**そのとき列はもう戻せない**。`invalidate` で済ませると、再実行が
  「古い答え」ではなく「拒否」を返す。
- **`time` の宣言が名指す列も同じ**（`field-in-time-axis`）。無い列を名指す宣言は §1.5 が防いでいる
  形そのものである。

⚠ **型の宣言は実データに対して検証する**（`field-type-refused` に件数と実例）。⚠ **単位は検証
できない**——`km` と書かれた列が km である保証はどこにも無いので、`unitStated` で**誰が述べたか**を
持つ。測ったことにしない。⚠ **測定値の型は宣言で上書きしない**（「測ると text・読者が number と
宣言」が区別できる）。

⚠ **履歴は逆操作**（どの行のどの列が何だったか）で持つ。4 万件の表を 20 回編集して地物の
スナップショットを 20 枚積めば、取り消しの機能そのものがメモリを食い尽くす。

### 6. ⚠⚠⚠ `accepts:'any'` は「どんな形でも」であって「形が無くてもよい」ではない

統計表は `geometry:null` の行として入る。そして `geometryType` は、**表でも・空のデータセットでも・
格子でも `null`** ——1 つの欄が分けられない 3 つである。だから `js/gis-datasets.js` が
`withGeometry` を**測り**、**幾何カーネルか測地を要する op**（宣言で判る）は
`input-has-no-geometry` で拒む。

これが無ければ buffer は全行を歩き、座標を 1 つも見つけず、**空の面のレイヤーを登録する**
——成功した処理・0 件の答え・そして**入力に場所が無かったことを述べるものがどこにも無い**状態。

⚠ **判定は op の名前の一覧ではなく、op 自身の宣言である。** `filter`・`timeWindow`・`join`・
`compute` はどちらも宣言しないので**表の上で動き続ける**。それが表を取り込める理由そのものである。

### 7. ⚠⚠ 属性値による着色 — 欠損は 0 の色ではない

- ⚠ **数かどうかを自分で判定しない**（`IntMapData` に訊く）。`"01100"` は数ではない。
- ⚠ **欠損は専用の色**で描き、件数を凡例に出す。0 の色で塗れば、読者は**空欄を最小値として読む**。
- ⚠ **色より多い分類を捨てない。** 「その他」に畳み、**畳んだ件数を凡例が述べる**。
- ⚠ **地図と凡例は同じ snapshot**（#R650 の形。別々に計算すると離れる）。
- ⚠ **描かれたレイヤーとデータセットは識別子で結ぶ。** title で結ぶと同じ名前の 2 ファイルで壊れる。
- そして **`registerDataset()` の `catch(_){}` をやめた**。地図のレイヤーは失わないまま、
  「地図には出たが分析には使えない」ことが**読者に見える**。

### 8. ⚠⚠⚠ #R735 が作った中止と進捗に、呼び出し元が 1 件も無かった

`run(step, {signal, onProgress})` は #R735 が作り、検査し、`docs/GIS-CORE.md` §2.6 に書いた。
**プログラムの中でそれを渡していたのは、その検査だけ**だった——`js/gis-panel.js` も
`js/gis-project.js` も第 2 引数なしで呼んでいた。

つまり:

- #R735 が「取り除いた」と書いた**固まったタブは、鎖の再計算では固まったままだった**。
- パネルが描けたはずの中止ボタンは、**効果のない操作**になるはずだった。

⇒ `setParams(id, params, opts)` と `load(id, opts)` が signal と進捗を運ぶ。進捗は
`{step, steps, id, op, done, total}`＝**鎖のどこか＋その中のどこか**（前者はこの層にしか判らず、
後者は op にしか判らない）。

⚠ **中止は取り消しではない。** 既に commit された段は残る——その地物は**新しい引数の答えである**。
止まるのは残りで、それらは失敗と**同じ**規則で `stale` になる（「計算し直していない」は、読者が
止めても op が断っても、その記録について同じ事実である）。

⚠ **中止はレコードを外す前に訊く。** 外した後で気づけば、同じことを言うために snapshot を
戻さなければならない。

### 9. ⚠⚠⚠ 門の母集合が、足された読み手を見ていなかった

「返しうる拒否コードは全部、読者向けの文を持つ」を測る検査が 2 本ある
（`tests/r729-gis-core-checks` ④ と `tests/r576-checks` ⑩）。どちらも**ソースを走査**して
`why: '…'` と `fail('…')` という**綴り**を集める。

この回に足した 4 つのモジュールは、どれも**構築子経由**で拒否を作る
（`mk(...)` / `no(...)` / `bad(...)`）。だから走査は**1 本も見つけなかった**——
`js/gis-expr.js` の 9 本・`js/gis-datasets.js` の 25 本・`js/gis-shapefile.js` の 7 本・
`js/gis-geopackage.js` の 15 本が、**門が緑のまま**読者に文の無いコードとして届くところだった。

⚠ **走査は教わった綴りを測り、宣言は事実を測る。** ⇒ 各モジュールが `REFUSALS` を宣言し、
**その構築子が未宣言のコードを拒む**（宣言と throw が離れられない）。検査は宣言を読む。

そしてその 1 手で、**この回のものではない欠陥**が出た:

> **#R735 が入れた `timeRefused` の 9 コードには、文が 1 つも無かった。**
> `timeRefused` 自体が**パネルにも地図にも出ていなかった**（`grep` で 0 件）——時間軸を宣言して
> 拒まれた読者は、**何も告げられず**、あとで `timeWindow` に `time-not-declared` と言われるだけ
> だった。

⚠ これは #R735 の実装の欠陥ではなく、**門の母集合の欠陥**である
（memory「母集合を広げたら針を測り直す」）。母集合が決めているのは、その門が**何を見られないか**である。

### 10. 検査

`tests/r737-gis-attributes-checks.test.mjs` が測るのは**連鎖**である。利用者が挙げた完成条件は
どちらも一続きの作業で、**個々の機能の検査では測れない**のがまさにそこだった:

1. 統計表が取り込め、**1 行も座標を与えられていない**
2. `join` が識別子で結び（`"1100"` は `"01100"` ではない）、件数を答える
3. `compute` が式の列を作り、綴り違いの列を拒む
4. **行政界＋コード付き CSV → 結合 → 計算列 → その列は number なので段階着色できる**
5. **道路 500 m → 区域別集計 → 保存 → 復元 → 距離だけ変更 → 下流まで更新**（そして
   拒まれる半径では鎖が**その場に残って印がつく**）
6. 中止と進捗が**呼び出し元から本当に届く**（§8 が直したもの）
7. 表は「形を測る処理」に渡らず、そうでない処理では動く

各モジュールの検査（shapefile・geopackage・expr・edits・style）は**バイト列を自分で組み立てる**
——バイナリ資産をリポジトリに足していない。GeoPackage の検査は SQLite を検査の中で符号化し、
**9 種の変異**でそれぞれが本当に噛むことを確かめた（オーバーフロー分割を無視する変異は 1 本だけを
赤くし、複数表を黙って先頭採用する変異も別の 1 本だけを赤くする）。

### 11. 残したもの（`docs/GIS-CORE.md` §6 が正本）

- **Worker**。#R735 が書いたとおり、足りないのは**並列性**であって応答性ではない。
  この層が呼ぶカーネルは全部このスレッドに居るので、ループだけ移せば呼べるものが無い。
- **分割読み込み**。`features()` は保持している配列を返す。取り込める大きさは今も
  「メモリに載るか」で決まる。
- **GeoTIFF の汎用の入口と、格子の再投影・再標本化**。⚠ ベクタは実際に再投影するので、
  この穴は**格子だけ**である。
- **解析用の座標系の選択**。`crs` は常に 4326、面積も距離も測地の km 固定。
- **Atlas から処理を走らせる経路**。`data.query` は取り込んだデータセットを**読める**が、
  `IntMapGisOps` を Atlas 側から呼ぶ経路は 1 件も無い——buffer や zonal を**依頼**できない。
  ⚠ これは #R733 が測った形（能力が在るのに模型に渡っていない）と同じ場所に居る。
