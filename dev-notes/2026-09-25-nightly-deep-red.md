## 1. ⚠⚠⚠ Overpass に締め切りが無く、利用者も数分待たされていた

夜間の実測: Overpass の 3 ミラーがそれぞれ **12 秒・102 秒・93 秒後に 504**。経路（`js/routing-ops.js`）と
ドローンの飛行前準備（`js/drone-ops.js` の飛行禁止区域チェック）は締め切りなしに 3 ミラーを順に試すので、
合計 207 秒以上止まり、テストは「Overpass が使えないなら飛ばす」判定まで届かなかった。**同じ形の実装が
12 ファイルに散っていた**（締め切り無し・ミラー 1 つだけ・並走・CORS 中継つき、とそれぞれ違う形）。
⇒ `js/overpass.js` の `overpassQuery` 1 つにまとめ、ミラーの一覧を持つのはここだけにした。
- 予算は問い合わせ自身が書く `[timeout:N]` ＋ 5 秒（`BODY_SLACK_MS`。観測: overpass-api.de は 955 KB を
  本文だけで 0.95 秒）。呼び手は下げられるが上げられない。1 ミラーの持ち分は予算÷ミラー数で、過ぎたら
  **別のサーバを並走**させる（同じ要求の二度目ではない——`.agents/rules/one-pass-or-a-reason.md` §5）。
- 504・429・JSON でない本文・`remark` の runtime error は即座に次へ。全部だめなら `OverpassUnavailable`
  （各ミラーで何が起きたか `attempts`）を投げ、**空の `elements` は正常な答え**——「照合できなかった」と
  「何も無い」を同じ答えにしない。
- 実測（Overpass を全部固めた一時 spec。測ったあと削除）: 経路は 65.1 秒で `err:'overpass'`、ドローンの
  `prepare()` は 42.7 秒で「照合できませんでした」（`nofly-data`）。修正前は 207 秒以上。
- 形: `import` にすると `new Function` で評価する既存の node 検査が 22 件落ちたので、7 本は
  `window.IntMapOverpass` 経由（`js/nominatim-gate.js` と同じ形。`src/main.js` に 1 行）、4 本は ES import。
- `tests/r217-checks` ②b・`tests/r254-checks` はミラーの**綴り**を固定していて「一覧は 1 か所」と矛盾したので、
  守っている事実（IntMapOverpass を使う・race で並走する）で測る形にした。

- ⚠ 新しい window グローバル **`IntMapOverpass`**（`check:surface` の基線に 1 行）と、起動時のモジュールが **302 → 304**（`js/overpass.js` と、それが import する `js/fetch-deadline.js` が起動時のチャンクに入った。`check:perf` の modules を 304 に）。7 本の呼び手が window 経由で読むので、呼ばれる前に居る必要がある。
