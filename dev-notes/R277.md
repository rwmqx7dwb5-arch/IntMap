## R277 — **「漏れが多すぎる」は 373 区域だった／中国を省で塗っていた／警報名が8言語のまま並んでいた**

> 「地形編集・水流で地形のポップアップで、ツールは上部に一行でスティックしろ。」
> 「気象警報はまだ対応していない国は灰色斜線で、発令されていないだけの地域は灰色に。」
> 「水流シミュレーションで、一回きりのやつで、1クリックの水量m³注水量m³/s流量の違いが判らない。
>   何が何かわからない。」
> 「警報レイヤー、日本以外でも区分単位、発令単位ごとに色分けしろ。正確にリアルタイムな情報に基づき
>   正確で忠実な色分けを。あと、漏れが多すぎる。また、対応国も増やせ。更新が遅すぎる。リアルタイムに
>   と言っている。警報名は設定言語で書け。」

4件のうち3件は #R275 と**ほとんど同じ文**だった。索引の常設教訓
（[[intmap-r271-lessons]]「同じ文が再送されたら、前回直した面ではない面を測れ」）どおり、
**まず #R275 の修正が効いているかを測った——4件とも効いていた。効いていない面が別にあった。**
そして今回は**新しい語**が3つ混ざっていた：「**一行で**」「**漏れが多すぎる**」「**警報名は設定言語で**」。

### ⚠⚠⚠ ①「漏れが多すぎる」——数えたら 373 区域

MeteoAlarm の35か国を同じ分に読み、公表区域と配置できた区域を数えた：

```
TOTAL placed 754 / 1127
AUT 30/116   ESP 93/157   SVK 0/59    MDA 0/42    POL 202/223  PRT 0/18
HRV 0/13     LTU 0/11     SRB 0/11    BIH 0/10    GRC 6/16     BEL 0/9
HUN 0/7      MNE 0/3      FIN 5/8     ITA 18/20   NLD 7/9      CYP 0/1
```

**33% が地図に出ていなかった。** 原因は1つで、**MeteoAlarm の CAP はそれらにポリゴンを持たない**
（`<geocode>` は `EMMA_ID` が1つだけ）——そして区域名が**その機関自身の呼び名**であって、
突き合わせ先の Eurostat NUTS の名前ではない：

```
Rijeka region [HR006]      Wien Brigittenau      Košice okolie [SK122]
Meseta cacereña [ES200]    Banja Luka [BA003]    Mazowieckie Province Przysuski County [PL1423]
```

**形は存在する。同じ機関が、この relay がすでに読んでいる WMO の登録簿に出している。**
実測、mem 006（GeoSphere Austria）は 164 行・**109 の区域名**に本物の `<polygon>` を持っていて、
その名前は MeteoAlarm が名乗る語彙そのもの（「Lienz」「Graz-Umgebung」「Leoben」）。

→ **形を4段のはしごで探す**（`maFeatures` / `askSwicGeo`）：

| 段 | 出どころ | 効いた国 |
|---|---|---|
| ① | CAP 自身の `<polygon>` | 英・蘭 |
| ② | **同じ機関が WMO 登録簿に出している形**（relay `?swicgeo=<mid>`） | 墺・斯洛伐克・西・波・塞・波黒・克・希 |
| ③ | Eurostat NUTS 2/3 | 伊・仏・独 |
| ④ | 国境そのもの（**区域名が国名のときだけ**） | 塞浦路斯 |

**実測 754 → 965 / 1,127。** ビルド済みページの全フィード合計では **3,096 / 3,264（94.9%）**。

⚠ **② は「第2の警報ソース」ではない。** `?swicgeo=` が返すのは **区域名と形だけ**で、
event も severity も時刻も入っていない。何が発令中かは今もその国のフィードが答えるので、
「ソースは一国一ソース」は保たれる。パネルの出典表記も変わらない。
⚠ **② は有効期限で絞らない。** 警報は期限切れになるが、その警報を描いた郡は期限切れにならない。
期限で絞った索引は「今日の天気と同じだけ完全」になり、索引の意味が無くなる。
⚠ 座標は**小数4桁（約 11 m）**に丸める。実測、オーストリアの生データ 1.5 MB → 要約 1.07 MB。

**残った 168 は国ごとに「置けた数／公表数」を言葉で印字する**（丸めない）。
モルドバ 42 と ポルトガル 17 が最大で、どちらも **WMO 登録簿にも1行も無い**——
IPMA の distrito も SHM の raion も、CORS の開いた公開境界データに存在しない。
**測って、残して、言葉で言う。**

### ⚠⚠⚠ ② 中国は 1,235 件のうち 300 件を、28 の「省」に塗っていた

`alertid` の上6桁は **GB/T 2260 の行政区画コード**で、`36073341600000` の `360733` は**会昌県**。
つまり「江西省贛州市会昌県気象台発布大風藍色預警信号」は**1つの県の大風警報**で、それが
江西省 167,000 km² を塗っていた。しかも `pageSize=300` を1回しか読んでいなかった（実測 count 1,235）。

→ 全ページ（1,000 件／リクエスト、`count` を読んで最大2ページ）＋ **コードで引く**：
**区・県（6桁） → 地級市（4桁+00） → 省（2桁+0000）**、最初に見つかったもの。境界は
DataV.GeoAtlas の `100000_full_city.json`（477 地級市・3.7 MB）と `100000_full.json`（省・0.57 MB）。
実測 **1,000/1,000 配置・223 区画**（149 が区・県、849 が地級市、**2 が省**——その2件は本当に
「江西省気象台」「黒龍江省気象台」が出した省域の警報）。

⚠ **`www.nmc.cn` はエッジから断続的に落ちる。** 実測、同じ分に 45 秒 × 2 回とも timeout（＝90,127 ms で
502）した一方、上がっているときは 0.9〜1.5 秒で返る。**ページの大きさとは無関係**。
relay の retry ループは `!r` で回っていて、`fetchGuarded` が **5xx を「解決」で返す**ため
**失敗ステータスは一度も再試行されていなかった**（`!(r && r.ok)` に）。

### ⚠⚠⚠ ③「発表なし」の灰色を、答えていない機関にも塗っていた

上の CMA の 502 が捕まえたのはそれ自体ではなく、**その隣**だった：`washTier` は
`readState(c)==='loading'` だけを斜線にしていたので、**`error` と `idle` は灰色**になる。
つまり上流が落ちた瞬間、**1,235 件が発令中の中国が「発表なし」の灰色**になっていた。
これは #R212 の「現在出てるのに、何も発令されてないと出てくる」と同じ欠陥の1段隣である。

→ **`ok` 以外はすべて斜線**。斜線は「この地図はこの国について何も述べていない」で、
**どの沈黙なのか**（未対応／順番待ち／取得不可）は、押した地点のカードが**言葉で**言う。

### ⚠⚠⚠ ④ 国全体の灰色が、発令中の区域の**上**に乗っていた

実測、ビルド済みページで `wp-alert-fill` が style index **34**、`wp-alert-choro` が **39**。
`ensureLayers()`（区域）も `ensureChoro()`（国の薄塗り・斜線）も `before` を指定しておらず、
薄塗りは `paintCountries()` の非同期の続きから作られるので**後から**着地する。
つまり **42% の灰色が、その国の発令中の区域の上に乗っていた**——そして
どちらが勝つかは**その回の Promise の着地順**で決まっていた。決まった答えより悪い。

→ `ensureChoro()` は `wp-alert-fill` を**名前で** `before` に指定する。灰色は「読んだうえで何も無い」で、
**発令中の場所で読み手が見る色にはなり得ない**。

### ⚠⚠⚠ ⑤「警報名は設定言語で書け」

1つの画面に、実測でこれだけ並んでいた：

```
Thunderstormwarning (墺)   ORAGE (象牙海岸)   STARKES GEWITTER (独)   Mye regn (諾)
Baixa Umidade (伯)   降雨 (台)   大风蓝色 (中)   大雨 (日)   ارتفاع درجات الحرارة
```

8言語3文字体系。→ `HAZ`（**25 の災害** × 各機関が実際に書く語のパターン）が分類し、`L()` が
設定言語で名前を出す。

⚠ **勝つのは「一番早く一致した」パターンであって、表の先頭ではない。** 先頭語が災害で残りは限定だから：
「Strong Wind and Large Waves」は wind、「雷雨大风」は thunderstorm、「rain-flood」は rain。
同着は表の順で決め、それが「VENT DE SABLE」（風の語が位置0にある砂嵐）を dust に入れる。
⚠ **機関の言葉は捨てず、並べる。** 地物は `hzr`（機関自身の表記）を持ち、押した地点のカードが
**「訳語（原語）」**の形で両方出す。表に無い語は**訳さずそのまま**出す——プレースホルダに潰すほうが失う。
⚠ **階級は災害名ではない。** 本文が「Yellow Warning」だけの行は災害を名乗っていないので名前に使わない
（旧実装は「Moderate Heat Related Impact」を地図に描いていた）。
⚠ 言語を切り替えると `relabel()` が **取得し直さずに描き直す**。

### ⚠⚠⚠ ⑥「更新が遅すぎる」(3回目) ——`busy` をラッチにすると、一番遅い国が次の tick を決める

#R275 は止まっていた輪番を輪番にし、**1リクエスト6か国 × 2本 / 30 秒**＝35 か国を約 90 秒で一周に置いた。
relay のエッジキャッシュは **60 秒**なので、それより速く聞いても同じバイトが返るだけ——
**60 秒が床で、90 秒はその上**だった。3本にして 35 か国 / 60 秒に合わせたところ、
**最古が 108 秒まで伸びた**（2本のときより悪い）。

原因は `maBusy` が `Promise.all(batches)` 全体を1つの真偽値で守っていたこと。
MeteoAlarm の1か国は最大 10 MB の上流取得なので、1本でも 30 秒を超えると**次の tick が丸ごと空振り**する。

→ `maBusy` / `swicBusy` は**飛んでいるバッチの数**（上限 `MA_CALLS` / `SWIC_CALLS`）。遅い1本は3枠のうち
1枠を占めるだけで、残り2枠が輪番を回し続ける。`maPend` / `swicPend` が「いま飛んでいる国」を持ち、
2つの枠が同じ国を取るのを防ぐ。⚠ `maAt` は**完了時にだけ**書く——先に書くと停止が隠れる。

実測（30 秒 tick）、冷えた初回一周で 109 秒まで上がったあと、**最古は 42〜57 秒**で振れる。

### ⚠⚠⚠ ⑦「1クリックの水量 m³／注水量 m³/s／流量 m³/s」——後ろ2つは同じ数だった

コードを読めば1行で決着する：

```js
sources.push({… rate:(flowM3s!=null ? flowM3s : pourRate)});   // placeSource
const srcRate=(x)=>Math.max(1, +x.rate || pourRate);            // 読む側
```

**「注水量」と「流量」は1つの量**で、後者が前者を上書きし、ついでに置いてある水源全部の `rate` も
書き換えていた。区別のつかない2つの操作子を前に「何が何かわからない」のは**読み手の問題ではない**。
#R275 は**モデル**を1つにした（「どちらも流量を持つ蛇口で、違うのは `cap` だけ」）が、**パネルは3箱のまま**だった。

→ パネルをモデルにする：**速さ1つ**（`pourRate`。`setRate()` が唯一の書き手で、置いてある水源すべてに
届く。Atlas の `setFlow()` も同じ関数）と、1回きりだけが持つ**総量**（`srcM3`）。
2つは**種類の違う数**（m³ は量、m³/s は速さ）なので取り違えようがなく、さらに
**パネルが割り算を自分でする**：

> 1クリックで合計 1,000,000 m³ を、毎秒 20,000 m³ の速さで出します（シミュレーション時間で約 50 秒）。
> 出し切ったら止まります。

継続では総量の箱ごと消え、「止めるまでその速さで出し続けます（合計に上限はありません）」と書く。

⚠ **この文の鍵は静的な文字列でなければならない。** `L('One click pours '+n(srcM3)+…)` は
**英語の引数を自分で組み立てる**——そして6言語目以降（fr / ko / 中文）の索引は
**英語の文字列で引く**ので、組み立てた鍵は永久に一致せず、静かに英語で出る。
`{v}` / `{r}` / `{t}` を後から差し替える形にした。⚠ **`npm run check:i18n` はこれを見つけられない**
（鍵が静的でないので、そもそも計器の宇宙に入らない）。

測っていなかった。ピン留めするのは**切替**であって、設定は流れてよい。

→ `.tw-tools` は `grid-template-columns:repeat(4,1fr)` の**1行 46.7 px**、中身は選択1つだけ。

### ⚠ 索引側の接頭辞一致

`lookupUnit()` は**問い合わせ側**を短くしていくだけだったので、「Antwerp」は「Prov. Antwerpen」を、
「Viseu」は「Viseu Dão Lafões」を見つけられなかった。→ **索引の鍵が問い合わせで始まる**場合も見る。
⚠ **一意に決まるときだけ。** 二つに当たる語幹はコイン投げで、**違う区域に警報を描くのは描かないより悪い**。
あわせて `_alias()` が先頭の行政語（`Prov.` / `Région de` / `Landkreis` …）を外した形と、
`A; B; C` の各要素も索引に入れる。実測、ベルギー 0/9 → 7/9、リトアニア 0/11 → 10/11。

### ⚠⚠⚠ 追記（本番検証）: 表が知らなかった語が 13 あり、そのうち1つは**都市名で埋まっていた**

デプロイ直後の本番で、地図に出ている**121 語**を分類器にかけた。**13 語が何にも解決しなかった**：

```
冰雹橙色 / 冰雹黄色                       → 雹。表に hail が無かった
山洪灾害蓝色 / 山洪风险黄色 …（5語）      → 山洪＝flash flood。パターンに 山洪 が無かった
Major Fire Impact                         → wildfire。`(forest|wild|…) ?fire` に素の Fire が無い
awareness_type=5, awareness_level=2 …（3）→ MeteoAlarm 自身の awareness_type コードが event 本文
Yellow Warning                            → 正しい。階級だけで災害を名乗っていない
```

`awareness_type` は EMMA の公表コード（1 風・2 雪氷・3 雷・4 霧・5 高温・6 低温・7 沿岸・
8 森林火災・9 なだれ・10 雨・12 雨と洪水・13 雹）なので、各災害のパターンにその番号を足した。

⚠⚠ **そこで踏んだ罠が2つある。**
1. `['wind',` は **JMA のコード表**（`'15':['wind',20]`）にも出てくるので、挿入位置をファイル頭から
   探すと**そちら**に解決し、`awareness_type=1` が **tsunami のパターン**に入った。
   → 挿入は `HAZ` ブロックの中だけで探す。`tests/r277 ⑪` が「tsunami に awareness コードが
   乗っていないこと」を検査する。
2. `\bfire\b` は **「Wildfire」に一致しない**（語の内側の fire の前に境界が無い）。→ `fire\b`。

### ⚠⚠⚠ 追記2（本番検証）: CORS が開いていることと「本番のオリジンから読める」ことは別

本番の警報パネルが `PLACED.CHN = [0, 1217]`——**中国が1区画も描かれていない**。ローカルでは 223 区画
描けていた。原因は CSP でも CORS でもなく、**DataV.GeoAtlas の hotlink 対策**だった。
実測、同じ秒・同じ URL で：

```
Referer: http://127.0.0.1:4277/                       → 200 / 569 KB
Referer: https://rwmqx7dwb5-arch.github.io/IntMap/    → 403
（Referer 無し、Origin だけ                            → 200）
```

`Access-Control-Allow-Origin: *` は返ってくる。**CORS は開いていて、Referer で閉じている。**
そして**ローカルのプレビューではこれが見えない**——127.0.0.1 は許されている側だから。

→ **relay 経由で読む**（relay は Referer を送らない）。`?cngeo=<adcode>[_full[_city]]` は名前を
**形で**検証し（パスではない）、境界データなので**1日**のエッジキャッシュ。
実測、本番のページから 200 / 0.56 MB と 3.69 MB、`?cngeo=../evil` は 400。

⚠ **教訓は「本番でしか出ない欠陥」ではなく、「ローカルが特別扱いされている」こと。** 127.0.0.1 は
許可リストに入っていることが多い（開発の便宜）ので、**新しいホストを足したら本番のオリジンから叩く**。
この round は他に4つのホストを足しており（gisco / g0v / smartnews-smri / supabase）、本番から
叩いたら 200・200・200・200 だった。**叩いて確かめたから、1つだけ 403 だと分かった。**

### ⚠⚠⚠ 追記: 災害名の英語は、その災害だけの鍵でなければならない

雹を `L('Hail','雹',…)` と書いた。**そして 'Hail' は4つの表すべてに既にあった**——
`js/time-borders.js` の `LA('Hail','ハーイル',…)`、サウジアラビアの**都市** حائل として。
実測 fr《Haïl》/ ko《하일》/ 中文《哈伊勒》。

**欠落は 0、未翻訳も 0、`npm run check:i18n` は緑。** それでも地図は3つの言語で
**都市名を災害として**印字するところだった。6言語目以降の索引は**英語の文字列で引く**からである。

同じ検査を全26災害に広げたら、5つが同じ形だった：`Wind`（風／風力）・`Fog`（霧）・`Snow`（雪）・
`Heavy rain`（強い雨）・`Thunderstorm`（雷雨）。どれも**意味は同じ**で害は無かったが、
**鍵が借り物である以上いつでも 'Hail' になりうる**。→ 災害側は自分の鍵を持つ：
`Strong wind` / `Dense fog` / `Heavy snow` / `Heavy rainfall` / `Thunderstorms` / `Hailstorm`。

`tests/r277 ⑩` は**その規則**を検査する——「1つの英語の鍵が2つの意味を持たない」。
`js/` 全体の `L(…)` / `LA(…)` を走査し、同じ英語で**違う日本語**を渡している箇所を1つでも見つけたら
