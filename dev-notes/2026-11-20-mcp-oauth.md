〈依頼〉 MCP を実用的な外部サービス接続へ。OAuth によるアカウント連携、サービスごとの権限・接続状態、実 MCP サーバとの継続接続、Tasks、更新通知、外部データの成果物への取り込み、Atlas が接続ツールを選べること。資格情報は共通基盤で扱い、追跡対象に秘密を書かない。実際に 1 件以上の実サーバへ接続して実測する。

## 0. 着手時点の事実

「MCP が無い」は誤り。#1277（サーバ）はマージ済み、#1279（クライアント）と #1304（2026-07-28 仕様対応・#1279 を含む）は未マージ（#1304 は CI 緑・auto-merge 待ち）。この PR は #1304 の先頭を土台にし、#1304 が squash merge されれば差分はこの主題だけになる。足りなかったのは **認証（Bearer の手貼りだけ）** と **実サービスでの実測**。Tasks（`resultType:'task'`・`tasks/get`・cancel・MRTR）は #1304 で実装済みで、ここでは触っていない。

## 1. 実測（2026-11-20・`scripts/mcp-real-probe.mjs`）

- **deepwiki**（`https://mcp.deepwiki.com/mcp`）・**context7**（`https://mcp.context7.com/mcp`）: どちらも**サインイン不要・2026-07-28 の無状態**。`server/discover` → `tools/list`（3 件・2 件、各約 1.2 秒）→ 読み取り専用ツールの実行に成功（deepwiki の `read_wiki_structure` 1,594 字・946 ms、context7 の `resolve-library-id` 1,814 字・1,508 ms）。両方とも `tools.listChanged:false` を宣言——**更新通知の実受信は実サーバでは測れず、モックだけ**。
- **Linear・Notion・Sentry**: 未認証で 401 + `resource_metadata`。保護リソースメタデータ → 認可サーバメタデータ（S256 対応）→ **動的クライアント登録まで実サーバで成功**（各サービスに使い捨ての公開クライアントが 1 つずつ登録された）→ 認可 URL を生成。**サインイン本体は利用者本人のアカウントが要るので未実測**（Linear・Notion・Sentry にこちらのアカウントは無い）。
- **CORS（curl で `Origin: https://rwmqx7dwb5-arch.github.io`）**: Linear・Notion は `/register`・`/token`・メタデータへ、Sentry はメタデータへ同オリジンを許可。⇒ OAuth はブラウザから直通で足り、リレーを通す必要が無い。

## 2. 作ったもの

- `js/atlas-mcp-oauth.js`（新・純関数）: 発見（RFC 9728 → 8414/OpenID）、公開クライアント登録（RFC 7591）、PKCE S256・`state`・`resource`（RFC 8707）、コード交換・更新・失効（RFC 7009）。**呼ぶエンドポイントは発行元と同じサイトだけ**（`oauth_endpoint_mismatch`）。PKCE を出さない認可サーバは拒否。
- `js/atlas-mcp-client.js`: サーバ記録に `oauth`・`enabled`。接続状態（`connected`/`needs_sign_in`/`disabled`/`none`・スコープ・期限）を**トークン抜きで**返す。期限の 1 分前と 401 で 1 回更新（refresh token の回転に備え 1 サーバ 1 本の単一飛行）、拒否されたら `needs_sign_in`（一時的な通信失敗では印を付けない）。`authorize`/`beginOAuth`/`finishOAuth`/`disconnect`/`setEnabled`/`watch`/`importableOf`/`pageSignInIo`。
- `mcp-oauth-callback.html`（新）: サービスの戻り先。クエリを同一オリジンの opener（無ければ BroadcastChannel）へ渡して閉じるだけで、保存も通信もしない。コード交換は PKCE の verifier を持つ IntMap 側だけが行う。
- `mcp.connect` に `authorize`/`disconnect`/`enable`/`disable`。新しい能力の行は足していない（能力数は 256 のまま）。`mcp.servers` が接続状態を出す。
- **更新通知**: 2026-07-28 の `subscriptions/listen` を直通で開き、`notifications/tools/list_changed` でツール一覧を古い扱いにする（`tools.listChanged` 宣言サーバだけ・リレーでは不可と理由を返す・5 回まで間隔を伸ばして再接続）。
- **取り込み**: 成功した結果が GeoJSON／レコード配列／CSV なら会話の添付台帳へ `external` で残す。データスタジオ（`tableToMap`）と `attach.recall` が同じ名前で読む。外部の語なので `carry` は載せず `declare` が名前だけ述べ、`recall` は囲いで包む（読者のファイルを装って次の入力へ入らない）。

## 3. 資格情報の置き場と送り先（共通基盤）

サーバ一覧は `intmap.mcp.servers.v1`（端末内）、**サインインで発行されたトークンは localStorage に書かず**、非抽出 AES-GCM 鍵（IndexedDB）で暗号化した `intmap-mcp-vault` にだけ置く（CodeQL の clear-text-storage 指摘への対応。手で貼ったトークンは従来どおり）。台帳の種別も `preference` から **`credential`** へ直した。送り先は発行元の token エンドポイントと、そのトークンを発行された MCP エンドポイントだけ。リレー経由は CORS を拒否するサーバへの MCP 呼び出しに限り、同じサーバへ転送するだけで保存しない。暗号化はディスク上の写しや localStorage の持ち出しを防ぐもので、ページ内で動くスクリプト（XSS）には効かない。リポジトリには鍵も資格情報も書いていない。

## 4. 検査

`tests/mcp-oauth-checks.test.mjs`（13 件・モック認可サーバ+MCP）: 401→サインイン→トークン使用、PKCE/`state`/`resource`/スコープ、偽 `state` は本物の試行を止めない・拒否は終了、期限切れの更新と単一飛行、401 での更新→失敗時の再サインイン要求、失効と消去、サイト外エンドポイント・PKCE 無し・登録不可・コールバック無しの拒否、無効化、リスン通知で 1 回だけ再読込、中継では監視不可、取り込みと台帳の除外・囲い。

## 5. できていないこと

- Linear・Notion・Sentry への**実サインインは未実測**（本人のアカウントが要る）。登録とメタデータの実測まで。
- 更新通知の受信は**モックのみ**（実サーバは `listChanged:false`）。
- 手で貼ったトークンは従来どおり平文。旧 HTTP+SSE のサーバは話さない。
- Atlas の選択は従来の `find_capability` の語彙検索（接続済みサーバのツールを名前と説明で探す）のまま。
