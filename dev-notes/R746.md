## R746 — 時計が「1m60s」と表示していた（#R744 の本番検証が実測）

〈#R744 の production verification。本番 3 ターン・DOM 標本 651 件〉

### 1. 実測

```
1m58s → 1m59s → 1m60s → 2m00s
                ^^^^^^ そんな時刻は無い
```

`js/atlas-progress.js` の `fmtMs` が、**同じ 1 つの量を 2 回丸めて**いた——分は
`Math.floor(n / 60000)`、秒は `Math.round((n % 60000) / 1000)`。119,500〜119,999 ms では
**分が 1・秒が 60** になる。⚠ **競合でも稀でもなく、毎分 0.5 秒ずつ必ず**起きる
（見出しは 250 ms ごとに塗り直されるので、その窓は 2 回描かれる）。同じ割れ方が境界の手前で
**「60.0s」**も出していた（`n < 60000` の枝が 59.95〜59.99 秒を 60.0 と丸める）。

### 2. 直したもの

**丸めるのは 1 回。** 秒に丸めてから分と秒へ割る。2 つの数のあいだで桁上がりが落ちる余地が、
数が 1 つなら存在しない。小数第 1 位の形の境界も 60,000 → **59,950 ms** にした
（そこは「60.0s」と書こうとしていた点で、答えは既に 1 分である）。

### 3. 検査 — `tests/r746-atlas-clock-rounding-checks.test.mjs`（3 本）

⚠ **述べているのは出力の性質であって、到達した答え（「1 回だけ丸める」）ではない**
（[[intmap-restate-the-defect-not-the-fix]]）:

- ① **存在しない時刻を印字しない**——0〜5 分の全境界の前後 ±1.2 秒を **10 ms 刻み**で掃く。
- ② **自分が名乗る精度より真値から離れない**——① だけなら「常に 0m00s」でも満たせる。
- ③ **時計が逆走しない**——① ② はどちらも**列**を見ないので、境界で戻る時計を見つけられない。

⚠ `fmtMs` は private のままにした（検査のためだけの export は `tests/r175` ③ が禁じる）。
`Date.now()` を動かして `done()` に塗らせる＝**読者の画面が塗られるのと同じ経路**で訊いている。
