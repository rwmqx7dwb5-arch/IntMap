## R749 — 格子は計算できたが、見ることができなかった

〈外部評価が指した 6 項目を、まず**今日の `main` で**確かめた回。⚠ **2 つは既に済んでいた**——
`union` が離れた領域を落とす件・距離検索が高緯度で取りこぼす件・カーネルの `null` 二義性は
**#R743** が直しており、「Atlas から `IntMapGisOps` を呼ぶ経路が 1 件も無い」も同じラウンドの
`js/gis-atlas.js` が埋めていた。評価の対象は 5 コミット前の `146dd47` だった。
⚠ ただし `docs/GIS-CORE.md` §6 は**その両方を「やらないこと」として掲げたまま**で、
`npm run check:docs` はそれを見ていなかった——**古い否定文は、否定されたあとも門から見えない。**〉

### 1. ⚠⚠⚠ ラスターの処理は、鎖の一歩ではなく鎖の終わりだった

`js/gis-core.js` の `draw()`:

```js
if (ds.kind === 'raster') return { ok:false, why:'draw-needs-features', … };
```

#R735 のこの 1 行は、**格子を置く先が無かったビルドでは正しかった**（例外を click の中で投げるより
名指しで断るほうがよい）。正しくなくなったのは、同じラウンドが ops に格子を**作らせた**瞬間である。
差分・条件抽出・レイヤーを焼いた格子——どれも計算でき、どれも見られなかった。

⇒ **エンジンが既に持っている動的画像に載せた。** `GE().layers.addDynamicImage` は
`js/tsunami.js` と `js/night-side.js` が描いている canvas source で、**両方のレンダラが実装している**。
ここで `addSource` を書けば「画素を地図に置く」3 つ目の綴りになり、**片方のレンダラでしか動かない**
——#R739 が Globe で測った「`draw()` が `ok:true` を返し、地図には何も無い」がその形である。

⚠ **行はエンジンに訊く。** canvas source は 4 隅で置かれ、テクスチャは**メルカトルの Y で**
線形補間される。緯度を等間隔に歩いて塗った格子は箱の中央で最大にずれる（#R195 の実測で
6.3°N–70.3°N の箱の中央が **8.05° ≈ 895 km**）。`imageRowLatitudes()` はエンジンが
「row r は何度か」に答える扉で、Cesium 側にもある。**列は訊かなくてよい**（メルカトルの X は経度の
一次関数）。

検査の参照は**塗り手の外**に置いた——stub は**どんな等間隔の歩き方でも出ない緯度**を返すので、
その呼び出しを無視した塗り手は偶然にも一致できない。

⚠ **消えた文が 1 つある。** `draw-needs-features` の文（5 言語）は、**そのコードが二度と返らなく**
なったので消した——到達しない拒否に付いた文は #R488 が記録している「死んだ規則が緑のまま残る」形である。
`check:i18n` の床は de/es/ru の positional と zh/zh-hans の inline が **1 行ずつだけ**下がり
（`--update-floor` の差分が他のどの数も動かさないことを確認した）、**読者が見られるものは 1 文字も減っていない**
——同じ画面のその状況で、格子はいま描かれる。

### 2. ⚠ 凡例は、絵を塗ったその集計である

`classifyRaster` は `describeBands()`（バンドを実際に歩いて min/max/欠損数を測る既存の関数）
を受け取り、値そのものは受け取らない。min/max を 2 か所で測れば、ランプと凡例はいつか離れる
（#R650 の形）。塗り手は**画素を数えながら塗り**、その数を凡例に書き戻す——「区分に 1 画素も無い」
「欠損が何画素あったか」は、読者が格子を見ているのか穴を見ているのかを言う唯一の数である。

断るものも 2 つある。**全セルが同じ値**（尺度が無い）と**全セル欠損**は**別のコード**で、
読者の次の行動が違う。分類の着色は**どの値が分類かを述べさせる**——「整数だから分類」は
`.agents/rules/no-ad-hoc-hardcoding.md` が禁じる推測で、メートル単位の標高は整数である。

### 3. ⚠⚠⚠ 2 つの module が、両方とも緑のまま噛み合っていなかった

`js/gis-geotiff.js` と `js/gis-warp.js` は 1 つの書かれた契約に対して並行に実装した。
**契約は実装ではない。**

| | 出していたもの |
|---|---|
| 読み手 | `affine: { x0, y0, dx, dy, rotated }` |
| warp | 6 要素の GeoTransform `[c,a,b,f,d,e]` か `grid:{west,north,pixelLng,pixelLat}` |

**どちらの検査も緑**で、**どちらのモジュールも正しく、落とされた GeoTIFF はその継ぎ目で断られる。**
これは [[intmap-wiring-complete-is-not-wiring-live]] が記録している形そのもので、
**各 module が自分の検査を通ることからは原理的に見えない。**

⇒ 変換器を `affineOf()` に **1 つだけ**置いた。⚠ **回転は行列から読む**——読み手の記述子は
`dx`/`dy` を大きさに畳んでいるので、`rotated:true` と述べながら行列を持たないものは
**断る**（大きさだけで置けば全画素が黙って誤る）。そして検査を 2 本足した: **検査の中で本物の
GeoTIFF のバイトを組み立て**、読み手 → warp → レジストリの契約 → 塗り手へ**通す**。

### 4. ⚠⚠ 「前の作業を再開する」と「以前の結果を再現する」は別の要求である

**⑴ 宣言した列の型と単位が、読み込み直すと消えていた。** `declared` は取り消し履歴と同じ袋にあり、
保存にも入っていなかった。⚠ 取り消しを一時的にするのは正しい——**消してはならないのは宣言のほう**で、
undo はキーストロークだが「この列は人数か、人口密度か」「単位は m か km か」は**データの意味**である。
⇒ 店を分け、保存に入れ、⚠ **戻すときも実データに対して検証する**。データが動いていて成り立たなく
なった宣言は**写さずに断り**、パネルがそう述べる（保存された宣言を無検証で写すのは
`.agents/rules/historical-verification.md` §2 の 3 が禁じる形）。

**⑵ 同じレシピは、実装が違えば同じ答えではない。** `js/gis-project.js` は処理を**段だけ**保存して
再計算する——正しい設計で、帰結が述べられていなかった。#R743 が `union` と距離のふるいの
**答えそのもの**を変えたので、**その前に保存されたプロジェクトは今日ひらくと違う数を持つ**。
記録には版が無く、述べようがなかった。

⇒ カーネルが版を持ち（`version()`）、op の段がそれを運び、読み込みは
**「同じ」「違う」「測れなかった」の 3 つ**を区別して返す（`engineChanged` / `engineUnknown`）。
⚠ **再計算は止めない**（読者のプロジェクトを開けなくするのは過剰）。⚠ **測れなかったものを
「同じ」に畳まない**——「読めなかった」を「同じ」の証拠に使う形は、この記録が何度も捕まえている。

⚠ **そして、手で保つ版は最初の 1 回で腐る。腐った版は版が無いより悪い**——変わったエンジンについて
「同じです」と読者に述べるから。⇒ 台帳 `scripts/gis-kernel-versions.mjs` がカーネルの sha256 を
版と並べて持ち、**バイトが動いて版が動いていなければ門が落ちる**。門が落ちたときの正直な直し方は
2 つしか無く、**そのどちらかを選ぶこと自体がこの門の目的**である（答えが変わりうる編集なら版を上げる、
変わりえない編集ならハッシュだけ記録する）。⚠ ハッシュは**改行を正規化してから**取る——
門の判定が走者の性質になる形は [[intmap-gate-verdict-must-not-depend-on-the-runner]] が実測している。

### 5. ⚠⚠⚠ 「全世界の矩形を渡した」ことと「全件取得した」ことは同義ではない

`js/gis-layers.js` は**描画器が持っているものを分析へ取り出す**橋だった。取り出せたものが
世界についての答えなのか、いま画面に載っているものについての答えなのかを、**橋は述べていなかった**
——だから読者にも Atlas にも区別がつかなかった。

`js/gis-sources.js` は取得に `coverage` を必ず付ける：
`completeness`（`all` / `partial` / `sample`）と**理由**・求めた範囲・答えた範囲・件数・時点・解像度。

⚠ **`all` は推測からは届かない。** レンダラが 400 機を持っていることは、外から見て
「世界の一覧」とも「いまの視野ぶんを取ってきた」とも区別がつかない。だから測れないものは
`partial` と理由を述べる——「知らない」を「全部だ」の代わりにしない
（[[intmap-coverage-counted-is-not-coverage-seen]] が件数について記録しているのと同じ形）。

⚠ **結果として、今日 `all` を述べられる供給元は取り込んだファイルだけである**
（ファイルが復号した地物が全部そこに在り、それは視野ではない）。内蔵レイヤーは 1 つも述べていない
——**これはこの層の欠陥ではなく、アプリの真の状態が初めて述べられた結果**である。

⚠ 付随して、`region()` は「レイヤーがオフ ⇒ 値が無い」を**全行についての事実として断つのをやめた**
（1 点試し、数が返れば読む。返らなければ `layer-not-visible` で断る）。

### 6. 残っていること

- **Worker はまだ無い。** 重い処理は中止でき進捗を述べフレームごとに譲るが、走るのはメインスレッド
  （⚠ ここで足りないのは並列性であって応答性ではない）。**分割読み込みも無い。**
- **GeoTIFF の overviews は数えるだけ**で読まない。BigTIFF・JPEG-in-TIFF・1/4 bit は名前付きの拒否。
- **内蔵レイヤーが自分の完全性を宣言していない**（§5）。世界の一覧を丸ごと持っている module が
  `IntMapGisSources.declare()` を呼べば、そのレイヤーについての解析は `all` を名乗れる。
- **PlanarConfiguration 2 の TIFF** は読めるはずのものを断っている（strip/tile 表の一般化が要る）。
