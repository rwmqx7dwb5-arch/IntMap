## R446 — **記事リーダーの第2手段は「遅い」のではなく、構造上ぜったいに成功しない経路だった**

> #R442 の調査中に見つかった別件。「`js/article-reader.js` の Strategy 2 は必ず失敗するのではないか」
> ——**まず観測してから直すこと**、という依頼。観測した結果、**必ず失敗する**が確認され、
> **それを隠していた 2 つ目の欠陥**が同じ関数の第1手段に見つかった。

### 何が起きていたか（本番で実測。2026-08-25・`https://rwmqx7dwb5-arch.github.io`）

`fetchReadable()` は 2 段構えである。第1段は `r.jina.ai` の Markdown、第2段は
`HOST.fetchViaProxy(item.link)` で記事ページの **HTML** を取り、`DOMParser` で
`<article>` / `<p>` / `og:description` を抜く。

**`js/proxy-fetch.js` は RSS/Atom しか「答え」と認めていなかった**——唯一の受理条件が
`isFeed(txt)` ＝ `<rss` か `<feed` を含むこと。記事ページの HTML はそれを満たさない。

その日の一面から実在の記事 2 本を、出荷中の ladder そのままで測った:

| 中継 | 応答 | 判定 |
|---|---|---|
| `proxy.corsfix.com` | 403（`{"corsfix_error":"domain_not_registered"}`・314 B） | 986 ms / 320 ms |
| `corsproxy.io` | **200 · `text/html` · 217,509 B**（dw.com の記事本体） | **「not feed」で破棄** 3,362 ms |
| `corsproxy.io` | **200 · `text/html` · 198,238 B**（aljazeera.com の記事本体） | **「not feed」で破棄** 1,087 ms |
| `api.allorigins.win` | 8 s の締切で abort | — |
| `api.codetabs.com` | 8 s の締切で abort | — |

race が全滅したあと bounded fallback が **同じページをもう一度取り**（HTTP キャッシュから
8 ms / 21 ms）、**もう一度捨てた**。

**合計 20,313 ms と 20,355 ms、戻り値は 2 回とも `null`。**
記事は届いていた。2 回届いて、2 回捨てられていた。

### ⚠⚠⚠ なぜ誰も気づかなかったか——第1段が「上流のエラーページ」で成功していた

`window.IntMapModules.articleReader` を本番のページ上で組み立て、`openArticleInSidebar()` を
実際に走らせて端から端まで測った（Read ボタンは #R11 以来この経路を呼んでいないので、
UI からは到達できない。#R169・#R430 の記録どおり）:

```
Strategy 1  r.jina.ai  200 · text/plain · 572 B · 5,826 ms
            「Markdown Content:」の中身 = DW 自身のエラー境界
              ## Something went wrong.
              We have been notified and are looking into it.
            （その上に jina 自身の警告「This page maybe requiring CAPTCHA」）
Strategy 2  一度も走らない
render      mode:'reader' / blocks:2 / ok:true / 総計 6,508 ms
```

**`txt.length > 200`（572）も `parsed.blocks.length >= 2`（2 ブロック）も通る。**
つまりリーダーは、**他人のエラーメッセージを記事本文として描く**状態で出荷されていた——
依頼文が Strategy 2 について警告していたのと**まったく同じ失敗が、Strategy 1 で既に起きていた**。

そしてこれが第2の欠陥を隠していた: 第1段が「成功」する限り第2段は走らないので、
**第2段が構造上成功できないことは一度も画面に出なかった。**

### 直したこと

**① `js/proxy-fetch.js` に「HTML を認める形」を足した（`opts.as`）。**
「何でも通す」にはしない。#R216 が `news-relay` で「interstitial は feed ではない」を 502 にした
のと同じ規律で、`as:'html'` が受理するのは**エラーページではない HTML 文書**だけ:

- **HTML 文書を名乗る**（`<!doctype html` / `<html`）——これが中継各社の **JSON エラー封筒**
  （実測 314 B）をそのまま落とす。
- **`HTML_MIN_BYTES` 以上**——実測、中継や遮断ページは 314 B / **2,041 B**（#R216 が測った
  Google の「Sorry…」）/ 7,594 B。実在の記事は 198,238 B と 217,509 B。
- **呼び手が読む標識を持つ**（`<p>` か description の meta）。どちらも無い文書は 1 ブロックも
  産めないので、受理は「空の答え」を返すことにしかならない。

⚠ **「この中に記事があるか」は呼び手の問いであり、この述語は答えない。** 呼び手は既に
その判定を持っている（40 字超の段落が 2 つ、無ければ `og:description`、それも無ければ
`ok:false` で埋め込み表示へ）。ここが答えるのは「ページか、それとも中継の詫び状か」だけ。
非 2xx の形はそもそもここまで来ない——実測、上の失敗はすべて 403 / 404 / 530 で返っている。

**② `opts.budgetMs` ——ladder 全体の上限。** 以前の下限は「8 秒の race ＋最大 4 本 × 6 秒の再試行」
で、実測 20.3 s かけて `null` を返していた。各試行の締切は**呼び手が名乗った残り時間**を超えない
（`Math.min(PROXY_TIMEOUT_MS, left())`）ので、3 秒の予算が 8 秒の試行に付き合うことはない。
既定は `BUDGET_MS`（20 s）で、ニュース取得側の呼び出しは 1 バイトも変えていない。

**③ `js/article-reader.js` に 1 つの上限と 1 つの床。**
`READER_BUDGET_MS` が両段あわせての上限で、第2段には**第1段が残した分**を渡す（残りが無ければ
第2段を行わない）。最悪 12 s + 20.3 s = 32 s だった spinner が、**20 s で必ず終わる**。
`MIN_ARTICLE_CHARS` は第1段の床——実測、あのエラー境界は markdown で **79 文字**、実在記事は
リード文だけで数百文字（同じ秒に測った aljazeera の抽出は 10,678 B）。
⚠ 第2段側の「40 字超の段落が 2 つ」は**わざと触っていない**。同じ問いの呼び手側の半分で、
そちらは元から正しく働いていた。

### ⚠ 直していないこと（判断であって、漏れではない）

**サイドバー内リーダーは今も UI から到達できない。** `.btn-read` は #R11 以来
`window.open(item.link)` で発信元サイトを開く。#R169 と #R430 はこれを**製品の判断**として
明示的に据え置いており、配線し直すのは今回の依頼の範囲外である。したがって本ラウンドが直したのは
**「呼ばれたときに壊れている」であって「呼ばれるようになった」ではない**。
到達経路は残っている——`js/news-events.js` が同じ面（`enterReaderPane()`）を使い、Atlas は
`window._imReader.body` から本文を読む（#R118）。

### 検査（`tests/r446-checks.test.mjs` · 6 本）

⚠ **grep ではなく出荷モジュールを動かしている。** `js/proxy-fetch.js` は export 1 本・DOM 無し・
`window` は try/catch なので、ブラウザが下す判定をそのまま node で下せる。`fetch` を差し替え、
4 本の中継に**実測した形の本文**を答えさせる。

1. `as:'html'` は記事ページを返し、**既定（feed）は同じ本文を今までどおり捨てる**（#R446 以前の
   挙動を、仮定ではなく性質として書いた）。
2. 200 で返る **JSON エラー封筒**・**interstitial**・**段落も description も無い殻**は、
   3 つとも `null`。1 本が落ちても次の中継が勝てることも測る。
3. 全中継が無応答のとき、`budgetMs` の中で終わり、**4 本とも race には出る**（予算は近道ではない）。
4. `js/article-reader.js` が `{as:'html',budgetMs:left}` で呼ぶこと、引数なしの呼び出しが
   消えていること。
5. 床が **79 < floor <= 400** の中にあること（測った数を検査が持つ）。
6. `news-relay` の注記から「呼び手はどうせ記事 HTML を捨てる」という**期限切れの一文**が
   消えていること。守っている当の保証（2 endpoint の allow-list）は無傷であることも同時に。

⚠ 4 と 6 は `codeOnly()` 越しに読む——**この検査ファイル自身の散文が針に当たらないように**（#R345）。
