## R376 — **本番検証が4件見つけた。リポジトリは最後まで自分と整合していた**

#R356 は複数予報モデルの基盤を出荷し、**門はすべて緑だった**——ノード検査 **2,236 / 2,236**、
ブラウザ 48 / 48、CI、CodeQL。そのあと本番で実際に触ってみて、**4件の欠陥が出た。**

**4件とも、リポジトリを自分自身と突き合わせる検査には原理的に見えない形だった。**
どれも「このリポジトリが持っている2つのもの」の食い違いで、**どちらの半分も単独では正しい**。

---

### ① Atlas は、成功したモデル切替を失敗として報告していた

本番実測、3モデル・3回とも:

```
IntMapOS.execute('data.wxModel', {layer:'ec-temp', model:'dwd_icon'})
  → status:"partial"  code:"not_rendered"  ok:false
     observed.paint = {poly:-1, line:-1, pins:-1, poi:-1, visible:0, objects:0}
```

**その 2.5 秒後の実際の状態は、全部 ICON になっていた**——凡例 `DWD ICON · 13 km · run 23 Aug,
12:00 UTC`、ピッカー `dwd_icon`、`modelOf('ec-temp')` = `"dwd_icon"`、style の source url も
`…/dwd_icon/…`。**画素比較でも 3.08% が変化し、変化域は地図領域だけ。**

原因は `data.wxModel` の観測器を `paint` と宣言していたこと。`paintNow()` が数えるのは
**描かれた地物**（Atlas 自身のクエリ源・可視レイヤー数・オブジェクト数）で、
**ラスタのソースを差し替えても、描かれる地物の数は前と同じ**である。`visible:0` はその帰結。

⚠ **これは「やっていない成功を主張する」のと同じ欠陥を、裏返しにしたものである。**
答えを信じた呼び出し側は、**動いている機能を信用しなくなる**。#R318 の
「`ok` は `status` からの導出であって主張ではない」が効いていたので、
**隠れずに嘘として出てきた**——そして直すべき場所は嘘のある側、つまり観測器のほうだった。

⇒ 観測器 **`wxModel`** を新設した。`IntMapWeatherEC.modelOf(id)` を全気象レイヤーについて読み、
**「この呼び出しが名指したレイヤーが、この呼び出しが求めたモデルを表示しているか」**を見る。
⚠ **dispatch の返り値を信じるのではない。** `setModel` は `commit()` でしか解決しないので
`raw` にも真実はあるが、`raw` だけを読む verifier は監査 ⑰ が禁じている形である。
観測器は**別の情報源**（モジュールが表示していると答えるもの）から取る。

⚠ 監査の表 2 つ（`OBSERVABLE` と `MAP_OBS`）にも登録が要った。登録しないと ⑦ と ⑱ が落ちる
——それが「地図を約束する能力が、地図を見られない観測器を持つ」ことを止めている仕組みで、
**新しい観測器を足すときに正しく赤くなった。**

### ② 続けて2回切り替えると、1回目が `not_painted_yet` を返した

本番で1回だけ観測。`whenCommitted` の待ち行列が、**次に来た commit なら何であれ全員を起こして**
いた。ICON への切替が飛んでいる間に GFS へ切り替えると、**ICON の commit が GFS の待ち手を
ICON の来歴で解決**し、`p.modelId !== 'ncep_gfs013'` で「まだ塗られていない」になる。
その4秒後には GFS が出ていた。

⇒ **比較を外すのが直しではない。** 比較こそが「他人の絵を自分の答えとして受け取らない」ための
ものである。間違っていたのは、**一致しない commit が待ち手を<b>消費して</b>しまう**ことだった。
待ち手は自分のモデルが来るまで**行列に残る**（あるいは時間切れになる）。

---

### ③ カーソルの数値だけが、既定モデルを読み続けていた

`js/map-readout.js` は `window.IntMapECMWF`——**既定インスタンス**——から `valueNow` /
`legend` / `validTime` / `bandNear` / `load` を取っていた。#R356 がレイヤーごとにモデルを
与えたあとも、そこは変わっていない。

つまり **ICON に切り替えたレイヤーの上で、ICON のタイルを見ながら、ECMWF の数値と
ECMWF の有効時刻が印字されていた。**

⚠⚠ **何も壊れて見えない。** もっともらしい気温は、目に見えて間違った気温ではない。
だから「地図・粒子・凡例・地点値が同じ表示状態を参照」は**好みではなく規則**なのである。

⇒ `IntMapWeatherEC.engineFor(id)` を公開し、読み出しは**そのレイヤーが読んでいるインスタンス**を
取る。⚠ 既定へフォールバックする——気象レイヤーでない id や、多モデルエンジンが無いビルドでも、
以前と同じ場を読めなければならない。検査は `window.IntMapECMWF` の出現が
**`ecFor` の中のフォールバック 1 回だけ**であることを数える。

### ④ 起動時に3モデルすべてが作られていた

本番実測: 気象レイヤーを1枚も点けていないのに `IntMapWxEngine.open()` が
`["ecmwf_ifs","ncep_gfs013","dwd_icon"]`。生成のスタックを取ると、凡例のピッカーが
**レイヤーが OFF でも**全モデルに `availability()` を訊いており、その入口が `model()`
——**無ければ作る**ほう——だった。

⚠ **通信は 1 本も起きていない**（metadata は `meta()` を呼んだときだけ取られる。実測 706 ms /
576 ms、どちらも私が §3 で呼んだ瞬間）。だから代金はオブジェクトであってバイトではない。
**それでも直す理由は、`js/wx-ecmwf.js` 自身のコメントが「モデルを切り替えないセッションは
ちょうど1つだけ作る」と書いており、それが真でなくなっていたことである。**

⇒ `IntMapWxEngine.peek(id)` ——**作らない**参照——を足し、`availFor` と `pruneMissing` は
そちらを使う。
⚠ **ただし peek だけにすると、ピッカーは「この変数は無い」と言えなくなる**（metadata が無ければ
`no_metadata` で、無効化しないのが正しい）。本番実測で**まさにそうだった**——海面気圧の凡例で
GFS が無効に見えたのは、私の検証スクリプトが先に GFS の metadata を取っていたからで、
**素のセッションでは無効になっていなかった**。
⇒ **凡例が実際に描かれたとき**に、提供モデルの `latest.json` を 1 回だけ暖める（3 kB × 2、
`IntMapWx` の同じキャッシュ経由）。気象凡例を開かないセッションは**今も 1 バイトも取らない**。

### この4件の共通の形

**どれも「2つのものの食い違い」で、どちらの半分も自分の側では正しかった。**

| | 半分A（正しい） | 半分B（正しい） | 食い違い |
|---|---|---|---|
| ① | `paint` は地物を数える | ラスタ差し替えは地物を変えない | 観測器が能力を見られない |
| ② | 待ち手はモデルを照合する | commit は待ち手を起こす | 照合前に消費される |
| ③ | 読み出しは既定を読む | レイヤーはモデルを持つ | 既定＝そのレイヤー、ではない |
| ④ | ピッカーは可用性を訊く | `model()` は無ければ作る | 訊くことが作ることになる |

**リポジトリを自分自身と比べる検査は、4件とも緑を再現し続ける**（#R333 が同じことを別の形で
測っている）。捕まえたのは**生きているサイトに実際に訊いた**ことだけだった。
