## R763 — 表示用に整えた値が、解析へ流れていなかった

〈#R759 に対する外部評価。4 段階の改修案と、現在のコードに対する具体的な指摘が届いた。
**§2〜§9 のすべての主張を、今日の `main`（`3835bdd2`）のコードで確かめてから**着手した。
⚠ **全部成立した。** そのうえで、指摘に無かった欠陥が 3 つ出た（下の §0）。この回は**第一段階と
第二段階**を実装する〉

## 0. 指摘に無かったもの — 確かめたからこそ出た 3 つ

1. **`IntMapGisSources.acquire()` は `js/` から 1 件も呼ばれていなかった。** 指摘は「非同期の本流が
   必要」と述べていたが、**扉はもう在って、呼び手が 0 だった**。`supply()` の呼び手も `adopt()` 1 か所で、
   そこが渡すのは `sync:true` だけ。⇒ 非同期の半分は**配線だけで通電していない**
   （[[intmap-wiring-complete-is-not-wiring-live]]）。
2. **`js/gis-raster.js` は `failed` を `empty` と別に数えている。** 指摘は「失敗と欠損が混ざる」と述べ、
   実際そうだったが、**分ける機構は 1 段下に在った**——`js/gis-sources.js` の `catch → null` が
   その上で潰していたので、`failed` は**構造として常に 0** だった。
3. **GIBS の目盛りは読者が °F を選ぶと °F を返す。** 指摘は単位の消失を述べていたが、その先に
   **表示の好みが解析の数を変える**という別の欠陥があった。

⚠ そして指摘のうち 1 つは**測り方が違っていた**: `rasterOutTime` が「入力中のラスタを全部集める」のは
そのとおりだが、`rasterMask` については**正しく働く**（2 番目が面だから）。誤っているのは `resample`
だけで、**規則の書かれ方ではなく、規則が代理で訊かれていること**が欠陥である（§4）。

## 1. ⚠⚠⚠ 18 行のうち、数を返すものは 0 行だった

点の標本（`sampleAt`）を実装している登録は 18 行。**素の数を返すものは 1 行も無い。**

| 返す形 | 件数 | 例 |
|---|---|---|
| 素の数 | **0** | — |
| 数字だけの文字列 | 1 | `aod`（単位文字列が**たまたま空**） |
| 単位付きの文字列 | 13 | `temp` `sst` `precip` `snow` `no2` `co` `elevation` `annprecip` `gx-*` 5 本 |
| 分類コード・名前・文 | 4 | `wind`（速度＋方位語＋度） `climate`（`Cfa · 温暖湿潤気候`） `choropleth` `thermal` |

`js/gis-datasets.js` の `asNumber` は**セル全体が数でなければ数と認めない**（「12 km」は 12 ではない）。
⇒ **気温も降水も標高も、区域統計に対して `layer-values-not-numeric` を返していた。**
唯一通っていた `aod` が通っていたのは、その単位が空文字だったからである。

⇒ **「区域統計の関数がある」と「内蔵の気温レイヤーで区域統計を実行できる」は別の事実**で、
真だったのは前者だけだった。

### 直したのは分解ではなく契約

`parseFloat` で割り直す道は取らなかった。それでは**単位も、丸める前の桁も、分類コードも、風の 2 成分も**
戻らないし、`「45% (sparse → dense)」` からは数を発明することになる。

- 登録が **`measure(lng,lat)`** で **`{value, unit}`**（数量）または **`{code, label}`**（分類）を述べ、
  `text` が読者に見せる文。**両方が 1 つの値から、1 か所で**作られる。
- ⚠ **新しい一覧は増えていない**——単位は元から `_om()` の kind ごとの分岐に 1 度だけ書かれており、
  この回がしたのは**それを連結で捨てるのをやめた**ことだけである。
- ⚠ **`sampleAt` は置き換えていない。** 文しか作れない行（`thermal`・`choropleth`）は今までどおりで、
  そのことを **`measure` を持たないことで述べる**。どの行が数量を述べるかは登録が決める。
- ⚠ **数量は上流が公表した単位で持つ。** 読者が °F を選んでいても解析の数は °C。変換は表示だけ。

## 2. ⚠⚠⚠ 失敗・欠損・文字列が 1 つのコードに潰れていた

`js/gis-raster.js` は `filled` / `empty` / `failed` を別々に数える。`js/gis-sources.js` の `sampleOne` が
**その 1 段上で例外を `null` に変えていた**ので、`failed` は**構造として常に 0** だった。

⇒ 上流が落ちた窓に対して、読者は `js/gis-panel.js` の**「そのレイヤーは数値ではなく文字列を返す」**を
見る。**海の窓に陸のデータを訊いたときも同じ文**だった。どちらも事実ではない。

- `layer-sample-failed` — 訊いて答えが得られなかった（**待てば直る**）
- `layer-values-all-missing` — どこでも答えたが、値がどこにも無い（**範囲を変える**）
- `layer-values-not-numeric` — 本当に文字列だった（従来どおり）
- ⚠ `failed` と `empty` を**重ならなくした**。投げた画素を両方に数えていたので、**「答えたが値が無かった
  画素」が対から読めなかった**。

## 3. ⚠⚠ 1 点で全体を断じていた

表示がオフのとき、`region()` は**窓の中央 1 画素**を試して、数でなければ窓全体を `layer-not-visible` で
断っていた。**日本を覆う窓の中央は海**である。⇒ 窓の 5 か所（中央と四象限）を試し、**どこも答えない
ときだけ**断る。⚠ 5 は測定値ではない——各象限と中央に 1 点ずつ置く最小の集合で、1 回だけ 5 回払う。

## 4. ⚠⚠⚠ 規則は正しく書かれていて、実装は代理を訊いていた

`rasterOutTime` の註はこう述べている——「**標本が出力に入った入力**が投票する」。
コードが訊いていたのは「**それは格子か**」。2 つは `rasterMask` では一致する（2 番目が面だから、
そして註はまさにその例で推論している）。**`resample` では一致しない。**

```
runResample(a, b):  値は a から読む。b からは格子の形だけ（west/north/pixel/width/height）
DECL.resample:      kinds: ['raster','raster']   ⇒ b は格子 ⇒ b が投票する
```

- 2020 年の a を 2025 年の b の格子へ合わせる → 記録は **2020–2025** を名乗った
- b が時点を述べていない → **a の日付ごと `null` になった**

⇒ **借りただけの入力を述べるのは、走った runner である。** それを知っているのは「`bDs.grid` だけを
読む」と決めたコードだけで、しかもそれは**この run についての陳述**であって op ごとの表ではない
（表にした瞬間、`DECL` は手書きの一覧になる。検査がそれを測る）。
[[intmap-one-predicate-three-dimensions]] と同じ形が、1 つ隣の op で再発していた。

## 5. ⚠⚠ 片方の端では prefix が理解され、もう片方では理解されていなかった

`fieldStatements` は入力の単位を**列名で**引く。`join` は**この app で唯一列名を変える op**。
⇒ `mass`（kg）は `joined_mass`（無単位）になり、派生記録は読者の宣言を拒む
（`edit-would-contradict-recipe`）ので**二度と付かなかった**。

⚠ **同じ関数の 11 行上にある衝突検査は `prefix + n` を見ていた。** 知識は在って、届いていなかった。
⇒ 改名を述べるのは改名した runner。`fieldStatements` は渡されたものを読むだけで、別の op の引数を
推測しない。⚠ **古い名前の陳述は消さない**——左の入力が同名の列を持っていることがあり、それは
出力に残っている。

## 6. ⚠⚠⚠ 演算自身が失った行が、記録に残らなかった

`withGeoStats` は計算できなかった件数を数えて `stats.geometryFailed` で返す。読むのは**そのターンの
画面と応答だけ**。⇒

```
入力は全部 all → buffer で 1,000 行のうち 120 行が計算できない → 残りが登録される
                                                              → その記録の coverage は all のまま
```

系譜を遡っても見つからない——**欠落は上流ではなく、ここで起きている**
（[[intmap-records-with-no-reader]]：数は在って、読む者が居なかった）。

⇒ `coverage.computed = {failed, why}` を足し、`completeness` を `partial`、`reason` を
`op-rows-not-computed`、`from` を **op の id**（どこで失われたか）にする。
⚠ **取得の陳述とは別の欄**——「求めた範囲のうちどこまで取れたか」と「取れたもののうちどこまで
計算できたか」は別の問いで、直し方も別。⚠ **理由の語彙は `js/gis-sources.js` の 1 つ**。
⚠ **入力が 1 つも述べていなくても、run 自身の欠落は述べる**（取り込んだファイルは coverage を持たない）。

## 7. ⚠⚠⚠ #R759 が「次の回の主題」と書いた最後の依存

`docs/GIS-CORE.md` §5.6 はこう書いていた——「表示せずに読み込む扉は今のところ無く、これが
『画面に依存しない取得』に残っている最後の依存である」。

**依存していたのはデータではなく描画だった。** `heritage`・`volcanoes`・`pharma` はどれも同梱文書を
fetch してレンダラのソースへ書くだけで、**fetch に地図は要らない**。しかも `js/layer-packs.js` は
#R311 から**その分け方を持っていた**（「the SECOND door into the module … with no row and no toggle
involved」）。足りなかったのは、それを**取得の層から訊けること**だった。

- 登録が **`load()`** を述べる。`IntMapLayers.loaderOf` が渡し、`supplierFor()` が**非同期の供給元**を作る
- ⚠ **`sync:true` を名乗らせない**——同期の扉がそれを呼ぶと fetch を投げて答えを捨てる
- ⇒ **`acquire()` に呼び手ができた**（§0 の 1）。`acquireDataset()` がその扉で、planner はこちらを使う
- ⚠ **`toDataset()` は同期のまま**。パネルがクリックハンドラから await 無しで呼ぶ出荷済みの契約で、
  対称性のために壊すものではない。**両者は同じ要求を組み立て、同じ登録へ渡す**
- ⚠ **範囲の判定は 1 つ**（`IntMapLayers.narrow`）——loader 経路が自前の判定を持てば、同じ依頼が
  「いま描かれているか」で違う行を返す

### ⚠ どの種類の行かも、描画に訊いていた

`list()` はレンダラの source から id を取る。⇒ 描かれていない行は `grid` に落ち、`acquire()` が
その分類で分岐して**地物の依頼を `region()` へ送り**「幅が無い」と断っていた。
いまは**供給元が地物を渡せるかどうか**で決める。

## 8. ⚠ 下で実装済みのものが、上の語彙から名乗れなかった

`region()` は `time` と `band` を #R752 から受ける。`acquire()` も通す。**`ACQUIRE.raster` に無かった**
ので、planner は `acquire-unknown-field` で断られた。しかも `toRaster()` も渡していなかった。
⇒ 「2020 年と 2025 年のこの範囲を取って同じ格子に合わせる」が**表現できなかった**
（[[intmap-prompt-that-hid-the-tools-in-hand]] の、道具ではなく語彙の版）。
⚠ 1 地点 1 値の供給元に帯を指定したら、**黙って 0 番を返さず** `band-not-selectable` で断る。

## 9. 検査の中に、検査が禁じている形があった

`tests/r759-gis-pipeline-checks` の ① は「`js/gis-atlas.js` が取得語彙の写しを持たないこと」を測る。
**その測定をしている file 自身が、stub の中に写しを持っていた**——`ACQUIRE` に欄を足しても
**このテストは緑のまま通る**。⇒ stub は語彙を**本物の module に訊く**。

## 10. 版

- `js/gis-ops.js` **ops-3 → ops-4**。⚠ **replay した記録が変わる**（`resample` の時点・prefix 付き join の
  単位・落とした行の coverage）。セルの中の数は動かないが、**2 つの日付のどちらを見せるかが変わる**
- `js/gis-raster.js` **raster-1 のまま**。⚠ **診断が変わったのであって答えは変わっていない**——
  `failed` と `empty` を重ならなくしただけで、格子は 1 セルも動かない。**版が測っているのはこの区別**

⚠ **`gis-core` の async chunk の天井を 348.6 kB → 352.7 kB（+4.1 kB）へ上げた。** この層は**遅延読み込み**で
起動費用ではない（`scripts/perf-budget.mjs` の言うとおり async は ceiling only）。上げたのは、増えた分が
この回が足した機能そのものだから——`measure` の契約・loader の供給元・3 つの拒否・coverage の `computed`。
⚠ **起動側（EAGER）の天井は動かしていない**。測定値は +2.9 kB で許容幅の中に収まっており、**比率が
許すからといって天井を上げると、ラチェットは 1 回ずつ上へ滑る**（それを止めるために在る）。
⚠ `--update` は使っていない——全項目を書き直すので、**起動の天井まで黙って上がる**。

## 11. 残っている（第三段階・第四段階）

- **境界画素の部分面積**（`zonal` は今も画素中心で採否を決める。`allTouched` / `fractional` は無い）
- **幾何演算の ctx**（24 op のうち 6 つ——`filter`・`buffer`・`dissolve`・`timeWindow`・`join`・`compute`——に
  中止・進捗が渡っていない。⚠ **そのすぐ上の註は「others … are handed it anyway」と書いており、偽である**）
- **処理全体のメモリ予算**（部分読み込みは在るが、選んだ格子も地物も配列で全部載る）
- **誤差の適用域**（球面近似の妥当な範囲を実測で定める）
- **分析 manifest と確定結果**（保存はレシピ。別の人・別の時点で**同じ結果を再現する**のは別のこと）
