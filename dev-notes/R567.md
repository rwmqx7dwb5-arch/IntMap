## R567 — **世界遺産レイヤー——「すべて」は 1,273 行ではなく 6,009 地点だった**

> 利用者「世界遺産をすべてマッピングしたレイヤーを作って。」

### 「すべて」の意味が、データの形で決まっていた

ユネスコ世界遺産センターは一覧全体を 1 本の XML で公表している（`https://whc.unesco.org/<locale>/list/xml/`）。
216 列・1,273 行。ここまでは「1 行 1 物件」だが、各行は `<geolocations>` を持ち、その中に
**構成資産ごとの `<poi>`** が並んでいる。実測（2026-09-09）:

| | |
|---|---|
| 登録物件 | 1,273（文化 991 / 自然 240 / 複合 42） |
| 構成資産の点 | **6,009** |
| 複数地点を持つ物件 | **484** |
| 座標が 1 つも無い物件 | 3 |

「カルパチア山脈及びヨーロッパ各地のブナ原生林」は **18 か国 93 地点**で 1 件である。
**行ごとに 1 本ピンを立てる実装は、登録されているものの 3 分の 2 を地図から落とす**——
しかも落ちたことが画面から分からない。だから描くのは行ではなく構成資産で、
feature は自分が属する物件 id を持つ。

座標が 1 つも無い 3 件（1567 第一次世界大戦の墓地群・72 クルアーニー／ランゲル・セントイライアス・
868 フランスのサンティアゴ・デ・コンポステーラの巡礼路）は**捨てず・作らず**、一覧に残して
凡例が件数を述べる。「1,273 件」と言いながら 1,270 件しか描かない状態を作らない。

### ⚠⚠⚠ 上流が持っている `danger` 列は、10 年前の写しだった

XML には `danger` 列がある。使わなかった。理由は実測で、それが結論より重要である:

| id | 物件 | 実際 | XML の `danger` |
|---|---|---|---|
| 23 | パルミラ | 2013 年から危機遺産 | 空 |
| 385 | サナア旧市街 | 2015 年から | 空 |
| 527 | キーウ：聖ソフィア大聖堂 | 2023 年から | 空 |
| 1703 | オデーサ歴史地区 | 2023 年から | 空 |

列全体を見ても最新値は「Y 2014」で、そこで更新が止まっている。
これをそのまま出すことは、**10 年前の写しを現在形のラベルで見せる**ことだった。

⇒ 危機遺産の状態は**維持されている側に訊く**。Wikidata の `P793（重要な出来事）→ Q222384`、
**終了修飾子 `P582` の無い文**が「いま危機遺産」。`P757`（世界遺産 ID）で結合する
——上流は構成資産にも ID を書く（`23bis`・`527-002`・`1208bis`）ので、先頭の数字へ畳む。
**52 件**が結合し、1 件（1150）は一覧に無い id を名乗ったので**黙って捨てず印字する**。
出典は 2 つに分けて表示する（一覧はユネスコ、危機遺産は Wikidata）。

**検査 ⑥ は件数を固定していない。** 「2014 年より後に危機遺産になった物件が 1 件でもあるか」を測る
——放棄された列に戻れば原理的に 0 件になるので、これが「維持されている情報源から来た」ことの
構造的な証拠になる。件数を固定すると、ユネスコ側が正しく増減しただけで赤くなる。

### ⚠⚠ Node の `fetch` は 403 になる。検査しているのは UA ではなく TLS の指紋

`whc.unesco.org` は Cloudflare のボット検査の内側にある。実測:

| 試したもの | 結果 |
|---|---|
| Node `fetch` + UA だけ | 403・`<row>` 0 件（「Just a moment…」の HTML） |
| 同 + Accept + Accept-Language | 403・0 件 |
| 同 + Chrome の sec-ch-ua / sec-fetch-* 一式 | 403・0 件 |
| `curl` | **200・2.5 MB・1,273 行** |

ヘッダをこれ以上盛るのは「何を測られているのか」の当て推量である。
**すでに通っているクライアントを呼ぶ**ほうが推測ではない——生成器は `curl` を呼ぶ
（Windows 10+ と CI のイメージに入っている）。CORS ヘッダも無いので**そもそもブラウザからは読めず**、
だからこのデータは同梱で、一覧は年 1 回（委員会会期）しか動かない。

### ⚠⚠ 言語は一覧に書かず、レジストリから導いて上流に訊いた

ユネスコ自身の言語切替は **en / fr しか出さない**（条約の作業言語）。にもかかわらず
es・ru・zh・ja・ar は XML を返す。公表された索引が無いので**探索する**——
`js/lang-registry.js` を vm で評価して `IntMapLang.htmlTag()` を引き（`jp`→`ja` の対応はそこにある。
ここに書き写さない）、得た subtag を全部叩く。**en/es/fr/ja/ru/zh が 200、de/ko は 404**。

⚠ **ユネスコの中国語がどちらの字体かは、測って決めた。** `scripts/zh-hans.mjs` の `toHans()` は
簡体字テキストの不動点なので、サイト名を通して変化しなければ簡体字である
——**1,104 件中 1,104 件が不変**。よって `zh-Hans` として記録した。
**先頭 2 文字が一致するから当てる、はしない**（`js/lang-registry.js` #R223 が明文で禁じている）ので、
**繁体字の読者には英語名が出る**。ユネスコが繁体字版を公表していない以上、それが正直な答えである。

### ファイルの形

- `data/whc-sites.json`（609 kB）— `sites` が 1 物件 1 行（**全言語の名称**・区分・登録年・登録基準・
  国・危機遺産の年）、`points` が `[物件index, lng, lat, 国index]` の**平坦な数値配列**。
  地図に渡す FeatureCollection は**読者の言語で実行時に組む**ので、言語を変えても再取得は無い。
- `data/whc-detail.<locale>.json.gz`（1 本 ≒ 345 kB）— 解説文・保有国名・写真・ユネスコのページ。
  ⚠ **1 本にまとめると 2.0 MB で、どの読者もその 6 分の 1 しか要らない。** 言語ごとに分け、
  **訳の無い物件にはその言語のファイルにも英文を入れて**、フォールバックのための 2 本目を無くした。
- 区分・地域・国の**語彙もファイルが持つ**。色も訳語もその語をキーにした表で、塗り分けは
  `whsDoc.categories` を歩いて組む——ユネスコが区分を増やしても**地図から消えず**、
  ユネスコ自身の語で名乗る。検査 ⑦ は acorn で「区分名が表のキーと訳語タプル以外に現れないこと」
  を測り、変異（`categories[i]==="Cultural"` を 1 行足す）で赤を確認した。
