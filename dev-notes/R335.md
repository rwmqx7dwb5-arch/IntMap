## R335 — **字体の変換器は語彙を変換しない、の二度目——今回は「表に何が欠けているか」を表の外から数えた**

`js/locales/ui.zh-hans.js` と `js/locales/pages.zh-hans.js` は翻訳ではなく**生成物**である。
繁体（`ui.zh.js` / `pages.zh-hant.js`）に `scripts/zh-hans.mjs` を通したもので、中身は2段:

1. **`WORDS` 表** — 台湾語 → 大陸語の**語彙**（左辺も右辺も繁体で書く）
2. **OpenCC `tw→cn`** — **字体**だけ

報告されたのは1語だった。**`社群`**——台湾語の「コミュニティ」で、大陸語は **`社區`**。
`社` も `群` も**両方の字体で同じ字**なので、②はこの語を**自分自身に変換する**。
つまり「字体が正しいか」を見るどんな検査にも、**この語は完全に正しく見える**。
#R319 が `纽西兰`／`玻里尼西亚` で書き留めたのと**同じ形**の欠陥が、1語あとに出ていた。

出荷されていた6か所（実測）:

| 場所 | 繁体（正しい） | 簡体で出ていたもの | あるべき |
|---|---|---|---|
| `pages` · airplanes.live の出典説明 | `社群 ADS-B` | **`社群 ADS-B`** | `社区 ADS-B` |
| `pages` · sources.html の本文 | `OpenStreetMap 社群` | **`OpenStreetMap 社群`** | `OpenStreetMap 社区` |
| `ui` · `tabCommunity` | `社群` | **`社群`** | `社区` |
| `ui` · `ctxPostHere` | `發佈到社群` | **`发布到社群`** | `发布到社区` |
| `ui` · industry-web の注記 | `Wikidata 由社群維護` | **`Wikidata 由社群维护`** | `…由社区维护` |
| `ui` · キーボード一覧 | `社群分頁` | **`社群分页`** | `社区分页` |

**丸ごとの語置換が安全であることは、先に数えて確かめた**——生態学の語義（`群落`）は corpus に **0 件**、
`社群媒體`（大陸は `社交媒體` であって `社區媒體` ではない）も **0 件**、既にある `社區`
（`約一個社區`＝about a neighbourhood）は**もともと正しい語**なので触らない。

### ⚠⚠⚠ 手で保つ語彙表は「自分に何が足りないか」を言えない

1行足せば終わる依頼だった。しかし**この欠陥の形は「1語」ではない**。
`WORDS` は手で保たれた表で、**#R251 の 440 対の字表とまったく同じ性質**を持つ——
**表に無い語は、表に無いという理由で誰にも見えない。**
#R251 のときは字表が 1,529 字中 439 字しか覆っておらず、残りは何ラウンドも黙って素通りしていた。

そこで**読むのをやめて、公表された表に訊いた**。

OpenCC には台湾プロファイルが**2つ**ある。`tw` は字体だけ、**`twp` は語彙も**変換する。
#R251 は `twp` を pipeline の**中で**使うことを正しく拒否している——中で走らせると
`WORDS` が直した大陸語をもう一度台湾語として読み、`檔案`→`文件`→**`文档`** になる。
**だが pipeline の外に置けば、それは変換器ではなく目録である。**

やったこと: 繁体側の**全 8,321 個の漢字ラン**それぞれに `WORDS`＋`tw→cn` と `WORDS`＋`twp→cn` を

### ⚠⚠⚠ `喬治亞` は1行では書けなかった

corpus には **州と国が両方**ある——`美國喬治亞州` と、国としての `喬治亞`。
大陸語では**州が `佐治亞州`・国が `格魯吉亞`** なので、**どちらに寄せても片方が壊れる。**
⇒ **2行に分けた**。`toHans()` の longest-first の並びが `美國喬治亞州` の中で州の行を先に当て、
その時点で `喬治亞` はもう残っていない。検査③は**出荷された `ui.zh-hans.js` の中で**
`美国佐治亚州` と `格鲁吉亚` が両方あり `乔治亚` が1つも無いことを見る。

### ⚠⚠ 3語は「そのままの語置換では誤る」ので入れなかった

#R322 が `複製` について書いたのと同じ形——**左辺は、この文書の中で語義が1つしかない語でなければならない。**

| 語 | か所 | なぜ丸ごと置換できないか |
|---|---|---|
| `擷取` | 13 | `螢幕擷取`＝**截取** だが `擷取標題`＝**抓取**。2つの語義が同居している |
| `向量` | 4 | `向量底圖圖磚`＝**矢量** だが `向量平均` は**数学の向量のまま**が正しい |
| `數位` | 1 | 単独出現1件のみで、数値なのか digital なのか**文字列からは決まらない** |

これらは**より狭い左辺**（`複製羊` の形）が要るのであって、行を1本足す話ではない。
**検査⑥がこの不在を「決定であって見落としではない」として固定する**——3語が `WORDS` の左辺に
**無いこと**と、3語が**まだ corpus に在ること**の両方を見るので、注記のほうが古くなったら赤くなる。

### ⚠⚠⚠ 目視ではなく等式で確かめた

#R319 は `旧.replaceAll('紐西蘭','新西蘭') === 新` で証明した。**同じ方法を49行へ拡張した**——
新しい49行を**簡体の綴りに直して**、長い順に、`HEAD` の生成物へ当てる:

```
applyNewRows(旧) === 新          ui.zh-hans.js  true    pages.zh-hans.js  true
書き換わった箇所                 113                     35              （合計 148）
1か所も当たらなかった行          0
```

**この等式が true であることは、「ファイルの中で変わったのはその語だけ」と同じ意味**である。

そして**文字数**——#R319 が「同じ文字数の置換なので長さ不変は証拠にならない」と書いたので、
今回は**長さが変わる行だけを名指しして予測を立て**、実測と突き合わせた:

| ファイル | 長さが変わる行 | 予測 Δ | 実測 Δ |
|---|---|---|---|
| `ui.zh-hans.js` | `沙乌地阿拉伯`−1・`克罗埃西亚`−1・`厄利垂亚`+1×2・`新罕布夏`+1・`衣索比亚`+1×3・`执行绪`−1×2・`乔治亚`+1 | **+3** | **+3** |
| `pages.zh-hans.js` | `乔治亚`+1 | **+1** | **+1** |

### ⚠⚠ 等長の左辺が corpus の中で重なる組が1つある——ただし今回のではない

長さの同じ行は**配列に書いてある順**に当たるので、2つの左辺が corpus の中で**部分的に重なる**と、
答えが「誰がどこに行を打ったか」に依存する。全数で調べたら**ちょうど1組**あった:

- `圖資`→`地圖數據` と `資料`→`數據` は、どちらも **`地圖資料`** の中で当たる。
  配列で `資料` が先に書いてあるので `地圖數據` になる。**逆順だと `地地圖數據料`。**

**#R335 の行ではない**（121行の表にも同じものがある）。今回の49行は、
**前へ移しても・後ろへ移しても・逆順にしても出力が同一**であることを実測した。
検査⑤は**この既存の1組だけ**を名指しで許す＝2組目が現れた瞬間に赤くなる。
⚠ 直すのは今回の範囲ではない。**見えるようにするのが今回の範囲。**

### ⚠ この方法にも見えないものがある

目録は `twp` の項目でできているので、**`twp` が知らない語は目録に出ない。**
`擷取` の全出現を読んでいて、掃引が一度も挙げなかった台湾語に3つ当たった:

- `行動電話門號` の **`門號`**（大陸は `號碼`）
- `存取權杖` の **`權杖`**（`令牌`）
- `愛滋病毒盛行率` の **`盛行率`**（`流行率`）

**今回は実装していない**（各出現の確認をしていない）。「掃引が挙げなかった」は
「存在しない」ではない、という実例としてここに残す。

| # | 見るもの |
