## R493 — **Atlas は地図の状態を読めたが、地図を見たことは一度も無かった**

**依頼**: 「Atlas自身が地図画像を添付できるようにする」——構造化 State ＋必要時だけ視覚入力の二層。

### ① 何が無かったのか

Atlas の**内受容感覚**は #R318 から完成していた。`js/atlas-state.js` は 18 セクションを合成して、
中心座標・zoom・bearing・pitch・base・投影・可視範囲の 4 辺・ON のレイヤー・**そのレイヤーが実際に
描画されたか**・選択・ピン・現在地・Chronos 時刻・開いているパネル・経路・シミュレーションまでを
毎ターン渡している。つまり Atlas は「北緯35, 東経139」ではなく
「この bbox を zoom 7.2・衛星・pitch 40° で見ていて、人口密度と地震が ON」を知っていた。

**知らなかったのは、それがどう見えるかである。** レイヤーが ON なのは分かっても、
「東側だけ異様に赤い」「この境界線なんか変」「点が密集している」「このラベルは何と書いてある」
「今見えているこの黄色い帯は何」「この2つは視覚的に重なっているか」は、
**画素を見た者にしか答えられない**。そして地図を自動で撮って Vision へ渡す経路は存在しなかった。

⚠ **無かったのは AI 基盤ではない。** 利用者が貼った画像を `input_image` としてモデルへ渡す経路は
#R149 から在り、`supabase/functions/ai-proxy` はどの task でも `images[]` を受ける。
足りなかったのは「**Atlas 自身が撮って添付する**」という 1 本の能力だけだった。

### ② `view.inspect`（tool 名 `look_at_map`）

読者がいま見ている画面を撮り、**次のモデル呼び出しに画像として添付**する。CORE ツール——
探しに行かないと見つからない能力は、それが要る当のターンで使われない。

| 引数 | 何を撮るか |
|---|---|
| `include:"screen"`（既定） | 地図＋その上の DOM（凡例・スケール・マーカー・ニュース帯・時間バー／操作系は隠す）。**凡例や帯についての問いに答えられる唯一の絵** |
| `include:"map"` | レンダラのフレームだけ。html2canvas（198 kB）を取りに行かないぶん安い |
| `reason` | 何を見に行ったか。読者に見せる説明文になる |

カメラを動かしたあと・レイヤーを切ったあとに**もう一度見て自分の操作の結果を確かめる**ことができ、
1 ターンに何度でも呼べる（`writes` は空・conflict key を持たない `read-only`）。

### ③ ⚠⚠⚠ 画像は transcript に載せられない——これがこの機能の設計そのもの

`js/atlas-agent.js` は tool の結果を**プロンプト本文の JSON** として戻す
（`'IntMap observed: '+JSON.stringify(m.content)`）。data URL をそこへ置くと、
それは画像ではなく**数十万文字の base64** になり、何も言わないままターンの context を食い尽くす。

そこで**画素と記録を別の道で運ぶ**:

- **画素** → `js/atlas-view-capture.js` の台帳が持ち、`askAIJSONEnvelope(..., VFRAMES.urls(), ...)`
  ＝**第3引数の vision channel**（#R149 から在る。`ai-proxy` が `input_image` にする）で次の呼び出しへ。
  この引数は今まで `atlas_turn` では常に `null` だった。
- **記録** → transcript には `{frame, include, capturedAt, bbox, center, zoom, bearing, pitch, base,
  projection, layersOn, chronos}` という**その瞬間の機械値だけ**（実測 300 バイト前後）。

そして `[VIEW FRAMES ATTACHED TO THIS MESSAGE]` ブロックが **image N ↔ view-frame-N** を結び、
最後に「**数量は上の行と状態ブロックから取れ。画像を測るな**」と言う。
⚠ **画像は定規ではない。** 座標・zoom・レイヤー名・日付は機械値として同時に渡してあるのだから、
画像から読み取らせるのは、既に正確に知っていることを近似に置き換える行為でしかない。

1 呼び出しに載せるのは**直近 3 枚**（`ai-proxy` の `MAX_IMAGES`＝4）。
⚠ **落とした枚数は明示する**——黙って切ると「全部見せた」と読まれる。

### ④ ⚠⚠ 撮る処理を 2 本にしない

絵そのものは screenshot ボタンが #R200 から撮っているものである。WebGL を **render tick の中で**
読む（`preserveDrawingBuffer` は意図的に OFF）、#R231 の**1 座標系**（出力はコンテナの CSS ボックス、
レンダラの密度で。両層をそこへ描く）、html2canvas による重ね層。
これを `js/atlas-view-capture.js` へ出し、**ボタンと Atlas が同じ 1 本を呼ぶ**。

⚠ #R231 は、1 つのファイルの中で地図層が backing store から、重ね層が CSS ボックスから寸法を取って
食い違ったときに何が起きるかの実測（モバイルで UI だけが引き伸ばされる）である。
**「読者が見ているもの」の答えが 2 つある状態は、それと同じ形をしている。**

ボタンに残ったのは**ボタンのもの**だけ——busy 状態・`capture-mode` を操作全体にかけること・
フラッシュ・保存。クラスは `finally` で外す（#R231: 途中で死んだキャプチャが操作系を隠したままに
してはならない）。

### ⑤ ⚠⚠⚠ 副産物: dispatch の `exec` は一度も Atlas に届いていなかった

この機能を作る過程で見つかった、**この機能とは無関係の**欠落。

`js/atlas-results.js` の `toLegacy` は機械的な `exec` ブロックを **`observed.exec` から読む**。
そこへ書く関数は `fromLegacy` **1 つだけ**で、**アプリはそれを呼んでいない**——
呼び出し 3 件はすべて `tests/r318-checks.test.mjs` の中である。生きている経路は
`execute()` の 10 段目で、`observed` は before/after のスナップショットと**検証器の観測**から
組まれる。`js/atlas-capabilities.js` の observer はどれも `exec` を名乗らない。
したがって `toLegacy` は `exec` を一度も立てず、`a.__exec` は常に null、
`_runOne` は `js/atlas-toolsurface.js` へ `exec:null` を渡し、`mechanical()` は
`observed` を出さなかった——**`exec` を返すすべての能力について**。

⚠ **#R413 はその代償の実測であり、それを知らなかった。**
「`exec` IS WHY THIS WAS UNUSABLE: js/atlas-toolsurface.js forwards `res.exec` and nothing else,
so the note reaches the READER while the turn that located them learned only ok:true」と書き、
`locate` に `{lat,lng,accuracyM,provenance}` を持たせた。**そのブロックは一度も届いていない。**
`tests/r413` が固定しているのは dispatch の**その行の綴り**で、それは真であり、
値が executor を生き延びるかについては何も言っていない（**#R488 の形**——綴りを固定する検査は
死んだ規則を守れない）。

修正は 10 段目の 3 行。⚠ **`Object.assign(…, verdict)` の後に置く**——
`verdict` が `observed` を持つと合成物を丸ごと置き換えるので、合成の**中**に足したものは
`camera` observer を使う能力（＝`view.locate`。このブロックが書かれた当の能力）で
また捨てられる。observer 自身が `exec` を名乗ったときは observer が勝つ。
`tests/r493-checks.test.mjs ④` が**本物の executor を駆動して** 3 つの経路を確かめる。

### ⑥ 読者に見せる

撮った絵は**回答の中に縮小版で出る**（`.atl-viewframe`・340 px・タップで拡大＝
`js/atlas-attach.js` の既存ライトボックス）。⚠ **画面を読んでおいてそれを言わない能力は、
読者が監査できない。** 「東側だけ赤い」で答えが決まるなら、その東側を見せる。

### ⑦ 増えていない行

`js/atlas-console.js` は **4,909 行のまま**（`tests/r419 ⑨d` の ceiling は `< 4,910`）。
⚠ **#R199 の shrink-only ceiling は上げるものではない**——主題が出ていくものである。
台帳・記録・プロンプトブロックはすべて `js/atlas-view-capture.js` にあり、
console に残ったのは**それを結ぶ 5 行**（import・台帳の生成・dispatch の 1 行・
`promptBlock()`・`urls()`）だけ。新しい行 2 本ぶんは、この round が触っている
2 対の隣接文をそれぞれ 1 行にまとめて払った。

### ⑧ 入口が 1 つなのは趣味ではなく規則

`js/atlas-view-capture.js` の export は **`makeViewCapture(deps)` の 1 本だけ**で、
`CAPTURE_CLASS` / `captureCanvas` / `captureFrame` はその戻り値のメンバである。理由は
`tests/r175-checks ③`——**js/ の named export は「どこかで名前で import されている」ことが要る**
（さもなければ死んだ export ＝ 死んだコード）。`js/screenshot.js` は起動バンドルに乗るので
キャプチャを**動的 import** で取りに行く（静的にすると `check:perf` の `eager.modules` が
283 → 284。押さない読者のほうが多いボタンのために全員の起動へ 6 kB 積むことになる）——そして
**動的 import はその検査に何も見えない**。扉を 1 枚にして `js/atlas-console.js`（元から遅延）が
それを名前で import すれば、ボタンは押された瞬間に**同じ扉**を開ける。
3 つを別々に export していたら、そのうち 2 つが「死んでいる」と見えていた。

⚠ 同じ規則で、**`grabRendererFrame` はトップレベルに置けない**（export されない
トップレベル宣言は #R175 が禁じている——モジュール化以前ならグローバルだったものだから）。
`captureCanvas` の中に入っている。

### ⑨ 作り物のレンダラでは答えられない 1 つの問い

台帳の論理（記録・落とす規則・プロンプトブロック・拒否）は `tests/r493-checks.test.mjs` が
**偽の renderer と偽の document で端から端まで駆動**している。そこで答えられないことが 1 つある——
**WebGL の読み出しに本当に絵が入っているか**。

⚠⚠⚠ **黒い矩形は「失敗」ではなく「自信のある誤答」になる。** `preserveDrawingBuffer` は意図的に
OFF なので、描画されていないバッファを読むと**全面 (0,0,0)** が返る。実測（プレビューペイン、
`document.hidden`）: requestAnimationFrame は 700 ms に **0 回**、`render` イベントは **0 回**、
標本 **628/628 画素が (0,0,0)**。それを Vision に渡せば「地図が暗い」と説明される。
だから実装は **render tick から来たフレームだけを受け取り**、来なければ
「ページが背面にあるので取得できるフレームが無かった」と**理由を言って断る**
（読者が押す screenshot ボタンは従来どおり受け取る——押した人は画面を見ているから）。

そのうえで `tests/r493.spec.js` が、**合成の起きるブラウザで撮った JPEG を復号して画素を標本し、
色があること**を主張する。実測 1.594 s（junit の testcase 時間。57〜93 s の壁時計は共有の
webServer ビルド）。⚠ **既存の spec に相乗りできなかった**——キャプチャを復号して読む spec は
他に 1 本も無い。総計の天井は**測った 2 秒ぶんだけ**動かした（4,630 → 4,632・#R451/#R410/#R405 と
同じやり方で `scripts/test-budget.mjs` の HISTORY に理由を書いた）。
⚠ **gate（core）は動いていない**——`currentRoundSpec()` が今回の spec を gate のものにし、
`tests/r466.spec.js`（5 s）が gate から出るので、30 s → 27 s に**下がった**。
