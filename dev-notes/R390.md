### 2. 盲点は「番人が名前を訊いていた」こと

`scripts/check-test-list.mjs` は #R301 が置いた番人で、`test:checks` の一覧と `tests/` の中身を
突き合わせる。ただし「何が検査ファイルか」の判定が**ファイル名**だった:

```js
export const IS_NODE_TEST = /\.test\.mjs$/;
```

慣例（`r<N>-checks.test.mjs`）より前に手で名付けられた `tests/security-logic.mjs` は、
**この番人が要求できる集合の外**にある。しかも `tests/r301-checks.test.mjs` ③ は、その穴を
**検査で明文化していた**:

> ⚠ AND IT DOES NOT DEMAND WHAT IT SHOULD NOT. (…) the two hand-named `*-logic.mjs` files that
> predate the convention are listed **and are allowed to be**.

「在っても無くてもよい」と書いてある以上、#R377 があの1行の巻き添えで落としたとき、
`npm test` も `npm run check:static` も CI も**言うことが何も無かった**。

⚠ この形は #R301 自身が書いている——「同じ穴を意識していない作者を一人も捕まえない」。
#R301 は `tests/r260 ⑥`（自分のファイルだけを訊く）についてそう書き、**自分の一般化にも
同じ限界を残した**: 慣例に沿った名前だけを一般化していた。

### 3. 直したこと — 番人は名前ではなく**中身**を訊く

`tests/` 配下の `.mjs` が **`node:test` を import しているなら、何という名前でも検査ファイル**であり、
一覧に無ければ error。名前の規則も**併存させた**ので、まだ `test(…)` を1本も書いていない
`*.test.mjs` も今までどおり捕まる。

```js
export const IS_NODE_TEST = /\.test\.mjs$/;                       // 名前で決まるもの
export const DECLARES_NODE_TESTS =
  /(?:\bfrom\s*|\brequire\s*\(\s*|\bimport\s*\(\s*|^\s*import\s+)['"]node:test['"]/m;   // 中身で決まるもの
export function isNodeTest(file, source) { … }
```

⚠⚠ **`readSource` は必須にして、省略したら `TypeError` を投げる。** 既定値を持たせると、
呼び忘れた誰かが **#R377 の挙動を黙って・緑で**取り戻す。それは修正ではなく穴そのもの。
（`tests/r390 ⑤` がこれを実行して確かめる。）

⚠ `tests/r301 ③` の「在っても無くてもよい」を書き換えた。**穴を許可していた一文が、
穴を塞ぐ変更を赤くする**ので、これは同時にしか直せない。
