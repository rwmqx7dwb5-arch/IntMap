## 1. 開いた凡例が次の凡例の下に入っていた（本番 375×812 で観測）

### 何が起きていたか

携帯で凡例を 3 枚以上出すと、どれも題だけの高さに畳まれて左端に縦に並ぶ。1 枚の ▢ を押すと、その
カードは本体の高さまで伸びるが、**下のカードは元の top のまま**で、伸びたカードの下半分がその下に入る。

実測（このブランチ、375×812・isMobile、ケッペン／積雪／レーダー／風の 4 枚）:

| 開いたカード | 修正前: 覆われた点（四隅＋中心・`elementFromPoint`） | 修正後 |
|---|---|---|
| `koppen-legend`（270 px） | 中心が `data-legend-radar` の下 | 0 |
| `data-legend-radar`（201 px） | `data-legend-snow` の 5 点全部がレーダーの下 | 0 |
| `data-legend-snow` / `data-legend-wind` | 0（最下段・最後の DOM 順） | 0 |

### 根本原因

`tileLegends()` は各カードを**実測の高さ**で積むので計算は正しい。誰も**もう一度訊かなかった**。
–／▢ のボタン（`ensureLegendMinimize` の `onclick`）は `toggleLegendMin(el)` だけを呼び、同じファイルの
他の 2 つの畳み（`_minimizeOpenLegends` とタイラー自身の畳み）はどちらも自分の `tileLegends()` で終わっていた
——「呼び出し側がみんな覚えている」ことで保たれていた規則を、次の呼び出し側が覚えていなかった。

### 直したこと

規則をボタンではなく**事実**（カードの大きさが変わった）に付けた。

- `watchLegendSize(el)`（`js/data-layers.js`）: `tileLegends()` が見つけた凡例（同じ `all`——凡例とは何か
  の 2 つ目の一覧を作らない）を 1 つの `ResizeObserver` に 1 回だけ登録する。大きさの変化は
  `js/runtime.js` の `frame('legends.reflow', …)` で**次のフレームに 1 回**の `tileLegends()` になる。
  中身が遅れて届いて高さが変わる場合・選挙の年で行数が変わる場合も同じ規則で直る。
- 観測コールバックの中では積み直さない（同じ深さの兄弟の大きさを変えると ResizeObserver のループ誤り）。
- **収束**: `tileLegends()` は `put` / `capTo` が同値を書かないので、入力の変わらない 2 回目は何も書かず、
  大きさも変わらない。実測、4 枚を順に開閉したあと 3 秒間の凡例の style/class 変化 0 件、
  ResizeObserver のエラー 0 件（携帯・デスクトップとも）。
- **読者が自分のボタンで開いた凡例は畳み返さない。** 積み直しが即座に走るようになったので、容器の
  予算が足りないときタイラーが開いたばかりのカードを畳み返しうる（ボタンを押しても開かない）。
  押して開いたら `legPinOpen`（畳まれた凡例を開き直したときに #R742 が付ける印と同じ）を付け、
  押して閉じたら外す。

### デスクトップでも同じ規則が効く（判断済み）

同じ欠陥はデスクトップにもあった（凡例は下端基準で積まれ、開いたカードは上へ伸びて上のカードに
重なる）。規則は置き場で分岐させないので、**デスクトップ・ワークスペースでも 1 枚を開くとその上の
凡例が押し上げられる**。積み方の算術（起点・間隔・折り返し・`data-grow-down` の記憶した top）は
変えていない。⚠ 1280×800 で観測した、ケッペンの凡例（デスクトップでは積みの外で自分の全高の場所を
持つ）が他の凡例や時刻表示と重なる件は**修正前から同じ**（前後とも 3 点）で、今回は触れていない。

## 2. `ofm` のタイルが届くたびに、地名ラベルと参照線を全部書き直していた（本番: 12 秒で `ofm-city` だけ 49 回）

### 何が起きていたか

`js/app-body.js` には `ofm` の `sourcedata`（`isSourceLoaded`）の購読が 2 つあり、時計もカメラも止まって
いても 0.1〜1.2 秒ごとにそれぞれ pass を丸ごと走らせていた。

- 地名ラベル（#R26）: `ensurePlaceLabels(); applyLabelLang();`——1 回で約 37 件（`ofm-country/admin1/
  city/other/river/peak/poi` の visibility・text-field・text-font・文字色・ハロー、`geo-sea` のソース再投入、
  era 層の書体と色）。
- 参照線など（#R38）: チェックされた `cb-admin1/roads/rail2` の `__refApply`（→ `_applyAdmin1`）、
  `ensureBordersLayer` ＋ `_applyBorders`（→ 歴史基図の `layer-light/dark(-nl)`）、`_imCoastReassert`——1 回で約 15 件。

facade は同値の省略を**意図して**しない（`js/geo-command-log.js` の #R322 の実測）ので、頻度は呼び出し側の責任。

### その購読は何のためにあったか（経緯）

#R26「デフォルト選択なのに地名ラベル/国境が出ない、再チェックで初めて出る」と #R38「Roads/Railways/
State borders をチェックしても表示されない、再読み込みで治る」。層は `visibility:'none'` で生まれ、
ソースが遅れて来ると作れない／作っても状態を与える人がいない。**最後の pass より後に生まれた層**
（遅れて足された・#R72 の自己修復で作り直された・`js/time-borders.js` が後から足した era 層）は、誰かが
もう一度 pass を走らせるまでその状態のまま。タイルの到着はその「誰か」の代わりだった。

### 直したこと——1 つの仕組みを facade に置いて、2 つの心拍に配る

購読が本当に訊きたいのは「タイルが来たか」ではなく「**前回の pass が見た層のうち、今は別物になった層が
あるか**」で、これは**層の同一性**の事実。判断を 2 か所に写さないため、`js/geo-engine.js` の facade に
`layers.witness()` を足した（型は `types/geo-engine.d.ts` の `GeoEngineLayerWitness`）。

- `run(fn)`: pass を走らせ、その間に**誰が**`layers.has` / `layers.get` で訊いた id でも記録する（pass が
  呼ぶ他モジュール——`js/time-admin1.js`・`js/coast-line.js`・歴史基図——の問い合わせも入る。書き手に
  記録係を配って回らない）。終わった時点で各 id をその時の層オブジェクト（無ければ `null`）と組にするので、
  pass 自身が作った層は「見た」に入る。例外で終わった pass は記録しない。入れ子にできる。
- `unchanged()`: pass が完走していて、記録した全 id が今も同じオブジェクトを指すときだけ真。
- 2 つの購読は `if(!beat.unchanged()) beat.run(() => { …元の pass… })`。
- 他の入力（言語・表示モード・テーマ・衛星・トグル・時計）はそれぞれの呼び出し元が pass を直接呼ぶので
  影響を受けない（言語ピル、設定の適用、`applyTheme`、トグルと再表明タイマー、`js/hist-cities.js` の時計）。
- ⚠ `getLayer()` が毎回写しを返すアダプタ（Cesium）では同一にならず、従来どおり毎回走る（悪化しない）。

途中で一度、判定を `js/place-labels.js` の `applyLabelLang({onlyNewLayers:true})` の中に置いたが、#R38 の
心拍にも同じ判断が要ると分かり、写さずに facade へ移した（`js/place-labels.js` は元のまま）。

### 実測（375×812、起動 6 秒後、`ofm` の `sourcedata` を 20 回発火。setLayout/setPaint/setFilter）

| | 修正前 | 修正後 |
|---|---|---|
| 全レイヤー | **1,240** | **0** |
| うち地名ラベル（`ofm` ソースの symbol 層） | 740 | 0 |
| うち `ofm-city` | 120 | 0 |
| うち #R38 の再表明（`ref-admin1` 60・`ref-admin2` 40・`ref-roads/rail/rail-dash` 各 20・`borders-only-line/casing` 各 20・`layer-light/-nl/dark/-nl` 各 20・`ofm-admin1` の visibility） | 約 300 | 0 |

⚠ この検査環境では、止まった地図に 12 秒間 `ofm` の `sourcedata` が 1 回も来なかった（本番は 0.1〜1.2 秒
ごと）。待っても何も証明しないので、検査はイベントを 20 回**発火**して測る。

## 検査

- `tests/legend-reflow-and-label-writes-checks.test.mjs`（node・評価）:
  ① `js/geo-engine.js` から `engineFacade` を切り出し、層が同一性を持つ偽のアダプタに結んで witness を評価
  （未実行は「変化あり」・出現／作り直し／削除を検出・見ていない id は無関係・pass が作った層は「見た」・
  例外の pass は記録しない・入れ子）。
  ② 実物の `js/place-labels.js` を同じ facade の下で心拍として走らせ、20 回で書き込み 0・作り直し／後から
  追加／削除でやり直し。`js/` の `ofm` の `sourcedata` 購読は全部 witness で囲まれている。
  ③ `watchLegendSize` の 1 要素 1 回の登録・次フレームに 1 回・コールバック内では積み直さない、
  ボタンの開閉が印を付け外しする。
  変異 7 つがそれぞれ赤: facade の `has` が記録しない／未実行を「変化なし」と答える／例外の pass を記録する／
  入れ子で外側に伝えない／#R38 の購読の門を外す／（凡例）印を外す／frame を経ず直接積み直す。
- `tests/form-control-names.spec.js` ②（実ブラウザ・375×812）に相乗り——携帯の凡例 3 枚を出すところまで
  同じなので起動を共有した（別 spec にすると起動 1 回分・約 15 s が全体の上限を超えた）。各カードを自分の
  ボタンで開き・閉じ、全カードの四隅と中心が自分自身・開いたカードが畳み返されない。`ofm` の
  `sourcedata` 20 回で**全レイヤーへの書き込み 0**、作り直した `ofm-city` は次の心拍で適用、基図（衛星→地図）・
  テーマ・言語の切替はラベルに届く。修正前のコードでは凡例の段で赤（`#koppen-legend` を開いた直後に
  その中心がレーダーの凡例の下）。
  ⚠ 払い: ② の 1.5 s × 層数 ＋ 1.5 s の固定待ちを条件待ち（上限は旧来の 1.5 s）に替えた。② の本体は
  10.2 / 10.5 s → 11.6 / 12.1 / 12.2 s。ファイル全体の実測は ① 8.7–11.1・② ≤12.2・③ 55.5–56.9 s で、
  表の書き手（`shard-plan --update`）の規則（テストごとに丸めて合計）で 80——`tests/durations.json` の値は
  変わらない（上限は据え置き）。
  ⚠ ① は修正前のコードでも 4 回中 2 回落ちる（描画された欄が 5 件で「>5」を満たさない）。今回とは無関係。
