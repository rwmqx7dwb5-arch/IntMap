## R713 — 歴史の記録が、同じ問いを 1 つの典拠にしか出していなかった

〈「IntMapの歴史地図のcoverageや忠実性、品質の漏れを全部埋めて。より広く、深く、忠実に。」〉

計測から始めた。⚠ **最初に立った 2 つの大きな穴は、どちらも実測で消えた**——`data/hist-kuni.js` が
令制国 68 か国のうち 15 しか持たないのは欠落ではなく join で（`data/hist-admin1.js` が 53 を
「山城国」等の日本語名で持ち、**重複 0・欠落 0 で 68**）、415 MB の `data/border-detail/` に
`check:*` が無いのも門が無いという意味ではなかった（`tests/r711-*` が引数無しの `check()` で
出荷バイトを見ている）。**残った本物は、同じ形の欠陥が 2 か所にあることだった。**

### 1. ⚠⚠⚠ 受け側が読んでいた欄を、持ち得る種別が一度も訊かれていなかった

`scripts/histcities/harvest.mjs` の OHM 掃引は `node["place"~…];out tags center;` で、
受け側の 1 行目は `el.lon != null ? el.lon : (el.center && el.center.lon)` だった。
**`center` は way と relation にしかない。** node は自分が座標なので `lat`/`lon` を持つ。
つまりその三項演算子の後半は**書かれた日から一度も評価されていない**——輪郭のために書かれた
コードが、輪郭を訊かないクエリの後ろにあった。

OHM 実測（2026-09-13）: `place=city|town|village|hamlet` の way 677・relation 812 の計 1,489 件、
うち**名前と（開始または終了）年代の両方を持つのが 1,425 件**。出荷している 6,442 都市に対して
2 割にあたる集合が、一度も訊かれていなかった。

⚠ **areas は分割しない。** 点の掃引が緯度経度タイルに割れているのは点が 6 桁あるからで、
1,489 件を同じ格子に割れば 96 回の問い合わせで同じ 1,489 件を取り、その数と無関係な格子で
2 つ目のキャッシュを作ることになる。1 問で足りる。id は**種別ごとに一意**なので、
併合は `type/id` で行う（way 12 と node 12 は別物）。

結果 **6,442 → 6,474 都市・9,205 → 9,246 の歴史名**。⚠ **13 件は消えていない**——
束の代表が輪郭側に移って id が変わっただけで、全 13 件について同じ位置・同じかそれ以上の
span を持つ行を確認した（Kraków・Sofia のように OHM が面で持つ都市がこれに当たる）。
新しく入った歴史名 45 件のうち括弧付きは 4 件・読点付きは 1 件で、既存の 34 件・10 件と同じ比率。

⚠⚠⚠ **輪郭の名前は点の名前より「正式」で、そこに製図者の但し書きが入る。**
`place` の面には «St. John, Kansas (1879-)» のような綴りがあり、括弧は**人間に向けて
どの St. John か・何年のものかを言っている**。cities500 にそんな集落は無いので同名判定の
証拠が取れず、`tests/r427-checks ⑪`（＝解決できない表示キーを拒む検査）が赤になった。
⇒ **地図のラベルが但し書きを運べない**という規則は #R686 が `plainLabel` として既に持っているので、
**書き直さず import した**（#R536）。

⚠⚠⚠ **ただし最初の版は、その規則で既存の行を 1 つ消していた。** 無条件に適用すると
«Khowa (Elliot)»——**今日出荷されている行で、候補が括弧付きの 1 つしかない**——が全キーを失って
落ちた。**新しい経路の後始末のために持ち込んだ規則が、既にある集落を削ってよいわけがない**
（`AGENTS.md` §3）。⇒ **規則ではなく選好にした**：平の綴りがあるならそちらを採り、無いなら
行はそのまま。実測 括弧付き候補 9 件・平を保つ行 9・括弧を保つ行 1・**失われた行 0**。
同名索引は新しい綴りのぶん再生成した（19,317 → 19,345 綴り）。

### 2. ⚠⚠⚠ 「根拠が弱い」と記録されていた拒否の 4 割は、候補が 1 件も無い状態だった

`data/histnames.json` の era lane は 3,029 名前のうち **520 行**しか持っていなかった
（描かれるラベルの 22.5%・外接矩形面積で 13.6%）。拒否の内訳を出すと最大が `string-only` 1,669 件。
その名前は「#R515 の誤り＝綴りだけでは足りない」を意味する印なのに、**内訳を割ると 1,208 件は
候補が 1 件も無かった**。量るものが無いことを、量って足りなかったことと同じ言葉で記録していた。

原因は `candidatesFor` が Wikidata の `rdfs:label` / `skos:altLabel` への**英語の等値**だからで、
製図者の綴りと Wikidata の綴りが一字違えば 0 件になる。⚠ **緩めるのは答えではない**——
曖昧一致はまさに #R515 で、この掃引が等値である理由そのもの。要るのは弱い等値ではなく
**同じ等値を出す 2 つ目の場所**で、英語版 Wikipedia は**リダイレクト**という形でそれを持っている
（編集者が書いた別名＝`skos:altLabel` と同種の主張が別のストアにある）。

⚠ **これは ranker ではない。** `action=query&redirects=1` は 1 つの記事にしか解決せず、
記事の Wikidata 項目は 1 つなので、**順位づけられた候補列そのものが存在しない**。
見つかった項目は `scripts/histeras/match.mjs` の尺度をそのまま通る——**1 行も緩めていない**。
200 名前の予備計測で 46 件が解決し（**全件がリダイレクトか正規化を経由**）、そのうち
**26 件だけが尺度を通った**。落ちた 20 件のうち 13 件は `elsewhere`＝地図がその名前を描く場所の
外にある記事で、これは尺度が仕事をしている姿である。

実測の結果: era **520 → 684 行**、cshapes 136 → 144、eraBase 18 → 30。
**描かれるラベルに占める割合 22.5% → 26.4%**（de 12.0→14.3 / es 13.1→15.3 / fr 14.1→17.0 /
jp 20.3→23.6 / ko 18.4→20.7 / ru 20.3→23.3 / zh 21.1→24.2%）。
⚠ **どのストアが答えたかは文書自身が持つ**（`lanes`: label 687 / article 171 / qid 283）。
印字された台帳は流れて消えるので、次に広げる者が読むのは文書のほうである。

⚠⚠⚠ **1 回目のビルドで prose が 101 → 85 に減り、それは退行だった。** `isProse` は
「Wikidata がこの綴りの項目を持っているか」で名前と説明文を分ける。新しいストアの項目を
同じ `byName` へ入れたので、**16 件の説明文が「項目がある」に転んで、その説明のために書かれた
訳文を落とした**。#R700 が base lane について警告したのと同じ扉である——2 つの問いは別の問いで、
別に置く。article の QID を `hasItem` の答えから除くと 101 に戻り、lane は純粋に加算になった。

### 3. 根拠の書かれていなかった 3 つの絞り込みを、実測して書いた

外部調査が「理由がどこにも書かれていない」と挙げたもの。**2 つは正しい絞り込みで、
書かれていなかっただけだった**（OHM 実測 2026-09-13）:

| 絞り込み | 実測 | 判断 |
|---|---|---|
| `place` の白名簿が 4 値 | `suburb`/`neighbourhood`/`locality` ほかで名前と年代を持つもの **37,611 件** | **広げない。** それらは集落ではなく集落の中の区画で、#R711 が実測した「1850 年の鹿児島＝平之馬場町」がその誤りそのもの。`municipality` は行政体で、admin1/admin2 が既に描いている |
| 国境 index が `boundary=administrative` だけ | `relation[type=boundary][!boundary][admin_level=2]` は **0 件**（同じ第 2 の枝は admin1 側では 549 中 11 件を拾う） | **広げる必要が無い。** level 2 の tag のされ方についての事実として書いた |
| admin が level 3–6 まで | level 7 は **2,097** relation・level 8 は **23,922** | **今回は広げない。** 7 は第 2 tier の 22,708 に対し 1 割増、8 は 82 MB をほぼ倍にする。配信予算であって「level 7 は歴史ではない」ではない、と書いた（`--levels` は引数のまま） |

### 5. 検査

`tests/r713-hist-coverage-checks.test.mjs`（9 件）。①は `coordOf()` を**実際に評価して**
座標を取り出せる element 種別を決め、それが掃引の訊く種別に入っていることを要求する——
綴りの一致ではなく**両側からの計測**なので、クエリと受け側の片方だけが編集されても落ちる。
②は `resolveArticles()` を評価し、正規化とリダイレクトの**連鎖**・循環での停止・曖昧さ回避と
不在ページの排除・API の区切り文字を含む名前を別の問いに変えないことを測る。
`lanes` の集計は**両側とも出荷バイトから導いて**照合する（#R699: 検査の中に書いた数は
検査されている数ではない）。
⚠ **2 つの欠陥をそのまま戻す変異で実際に赤になることを確認した**（`OHM_PLACE_KINDS` を
`['node']` へ戻す → ①が赤／リダイレクトの追跡を 1 段へ戻す → ②が赤）。

### 6. ⚠⚠⚠ 9 つの出典ページが同じ総数を述べていて、それを測るものが 1 つも無かった

`data/histnames.json` の訳語総数は出典ページにも書いてある——英語で
「N localized strings in all」、日本語で「訳語は合わせて N 件」、ほか 7 言語の言い回しで。
`check:docs` の histnames 針は `.md` を「N 名前」「N の訳語」で読むので、**この言い回しは
どの針の射程にも入っていなかった**。見つけた時点で **9 言語すべてが 5,088 と述べ、記録は
5,093 を持っていた**——今回の変更が無くても既にずれており、ずれは広がるだけだった。

⚠ **直し方は 9 通りの言い回しの表ではない。** 訳された主張は**1 つの文とその n 個の訳**なので、
正本が述べる数はどの訳も述べている。⇒ **各ファイルがその数を含むかだけを訊く**——言語に依存せず、
語順の表も要らない（`histb-count` が国境記録について既に使っている形）。
9 ファイルを 6,124 へ直し、針を足した。⚠ **1 ファイルだけ 5,088 に戻す変異で赤になることを確認した。**

⚠ **どちらも「名前が読者に届く割合」と「記録が上流をどれだけ写しているか」の改善であって、
歴史的な名称そのものや古代の年代の正しさの証明ではない。**
