## R309 — **配線はあった。ポップアップは同じ1ミリ秒のうちに取り消されていた**

依頼7件。フロストガラス3件（Countries の並び替え帯／入力欄／地名検索バー）、昔の国名ラベル、
Atlas のプリセット、レイヤー欄の「基本表示」、そしてサムネイル23枚。

### 1.「昔の国の国名ラベルを、今とおなじでクリック可能にして。」

#### 測った — 3回、計器を2回まちがえた

`origin/main` をビルドし、1914 年・z4.2・中欧で実際に押した。

| 何を訊いたか | 答え |
|---|---|
| `imtb-lbl` / `imtb-lbl2` は `clickLayers()` に居るか | **居る**（時間旅行を始めた時点で登録される） |
| クリックでハンドラは発火するか | **する**（同じ層に自分の witness を足して 1 回） |
| カーソルは pointer になるか | **なる** |
| `_imPlacePopup` は呼ばれるか | **呼ばれる**（`R309-PP-CALL Sweden … geojson:true`） |
| `showPopup` は投げるか | **投げない**（catch に log を仕込んで確認） |
| `.maplibregl-popup` は DOM に出るか | **出ない** |

⚠ **最初の2回は私の計器が間違っていた。** ①走査点がウィンドウ座標のまま
`queryRenderedFeatures` に渡っていた（**それは地図コンテナ相対**で、左サイドバー 400 px ぶんずれる）。
②走査点が上部コントロールの下に入っていて、`page.mouse.click` は HTML 要素に当たっていた。
どちらのときも **「現代の国名ラベルも開かない」** という結果が出た——**動いているはずのものが
動いていないと出たら、計器を疑う**。`document.elementFromPoint` が canvas を返す点だけを使い、
コンテナ相対とウィンドウ相対を分けたら、現代側は `Danmark (Denmark) / Copy name / Wikipedia /
AI brief / Isolate / Move` を開き、era 側だけが開かなかった。

#### 原因

MutationObserver を 1 クリックに当てると、`.maplibregl-popup` の追加と削除が
**`+33100` → `-33100`＝同じミリ秒**に記録された。

`js/map-ui.js` の汎用クリック fallback は、タップが自分の `ALL_LBL`（現代の地名ラベル9層）に
**当たらなかった**ときに `clearHL()` を呼ぶ。`clearHL()` は `popup.remove()` を含む。
そしてこの fallback は `_deferLabel`＝`Promise.resolve().then(…)` の中にあるので、
**同期ハンドラが開いたポップアップより必ず後に走る**。era のラベルは `ALL_LBL` に無い。
つまり era のクリックは、**開いて、取り消されて**いた。

#### 直した

`#R210` が `claimClick` / `clickClaimed` を作ったのは**まさにこの衝突のため**で、
`_deferLabel` は最初の一行で `claimed()` を見ている。era 側がそれを名乗っていなかっただけ。
`_clk` の本体を `_openEra(feature, lngLat, e)` に切り出し、ポップアップを開く前に
`GE().events.claimClick(e)` を呼ぶ。

実測（同じ手順・同じビルド）: era ラベルのクリックで
`🇸🇪Sweden / Copy name / Wikipedia / AI brief / Isolate / Move` が開く。

#### 「見た目も挙動も完全に同じに」

`ofm-country`（`js/place-labels.js`）と突き合わせた実測差は8項目あった。

| | `ofm-country` | `imtb-lbl`（改名国） | `imtb-lbl2`（同名国） |
|---|---|---|---|
| `text-font` | `['Noto Sans JP','Noto Sans SC']` | `'Noto Sans Regular'` | `'Noto Sans Regular'` |
| `text-size` (z1→z4) | 12 → 17 | **8.5 → 12** | 12 → 17 |
| `text-letter-spacing` | 0.08 | **0.06** | 0.08 |

| `text-halo-width` | 1.7 | **1.5** | **1.4** |

全部 `ofm-country` の値にした。⚠ `Noto Sans Regular` は `js/map-typography.js` が

**すでに読み手の言語**で焼き込まれており、地物に `name:*` キーが1つも無いので、`placeFont()` の
per-label `case`（`has('name:ja')` を訊く）は**必ず汎 Han 面へ倒れる**。だから `readerFont()`

色は生成時の固定値ではなく `applyLabelLang()` が塗り直す。⚠ **`visibility` は書かない**——
それは `window._applyBorders()` の持ち物で、#R94l が「時間旅行中は**常に**出す」と決めている。

**パディング付きタップ**も足した。`js/map-ui.js` は #R23 から全ての地名ラベルに
マウス 6px・指 15px の当たり判定を持っており（「指のタップはグリフにはまず当たらない」）、
era 側だけそれが無かった＝携帯では**死んだ文字**だった。実測、改修後は +4/+8/+12/+16 px で開く。

⚠ **重複ラベルは私の退行ではない。** 「Austria-Hungary」が3つ出るのは MultiPolygon の
パートごとにアンカーが立つ MapLibre の仕様で、改修前のスクリーンショットにも同じ数だけ出ている。

### 2. フロストガラスの3件 — 原因は2つしかなかった

塗っている同じ `--glass-fill`** をもう一度塗る。実測 `rgba(255,255,255,0.34)`・rect `[24,207,351,43]`

直し方は**このファイルの中に既にあった**: #R40 が `.air-inbar` に出した答え
——**フロストの2モードで背景を透明にし、2度目の `backdrop-filter` を足さない**

⚠ 利用者に確認したところ「3か所すべて直す」だったので、**同じ形を数え直した。5本あった。**

#### ⑵ 詳細度（地名検索バーが潰れる）

同じ `@media(min-width:769px)` の中で:

- `body.sidebar-glass:has(.sidebar:not(.collapsed)) .map-search` … **(0,4,1)**
  （`:has()` の詳細度は引数中で最も詳細な `.sidebar:not(.collapsed)`＝(0,2,0)）
- `body.ms-narrow .map-search` … **(0,2,1)**

前者が `left` と `max-width` を、後者が `right` / `width:auto` / `transform:none` を持っていく。
ところが `--ms-left` と `--ms-right` は `js/mobile-ui.js` が**「見える帯の中央にピルを置く」ために
対で**書いた値で、片方だけ採ると意味を失う。

実測（1440×900・translucent・左サイドバー展開・右 Layers 開）: `body` は
`sidebar-translucent sidebar-glass lsr-avail lsr-open ms-narrow`、`#map-search` は
`left:920px` / `right:619px` / rect **`[920, 14, 18, 43]`＝幅 18px**。
`920 = 400 + (1440−400)/2` で、フロスト用の式そのもの。

→ ① `:not(.ms-narrow)` を足して、watcher が担当しているときは**規則ごと降りる**。
② 降りない広い窓のために `body.lsr-open` の枝を足し、**中心と max-width の両方から `--lsr-w` を引く**
（元の式は右サイドバーを一切引いておらず、潰れないときも右へ寄りすぎ・広すぎだった）。

実測 **18 → 380 px**、左サイドバー右端 400・右サイドバー左端 1140・上部コントロール 840 の
**どれとも重ならない**。1920 幅（`ms-narrow` が付かない経路）でも [961,10,398,43]（右端 1359 が
コントロール左端 1320 と重なっていた）→ [811,10,398,43]。**Solid は全条件で前後完全一致。**

### 3.「Base map & labels のオン数をレイヤーのオン数にみなすな。」

数えていた理由は、**その節の中身が4つの写しで食い違っていたこと**だった。

| 写し | 中身 |
|---|---|
| `_refreshActiveLayers()` の `skip`（`Active layers (N)`） | **11 個**——`dl-tz` と `beta-dl-bldg3d` が無い |
| `reorganizeLayerPanel` の並べ替え | 10 個 ＋ 後から `rowFor()` で3行 |
| 未配置行の掃き出し除外 | 10 個 |
| `IntMapWidgetCore.activeLayers()`（`N layers on`） | 10 個の `cb-*` を**偶然**除外（bare label なので `.lyr-row` に当たらない）＝残り3つを数えていた |

#R235 が `dl-nightside` について一度直したが、**直したのは4つのうち1つ**で、
#R271（`dl-tz`）と #R273（`beta-dl-bldg3d`）が節へ移したときどの写しも学ばなかった。

→ **`window.IntMapBasicLayers`（13 個）を1本立てて、数える側は全部それを引く。**
実測、`Active layers (2)` と ウィジェットの `2` が一致（オンの基本表示 8 個が両方から外れる）。
**おすすめレイヤーのルーレット**も同じ一覧を読むので、基本表示を「まだ試していないレイヤー」として
勧めなくなった——`docs/MAP-LAYERS.md` が要求していたのに、`FEAT_IDS` という**もう存在しない名前**を
指していたので誰も守っていなかった規則。

⚠ **末尾の「OFF を再送しない」除外は別の規則**（#R38: 状態を持つハンドラを再 dispatch すると
勝手に ON へ戻る）。同じ id が並ぶが問いが違うので、統合していない。

**形も変えた。** 基本表示の 13 行だけ、3列タイルではなく**全幅の行＋iOS 風トグル**
（`.lst-tile.lst-row` ＋ `.lst-sw`）で、**サムネイルを持たない**——「地名」の写真は
言葉以上のことを何も言わない。⚠ 行も `.lst-tile` クラスを持ち続ける：
`syncTiles` / `filterTiles` / `_setTileOn` と「行数が変わったら建て直す」3つの門が
**全部このクラスを問い合わせている**ので、別のクラス名にすれば全部を探し直すことになる。
実測 **66 → 46 px**（最初 `box-sizing:border-box` を書き忘れて `min-height:46px` が効いていなかった）。

### 4.「Atlas のプリセットを、今地図で見ている地域に応じて。」

4つの定数だった。ケニアへ飛んだ人にも「アメリカ・中国・インドを比較」を出していて、
**同じファイルの 60 行上にある `codeAtPoint`** に一度も訊いていなかった。

`_exPlace()` が地図中心の国を解き、`examples()` がその名前を差し込んだ4本
（最新の状況／周辺国との比較／1990年からの経済／天気と発表中の警報）を返す。
海の上や、**1つの国を主題と呼べないほど引いた表示（z<2.5）**では世界規模の4本に戻る。
⚠ **ズームの床は答えの一部であって調整つまみではない**——半球を見ているときに中心画素が落ちた国を
名乗るのは、#R302 が日照パネルから外した「推測に名前を付ける」と同じ誤り。

引き直しはカメラが落ち着いて **600 ms**（`js/widget-scheduler.js` が pan の後に待つのと同じ静けさ）、
**主題が変わったときだけ**。チップを描く関数は**1つ**にした——2か所に書かれていたので、
カメラという3人目の呼び手は3つ目の写しになるところだった。

⚠⚠ **同時に i18n の穴が1つ塞がった。** 旧実装は `L([...],[...],…)` と**配列**を渡しており、
`js/lang-registry.js` は `arguments[0]` が**文字列のときしか** inline 表を引かない
＝ **zh / zh-hans / fr / ko では4つのチップが全部英語のまま**だった。しかも
`scripts/i18n-report.mjs` は「第1引数が Literal でない `L()`」を捨てるので、
**`check:i18n` は 100% 緑を出していた**。1文字列1呼び出しに書き替えたので、
いまは計器に見えている——そして 4 言語ぶんの穴が実際に開き、埋めた。

⚠⚠⚠ **そして 9 言語を埋める過程で、私が書いた文の2つが誤りだと分かった。**

**⑴ ロシア語の `{place}` が格変化していなかった。** `cName()` が返すのは CLDR の国名——
**冠詞なし・主格**（`Кения` / `Schweiz` / `Kenya`）——なので、格を要求する位置に差し込むと
`в Кения`（正しくは `в Кении`）になる。ロシア語はほぼ全部の国名が変化し、ドイツ語も
20数か国に冠詞が付く（`von Schweiz` / `mit die Schweiz`）。→ **ru と de を、名前を先頭に置く
同格の形に書き直した**（`{place} — что происходит прямо сейчас?` /
`{place}: Wie hat sich die Wirtschaft seit 1990 entwickelt?`）。フランス語と韓国語は
翻訳の段階で同じ手が採られている（仏は `sur le` / `de la` を避ける同格、韓は音節末で変わる
은/는・와/과 を1つも使わない）。日本語・スペイン語・英語は名前をそのまま置ける。
⚠ **英語の文字列だけは書き替えない**——それが4言語の**引き当て鍵**で、locale 表がそれで索引されている。

**⑵ 世界表示の4本目、日本語だけ別の質問だった。** `L('Which countries have the highest life
expectancy?','日本の経済は1990年からどう変わった？',…)`——配列形だった頃からの取り違えで、
`check:i18n` は「鍵に値があるか」しか見ないので緑のまま通っていた。→ 鍵の訳
（`平均寿命が最も長い国は？`）に直した。**日本語の読み手はこれで「平均寿命」の例を取り戻す**。
⚠ **1本目の「日本・ドイツ・インドを比較」（英語は USA/China/India）は<b>直していない</b>**
——#R103 が「JP stays Japan-flavoured」と明記した**意図的なローカライズ**で、質問の形は同じ
（大国3つを比べる）。⑵ は質問そのものが別だったので誤りだが、こちらは違う。
