## R534 — **「開いているシミュレーション」は、値ではなくキーを読んでいた**

> 報告:「Atlasの地図画像誤答 — 欠陥修正のみ。今回の誤答は、Vision機構を作り直す必要のある問題ではありません。
> 既存の Atlas state pipeline に明確な欠陥があります。」

地図の画像を見せて何が写っているかを訊いたら、Atlas は**放射線または日射シミュレーション**だと答えた。
どちらも地図に出ていない。画像の取得・Vision チャネル・シミュレーションのモジュール本体は関係が無く、
**state パイプラインは最後の1行まで正しくて、最後の1行が答えを捨てていた。**

### 直接原因 — 訊いた答えを、キーの存在で上書きしていた

`js/atlas-console.js:3979` の `_simulationState()` は、各モジュールに `state()` / `isOpen()` / `painted()` を
**訊いて**、返ってきた答えを記録する（#R290 の読み順——「起動された」という事実から推定しない）。
だから radiation と insolation——**boot 時に必ず生成される 2 本**（js/app-body.js:4087 / :3772）——は、
読者が何も触っていなくても正直に `{open:false}` / `{painted:false}` を publish する。これは正常。

`js/atlas-state.js` の `renderPrompt()` が、それをこう印字していた:

```js
var sim = snap.simulations;
if (sim && Object.keys(sim).length) lines.push('Simulations open: ' + Object.keys(sim).join(', ') + '.');
```

**値を一度も読んでいない。** キーがあるだけで「開いている」と Atlas に伝わる:

```
{radiation:{open:false}, insolation:{painted:false}}  →  "Simulations open: radiation, insolation."
```

⚠ **ON と OFF が同一の文になる**（`open:false` と `open:true` の出力が 1 バイトも違わない。実測）。
Atlas はその文のとおりに答えたのであって、間違えたのは Atlas ではない。

### 実測 — 8 モジュールの公開 API は揃っていない

直す前に、`_simulationState()` が名指す 8 本が**実際に何を publish しているか**を全部読んだ。

| モジュール | `state()` | `isOpen()` | `painted()` | presence として届くキー |
|---|---|---|---|---|
| IntMapSeismic (js/seismic.js:5491) | あり | 無い | 無い | `open`（パネル表示） |
| IntMapTsunami (js/tsunami.js:1123) | あり | 無い | 無い | `open`（パネル表示） |
| IntMapTerrainWater (js/terrain-water.js:2674) | あり | あり:2449 | 無い | `open`（パネル表示） |
| IntMapLOS (js/viewshed.js:745) | あり | あり:722 | 無い | `open`（パネル表示） |
| IntMapNightSky (js/night-sky.js:893) | あり | あり:876 | 無い | `open`（**地図を覆う全画面オーバーレイ**） |
| IntMapRadiation (js/sims.js:273) | 無い | あり | 無い | `open`（パネル表示 **または** `imrad-src` に feature） |
| IntMapFlightSim (js/flight-sim.js:2146) | 無い | 無い | 無い | **何も出ない**（`active()` だけ） |
| IntMapInsolation (js/insolation.js:333) | あり | 無い | 無い（`isPainted`） | `painted`（ラスタを実際に載せた） |

⚠⚠⚠ **`painted()` メソッドを実装しているモジュールは 0 本。** insolation は `isPainted` という別名なので
`typeof m.painted==='function'` に当たらない——`painted` が snapshot に届く経路は `state()` のキーだけである。
（probe 自体は残す。モジュールが答えてよい契約であることに変わりはない。）

⚠⚠ **`open` の意味はモジュールごとに違う。** 5 本は「パネルが表示されている」、nightSky は
「地図を覆う板が出ている」、**描画源そのものを見ているのは radiation だけ**。

### 直し方 — 語彙を 1 つ宣言し、値を読む

```js
var SIM_PRESENT = ['open', 'painted'];
...
var simOn = Object.keys(sim).filter(function (k) {
  var st = sim[k];
  if (!st || typeof st !== 'object') return false;
  return SIM_PRESENT.some(function (f) { return st[f] === true; });
});
if (simOn.length) lines.push('Simulations open: ' + simOn.join(', ') + '.');
```

新しい state schema も Render Manifest も consistency gate も足していない（報告の指示どおり）。
既に取得済みの値を読むだけである。

⚠⚠⚠ **「truthy なフィールドが 1 つでもあれば active」では直らない。** `js/viewshed.js:745` は
**パネルが閉じていても** `obsH:2` `tgtH:0` `rangeKm:60` `k:1.3333` を publish する——
**パラメータはただで truthy** なので、その修理は LOS を「開いている」と言い続ける＝
同じ嘘を別の形で言い直すだけになる。`tests/r534 ③` がその修理を明示的に赤にする。

### 検査 — `tests/r534-checks.test.mjs`（8 本）

① 報告された形が何も言わないこと／①b `open` と `painted` の両方の経路／
② **本当に出ているものは今も名指されること**（文を消す修理を止める）／②b 4 本混在で active な 2 本だけ／
③ パラメータは presence ではない／④ **旧実装をその場で書き直して、報告どおりの偽文が出ることを示す**／
⑤ **語彙を provider のソースから読む**——`_simulationState()` の `st.<名前>=` 代入を数え上げ、
`SIM_PRESENT` と**集合として一致**することを要求する／⑤b provider が今も「訊いて」いること。

⚠⚠ ⑤ が #R529 の教訓の 1 段小さい版である: **ソースが既に持っている一覧を、手で二重に持たない。**
provider が 3 つ目の probe（`st.active = !!m.active()`）を覚えたら、renderer に教えるまで赤いままになる
——そのモジュールが黙って文から抜け落ちる代わりに。

⚠⚠ **緑を見ただけでは何も証明できない**ので、6 通りの壊し方で赤を実測した:

| 壊し方 | 結果 |
|---|---|

### 今回直していない（範囲外・実測済み）

報告が「触らなくてよいもの」を明示していたので、**次の 2 件は直さずに記録する**。

1. ⚠⚠⚠ **flightSim は `simulations` に一度も現れない。** `state`/`isOpen`/`painted` のどれも持たず
   `active()`（js/flight-sim.js:2146）だけなので、`_simulationState()` の `Object.keys(st).length` が 0 になり
   キーごと落ちる（js/atlas-console.js:3985）。**飛行中でも Atlas はそれを知らない。**
   直すなら provider に `st.active = !!m.active()` を 1 行足すが、それは Atlas に渡る文の変更である。
   ⚠ そのとき `tests/r534 ⑤` が赤くなり、`SIM_PRESENT` に `active` を足すまで通らない（上の表 ⓔ で実測済み）。
2. ⚠⚠ **`open` は「地図に描かれている」ではない。** `open:true` なのに何も無い窓は全モジュールにある
   （パネルを開けた直後の非同期 build 中）。LOS の `clear()` は `last` を null にしない（js/viewshed.js:710）ので
   「消去」後も `last` が残り、radiation は沈着ゾーンを描いてからプルーム点を書くので
   `open:false` のまま沈着が出ている 1 フレームの窓がある。
   これらは «Simulations open» という文が主張していることの**外側**なので、この文の修正では扱わない。
