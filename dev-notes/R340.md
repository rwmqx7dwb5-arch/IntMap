## R340 — **「最近の出来事をまとめて」が無関係な記事を1つの出来事にしていた——254ラウンド、検査は0件**

「IntMap の Atlas capability `research.events` が、現在の本番データで誤ったクラスタリングをしている。」

### 何が起きていたか（実測）

`research.events`（#R76・別名 `newsEvents` / `groupNews`）は、読み込み済みのニュースを
**出来事単位**に束ねて返す。束ね方は `js/atlas-console.js` の 58 行の `case` の中に直書きされており、
**`tests/` にこの機能を名乗る検査は1本も無かった**。ブラウザの外から呼べる形になっていないので、
そもそも書きようが無かった。

本番 `current_news` の **1,641 行**を、出荷中の決定論エンジン `js/newsgeo.js` に通して測った
（＝ブラウザで実際に効いている経路。`USE_SERVER_NEWS=false`）:

| | 件数 |
|---|---|
| 地点が付いた記事 | 1,005 |
| うち **「国」に解決**したもの | **499（49.7%）** |
| `[-98, 39.5]`（United States）の **1点**に積み上がった記事 | **92** |
| `[104, 35]`（中国） | 64 |
| `[31.5, 49]`（ウクライナ） | 46 |

#R76 の規則は「場所 ≤150 km × 時刻 ≤48 h × Jaccard ≥0.15、**ただし `d<30 km && Δt≤24 h` なら
≥0.06 に緩和**」。国レベルの主題どうしは **`d` が厳密に 0** なので、緩和の地理条件は
**構造的に必ず真**になる。残る関門は **6%** だけで、CJK バイグラムが2つ一致するか、
英単語が1つ共通するだけで超える。実測（600件）**283 events ／ 最大 36 ／ 全 join の 60% が緩和経由**。

36件の「1つの出来事」の中身: イランの経済戦争／目薬 40,000 本の回収／アメリカン航空機内の
ノートPC 発火／米国債務 40 兆ドル／子のいない米国人の老後不安。

**根本原因**は `d = 0` を**近接として扱っていたこと**。国の重心に載った2記事は「同じ場所にある」
のではなく**「同じ名前で整理されている」**だけで、その一致は地理的な証拠を1ビットも含まない。
#R76 はそれを**証拠の割引**として使っていた。

### 途中で前提が変わった——#R334 が同じ結論に独立に到達していた

このラウンドの作業中に **#R334（IM-20260823-001 Phase B）が merge** され、
`supabase/functions/_shared/news-cluster.js`（348行）が入った。読むと**同じ根本原因**に
到達しており、しかもこちらが独自に書いていたものより**良い**:

| | このラウンドの初稿 | #R334 |
|---|---|---|
| 場所の扱い | 精密／代表点の2分 | **6段**（tight / near / countrySame / countryNear / unknown / far） |
| 代表点の閾値 | 他と同じ | **他より高い**（0.27 > near 0.24 > tight 0.19） |
| 判定の入口 | Jaccard のみ | Jaccard ／ **包含率** ／ **IDF 重み**の3つ |
| 推移 | 素の union-find | **強い辺から結び、塊どうしは過半の対が一致するかを検算**（0.34） |
| 語幹化 | 無し | 語尾4種だけ落とす保守的な形 |

そして `docs/NEWS-EVENTS.md` は「`research.events` は新パイプラインへ載せ替える。
**第二のクラスタリング実装を残さない**」と決めている。

⇒ **自分が書いた実装を捨て、共有モジュールを import した。**
`js/news-cluster.js` は**アダプタ**になった——読み込み済みフィードの項目の形を入れて、
返信に出す出来事オブジェクトの形で返すだけ。**「同じ出来事か」を決める式は1本しか無い。**

⚠ **写しは作っていない。** `js/newsgeo.js` が `supabase/functions/_shared/` へ**複製**されるのは、
Deno の Edge Function が `supabase/functions/` の外を import できないからで、
**この制約は一方向にしか効かない**。Vite のバンドルには同じ制約が無いので、ブラウザ側は
共有ファイルを直接読む。**写しは古くなりうるが、1本しかないものは古くなりようがない。**

### #R334 の検査 ⑪ を書き換えた（緩めたのではない）

⑪「the clustering logic is server-only and reaches no client bundle」は、
`js/` と `src/` を `git grep news-cluster` して0件であることを要求していた。
**理由はその検査自身に書いてある**——「src/main.js が js/*.js を**全部** import する構造なので、
js/ に置いた瞬間 eager バンドルへ入る」。

**その前提はこの構成では成り立たない。** `src/main.js` は js/ を全部 import してはおらず
（`scripts/static-checks.mjs` は静的 import・動的 import・兄弟 import の3経路を認めている）、
`js/atlas-console.js` は `js/lazy-modules.js` に載った**押されてから取りに行くモジュール**である。
**実測: 起動時に配られる chunk に `countrySame` は 0 件**で、出てくるのは Atlas を開いたときの
async chunk だけ。指示 §17 の要件（「clustering をブラウザの**起動経路**へ置かない」）は満たされている。

⇒ ファイル名を grep するのをやめ、**「参照してよいのはアダプタ経由だけ」＋「アダプタを import
している側は `lazyFiles()` に載っていること」**を直接主張する形にした。
⚠ **緩和ではない**——元の形は「eager に入ったか」を一度も見ていなかった。
⚠ `src/main.js` に `import '../js/news-cluster.js';` を1行足すと**赤くなることを確かめた**。

### このラウンドがまだ決めていること

アダプタが決めるのは2つだけ:

1. **記事がどの点にあるか。** `analysis.subjectLoc`（主題）を見る。Publisher ピンモードでは
   `js/app-body.js` の `applyPinMode()` が `analysis.loc` を媒体HQへ書き換えるので、その状態で
   events を撃つと「CNN の全記事がアトランタで起きた1つの出来事」になりうる。
   **出来事が何であるかが表示トグルで変わってはならない。** 保存済み記事のスナップショット
   （`js/news-ui.js` の `snapAnalysis`）は `subjectLoc` を持たないので、そこは `mapped === true`
   ＝「このピンは主題である」というレコード自身の申告を使う。範囲指定（「東京の出来事」）の
   絞り込みも同じ問いを訊く。
2. **出来事を返信でどう見せるか。** 媒体の一覧・重心・「最初の報道→最新」の幅。

**`case 'events'` の3つの `return` は `meta` を1つも持っていなかった。** 能力表は
`produces = 'map,explanation'` と宣言しているので、`PLACE_NOT_FOUND` / `NO_ARTICLES` / `OK` を付けた。
`OK` は**ピンが実際に描けたか**で `produced` を分ける。⚠ 依頼は「4つの return」と書いていたが、
このブロックには **3つしかない**——引用された行範囲の先頭1行が、隣の `case 'impact'` の閉じ
`return` だった。`impact` は触っていない。

**脚注も直した。** 「位置≤150km×時間≤48h×見出し類似」と**規則そのもの**を書いていたので、
数値を共有モジュールの `DEFAULTS` から**読む**ようにした（9言語。`place` と
`headline similarity` の2語を `scripts/i18n/r340-a.json` に足し、fr / ko / zh-Hant へ、
zh-Hans は生成）。⚠ 代表点についての説明も「束ねません」から
**「より強く一致を求めます」**に直した——共有モジュールは閾値を**上げて**いるので、前の文は嘘だった。

### 検査（`tests/r340-checks.test.mjs`・10本・`test:checks` に登録済み）

corpus は**本番の見出し 400 件**を出荷中の locator に通した本物の答え付き。捏造は1件も無い。
壁時計を読まない（`capturedAt` を固定して「何時間前か」を検査側が渡す）。

① fixture が壊れていないこと／② **Walmart の決算と Apple Pay 対応が別の出来事**（かつ Apple Pay は
まとまっている＝過剰分割で「直した」ことにしない）／③ **刀襲撃が1つの出来事**（9報すべて）／
④ United States 代表点の最大クラスタが小さく、全員が語彙を共有していること／
⑤ 0.06 の緩和分岐が出荷ソースから消えていること・`case` が自前の union-find を持ち直していないこと・
**アダプタが閾値を1つも持っていないこと**（`0.\d+` が0個）・`countrySame > near > tight` という
**anti-#R76 の不変条件**／⑥ `geoClass()` の6分類と `pairVerdict()` の理由／
⑦ **Publisher ピンモードで events が1件も変わらない**／⑧ トークン化が**真の一致を上げ・偽の一致を下げる**
（刀襲撃の2報 0.417→**0.714**、furniture だけの2本 0.357→**0.222**）／⑨ 決定論／
⑩ 3つの `return` すべてが `meta` を持ち、脚注が定数を**読んで**いること。

⚠ **落ちうる門であることを確かめた。** 共有モジュールの閾値を #R76 の形
（tight 0.06 / near 0.15 / countrySame 0.06）に差し替えると **②④⑤⑧⑨ が赤**。
⑤⑩ は `git show origin/main:js/atlas-console.js` に対して3本の正規表現がすべて当たり、
`return` 3件 / `meta` 0件を報告する。

⚠ **検査自身の欠陥を3つ踏んだ。** ⑨の最初の版は各出来事を `titles.join('|')` で表していたが、
**実際の見出しに `|` が入っている**（「…in Bali | World News」）ので同じ入力の2回の実行が不一致に
なった——区切り文字は値の中に現れてはならない。⑨の次の版は
`js/news-cluster.js` を `Date.now()` で grep して赤くなった——当たったのは
**「`Date.now()` を呼んではならない理由」を書いた自分のコメント**だった（コメントを剥がしてから測る）。
⑧の最初の版は「ひらがなの膠着」の例に `のロ`（ひらがな＋カタカナ）を挙げていた——規則は
**文字の種類**であって助詞かどうかではない。

### 直していないこと

- **共有モジュールのアルゴリズムには一切手を入れていない。** ヘッダの注記だけ直した
  （「ブラウザのバンドルに入れてはならない」は、このラウンドで事実でなくなったため）。
- ⚠ **日本語の見出しについて**: 共有モジュールのトークン化はひらがなだけのバイグラム
  （「など」「した」「には」）を落とさない。初稿ではそれを落としており、JP 300 件で
  **正しい統合が1件増え、誤分割は0件**だった。ただし#R334 側の fixture で測っていないので、
  **サーバー側の挙動を変える提案としては未検証**。現状のフィードは 43% が日本語なので、
  次のラウンドで #R334 の fixture に対して測る価値がある。
- ⚠ **rebase のたびにこのファイルの索引が壊れる。** 本ラウンドは4回 rebase したが、そのたびに
  `origin/main` の索引に**並びの乱れ**か**重複**があった。ここで直したのは**行の並べ替えだけ**——
  64行を降順に並べ直した（**足しても引いてもいない純粋な置換**であることを、並べ替えの前後で
  行の多重集合が一致することで確かめてある）。⚠ **`#R310` は内容の違う2行が並んでおり、
  どちらが正しいかは書いた人にしか決められないので触っていない**（`#R323` の byte 同一な重複は、
  別のラウンドが既に直していた）。⚠ **索引と本文の並びを突き合わせる検査はまだ無い**——
  `tests/r217 ⑦a` が見ているのは `##` 見出しの並びだけで、索引はどう壊れても赤にならない。
- **`.claude/launch.json` は触っていない。** `origin/main` の最新エントリは `intmap-preview-r322` で、
  #R323 / #R325 / #R333 / #R334 はどれも足していない。追跡対象のこのファイルを毎ラウンド触ると
  `master-sync --ff-only` が塞がる（#R320 の実測）。⚠ `CLAUDE.md` §2 は「新しいラウンドでは
  同じ形で1件追加する」と書いたままなので、**規程と実態が食い違っている**。
