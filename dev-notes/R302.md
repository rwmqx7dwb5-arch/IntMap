### ⑤ 風——「品質保ったまま爆速に」。標本も格子も粒子も補間も1つも触っていない

削ったのは**待ち・重複・再構築**だけ。

1. **SDK 340 kB と `latest.json` 3 kB が直列だった**（`loadSDK().then(… fetchMeta() …)`。ファイル自身の
   コメントが「メタデータは SDK を必要としない」と書いていた）。→ `Promise.all`。stub 実測で
   resolve **460 → 352 ms**。
2. **粒子のリスポーンごとに `getBounds()` と `heldBand()` を訊いていた**（`heldBand` は `stateKey()` を
   通り `Date.parse`×2 と `new URLSearchParams`×2。寿命 1.2〜3.6 秒・最大 6,000 粒子＝**毎秒 2,500 回**）。
   1フレームの中で値は変わらない。→ **フレーム単位で1回**（`spawnCtx`）。撒く範囲・帯の門・8回の
   やり直しは1つも変えていない。
3. **予報時刻の先読みが地球まるごとを暖めていた**——`prefetch(vars, i+1)` に**視野を渡していなかった**
   ので `band=null` に落ち、1か国を見ている読み手のために **13.2M 標本**を暖めていた。しかも
   **風レイヤーが OFF でも** u/v の2変数を連結していた。→ 視野を渡し、風が ON のときだけ含める。
4. **時刻ラベル 109 件に毎回 `Intl` を作っていた**（凡例は `load()` の開始と終了・`time`/`play`/`meta`
   ごとに再描画される）。→ **軸・言語・タイムゾーンを鍵にメモ化**。9言語×3TZ×2軸×3now×5index＝
   **810 レンダーで出力差分 0**、`E.fmt` 呼び出し **1,332 → 133**。
5. **`fmt()` が値ごとに `Intl.DateTimeFormat` を作っていた**。→ `[locale, options]` でメモ化。
   9言語×3TZ×48時刻＝**1,296 件で `toLocaleString` と完全一致**。
6. **`warmed[mark]` を非同期の前に立てて一度も降ろしていなかった**——失敗した warm は
   ページの寿命ぶん永久に再試行されない。→ 失敗で降ろす。
7. **色面スロットが同じ鍵で二度発注されうる窓があった**（`load()` が非同期なので `idle` が先に来る）。
   `addField` は無条件に remove→removeSource→addSource する。→ `liveSlot` で早期 return。
8. **`fetchMeta(force)` に `force` を渡す呼び出しが 0 件だった**＝新しいモデルランで軸を貼り直す分岐が
   **到達不能**で、開きっぱなしのタブは前日のランを持ち続ける。→ 15 分の窓。実測、時計を16分進めると
   `referenceTime` が **00Z → 06Z**。
   ⚠ **採らなかったもの**: `setToOmFile` の「今そのファイルを指しているか」ガード。固定版 SDK の中を
   読んだところ、**色面ラスタが1枚デコードされるたびに、この module の外で共有 reader が別ファイルへ
   向け直される**（2スロット＝2時刻が同時に生きる）。現在のファイルを晒すプロパティも無いので、
   このキャッシュは**外れたときに静かに別の時刻を読む**＝品質の退行になる。
