## R443 — **同じ行の右半分だけが英語だった。訳が無かったのではなく、読み手が居なかった**

報告は本番（R430・日本語）の国別カード1行についてのものだった。

```
アメリカ合衆国   Region  北アメリカ / Northern America
ドイツ           Region  ヨーロッパ / Western Europe
```

左は訳されていて、右は英語。de / ru / es / fr / ko / zh-Hant / zh-Hans でも同じ。
`js/countries-ui.js` の `renderCountryDetailBody()` の1行が、そのまま画面である。

```js
[HOST.t('statRegion'),(s.region?_regionName(s.region):'—')+(s.subregion?' / '+s.subregion:'')],
```

#R424 はこの行の**左半分**を直したラウンドで、右半分を1文で見送っていた——「`subregion` は
Natural Earth の約24値の SUBREGION で、**表に無いので**当面は英語のまま（首都と同じ）」。

**その一文が、このリポジトリについて事実ではなかった。**

### 書く前に、上流と自分たちの持ち物を数えた

まず語彙。`loadCountryData()` が取りに行く3つの縮尺を実際に取得して数えた（2026-08-25）。

| ファイル | features | 異なり SUBREGION | 空の SUBREGION |
|---|---|---|---|
| `ne_110m_admin_0_countries` | 177 | **22** | **0** |
| `ne_50m_admin_0_countries` | 242 | **24** | **0** |
| `ne_10m_admin_0_countries` | 258 | **24** | **0** |

和集合は**ちょうど24値**。110m に無い2つは `Micronesia` と `Polynesia`（ミクロネシア連邦・
北マリアナ・グアム／米領サモア・トンガ・サモア…＝細かい縮尺にだけ居る島嶼）。
そして**どの縮尺にも空の SUBREGION が1件も無い**ので、`enrichCountry()` の

```js
if(!s.subregion && c.subregion) s.subregion=c.subregion;   // restcountries
```

は**この欄では実際には通らない**。#R424 が CONTINENT について測ったのと、同じ結論が隣の欄でも
成り立っていた。

次に持ち物。**24値ぶんの9言語の訳は、すでに全部このリポジトリの中に在った。**

- `js/atlas-examples.js` の `SUB` が **22値**。#R313 追記2 が置いたもので、そのラウンドは
  「M49 コードを `Intl.DisplayNames` に訊く」実装が**ブラウザでは22中0しか解決しない**（Node の
  ICU では22中22。だから Node を測っていた門は永久に緑だった）ことを本番で実測して、
  **出荷文字列**に切り替えている。
- 残る2値 `Antarctica` と `Seven seas (open ocean)` は、**`_REGIONS` の鍵として既に在った**
  （#R424 が「Natural Earth には8つ目の CONTINENT 値がある」を実測して足したもの）。
- `js/locales/ui.{fr,ko,zh,zh-hans}.js` は **24値すべて inline 済み**（実測 欠け0・英語と同一の
  値も0）。

つまり **訳が無かったのではない。同じ欄について表が2つ在り、カードがそのどちらにも繋がって
いなかった。** このラウンドで書いた新しい訳語は**0語**である。

### 直し方は「もう1つ表を作る」ではない

同じ24語×5引数をもう1本置けば、次に綴りを直した誰かが**片方だけ**直す。それは今回の欠陥
そのものの形なので、**表を1本にして読み手を2つにした。**

- `js/countries-ui.js` の top-level に `window._imSubregionName = function(sub, lang){…}` を置く。
  表は関数自身に遅延で吊る（`window._imSubregionName._t` ＝ 同じファイルの
  `window._imCldrRegion._c` と同じ形。`tests/r175 ③` の「未 export の top-level 宣言を作らない」に
  触れない）。解決は `IntMapLang.t(lang, …)`＝`pick()` に言語を第1引数で渡す形なので、
  en/jp/de/ru/es は位置引数、fr/ko/zh/zh-hans は英語の鍵で inline 表——**他のどの呼び出し口とも
  同じ規則**。
- `js/atlas-examples.js` はそこを読み、自分の `SUB` を捨てる。`subName()` は `HOST.lang` を
  渡すだけになった。
- 門は `tests/r424-checks ⑩`。**`js/*.js` を全部読んで、この24語を宣言しているファイルが
  ちょうど1本であること**を検査する。`js/locales/ui.*.js` の inline 表は別の機構（英語の鍵で
  引く、位置引数の5つより先の言語のためのもの）なので対象外。

### 最初は `export` にして、挙動を1バイトも変えないまま16件を赤くした

`tests/r175 ③` は「未 export の top-level 宣言」を禁じており、その診断文自身が
«wrapped, exported, or **attached to window** instead» と3つを並べている。**export のほうが
検査しやすい**（`import` される名前として追える）ので最初はそれを選んだ。

`npm run test:checks` が **2,737 件中 16 件赤**を返した。

```
✖ R375 ① every id the geometry produces has a row in countryStats
     SyntaxError: Unexpected token 'export'
         at new Function (<anonymous>)
```

`js/countries-ui.js` は、**複数の検査ハーネスが `new Function(src)` で素のスクリプトとして
実行している**——合成した Natural Earth feature を本物の `_mkStat` と本物の 10 m 昇格パスに
通して、`tests/r375` ①〜⑦（#R375 の「110m 177 コードと 10m 252 コードの差 75 行」）、
`tests/r423` ①〜③（#R423 のノルウェー）を測るため。**`export` という1語が、その全部に対して
SyntaxError である。**

⚠ **前例のほうが正しかった。** 同じファイルの `window._imCldrRegion` が window に載っている
理由がこれで、`export` を選んだのは**その理由を読まずに一般論で決めた**ということだった。
⑩ にその性質を直接足した——`js/countries-ui.js` が **classic script として parse できること**を
`acorn` で確かめ、`new Function(` と `countries-ui.js` の両方を含む検査ファイルを
**ディレクトリから数えて**（名前を書き写さずに）3本以上あることを言う。制約が消えた日には
その行が先に落ちるので、次の誰かは16件ではなく1件から学ぶ。

### 訳した瞬間に、同じ語が2回出る行が出てくる

Natural Earth の CONTINENT と SUBREGION は、**同じ場所を指す組**を4つ持っている。

| CONTINENT | SUBREGION | 行数 | en | ja / de / ru / es / fr / ko / zh / zh-hans |
|---|---|---:|---|---|
| North America | Northern America | 13 | **別語** | **同語**（北アメリカ・Nordamerika・Северная Америка …） |
| South America | South America | 41 | 同語 | 同語 |
| Antarctica | Antarctica | 3 | 同語 | 同語 |
| Seven seas (open ocean) | Seven seas (open ocean) | 12 | 同語 | 同語 |

英語では今この瞬間も「South America / South America」と出ている（41行）。訳せば ja/de/ru/es/
fr/ko/zh でも「北アメリカ / 北アメリカ」が出る。⇒ **解決したあとの文字列が一致したら1つに畳む。**

```js
const _regRow=(a,b)=>(a||'—')+((b&&b!==a)?' / '+b:'');
```

⚠ **比べるのは訳したあとの文字列であって、英語の鍵ではない。** 鍵で比べれば
`North America ≠ Northern America` なので4組のうち3組しか畳めず、しかも英語では
**畳んではいけない**（別の語なので、両方出るのが正しい）。手書きの組表を持てば、次に訳語を
編集した誰かの手で静かに古くなる。**読者が見ようとしているものを比べる**のが、唯一ずれない。

### 移した表を綴りで探していた門が、移した瞬間に赤くなった

`tests/r313b ②` は `const SUB=\{…\};` を正規表現で切り出し、`SUB[s]` を `subName()` の中に
要求していた。**表が動いた瞬間に2本とも赤。** これは [[intmap-r433-lessons]] の形
——退役した綴りは、製品ではなく**それをまだ検査しているもの**に生き残る——なので、
検査は消さずに**新しい住所へ向け直した**。守っている性質（「名前は出荷された literal で、
実行時に何も引かない」「ja は日本語の字・ru はキリル文字」「de/es は英語の写しではない」）は
1つも変えていない。

⚠ **1か所だけ、性質の書き方を変える必要があった。** 「`Intl.DisplayNames` を使っていない」は
`js/atlas-examples.js` に対してはファイル全体に掛けられたが、移転先の `js/countries-ui.js` には
**`window._imCldrRegion` が居る**（2文字の国コードのための、ブラウザが実際に答えられる唯一の
用途）。ファイル全体に掛ければ必ず誤検出するので、**解決器の本体だけ**を切り出して掛けた。

### 検査

`tests/r424-checks.test.mjs` に ⑥〜⑩ を足した（新しい表形の門は作らない——同じ主題は同じ
ファイル）。

| | 何を訊くか |
|---|---|
| ⑥ | 表の鍵の集合が **Natural Earth の24値そのもの**か（欠けも、上流に無い鍵も赤） |
| ⑦ | 各行が **5引数の call** で、第0引数が自分の鍵か（`scripts/i18n-*.mjs` が見える形） |
| ⑧ | **app 自身の解決器を実行して**9言語ぶんの答えを見る（es の `Melanesia`/`Micronesia` だけが英語と同綴りで、それは RAE の綴り＝`scripts/i18n-positional-audit.mjs` が #R309 から同じ主張を持っている） |
| ⑨ | 2つの表が**重なる3鍵で同じ5引数**か＋4組が**9言語で実際に一致するか**（`en North America / Northern America` だけが不一致であることを `deepEqual` で固定） |
| ⑩ | カードが解決器を通しているか・畳みが**解決後**を比べているか・**24語を宣言する `js/*.js` がちょうど1本**か・Atlas が同じ表を読んでいるか・**`js/countries-ui.js` が classic script として parse できるか**（上の節） |

そして**画面**は `tests/r424.spec.js` が読む。この spec はすでに「歴史の行のカードの Region」を
読んでいたので、末尾に**現代の行**を足した——時計を現在へ戻し、USA と DEU のカードを
日本語と英語で開く。

- ja: USA 「北アメリカ」（畳む）／DEU 「ヨーロッパ / 西ヨーロッパ」（畳まない）
- en: USA 「North America / Northern America」（畳まない）／DEU 「Europe / Western Europe」

⚠ **1か国では足りない。** USA だけなら「日本語で1語になった」が**訳した**のか**畳んだ**のか
区別できない。DEU は9言語すべてで左右が別語なので、**訳が画面に届いたこと**を言うのは
そちら。逆に USA の英語は、**畳みすぎていないこと**を言う。
