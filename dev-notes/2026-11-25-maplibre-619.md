title: MapLibre 6.19 へ追従する — transform が無くなったカメラに、地図操作の修復を移す
date: 2026-11-25
---

〈依頼〉dependabot の #1367（maplibre-gl 6.18.0 → 6.19.0・proj4 2.22 → 2.23）が赤のまま止まっていた。依存の更新だけでは着地できないので、地図操作の修復コードを 6.19 に追従させる。

## 何が変わったか（6.19 の実物を読んで）

6.19 はカメラの内部を作り直した。`geo/transform.ts`・`transform_interface.ts`（ITransform）・`geo/projection/*_transform.ts`・`*_camera_helper.ts`・`ui/elevation_hold.ts` が消え、カメラは**不変の素データ** `CameraViewState` と、それを投影する純粋関数（`src/camera/`：`projectCamera`・`getCameraMath`・`camera_updates` の setter・`applyConstrain`）になった。状態は zustand の store が持つ（新しい依存 `zustand`）。

IntMap の `js/geo-engine.js` は `camera.transform` と `_requestedCameraState` を `_tr()` 1 か所で読んでいた。6.19 では両方とも無く、`_tr()` は null を返す。**例外は 1 つも出ず**、次の機能が黙って止まる（#R162 の形）:
- 見上げ（pitch 90° 超）の修復: `_raiseCameraByPitchAndZoom` は名前こそ残るが、受け渡すのは transform ではなく状態。`clone()` が無く、修復は MapLibre の補正をそのまま返し、ドラッグは 90° で止まる。
- ホイールのばね（`_smoothWheel`）・地球の縁（`_limbUniforms`）・持ち上げた投影（`_lifted`）・視錐台（`viewFrame`）・目の位置・地平線の遠景（`setHorizonReach`）・地表判定（`onSurface`）・`worldSize`。
- フックの引数は Transform の複製から**メトリクス**（状態＋派生値）になり、`isGlobeRendering` と `applyConstrain` を持たない。球面の分岐と到達判定（`gGuard`）が黙って無くなる。

## どう直したか

- `src/vendor.js` が 6.19 のカメラ関数を `window.maplibreglCamera` として公開する。`src/index.ts` は export しないので、build が既にコンパイルしている MapLibre のソースから import する（`vite.config.js` の alias `maplibre-gl/src/…`）。描画器が使うのと**同じモジュール**で、行列を IntMap 側で導き直さない。
- `js/geo-engine.js` の `_TrView` が状態を 1 つ持ち、上の読み手が transform に訊いていた名前（`center`・`zoom`・`pitch`・`worldSize`・行列・`farZ`・`centerOffset`・`isGlobeRendering`・`getProjectionDataForCustomLayer`・`isPointOnMapSurface`・`applyConstrain`・`clone`／`set*`・`overrideNearFarZ`／`clearNearFarZOverride`）に、MapLibre の関数から答える。行列と遠近面は**描かれているカメラ**（`renderedProjectedCamera`。地球儀では描画中は vertical perspective、mercator に移ったあとは mercator）から取る。6.18 の globe transform が転送していた先と同じ。
- `clone()` は状態を写した新しい `_TrView` で、setter は状態を**置き換える**（見上げの修復が判定するカメラ）。生きたカメラの遠近面は、MapLibre 自身の `applyStateChange` を通して変える。
- `_tr(m, proposed)` の「提案中のカメラ」は、MapLibre 自身のハンドラが読む `proposedProjectedCamera` の元（`_viewAsDrawn()`）。描かれているカメラは `renderedState`。状態 1 つにつき `_TrView` を 1 つ持つので（WeakMap）、同一性で cache する読み手（`_lifted`）もそのまま効く。
- 見上げの修復とフックの判断ロジックは変えていない。変えたのは、カメラをどこから読むかと、どう写すかだけ。

## 検査

- `tests/look-up-gesture-checks`: 「transform を返す」を「受け取ったのと同じ型のカメラを返す」（往復の契約）に、「`applyUpdatedTransform` が先に届く」を「`transformCameraUpdate` を呼ぶ全てのメソッドが先に届く」（6.19 では `_adjustMovement`）に。6.19 の `private` 修飾子もメソッドの走査に含めた。
- `tests/cesium-globe-drag-checks`: 6.19 の状態・文脈・`getCameraMotions(ctx).pan` で MapLibre の地球儀パンを組み直し、Cesium 側の書き写しと突き合わせた。全 9 経路で一致（最大差 4×10⁻¹¹）。
- `tests/map-motion-checks` ②⑤: 変数名が `tr`／`transform` から `projectedCamera` に変わっただけ。式そのもの（両辺で同じ変数）を照合する形にした。
- `tests/helpers/camera-ruler.js`: 描画器が毎フレーム受け取る `camera.projectedCamera`（MapLibre が状態ごとに cache する、そのフレームの実物）を読む。
- `tests/r179.spec.js`: 修復するメソッドに渡す見上げのカメラを、MapLibre の setter で状態として作る。

## 起動予算

`eager.modules` 916 → 927、async チャンク `lib` 126.7 → 133.7 kB。増分は MapLibre 6.19 自身（新しい依存 zustand と、カメラ関数への分割）で、IntMap が足したものではない。dependabot の #1367 の CI でも同じ数字が出ていた。天井は CI の実測へ上げた。
