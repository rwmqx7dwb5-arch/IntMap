## R485 — **帰属表示は「在った」が「見えていなかった」**

#R479 は CARTO の規約が求める帰属表示を地図の上に出した。**出したつもりだった。**
本番にデプロイしたあと、スクリーンショットを自分で見て気づいた（#R95 の STANDING）。

### 実測

```
production R479 · #map-credit を elementFromPoint で自分の3点に問う
  desktop 1280x800   rect [1097,765,169,26]   tops = lst-prev / lst-grid / lst-grid
  desktop 1920x1080  rect [1737,1045,169,26]  tops = lst-root / lst-root / lst-root
  phone   390x844    rect [207,809,169,26]    tops = btn-stats / btn-community / control-panel
```

⚠⚠⚠ **どのビューポートでも、credit は自分の全ての点で別の要素に覆われていた。**
それでも #R479 の検査は緑だった——`display !== 'none'`・`visibility === 'visible'`・
`opacity > 0.5`・「viewport の中」は、**上に不透明な板が乗っていても全部真**だからである。
#R477（海岸線が不透明ラスタの9層下・`queryRenderedFeatures` は両方の状態で 15 本返す）と
#R455（レイヤーの箱が入っている≠地図に在る）と同じ形が、もう一段上で再発した。
**問うべきは「その要素が最前面か」であって「その要素が可視か」ではない。**

### 移せる角は無かった

⚠⚠⚠ 「では別の角へ」で済むと思ったが、実測がそれを潰した。座標読み取り（x 409–780。
⚠ **地図モードでもマウスが地図上にあれば出る**——sat 専用ではない、と実測で確かめた）・
国情報パネル（x 424–718・bottom 60–174）・**展開した** Chronos（x 630–970）・
レイヤーパネル（x≥993）を全部立てた状態で、175×26 が収まる矩形を地図カラム全面に
20px 刻みで走査した結果は **ゼロ**だった。

```
bottom:  6px   x 406..621   ← 座標読み取りが出るとここも消える
bottom: 18px   x 406..621
bottom: 30px   x 406..621
（それ以外の帯は国情報／Chronos／パネルのいずれかの下）
```

**浮かせている限り、この地図カラムでは保証できない。**

### 答えはオーバーレイをやめること

利用者の選択は「地図下端の細い帯にする」だった。`.map-column` を縦 flex にして、
地図がその上を取り、credit が下の**行**になる。

```
.map-column{ flex:1; min-width:0; display:flex; flex-direction:column; height:100%; }
.map-column > .map-container{ flex:1 1 auto; height:auto; min-height:0; }
.map-credit{ flex:0 0 auto; … }
```

⚠ **どのオーバーレイの包含ブロックも届かない行は、覆われようがない。**
`.map-container` は `position:relative` のままなので、**既存の HUD は座標を1つも変えていない**
（`tests/r252` が固定する座標読み取りの 9/9 も無傷）。変わったのは地図が 23px 縮んだことだけ。

⚠ **`index.html` の行数は据え置き**——app shell は 8,050 行未満に縛られている（`tests/r168` #8）ので、
wrapper は `.map-container` と**同じ行で開いて同じ行で閉じる**。結果 8048 行のまま、
`index.html` も 972 行のまま（`check:docs` の `app-size` も動かない）。

⚠ **`body.sidebar-glass` も行のまま。** そこは地図が `position:absolute; inset:0` で列全面を取るので、
credit を別の形（pill）にするのではなく、**地図の方を1帯ぶん短くする**——
`body.sidebar-glass .map-column > .map-container{ bottom:var(--credit-h); }`。
高さの名前は `--credit-h` の1つだけなので、帯と地図が食い違いようがない。

⚠ **pill のままなのは携帯だけ**（`.map-container{position:fixed;inset:0}` で地図が viewport 全面を取り、
その下端はシートとツールバーのもの——実測でオフセット約 150px 未満はすべて覆われる）。
位置は**実測で露出を確認した**シート連動オフセット
`bottom:calc(var(--sheet-cover, var(--peek-h)) + 12px)`——座標読み取り（`css/intmap.css` の
モバイル規則）と Chronos が既に使っている同じ変数である。

### 門は「遮蔽そのもの」を見る

| どこ | tier | 何を主張するか |
|---|---|---|
| `tests/r485-checks.test.mjs`（5本） | **毎 push** | credit が `#map-container` の**外**にある／カラムが縦 flex／基底規則が `position` を持たない／capture mode で消えない／**既存 HUD の座標が動いていない** |
| `tests/smoke.spec.js` ⑨ | **core** | 実ブラウザで credit の**文字**を hit-test し、`covered` が空であること |

⚠ **帯はカラム全幅なので右端はレイヤーパネルの下に入る。それは正しい**——そこは地図もパネルの下である。
主張するのは「読むべき文字が露出しているか」であって「箱の全点が露出しているか」ではない。

⚠ **発火を実測した**（#R465 の形）: CSS を #R479 の pill に戻して build し直すと ⑨ は
`covered` が5点で**赤**、帯に戻すと**緑**。
