## R674 — **ラウンド番号は名前ではない——同じ番号を持った 2 セッションが、同じファイルを新規作成していた**

> 利用者の依頼（#R671 の最終報告での承認を受けて）:「並行セッション間で『ラウンド番号だけの名前』が
> 構造的に衝突する。R671 で実際に起きた被害を踏まえ、**主題を名前に含める規約**を入れてほしい。
> 報告された 1 件のための特例ではなく、**その事例を生んだ構造**（＝名前の一意性を誰も保証して
> いないこと）を直すこと。既存の数百本を一括改名するなら必ず確認を取ること。」

### 1. 実測された被害は 2 種類あり、原因は 1 つだった

| # | 何が起きたか | 直接の原因 |
|---|---|---|
| ① | `tests/r568-checks.test.mjs` を 2 セッションが**両方新規作成**。git が add/add を立て、着地の自動化がそれを取り込んで**衝突マーカーごと commit** した。ファイルは `SyntaxError: Unexpected token '==='` で**1 本も走らなくなった** | `node land.mjs \| tail -4` が `$?` を `tail` のものにしていた（#R420 の再演） |
| ② | memory の `intmap-r<N>-lessons.md` を改番のたびに rename していて、**別セッションのファイルに重ねて自分の記憶を失った**（`intmap-r671-lessons.md` は令制国ラウンドのものだった） | 番号だけの名前がセッション間で一意でない。**#R565 で同じ被害が既に記録されていた＝2 回目** |

どちらも「自動化の不注意」ではない。**同じ名前を 2 つのセッションが正当に主張できてしまう**ことの
帰結であり、①の直接原因を直しても②は残る。

⚠ **改番は例外ではなく定常状態である。** #R671 は 7 回（R560→566→568→569→572→576→577→583→587→671）、
同じ時期の別セッションは 4 回。番号は**このセッションのものではない**——全員が同じ走査
（`scripts/worktree.mjs` の `nextRound`）から「次の空き番号」を取り、`origin/main` が動くたびに取り直す。

### 2. ⚠⚠⚠ 直せるのは merge ではなく、名前である

1 つのチェックアウトの中では「相手のセッションが別の番号を取ったか」を**原理的に証明できない**
——相手の branch はここに無い。証明できるのは、**名前が番号の持たないものを持っているか**だけ。

⇒ **番号 ＋ 主題**。`r674-round-naming` と `r671-dem-store` は、番号がどう動いても衝突しない。

| 何 | 名前 | 例 |
|---|---|---|
| その回の回帰検査 | `tests/r<N>-<主題>-checks.test.mjs` | `tests/r671-dem-store-checks.test.mjs` |
| その回の spec | `tests/r<N>-<主題>.spec.js` | `tests/r180-cesium.spec.js` |
| memory | `memory/intmap-<主題>.md`（**番号を入れない**） | `memory/intmap-dem-tile-store-budget.md` |

規約の正本は **`.agents/skills/intmap-round/SKILL.md` §4**。
**tests と memory は同じ 1 つの事実**なので正本は 1 つでなければならず、memory はリポジトリの外に
あって `docs/TESTING.md` の管轄に入らない。そして `.agents/rules/` は**毎セッション課金される常設集合**で
1 ファイル 6,144 バイトの天井があり（`tests/r295-checks.test.mjs` ⑥。実測、直前の main で余白 13 バイト）、
**その天井のテスト自身が「詳細は agent か skill へ移せ」と言っている**——実測された被害も 2 つの数の
理由もそこには入らない。⇒ **常設側（`AGENTS.md` §1・`execution-strategy.md` §3）は 1 行の命令だけ**を
持ち、**理由と実測は skill が持つ**。`docs/TESTING.md` は門が何を測っているかを、そこへ向けて書く。

### 3. 既存の 418 本は、一覧ではなく 2 つの数で留めた

一括改名は**していない**（`AGENTS.md` §3 の 1。提案は最終報告に出した）。
留め方に一覧を使わなかったのは、**418 の綴りを並べた一覧は次の 1 本を入れるために編集される**
ことになり、**その編集こそ止めたいもの**だからである（`.agents/rules/no-ad-hoc-hardcoding.md` §1）。

`scripts/round-names.mjs`:

| | 何を留めるか | 失効条件 |
|---|---|---|
| `LEGACY_BARE_COUNT = 418` | 裸の名前の**数**。**下向きにしか動かない**——足せば赤、legacy を改名して減れば「下げろ」と赤 | ラウンドが legacy を正当に改名したとき |
| `LEGACY_BARE_MAX_ROUND = 673` | 裸の名前の**最大ラウンド**。番号は単調に配られるので、**それより上の裸の名前は規約の後に書かれたもの** | 同上（主題つきの 35 本は r671 まで来ている） |

⚠ **どちらか一方は迂回できるが、両方は迂回できない。** 裸を 1 本足して legacy を 1 本改名すれば
数は動かない（ラウンドが捕まえる）。使われていない小さい番号を使えばラウンドは動かない（数が捕まえる）。

実測 2026-09-10（この規約を載せた木そのもので）: 裸 418 本・最大ラウンド 673・主題つき 36 本で最大 r674。

⚠ **この 2 つの数は、このラウンドが開いている間に動いた。** R672 を別セッションが先に merge し
（その回が `tests/r672-checks.test.mjs` を 1 本足した）、こちらは R674 へ改番した。門は正しく赤くなり、
**規約より前に着地したそのファイルは、このラウンドが改名してよいものではない**ので数を測り直した
——これは失効条件が働いたのであって、門を避けるための編集ではない。

### 4. 名前を配る側と裁く側が、同じ定義を共有している

`node scripts/worktree.mjs new <slug>` は、番号を取ったその場で置くべきファイル名を印字する
（`.claude/launch.json` の preview 設定と同じ扱い——**手で書かせない**）。その名前を作るのも、
`check:static` の `round-name` が disk を裁くのも、**`scripts/round-names.mjs` の同じ 2 つの関数**である。

別々の綴りにすると、**道具が自分の門に拒まれる名前を配れる**（#R536 の形）。
検査 ⑤ がその輪を閉じる——`roundArtefactNames()` が返した名前を `roundNameProblems()` に食わせ、
**問題ゼロであること**を測る。

### 5. 検査（`tests/r674-round-naming-checks.test.mjs`・7 本）

出荷されている述語をそのまま評価する（**手で写した複製は門から離れて緑のまま残る**・#R499）。

| | 何を測るか |
|---|---|
| ① | 裸／主題つきの分類。`r<N>-checks.test.mjs`・`r<N>.spec.js` は裸、`r<N>-hover-checks.test.mjs`・`r<N>-model.test.mjs`・`r<N>-cesium.spec.js` は主題つき。helper・corpus・名前つきスイートは**そもそも per-round artefact ではない** |
| ② | 記録した 2 つの数が、いまの `tests/` と**完全に一致する** |
| ③ | 記録より上のラウンドの裸の名前 → **その名前を名指して**赤 |
| ④ | 使われていない**小さい**番号の裸の名前 → ラウンド節は見られない。**数が**赤にする |
| ⑤ | ⚠ **緑のままでなければならない**ケース。同じ新ラウンドの主題つきの名前は通る（**すべてを拒む規則は何も証明しない**） |
| ⑥ | legacy を 1 本消すと「`Lower it to` …」で赤（**締め直されないラチェットは何も主張しなくなる**） |
| ⑦ | `check:static` を**子プロセスで**走らせ、disk に裸の名前があるときに実際に赤くなることを測る。木の錠（`tests/helpers/gate-lock.mjs`）を取り、前提の緑は `runGate()` で判定する（#R623） |

⚠ ⑦ が要るのは、**module が完璧で到達不能でありうる**から（#R628 は呼び出し元の無いゲートを 1 本
実測している）。変異試験: `err('round-name', p)` の 1 行を `void` に落とすと ⑦ だけが赤になることを確認した。
