## R426 — **国を囲む枠は「その国が在る場所」ではなく「その国が土地を持つ全ての場所」だった**

依頼はこうだった。

> `js/countries-ui.js` は `countryStats[code].bbox` を `_bboxOf(f)` で **Natural Earth の feature
> 全体**から作っている（`_mkStat` の `bbox:` に付いた `#R185` のコメント）。`js/place-framing.js`
> は公表された範囲を class zoom より優先するので、遠い海外領土を同じ feature に抱えた国は
> **ほぼ惑星規模**で構えられる。実測で緯度 40° を超えるのは NOR / FRA / USA / AUS / NZL / NLD /
> CAN / RUS の 8 件。これは **#R423 が作った欠陥ではなく既存**である。

データについては 1 件残らずその通りだった（同梱の CDN 版 `ne_10m_admin_0_countries.geojson`・
252 コード・2026-08-25 に再測）。

```
NOR Norway        dLat=135.2  dLon=42.8    ブーベ島 54.5°S・ヤンマイエン・スヴァールバル
FRA France        dLat=72.5   dLon=117.7   仏領ギアナ・レユニオン・ニューカレドニア・仏領ポリネシア
USA United States dLat=52.5   dLon=358.9   グアム・米領サモア・±180 をまたぐアラスカ
AUS Australia     dLat=45.5   dLon=46.2    マッコーリー島 54.6°S（128 km²）
NZL New Zealand   dLat=44.1   dLon=356.8
NLD Netherlands   dLat=41.5   dLon=75.6    カリブのオランダ
CAN Canada        dLat=41.4   dLon=88.4
RUS Russia        dLat=40.7   dLon=360.0
```

### ⚠⚠⚠ 報告された 8 件は入口であって、症状ではなかった

**「惑星規模で構えられる」が実際に何を意味するかは国ごとに違い、測るまで分からなかった。**
HEAD の `js/place-framing.js` に union の箱を食わせて 252 コードを走らせると:

```
実枠で構える           220
拒否 → country zoom 4.4  25   IDN CHL FRA NOR VNM DNK NLD HRV ECU PRT NCL BHS ATF SYC
                              MHL SHN MUS COK TON TUV FSM VUT ASM PLW MNP
「巨大」→ zoom 3.2        7   RUS USA ATA FJI NZL KIR UMI
```

壊れ方は 2 通りあり、**どちらもカメラがその国を見ていないことで終わる**。

1. **外れ値で膨らんだ枠は、捨てられる。** #R185 の OUTLIER 規則は「label 点が箱の真ん中に無い
   ＝この範囲は外れ値に引きずられている」と読んで箱を捨てる。だからノルウェーもフランスも
   オランダもエクアドルもポルトガルもチリも**デンマークも**、**一律 `country` zoom 4.4** に
   落ちていた——**#R185 がまさに消すために存在した欠陥**が、#R185 自身の作った箱によって
   戻っていたことになる。捨てられなかった国は外れ値で伸びた枠のまま構えられていた
   （豪州は 128 km² の島 1 つで緯度 45.5°、南アフリカはプリンス・エドワード諸島で 24.8°）。
2. **書き下せない枠は、拒否される。** ±180 をまたぐ環は min/max では `-180…180` ＝地球全幅に
   なる。`(e-w)>180` は当然に拒否され、米・露・NZ・フィジー・キリバスは label 点へ **zoom 3.2**
   で飛ばされていた。ロシアの label は (44.7, 58.2)＝ヨーロッパ・ロシアの奥で、国は四方の外。

⇒ **「枠が大きすぎる」ではなく「枠が無い」が多数派だった。** 直す対象は箱の大きさではなく、
**1 つの数に 2 つの問いを答えさせていたこと**である。

### ⚠⚠⚠ 2 つの箱に分けた——問いが 2 つあるから

`bbox` は 2 か所に配られていた。**カメラを向ける先**（`js/search-geocode.js` → place-framing）と、
**当たり判定の足切り**（`js/atlas-view-subject.js`——視界の 6×6 標本を国ポリゴンに当てる前の
安い拒否）。ノルウェーではその 2 つが**緯度 135.2° 対 13.2°** で違う。足切りは union でなければ
ならない（枠で切ると「ブーベ島はノルウェーではない」と答える）。枠は union であってはならない。

新設した `js/country-extent.js` が両方を作る。`js/place-framing.js` と同じ理由で自分のファイル
——純粋で、地図にもレンダラにも HOST にも **turf にも**触らないので、実データに対して Node で
測れる。以下の数字は全部そこで測った。

- `homeExtent(geometry, labelPoint)` … **その国が在る場所**。`countryStats[code].bbox`。
- `fullExtent(geometry)` … **その国が土地を持つ全ての場所**。`countryStats[code].bboxAll`。
  中身は `_bboxOf` と 1 バイト違わない（読み手が変わっただけ）。

### ⚠⚠⚠ 距離だけでは決まらない——アラスカとサラワクは同じだけ遠い

最初に書いたのは距離だけの規則で、**マレーシアで破綻した**。実測:

```
マレー半島 ←→ サラワク    5.4°   サラワクはマレーシアの 39.8 %   ← 入らなければならない
CONUS      ←→ アラスカ    5.4°   アラスカは合衆国の 15.0 %       ← 入ってはならない
```

**距離が同じで、答えが逆。** 分けているのは面積の割合だった。⇒ **「錨から 3° 以内で連なる」か
「国土の 1/3 以上を占める」**なら枠に入る。252 コードで両方の定数を掃引して窓を測った:

- `MAJOR_SHARE` … **0.29〜0.39 のどこでも 252 件が 1 つも動かない**。窓の両端はまさに分けたい
  2 つ——セーシェル（0.29）とサラワク（0.40）。**1/3 は窓の中**。
- `GAP_DEG` … **2.5°〜4° で「有り得ない枠」「土地の 40 % 以上を失う枠」の件数が同一**。つまり
  この欠陥はその範囲のどこでも直る＝**定数は際どく置かれていない**。3° を選んだのは、そこが
  小さな島嶼国が**丸ごと**枠に入る値だから（ソロモン 48/48・トンガ 10/10・マーシャル 22/22・
  赤道ギニア 3/3）。外すべき最短のものはノルウェーのビョルネイア **3.18°**（スヴァールバルへの
  飛び石。スヴァールバル自体は 5.40°）。チリのフアン・フェルナンデス諸島が **3.05°** で
  すぐ外側に居るが、入れても枠は経度 9.3°→14° に広がるだけで、**チリの zoom を決めているのは
  緯度 38.4° のほう**なのでカメラは動かない。
- ⚠ **km ではなく度。** 71°N の経度 1° は地上では短く、**地図の上では短くない**。この数は旅程
  ではなく**枠**のために選んでいる。

錨は **その国が自分の名前を置いた場所**（NE の `LABEL_X`/`LABEL_Y`）。面積ではない——キリバスの
label はキリティマティにあり、環礁の最大の塊から 3,300 km 離れている。label がどのパートにも
入らなければ最大のパートが代わる。連結は**単連結**（日本が南西諸島を伝って沖縄へ届くため。
錨から直接測る規則だと 8° の跳躍になって拒否される）。

### ⚠⚠⚠ ±180 は「拒否する」のではなく「書き下せる」ようにした

Natural Earth は環を ±180 で切るので、**1 つのパートは決してまたがない**——またぐのは 2 つの
union のほうで、min/max はそれを言えない。だから枠は経度を**区間** `[w, e]` として持ち、`e` は
180 を越えてよい。パートは -360° / 0° / +360° の 3 つで試して**区間が最短になる**ものを採る。

```
RUS  26.9°E → 191.0°E   = 164.1° 幅（ロシア）      旧: -180 → 180 = 360°（地球全幅）
FJI 176.9°E → 184.1°E   =   7.2° 幅（フィジー）
NZL 165.9°E → 178.8°E   =  13.0° 幅（またがない——またぐのはチャタム諸島とケルマデック諸島）
```

`e - w` が本当の幅になるので、`js/place-framing.js` の `(e-w)>180` はもう当たらない。
**MapLibre の `cameraForBounds` はこの箱を正しく解く**（実測: ロシア→中心 108.95°E・zoom 1.69、
フィジー→中心 180.5°）。Cesium 側は #R181 が既に `((east-west)%360+360)%360` で持っている。
**極を一周する形だけは区間にならない**ので `-180…180` を返し、既定の「巨大」の道へ落ちる
——**南極大陸 1 件だけ**がそれに当たる。

### ⚠⚠ 出所の印——推測を、もう刈ってある箱に当てない

枠を直しただけでは **20 件がまだ 4.4 に落ちた**。OUTLIER 規則が効き続けるからで、それは
「出所の分からない箱」に対する**推測**である（geocoder は 1 つの数を寄越すだけで、中に何が
入っているかを訊く方法が無い）。我々の国の行はそうではない。⇒ `_localRaw` が `homeExtent: true`
を付け、`placeExtent` はその印があるとき OUTLIER 判定を飛ばす。

いちばん分かりやすいのがデンマークで、**15 パート全部（ボーンホルム島を含む）が枠の中に入って
いるのに label は箱の 13 % の位置**にある——ユラン半島がそこだからで、外れ値は 1 つも無い。

### ⚠⚠ `atlas-examples` の 4 つの主張は、全部 union の話だった

`js/atlas-examples.js` の地理 chip は `bbox` を読む。**枠を読ませたら 4 つとも壊れる**:
`spread` は**外れ値そのものの測定**（フランスの 184 は仏領ギアナとレユニオンが生んでいる）、
`arctic` は合衆国について**アラスカが答え**、`tropics` は「国全体が回帰線の間か」なので枠にすると
偽陽性が出る。⇒ `bboxAll` を読ませた。**fallback は付けない**——union を持たない行は 4 つとも
refuse する（#R337 が選んだのと同じ安全な向き）。`js/atlas-view-subject.js` も同様に `bboxAll` で、
無ければ `null`＝ray-cast へ落ちる（遅くなるだけで、答えは正しい）。

### この回で踏んだもの

- ⚠⚠ **vm の中で作られた配列は `deepStrictEqual` が prototype で落とす。** 中身が同一なのに
  `[0,0,2,14]` と `[0,0,2,14]` が不一致になり、差分表示は同じ数字を並べる。`filter`/`map` の
  結果も向こうの realm の配列になるので、`assert.deepEqual(frameAll(true), [])` は
  **空配列同士でも落ちる**。⇒ `Array.from` でこちら側に写してから比べる。
- ⚠⚠ **プレビュー面が表示されていないとフレームを合成しない**ので、`flyTo` のアニメーションが
  1 フレームも進まない。`getZoom()` は初期値のままで「カメラが動かない」に見える——実際には
  決定は正しく下りていた。⇒ 見るべきは動いた結果ではなく**カメラに何を頼んだか**で、
  `forBounds`/`flyTo` を包んで引数を捕まえた。
- ⚠⚠ **Bash の heredoc にバッククォートを含む JS/Python を流すと、シェルがコマンド置換として
  食う。** `js/country-extent.js` は書き込まれず（`unexpected EOF`）、後の python one-liner は
  コメント中の `` `filter` `` `` `map` `` を**黙って消してファイルを書いた**。⇒ 本文のあるファイルは
  Write / Edit で書く。
- ⚠ **eager module が 279 → 280**（新ファイル 1 本・raw +0.8 kB・gzip +0.8 kB）。意図した値上げ
