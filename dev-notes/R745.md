## R745 — 緑の門は、本番がどの組み合わせで走っているかについて何も言っていなかった

〈外部レビューを受けた回。依頼は「できるだけ多くやって。完全にこれに従わなくてよい」。
⚠ レビューが最優先に挙げた「共通 GIS を Atlas へ接続する」は**別セッションが #R743 で実装中**
だったので触っていない（`feat/r743-gis-kernel-correctness`）。ここは**誰も測っていなかったもの**を測った。〉

### 1. ⚠⚠⚠ 3 つの配備単位があり、その組み合わせを測るものが 1 つも無かった

IntMap は静的サイト（Pages）・Edge Functions（Supabase）・DB（migration）という**独立した 3 つの
配備単位**でできている。`npm test` はチェックアウトを測る。CI はコミットを測る。
**「本番はいまどの組み合わせで走っているか」を訊く道具は無かった。**

`node scripts/release-state.mjs` が 3 面を測る（`npm run release:state` / `release:check`）。
2026-09-16、最初に測った本番:

| 面 | 実測 |
|---|---|
| 静的サイト | `build-info.json` の sha ＝ `origin/main`（一致） |
| Edge Functions | **17 本のうち 7 本**がリポジトリと違うソースで走っていた |
| DB migration | local 7 本が remote に無く、remote 2 本が local に無い |

7 本のうち `monitor-run` / `news-ingest` / `refresh-news` は **Atlas persona の `workspace` 段落を
持たない版**で、これは註ではなく**モデルへ渡す指示そのもの**の違いである（`ai-proxy` だけが新しい
版を持っていた）。`volcano-feed` は #R346 版のまま——#R353 が `main` に入って 3 週間。
7 本を deploy し、測り直して **17/17 一致**にした。

⚠ **DB の食い違いは自動では埋めない。** `docs/DATABASE.md` が述べるベースライン再構築の経緯があり、
「local にしか無い」は「適用漏れ」とは限らない。道具は述べるところまでを行い、適用は人が判断する。

### 2. ⚠⚠⚠ 時刻は配備の同一性を答えない

最初の版はコミット時刻と `updated_at` を比べた。**17 本すべてが「ソースのほうが新しい」**と出た。
中身で測ると違っていたのは 7 本で、`ais-feed` は **1 バイトも違わなかった**。

理由は 2 つあり、どちらも時刻では原理的に解けない:

- ラウンドの途中（merge の前）に worktree から deploy すると、**正しく配備されていても**
  コミットのほうが新しく見える。
- squash merge のコミット時刻は、そのラウンドが始まった時刻ではない。

⇒ 判定は **`supabase functions download` で取り寄せたソースの中身**で行う。時刻は文脈として
印字するだけ。⚠ 取り寄せは**1 本ずつ別の workdir へ**落とす——同じ木へ重ねると、あとから落とした
関数の `_shared/` が前の関数のものを上書きし、**比較が別の関数についての答えになる**。

### 3. ⚠⚠⚠ その道具自身が「読めなかった」を「同じだ」として報告した

一致の判定を `git diff --no-index --numstat` の出力が空かどうかに置いた。呼び出し側は失敗時に
空文字列を返す作りだった。**違っている 7 本が全部「一致」として緑で報告された。**
（この形は上流に対しても自分の道具の中でも同じように壊れる——`intmap-one-store-was-asked`。）

⇒ **判定はバイトそのものに付ける**（`readFileSync(a).equals(readFileSync(b))`）。git は「何行
動いたか」を飾るためだけに呼ぶ。**0 ファイルは「一致」ではなく `unknown`**。
回帰は `tests/r745-arch-review-followup-checks.test.mjs` ⑤——**何も答えられない git** を渡しても
違いが違いとして出ることを測る。

### 4. ⚠⚠⚠ 1 つの窓は、その語についての証拠ではない（#R727 の退行）

nightly の deep tier（PR でも push でも走らない）を切り分けたら 7 件中**本物の製品退行が 1 件**。

`find_capability('ありがとう')` が `data.query` を返していた。CJK は空白を持たないので 2 文字窓に
切られる（あり・りが・がと・とう）。`あり` は**ただ 1 つのカタログ文**——`data.query` の例文
「…地震があり、半径100km以内に…」——に入っている。df=1 は**最も希少**で、探索は希少さに点を
与えるので、断片が満点を取った。**礼の言葉が空間クエリへ送られていた。**

⇒ run は**自分の窓の 2 つ以上**で認める（窓を 1 つしか作れない run はその 1 つで足りる）。
「ひまわり」はその語を持つ文がすべての窓を持つので通り、偶然共有された断片は落ちる。
⚠ 除外語の一覧は作らない（`.agents/rules/no-ad-hoc-hardcoding.md`）。

### 5. ⚠⚠ 検査が太陽ではなく暦を見ていた

`tests/r201.spec.js` の「分点以外では片方の極だけが暗い」が 2026-09-15 から赤かった。製品は正しい。
窓は**接合緯度 85.06°**で採られるので、片方の極が丸ごと昼でもう片方が丸ごと夜なのは
**|赤緯| > 90 − 85.06 ≈ 4.94°** のあいだだけ。その内側（年に約 56 日、9/8–10/6 と 3/8–4/4 あたり）は
**両極が同時に昼と夜を持つ**のが正しい振る舞いである。

⇒ レイヤー自身の `solar()` が述べる赤緯（`_solar()` で公開）で場合分けする。日付の一覧は書かない。

### 6. ⚠ #R734 が否定した文が、2 つの文書に否定されたまま残っていた

#R734 は「重ね合わせを一度も走らせない読者は sweep-line を落とさない」を**本番で否定**して
`js/gis-geometry.js` と `vite.config.js` に記録したが、同じ文を述べている `Architecture.md` と
`docs/FILES.md` はそのままだった。`dist/` で測り直すと今日も同じ: `geo-<hash>.js`（52,137 B）は
`main-<hash>.js` が静的に import し、`index.html` に `modulepreload` まで置かれている。両方を直した。

### 7. 測ったが、この回では直していないもの（レビューの主張の照合）

| レビューの主張 | 実測 |
|---|---|
| GIS 処理を Atlas から直接実行する経路が無い | **真**（`js/atlas-*.js` から `IntMapGisOps` への参照 0 件）。⚠ ただし **#R743 が実装中**なので触っていない |
| 新旧の実行経路が共存している | **真、かつもっと悪い**。`OS.exec()` の呼び出しは製品コードに 31 件、`IntMapOS.execute()` は 2 件（どちらも Atlas のターンループ）で、**UI のボタンは 1 件も execute() を通らない**。さらに `cap.execute = legacyExecute(cap)` は無条件なので、**139 能力すべてが execute() 経由でも旧 dispatch の switch に着地する** |
| 行数上限が書式を支配している | **真**。app shell の上限 8,050 行に対し実測 8,049 行（余白 1 行）で、`src/main.js` には上限のために import を 1 行へ詰めた箇所が 11 行・`js/atlas-console.js` に 3 行ある |
| GIS の再現性（レシピに演算の版が無い） | **真**。保存される段は `{op, inputs, params}` だけで、実装の版も入力のハッシュも無い（`RECORD_VERSION` は誰も読まない） |
