## R394 — **埋め込みは1本も無いのに、23本の辺が「embedding が決めた」と記録されていた**

「続き」。#R386 が出来事を利用者に届けたあと、**本番の表を読み直した**。

### 監査の列が、走っていない機構の名前を名乗っていた

```
links labelled assigned_by='embedding' : 23
articles with an embedding             : 0
```

出どころは #R386 が書いた 1 行——`news_event_merge_into` が、機械の merge なら無条件で
`assigned_by='embedding'` と書いていた。ところが `link` 段の候補は **語の共有からしか出ていない**
（この鍵は埋め込みモデルに届かない）。#R334 がこの列に 4 値を置いたのは「どの段が何件を運んだか」
を数えるためなので、**走っていない機構の名前が入るとその列は情報ではなく嘘を持つ。**

⇒ **何で決めたかは呼び出し側が引数で渡す**（`p_decided_by`。関数側でも値を確かめる）。
4 引数の古い形は `drop` した——残すと、知らない呼び出し側がそちらに解決して直した経路が迂回される。

⚠ 監査の note も同じ罠だった。`Number(null).toFixed(3)` は `"0.000"` なので、**cos が無いのに
「cos 0.000」**と 11 行に書かれていた。**無かったものを 0 と書くのは、無かったと書くことではない。**

⚠ 直したのは**名札だけ**である。どの記事がどの Event に属するかは 1 行も動かしていないし、
直したのは「`embedding` を名乗っているのに記事が埋め込みを持たない」——**入力が存在しないことが
データから証明できる辺だけ**である。数える側は `news-events-eval.mjs --from-db` が常に印字する
「⚠ 走っていない機構を名乗る辺」で、**この行が 0 でなくなった日が、また同じことが起きた日である。**

### そして、#R351 の門は一度も発火していなかった

同じファイルを直しているとき、自分の書いた正規表現が効かなかった。原因を見たら `\b` が
**バックスペース文字 1 個（0x08）** になっていた——書いた道具がバックスラッシュを 1 段落として
潰していた。そこで隣を見たら、**#R351 が書いた Yonhap 索引記事の門にも同じものが入っていた**。

`origin/main` で実測して確かめた: `headlineReject('Yonhap News Summary', 'SEOUL … The following is …')`
は **`null`** を返す。**その規則は書かれた日から一度も何も落としていなかった。**
JavaScript としては完全に妥当なので `node --check` も lint も黙る。

⇒ `scripts/static-checks.mjs` の **`regex-control-char`**。⚠ **「制御文字を禁止」ではない**
——`js/world-packs.js` や `scripts/rail/build.mjs` は U+0001 を区切りとして**意図的に**使っており、
それは正しい。危ないのは**正規表現の中**だけで、そこに制御文字が要る理由はまず無い。
実測: ソース 858 本のうち制御文字を含む 12 行、壊れていたのはこの規則が見る 2 行だけ。
残る 10 行（意図的な区切り）は `\u0001` のエスケープ書きに直した——**同じ潰れ方を二度と受けない
書き方**であって、挙動は 1 ビットも変わらない。

### 「値が違う」は「食い違っている」ではない

#R386 の相違の規則が本番で出したのは 2 件で、**うち 1 件は誤り**だった:

```
❌ 香港の上場   Bloomberg「$1.8 Billion」(Shein の IPO) / Reuters「$10 billion」(Alibaba の売出)
                CNBC「$10.2 billion」 / Reuters「$27 billion」(Shein の評価額)
```

**同じ記事群に出てくる別々の数字**であって、同じ数字についての食い違いではない。
⇒ **同じ量についての別々の説明だけ**を相違と呼ぶ。2 つの値がそれでありうるのは互いに丸めや
精度の差の範囲にあるときで、倍半分も違えば別の事実である。実測: 正しい 2 組は min/max **0.966**
（Uber の制裁金）と **0.980**（Alibaba）、誤りの相手は **0.18 / 0.37**。⇒ `sameQuantityRatio = 0.5`。
⚠ 閾値は「隙間の真ん中」ではなく**意味**で選んだ——同じ数字の別々の報じ方は丸めの差であり、
2 倍は丸めではない。

そして、そもそも**規則がほとんど発火していなかった理由**が別にあった:

⚠⚠⚠ **英語のニュースは死者数を「動詞が先」で書く。** «kills 30» / «killed 16» /
«kill at least 10» が **24 件**、#R386 が見ていた «30 killed» は **4 件**。⇒ 両方の綴りを持つ
（抽出 **76 → 108**・数量を持つ Event **51 → 66**）。
⚠ そのうえ «Girl, 17, killed in Swedish sword attack» の **17 を死者数として取り出していた**
——コンマ止めの数字と «N-year-old» の直前を外した。

**精度 1/2 → 3/3。** 新しく出たのは日本の地震で、AP «injuring more than 30» と
Al Jazeera «37 injured»（min/max 0.811）——まさにこの機能が見せるべきものである。

⚠⚠ **そして規則は表示の層の奥にあった**——`js/news-events.js` の factory の中なので
**ブラウザの外からは誰も呼べず**、歩留まりも精度も測れなかった（#R340 が `research.events` で
直したのと同じ形）。⇒ `js/news-claims.js` へ出し、`scripts/news-events-eval.mjs --diffs` が
**UI と同じ 1 本**を本番のデータで測る。⚠ 最初その計器は `description` を select しておらず、
**見出しだけを読んで歩留まりを半分に見せた**——測るものと動くものを別にしない、の同じ形。

### 地点の無い出来事に、地点を持たせない

実測: active 1,069 件のうち **330 件（30.9%）が座標を持たない**。`applyPinMode` は記事モードの
ために擬似座標（`hashLocFromString`）を配るので、**地図の 3 割が「そこで起きていない出来事」の
ピン**になっていた。§9 の「正直に出すもの: 場所不明」は**印を付けて出す**ことであって、
**在りもしない座標を配る**ことではない。⇒ 出来事モードではピンを立てない（カードは残り、
チップは「場所不明」と言い、`state().unplacedCount` が数える）。⚠ 記事モードは 1 ビットも変えない。

`link` 段が結んだ **11 件は 11/11 正しい**（Alibaba の塊の汚れは `assign` 段が入れたもの）。
