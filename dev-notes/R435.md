## R435 — **報告は3つ、原因は1つ——「同じ面に描く」と決めただけで、その面への入り方は共有していなかった**

> 「ニュースで、出来事カードを開いたときに左上に出る戻るボタンが見えない。そしてデザインが
> 浮いている。添付画像のように半分だけになる謎の状態に勝手になるバグもやめろ。」
> （添付は電話のスクリーンショット。上半分にニュースの一覧、下半分に出来事の詳細、その左上に
> 中身の見えない小さな白い箱）

`#news-reader-pane` は IntMap の**唯一の「読む面」**である。記事 reader がそこに記事を描き、
出来事の詳細（#R386）もそこに Event を描く——`docs/NEWS-EVENTS.md` §9 が「同じ News surface 内で」
と決め、`js/news-events.js` の見出しも「記事の reader と同じ面」と書いている。
**決めていたのは描く場所だけで、その面への入り方は共有していなかった。**
記事 reader の入口は 9 行ある。詳細が持っていたのは 2 行だった:

```js
feed.style.display = 'none';
pane.style.display = '';
```

報告の 3 つは、この差し引き 7 行から出ている。**別々の欠陥ではない。**

### ① 「戻るボタンが見えない」——当たらない CSS と、画面の外

詳細の帯はこう書かれていた。

```js
'<div class="reader-bar"><button class="btn-back" id="ev-back">' + …
html += '<div class="ev-detail">';
```

そして `css/intmap.css` の規則は `.ev-detail .reader-bar` と `.ev-detail .btn-back`。
**帯は `.ev-detail` の兄弟であって子孫ではない**ので、その 3 規則は #R386 から一度も
当たっていない。⚠⚠⚠ **当たらない CSS は、綴りとしては完全に健在である**——規則も在り、
クラス名も在り、`grep` は両方を見つける。違うのは「その要素に当たったか」だけで、
それは計算済みスタイルにしか無い。

実測（ローカル build・390×780・ブラウザ）:

| | 修正前 | 修正後 |
|---|---|---|
| `#ev-back` の背景 | `rgb(240,240,240)` | `rgba(0,0,0,0.05)`（`--input-bg`） |
| 角丸 / padding | `0px` / `0px` | `999px` / `9px 14px` |
| border | `2px outset` | なし |
| 大きさ | 44.0 × 20 | 67.7 × 34 |
| 帯の `position` | `static` | `sticky` |

つまり **OS 既定の `<button>` がそのまま出荷されていた**。しかも帯が sticky でないので、
少しスクロールすると流れて二度と戻らない。

⚠⚠⚠ **そして電話では、そもそも画面の中に無かった。** 記事 reader の入口は
`window.__setDetent('full')` を呼ぶが、詳細は呼ばない。シートが既定の peek に居るまま詳細を
開くと、**戻るボタンは 780px の視野に対して y=866**——報告の「見えない」は、色ではなく
**画面の下に落ちている**という意味だった（修正後は y=208）。

### ② 「デザインが浮いている」——一覧の外皮の下に描かれていた

記事 reader は面へ入るときに `.control-panel`（タブ列）と `#sidebar-search-bar` を伏せる。
詳細は伏せない。だから詳細は「IntMap ロゴ → タブ列 → 検索欄 → scope と カテゴリの chips」の
**下に残った帯**に描かれ、読む面ではなく一覧の残り物に見えていた（実測: それぞれ 42 / 44 / 27 px、
合わせて 113 px を一覧の外皮が占めたまま）。

### ③ 「半分だけになる謎の状態に勝手になる」——`renderUI()` が読む面を知らなかった

`renderUI()`（`js/news-ui.js`）は「いま開いているタブを描き直す」関数で、
**`#news-reader-pane` の存在を一度も参照していなかった**。だから再描画のたびに
`feed.style.display='flex'` を実行し、サイドバーの flex 列に `flex:1 1 auto` の兄弟が 2 つ並ぶ。
実測（390×780）:

- Countries タブへ移る → `#countries-feed` 436px @y=302 の**下に** `#news-reader-pane` 42px @y=738
  （読む面が他のタブへ漏れる）
- News へ戻る → `#live-news-feed` 85px @y=339 と `#news-reader-pane` 356px @y=424
  ＝**添付画像そのもの**

「勝手に」なのは、`renderUI()` の呼び手のほとんどが**背景**だからである——Supabase の realtime
購読（`geo_pins` の変化）と auth の再確認（`js/auth-ui.js`）、設定の適用と言語切替
（`js/app-body.js`）。読者は何も操作していない。

### 直し — 入口 1 本・出口 1 本・1 面だけ

- **`enterReaderPane()`**（`js/article-reader.js`）。サイドバーを開き、電話ならシートを full にし、
  一覧の外皮（`.control-panel`・`#sidebar-search-bar`・`#news-pin-toggle`・`#news-filter-toggle`・
  `#ai-geocode-row`）と各 feed を伏せ、面を出す。記事 reader の入口をそのまま関数にしたうえで、
  **chips 2 行を足した**（②）。⚠ これは記事 reader の見た目も変える——読む面は 1 つなので、
  片方だけ chips が残る状態のほうが誤りである。
- **`closeReaderPane(quiet)`**（`js/app-body.js`。旧 `closeArticleReader`）。面を捨て、
  `renderUI()` が自分で決めない `.control-panel` を戻す。`quiet` は既に再描画中の呼び手
  （`renderUI` / `setMode`）用で、1 回の操作でタブを 2 度描かないため。
- **`openDetail()`** は `HOST.enterReaderPane()` で入り、戻るボタンは `HOST.closeReaderPane()` で出る。
  帯は記事 reader と同じ **`.nrp-bar` / `.nrp-back`**、`.ev-detail` に scope した写しは削除した。
- **`renderUI()` は 1 面しか出さない。** News 以外へ移れば読む面を閉じ、News に居るなら読む面を
  残して一覧をその下で更新する。**`setMode()`（タブと scope の操作）は必ず読む面を離れる。**
- **Atlas の `selectedEventId` は面を観測して答える**（`selectedShown()`）。閉じる経路は戻るボタン
  だけではないので、覚えている publicId は「最後に開いたもの」であって「いま出ているもの」では
  ない（#R340 の produces-observed）。実測: タブを移ると `null` を返すようになった（以前は
  画面に無い出来事の id を返し続けた）。

### ④ 同じ「半分だけ」が、workspace mode にもう 1 本あった

サイドバー側を直したあとに測って見つけた。`js/workspace.js` の layout CSS は News ウィンドウの
一覧を `display:flex !important` で出す——**サイドバーのタブ状態がそこへ手を伸ばせないように
するための規則**で、それ自体は正しい。だが同じ `!important` が**読む面の伏せ方も上書きして
いた**。実測（1280×800・ws の News ウィンドウを開き、詳細を開いた状態）:
`#live-news-feed` 35px @y=113 と `#news-reader-pane` 114px @y=148 が同時に出る＝**サイドバーで
報告されたのと同じ絵**である。

⚠ **決定を 2 か所に写さない。** 入口が `body.im-reading` を立て、出口が下ろす。workspace の
規則はその 1 つのクラスを読む（`body.ws-mode.im-reading .ws-news #live-news-feed …{display:none !important}`）。
実測（修正後・同じ手順）: 詳細を開くと feed / search / chips とも `none`、読む面だけが 201px @y=61。
戻ると `im-reading` が下り、一覧が 116px @y=146 で戻る。

### 検査

- **`tests/r435-checks.test.mjs`（8 本・常時実行）。** ①**単独のクラスは必ず規則を持つ**——
  詳細の帯のクラスはその要素の唯一のクラスだったので、この 1 本が 49 ラウンド前に在れば赤だった。
  走査は読む面を描く 3 ファイル全部で、**免除一覧を持たない**（複数クラスの要素は主張の対象外
  ——`class="ev-d-sec ev-figs"` のように片方が装飾を持つ形が正当に在るため）。②帯の綴りと規則が
  1 組であること。③入口と出口。④**伏せる id の一覧を `enterReaderPane()` から読み出して**、
  その全部が `closeReaderPane()` か `renderUI()` に現れること（入口に足して出口に足し忘れると赤）。
  ④b「読んでいる」の合図は 1 つのクラスで、付ける側と外す側が対になっていること（workspace の規則が
  それを読むこと）。⑤`renderUI()` の 1 面規則。⑥`setMode()` の離脱。⑦`selectedShown()` を**実際に走らせて** 4 通り。
  ⚠ **8 通りに変異させて、対応する検査が全部赤になることを実測した。**
  ⚠ 最初の版の ① は**変異に対して緑だった**——raw な CSS を読んでいたので、削除した規則の跡に
  残した**注記の中の綴り**を「規則が在る」と読んでいた（#R345 の形。14 回目）。
- **`tests/r435.spec.js`（core tier・1 テスト・電話の視野 390×780）。** ①②③ はどれも
  **計算済みスタイルと配置にしか現れない**ので、綴りの検査では言えない。
  ⚠ 待つのは「シートが止まったこと」であって主張そのものではない——戻るボタンが画面に入るのを
  待ってから同じことを assert すると、その assert は二度と赤にならない（#R399）。
  固定の `waitForTimeout` は 0 本。

### 試験予算

`tests/r435.spec.js` は **nightly（deep）に落ちる**。`currentRoundSpec()` は「ディスクにある最大の
番号」で、push の順で番号が配られるため、merge 時点の最大は **r439** だった——だから core の
無料枠はそちらが持ち、5 秒のこの spec は価格の規則どおり deep に入る。
**この round が core に足したものは 0 秒である。**
⇒ **この round の push を守るのは `tests/r435-checks.test.mjs`（8 本・常時実行）**で、綴りで言える
半分——出す class と規則の対応・入口と出口が 1 本ずつ・伏せたものを誰かが戻す・`renderUI()` の
1 面規則・`setMode()` の離脱・Atlas の選択の観測——を全部持つ。ブラウザにしか言えない半分は
nightly で回る。

実測（warm server・1 worker・reporter が測る test body）: 最初の版 5,215 ms、固定 sleep 3.1 秒を
条件待ちに置き換えて **4,060 / 4,309 / 3,858 / 2,947 ms**（4 回）。上界 4,309 を切り上げて **5** を
計上——#R416（4,123 → 5）と同じ方法・同じ丸めである。**総計は 4,613 → 4,618**、#R405 / #R416 /
#R428 / #R410 と同じく**測った分だけ**動かした。
⚠ **core の天井は 35 → 28 に下がったが、それはこの round の節約ではない**（#R439 の spec が
`currentRoundSpec()` になり、10 秒の r424 が門から降りた結果）。この規程では天井は誰の手柄でも
床に従って下がるので、下げたうえで**自分の功績にしない**——#R416 が同じ形を同じ言葉で記録している。
⚠ **他の項目から払わなかった。** 候補として `tests/r170.spec.js`（計上 77）を測ったが、
test body 46.2 秒・**wall 92.9 秒**（9 本すべて成功・skip 0）で、#R355 が使った wall の読みでは
計上のほうが低い。#R322 の規則——機械と食い違う表から今回の節約を取らない——に従って見送った。
