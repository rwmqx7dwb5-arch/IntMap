データ品質の公開台帳・merge から自動生成する更新情報・秘密なしでも測れる Atlas 夜間評価。GitHub の設定変更と
secret の作成はしない。

## 1. 作ったもの

**① データ元の記録（公開台帳）。** `scripts/build-service-status.mjs` に `advanceHistory`——毎晩の結果を
`history`（`nights` と、ホストごとに 1 晩 1 文字 `a/r/d/u/.`）へ畳み込む。最大 `HISTORY_KEEP`＝90 晩
（upstream-liveness の artifact の保持期間と同じ。由来と失効は定数の註）。**測った晩だけが晩**、同じ晩は二度足さない、
古い晩は過去を書き換えない、回線の無い晩は全ホスト `u`、どの晩にも訊いていないホストは抜ける。`--backfill` で
GitHub がまだ持つ結果から埋めた（3 晩: 10-01・10-02・10-03）。
読み手: 状態ページ（晩ごとの棒＝測れた確認のうち応答した割合。全部応答で緑・1 つでも応答しないと橙——色の閾値は無い／
各データ元の帯／「直近 N 晩の確認のうち M 晩で応答」）、`sources.html` とアプリ内の出典一覧（**照合できる全行**に
`sourceRecord`）、Atlas の `diagnose`（`describe()` が記録の行を文で持つ）。

**② 2 つの宇宙の言葉。** `readerLedger()` が outbound-hosts の行に、`scripts/elections/upstreams.json` の probe を
`buildProbes()`（識別子の正本）から足す——言葉はパックの発行元と、そこで読むもの。`buildProbes` は `pack`・`publisher`・
`reads` を probe に足すだけ（加算）。`readerUpstreams` は `group: 'build'` を運ぶ。⑦ は同じ `readerLedger()` で照合し、
全行が en/jp の言葉を持つことも測る。

**③ 新着（更新情報）。** 正本は各 merge の記録——`dev-notes/*.md` の front matter に `newsen:` / `newsjp:`
（`scripts/dev-notes.mjs` `newsProblems`: 両方か無しか・平文・絵文字なし・280 字以内・日本語の行は日本語。
`--check` が門）。`scripts/whats-new.mjs`（vite の `whatsNewPlugin`）が build 時に `whats-new.json`・
`updates.html`／`ja/updates.html`・Atom `updates.xml`／`ja/updates.xml`・`sitemap-updates.xml`（`sitemap-index.xml` に連結）を
`dist/` に書く。**追跡しない**（毎 PR が書き換えると並行 PR が衝突する）。dev サーバでは `/whats-new.json` を
その場で答える。PR へのリンクは記録が番号を持ち、リポジトリが読めるとき（`GITHUB_REPOSITORY` か `origin`）だけ。
アプリ: 設定 ▸ 新着（`js/whats-new.js`、握り `window.IntMapWhatsNew` は `js/layer-state.js`）、未読の印は
ボタンが初めて画面に入ったとき（IntersectionObserver）に数える＝起動では何も取らない。**未読＝この端末でまだ
見せていないもの**、初めての端末は基準を記録するだけ。Atlas: `system.whatsNew`（`since`・`limit`）。
2026-10-02〜03 の記録のうち読者に見える変化を起こした 40 本に、題と本文から 1 行ずつ書いた。
`.agents/skills/intmap-round/` §3 に書式を足した（以後の記録が自分で書く）。

**④ Atlas 夜間評価のセッション不要の半分。** `scripts/atlas-eval/reach.mjs`——解答つきの問いのうち `capabilities`
を持つものについて、**問いの言葉そのもの**を find_capability と同じ語彙検索（`FIND_OPTS`、`js/atlas-toolsurface.js` と
同じ綴りであることを検査が測る）に渡し、要る能力の順位か「届かない」を記録。`scripts/atlas-eval.mjs --offline` が
カセットの再生と合わせて `atlas-eval-offline.json`/`.md` を書く。`atlas-eval.yml` に Secret を読まない `offline` job を
足し、artifact `atlas-eval-offline` と Job summary に出す（run は緑にならない——`eval` job は今まで通り落ちて理由を言う）。
`runDetail` はライブの報告を**名前で**（`LIVE_REPORT`）探すように直し、オフラインの成果物で「測った」にならない。
`build-service-status.mjs` が最新の `atlas-eval-offline` を件数だけ `atlasEval.offline` に運び、状態ページの Atlas 節に
「ログイン不要の部分の計測」の行（「IntMap 自身のコードの確認で、答えの評価ではありません」と述べる）。
