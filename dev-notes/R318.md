## R318 — **「何ができるか」の一覧が5つあり、どの2つも一致していなかった**

依頼は1件で、機能の修正ではなかった。「Atlasを、IntMapの一部機能を自然言語で呼び出すラッパーではなく、
IntMap全体を理解・操作・検証・完遂する制御層へ進化させてください」——到達性・実行権限・信頼性・
複合処理能力・自己修復能力の5項目。そして「単なるsystem promptの追記、dispatch caseの大量追加、
正規表現の追加、上限文字数の増加だけで完了としてはいけません」。

### 0. まず数えた

実装の前に、Atlas の操作面を機械的に全数抽出した。結果:

| 一覧 | 件数 | 何が正本のつもりだったか |
|---|---|---|
| dispatch の `switch(a.type)` | **115 case グループ / 263 綴り** | 実行できるもの |
| `function SYS()` のカタログ | **38 ブロック / 58 kB** | planner が知っているもの |
| `ATLAS_ACTION_CAPABILITIES` | **4 件** | 能力の意味論（時制・証拠・出力） |
| `IntMapOS` の登録済みコマンド | **42 件** | UI と Atlas が共有する実体 |
| `controlCatalog()` | DOM 順の**先頭 140 件** | 「その他の操作」 |

**どの2つも一致していなかった。** そして、この日記に繰り返し出てくる Atlas の欠陥は、
**すべて「そのうち2つの食い違い」という同じ形**をしている:

- #R278「その機能は実行できません」＝(1) にあって (2) に無い
- #R115「徒歩1時間で行ける範囲」→半径円 ＝(2) に radius があって isochrone が無い
- #R268 押しても何も起きない／#R291 経路は計算され描かれない／#R302 地点を訊かず中心を使う
  ＝**主張と観測の食い違い**

計測で出た他の実物:

- `js/atlas-controls.js` の `out.slice(0,140)` が、**DOM 順で**どの操作が存在するかを決めている。
- `moduleCatalog()` は `Object.keys(window)` を歩くだけなので、**遅延モジュール 8 本は未ロードの間
  Atlas にとって存在しない**（静的に数えて 67 → 59）。
- `case 'lineOfSight'` が **2 か所**にあり、後ろの1つは JS の規則上**一度も入られたことがない**。
- `js/monitors.js` が、登録されていないコマンドを `exec` して**戻り値を捨て `{ok:true}` を返して**いた。
- `_aiLangName()` が **zh の利用者に「英文で書け」と AI に指示していた**（下記 §5）。

### 1. `IntMapOS.exec()` は `run()` を呼ぶ前に成功を記録していた

これが「信頼性」の根だった。実装は、ログ用のレコードに `ok:true` を立ててから `run()` を呼び、
**返り値の `.ok === false`** だけを見て降格する。Promise には `.ok` が無いので:

> **登録済み 42 コマンドのうち 10 本（`SIM_TOOLS` の 8 本・`sim.seismic`・`layers.data`）は、
> 自分の最初の await が再開するより前に「成功」として記録されていた。**
> そのあとの reject は、一度も記録されなかった。#R82 から今日まで。

`exec()` の**署名・戻り値・同期挙動は 1 バイトも変えていない**（41 か所の呼び出しと、
ツールバーのボタンがそれに依存している）。変えたのは、thenable を返したときに
**記録を `pending` にして、決着したときにその記録を確定させる**ことと、
その全部を operation バスに出すこと。

そのうえで、**新しい扉**を足した:

```
IntMapOS.execute(capabilityId, args, {source, turnId, signal})
```

11 段ある。**能力の解決 → 可用性 → 引数 schema → 必要な入力の解決 → 競合キーの取得 →
前の観測 → 実行 → 完了待ち（同期・Promise を問わず） → 後の観測 → 事後条件の検証 →
構造化結果**。各段は `planned / validating / waiting-input / started / progress / completed /
partial / failed / cancelled / superseded` としてイベントに出る。

### 2. `ok` を書けなくした

`{ok, html}` の `ok` は**手書きの真偽値**で、`catch(_){}` の直後でも書ける。書ける限り、いつか書かれる。

新しい結果の形（`js/atlas-results.js`）では `status` が唯一の事実で、`ok` は
`status === 'completed'` からの**読み取り専用の getter**。列挙可能なので JSON にも出るし、
`r.ok` を読む既存コードもそのまま動く。**代入すると（module strict mode なので）その行で throw する。**

status は 7 つ。それぞれ「実際に起きたのに、古い形では真か偽のどちらかにするしかなかった」もの:

```
completed  事後条件を観測した      partial    一部の対象だけ
running    始まって、まだ続いている  failed     起きなかった（code が理由を言う）
needs_input 必要な入力が無い        cancelled  呼び出し側が中止した
superseded  新しい依頼が置き換えた
```

### 3. 対象を勝手に決めない（#R302 の回帰条件を、表の1列にした）

「地点が必要なツールだけ地点を求め、勝手に地図中心を選ばない」は #R302 の回帰条件だが、
守っていたのは**その1つのツールだけ**だった。レジストリの表に「必要な対象」の列を足し、
`required` の能力に対象が渡されなければ `needs_input` と**再開トークン**を返す。
**43 能力が該当する。** 監査の④が、`mapCenterAllowed` を宣言した能力を落とす。

### 4. 58 kB を1バイトも書き換えずに移した

「SYS()のアクション説明はRegistryから生成する」。しかし SYS の本文は **72,604 バイトの
手で調整されたプロンプト**で、各段落は #R115 の半径円、#R157 の highlight schema、#R278 の
6つの不可視機能——**それぞれ具体的な誤読を1つずつ潰した結果**である。書き直せば、その訂正が失われる。

だから**書き直さずに移した**。`js/atlas-catalog-text.js` が 38 ブロックを**逐語で**持ち、
各ブロックに**それがどの能力を説明しているか**というタグを1つだけ足した。それだけで:

- `text(null)` は**#R311 が送っていたプロンプトそのもの**（56,643 バイト）
- `text(['routing.route','routing.isochrone'])` は **14,627 バイト**
- 監査が逆向きの問い——「どの能力も説明していないブロックはあるか」「どのブロックも説明していない
  能力はあるか」——を機械的に訊ける

選択は**全能力を採点**して行う（`selectCapabilities`）。確信が低ければ広げ、信号が無ければ全部送る。
**先頭 N 件で切る形にはしない**——それは能力が消える仕組みそのものだから。

⚠ **なぜ本文だけ別ファイルなのか。** `js/atlas-console.js` は #R224 が**起動バンドルの 658 kB**
だったために on-demand にした。記述子は起動側に要る（`IntMapOS.execute()` と UI が Atlas より先に
使う。§10 の「ロード前から発見できる」も同じ要求）。プロンプトの散文は要らない——planner しか読まない。
だから記述子は起動バンドル、58 kB は Atlas チャンク。

### 5. 9言語のうち3つが、自分の言語で答えを受け取れていなかった

`_aiLangName()` は `IntMapLang.t(currentLang,'English','Japanese','German','Russian','Spanish')`
だった。`t()` は**位置引数が5つ**で、6言語目以降は**英語原文をキーにした inline 表**を引く。
そして `js/locales/ui.zh.js` は `'English'` を——**利用者にとってはまったく正しく**——「英文」と訳している。

この値は利用者向けではない。`_aiLangLine()` が
`Write your ENTIRE response in <名前> only` に差し込んで**モデルに送る**。つまり:

> **繁體中文・简体中文の利用者は「英文で書け」と中国語で指示され、
> フランス語・韓国語（inline エントリ無し）は英語でそう指示されていた。**

`js/lang-registry.js` に `englishName(code)` を足した。`Intl.DisplayNames(['en'])` から**導出**するので、
10 言語目でもここは編集しなくてよい（#R232 の「新しい言語は1ファイル」を壊さない）。
逆向きの `codeForEnglishName()` は `englishName()` から作ってあるので、2つが食い違うことはない。

同じ形の表が他に4つあった。`_mirrorLang`（5言語）・`_replyLang` の CJK fallback（5言語。
**漢字を書く zh / fr / ko の利用者は日本語で答えられていた**）・`case 'language'`（5言語。
「한국어로して」は「非対応の言語」と答えられていた）・音声入力の `langMap`（5言語）。全部 9 言語にした。

⚠ **#R85d の規則は変えていない**——「仮名の無い漢字だけの入力を中国語と決めつけない」は今も正しい。
その**理由**（「IntMap は中国語で返答しない」）が #R223/#R224 以降は事実でなくなっただけ。

### 6. 1つの質問が、最大3回の利用枠を無言で使っていた

Atlas は1つの依頼を planner ＋ **最大2回の bounded repair** で終える（画像なら読み取り＋自己検算の再読）。
`ai-proxy` は **HTTP リクエスト1本＝1消費**だったので、**1つの質問が最大3回**を使うことがあり、
それを表示する場所も、事前に警告する場所も無かった。

ターン鍵を入れた。クライアントは `x-intmap-turn` ヘッダに載せ、**その鍵の最初の1本だけが消費する**。
⚠ **鍵は信用していない**。行の主キーが `(user_id, turn_key)` なのでアカウントを跨げない。
1つの鍵が運べる回数（`TURN_MAX_CALLS`）と鍵の寿命（`TURN_TTL_S`）は Edge Function の**定数**で、
呼び出し側から上げられない。上限超過は 429 `{error:"turn_calls"}` で、1日上限の
429 `{error:"limit"}` とは**別の文言**を出す——後者は「明日また」、前者は「IntMap の修復ループが
詰まった」であって、利用者が払ったものの話ではない。

⚠ **ヘッダなのは、本文を読む前に消費するから。** 上限超過の呼び出し元の本文は、そもそも parse しない。
⚠ **払い戻しは charge とターンの両方を解放する**（`refund_ai_turn`）。片方だけ返すと、
再試行が「誰も払っていないターンの続き」として無料になる。

### 7. 状態は文章ではなくデータになった

`stateContext()` は 29 本の `lines.push(...)` で、**必要になったラウンドが1本ずつ足した文章**だった。
誰も足すのを覚えていなかった主題は planner から見えない——#R278 の形である。

各サブシステムが provider を登録し、**合成したスナップショットが正本**、モデル向けの文章は
そこからの**派生**になった。「読み方の規則」（`map "here"/"there" to it`、
`this date is a DISPLAY setting, NEVER the year of the data`）は provider ではなく **renderer** に置いた。
事実は1か所、規則も1か所、二重化しない。

⚠ **文章は同じ文章である。** 移す前に、旧本文を逐語で動かす等価ハーネスを作り、
同じ偽グローバルで両方を駆動して1行ずつ突き合わせた——**31 行出て、31 行入り、順序も同じ**。

ターン台帳も足した。`_hist`（切り詰めた散文）とは別に、**目標・計画・能力 ID・正確な引数・結果・
objectId・再開トークン**を turn 単位で持つので、「それ」「さっきの経路」が**ID で**解決する。
メッセージを編集して巻き戻すと、**構造化側も同じ turn から捨てる**——取り消した turn が作った
オブジェクトを「それ」が指し続けないように。

### 8. 監査 20 項目と、それが赤くなることの実証

`scripts/atlas-catalog.mjs`（#R278）は良い問いを1つ訊いている——「planner に説明されているか」。
それが**唯一訊かれていた問い**だった。新しい監査は残り 19 を訊く（`scripts/atlas-capability-audit.mjs`）。

⚠ **緑しか見たことのないゲートは、何も見ていないゲートと区別がつかない。**
20 項目すべてが**入力をデータとして受け取り**、`tests/r318-checks.test.mjs` が各項目に
**欠陥を仕込んだ fixture**を与えて赤くなることを確かめる。

初回実行で、この監査は**6件**を出した。5件は本物:

1. `lineOfSight` の到達不能ラベル（削除。JS の規則上、削除は挙動を変えられない）
2. `map.measure` が `map` を生成すると宣言していた（ツールを**構えるだけ**で、線は利用者が引く）
3. `data.satelliteCompare` の観測器がパネルしか見ていなかった（**両方**見る観測器を足した）
4. `IntMapOS.exec('tab.monitors')` を登録なしで呼び、**戻り値を捨てて `{ok:true}` を返して**いた
   （撤去は撤去のまま。直したのは**報告**のほう）
5. 4言語のロケールに新しい結果文言 29 件が無い

6件目は**私自身の検査が私自身のコードに当たった**もので、直したのは検査のほう:
`slice(0, N)` を一律に禁じたら、`API.all()` の**母集合**を切ることと、プロンプトに同行させる
**近い候補の件数**を切ることが区別できなかった。禁じるべきは前者だけ。
（さらに、`IntMapOS.exec('tab.monitors')` を**コメントの中で**見つけて赤くなった。
この日記で **8 回目**の同じ形なので、監査はコメントを剥いでから読む。）

### 9b. 起動の重さは、この主題が払える値段ではなかった

#R311 が**起動バンドルに予算**を付けた（`scripts/perf-budget.mjs`。「A startup cost that goes up
needs a reason — say it, or take it back out」）。カーネル4本をまるごと eager にすると
**+18.9 kB brotli / eager モジュール +4**。**質問を一度もしない読み手が払う値段**である。

指示書 §3・§10 が eager を要求しているのは**記述子だけ**——「能力は、そのモジュールが読み込まれる
前から発見できる」。executor も結果の形も状態台帳も、**何かが実際に走るまで誰も要らない**。
だから記述子（`js/atlas-capabilities.js`）だけが起動バンドルに残り、`IntMapOS.execute()` は
`import()` の上に乗った薄い await になった。**`execute()` は最初から存在する**——元から Promise を
返す関数なので、取得は呼び出し側が既にしていた await の中に隠れる。

実測 **+18.9 → +8.5 kB brotli**、eager モジュール **+4 → +1**（残りは記述子そのもの）。
新しい基準値を `tests/perf-baseline.json` に記録した。

### 9c. そして、その分割が Atlas を丸ごと殺していた

分割の直後、ブラウザ検査が1行だけ出した:

```
[IntMap] lazy module atlasConsole — its factory threw: Cannot access 'Jt' before initialization
```

**Atlas は本番ビルドで一度も mount できていなかった。** 原因は2つ、どちらも同じ形（TDZ）:

1. `js/atlas-executor.js` が `js/atlas-capabilities.js` を **static import** し、
   `atlas-capabilities.js` が executor を **dynamic import** していた——起動チャンクとこのチャンクの
   間の輪。Rollup はどちらかを先に評価するしかなく、片方の `const` が自分の TDZ の中にいる順序を選ぶ。
   ⇒ **レジストリは引数で渡す**（両方の呼び出し側が既に持っている）。executor は import しない。
2. `_requestProfile` ほか #R135 の名前は**巻き上げられる `function` 宣言**だったので、
   500行**上**の `window.IntMapAtlasQA` という**オブジェクトリテラル**がそれを名指しできていた。
   分割で destructuring の `const` になった瞬間、その参照は TDZ に落ちた。
   ⇒ 束縛を、必要な最後の依存（`WORLD_RE`）の直後まで**上げた**。

⚠ **どちらも `node --check` を通り、`npm run test:checks` の 1,900 件を通り、監査 20 項目を通る。**
バンドラが決める評価順は、ソースを読む検査には見えない。#R301 が「ソースしか読まない検査は
バンドラがそれを保ったかを言えない」と書いたのと同じことが、今度は逆向きに起きた——
**見つけたのは本物のブラウザで本物のビルドを開いた 1 本**だった。

### 10. 今回入れなかったもの（理由つき）

- **plan schema の provider 側強制。** IntMap の他の schema は Gemini の方言（`type:'OBJECT'`）で
  書かれており、本番の provider（OpenAI Responses API）は別方言を要る。しかも `atlas_plan` は
  #R113c の**実測**（強制 JSON モードが大きい planner プロンプトを 45 秒のタイムアウトへ押し込んだ）で
  Gemini の JSON モードから外してある。**強制しているのはクライアント側の決定論的な検証**で、
  未知の能力・未知の引数・解決できない `$ref`・壊れた依存を、**理由つきで拒否して黙って捨てない**。
  schema 自体は `opts.schema` で proxy まで届いており、方言が揃った provider ではそのまま効く。
- **`control` / `module` の全面移行。** §14 の要求（完全一致優先・曖昧なら候補を返す・
  `click()` 後の事後条件・140 件上限の撤廃）のうち、**事後条件と ambiguous_target は入った**
  （`control` 観測器）。`moduleCatalog()` が `IntMapLazy` を見ずに `Object.keys(window)` を歩く点と、
  `controlCatalog()` の 140 件は**まだ残っている**——どちらも DOM 走査の設計そのものを
  差し替える必要があり、この主題1本で1ラウンドある。監査の⑮がその状態を毎回印字する。
