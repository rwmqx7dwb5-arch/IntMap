## R427 — **都市名ラベルが年に従う——608都市・685の歴史名・9言語、層は1本も足さずに**

> 「IntMapは、現在は国名ラベルに関してはChronosに対応していますが、都市名ラベルも同じ要領で
> 対応するようにヴォルゴグラードなど。できる限り多くの、地名の変わった経験のある都市に対応して。
> 江戸なんかも。数百以上に。」

国名は #R94k から時間を旅していた（`js/history.js` の `histId` が名前と旗を差し替え、
`js/time-borders.js` が `imtb-lbl` で描く）。同じことを1段下——**集落の名前**——でやる。

### 1. なぜ「層を足す」ではなく「式を包む」なのか

集落のラベルは OpenMapTiles の地物（`ofm-city`・source-layer `place`）で、**このアプリが書ける
プロパティは1つも無い**。素直に見える答えは「自前の点を上に描き、タイル側を隠す」だが、これは
2つ払う——**ラベルがタイルの選んだ位置から動く**（衝突処理も凡例順もそこで決まっている）し、
**隠すにも結局名前照合が要る**ので難所を1つも回避しない。

⚠ **なので `text-field` そのものを書き換える。** `js/hist-cities.js` が組む式は
**既定が従来の言語式そのもの**である `match` なので、記録にある都市は**タイル自身の位置**に
その年の名前で描かれ、地球上の他のラベルは1バイトも変わらない。`match` はハッシュ引きなので
費用は表の大きさに比例しない。

⚠ **`match` は2段（`name:en` → `name`）。** タイルがどちらの欄に綴りを持っているか分からないので、
都市のキーは**両方**に入る。

実測（本番形の Chromium・1942年・ヴォルゴグラード上空 z6）:

| | `text-field` |
|---|---|
| Now | `["coalesce",["get","name:en"],…]` — **103 B** |
| 1942 | `["match",["coalesce",["get","name:en"],""],["Kinshasa"],"Léopoldville",…]` — **27,832 B・420分岐** |

そして画面には **Stalingrad** が出て、同じ視野の Mikhaylovka・Kamyshin・Volzhskiy・Shakhty・
Volgodonsk・Elista・Salsk・Astrakhan は**1文字も変わらない**。

### 2. ⚠⚠⚠ 綴りは1つの都市しか指してはならない——これが記録の設計を決めた

書き換えは**タイル自身の名前との一致**で起きる。だから同じ綴りを別の都市が持っていれば、
**その都市も改名されてしまう**。`scripts/build-hist-cities.mjs` は全キーを
`data/gazetteer-world.json.gz`（GeoNames cities1000＋別名）と照合し、
**40 km 以内に本人が居ること**と、**2万人以上の別の集落が同じ綴りを持たないこと**を要求する。

**実測でこれが落とした4行**（どれも「良い行」に見えていた）:

| 落とした行 | 衝突相手 |
|---|---|
| アルマヴィル（アルメニア・旧 Hoktemberyan） | アルマヴィル（クラスノダール地方・**199,548人**・589 km） |
| シルヴァン（アゼルバイジャン・旧 Ali Bayramli） | シルヴァン（イラン北ホラーサーン・**82,790人**・830 km） |
| カドマ（ジンバブエ・旧 Gatooma） | **門真市**（大阪府・**131,727人**・12,558 km） |
| テリヨキ（→ゼレノゴルスク） | ゼレノゴルスク（クラスノヤルスク地方・**71,354人**・**ラテンもキリルも同じ綴り**） |

⚠ **`!` を付けた例外は6件だけで、すべて理由が行に書いてある。** район（Korolyov・Podilsk）、
okres（Komárno）、distrito（Latina）＝**行政区画で `place` 層に存在しない**もの、および
Кировск／Истра／Светлогорск／Constanța／Santo Domingo のように **GeoNames の alt にしか無い旧称・
異言語の exonym** で、相手のタイルが今その綴りを持っていないもの。

### 3. ⚠⚠⚠ 門は「2都市が同じ綴り」しか見ておらず、「1行の中で2回」を素通りさせていた

最初に書いた照合は `prior && prior !== r.id`——文にすると「1つの綴りが2つの都市を指してはならない」で、
`['Jakarta','Jakarta']` は**素通りする**。3行あった（Jakarta・Goranboy・Balkanabat）。

⚠ **これは無害な打ち間違いではない。** 有効な都市のキーは**すべて1つの `match`** に入り、
MapLibre にとって重複した分岐ラベルは**間違った答えではなく拒否される style** である——
«Branch labels must be unique»、`addLayer` が throw し、**ラベル層が丸ごと存在しなくなる**
（#R211 がその壊れ方を実測している）。

⚠⚠⚠ **見つけたのは、このラウンドで書いた検査の初回実行だった。** `tests/r427-checks ⑦` は
サンドボックスで `js/hist-cities.js` を起動し、`fetch` に**本物の `data/hist-cities.json`** を
食わせ、`js/place-labels.js` が `setLayout` に渡すのと**同じ式**を受け取って、
`@maplibre/maplibre-gl-style-spec` の `createExpression`——**レンダラ自身のパーサ**——に通す。
ソースを読む検査は6本とも緑だった。門はいま**レンダラが訊く質問**を訊く。

### 4. ⚠⚠ 判定はクロックであって国境層ではない

現代の**国名**ラベルは `IntMapTimeBorders.active()` で隠れる。都市名がそれに乗ってはいけない——
その旗は CShapes が2019年で終わるため**2020年以降 false** で、2022年の**ヌルスルタン→アスタナ**は
永久に出なくなる。名前は年についての事実なので、**年を時計に訊く**。検査⑧が2020年で
`Nur-Sultan` を要求することでこれを固定している。

⚠ **適用先は `ofm-city`（`class in [city, town]`）だけ。** §2 の免除理由はこの絞り込みを前提に
書いてあるので、`ofm-other`（suburb・quarter・village）へ広げると**書いた理由が黙って無効になる**。
`tests/r427-checks ⑤` が呼び出し箇所を**ちょうど1つ**に縛る。

### 5. 9言語——「英語へのフォールバック」ではなく、現行の地図がやっていることと同じ

`N(en, ja, ru, zh-Hant, zh-Hans, ko, {de,es,fr})`。**0 は欠落ではなく主張**で、
「この地名にその言語の定着した形は無い」という意味である。そのときの答えは**ラテン文字の名前**で、
これは `js/place-labels.js` が**今すでにやっていること**（`name:zh-Hant`→`name:zh`→`name:en`→
`name:latin`）——OSM が中国語タグを持たない都市は、Chinese の読者にも既にラテン文字で出ている。
ここで音訳を発明すれば、**過去が現在より多くを主張する**ことになる。

⚠ **既定はビルドが解決し、`data/hist-cities.json` は9つのキーをすべて綴り出す**ので、実行時に
fallback 規則は1つも無い。被覆は**測って印字する**:

```
en 685/685 · jp 685/685 · ru 685/685 · zh 199 · zh-hans 199 · ko 199 · de 131 · fr 101 · es 64
```

⚠ 中国の exonym 行（Canton／Amoy／Chungking／Mukden／Tientsin／Port Arthur／Peking…）は
**zh/jp/ko 欄が現代名を繰り返す**。廣州はずっと廣州だったのだから、それが正しい——
変わったのは英語（と独仏西）の**単語**のほうで、中国語話者には**変化が見えないのが正解**である。
⚠ 逆に Pusan→Busan や Kiev→Kyiv のような**単なるローマ字表記の変更は入れていない**。

### 7. 残っていること（隠さず書く）

- ⚠ **恒久のブラウザ spec は足していない。** `scripts/test-budget.mjs` の天井は **75.6 / 75.6 分**で
  余白がゼロで、1本足せば同じだけどこかから取らねばならない。⑦⑧ が**実物のパーサと評価器**を
  通しているので機構そのものは押さえてあるが、「レイヤーが実際にその式を受け取った」の部分は
  ⑤（ソース）が押さえている。
- ⚠ **本番形の検証は Playwright で行った**——preview ツールは**他セッションが5枠すべてを占めており**
  起動できなかった。Playwright は自分でサーバを立てて畳むので居残らない。
- ⚠ **クロックの下限は1850年**（`js/chronos.js` の `YMIN`）なので、それ以前の改名は記録に入れていない。
  これは仕様であって欠落ではない。`scripts/build-hist-cities.mjs` は**下限より前に終わる span を拒む**
  （実測でヤコバーバードの1行がこれで落ちた——出荷されて一生画面に出ない行を作らないため）。
- ⚠ **`from` が開いている span は「建設された年から」ではない。** 実測の分布は
  1860年 480件 → 1942年 420 → 1980年 176 → 2000年 77 → 2020年 6 → 2024年 0 で、歴史的に妥当な形を
  している。ただし 1860年に「レオポルドヴィル」と出るキンシャサは、**1881年に作られた町**である。
  ⚠ これは**この層がもともと持っている性質**で、このラウンドが足したものではない——`ofm-city` は
  どの年でも**今日の集落集合**を描くので、1860年の地図には元々キンシャサが出ている。そこに
  「最も古い記録上の名前」を書くのは、現代名を書くよりは近い。**建設年で `from` を締めるのは
  別の調査**であり、やっていない。
