## R477 — **アンカーは「どこで生まれるか」しか決めていない。「どこに居るか」を決める一覧に、海岸線は4ラウンド入っていなかった**

依頼は1行。**「Wind gusts で Coastlines & shores が見えない。」**

### 実測した状態

ビルド済みアプリ・基本表示のみ（#R476 で `cb-coast` は既定オン）・`dl-ec-gust` を点灯・平面投影・
本州上空 z6。スタイルのレイヤー順は次のとおりだった。

```
21:borders-only-casing   22:coast-only-casing   23:coast-only-line
…
30:im-night-lights-lyr   31:im-night-shade
32:ec-gust-0             ← raster-opacity 1（不透明）
33:layer-sat-labels      34:borders-only-line
```

**国境線は不透明ラスタの上に、海岸線はその9層下にあった。** 最大瞬間風速は `raster-opacity` が 1 の
ラスタなので、海岸線は「薄くなっていた」のではなく**消えていた**。⚠ `queryRenderedFeatures` は
どちらの状態でも `coast-only-line` を **15 本**返す——**幾何は常にそこにあり、上に不透明な一枚が
載っていただけ**なので、「描かれているか」を問う計器はこの欠陥に対して構造的に沈黙する。

### 原因——`js/coast-line.js` には欠陥が1バイトも無い

`js/coast-line.js`（#R289）は `borders-only-line` と**同じ `ofm` ベクタソース・同じ `BORDER_COLOR`・
同じ `BORDER_WIDTH`／`BORDER_CASING`・同じ黒縁の対・同じ retry の梯子**を使う。そして
**同じ `before` アンカー**を計算する。「全く同じ手法で」は文字どおり守られていた。

**上に居続けるかを決めるのは、そのアンカーではない。**

| 決めるもの | 何を決めるか |
|---|---|
| `before` アンカー（`js/coast-line.js` / `js/app-body.js`） | レイヤーが**生まれる**位置 |
| **`js/label-occlusion.js` の `STACK`** | レイヤーが**居る**位置 |

`STACK` は #R19 の規則「地名や国境はどのレイヤーよりも最前部に」の実体で、`idle` と `styledata` の
**たびに再表明される**。だから追加順は毎回上書きされる——ファイルの中のコメントが
「the order these layers are ADDED in is transient」と書いているとおりである。

`borders-only-line` はこの一覧に在り、**`coast-only-line` は #R289 以来一度も入っていなかった。**
つまり2本の線は、**検査が見ていた全ての性質で同一で、読み手に見える唯一の性質で正反対**だった。

### 黒縁は線の一部なので、一緒に上げる

`raise()` は**一覧に在るものを動かし、無いものを置いていく**。だから線だけを一覧に書くと、
線は上がらず**対が割れる**。

`borders-only-casing` は **#R210 以来ずっと割れていた**（上の実測では線から13層離れており、
その間に gust ラスタが居た）。黒縁は「淡い基図の上で白い線を読ませる」ために線の直下に置く対で、
それが効かない状態が誰にも報告されないまま続いていた。

`STACK` はこの順になった。

```js
['layer-sat-labels','coast-only-casing','coast-only-line','borders-only-casing','borders-only-line','ofm-river', … ]
```

- **縁は必ず線の直前**（一覧の順に `move` するので、「直前」＝「直下」）。
- **国境と海岸線が同じ地物の上を走るときは国境が勝つ**（海岸線の対を先に、国境の対をあとに）。

修正後の実測: `29:ec-gust-0  30:layer-sat-labels  31:coast-only-casing  32:coast-only-line
33:borders-only-casing  34:borders-only-line`。

### 門——3段、どれも写しを持たない

| 段 | 何を測るか | いつ走るか |
|---|---|---|
| `tests/r477-checks.test.mjs` ①〜⑤ | `STACK` と `js/data-layers.js` の `BASE`（#R79 の監査表）を**両方パースして**照合 | 毎 push（`test:checks`） |
| `tests/smoke.spec.js` ㉑ | **最上段に層を1枚足して自己修復を実際に走らせる** | 毎 push（core tier） |
| `tests/prod-smoke.spec.js`（#R398 に相乗り） | **本番の実ラスタの上に本当に載っているか** | deploy のたび |

- **①** `cb-borders` と `cb-coast` が駆動する id が**全部** `STACK` に在る。⚠ 行の名前は主題なので
  名指すが、**どの id を駆動するかは書き写さず `BASE` から取る**（#R309 が製品から消した写しの形を
  門の中に作らない——#R476 と同じ判断）。
- **②** `STACK` の中の `*-casing` は、**必ず直後が同じ接頭辞の `*-line`**。一覧自身の綴りから導出
  するので、あとから足された対にも効く。
- **③ 一般形**——**どの base トグルも「全部一覧に在る」か「全部無い」かのどちらかで、半分だけは
  禁止**。`borders-only-casing` が #R210 から陥っていた状態そのものを名前で禁じる。
- **④** 海岸線の対が国境の対より前（＝下）。**⑤** `raise()` が今も `STACK` を順に `move` し、
  `inPlace()` が今も「**最下段の label が最上段の data より上**」（#R25）を要求し、`idle` と
  `styledata` の両方で再表明されること——①〜④ は一覧についての主張なので、**一覧が適用され
  なくなれば全部意味を失う**。
- ⚠ **どれも出荷版のソースで赤を確認した**: `tests/r477-checks` は 5 本中 **4 本が赤**、
  `tests/smoke ㉑` は `Expected: > 32 / Received: 23` で赤。

### この欠陥が4ラウンド見えなかった理由

`tests/smoke.spec.js` ㉑ は #R289 以来、海岸線を**国境線自身の実測値**と突き合わせてきた——
色・幅の梯子・縁の梯子・両方が地図に載っていること・オフがオフのままであること。
**その5本は、この欠陥の全期間ずっと緑だった。**

**同一性を測る検査は、測っていない次元での正反対を止められない。** ㉑ に足りなかったのは
「同じか」ではなく「**どこに居るか**」で、それは #R439 が等圧線について同じ形で学んだこと
（不透明ラスタの下に 3,299 本の等圧線が描かれていた）の、1段外側での再発である。

### 触っていないもの

- `js/coast-line.js` の描画・`before` アンカー・retry の梯子・`window._imCoastAuto` のラッチ。
  変えたのは**先頭のコメントに `STACK` を名指す1段落を足したことだけ**。
- ECMWF ラスタの位置（`js/wx-ecmwf.js` の `before()`／`lift()`／`toTop()`）。天気は
  **夜側の上・ラベルと国境の下**という Windy の配置のまま（#R299/#R439）で、1バイトも動かしていない。
- 基本表示の他の行（`cb-poi` / `cb-admin1` / `cb-roads` / `cb-rail2`）。これらも `STACK` の外に
  居るが、#R19 の規則が名指すのは「地名と国境」であり、**海岸線は国境線として実装された線**で
  ある一方、道路・鉄道・州県境・施設名はそうではない。**依頼の範囲外なので触っていない。**
