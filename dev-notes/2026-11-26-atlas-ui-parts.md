発注書（ハプスブルク帝国・スヴァウキ回廊の 2 事例）が指した「何を作れば理解が深まるかを Atlas が自分で決め、それを実現する力」のうち、
次の 4 つを実装した。**どれも特定の主題・事例のための記述を持たない**（言語分布・回廊・黒土地帯のデータも分岐も足していない）。

1. **回答内の汎用切り替え `tabs` / `steps`**（`ui.inlineControls` と `ui.compose` の `controls` ブロックの新しい種類）。
   選択肢ごとに**能力呼び出しの束**（カメラ・時刻・レイヤー・データの描画など、Atlas 自身が呼べる能力）を結び、押すと**モデル往復なしで**
   その場で実行される。許す呼び出しの条件は能力表が決める（存在する・セッション内で戻せる・確認不要・単純なデータ）
   — `js/atlas-ui-spec.js` `switchCallProblem`。描くときと押すときの 2 回同じ関数で検査する（保存された回答のマークアップは信頼しない）。
   押下側は `js/atlas-switch.js`（新規・入口 1 つ）。`ui.inlineControls` は、これまで描けない項目を黙って落としていたが、描けないときは
   理由つきで Atlas に返す。
2. **内部の検証過程が回答文に漏れる**（「4つの区画が面として表示されているため、描き直しは不要です」）。経路を特定した:
   ゴール検証の注記（`atlas-agent.js` の `goalNote`）と出力ゲートの注記が、Atlas に「そのまま回答して**理由を述べよ**」と求めており、
   理由を書く場所が読者に見せる `final_text` しか無かった。**書く場所が無いのが構造の欠陥**なので、返信スキーマに `note_to_intmap`（読者に見せない・
   `trace.machineNotes` に記録）を足し、注記はそこを指し、システムプロンプトに「`final_text` は読者への答えのみ」を 1 行足した。
   語彙の禁止リストは作っていない。
3. **画面を撮るときに地図上のボタンが一瞬消える**。原因は `captureCanvas` が撮影の間ずっと**生きた `document.body`** に `capture-mode` を付けていたこと
   （idle 待ち＋描画待ち＋html2canvas で数秒）。html2canvas の `onclone`（複製した文書）にだけ付けるよう移した。写真は同じ（同じ CSS で同じ部品が消える）で、
   読者の画面は変わらない。`finally` の復元は不要になり削除。
4. **Eval に initiative の軸**（`scripts/atlas-eval/initiative.mjs`・`open-questions.json`）。独立グレーダー `atlas_grade` のスキーマに
   `initiative`（0〜2）を加えたが、**合否の導出には入れない**（単純な事実照会を平易に答えるのは正しいので 1）。0 は「問いが広がりを招いているのに言葉だけ」。
   グレーダーには「そのターンが実際に何を実行したか」を 1 行で渡す（能力表の `produces` から導出した出力の種類・押せる部品の有無）。
   問題集は**正解も期待する能力も地図も持たない**開いた質問 6 本（気候・都市・移住・産業・物流・水）。数は事実として併記するだけで目標にしない。

**確かめたこと / まだのこと**: 単体検査（`tests/atlas-ui-parts-checks.test.mjs`）と関連既存検査。本番での実測（別主題の未知の質問 2 つ以上）は merge・deploy 後に行い、
結果は追記する。外部データの取得→変換→結合→塗り分けの 1 本の流れの実測（項目 2）も本番で行う。
