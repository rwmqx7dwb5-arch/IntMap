## R549 — **ShakeMap の凡例は、1つの扉から入ったときだけ地図に追従していた**

#R546 の**本番検証**が見つけた 2 件。どちらも「動いているように見える」形で、
ローカルの検査は 12 本とも緑、ブラウザでの通し確認も（`show()` から入っていたので）緑だった。

### 1. 凡例を載せていたのは `show()` だけだった

`open(id, metric)` は地図を新しい指標に描き替えるのに、凡例には触れていなかった。
本番実測: `open('nc72282711','pga')` の直後、`state()` は `metric:'pga' / units:'pctg' /
levels:[0.2…50]`、地図は PGA（面なし・等値線のみ）。**凡例は MMI の 2.5…7.5 のまま**、
1.5 秒待っても変わらない。

⇒ **凡例を載せることは「開く」ことの一部**である。`open()` が自分で `mountLegend()` を呼び、
`show()`（地図のクリックハンドラと dispatch が使う扉）は**同じものの別名**になった。
指標ボタンの `.then(mountLegend)` も要らなくなったので外した。

### 2. ⚠⚠⚠ 見出しは、どの扉から入っても一度も追従しなかった

指標ボタンを押す UI 経路では本文（色見本・単位・「色表が無いので等値線のみ」の注記）は
正しく更新される。**それでも `<h4>` だけは「ShakeMap（USGS） · MMI」のまま**で、PGA でも
PSA(1.0) でも変わらない。

理由は名前の渡し方にある。`_registerLayerOpacity(id, name, …)` は `name` を
`ensureGenericLegend` へ渡すが、**あの関数は箱を「作るとき」にしか `<h4>` を書かない**。
2 回目以降の呼び出しが持ってきた新しい名前は、黙って捨てられる。
⚠ **渡した値が使われたかどうかは、渡した側からは見えない。** 本文は毎回組み立て直していたので
正しく、見出しだけが「1 回目の値」で凍っていた。

⇒ `mountLegend()` が `<h4>` を**自分で書く**。

### 3. 本番でしか出なかった欠陥が、これで 2 つ目

#R546 の `image` source に鍵を 1 つ多く渡していた件（等値線も凡例も出るのに面だけ無い）と
同じ形——**機能はもっともらしく動いており、計器はどれも「その主張」を見ていなかった**。
⚠ 1 つ目は stub のレンダラが何でも受け取るせいで、2 つ目は**凡例ホストを stub していなかった**
せいで見えなかった。`tests/r549-checks.test.mjs` は凡例ホストを
`js/data-layers.js` が作るのと同じ形（箱は再利用、見出しは作成時のみ書く）で stub し、
**箱の中身と見出しの文字列**を測る。
⚠ **変異させて赤を見た**——2 行を外すと 0 pass / 2 fail。

⚠ harness の落とし穴も 1 つ記録しておく: このモジュールは `IntMapSafe` を**裸のグローバル**として
読む（`js/wb-layers.js` ほか app 全体の作法）。`window.IntMapSafe` だけを定義した sandbox では
`mountLegend()` が自分の catch に落ちて**何も書かない**ので、検査は「凡例が載っていない」と
読んでしまう。`globalThis` にも置くこと。
