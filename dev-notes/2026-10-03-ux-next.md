〈依頼〉全権委任の第 2 波・デスクトップの UI/UX と企業アトラスの担当。「体験の造形」——新しい読者・使い道を生む商品を 1〜2 本、実データと実挙動で。途中で追加: 本番 f01c607 で国の吹き出しの Wikipedia 照会が多言語を並べた表示ラベル（`ⵍⵉⴱⵢⴰ ليبيا Libya`）を記事名にして 404、ボタンが出ない——表示用の値を照会に使っている構造を直す（検査付き）。

## 0. 測った（前）

- **「コマンドパレット」は 7 つのコメントの中にだけ在った。** `js/data-layers.js`（地震・パンデミックのシミュレーター）・`js/session-tabs.js`（`company.open`）・`js/app-body.js`（`ui.sidebar.open`）・`js/map-ui.js`・`js/routing.js` が「ボタン・パレット・Atlas が同じ 1 本を押す」と書いていたが、パレットは存在しなかった。Ctrl/⌘+K は Atlas を開くだけ（#R42）。
- 入口の数: レイヤー 170 余り（14 の棚）・Layers パネル足元のツール・5 つのタブ・OS コマンド・端末上の地名・企業 533 社・作例 16 本とツアー——どれも**それぞれのパネルの中**にあり、読者はどのパネルを開けばよいかを知っている必要があった。
- 企業アトラスは「この企業はどこに？」（1 社のプロフィールと拠点）には答え、「**ここにはどの企業が？**」には答えられなかった。拠点は 1 社 1 ファイル（533 ファイル・3.8 MB）で、全企業を同時に読む索引が無い。実測: プロフィールが公表している拠点は **4,466 か所**（本社 539・発電所 802・子会社事業所 1,949・倉庫 330・データセンター 223・鉱山 120・工場 125・製油所 62…／精度 exact 2,789・city 1,677）。
- **Wikipedia の照会**（`js/map-ui.js` の地名ポップアップ）: 照会語は地物の `name`（OSM の `name` タグ）。リビア・モロッコ・アルジェリアなどでは `name` が**公用文字を並べた表示形**で、どの言語版にも記事が無い。同じ地物は `name:en`「Libya」・`name:ja`「リビア」を持っていた。読者の言語版も `{jp:'ja',de,ru,es}` の 5 項目表で、fr/ko/zh の読者は英語版へ送られていた。生の照会を node から実測: 新しい経路で en は `https://en.wikipedia.org/wiki/Libya`、日本語の読者は `https://ja.wikipedia.org/wiki/リビア` に着く。

## 1. 作ったもの

### コマンドパレット（`js/command-palette.js`・遅延）

- Ctrl/⌘+K（`js/keyboard-shortcuts.js`。入力欄の中でも効く）・OS `ui.palette`・Atlas `panel.palette`（`query` を入れて開く。結果に「いま何が出ているか」を載せる）。
- **一覧を 1 つも持たない。** 行は開いた瞬間に持ち主から読む: OS コマンドのうちコントロールに結ばれたもの（`btn`・`data-os-act`。名前はそのコントロールの読者の言語の名前）／meta `title`（[en, jp]）を宣言したコマンド（コントロールがまだ描かれていなくても出る——今回 `company.footprint` が最初の 1 件）／ツールバー（地図の操作列・タブ・Layers のツール・`btn-tool-*`）／レイヤーの登録簿の全行（状態のスイッチつき）／`localFuzzyPlaces`／企業の索引（2 文字目で 1 回取る）／`galleryItems`／最後に Atlas。
- 選んだら**持ち主の経路**: レイヤーは行のチェックボックスと `change`、地名は検索欄の結果行と同じ `gotoPlace`（`search-geocode.js` に `goToLocal` を足し、`IM_HOST.goToLocalPlace` で渡す）、全文検索は検索欄の Enter、企業は `company.open`、作例は `openShowcase`、Atlas は `run`。
- 並びは一致の度合いだけ（全体 100・前方 90・語頭 80・内部 66・全語 50/60）。種類で重みを付けない。同点は最近選んだもの（キーで 8 件）→短い名前。
- **Atlas を開く手段は減っていない**: 1 文字キー A、パレットの最後の行、パレットの欄で Ctrl/⌘+K（打った文をそのまま質問に）。キーボードのヘルプの行を書き換えた。
- レイヤー行の名前の読み方は Atlas の中に 2 回書かれていた（`layerCatalog` と `_labelOf`）。`js/layer-row-label.js` に 1 つにし、Atlas とパレットが同じものを読む。

### 企業の拠点の地図（`js/company-footprint.js`・`data/companies/footprint.json`）

- **データ**: `scripts/companies/footprint.mjs` がプロフィールから導出する（足さない・推測しない・精度と状態を落とさない・座標は 5 桁）。`build.mjs` が索引の直後に書き、`companies-audit.mjs` ㉒ が「出荷したファイル＝いまのプロフィールから導いたもの」をバイトで見る（壊したファイルで落ちることを確かめた）。毎週の再取得の workflow は `git add data/companies` なので一緒に提案される。
- **画面**: 全拠点をクラスタで描き、左上のカード（グループ 6 種の切り替えと件数・業種・**表示範囲の企業と国**・「出典が公表している拠点だけ」の一文）。表示範囲は `moveend` のたびに数え直す（日付変更線をまたぐ箱も）。点のカードは市・地域の代表点をそう述べる。企業を押すとプロフィール。カメラは動かさない（クラスタを押したときだけ）。
- **入口**: Companies タブの「拠点の地図」・OS `company.footprint`・コマンドパレット・Atlas `data.companySites`（`show`／`query`／`hide`・国・グループ・業種・表示範囲。結果は構造化して `meta.companySites` に）。観測器 `companySites` は source を `map.companySites` として claim した描画の件数を数え、数えられないときは「失敗」ではなく `unobserved`（one-pass-or-a-reason §5）。

### Wikipedia を照会用の欄で（`js/wiki-lookup.js`）

- `wikiTargets(props, keys)`: ① `wikidata` の QID（sitelinks で読者の版→en）② 地図のラベルが読む `name:<言語>` の順（`IntMapOsmNameKeys`——言語の表はここに書かない）、それぞれ**その言語の版**で（`name:zh-Hant`→zh）③ `name:en`・`name_en`・`name_int`・`name:latin` を en で ④ 最後に `name`——**1 つの書記体系で書かれているときだけ**（Unicode の Script 属性で数える。日本語の漢字かなカナ、韓国語のハングル＋漢字は 1 つ）。ラベル自身が拒む `name:*`（#R691 の記録された誤訳）は照会でも拒む。
- 地名ポップアップの 3 つの呼び手（ラベルのクリック・水域地形ラベル・指の余白つきの当たり）が地物の properties を渡す。歴史の政体（`opts.wiki` の明示題）の経路は変えていない。

## 2. 否定した・残したもの

- **パレットに OS コマンドを全部は並べない。** `layer.on {id}` のような引数つきの API は名前で差し出すものではない（Atlas が扉）。題を宣言したものとコントロールに結ばれたものだけ。
- **企業の拠点の地図はレイヤーの登録簿に入れなかった。** 1 社の拠点（`company-facilities`）と同じく企業アトラスの表示で、共有リンク・Chronos の時間宣言（拠点は開設日をほぼ述べていない）に載せる根拠がまだ無い。載せるなら「拠点の開設・閉鎖年」を Chronos に宣言する仕事が先。
- Atlas の POI ポップアップ（`js/atlas-console.js` の `poi-wiki`）は QID・wiki 欄を先に使っているが、名前だけの POI は `p.name` で引く。同じ `wikiTargets` に寄せられる——今回は範囲外として残す。
- 国カードの紹介文（`js/countries-ui.js` `_fillCountryIntro`）は国の表示名（`cName`）で引く。表示名は curated で多言語の並記ではないので今回の症状ではないが、照会を ISO→QID にする余地はある。

- 境界の窓口（`tests/global-surface-baseline.json` を `--update`）: `IM_HOST.goToLocalPlace`（検索欄の飛び方をパレットへ渡す 1 本）と `window.IntMapCompanyFootprint`（遅延 module の公開名。`IntMapCompanyFacilities` と同じ形）が新しく、読みが増えたのは `IntMapOS`・`IntMapLazy`・`IntMapCompanyData`・`IntMapAtlas`・`IntMapDialog`・`IntMapHiddenLayerRows`・`IntMapOsmName(Keys)`・`IntMapPlaceFraming`・`IntMapI18N`・`IntMapSafe`。どれも持ち主がまだ export していない（`IntMapDialog` だけは `module-graph --plan` が「いま export できる」と言う——次に移すならここ）。
- `fetch` は 2 本とも期限つき: Wikipedia の照会は `readWithin(u, clockFor(u,'direct'))`、footprint は `jsonWithin(…, 20000, …, {idle:true})`（20 秒の無音は推定値。ファイルが 1 MB を超えたら見直す）。

- **起動費用**: 起動時の module は増やしていない（`wiki-lookup.js` は最初 `map-ui.js` から静的 import して eager.modules を 311→312 にしたので、ポップアップが使うときに動的 import へ変えた）。遅延側は async.raw 11,937.7→12,002.7 kB・async.gzip 3,944.7→3,971.9 kB に上げた（`perf-budget --update`）。内訳は新しい遅延チャンク `command-palette` 13.8 kB・`company-footprint` 15.3 kB・`wiki-lookup` 2.3 kB・`layer-row-label` 0.4 kB と、Atlas の能力 2 本（行・説明・観測器）。どれも押したとき・訊いたときにしか読まれない。`data/companies/footprint.json`（271 kB／gzip 92 kB）は「拠点の地図」を開いたときだけ。

- `tests/ux-next.spec.js`（ブラウザ・1 ページ）: ① Ctrl+K→「night」→Enter で登録簿の行がオン・「pandemic」の操作・「company sites」が題で出る・「Japan」で日本へ飛ぶ・Esc ② `company.footprint` の描画件数＝ファイルの行数（レンダラに訊く）・本社を切ると件数が減る・日本の集計・閉じると source が消える ③ リビアの合成表示名で `_imPlacePopup` → 照会は en「Libya」で、表示名は 1 度も訊かれず、ボタンが出る（網は route で偽装）。
