## R395 — **ラベルは9言語で、値は英語だった——そして計器は正しく 100% を出していた**

依頼は2つ。「火山レイヤーを引き続き進めて」と「**クリックしたら出てくるカードの情報が翻訳されていない**」。

日本語で火山を開くと、こう出ていた——

```
火山の型          Stratovolcano
地形区分          Composite
構造区分          Subduction zone / Continental crust (> 25 km)
主要なマグマ組成   Andesite / Basaltic Andesite
地域              Eastern Asia Volcanic Regions
国                Japan
収録の根拠         Eruption Observed
```

**左辺は全部日本語で、右辺は全部英語。** `npm run check:i18n` は 100% を出しており、**それは正しい**——
あの門が測るのは「表がどれだけ埋まっているか」であって、`row(L('火山の型',…), p.t)` は
**翻訳呼び出しが1件**として 100% に貢献し、`p.t` は**どの計器の分母にも入らない**。
[[intmap-recurring-lessons]] B の再演で、直し方は新しい計器ではなく、**その値を計器の宇宙に入れること**。

### 訳せるのは、それが閉じた語彙だから——そして要求はデータから導出した

同梱ファイルが実際に持っている相異なり数（実測）: 火山型 **27**／岩石 **10**／構造区分 **10**／
地形区分 **7**／地質時代 **1**／収録の根拠 **5**／証拠方法 **25**／GVP 地域 **19**／小地域 **116**、
＋ USGS の航空カラーコードと警戒レベル **9**・脅威度 **5**・観測所名 **6**、週間報告の状況語 **7**、
気象庁の発表文言と変化 **8**、国名の修飾句 **2**。合計 **256 行 × 8 言語**。

表は `js/volcano-intel.js` の `VOCAB`、形は **`LA(英語, 日本語, ドイツ語, ロシア語, スペイン語)`**——
`IntMapLang.pickArgs` に束ねた**呼び出し**なので i18n の計器から見え、fr/ko/zh/zh-Hans は
`js/locales/ui.*.js` が英語文字列を鍵に持つ（他のすべての呼び出しと同じ経路）。
⚠ **新しい翻訳ヘルパーを作らない**——#R353 は arrow function のエイリアスで 40 件を落としている。

⚠⚠⚠ **`tests/rNNN-checks ①` は必要な語彙をデータから数え上げる。** `data/volcanoes_gvp.json` と
`data/volcano-detail.json.gz` を読んで**カードが印字しうる値**を列挙し、それぞれに行があることを要求する。
手で保つ表は「自分に何が足りないか」を言えない（#R335）ので、**スミソニアンが 28 個目の火山型を
足した日に、英語で出荷されるのではなくビルドが落ちる**（`Stratovolcano` の行を1つ消して赤を実測）。

### 国名は表に持たない——CLDR に訊く

`Country` は文字列だが、読者の言語の国名は**プラットフォームが持っている**（`Intl.DisplayNames`・
`js/widget-core.js`・#R249「never a bundled table」）。だから表が持つのは **ISO 3166 コード88件**で、
名前は CLDR から来る。⚠ **GVP 自身の複合はそのまま保つ**——国境上の火山は両国を名乗り、
GVP が但し書きを付けている2件（`Japan - administered by Russia` / `France - claimed by Vanuatu`）は
**その但し書きごと**示す。落とせば、**GVP 自身が主張していない主権をこの地図が主張する**ことになる。

### 訳さないもの——機関が書いた散文

地質の概要（全1,214座で **894,670 字**）・VONA の本文・週間報告の記述文は、語彙ではなく
**機関が書いた文章**である。利用者に選択肢（分類語だけ／AI で事前翻訳して同梱／開いたとき都度翻訳）を
示して**「分類語を9言語＋概要は英語原文と明示」**を選ばれたので、公表された言語のまま示し、
**その言語を読者の言語で述べる**1行（`.volc-orig`）を付けた。黙って出せば「翻訳漏れ」に見え、
機械翻訳すれば**観測機関の口に言葉を入れる**。⚠ 気象庁の文言だけは定型句なので**訳したうえで
原文を括弧で併記**する——「レベル２（火口周辺規制）」はニュースで読者が聞く言葉そのものである。

### ⚠⚠⚠ #R231 の鍵の保護は、ファイルの半分にしか届いていなかった

`scripts/zh-hans.mjs` は「`inline` の鍵は英語原文なので変換してはならない」を #R231 で入れている。
その正規表現は**インデントちょうど4文字**——`ui` 表の——を見ており、
`scripts/i18n-append-inline.mjs` が書く `inline` 表は**2文字**なので、**inline の鍵は一度も
保護されていなかった**。**全部の鍵が英語である限り見えない**（字体変換は ASCII に何もしない）。
気象庁は警報を日本語で発表し、**鍵はその文言そのもの**なので、このラウンドが最初の非英語の鍵を作り、
2件が壊れた——「レベル２（火口周辺**規制**）」→「…火口周辺**规制**）」。**どの呼び出し側も作れない鍵**で、
訳はファイルの中に在って一度も使われない。⇒ インデントを `\s{2,}` に広げ、
**生成物2本の差分がちょうどその2鍵だけであることを実測**した（`pages.zh-hans.js` は差分ゼロ）。
`tests/rNNN-checks ⑪` が「2つの中国語ロケールの鍵の並びがバイト単位で同じ」を主張し、
**その検査が空振りでないこと**（Han を含む鍵が4件以上あること）も同時に主張する。

### ⚠⚠ 台湾語彙の掃引——#R335 の目録を今回の 256 件に当てた

地名を一度に大量に足すのは、**字体がすでに共通なのでどの字体検査にも正しく見える**穴が開く瞬間である
（#R319 の `纽西兰`、#R335 の `社群`）。OpenCC の `twp→cn` を**出荷される簡体文字列**に当てて実測:
**9件の不一致のうち6件が本物**（`維德角`→佛得角・`肯亞`→肯尼亞・`葛摩`→科摩羅・`萬那杜`→瓦努阿圖・
`索馬利亞`→索馬里・`矽質`→硅質）、**3件は同じ偽陽性**（GVP の «New …» に対する `新增`→`添加`。
twp のソフトウェア語義であって、ここでは `新增` が正しい）。
⚠ **目録は網羅的ではない**ので地域名も読み、twp が挙げなかった同じ形を**6件**足した
（`安地斯`4か所・`加拉巴哥`3・`克馬得`4・`民答那峨`・`皮特康`・`加里波底`・`安地列斯`2）。
⚠ **`東加` は素の行にしてはならない**——`東加勒比`／`東加州`／`東加拿大` の接頭辞になる（#R322 の
`複製羊` の罠）ので、**トンガ–ケルマデックにしか現れない em ダッシュ込みの `東加—`** に絞った。
⚠ `矽`→`硅` は**このラウンドと無関係な既存の site も直した**（`二氧化矽`→`二氧化硅`）。

### ⚠⚠⚠ 「公表なし」と言われていた 65 座に、USGS は毎日水準を公表していた

①の段は `volcano/getElevatedVolcanoes` を読んでいた。**この API は定義上「平常より上」だけを返す**
（実測5件）。それ以外の米国の火山は⓪へ落ち、カードは「現在の警戒レベルを公表している観測機関が
ありません」と述べていた——**このファイルが真であらしめようとしている、まさにその一文**である。
`volcano/getMonitoredVolcanoes` は監視対象の全体を同じ形で返す。同じ分の実測: **70件・うち
GREEN/NORMAL が65件**、elevated の5件は**色・レベル・時刻までバイト単位で一致**（＝別の意見ではなく
上位集合）。⇒ ①は両方を読み、**GREEN/NORMAL を「発表」として述べる**。
地図の `status` モードは rank 0 を基底色と**別の色**で描く仕組みを #R353 が既に持っていた——
このラウンドまで、**そこに該当する火山がほとんど存在しなかっただけ**である。
⚠ **地殻変動（InSAR）は入れていない**——COMET の火山変動ポータルは API ではなく HTML を返し
（CORS も無い）、機械可読で権威のある全球フィードは見つからなかった。**無いものは無いと言う。**

### 1,214 を問いに絞る／噴火記録をマスタークロックに載せる

絞り込みは4つの独立したトグルで AND 合成: `spoken`（現在の状況を公表している火山だけ）／
`elevated`（平常より上）／`big`（VEI 4 以上を出したことがある）／`recent`（1950年以降に噴火）。
すべて**同梱ファイルが既に持っている属性**なので取得も推定も無い。
⚠ `spoken` は**不在の検査**（`['has','st']`）——`st` は誰も述べていない火山には**無い**。
⚠ **ハロー自身の条件は残す**（`['all', HALO_BASE, …読者の絞り込み]`）。輪は「今日、機関がこの火山に
ついて話している」という別の主張で、読者の絞り込みがその意味を変えてはならない。

時間軸は `volcano.time`。索引はカードが使うのと**同じ同梱ファイル**から作る。
⚠ **終了年が空欄の噴火を「終わっていない噴火」にしない**——GVP は「継続中」と「記録が無い」の
**両方に空欄**を使うので、空欄は開始年だけを数える。そうしないと19世紀の噴火が以後の全年に塗られる。
⚠ 時計の下限は1850年（`js/chronos.js`）で、凡例がそう述べる（カードには記録上の全噴火が出る）。

### Atlas は火山を運転できなかった

`js/beta-overlays.js` は #R353 から `volcano.*` のカーネルコマンドを登録していたのに、
**capability レジストリに火山の行が1つも無かった**——読者はボタンを押せて Atlas は押せない、という
#R318 が終わらせたはずの「5つの一覧が食い違う」形。⇒ **`data.volcano`**（名前でカードを開き記録から
答える）と **`map.volcanoFilter`**（色モード・4つの絞り込み・時間軸）を、**3つの一覧すべてに同時に**
足した（capability 表・dispatch の8スペース `case`・SYS ブロック）。監査20問は全緑。
⚠ `data.layerValues` とは重複しない——あちらの名前抽出器は `p.name||p.title||…` を見るが、
**火山の properties は1文字の鍵**なので「火山: N 件」しか言えない。

### 実測・実務

- **カードは言語切替に追随する**（`IntMapLangSwitch.bind`）。値がレンダリング時に解決されるように
  なったので、あとは描き直す理由だけが足りなかった。⚠ 火山灰 SIGMET のラベルも同じ理由で
  **fetch 時に焼かず**フィールドから作り直す（移動方向は `js/compass.js` の16方位・9言語）。
- **ハザード域の5区分の名前は1か所に畳んだ**（`js/volcano-layers.js` の `HAZ_NAME`）。凡例だけが
  訳されていて、地図のポップアップは USGS の生値だった＝同じポリゴンが2つの名前を持っていた。
- **数は連結ではなく `{n}`**（#R355）。凡例の年と件数、Atlas の答えの3文をプレースホルダーに直した。
- **⚠⚠⚠ `i18n-apply-inline` を回すと、後のラウンドが消した文字列が locale 表へ戻ってくる。**
  この掃引器は「**足すだけ**」で、鍵は**英語の原文そのもの**。だから**呼び出し側の英語が変わった行**は
  辞書の中に孤児として残り、**次に誰かが apply を回した瞬間に locale 表へ再投入される**。
  実測（このラウンドが踏んだ）: `scripts/i18n/r251-d.json` が
  「3D terrain, real imagery, and travel back to **1900**」を持っていた——#R380 が呼び出し側と locale 表を
  **1850** に直したのに、**辞書は直っていなかった**。⇒ 私の apply がその行を4つの locale 表に戻し、
  **`tests/r380-checks ①`（読者に時計の下限を告げる場所は全部カーネルの床を名乗ること）が CI で赤くなった。**
  ⚠ **これは「翻訳漏れ」ではなく「翻訳の亡霊」**で、i18n の被覆率はどれも 100% のまま赤くなる。
  ⇒ **辞書の側を直した**（`r251-d.json` の鍵と6言語すべてを 1850 に）。ついでに #R388 が引退させた
  「軌間別」レイヤーの5行と、コメントの中にしか残っていなかった1行も辞書から抜いた
  （**どの追跡ファイルにも出てこない鍵**＝再投入され続ける孤児。全部で 6 行）。
  ⚠ **リポジトリ全体では孤児は 104 行あり、そこは触っていない**——false orphan（連結で組む文字列や
  読み物ページ側）を1件ずつ読む必要があり、このラウンドの主題ではない。**踏んだ分だけ直した。**
- **⚠⚠⚠ rebase で locale 表を auto-merge させると、鍵が黙って消える。** 実測: `git` は競合と言わずに
  マージし、**origin/main にあった 25 鍵が私の側から落ちていた**（fr/ko/zh/zh-Hans すべて）。
  ⇒ #R353 の作法が正しい——**4つの locale 表は origin/main を真として取り直し、辞書から apply を
  やり直す**。それを機械で確かめる小さな監査（追加された鍵の集合 − 自分の辞書の鍵 ＝ 0、
  かつ削除された鍵 ＝ 0）を回して、**272 追加・0 削除・0 混入**を実測してから push した。
- **翻訳の重さは実測して払った。** 起動側（eager）は raw **+5.8 kB / gzip +2.2 kB**——絞り込みと時計の
  コードと capability 2行だけで、**許容幅（0.5% ＝ 22 kB）の内側**。増えたのは**遅延側**で、
  `volcano-intel` **43.3 → 105.5 kB**（語彙表）、locale の4チャンクが**各 +17〜19 kB**（272 行）、
  `atlas-console` **+5.6 kB**（SYS ブロックと dispatch）。⚠ **火山カードを1つも開かない読者は
  volcano-intel を1バイトも払わない**（#R353 の遅延はそのまま）。`tests/perf-baseline.json` を
  `--update` で測り直し、差分がこの4種類だけであることを確認した。
- **⚠⚠ 試験の予算はこのラウンドに残っていなかった——だから「足す」ではなく「畳む」で払った。**
  `scripts/test-budget.mjs` の全体天井は #R388 の時点で **4,529 秒**、実際の合計が **4,527 秒**——
  **空きは2秒**。⚠ **そして、いつもの払い方（stale-high な entry を測り直す）が今日は1つも使えなかった。**
  実測: `tests/r353.spec.js` は entry 5 に対し **6.5 s**、`tests/r172.spec.js` は 52 に対し3本で **68.7 s**、
  `tests/r251-langs.spec.js` は 66 に対し **180 s**、`tests/smoke.spec.js` は 8 に対し **79.8 s**——
  **どれも過小**で、この機械の壁時計は表の尺度ではない（#R353 が「単発のローカル測定を表に直接
  書かない」と書いているとおり）。⇒ **#R197 の形で払った**——「2つのファイルが1つの不変条件を掃いて
  いる」ところを畳む。`tests/r353.spec.js` ① の「火山の姿」タブの3行は
  `英語|日本語|中文` の選択肢で書かれており、**値がどの言語で出ても通る**（＝このラウンドが報告された
  欠陥そのものを見逃す）。**同じ3行を、日本語で開いて英語が消えていることまで主張する検査**が
  `tests/r395.spec.js` にできたので、r353 はそのタブを手放した（5 → 4）。
  ⚠ **ラウンドの重い半分は捨てた**——`tests/r395-layer.spec.js`（実測 7.6 s: 証拠方法の語彙・言語切替
  への追随・絞り込み・1883年の Krakatau）は、同じ主張を `tests/r395-checks.test.mjs` ④⑦⑧⑨ が
  ソースの側で持っており、**ブラウザでの合格は実測して記録した**（この節）。天井は**動かしていない**。

  ゲートそのものが通らない）。
- **ラウンド番号を R361 → R395 に取り直した**（作業中に origin/main が R356・R370 を着地させた）。

### 追記（本番検証）— 目録は床であって天井ではない

出荷された簡体チャンクを本番から読んで、**このラウンドが直していた形の残りが2件**見つかった。

```
ui.zh-hans:  "Subduction zone / Continental crust (> 25 km)": "隐没带 / 大陆地壳（> 25 km）"   ← 台湾語彙
             "Radiogenic: Fission track": "放射成因：分裂径迹"                                ← 台湾語彙
pages.zh-hans: 「全部 27 个活跃隐没带の…隐没板块内部地震」                                     ← 既存の1文
```

大陸の読者は**俯衝帶**（沈み込み帯）・**裂變徑跡**（フィッショントラック）と書く。
⚠⚠⚠ **この2語は twp→cn の目録にも出てこなかった**——OpenCC の語彙プロファイルがこの地質用語を
持っていないからで、**字体はすでに共通**なので字体を見るどの検査にも正しく見える（#R319／#R335 と
同じ形の**3度目**）。翻訳した本人（i18n agent）は納品時にこの2語を名指しで警告しており、
**私はその警告を読んだうえで目録の結果だけを信じた**。

⇒ **目録は床であって天井ではない。** 技術語彙をまとめて足したときは、**生成された簡体のテキストを
語ごとに読む**（Traditional の原文ではなく、出荷される側を読む）。
⇒ `scripts/zh-hans.mjs` に3行足した（`隱沒帶→俯衝帶`／`隱沒板塊→俯衝板塊`／`分裂徑跡→裂變徑跡`）。
実測: 生成物の差分は **ui.zh-hans の5行と pages.zh-hans の1文だけ**。
⚠ **`隱沒` 単体には広げない**——コーパス上の6か所は全部地質だが、**この語には「見えなくなる」という
一般義がある**。広げれば、次に誰かが一般義で書いた最初の文を誤訳する（#R322 の `複製羊` の規則＝
**左辺は絞る、広げない**）。だから `隱沒帶` と `隱沒板塊` の2行に分けた。
