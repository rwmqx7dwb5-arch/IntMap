## R415 — **テストが選んだポートは、このマシンの 42 チェックアウトぜんぶで同じポートだった**

依頼は 1 ファイル 1 行の報告だった——`tests/r208-checks.test.mjs` ⑩（「`scripts/serve.mjs` は
GitHub Pages と同じように `Accept-Encoding` に答える」）が `const PORT = 4188;` で server を
spawn している。

### 何が起きていたか

`CLAUDE.md` §6 は並行セッションそれぞれに専用の worktree を要求している。**実測 2026-08-24 で 42 本**
あった。⑩ の 4188 は**そのすべてで同じ 4188** なので、2 番目のセッションがここに来たときには、
自分とは何の関係もないラウンドのプロセスが 4188 を LISTENING で保持している。spawn は
`EADDRINUSE 127.0.0.1:4188` で死に、`stdout` に「static server on」は永久に来ず、**15 秒後に
`Error: serve.mjs did not come up` で赤**になる。同じ木で単独に走らせれば緑。

⚠⚠⚠ **この形の赤は、目の前の diff を告発する。** 理由が diff のどこにも書いていないのに赤で、
単独では緑なので、「別のセッションがポートを握っていた」という正しい結論に**最初の一手で辿り着く
読者はいない**。⑩ には path-traversal の半分もあり、そちらは `const SUB = 4189` で**2 本目**を
binding していた。

### なぜ「もう 1 本 derive する」では駄目なのか

`tests/helpers/session-seed.js` は #R282 追記でこの問題をすでに解いている——リンクされた worktree の
`.git` は FILE、main worktree のそれは DIRECTORY、という 1 回の `stat` からチェックアウトごとの
私有ポート（原本と CI は 4173・各 worktree は 4174–4373）を導出する。⑩ はそれより前に書かれていて、
literal を binding していた。

**しかしそこから導出しても直らない。** `npm test` はソース半分（`test:checks`）とブラウザ半分を
`scripts/test-parallel.mjs` で**同時に**走らせる。つまりこのチェックアウトから導出した番号は、
**この run 自身の Playwright dev サーバが握っている番号**である。派生を 1 つ足すのは、衝突相手を
「他人」から「自分」に変えるだけだった。

### 採ったもの — `--port 0`、そして「bind した番号」を名乗る ready 行

`--port 0` はカーネルに「bind の瞬間に空いている番号をくれ」と頼む。衝突しうる番号が存在しない。
唯一必要なのは、**呼び出し側がその番号を知る方法**である。`scripts/serve.mjs` の ready 行は
要求された `PORT` を印字していたので、port 0 では `:0/` と答えてしまう。`server.address().port` を
読むように変えた——番号を名指しする既存の呼び出し側にとっては同じ値なので、**振る舞いは 1 ミリも
動かない**。

⑩ 自身は主張を 1 文字も変えていない（compression は Pages と同じか・`data/*.json.gz` は gzip
**BODY** であって gzip **ENCODED** ではないか・served root の外へ出られないか）。変わったのは
「番号をどこから得るか」だけである。

### 門 — 報告された 1 ファイルではなく `tests/` 全体に訊く

`tests/r415-checks.test.mjs` ①。**走査対象はディスクを歩いて得る**（#R399: 手書きの「走査する
文書の一覧」が欠陥そのものだった）。各ファイルを acorn で解析し、テストが自分で選んだポートを 4 通り
落とす:

| | 形 |
|---|---|
| ① | 引数列の `--port <n>` / `--port=<n>` |
| ② | spawn する **server** の env の `PORT=<n>` |
| ③ | `.listen(<n>)` |
| ④ | loopback URL の literal port を `fetch()` などが dial している |

**免除一覧は持たない。** 固定ポートが要ると考えるラウンドは、このファイルと議論することになる。

⚠⚠ **`const PORT = 4188` … `String(PORT)` を読めない検査は、書かれた当のファイルを「清潔」と呼ぶ。**
報告された欠陥がまさにその綴りだったので、単純な `const X = <数値>` の束縛を解決してから port の
位置を読む。`` `http://127.0.0.1:${SUB}/x` `` も同じ経路で解決するので、④ は `const SUB = 4189` を
見抜く。

⚠⚠ **② は「listen する子プロセス」に限定した。** `tests/r387-checks.test.mjs` ⑥ は
`PORT: '4999'` を、`scripts/frame-profile.mjs` を import して `BASE` を印字するだけの子に渡す——
**bind もしなければ dial もしない歩哨値**で、返ってきた文字列が何かを訊いている。これを落として
免除で黙らせれば、**門は初日から免除一覧付きで届く**（腐るのはその一覧である）。限定が開ける穴は
④ が逆側から閉じている——**誰も話しかけない bind は衝突ではなく、話しかけるとは literal を dial
することだから**。

⚠⚠ **② は「綴られている」ではなく「測る」。** ready 行を要求ポートに戻す変異を当てると、
serve.mjs は `:0/` を印字し、port 0 を使う呼び出し元は全員 timeout まで固まって
`«serve.mjs did not come up»` で死ぬ——**#R415 が消しに来たその文そのもの**。だから ② は本物の
server を起動し、stdout から番号を取り、その番号にファイルを要求する。

### 実測

| | 結果 |
|---|---|
| 旧版・4188 を占有 | **赤**（`Error: serve.mjs did not come up`） |
| 新版・4188 **と** 4189 を占有 | 緑 |
| 新版・同じ木で 2 本同時実行 | 両方緑（exit 0 / exit 0） |
| `tests/r208-checks.test.mjs` 全体 | 26 pass / 0 fail（⑩ は 293 ms） |
| 門の変異 | **7 通りで赤**（`String(PORT)`・`--port=4188`・`.listen(4188)`・literal fetch・`${SUB}` テンプレート・server の env `PORT`・`localhost:` 綴り）、**4 通りの対照で緑**（`--port 0`・導出値・fixture 文字列・listen しない子の env） |
| ready 行の退行 | ② が赤（「the ready line named 0」）。同じ変異で ⑩ は `fetch failed` としか言わない＝**②は不可解な失敗を名前のある失敗に変える** |

`tests/` の他のファイルに固定ポートを binding しているものは無かった（`tests/r257`・`tests/r286`・
`tests/r277`・`tests/r387` の `127.0.0.1:4173` などはすべて**他のファイルの中身を照合する fixture
文字列**で、dial していない。門の ④ が call を見るのはそのためである）。
