## R469 — **レイヤー欄の「基本表示」は 11 個のスイッチではなく 3 択になった**（そして各カテゴリは名指しの行だけを見せる）

> 「基本表示の『タイムゾーン（現在時刻）』レイヤーは、基本表示ではなく普通のレイヤーにして。もとは
> 基本表示があった場所をデフォルト/クリーン/カスタムとして、カスタムを選択すれば今の基本表示の一覧が
> 出てくるように。…複数選択ではないです。どれか一つ。どれかをオンにしたら、それまでのやつが勝手に
> トグルがオフになる形式に。」／「以下に指定されたレイヤー以外は、『その他N件』と、各カテゴリの中で
> 畳むようにして。また、提示した順番はカテゴリ内での新たな並び順に対応します。」／「ツールも、レイヤー
> カテゴリと同様に畳めるように。また、レイヤー検索欄が、ツールにも効くように。」／「フロストガラス時に、
> 『表示中のレイヤー』の背景の色が濃すぎ。」

着手前に読者へ確認したのは4点（`AskUserQuestion`）——タイムゾーンの行き先＝**政治・統治の「その他」**、
ベータには畳みを**適用しない**、宇宙／海洋の改名は**全9言語**、国境・国情報は**行だけ隠す**。

### ⚠⚠⚠ モードは状態についての主張なので、状態より長生きしてはならない

「デフォルト／クリーン／カスタム」を3つの真偽値で持つと、**排他を保つコードが3か所**要る。
正本を `window.IntMapBaseDisplay` の**値ひとつ**にしたので、排他は書かなくても成り立つ
（「どれかをオンにしたら、それまでのやつが勝手にオフ」は、値が1つであることの帰結）。

問題はその先だった。**基本表示を動かせるのは、この3行だけではない**——Atlas の `layers` 操作、
風レイヤーを点けたときの海岸線の1回きりの提案（#R289）、セッション復元。どれかが動いた瞬間、
「デフォルト」と書かれた見出しの下はもうデフォルトではない。→ `reconcile()` が**モードを
「カスタム」へ降格させる**（そして 11 行の一覧が出る＝読者は何が違うのかを見られる）。

⚠ **その判定は落ち着いた状態に対して行う（400 ms のデバウンス）。** 復元は change イベントの**列**で
あって、その途中の状態は読者が選んだ状態ではない。デバウンス無しで書いた最初の版は、**毎回の
読み込みが半分適用されたセッションを見て「カスタム」と判定していた**。

⚠ **既定の集合は導出する。** 9 個の `cb-*` は `window.IntMapDefaultOn`、残る 2 行はそこに無いので
`IntMapBaseDisplay` が明示する。#R309 は「基本表示に何が入っているか」の**手書きの写し4本**を1本に
まとめたラウンドで、その**既定値**の写しを作るのは、同じ欠陥の1つ隣の欄。
実測（本番と同じ build・9言語）: デフォルトを押すと `cb-names / cb-geolabels / cb-poi / cb-borders /
cb-admin1 / cb-roads / cb-rail2 / dl-nightside` の **8 行**だけが点く。クリーンは **0**。

### ⚠⚠ 行を隠すことと、レイヤーを消すことは別

読者は「国境・国情報レイヤーは完全削除して」と書き、確認の結果**「レイヤー行だけ隠す」**を選んだ。
そこで `window.IntMapHiddenLayerRows`（`cb-countries` と `dl-contours`）——**チェックボックスは
`#layer-dropdown` に残る**ので、レイヤー本体・ハンドラ・凡例・不透明度・セッションの保存/復元・
Atlas の `countryInfo`・Countries ウィンドウの連動（`_wsCountryInfo`）は**1バイトも変えていない**。

⚠ **行を配る掃き出しには全部教えること。** `order.push` は要素を**移動**させるので、誰も引き取らない
行はベータに落ちる——#R271 で 🕒 タイムゾーンが実際にそこへ出たのと同じ経路。
`reorganizeLayerPanel` はこれらを `placed` に入れ、`rowsFromDropdown()` はタイルを作らない。
⚠ **`cb-countries` は「数えない」側からは外した。** 行が無くなった今、**「表示中のレイヤー」のチップが
唯一の消し方**である。行もチップも無いレイヤーは、点いたら消せないレイヤー。

### ⚠⚠ 名指しの件数は、並び順と同じ場所に置く

`GROUPS` の各要素が `[キー, id の配列, 名指しされた件数]` の3つ組になった。配列は**読者が挙げた順**で、
先頭の件数本だけが並び、残りは**カテゴリの中の「その他N件」**の後ろに畳まれる
（実測 **18 の棚・140 行・名指し 56 / 畳み 84**）。どのレイヤーを最初に見せるかは読者が決めたことで、
順序と不可分だから同じ行に書く。描画側（`js/map-ui.js`）はこの配列を読まない——
`reorganizeLayerPanel` が畳む行に `data-lyr-rest="1"` を書き、`rowsFromDropdown()` がそれを運ぶ。

⚠ **ベータには適用しない**（読者のカテゴリ一覧にベータは無い。適用すると全行が1行の後ろに隠れる）。
掃き出しは印を**明示的に消す**——この関数は冪等で、棚から出た行が古い印を持ち込みうる。

### ⚠⚠ 等高線は「廃止」ではなく「引っ越し」だった

「等高線レイヤーは廃止し、標高（カラー段彩）、陰影起伏（標高）、カラー段彩・陰影（ASTER）の凡例内で
トグルでオンオフできるように統合。」→ **状態は今までどおり `dl-contours` のチェックボックス**で、
凡例のトグルは**それを押すだけ**。だからトグル経路も不透明度も自己修復監査もセッションも Atlas の
入口も書き換えていない。**組み立ては1本**（`ensureContourSwitch`）で 3 枚の凡例に配る——markup を
3 か所に写すのは、1 枚だけ直る欠陥の作り方（[[intmap-r463-lessons]]）。細かさスライダはトグルの直下に
移り、オフの間は隠れる。

⚠ **統合が開ける罠を先に塞いだ**——3 つの持ち場が全部オフになると、線は地図に残り、スイッチのある
凡例は 1 枚も無い。`_contourHostOn()` が最後の1枚と一緒に等高線を消す。実測: 1 枚オフでは残り、
2 枚目のオフで消える。

⚠ **「⛰ 傾斜・斜面方向」は本当に消した**（読者の「完全削除」）——`js/sims.js` のモジュール、`dl-slope`、
`imslope-fill`、`src/main.js` の `MODULE_FACTORIES`、Atlas の dispatch・能力表・スキーマ・カタログ本文、
4 言語の 8 鍵。実測（本番と同じ build）: `IntMapCapabilities.all()` は 126 件で `sim.slopeAspect` を
含まず、`resolve('slope')` は `null`、対照の `sim.rfCoverage` は `true`。`dist/` 全体に綴りゼロ。

### ⚠⚠ 畳めるようにしたら、検索は畳みを飛び越えなければならない

「ツール」節の見出しは、chevron もクリックリスナーも件数も無い `.lst-sech` で、`:hover` だけが
当たっていた——**押せそうに見えて何も起きない見出し**。カテゴリと同じ形にした（`.lst-toolbody`）。

そして同じ文の後半「レイヤー検索欄が、ツールにも効くように」。#R291 の実装は**動いていた**（実測:
`route` で 0 タイル / 1 ツール）。効かなくなるのは**畳めるようにした後**で、行は正しく絞られたまま
読者に見えない body の中にいる＝「検索が効かない」と読める。→ `filterTiles` は問い合わせがある間、
`.lst-toolbody` を inline の `display` で開ける。**同じ規則がカテゴリの「その他N件」と基本表示の
11 行にも効く**——実測: `roads` は（デフォルトのとき隠れている）基本表示の行を出し、`dew` は畳まれた
「その他」の行を出し、`route` はツールを出す。**問い合わせは畳みより強い。**

⚠ **表示/非表示を CSS と inline の2系統で決めない。** `filterTiles` は全タイルに inline の `display` を
書くので、モードや畳みを CSS 側で決めると**検索の強制展開と同じプロパティを奪い合う**。決めるのは1か所。

### ⚠⚠ 「行数が変わったら建て直す」門が、静かに死ぬところだった

3 択の行も `.lst-tile` である。素朴に数えると `have` は永久に `want + 3` になり、**パネルは正しいまま、
開くたびに全部組み直される**——#R72 が「layersをクリックしたときの反応が非常に遅い」に対して書いた
安い経路が、見た目には何も壊さずに死ぬ。門は `.lst-tile[data-lid]` を数える（4 か所）。
同じ理由で **11 行は「カスタム」でないときも組み立てて、隠すのは `filterTiles`** ——モードごとに
タイルの数が変わると、その門が毎回建て直しになる。

### ⚠ フロストガラスの「表示中のレイヤー」は、パネルで唯一マップを透かさない帯だった

実測（フロスト・ダーク・同じ瞬間）: 帯は **`rgb(28,28,30)` ＝完全不透明**、その下のパネルは
**`rgba(28,28,30,0.85)` ＋ 25px blur**。原因は `--panel-bg` が
`body:not(.sidebar-translucent):not(.sidebar-glass2)` の下でしか宣言されていないこと——2 つのフロスト
表示では `var(--panel-bg,var(--card-bg))` の**フォールバックが発火していた**。

→ **「もっと透明に」ではなく「パネルと同じ材質」**。`--sidebar-bg`（`#layer-sidebar-r` 自身が塗られて
いるトークン）を使い、**帯は自分の `backdrop-filter` を保つ**——#R115 の本当の要求は「透過するな」では
なく「下を流れる行が透けて読めるな」で、それを守るのは塗りではなく blur のほう。
携帯のシートも同じ欠陥・同じ理由で、そちらは `.m-sheet` 自身の `--glass-fill` を取る。
実測: フロスト時 帯 `rgba(28,28,30,0.85)` ＋ blur ＝**パネルと一致**、Solid は
帯 `rgb(20,20,22)` ＝パネルと一致（#R252 のまま・#R115 のまま）。
