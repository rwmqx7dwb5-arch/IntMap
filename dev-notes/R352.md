## R352 — **本番検証が見つけた3件は、どれも「答えたように見えて別のものを答えていた」**

依頼は #R341（航空レイヤーの全面再設計）の**本番検証で残った不一致を潰すこと**。
#R341 は自分の主張については全部緑で、そのうえで**自分のコードの3か所**が、
呼び出し側から見て「答えた」ように見えながら別のものを返していた。

### ⚠⚠⚠ カードは10枚中10枚が、1機も供給していない provider を出典として印字していた

`js/aircraft-detail.js` の `.acp-src` は `'airplanes.live · ADS-B'` という**文字列リテラル**だった。
#R341 はライブ経路を **adsb.lol** へ移し、ホバーのツールチップにはそう言わせた——`_planeSourceLine()` を
書き、`x-intmap-attribution` ヘッダから名前を運ぶところまで作った。**カードの1行だけが取り残された。**

これは装飾ではない。**adsb.lol のデータは ODbL 1.0 で、出典表記は義務**である。
そして #R341 自身がその義務のために `Access-Control-Expose-Headers` を直している。
**間違った出典を名乗るのは、名乗らないより悪い**——義務を果たしていないうえに、
それを無関係な第三者に押し付けている。

```
本番のカード10枚:  .acp-src = "airplanes.live · ADS-B"   10 / 10
そのとき描かれていた機体の供給元:  adsb.lol                 10 / 10
```

⇒ カードは**渡された行を印字する**（`p._srcLine || リテラル`）。
リテラルは消していない——`?aviation=v1` の巻き戻し経路の record は `_srcLine` を持たず、
**その経路は本当に airplanes.live を使っていた**。リテラルを消すのは、同じ licence 問題を
逆向きに作ることになる。⚠ **だから検査は「リテラルが在るか」ではなく「リテラルが
`_srcLine||` の右側に在るか」を見る**（`tests/r352-checks ①`）。

### ⚠⚠⚠ `snapshotFor()` は幾何だけを返し、呼び出し側にはそれが分からなかった

ストアは全機の ICAO アドレスを持っている（`ST.ids[i]`）。公開スナップショットは
`lon / lat / altFt / trackDeg` の4つだけを返していた。本番検証は「いま何が写っているのか」を
この API に訊き、**識別子が1つも返らないので、画面の格子に `pick()` を撃って回る**という
迂回をした。

⚠ **「答えなかった」なら気づく。「別のものを答えた」は気づかない。**
⇒ `hex: hexOf(ST.ids[i])` を足した。

### ⚠⚠⚠ 1つのヘッダが2つの意味を運んでいた——だからどちらの意味でも読めなかった

`x-intmap-age-ms` は、

- `world` チャンネルでは **スナップショットを組み立ててからの経過**、
- `view` チャンネルでは **箱の中で最も古い機体の観測齢**

を返していた。本番実測:

```
world  x-intmap-age-ms   12.7 – 13.5 s      ← スナップショットの齢
view   x-intmap-age-ms  531   – 564   s      ← 箱の中で最も古い機体の齢
```

同じフィールドに交互に入る。**この値から「データの古さ」は読めない**——
新しい答えの中に古い観測が入っている状態と、答えそのものが古い状態が、区別できない。
指示書 §22.2 は「取得元の観測時刻・IntMap が受け取った時刻・クライアントが描画した時刻」を
区別できることを要求していて、**このフィールドはその区別をちょうど消していた**。

⇒ **2つの事実には2つのヘッダ。** `x-intmap-age-ms` は常に「**答えの齢**」、
`x-intmap-oldest-ms` は「**その中で最も古い観測の齢**」。
worker は両方を別のフィールドに読み、`stats()` は `serverAgeMs` と `oldestObservationMs` を別々に出す。

⚠ **これは1行の綴りではなく「形」なので、綴りを禁止しても戻ってくる。**
チャンネルを1つ足せば、手元にあるほうの齢を渡すことで簡単に再発する。
⇒ `tests/r352-checks ⑤` は**古い綴りを探さない**。`binResponse()` の呼び出しを
**括弧を数えて全部列挙し**、`ageMs` と `oldestMs` の**両方を名乗らない呼び出しがあれば落ちる**。
**片方しか書かないチャンネルは書けない。**

⚠ **齢の計算を毎リクエストの走査にしない。** world は**同じバイト列を全員に配る**ので、
最大 5 万件を毎回歩いても何も買わない。`noteOldest()` が**集合が変わる3か所**（構築・hydrate・
期限切れ）で最古の `seenAt` を記録し、リクエスト時は引き算1回（`tests/r352-checks ⑥` が
world の応答経路に `STATE.world.values()` の走査が戻っていないことを見る）。

### 検査は9本＋ブラウザ2本、**全部を壊して赤を見てから緑にした**

| 壊したもの | 赤くなった検査 |
|---|---|
| カードをリテラルへ戻す | ① |
| `_av2Plane` から `_srcLine` を外す | ② |
| `snapshotFor` から `hex` を外す | ③ |
| `Access-Control-Expose-Headers` から新ヘッダを外す | ④ |
| `ageMs: oldest` へ戻す | ⑤ |
| world の応答経路に全件走査を戻す | ⑥ |
| worker が新ヘッダを読むのをやめる | ⑦ |
| `x-intmap-oldest-ms` に `meta.ageMs` を入れる | ⑨ |
| `x-intmap-age-ms` に `meta.oldestMs` を入れる | ⑨ |

⚠ **⑨ は綴りではなく値を見る。** Edge Function の `hdr()` と `binResponse()` を**そのまま取り出して
実行し**、`ageMs:350 / oldestMs:540000` を渡して2つのヘッダが**別々の数**で出ることを確かめる。
#R341 の誤診はまさに**ヘッダの値**（em ダッシュ1文字）が原因で、
**関数を読む検査は、到達されない関数にも満足する**（#R317・#R318）。

⚠ **ブラウザ側 `tests/r352.spec.js` は DOM の文字列を読む。** 出典表記の義務は
「式が `_srcLine` を読んでいること」ではなく「**読者が見る文字列**」で果たされる。
`IntMapAircraftPanel.open()` を実際に呼び、`.acp-src` の `textContent` を読む。
**フィードは要らない**——record はこのファイルが供給する。だから
`?aviation=v1` のフォールバック分岐（**ライブのフィードでは決して通らない**）も検査できる。

### 変えていないもの

**製品の挙動で変わったのはカードの1行だけ。** ヘッダは1本増えたが、
`x-intmap-age-ms` は world では**以前と同じ値**を返す（view だけが「答えの齢」に変わる）。
`genSyntheticPlanes()`・旧経路・レンダラ・ワイヤ形式は1バイトも触っていない。
