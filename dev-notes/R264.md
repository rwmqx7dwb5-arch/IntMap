## R264 — **精細化の発火条件が梯子の1段目とちょうど同じだったので、その段だけ一度も直っていなかった／集計は浮く必要が無かった／ツールのカードは状態を持てる**

> 「データセンター、AIインフラレイヤーにポップアップ二つあるのを辞めろ。／地形編集・水流でたまに、直線で地形を完全無視するクソ区間がある。再生ボタンは四角にしろ。／レイヤー欄のToolsのカードは、タイルカードと同様に選択中はハイライトし、カード間の間隔が今ないから少し開けること。もう一度タイルを押したら選択解除されるように。／過去・最近の地震から選んだ場合、Place the hypocenterピルは表示しないように。」

⚠ **「再生ボタンは四角にしろ」は訊いたら取り下げられた。** 本番の `main-*.js` はローカルビルドと同一ハッシュで、`.tw-play` は **38×38 px・角丸 11 px**、`.sq-play` は **32×32 px・角丸 9 px**——どちらも円ではない（#R261 の変更は本番に載っている）。測った数字を添えて「どちらの意味か」を訊いた結果が「すでに解決済みでした」。**1バイトも触っていない。** [[intmap-r252-lessons]] と同じ形——**再現して数字を出してから訊く**と、訊くこと自体が答えになる。

### ① 「直線で地形を完全無視する区間」——精細化の発火条件が、梯子の1段目とちょうど同じだった

同じ文が**4回目**。#R258 は湖の横断を、#R261 は粗い段の脚を細かい格子で歩き直す `refineCrossing()` を作った。どちらも本物で、どちらも生きている。壊れていたのは**数字1つ**。

粗い段の梯子は `[3, 9, 27]`。**最初の倍率は 3** なので、その段の1セルはちょうど `3 × 細かい標本間隔`。そして発火条件は

```js
if(!(L > REFINE_MIN_CELLS /* 3 */ * spacingM)) return null;
```

——**厳密な大なり**に、**等しい長さ**を渡していた。**×3 の段の脚は構成上ぜんぶ落ちる。** 一番よく使われる段が、精細化を一度も通っていなかった。

実測（本番ビルド・実 DEM・`_dbgTrace().legs.worst`）:

| 起点 | 最細標本 | 最長の脚 | 自分の段では | **最細標本では** | `coarseLegs` |
|---|---|---|---|---|---|
| 琵琶湖 | 23 m | **280 m** | 1.0 セル | **12 セル** | **0** |
| デスバレー | 23 m | **277 m** | 1.0 セル | **12 セル** | **0** |
| パンノニア平原 | 20 m | 163 m | 2.0 セル | 8.4 セル | **0** |
| 西シベリア | 14 m | 112 m | 1.9 セル | 7.8 セル | **0** |

⚠⚠ **そして `coarseLegs` は4本とも 0 だった。** 数え方が

```js
if(gcM(pv, step.at) > REFINE_MIN_CELLS * spacing) coarseLegs++;
```

——**精細化が諦める閾値と同じ定数**。「精細化が取らなかった脚」を「精細化の閾値を超えた脚」で数えていたので、**取らなかった脚を報告できるはずがなかった**。計器が、見張っている当のコードによって定義されていた（[[intmap-recurring-lessons]] の「自分の検査が自分を捕まえられない」）。

**直し: 2つの問いには2つの定数。**

- `REFINE_MIN_CELLS = 1.5` — **これは弦か？** 細かい格子の1歩は1標本間隔、斜めで √2。それを超えたら見ていない地面を横切っている。×3 も ×9 も ×27 も、これで全部歩き直される。
- `COARSE_REPORT_CELLS = 3` — **目に見える継ぎ目か？** 判定はトレースの**最細標本**に対して（#R250「見るべきは比」）。**精細化の都合とは独立**なので、諦めた脚を報告できる。

⚠ **最初の版は4本のうち2本を悪化させた。捕まえたのは実測。** `nodata` は**地面の事実ではなくキャッシュの事実**だった——精細化の窓が増えると `js/map-readout.js` の `_demCacheTrim`（LRU）が**後から来る広い窓のタイルを先に追い出す**。実測: パンノニア／西シベリアで decline 0 → **5件ずつ**、最長脚が **163 → 3,114 m**・**112 → 753 m**。×3 の段を直して ×27／×9 の段を壊していた。
→ `floodWindow` が null を返したら、**その窓自身の footprint（5×5 格子）を温めて1回だけ再試行**する（`refineCrossing` は async になった）。`warmCrossing` はチェーン全体を最大40標本で温めるので、その真ん中の 8 km の窓は覆われない。**それでも駄目なら本物の欠落**として数えて印字する（#R185）。

実測（修正後・6本）:

| 起点 | 最長の脚 | **最細標本では** | `coarseLegs` | decline |
|---|---|---|---|---|
| 琵琶湖 | 280 → **176 m** | 12 → **7.5** | 0 | 0 |
| デスバレー | 277 → **182 m** | 12 → **7.9** | 0 | 0 |
| パンノニア平原 | 163 m | 8.4 | 0 | 0 |
| 西シベリア | 112 m | 7.8 | 0 | 0 |
| アルプス | 157 m | 8.0 | 0 | 0 |
| アマゾン | 225 m | 8.0 | 0 | 0 |

⚠ **報告された症状そのものを測る計器を足した**（`_dbgTrace().straight`）。3ラウンド「脚の長さ」を測ってきたが、報告は**脚**ではなく**区間**——方位が 3° 以内で続く脚の**連なり**の話をしている。そして**その区間の起伏 `reliefM` も返す**：平らな湖面では最小上昇経路は**定義上まっすぐ**（どの向きも同じコストなら最短が勝つ）ので、起伏の無い直線は欠陥ではなく水面である。実測の最長直線区間は琵琶湖 4,618 m（198脚）で **起伏 0.0 m・落差 0.0 m**＝湖面、パンノニア 14,419 m で **起伏 5.4 m**＝氾濫原、西シベリア 2,267 m で起伏 14.7 m。**どれも1点1点が実 DEM の読み値**で、#R263 の 280 m の弦とは別物。

### ② データセンター層のポップアップが2つあった

#R261 は「今画面に何があるか」を答えるパネルを作った。中身は正しい（推定を1つもしない・公表容量は必ず「N件／全M件」）。**間違っていたのは、それを浮遊ウィンドウ（`.tool-panel`）にしたこと。** この層は点をクリックすると**詳細カード**も浮くので、レイヤーが用意した唯一の操作をした利用者の画面に**2つ重なる**。

2つは**種類の違う答え**で、浮くべきなのは片方だけ:

- 「**この点は何か**」は指で触れた点についての答え → その点の横に置く意味がある → 浮遊カードのまま
- 「**表示範囲に何があるか**」は**レイヤーについての答え** → レイヤーの操作が並ぶ場所へ → `_registerLayerOpacity('dc2',…)` が作る凡例（色キーと分類スイッチが**既に居る箱**）の中（`.dc-sum`）

⚠ **何も落としていない。** 件数・「N件／全M件」の分母・分類別内訳（そのままフィルタ）・容量順の上位（クリックで飛ぶ）は**同じ markup・同じ handler**で、宿主が変わっただけ。宿主は**消費側（`js/layer-packs.js`）が渡す**（`mountSummary(el)`）——行を作るのは消費側なので、モジュール側でセレクタを推測しない（[[intmap-r253-lessons]]「一覧は必ず1つ忘れる」）。⚠ 言語切替やパネル再編で行は作り直されるので **ON のたびに mount し直す**。

実測: レイヤーON で浮くのは `#data-legend-dc2` の**1つだけ**（`#dc-panel` は存在しない）、点クリックで `#dc-detail` が加わる。凡例内の分類フィルタは実測で効く（`ai` を切って戻す）、上位一覧は 25件中**公表2件・3.20 GW** を分母つきで出す。

### ③ Tools のカードがタイルカードと同じ振る舞いになった

実測（修正前）: 可視の4行の間隔は **0, 0, 0 px**（隣のタイル格子は `gap:8px`）で、`.lst-toolrow.on` という規則は**存在せず**、どこからも付けていなかった。

- 間隔は**タイル格子と同じ 8px**（`.lst-tools` を `display:flex` の縦並びに。節見出しは自分の下マージンを gap に譲る）
- `.lst-toolrow.on` は **`.lst-tile.on` と一字一句同じ宣言**（アクセント枠＋1px リング）。⚠ `#id .cls:hover` と `#id .cls.on` は**詳細度が同じ**なので、`.lst-tile.on` と同様に **`:hover` の後**に書く（そうしないと押している間だけ枠が消える）
- **開いているツールの行が光り、もう一度押すと閉じる**

⚠ **タイルはチェックボックスを持つが、ツールカードは何も持たない。** 状態はシミュレータの中にあるので**モジュールに訊く**——各行に `mod:'IntMapX'` を**1つ**書き（`run` の隣、忘れようがない場所）、`_toolOn()` が `isOpen()`（無ければ `state().open`）を、`_toolOff()` が `close()` を呼ぶ。**キャッシュしない**ので、✕ や Atlas や別の経路で閉じられた窓とも食い違わない。再同期は `pointerup`（ツール欄が実在するときだけ）——タイマーも observer も第二の状態も持たない。

⚠ **そのために `close()`／`isOpen()` を持っていなかった7モジュールに追加した**（`js/sims.js` の 電波到達範囲・公共交通の到達圏・浸水/津波ハザード・地球リプレイ・放射性プルーム、`js/viewshed.js` の見通し線、`js/map-tools.js` の到達圏）。パネルを持たない2つ（プルーム・公共交通）は**自分が描いたもの**を答える＝地図と食い違いようがない。既存のヘッダの ✕ は**同じ `close()` を呼ぶよう付け替えた**（出口を2つにしない）。

実測: 13行のうち **12行が「押す→光る→もう一度押す→消える」**（公共交通は鉄道のある場所で確認——東京で 1,364 駅、行は点灯）。

⚠⚠ **残る1行 `sim.radiation` は #R258 以来ずっと死んでいる。** `IntMapRadiation.openPanel()` を呼ぶが、そのモジュールに `openPanel` は**一度も存在しない**（実測 `OS.exec('sim.radiation')` → **false**、`typeof openPanel` → `undefined`）。このモジュールにはパネルが無く、Atlas からの `run(site, opts)` しか入口が無いので、**パネルを新設するのは今回の依頼の範囲外**。既定の同位体や放出量を勝手に決めるのは標準指示に反する。**直さずに報告する**——`isOpen`／`close` は本物（Atlas がプルームを描いていれば光り、押せば消える）。

### ③ 追記 —— 遅延チャンクのツールは、行が光る前にパネルが開いていた（**捕まえたのは本番検証**）

13個のうち**8個は遅延チャンク**で、`OS.exec` を押してから実際に開くまで**秒**かかる。押した直後の同期と
`setTimeout(syncTools,340)` はどちらもその前に走り終わるので、**パネルは開いているのに行は光らない**——
実測（本番 R264・`sim.seismic`）: `state().open` **true**・`#sq-panel` は `display:flex`・行は **`on` なし**。
次に**ページのどこかでポインタを離した瞬間**に光った（`pointerup` の再同期が拾った）。

**時間を当てにするな。開いたことを教えてくれるものに繋げ。** `OS.exec` は**コマンドが返したものをそのまま返す**
（`js/app-body.js`）ので、遅延ツールでは**到着の Promise** そのもの。そこに `syncTools` を繋いだ。
実測（修正後・ポインタ操作を一切挟まず）: 押してから **500 ms 後には点灯**し、7 秒後まで点灯したまま。

⚠ この欠陥は**ローカル検証では見えなかった**——プログラムから `.click()` すると `pointerup` が飛ばないので
「押した後しばらくして光る」形にならず、本番でも同じ理由で**最初は行が消えたまま**に見えた。
[[intmap-r252-lessons]]「状態を持つUIは両方の状態で測れ」の時間版＝**遅い経路でも測れ**。

### ④ 過去・最近の地震から選んだのに、ピルが「震央を置く」と言い続けていた

#R240 の規則は正しい——「震央がまだ無いときは、やることが1つしか無く、それは地図の上でやることなので、タップを live にして HUD がそう言う」。見落としていたのは、**「震央を置く」にはもう1つのやり方がある**こと: カタログ／USGS フィードから**読み込む**。`applyEvent()` も `applyReal()` も `epi` を設定するのに**武装を解除しなかった**ので、

- 地図の上のピル `#sq-hud` は、**公表された震源を持つ地震**に対して「② 震央を置く」と言い続け、
- 次に地図をタップすると、その震央が**黙って動いた**。

解除は**ローダの中**で行う。HUD は `clickMode` の**読み出し**であって（#R239）、そこに第二の判断を持たせるのは、この HUD が避けるために作られた欠陥そのもの。`clearEvent()` は従来どおり再武装する（#R242「読み込みの逆が読み込み解除」）。
⚠ `applyReal` は `render()` を呼ばない——既存ノードを書き換え `.sq-out` を掴んだままなので呼べない——ので、`close()` と同じく `_hud()` を直接叩く。

実測: **過去の地震10件**／**最近の地震142件**の両経路で、選択前 `clickMode='epi'`・ピル **on** → 選択後 `clickMode='none'`・`epi` あり・ピル **off** → 選択解除で `clickMode='epi'`・ピル **on**。

### 検査

`tests/r264-checks.test.mjs`（7件）。①発火条件は**梯子の最小倍率より下**（定数ではなく**関係**を検査し、`refineCrossing` の呼び出し位置から梯子を特定する——このファイルには `pitEscape()` の無関係な `mult` ループがもう1つある） ②`coarseLegs` は**最細標本**に対して数え、`straight` を印字する ③集計は自分の窓を持たず、消費側が渡した宿主に mount する（分母・分類行・上位一覧は残っている） ④ツール行の間隔＝タイル格子の間隔、`.on` は `.lst-tile.on` と**同一宣言**かつ `:hover` の**後** ⑤全行が `mod` を持ち、全モジュールが「開いているか」を答え「閉じる」を持つ ⑥両ローダが武装を解除し、`clearEvent` は戻す。HUD は `clickMode` だけを読む ⑦ビルド印2つが最新ラウンドを指す。
