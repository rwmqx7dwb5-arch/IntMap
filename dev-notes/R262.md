## R262 — **取得の失敗が「ここには何も無い」としてキャッシュされていた**

> #R261 の**本番検証**で見つけた。テストでは見つからなかった——キャッシュが冷えている必要があったから。

**実測（production, R261, 東京 z11, 緊急対応拠点レイヤー）**

| 測ったもの | 値 |
|---|---|
| レイヤーを ON にして 45 秒後のソース件数 | **0** |
| `refresh()` の所要 | ミリ秒（例外なし） |
| 同じページから同じ Overpass クエリを直接 | **1,200 件 / 6.7 秒** |

`overpass()` は**全ミラーが失敗したとき `null`** を返す。`refresh()` はその `null` から

```js
const els = await overpass(ql);
feats = [];
(els||[]).forEach(…);          // null → 何も入らない
cache.set(ck, feats);          // ← 「このビューは空」として保存される
```

を作っていた。`lastKey` は await の**前**に立っているので、以後そのビューでは `cache.get(ck)` が
短絡して**二度と要求が飛ばない**。再トグルしても `lastKey` は残る。**1度の遅延が、そのセッションの
間ずっと「ここには何も無い」になる。**

⚠ **欠陥は #R255 が書いた共通エンジンにあり、施設レイヤー12種すべてに効いていた。**
#R261 が6つ足して**冷えたキャッシュで測った**から見えただけで、新しいコードのバグではない。

**直し**: Overpass が**実際に答えたときだけ**キャッシュする。失敗したら `lastKey` を空にして
次の `moveend`（または再トグル）で再試行し、`busy` も解く。凡例は「0件」と「応答が無い」を
**別の文**で出す（オレンジ）。`fetchState` は `state()` から読めるので、検証は凡例の文面を
parse しなくてよい。

**教訓: 「空の答え」と「答えが無い」を同じ値にするな。**
`catch` を静かにするな、という #R254 の教訓の兄弟——こちらは例外すら出ない。

検査: `tests/r262-checks.test.mjs`（3件）。①null ガードが **cache.set より前**にあること
②2つの文が画面と API で区別できること ③ビルド印。
