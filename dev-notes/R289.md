## R289 — **十の指示、ほとんどが「一つの事実に持ち主を一人」に落ちた／2,300 セル中 2 つがこちらの間違いだった／ラウンド番号は3度目の取られ方をした**

> 「風レイヤーのホバー地点の数値は座標標高常時表示欄に表示されると思いますが、風向きも、矢印を動的に動くように
> 表示してください。また、日本語設定でも座標標高常時表示欄にNEと表示されますが、ちゃんと北東と書くように。
> （ほかの言語でも。それが自然な表記ならば。）…（十項目）」

十件が一度に届いた回。実装として見ると**ほとんどが同じ形**だった——**同じ事実がいくつもの場所に書かれていて、
報告されたのはそのうちの一つ**。以下、指示の順に。

### ① 「NE」は1か所ではなく6か所に書かれていた

「日本語設定でも座標標高常時表示欄にNEと表示されます」。報告は常時表示欄の風チップについてだが、
**16方位の英略号を私有の配列として持っている場所を数えたら6つあった**:

```
js/map-readout.js  常時表示欄の風チップ        ← 報告された場所
js/weather.js      天気ポップアップの風の行
js/app-body.js     compassDir()（航空機の機首方位）
js/night-sky.js    星空パネルの視線方位
js/sims.js         太陽位置パネルの方位角
js/street-view.js  ストリートビューの向き
```

報告された1か所だけ直すと、**残り5か所は日本語で「NE」と言い続ける**。同じ欠陥の、爆風半径だけ小さい版。
→ `js/compass.js` が唯一の表になり、6か所すべてがそこから読む。

⚠ **`L('N','北',…)` では書けない。** 6言語目以降は `inline` 表を**英語文字列をキーに**引く（`js/lang-registry.js`）。
ここでの英語は `'N'` `'E'` `'S'` `'W'` `'NE'` ——**このアプリが作りうる最も衝突しやすい鍵**で、#R277 が
`LA('Hail', …)` が「حائل（サウジの都市ハーイル）」に化けた形でちょうど1ラウンド払っている。方位名は
翻訳者に推測させる UI 文字列でもなく、**言語ごとに固定された慣習**なので、9つの表を全部書き出した。

⚠ **表記は言語で違い、CJK を1つに束ねると片方が必ず嘘になる。**
独は `O`（Ost）で `NO`、仏西は `O`（Ouest / Oeste）で `SO`、露はキリル略号 `С В Ю З`。
そして**日本語は「北東」（北が先）・中国語は「東北」（東が先）**——「北東」は中国語ではない。

### ② 風向きの矢印は「動的に」——位相を持ち越す

⚠⚠ **常時表示欄は `innerHTML` でマウス移動のたびに作り直される。** 素直に CSS キーフレームを載せると、
新しいノードは**毎秒60回 t=0 から撒き直され**、「指を動かしている間だけ止まって見える矢印」になる
——**動的でありたい機能が、触っている間だけ静止する**。
→ **負の `animation-delay`** を共有時計（`performance.now()`）から与える。作り直されても位相が続く。

矢印は**風下**を向く。`dir` は気象の「どこから」（`js/weather.js` の `atan2(-u,-v)`）なので +180 で、
すぐ隣で流れている粒子と**同じ向き**になる。隣の絵と食い違う矢印は、無いより悪い。
速さは風速から（`1.5/(0.35+v·0.09)` 秒、0.34–3 秒でクランプ）。`prefers-reduced-motion` では止まる。

### ③ 海岸線を「国境線と全く同じ手法で」

「全く同じ手法で」を字義どおりに取ると、これは新しいデータセットではなく**短いファイル1本**になる:
同じ `ofm` ベクタソース・同じ `BORDER_COLOR`・同じ `BORDER_WIDTH`／`BORDER_CASING` の梯子・同じ
「黒縁を線の下に」の対・同じ `before` アンカー・同じ再試行の梯子。**違うのは `source-layer` だけ**
（`boundary` → `water`）。海のポリゴンの輪＝海岸線、湖のポリゴンの輪＝湖岸線——**1つの幾何**なので
「海岸線とは言いましたが湖沼との境界線もこれに含みます」に1レイヤーで答えられる。

⚠⚠ **タイルの継ぎ目は出ない。これは期待ではなく測定である。** ポリゴン層を線で描くと普通は
タイルのクリップ辺が海の上に格子として出る。実タイル（z4 大西洋・z5 と z8 東京・z8 琵琶湖）を復号すると
切断は extent 4096 に対し **−64 / +4160**、つまり**バッファの中＝描画される正方形の外**で、
タイル境界ちょうどに乗る線分は **1,145／3,595／2,590／56 中 0**。MapLibre のタイル別ステンシルが
バッファを捨てるので、見えるものが無い。

⚠ `swimming_pool` は除く／`dock` は除かない。要求は 海岸線＋湖沼＝**陸と水の境**で、z17 のホテルのプールは
それではない。ドックの水面はそれである。

⚠ **「風レイヤーオン時はデフォルトでオン」は既定であって連動ではない。** ラッチが1回だけ提案する——
風を点けたまま海岸線を消した読み手を次の点灯で覆すのは、#R85 が記録した「オフにしてるレイヤーが勝手につく」。

### ④ 3レイヤーの削除

紫外線エアロゾル指数（`gxaero`）・一酸化炭素（`gxco`）・雲赤外（`clouds` ＝ GIBS 静止衛星3枚）。
目録・配色表・サムネイル・Atlas の別名・`data/gibs-range.json` の実測範囲・`lyrClouds` の i18n キーまで。
⚠ ECMWF の雲量（`ec-cloud`）は**別のレイヤー**で、名指しされていないので残る。

### ⑤ 対になっているレイヤーを1本に

CO₂（総量 Mt ↔ 1人当たり t）と、同じ形の国防費（$B ↔ 対GDP%）。凡例の中の切り替えで、行の名前も一緒に変わる。
⚠ **モードが変わったら塗り式を貼り直す。** `addLayer` の枝は初回しか通らないので、そのままでは
**メガトンを1人当たりの目盛りで塗る**（20 Mt 超の国が全部同じ濃い赤になる）。
⚠ **サムネイル側の写しも「読み込み前の答え」でしかない**ので、`IntMapWB.codeOf`／`rampOf` が現在のモードを答える
（#R270 が ramp について作った規則の、code 側）。

⚠⚠ **そして行の名前が空になった。** ブラウザで見たら CO₂ の行が**ラベル無し**で描かれていた。
`ALL` が各エントリの**浅いコピー**で、モーダルなエントリは top-level の `n` を持たない（名前はモードのもの）
のに `modes` がコピーに載っていなかった——`V()` に解決するものが無く `bxLabel` が空文字を返す。
**他は全部正しかった**。だから `tests/r289 ④` は仕組みではなく**ラベルそのもの**を測る。

### ⑥ NATO / EU を加盟年で塗り分ける

両レイヤーとも #R14／#R26 から**本物の加盟年**を持っていて、年スライダーがそれで絞り込んでいる。
塗り分けはその年を**濾すのではなく見せる**。11 の波（NATO）と 8 の波（EU）は11段の青では見分けられないので、
順序尺度（viridis を標本化）を使う——暗い＝原加盟、明るい＝新しい。

⚠ **凡例のグラデーション帯は年別モードでは隠す。** #R270 の欠陥は「凡例が自分の色と矛盾していた」で、
年で塗られた地図の上の一様な青い帯は**同じ主張**である。代わりに波ごとのチップ（年と国数）を出す。
⚠ **「一度だけ組む」ガードを `return` から分岐に変えた。** 年の `<select>` を作り直さない理由（開いた指の下で
閉じる・#R266）は正しいが、**選択状態が凡例の表示中に変わる控えを早期 return の向こうに置くと、
1回組まれて二度と更新されない**＝「押しても何も起きない」（#R268）。

### ⑦ アメリカ大統領選挙：クリックした州の票と選挙人

州別の得票と選挙人を 60 回分すべて取り込んだ（**2,342 州行**、`data/us-elections.json` 28 KB → 136 KB）。

⚠⚠ **列の対応は推測せず導出した。** 元データ（zonination/election-history）の候補列は**位置指定**で、
どこにも名前が書かれておらず、順序は年ごとに変わる（2016 は1列目がクリントン、1824 は1列目がアダムズ）。
そこで**このファイルが既に検算している事実**から導く——各州で選挙人が最多の列は、州マトリクスがその州を
塗っている候補と一致するはず。それを約50州で数えれば、年ごとに1つの割り当てが決まる。

⚠⚠⚠ **そして同じ規則で全セルを検算したら、2,300 セル中 2 つが食い違い、どちらもこちらの表が間違っていた。**

- **1832 バーモント** — 「クレイ」と書いてあった。バーモントの選挙人7は **ウィリアム・ワート**（反フリーメイソン党）
  のもので、彼が唯一取った州である。13,112 票 40.5%、クレイ 11,161、ジャクソン 7,865。元データはこの州を
  「Other」に分類しているので**もともと override が要る**セルで、その override が**別人を名指ししていた**。
- **1892 ワイオミング** — 「クリーヴランド」。これは元データの党ラベルの誤りをそのまま信じたもので、
  ワイオミングの選挙人3は **ハリソン**（8,454 票 50.6%）。クリーヴランドはそもそも出ておらず、列は文字どおり 0
  （民主党はポピュリスト票に合流した）。

⚠ **1892 ノースダコタは誤りではないので変えていない**——3人の候補に1票ずつ割れた州で、州が割れたなら
1色では表せない。だから検算は**同点＝分割**として通し、塗りは override の答えのままで、新しいパネルが
実際の 1/1/1 を見せる。

2020 と 2024 は元データの範囲外なので、州別得票は**認定結果の郡別集計**（tonmcg）を州に合計し
（ジョージア 2020 バイデン 2,473,633／トランプ 2,461,854、2024 トランプ 2,663,117／ハリス 2,548,017 と完全一致）、
選挙人は 2010／2020 の国勢調査配分。⚠ **配分表は2通りに検算される**——合計 538 と、勝者総取り＋既に記録済みの
分割区で全国合計（306/232・312/226）が再現できること。誤植のある配分表は両方は通れない。

⚠ **無いものは無いままにする。** 1824 年以前はほとんどの州に一般投票が存在せず（州議会が選挙人を選んだ）、
サウスカロライナは 1860 年まで。そういう州には選挙人の行と**理由の1行**が出る——長さ0の棒は出さない。
棒は**その州自身の総投票数**に対する割合なので、他の候補が居た年は 100% に足りない（1960 ミシシッピの
非拘束名簿は両名を上回っており、記録の列に入っていない。2名に正規化すれば 36% が 60% に化ける）。

年送りの `‹ ›` は 30 px・字は 13 px だった → 箱 38 px・字 22 px（携帯では 44 px）。

### ⑧ Chronos

統一時間機能を **Chronos** に改名し、パネルは「Chronos／IntMapの統一時間を操作」、
折り畳みボタンは「Chronos／地図の時間を操作」。⌛（CSS の `::before`）は削除。

⚠ **カーネルは `js/chronos.js` へ出した。** 名前が付いたものは主題であり、主題は自分のファイルを持つ
（そして `tests/r168 #8` のシェル行数上限が、このラウンドがシェルに足した分だけ**何かを外へ出せ**と要求する）。
`window.IntMapTime` という**契約名は変えない**——30 近いファイルがそう呼んでおり、表示名に合わせて契約を
改名するのは改名のための改名である。
⚠ カーネルは `newsDate`（`js/app-body.js` のクロージャ変数）に**代入していた**ので、そこだけは
**最初に登録される購読者**に置き換えた——「他の誰よりも先に整合する」という性質は同じまま。

⚠⚠ **「どこの時刻を採用するか」のプルダウン**（端末／UTC／地図中心の標準時／主要24タイムゾーン）。
**時刻そのものは変わらない**——タイムゾーンは瞬間の**書き方**であって2つ目の時計ではない（#R265・#R267 が
それぞれ消した「2つの時計」）。決めるのは2つだけ：このパネルが瞬間を**どう印字するか**と、
時刻タブの「14:30」を**どう瞬間に読み戻すか**。
⚠⚠ **こわいのは読み戻しのほう。** `base.setHours(h,m)` は**端末ローカル**に書くので、UTC を選んでいても
「端末の 14:30」を設定していた——**操作と時計が別のことを意味する**、まさにゾーン選択が防ぐべき欠陥。
逆変換は「UTC のつもりで組んで、その瞬間のオフセットを引き、**もう一度測って1回補正**」——ゾーンの
オフセットは訊ねる瞬間に依存し、DST の境目が最初の推測を動かすため。
⚠ 「地図中心」は `js/layer-packs.js` のタイムゾーン層が**既に持っている** Natural Earth のポリゴンから読む
（`window.IntMapTimeZones`）。**標準時**であることは選択肢自身が明記する——あのデータに DST 規則は無い。
`offsetAt()` は**取得しない**（毎再描画で走る getter が通信を始めると、呼ぶ側は「まだ」と「ここには無い」を
区別できない）。

### ⑨ 時間で変わるもののうち、自分の時計を持っていたもの

ニュース・国データ・国境・ケッペン・日付付きラスタ・昼夜・空はすべて既に購読している。
ECMWF の予報軸は**同じラウンド番号の #R288（別セッション）が先に取り込んだ**。残っていたのは
**ライブ衛星**で、SGP4 は瞬間を取るのに `new Date()` を渡していた——**中身がまるごと時間の関数である**
唯一のレイヤーが、**時計の動かない**唯一のレイヤーだった。
⚠ 軌道要素の「古さ」も**そのフレームの瞬間**で測る。10分外挿と3週間外挿は別の主張で、パネルはその数字を
既に印字している——時間旅行するとその2つ目が普通になるので、印字が真であり続けるには基準を動かすしかない。

### ⑩ Flat では宇宙へ行かない

渡り方は**球のために書かれている**——画面上の**面**と大きさを空のカメラへ引き渡す（`handoverRadiusPx`、軸の注記）。
Web メルカトルの床にそんな面は無いので、ジェスチャは地図が居たことのない場所へ着いていた。
⚠ **ゲージも一緒に止める**——絶対に発火しない予告は欠陥の悪いほうの半分。
⚠ **戻り道（`pushIn`）は塞がない**——既に宇宙に居てから Flat にした人を閉じ込めることになる。
⚠ 検査は**両方向**：Flat では床に居ても開かない／Globe では同じジェスチャで開く。片方だけなら
「トリガーが壊れている」でも緑になる。

### ⚠⚠⚠ ラウンド番号が3度目の取られ方をした

全部書き上げてブラウザ検証に入った時点で `origin/main` は**別セッションの R288** に進んでいた
（#R285・#R286 に続き3回目）。しかもその回は**同じ ECMWF の時計**を直していた。

- 33 か所を **R289** へ改番し、`tests/r288-checks.test.mjs` を `r289` へ改名（add/add 衝突を避ける）。
- **ECMWF は向こうの実装が上位互換なので、自分の分を捨てた**（`git checkout --ours js/wx-ecmwf.js`）。
  自分が書いた `tests/r276` の変更も戻し、`tests/r289 ⑨` は**向こうの `_followClock` が持つ性質**を測る形に書き直した。
- ⚠ **衝突は両側から組み直した。** 向こうは `temp` を消し（`ec-temp` へ）、こちらは `clouds`／`gxaero`／`gxco`／
  `wbco2t`／`milSpendGDP` を消す。**どちらかを丸ごと採れば相手の指示を取り消す**——#R280 の
  「ファイル単位の解決は、そのファイルの他の行についての判断ではない」がそのまま当てはまる。
- ⚠ **`.claude/launch.json` に別セッションの temp 絶対パスが commit されていた**（`…/wt-r287/dist`）。
  その一時ディレクトリが消えれば死んだサーバになるので、相対 `dist` に直した。
