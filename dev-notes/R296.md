### ① ⚠⚠⚠ 「消したはずのウィジェットが勝手に復元して出現する」——**同期していたのは1つ前の形式の板だった**

`js/app-body.js` の `collect()` は一行だった：

```js
d.widgets = JSON.parse(localStorage.getItem('intmap_widgets3') || '[]');
```

`intmap_widgets3` は **#R292 が移行元として残し、新しいストアが二度と書かないキー**である。つまり
アカウントに入っていたのは**移行前の板が凍ったもの**で、`_syncPrefsDown` はそれを `_setActive` に渡し、
`applyLegacy` は**板を丸ごと置き換える**。サインインのたび、すべての端末で、**読み手が消したカードが
戻ってきていた。**

⚠ **そして v4 のペイロードは一度も送られていなかった。** #R292 はこの往復のために `_payload()`（サイズ・
スタック・カード設定を持つ v4 レコード）を公開しており、**呼び出しは 0**。板はレガシーの一覧として上がって
いたので、**スタックはばらけたカードとして、S のカードは既定サイズとして戻ってきた**。
→ 両方向とも**モジュールに訊く**（`_active()` と `_payload()`）。⚠ `[]` も往復する——**空の板は板**であり、
それは `js/widget-store.js` が `empty:true` を書いている理由と同じものである。

⚠ #R292 のファイル冒頭は「アカウント同期はこの2つを通して板を往復させる」と書いていた。**書いてあった
契約と、実際に呼ばれていた経路が別物だった**——`tests/r292 ⑪` は下り側だけを検査していて、上り側が
まったく別のキーだったことは誰にも見えなかった。検査は**両端**を見るように直した。

### ② ⚠⚠⚠ 「ウィジェット画面をスクロールできない」——**スクロールする祖先が1つも無かった**

計器は単純で、`#widget-board` から `documentElement` まで祖先を歩いて `overflow-y` を読むだけ：

```
#widget-board.wgt-board   visible     740px
#sidebar.sidebar          visible     clientHeight 900 / scrollHeight 903
.operation-room           hidden
body                      hidden
```

**どれもスクロールしない。** サイドバーのスクロール領域は `.content-area` で、`ensureBoard()` は板を
`#live-news-feed`（それ自身が `.content-area`）の**兄弟として**差し込む。つまり板は `.sidebar` の直下の
flex 子で、行き場が無い。ビューポートを超えた分は `.operation-room` の `overflow:hidden` に切られて
**スクロールバーもホイールもドラッグも効かない**。カードが十数枚あればノートPCでも板はサイドバーより高い。

→ 板が「見せているペイン」であるとき、板そのものがサイドバーのスクロール領域になる
（`flex:1 1 auto; min-height:0; overflow-y:auto`——`.content-area` が既に宣言しているのと同じ幾何）。
⚠ **`.sidebar >` に限定する。** 同じ要素は Workspace ペインと携帯シートにも載り、そちらは自分で
スクロールする。中に2つ目のスクローラを作るのは #R34 が1ラウンド使った入れ子スクロールの罠。

### ③ ⚠⚠ 「自動でウィジェットを敷き詰めてくれない」——**#R292 は隙間を<b>価格</b>として受け入れていた**

既定の板を2列で測ると、S（1列）のあとに M（2列）が4枚続くので**1行目に 171×131 px の穴**が空く。
`grid-auto-flow: dense` を使えば埋まるが、#R292 はそれを明示的に拒否していて、理由も正しい——
**dense はカードを<b>見た目だけ</b>動かし、DOM では動かさない**ので、キーボードでの並べ替えと
スクリーンリーダーの読み上げが静かに壊れる。

→ **dense 配置を DOM の並びで計算する**（`packOrder(items, cols)`）。同じ敷き詰めで、読み上げ順序と
視覚順序は一致したまま。**カードは前にしか動かない**——空いたままになるはずの穴に、あとのカードのうち
入るものを引いてくるだけで、後ろへ押し戻すことはしない。

⚠ **検査の不変条件は「穴が0」ではない。** 書きながら測って分かったのは、`[m s l s s m]` を2列で敷くと
**最後に必ず1セル空く**——そこへ来た時点で残っているのが2列幅のカードしかないからで、これは欠陥ではなく
算術である。「0」を要求する検査は**入るものを飛ばして後ろのカードを引っ張る**ことでしか満たせず、それは
この packer が絶対にしてはいけない唯一のことだった。だから検査するのは dense 配置の定義そのもの——
**「空いているセルはすべて、そのあとに来たどのカードも入らないから空いている」**。

### ④ ⚠⚠⚠ 「経路機能は現在地を地点に楽に選べるように」——**`useHere` には呼び出しが無かった**

`js/routing-ui.js` の `useHere(which)` は #R291 から存在する。権限の要求、`asking`/`denied`/`timeout`/
`error` の4状態、精度が悪いときの注意、拒否されたときの次の一手まで書いてある。**プログラム全体を
検索して呼び出しは 0。** 現在地に届く唯一の道は、欄に文字を打って候補に「現在地」が出るのを期待する
ことだった。これは #R291 自身が `openPanel` について見つけた形で、#R268 は同じものを1ラウンドで3つ
数えている。

→ 地図から点を拾う ◎ の隣に、**どの地点欄にも**現在地のボタンを置いた。ラベルは状態の関数なので、
待っている最中も拒否されたことも黙らない。⚠ **パネルを開いただけでは何も要求しない**——許可を訊くのは
押した瞬間だけで、これは #R291 が最初から書いていた性質。

### ⑤ ⚠⚠ 「「徒歩 → END」ではなく「徒歩 → 到着」でいい」——**`END` は地名ではなく<b>番兵</b>だった**

MOTIS は旅程の両端を `START` / `END` と名づける。これは場所の名前ではなく、API が「あなたがくれた座標」と
言っているだけである。それが素通りしていたので、**どの言語でも最後の徒歩が「徒歩 → END」**と出ていた。

→ 番兵は `js/routing.js` で潰し、**どちらの端かを<b>フラグ</b>で運ぶ**（`fromStart` / `toEnd`）。
語は `js/routing-cards.js` が**描画時に**選ぶ。⚠ #R291 追記の教訓がそのまま効く——**経路データに焼き込んだ
翻訳文字列は一度しか解決されず、言語切替に二度とついてこない**。

### ⑥ ⚠⚠ 「経路機能で、現地の時刻に合わせろ」

パリ発 08:40 は**パリの** 08:40 である。これまで経路の時刻はすべて読み手の時計（設定があればその
タイムゾーン、無ければ端末）で描かれていたので、東京→パリの旅程は端から端まで東京時間で読み上げられ、
到着が出発より前に見えた。

→ **座標から実効オフセットを引く**（`IntMapTimeZones.offsetAt(lng,lat)`——Chronos の「地図中心の標準時」が
使っているのと同じ仕組み）。IANA 名は持っていないので `Intl` に渡さず、**ずらした瞬間を UTC で書式化**する
——どの実行環境でも桁が現地のものになる唯一の組み方。乗車区間は**乗った駅と降りる駅でそれぞれ**時計を持つ。
⚠ **設定で明示したタイムゾーンは今も優先される**（アプリ全体を1つの時計で読むという選択だから）。
⚠ そしてポリゴンは**このパネルが要求する**（`TZ.ensure()`）——#R293 ⑧ は「`ready()` を誰も呼んでいない」
ために「地図中心の標準時」が黙って端末の時計に落ちたラウンドである。

### ⑦ ⚠⚠ 「経路カードが広がって詳細が表示されるUIに」——**カードが `<button>` であることが理由だった**

#R291 は手順の一覧をカード一覧の**下**に置き、理由も書いていた：「ボタンであるカードの中に、ボタンで
できた手順の一覧は入れられない」。それは `<button>` については正しく、そう**していたのはカードの要素の
ほう**だった。→ カードは `div[role="radio"]`（囲っている radiogroup が最初からそう宣言していたもの）になり、
中の手順は普通のボタンのままでいられる。`data-ai` と `.rt-alt` は不変なので、既存のハンドラと検査は
同じものを指し続ける。

⚠ **押下の判定順が意味を持つようになった。** 詳細がカードの中にあると、手順を押しても
`closest('.rt-alt')` が当たる。カードを先に判定すると**すべての手順の押下を飲んで**、既に選ばれている
候補を選び直して再描画する——それは「押しても何も起きない」に完全に見える。**手順を先に判定する。**

### ⑧ ⚠⚠ 「経路機能を閉じても地図に経路が残り続けるのをやめろ」——**#R291 の判断を読み手が覆した**

#R291 ⑷ は「パネルの ✕ が経路を消していた」を欠陥として直し、閉じても経路が残るようにした。あれは
私自身の §2.2 の読みであって、読み手の指示ではなかった。今回その逆が言葉で来たので、**閉じることは
消すこと**にした。⚠ ただし**地点は残す**——出発地・目的地・経由地はストアに残るので、開き直せば同じ
旅程が出て1回の計算で戻る。「経路を消去」は**閉じずに**消すために残る。

### ⑨ ⚠⚠ 「レイヤー選択欄はclassic dropdownを完全削除」——**要素を消すことは、レイヤーを消すことだった**

触る前に数えた：`#layer-dropdown` は **20 ファイル・71 か所**から参照されていて、**このアプリのレイヤーの
チェックボックスは全部その中にいる**。右サイドバーのタイルは `rowsFromDropdown()` がその要素を歩いて
組み立てているし、レイヤープリセット・Atlas のレイヤーカタログ・不具合報告・共有ハッシュも同じ要素を
数えている。**ノードを消しても dropdown は消えず、レイヤーが消える。**

→ 消したのは**表面**である。開くクラス（`.layer-dropdown.show`）、外側クリックでの解除、
`#map-container` への持ち上げと位置決め、その中だけにあった検索欄（`IntMapModules.layerSearch`）、
そして設定の「レイヤー選択欄」の行——**保存・読み込み・確定のすべてから**。`Layers` ボタンは
`IntMapLayerSidebar.toggle()` しか呼ばない。要素は**常時 `display:none` のレジストリ**として残る。
⚠ 携帯は #R232 から既にタイル盤で、classic の行は `body.m-lyr-tiles` が隠していた——**表面としての
classic はデスクトップにしか無かった**。

### ⑩ ⚠⚠ 4つのツール行が消え、**どれ1つ機能を失っていない**

| 消えた行 | 依頼 | 機能はどこへ行ったか |
|---|---|---|
| 浸水・津波ハザード（`IntMapDisaster`） | 「4つのうち、放射性物質拡散シミュレーションを残し全削除」 | 4択の `放射性物質` は**別のパネルを開くだけの入口**だった。残るのは `IntMapRadiation` で、これは自分の行を持っている |
| 公共交通の到達圏（`IntMapTransitReach`） | 「到達圏と公共交通機関の到達圏に分離するのを辞めろ」 | 到達圏パネルの**4つ目の交通手段**。エンジンは1行も変えていない——パネルが呼ぶ |
| 電波到達範囲（`IntMapRF`） | 「電波・通信圏と見通し線解析を統合して」 | `IntMapLOS` の**モード**。⚠ RF の物理は LOS の**真部分集合**だった（52×52 セルの 4/3 地球見通し 対 ラスタ解像度の同じ可視領域＋屈折・第1フレネル・ナイフエッジ回折）。RF だけが持っていた**送信出力と自由空間の予算**は式ごと移した |
| 地球リプレイ（`IntMapEarthReplay`） | 「存在意義が不明だから全削除」 | Chronos がその時計である。日付・時刻・再生を持ち、昼夜境界はそれに従う |
| 津波シミュレーター（行のみ） | 「ボタンを設置しないように」 | **モジュールはそのまま。** 地震シミュレーターが震源を持ってから渡す。単独の入口は読み手に断層を発明させる |

⚠ **`IntMapRadiation` には #R264 が測った「開かないボタン」があった。** ツール行は `openPanel()` を
呼び、モジュールはそれを持っていない——`typeof` は `undefined`、呼べば投げ、catch が false を返し、
`IntMapOS.exec('sim.radiation')` は **false** だった。#R264 はそれを直さずに報告し、理由も書いていた
（「読み手の代わりに核種と放出率を選ぶのは、規程が禁じている発明されたデータそのもの」）。
**その理由が反対しているのは<b>走る既定値</b>であって、パネルではない**——パネルはまさに読み手がそれを
述べる場所である。そして今回それは**唯一の扉になった**ので、作った。放出量・核種・放出時間・追跡時間は
すべて操作子から来て、読み手が地点を置いて「実行」を押すまで何も走らない。

### ⑪ Atlas — 返答が答えから始まる

- **冒頭の見出しと交通手段タブを消した**（`_hdr` は空文字）。どちらも「読み手が今打った質問の言い直し」と
  「会話ログの中に置かれた2つ目の操作子」で、#R291 が本物のパネルを作って以降は**置き場所が違う**。
  ⚠ 空にするのであって消さない——下の6つの分岐（見つかった／取り消し／タイムアウト／交通なし／経路なし）が
  それぞれ前置するので、1つの空文字が**6か所の編集がばらけるのを防ぐ**。
  ⚠ ボタンが出なくなったので、それを待っていた `.atl-route-mode` のハンドラと CSS 4行も消した。
- **注記は1文だけ**。落としたのは提供者の名前（`js/routing-providers.js` とパネルが言う）と、読み手が
  既に知っている言い回しの案内。残したのは**注意そのもの**——読み手が誤解しうる唯一の点。
- **読み手自身のメッセージもコピーできる。** ボタンは**1つの関数**なので、「このメッセージをコピー」が
  何を指すか（バブルの `innerText`）で2つが食い違うことがない。読み手のバブルは Copy だけで Retry は
  無い——自分の文を再実行するのは、その返答の下に既にある Retry である。
  ⚠ 返答の直前の兄弟が「読み手のメッセージ」だと仮定していた自動スクロールは、間に入った copy バーを
  **跨ぐ**ようにした（隣接を仮定した参照は黙って動かなくなる）。

### ⑫ 「経路ポップアップは無条件で透過するな」

「無条件で」が欠陥の名前である。このアプリの他の面はすべて読み手自身の 設定 ▸ サイドバーの質感 に従う
（`body.sidebar-translucent` / `.sidebar-glass2`、それ以外は不透明＝既定）。経路パネルだけは誰にも訊かず、
`--popup-bg`（rgba …0.72）と 20 px の backdrop-filter を無条件に宣言していた。
→ `js/map-ui.js` が `#layer-sidebar-r` に既に使っているのと同じ形にした。

### ⑬ 測ったが、このラウンドでは直していないこと

範囲が絞られる前に本番（R293 配信済）へ計器を当てている。**数字はここに残す**——次に警報を触る回の
出発点になるので、消さない。

- **中国が塗られていない。** `grades.cma` は 60 秒後も `loading`、90 秒後に `error`、`china: 0`。
  原因は上流ではない——`www.nmc.cn` は**このマシンから 4.4 秒で 200**。relay 経由が詰まっていて、
  `alerts-relay?u=<nmc>` は**同じ URL で 0.5 秒のときと 45 秒超で切れるとき**がある（#R269 が 20 秒→45 秒に
  上げ、1回再試行するので上限は 90 秒）。クライアント側には制限時間が無いので `cmaBusy` が最大90秒立ち、
  30 秒ごとの tick はその間 CMA を飛ばす。
- **警報そのものは単位で塗れている。** 2,704 区域・55 か国、**全部が発令単位**
  （日本 839 muni／台湾 257 township／ポーランド 231 region／ドイツ 173 district／…）。
  「日本以外でも区分単位で」は成立している。
- **「発令なし」の灰色は z3 以上でしか出ない**（`QUIET_UNIT_Z`）。世界表示で `unitCount: 0` なのは
  仕様であって退行ではない——z6 で 1,026、z5 で 3,368 まで増える。**世界ズームで測って「壊れている」と
  書かなかったのは、そこが視野の外だと知っていたからである。**
- **ポップアップは 318×177 px で、「発表」と「IntMap 取得」の2つの時計が出ている**
  （`issued Aug 21, 08:10 PM · IntMap read Aug 21, 08:14 PM`）。#R293 ⑥ は効いている。

### 追記 — **本番検証で 1 件。自分がさっき直したボタンを、同じコミットで壊していた**

deploy 後の本番で Atlas を開いて測ったら、コピーボタンがこうだった——

```
title       "Copy message"              ← 正しい
textContent ""                          ← 文字が無い
innerHTML   …<rect …></rect></svg>      ← path も span も無い
```

しかも**読み手のメッセージ側だけでなく、返答側のボタンも**である。つまりこのラウンドは
「読み手のメッセージもコピーできるように」を実装しながら、**#R72 から動いていたボタンを壊していた**。

原因は 1 つの文字列だった。`copyBtn` を作るとき、`cpSvg` を**切り詰められたコンソール出力から**貼った
——`cut -c1-250` で切られた末尾が `…<path d="M5 15V5a2 2 0 0 1 2-2h1` である。これを `innerHTML` に
入れると、HTML パーサは**未終端のタグのあとを全部属性として飲み込む**ので、閉じる `</svg>` も、その後ろに
連結していた `<span>Copy</span>` も消える。

⚠⚠⚠ **`node --check` はこれを見られない。** JavaScript としては完全に妥当で、壊れているのは
**文字列の中の HTML** だけだからである。自分の検査も緑だった——`copyBtn` が存在することと、
`writeText(src.innerText` が 1 つしか無いことは確かめていたが、**ボタンが文字を描くかを一度も問っていなかった**。

→ 文字列を完全な形へ戻し、検査は**欠陥があった場所に**置いた：`cpSvg` が `<svg` で始まり `</svg>` で
終わること、そして**`<` と `>` の数が一致すること**。安くて、同じ壊れ方を二度と通さない。

⚠ そして**同じ形を diff 全体へ掛け直した**——このラウンドが追加した全行のうち、タグが閉じていないのは
**この事件を引用している自分のコメント 1 行だけ**だった。制御文字の掃き出しも 0 件。
**1 件見つけたら、同じ形が他に何件あるかを数える**——これは #R289 の「報告された 1 か所を直す前に、
同じ事実が何か所にあるか数えろ」を、自分の diff に適用したものである。
