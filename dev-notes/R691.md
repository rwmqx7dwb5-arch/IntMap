## R691 — **`name:ja` が在ることと、それが日本語名であることは別だった**

〈アダナ市街のスクリーンショット 1 枚と、「これ」「クソごみ」〉

### 1. 報告は 4 件、実測は 45 件

最初の報告は `Seyhan → 強川` ほか 3 件だった。スクリーンショットが来て、それが
**市街地の地名がまるごと直訳漢字になっている**画面だと分かった。数え直した:

| 測ったもの | 値 |
|---|---|
| アダナ県で `name:ja` を持つ要素 | 1,950 |
| うち地図ラベルになる（`place` / `boundary`） | 78 |
| その 78 のうち、**版履歴で同一アカウントが最後に書いた**もの | **73** |
| うち漢字の意訳・当て字 | **45** |

`Barış → 平和`、`Fatih → 征服者`、`Yenibaraj → 新弾幕`、`Beyazevler → 白家`、
`Bahçeşehir → 園都市`、`Kabasakal → 失礼顎鬚`、`Karslılar → 蚊流酢人達`、`Yurt → 国`、
`Pınar → 春`、`Döşeme → 床`。

⚠ **正しい 2 件だけが別人の編集だった**——`Adana → アダナ`（Largesurfacearea）と
`Ceyhan → ジェイハン`（katpatuka）。

### 2. ⚠⚠⚠ 報告された前提のうち 2 つは、実測で覆った

- **`Adana → 亜駄名` は既に直っている**。現在の OSM は `アダナ`。`Toros → 強山` も
  ノード側は `トロス` に戻っている（関係のほうはまだ `強山`）。
- **`relation/1249257` は川ではなくセイハン区**（`boundary=administrative`, `admin_level=6`）。
  セイハン川は `relation/158234` で、そちらにも `強川` が入っている。ただし
  OpenMapTiles の `waterway` 層は **way から**作られ、way に `name:ja` は無いので、
  **川のラベルは元から `Seyhan` と出ていた**。

⚠ **Wikidata も同じ人物に汚染されている**: `Q524349` の ja ラベルが `強川`、
`Q1430729` が `黄松`、`Q6062275` の別名に `強山／つよやま`。まともな音写
（セイハン・サリチャム）は alias 側にしか残っていない。⇒ **Wikidata を正解の出所にできない。**

### 3. ⚠⚠⚠ 描画時に判定できる規則は無い

「漢字が入っていたら拒む」は書けない。同じ掃引に入ってくる `黒海`（Karadeniz）・
`金角湾`（Haliç）・`東アナトリア断層`・`中東工科大学`・`フランス大使館`・`ヨズガト県` は
**全部正しい日本語名**である。そして MapLibre の式には**正規表現が無い**ので、
どんな綴りの規則もそもそもレンダラの中では走らない。

⇒ 判定は `scripts/build-osm-ja-rejects.mjs` の中で**生きた OSM に対して 1 回**走り、
出荷されるのは**その観測**である。基準は 3 つ全部を満たしたときだけ:

1. **集落か行政区画**（`place` が集落クラス、または `boundary=administrative`）。
   海・海峡・断層・公園・大学・大使館は**意図的に外す**——日本語が本当に訳す種類だから。
2. **`name` がラテン文字**（CJK 圏の外＝日本語名は音写であって語の翻訳ではない）。
3. **末尾の一般名（…県/市/区/町/村/島/地方）を落としても、まだ漢字が残る**。
   `ヨズガト県` は `ヨズガト` になるので残り、`平和` は何も落ちないので拒まれる。

### 4. ⚠⚠⚠ 訂正ではなく拒否

「Kabasakal の日本語名」は公刊されていない。当てれば**発明**であって、それは
`AGENTS.md` §3 の 3 が禁じる偽の実装である。だから直さず**拒む**——記録した
**組**（`name` と `name:ja` の両方）が一致したときだけその値を捨て、
`name:en` → `name:latin` → `name_int` → `name` という、**`name:ja` を持たない
何千ものトルコの地名が既に使っている**代替に落とす。ラベルは `Kabasakal` になる。

⚠ **組で一致させるから、一覧はひとりでに失効する。** 上流が値を直した瞬間に行は
不活性になり、新しい値がそのまま使われる。`Adana` と `Toros` では**報告と掃引の間に
実際にそれが起きた**——だから 2 件とも出力に入っていない。

### 5. ⚠⚠ 基準には偽陽性があり、消さずに名前を付けた

掃引は 50 件を出し、そのうち **`Karadeniz Bölgesi → 黒海地方` は正しい**（黒海は
日本語の語なので、それにちなむ地方も日本語では訳される）。

`admin_level` で切る「規則」も試した。**やめた**——それは 1 行に合わせて引いた線であって
名前についての事実ではない（同じアカウントは `place=city` にも届いており、トルコの県名は
既に全部音写されている）。⇒ `KEEP` に**理由の文つきで 1 件**、検査が理由の存在を測る。

### 6. ⚠⚠ 鍵の並びを読む側が 2 つあった

`js/place-labels.js` は「どの `name:*` を見るか」を `window.IntMapOsmNameKeys` として
公開しており、`js/map-ui.js` のポップアップと `js/atlas-view-subject.js` の Atlas chip が
**その並びを自分で走査**していた。**走査は拒否を知らない**——ラベルが `Yüreğir` になった
隣で、ポップアップだけが `良癖` と書く。

⇒ 並びだけでなく**答え**を配る: `window.IntMapOsmName(properties, keys)`。
両方の呼び出し側がそれに訊き、検査は**3 者が同じ文字列を返すこと**を測る。

### 7. 検査は評価する

- `applyLabelLang()` を実際に走らせ、**`setLayout` に渡された `text-field` そのもの**を取り、
  `@maplibre/maplibre-gl-style-spec` の `createExpression` に食わせて**MapLibre 自身に
  評価させる**（#R427 と同じ。`match` の枝ラベル重複は「誤答」ではなく**式の拒否**なので、
  本物のパーサ以外には判定できない）。
- 掃引スクリプトの `isRefusable()` を `import` して、**出荷された全 49 行**がその基準から
  出てくることを確かめる（手で 1 行足したら落ちる）。
- 「直った上流は使われる」「他の言語は影響を受けない」「日本語名を発明していない」を
  それぞれ式の評価で測る。

⚠ **門にはしていない**——`--check` は Overpass が要るので CI に置けない
（`check:histborders` / `check:histeras` と同じ判断・同じ理由）。

### 8. 残り

- **川と施設は範囲外**（基準 1 で外れる）: `Seyhan`(river) → `強川`、
  `Seyhan Belediyesi Kahve Müzesi` → `強川自治体コーヒー博物館`、
  `Çukurova Gastronomi Pazarı` → `強山州食区店`。前者は地図に出ておらず、
  後 2 つは POI トグルを入れたときだけ出る。
- **掃引はトルコだけ**。同じ形が他国にあるかは測っていない。
