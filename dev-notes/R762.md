## R762 — ChatGPT の発話を自動でやることリストにする経路を撤去した

〈利用者の依頼:「ChatGPTで私が話した内容をClaudeのやることリストに自動でする機能を消して。HANDOFF（おそらく）」。
撤去の範囲（全部か・取り込みだけか・読むのをやめるだけか）と issue #225 の扱いは、着手前に確認した〉

### 1. 消したのは機能の寄せ集めではなく、1 本の経路

```
ChatGPT の会話  →  GitHub issue #225（受信箱）  →  handoff-inbox.mjs pull
                →  GPT-HANDOFF/HANDOFF.md（ローカル・git 追跡外）
                →  handoff.mjs prepare（ラウンド着手時にエージェントが読む「やることリスト」）
                →  HANDOFF-REVIEW.cmd の承認 UI（利用者検証 → 自動アーカイブ）
```

この 5 段は互いの状態を参照し合っていたので、どこかを残すと「入口だけ無い」「出口だけ無い」機構になる。
⇒ **段ごとに判断せず、経路として外した。** 削除 7 ファイル、参照の掃除 10 ファイル。

⚠ **`~/.intmap-handoff`（カーソル）と `GPT-HANDOFF/`（ローカルの HANDOFF 本体）はリポジトリの外**なので、
このコミットでは消えない。残っていても読む者がいなくなる。利用者が消したければ手で消せる状態にしてある。

### 2. ⚠⚠⚠ 規則ファイルを消すとき、門は「余った import」を見ていない

`check:agents` は `.agents/rules/` を **readdir して**「そこにある全ファイルが `CLAUDE.md` から
import されているか」を測る。つまり見ているのは **ファイル → import** の向きだけで、
**import → ファイル**（実在しないものへの `@`）は 1 つも測っていない。

⇒ 規則を消して import 行を残すと、**門は緑のまま、毎セッション死んだ参照が配られる**。
今回は先に `CLAUDE.md:14` を消したので落ちなかったが、これは運が良かっただけである。
`.codex/config.toml` の rules 列挙は**手書き**で、そちらは門が一切見ていない（同じ回に直した）。

### 3. ⚠⚠⚠ 検査の証人が消えるとき、消すのは検査ではなく証人

`tests/r295-checks.test.mjs` ⑤ は `.claude/settings.json` の deny 規則
`Edit(GPT-HANDOFF/HANDOFF.md)` の存在を assert していた。撤去すれば必ず赤くなる。

⚠ **ここで検査ごと消すのは「見るのをやめた回」になる**（[[intmap-refusal-that-becomes-implementation]]）。
⑤ が測っている欠陥は deny 規則ではない——**「hook を足すつもりのラウンドが settings.json を
書き直して、既に在った権限を黙って落とす」**ことで、deny はその目撃者にすぎなかった。

⇒ 検査は残し、証人を **allow 一覧**（`scripts/worktree.mjs` など、毎ラウンド無言で走るゲート）に
付け替えた。欠陥の言明は元のまま、測る対象だけが今日も存在するものに変わっている。

### 4. 回帰は「7 ファイルが無いこと」ではなく「経路を名指す指示が無いこと」

`tests/r762-handoff-removal-checks.test.mjs` 4 本。

撤去した機構は、まとめて復活しない——**参照 1 本ずつ戻ってくる**（`handoff.mjs` を走らせる script が
1 行、HANDOFF を読めと言う規則が 1 つ、実在しないファイルを指す索引行が 1 つ）。
だから ① で消したファイルの不在を見たあと、② は**追跡された指示の面**（md/mjs/js/json/toml/yml/cmd/ps1）を
`git grep` で走査して、この経路の綴りが 1 つも残っていないことを測る。`DEV-NOTES.md` と
`DEV-NOTES-ARCHIVE.md` は母集合から外す——**ラウンド記録は「当時そうだった」を述べ続けるのが仕事**だから。

⚠ **針は 1 つの綴りから作る。** `git grep` 用の文字列と JS の `RegExp` を別々に書けば、
それは同じ規則の 2 実装で、両方が同じだけ間違っていれば緑になる（[[intmap-contract-is-not-implementation]]）。
⇒ `NEEDLE_SRC` 1 か所を両方が取り、③ が**この回に実際に消した行**を針に食わせて「捕まえられるか」を測る。

変異で確かめた: `CLAUDE.md` に `node scripts/handoff.mjs prepare` を 1 行足すと ② が落ちる（実測）。

⚠ 最初に書いた ② は全追跡ファイルを `readFileSync` で読んでいて **71 秒**かかった。
`git grep`（追跡ファイルのみ・バイナリを飛ばす）に替えて **1.9 秒**。

### 5. 残したもの

- `DEV-NOTES.md` / `DEV-NOTES-ARCHIVE.md` の handoff の記述は **1 行も消していない**。
- `scripts/master-sync.mjs:11` の "handoff workflow" は **#R282 の実測**（原本が 15 コミット遅れていた
  ときに欠けていたものの列挙）であって、この経路への指示ではない。残す。
- GitHub issue #225 は削除せず、撤去を述べるコメントを付けて**クローズ**した。
  ⚠ ChatGPT 側の指示文（どの発話を拾って #225 へ積むか）は**このリポジトリの外**にあるので、
  外すのは利用者の操作である。issue を閉じたことで、積まれても誰も読まない状態にはなっている。
