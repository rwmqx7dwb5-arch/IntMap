## R398 — **海面気圧は3つの絵を同時に壊していて、見えていたのは一番小さいものだった**

> 「IntMap: 海面気圧レイヤーのカーソル読み出しが、自分の凡例と 100 倍食い違っている。…
>   **⚠ 先に測るべきこと（推測で直さない）**——色ラスタも同じ食い違いを起こしているか。SDK が
>   940〜1060 のスケールで Pa の値を塗っているなら、海面気圧レイヤーは全面が上限色で塗り潰されて
>   いるはず。…同じ生値を読む他の経路も全部調べる。1か所だけ直すと「2つの表が食い違う」という、
>   このリポジトリが繰り返している形になる。」

依頼の指示どおり、直す前に測った。**塗り潰されていた。**

### 測ったもの

| 何を | 実測 |
|---|---|
| `IntMapECMWF.valueNow('pressure_msl', 35, −80)` | **101,458.75**（＝ Pa） |
| `legend('pressure_msl')` | **hPa**・940…1060 |
| `getColor(ramp, 100000)` / `(…, 101458.75)` / `(…, 102500)` | **すべて `[255,68,68]`** ＝ 配色表の最後の色 |
| 海面気圧レイヤーの画面 | **全球一面の赤**（スクリーンショット。北極から南極まで `#FF4444` 一色で、すぐ隣に青→白→赤の凡例が並んでいる） |
| 修正後の同じ視野・27 標本 | 色は **8 種類**（北大西洋の高気圧・南極周極低気圧が出る） |

`getColor` は SDK のタイルワーカーが**画素ごとに通す関数そのもの**なので、これは推測ではなく
「地球上のどの値もこの色になる」という直接の測定である。**カーソル読み出しの「101237 hPa」は
3つの被害のうち一番小さいものだった。**

**他の7変数は生きた場を1点ずつ測って一致していた**——気温 21.95 °C・露点 17.33 °C・突風 4.69 m/s・
風 2.23 m/s・雲量 5.53 %・降水 0.86 mm・CAPE 11.25 J/kg。**食い違う変数が1つしか無かったことが、
アプリのどの部分も気づけなかった理由**である（比較の相手が居ない）。

### 直し方——1つの宣言と、4つの導出

`js/wx-ecmwf.js` の **`FIELD_UNITS`**（`{pressure_msl:{field:'Pa',display:'hPa',per:100}}`）だけが
この事実を持ち、他は全部そこから導く。

| 何を | どの単位で | どこから |
|---|---|---|
| レンダラへ渡す配色表 `omSettings().colorScales` | **場の単位** | 読み手の表を `inFieldUnits` で `× per` |
| `scale()` / `legend()` | **読み手の単位** | `displayScales`（SDK の表そのまま・**不変**） |
| `sampler()` ＝ `valueNow` / `valueAt` | **読み手の単位** | 場の値を `÷ per` |
| 等値線のラベル | **読み手の単位** | SDK が書いた等値線の値を `÷ per` |

**配色表を場の単位で渡すことが、色ラスタと等値線の高度を同時に正す**——SDK は画素の値をこの表に
直接引き当て、**等値線の高度にも同じ表の breakpoints を使う**から。凡例側は1文字も変わらない。

⚠ `getColorScale` は明暗を先に解決してしまうので、`inFieldUnits` は**両方問い合わせて対にして戻す**。
片方だけ倍率をかけて保存すると、暗色の読み手に明色が出る。

⚠ 地点値の変換は **`sampler()` の中の1回だけ**。`valueNow` も `valueAt` もこの関数なので、
「カーソルの数値は隣の凡例の単位」は**構造上そうなる**——2つのファイルが合意しているのではない。

### 見つかったもう1つ——等圧線は**単位とは無関係にも**壊れていた

SDK のベクタタイルは URL で「何を描くか」を言う。`arrows=true` なら矢羽根、`contours=true` なら
等値線で、**どちらも書かない URL の MVT には `contours` レイヤーが存在しない**。`ec-isobars` は
素の URL を送っていた。実測・同一ファイル同一視野:

    …?variable=pressure_msl                    0 地物
    …?variable=pressure_msl&contours=true    900 地物  value "100500"

**レイヤーは可視・ソースは loaded・タイルは取得済み、その全部が空**——「等圧線」は行が出来てから
一度も線を引いていなかった。⚠ **これは今回の単位欠陥とは別の原因**であり、
「単位が違うから交差しなかった」という当初の見立ては**測って外れた**。両方が要る。

ラベルはさらに2つ足りなかった。`symbol-placement:'line'` はこの等値線の形状に**1枚も置けない**
（実測 line **0**・line-center **0**・`text-allow-overlap` を足しても **0**・point **25**。
`tile_size` 512/1024/2048 のどれでも同じなので MVT の extent の問題ではない——SDK が1本の等値線を
短い区間の集まりとして出すため、z3.4 で画面上の中央値 **16 px**）。書体も名指していなかった
（アプリの他のシンボルレイヤーは全部 `Noto Sans Regular` を名指しており、ここだけが既定のまま）。
→ `point` 配置＋書体明示で **12 枚が「1020」のように hPa で出る**（生の高度は 102000 Pa）。

利用者に確認したうえで直した（依頼の範囲外だが、直さなければ今回入れたラベル変換が
**永久に観測できない**＝ハリボテになるため）。

### 検査——数値ではなく関係を書く

- **`tests/r398-checks.test.mjs`（9本）** 宣言ブロックを `vm` に切り出して**実行**する:
  `× per` が正確であること・**割り戻して元の breakpoints に一致すること**・明暗の対が生き残ること・
  `rgba` 型の両端も同じ倍率を通ること・**未宣言の変数は `null` を返して何も触られないこと**。
  加えて、単位の文字列がこの宣言の外に1つも無いこと／`scale()` が `displayScales` を読むこと／
  読み出しの**数値と単位が同じエンジン・同じ変数から来る**こと／ラベルが `.per` を使い literal を
  書かないこと／等値線に必要な3条件が揃っていること。**倍率が 100 であるとはどこにも書いていない。**
- **`tests/prod-smoke.spec.js`（2本）** 出荷ラスタを**レイヤー表から数え上げて全部**測る:
  ① 読み手の数値が読み手の帯に載る（帯1本分の余裕つき——極端な気象では落ちず、100 倍では落ちる）、
  ② 2つの配色表が宣言した倍率ちょうど1つぶんだけ離れている、③ **場が帯の 1/50 以上ばらついているのに
  色が1種類なら落とす**（＝一面の赤の症状を、色名を書かずに述べたもの）。等圧線側は
  「`contours=true` を頼んでいる・地物がある・高度が帯に載る・ラベルが実際に配置されている」。

⚠⚠ **自分の門が「理由のない赤」だった。** 最初に書いた本番検査を不具合版に当てたら
`EC.fieldUnit is not a function` で落ちた——**赤ではあるが、主張が1つも発火していない**。
`EC.fieldUnit ? … : null` に退化させて撮り直し、
`ec-slp: the highest live value (101710 hPa) is on its own key (940…1060 hPa)` と
`the isobar source asks the SDK for contours / Received: …?variable=pressure_msl` で
**主張そのものが赤になること**を実測した。等圧線側の「等値線が来なければ skip」も同じ理由で
**失敗に変えた**——それは skip すべき不在ではなく、この検査が存在する理由そのものだから。

### 触れなかったもの

- Atlas の `data.layerValues` は ECMWF の場を**気温と風の2つしか**登録していない
  （`js/map-ui.js`）。気圧は登録が無く、カタログも気圧を名乗っていないので、今回の食い違いは
  Atlas には届いていなかった。**登録を増やすのは依頼の範囲外**なので触っていない。
- `js/layer-previews.js` の `dl-ec-slp` プレビューは Open-Meteo の地点 API（hPa）から自前の
  斜面で描いており、**正しかった**。本物のレイヤーが一面の赤だったあいだ、サムネイルだけが
  正しい気圧図を出していた——「2つの表が食い違う」の実例がもう1つ、依頼の中にあった。
