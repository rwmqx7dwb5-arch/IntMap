## R317 — **Windows でだけ必ず赤い検査が1本、#R283 の30ラウンド後に新しく書かれていた**

> 「`tests/r313-checks.test.mjs` が **Windows のチェックアウトでだけ**必ず赤くなる。」

### 症状

```
✖ R313 ⑤ exactly one file moves the camera on a layer toggle, and it is the file the constitution names
  AssertionError: bboxOfFC is a named function this test can lift out
      at tests/r313-checks.test.mjs:260

  Windows (このマシン)  7 pass / 1 fail        CI (Linux)  8 pass / 0 fail
```

### 原因——検査が固定していたのは「内容」ではなく「チェックアウトのバイト」だった

⑤ の最後の段は、**出荷中の `bboxOfFC` をファイルから切り出して実際に走らせる**。

```js
const fnSrc = `/function bboxOfFC[\s\S]*?\n  \}\n/`.exec(read('js/layer-home.js'));
assert.ok(fnSrc, 'bboxOfFC is a named function this test can lift out');
```

この式は `}` の直後に**裸の `\n`** を要求する。ところが `js/layer-home.js` は

```
$ git ls-files --eol js/layer-home.js
i/lf    w/crlf    js/layer-home.js
```

——索引は LF、**作業コピーは CRLF**。`}` と改行の間に `\r` が座るので、この式は Windows では
**当たりようがない**。CI は Linux で同じファイルを LF で読むので、当たる。
`const read = (p) => readFileSync(resolve(ROOT, p), 'utf8');` が、行末を正規化しないまま
**バイトを**渡していた。

⚠⚠⚠ **そして「常に赤い」は、ここでは「一度も実行されていない」と同じ意味だった。** `fnSrc` が
`null` で止まるので、その先——フランス本土・**クリッパートン島**・フィンランドの3地物を出荷中の
関数に通し、EU の果が東太平洋（西端 −109.25°）へ伸びないことと、`false` を渡せば真の外接矩形が
今も返ることを確かめる部分——は、**このマシンで一度も走ったことがない**。
#R283 の見出しがそう書いている:「いつも同じ理由で赤い赤は、検査が無いより悪い——失敗の一覧を
読み飛ばす癖を教えるからである。」

### 直し方——#R283 が用意した道具を通すだけ

```diff
-import { readFileSync, existsSync } from 'node:fs';
+import { existsSync } from 'node:fs';
+import { readLF } from '../scripts/eol.mjs';

-const read = (p) => readFileSync(resolve(ROOT, p), 'utf8');
+const read = (p) => readLF(resolve(ROOT, p));
```

`code()` は `read()` の上に載っているので、8件すべての読み口が同時に追随する。

⚠ **式も閾値も1文字も緩めていない。** `readLF` が落とすのは**改行の前の `\r` だけ**で、
改行を要求する式は今も改行を要求し、1文字違う2つの文は今も違う——`scripts/eol.mjs` 冒頭の
**「NORMALISES; IT DOES NOT RELAX」**であり、その両方向は `tests/r283-checks ①` と `③` が
既に押さえている（緩める形で「直す」としたら、まさにそこが緑のまま通ってしまう）。

### 検証

```
node --test tests/r313-checks.test.mjs      改修前  7 pass / 1 fail
                                           改修後  8 pass / 0 fail
node --test tests/r283-checks.test.mjs tests/r313-checks.test.mjs   12 pass / 0 fail
```

⑤ が緑になったのは**式を通したから**ではなく、**初めて走ったから**である。出荷中の
`bboxOfFC` を合成 FC に通した実測:

```
bboxOfFC(fc, true)    [[-5, 42], [31, 70]]           ← 国コードごとに最大の陸塊
bboxOfFC(fc, false)   [[-109.25, 10.27], [31, 70]]   ← 旗を外せば真の外接矩形（＝グループ化は
                                                        CHOICE であって、データを隠す修正ではない）
```

クリッパートン島（−109.25°）が `true` 側で落ち、`false` 側で今も現れる——#R313 が書いたとおりに
動いていることを、このマシンで初めて確かめた。

### ⚠⚠ ゲートは「一覧」で、r313 はそこに載っていなかった

#R283 は道具（`scripts/eol.mjs`）と**ゲート**（`tests/r283-checks ②`）の両方を置いている。
ゲートは正しく動いていた——ただし**名指ししているのは `r261` と `r232` の2本だけ**で、
30ラウンド後に新しく書かれた r313 について、このゲートは何も言っていない。
#R301 が測ったのと**同じ形**である:「一覧から漏れた検査は永久に緑」。

r313 をその一覧に足した。**ただし足すことは「次の1本を見つけること」ではない。**
`readLF` を通していない `tests/r*-checks.test.mjs` は**なお 144 本**あり、そのどれもが
同じ形で書ける。今回それを一括で変えることはしていない——依頼の範囲外であり、
144 本ぶんの赤を同時に開ける作業になる。**この段落は、次のラウンドのための計測値である。**
