## R323 — **同じエンジンを説明する表が3つあり、どれも突き合わされていなかった**

IntMap は「このレンダラに何ができるか」を**3か所**で宣言している。

| # | 表 | 場所 | 役割 |
|---|---|---|---|
| 1 | `MAPLIBRE_CAPS` | `js/geo-engine.js` | 出荷しているエンジン |
| 2 | `CESIUM_CONTRACT.capabilities` | `js/geo-engine.js` | 宣言だけの契約 |
| 3 | `CESIUM_CAPS` | `js/cesium-engine.js` | 実物の Cesium アダプタ |

**この3つを比べる門は無かった。** `npm run check:engine`（`scripts/engine-coupling.mjs`）は
「`js/geo-engine.js` 以外がレンダラを名指ししていないか」を AST で数える門で、これは**別の問い**である。
表の中身については、各ラウンドの検査が**ファイル全体への正規表現**で個別に触っていただけだった。

#R321 時点の実測（3表を AST から読んで並べたもの）:

| key | `MAPLIBRE_CAPS` | `CESIUM_CONTRACT` | `CESIUM_CAPS` |
|---|---|---|---|
| `orbit3d` | true | **キーごと不在** | true |
| `solid3d` | true | **true** | **false** |
| `flat` | true | **false** | **true** |

### どれが正しいかは、アダプタを読んで決めた

3件とも**アダプタの実装を読んで**答えを出し、3件とも**契約のほうが間違っていた**。

- **`flat` → true。** アダプタの `setProjection('flat')` は `morphToColumbusView(0.6)` を呼ぶ。
  Columbus View は**傾けられて地形も載る Mercator 平面**で、`getProjection()` はこのモードに
  `'mercator'` を返す。それがこのアプリの言う flat である（本当に flat になれない `SCENE2D` は、
  正射影で pitch を奪うのでアダプタが**意図的に使っていない**モード）。
- **`solid3d` → false。** アダプタは `addSolid`/`setSolid`/`removeSolid` を**ハードな `false`** で
  返す。**意図的**で、コメントもそう書いている——Cesium のポリゴンは上下を閉じられるが、
  `js/solid3d.js` が視点から計算する**吸収シェーディング**は native ではないので、
  `js/volume3d.js` の `canSolid()`（`can('solid3d') && layers.addSolid`）には**既存の
  フォールバックを取らせる**。契約が true を主張すると、そのフォールバックが奪われる。
- **`orbit3d` → true。** アダプタは #R202 以来 `addOrbit`/`setOrbit`/`removeOrbit` を持っている
  （実物の `PointPrimitiveCollection`。実際の楕円体シーンに実際の高度で置かれるので、惑星の裏側による
  遮蔽は深度バッファの仕事になる）。表にキーが無いだけで、`GE().contracts().cesium.capabilities.orbit3d`
  は `undefined` を返していた——**呼び出し側から見て「このエンジンにはできない」と区別がつかない**。

### ⚠ 正反対を主張する2本の検査が、どちらも緑のまま共存していた

`solid3d` については、**すでに2本の検査が反対のことを主張していた**。

- `tests/r173-checks` … 契約に `assert.match(cesium, /solid3d:true/)`
- `tests/r180-checks ③` … アダプタに `assert.match(eng, /solid3d:false/)`

ひとつのエンジンについての**矛盾した2つの断言**が、#R180 から今日まで**両方とも緑**だった。
**どちらも片方の表しか見ていないので、矛盾はどちらの赤にもならない。**
#R173 は Cesium の SDK がまだ無い時期に「Cesium 級のエンジンならできるはず」を書き、
#R180 は SDK を手にして測って `false` を書いた——**後から測ったほうが正しい**。

### ⚠ そして `orbit3d` は、検査の形のせいで原理的に見えなかった

```js
/* tests/r202-checks ③a */
assert.match(ge, /orbit3d:true/, 'MapLibre declares it');
```

`ge` は `js/geo-engine.js` の**全文**である。`MAPLIBRE_CAPS` にある `orbit3d:true` がこの要求を
満たすので、**同じファイルの下のほうにある契約からキーが丸ごと欠けていても、この検査は緑になる**。
#R318 が数えた「『何ができるか』の一覧が5つあり、どの2つも一致していない」と**同じ形**で、
一覧がコマンドカタログではなく**能力宣言**であるという点だけが違う。

### 門 — `tests/r323-checks.test.mjs`（7本）

3表を **AST から**読み、構造として比べる。文字列がファイルのどこかに在ることは、もう答えではない。

| # | 主張 |
|---|---|
| ⓪ | 3表が**実際に見つかった**（改名・移動で黙って空になったら赤。#R301） |
| ① | 3表は**同じキー集合**を宣言する |
| ② | Cesium の2表は**すべての値**で一致する（同じ1つのエンジンの話だから） |
| ③ | 契約は**アダプタが拒む能力を主張しない** |
| ④ | 読み手が**表を区別している**（1つのキーに2つの違う値を出せることが証拠） |
| ⑤ | **比較器が空虚でない**——#R321 当時の表を食わせると3件ちょうどを報告する |
| ⑥ | `can()` が**探針を能力として訊いていない** |

⚠ **①〜③は MapLibre と Cesium の「値」を比べない。** 値が違うことこそ能力表の存在理由で、
比べてよいのは**キー集合**だけ。値まで比べてよいのは**同じエンジンを説明する2表**（契約とアダプタ）だけである。

⚠ **②は③を含む。** それでも③を別に立てたのは、**過小申告と過大申告の代償が違う**から——
過小申告は機能を1つ失うだけだが、**過大申告は呼び出し側に yes を渡してから下で失敗する**。

### ⚠ 「能力」と「探針」は、名前の一覧ではなく**種類**で分けた

キー集合を厳密に比べようとすると4つ目の差が出る: `CESIUM_CAPS` だけが `styleGaps()` を持つ。
これは**関数**で、`can(f)` は `!!(c && c[f])` なので——**空配列を返す関数でも `can()` は true を返す**。

そこで**宣言＝リテラルと（リテラルの）配列リテラル**、**それ以外＝探針**と定義し、比較は宣言だけを見る。
`styleGaps` と綴った例外表を書かなかったのは、**2つ目の探針が現れた瞬間に逆になる**から——
種類で分ければ、新しい探針は門を鳴らさず、新しい能力は必ず鳴らす。
その定義が健全であり続けるための裏取りが⑥で、`can()` が探針を訊いていないことと、
`can()` が実際に訊く能力を両エンジンが宣言していることを両方見る。

### ⚠ 門が落ちることを、実ファイルで3方向確かめた

⑤は同じ比較器に #R321 当時の値を食わせる**メモリ内**の自己検査だが、それだけでは
「実ファイルを読む経路」が生きている証拠にならない。ソースを実際に書き換えて確認した:

| 書き換え | 結果 |
|---|---|
| 契約を #R321 の姿へ戻す | ①②③⑤ が赤・`orbit3d — missing from CESIUM_CONTRACT.capabilities` と `solid3d — CESIUM_CONTRACT says true, CESIUM_CAPS says false` を名指し |
| 契約の `flat` **だけ**を反転 | ②⑤ が赤・`flat — CESIUM_CONTRACT says false, CESIUM_CAPS says true` |
| **アダプタ**の `orbit3d` を反転 | ②③⑤ が赤・過大申告として `orbit3d` を名指し |

### ⚠ 注記を書く場所が、他の4ラウンドに縛られていた

`tests/r170`・`r171`・`r172`（2本）・`r173` は、いずれも
`INDEX.indexOf('const CESIUM' + '_CONTRACT=')` から **1400〜1600 文字**の窓を切って、その中に
`globeAllZooms` / `tiltRange` / `cameraAltitude` / `eyeControl:true` / `solid3d` が在ることを要求する。
**リテラルの中に長い説明を入れると、それらが窓の外へ押し出される。**
直した本人と無関係な4ラウンドが「自分と関係ない理由で」赤くなるので、
説明は宣言の**上**（＝どの窓よりも手前）に置き、リテラルの中の変更は値だけに留めた。
実測、変更後も `eyeControl:true` は起点から **695 文字**（予算 1400）。

### ⚠ 直した当の盲点に、検証中の自分が引っかかった

修正後、`, globe:true, flat:true, terrain3d:true,` は `js/geo-engine.js` に**2回**現れる
（`MAPLIBRE_CAPS` と契約が、同じ質問に同じ答えを書いているのだから当然である）。
門を実ファイルで壊してみるスクリプトが `String.replace` で最初の1件を掴み——
**契約ではなく `MAPLIBRE_CAPS` のほうを書き換えた**。門は正しく振る舞った
（MapLibre と Cesium の値は比べないので赤くならない）が、これは**直したばかりの盲点の縮小版**である。

最初の編集が正しい側に当たったのは、置換の前に**出現回数がちょうど1であること**を確かめる番人
（`must1()`）を通していたからで、当時はまだ契約側にしか `flat:false` が無かった。
**「一意であることを確かめてから置換する」以外に、正しい表を掴んだ証拠は無い。**

### 触れなかったもの

- **`CESIUM_CONTRACT.implemented:false`** … `js/cesium-engine.js` は実在するので字面は古びて見えるが、
  実行時に読む者はおらず、`tests/r152-checks` が `implemented:false` を固定している。
  依頼の範囲は能力キー3つなので**記録だけ残す**。
- **`tests/r202-checks ③a` の全文正規表現** … 今も真であることを主張してはいる（修正後は両表に
  `orbit3d:true` が在る）。**盲点は新しい門が構造として塞いだ**ので、他ラウンドの検査は書き換えていない。

⚠ **`contracts()` に実行時の消費者はいない**（`tests/prod-smoke.spec.js` が `!!` で存在だけ見る）。
`can('solid3d')` を読む `js/volume3d.js` は**動いているアダプタ**の表を見るので、
今回の変更で**挙動は1つも変わらない**。変わったのは、宣言が事実と一致していることと、
次に食い違ったら門が鳴ることである。
