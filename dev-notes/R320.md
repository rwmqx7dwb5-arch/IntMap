## R320 — **五つ目の一覧はまだ立っていた——DOM 順の先頭 140 件**

#R318 は「何ができるか」の一覧が5つあり、どの2つも一致していないことを数え、4つを1つの
レジストリに畳んだ。**5つ目はそのまま残し、借りとして名前を書いた。**これはその返済である。

### 1. 「どの操作が存在するか」を、文書のどこに座っているかが決めていた

`js/atlas-controls.js` の `controlCatalog()` は `out.slice(0,140)` だった。母集合は
`_ctlEls()`——ページ上の **button / input / select / textarea / [role=button]** 全部。
141 番目に居る操作は、**Atlas にとって存在しない操作**であり、しかも**そう言われもしない**。

⚠ **上限そのものは残す。** プロンプトには実際のバイト予算がある（`ai-proxy` の `MAX_SYSTEM`）。
変えたのは2つ:

- **依頼に対して採点して残す**（`_ctlRelevance`。`findControl` と同じ語を見るので、
  **見せた一覧と実際に見つかる操作が食い違えない**）
- **落とした分を数えて言う**——`… and N more on-screen control(s) not listed here — name one and
  it will still be found`。**黙って切った一覧は、完全な一覧として読まれる。**
  それがこのラウンドが取り除いている仕組みそのもの。

### 2. 「近い候補が複数」を、上位1件で押していた

`doControl` は `findControl` の最高得点をそのまま押していた。得点差が 1 点でも 40 点でも同じ。
⇒ `findControl` が**見た場全体**を残し、`doControl` は上位と **0.92 倍以内**の候補が2つ以上あれば
`ambiguous_target` を候補つきで返す（#R318 の `control` 検証器がそれを `needs_input` にする）。

⚠ **閾値は比ではなく差では駄目だった。** id 完全一致 (100) の隣に語一致 (62) が居るのは並びではない。
ラベル一致の 62 と 61 が並びである。⚠ 隠れた重複は上流で ×0.6 されているので、
デスクトップのボタンとモバイルの写しは並びとして読まれない。

### 3. 「まだ読み込まれていない」を「無い」と答えていた

`moduleCatalog()` は `Object.keys(window)` を歩くだけだった。#R209 が on-demand にした
**8 つのサブシステム**は、誰かが偶然取りに行くまで **IntMap に無いもの**で、`doModule` は
そのどれに対しても `Module/method not found` と答えた。

⇒ `js/lazy-modules.js` の `PUBLISHES`（**起動時から存在する目録**）を `publishes(name)` として
公開し、カタログは**コードが来る前に名前を出す**（`[loads on demand]` と印をつけて）。
`doModule` は無ければ `IntMapLazy.need()` して**その promise を返す**——返さなければ、
カーネルの完了待ちは取得を含まない。

⚠ **メソッドの許可リストは変えていない。** このラウンドが広げたのは**到達**であって**権限**ではない。

### 4. 10 回目——自分の検査が自分のコードに当たった

#R318 の監査 ⑮ は `controlCatalog … slice(0, <数字>)` を 400 文字以内で探す近接正規表現で、
今回足した `controlCandidates` の**無関係な `slice(0, 6)`** に当たった。
⇒ 訊いていた問いが違った。「slice があるか」ではなく
**「誰にも告げられずに操作が消えうるか」**である。検査を問いのほうへ書き直した:
上限は許す・**落としたものを言わなければ落ちる**・**DOM 順で切っていれば落ちる**。
