## R400 — **deep tier は6夜連続で赤く、それを赤くしていた表はブラウザを一度も必要としていなかった**

nightly の deep tier が 08-19 失敗 / 08-20 中断 / 08-21 失敗 / 08-22 中断 / 08-23 失敗——
**一度も緑になっていなかった。** 切り分けると硬い失敗は 3 件で、原因は 3 つとも違った。

### 1. `tests/r209.spec.js` — 手で保つ表が、5 ラウンド分ずれていた

「遅延モジュールは全部ちゃんと届いて登録されるか」の検査。その先頭の主張は
**spec の手書き `MEMBER` 表と `js/lazy-modules.js` の実レジストリが同じ集合か**である。

実測（2026-08-24 の main）: **レジストリ 32 本・表 24 本。8 本足りない。**

| 足したラウンド | 足し忘れたモジュール |
|---|---|
| R349 | `warLayer` |
| R353 | `volcanoIntel` `volcanoLayers` |
| R354 | `companyData` `companyPanel` `companyFacilities` |
| R386 | `newsEvents` |
| R388 | `railways` |

**そしてこれは 3 度目である。** その spec の #R341 の注記が 1 度目を記録している——#R322 が
`analysis*` 5 本を足して表に足さず、**そのマージ以降ずっと deep tier が赤かった**。

**⚠ 繰り返す原因は不注意ではなく<b>層</b>である。** この 2 つの表を突き合わせているのは
その 1 行だけで、それが **夜しか走らない spec** の中にある。行を落としたラウンドは
6 日後に、**だれも見ていないジョブ**から、**他人のラウンドに紐づいた形で**知らされる。
5 つのラウンドが同じ漏れをしたのは、**どのラウンドも見えなかったから**である。

だから **ブラウザの要らない半分を node tier に出した**（`tests/r400-checks.test.mjs`・
`test:checks` に登録＝**毎 push 走る**）。①レジストリ⇔表の双方向一致、②表が名指す global が
ローダーが publish する global と一致、③**判定ロジックを変異させて赤を見る**。
spec は実行時の半分（読み込んだが何も publish しないモジュールは、ブラウザでしか捕まらない）を
そのまま持つ。変わったのは**「行を落としたことをいつ知るか」**——他人の nightly ではなく自分の push。

⚠ 検算: 8 行を戻す前の表に対して ① だけが赤くなり、戻した後は 3 件とも緑（実測）。

### 2. `tests/r170.spec.js:199` — 市場カードは扉が 1 枚増えていた

`page.waitForSelector('.co-detail-rows')` が 15 秒で timeout。**ローカルでも再現**（1 failed /
8 passed）＝CI が遅いのではない。ただし壊れていたのはアプリではなかった。

**#R354 がダブルクリックの先を企業アトラス（`js/company-panel.js`）へ差し替え**、
「市場カードは**移動したが削除していない**（CONSTITUTION §0.3）」と明記していた。
アトラスには `button.cop-mkt`（「市場データ」）があり、そこから**同じオーバーレイ**が開く。
つまり `.co-detail-rows` は「ダブルクリックだけ」では出なくなり、**この検査は古い扉を叩き続けていた**。
主張（すべての数値に日付が付く）は今も真で、経路が 1 クリック伸びただけ。

検査を現在の扉に合わせた。⚠ **両方の経路を受ける**——アプリ自身が両方を受けるからである
（`openCompanyAtlas()` は遅延モジュール 3 本を要し、その取得が失敗したらカードを直接開く）。
パネルを要求する検査は、欠陥でない理由で遅い回線を赤くする。

### 3. `tests/r184-cesium-fs.spec.js:64` — 時計が実測より短かった

`page.evaluate: Test timeout of 180000ms exceeded`。**ローカルでは 3 件とも通る。**
08-19・08-21 では落ちておらず、08-23 の一夜だけ。実測を取った:

| テスト | ローカル | 上限 |
|---|---|---|
| ① camera capabilities | 9 s | 180 s |
| ② **the aircraft flies** | **87 s** | **180 s** |
| ③ MapLibre 側は無傷 | 38 s | 150 s |

ローカル合計 134 s に対し `tests/durations.json` は同ファイルを **CI で 234 s** と記録している
——**CI ランナーはこの機械の約 1.75 倍遅い**。②は CI で約 152 s、上限 180 s に対し**余裕 18%**。
スイート中で最も重い Cesium テスト（ソフトウェア WebGL でレンダラを起動し、20 秒ぶん飛ばす）に
18% は薄すぎる。**②の上限だけを 300 s にした。**

⚠ **これは時計であって主張ではない。** 下の期待値は 1 つも変えていない。変わったのは
「遅いランナーが緑の事実を赤い夜に変えない」ことだけ——**狼少年の警報は無視される**警報であり、
#R304 がその代価（14 夜だれも読まなかった赤）を実測している。

### 6. ⚠ このラウンドで**直していない**もの——4 時間前に入った別の退行

③を検証している最中に、同じ spec の**①が落ちた**。私が触った表とは無関係で、原因も別である。

```
Error: nothing is fetched without a gesture except the Atlas kernel …
+ Array [ "newsEvents" ]        tests/r209.spec.js:116
```

**遅延モジュール `newsEvents` が、ジェスチャ無しに起動時に取得されている。**
`js/lazy-modules.js:123` は「News タブを開くまで **1 バイトも降ってこない**」と宣言しているのに、
`js/news-feed.js:213` が**既定フィードの描画中に** `need('newsEvents')` を呼ぶ
（`NEWS_EVENT_MODE` は `js/app-body.js:2474` で固定 `true`）。**宣言と実装が矛盾している。**
ビルド後のチャンクは **18.0 kB**。

新しいことは日付で確定できる——R386（`fee0f4c`）の merge は **2026-08-24 07:51 +0900**、
08-23 の nightly が走った commit（`3b38b63`）は **2026-08-24 03:08 +0900**。**4 時間 43 分後**である。
だから①はその夜は通っていて、**今夜の nightly が初めて捕まえる**。

⚠ **意図的に直していない。** 解き方は (a) 宣言どおり遅延させる（起動時は記事フィードのまま）／
(b) eager として受け入れ `check:perf` の予算に 18 kB を通し `atlasConsole` と同じ免除を①に書く／
(c) R386 の作者が意図した別の形——のいずれかで、**これは製品判断**であり、
4 時間前に出荷された機能を他セッションが今まさに触っている可能性がある（`CLAUDE.md` §6）。
推測で選ばない。**①を弱めて通すことは禁止**と書き添えて別ラウンドへ送った。
