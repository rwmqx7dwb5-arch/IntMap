〈依頼は「歴史地図の coverage や忠実性、品質の漏れを全部埋めて。より広く、深く、忠実に」〉

### 0. ⚠⚠⚠ まずこの回自身の違反 — `CONSTITUTION.md` を読まずに着手した

`AGENTS.md` §1 は着手前の必読に `CONSTITUTION.md` を挙げている。**読まずに scout を飛ばした。**
そのため §7 追補（2026-09-12）——**9 言語体制は完全凍結・英語と日本語のみ・
「◯◯語の被覆が低い」はそれだけでは着手の理由にならない・実態を改善対象にしろ**——を知らないまま、
**fr/ko/zh の名前被覆が低いことをラウンドの主題に据えた。**

⚠ **§7 追補は `AGENTS.md` には書かれていない**（§3-5 は §7 を指すだけ）。
**憲法を開かない限り、凍結の事実には到達しない。**

実測で示される違反の形: 名前の所有権を「名前ごと」→「名前×言語ごと」に変えた結果は
**fr +482・ko +622・zh +635 の描画ラベル**で、**jp と ru は 1 件も動いていない**。
つまり**憲法が「存在するものとして扱え」と言う唯一の読者層に、この作業は何も届けていない。**

変更自体は残す（§7 は「出典が書いたラベルは全言語運ぶ」とし、凍結は削除ではない。利用者の判断）。
**成果としてではなく、逸れた記録として残す。**

### 1. 収録範囲 — 測った結果、Pleiades には伸びしろが無かった

|---|---|---|
| 建造物 | 約 3,300 | station 1,118・fort 734・villa 354・temple 284・sanctuary 242・church 165・bath 60・bridge 38 |
| 自然物 | 約 2,200 | river 1,024・mountain 390・island 387・cape 279・lake 113 |
| 領域 | 約 500 | region 392・province 81・district 41 |
| 地名でない | 約 2,900 | label 1,636・people 1,044・unlocated 315・unknown 144 |

⚠⚠⚠ **建造物も自然物も地名ではない**（利用者の指示）。領域は **era レイヤーが既にポリゴンで
描いている**ので、代表点を打てば同じものを 2 通りに描くことになる。
**厳密な意味の地名（人が住む場所の名）で漏れているのは `vicus` 7・`deme-attic` 10・`pagus` 5・

### 2. 忠実性 — 実測 2 件。どちらもこの回では直せない（理由つき）

**① 塗りと線が別の精度で描かれている（本番相当のブラウザで実測）**

`js/border-coast.js` の `lineGeom()` だけが `detailLine()` を通り、**塗り (`imtb-fill`) は束の粗い環のまま**。
実測（1800 年・ピレネー・z12・`queryRenderedFeatures` で両者を画面座標に投影して距離を測定）:

| | 中央 | p90 | p99 | 最大 |
|---|---|---|---|---|
| 塗りの縁と描かれた国境線の距離 | **4.5 px** | 16.6 px | 26.1 px | **29.9 px** |

クリック判定も粗いほうを使う。⚠ **これは見落としではなく設計**——`detailLine` は
**視野に重なる断片だけ**を取る（「帝国の一部が見えているだけで輪郭全体を取りに行かない」）。
塗りを精緻化するには**記録の輪郭を丸ごと取得**する必要があり、それは断片設計が避けているものそのもの。
⇒ **直すなら見え方の設計変更で、`CONSTITUTION.md` §0-3 の承認事項。提案に留める。**

**② 自己交差する環が 1,793 本ある**

| 束 | 自己交差 | 率 | 簡略化 |
|---|---|---|---|
| `hist-admin1` | 513 | 6.2% | DP 0.004° |
| `hist-admin2` | 1,123 | 4.8% | DP 0.004° |
| `hist-borders` | 157 | 4.4% | DP 0.004° |
| `cshapes` | 7 | **0.3%** | **なし（tolerance 0）** |
| `hist-kuni` | 0 | **0%** | なし |

**簡略化を通る 3 束だけが 15〜20 倍高い。** Douglas-Peucker は凹形の位相を保存しないので、
これは上流の誤りではなく**自分の簡略化が作った蝶ネクタイ**である可能性が高い。
⇒ **オフラインでは直せない**——`data/border-detail/`（409 MB）の索引は
**粗い環の指紋で鍵付けされている**ので、環を作り直すと 409 MB が丸ごと無効になり、
その再生成には OHM の 3.4 GB キャッシュが要る（この機械に無い）。**提案に留める。**

**③ #R695 の「admin1 が admin2 より粗い」は今日は偽。** 両束とも 0.004°/4 桁で、
admin1 のほうがむしろ密（環あたり中央値 35.1 対 27.9）。残る 1.20 倍は**単位の大きさ**であって許容幅ではない。

### 3. 直した品質の漏れ

- ⚠⚠⚠ **散文が実体と食い違っていたのに、それを見る規則が 1 つも無かった。**
  `scripts/doc-facts.mjs` は母集合を git から**発見**するが、**追跡された `*.md` だけ**である。
  ビルドスクリプトの中の散文は同じ種類の主張を同じ出荷バイトについてしており、
  **どの規則も 1 語も読んでいない。** 実測: `scripts/asset-report.mjs` は `data/hist-eras.js` を
  **「53 枚」**と書いていた——**#R707 が落ちていた 1 枚を戻して以来 54 枚**で、
  「読者が何に金を払っているか」を伝えるための行が、それ以来ずっと間違っていた。
  ⇒ 検査④が束から数え直す（⚠ 主張が見つからなければ落第。1 件も当たらない針は緑を出す・#R699）。
- `scripts/build-hist-eras.mjs` の `DEC = 3` に「cshapes と hist-borders に合わせた」と書いてあったが
  **どちらとも合っていない**（実測 cshapes 5 桁・hist-borders 4 桁）。この束は 6 束で最も粗く、
  それは意図だが、**合っていない相手と合っていると書く文は、1688/1689 の継ぎ目を
  「記録の性質」ではなく「バグ」と読ませる。**

### 4. 門とラチェットの漏れ

- ⚠⚠ **`--check` を持ちながら宣言されていない生成器は、それを探す規則から原理的に見えない。**
  未到達の門を探す 3 規則（`gate-callers`・`gate-lists`・`ci-gates`）は
  **どれも `package.json` の宣言済み `check:*` を母集合にする。** 2 件:
  - `data/border-detail/`（5,622 ファイル・409 MB）。⚠ **無防備ではなかった**——
    `tests/r711-…` が `check()` を関数として走らせていた。欠けていたのは**名前**で、
    門の表にも CI ステップにも無かった。⇒ `check:borderdetail`。
    **41 秒は 2 回払わない**——全件の通しは門へ**移し**、r711 には拒否の事例を残した。
  - `data/hist-places.json`。こちらは**本物の穴**で、2 本の検査は fixture の上で選択規則を試すだけ、
    **出荷バイトを典拠記録と照合するものが 1 つも無かった。** ⇒ `check:histplaces`（0.14 秒）。
- ⚠⚠ **金属に触れなくなった逆ラチェットは、ラチェットではない。**
  `ORPHAN_POINTS = 1569` は「再プールされたら失効。再測定せよ」と自分で書いていた。
  #R711/#R712 が再プールし、**誰も再測定しなかった**ので、孤立リングを 1 本も持たないファイルに
  1,569 点の余白を差し出し続けていた。⇒ **実測 0** へ。
  `tests/r700-checks ⑪` が「今日のバイトは six 持つ」と**リテラルで抱えていた**ので、
  実ファイルから導出する形に述べ直した。
- ⚠⚠ `data/hist-eras.js` には**天井が存在しなかった**。門は「10,388 named / 6,955 unnamed」と
  **印字しながら、どちらも縛っていなかった**。名前が読めなくなった feature は `blank`（身元の無い幾何）へ
  落ちるが、**この門の不変条件はその移動の両側で真**である。
  ⇒ `NAMED_MIN` / `BLANK_MAX`。両方向の変異で赤になることを確認。
- `docs/FILES.md` が `hist-places` を 6,032 地点と書き、`Architecture.md` と `PRODUCT.md` は 6,698 だった
  （**1 つの事実に 2 つの答え**）。⇒ `doc-facts` に `hist-places` 規則。
  ⚠ **針は自分の主語を名乗る**（裸の「N 地点」は放射線の観測局も数える）。
  ⚠ **改行は主張の一部ではない**——`Architecture.md` はこの文を折り返すので、
  生バイトを読む針は隣の `PRODUCT.md` だけを見て**こちらを見なかった**。空白を畳んでから照合する。
