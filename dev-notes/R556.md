## R556 — **船が出なかったのは鍵の問題ではなく、届いていたフレームを捨てていたからだった**

> 「船舶レイヤーが表示されない。ふざけるな。」

### 1. 症状——世界のほとんどの海で、点けても何も起きない

本番実測（2026-09-09・修正前）:

| 海域 | 隻数 |
|---|---|
| フィンランド湾 | **440** |
| 東京湾 | **0** |
| 英仏海峡 | **0** |
| シンガポール | **0** |
| ジブラルタル | **0** |

レイヤーは正しく作られ `visible` になり、`ais-feed` は 200 を返す——**配線は生きていた**。
`?meta=1` は `byProvider: {digitraffic: 1102, aisstream: 0}`。全球担当が 0 なので、
鍵無しの利用者に出る船は Digitraffic（フィンランド海域）だけだった。

### 2. ⚠⚠⚠ #R510 は「利用者にしか直せない」で止まっていた。値は本物の鍵を内包していた

#R510 は 9/6 に `klen79:kshapeother` を記録し、「aisstream が発行する形ではない・**これは利用者にしか
直せない**」と書いて終わっていた。3 日後、同じ形のまま船は出ていない。

秘密の値は読めない（`supabase secrets list` は sha256 だけ）。⇒ **関数自身に、値を 1 文字も出さずに
「形」を報告させた**——長さ・文字クラス・そこから導ける候補の長さと形だけ。答え:

```
len 79 · alnum 73 / dash 2 / equals 1 / space 3
candidates: stored(79, other) · after-delimiter(40, hex)   ← aisstream が発行する形そのもの
```

⚠ **鍵を推測してはならない。値が実際に内包している候補を上流に訊く。** 実測:

```
try:stored:len79:other        | open | sent | error:Unexpected EOF | close   ← 拒否
try:after-delimiter:len40:hex | open | sent | （切られない）                ← 受理
```

手元で**でたらめな 40 hex・79 文字の飾り付き・空文字**を投げると 3 つとも即 `error`。
**拒否の形は 1 つしかなく、取り出した鍵はそれではなかった。**

### 3. ⚠⚠⚠ それでもフレームは 0 だった——数えさせたら 1,224 件届いていた

受理されているのに `aisstream=0`。トレースに**フレーム数**を数えさせた:

```
end:alive:frames1224:pos0    |  nonjson:[object Blob] × 3
```

**15 秒で 1,224 フレーム。保持した船は 0。** WebSocket の既定 `binaryType` は `blob` で、
`String(ev.data)` は文字列 `"[object Blob]"` になる。`JSON.parse` が投げ、`catch(_){}` が飲む。
**船はずっと届いていて、ずっと捨てられていた。**

⚠ しかも `nonjson:` のトレースは `STATE.wsTrace.length < 6` という**書かれた当時の長さを前提にした
番人**に抑え込まれていて、候補を 2 つ試すと 6 件を超えるので**その 1 行が一度も出なかった**。
計器が黙っていたのは壊れていたからではなく、**自分の出力が長くなったことを知らなかったから**。

⇒ socket は `arraybuffer` を要求し、フレームは**文字列でもバイト列でも読める形で復号**する。

### 4. ⚠⚠⚠ 同じ欠陥がブラウザの BYOK 経路にもあった

`js/data-layers.js` の `ws.onmessage=(ev)=>{ … JSON.parse(ev.data) … }` も同じ。
ブラウザの既定 `binaryType` も `blob` なので、**自分の鍵を設定に入れた利用者も 1 隻も見ていない**。
設定画面は「鍵なしでも動く／自分の鍵を足せば全世界」と説明していた——**その裏で、鍵は関係なかった**。

### 5. ⚠⚠ 受理を「フレーム数」で判定してはならない。socket を 2 本開いてもならない

最初に書いた判定は「3 秒で 1 件でも来たら受理」だった。**拒否は即座に閉じられ、受理は数秒黙っている
ことがある**ので、これは動いている資格情報を捨てる。⇒ 判定は**上流が切ったかどうか**。

次に書いた版は probe 用と drain 用に **socket を 2 本**開いた。aisstream は鍵 1 本あたり 3 接続で、
**4 本目は拒否と見分けのつかない無言**で落とされる（#R510 が書いていた）——つまり
**自分の probe が、自分の見つけた鍵を無言にしていた**。⇒ 判定と本読みは**同じ 1 本の socket**が行い、
次の候補は前の socket が閉じるまで開かない。

### 6. ⚠⚠ 空の海は 2 つの事実で、ブラウザはどちらも同じ絵にしていた

#R510 §8 は「被覆は答えた provider だけを名乗る」を**関数側で**直したが、ブラウザは 200 を `if(r.ok)` で
受けて**無言で空の海を描いていた**。トーストも注記もエラーも 0 件。

⇒ 応答が **`cov`＝いま保持している船の外接矩形**を運ぶ（**保持している船から導く**——地名も座標定数も
コードに書かない）。視野がその外で 0 隻なら、理由を**1 度だけ**言う（30 秒ごとの催促にしない）。
⚠ **外接矩形は過大にしか外さない**——中の隙間は「被覆内で、たまたま空」と読まれる。つまり
**実際に見えている海を「範囲外」と告げることは構造上できない**。
⚠ そして aisstream が答えている今、この矩形は世界なので、**この注記はひとりでに出なくなる**。

### 7. ⚠⚠⚠ なぜ検査が全部緑だったか——スタブが実物より寛容だった

`tests/r510-checks.test.mjs` の WebSocket スタブは `this.onmessage({ data: JSON.stringify(m) })`——
**文字列**を送っていた。本番はバイト列を送る。**このスタブでは、この欠陥は原理的に起こせない。**
#R552 は「実物より**高機能**な fixture は無力」を記録したが、こちらはその裏返しで
**実物より寛容な fixture は、実物の壊れ方を隠す**。

⇒ `tests/r556-checks.test.mjs` のスタブは**バイトで送り**、`arraybuffer` を要求しなかった読み手には
`toString()` が `"[object Blob]"` を返す物を渡す。⚠ そして ①〜⑤ は**変異試験で全部赤を確認**した。

### 8. 本番実測（この回の変更後）

```
x-intmap-coverage: digitraffic:1103+aisstream:868
東京湾 ?bbox=139,34.5,141,36 → n:3   （KEIYO MARU 他）
```

### 検査

`tests/r556-checks.test.mjs` 5 本。① **バイトで届いたフレームが船として保持される**（本番の退行そのもの）。
② 包まれた資格情報が取り出されて使われ、**包みも鍵も応答のどこにも出ない**。③ **socket は同時に 1 本**。
④ 0 隻の答えも**集合全体の被覆**を運ぶ。⑤ **ディスクから発見した** js/ のすべての aisstream socket が
`arraybuffer` を要求し、`JSON.parse(<event>.data)` がどこにも無い（綴りではなく AST）。
⚠ `tests/r510-checks.test.mjs` ③⑩ は**綴りを固定していた**ので、同じ 2 つの事実を測る形へ直した。
