## R551 — **一つの依頼が二つの地図になっていたのは、途中経過を「完成した別の成果物」として扱っていたから**

> 「地図マッピングが一回で完結せず、途中結果と完成結果が二重表示される問題」
> 「最初から可能な限り16件すべてを処理する／途中で一部だけ解決した場合は、残りだけを継続処理する／
>   同じ依頼を完成させるための再試行なら、最終的には1つの完成版だけ表示する」
> 「局所的な表示修正ではなく execution/result/artifact lifecycle 全体を修正してください」

### 症状

「日本の製鉄所をマッピングして」という **1 つの依頼**に対し、返信の中に地図の説明が **2 つ縦に並んだ**。

| | 見出し | 内容 |
|---|---|---|
| 上 | 日本の主な製鉄所 | 5 件 ＋ 「配置できなかった場所」11 件 |
| 下 | 日本の主要製鉄所・製鉄地区 | 16 件（多くが「製鉄所」から**市名**に変わっている） |

### 5 つの原因が 1 本の鎖になっていた

**どれか 1 つを直しても症状は消えない。**

1. **部分成功が「完了」として外へ出る。** `js/atlas-map-compose.js` は `exec.status:"partial"` と
   正しく名乗っていた。ところが `js/atlas-capabilities.js` の `paint` 観測器が読むのは `meta.partial` で、
   モジュールはそこに何も書いていなかった。`paint` が訊く質問は「前後で何か動いたか」だけなので、
   **compose の source が 0 → 5 になった時点で `completed`**。
2. **その「完了」が `doneCalls` に凍結される。** `js/atlas-agent.js` は `rec.ok !== false` を条件に
   成功を記憶する。`ok` は `status === "completed"` からの導出（#R318）なので、**半分しか終わって
   いない呼び出しが「このターンで既に実行済み」になる**。同じ引数で残りを試そうとすると、古い
   半端な結果がそのまま返る。
3. **だから Atlas は引数を変える。** 未配置 11 件を見て、別名（施設名 → 市名）で `compose_map` を
   もう一度呼ぶ。これは正しい判断である。
4. **引数を変えると別の操作になる。** `js/atlas-turn-results.js` の同一性は action の型と**引数**。
   `meta.resultKey` で「引数は違うが同じ結果」を名乗る仕組みは #R441 から存在したが、
   **`map.compose` はそれを使っていなかった**。`title` も `items` も変わっているので別キー、両方 `keep`。
5. **地図は 1 枚しか持っていない。** compose の描画元は `atl-compose-src` **1 本**で、2 回目の呼び出しは
   1 回目を上書きする。つまり **上に出ていた 5 件の凡例は、その時点で地図に存在しない印を説明していた**。

### ⚠⚠⚠ `__paintRun` は、自分で書いた行に自分で消されていた

`js/atlas-map-compose.js` には「同一ターン内は加算、ターンをまたぐと置換」という分岐があり、
#R489 の `__paintRun` を読んでいた。**その分岐は本番で一度も走ったことが無かった。**

```
runActions:  a.__paintRun = "run" + gen              ← 印を押す
             const _args = {}; Object.keys(a).forEach(k => {
               if (k !== "type" && k.slice(0,2) !== "__") _args[k] = a[k];   ← 同じ関数で剥がす
             });
             EXEC.execute(cap.id, _args, …)
```

`legacyExecute` は `args` だけで action を組み直すので、`COMPOSE.run(a)` に届く `a.__paintRun` は常に
`undefined`＝`prun` は常に `null`。

⚠ **「`__` を除外するのをやめる」は直しではない。** それをすると同一ターン内が本当に加算になり、
5 件 + 16 件 = **21 件**になる。実行文脈は**引数ではない**——モデルが書いてよいものでも、schema に
載るものでもない——ので、`cap.execute(ctx, args, opts)` の**第 3 引数**として運ぶ。

### 直した形 — 1 依頼 = 1 artifact、compose ごとに revision

- **artifact id はターンから導く。** `map:<turnId>`。同じターンの 2 回目は 2 枚目ではなく **revision 2**。
- **revision は地図全体を言い直す。** 追加でも差分でもない。
  - **追加にできない理由**: 16 件を再送されたら 5 + 16 = 21 になる。
  - **差分（未解決だけ）にできない理由**: 「君津製鉄所」を「君津市」で再試行したとき、
    その 2 つが**同じ対象だと知っているのは Atlas だけ**である。コードが綴りで突き合わせれば、
    それは推測になる（`.agents/rules/no-ad-hoc-hardcoding.md`）。
  - **言い直しは無料**である。置けた地点は台帳（`atlas-geo-ledger`）に入っているので、再掲しても
    ジオコーダへの問い合わせも待ちも発生しない。`exec.note` がそう明記して依頼する。
- **返信は `revision` の大きいほうだけを残す**（`js/atlas-turn-results.js`）。⚠ **点数では選ばない。**
  正直に `partial` と名乗った新しい版は #R441 の `score` で **2 点低い**。それでも地図が保持して
  いるのは新しい版なので、古い版を載せた返信は「もう無い印」の説明になる。
- **`map.compose` 専用の観測器。** 「頼まれた数」対「**いま地図に載っている数**」で判定する。
  ⚠ 増減の差分では見ない——**16 件を正しい座標へ直しても 16 → 16 で「描かれていない」になる**からで、
  これは今回の症状の裏返しである。

### なぜ一回で 16 件できなかったのか（表示とは別の問題）

解決は**逐次**で、Nominatim のレート下限は **1,100 ms**（`js/nominatim-gate.js`）、1 名につき最大 2 クエリ、
パス予算は 26 s。16 件なら**送信スロット待ちだけで 17〜35 s** になり、リストの後半は時計切れになる。

そのうえ Web 検証への一括エスカレーションが `reason !== "not_found"` で**時計切れを除外していた**。
この呼び出しは**名前が何本あっても 1 回**で全部を運ぶ設計なのに、**いちばん助かるはずの名前だけが
乗れなかった**。⇒ 理由を分け、回復可能な 3 つ（`not_found` / `timeout` / `not_attempted`）は全部載せる。

| 理由 | 意味 | Web 検証へ |
|---|---|---|
| `not_found` | その綴りの地物を gazetteer が持たない | ○ |
| `timeout` | 問い合わせ中に時計が尽きた（**存在の否定ではない**） | ○ |
| `not_attempted` | 順番が来る前に時計が尽きた＝**一度も訊いていない** | ○ |
| `over_item_limit` | 上限 24 を超えた分 | ×（数の問題） |

⚠ **`MAX_ITEMS = 24` の `.slice()` は黙って落としていた**（schema に `maxItems` が無いのでモデルは上限を
知りようがない）⇒ schema で**宣言**し（モデルが 25 件を送らなくなるのが構造側の直し）、runtime に
届いた超過分は `over_item_limit` として**報告する**。無言の切り捨てをやめる。

⚠ **町は工場ではない。** 未配置を市名に置き換えて 16/16 にするのは、完成度と引き換えに**精度を落とす**
操作である。置換するかどうかは Atlas の判断（`CONSTITUTION.md` §5）だが、`exec.note` は
**「概略位置だと読者に言え」**を要求する。コードが黙って同一視することはしない。

### ⚠⚠⚠ 正直になった途端、正直な答えが門に弾かれるところだった

`partial` を正しく伝えたら、**#R511 の出力宣言の門が誤作動する**ことが分かった。
`js/atlas-toolsurface.js` は `changedMap`（＝この呼び出しは地図を出した）を **`completed` のときだけ**
刻んでいた。それは 「partial ＝ 何も描かれていない」 という前提の上に成り立っていて、
`js/atlas-capabilities.js` の当時の partial は 17 件すべてがその通りだったので、当時は正しかった。

**map.compose がその前提を壊す。** 5/16 は partial だが、**5 本の印は本当に地図に載っている**。
古い行のままなら、`answer_mode:"map"` の回答が **`map_not_drawn`（地図が描かれていない）で差し戻される**
——読者が見ている地図について。そして差し戻しの回復手段は「compose_map をもう一度呼べ」＝**2 枚目のカード**。
今回消そうとしているものが、別の入口から戻ってくるところだった。

⇒ 判定を**完成度から観測へ**移した。事後条件を観測できなかった verdict は `produced: []` と名乗る
（17 件すべてに付けた。**どれも挙動は変わらない**——`completed` しか通さない門にそもそも到達していなかった）。
門は「status が何か」ではなく「**何か出たか**」を訊く。

⚠ この欠陥は**症状としては一度も観測されていない**。partial を正しく伝える変更を入れた**後で**
初めて到達可能になる経路で、検査 ⑪ を書いて mutation で赤を確認した。
### 検査（`tests/r551-checks.test.mjs`・11 本）

出荷モジュールを走らせる（#R505）。①artifact 同一性と revision ②版は置き換える（5+16=21 にならない）
③返信は 1 ブロック・**点数が低くても新しい版**が残る ④partial がカーネルまで届く ⑤同数・座標だけ修正でも
`completed` ⑥時計切れは `not_found` と区別され Web 検証へ載る ⑦25 件目は黙って消えない＋schema と runtime の
上限が同じ数 ⑧実行文脈が引数ではなく第 3 引数で届く ⑨partial は記憶しない ⑩note が「次にどうすれば終わるか」を渡す

⚠ **④⑤ は差分検査**である。同じ証拠に**旧 observer を並べて**「前の実装ならここで間違えた」を実測する。
④ で分かったのは、`paint` は `meta.partial` を**ちゃんと読んでいた**ということ——欠けていたのは観測器では
なく**モジュール側の申告**で、壊れていたのは片方ではなく**組み合わせ**だった。

⚠ **予算の検査は `now` を注入して実時計を使わない。** `ITEM_TIMEOUT_MS` は 1,000、`PASS_BUDGET_MS` は 2,000 の
**下限**を持つので `itemTimeoutMs:200` / `passBudgetMs:100` は効かない。最初に書いた版は 4 秒待ったうえ、
意図した `not_attempted` ではなく両方 `timeout` を測っていた（緑にならなかったので気づけた）。

⚠ **mutation で赤を確認した。** revision 規則・`resultKey`・`partial` をそれぞれ外すと ①③④ が落ちる。
⚠ そして**最初の mutation は効いていなかった**——`js/` は CRLF なので `/….*\n/` は当たらない（`.` は `\r` を
越えない）。「無害な修正を入れたのにテストが緑のまま」を、テストが通ったと読むところだった（#R548 と同じ形）。

### ついでに直した: 同じ事実を持つ手書きの一覧が 2 本あった

新しい観測器 `mapCompose` を足したら `npm run check:capabilities` が 2 つ落ちた——
`scripts/atlas-capability-audit.mjs` が「どの観測器が地図を見ているか」を **2 か所に手で並べて**いた
（⑦ の `OBSERVABLE` と ⑱ の `MAP_OBS`）。観測器を 1 つ足すと**両方**に書かないと監査が自分自身と
食い違う。⇒ `MAP_OBS` を `OBSERVABLE` から**導出**した（1 回登録すれば全部に効く）。
導出結果は**旧の一覧＋`mapCompose` ちょうど**で、失われた項目は無いことを実測して確かめた。
### 綴りを固定していた検査 3 本（どれも「正しい実装を欠陥と呼んだ」）

| 検査 | 何を固定していたか | 事実で訊く形へ |
|---|---|---|
| `tests/r511 ⑨` | dispatch 行の綴り・observer 名 `paint` | 新しい綴り／`mapCompose` |
| `tests/r515 ③` | note の文言 `/compose_map again/` | note が**道具の名前と artifact の名前**を含むか |
| `tests/r376 ①b` | `const MAP_OBS = [… 'wxModel' …]` という**手書き配列** | **監査を実際に走らせ**、wxModel を観測器とする能力が `map-verified` に落ちないこと |

⚠ とくに `r376 ①b` は、**その配列を消したこと自体が守りたい事実を構造的に真にした**のに赤くなった
（#R488 / #R529 / #R546 と同じ形）。この検査は #R495 で一度「位置ではなく所属」に緩められており、
今回で**ソースを読むのをやめて監査を走らせる**形になった。変異試験（`OBSERVABLE.wxModel` から `map` を
外す）で赤を確認している。

### 残していない直し（意図的に採らなかった案）

| 案 | 採らなかった理由 |
|---|---|
| 最後の compose だけ表示 | 意図的に独立した 2 枚目まで消える。identity の問題を表示で隠すだけ |
| HTML 完全一致の重複排除 | `composeId` が毎回変わるのでそもそも一致しない。#R441 が同じ壁に当たっている |
| `__` の除外をやめる | 同一ターン加算が本当に効いて 5+16=21 になる |
| `PASS_BUDGET_MS` を伸ばす | 逐次・partial 伝播・identity は残る。待ち時間だけ伸びる |
| Nominatim を `Promise.all` | 公開エンドポイントのレート方針違反。gate は正しい |
| 未配置を市名へ自動置換 | 意味的対象を**コードが**すり替える。判断は Atlas のもの |
