## R291 — **経路の全面監査と作り直し。最初に見つかったのは欠陥ではなく、扉が無かったことだった**

> 「IntMapの経路機能を全面的に監査し、Google Maps・Apple Maps・Wazeと比較して不足している機能、
> 使用感、UI、モバイル対応、アクセシビリティ、信頼性を改善してください。単なる見た目の模倣ではなく、
> IntMapが既に持つ高度な経路分析機能を残したまま、日常利用でも自然に使える経路計画機能へ作り直して
> ください。」

### ⓪ 監査の最初の1件 — この機能には入口が無かった

指示書は27節・200項目あり、最初にやったのは §1 の現状監査である。そこで出てきた最初の事実が、
残り26節の前提を変えた。

**`js/routing.js` の `openPanel` は #R84 から export されていて、プログラムのどこからも呼ばれていない。**
`js/`・`index.html`・`js/map-ui.js` のツール一覧・右クリックメニュー・コマンドパレット・`IntMapOS`
のすべてを `openPanel` / `route-panel` / `IntMapRouting.` で検索した結果が**呼び出し 0 件**。
交通手段の切替・経由地・有料道路／高速／フェリーの回避・地図に描く通過禁止範囲・公共交通の
モード絞り込みと徒歩上限・6つの分析（標高・国境・沿道・到着時刻・経路差・過去の路線網）を
持つ経路パネルが、**7ラウンドのあいだ誰にも開けなかった**。経路に到達する唯一の道は
「Atlas に文章を打つ」だった。

これは #R261 が5つのシミュレータで見つけたのと同じ形（扉の無い機能）で、こちらは
**日常機能**である分だけ高くつく。だから §26 の P0 の1番が「Layers → Tools の正式入口」なのは
正しく、この回はそこから始めた。

⚠ もう一つ、`js/map-tools.js` の海路パネルも `id='route-panel'` を名乗っていた——**同じ id が
2つ**。新しいパネルは同じ id を使うが、旧パネルは削除したので重複は解消している。

### ① 入口 — Layers ▸ Tools ▸ Directions／経路

`js/map-ui.js` の `SIM_TOOLS` の**先頭行**。シミュレータより上に置いたのは、これが特殊機能では
なく日常機能だからである。

- `run` は `_lazy('routeUi', …)`。**パネルは押されて初めて取得される**（`js/lazy-modules.js` の
  10本目）。ルーター自体は eager のまま——Atlas はパネル無しで経路を出せなければならない。
- `mod:'IntMapRouteUI'` があるので、行は `isOpen()` を毎回訊く。**2度目の押下はパネルを閉じる**
  だけで、経路は地図に残る（§2.2）。
- `dot:()=>IntMapRouteStore.hasRoute()` — **経路はあるがパネルは閉じている**という状態を、
  「開いている」とは別の控えめな印で言う。
- `keys:'route directions … 経路 ルート 道順 …'` と、レイヤー検索が**ツール行も絞る**ようにした
  （これまで検索はレイヤータイルだけを絞り、ツール行には触っていなかった）。
- **地図上に常設のボタンは1つも足していない**（§0/§2.1）。

### ② 状態 — 2つあり、互いを読めなかった

`_rsets`（routeSetId ごとの候補と選択）は #R126 から共有で、そこは正しかった。問題は**同じ
クロージャの中**にあった `pFrom / pTo / pVia / pMode / pAvoid / pAreas / pTModes / pMaxWalk /
pLastResult` で、これらは**パネルの私有変数**である。Atlas は1つも読めず、1つも書かなかった。
「Atlas で『車で』と言った」と「パネルの 🚗 を押した」は、同じ旅についての**別々の事実**だった。

→ `js/routing-store.js`（`window.IntMapRouteStore`）。DOM も地図も fetch も触らないので、
状態遷移は Node で検証できる（`tests/r291-checks.test.mjs`）。

- **確定した地点と未確定の文字列を別々に持つ。** `setText()` が地点を無効化し、`points()` が
  半端な欄をルーターに渡さない。#R126 の規則が「習慣」から「性質」になった。
- **`route()` は誰が呼んでも store に着地する。** Atlas も パネルも同じ関数を通るので、経路を
  引いたあとの状態は1つ。
- **古い応答は状態にならない。** ルーター側の requestId が「描かない」を保証し、store の
  `settle(id,…)` が「状態にならない」を保証する。
- **入替は旅程全体を逆順にする。** `A → 1 → 2 → B` の入替は `B → 2 → 1 → A`。旧パネルは
  `const tmp=f.value; f.value=t.value; t.value=tmp;` で**両端だけ**を交換しており、経由地の順は
  そのままだった——それは同じ2点を結ぶ**別の旅**である。

### ③ 検索 — 「検索」ではなく「1件の決め打ち」だった

`geo1()` は候補を5件取り、`_pickNear()`（300km 以内の最寄り、無ければ最大人口）で**1件に決め**、
それを欄に書いた。#R126 がその順位付けを足したのは正しい（「ドイツを見ているのに Potsdam NY」）。
間違っていたのは、それが**最後の一言**だったこと。同名・同規模の2つが40km離れているとき、
どちらが勝ったかを知る方法は**あとで地図を見ること**しかなかった。

→ `js/routing-geocode.js`。順位付けはそのまま、**リストを返す**。確定するのは、利用者が選ぶか、
地図を押すか、現在地か、座標を打つかの4つだけ。

- 出典は4つ——座標（**どこにも送らない**）／新幹線駅の完全一致（「仙台駅」が寿司屋にならない）／
  Open-Meteo（人口と admin1 を持つ）／Nominatim（住所・駅・空港・港・POI）。
- ⚠ **Nominatim の利用規約は 1 req/s。** 240ms のデバウンス＋**ここでの流量制限**（窓の中の要求は
  待たせず捨てる）＋同一クエリの5分 LRU。3文字未満では Nominatim を呼ばない。
- ⚠ **利用者の座標は問い合わせに入らない。** 近接は**応答が届いたあとの順位付け**にしか使わない。
- 現在地は**押されたときだけ**許可を求める。パネルを開いただけでは訊かない（§4.3）。

### ④ 描画 — 同じ経路が2か所で組まれていた

`js/atlas-console.js` の `.atl-trip` / `_legRow` / `_stepList` / `_ic()` と、`js/routing.js` の
`.rp-alt` / `legRows()` / `stepRows()` / `_modeIcon()`。**比べられたことがなく、見える形で食い
違っていた**：

- Atlas は**リアルタイム札と遅延**（`● +3 min late`）を出し、パネルは `_buildItin` で `rt` と
  `delay` を計算しておいて**どちらも描いていなかった**。同じ列車が、片方では「live」で
  もう片方では無言。
- Atlas は候補ごとの発着時刻を出し、パネルは合計だけ。
- **どちらも測定単位の設定を見ていなかった**（km 決め打ち）。

→ `js/routing-cards.js`。純関数（データ, オプション）→ HTML。両方が呼ぶ。

- 図形は**SVG**（絵文字は使わない）。アイコンは `aria-hidden` で、名前は**本物の文字**として隣に置く。
- 「リアルタイム」は上流が `realTime === true` にした区間だけ。**一部だけなら「一部リアルタイム
  (1/2)」**、遅延0は「定刻」（「+0分」とは書かない）。
- 車線案内の `▮▯` は**言葉にする**（「車線: 2, 3 ／ 3」）。
- 距離は `metric / imperial / both` に従い、時刻はアプリの時計タイムゾーンで、日をまたぐ到着は
  「（翌日）」と書く。

### ⑤ プロバイダーの能力は表であって `if` ではない

3つのルーターはほとんど何も一致していない。それが**条件文として散っている**あいだ、UI からは
見えない——押しても何も起きないボタンはそうやって出荷される。

`js/routing-providers.js` は同じ事実を**データ**にした。UI は「これを出してよいか」をここに訊く。

| | OSRM | Valhalla | MOTIS |
|---|---|---|---|
| 代替経路 | 3（**経由地があると 0**） | 1 | 5 |
| 回避（有料/高速/フェリー） | ✗（demo は `exclude=` を拒否） | ✓ | — |
| 通過禁止範囲 | ✗ | ✓（徒歩・自転車も） | — |
| 出発/到着時刻 | ✗ | ✗ | ✓ |
| ライブ交通 | ✗ | ✗ | ✗ |
| リアルタイム公共交通 | — | — | ✓ |

⚠ **`liveTraffic: true` はどの行にも無い。** だから道路の所要時間は常に「標準所要時間・リアルタイム
交通量は未反映」と書く（§7.2）。この表が、将来「渋滞考慮」という語を**データ無しで**足すことを
止める。

そして**選ぶことの代償を言う**ようにした：

- 経由地があるので代替経路が1本 → 「経由地を含むため、このプロバイダーでは代替経路を取得できません」
- 回避条件を Valhalla が処理したので1本 → 「回避条件は1経路のみを返すプロバイダーで処理しています」
- 回避条件／通過禁止範囲が**適用できなかった** → それぞれ別の文で（適用できなかった範囲を
  「黙って通る」ことは無い）
- 「高速道路を回避」は Valhalla では `use_highways=0.1` の**強い優先**であって禁止ではない、と書く

### ⑦ 自分で書いた欠陥を、テストが2つ捕まえた

- **タイムゾーン変換の符号が逆だった。** `getTimezoneOffset()` は「UTC − ローカル」なので端末
  オフセットはその**負**。`+` で書いたため端末オフセットの2倍ずれ、UTC+9 の機械では 14:30 の
  出発が**18時間前**になった。名前のあるタイムゾーンで検算する Node テストが無ければ、
  「自分の端末では合っている」で通っていた。
- **候補カードを押しても何も起きなかった。** 押下処理が `.rtp-alt`（このファイルの接頭辞）を
  探していたが、描画側の `js/routing-cards.js` は `.rt-alt` を出す。1文字の不一致で分岐が
  一度も成立しない。同じ日に**同じ形**をもう1件やっている——`note()` が `.rt-note` を出すのに
  CSS が `.rtp-note` を定義していて、正しい文が**素のテキストで**出ていた。

### 追記（本番検証） — **本番検証で1件：カードの差別化ラベルだけが言語切替についてこなかった**

本番（`R291` の配信済ビルド）で確かめた項目はすべて緑だった——入口・遅延取得（押す前は
`IntMapRouteUI` が `undefined`、押したあと `object`）・候補カード・地図の A/B とヒット領域・
閉じても残る・再オープンで復元・候補一覧・携帯のボトムシート（320px で横にはみ出さない）。

**1件だけ見つかった。** 経路を出してからアプリを日本語に切り替えると、周りがすべて日本語になった
中で**候補カードの差別化ラベルだけが「Fastest」のまま**だった。

原因はパネル側ではない。カードの**他の文字列は全部描画時に作られている**——正直な注記は
鍵（`note('roadTypical')`）、距離と時刻は `js/routing-cards.js`、手順の文は毎回 `maneuver()` を呼ぶ。
だから `intmap-lang` の再描画で全部直った。直らなかったのは `a.label` だけで、それは
**経路を計算した時点で `LL(...)` を解決して焼き込んだ文字列**だった。

> [[intmap-recurring-lessons]] の「翻訳をデータとして持つ」の**1段上の形**。#R241 が見つけたのは
> 「配列で持った翻訳を言語番号で引いている」だった。こちらはタプルでさえない——**一度解決して
> 文字列になってしまったものは、二度と解決できない**。i18n ゲートはこれを見ない（呼び出し側は
> 正しく 5 引数の `LL(...)` であり、全言語分ある）。**見えるのは実際に切り替えたときだけ**。

### 直し方：ラベルを「文」から「記述子」へ

`js/routing.js` の `_labelRoad()` が `a.labelKey = {k:'fastest'|'shortest'|'delta'|'route', min, avoid}`
を書き、`IntMapRouteCards.altLabel(a, o)` が**その瞬間の言語で**文にする。

⚠ **`a.label`（文字列）は消していない。** Atlas の返答は**永続的な会話履歴**で、その時の言語のまま
残るのが正しい（過去の発言を後から翻訳し直さない）し、`tests/r184-routing` がこの名前を読んでいる。
古い候補（`labelKey` を持たないもの）は `altLabel()` が `label` をそのまま返すので、**何も失わない**。
