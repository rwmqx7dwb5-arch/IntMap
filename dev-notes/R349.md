## R349 — **1850 まで下げ、両大戦を日ごとに**

依頼は2つだった。「IntMapは、1850年までさかのぼれるように。（1900までと完全に同様に。単に対応年を
延長するだけです。）」と「また、WW1, WW2の月日ごとの勢力変遷も見れるように。」。範囲は着手前に確認して
いる——**全戦域**・**面＋線＋主要な作戦の地点**・**レイヤー1行＋Chronos 連動**・**出典が届く範囲まで全部**。

### ⚠ 「窓の下限」を政体の開始年として書いていた

`js/time-borders.js` の時代→記事の表は、大半の行が `1900` から始まっていた。それは**フランス第三共和政が
1900 年に始まったから**ではなく、**そこで時計が止まっていたから**である。`1900` は「これ以上前は誰も
訊けない」という意味の数で、**下限を動かした瞬間、その全部が新たに到達可能で新たに誤りな主張**になる
——1875 年のフランスをクリックすると、成立の5年前の第三共和政に解決する。各行を**その政体自身の
開始年**（または 1850）にし、1850–1900 に在った政体は**自分の期間**を持つようにした（第二共和政 1850–52／
第二帝政 1852–70／ドイツ連邦 1850–66／北ドイツ連邦 1867–71／江戸幕府 −1868／サルデーニャ王国 −1861／
オーストリア帝国 −1867／東インド会社統治 1850–58／朝鮮 −1897／ブラジル帝国 −1889／コンバウン朝 −1885／
清朝統治下の台湾 −1895 ほか）。**28 本の記事名は en.wikipedia の API で実在を確認**し、リダイレクトの
4本は正規の題へ寄せた。

同じ形が `js/history.js` にもあった。**オスマン帝国の `from` は 1876**——アブデュルハミト2世の即位年で、
帝国の開始年ではない。`activeAt()` はこれを**国家の存続期間**として読むので、1850–1875 は帝国を隠し、
**トルコ・シリア・レバノン・イラク・ヨルダン・イスラエル・パレスチナの7つ**を主権国として並べる
ところだった。1299 に直した。**東インド会社統治**（1773–1858-06-27）も足した——同じ領域・同じ3つの
後継国で、これが無いと 1850–57 はインド・パキスタン・バングラデシュが3つの独立国になる。

### ⚠ 下限は4か所に書き写されていた

`js/news-timeline.js` はスライダーの `min`・入力のガード・反映のクランプ・目盛りの先頭に `1900` を
持っていた。**食い違い方が静か**である——1900 で止まるスライダーは 1850 にドラッグできないだけで、
どこも故障を報告しない。全部 `IntMapTime.min` を**実行時に読む**ようにした。

### ⚠ MAXGAP は「代替」を守る規則で、「唯一の出典」には当てはまらない

年次の国境は CShapes 2.0 が **1886–2019**。それより下はスナップショットで、上流（historical-basemaps）が
持っているのは **1815 と 1880 の2枚だけ**——その間には1枚も無い。`nearest()` の `MAXGAP=20` は
「隙間が広いなら前へ飛ばない」規則なので、**1815→1880 の 65 年**に当たって 1875 年に**1815 年の地図**を
返すところだった（60 年古い）。あの上限の目的は「年次の出典があるのに degraded mode が 1980 年に
post-Soviet の世界を描く」ことの防止で、**1886 年より下ではスナップショットは代替ではなく唯一の出典**
だから、近いほうを採るのが最善の答えになる。`y < CS_MIN` で外した。実測: 1875→1880・1850→1880・
1830→1815・1980→1960（degraded の防護は生きている）。

### 出典が届く範囲まで、それぞれ

`data/maddison.json` は 1900–2018 しか入っていなかった。それは**出典の限界ではなく、旧下限の限界**で、
Maddison Project Database 2020 はほとんどの国を 1820 年から持っている。`scripts/build-maddison.mjs` が
上流（OWID がミラーする MPD2020 の CSV）から**1850 年まで延長する**。⚠ **延長であって書き換えではない**:
実測 **changed 0 / removed 0 / added 1,792**。168 コードのうち **153 は 1900–2018 を1セルも違わず再現**し、
残り 15 は**丸めの ±1 だけ**（ベルギー 1967 は 9,556.5 千人——committed 側は切り捨て、ミラーは切り上げ）。
その 15 を再丸めするのは、1850 に届く話の中で**誰も頼んでいない 15 個の数を黙って変える**ことなので、
**committed の値を通し、代わりに毎回照合する**（許容を超えたらビルドが落ちる）。`js/history.js` の
`minYear` は**読み込んだファイルから測る**ようにした——横に置いた literal は「そこにある数を範囲外だと
言い続ける」形の食い違いを作る。気候区は最古のラスタが 1901-1930 なので、それより前もその期間を出す。
**凡例に期間セレクタがあり、現在の期間名がそこに出ている**ので、1875 年に 1901-1930 を見ている読み手は
そう言われている。

### 記録は文であって、ポリラインではない

戦線の日ごとの公開データセットは（探した範囲では）存在しない。存在するのは**日付入りの地図**（大半は
まだ著作権下）と、**書かれた記録**である。記録は歴史家が書く形をしている——「1941年12月5日、戦線は
レニングラードからチフヴィン、カリーニン、クリン、トゥーラ、イェレツを通ってロストフへ」。だから
`scripts/wars/` は**記録をその形のまま**持ち、`scripts/build-wars.mjs` が幾何にする。`places.mjs` が
名前→座標の**唯一の場所**（239 件は同梱の gazetteer と 30 km 以内であることを照合。⚠ 6件は gazetteer が
**同名の別の場所**を知っている——ここの Kalinin は Tver の戦時名で、gazetteer の Kalinin は千キロ離れた町。
Midway はここでは環礁、gazetteer では米国の町。**名前で例外にして理由を書く**ほうが、全部の許容を
緩めるより狭い）。

**⚠ 記録が位置を伝えていない日には線を引かない。** 最後の位置を保持し、**凡例がその線の日付を出す**。
補間して滑らかに動かすのは、誰も書いていない主張を描くことになる。同じ理由で**ポケットは線ではない**
——トブルク（1941）・セヴァストポリ（1942）・クールラント（1945）・バストーニュ（1944-12）は、前線が
百キロ先にある側が保持していた場所で、1本の線では描けない。**それぞれ作戦（点）として持ち**、塗りは
囲んだ側に渡す。既知の・限られた過小申告であって、包囲を切り抜くために2つ目の多角形を発明することは
しない。**太平洋には前線が無かった**ので線も引かない——島嶼戦は「どの場所がいつ手を変えたか」であり、
それはまさに `control` と `events` が持っている形である。

### ⚠⚠⚠ 最初の緑のビルドは、どの門も訊いていない3か所で間違っていた

全部の門が緑になったあとで、よく知られた事実を並べて**自分で照会した**（`WarGeom` に通して都市の
所属を出す小さなスクリプト）。3件出た。**どれも門が「合格」と言っていた**。

⑴ **1943年7月のクルスクとオリョールの突出部は<b>噛み合っている</b>**。ドイツ側がオリョールで**東へ**、
ソ連側がクルスクで**西へ**張り出しており、その間をまっすぐ引いた線は**オリョールを1か月早く赤軍に渡す**
（実測 AXIS のはずが ALLIED）。⇒ 線をボルホフ→ノヴォシリ→マロアルハンゲリスク→セフスク→ルイリスク→
ベルゴロドと折り、両方の突出部を通す。

⑵ **軍が降伏したあとも戦線が切り続ける**。`until` の無い戦線は最後に引かれた線を保持するので、
**イタリアは 1945年5月2日に全土が連合国**、**ドイツの多角形は 5月7日で終わる**のに、9月まで分割された
ままだった。⚠ CShapes はドイツを 5月8日に**2つの占領地区（gw260 / gw265）に置き換える**ので、
「8月にベルリンを誰が持っているか」は 255 ではなく**その2つ**への質問になる。

⑶ **休戦とその次の引用可能な線のあいだに、線が無い**。イタリアは 1943年9月8日に枢軸から出て、翌朝には
ドイツが北部を押さえた。ヴォルトゥルノ（10月1日）までの3週間に引ける線は無いので、**その3週間は
CONTESTED**——国を一色に塗るより小さく、そして真である。

⚠ そして**アンカーの都市は「線の上」なので、どちらの側でもない**。ヴェルダン（1916）とハリコフ（1943）は
どちらも線の点で、**街そのものは陥ちていない／陥ちている**のに答えが逆に出た。⇒ 記録の言い方
（「線はヴェルダンを通った」）から**実際の前線の点**へ（ドゥオモン要塞・イジューム）。
⇒ 7件を `scripts/build-wars.mjs` と `tests/r349-checks ⑦` の両方に足した（**47 件**）。

### ⚠ 面は保存しない——線から切り出す

東部戦線 1本でも日付は数十あり、切る相手はソ連＝**136 ポリゴン**。両側を日付ごとに持てば、ほとんど
同じ海岸線を数十 MB 運ぶことになる。**線を運べば `data/wars.json` は全部で 58.8 kB** で、海岸線はもう
読み手の機械にある（`data/cshapes.js`——タイムマシンが読む）。切断は `js/war-geom.js` の**1本**で、
**ビルドとブラウザの両方**がそれを import する（`tests/r175 ③` が名前で束ねる）。2つ目の写しは
**線が国の輪郭を60km west に切っているのに、塗りはハリコフをドイツ側に置く**という形で静かにずれる。

### ⚠ 「交差はちょうど2回」は、厳しいのではなく世界について間違っていた

最初の切断は「1つの環は 0 回か 2 回だけ交差される」と決めていた——前線は国を横切るのだから、入って
出る、という理屈で。**実測: 記録された 41 本の線のうち 34 本が拒否された**。国境の町2つを結ぶ弦は、
実際のギザギザな国境を何度も跨ぐ。⇒ 一般化した。**交差は経路に沿って対になる**（経路は国の外から
始まるので、その arc は 内・外・内・外 と交代する）ので、path 順で `j XOR 1` が連結子になり、包含判定は
要らない。**奇数回だけ**が今も故障（＝延長が国から出られていない）。検査は合成図形で**面積が保存される**
ことを見る（8回交差で片側が3片になる鋸歯を含め、誤差 1e-6 未満）。

### ⚠ 延長が長すぎて、同じ国を2回切っていた

最初の版は端を「多角形の径×2」まで伸ばしていた。ソ連ではそれが **340°** で、「延長」がアジアを
回り込んで**前線が一度も無かった場所で**国をもう一度切っていた。⇒ 端点が多角形の外に出るまで
**1.6 倍ずつ**伸ばして止める。届く距離を決めるのは**越えるべき国境**であって、その後ろにある国の
大きさではない。

### ⚠⚠⚠ 2つの戦線が同じ国を切るとき、「1本を選ぶ」も「合成」も間違い

ソ連は 1941–44 のあいだ、**東部戦線とフィンランド戦線の両方**に切られている。

⑴ **最後に宣言された戦線を選ぶ**——実測、**カレリアの線が「1942年11月にロストフを誰が持っていたか」に
答えた**。
⑵ **A で切ってから、その断片を B で切る**——こちらのほうが悪い。フィンランドの線はカレリアの首を
横切るが、その首は**東部戦線がすでにドイツに渡した断片**の一部である。だから「フィンランド線の反対側」が
**ドイツ占領下のウクライナ全部**になり、一手でソ連側に貼り替わる。実測、どちらもロストフが ALLIED
（記録は AXIS）。

⇒ **幾何と標識を分ける。** 切断は**セル**を作るだけ——2本の線が国を3〜4片にするのは算術である——
そのうえで各セルを、**その線がいちばん近い戦線**が、**セルがある側**で標識する。東部戦線の近くでは
東部戦線が決め、カレリアではフィンランド戦線が決め、**千キロ離れたものは何も貼り替えられない**。

### 門 — `scripts/build-wars.mjs` と `tests/r349-checks.test.mjs`（8本）

ビルドは**証明できないものを書かない**: 地名が表にあるか、gazetteer が知っている座標と 30 km 以内か、
gwcode が**その日付に**実在する CShapes の実体か、線が**切ると主張した国を実際に切る**か、そして
**名指しの都市が記録どおりの側に落ちるか**（38 件）。最後のものが、**両側の形は正しいのに左右が逆**と
いう欠陥を捕まえる唯一の検査で、`WarGeom` を通して——**ブラウザが描くのと同じコードで**——評価する。

⚠ **門が本当に落ちることを実ファイルで確かめた**: `data/wars.json` の 1940-06-25 の分界線の左右を
入れ替えると `tests/r349-checks ⑦` **だけ**が赤くなり（パリが NEUTRAL、ヴィシーが AXIS と報告）、
戻すと緑に戻る。⑦ は**出荷された JSON** を読むので、訊いているのは「読み手が何を見るか」であって
「著者が何を意図したか」ではない。

ブラウザ側の2本（`tests/smoke.spec.js` の `#R349 …`）は: スライダーが**手と同じやり方で** 1850 まで動くこと、1875 年
（年次の出典が届かない年）に**実際に多角形が到着**して 1880 のスナップショットだと名乗ること、そして
**`queryRenderedFeatures` がミンスクで AXIS・モスクワで ALLIED を返す**こと。⚠ 2つの都市は**同じ
CShapes の多角形（ソ連）の中**にあるので、両者を区別できるのは切断だけである——切れていない層は
両方に同じ答えを返し、左右が逆の層は両方に逆の答えを返す。

### ⚠ Browser ペインでは地図が完成しない——が、そこで本物の欠陥が出た

`canDraw()`（＝`GE().ready()`）はペインの中で永久に false のままで、レイヤーは一度も描かれない。これは
#R313/#R314 が記録している制約そのもの（`document.hidden` 固定）で、検証は Playwright の可視ページで
行った。ただしそこで**実装の欠陥**が1つ出た: スタイルが未完成のとき `paint()` は `false` を返して
**それきり忘れて**いた——読み込み中に行を入れた場合や、地図が落ち着く前に Atlas が日付を指定した場合、
読み手が時計をもう一度動かすまで層は黙って空になる。⚠ そして再試行を `once('idle')` で書くのは
**この場合いちばん悪い**——**すでに idle な地図はもう二度と発火しない**、つまり満たすのが最も容易な
状況でだけ永久に来ない。短いポーリングにした。

### ⚠ 起動予算が「行だけを eager に」と言った

最初は `js/war-fronts.js` を丸ごと eager にしていた。`npm run check:perf` の実測は
**eager raw +24.3 kB / gzip +8.4 kB / modules +2**——**既定 OFF のレイヤーのために、全セッションが**
払う分である。これはまさに #R311 の予算が気づくために存在する事象で、#R311（6サブシステム）も
#R322（`js/analysis-panels.js`）も同じ答えを出している: **起動時に何かを登録するものは eager、
本体は後**。

⇒ `js/war-fronts.js` は**行と IntMapOS の2命令だけ**（6.5 kB）になり、塗り・戦線・凡例・切断は
`js/war-layer.js`（on-demand・`__imWarFronts`）へ移した。⚠ **行そのものは遅延できない**——
「見えないレイヤーを探し当てて初めて現れる行」は行ではない。実測 **modules +1**、`war-layer` は **18.1 kB の async チャンク**。
⚠ この round 全体の eager 増は **raw +14.8 kB / gzip +5.1 kB** で、その大半は分割の残りではなく
**1850 側**——時代→記事の表・東インド会社の旗・目盛りの導出は、どれも eager な `js/time-borders.js` /
`js/history.js` / `js/news-timeline.js` の中にある。
⚠ 公開する名前を `IntMapWarFronts`（行の façade・eager）と `__imWarFronts`（本体・lazy）に分けたのは
#R322 と同じ理由で、`js/atlas-controls.js` が `window.IntMap*` を**列挙で**見つけるから——同じ機能に
2つの `IntMap…` があると、planner には capability が2つあるように見える。

### 触れなかったもの

戦線の記録は**西部・東部・イタリア・バルカン・中東・北アフリカ・中国**の 13 戦線・**60 本の日付**で、
太平洋は前記の理由で `control` と `events` だけ。日本は**この窓の初日から枢軸**として描く（対中戦争は
1937 年から続いている）——三国同盟（1940-09-27）は出来事として並んでいるので、読み手はどちらがどちらの
事実か見分けられる。フィンランドとタイは**枢軸の共同交戦国**という独自の側で、加盟国とは色が違う。
