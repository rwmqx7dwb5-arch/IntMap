### 1. ⚠⚠⚠ `map.highlight` が `targets` を読む器と読まない器に挟まれて、名前の一覧が丸ごと消えていた

**失敗 31 件のうち 14 件が `map.highlight`** で、全部同じ形。同じ 16 個の文字列を、同じ本番で、1 手違いで:

```
map.highlight {targets:["Botswana","Burkina Faso",…]}    → failed/failed
map.highlight {countries:["Botswana","Burkina Faso",…]}  → completed/ok
```

`targets` は `js/atlas-catalog-text.js` が**最初に**documenting している形である。5 問が踏んだ
（アフリカの内陸国／左側通行の国／ブラジルの隣国／ユーロ導入国／中露両方と接する国）。どれも読者には

> ⚠ Nothing is highlighted yet — name the countries or regions

が出た——**10〜54 か国を名指した命令に対して**。「アフリカの内陸国」は `repeated_calls` で終わり、
地図に何も描かれず、訊かれた数も答えられなかった。

正体は **#R742 の修正が約束した落とし込みが、落ちる先に届いていなかった**こと。
`js/atlas-country-ids.js` は名前だけの要求に `null` を返す——**わざと**で、それが「具体地名の解決器へ
落ちる」合図である。ところがその解決器は `js/atlas-console.js` の中に**自分の欄の一覧を手で書いて**
おり、そこに `targets` が無かった。⇒ 要求はどちらの器にも読まれずに消えた。
本番実測で `resolveHl('Botswana')→BWA`、16 件すべて解決する。

⇒ **欠陥は「一覧に `targets` が無かった」ではなく「一覧が 2 つあった」。** どの欄が要求を運ぶかを
述べる場所を `js/atlas-country-ids.js` の `REQUEST_FIELDS` 1 か所にし、**両方の器がそれを取る**。
次に欄が増えても、片方だけに入ることが構造的に起きない。

### 2. ⚠⚠⚠ 取り除く操作が「何も現れなかった」ことを理由に失敗と判定されていた

`map.clearHighlights` と `highlight {on:false}` は汎用 `paint` の判定に乗る。その最後の行は
「何も動かなかった ⇒ `not_rendered`」で、**既に片付いた地図を片付けると何も動かない**。実測:

```
「Colour the world by population density」   reset:FAIL/not_rendered ×6（16 操作のうち 6）
「Turn off everything you turned on」        highlight:FAIL/not_rendered ×5 · 44s · repeated_calls
                                            （同じ瞬間の Objects パネルは「0 on the map」）
```

⚠ **同じ欠陥は `map.clear` については既に直してあった**（`clear` の判定に移してある）。
`js/atlas-capabilities.js` のその直下のコメントが理由まで書いている。**規則がその 1 行に付いていて、
事実に付いていなかった**——[[intmap-hist-names-rule-belongs-to-the-name]] と同じ形。しかも
`highlight {on:false}` は**描く能力そのもの**が消す経路なので、行を付け替えても届かない。

⇒ **#R742 の宣言に、もう半分を足した。** 描いた側が「何を描いたか」を述べる仕組み（`meta.painted`）に、
**「この面はこれから空であるべき」**を述べる形（名指しした面の空配列）を足し、判定は**在ることを
確かめるのと同じやり方で、無いことを確かめる**。⚠ **読むのであって信じるのではない**——
6 か国が塗られたまま「消した」と宣言すれば、判定は今までどおり `not_rendered`。
⚠ **`{}` と宣言の不在は今までどおり `null`**（何も述べていないものは主張ではない）。

### 3. ⚠⚠⚠ 1 個を名指されて 16,010 個を描き、回答文は「1 個だけ置いた」と述べた（#R742 §8 の残件）

「Where is the ISS right now? Put a **single** marker on it.」→ Atlas は**正しいものを要求している**
（`satellites "ISS"`）。判定は `ok`。回答文は「I placed the single live ISS marker and ground track」。
**地球は端から端まで水色の点で埋まった。** ISS の詳細カード（高度 418 km・7.66 km/s・次のパス 3 本）は
完全に正しい。

`name` は**焦点**しか選ばず、propagate されるカタログを決めるのは `group` だけで、既定は
`active`（**16,010 機**・3 MB）。⚠ この数は**本番で数えたもの**（2026-09-16、レイヤーを点けて
`A.state().catalogue`）——`GROUPS[].kb` は**ダウンロードの宣言サイズ（KB）であって機数ではない**。
`js/atlas-catalog-text.js` はこの挙動を**自分で書いており**
（「thousands of dots around the one object when they asked about a single satellite」）、
persona は**明示的に禁じている**（「a question about one object is not a reason to draw thousands」）。

⇒ カタログを**選ぶ**。⚠ **隠れたフィルタではない**——#R266 が「ここから見えるものだけ」の
チェックボックスを外したのは、まさにそれが「カタログが持つより少なく描く 2 つ目の無言の道」だったから。
カタログは製品が認めた道で、返答がその名前と機数を述べる。⚠ **名前の表は作らない**——CelesTrak が
中身を決めるので、**小さいカタログに「持っているか」を訊く**。⚠ **もともと取るはずだったバイト数で
上限を切る**（今選ばれているカタログの `kb` を超えない範囲で、小さい順に）。絞れなければ今までどおり。

### 4. ⚠⚠⚠ 店が自分の鍵を受け付けなかった——#R742 が highlight で直した形の、1 つ隣の読み手

「List every active volcano in Indonesia」の**同じ 1 ターンの中で**:

```

data.query {from:'volcanoes', where:[{country '==' 'Indonesia'}]}   → 101 Volcanoes
```

[[intmap-store-refused-its-own-key]]。国名とコードの対応は `iso2to3` が既に読んでいる**同じ
`countryStats` の記録**なので、訊くのは店自身の申告を読むことであって綴りの推測ではない。

⚠ **「1 件も一致しなかった」と「この表には訊けない」は別の答えで、同じ空の答えになっていた。**
行が国を 1 つも名乗らない表は、**名指しで拒否**する（0 件を完全な答えとして出さない）。

### 5. ⚠ 年が数量として印字されていた

同じ表が読者に **「LAST KNOWN ERUPTION  2,022」「1,952」** を出していた。`fmt()` は 1000 以上を
桁区切りする——人・メートル・ドルには正しく、**時点の名前**である唯一の数には誤り。
`kind` は `number` のまま（順序と全ての数値述語がそれを読む）。変えたのは**印字だけ**。
⚠ **最初の版は `fmtYear` を `elevM` に付けていた**（`fmt()` は自分の書式化器があれば即 return するので、
桁区切りだけでなく**単位 m まで落ちる**）。**この回の検査がそれを捕まえた**
——[[intmap-my-own-fix-had-the-shape-i-was-fixing]] を踏みかけた。

### 6. ⚠⚠⚠ 目録が「これを使え」と名指しした行動が、手の中に無い唯一の行動だった

⇒ `data.query` を CORE に入れた（`query_data`）。⚠ **何も取り上げていない**（CONSTITUTION.md §5）

### 7. ⚠⚠ 1 つの返答が 2 つの言語で書かれていた

`js/atlas-console.js` は**読者が書いた言語**を映す（`_mirrorLang()`）。`js/atlas-query.js` は
**UI の言語**を読んでいた。英語 UI に日本語で訊くと、同じ吹き出しに
「✓ ハイライトを消去しました。」「移動先: 日本」と
「⚠ This query names something IntMap does not have…」が並ぶ。**翻訳漏れではない**
——2 つの器が「誰が読んでいるか」について別の問いに答えていた。⇒ 合成する側が、合成している
返答の言語を渡す（`bind({lang})`）。渡されなければ UI 言語のまま＝Data-query パネル自身の用途には正しい。
