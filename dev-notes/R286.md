## R286 — **「先読み」が、ブラウザに読み込めない URL を渡していた**

> 「tests/monitors.spec.js:214 ("no uncaught page errors and no non-benign console errors")
> fails intermittently with 20 console errors of the form:
> `Loading the image 'imapsat://2/0/2' violates the following Content Security Policy
> directive: "img-src 'self' https: data: blob:". The action has been blocked.`
> … the fact that Chromium is trying to load `imapsat://…` as an image means some path is
> handing the raw URL to the browser instead of going through the registered protocol.
> Do NOT "fix" it by adding `imapsat:` to the CSP img-src or by adding the message to the
> benign-console-error allowlist — those hide it.」

**報告のこの一文が、そのまま診断だった。** `imapsat://` は IntMap 自身が
`scene.addProtocol` で登録したスキーム（`js/sat-proto.js:310`）で、正しく配信されていれば
**ブラウザの画像読み込みは一度も発生しない**。だから「ブラウザが `imapsat://` を画像として
読もうとした」というメッセージ自体が、**生の URL がハンドラを迂回した**という意味になる。

### 1. 迂回していたのは 1 か所だけだった

`<img>` に URL を渡しうる箇所を全部見て、**動いているスタイルの `tiles[0]` を読んでいるのは
3 か所**——`js/dash-extended.js`（カメラ先読み）、`js/cesium-layers.js`、`js/tile-warm.js`。
後ろの 2 つは scheme を見ている：

- `js/cesium-layers.js` は URL から scheme を切り出し、`protocols[scheme]` に**渡している**
  （`requestImage`）。
- `js/tile-warm.js` は **#R206 で**「プロトコルが公開する実 URL」を使うようになっている
  （`IntMapSatProto.tileUrl`）。

残る `js/dash-extended.js` だけが、雛形をそのまま URL として扱っていた：

```js
const s=st.sources['satellite']; return s&&s.tiles&&s.tiles[0];        // → 'imapsat://{z}/{y}/{x}'
const url=tpl.replace('{z}',z).replace('{x}',x).replace('{y}',y);
const im=new Image(); im.decoding='async'; im.src=url;                 // ← ブラウザに渡している
```

衛星ソースが**プロトコル URL を持つのは #R158 以降ずっと**で、**#R207 以降は衛星が既定の
ベースマップ**。つまりこれは珍しい経路ではなく**普通の状態**であり、この先読みは
**#R158 以降ずっと 1 枚も温めていなかった**。温めない代わりに、CSP 違反だけを出していた。

### 2. 断続的だったのは欠陥ではなく引き金のほう

このブロックは `moveend` の**2 連**でしか走らない（速度が 550 ms 換算で 0.15° を超えたときだけ）。
monitors spec では `window._radiusFromPoint(139.7, 35.68)` → `(2.35, 48.85)` ＝**東京からパリ**が
その条件を満たす。**再現の前に算数で当たりを付けられた**：中心 (2.35, 48.85)・z=2 なら
`n=4, xc=2, yc=1`、`dy` が `y<0` になる 5 件を落として **ちょうど 20 件**。その集合には報告の
`imapsat://2/0/2`（z=2, y=0, x=2）が入っている。

実測（`HTMLImageElement.prototype.src` に記録を挟んで数えた）：**20 件、20 件とも一致**。

### 3. 直し方 — 「ブラウザが読み込める URL だけを出す」

scheme を見る。`http`/`https`/スキーム無しは今までどおり、それ以外は**何も出さない**。
このアプリが登録しているプロトコルは **7 本**（`imapsat` / `pmtiles` / `om` ／ DEM・world-base・
crop・Cesium 側）あるので、規則は**名前ではなく scheme**に置いた。

```js
const browserLoadable=(tpl)=>{ const m=/^\s*([a-z0-9+.-]+):/i.exec(tpl||''); return !m||/^https?$/i.test(m[1]); };
```

⚠ **これは「黙らせた」のではない。** 衛星の先読みは `js/tile-warm.js` が**同じ `moveend` で**
担当していて、そちらは `IntMapSatProto.tileUrl` でレンダラが実際に要求するレベル・
2 ホストの振り分け・重複記憶まで持っている。ここに 25 枚の第 2 の先読みを新しく作れば、
**#R196 が携帯で測った「865 リクエスト／実タイルは 112 枚」を作り直すだけ**になる。
`tests/r286 ⑤` はその担当が実在することを測る——**根拠を文章で書いたら、同じラウンドで
その根拠を測る検査を書く**（#R278）。

⚠ **拒否は観測できる**（`SpeculativePrefetch.last()` が `{tpl, warmed, refused}` を返す）。
「正しく断った」と「経路ごと消えて静かになった」は、そうしないと同じ緑に見える。

### 4. 塞いだ近道 2 つと、開いていた穴 1 つ

報告が名指しした 2 つの近道——`img-src` に `imapsat:` を足す／benign 一覧にメッセージを足す——は
**振る舞いで**検査した（`tests/r286 ③④`：CSP を meta タグから**解析して集合比較**し、`isBenign()` を
**実際のメッセージで呼ぶ**）。

そして ④ を書いたら、**その benign 一覧に穴が開いていることが分かった**。今回ゲートが鳴ったのは
**綴りの偶然**だった：

```
/load.*(tile|glyph|sprite|source image)/i
   ✗  "Loading the image 'imapsat://2/0/2' violates …"   → 一致しない（＝赤くなった）
   ✓  "Loading the image 'pmtiles://a/1/2/3' violates …" → 一致する（＝benign 扱い）
```

`Loading the image 'pm`**`tile`**`s://…` である。**同じ漏れが `pmtiles://` で起きていたら、
ゲートは一度も鳴らなかった。** → **CSP 違反はどんな文面でも benign にしない**。
hermetic なルーティングはホストを塞ぐので出るのは `net::ERR_FAILED` であって CSP 違反ではなく、
CSP 違反は「ページが**自分の**ポリシーに反するものを要求した」＝定義上つねに欠陥。
（実測：この 1 行を足しても `smoke` の「no critical console.error」は緑のまま＝
正当な CSP 違反はこのアプリに 1 件も無い。）

### 5. 検査は「1 つの綴り」ではなく「全部の画像」に張った

`tests/smoke.spec.js` は `addInitScript` で `HTMLImageElement` の **`src` プロパティと
`setAttribute('src')` の両方の扉**に記録を挟み、`img-src` が認める集合
（`https:` / `http:` / `data:` / `blob:` / スキーム無し）の外を **1 件でも**見たら落ちる。
記録するのは違反だけなので、数百枚読み込む起動でも 1 枚あたり正規表現 1 回。
⚠ `setAttribute` は **`HTMLImageElement.prototype` に影として置く**——`Element.prototype` を
包むと全要素の属性設定を通ることになる。

**スペックは 1 本も増やしていない**（#R207 と同じ理由：起動はこのファイルが既に払っている。
`scripts/test-budget.mjs` の core は残り 0 分）。ソース側は `tests/r286-checks.test.mjs`。

### 6. 赤くなることを先に確かめた

- 修正前のビルドに対して `R286 ⑳` は **20 件の `imapsat://…` を並べて**落ちた。
- `tests/r286 ①②④` も修正前のソースで赤（③⑤ は「塞いだ近道」「根拠の担当」なので両方で緑）。
- 修正後：`monitors.spec.js` を **5 連続**（`--repeat-each=5`）＝ **45/45 緑**。

### 7. 追記 — その `npm test` を回して、**#R283 の欠陥の 4 例目**が出た

修正の検証で全件を回したら、**今回の変更と無関係な既存の失敗が 1 件**出た：

```
✖ R280 ② every rule this round added FAILS when its fact is made wrong
  AssertionError: privacy.html no longer contains the anchor for the legal case
```

`tests/r280-checks.test.mjs` は各ルールを**わざと壊して赤くなることを確かめる**検査で、
壊す位置を LF 付きの文字列で指している：

```js
{ rule: 'legal', file: 'privacy.html',
  from: '<script src="./js/legal-text.js"></script>\n', to: '' },
```

実測：`privacy.html` の当該箇所の直後は、この作業コピーでは `\r\n`（`git show HEAD:privacy.html`
は `\n`）。`.gitattributes` が LF に固定しているのは **Linux で実行・解析される拡張子だけ**で
`*.html` は入っていない。**Windows で必ず赤／CI では必ず緑**——#R283 が直したのと**同じ形の 4 例目**。

⚠ **読み込みを正規化してはいけなかった。** ② は壊したあと**元のバイト列を書き戻して復元する**ので、
`readLF` で読むようにすると**テストを走らせただけで作業コピーの改行が LF に書き換わる**。
そこで直したのは**照合の側**——アンカー中の改行だけを `\r?\n` に広げ、他の文字は全部
エスケープしたまま（`anchorRe`）。**緩めていない**：`tests/r286 ⑥` が
「LF でも CRLF でも一致する」「**改行が本当に無ければ今も不一致**」「`.` は `.`、`$` は `$`」の
**両方向**を検査し、さらに**実際の `privacy.html` に対して**一致することを見る。

実測：`tests/r280-checks.test.mjs` は 9/9 緑になり、走らせたあとの
`privacy.html` / `CONSTITUTION.md` / `docs/README.md` / `00_structure_test.sql` は**差分ゼロ**。

⚠ この修正は**利用者に確認してから**入れた（`CLAUDE.md` §3.2）。依頼された欠陥とは別物なので。

### 8. 追記 — **ロックは「書く側」だけを見ていて、「読む側」を見ていなかった**

⑦ を直して回した `npm test` で、今度は `R280 ①` が落ちた：

```
✖ R280 ① check:docs is green on the committed tree
    ✖ build-info — docs/_doc-facts-negative-probe.md spells the stamp file with a leading hyphen
    ✖ doc-index — docs/README.md does not list docs/_doc-facts-negative-probe.md
```

`docs/_doc-facts-negative-probe.md` は **`tests/r274 ③` が一時的に置くファイル**で、
「ルールを壊したら本当に赤くなるか」を証明するためのもの。`node --test` は**ファイルを並列に
走らせる**ので、r274 ③ がそれを置いている最中に `R280 ①` が `check:docs` を走らせると、
**プローブを「コミット済みツリーの欠陥」として報告する**。

`tests/helpers/gate-lock.mjs` はまさにこのために #R280 が書いたもので、**書き換える 2 本
（`tests/r274 ③` と `tests/r280 ②`）は両方ともロックを取っている**。取っていなかったのは
**`R280 ①`**——**ツリーが清潔であることを検査する読み手**で、ロックの注記が
「⚠ ツリーを触るものは全部これを通せ」と書いている対象そのものだった。

⚠ **共有された不変条件を読む側も、ロックの当事者である。** 排他は書き手同士の問題に見えるが、
「今この瞬間は誰も壊していない」を主張する読み手は、書き手と排他でなければ意味を持たない。

→ `①` を `withTreeLock` で囲んだ（**検査の中身は 1 字も変えていない**）。これで重なりは
確率ではなく**構成上**起きない。実測：この 1 ラウンドで 2 回踏み（CI はたまたま当たらなかった）、
修正後は全件緑。⚠ **このラウンドが検査ファイルを 1 本足したことで並列プールが増え、
潜在していたこの競合が当たりやすくなっていた**——自分が悪化させた分を閉じたことになる。

⚠ この修正も**利用者に確認してから**入れた（`CLAUDE.md` §3.2）。
