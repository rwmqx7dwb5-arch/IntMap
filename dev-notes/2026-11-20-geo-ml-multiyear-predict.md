〈依頼〉総合技術調査（2026-11-20）の P2: 二時点を超える複数年の変化分析、地域の意味分類、変化の解釈、そして目的変数と地理空間データから「特徴量 → モデル → 空間/時間分割評価 → 不確実性つきで地図へ」を自律で回せる環境。単純回帰は既存の Python で足りるので、**足りない一連の統合**を作る。撮影日不明の画像を Chronos 指定日の画像として扱わない。

## 1. 構成

- `js/geo-ml.js`（純粋・node で評価）— 4 つの仕事。
  - **A. 複数年の変化**: `admitObservations` は撮影日を**観測として述べた**ものだけを通す（`dateBasis` が `acquired` か、期間を持つ `composite`）。ファイル名・取得日・背景タイルの年・日付なしは rejected に理由つきで残る。`selectForTime` は Chronos の指定日に最も近い**撮影日つき**の観測を許容日数内で選び、無ければ「無い」と言う（近い年の別の画像を当てない）。`seriesStats` は Theil–Sen（速さ/年）・Mann–Kendall（同順位補正つき）・平均の段差の最大（時期は**2 つの観測日で挟んだ区間**まで）。型は stable / gradual / abrupt。**閾値の定数は置かない**: 段差の帰無分布は観測数ごとに simulate（比なので尺度に依らない）、傾向は MK の p。
  - **B. 意味分類**: 原型は OSM タグの意味（`CLASS_PROTOTYPES`）で、**較正していない**と述べる。利用者が正解を渡せば `fitPrototypes`（1 つ抜き正答率と最頻クラスの基準つき）。証拠が無い地域は `unclassified (mapped-nothing)` で、農村とは言わない。農地は `geo.similar` の特徴に無いので 1 区画 1 リクエストで足す。
  - **C. 変化の解釈**: 施設・ニュース・統計を、変化の窓の**場所と時期の一致**に結ぶ。窓より後のもの（`followed-the-change`）と日付の無いものは「説明に使えない」と名指し。統計は共通年 5 以上の順位相関のみ。関係は coincides までで、原因とは言わない。
  - **D. 予測モデル**: 特徴量づくり（ラスターの値と近傍平均・点レイヤーの半径内件数/最近傍距離・多角形の内外。**取れない所は NaN で 0 にしない**）→ ridge（λ は空間 CV で選ぶ）と木の集まり（Breiman の慣行値）→ **空間ブロック CV**（ブロックごと保留・バッファ任意）を本命にし、**ランダム分割の点数を並べて**水増し分を見せる → 時間列があれば**未来側の保留** → 分割共形の区間（空間 CV の残差の分位。他の fold の分位を当てた fold の実測被覆を報告）→ 置換重要度 → 学習範囲の外・学習点から遠い点に `extrapolating`。
- `js/geo-ml-run.js` — 上を `IntMapData` に結ぶ。結果は**新しいデータセット**（変化は 7 バンドのラスター、分類と予測は点）で、`provenance.evidence` に撮影日・手順・制約を持つ。`map.drawDataset` で描く。
- `js/atlas-cap-geo.js` — 能力 `geo.ml`（`op: trend|classify|interpret|model`）。1 つの扉に束ねた理由: 4 つ別々に足すと能力数・表・perf 天井が 4 倍動き、利用者の目的（一連の作業）は 1 つなので。

## 2. 測ったこと（合成データ。`tests/geo-ml-checks.test.mjs`・`tests/geo-ml-run-checks.test.mjs`）

- **偽陽性**: 雑音だけの系列 1500 本（n=8）で、段差/傾向と判定された割合は 12% 未満（α=0.05 の下で。n が小さいときの MK は保守的でない側に寄る）。
- 段差は 2019.45–2020.45 の区間として出る（その年の中での日付は言わない）。直線の傾きは Theil–Sen が −0.2/年を 0.05 以内で復元。
- **雑音だけの目的変数**: 「空間ブロック全 fold で平均に勝つ」を満たさず `does-not-beat-the-mean-under-spatial-validation` が立つ。最初は「skill > 0」だけで判定し、seed 4 と 7 で**雑音が通った**（skill 0.0015 と 0.035。最良モデルを選んだ後の選択バイアス）。全 fold で勝つことを要件に直した。
- 位置だけの関数（座標が特徴）では、ランダム CV の RMSE が空間 CV より小さく出て、報告が両方を並べる（水増し 5% 超）。
- 実信号（x1 が y に効く）: 空間 CV の skill 0.3 超・区間の実測被覆 0.8 超・重要度の 1 位は x1。

## 3. 保証していないこと・残り

- 実際の衛星データでの end-to-end は未実施（#1318 の結果ラスタが merge されてから、東京などで `trend` を実測する）。ここの検証は合成データで、**アルゴリズムの性質**を測ったもの。
- 季節は `season` を指定しなければ除かない。大気・雲・太陽高度の差は SCL などで除いた観測を渡す前提（#1318 の光学は雲量順に引く）。
- 分類の原型は事前知識で較正していない。農業は OSM の `landuse` の件数に依るので、農地が描かれていない国では `unclassified` になりうる（農村とは言わない設計）。
- 予測モデルは点から点へ。面データの目的変数は代表点（重心）として扱う（`pointsOf`）。木の集まりは JS 実装で、数万点を超える学習は想定していない（その規模は既存の Python 経路）。
- 区間は交換可能性の仮定の下の分割共形。空間ブロックの残差を使うので「保留ブロックでは当たる」を測るが、学習域の外（`extrapolating`）では検証されていない。
- 時間検証は 1 つの cutoff の保留。ローリング・オリジンの検証はしていない。
