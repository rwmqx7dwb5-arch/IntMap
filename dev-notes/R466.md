## R466 — **訳は在った。書き直す契機が無かった**（設定の中で言語を変えると、設定の中身だけが前の言語のまま）

「言語を fr / ko / zh に変えても『国別メディアのニュース』の16か国が英語のまま」——#R450 の本番検証中に
見つかり、そのラウンドの範囲外だったもの。

### まず、当たり前の説明のほうが間違っていた

いちばん自然な読みは「`js/tables.js` の `NEWS_COUNTRY_FEEDS` が `LA(...)` に引数を5つしか渡していないので
fr/ko/zh が英語に落ちる」である。**木はそう言っていない。**

- `js/locales/ui.fr.js` は行を**持っている**（`"United States": "États-Unis"`。他言語も同様）。
- 読み手は全部レジストリ経由（`js/news-sources.js` の `LNS.arr(f.name)` ＝ `pick()` の適用）なので、
  位置引数の外にある4言語は inline 表で解決される。

実機で確かめると、切替の直後に `IntMapLang.t('fr','United States',…)` は**その場で `États-Unis` を返して
いた**。訳は在り、引き方も正しい。欠けていたのは**書き直す契機**だった。

### 原因（1文で）

**設定モーダルの中身を塗る関数を呼ぶのは `#btn-open-settings` の処理だけで、言語の `<select>` は
その設定モーダルの中にある。** だから「言語を選ぶ」と「その結果を読む」の間に、そのダイアログが
開き直される機会が**構造上1度も無い**。`updateI18n()` が貼り直せるのは `data-i18n*` を持つ markup だけで、
JS が `textContent` に書いた文字列には属性が無いので届かない。

実測（本番 R450 のビルド、およびこの worktree のローカルビルド）:

| | 切替直後（fr） | 同じ言語でリロード（fr） |
|---|---|---|
| `#newscountry-multi .ncx` ×16 | United States / United Kingdom / Japan … | États-Unis / Royaume-Uni / Japon … |
| `#newscountry-dd-label` | None (default feeds only) | Aucun (flux par défaut uniquement) |
| `#setting-tz` の `auto` 行・`#tz-results` | Local (System Default) | Local (réglage du système) |

### 報告された2件で終わらせず、面ごと測った

en で開く → **その場で** fr に切り替える → **同じ言語でリロードする**、の3枚のスナップショットを
DOM の全ノードで突き合わせ、「切替では英語のまま（B===A）かつリロードでは仏語（C≠A）」を数えた。
**設定モーダルの中だけで 52 ノード**。全数調査（`intmap-scout`）と合わせて、直した箇所は
**設定の中に7つ・外に3つ**:

| 面 | 塗る関数 | 直し方 |
|---|---|---|
| 国別メディアの16か国・要約 | `js/news-sources.js` `renderCountries()` | **貼り替え**（`relabel()` を新設） |
| 提供元の要約・空欄の文 | `js/news-sources.js` `render()` | 同上 |
| 時刻帯コンボの `auto` 行・「該当なし」 | `js/app-body.js` `populateTimezones()` | 絞り込みを持ったまま再構築 |
| エンジンの状態行 | `js/app-body.js`（開く処理に埋まっていた） | `syncEngineStatus()` へ切り出し |
| ティッカーの項目選択欄 | `js/i18n-late.js` `_populateTickerSyms()` | 再構築（毎チェックが即確定するので安全） |
| 設定の AI 欄 | `js/ai-core.js` `aiRenderSettings()` | 再構築（利用者の入力を持たない） |
| 衛星画像の API キー欄 | `js/satellite.js` `satRenderKeyInputs()` | **貼り替え**（`satRelabelKeyInputs()` を新設） |
| レイヤーのお気に入りチップ | `js/layer-favs.js` `renderLayerFavs()` | 再描画（チップは導出物） |
| 比較ビューの入口ボタン | `js/compare.js` `mountButton()` | ラベルを関数にして貼り替え |
| Atlas の命名掃引（`aria-label` 全般） | `js/atlas-controls.js` `_uiNameSweep()` | 自分の名前だけ取り返して掃き直す |

### ⚠⚠ 貼り替えであって再描画ではない

`renderCountries()` はチェックを **`window.imNewsCountries`（＝Apply で確定した選択）** から書き戻す。
言語切替でそれを呼べば国名は直る——**そして、まだ Apply していないチェックが黙って消える。**
衛星の鍵欄も同じで、`value=` を**保存済みの鍵**から書き出すので、打ちかけの鍵が消える。
だからこの2つは、文字だけを書き替える経路を別に持つ。ボタンの要約は
**画面のチェックの側**から作り直す（確定済みから作ると「未選択」に戻ってしまう）。

実測（ローカル、fr→jp）: チェック2つ（jp / cn）・打ちかけの鍵 `TYPED-NOT-APPLIED`・時刻帯の絞り込み
`tok` が**全部残ったまま**、国名・提供者名・状態語・`auto` 行・ティッカーの見出しが日本語になった。

### ⚠⚠ `#opt-tz-auto` は #R18 から一度も見つかっていなかった

`updateI18n()` に `document.getElementById('opt-tz-auto').innerText = d.optLocal;` があった。
index.html は **#R18 で native `<select>` をコンボボックスに替えたときからその id を持っていない**
（`git grep` で全追跡ファイル中この1行のみ）。当てが外れている行は、当てが外れていることを言わない。
削除し、代わりにコンボの再構築を `intmap-lang` に繋いだ。

### ⚠⚠ `aria-label` は「その要素が最初に現れた言語」で固まる

`_uiNameSweep()` は `:not([aria-label])` にしか名前を付けない（#R77 の設計として正しい——他所が
意図して書いた名前を上書きしないため）。結果として、**一度英語で名付けられた読み上げ名は
セッションが終わるまで英語のまま**だった。実測: fr に切り替えたあともニュース言語のチェックボックスは
「English」「Japanese」と名乗り、×ボタンは「close: …」のままだった。
⇒ 掃引が書いた名前に `data-imname` を刻み、言語が変わったら**その印の付いたものだけ**を取り返して
掃き直す。Atlas はこの名前でコントロールを探すので、これは読み上げだけの話ではない。

### ⚠ 押せないボタンに繋がったままの relabel

`js/dash-extended.js` の `_r7Relabel()` は**ヘッダの言語ピル**（`lang-jp` / `lang-en` / …）の click を
聞いていた。`css/intmap.css` は **#R11 から `.lang-toggle{display:none!important}`**（「言語は設定から
変える」）なので、そのボタンは押しようがない——つまりこの relabel は**一度も発火していなかった**。
`intmap-lang` に繋ぎ替えた。中で `refreshDisputeLabels()` を呼んでいるので、係争境界の地図ラベルにも効く。

### ゲートは「壊れ方」を測る

- `tests/r466-checks.test.mjs`（7本）: 塗る側9ファイルが全部 `intmap-lang` を聞いていること／
  死んだ id を触る行が無いこと／掃引が印を付けてそれだけ取り返すこと／隠されたピルを引き金にして
  いないこと／鍵欄を作り直していないこと。**⑥ は本物の `relabel()` と `countryLabelOf()` を
  `new Function` で走らせ**、国名が表から書き直され、要約が**チェックの側**から作られることを測る。
  ⑦ は「再描画してはいけない」根拠（`renderCountries()` が確定済みから書き戻すこと）を見張る。
  ⚠ 7本とも、修正前のソースに対して**7本とも赤**になることを確認済み。
- `tests/r466.spec.js`（実 Chromium）: **仏語の綴りを1つも写さない。** 測るのは
  **「設定を開き直しても1文字も変わらないこと」**——それがこの欠陥の定義そのものであり、
  将来この形で足された別のコントロールも同じ主張で捕まる。修正前のビルドでは、報告そのものの

### 残っている（測れなかったもの）

- **`#coord-readout`**。ポインタ移動・地図移動のたびに描き直されるので原則として自分で直るが、
