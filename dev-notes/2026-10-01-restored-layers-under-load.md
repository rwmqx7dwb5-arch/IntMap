## 1. ページの主スレッドを何が占めていたか（実測）

器具は scratchpad の使い捨て spec（CDP `Profiler`・`IntMapTime.set` の包み・`setInterval` の遅れの記録）。出荷物には残していない。
場面は spec と同じ共有リンク（`sharedIds()` の 87 行）・1280×720・headless Chromium。

- **時計が 1991-06-25 12:00 で止まっている。** `IntMapTime.state()` = `{isLive:false, source:"query"}`。リンクが運ぶ戦争レイヤー
  5 本が、オンになるたびに自分の開始日へ時計を合わせる（`js/war-layer.js` toggle。順に 1939-08-23 → 1914-06-28 →
  1950-06-25 → 1954-04-26 → 1991-06-25、最後のものが残る）。
- **衛星レイヤーの伝播の費用は瞬間と元期の距離で決まる。** `IntMapSatellites._propagateAll(when)` を同じページで瞬間ごとに:

  | 瞬間 | 1 回の時間 | 描いた数 |
  |---|---|---|
  | 1939-08-23 | 4,243 ms | 5,933 |
  | 1914-06-28 | 5,386 ms | 5,234 |
  | 1950-06-25 | 3,627 ms | 6,228 |
  | 1954-04-26 | 3,475 ms | 6,485 |
  | 1991-06-25 | 1,762 ms | 8,355 |
  | 現在 | 77 ms | 15,968 |

  原因は satellite.js 7.1.0 の `sgp4()`：深宇宙の共鳴軌道（静止・半日周期）の積分器 `dspace()` に記録の `atime` を渡し、
  進めた `atime`/`xli`/`xni` を**捨てる**ので、毎回元期から 720 分刻みで積み直す（Vallado の参照実装は記録に書き戻す）。
  モジュールの註の「21 ms」は元期から 1 日の場合の値だった。
- **落ち着いたページ（起動 60 秒後から 30 秒の CPU プロファイル）**: `dspace` の自己時間 **7.3 秒**。呼び出し元は 3 秒ごとの tick、
  **毎フレームの `moveend`**（地球の自転 `beta-dl-spin` が毎フレーム `setCenter` する）、時計の購読者。止まった時計の下で
  全員が同じ瞬間を訊き、毎回 1.75 秒の途切れないタスクで同じ答えを作り直していた。
- **held の解放直後 60 秒**: `dspace` **19 秒**。`IntMapTime.set` の購読者（`js/app-body.js` #R289）から同期で呼ばれ、
  戦争レイヤーの 5 回の時計合わせの中で 8.9 秒と 10.5 秒の連続区間になっていた。held ではリンクの 93 件の変更が解放時に
  一度に届くので、この塊が観測窓のちょうど中に落ちる。plain では起動の途中に分散する。
- 残りは `(program)`（ソフトウェア WebGL の描画と Commit 待ち）。地球の自転・航空機・衛星軌道のカスタムレイヤーは
  毎フレーム描き直しを頼むので、全レイヤーの頁は idle にならない。それ自体は仕様（アニメーション）で、描画は
  フレーム単位で区切られる。区切られないのは上の伝播だった。

## 2. 直したこと（利用者承認済み「全部任せる」）

### 2.1 衛星は、その衛星の軌道要素が述べる期間の中だけ計算し描く

1914 年に 5,234 機、1991 年に 8,355 機を描いていたのは、2026 年の軌道要素を 112 年・35 年遡らせて SGP4 に解かせた
**作られた位置**だった（`.agents/rules/historical-verification.md` §2 の 3）。⇒ `js/satellites-live.js` `_elementSpan(s)`:
各要素セットの元期（`jdsatepoch`）の前後、平均運動の帯ごとの幅の中だけを「述べている」とし、その外は**計算もしない**。
国際標識の打ち上げ年（`98067A` → 1998 年 1 月 1 日）より前も外（元期の窓だけだと若い高軌道は打ち上げ前まで届く）。

**幅は実測で決めた**（推定の部分は推定と書く。表・基準・失効条件の正本は `_SPAN_BANDS` の註）:
同梱カタログの履歴 61 枚（`data/tle/catalogue.tle`、2026-08-01〜09-30、satellite.js 7.1.0）で、各物体の古い要素を
最新の要素の元期まで進め、最新の要素がそこで示す位置と比べた（3 枚に 1 枚を使用。物体数は帯×経過日数ごとに下表の n）。
基準は「半数が 100 km 以内、9 割が 1,000 km 以内」（世界の縮尺で点が正しい場所にあり、可視範囲の円が正しい地面を覆う）。

| 帯（平均運動） | 経過 | n | 中央値 | p90 | 採った幅 |
|---|---|---|---|---|---|
| LEO > 11 周/日 | 5 日 | 15,045 | 38 km | 394 km | **5 日** |
| | 7 日 | 331 | 115 km | 2,473 km | （超える） |
| MEO/HEO 1.5–11 | 60 日 | 205 | 18 km | 226 km | **60 日**（測れた最長。推定の上限） |
| GEO ≤ 1.5 | 14 日 | 2,278 | 85 km | 253 km | **14 日** |
| | 21 日 | 2,379 | 185 km | 480 km | （超える） |

⚠ 推定: 履歴は古い要素を**前へ**進めた比較で、時計が過去にあるとき（後ろへ）にも同じ幅を当てている。MEO/HEO は
履歴の長さで頭打ち。⚠ 失効: satellite.js の伝播器が変わったとき、カタログの出どころが変わったとき、履歴が延びて
MEO/HEO の上限が測れるようになったとき。測り直しは scratchpad の手順（`git log -- data/tle/catalogue.tle` の各版を
`git show` で取り出し、上の比較を回す）。

**描く数の変化**（同梱カタログ 15,968 件）:

| 時計 | 前 | 後 | 1 回の伝播 |
|---|---|---|---|
| 1914-06-28 | 5,234 | **0** | 5,386 ms → 3 ms |
| 1991-06-25 | 8,355 | **0** | 1,762 ms → 1 ms |
| 2026-09-20 | — | 806（GEO・MEO だけ） | |
| 2026-09-27 | — | 15,961 | |
| 現在（2026-10-01） | 15,968 | **15,953**（元期が古すぎる 15 件を除く） | 77 → 51 ms |
| −72 h・−48 h・−24 h（再生） | | 15,960 / 15,958 / 15,957 | |

時計を数日動かして動きを見る使い方は窓の中（`IntMapTime` は未来を今に留めるので、前へは今まで）。

**範囲の外であることを述べる**: カタログ全部が範囲の外なら、凡例が「この日時の軌道要素はありません（手元の要素が
述べるのは 2026-07-17〜2026-11-29）」と言い、行の状態は `js/layer-state.js` の新しい状態 **`nodata`**（失敗ではない
のでトーストせず、灰色の pill「この日時のデータなし」）。Atlas は `layerStates`（`IntMapLayerState.snapshot()`）で読む。
一部だけ外なら凡例に「・N 機はこの日時の軌道要素なし」。Now に戻ると状態は消え、従来どおり。
次回通過の探索も要素の範囲で止まり、`{ none, limited, elementsTo }` で「要素の有効期限まで探した」と述べる
（詳細カードと Atlas の衛星の事実で文を分けた）。

### 2.2 同じ瞬間の伝播は 1 回（最初の直し）

`propagateAll` は「カタログ（`sats` の同一性）＋瞬間」が同じなら最後の答えを返す（`propagateAll._last`）。時計が止まって
いる間の tick・`moveend`（地球の自転で毎フレーム）・時計の購読者が同じ瞬間を訊いても 1 回。落ち着いたページ 30 秒の
`dspace` 7.3 秒 → 0。2.1 の後では過去の伝播そのものが消えたので、効くのは「今」付近で時計を止めたとき。

### 2.3 案 2（時計の購読をフレームの最後の 1 回にまとめる）は**やらない**——測って不要だった

2.1 の後、held の解放直後 60 秒の CPU プロファイルで `dspace` は **19 秒 → 0**、`propagateAll` の呼び出しは 1 回 0.1 秒
程度が 2 回だけ。戦争レイヤーが時計を 5 回跳ばしても、範囲の外は 1〜3 ms で終わる。まとめる理由が残っていない。

### 2.4 回数で打ち切る待ちを、待っている事象で解く

| どこ | 前 | 後 |
|---|---|---|
| `js/world-packs-rows.js` `whenDrawable` | 250 ms × 80 回で黙って諦める | `GE().whenCanDraw()`（styledata / load / idle で canDraw が真になった瞬間、それより前には答えない） |
| 同 `withCountrySource` | 200 ms × 200 回、尽きたら失敗と同じ `false` | 国のコレクション（ラッチされた `loadCountryData` が落ち着いた時点で有るか無いか）と `whenCanDraw` の 2 つ。`false` は「コレクションが届かなかった／描画器が拒んだ」だけ |
| `js/war-layer.js` `whenDrawable` | 300 ms × 40 回（「~12 s; a map that never draws is not our fault to log」） | 記録（自前のラッチされた `load()`）と `whenCanDraw` の両方を待つ |
| `js/net-health-live.js` `whenDrawable`（再現の途中で見つけた 4 つ目。held に `nr-pt` だけが無い赤） | 300 ms × 60 回（「18 s」） | `whenCanDraw`。描画器が受けられるのに描けなかったら描画器の次の変化（styledata / idle）でもう 1 回、2 回目の拒否は行に `failed` |

失敗が**観測された**とき（国のコレクションが届かない・戦争の記録が届かない）は、黙って捨てずに行の状態
（`js/layer-state.js` の `failed`、警報は `panel.failed()` を新設して `wp-dl-alerts` に）へ出す。

### 2.5 衛星カタログの読み込みの期限も、頁自身の凍結を数えていた（再現の途中で見つけた）

上の直しの後の再現で、held に `lyr-sats*` の 6 枚だけが無い赤が 1 回出た。原因は `load()` の `grab(BUNDLED, 15000)`——
同一オリジンの 2.5 MB を**読み切るまで**を壁時計 15 秒の `setTimeout(abort)` で縛っていた。負荷下では 15〜25 秒かかり
（trace では状態 −1＝打ち切り）、ライブの段は封鎖、キャッシュも無いので「カタログを読み込めません」で層が一度も
足されなかった。⇒ 共有の `js/fetch-deadline.js` `readWithin(..., {idle:true})` に替えた（歩数で数える時計なので凍結は
上流の沈黙に数えない。`idle` で「最長の沈黙」を縛り、届き続けるダウンロードは止めない）。ライブの段も同じ読み手。
`fetch()` の無期限の呼び出しの台帳は 3 → 2（`tests/fetch-deadline-baseline.json`）。

## 4. 残る原因（特定）

解放直後 60 秒の held の CPU プロファイル（直した後）: **`(program)` 56.9 秒 / 69 秒**、JS の最大は MapLibre の
worker 応答の受け取り 1.6 秒。`(program)` はソフトウェア WebGL の描画と Commit の待ち。地球の自転
（`beta-dl-spin`、毎フレーム `setCenter`）・航空機の GPU クラウド・衛星軌道のカスタムレイヤーは毎フレーム描き直しを
頼むので、全レイヤーの頁は idle にならず、1 フレーム 0.5〜1 秒の描画が主スレッドを埋める。それは仕様（アニメーション）
で、作られた位置や回数切れのような「やらなくてよい仕事」ではない。残る赤は欠ける層が毎回違い（警報・戦争＋衛星・
海底ケーブル・航空機/レーダー）、どれも遅れて来る途中——止まった経路は見つからなかった。

⚠ CI の 4 vCPU（Linux）でまだ赤が出るなら、残りは上の描画の飽和か、次の「回数／壁時計で打ち切る待ち」である。
⚠ 未着手で残すもの: 壁時計の `setTimeout(abort)` で読み切りを縛る取得がまだ十数か所ある（`js/volcano-layers.js`・
`js/beta-overlays.js`・`js/border-coast.js`・`js/time-borders.js` ほか。`grep -n "setTimeout(.*abort"`）。2.5 と同じ形で、
負荷下では「上流が答えない」と誤って判定しうる。`hiResCountries`（1,600 ms × 14 回）も回数で打ち切る。

## 5. 否定された見立て

- 「前の spec が残すもの（Service Worker・キャッシュ・IndexedDB）が効いている」——各テストは新しい context で、
  `serviceWorkers:'block'`。shard 依存の正体は相方の worker が**同時に**使う CPU だった（通過した run は相方が軽い）。
- 「CPU 減速で再現できる」——22 コアの机上では 2 倍・4 倍の減速（4 ページ同時）で 8/8 通過。減速は頁の主スレッドだけを
  遅くし、ソフトウェア GL の GPU プロセスと worker は遅くならない。4 コア固定＋相方の同時実行で初めて赤が出た。
- 「同じ値の `setLayoutProperty`/`setPaintProperty` が描き直しを回し続けている」——MapLibre 6.11.2 の `Map.set*Property` は
  値が同じでも `_update(true)` を呼ぶので、15 秒に 1,743 回の空書き込みは確かに再描画を頼んでいた。ところが
  `?cmdskip=sourceData,paint,layout,filter`（#R322 の A/B のつまみ）で全部止めても描画回数は 15 秒 32 → 33 回で変わらず、
  頁は idle にならなかった。描き直しの主は自転とアニメーションの層。#R322 の判定（paint/layout の skip は OFF）は覆らない。
- 「#849 の衛星カタログ更新が原因」——件数は 15,968 で変わらず、元期の中央値は 20.2 → 18.6 時間。費用を決めていたのは
  時計の瞬間だった。
- 「時計の購読をまとめれば（案 2）足りる」——2.1 の後では対象の仕事が残っていない（2.3）。
