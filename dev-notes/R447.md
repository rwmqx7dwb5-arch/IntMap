## R447 — **使っていないのに「使い切った」と言われた。その数字は、サーバーが送ったものではなかった**

報告は本番（R441・ログイン済み・2026-08-25）で観測された1件。リロード直後のページで Atlas に
質問を送ったところ、**ネットワーク要求が1本も出ないまま**こう返ってきた。

```
本日の無料AI使用回数に達しました。
```

同時刻に `public.ai_usage` をそのアカウント（`usage_date=2026-08-25`）について直接見ると、
**`count: 0`**。もう一度リロードしたら、同じアカウントで正常に通った。

### まず「その 429 は誰が書いたのか」を確定させた

`supabase/functions/ai-proxy/index.ts` が 429 を返すのは**2か所だけ**である。

```ts
if (reason === "turn_calls") return json({ error: "turn_calls", used, limit, calls: row?.calls ?? 0 }, 429);
return json({ error: "limit", used, limit }, 429);
```

**どちらも `used` を載せ、どちらも自分の名を名乗る。** そして本番に出ているのがこの版であることも
確かめた——`supabase functions list` の `ai-proxy` は version 54 / `updated_at` 2026-08-24T13:43:11Z、
リポジトリでこのファイルに触れた最後の commit は同日 13:42 UTC（#R413）。

さらに重要なのは、**この2つはどちらも `count: 0` では起こり得ない**ということ。

| 429 | 起こる条件 | そのときの `ai_usage.count` |
|---|---|---|
| `error:"limit"` | `increment_ai_usage` の `where u.count < p_limit` が偽＝**既に上限に達した行がある** | **10**（上限） |
| `error:"turn_calls"` | 最初の1本が課金済みのターンが `TURN_MAX_CALLS` を超えた | **1以上** |

どちらも払い戻さない。⇒ **観測された `count: 0` は、「その 429 は ai-proxy の枠管理が書いたものでは**
**ない」ことの証明**である。来たのは関数の**手前**（プラットフォーム側のレート制限）の 429 だった。

### 数字を書いたのはクライアントだった

`js/ai-core.js` の 429 処理は、こう書かれていた。

```js
if(r.status===429){ let j=null; try{ j=await r.json(); }catch(_){}
  if(j&&typeof j.used==='number') aiSetUsage(j.used, j.limit);
  else { HOST.aiUsage.date=aiToday(); HOST.aiUsage.used=aiDailyLimit(); }   // ← ここ
  if(j&&j.error==='turn_calls') throw new Error(aiTurnCallsMsg());
  throw new Error(aiLimitMsg()); }
```

`HOST.aiUsage` は `public.ai_usage` の当日行の**写し**である。`else` 枝は、**サーバーが一度も言って**
**いない数**（＝上限そのもの）をそこへ書き込む。ai-proxy の 429 は必ず `used` を持つので、この枝は
**ai-proxy 以外の 429 でしか通らない**——つまり「利用者の1日について何も知らない応答」を
「1日の枠を使い切った」と読み替える枝だった。

**依頼が第一容疑者に挙げていた `turn_calls` は、犯人ではなかった。** 本物の ai-core を node で
走らせて確かめた（下の再現ハーネス）。`{error:"turn_calls", used:3, limit:10}` を返すと写しは
`used:3`・残り7、文言も専用のものになる。`used` が付いている限り `else` 枝は通らない。

### 再現

`js/ai-core.js` を**本物のまま**（`new Function` で、index.html と同じ素のスクリプトとして）
実行し、`fetch` と `window.sb` だけを差し替えて、報告と同じ状況を作った。

```
① 名乗りの無い 429（server ai_usage.count = 0）
   thrown        : 本日の無料AI使用回数に達しました。
   aiUsage       : {"date":"2026-08-25","used":10,"limit":10}
   NEXT question : 本日の無料AI使用回数に達しました。
   network calls for that next question: 0
   aiGate()      : false
```

**報告と1バイト違わない。** 写しは 10 に固定され、次の質問は**要求を1本も出さずに**断られる。

### リロードが唯一の治療だった理由

固定された写しを読み直す経路は、リポジトリ全体で **2つしかなかった**。

| `aiFetchUsage()` の呼び出し元 | いつ |
|---|---|
| `js/auth-ui.js` | ログイン／OAuth 復帰のとき |
| `js/app-body.js`（設定パネル） | 設定を開いたとき |

そして門は3つとも**同期で写しを読むだけ**だった。`aiGate()`、`askAI`/`askAIEnvelope`、そして
`js/atlas-console.js` の `_aiReady`。**サーバーは一度も訊かれない**ので、写しが間違っていることを
誰にも訂正できない。新しいページを作れば新しいオブジェクトができる——それがリロードの正体。

⚠ **報告された拒否は3本目**（`js/atlas-console.js:4704`）で起きている。そこは `askAI` に着く前に
`return` するので、**ai-core だけ直しても Atlas のターンは直らない**。規則の綴りが3本あることが、
この欠陥の形そのものだった。

### 直したこと

1. **写しには、サーバーが送った数以外を書かない。** 429 は**本文を1回だけ読んで保持し**
   （`r.json()` は投げた瞬間に本体ごと捨てる——このラウンドが「どの 429 か分かっていない」から
   始まったのはそのため）、`error` が `limit` / `turn_calls` を名乗るものだけが写しを書ける。
   名乗りの無い 429 は**写しに触れず**、「AIサービスが混雑しています（IntMapの利用回数上限では
   ありません）」——既にある `provider_rate_limit` の9言語の文——を出す。**新しい文言は足していない。**
2. **写しが「残り0」と言ったら、断る前に行を読み直す。** `aiQuotaBlocked()` が唯一の答えで、
   非同期の門（`askAI` / `askAIEnvelope` / Atlas のターン）はすべてこれを通る。`public.ai_usage` は
   RLS で本人だけが自分の行を読めるので、権限は既にある。クリック時の同期の門 `aiGate()` は
   1回だけ断ってから背景で読み直す⇒**次のクリックはサーバーの数で答えられる**。
3. **規則の綴りを1本にした。** `aiOverQuota()` が唯一の綴りで、`js/atlas-console.js` は
   `await aiQuotaBlocked()` を通る。⚠ **失敗時は開ける**——権威は ai-proxy にあり、
   「誰も送っていない数で断る」ことこそが、いま直した欠陥だから。
4. **名指せない 429 の本体を残す**（`window._aiLast429`＝`{at, attributed, error, used, body}`）。

### サーバーが数えている数と、クライアントが見せる数がずれる経路（洗い出し）

| 経路 | 状態 |
|---|---|
| 名乗りの無い 429 → 写しに上限を書く | **これが今回の欠陥。直した** |
| 写しが古くなっても読み直す経路が無い | **直した**（`aiQuotaBlocked()`／`aiGate()` の背景同期） |
| ターン継続の課金されない呼び（`charged:false`） | ずれない——応答は実際の `count` を載せる |
| プロバイダ失敗の払い戻し（`refund_ai_turn`） | ずれない。**払い戻しでサーバーは減るが、502/503 には `used` が無い**——ただしクライアントは成功か 429 でしか `used` を学ばないので、払い戻し前の数を持っていない |
| **プランの上限がクライアントの当て推量** | **残している。** `aiFetchUsage()` は `limit` に `aiUsage.limit \|\| AI_FREE_DAILY`（＝10）を書き戻し、`profiles.plan` を読まない。`PLAN_LIMITS` は plus 50 / pro 200 を持つ。free 10 ＝ AI_FREE_DAILY 10 なので**今日は誰にも当たらない**が、有料プランが出た日に「サーバーは許すのにクライアントが 10 で断る」になる。直すには上限をクライアントへ届ける必要があり、それは欠陥の修正ではなく**クライアントが読むものを増やす変更**なので、このラウンドではやっていない |

### 検査（`tests/r447-checks.test.mjs`・10本）

⚠ **綴りではなく挙動を測る。** 欠陥は実行時に書かれた**値**で、`js/ai-core.js` のどの行も
「正しく書かれて」いた——綴りを見る検査なら全行が緑になる。だからモジュールを本物のまま
実行し、`fetch` と `sb` だけを差し替える。

| | 何を falsifiable にするか |
|---|---|
| ①a/①b | 名乗りの無い 429 は日を消費せず、日次上限を名乗らず、**次の質問を黙らせない**（要求が実際に出ることを数える） |
| ②a/②b | ai-proxy 自身の2つの 429 は今までどおり信じ、今までどおり区別する（#R318 の回帰） |
| ③a/③b/③c | 古い写しは**断る前に行から読み直される**。同期の門は1回断って自分で直る。**本物の上限は読み直しても上限のまま** |
| ④ | 規則の綴りは1本（`aiUsage.used = aiDailyLimit()` の形が二度と現れないことも含む） |
| ⑤ | 名指せない 429 は、**名指すための本体**を残す |
| ⑥ | サーバー側の前提——429 はちょうど2か所・どちらも `used` を載せる・`turn_calls` は実際の count を返す・日次 429 は上限に達した行を要する |

修正前の木で走らせると **10本中6本が赤**（②a・②b・③c・⑥ は両方の状態で緑であるべき回帰の錨）。

⚠ `js/atlas-console.js` は行数の上限（`tests/r318 ⑨b`＝4,910 行未満）に当たった。**閾値は上げず**
**注釈を削った**（[[intmap-r433-lessons]]＝閾値を上げるのは defect の再導入）。4,908 行。
