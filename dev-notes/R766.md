## R766 — 「データと分析」の入口は、どの幅でも読者に届いていなかった。同じ欠陥はこれで 3 度目

〈#R763 の production verification 中に見つかった、その回とは無関係の既存の欠陥。
報告は「試したどの幅でも押せなかった（1024 / 820 / 760 / 700）」で、
**押せる幅が本当に 1 つも無いのかは確認できていない**と明記されていた。そこを確定させるところから始めた〉

### 1. 実測 — 押せる幅は 1 つも無い

本番（build **R765**）を 18 幅で測った。各幅で `resize` のあと**必ずリロード**して load-time の分岐を
走らせ直し、その幅が実際に使うレイヤー UI を**開いてから**測っている。

| 幅 | `body` | `#layer-dropdown` | `#layer-tools` | 開いた UI | `#btn-gis-panel` |
|---|---|---|---|---|---|
| 320〜767 | `m-lyr-tiles lsr-avail` | flex / `h=0` | **none** | ボトムシート | `0,0,0,0` |
| **768** | `m-lyr-tiles lsr-avail` | flex / `h=0` | **none** | ボトムシート | `0,0,0,0` |
| **769**〜1920 | `ms-narrow lsr-avail lsr-open` | **none** | flex | 右ドック | `0,0,0,0` |

⚠ **分岐の境界は 768/769 のちょうど間**で、**768 は touch 0 でも `m-lyr-tiles` が付いた**
——この分岐は幅だけで決まっており touch を見ていない（#R661 の懸念はここには効いていない）。
`preset:"mobile"` / `preset:"tablet"` とカスタム幅の結果は**完全に一致**した。

⚠⚠⚠ **そして消えていたのは「データと分析」だけではなかった。** 18 幅すべてで
`#btn-gis-panel` `#btn-upload-geojson` `#btn-compare` `#btn-correlate` `#btn-edu` `#lp-save`
`#btn-seismic-sim` `#btn-pandemic-sim` の **8 個全部**が `rect 0,0,0,0` / `offsetParent:null`。

**8 個はどれも隠されていない。** `display` は `block`/`flex`、`visibility:visible`。
隠れているのは**祖先**である。診断として `#layer-dropdown` を `display:flex` にしたら、
同じ 1440 幅で 8 個すべてが `258×31` の矩形を持ち、`elementFromPoint` が**全部 HIT** になった。
⇒ **欠けていたのはボタンでも CSS でもなく、経路。**

### 2. なぜ届かないのか — 2 つの別々の原因が 2 つの幅域を塞いでいた

1. **≥769px**: `#layer-dropdown` を表示する規則が**存在しない**。`imLayerPanel` は
   **#R296 以降ただの定数 `'right'`**（`js/app-body.js`。設定項目も localStorage の値も無い）なので、
   `apply()` の `document.body.classList.remove('lsr-avail')` 腕は**到達不能**で、
   `body.lsr-avail` は**全幅・全端末で常時付いている**。CSSOM を全走査して `.layer-dropdown` に
   `display` を書く規則は「基底の `none`」と「`#mo-mount-layers` の中のときだけ `flex !important`」
   の 2 つだけだった。
2. **≤768px**: `css/intmap.css` の 1 行が帯を名指しで殺している
   ——`body.m-lyr-tiles #mo-mount-layers .layer-dropdown > #layer-tools{ display:none !important; }`。
   シートは開き `#layer-dropdown` は `flex` になるが、`#layer-tools` が `none`。

### 3. ⚠⚠⚠ 同じ指示に同じ間違った答えを返したのは 3 度目で、その記録は現場に書いてあった

- **#R242** が地震シミュレーターのボタンを `#layer-tools` に足し、**#R243** が書き直した。
- **#R666** がパンデミックのボタンを `#layer-tools` に足し、**#R670** が書き直した。
- **#R729** が「データと分析」を `#layer-tools` に足し、**今回**報告された。

`js/map-ui.js` のツール CSS の直前には #R243 の警告が、`SIM_TOOLS` の中には #R670 の警告が
**散文で書いてある。私はそれを読んでから作業した。**
⇒ **現場の警告は「足すな」とは言えても「足したら届かない」を測れない。**

⚠⚠ **そして最初の 2 回の直し方が、3 度目を必然にしていた。**
どちらも**扉を 1 つ `SIM_TOOLS` へ写す**という答えで、それは報告された 1 個を直し、
**次の 1 個を暗いまま残す**（`.agents/rules/no-ad-hoc-hardcoding.md` §1 が禁じる形そのもの）。
実際その 2 回で救われたのは 2 個だけで、**残り 6 個は #R296 以降ずっと暗いまま**だった。

### 4. 直したもの — 一覧ではなく経路

`#layer-tools` は**実体が 1 つのノード**である。写しを作らず、
**読者が実際に見ているホストの Tools 節（`.lst-toolbody`）へ移す。**

**この形の先例はリポジトリの中に既にあった**——`#layer-active-section` が
`_placeActiveSection()`（`js/data-layers.js`）で、まさにこれをやっている。
正本は `Architecture.md` §8.6。

- **ホストは幅から導かず、ブラウザに訊く。** 携帯でもデスクトップのサイドバーは `isConnected` の
  ままなので `_liveHosts()` だけでは隠れたほうに置いてしまう。`getClientRects().length`
  （＝組版されているか）が browser 自身の答えで、`_hostShown` が「実際に引き上がっているシート」を
  優先する。運べるホストが無ければ**帯はそのまま**（fail safe）。
- ⚠⚠⚠ **自分で入れた欠陥を 1 つ、実測で見つけた。** `buildTiles()` は `.lst-root` を
  `replaceWith` で丸ごと差し替えるので、**運んだ帯ごと捨てられる**。そして**外れたノードは
  `getElementById` から消える**ので、id で救い出す `reorganizeLayerPanel()` は
  それらを見つけられず、空の帯を作り直す。
  **実測: 携帯 375px で `#btn-correlate` / `#edu-mount` / `#lyr-presets` が
  セッションの残り全部で行方不明になった。** 局所の検査は全部緑のままだった。
  ⇒ 捨てられる**前に** `#layer-dropdown` へ退避させる（`unmountFrom()` も同じ）。
  ⚠ **`document.body` へは退避させない**——パネルの外に出た帯は地図の上に描かれる。
- **二重の扉は宣言から計算する。** 地震とパンデミックは `.lst-toolrow` を既に持つので、
  帯の写しも出すと同じコマンドを 2 か所が差し出す。ボタンが `data-os-act` で、行が `data-act` で
  **自分が押すコマンドを名乗り**、重なったほうのボタンが隠れる。
  **id の対応表はどこにも書かない**——行が明日足されれば、その双子はひとりでに黙る。
  印を**ボタンに**付けるのは `data-lyr-tool` が #R729 でそうした理由と同じ。
- 節の見出しは 1 つ（入れ子の 2 つ目を CSS が隠す。⚠ **規則は「配置」に付いていて、ボタンの id には
  付いていない**）。件数は運んだあとに**数え直す**。検索も帯に効く——帯のボタンは `data-nm` を
  持たないので**読者に見えている文字**で照合する（これが無いと「経路」で絞った画面に
  比較ビューとデータと分析が残っていた）。

**実測（ローカル build）**: デスクトップ 1024 で 6 個すべて `245×34` / `elementFromPoint` HIT、
携帯 375 でも 6 個すべて HIT、双子 2 個は `display:none`、件数は **17**（行 11 ＋ 扉 6）。
`#btn-gis-panel` を**実際に押して** `IntMapGis.panel.isOpen()` が true・パネル `360×568`。

### 5. 検査 — 綴りではなく到達可能性、そして置き場所も判断のうち

`tests/smoke.spec.js` の **R766 ①②③**。

⚠⚠⚠ **「`#btn-gis-panel` が在る」を測ってはならない。** それは**ずっと在った**——ハンドラも、
遅延モジュールも、OS アクションも。その綴りを書いた検査は**出荷済みのビルドで緑になる**
（[[intmap-restate-the-defect-not-the-fix]]）。測るのは元の欠陥のほう:

> **帯が差し出す扉は、読者が開くパネルから到達できる。**

扉は**列挙せず DOM から数え上げ**、`elementFromPoint` で 1 つずつ訊く
（[[intmap-visible-is-not-unoccluded]]——`display` / `visibility` / `opacity` /「viewport の中」は
**不透明な板が乗っていても全部通る**）。⚠ 下限は「1 つ以上」で**今日の個数ではない**——
携帯では `#btn-correlate` / `#edu-mount` / `#lyr-presets` が作られないので、
個数を固定するとその差が不合格になる。

⚠⚠ **置き場所が `smoke.spec.js` なのは意図的である。** 新しい spec を 1 本足すと、

- `check:testbudget` の **core 天井（0.6 分）を壊す**（未計測の spec は p75 = 41s で課金される）。
- `scripts/tiers.mjs` の current-round 例外により、**次のラウンドで deep へ降りる**
  ——deep は nightly と dispatch でしか走らないので、**push でも PR でも走らなくなる**
  （[[intmap-deep-tier-rots-unwatched]]）。**3 度再発した欠陥の検査としては最悪の置き場所。**

`smoke.spec.js` は `CORE_ALWAYS` で**既に起動している**。`scripts/test-budget.mjs` 自身が
その理由を書いている——「the assertions are free, the boot was the whole price」。
⚠ 携帯の面も**リロード不要**で測れる（`js/mobile-ui.js` の `syncResponsive` が `resize` と
`mq.change` で `applyLayout` を回すので、2 つ目の起動を買わずに両レイアウトが測れる）。

`tests/r766-gis-entrance-checks.test.mjs`（4 本・147 ms）は**ソースが答えられることだけ**を測る
——運んだノードは捨てられる前に救い出されているか（**順序**）・二重の扉の判定が宣言からの計算の
ままか・`data-os-act` が実在するコマンドを名乗っているか・帯を動かす各経路のあとに再配置が
走るか。⚠ **到達可能性そのものはここでは測らない**（ソースを読むことは、この欠陥が 3 ラウンド
生き延びた方法そのものである）。

### 6. 測定の罠 — シートの transition はペインが合成されていないと進まない

携帯の測定で `#mo-sheet` の `top` が **879**（viewport 812 の外）から動かず、
`scrollIntoView` も効かない状態が 2 度あった。**screenshot を 1 枚撮ると 146 に進む。**
[[intmap-raf-zero-is-not-a-product-defect]] と同じ形で、**製品の欠陥ではなく測定環境**である。
到達可能性を測る前に必ず 1 枚撮ること。

### 7. 残っていること

- 運ばれた 6 個は**既存の絵文字ボタンのまま**で、SVG の `.lst-toolrow` と並ぶと様式が揃わない。
  既存 UI の作り直しは今回の依頼の外なので触っていない（`AGENTS.md` §3-2）。
- 扉は 11 行の**あと**に並ぶので、デスクトップでは「データと分析」に届くのにスクロールが要る。
  並び順は製品の判断なので、帯が元々持っていた順序のままにした。
- `tests/durations.json` の `tests/smoke.spec.js` は **8**だが、このマシンでの実測は
  **186 秒**である（台帳は CI の分割実行由来で、このマシンの直列実行とは別の数）。
  今回の増分は **5.8 秒**（① 2.5s / ② 0.8s / ③ 2.5s）で、`check:testbudget` は緑のまま
  （core 0.5 / 0.6 分・全体 81.4 / 81.4 分）。**台帳のずれ自体はこの回の主題ではないので触っていない**
  ——直すなら suite 全体を測り直す回が要る。
- `npm test` の赤 10 件のうち **5 件は tree lock の待ち（並行セッション）**・**1 件は SwiftShader の
  fragment shader** で、どちらも主張の不一致ではない（[[intmap-r301-lessons]]）。
  残り **5 件はビルド印が R765 のままだったこと 1 つの別の読み手**で、印を上げて解消した
  （[[intmap-round-number-has-five-readers]] そのまま）。
