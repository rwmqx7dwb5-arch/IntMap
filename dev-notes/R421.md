## R421 — **歴史国境の更新を「年」から「日」へ——日付は最初からデータの中にあった**

「歴史国境の更新ペースをさらに細かくして。理想は月日単位。特に20s前半が荒い。」

### 1. 細かくするために足したものは何も無い。捨てるのをやめただけである

`data/cshapes.js` の 1 レコードは `["United States of America",2,1886,1,1,1959,1,2,[…]]`——
**`開始年月日 → 終了年月日`**。日付は #R117 でこの束を作った日から入っていた。
それを読む側が、こう書いてあった：

```js
/* active on July 1 of `year` */
const started=(sy<year)||(sy===year&&(sm<7||(sm===7&&sd<=1)));
```

**暦年に1回、7月1日に生きていたかどうかだけを訊いていた。** 実測（出荷している束そのもの）：

| | 旧（7月1日） | 新（日単位） |
|---|---|---|
| 標本を取る瞬間 | **104**（暦年） | **369**（実際の変化日） |
| 到達できる異なる世界 | **68** | **132** |

レコードは 710 本・変化日は 365。**変化の約 72% は、ディスクの上にありながら画面に出る道が無かった。**

### 2. 時計と地図は、別々の日を指していた

`IntMapTime.setYear(y)` が置くのは **6月15日**（`js/chronos.js`：`Date.UTC(y,5,15,12)`）。
`csFC` が読んでいたのは **7月1日**。1920 年でこの2日は同じ世界ではない——**166 主体と 167 主体**。
つまり**年スライダーは、自分が名乗っている瞬間より16日先の世界を描いていた。**

⚠ **どちらかに寄せて直していない。** 寄せれば慣習が2つ残り、次に誰かが片方だけ動かす。
`go()` が**時計の瞬時そのもの**を受け取るようにして、**2つ目の慣習を消した**。

### 3. 報告された「20s前半」は、この file で最も密な年だった

1920 年の変化日は **14 本**——1/12 タルトゥ、2/2、2/10、2/11、3/17、4/26、6/4、6/28、
7/23 セーヴル、9/2、10/7、**10/28 ベッサラビア**、12/17、12/24。
これが **5 つの異なる世界**を作る。**7月1日サンプルはそのうち 1 つしか見せていなかった。**

本番ビルドで実測（1920 年内で地図が本当に描き替わることの確認）：

```
1920-06-15 → epoch cs19200604  166 主体   ← 年スライダーが落ちる場所
1920-10-28 → epoch cs19201028  166 主体   ← Emirate of Bukhara が消え、Ruanda-Urundi (Belgium) が現れる
1920-11-05 → epoch cs19201028             ← 同じエポック＝再描画ゼロ
```

7月以外の日でも日単位であることの独立した確認——**ドイツ再統一は 1990-10-03**：
`1990-10-02` に German Democratic Republic は**居り**、`1990-10-04` には**居ない**（epoch `cs19901003`）。
年単位の選択子には**そもそも表現できない**事実である。

### 4. 「増やした」ではなく「捨てるのをやめた」ことを、検査に書いた

粒度を細かくする変更で怖いのは、**粒度以外の何かが一緒に動くこと**。だから
`tests/r418-checks.test.mjs` ④ は、**1886〜2019 の134年すべてについて、新しい選択子の
7月1日の世界が旧選択子と完全に一致する**ことを要求する（実測 **不一致 0**）。
一致しないなら、それは粒度の話ではない。

⑤ は逆側——**どのエポックでも地図が空にならない**（最小 128 主体）。終了日の包含判定を
1日間違えると、変わり目の日だけ世界が消える。これは赤くならずに**静かに**起こる形である。

### 5. キャッシュの鍵は日付ではなく「エポック」

鍵を日付にすると、スクラブした日数だけ FeatureCollection を作り直し、
「同じなら何もしない」短絡が死ぬ。鍵は `csEpoch(d,y,m,d)`＝**その日以前で最も新しい変化日**。
同じエポックに入る2つの日は同じ鍵になるので、**変化の無い年代をいくら擦っても再描画は起きない**
（1920-11-05 が 1920-10-28 の鍵を共有することを実測）。1920 は逆に 14 回刻む。

### 6. 176年を300pxに載せたスライダーでは、10月28日に指で止められない

だから **国境ステッパー**（`#ntl-bstep`）を置いた。「実際の国境変更日にスナップ」——
利用者が選んだ形である。年スライダーは粗い移動のまま、`‹ ›` が**実際の変化日**を1つずつ歩き、
間の readout が**いま画面に出ている世界が生まれた日**を出す。

⚠ **変化日の一覧を UI 側に持たせていない。** 持てば多角形と食い違う日が必ず来る。
一覧は多角形と**同じレコード**から導出し（`csBounds`：各レコードの開始日と、**終了日の翌日**——
後継レコードの無い消滅もエポックを終わらせる）、`IntMapTimeBorders` が
`changeAfter` / `changeBefore` / `changeAt` / `changeDates` で公開する。パネルはそれだけを尋ねる。

⚠ **ステッパーはマスタークロックに書く。** 国境レンダラを直接叩けば、
ニュース・統計・気候区だけが取り残されて、1つの瞬間に2つの世界ができる。

⚠ **ローカルの getter であって `iso` ではない。** `IntMapTime` の `iso` は `toISOString()`＝UTC。
`#ntl-date` が書くのは**ローカル午前0時**なので、UTC で読み直すと東半球では
**利用者が選んだ日の前日**が描かれる。`e.year` が既に `getFullYear()`（ローカル）なので、
月と日も同じ場所から取る。

### 7. ⚠⚠⚠ 4か所から呼ばれ、どこにも定義が無かった関数

作業中にコンソールを見て見つけた、**この経路の既存の不具合**（利用者の承認を得て同じ PR で直した）。

`js/time-borders.js` は `whenStyleReady()` を **4 か所**で呼ぶ。この関数は
`js/data-layers.js` の**モジュール内部**にしか存在せず、**#R163 がこのファイルを index.html の
クロージャから出した時からスコープ外**だった。実測：**起動毎に 6 件の uncaught rejection**。

これは #R140 が「歴史的国境が表示されない・再読み込みで治る」を直すために入れた
**再試行機構そのもの**である。スタイル読込中に `ensure()` が false を返したとき、
準備できてから描き直すはずだった。**一度も動いていない。**

⚠ **なぜ 90 ラウンド誰も気づかなかったか。4か所のうち3か所が `try{}catch(_){}` の中にある。**
catch が ReferenceError を飲み、描き直しが起きないことは「再試行は要らなかった」と
見分けがつかなかった。**最初の行で throw する機構は、弱い安全網ではない——安全網が無い。**

正本と同じ形（listen ＋ poll ＋ 約6秒で強制解決）を、**この file 自身の `_imCanDraw()`** の上に置いた
——「まだ描けるか」の考えを2つ持たないため。実測：修正後、同じ操作でエラー **0 件**。

### 8. Atlas は日単位を自動的に継承した——カタログだけが古かった

Atlas は `{"type":"timeTravel","date":"YYYY-MM-DD"}` で**既に任意の日付を置ける**ので、
dispatch にも schema にも手を入れずに日単位の国境を得た。**能力は増やしていない**
（`CONSTITUTION.md` §5：制限も例外も増やさない）。

古かったのは**説明**だけ——カタログは「歴史には YEAR を使え」と教えていた。#R115 の規則
「カタログが書いていない能力は planner に存在しない」の裏側で、**実体が変わったのに
説明が変わらなければ、planner は使えるものを使わない**。条約・分割・独立を訊かれたら
**発効日**を出すよう書き直した（例つき）。

### 9. 残した既知の食い違い（この round では直していない）

Atlas の `a.date` は `Date.parse("1920-10-28")`＝**UTC 午前0時**を置く。`#ntl-date` は
**ローカル午前0時**を置く。**書き手が2人いて慣習が違う。** 西半球の利用者が Atlas に
`1920-10-28` を頼むと、国境は 10-27 の世界になり得る。
これは news・統計・気候区にも同じだけ効く**アプリ全体の話**で、正しく直すには
書き手全部と `ymdISO` の側を揃える必要があるため、**この round の範囲では触っていない**。
