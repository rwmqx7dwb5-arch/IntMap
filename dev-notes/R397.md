## R397 — **検証器の目が閉じていた——そして IntMap 自身のデータが天井になっていた**

> 依頼: 「Atlas を『IntMap内の情報だけで回答する付属チャット』から、IntMap全体を観測・操作しながら、
> 必要に応じて外部世界へ自由に情報を取りに行ける Central OS へ。**Atlas が IntMap を使うのであり、
> Atlas が IntMap に従属するのではない。**」（追加指示: 質問意図を Capability 制約より優先／
> `research.brief` は明示要求時のみ／通常の知識質問に画面操作を自動追加しない／代表座標を
> 「ユーザー指定地点」として prompt へ渡すな／Answer Audit に「元の質問へ直接答えたか」を追加）

### 着手前に測ったこと — 部品は既にあった

Central OS の構造は**ほぼ全部実装済み**だった: 能力レジストリ **126**（#R318）・`IntMapOS.execute()` の
**11 段**（前後観測・事後条件・競合直列化）・planner の**依存グラフと GoalSpec**・evidence registry・
claim/dimension の回答契約・状態 provider **17**。だから「作る」ラウンドではなかった。
**動いていなかったのは、それらが自分の仕事を確かめる目である。**

### ⚠⚠⚠ ① 検証器そのものが、存在しない名前を3つ呼んでいた

| 書かれていた名前 | 実際 | 起きていたこと |
|---|---|---|
| `GE().layers.list()` | **ファサードに無い**（`has`/`add`/`remove`/`setVisible`/`isVisible`/`getLayout`/`sourceData` のみ） | `?` ガードが null 枝を取り `visibleLayerIds()` は**永久に `[]`**。`layer` 観測器**13 能力**と `paintNow().visible` が常に 0 |
| `getCenter()` を `c[0]`/`c[1]` | **両アダプタとも `{lng,lat}`** | `+undefined`＝NaN、そして **`JSON.stringify(NaN)` は `null`** ⇒ `changed()` は null 同士を比較。**カメラ観測器はズーム・方位・傾きしか見えていなかった** |
| `'nlq-pin-src'` / `'atl-poi-src'` | **全リポジトリでこの1行にしか出現しない**（実名は `user-pins`／`nlq-poi-src`） | `sourceFeatureCount` が catch を取り `pins`/`poi` は常に **-1**。`paint` 観測器**23 能力**がピンの出現を見られない |

**②の帰結が報告の中心だった**: 同じズームのまま惑星を横断する `view.flyTo`——国から国へ飛ぶのは
正にこれ——が `partial / no_change` を返す。**起きていない失敗が修復ループに入る。**

⚠ **教訓は綴りではなくガードの側にある。** `GE().layers.list ? … : null` と `catch (_) { return -1 }`
はどちらも用心として書かれていて、どちらも「この名前は間違っている」を**もっともらしい読み**に変換した。
⇒ `tests/r397-checks.test.mjs` の §1〜② が、**ファサードと生成側のソースから名前を導出して**照合する。

### ⚠⚠⚠ ② 目的の門は、やはり注記だった

`js/atlas-planner.js` の見出しはこう書いている——「**THE GOAL IS A GATE, NOT A NOTE.** #R135 は
`_goalValidation` を計算して debug record に入れ、**誰も読まなかった**」。そして **#R318 がもう一度
debug record に入れていた**。本番の唯一の呼びは**修復ループが終わったあと**なので何も作用できない。
⇒ `js/atlas-policy.js` の `unmetGoalText()` が判定文を返し、**呼びが全部成功していても目的が未達なら**
同じ有界修復ループ（最大2回）に入る。修復プロンプトは2種を区別する——失敗した呼びは**別の呼び**を、
未達の目的は**欠けている生成物**を求める。

### ⚠⚠⚠ ③ schema は Gemini に届き、OpenAI には一度も届いていなかった

`responseSchema` は全 JSON タスクで解決され `callGemini` に4か所で渡っていた。**`callOpenAI` には
その引数が無かった。** 現行 provider は `{type:"json_object"}` だけを受け取り、フィールド名・列挙・
必須集合は**タスク規則の散文とクライアントの事後正規化にしか存在しなかった**。
⇒ `strictJsonSchema()`: 大文字型名→小文字、**任意フィールドは `["string","null"]` に広げる**、
**列挙も同時に `null` へ広げる**（型で許して列挙で禁じると、どのインスタンスも通らない schema になる）。
既存の 400 梯子に `schema → json_object` の段を足したので、方言を嫌うモデルでも**失う応答は無い**。

### ⚠⚠⚠ ④ 「未配置」は geocoder の不具合ではなく、欠けた欄だった

`_pinReplyPlaces` の mapper は `name/country/kind/summary` を読み、**座標を1つも読まない**。既存ピンとの
照合は**正規化した名前の完全一致だけ**——USGS の「14 km SSW of X」と本文の「X」は**別の場所**である。
⇒ 正しく解決済みの座標を捨てて再照会し、2度目が厳しいと 「本文に登場したが未配置」。

`js/atlas-geo-object.js` が1つの形（ID・名前・緯度経度・種別・日時・出典・確度＋**provenance**）を持ち、
照合は**3通り**（`geoId`／正規化名／**含有**）。`pointLike` な座標は**再解決しない**（2度目の照会は
一致するか*外す*かで、外れたとき正しい位置が負ける）。`analyze` 経路が `_env.places` を `{n,c,k}` に
**再平坦化**していた1行——統合した座標を、必要になる1行前で捨てていた——も直した。

### ⚠⚠⚠ ⑤ 代表点は「地点」ではない

`resolved_place_centroid` は `POINT_LIKE` の**外**に置き、`describesUserPoint()` が唯一の判定。
**provenance を宣言しない座標は centroid 級に落ちる**——上へ推定すると、この欄を作った理由が消える。

### ⚠⚠ ⑥ 自分の新モジュールが、1版だけ報告のバグを再現した

`isFinite(Number(null))` は **true**（`Number(null)` は 0）。だから `placed({lng:null, lat:null})` が
真になり、`mergeKnown()` は「座標を持っていない対象にだけ補う」ので**このファイルの存在理由である
統合を飛ばした**。自分で書いた確認スクリプトの4番目のケースが捕まえた。**Null Island は場所ではない。**

### ⚠⚠⚠ ⑦ 偏りは標本の偏りだった

「世界の異常TOP3で地震だけ3件」——**モデルが地震を好んだのではない。** `[EARTHQUAKES (USGS, last 24 h)]`
は**数十行のリスト**で各行にマグニチュードが付いている。他の災害は**散文1〜2行**。⇒ **並べられる行が
それしか無かった。** 「分野横断で比較せよ」というプロンプトは、ソート済みの数値列と段落を比べさせている。

`js/atlas-anomaly-score.js`: 深刻度は**種別ごとの固有スケール**（Mw／カテゴリ／VAL／CAP の4段）、他に
影響人口・地理的範囲・平常時からの乖離・新しさ・確度・国際的重要性の**7成分**。severity は最大の重みで
**なお半分未満**——だから**人口密集地の M5.8 が外洋の M7.4 に勝つ**（実測 0.7194 > 0.7084）。
そして**各種別の上位だけを競わせる**。⚠ **出力の割当ではない**——真に地震の日は地震が1位（実測）。
⚠ 測っていない成分は `missing` に名前で出し、**既定値を与えない**。

### ⚠⚠⚠ ⑧ 意図は capability カタログより強い

- 明示要求の無い `brief` は **`analyze` へ差し替える**（消さない。質問には答えが返らなければならない）
- 地図意図の無い**視点・選択操作**は落とす。`researchMap` は説明も担うので `analyze` へ落とす
- ⚠ **自分の門が最初にこの要件を壊した**: 「台湾へ旅行したい」には地図の動詞が1つも無いので `flyTo`
  が落ちた——**「台湾への移動が失敗しない」は依頼が名指した要件**である。⇒ 旅行・旅程を別の意図として
  9言語で立てた。明示要求の `brief` も地図意図に含める
- ⚠ **空のプランを返さない**——全部落とすと質問が沈黙になる

### ⚠⚠ ⑨ 「元の質問に答えたか」は警告に留めた

`error` として書いたら **`tests/r350` の正しい回答例で発火した**。質問は「中華人民共和国は世界有数の
経済規模。実際に支えているのは何？」、回答は「需要面では最終消費が最大で、規模そのものを可能にして
いるのは製造能力・供給網…」——**良い回答が、質問の名詞を1つも再利用していない**。語の重なりで測る限り
この例は通せず、`error` は正しい回答を修復パスへ送って利用者の枠を余分に使う。⇒ 所見は記録し
（`answer.question_not_addressed` / `answer.question_only_peripheral`、どちらも `warning`）、`error` へ
上げるには**主語・焦点を解析する仕組み**が要る。⚠ 日本語と英語で**同じ欠陥に同じ判定**が出るまで直した。

### ⚠⚠ ⑩ 状態の6セクションはモデルに0バイト届いていた

コメントが「`toPrompt` の JSON で届く」と書いていたが、**`toPrompt` の本番呼び出しは0件**。
⇒ 6セクションを `renderPrompt` に載せ（**中身があるときだけ**）、**警報・監視・Workspace** の provider を
足し、`settings` に地図エンジンを足した。⚠ **base/projection は足していない**（`camera` が既に両方を
持つ＝2つ目の写しは食い違いの始まり）。⚠ **実在しない API は使わずに書いた**——`IntMapTime` に
`play()`/`range()` は無く、`IntMapWxPlayer` の公開鍵に再生状態を読む口が無いので**再生状態は
載せていない**。`IntMapMonitors` の一覧は async かつ Supabase を叩くので、在否と領域だけを載せた。

### ⚠⚠⚠ 自分が入れた高深刻度の ReDoS を CodeQL が PR で捕まえた

「元の質問に答えたか」の助詞剥がしを `(?:の|は|…|と|…|とは|…)+$` と書いた。**`と` と `は` が
`とは` と並んで選択肢にいる**ので、「とはとはとは…」は各段で2通りに分解できる。`+` と `$` の組み合わせで、
一致しない末尾は全経路を試す——**利用者が打った質問文が入力である**。

実測（当該部分パターン単体）: **16 回 27 ms → 20 回 47 ms → 24 回 767 ms → 26 回 3,484 ms**。
54 文字の質問でタブが 3.5 秒固まる。40 回なら時間の単位になる。

⇒ **量化子を選択肢の上に置くのをやめた**。1 パス 1 トークンを固定文字数のループ（12 回）で剥がす。
実測: **20,000 回で 2.0 ms**（線形）。`tests/r397-checks.test.mjs ⑩d` が**形（`)+` が無いこと）と
時計（20,000 回が 500 ms 未満）の両方**を見る——時計だけでは不安定、形だけでは走っている証拠にならない。

⚠ **ローカルの門は7本とも緑で、`npm test` も緑で、これは1つも捕まえられなかった。** 静的解析が
別の質問を訊いているからである。**CI の CodeQL は「通ればよい確認」ではない。**

### 起動予算を上げた理由（ratchet は理由を要求する）

`node scripts/perf-budget.mjs --update`。実測の増分と、それを受け入れた根拠:

| 項目 | 増分 | 何が増えたか |
|---|---|---|
| eager brotli | **+0.4 kB** | `js/atlas-capabilities.js` の観測器3件（`getStyle()` を1回読む走査・`getCenter()` の防御的な読み・実名の source id）。**起動モジュール数は 279 のまま** ⇒ 新規3本は async 側だけに載っており、分割は意図どおり |
| async `atlas-console` | +20.4 kB | 新規3本（geo-object / policy / anomaly-score）と方針3節。**要求されたときにだけ取得される** |
| async `atlas-executor` | +2.6 kB | `js/atlas-state.js` の provider 3本と `renderPrompt` の9行 |

⚠ **eager の +0.4 kB は「45 能力分の検証が動くようになる」対価**である。観測器が `[]` と NaN と `-1` を
返している間、`view.flyTo` は「動かなかった」と報告し、ピンは「立たなかった」と報告していた。
起動バイトが増える変更は理由を言わなければならない（#R311）——これがその理由。
