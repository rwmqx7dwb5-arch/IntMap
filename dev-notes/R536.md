## R536 — **6つの地名が「特定できませんでした」と出たのは、地名が難しかったからではない**

> 利用者報告: 「京阪神の経済をわかりやすく解説して」の回答の末尾に
> 「本文に登場したが未配置（正確に特定できませんでした）: 大阪府, 京都府, 兵庫県, 大阪市, 京都市, 神戸市」。
> 「特定できなわけがない。」

そのとおりだった。**特定できなかったのではなく、一度も特定しに行っていなかった。**

### 何がそこにあったか

`_pinReplyPlaces`（`js/atlas-verify.js`）は、回答が名指した地点を 4 段のはしごで解決する——
**届いた座標 → この会話の geo 台帳 → 地域ジオコーダ → 厳格 Nominatim**。#R489 が 2 段目を足したとき、
こう書いた:

```js
if(GEOBJ.pointLike(it)){ g={...}; }
else if(ledger){ try{ const k=ledger.resolve(it.name,…); if(k&&k.lng!=null) g={...}; }catch(_){} }
else if(it.src==='structured'){ … geocode … }
else { … _atlGeocodeStrict … }
```

**段の条件が「上の段が答えたか」ではなく「その解決器が存在するか」になっている。**
`ledger` は `js/atlas-console.js:1765` が `GLEDGER` として**必ず渡すオブジェクト**なので、
座標を持たずに届いた地点は**例外なく** 2 段目の腕に入る。そして台帳がその名前を持っていなければ
——**前のターンが同じ名前を解決済みでない限り、常にそうである**——`g` は `null` のまま
**連鎖がそこで終わる**。下の 2 段は本番で**一度も実行されない**。

台帳は解決に成功したものしか記録しないので、これは自分では抜けられない: 解決しない → 記録されない →
次も解決しない。**本番の Atlas は、この経路から Nominatim を一度も呼んでいなかった。**

### 実測（出荷モジュールを評価した）

`js/atlas-verify.js` は本物の ES module なので、Node から `import()` して同じ 6 件を通した
（#R505 の作法——ソースを読む検査ではなく、走らせる）。

| 渡した `ledger` | ジオコーダ照会 | 結果 |
|---|---|---|
| `null`（node の検査が見ていた形） | **6 回** | 配置される |
| 空の `GLEDGER`（**本番が必ず渡す形**） | **0 回** | 6 件すべて「未配置」 |

下段の文面は、利用者が貼った文面と一字一句同じだった。

### ⚠⚠⚠ 全計器が緑だった理由は、ファイル自身が書いていた

`js/atlas-verify.js` の注記にこうある——「**OPTIONAL: without a ledger this file behaves exactly as
it did (the node checks)**」。この主張は**散文で宣言され、その片側だけが検査されていた**。
台帳を渡した側は一度も走っていない。#R429 の形（1 つの経路だけを守る検査）であり、
`AGENTS.md` §3 の 9（`.agents/rules/no-ad-hoc-hardcoding.md`）が言う「規則は関数ではなく事実に付ける」の裏返しでもある。

### 直し方 — 段の条件を「答えたか」に戻す

各段を `if(!g && …)` にした。これで**答えられなかった段が、はしごを終わらせることができない**。
構造以外は何も変えていない: `pointLike` を再解決しない #R397 の規則、structured は `geocode` →
厳格 Nominatim の順、text 候補は国ヒント無しで厳格のみ、`ambiguous` は配置せず `ambiguous` と報告、
`infraFail` の数え方、14 ピンの上限、0.05° のセル重複除去、`PINPASS_BUDGET_MS` の予算——すべて元のまま。

### 検査 — 綴りではなく、走らせて測る

`tests/r536-checks.test.mjs`（5 本）。出荷モジュールを、**アプリが取りうるすべての台帳の状態**で走らせ、
ジオコーダと Nominatim を差し替えて**到達した段を数える**。守っている事実は
**「何も言えない任意の段は、その段が無いのと区別できてはならない」**:

1. 空の台帳は、台帳無しと**まったく同じ**照会・同じ配置・同じ未配置一覧を出す
2. 名前を持っている台帳は、その 1 件だけ照会を省き、残り 5 件は照会される（#R489 の利得は保たれている）
3. 座標を持って届いた地点は、どの解決器にも届かない（#R397 を綴りではなく挙動で）
4. ジオコーダが答えなければ、厳格 Nominatim まで落ちる
5. 同名 2 件は `ambiguous` として報告され、片方にピンされない

⚠ **修正前のモジュールに対して 5 本すべてが赤、修正後に 5 本すべてが緑**であることを実測してから採用した。

### 残っている観察（直していない）

台帳への問い合わせは `ledger.resolve(it.name,{countryCode:it.countryCode})` だが、この `it` を作る
mapper は `name/country/kind/summary/lng/lat/provenance/src` しか写さないので **`countryCode` は常に
`undefined`**——絞り込みのヒントが構造的に届いていない。`js/atlas-console.js:3088` の
`{countryName:…}` も台帳の `resolve` が読まない名前である。今回の不具合とは独立なので触っていない。
