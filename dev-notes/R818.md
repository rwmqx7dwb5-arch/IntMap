走れた検査はすべて緑。**PR の画面にも ruleset にも「何が足りないか」は出ない。**

`Protect main` の必須チェックは 4 本: `Browser smoke + internal QA` / `Static checks` /
`Regression suite` / **`Migrations rebuild + RLS/permission tests`**。4 本目が加わったのは
**2026-09-18 03:14**（ruleset の `updated_at`）で、その job は `.github/workflows/db.yml`——
**`paths: [supabase/**, …]` で絞られていた。**

## 1. ⚠⚠⚠ 抑えられた必須チェックは「skip」ではなく「pending」である

path フィルタが job を起動しなければ、その context は**一度も報告されない**。
GitHub はその不在を「走らせる必要が無かった」とは読まない——**「まだ終わっていない」と読む。**

⚠ **どちらの設定も単独では正しい。** 絞るのは正しく（DB を触らない PR に 8 分の Docker は要らない）、
必須にするのも正しい（migration を未検証で main に入れない）。**2 つが揃ってはじめて**、
`supabase/` を触らない全ラウンドを永久に止める門になった。直前の 3 ラウンドが通っていたのは
**ruleset 変更より前だった**という、それだけの理由。

## 2. 直したのは引き金であって、要求ではない

- **`pull_request:` からフィルタを撤去**——どの PR でも job が起動し、**報告する**
- **重い工程は `steps.scope.outputs.run` の後ろへ**（Docker・Supabase CLI・rebuild・pgTAP・
  backup/restore）。飛ばしたことが**「外の不在」ではなく「ログの中の可視な skip」**になる。
  DB を触らない PR が払うのは数秒
- **判定は git で**。`dorny/paths-filter` 等を足すと SHA 固定の供給網依存が 1 つ増える（#R138 SEC）
  ——同じ問いは `git diff --name-only` で答えられる

⚠⚠ **見張りは走らせる側に倒す。** push・manual dispatch・base commit が手元に無い・diff が
計算できない——**どれでも全部走らせる**（`run_full`）。答えられない問いに「skip」と答えることが、
この見張りが唯一してはならないこと。`fetch-depth: 0` はそのためで、無いと全 PR が
「base が無い」経路に落ちて**毎回 8 分払う**（正しいが高い）。

## 3. 検査

`tests/r793-db-gate-never-reports-checks.test.mjs`（4 本）。⚠ **測るのは「`paths:` が無いこと」
ではない**——それはこの回が到達した答えで、守るべき欠陥ではない
（[[intmap-restate-the-defect-not-the-fix]]）:

1. `pull_request` に `paths` / `paths-ignore` / `branches` のどれも無い（**到達可能性として述べる**）
2. job 名が必須チェックの綴りのまま（改名は同じ BLOCKED を無言で作る）
3. **データベースに触る工程が 1 つ残らず見張りの後ろ**——⚠ 手で並べた step 名ではなく
   「`supabase` / `psql` / `backup-db.sh` / `restore-test.sh` に触れているか」で母集合を作る
4. 見張りが `supabase/` を見ており、答えられない 3 経路が `run=true` に倒れる

⚠ **1 だけを見る検査は「報告するが何もしない job」を緑にする**——[[intmap-records-with-no-reader]]
の裏返し（記録の無い読み手）。だから 3 と 4 が要る。

⚠ 変異 3 通り（フィルタ復活・見張りの脱落・fail-closed 化）で**それぞれ 1 本ずつ**赤くなることを
確かめた。

## 4. ⚠ 残っている穴

**どの context が必須かは GitHub の設定にあり、チェックアウトからは読めない。** この検査が
測れるのは**リポジトリが持っている側の半分**（job は常に到達できる＝どんな要求を足しても安全）
だけで、「必須にした名前が本当に報告されうるか」の対照は**夜間の網でしか持てない**
（[[intmap-discovered-list-is-a-photograph]] と同じ形——上流照合は別に持つ）。
