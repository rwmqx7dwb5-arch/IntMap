## R467 — **ゲートが fr 100% と言っている画面に「Display name」が出ていた**

#R459 の本番検証（fr / ko）で見つかった。#R459 が直したはずの2件が残っていた:

```
#am-name  placeholder="Display name"
#am-pass  placeholder="Password"
```

### ① 呼び先が証明できないと、その文字列は宇宙から消える

#R459 は両方を `_authL(…)` で包んだ。`js/auth-ui.js` のそれは**遅延ラッパ**である:

```js
function _authL(){
  if(!_authL._p) _authL._p=window.IntMapLang.pick(()=>HOST.lang);
  return _authL._p.apply(null,arguments);
}
```

⚠⚠⚠ **これは `scripts/i18n-helpers.mjs` がヘルパだと証明できない唯一の形**で、
`Architecture.md` §10.1 は `js/map-readout.js` について**すでに記録していた**——ただし
「死んだ鍵の検査に使うな」という**片方向**の注意としてだけ。逆向きにも同じだけ危ないことは
書かれていなかった:

**呼び先が証明できない ⇒ その英語原文は `want` 集合に入らない ⇒ fr / ko / zh は inline 表を
引けず、`pick()` の引数0（＝英語）に落ちる。** `pick()` が位置引数で解決するのは最初の5言語だけ
なので、**5言語は正しく4言語は英語**という状態が、**どの百分率も下がらないまま**成立する。

⇒ **直し方は「表に行を足す」ではない。「計器が読める綴りで書く」である。**
`window.IntMapLang.t(HOST.lang,…)` に変えた瞬間に、ゲート自身が fr/ko/zh の不足を要求してきた:

```
fr: 2 of 5435 inline strings have no entry
    'Display name'   /* auth-ui.js */
    'Password'       /* auth-ui.js */
```

**要求されて初めて訳を足せる。** 遅延ラッパ自体は #R168/#R169 の factory 規則
（factory の本体では `const x=f()` は「宣言」ではない・`tests/r168-checks ④`）から来ているので
消せない——だから**綴りのほうを選ぶ**。

### ② 同じ属性に書き手が2人いた（#R459 の★とまったく同じ形）

テンプレートを直してもまだ英語だった。`js/auth-ui.js:178` のタブ切替が、開くたびに
`#am-pass` の placeholder を**上書きしていた**:

```js
$am('am-pass').placeholder = mode==='signup' ? _authL('Password (min. 8 chars…',…) : _authL('Password',…);
```

⚠ **#R459 が「★は2人の書き手がいるから両方直せ」と書いた、その同じ形**が1ラウンド後に別の場所で。
これは偶然ではなく、**「属性を書く場所」と「属性を書き直す場所」が別々に育つ**という構造。

⚠⚠ **さらにその1行上の送信ボタンはヘルパすら通っていなかった**——
`textContent = mode==='login'?'Log In':'Create account'` ＝ **9言語すべてで英語**。
属性ではないので #R459 の走査対象外だったが、同じ文の中にあったので併せて直した。

### ③ 検査は呼び出しグラフではなく「表」に訊く

`tests/r464-checks.test.mjs`。①は**この一族が画面に出す英語原文それぞれについて、
fr / ko / zh / zh-Hans の表が英語以外を持っているか**を直接読む。呼び出しグラフを経由しないので、
呼び先が証明できるかどうかに影響されない——**それがこのラウンドの欠陥そのものだった**から。

⚠ **変異させて赤になることを実測した**（`ui.fr.js` の `"Password"` の訳を英語に戻すと ① が落ちる）。
②は「両方の書き手」が証明可能な綴りであることを、③は §10.1 にこの盲点が**逆向きにも**
書かれていることを固定する。

### ④ ついでに直したもの — `package.json` に `"test:checks"` が2つあった

`origin/main` の `package.json` は **`"test:checks"` キーを2本**持っていた（56行目と57行目）。
`JSON.parse` は**後のほうだけを残す**ので、前のリストは丸ごと死んでいる。
⚠ **今回は被害ゼロ**——実測すると勝っているリスト（250本）は負けているリスト（248本）の
**真の上位集合**で、失われた検査は0本だった。だが次に前の行へ足したラウンドは、
**その検査が一度も走らないまま緑**になる（`tests/r260 ⑥` がまさにその形を記録している）。
このラウンドで1本に畳んだ。
