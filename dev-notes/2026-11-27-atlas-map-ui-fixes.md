〈依頼〉 発注書 2026-11-27 の 11 項目と、ボット確認の表示の画像（「ご自身で開けるわけねーだろ・利用者に偉そうに仕事押し付けんな」）。個別の事例ではなく、それぞれを生んだ構造を直した。

## 1. ボット確認の表示
- 文面は `handoffText`（`js/web-browse.js`）。「ご自身で開いて手続きを済ませ、ダウンロードして添付してください」を、**ページについての事実**（「〜の向こうにあり、Atlas は読めませんでした。別の取得元を当たります」）に変えた。ライブブラウザの案内も「必ず済ませてください」から任意のリンクに。
- モデルへの指示（`exec.web.next`）は「利用者に伝えよ」から `HANDOFF_NEXT` へ: 利用者に開く・確認を済ませる・ダウンロード・添付を頼まず、同じデータを別の配布元・ミラー・公式 API・カタログ・検索・アーカイブから自分で探す。それでも無かったものだけを回答で 1 回述べる。
- **誤判定の構造**（`supabase/functions/_shared/web-browse.js` `handoffOf`）: captcha のタグ（フッターのウィジェットなど）や password 欄（ヘッダのログイン窓）が**1 つでもあれば本文が取れていても**ページ全体を捨てていた。本文を読み取れたページは壁ではない——壁と呼ぶのは「ほとんど何も書かれておらず、リンクもほぼ無い」ページ（`blank` と同じ測り方の `bare`）だけ。429（レート制限）は人の手続きではないので壁としない。
- ボット確認の回避は実装していない（Atlas は壁を越えない方針のまま）。

## 2. 描いたものの表示・Objects
- `ensureLineLayer` のレイヤー id が国ハイライトの輪郭と同じ `nlq-line` で、**先に国をハイライトしていると川・経路の線が一度も描かれなかった**（`has('nlq-line')` で return true）。線のレイヤーを `nlq-lines` に（`_OVL.lines`・flight-sim の一覧・既存 spec も）。
- 古い返信のスイッチが共有レイヤーを OFF にしていると、**次に描いたものが非表示のまま**（描いた・一覧にある・見えない・自分のチップも OFF）だった。run が描いた surface は表示に戻す。
- Objects の包括ルートは `state:'drawn'` だけを拾い、スイッチで隠した surface は一覧から消えて戻せなかった。`hidden` も載せ、`toggleHide` は実際のレイヤー状態から反転する。
- 未確認のまま残るもの: `data.ratio/relate/scoreMap` が描く `nlq-choro` は `nlq-src`（共有ソース・未 claim）なので、能力に `chips:` が無いと答えのスイッチが出ない可能性。実行経路は追っていない。

## 3. Atlas の撤回の繰り返し・「完了していないもの」
- 検証役の所見に Atlas が**理由付きで答えた**（呼び出し無し・`note_to_intmap` に理由）ものは「異議あり」（`trace.goalContested`）として記録し、利用者には「完了していない」と出さない。
- **同じ所見が 2 回続けて返ったら**、もう一度差し戻さない（出力の門の `moved` と同じ規則・`trace.goalRepeated`）。再描画のたびに回答を流して撤回するループの止め方で、上限ではない。
- `unobserved`（実行したが効果を観測できなかった）の計画手順を「未了」に数えない（出力の門は ranBy を「作った」と数えており、同じ規則の 2 実装が食い違っていた）。
- 差し戻された回答の下書きは、次のモデル呼び出しで**消さず、軌跡のノートへ移す**（`atlas-live.js hooks`）。

## 4. フローティング Atlas
- 自分のメッセージの吹き出しを戻した（背景オフ）。#1477 は矩形のグローを退けるために吹き出しごと外していたが、別の話: グローは文字（text-shadow）、吹き出しは形。単色の薄い白と 1px の縁だけで、グラデーション・box-shadow・backdrop blur は使わない。
- 回答内の button / input / select / textarea は text-shadow を継承しないので `inherit`。インラインコードと表の塗りは外した。
- 思考行（`.atl-stage`、透明塗りのシマー）に別の形の光を付ける案は、既存の規則（`filter:drop-shadow` を浮遊に使わない）に当たるため入れていない。

## 5. 位置
- Chronos の上端を測って `--ntl-clear`（地図の下端からの高さ）を公開（`news-timeline.js`）。衛星表示時のツールパネルと標高断面は `bottom:max(…,var(--ntl-clear))` で読む。**Chronos から逃げる共有の仕組みは無かった**ので、下端固定のポップアップはこの 1 本の変数を読む。
- Objects: 言語切替の作り直しが位置・ドラッグを失い左上固定に戻っていた／アンカーのボタンが非表示のうちに置いて左上へ落ちていた。作り直し後に置き直し、`open()` は `tickFab()` を先に。

## 6. ラベル
- 国名は #1479 の `NAME_GONE_SHARE=1` で済み。**歴史の国名（`imtb-lbl`/`imtb-lbl2`）は zoom の規則が無く**衝突判定だけだった。名前の点が立つ部分の外接箱（`_bb`）を持たせ、同じ `viewShare` で領域が視界を満たしたら消す。名前は 1 件も列挙しない。

## 7. Isolate の輪郭（穴の陸の縁を、地図の国境線に沿わせた）
本番で Germany を Isolate し、z6.5 で ofm の国境線（DEU）から穴（Natural Earth 10m）までを測った: 中央値 1.5 km・最大 4.1 km。穴の元と画面の線が別の測量で、拡大するほど px に出る。#1479 の「縁に ofm の線を引き直す」だけでは、穴の縁そのものが線の横に残る。
- z5 以上（ofm が国境線を持つ範囲）で、穴の輪の頂点のうち、**その国のコードの国境線**から SNAP_DEG（0.04°≒4.4 km＝測った最大のずれ）以内のものを線の上へ移し、線に沿って走る区間は 0.003°（≒330 m）刻みに密にした。海岸（ofm に国境線が無い・maritime は除外）と、SNAP_DEG より遠い頂点は測量のまま。読み込み済みタイルの国境線が変わるたびに idle で、**元の輪から**作り直す（自分の出力からは作らない・z5 未満は元の輪に戻す）。
- 実測（本番・同じ式を貼って評価）: Poland, z6.3 で ofm の国境線の頂点から輪までの距離が 中央値 0.86 km → 0.08 km、p90 1.93 → 0.84 km。最大 7 km は SNAP_DEG を超える差で、移していない（安全側）。Germany は国境が飛び地（ヴェンバーン）や湖（ボーデン湖）を含み、中央値 1.5 → 0.7 km と効きが弱い。そこは別の問題（線が輪の外・湖の中を通る）で残る。
- 読み込み済みの範囲だけが対象（画面の外・まだ読まれていないタイルの国境は元の輪のまま。動かすと idle で追いつく）。
- この変更で `js/time-borders.js` が `window.IntMapCountryExtent` を読む（歴史の国名の規則。既に `js/place-labels.js` が読んでいる同じ窓口）。
