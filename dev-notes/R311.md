## R311 — **起動を重くしていたのは「大きさ」ではなく「誰も見ていないうちに済ませていた仕事」だった**

> 「初回起動速度／地図が表示されるまでの速度／操作可能になるまでの速度…を徹底的に改善してください。
>   ただし、**品質ダウングレードは一切禁止**です。…同じ、またはそれ以上の品質を、より少ない無駄で
>   実現すること。」

依頼は「中心仮説」まで書いてあった——**軽量 descriptor と重い実装が分離されていない**。それは正しかったが、
**測ってみると、時間を食っていたのは主にバイト数ではなかった。**

### ⓪ 最初に計器を作った（そして計器が3回、私の結論をひっくり返した）

- **`scripts/build-report.mjs`（vite プラグイン＋CLI）** — Rollup の**最終グラフ**から eager
  （`index.html` のエントリ＋その静的 import の推移閉包＝Vite が `modulepreload` を出す集合）と async を
  **導出**する。ファイル名から読まない。⚠ **「いちばん大きい chunk」を見るゲートは起動費用について
  何も言っていない**——このリポジトリの最大 chunk は Cesium 4.7 MB で、既定セッションは 1 バイトも取らない。
- **`scripts/perf-budget.mjs`（`npm run check:perf`・CI の静的 job）** — eager は**両方向のラチェット**、
  async chunk と `dist/` の合計は**天井だけ**。⚠ **`requests` と `modules` はバイトではなく個数**なので、
  バイト用の許容幅（2 kB）を当てると `6 > 6 + 2048` は**どんな値でも偽**＝表の上では守られているように見えて
  **絶対に落ちない行**になっていた（#R301 が丸ごと2本の検査で見つけたのと同じ形）。完全一致に直した。
- **`scripts/frame-profile.mjs` に3つ足した** — ⑴ `--boot` が **first map pixel と interaction-ready を
  分ける**（起動画面は `__imBoot` の実マイルストンで外れるので「最初の描画」は「使える」ではない）＋
  long task ＋ GC 後のヒープ。⚠ **long task の observer は `addInitScript` で最初のスクリプトより前に置く**
  ——`longtask` は mark のようには保持されないので、後から作った observer は「1秒固まった起動」を 0 と報告する。
  ⑵ `--mem`（`IntMapOS.exec` で開閉を 10 回。**ボタンと Atlas が通るのと同じ経路**）。
  ⑶ `--attribute`（boot の CPU プロファイルを **js/ ファイル別の self time** に）。

⚠⚠⚠ **計器が私の読みを3回ひっくり返した。**
⑴ **「新しい context は冷えたブラウザではない」**——Chromium の HTTP キャッシュはプロセス単位なので、
同じ 5 回の run の中で JS 転送が **3,282 kB と 1,792 kB** の間を行き来し、「最初の描画」が半秒動いていた。
`Network.setCacheDisabled` を入れるまで、私は自分の改修を**測っていなかった**。
⑵ **replay キャッシュが足りない掃引は「速い」と嘘をつく**——2,745 件が blocked のとき MEAN 20.68 ms、
キャッシュを埋めて地図が本当に描かれると **32.42 ms**。器械自身の警告文が正しかった。
⑶ **A/B の相手を間違えていた**——最初の baseline は R308 で、途中で R309 が main に入った。R309 自身が
起動を速くしている（プレビュー画像の自前ホスト化で GIBS/Terrascope の実タイル取得が消えた）ので、
**R309 を baseline に取り直すまで、私は自分の効果を 2 倍に見積もっていた**。

### ② `js/layer-previews.js` — #R193 は画像だけを門の外に出し、canvas は出していなかった

#R193 は「起動時の読み込みをもっと早く」に対して**画像キュー**の開始を遅らせた（パネル表示 `kick()` か
最初の idle か 6 秒の早いほう）。しかし `into()` の**残り4経路**（`STAT` / `MEMBERS` / `REAL` / `PAINT`）は
その門を通らず、**行が組み立てられた瞬間に canvas を描き始めていた**。さらに `_kickGeo()` が

⇒ **同じ門に通しただけ**（`_paintJob` / `_paintQ`、drain は `_openQueue` の中の 1 か所）。
⚠ **IntersectionObserver で代替してはならない**——#R72 がそれをやって #R73 が取り消した（画面外で組まれた行が
二度と見直されず、グラデーションのまま残る）。門は必ず開く。

実測（94 レイヤーに `into()` を掛け、HEAD 版と並べて同じ入力に通した）:

| 版 | 門の開き方 | 行の組み立て時 | 門が開いた後 | 合計 |
|---|---|---:|---:|---:|
| HEAD | kick | canvas **19** | 10 | 29 |
| 改修後 | kick | canvas **0** | 29 | **29** |
| HEAD | idle/6s | **19** | 8 | 27 |
| 改修後 | idle/6s | **0** | 27 | **27** |
| HEAD | 2パネル同時 | **24** | 20 | 44 |
| 改修後 | 2パネル同時 | **0** | 44 | **44** |

**合計が一致している**＝仕事は 1 つも消えていない。`loadCountryData()` の起動時呼び出しは 1 → 0。

### ③ `js/news-context.js` — 同じ正規表現を 20 回コンパイルしていた

`rebuildGeoIndex()` は 1 起動で **5 回**呼ばれる（呼び出し元は 5 つとも別で 5 つとも正しい）。そのたびに
`HOST.geoDB=…flatMap(g=>({...g,type}))` が**項目を新しいオブジェクトで作り直す**ので、前回の `_terms` は
**原理的に 1 件も生き残れない**。

実測: コンパイル **193,014 本**、うち **145,701 本（75.5%）が焼き直し**。distinct な term は 47,313。
`Venezuela` `Pakistan` `Beirut` `Taipei` `Israel` `Seoul` `Iran` は **20 回**コンパイルされていた。
pass 3〜5 は **99.4 / 99.9 / 100%** が焼き直し。

⇒ `terms` 配列の同一性で覚え、**全要素を照合してから**再利用する。
⚠ **「同じ配列オブジェクトだった」は「同じ語だった」ではない**——照合しない再利用は、古い matcher が
黙って別の場所に当たる**沈黙する誤配置**になる。
⚠ `RegExp` を共有してよいのは `g`/`y` フラグが無い（`lastIndex` を持たない）から。フラグを足したら成立しない。

実測: **193,014 → 50,817（−73.7%）**、ループ合計の中央値 **396.9 → 221.1 ms**（対にした 7 組すべて負・
中央値 −162.7 ms）。等価性は**実データ 193,125 スロット**（term/jp/cyr/source/flags）で**不一致 0**。

### ④ ホバーは、既に知っていることに二度払っていた

- **`positionTooltip`（`js/app-body.js`）はアプリ中のすべてのホバー処理が毎 mousemove で呼ぶ**のに、
  `document.getElementById('map-container').getBoundingClientRect()` で開いていた。読んでいたのは
  `.width`/`.height` だけ——**ウィンドウが変わったときにしか変わらない数を、毎秒 60 回、強制同期レイアウトで
  学び直していた**。ResizeObserver に。
- **`setMapTooltipHTML`** — 同じ markup なら書かない。ポインタが同じ地物の上に居るあいだ（＝ほとんどの時間）
  文字列は同一で、それでも代入して subtree を作り直し、次の `offsetWidth` を reflow にしていた。
- **`renderCoordReadout`（`js/map-readout.js`）は読み出し全体を毎 rAF で `innerHTML` 再生成していた**
  ——ソース自身が :271-272 でそう書いていた。6 つの chip を初回に一度だけ作り、**変わった text node と
  attribute だけ**書く。⚠ 出現する chip の**集合**が変わったときだけ並べ直す。
  実測（3,000 描画・best of 3）: 移動中 **51.9 → 3.8 ms**、静止 **40.5 → 1.9 ms**、
  ノード **+15,000/−15,000 → 0/0**。**21 手順の状態を DOM・text・computed style・行列まで突き合わせて 21/21 一致。**
- ⚠⚠⚠ **地図とは無関係のハンドラが、地図の上でも走っていた。** `js/window-manager.js:557` の
  document **capture** 段の `pointermove` は、最初に `addEdgeResize` が呼ばれた時点で武装し、
  **以後セッション中ずっと・間引きなしで**、登録ウィンドウ 1 枚ごとに `getComputedStyle` ＋
  `getBoundingClientRect` を実行していた。世代付きキャッシュ＋外殻の箱による事前判定へ。
  ⚠ **押下（pointerdown）は必ず生の矩形で測る**——だから「掴めない縁」は**原理的に作れない**（劣化しうるのは
  カーソル表示だけで、上限 250 ms）。実測: 読み取り **93,508 → 1,596**（workspace は 59,291 → 1,614）、
  **46,754 点の pointermove でカーソル系列が完全一致・46,754 点の pointerdown で resize 判定も完全一致**。

### ⑤ 同じ 9.76 MB を 2 回配っていた

`data/ecoregions_2017.js`（9,761,502 B）と `data/ecoregions_2017.geojson`（9,761,476 B）は、
接頭辞 25 バイトと末尾のセミコロンを剥がすと **SHA-256 が完全一致**。1 セッションが取るのは片方だけ。

`.js` は #R13b の産物で、当時サイトは `file:///…/index.html` として開かれており Chrome が
ローカル `fetch()` を禁じていた。**#R175 以降 `index.html` は `<script type="module" crossorigin>` を
読み、`file://` はそれを拒む**——その状況はもう起こりえない。

⇒ `STATIC_EXCLUDE` で `.js` を**配布から**外す（**リポジトリからは消していない**）。
`window.__loadEcoregions` は**両方の経路を残したまま順番だけ入れ替えた**（fetch が先・`<script>` が後）。
⚠ 本番のヘッダを実測して確かめた: `.geojson` は `Content-Length 2,068,476 / Content-Encoding gzip`、
`.js` は `2,068,510 / gzip`——**転送量の差は 34 バイト**。読み手は 1 バイトも損をせず、配布は 9.76 MB 減る。
おまけに `JSON.parse` は「9.76 MB を JavaScript ソースとして V8 に解析させる」より速い。

### やらなかったこと（理由付き）

- **共通 priority broker（依頼 §5.2）を作らなかった。** 合流・レーン・dedupe・TTL・backoff の所有者は
  **既に 6 つある**（`js/widget-scheduler.js` の requestKey／`js/wx-ecmwf.js` の `serial()` 2 レーン／
  `sw.js` の `PREFETCH_LANES`／`js/tile-warm.js` の `WARM_LANES`／`js/sat-proto.js` の hold／
  `js/runtime.js` の camera/frame/timer/idle 登録簿）。その上にもう 1 つ被せるのは
  **「動いているサブシステムを丸ごと書き直さない」に正面から反する**。
- **Supabase の初期分離（依頼 §8）をしなかった——測ったから。** eager 127.6 kB raw / 34.9 kB gzip
  （eager の 2.8%）、boot の CPU プロファイルでの self time **10.1 ms**。依頼自身が
  「測定効果が小さい場合は、無理に複雑化しないでください」と書いている。
- **service worker は既に正しかった。** `cache.addAll` / `precache` は **0 件**、install は `skipWaiting`
  のみ、activate が現行タイルキャッシュとページ所有のデータキャッシュ以外を全部消す。直すものが無い。
- **`js/analysis-panels.js`** は ⑥ のとおり据え置き。次に手を出すなら「ボタン 2 つと map-click だけを
  小片に分ける」が正しい形。

### ついでに直した

**`npm run dev` は `origin/main` で起動しなかった。** 依存の事前バンドルは esbuild が自分で解決するので
`resolve.alias` が届かず、`satellite.js` の Emscripten 入口（top-level await）に当たって
《Top-level await is not available》で死ぬ。**本番は Rollup が alias を尊重するので一度も壊れておらず、
だから `npm run build` しか走らせない round には見えなかった。** `optimizeDeps.exclude` で解決。
