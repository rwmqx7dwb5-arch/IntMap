### 1. ⚠⚠⚠ 1 つの述語に 3 つの次元を答えさせると、答えられない 2 つには `true` を返すしかない

`rasterize` の画素判定はこうだった。

```js
function coveredBy(g, lngLat) {
  if (g.type === 'Polygon' || g.type === 'MultiPolygon') return pointInPolygon(lngLat, g);
  if (g.type === 'GeometryCollection') return (g.geometries || []).some(…);
  return true;                                   // ← 点・線・Multi 系が全部ここ
}
```

そして呼び出し側は**外接矩形の全セルを走査**していた。実測: 16×16 の格子で
**対角線 1 本が 256 セル**・**離れた 2 点の MultiPoint が 256 セル**（GDAL の既定はそれぞれ 16・2）。
道路や河川を格子にすると、**その川がどこにも無い場所まで川になっていた**。

⚠ **欠陥は「分岐が足りない」ではない。** 「その画素はその形に触れているか」は**次元ごとに別の問い**で
あり、1 つの述語に 3 つを答えさせた時点で、答えられない 2 つには `true` しか返せなくなる。
直上のコメントは「点は自分の画素に入る」という**単点についてだけ正しい**理由を書いており、
コードはそれを線と MultiPoint にも適用していた——[[intmap-hist-names-rule-belongs-to-the-name]] と
同じ、**規則を事実ではなく 1 つの事例に付けた**形である。

⇒ `burnGeometry()` が次元で分ける。面は**画素の中心**（`zonal` が逆向きに使う規則と 1 つ）、
点は**その点を含む画素**、線は**その画素を通るか**（Amanatides–Woo の格子走査）。

⚠ **同じ関数の中で、もう 1 つ静かな欠落を見つけた。** `rasterize` の extent の既定は**データ自身**
なので、**最東・最北の座標はちょうど外周の上に乗り**、`floor()` がそれを格子の 1 つ外へ送っていた。
端の例外ではなく**常態**である。いまは最後の画素に属する。

⚠ 検査の fixture が最初に落ちたのは実装の誤りではなく、**傾き −1 ちょうどの線が格子の角を正確に通る
縮退**だった（そこでは「どちらの画素か」に答えが無い）。**答えの無い問いを訊く fixture は、
走査ではなく tie-break を測る。** 傾きを変えた。

### 2. ⚠⚠⚠ 供給元の入口は在ったが、そこに立つ者が 0 人だった

`js/gis-sources.js` は「範囲・時刻・属性条件・列・件数・続き」を受ける契約を持っていた。
**`supply(id, impl)` を呼ぶコードが 1 行も無かった**ので、その契約は 1 度も満たされなかった。
内蔵レイヤーの分析は `IntMapLayers.featuresIn` 経由で**レンダラの `sourceData()` をそのまま読む**——
登録 23 行のうち 11 行がそれで、航空機は `getBounds()` でカメラ矩形を上流に投げている。
つまり**「この地域の施設を数える」の答えが、地図の拡大率と表示状態で変わった**。

⚠ **宣言が届く経路自体が無かった。** `IntMapLayers.state()` は `{id,on,label,time,source,legend}` の
**6 欄だけ**を組み立てて返すので、登録がデータについて何を述べても供給元層には届かない。
⇒ `state()` を太らせるのではなく（それは利用者向けの状態）、**`declarationOf(id)` という別の 1 本**を
足した。レイヤーは `holds` で自分について述べ、`supplierFor(id)` が**その宣言から供給元を作る**。
**一覧はどこにも無い**——全件を持ち視野に縛られないと述べた行だけが `where` と `cursor` を答えられる。

⚠ **述べさせたのは 4 行だけで、5 つめは測って否定した。** `earthquakes` は URL が
`limit=2000&minmagnitude=6` なので完全性を名乗れない。`volcanoes` は全件だが、観測所の状態が
同じ地物へ更新されるので **`live` は述べていない**（[[intmap-data-must-not-claim-an-author-it-lacks]]）。

⚠ **`where` の実行を `ops.run('filter')` へ委譲する案は測って否定された。** `run` は async で、
委譲すると供給元が非同期になり、`features()`（同期の扉）がその行の**全読み取りを
`supplier-is-async` で断る**ようになる＝既存機能の後退。代わりに実行器を 1 つ置き、
**意味の等価を `ops.run('filter')` との照合で計測**した（9 演算子＋空セルで同じ行）。

⚠ **Atlas のカタログ行に `coverage` が無かった。** 取得の完全性の判定は記録されていたのに、
planner に渡るのは `origin` だけ。**「これは世界についての答えか」を知らない planner は、
カメラが向いていたものについて「世界で最も◯◯な国」と言える。**

### 3. ⚠⚠⚠ 書いてあるのに死んでいた中断——`ctx:` を渡すコードが `js/` 全体で 0 件

`js/gis-warp.js:583` の行ごとの `if (ctx && !(await ctx.tick(W, N)))` は **#R749 以来 1 度も
評価されていない**。`useCtx()` は `opts.ctx` しか見ないのに、呼び出し側は
`{method, signal, onProgress}` を渡していた。**`ctx` は常に `null` だった。**

`RK.combine` はそもそも非 async・ctx 引数なしで、`width*height` の中断不能な単一ループ。
呼び出し側は**開始前に 1 回 tick して**いたので、「中止できる」ように読めた。
⚠ **大きな格子を合成し始めたら最後まで返ってこない**——[[intmap-sync-loop-cannot-be-cancelled]]
そのものが、1 階層下で再演していた。

⇒ `mask`/`diff`/`combine`/`merge`/`zonal` と warp の出力ループを**1 本の `paced()` に畳んだ**。
⚠ **同期版と中断版の 2 実装を作っていない**——同じ 1 本のループが、`ctx` の有無で
**いつスレッドを手放すかだけ**を変える（[[intmap-contract-is-not-implementation]]）。
⚠ **刻みは時間**（`makeCtx` の 1 フレーム）。`paced` が決めるのは「何画素ごとに時計に訊くか」だけで、
二重の時間ゲートを作っていない。

⚠ **偽陰性ゼロを測った**: 中断しない ctx を渡した結果が、**ctx を 1 つも渡さない同じ walk と
1 画素も違わない**こと（参照は測る対象の外に置く）。
⚠ **中止の検査が「止まった」しか見ないと、何でも `cancelled` と答える実装が通る。** すべての例に
「完走して同じ答えを出す双子」を付けた。

⚠ 検査の作り方でも 1 つ学んだ。`rasterMask`/`rasterDiff` は**格子が小さいと 1 フレームで終わる**ので
「進捗が出たら中止」は**機械の速さを測ってしまう**。この 2 つは **runner の先頭に guard を持たない**
——だから**あらかじめ中止した signal** は、カーネルが walk の途中で ctx に訊かない限り見えない。
それが決定的で、かつ決定論的な梃子だった（guard が足された日に落ちるよう、runner の本文も測っている）。

### 4. 演算ごとに「どの面で計算したか」を述べる。⚠ ただし許容誤差は述べない

球面の面積（球面過剰）と、展開した度平面の面積は**別の数**である。24 op のどれも自分の面を
述べていなかったので、**2 つの op の数を組み合わせた読み手は、食い違いを見る手段が無かった**。
⇒ 閉じた語彙 `sphere` / `degree-plane` / `degree-grid` / `stated-plane` を全 op が宣言する。

⚠ **「許容誤差」は宣言していない。** 書くなら**何を測っていつ失効するか**を書かねばならず
（`.agents/rules/no-ad-hoc-hardcoding.md` §4）、その測定は今日存在しない。**代わりに述べたのは
「どこで近似せずに拒むか」**——`geometry-wraps-world` と `crs-plane-seam-crossed`。
**測定のふりをした数を置くより、置かない理由を書くほうが正しい。**

⚠ **`measure` は `js/gis-crs.js` の `assess()` を 1 度も呼んでいなかった。** #R752 から在るのに。
UTM のゾーンを 2 つ外れて測っても、数を返して**何も言わなかった**。いま適合度が答えに載る。
⚠ **拒まない**——面を選んだのは読み手であり、`outside: 0` は適合の証明にもならない（全球面は
それ以外を報告できない）。**報告であって判定ではない。**

⚠ **正距方位面は実装済みで到達不能だった。** `planeSpec()` のコード分岐を `PLANES` からの発見に変え、
コードを持たない面のために `kind:v1,v2` の一般文法を足した。**別名表は無い。**
副作用として `mollweide:<lon0>` も名指せるようになった。

### 5. 外部 GIS が普通に書き出したファイルを読む／解析した結果を外へ渡す

**BigTIFF**（magic 43）・**predictor 3**（浮動小数点の水平差分。バイト平面を分けてから差分を取る、
整数の predictor 2 の一般化では**ない**）・**PlanarConfiguration 2**（バンド別格納）を読む。
⚠ **分岐で汚していない**——BigTIFF は offset 幅・IFD 項目数・項目長が違うだけなので、
**その 4 つを読み取り器の引数にした**。同じ 1 本の walk が両方の容器を読む。
⚠ **JPEG-in-TIFF は拒否のまま**で、**なぜ今日できないか**（量子化/ハフマン表がタグ 347 に分離され、
プラットフォームの復号器は 8bit sRGB を返す＝この扉が運ぶ標本ではない）と**消せる条件**を書いた。

そして**出口**（`js/gis-export.js`）。GeoJSON・CSV・GeoTIFF。
⚠ **「書き出せた」は「読み直せた」ではない。** 3 形式とも既存の読み手が読み返し、**許容幅 0** で
一致を測る（JSON の double は最短往復表記、float32 は `Math.fround`、ジオ参照は binary64）。
⚠ **画素が一致しても場所が違えば別のデータ**なので、grid の west/north/pixel も測る。
⚠ **持っていない出典を主張しない**——述べていないデータセットには欄自体を作らない。
⚠ **TIFF の ASCII フィールドは UTF-8 で書く**。7bit に落としたら
「CC BY 4.0 — 国土地理院」が `?` に潰れた＝**ライセンスの破壊**（[[intmap-licence-must-be-a-value]]）。
⚠ **CSV は形式に出典の欄が無いので運べない。運べなかったことを画面が述べる。**

### 6. ⚠ 拒否を実装に変えた回は、検査を消す回になりやすい

BigTIFF・PlanarConfiguration 2・predictor 3 が通るようになったので、それらを
「拒まれる」と主張していた既存の検査 2 件が誤りになった。
⚠ **消さずに絞った**（[[intmap-refusal-that-becomes-implementation]]）:
BigTIFF は「**8 バイト以外の offset 幅を述べる BigTIFF**」の拒否として残り、
PlanarConfiguration は「**TIFF 6.0 が定義しない値 3**」の拒否として残る。**拒否コードは 1 つも消していない。**

⚠ 同じ理由で `js/map-ui.js` の読者向けの文も直した。「これは BigTIFF です。この読み取りは従来の
TIFF 配置だけを扱います」は**もう嘘**で、そのまま置けば**開けたはずのファイルを変換しに行かせる**。
⚠ その結果 zh / zh-hans の inline 行が 1 つ到達不能になった。**英文が変わったのだから訳文も
その偽の文の訳**であり、復元する対象が無い。retire して床を 1 下げ、理由をここに書く
（[[intmap-authoring-narrowed-not-deleted]] が求めるのは「復元するか、理由を述べて床を下げる」）。

### 7b. ⚠ 段 3 を飛ばして push した — `check:perf` は build が要るので段 1 の 9 門に入っていない

CI の `Static checks` が落ちた。手元では 9 門とも緑だったが、**`check:perf` と `check:assets` は
build が要る段**（`.agents/rules/execution-strategy.md` §4 が「**build が要る**」と印を付けている）で、
段 1 には入っていない。**環境差ではなく、走らせていなかっただけ**——ローカルで同じ数値が再現した。

```
async chunk "gis-core" grew: 355.7 kB > ceiling 322.2 kB
```

⚠ **最初にやったのは天井を上げることではない。** `js/gis-shapefile.js`・`js/gis-geotiff.js`・
`js/gis-geopackage.js` は**既に別の async chunk**で、理由は「そのファイルを読むときにしか要らない」。
`js/gis-export.js` は同じ性質（**書き出すときにしか要らない**）なので、同じ前例に合わせて切った。

⚠ **それでも残る +19.2 kB は ops そのもの**（次元別の焼き方・`ctx` の受け渡し・供給元・面の宣言）で、

- **失効条件**: GIS のカーネルに機能を足したとき。**この天井は「ここまでなら黙って増えてよい」では

⚠ **CodeQL も 1 件赤かった**（`js/incomplete-url-substring-sanitization`、high）。

**誤検出ではあるが、指摘そのものは正しい**——「その文字列がどこかに在る」は、出典が**間違った項目**に
書かれていても通る。⇒ 文書を項目として読み、**名前を指定して値を厳密比較**するようにした。
**検査は強くなり、警告も消えた。**

⚠ そのとき自分で 2 つ踏んだ: ① 動的 import を `.then(m => m.NAME())` と書いたら
`tests/r175-checks ③` が **呼ばれている export を dead code と報告した**（この検査が import と
認めるのは `(await import(…)).NAME` の形だけ）。② その正しい綴りを**コメントに例として書いたら**、
同じ検査が**散文の中の import を本物として読み**「存在しないモジュールを動的に読み込んでいる」と
報告した。**検査は散文とコードを区別しない。**
