## R506 — **航跡は消えたのではない。記録の片側だけが残っていた**

> 「航空トラフィックレイヤーは、前までトラックもあったんですが、なくなってしまいました。」

### 1. 本当にあった。そして記録は今も動いていた

#R341 が航空レイヤーを丸ごと置き換えたとき、`src/aviation-worker.js` の **TRACK リングバッファは
持ち越された**（同ラウンドが「これは実機能で `CONSTITUTION` §0.3 が縮小を禁じている」と自分で
書いている。2,000機 × 64点・視野チャンネルのみ）。持ち越されなかったのは**反対側**である:

| 何 | どこを読んでいたか |
|---|---|
| 描画（`drawTrack` / `TRACK_LINE` / `TRACK_3D`） | 旧レイヤーの `planeTracks` |
| 詳細カードの「軌跡を表示/非表示」行（`_trackCard`） | 同上 |
| Atlas の `layers.aircraftTrack` | `window.IntMapPlanes3D`（＝ `planesData` / `planeTracks`） |

**`planeTracks` は旧掃引が止まった日から空**なので、機体を選ぶと `drawTrack` は 0 点の軌跡を描き、
両レイヤーを `visibility:none` にしていた。
⚠ **空の軌跡と「まだ軌跡が無い」は画面上で見分けがつかない。** だから壊れたと気づけなかった。

⇒ 足したのは**橋だけ**である。`aviation-live` に `track()` / `find()` / `onTrack()` を生やし、
`data-layers` が worker の点を `planeTracks` に入れる。
⚠ **描画は1行も作り直していない**——2-D の線も、高度に沿う 3-D 押し出しも、脚ごとの地面クランプ
（#R174）も、`trackStats` も、カードの行も、Atlas の動詞も、全部出荷済みのコードのまま。
隣に2つ目の描画を建てるのが「1つの事実に正本が2つ」（§22.1）の始まりである。

⚠ **フィートとメートル。** `planeTracks` は**メートル AMSL**（`drawTrack` が脚ごとに地面を引く）で、
wire は `altFt`。換算を落とした軌跡は **3.3 倍の高さ**に描かれ、しかも**動く機能に見える**。

### 2. ⚠⚠⚠ 繋いだ瞬間に、描ける状態ではないことが分かった

本番実測（London z7・箱の中 263 機）:

| | |
|---|---|
| 脚の**中央値** | **267 kt** ← 正しい。機体自身の対地速度と一致する |
| 900 kt を超えた脚 | **263 本中 30 本** |
| 最悪 | **25,283 kt**（1,679 km を 129 秒） |

サンプル: `EZY18TA`（対地 443 kt）の脚は `[435, 426, 26, 486, 89, 467, 435]`——**正しい値と
おかしい値が交互に並ぶ**。世界集合が「何分も更新されない記録」を返し、更新された瞬間に飛ぶからである。

**1,679 km の直線は、どの飛行機も飛んでいない。軌跡は証拠であって（§17.1）、これは捏造になる。**
⇒ `trackRecord` に物理の門: 前の点からの大圏距離が **`TRACK_MAX_KT = 1500`** を超える脚は、
繋がずに**そこから track を始め直す**。前の点も本物の観測だが、**この点とは連続していない**。
⚠ 門は「速い」ではなく「不可能」を落とす——旅客機の巡航は約 600 kt で、追い風と粗い時刻印で
実在の脚がそれを大きく超えることはある。

### 3. ⚠⚠ 追い出しは、毎回スロット0を選んでいた

`TRACK.used` にはメッセージの時刻が入っていた。**1通のメッセージで書かれたスロットは全部同じ値**に
なり、追い出しの走査は「走っている最小より小さい最初のスロット」を取るので、満杯になった後は
**常にスロット0**を返す。アプリは z1 で開くので**最初の視野ポーリングが全球**＝2,000 枠を超える
機体数が一度に来る。⇒ `used` を**単調カウンタ**にした。「最後に更新されたのが一番古いもの」が
本当にその意味になる。

### 4. ⚠ 視野チャンネルの判断を、計器に出した

原因を追うのに半日を推測で溶かした。同じ箱を5回叩いて `x-intmap-oldest-ms` が 252→264 秒と
増え続ける一方、`?meta=1` は**満タンのバケツと backoff 0** を報告する——「何もランクされていない」
「その空は十分新しいと判断した」「予算が0だった」の3つが、外からは同じ顔をしていた。
⇒ `x-intmap-note`: `cands / ranked / stalestS / worth / grant / tokens / inBox`、
読んだ場合は `up / fail / merged` も。**「grant=4」はトークンを4つ使ったという意味しかなく、
新しい位置が返ったという意味ではない**——これが分かるまでが長かった。

実測でこう出た:
```
cands=9,ranked=4,stalestS=48,worth=1,grant=4,tokens=2,inBox=276,up=4,fail=1,merged=50
cands=9,ranked=4,stalestS=31,worth=0,grant=0,tokens=0,inBox=276
```
読み取りは正常に効いていて、45 秒の「訊く価値」の閾値で間引かれているだけだった。
