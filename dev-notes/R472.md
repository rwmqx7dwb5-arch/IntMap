## R472 — **回答は間違っていなかった。IntMap が自分の規則で消していた**

報告は 1 枚の返信である。上半分に Atlas 自身の回答——「前の案内を訂正します。〜養老公園です」——が
あり、その真下に `analyze` が描いた

> ⚠ 裏付けを確認できなかった記述は、この回答から取り除きました

が続き、さらに下の行が **「使用データ: ニュース, 地震, ライブWeb検証」** と言っている。

### 本番で測ってから直した

`IntMapConsole.runDirect` で本番の `analyze` を走らせ、`fetch` を包んで ai-proxy の応答をそのまま
読んだ。1 回目の呼び出しはこう返っていた。

```
meta: { provider:"openai", model:"gpt-5.6-terra", task:"analysis_structured",
        webAttached:true, webUsed:true, webSearches:2, schemaAttached:true }
citations: []                     ← 検索は 2 回走っていて、引用は 0 件
```

そして本文は**正しい**。赤坂スポーツ公園、大垣市草道島町40-1、見頃は 4 月下旬〜5 月。
`evidenceIds` だけが全部空だった。

原因を確かめるため、**同じ質問・同じ `task`・同じ schema・同じ webMode** で system prompt だけを
変えて 2 本投げた。

| system prompt | 検索回数 | **引用** |
|---|---|---|
| IntMap の ANSWER CONTRACT **あり** | 2 | **0 件** |
| **なし**（"Answer in Japanese."） | 2 | **2 件** |

⚠⚠⚠ **url_citation 注釈は、モデルが URL を書いた場所に付く。** 契約なしの応答を offset で切り出すと
`([city.hida.gifu.jp](https://www.city.hida.gifu.jp/map/s912.html))` ——モデルが書いた
インライン引用そのものである。そして IntMap の ANSWER CONTRACT の 1 行目付近はこう言う:
**「you may NOT write a URL, a domain name, or a source name anywhere」**。

**つまり `hosted_web` の記録は、この経路では構造上ぜったいに台帳へ入らない。**
IntMap は「URL を書くな」と言い、そのせいで「どのページを読んだか」を教えてもらえなくなっていた。

### そこから先は、どの段も正確に仕事をしていた

台帳に `hosted_web` が無いので、`evidence.primary_unsupported` が全 primary claim に立つ。
修復は**同じ空の証拠一覧**を見せられて「无法核实」（確認できません）と書き直す。
`degrade()` が所見の付いた claim を全部削除し、`directAnswer.text` が空になる。
呼び出し側は空の主文を見て `R(false, '⚠ 分析没有回传结果')` を返す。**道具は何も返さない。**

**欠けていたのは「文とページを結ぶ id」だけで、その id が存在し得ないのは IntMap の規則のせいである。**
規則を守ったことを理由に、正しい回答が消されていた。

### 最初の草案は間違っていた

最初に書いたのは二段階だった——契約を持たない短い「収集専用」呼び出しで先に検索を走らせ
（実測 3 問すべてで本物の URL が span 付きで返る・各 5.7〜6.5 秒）、その citation を台帳へ入れてから
構造化回答を書かせる。動く。**が、それは修正に修正を重ねる方向だった。**

> 「もっと破壊的にシンプルにしろ。修正に修正を重ね、そのための修正を行う必要はない。
>  Atlas はコードプロダクトではない。AI です。」

### 消したもの

| 消したもの | それが何をしていたか |
|---|---|
| `degrade()`（`js/atlas-answer-audit.js`） | 所見の付いた claim を削除し、節を削除し、冒頭結論を生き残りに差し替えて回答を組み直していた |
| `repairBrief()` と 2 回目の `ask()` | 所見を突きつけてモデルにもう一度書かせていた |
| 劣化バナー（`js/atlas-answer-render.js` の `.atl-degraded`） | 削ったことを読者に告げていた。削るのをやめたので、告げる中身が無い |
| `MAX_MODEL_CALLS` | 数えるものが 1 つになった |
| `status:'degraded'` / `removedClaims`（`js/atlas-toolsurface.js`） | 「中身を抜かれた」と Atlas に伝えていた |

### 残したもの

**監査そのものは 1 行も削っていない。** 39 の監査コードは全部そのまま発火し、`AUDIT_CODES` の
severity も残っている（**ただし何も決めない**）。所見は開発トレースと **Atlas** へ渡る。

Atlas は AI である。`contradiction.superlative_beaten`（回答が自分の本文と矛盾している——読者に
言うべきだ）と `evidence.primary_unsupported`（IntMap に結ぶ記録が無かっただけ——たいてい言うことは
無い）の違いは、**このリポジトリの severity 欄より Atlas のほうがうまく判断できる。**

### 並んでいた 2 つ目の回答は、2 つ目の欠陥ではない

依頼は「最終回答の所有者を 1 つにするべきだ」とも言っていた。**それは既に決まっている。**
`js/atlas-policy.js` の `turnMechanics()`:

> A tool result marked "rendered" has already been shown to the reader with its sources —
> frame it in a sentence rather than writing it again.

`js/atlas-toolsurface.js` は `rendered` を立て、中身を抜かれた回答には #R419 の但し書きを付けて
Atlas へ渡していた。**中身を抜かれたと告げられた Atlas が自分で答え直したのは、設計どおりである。**
所有者を作り替える変更は 1 行も要らなかった。⚠ **報告された症状が 2 つでも、原因が 2 つとは限らない。**

### 読者の保護は 1 つも減っていない

#R350 を名づけた保証——**モデルが捏造した URL がリンクとして読者に届かない**——は
`degrade()` ではなく **renderer と registry** にある。

- `stripModelUrls()` が本文のあらゆるフィールドに掛かり、URL は**ホスト名に潰れてリンクにならない**
  （実測: `詳しくは https://fabricated.example.com/x を参照。` →
  `<div class="atl-lead">詳しくは fabricated.example.com を参照。</div>`）
- 出典カードは**台帳の記録からしか**作られない。`hosted_web` は「その呼び出しで検索が実際に走り、
  注釈がその呼び出しの ID を持つ」ときだけ admit される（`addProviderCitations`）

`tests/r472-checks` ⑤ が、外せる場所ごとにそれを測る。**⑤a・⑤b・⑤c と ⑥b は修正前でも緑**——
「変えていない」を実測にしてある。

### プロンプトが嘘をつくのもやめた

```
[EVIDENCE RECORDS — … Use ONLY these ids.
 They are the only sources that exist for this answer …]
```

検索がこれから走る呼び出しに対して、この文は**偽**である。そして IntMap が記事を 1 本も持たない
問いでは、**空の一覧**についての宣言だった。検索が走らないときだけそう言う。走るときは
「検索で開くページにはまだ id が無い／URL を書くな／id を捏造するな」だけを伝える。
