## 1. 作ったもの——調査ノート

- **`js/atlas-notebook-store.js`**（データだけ）: ターン→記録、`diffResults`（2 時点の行を**識別子で**突き合わせる。
  改名は「変わった」、表示上限で切れていたら「下へ移っただけの可能性」と言う）、検索、Markdown／ノートのファイル、
  IndexedDB とメモリの保存、アカウントとの突き合わせ（墓標なし：一度同期した記録がアカウントに無い＝他で消された）。
- **`js/atlas-notebook.js`**（ページ）: `ASTATE.onTurnEnd` で綴じる。問い合わせの行はカーネルのバスで受け、
  **そのターンの開始〜終了の間に載ったものだけ**を取る（地図の idle を待つ前に切る——待つ間に送られた次の問いの行を混ぜない）。
  Atlas パネルの「調査ノート」帯とシート（一覧・検索・詳細・メモ・設定）。
- **再現** = `runDirect` で ① 時計 ② 能力表の第 7 列が `session` の操作 ③ 時計・レイヤー・カメラ を戻して**読み返す**。
- **今と比べる** = `notebook.compare`。保存した問い合わせを今走らせ、差をノートに綴じる（同じ問いの記録が時系列に並ぶ）。
- **Atlas の能力 3 つ**（`js/atlas-cap-notebook.js`）: `notebook.list` / `notebook.open` / `notebook.compare`。
  `open` は記録した操作を**自分では走らせず**、呼び出しそのものを Atlas に渡す（何を呼ぶかは Atlas が決める・§5）。
- **アカウント同期**（既定オフ）: `supabase/migrations/20261003090000_atlas_notebook.sql`、pgTAP は
  `supabase/tests/18_atlas_notebook_test.sql`。本人だけ（RLS の USING と WITH CHECK）・アカウント削除で消える。

### 1.1 置いた 2 つの上限は推定である

`payload` 1 行 1 MiB、1 アカウント 100 MiB。**本番のノートが存在しなかったので測れていない**——1 記録を数十 kB と
**推定**し、その 30 kB を毎日 1 年綴じた読者の約 10 倍を置いた。PostgREST で直接書ける表なので、1 つの公開鍵で
どれだけ書けるかの天井は要る（2026-09-30 の監査が feedback / bug_reports で見つけた形）。超えたら拒否は名前で返り、
パネルは「送れなかった記録と理由」を出し、記録は端末に残る。**読者の実際のノートが当たったら上げる。**

- `check:surface`: **window.IntMapOS の読み 3（js/atlas-query.js の emit・js/atlas-notebook.js の on・
  js/atlas-cap-system.js の診断）** を `--update` で記録した（51 → 54）。IntMapOS は app-body.js が作って export しない
  （`module-graph --plan`: owner reads …）ので、「持ち主から import する」道がまだ無い。
- `check:static` の 2 つの台帳: **output-taint に js/atlas-notebook.js 1**（保存した回答を返答と同じ markdown 描画器
  `mdMini` で描く 1 か所。描画器は別モジュールなので解析が追えない——返答の泡と同じ扱い）。**data-effect は 0**
  （書き込みに届くボタンはすべて `data-effect` を宣言: 同期・メモ・ピン＝private、削除＝destructive、もう一度訊く＝outward）。
- 能力の数 154 → 157（到達可能 153 → 156）、カタログのブロック 61 → 62、表 39 → 40、migration 37 → 38、pgTAP 19 → 20 本を
  文書に反映した（`check:docs`）。

- **ページでの検査は既存の spec に相乗りさせた。** 独立の `tests/atlas-os.spec.js`（ログイン済みで 1 回起動）は 52 s
  測れたが、全体の天井（`check:testbudget` 87.5 min）の余白は 4 s だった。天井は上げず、同じ実ターンを既に走らせて
  いる `tests/atlas-live-stream.spec.js` に ⑥ として足した（その spec は 31.9 s で、記録値 36 s を超えない）。
  再読み込みの代わりに **IndexedDB を新しく開いて読む**——再読み込みが読むのはそこなので、同じ主張をより安く確かめる。
  その spec で 1 件見つかった: 帯を押すと、最後に読んだ記録が開いたまま一覧に戻らなかった（`show()` を修正）。
