## R753 — アカウントのボタンからアイコンを外し、メニューが述べていなかった 4 つを述べさせた

〈「アカウントのボタンは、アイコンを表示しないように。また、アカウントメニューにもAIの残使用回数を
書くように。その他、アカウントメニューで、機能や実態、UI含めて全面見直しして。」〉

### 1. アイコンは「出す／出さない」ではなく「どの幅で出すか」だった

広い画面のボタンは**名前だけのピル**になった。携帯は**変えていない**——そこではアイコンが
ボタンそのもの（34px の丸）で、名前を出すと #R30 が実測した「ヘッダーが改行される」に戻る。
利用者に確認して「スマホはアイコンのまま（PC だけ文字だけにする）」。

⇒ markup は 1 つのまま、`#btn-account .acct-av{display:none}` と `@media(max-width:768px)` の
1 行で出し分ける。**同じ DOM を 2 つの幅で出し分ける**ので、書き手（`updateAccountButton`）に
分岐は増えていない。

### 2. 残り回数は 2 つあり、数を決める場所は 1 つでなければならない

IntMap のサーバーは日次の行を**2 本**持っている——`ai_usage`（Atlas の回答）と
`ai_gloss_usage`（用語解説）。片方が尽きてももう片方は動く（それがレーンの目的・#R491）。
だから 1 行にまとめず**2 行**で述べる。

⚠ 数は**アカウントメニューが計算しない**。`js/ai-core.js` に `aiUsageSummary()` を 1 つ置き、
設定パネルとアカウントメニューは**その答えを描くだけ**。2 つ目の計算を書けば「1 つの問いに
2 つの答え」ができる（`.agents/rules/no-ad-hoc-hardcoding.md` §2-3）。開くたびに
`aiRefreshUsage()` が**両方の行を読み直す**——鏡の古い数を、まさにそれを確かめに来た読者に
述べないため（#R447 の規則を第 2 のレーンにも広げた）。

### 3. 全面見直しで出た「述べていなかったこと」4 つ

| # | 画面が黙っていたこと | いま |
|---|---|---|
| ① | 口座の状態である **AI の残量**がこの画面に無い（設定の 3 グループ下にだけあった） | 身元の直下にカード 1 枚 |
| ② | **どの方法でログインしているか**が無い。Google の口座に IntMap 側のパスワードは無いのに「パスワードを変更」は欄を開いていた | 見出しが方法を名乗り、OAuth では欄を開かずそう言う |
| ③ | 絵文字を選ぶと端末の画像は消えるのに **`profiles.avatar_url` は残り**、コミュニティには差し替えたはずの写真が出続けた。画像を消す出口も無かった | どちらの操作も列を空にし、「画像を削除」を置いた。カードは「これはコミュニティの画像でもある」と書く |
| ④ | Esc で閉じられず、`role`/`aria-modal` も focus の行き先も無かった | dialog として開き、Esc は上にあるものから閉じ、focus は開いたボタンへ戻る |

### 4. ⚠⚠⚠ `HOST.user` は 2 か所で組まれていて、片方にしか無い欄があった

新しい `provider` を `refreshCurrentUser()` にだけ書いた。hermetic な試験で「Google でログイン」が
**空**になった——`onAuthStateChange` が**同期で**組む暫定の user（Supabase を呼べない。#14 の
デッドロック）が、プロフィール行が届くまで、**通信が死んでいれば永久に**、全パネルが読む user である。

⇒ `_sessionProvider()` 1 つを両方の構築が呼ぶ。**2 つの構築があるオブジェクトに、片方しか
書かない欄を足さない。**

### 5. 問いはブラウザではなくアプリがする

`window.confirm` / `window.prompt` が 5 か所あった。あれはスタイルも翻訳も効かず、携帯では
**「127.0.0.1 says…」と出自の名前で**出る。シートの中で訊く `_acctAsk()` 1 つに集約した
（**2 つ目の訊き方を作らない**——それは同じ判断を 2 度書くことだから）。

### 6. 死んだ規則と、規則の無い class は同じ 1 つの検査で見える

`acct-danger` は #R231 から**規則の無い class**だった（その註が述べる「破壊的な 2 つを視覚的に
離す」は一度も描かれていない）。逆に `.acct-color` は**使う者のいない規則**だった。どちらも
綴りを固定する検査には見えないが、**CSSOM に訊けば両方見える**（#R488 の形）。

⚠ **いま当たらない ＝ 死んでいる、ではない**（`.acct-ai-out` は残 0 の色、`.acct-ask-danger` は
破壊的な確認で、パネルは一度に 1 つの状態しか取れない）。除外を手書きの表にすると、次に足した
状態が黙って許される。⇒ 判定は「**その class をモジュールが書いているか**」——状態の class は
`js/auth-ui.js` に在り、消えた部品の class はどこにも無い。

⚠ そして CSSOM を歩くときの罠: **入れ子 CSS を持つブラウザでは CSSStyleRule も `.cssRules` を
持つ**（空）。「`cssRules` があれば入れ物なので中へ」と書くと、**52 個ある規則が 0 個**に見えた。

### 7. ⚠ このパネルのログイン後の半分は、一度も試験されていなかった

`tests/r168.spec.js` は自分の頭でそう書いている——「currentUser は届かない。hermetic policy が
Supabase を塞ぐし、資格情報を試験に置くわけにはいかない」。塞がっているのは**通信**であって
**セッション**ではない。supabase-js は `getSession()` を localStorage から答えるので、
**期限が未来のセッション 1 個**で `refreshCurrentUser()` が走り、本物の `openAccountMenu()` が
開く。その後の要求（プロフィール行・当日の利用行）は意図どおり全部落ち、モジュール自身の catch が
受ける——**通信の無い端末でこのパネルが耐えるべき状態そのもの**。資格情報は 1 文字も要らない。

### 8. この spec がどの段で走るか、と、翻訳の床が 1 下がったこと

spec の実測は **594 / 1,970 / 574 ms ＝ 表の 2 秒**で、`CORE_MAX_S`＝1 を超えるので **deep tier
（nightly）**に入る。**価格であって好みではない**（`scripts/tiers.mjs`）。push を門で守るのは
同じ回の **checks 側**（node・`npm test` に内包）で、#R620 と同じ関係。全体の天井は測った分だけ
動かした（4,880 → 4,882 秒。理由は `scripts/test-budget.mjs` の HISTORY に 1 行）。

⚠ **7 言語の床が各 1 だけ下がった**（de/es/ru 7601→7600・fr/ko 6132→6131・zh 系 6299→6298）。
理由は**削除ではなく置き換え**: 「Your profile」は見出しが「アカウント」になって消え、
ログアウトの確認文はブラウザのダイアログごと無くなった。新しい文は CONSTITUTION §7 のとおり
**en+jp で書く**ので、7 言語の inline 表には入らない。死に鍵 6 行は codemod で外した。

### 9. ⚠ `display` を書く class は `[hidden]` の答えも持たなければならない

`.acct-btn{display:inline-block}` は UA の `[hidden]{display:none}` を**上書きする**（author が
UA に勝つ）。新設の「画像を削除」は `hidden` 付きで書いたのに、**消す画像が無いまま見えていた**。
出荷前にブラウザで見て気づいた——`hidden` を付けたことは、隠れたことの証拠ではない。
