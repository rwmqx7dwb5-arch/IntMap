## R494 — **見出しの余白を二度足してから引き算していたのは、レンダラが自分の作ったものを知らなかったから**

> 「一番やるべきなのは、細かなCSS調整より、`文字列 → regex置換 → 空divで余白` から
> `文字列 → Markdown構造解析 → semantic DOM → CSS組版` への置き換えです。
> 今のコードにはすでに「見出しの余白を直したら、改行から生成された1.5em spacerまで消さないと二重になる」
> という補正処理が入っています。これはまさに、現行レンダラがかなり成熟した結果、
> regex方式そのものが次のボトルネックになり始めているサインです。」

### ① 後処理は、症状ではなく設計を指していた

`mdMini()` は #R149 から #R232 まで、`esc(text)` に続く**12本の `.replace()`** だった。行の形を
`<div>` に書き換え、改行を**要素**にする——空行は高さ 1.5em の空 div、文末＋単一改行は 0.82em の空 div、
それ以外は `<br>`。

markdown の見出しは前後を空行で挟まれた行なので、段落の規則は**見出しの両側に必ず spacer を出す**。
見出し自身のマージンと足されて、`## ` は上に **2.05em + 1.5em = 3.55em**、下に 0.62em + 1.5em = 2.12em の
空白で開いていた。#R232 はこれを、**完成した HTML を後から読み直して見出しの隣の spacer を削除する後処理**で
直した——テンパードな `(?:(?!</div>)[\s\S])*` まで書いて。

⚠ **自分の出力を読み直して直すレンダラは、自分が何を作ったのか知らないと言っている。**
そしてそれは、この方式で表現できるものの限界でもあった。箇条書きは `•&nbsp;` と hanging indent を持つ
`<div>` なので、**入れ子の箇条書きは「もっと空白の多い箇条書き」**でしかない。番号付きリストは #R154 が
`1.` と `①` を `- ` に**書き換えて**いたので番号が消えた。項目の中に第2段落やコードブロックは置けない
——「中」というものが無いから。`>` の引用は**行ごとに枠が1つ**できた。

### ② 行 → ブロック木 → semantic DOM → CSS

`js/atlas-markdown.js`。行を走査してブロックの木（見出し・段落・リストと項目・引用・水平線）を作り、
`<p>` / `<h1>`〜`<h6>` / `<ul>` / `<ol>` / `<li>` / `<blockquote>` / `<hr>` を組み立てる。
**余白は1バイトも吐かない**。

⚠ **二重の余白は直っていない。表現できなくなった。** 段落の下マージンと見出しの上マージンは**相殺する**
（margin collapsing）ので、#R232 が手で引き算していたものをブラウザがただでやる。
実測（`tests/r494.spec.js` #1・実ブラウザ・`getBoundingClientRect()`）: 段落の下マージン **21px**、
見出しの上マージン **27.4px**、その間の隙間 **27.4px**——**max であって和ではない**。
検査は max との一致と「和より小さい」の**両方**を主張する。相殺が止まった日に落ちる。

⚠ **#R156 が守っているもの（コード・数式・表）はこの解析器に見せない。** それらは解析の前に
PUA プレースホルダへ退避されていて（#R156/#R463）、`# IntMap — Developer / Context Notes


 や `#` が markdown として読まれないための仕組みだから。
段落の**途中**にブロックのプレースホルダが混じる場合だけ `<p>` ではなく `<div>` で包む——`<p>` の中の
`<div>` はパーサが段落を閉じてしまい、残りの文が要素の外へ出るため。

### ③ 入れ子が効かなかった真因は、字下げを消していた1行だった

`_atlStanza` は、モデルが構造を書かなかった返答を組み直す。その入口が
`raw.split(/\n\s*\n|\n/).map(s=>s.trim())` で、**全行の字下げを、誰かが見る前に消していた**。
子項目と親項目が同じ列で解析器に届くのだから、何を書いても入れ子にはならない。

リスト行は**列を保つ**ようにした（散文の段落は今までどおり trim する——そちらの字下げには意味が無い）。
マーカーは**書き換えるのではなく正規化する**: 「1、」→「1. 」は番号を保ち、①-⑳ は値を保ち、
互いに置換可能な記号（•・*+）だけが `- ` に畳まれる。全角の字下げは半角2つになる（列を数えるため）。

### ④ 綴りを固定していた検査が10本落ちた——落ちたのは規則ではなく、実装の写しだった

置き換えで赤くなった検査は、ほぼ全部が**その `.replace()` の文字列そのもの**を主張していた。

```
tests/r159-checks ①  ok('.replace(/^##\s*(.+)$/gm,\'<div class="atl-h" style="font-weight:600;color:var(--text-main)')
```

これが守っていたのは「見出しは semibold で単色である」ではなく、**「レンダラが正規表現の連鎖であり続けること」**
だった。#R488 が記録したのと同じ形（綴りを固定する検査は、綴りの背後で規則が死んでも気づけない）の裏返しで、
ここでは**規則は生きたまま、検査だけが落ちた**。

規則は **CSS に1回だけ**書いて（`js/atlas-styles.js`）、検査は**描画結果に訊く**ようにした:

| 規則 | いま誰が言っているか | 誰が確かめるか |
|---|---|---|
| #R154 見出しを色分けしない | `.atl-h{…color:var(--text-main)}` 1本 | r494-checks ⑥（`.atl-h[1-6]` のどれも `color:` を持たない） |
| #R159 本文に太字は無い | `js/atlas-markdown.js` の `**…**`→平文 | r494-checks ⑥（描画して `<b>`/`<strong>` が無い） |
| #R158 段落の余白 1.5em | `.atl-p{margin:0 0 1.5em}` | r494.spec #1（実測ピクセル） |
| #R150 文末＋改行は狭い余白 | `.atl-ps{margin-bottom:.82em}` | r494-checks ① |
| 見出しの階層 | `.atl-h1`〜`.atl-h6` | r494-checks ⑧（6段が**厳密に単調減少**） |

⚠ **H4〜H6 は全部 1.3em だった**（H3 と同じ）。3段の入れ子を書いた返答は、3段目・4段目・5段目が
同じ見た目で出ていた。1.14 / 1.02 / .94em の階段になり、見出しには `text-wrap: balance`、本文には
`text-wrap: pretty` が付いた。

### ⑤ ついでに直った、規模の小さいもの

- **コードに色が付いた**——`js/atlas-highlight.js`。外部ライブラリ**ゼロ**（Prism/highlight.js は
  1文法も入れない状態で 20–100 kB あり、その全部が起動予算に乗る）。js/ts・python・json・html/xml・
  css・sql・bash・yaml の8文法＋未知の言語名へのフォールバック、**言語名が無ければ着色しない**。
  ⚠ `esc(code)` が座っていた場所を置き換えたので、**その責任ごと引き継いでいる**: 出力に現れる
  タグはこのファイルが書いた `<span>` **だけ**で、検査はそう主張する（`/<(?!\/?span[ >])/`）。
- **Wrap トグル**——`Copy` の隣。既定は今までどおり `white-space:pre` ＋ 横スクロール（行が意味を持つ
  コードの唯一正直な描き方）。JSON 1行やログのために読み手が**ブロックごとに**切り替える。
- **表の列は中身で折り返しが決まる**——全セル `nowrap` は数字には正しく、文章の列には誤りで、
  説明が1列あるだけで表が数画面横に伸びていた。列の全セルが短いか測定値に見える間は nowrap、
  1つでも文なら**その列だけ**折り返す。
- **`\|` がセルの中に留まる**——行の分割が `split('|')` だったので、GFM がそのために用意した
  エスケープが**まさにその文字で行を切り**、以降の列が1つずつ左へずれていた（黙って）。
- **出典カードの7件目以降**——`slice(0,6)` は**黙った打ち切り**で、9本の記事に支えられた返答が6本を見せて
  何も言わなかった。それは画面の上では「これが出典です」と読める、コードが偽と知っている主張である。
  見せる枚数は6のままで、残りは `+3` のチップの裏に**描かれている**。
- **引用番号は1つの pill にまとまった**——`[1][2][3]` が3つの丸として散っていた。1つの背景・
  1つの輪郭・数字の間にヘアライン。**リンクは1つも失われていない**（各数字は今も自分の出典への anchor）。
- **本文 12.8px → 13.5px/1.62**、`word-break:break-word` → **`line-break:strict` ＋ `word-break:normal`
  ＋ `overflow-wrap:anywhere`**。前者は任意の2文字の間で改行を許す＝日本語では行頭に「、」「。」「）」が
  来ることを許すという意味で、禁則処理はそれを防ぐために存在する。
- **返答本体は名前のあるクラスになった**（`.atl-md`）。`style="font-size:14px;line-height:1.68;"` という
  **インライン文字列を5か所が書き写して**いて、モバイルの拡大規則は `[style*="font-size:14px"]` で
  それを**綴りで**拾っていた——1か所が `font-size: 14px` と書いた日に黙って外れる種類の結合である。
