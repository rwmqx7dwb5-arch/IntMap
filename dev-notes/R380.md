## R380 — **1850 までの拡張を全数監査した**

依頼はこうだった。「IntMapで1850年までのcoverage拡大をしたと思いますが、その分を徹底的に監査し、
修正してください。」

監査の基準は**外から持ち込まなかった**。#R349 自身が2つの不変条件を書いている——

> 「各サブシステムは**自分の出典が届くところまで**遡り、止まるところでそう言う。時計は最短のものに
>  揃えない」（`js/chronos.js`）
> 「各下限は**その政体自身の開始年**であって、窓の下限ではない」（`js/time-borders.js` `_ERA_WIKI`）

この2文を、**出荷されたバンドルに 1 年ずつ当てて測った**。結果は「掃引が途中で止まっていた」であり、
しかも**止まっていることを見張るはずの検査が、止まっていることに気づけない形**をしていた。

### 1. 「1900 で始まる時代はもう無い」と題した検査が、15 行が 1900 で始まったまま緑だった

`tests/r349-checks ④` の題は文字どおり *no era span still opens at 1900 just because the window used
to* である。中身は **20 個の国コードを手で並べた一覧**で、表そのものは一度も読んでいなかった。表を
構文解析すると **125 行**あり、そのうち **15 行**が `1900` で始まっていた。

### 2. 比較パネルの下限は「時計の下限の3つ目の写し」で、1900 のままだった

`js/stats-compare.js` の `_ttYear()` は `(y>=1900&&y<now)?y:null`。この関数の `null` は**すべての
読み手にとって「いま LIVE」の意味**である。つまり 1850–1899 では——時計が受け付け、Countries タブが
答え、Maddison が持っている年で——**比較パネルだけが今日の数字を19世紀の年号の下に描いていた**。
警告帯も出ない: 帯は `ty` があるときだけ出るので、「遡りすぎ」と「現在」が同じ `null` に潰れていた。

下限を `T.min` にした。1875 は既存の `ty<1960` の分岐（「この年の長期推計値 — 世界銀行・IMF の年次
データは1960年以降」）に落ちる——**この帯はもとから在り、誰も到達できなかっただけ**だった。
同じ形が `_yoptsAvail()` の**4つ目の写し**にもあった（系列が届く前の仮の年一覧）。

### 3. Atlas の拒否文が、9言語すべてで 1900 と言っていた

```js
if(y<T.min) return R(false, warn('⚠ '+L('Chronos reaches back to 1900', …)));
```

**ガードは正しい**（`T.min` を読むので 1850）。古いのは**その隣の文だけ**で、1840 を頼んだ読者は
「Chronosは1900年まで遡れます」を受け取る——**同じ文の次の節が受け付ける 1875 を、拒否したように
読める**。`{y}` プレースホルダにして `T.min` から埋める（`{place}` の前例、#R309）。

同じ掃け残りが4つ: **Atlas の能力表（プランナへの契約文）** が `deep time, 1900→now`、
**オンボーディング**が「1900年まで遡って表示」、**README** が *from 1900 to the present*、そして
**`Architecture.md` が同じ事実を 1820 / 1900 / 1850 の3通りで書いていた**（`js/chronos.js` のコメント
にも 1820 が残っていた——実測の下限は 1850）。使われなくなった `1900 to present` /
`The time machine reaches back to 1900` の locale 行も4言語から外した。

### 4. オーストリアは、#R349 がオスマン帝国について直したのと同じ形のまま残っていた

`AUH` の `from` は `1867-06-08`＝アウスグライヒで、**成立日として正しい**。だからこそ 1850–1866 は
**どの旧国家にも属さない**空白になり、オーストリア・ハンガリー・チェコ・スロバキア・スロベニア・
クロアチア・ボスニアが**主権国7つとして並んでいた**——#R349 が「1850–1875 は帝国を隠して7つの現代の
後継国を並べるところだった」と書いた、まさにその文の隣国である。

しかも**地図のポップアップは同じ年に「オーストリア帝国」と答えていた**（`_ERA_WIKI.AUT` は #R349 が
`[[1850,1867,'Austrian_Empire']]` に直している）。**アプリの半分どうしが、同じ年について食い違って
いた。**

⚠ **直し方は「寿命を広げる」ではない。** オーストリア帝国（1804–1867）は二重帝国とは別の国家で、
`AUH` を広げれば 1850 に「オーストリア＝ハンガリー」と書くことになる。#R349 が東インド会社を Raj の
前に置いたのと同じやり方で、**`AUE` を1行足した**（黒地に金の帝国旗・首都ウィーン・人口 37,500,000＝
記事の infobox の 1843 年推計）。

朝鮮も同じ形で、しかも一段悪かった: `IntMapHistId` が KOR を「朝鮮」に**改名**していたので、一覧に
**「朝鮮」と「北朝鮮」が並ぶ**ことになる（存在しない国が、分割される前の王朝の隣に）。**改名では
足りない——現代の後継が2つ以上ある国は集約しなければならない。**`KOJ`（朝鮮 –1897）と `KOE`
（大韓帝国 1897–1910）を足し、`JEM`（1910-08-29–）と**継ぎ目なく**繋いだ（検査 ⑥ が「前の国の最終日の
翌日が次の国の初日」を全チェーンについて主張する）。

### 5. そして最大の発見——旧国家も改名した国も、Countries タブから丸ごと消えていた

#R245 がこのファイルの名前を `LA(en, ja, de, ru, es)` ＝ **配列**にした。`agg()` と `histId.apply()` は
`name.en` / `name.jp` を読み続けており、**配列の `.en` は `undefined`**。そして
`js/countries-ui.js` の `renderStats` は `filter(s => s.nameEn && …)` である。

**改名が、改名した行の名前を `undefined` で上書きしていた。**

実測（1860 の Countries タブ、修正前）:

```
1 United States $140B · 2 Germany $94B · 3 Italy $67B · 4 Spain $30B · 5 Belgium $17B …
```

ロシア帝国もイギリスも英領インドもフランスも清もオスマン帝国もオランダ領東インドも朝鮮も無い——
**1860 年の上位10経済圏がすべて欠けていた**。そこに居るのは「その年に `histId` の項目を持たない国」
だけで、イタリアが居るのは `ITA` の項目が 1861 からだからであり、ドイツが居るのは 1871 からだった。

タプルの読み手を**1本の関数**にして両方の書き手が使う（`nameEn` は英語のまま——検索・並べ替え・
Atlas の名前照合が読む。`nameJp` は日本語スロット。タプル自身は `name` に載ったままで、地図のラベルは
これまでどおり `js/time-borders.js` の `_LTB.arr` が9言語に解決する）。

実測（同じ画面、修正後）:

```
1 ロシア帝国 $435B · 2 英領インド帝国 $300B · 3 イギリス $147B · 4 アメリカ $140B
5 フランス第二帝政 $112B · 6 オーストリア帝国 $105B · 7 ドイツ $94B · 8 イタリア $67B
9 オスマン帝国 $35B · 10 スペイン $30B · 11 オランダ領東インド $21B · … · 13 朝鮮 $13B
```

⚠ この欠陥は #R349 のものではない（#R245 以来ずっとある）。それでも**このラウンドで直さなければ
ならなかった**——4節の `AUE` は7つの後継国を隠すので、名前が出ない限り 1850–1866 は「7か国」から
**「1か国も無い」**に変わる。**直さずに足すと退行になる。**

### 6. 出典ページは「1850–1885 が1枚の絵である」ことを言っていなかった

`nearest()` は 1815 と 1880 の中点（1847.5）より上では必ず 1880 を返す。時計の下限は 1850 なので、
**時計から 1815 のスナップショットには決して届かない**（`YEARS` に在るのは β の重ね合わせ用ピッカーの
ため）。つまり **1850–1885 はどの年も 1880 年の国境**で、1886 以降だけが CShapes の年次である。

#R349 の commit は「出典ページがそう書いている」と書いているが、実際に変わったのは Maddison の行と
CShapes の行だけで、**historical-basemaps の行は「最寄りのスナップショットへの自動フォールバック」の
ままだった**——1886 年より下では**フォールバックではなく唯一の出典**である。9言語すべてに書いた
（検査 ⑧ が `CS_MIN` と `YEARS` を読んで、9言語の行が 1886 / 1815 / 1880 / 1850 を含むことを見る）。

### 検証

`tests/r383-checks.test.mjs`（9本・`test:checks` に登録）＋ `tests/r349-checks ④` の書き換え。
**否定形の検査には「赤にできる一行」を添えてある**: ① は走査が reach-claim を8件以上見つけたことを
先に主張し（見つけていない走査は空の tree でも緑になる）、⑤ と ⑨ は実際に壊して赤を見た
（`AUE.from` を 1870 に→⑤⑦が赤・戻すと緑／`nameEn:_nmEn(nm)` を `nm.en` に戻す→⑨が赤）。
⑤⑥⑦⑨ は **`js/history.js` をスタブ `window` で読み込んで実際に走らせる**——綴りではなく答えを訊く。

⚠ **12回目、検査が自分の散文に当たった**: ⑨の `name.en` 走査が、その欠陥を説明した**自分のコメント**を
2件拾って赤くなった。`scripts/code-only.mjs`（#R345）を通した。

### 直さなかったもの（測ったうえで）

- **1850–1885 の国境は実行時に raw.githubusercontent.com から取る**（1880 の1枚・1.3 MB）。1886 以降は
  自己ホストの `data/cshapes.js`。**新しい範囲だけが第三者の CDN に依存している**が、自己ホスト化は
  データ 1.3 MB の追加であり、依頼の「監査と修正」の範囲を超えるので**記録に留める**。取得に失敗した
  ときの挙動は従来どおり（4 秒ごとに再試行）。
- **旧国家の名前は、Countries **一覧**では en/ja 以外の6言語で英語**（`cName` が `nameEn`/`nameJp` しか
  見ないため）。**地図のラベルは9言語で正しい**。#R245 以前と同じ挙動で、このラウンドが直したのは
  「名前が消えていた」ことであって、ここを変えるには `cName` に機構を足すことになる（app shell の
  行数予算 8,000 は現在 7,999）。
- **メキシコ（1850–1863 / 1868–1875）とポーランド（–1917）は現代記事に落ちる**。これは**偽の主張では
  なく空白**で、その期間の国家形態は「メキシコ合衆国」「（分割下で国家なし）」だから、`_ERA_WIKI` の
  規則を破ってはいない。

### 副作用として直った数

`js/app-body.js` のシェル行数は**±0**——最初に足した2行コメントが予算 8,000 をちょうど 1 行
超えて `tests/r168 #8` を赤くしたので、1行に畳んだ（#R353 が同じ壁に当たっている）。
起動バイトは **raw +3.9 kB / gzip +1.0 kB / brotli +0.9 kB**、モジュール数 ±0（`check:perf` の
ラチェットの許容内）。増えたのは `js/history.js` の3行——オーストリア帝国と朝鮮／大韓帝国の
登録（旗2枚・9言語ぶんの名前・推計値）で、この登録簿は既に 16 の旧国家を eager に持っているから
3つを別チャンクへ出すほうが構造として不揃いになる。**測った数を書く**——ここは最初「±0」と書いて
いて、それは `EAGER` の行を読まずに `ASYNC`/`DEPLOY` だけを見た結果だった。
