〈依頼〉 費用・キャッシュ・台帳・上限・子 AI のモデル指定・ストリーミングは既にある。足りないのは (1) 完成した仕事ごとの総費用/時間/モデル/ツール、(2) 仕事に応じたモデルの使い分け、(3) 長時間ジョブでの非同期 API の可否、(4) 同一分析の再利用。

## 0. 着手時の状態（他セッションと重ならないために）

- 永続ジョブ #1294/#1317 と作業成果物 #1314、PTC #1307 は **未 merge**（open）。永続ジョブには触れていない。`js/compute-sandbox.js` は #1307 も触るため、こちらの差分は `run()` の 3 か所と import だけに絞った。
- 既にあったもの: プロキシは 1 リクエストごとに `meta.costUsd` / `modelServed` / `priceKnown` を返す。委譲の子には `ATLAS_DELEGATION_MODEL`（全子で 1 つ）。1 ターン内の同一呼び出しの再利用（`callKey`）、1 委譲内の契約再利用（`contractKey`）。**ターンをまたぐ再利用と、ターン単位の合計は無かった。**

## 1. 作ったもの

- **`js/atlas-run-ledger.js`**: `runTurn` が 1 ターンの提供元応答（モデル・費用・時間・Web）とツール実行（名前・時間・成否・委譲の子の費用）を集め、`result.run` / `trace.run` で返す。直近 50 件は `IntMapAtlasAgent.runHistory`。回答の下に 1 行（費用・時間・モデル・主なツール）を出す。
  - 費用が報告されなかった応答は 0 円と数えず `costUnknownCalls` に数え、行に「未取得分」と出す。価格表に無いモデルは最高単価換算であることを書く。
  - **観測するだけで、何も制限しない。**
- **仕事ごとのモデル選択**: 子のタスクが任意の `model` を持てる。選べるモデルは価格つきの一覧で、`meta.delegationModels`（`delegationPolicy` の形は他の読者が固定しているので別キー）としてページに届き、Atlas のコンテキストに「モデル id と入力/出力単価」として載る。サーバは一覧にある id だけを受け入れ（`x-intmap-model`）、無ければ理由つきで無視して従来の設定どおりに走らせる。
  - 一覧は `ATLAS_MODEL_OPTIONS`（カンマ区切り）、未設定なら提供元の既定＋OpenAI の FALLBACK_CHAIN のうち**価格が表にあるもの**。種類分け（「調査用」「抽出用」）をコードに書いていない：どれが要るかは仕事を書く Atlas が決める。
  - モデルは契約の同一性と再実行鍵に入る（強いモデルでの再依頼は重複ではない）。
- **同じ分析の再利用 `js/atlas-result-reuse.js`**: `compute.run` は、コード・入力データの**内容の指紋**・実行条件（ランタイム版）が同じなら前回の結果（同じデータセット id）を返す。出力データセットが消えた・古くなった・件数が変わった場合は再計算。乱数・時刻を使うコード、指紋を取れない（大きすぎる）入力は再利用しない。カードには「再計算していません」と出る。

## 2. 非同期/バックグラウンド API の可否——**測れていない**

- この環境に OpenAI の鍵が無く、本番へは利用者ログインが要るため、**実測はしていない**。以下は公開情報（2026-11-20 の検索）で、第三者記事を含む。**公式の価格ページで確認してから使うこと。**
  - Batch と Flex は標準の 50%。Flex は `service_tier:"flex"`、遅く、容量不足で 429 になりうる。Flex の価格表に載るのは Terra・Luna で、**現行の既定 Sol は載らない**（未確認）。
  - Background mode の既定は非同期になるだけで割引なし。2026-11-17 に 2 時間・8 時間の窓（30%・40% 引き）が beta で出たとの記事がある（Flex とは併用不可）。
- **判断**: 対話の 1 ターン（秒〜数十秒で返したい）には使えない。使い所は永続ジョブ（#1294/#1317）の長い調査・抽出で、結果を待たない読み取り仕事。**アダプタは作っていない**——価格と対応モデルが一次情報で確認できていないものを呼び出し経路に入れないため。永続ジョブが merge されたら、そこへ `service_tier` を選べる口を足し、同じ課題で費用と所要時間を実測する（この記録の §3 の計器でその比較ができる）。

## 3. 実測に基づく「プロバイダ・モデルごとの本当の効果」について

- **まだ言えない。** 台帳（`ai_turns`・`ai_delegation_journal`）にはモデルとトークンがあるが、「同じ課題を別のモデルで」という対が無い。今回の `run` 記録はその対を取るための計器で、効果の主張はこれが溜まってから。2026-11-18 の記録にある数字（最大 $0.61・p99 入力 34.6 万トークン）は単一モデルの値で、モデル間の比較ではない。
