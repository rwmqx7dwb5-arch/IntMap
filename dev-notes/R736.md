## R736 — 成功した描画が「描かれていない」と報告され、歴史の政体は塗れなかった

〈本番（ログイン済み）で Atlas に 7 本の複合指示を出し、回答文と地図を実際に見た回〉

### 0. 実測（本番・2026-09-15）

### 1. ⚠⚠⚠ 国のハイライトは、成功するたび「描かれていない」と報告されていた

`js/atlas-capabilities.js` の `paintNow()` は、地図の操作が**何かをしたか**を
「geojson ソースの地物数を手で並べた一覧」で測る。ところが国のハイライトは
`nlq-src` への **`setFeatureState`** で塗る——**どのソースにも 1 件も足さず、レイヤーも増えない**。
歴史年では `nlq-era-src` に塗るが、**それも一覧に無い**。

⇒ `changed(before, after)` は必ず false、`verify()` の判定は **`not_rendered`**。
実測: `highlight` 3 回、**3 回とも `_hlPolys`/feature-state に実際に入り**、
**3 回とも `ok:false code:'not_rendered'`**。
「描けていない」と 3 度言われたターンは、残りの手を描き直しと `find_capability` に使い、
**約束した棒グラフを描かずに**作業上限で終わった。

⚠⚠⚠ **そして最悪の 1 本は、この欠陥だけでできていた。**
「世界で人口密度が最も高い10か国を地図で色分けして、上位3つの理由を説明して。」
**21 手・10 分 29 秒**、そして中身は

```
highlight → not_rendered → rank "density" → not_rendered →
highlight → not_rendered → rank "density" → not_rendered →  … これが 7 周
```

**地図は最初の 1 組で正しく塗られていた。** `data.rank` の色分けも `setFeatureState({choroV})` で塗るので、
ハイライトとまったく同じ理由で観測されない。7 回「何も描かれていない」と言われた模型は、7 回描き直した。
⇒ 申告は `_choroState` の件数と、**どの指標で塗っているか**（`_choroMetric`）も運ぶ
——同じ国を別の指標で塗り直すことは、件数では動かない変化だから。
⚠ **一覧の中身ではなく、一覧という形が欠陥である。** 新しい塗り面が増えるたび、誰かが
ここに足すことを憶えていなければならない——**#R735 が `nlq-fac-src` で 1 度払っている**
（`.agents/rules/no-ad-hoc-hardcoding.md` §2.4）。

⇒ **塗る側が、塗ったものを自分で宣言する。** `js/atlas-console.js` は
`window._imAtlasPaint.now()` を、塗る状態のすぐ隣で公開する（件数だけ——観測側が要るのは
「何かが描かれたときに動く値」であって絵ではない）。`paintNow()` はその申告を運ぶ。

### 2. ⚠⚠⚠ 歴史の政体は、それが地図に描かれている最中に限ってハイライトできなかった

`highlight(codes)` は `valid`（**現代の国 geojson** の id 集合）に無いコードを
**`_eraGeomsFor` を訊く前に** `return` していた。

実測 1914-06-28:

- `IntMapAtlasDebug.resolveHl('Ottoman Empire')` → **`{kind:'country', code:'OTT'}`**（`js/history.js`）
- `IntMapTimeBorders.geomForCode('OTT')` → **本物の MultiPolygon**
- `IntMapAtlasDebug.codesGeo(['OTT'])` → `hit: []`（現代の記録は持っていない）
- ハイライト → **2 回連続で失敗**。文面は「地図読込中。もう一度お試しください」

その文面は**起きていない競合についての主張**で、しかも再試行は原理的に成功しない。
（#R142 が置いた `valid` の門は正しい趣旨——「描けない形を描いたと言うな」——だが、
**1 つの記録にしか訊いていなかった**。[[intmap-one-store-was-asked]]）

⇒ 「この地図はこれを描けるか」を、**いま描いている記録すべて**に訊く。順序は
**歴史記録が先**——それが読者のカーソルの下にある形だからで、`_eraGeomsFor` は
現在時刻では `null` を返すので**現代の経路は 1 バイトも変わらない**。
`unionBox`（カメラの枠取り）も同じ順で直した——塗ったのが歴史の形なら、
枠は同じコードの**現代の**多角形ではなく、その形に付く。

### 2b. ⚠⚠⚠ カメラは、動かなかった移動を「移動しました」と報告していた

「Turn on the night lights layer, fly to the Korean peninsula, and tell me what the image shows」——
レイヤーは点き、返答は **`ok:true`** で「Moved to: Korean Peninsula」と述べ、**カメラは 1 度も動かなかった**。
`IntMapConsole.dispatch({type:'flyTo',place:'Korean Peninsula'})` で 100% 再現する。

⚠ **偽の成功は、失敗より悪い。** 返答は読者が頼んだ行き先を名指し、地図はまったく別の場所を映している。

実測（`tests/fixtures/r736-nominatim.json`・2026-09-15 の実応答）:

| 問い合わせ | 上流が返したもの |
|---|---|
| Korean Peninsula | Peninsula Korean Baptist Church（バージニア州）／韓国料理店・食材店・語学学校 — **8 件すべて importance 0.000** |
| Chesapeake Bay | Chesapeake Bay — 0.604 |
| Mount Fuji | Mount Fuji — 0.608 |

**OSM に「Korean Peninsula」という地物が無い**ので、自由文検索は一致しない語を落として残りで並べる。
`_nomExtent` は importance 順の先頭を採るだけで、その下にあるのは**低 importance の「集落」型だけ**を見る門。
**POI は 1 件も見ていなかった。**

⚠ **止める規則は同じファイルに在った。** #R515 は同じ理由で `geocode`（点の解決器）に名前一致の床を入れた。
`placeExtent` が使う `_nomExtent` は、その姉妹である。#R429・#R488 と同じ形——
**1 つの関数に書いた規則は、その関数しか守らない。**

⇒ 2 段で、どちらもこのファイルが既に持っている尺度:

1. **同じ `_nameAgreement` の床**を、候補を**並べ替える前**に適用する（`namedetails=1` も同じく要求する——
   「Mount Fuji」が富士山と一致するのは `name:en` を通してであって、運ではない）。
2. **典拠自身の雑音床（`importance < 0.05`）では、名前が問い合わせを包含するものだけが発言できる。**
   教会は bigram 一致 **0.63** で 1 を通る——2 で落ちる。実在の地物（0.604 / 0.608）は床のはるか上なので無傷で、
   importance の低い POI でも**名前そのもの**が問い合わせなら（「Tokyo Station」→東京駅）通る。

### 2c. モデルを Terra に、`gpt-6-astra` を選択肢から取り下げ（利用者の指示）

「一般向けアカウントのモデルは GPT 5.6 Terra に。6 Astra は管理者アカウントの選択肢から削除。
管理者アカウントのデフォルトも Terra に。」

⚠ **3 文目に新しい設定は要らなかった。** 管理者の「既定」は読者のモデルそのもので、
`js/ai-core.js` はそれを「Server default — <id>」と**名前で**提示する（`serverDefault.model`）。
無い設定を作って試験すれば、IntMap が持っていないものを測ることになる。

- `OPENAI_DEFAULT_MODEL` = `gpt-5.6-terra`、`AI_MODEL` シークレットも同じ値へ。
  ⚠ **両方でなければならない**——#R722 の欠陥はまさに「秒読みで勝つのは秘密のほうで、
  定数が名指すモデルは何か月も走らなかった」ことだった。
- 梯子は `terra → sol → luna`。順序の方針（新しい順・最後は一度も失っていない Luna）は変えず、
  頭だけが動いた。梯子が置き換えるためにあるモデルを梯子の先頭に置かないことは検査が測る。
- **取り下げ**は目録の中に書かない。`listModels` はモデル名を 1 つも持ってはならない
  （`tests/r722` ②。持てば「その日に撮った写真」になる）ので、所有者の決定は**別の事実**として
  定数の隣に `WITHDRAWN_MODELS` 1 行で在る。⚠ **呼び出しは塞がない**——proxy は渡された id を
  そのまま呼ぶ（`CONSTITUTION.md` §0.3）。変わるのは**提示されるもの**だけで、検査は
  「読まれるのは目録を組み立てる 1 か所だけ」を数で測る。
- 既に `gpt-6-astra` を選んでいた口座は、**次に設定を開いた時点で**サーバー既定へ戻る。
  `<select>` は持っていない値を表示できないので、放置すると画面は「サーバー既定」と読めるのに
  呼び出しは取り下げたモデルを名乗り続ける。⚠ **提供者が答えたときだけ**落とす——到達できない
  提供者は空の一覧を返すので、そこで落とすと読者の選択をネットワーク障害に奪われる。

### 3. 検査

`tests/r736-atlas-multiprobe-checks.test.mjs` — 出荷している `js/atlas-geo-resolve.js` を、`fetch` だけ差し替えて
**実応答の写し**（`tests/fixtures/r736-nominatim.json`）の上で走らせる（`tests/r515-checks.test.mjs` と同じ形）。
②は**データについての事実**として書いてある——次に同じ欠陥を「類似度の閾値だけ」で直そうとする回が、
写しを見て**それでは無理だ**と分かるように。

`tests/r736-atlas-multiprobe.spec.js` — どちらも**実際の dispatch を通す**。
①は**関数の中の順序**、②は**動かなければならない値**で、どちらも綴りを探す検査には見えない
（#R505）。**修正を外すと 2 本とも赤になることを個別に確認した。**

⚠ ページエラーの検査は置かなかった。このランナーの headless MapLibre は
fragment shader のコンパイルに失敗するので、それは IntMap ではなく**走者**を測る
（[[intmap-gate-verdict-must-not-depend-on-the-runner]]）。

### 4. 測ったが、この回では直していないもの

1. **純然たる歴史の問いが `research.analyze` へ行った。** 「オスマン帝国の領域は現代のどの国か」
   に対し、根拠として**現在のニュース記事**（Trump・ウクライナ）が集まり、回答契約は
   「証拠が無いので答えられない」と**拒否**した。5m41s かけた非回答。
2. **`data.compareStats` がサイドバーを Countries に切り替える。** Atlas に訊いた読者は、
   その瞬間から**自分の質問への回答を見られない**。
3. **直前に 300 km の円を描いた `flyTo` が街路レベルまで寄る。** 円は完全に画面外。
   同じターンで描いたものが枠に入っていない。
4. **「円の中に入る県は」が幾何ではなく web 検索で答えられる。** `admin1-world.json.gz` と
   #R732 の空間演算が手元にあるのに訊かれていない。
5. **返信末尾の `Atlas can be inaccurate — verify important facts.` が日本語の返信でも英語のまま。**
