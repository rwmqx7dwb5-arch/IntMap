### ⓪ nightly は存在し、毎晩走っていた——**14夜連続で赤**だった

```bash
gh run list --workflow=ci.yml --event=schedule --limit 40
```

| 日付 | 結果 |
|---|---|
| 2026-08-21 / 08-19 / 08-17 … 08-08 | **failure ×12** |
| 2026-08-20 / 08-18 | cancelled ×2 |

### ⑨'' `r173` は測ったが直していない——**そして直したふりもしていない**

`r173 ①`（コックピットに世界があり、視点が機体にある）は降下側で `|eyeAlt − alt|` が **~250 m**。
⚠ **カメラは疑うところではなかった**——降下の全区間を2秒ごとに標本すると `eyeAlt` は `alt` を
**0.1 m 以内**で追い、地形が途中で届いても追い続ける（実測）。250 m は**ランプ1段ぶん**
（(6000−250)/25 = 230 m）で、検査が `S.alt` を**シミュレータの外から**書き、カメラは**中から**
書かれるという非対称そのものである。

三つ試して、**三つとも証拠が足りなかった**ので全部戻した:

1. **測る前に一時停止**（このファイル自身の規則。降下側にだけ適用されていなかった）→ 変わらず。
2. **`?rafshim=1`**（このスイートの14本が「非フォーカスのページは rAF をほぼ絞られる」を理由に
   使っている）→ 5回中2回通り、3回落ちた。**決着しない。**
3. **時計ではなくフレームを待つ**（カメラが機体に届くまで30秒待って、届いたことを主張する）
   → 2 worker で**30秒待っても届かない**。つまり「1フレーム分の遅れ」でもない。

分かっているのはここまで: **単独で3回通り、CI の nightly でも通り（2.7 分）、2 worker の55本
フル走行では約半分の確率で落ちる。** 何が正しい直し方かを示す証拠が無いので、`tests/r173.spec.js`
は**このラウンドで1バイトも変えていない**。⚠ 分からないものを、それらしい変更で埋めない。
（`tests/durations.json` の `solo` に入れる手はあるが、`playwright.config.js` の `testMatch` が
`IM_SUITE=cesium` を `-cesium*` に限っているので、**CI ではその1本が黙って走らなくなる**。
共有機構をこの1本のために広げるのは、測れていない変更としては大きすぎる。）
### ⑩ このラウンドの途中で #R301 が merge され、その検査が**次のラウンドを必ず落とす**形をしていた

`tests/r301-checks.test.mjs ⑦` が `window.__imBuild='R301'` を**リテラルで**固定していた。
