### ① 気象警報 — 2つの尺度が1つのパレットを共有し、凡例はもう一方の名前を読んでいた

世界の凡例が印字していたもの（実測、本番のビルド）:

| 見本 | 印字されていた名前 |
|---|---|
| **紫** `#a335ee` | **赤（最も深刻）** |
| **赤** `#ff3b30` | **オレンジ（深刻）** |
| **黄** `#ffcc00` | **緑（情報）** |

3行とも自分の色と矛盾している。原因は1行で、`tierKey(names)` が**命名関数を引数に取りながら色は常に
`TIERCOL`** だったこと。呼び出しは2か所あり、片方が GDACS の Green/Orange/Red を渡していた。
⚠ **鍵は、それが鍵である対象から色を取る。** `keyRows(col,name)` はパレットと名前を**一緒に**受け取るので、
あの行はもう書けない。

**そして「日本は発令されてない箇所が紫色」は、凡例の話ではなく塗りの話だった。**
GDACS は**国単位の事象**フィードで、`washTier()` は事象の `affectedcountries` に載った国を `TIERCOL` で
塗っていた。実測（同じ分）: GDACS は **Red の熱帯低気圧 BAVI-26** を配信しており、その影響国リストに日本が
入っている ⇒ `feature-state.wpAlert` = 3 ⇒ **国土全体が #a335ee**。その下では気象庁のポリゴンが
**15都道府県すべて注意報（黄）**と言っていた。片方が「特別警報」と読める色で国を塗り、もう片方が
「注意報」と塗る——**同じレイヤーの中で**。

→ 3つ直した。
* **GDACS は自分の色**（緑 `#3d9a3d` / 橙 `#f08c00` / 赤 `#e02b1d`）で、**自分の凡例**を持つ。実測、
  TIERCOL と GDACSCOL は**1色も共有しない**（テストがそう検査する）。
* **発令区域そのものを描いている国は、国全体を塗らない。** `GEOM_FEEDS` = jma / nws / eccc / inmet。
  その国では**形が答え**であって、国を1色にすることはその答えと矛盾する以外にできることが無い。
  実測（修正後）: JPN・USA・CAN・BRA の `wpAlert` は **0**、CHN は **3**（中国気象局自身の最上位）、
  FRA/IDN/PHL は **13**＝GDACS 赤、RUS は **12**＝GDACS 橙。
* **薄塗りは薄塗りのまま。** 不透明度スライダ（`_registerLayerOpacity`）は `fill-opacity` を**1つのスカラで
  上書きする**ので、アルファは**色の側**に入れた（`rgba(…,0.40)`）。従来は 0.85 で国が塗り潰されていた。

### ② 「昼夜オフ」は「太陽の位置が不明」ではない

#R240 は昼夜表示がオフのとき太陽を**カメラ中心の真上**へ向けている——散乱の積分に正しいフレームの太陽を
与えるためで、そこは正しかった。**その事実が `_sunElevAtCentre()` に伝わっていなかった。**
この関数は同じ状態に `null`＝「不明」を返し続け、読者は3つある:

* `_limbOwnsRim()` は `null` で **false** ⇒ **この app 自身の大気（js/limb-layer.js、#R227–#R238 の全部）が
  そもそも点かない**
* `_skyColour()` は `_SKY_SPACE`（`#060b16`）＝**真昼に空が宇宙**
* `_horizonColour()` は `_SKY_H_DAY`（`#c2ccd1`）＝**平坦な灰色の帯**

つまり昼夜表示を切ると、計算された色のついた本物の空気が消え、maplibre 自前の粗い光輪と灰色の帯に
入れ替わっていた。**「同じ大気を表示するように」はこれのこと。**（確認: 「明るさ・色は同じ、境は出さない」）

→ **その状態の太陽は既知**で、`_aimSun()` がカメラ中心へ置いたところにある。90° は仮定ではなく
**この直前に自分で向けた光の読み戻し**である。`_relAzimuth()` も同じ読みに合わせた（天頂の太陽に方位は無い）。

実測（衛星写真・地球儀 z1.2・同一カメラ、円盤の 0.30R / 0.75R / 0.97R の平均輝度）:

| 状態 | 0.30R | 0.75R | 0.97R | 縁÷内側 |
|---|---|---|---|---|
| 昼夜オン | 144.7 | 108.3 | 100.6 | **0.70**（＝ターミネータが見えている） |
| 昼夜オフ（修正後） | 157.3 | 153.1 | **196.4** | **1.25**（＝空気が縁で明るい・境は無い） |
| 昼夜オン（戻して） | 144.7 | 106.4 | 100.5 | 0.70（可逆） |

⚠ **標準マップは1バイトも変わっていない。** #R241 は
「衛生写真ではあっても、標準マップでは大気はなし」という明示の指示で、`_sunElevAtCentre()` の
**最初の行が `!_satelliteUp()` の早期 return** なので、Map 基盤では従来どおり「不明」を返し
`atmosphere-blend` は 0 のままである。実測でも Map の `sky-color` は `#060b16`、`ab` は `0`。

### ③ 言語分布の「色の凡例」が「セルビア語」としか読めなかった

#R268 は**名前**を分け（実測、鍵には「セルビア語」「クロアチア語」「ボスニア語」の3行が確かにある）、
「塗は同じ色のままでいい」に従って**4標準に1つの塗り**を残した。今回の報告は「**色の凡例**」で、そこが
まさに問題だった: 1つの塗りだと**その3行に同じ見本が付く**ので、地図の色に付く名前は「その色を最初に
名乗る行」——セルビア語（2か国を代表。クロアチア語とボスニア語は1か国ずつで、順位表で19行と32行下）。
**鍵を通して地図を読むと、クロアチアもボスニアも依然セルビア語だった。**
→ 各標準に自分の色。`LANG_ONE_COLOUR` と `grpOf` は**使われなくなった**のではなく**削除**した。

### ④ 世界銀行の凡例が「段彩」だった

塗りは `['interpolate',['linear'],['get','v'],…]`＝**連続**なのに、鍵は**1停止1個の四角**が7個。
−6% の国の色は**自分の凡例のどこにも無かった**。他のレイヤー（HDI・1人当たりGDP・人口密度・出生率・
国防費＝`makeLegend`）は全部グラデーション帯である。
→ 帯にした。⚠ **停止は値の位置に置く**——`interpolate` は値について線形なので、等間隔に並べた帯は
ランプが不等間隔な層（CO₂ の 0/2/5/10/20 t など、ほとんどがそう）で**地図と違う関数**になる。
⚠ **サムネイルも同じ関数にした。** `js/layer-previews.js` の `rampColor` は「値以下の最後の停止」を
返す**階段**で、しかも `WBP` にランプの**複製**を持っていた——#R268 が層のランプを発散配色にしたとき
複製は赤→緑のまま残り、**タイルと地図が1ラウンド違う色を示していた**。ランプは層から読み
（`IntMapWB.rampOf`）、複製との一致は**テストが全61層について検査**する。

### ⑤ 「年を変えられる層」は3回目の指示だった

#R268 の追記はパネル全体を数え直し、6層を「**既にマスタークロックで変えられる**」に分類した。
**データについては真で、読者については偽**である: その6層には年を変えられると書いた物が何も無く、
変える操作は画面の反対側にある「過去の世界を見る」ボタンだった。いっぽう世界銀行の塗り分け（#R266）、
GIBS のラスタ（#R268）、ケッペン、土地被覆、夜間光、年降水量、米大統領選は**自分の凡例に年**を持っている。
同じ問いに、開いたレイヤー次第で2つの答えがあった。

→ **凡例の年セレクタ**を、`window.IntMapTime` を**読んで書く** 1 本の実装（`legendClockYear`）として作り、
1人当たりGDP・人口密度・合計特殊出生率・国防費・国防費対GDP・HDI・貿易フロー・エネルギー構成・作物に付けた。
⚠ **2つ目の時計は作らない**（#R265/#R267 が2度取り除いた形）。行は自分の年を持たず、時計が動けば行も動く。
⚠ 範囲は**各出典自身のもの**: Maddison 1900–／世界銀行 1960–／BACI 1995–2024／OWID は**読み込んだ CSV から
実測**／GAEZ は clock が近い基準年を選ぶ。

**そして HDI は「年系列そのものが無い」ではなかった。** UNDP の人間開発報告書室は
**1990→2022 の完全な合成指数時系列**を公開しており、app はその **33 列のうち 1 列**を `js/tables.js` に
持っていた。`scripts/build-hdi.mjs` が `data/hdi-series.json`（**193か国 × 33年**、集計行は落とす）を書き、
`js/time-countries.js` がマスタークロックに重ねる。実測: 日本 2000年 **0.883** → 現在 **0.920**。
⚠ **規則そのものは生きている**——1990 より前は UNDP が何も公表していないので `hdi` は `null`（「データなし」）、
最後の公表年より後はその列が立ち、凡例は**画面に出ている年**を印字する（`_imHdiYear`）。
⚠ **その印字はタイマーではなく再描画に繋いだ**（#R264 の「終わった時刻を推定するな」。重ね合わせは
`loadCountryData`＋Maddison＋HDI の着地待ちで**数秒**かかるので、420 ms 後に読むと
「この年の HDI は公表されていません」と**公表されている年について**言う）。

⚠ **監査の1件は自分の読み違いだった。** 失業率（β）を「固定スナップショット」として質問に出したが、
実測すると `beta-dl-unemp` は `wbToggle` 経由で**36年分の年セレクタを既に持っていた**（現在値 2025）。
`beta-dl-cpi`・`internet`・`lifeexp`・`precip` も同様。#R266 が入れている。

### ⑥ レイヤー検索の × は、この app のどの書体も持たない文字だった

実測、動いているページで `measureText('✕')` を 12px で:

| 指定した family | ✕ の送り幅 | X の送り幅 |
|---|---|---|
| Inter | **9.8027** | 8.186 |
| "Noto Sans JP" | **9.8027** | 6.876 |
| system-ui | **9.8027** | 7.078 |
| sans-serif | **9.8027** | 6.876 |

**どの family でも同じ数**＝どれもこの字を持たず、全部プラットフォームの記号フォントに落ちている。
だからあの印は、画面上の他のどの字とも違う太さ・大きさ・ベースラインで描かれ、OS ごとに別の形になる。
→ **幾何**にした（`window.IntMapClearGlyph()`：1つの SVG の2本のストローク、`stroke-linecap:round`）。
⚠ 検索欄は**2つある**ので定義は1つ（#R239 の教訓）。⚠ `type=search` が付ける **WebKit 自前の ✕** も
消した——Chrome では自前の印の**下にもう1つ**描かれていた。

### ⑦ 地形編集・水流のパネルは、誰にも見えない場所で開いていた

実測、ビルド済みのサイト・デスクトップ・既定プロファイル: パネルは `left:16px; top:80px; z-index:1402`、

`elementsFromPoint` を叩くと**サイドバーが返る**。切れているのでも legend の裏でもなく、**自分で選んだ
座標で完全に隠れていた**。

2つとも構造的な誤りだった。
* **1402 はこの app に無い帯である。** `css/intmap.css` の §「WHO IS IN FRONT」と

  パネルは全部その中にいて、これだけが 800 下にいた。→ `registerWindow`。
* **位置が定数だった。** #R252 の教訓そのもの（「動く障害物は矩形を実測しろ」）。サイドバーは開いても
  閉じてもよく、その幅はこのファイルが決めてよいものではない。→ `placeClear()` が**地図を覆っている
  ものを実測**して脇に開く（js/space.js のゲージが空いた中央を探すのと同じやり方）。
  読者が動かした後は動かさない。実測（修正後）: サイドバー展開時 x=**416**、z=**2201**、
  ヘッダの最前面はパネル自身。

**余白も測った。** 盛るモードの行の高さは **40 / 44 / 45 / 49 px** の4種類だった——`min-height:40px` に
7px の padding を足し、中身（30px の数値ボックス、35px のセグメント、16px のチェックボックス）が
高さを決めていたから。#R258 は設計注記に「40 px の行」と書いて、中身に決めさせていた。→ **44 px 1種**。
そして `<details>` 2つは**カードの外**にあり、テキストが他の全部より **12px 左**から始まっていた
（実測: カードは x 29→335 で本文 41、`<details>` は 29→335 で本文 **29**）。→ カードに入れた。
