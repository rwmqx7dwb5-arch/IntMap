## R433 — **製品から消した上限を、テストのほうがまだ主張していた**

#R430 の CI 調査で見つかったが、そのラウンドの範囲外だったので手が付いていなかった。
run 32755799194 の Deep rest 5/5 で、`tests/r318-atlas.spec.js:214` の
«R406 ② tool surface is small» が **2回とも同一値で**落ちている（flaky ではない）。

### 何が起きていたか

`expect(hit.matches.length).toBeLessThanOrEqual(8)` が **10** を受け取っていた。
原因は退行ではなく**修正**である——**#R413（fa924f6）が `js/atlas-toolsurface.js` から
`var MAX_FIND = 8;` を消した**。その上限は同点をアルファベット順で切っており、
「現在地から大阪駅までの経路」では10件が同点16になって `routing.route` が**9位で脱落**し、
代わりに届く5本の `navigation.*` は全部「先に経路を計画してください」と答える実装だった。
R413 は `tests/r318-checks.test.mjs` と `tests/r406-turn.test.mjs`（その166行のコメントが
`matches.length <= 8` を消したと書いている）は直したが、**この spec は開いていない。**

⚠ **2つ目の陳腐化した assert が同じテストに隠れていた。** 234行の
`expect(r.documented).toBeGreaterThan(0)` は `hit.matches.filter((m) => m.documentation).length`
を数えるが、#R413 は `documentation` を各 match から**戻り値の最上位へ移している**
（41の共有ブロックを ids ごとに1回だけ配る。同じ10件で 67,600 → 20,200 B、1文字も切らずに）。
232行が先に落ちていたので、**234行は一度も実行されていなかった。**

### 直し方——閾値は上げず、消した

`CONSTITUTION.md` §5 は「報告された不具合に対して、条件文・除外リスト・打ち切り件数を足して
塞がない」と書いている。`<= 8` を `<= 10` にするのは、R413 が名指しで否定した動きである。

代わりに、**1つの assert が混ぜていた2つの主張を分けた**。

- **«small» は「送られるもの」についての事実**で、discovery とは関係が無い。core tool ブロックは
  **4,596字**、それが立っている catalogue は **50,000字超**。この主張は元から健全で、そのまま残る。
- **discovery が負うのは関連性であって件数ではない。** 件数に上界は無く、**持たせてもいけない**
  ——それは要求に従って動く。実測: 「isochrone reachable area」は 125 のうち **10件**を返し
  `routing.isochrone` が**スコア161**で1位（残り9件は同点16）、「ありがとう」は **0件**。
  **固定ページなら、この2つの数は同時に出せない。**

そのうえで **#R413 が直した defect そのもの**を browser 側に固定した——
「現在地から大阪駅までの経路」で `routing.route` が結果に含まれること。deep tier には
この回帰ガードが無かった。234行は `documentation` の新しい位置（最上位・非空）を読み、
**各 match が自分の写しを持っていないこと**も同時に主張する。

### 見逃した門を、defect と同じ幅に広げた（⑫）

`tests/r413-checks` は既に2方向からこの上限を見張っていた——⑨ が `js/atlas-toolsurface.js` に
`MAX_FIND` の綴りが無いことを、⑦ が**実レジストリで実際に `find()` を走らせて**
「スコアしたものは全部返る」ことを。**両方とも12日間ずっと緑だった。**
⚠ **退役した上限は、製品ではなく、それをまだ検査しているもののほうに生き残る。**
しかもこの1本は最悪の番地に生き残った——deep tier は `schedule` と `workflow_dispatch` でしか
走らないので、毎晩赤くなりながら **PR は1本も落ちなかった**。

⑫ は `tests/` の **322本**を歩き、`matches` の件数を**数値リテラル**で縛る assert を禁じる。
⚠ **禁じるのは数字であって比較ではない**——`expect(r.matches).toBeLessThan(r.registry)` は
「これは検索であってレジストリではない」という正しい主張なので**合法のまま**通す。
⚠ **針は断片から組んである**（`'toBeLess' + 'Than'`）。まとめて書くと `code()` が文字列リテラルを
伏せたあとも**この検査自身のコードに当たる**——ヘッダが13回と数えている self-hit の14回目になる。

### 実測した赤

- 製品に `MAX_FIND = 8` を戻す → «R406 ②» が赤。落ちた8件は
  `navigation.camera, navigation.start, navigation.status, navigation.stop, navigation.voice,
  routing.drone, routing.isochrone, routing.optimizeStops` で、**#R413 の記録と同じ並び**。
- `documentation` を各 match に戻して最上位から外す → 同じテストが赤。
- テスト木に上限を書き戻す4通り（R413 が消した行そのもの／メッセージ付き／2行にまたがる形／
  `assert.ok(... <= 8)`）→ ⑫ が4通りとも赤。`toBeLessThan(r.registry)` は緑。
