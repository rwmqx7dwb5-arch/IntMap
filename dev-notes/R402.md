### 3. ⚠⚠⚠ それでも残っていた半分——**#R372 の最初の版は、本番が最初の検出器だった**

#R372 追記2/3 自身がこう書いている——「`setMode()` は `renderUI()` しか呼ばず、タブは
**起動時の取得が `globalData` を埋めていたことに寄生していた**」。起動時の取得を止めた最初の版で
**News タブは永久に「Loading articles...」のまま**になり、見つかったのは**本番**である
（実測: クリック後に `news_events` / `news_sources` / relay へのリクエスト **0 件**、
`IntMapNewsEvents` は `undefined`）。

`tests/r372-checks.test.mjs` ⑬⑮ が**ソースの形**として両方を押さえている。押さえられないのは
**「1 クリックで本当に降りてきて、一覧が出来事になり、カードが描かれる」**——それはブラウザにしか
訊けない。⇒ この round が残すのは `tests/r402.spec.js` **1 本だけ**である。

- **①** 何も訊かれていないページで: 旗は立っている・ローダーは `newsEvents` を知っている・
  News は既定タブではない——そのうえで `IntMapLazy.pending()` に `newsEvents` は無く、
  `window.IntMapNewsEvents` は `undefined`、面は `articles`。
- **②** 同じページでタブを **1 回押すだけ**（`need()` も `fetchData()` も検査からは呼ばない）:
  `pending()` に `newsEvents` が入り、モジュールが公開され、面が `events` になり、
  `.news-item` が**描かれ**、「読み込み中」の空メッセージが**残っていない**。

⚠⚠ **半分だけでは足りない。** `r209 ①` は「ジェスチャ無しに何が降りてきたか」を数えるので、
`newsEvents` を**永久に壊しても緑**になる——「取りに行かない」と「機能が無い」を見分けられない
（#R162/#R200/#R205/#R208 の形）。②が在って初めて①が主張になる。

### 5. ⚠ 引き継ぎ文の前提を 1 つ訂正した — (b) は書いてあるより安い（が、選ばれなかった）

#R400 は (b) を「`check:perf` の eager 予算に 18 kB を通す」と見積もっていた。**通らない。**
`scripts/perf-budget.mjs` の `eager` は `scripts/build-report.mjs` が測る **Rollup のエントリ静的
クロージャ**で、`newsEvents` は動的 import だから `async_` 側に入る。動的 import のまま起動時に
取得しても、**予算の数字は 1 バイトも動かない**——つまり **`check:perf` はこの欠陥を原理的に
捕まえられない**。捕まえられるのは `r209 ①` の `IntMapLazy.pending()` と、この round の
`tests/r402.spec.js` だけである。
