## R505 — **出荷した Edge Function が、本番で一度も動かなかった**

#R504 を deploy した直後の本番:

```
GET /functions/v1/aviation-feed?meta=1
HTTP/1.1 500 Internal Server Error
{"code":"WORKER_ERROR","message":"Function exited due to an error (please check logs)"}
```

### 1. ⚠⚠⚠ 45 行の距離が、全リクエストを 500 にした

```js
const WORLD_SLICE_TILES = 3;
const SWEEP_TILES_MAX = READ_BURST;   // ← 110 行目
…
const READ_BURST = 6;                 // ← 155 行目
```

**temporal dead zone。** `const` は巻き上げられるが初期化されないので、
module を評価した瞬間に `Cannot access 'READ_BURST' before initialization` が投げられ、
ファイル末尾の `Deno.serve` には**一度も到達しない**。だから 500 なのは1つの channel ではなく
**関数そのもの**である。

### 2. ⚠⚠⚠ 何一つ捕まえなかった

| 門 | 結果 | なぜ見えなかったか |
|---|---|---|
| `npm run check:static` | 緑 | **構文**を読む。この順序は構文的に正しい |
| `npm test`（checks 3,136 本） | 全部緑 | どれもこの関数を**実行しない** |
| CI | pass 7 / skip 3 | 同上 |
| #R504 自身の 13 本 | 全部緑 | 定数を**文字列として**読み、「`READ_BURST` を参照しているか」は確かめたが「**その時点で存在するか**」は一度も訊いていない |

⚠ **これは「テストが足りなかった」ではない。「テストの種類が1つも無かった」である。**
この repo の Edge Function 検査は**全部ソースを読む**検査で、**module 本体を評価する**検査がゼロだった。
だから穴は `aviation-feed` のものではなく、**13 本すべて**に空いていた。

### 3. ⚠⚠ 「本物を走らせる」以外の方法では、この穴は塞がらなかった

最初に書いた門は「`import` 行を落として本体を `vm` に流す」形だった。結果:

- **5 本**は複数行 import を切り損ね → `Cannot use import statement outside a module`
- **3 本**は **TypeScript の型注釈**で `Unexpected token ':'`（`vm` は JS しか読まない）
- **1 本**は import された名前をトップレベルで使用 → `personaPrompt is not defined`

**どれも「この検査の粗さ」であって「その関数の欠陥」ではない。** それでも赤は同じ顔をするので、
この門は「無視することを教える門」になる（#R346 の「成功を意味する赤」の裏返し）。

⇒ **Node 24 は `.ts` を素で `import()` できる。** 関数ごとに子プロセスを1つ起こし、
`globalThis.Deno = { env:{get:()=>""}, serve:()=>{} }` だけ置いて **実際の module graph を評価する**。
`_shared/` も本物が読まれ、型注釈も剥がれ、import の書き方も関係なくなる。
⚠ **それ以外は何も stub しない**——足りない platform global は、まさにこの門が探している欠陥である。
⚠ **子プロセスなのは意図的**: これらの module は `globalThis` に物を置き、末尾で `Deno.serve` を呼ぶ。
13 本を同じプロセスで評価すると、ある関数のトップレベルが別の関数の結果を決めてしまう。

⚠ **関数の一覧は列挙せず、ディレクトリから見つける。** 14 本目がこの門に気づかれずに増えることを
防ぐため（#R465 の形）。

### 4. 復旧と、#R504 が直した当のものの本番実測

redeploy 後、`?ch=world&refresh=1&tiles=6` を 20 秒間隔で4回:

| slice | `x-intmap-count` | `x-intmap-coverage` | `x-intmap-save` |
|---|---|---|---|
| 1 | 2,813 | **lattice 3/980** | ok |
| 2 | 2,831 | **6/980** | ok |
| 3 | 2,846 | **9/980** | ok |
| 4 | 2,846 | **12/980** | ok |

そして**別の isolate**（`?meta=1`）が `sweepLedger: loaded` / `cursor: 24` を報告した。
**被覆率がヘッダ導入以来はじめて 0 から動き、掃引の進捗が isolate を越えた**——#R504 が直した
当のものが、実際に効いている。
