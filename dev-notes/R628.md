## R628 — **毎ラウンド従えと書いてある指示が、宛先の無い番地を持っていた**

〈利用者「今回は文書、指示、憲法系統の点検や検査、整理をしてください」〉

文書どうしの食い違いを見る仕組みは、このリポジトリでは厚い——`scripts/doc-facts.mjs` に 30 余の規則があり、
Edge Function の本数も、言語の数も、起動の重さも、能力表の大きさも、**書き写された数はほぼ全部**照合されている。
このラウンドが見つけたのは、その網の**目の形**のほうだった。

### 1. ⚠⚠⚠ 「§11.8 のバックアップ状態を必ず記載する」——§11 は 11.4 で終わる

`AGENTS.md` §10 は、最終報告の末尾に §11.8 の書式を書けと要求している。**§11.8 は無い。**
同じ節の §11.5 も無い（実体は §11.3）。`docs/FILES.md` は 2 か所で `CLAUDE.md` §6 を指していたが、
**#R503 が恒久指示を `AGENTS.md` へ移して以降、その文書は §A-5 までしか持たない。**

死んだ節番号は誤記ではない。**「その規則はどこかに書いてある」という約束**として読まれ、
読みに行った者は、それに触れてもいない文書に着く。しかもこれは**毎ラウンド従う指示の側**にあった。

⇒ 規則 **`section-refs`**。文書の名前を挙げたうえでの `§N` を、その文書の見出しへ解決する。

- **見ないもの**: 裸の `§N`（自文書参照・文脈依存）と、リポジトリ外の「指示書 §N」。**解決できるものだけを見る。**
- `Architecture.md` / `docs/FILES.md` / `docs/MAP-LAYERS.md` は **節番号の名前空間を共有する**（`CONSTITUTION.md` §6 の宣言）ので 1 プール。
- 「§3 の 5 番」という**項目参照**は、§3 の番号付き箇条書きに 5 番目があるときだけ通す。
  ⚠ **ここが静かにずれる向きである**——§3 に 1 項挿入すると、それより下を指す参照が全部ずれるのに、見出しではないので誰も気づかない。

実測 **167 件**を解決する。この規則が捕まえたのは 4 件——`docs/FILES.md` の `CLAUDE.md` §6 が 2 件、
`docs/AVIATION-DATA-SOURCES.md` の `AGENTS.md` §5.2、`docs/SHIPS-ARCHITECTURE.md` の `AVIATION-ARCHITECTURE.md` §22.2。

⚠ **§11.8 と §11.5、そして `docs/PHOTO-GEOLOCATION.md` の §9.1 は、この規則では捕まらない。**
どれも文書名を伴わない**自文書参照**だからである。見つけたのは全数調査のほうで、規則が守るのは
「名前を挙げたうえでの番地」だけ。**この残余は縮められるが、縮めるには「裸の §N は自文書を指す」と
決めてしまう必要があり、それが正しくない文書が現にある**（`docs/BACKUP-RESTORE.md` の見出しの中の §10、
`docs/MONITORING.md` の §8.4／§8.5 は、どれも読者から見て自文書の番号に見えるリポジトリ外の参照）。

⚠ **書いている途中で 2 回、規則のほうが間違えた。** `§X.Y` の親節の本文を取る正規表現に `m` を付けていたので
`$` が**行末**で止まり、項目参照が全部「空の節への番地」に見えた。そして
「[`docs/README.md`](docs/README.md) と `CONSTITUTION.md` §6」で、**24 文字の隙間が別の文書名をまたいで**
README.md への番地を捏造した。⇒ 隙間はバッククォートと `]` を含めない。

### 2. ⚠⚠⚠ 18 本のゲートのうち 1 本は、誰も呼んでいなかった

`check:bordercoast` は `package.json` にあり、`.agents/rules/execution-strategy.md` §4 の表にもあり、
`.agents/roles/intmap-verifier.md` の表にもあった。**`ci.yml` にも `scripts/test-parallel.mjs` にも無かった。**
`npm test` が届いていたのは `tests/r531-checks` の **8 分の 1 標本**だけで、
`scripts/build-border-coast.mjs` は自分のソースに「as `npm run check:bordercoast` does in CI」と書いていた。

**`docs/TESTING.md` はこの隙間を、#R381 が 15 ラウンド見逃した形として自分で名指ししていた。**
`gate-lists` は 2 つの指示表を突き合わせ、`ci-gates` は `npm test` が走らせるものを `ci.yml` と突き合わせる——
**どちらも「宣言されただけのゲート」を母集合に持たない。**

⇒ 規則 **`gate-callers`**。母集合は **`package.json` の `check:*` そのもの**。
**ゲートは、自分が宣言されている一覧からは隠れられない。** 手で書いた表からは隠れられる。
`ci.yml` には完全再導出のステップを足した（33,600 リング・**実測 32 秒**・オフライン）。

⚠ **最初の版は緑だった。** `ci.yml` のコメントを落とさずに呼び出し元を探したので、
私がそのステップに添えた「as `npm run check:bordercoast` does in CI」という**引用**が呼び出しに見え、
**ステップを消しても通った**。不在を説明している文が、存在の証拠になっていた。

### 3. ⚠⚠⚠ 見られていなかった文書がある——除外されていたのではなく

`fonts/README.md` は現状文書である。恒久指示の引用（「IntMap内のすべての文字は以下にしろ。（恒久的に）」）を持ち、
書体ごとの対応表と、各ファイルの正体と、再生成手順と、そして **OFL が要求する著作権表示・ライセンス表示そのもの**を持つ
——末尾が「The OFL requires the copyright notice and licence to travel with the fonts; **that is what this file is**」と明言している。

それが `docs/README.md` の索引にも、`check:docs` の走査母集合にも入っていなかった。
**除外リストに載っていたのではない。** `PROSE_DOCS` が

```js
readdirSync(ROOT).filter(md)  +  readdirSync(ROOT/docs).filter(md)
```

という**手で書いた 2 つのディレクトリ**で、1 つ隣を見ていなかっただけ。
**手で書いた母集合は、リポジトリが育っても育たない**——自分が書かれた時点の木について、静かに答え続ける。

⇒ 母集合を **git の追跡一覧から発見**し、除外は**書かれた理由つき**にした
（履歴 `DEV-NOTES*` / `.agents/`（instruction 側で走査）/ `.claude/` `.codex/`（生成物）/ `CLAUDE.local.md`）。
`.agents/rules/no-ad-hoc-hardcoding.md` §2 の 4 が言っているとおり、**一覧が要るなら一覧を発見する。**
同じ穴に `.github/pull_request_template.md` も居た。

**「除外されていない」ことと「見られている」ことは別である。**

⚠ **そして最初の版は、直したはずの穴を別の形で開け直した。** git に**追跡されているもの**だけを訊いたので、
**このラウンドで書いている最中の `.md` がゲートに見えなくなった**——`tests/r274-checks` ③ は、
負の証拠として `docs/` に文書を 1 本**書き下ろして**ゲートが赤くなることを確かめる検査で、
その文書が置かれている状態でゲートは 44 文書すべてを ✓ と印字して exit 0 した。
**「まだコミットしていない文書」は、そのラウンドがいちばん間違えやすい文書である。**
⇒ 両方訊く（追跡されているものと、`--others --exclude-standard`＝git が見えていてまだ追跡していないもの）。
⚠ **検査を書き換えて逃がさなかった**——逃がしていれば、負の証拠そのものが証拠でなくなる。

### 4. ⚠⚠ 9 言語の名簿が、実装が鍵にしない綴りで書かれていた

`AGENTS.md` §3 の 5・`PRODUCT.md`・`.agents/roles/intmap-i18n.md` は
`en / ja / de / ru / es / zh-Hant / zh-Hans / fr / ko` と書いていた。実装は `jp` と `zh` で、
`ja` / `zh-Hant` は `js/lang-registry.js` が**別名として受理するだけ**である。

**#R588 が実測した欠陥がこの形だった**——選挙パックが `ja`/`zh-Hant` と書き、`nm()` が生比較していたので
**113 の選挙の日本語・中国語の注記が誰にも届かず**、fallback が実在する文字列なので全計器が緑だった。
既存の `languages` 規則は**個数と `ui.*.js` の集合しか**比べていない。
**綴りを写した指示を読んだ次のラウンドが、同じ欠陥をもう一度書く。**

⇒ 9 語ぜんぶが揃った名簿に限り、`IntMapLangCodes` の綴りであることを要求する。
（別名を**説明するために**別名を書く文書——`docs/ELECTIONS.md`——は、9 語の名簿ではないので当たらない。）

### 10. 検査

`tests/r628-checks.test.mjs`（6 件）。①② が `section-refs` の 2 つの形、③ が `gate-callers`、
④ が広がった母集合（`fonts/README.md` の索引行を外すと落ちる）、⑤ が `languages` の別名綴り、
⑥ が `--rule=` の綴り間違いが黙って緑にならないこと。
変異は**木のロックを握ったまま `--rule=` で回し、取得は 1 回に畳む**（#R407 と同じ理由——
握る時間を短く、取る回数を少なく、待つ時間を長く）。

⚠ ⑥ は**木の状態を訊いてはいけない場所で訊いていた**。ロックを取らない検査なので、
`tests/r274-checks` ③ が**未追跡の負の証拠を `docs/` に置いている 334 秒**のあいだ、
**正しく赤い `doc-index` を自分の失敗として読んだ**——#R628 が母集合に未追跡分を足したことで、
この 2 本は初めて衝突した。⇒ 木についての主張は錠の中（⑤b）へ、綴りの主張だけを外に残す。
**閾値もプローブも動かしていない。**

⚠ ④ は書いている途中で一度、**何も証明していなかった**。索引は同じパスを**リンクの表示名と href の 2 回**書くので、
1 つ目だけを変異させても 2 つ目が部分文字列の照合を満たしていた。
