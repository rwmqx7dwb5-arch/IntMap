### ① admin.html — 「ローカル優先、CDN fallback」は、ローカルが存在しないので fallback ではなかった

```html
<script src="supabase.js"></script>
<script>window.supabase||document.write('<scr'+'ipt src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2">…')</script>
```

`supabase.js` は **`git ls-files` に一度も無い**。実測、本番の `admin.html` はこの2行をそのまま配信して
いる。つまり運用コンソールの認証スタックは、**版を固定していない第三者 CDN のメジャータグ**を
`document.write` でパーサへ流し込んだものだった——integrity も無く、そのURLが返した何かをそのまま実行する。

同じページの取込ボタンはこうだった：

```js
const geoRaw = eval('(' + sliceBalanced(txt, …, '{', '}') + ')');
```

`txt` は `intmap.html` の fetch に失敗したときの**ファイルピッカー**から来る——そして `intmap.html` は
もう何ラウンドもこのリポジトリに無いので、**毎回**ピッカーの経路だ。`eval` はそのテキストを読むのではなく
**走らせる**。オブジェクトリテラルは、値の1つが `[].constructor.constructor('…')()` になった瞬間に
オブジェクトリテラルではなくなる。前に置いてある再認証プロンプトは「キーボードの前にいるのが管理者か」を
証明するもので、**ファイルの中身については何も言っていない**。

→ SDK は package.json が固定する版（2.58.0）の UMD を `dist/vendor/supabase-js.js` へ同梱。取込は
`js/admin-literal.js` の**パーサ**が読む：オブジェクト・配列・文字列・数値・`true/false/null/undefined`・
コメント・末尾カンマ **だけ**を受け、識別子・呼び出し・演算子・テンプレート置換・getter は `SyntaxError`。
⚠ **JSON.parse では駄目**——入力は JS ソースで、`{ name:{en:'…'} }` のように素の識別子キーと単引用符を
持つ。JSON より広く、JS より狭く、「データ」で止まる。`__proto__` はキーとして拒否する（オブジェクト
リテラルの `__proto__:` は**キーの追加ではなくプロトタイプの差し替え**）。
その結果 admin の CSP から `'unsafe-eval'` と `https://cdn.jsdelivr.net` が消えた。**eval の無いページに
eval を許す CSP は、誰も見ていない許可**。

### ③ Service Worker — パス規則がホストを一度も見ていなかった

```js
return TILE_PATHS.some((p) => u.pathname.indexOf(p) !== -1);   // ← ホスト判定なし
```

`https://anything.example/terrarium/x.png` は「タイル」だった：初回で保存され、60日 cache-first で返り、
`store()` が Response を作り直すので**同一オリジンの本文としてページに戻る**。コメントは「他に
`/terrarium/` を含む URL を要求するものは無いので過剰一致しない」と書いていたが、それは IntMap 自身の
コードについての言明であって、**リクエストが何になりうるか**についての言明ではない。
同じ形がホスト判定にもあった：`h.endsWith(t)` にはドットが無く、`api.mapbox.com` は
`notapi.mapbox.com` にも一致する。

`postMessage` の口はもっと直接的だった。送信元を訊かず、URL を allowlist に通さず、既定の
`credentials` で fetch していた——**ワンショットの postMessage で届く、Cookie 付きの汎用 fetch＋
キャッシュ汚染プリミティブ**。→ 送信元は**このオリジンの window client** であること、URL は
`isTileRequest()` を通ること、長さ・件数の上限、`credentials:'omit'`、応答1件のバイト上限と
`storage.estimate()` による容量上限。⚠ **allowlist 外は page に差し戻す**（`prefetch-declined`）ので、
読者が Settings に打ち込むカスタム XYZ プロバイダの温めは失われない——「同じ allowlist を適用しろ」を
機能の縮小にしないための1往復。

### ④ delete-account — 「その後」が順序でしかなかった

```js
for (const table of OWNED_BY_USER_ID) { const {error} = await db.from(table).delete().eq("user_id", uid);
  if (error) failed.push(table); }              // ← これ以降 failed は誰も読まない
const {error: delErr} = await db.auth.admin.deleteUser(uid);   // ← どちらでも走る
```

16 の DELETE は 16 のトランザクションで、失敗しても Auth ユーザーは消える。**auth.users が消えた後、
本人はもう入り直して頼めない**——残った行は、もう誰にも帰属させられず、もう誰にも消せない。
⚠ **FK のカスケードは代わりにならない**：監査したところ `donations` / `feedback` / `bug_reports` は
`ON DELETE SET NULL` で、Auth ユーザーを消すと**本人が書いた文章が NULL の持ち主のまま残る**。

→ `public.delete_account_data(uuid)`（SECURITY DEFINER・`search_path=''`・service_role のみ）。
所有テーブルは `pg_constraint` から**発見**する（＋`user_id uuid` で FK が欠けている列も。⚠ これは
保険ではなく**実測**——本番の `bug_reports.user_id` には FK が無い。baseline は宣言しているのに）。
1トランザクションで消し、**数え直し**、残っていれば raise＝全部ロールバック。Edge Function は
`ok` が返ったときだけ Auth ユーザーを消す。migration が欠けた FK を貼り直し、`area_monitors` 系から
`authenticated` の **TRUNCATE**（RLS の対象外）を revoke する。

### ⑤ ai-proxy — 「サーバーログ用」と書いてあったものが応答に載っていた
