## R384 — **カードは「見出し」だけ9言語だった／格子が入り江を「池」にして 41,489 km を陸の上に引いていた**

依頼はこうだった。「海底ケーブルレイヤーの正確化を引き続き進めて。また、クリックしたら出てくる
カードの情報が翻訳されていない。凡例に、正確な位置を示しているわけではないという趣旨の文言を
書いておいて。」

### 1. カードは9言語で、答えは英語だった

#R355 はポップアップの **20 本の文字列**を `window.IntMapLang.t(HOST.lang, …)` で綴り、
`scripts/i18n-helpers.mjs` が見えるようにわざわざ `L` の包みを外した。ゲートは 100% を出す。
日本語で開いた実測は、こうだった。

```
接続国・地域   Cyprus · Syria
陸揚げ地点     Pentaskhinos, Cyprus · Tartous, Syria
運用開始       2000 August
国・地域       Indonesia            ← 1,922 の陸揚げ地点すべて
```

⚠⚠⚠ **呼び出し箇所の監査は、値が英語のデータである行を見ることができない。**
TeleGeography が持っているのは**英語の国名**と**散文の日付**で、どちらも読む場所では翻訳できない。

⇒ **翻訳するのではなく、結合鍵を作る。** `scripts/build-subcables.mjs` が

| 出るもの | いままで | いま |
|---|---|---|
| 国 | `countries: ["Cyprus","Syria"]` | ＋ `countryCodes: ["CY","SY"]`（索引が揃っている） |
| 陸揚げ地点 | `country: "Indonesia"` | ＋ `cc: "ID"` |
| 運用開始 | `rfs: "2000 August"` | ＋ `rfsMonth` / `rfsQuarter`（`rfsYear` は既にあった） |
| 総延長 | `length: "1,041 km"` | ＋ `lengthKm: 1041` |

を出し、ブラウザ側は `window._imCldrRegion`（`js/countries-ui.js`・#R240）と
`Intl.DateTimeFormat` / `Intl.NumberFormat` に訊く。

⚠ **186 × 9 の国名表は書かない。** #R240 が Countries タブについて確立した規則で、
CLDR は ISO の全地域の訳語をすでに持っている。ここで作るのは**鍵だけ**である。

⚠ **陸揚げ地点の名前は末尾が英語の国名**（「Sangata, Indonesia」）。地名そのものは固有名詞なので
残し、**記録が持っている国名と完全に一致する末尾だけ**を差し替える（推測しない）。

### 2. 逆引きを壊していたのは、廃止された alpha-2 だった

`scripts/subcables/regions.mjs` は Node 自身の ICU に 676 通りの2文字を訊き、名前を返したものを
逆引きの索引にする。最初の版は 186 綴り中 **28 が未解決**で、その内訳が意外だった——
「United Kingdom」「France」「Germany」「Russia」「Vietnam」「Yemen」「Vanuatu」「Timor-Leste」
「Benin」「Curaçao」が **AMBIG** だったのである。

⚠⚠⚠ **ICU は廃止された地域コードも解決する。** UK/GB・DD/DE・SU/RU・VD/VN・YD/YE・NH/VU・
TP/TL・DY/BJ・AN/CW は**同じ英語名**を返すので、索引は「2つのコードが同じ名前を主張している」と
読んで両方を捨てていた。`Intl.Locale('und-XX').maximize().region` が正規形を言うので、
**表を書かずに**別名だけ落とせる（実測 **263 コード**）。

残る 8 件は CLDR が違う綴りを使うもの——「Congo, Dem. Rep.」対「Congo - Kinshasa」、
「Turkey」対「Türkiye」、「Virgin Islands (U.S.)」対「U.S. Virgin Islands」など——で、
`data/subcable-overrides.json` の `countryCodes` にある。⚠ **解決できなかった綴りは英語のまま**で、
`data/subcables.build.json` の `regions` がそれを列挙する（実測 **186/186 解決・未解決 0**）。

### 3. 格子は入り江・フィヨルド・河口を「池」にする

#R355 の `estimated` **47,181 km** の正体を測った。46 本のケーブルの脚が「経路なし」で
測地線に落ちており、その理由は一つだった。

⚠⚠⚠ **9.26 km のセルでは、水域が外洋とセル同士で繋がらないことがある。**
格子を塗り分けると、**水域は 2,331 個**——1つが世界の海（6,260,491 セル）で、残りは池である。

| 陸揚げ地点 | 落ちる水域 | 影響したケーブル |
|---|---|---|
| Halifax, NS | c1348 | exa-north-and-south・exa-express |
| Stockholm | c849 | eastern-light ×2・sweden-latvia・baltic-sea-submarine-cable |
| Hillsboro, OR | c1332 | northstar・hawaiki |
| Valdez / Whittier, AK | c770 / c795 | alaska-united-east・northstar |
| Milton, NL | c1272 | greenland-connect |
| Port Alberni, BC | c1241 | topaz |
| Thanlyin, Myanmar | c1731 | umo |
| Jacksonville, FL | c1588 | amx-1 |
| Tortel, Chile ほか | c2125 ほか | fibra-optica-austral・connected-coast（105 点中 14 点） |

`snapToSea` は正しく「いちばん近い水」を見つける。それが**出られない数セル**なのである。

⇒ ルータが**連結成分**を持ち、`route()` は両端の最近傍セルが違う水域にあるとき
**両方が届く水域の中でいちばん安い組**を選ぶ（`sharedSnap`）。

⚠ **#R355 が置いた 60 km の上限は 1 m も動かしていない。** 変えたのは「どの水を選んでよいか」で
あって「どこまで動かしてよいか」ではない。共有する水域が上限内に無ければ、脚は今も**拒否される**
——アマゾン川のケーブルを大西洋へ引きずり出さないための規則はそのまま効いている。

### 4. ケーブルが川に敷かれていることがある

ブラジルの **Norte Conectado**（Infovia 00–08）と **Projeto Amazônia Conectada** は、
アマゾン川・ソリモンエス川・リオネグロ川・ブランコ川・マデイラ川・ジュルア川に敷かれた
海底ケーブルシステムである。標高格子に川は無いので、#R355 はその **10 本・10,093 km を
熱帯雨林の上の測地線**として出荷しており、QA の「陸地横断」上位 10 件はこの 10 本だった
（1地物あたり 411・321・273・256・250… の標本が陸の上）。

⇒ `data/subcable-overrides.json` の **`rivers`**。運河と同じ機構で掘るが、**経路は書かない**——
湖と同じ Natural Earth 1:10m（パブリックドメイン）の川の中心線を、**名前と bbox で**選ぶ。

⚠ **名前だけでは川を特定できない。** `Negro` はこのデータセットに**4本**あり、そのうち3本は
アルゼンチンとウルグアイのリオ・ネグロである。各項目は `why` と bbox を必須にし、
build が「何地物に当たったか」「何セル開けたか」を報告する（**当たらなければ例外**）。

実測、中心線は Tabatinga 3 km・Tefé 7 km・Manaus 5 km・São Gabriel 2 km・Moura 4 km・
Boa Vista 4 km・Porto Velho 2 km・Humaitá 2 km・Borba 2 km・Cruzeiro do Sul 1 km を通る。
開けたセル: Amazonas +615・Negro +368・Branco +238・Madeira +280・Juruá +335。

⚠ **プルス川は Natural Earth 1:10m に無い**ので、Infovia-06（マナカプル→リオブランコ）は
**今も `estimated`** である。無いものは無いと言う。

### 5. 実測（#R355 → #R384）

| | #R355 | #R384 |
|---|---|---|
| `estimated`（測地線） | **47,181 km**（2.28%） | **5,692 km（0.28%）** |
| `estimated` の地物 | 98 | **13** |
| `reconstructed` | 1,943,815 km | 1,983,142 km |
| `verified` | 78,690 km | 78,690 km（変わらず） |
| ルータの失敗 | 375 | **68** |
| 陸に落ちた標本 | 4,085 | **1,262** |
| 陸を横切る地物 | 259 | 244 |
| 自己交差 | 8 地物 / 18 交差 | **1 / 3** |
| 迂回率 p99 | 1.902 | 1.882 |
| 公表長との比 p50 | 0.989 | 0.988 |
| 頂点 | 62,005 | 61,055 |
| `subcables.json`（gzip） | 462,597 B | **451,930 B**（減った） |

⚠ **幾何が変わったのは 38 本で、そのうち「測地線を 1 km も持っていなかった」ものは 0 本**である。
つまり **664 本の既に routed だったケーブルは 1 バイトも動いていない**——この変更は
「失敗していた脚」だけに触れている。

⚠ **公表長との比はほとんど動いていない**（p50 0.989 → 0.988、外れ値 60 → 60、合計 ×1.0100 →
×1.0086）。それでよい——測地線は「いちばん短い経路」なので、陸の上を突っ切っていた線を海の上の
経路に置き換えると**長くなる**。この変更の主張は「線が水の上に載った」であって「長さが公表値に
近づいた」ではなく、**それを測る数字は陸に落ちた標本のほう**である（4,085 → 1,262）。

### 6. 凡例の但し書きは、DOM に在って1画素も描かれていなかった

「正確な位置を示しているわけではない」を `LEGEND_NOTE` として9言語で足し、
`.dl-desc` の**中**に描いた（`ensureGenericLegend()` は言語切替のたびに `.dl-desc` を消して
作り直すので、**兄弟に置くと切替のたびに増える**）。ブラウザ検査も書いた。緑だった。

⚠⚠⚠ **そして本番のスクリーンショットに、その但し書きは無かった。**
最初に付けたクラス `dl-note` は、**レイヤー行の日付注記が既に使っている**もので、
`.dl-note{ display:none; … }` である（日付が入ったときだけ JS が見せる）。
9言語ぶんの翻訳が入った div が、高さ 0 で DOM に立っていた。

⚠⚠⚠ **私の検査も緑だった。** `textContent` は**隠れた節点を歩く**。

⇒ クラスを `dl-caveat` にし、検査は `offsetHeight` と computed `display` を訊くようにした。
そして**クラス名が他のどこでも使われていないこと**自体を検査に足した——名前空間の衝突は
「その1件を直す」のではなく「同じ形が来られないようにする」のが正しい。

⚠ ついでに、この注意書きを書いた最初の版が **CSS のテンプレートリテラルの中にバックティックを
入れて build を落とした**（`js/data-layers.js` はその危険を自分のコメントに書いてある）。

### 7. 翻訳の計器は「テキストであるか」を訊いていなかった

`js/locales/ui.fr.js` は **U+FFFD を2つ**積んでいた——#R355 追記の
「Surveyed sections」のフランス語が「Tron?ons relev?s」として出荷されていた。
すべての翻訳計器が緑なのは、どれも「entry が在るか」「英語と違うか」しか訊かないからで、
**両方の答えが「はい」**だったのである。

⇒ 直し、`js/locales/` 全体を走査する検査を足した。⚠ **否定の主張なので、赤にできることを実測した**
（planted な U+FFFD を検出する隣の検査を同じファイルに置いてある）。

### 8. 調べて、拒否が正しいと分かったもの

実測すると、**採用されなかった実測経路が 80,249 km**（343 片・217 の名前）あった。
現行の `verified` 78,690 km より多い。1本ずつ読んだ結果、**その大半は正しい拒否**だった:
SeaMeWe-3・Japan-U.S. Cable Network・TAT-5/6/8/11/12・TPC-5・SeaMeWe-2 の各セグメントは
**TeleGeography の目録に存在しない**——退役したケーブルだからである。NOAA と EMODnet は
退役した回廊も収録する。近くの現役ケーブルに結び付けるのは §6 が禁じている誤りそのもので、
**「実測データが余っている」ように見えることと「使える実測データがある」ことは別**である。
