## R772 — 地名ラベルの下に、その土地が使っている名前を置いた

〈利用者の依頼:「Place-name labels ってありますよね。それを、設定言語の下に現地語で地名を併記する
地名ラベルも選べる設定を追加して。」／追補:「Google Earth の実サイトを英語版で見てください。
それを参考に。」〉

### 1. 参考にしたものを、実際に見た

推測で「たぶん括弧書きだろう」と決めずに、英語の Google マップ／Google Earth を開いて東京を見た。
測れたのは 2 点だけで、実装したのもその 2 点である。

- **2 行**。«Tokyo» が上、«東京» が下。括弧でも斜線でもない。
- **一致したら 1 行**。Kawasaki は «Kawasaki / 川崎市» と 2 行だが、ラテン文字圏の地名は 1 行。

### 2. 4 つ目の言語ではなく、同じ式の下の 1 行

`js/place-labels.js` の `applyLabelLang()` は既に `ui` / `local` / `en` の 3 つを組み立てている。
`ui+local` はその 4 つ目の枝**ではない**——`ui` が作った式 `_ui` をそのまま受け取り、

```js
['case', ['any', ['==', _loc, ''], ['==', ['to-string', _ui], _loc]], _ui,
         ['concat', _ui, '\n', _loc]]
```

で包むだけ。だから**読者の文字を決めている規則は 1 つも書き直していない**——鍵の並び
（`OSM_NAME_KEYS`）も、#R691 が記録した `name:ja` の拒否も、#R427 の歴史都市名の上書きも、
`_ui` の中でこれまでどおり効く。言語ごとの分岐を 1 つも足していないので、**次に足される言語は
何もしなくてもこのモードに入る**（[[intmap-hist-names-rule-belongs-to-the-name]] と同じ線で、
規則は経路ではなく式そのものに付いている）。

`case` の第 1 腕が「1 行で描く」条件で、2 つの事実を同時に扱う: 現地名が無い瓦（末尾の空行を
作らない）と、設定言語の名前が現地名と同じ値に解決する瓦。⚠ **後者は縁ではなく常態である**
——ヨーロッパでは、設定言語の鍵を持たない瓦は `coalesce` の最後で `name` 自身に落ちるので、
包まなければ «Paris / Paris» が延々と並ぶ。

### 3. ⚠⚠⚠ `format` を選んでいたら、片方のエンジンで全ラベルが無言で消えていた

Google の 2 行目は 1 行目より少し小さい。MapLibre でそれをやる方法は `format` の
`font-scale` **1 つだけ**である。選ばなかった理由は好みではない:

```js
// js/cesium-style.js:203
const UNSUPPORTED=new Set(['format','image','number-format', …]);
```

**Cesium エンジンは同じ layout を読む**（`js/cesium-layers.js:738` が `layout['text-field']` を
この評価器に渡す）。`format` を書いていれば、MapLibre では綺麗な 2 行、Cesium では**全ラベルが
消える**——そして両方を同時に見る検査は無いので、緑のまま出荷できた。
⇒ 検査 ⑥ は、**その一覧を `js/cesium-style.js` から読んで**、この回の式が使う演算子と突き合わせる
（書き写せばその瞬間に離れる。[[intmap-licence-must-be-a-value]] と同じ形）。

### 4. 書体は 1 行も触っていない（触らなくてよいことを確かめた）

2 行目は漢字・ハングル・キリル文字になりうるので、`text-font` が足りないのではないかを先に見た。
`placeFont()`（`js/map-typography.js`）は「読者の言語の鍵を**持つ**瓦には読者のスタック、持たない
瓦には汎 Han 面」を返す。**2 行目が付くのはちょうど「読者の鍵を持つ瓦」のほう**で、そのスタックは
末尾が `Noto Sans SC`（JP ∪ TC ∪ SC を覆う面）なので、1 行目の異体字も 2 行目の現地名も同じ
スタックで描ける。⇒ **足すものは無い**。

### 5. 8 レイヤー全部（市だけ直すと #R429 の形になる）

瓦名を描いているのは `ofm-country` / `ofm-admin1` / `ofm-city` / `ofm-other` / `ofm-poi` /
`ofm-river` / `ofm-water` / `ofm-peak` の 8 つで、どれも `nameExpr` を受け取る。式そのものを
包んだので全部が同時に 2 行になるが、**それを主張するのは検査**（⑤）であって構造ではない。
`ofm-peak` だけは `['concat','▲ ',nameExpr]` なので «▲ Tokyo / 東京» になる——▲ は 1 行目に残る。

### 6. ⚠ 検査の 1 本目を、自分で踏んだ

⑦ は「設定の各選択肢は、他と違う描画をするか（死んだ選択肢が無いか）」を測る。最初はそれを
**英語 UI だけ**で訊いた——`ui` と `en` が同じ答えになり、**正しい実装が落第した**。
2 つは英語話者にとって同じで、それでも別の設定である。
⇒ 問いを **jp と en の両方**に出す。[[intmap-ceiling-guards-are-not-policies]] がこの形を持っている
（検査の中の数には「方針」と「正規表現が当たったかの番人」の 2 種類がある）。

### 7. 測ったもの

`tests/r772-label-lang-bilingual-checks.test.mjs` **7 本**。
⚠ **どれもソースを読まない**——`@maplibre/maplibre-gl-style-spec` の `createExpression` で
**MapLibre 自身に**式を解釈させ、瓦の properties を食わせて**描かれる文字列**を測る
（`tests/r691-…` と同じ台。[[intmap-edge-function-must-be-evaluated]]）。

| # | 測っていること |
|---|---|
| ① | 英語 UI の東京が `Tokyo\n東京`、日本語 UI のパリが `パリ\nParis`。**読者の言語が 1 行目** |
| ② | 英語/フランス語 UI のパリは 1 行。読者の言語の鍵を持たない瓦も 1 行 |
| ③ | `name` の無い行は末尾に改行を残さない |
| ④ | `ui` / `local` / `en` の 3 つは 5 通りの組で従前どおり 1 行 |
| ⑤ | 8 レイヤー全部に 2 行目が届く（peak の ▲ は 1 行目） |
| ⑥ | 式の演算子が `js/cesium-style.js` の UNSUPPORTED と 1 つも交わらない |
| ⑦ | index.html の選択肢と、実際に**走らせた**挙動が 1 対 1（jp と en の両方で訊く） |

### 7b. 既定にした（追補の指示）

「このハイブリッド方式をデフォルト設定に。」⇒ `js/app-body.js` の初期値を `ui+local` に。
⚠ **既に選んである読者の設定は変わらない**——`loadSettings()` が `intmap_settings.labelLang` を
そのまま戻すので、これは**初回の訪問が何を見るか**だけの変更である。
⚠ **既定は 1 か所には書かれていない**——初期値（`js/app-body.js`）・選択肢（`index.html`）・
枝（`js/place-labels.js`）の 3 つが揃って初めて既定になる。実装されていないモードを既定に
置いても、地図は 1 行で描かれるだけで**何も落ちない** ⇒ ⑧ は 3 つとも読み、そのうえで
**その既定値で実際に描かせて** 2 行になることを測る。

### 8. 触っていないが見つけたもの

- **キュレーションされた海洋名（`geo-sea`）は 1 行のまま。** `js/place-labels.js` の海の台帳は
  5 言語の列を持つが**現地表記の列を持たない**ので、2 行目に置けるものが無い。#R242 が
  `en`/`local` を英語に落としているのと同じ理由で、**無い欄を綴りの写しで埋めない**
  （[[intmap-data-must-not-claim-an-author-it-lacks]]）。
- **時代のラベル（`imtb-lbl` / `imta-lbl`）も 1 行のまま。** 歴史記録にも現地表記の列は無い。
