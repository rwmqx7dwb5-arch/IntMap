## R518 — **1850年から1885年までは、1880年の地図が36年ぶん引き伸ばされていた**

〈「1850–1885の国境を本気で埋めて」〉

### 何が起きていたか（実測）

時計の下限は **1850 年**（`js/chronos.js` の `YMIN`）。同梱の歴史国境 `data/cshapes.js` の
最古の日付は **1886-01-01**。その間の 36 年について、710 レコードを全部歩いた結果は:

| 年 | 生きているレコード | 変化日 |
|---|---|---|
| 1850〜1885 の各年 | **0 件** | **0 件** |
| 1886 | 128 件 | — |

したがって `go()` は必ず `nearest(year)` へ落ちる。候補は
`YEARS=[1815,1880,1900,…]` で、1815 と 1880 の切替点は中点の **1847.5 年**——**下限の外**。
つまり **1850 を選んでも 1885 を選んでも、同じ `world_1880.geojson`**（236 features・169 政体・
1.3 MB・`raw.githubusercontent.com` から CORS プロキシ越し）が描かれていた。
**36 年が 1 フレーム。** 1850 年のヨーロッパに、ドイツ帝国とイタリア王国が出ていた。

⚠ 文書はこれを**正しく書いていた**（`Architecture.md`・`PRODUCT.md`・9言語の出典ページが
「1850–1885 はどの年も 1880 年の国境」と明記）。**隠れていたのではなく、直っていなかった。**

### なぜ OpenHistoricalMap なのか

上流に他のフレームが無いのは本当だった——aourednik/historical-basemaps の `geojson/` を
2026-09-07 に再取得して確認: `world_1815` の次は `world_1880`、その間は無い。CShapes は 1886 から。
Euratlas も MPIDR も再配布できない。

**OpenHistoricalMap（当時 ODbL 1.0 と表記・#R530 で CC0 1.0 に訂正）** が違うのは、その 19 世紀の `admin_level=2` 境界関係が
**`start_date` / `end_date` を日単位で持つ**ことである。それは `data/cshapes.js` が既に持っている形
そのものなので、#R421 が 1886–2019 のために書いた日単位の機構（エポック鍵・変化日索引・
二分探索）が**下へ伸びる**。新しい仕組みを作る必要が無い。

### 作ったもの

- **`scripts/build-hist-borders.mjs`**（＋ `scripts/histborders/{fetch,geom}.mjs`）——
  Overpass から 1850–1885 に重なる **506 関係**（約 400 MB）を取り、リングを縫い、
  Douglas–Peucker で簡略化し、リングをプールして `data/hist-borders.js` を書く。
- **`data/hist-borders.js`** — **494 レコード・2,825 リング・311,088 点・5.3 MB**。
  窓の中の**変化日 216 件**。各年 6月15日に生きている政体 **164〜216**。
- **`js/time-borders.js`** — `HB_MIN`/`HB_MAX`・`hbLoad`/`hbBounds`/`hbEpoch`/`hbFC`。
  `go()` は CShapes 帯の直後・スナップショット代替の**前**にこの帯を置く。
  `changeAfter`/`changeBefore`/`changeDates` は `_allBounds()` で**両方の束**を訊く。
- 出典ページに **OpenHistoricalMap** の項目を **9 言語**で追加し（⚠ ライセンスを ODbL 1.0 と書いたが誤りで、#R530 が CC0 1.0 に訂正して1行に統合した）、地図の attribution にも入れた。

1860 年のヨーロッパに、両シチリア王国・教皇領・サルデーニャ王国・イオニア諸島合衆国・
**32 のドイツ諸邦**（ハノーファー・クアヘッセン・ナッサウ・オルデンブルク・リッペ・ロイス＝ゲーラ…）が出る。
1863 年に南部連合が出る——**しかも 12 レコードの日付付きの連鎖**で、州が脱退するたびに形が変わる。

### ⚠⚠⚠ 排他の終了日を知っていて、それでも1日足した

出典を選ぶ前に測ってあった: **同一 `wikidata` の連続 180 組のうち 151 組**が
「終了日 ＝ 後継の開始日」＝ OHM の `end_date` は**排他**。CShapes の終了日は**包含**。

それを header に書いたうえで、`parseDate(s, isEnd)` は日付が完全な場合にも `dayAfter()` を
かけていた——**隣の `csBounds` が「終了日の翌日」を境界に取るから**という、書いている当人の反射。
結果、**排他の読みを選んだ当の 151 組が、1日ずつ重なる**。実測 **176 組中 107 組が重複**。

捕まえたのは**自分で書いた回帰検査**で、ソースの綴りを見る検査ではなく
**出来上がったデータの中で「同じ `wikidata` が同じ日に2回描かれないか」**を訊いたほうだった。
⚠ 綴りを見る検査（`hbFC` が `<=t` を使っているか）は**最初から緑**だった——コードは正しく、
**コードに渡る前の数**が間違っていたから。

同時に見つかった 2 種類:
- **1日しかないレコード**（`start_date === end_date`）は排他の読みでは**何も覆わない**。
  上流に 8 件あり、うち 2 件は南部連合の 1861-01-09 と 01-10 ＝ 脱退した州ごとに1枚。1日として読む。
- **入れ子の重複**（後のレコードが前のと同時かそれ以前に始まる）は詰めようがない。
  Bahawalpur State はバイト単位で同一の関係が 2 本、南部連合は名前違いの写しが 1 本。**長いほうを捨てる**。

### ⚠⚠ 片方向の縫合が、チリの本土を捨てていた

OHM の境界関係は**閉じた輪ではなく way の袋**なので、リングは端点を突き合わせて組み直す。
最初の実装は種の way から**前へだけ**伸ばしていた。輪郭に穴が1つでもあると（＝次数1の端点が
2つある開いた道）、**種を置いた場所で道が刻まれる**。実測:

| 関係 | 片方向 | 双方向 |
|---|---|---|
| チリ 1861–1866 | 閉 8 ＋ **開 18 片**（最大 4,926 点＝本土）| 閉 8 ＋ 開 1（穴 0.358°）|
| ボリビア 1839–1866 | 閉 0 ＋ 開 2 | 閉 0 ＋ 開 1（穴 0.358°）|

「閉じない」ものは捨てていたので、**チリの本土とボリビアの全体が地図から消えていた**。
双方向に伸ばすと 1 本の鎖になり、穴は図形の対角の **1.4〜2.6%** ＝橋渡しして良い大きさだと
**測って**判定できる（カナダの2週間だけの 13 点の切れ端は比が 1.00 なので捨てられる）。

### ⚠⚠ `out geom` は下位 relation を展開しない

27 の関係が relation を member に持つ。**南部連合とサラワクは way を1本も持たない**
（ジオメトリが全部下位関係の中）ので、素直に読むと**存在しない国**になる。
Qing は 12 本、オーストリア帝国は 17 本、デンマークは 1 本の島・飛地をそこに置いている。再帰的に展開する。

### ⚠ 簡略化の予算は、隣に置いてあるファイル

OHM の way は CShapes よりずっと細かく描かれている。素の組み立ては **462k 点 / 7.7 MB** ——
CShapes の 338k / 5.6 MB より重い＝**1860 年の国境が、1886–2019 の全部より重い**。
掃引すると 0.008°→462k、0.010°→388k、**0.012°→336k**、0.015°→280k。
0.012°（≈1.3 km）が隣のファイル自身の数字に並ぶので、そこにした（最終 311k 点は重複除去後）。

### ⚠ 名前はポリゴンと一緒に運ぶ

era ラベルの多言語化は、これまで**英語名を照合する表**（`_eraLocName` ほか）でやっていた。
«Germany» には効くが «Kurhessen» «Rupert's Land» «Zuid-Afrikaansche Republiek» には**永久に効かない**——
`tagSame` の else 枝は `_eraLocName` が null を返すと `_locName` を**消す**ので、この時代は
まるごと英語のままになる。

OHM は `name:en/ja/de/ru/es/zh/fr/ko` を持っている（274〜435 / 494）ので、**9 言語の名前を
ポリゴンに載せて運ぶ**（`_i18n`）。`tagSame` はそれを `_eraLocName` より**先に**読む。
簡体は `name:zh` から opencc-js で派生（#R224 の規則。⚠ `name:zh` は繁簡が混在しているので
**両方向へ正規化**する）。実測: 両シチリア王国 / Königreich beider Sizilien / 兩西西里王國 /
양시칠리아 왕국 / Королевство обеих Сицилий。

### ⚠ 国境ステッパーは、この36年では死んでいた

`changeAfter`/`changeBefore`/`changeDates`（`#ntl-bstep`）は `csBounds` だけを訊いていたので、
1850–1885 では**答えられる日が1つも無かった**。両方の束を合わせて **585 日**（うち 216 日がこの窓。CShapes 側が 369 日）。
⚠ **この数は本番検証で直した。** 出荷前に手元で測った 682 は、`parseDate` が日付に 1 日足していた
ビルド（窓内 313 日）の数字で、修正後のデータを測り直していなかった——**同じターンの中で
直したものの数字が、直す前のまま文章に残っていた**。
`range()` の下限も 1886 → 1850。

### ⚠ 押した政体ではなく、その現代の後継が答えていた

`resolveHist` は統計の出どころを得るために**必ず現代の国へ解決**し、そのあと名前と Wikipedia を
その国のもので**上書き**する。1886–2019 ではたいてい正しい。この窓では逆で、実測:

| 押したもの（1860） | 直す前の答え | 直した後 |
|---|---|---|
| Kingdom of the Two Sicilies | **Italy** / `Kingdom_of_Sardinia` | 両シチリア王国 / `Kingdom_of_the_Two_Sicilies`（統計は ITA）|
| Papal States | **Italy** / `Kingdom_of_Sardinia` | 教皇領 / `Papal_States` |
| Kingdom of Prussia | **Germany** / `German_Confederation` | プロイセン王国 / `Kingdom_of_Prussia` |

⚠ **数字の出どころ（`code`）は触らない**——変えたのは名前と記事だけ。記録の英語名が現代の国と
**同じ**なら現代側の訳語を使う（Mexico → メキシコ）。**違うときは現代の国旗も落とす**
（両シチリア王国はイタリア国旗を掲げていない）。⚠ **200 の政体が全部「イタリア」「ドイツ」と
名乗る国境は、埋めたことにならない**ので、これは今回の作業の一部として入れた。

### 検査

- `tests/r518-checks.test.mjs` **15 本** — 窓のどの年にも 100 政体以上いること／この窓にしか
  存在しない 6 政体（南部連合・両シチリア・教皇領・プロイセン・ハノーファー・ロシア領アメリカ）が
  実在すること／**同じ `wikidata` が同じ日に2回描かれないこと**（上の欠陥を捕まえた検査）／
  `hbFC` と `csFC` が別々の規約であり続けること／`tagSame` が `_i18n` を先に読むこと／
  `go()` の帯順／時計の下限と記録の下限が同じ数であること／9言語の帰属表記／**押した政体の同一性が現代の後継に上書きされないこと**。
- `npm run check:histborders`（`--check`）— **再生成はしない**（CI に約 400 MB の上流応答は置けない）。
  同梱ファイルの不変条件を測る。**残余は `docs/TESTING.md` に書いた**——上流から乖離した
  ファイルはこの門を通る。
  ⚠ **`scripts/test-parallel.mjs` と `.github/workflows/ci.yml` の両方に登録した。**
  `package.json` に `check:*` を足しただけでは**呼び出し元が無い**（`check:docs` の `gate-lists` /
  `ci-gates` は2つの一覧を突き合わせるが、一覧と実行器の隙間は見ない）——それが #R381 の見つけた、
  `data/wars.json` が15ラウンド何とでも言えた形そのもの。
- `npm run check:perf` の **`dist.total` と `dist.data` の天井だけ**を手で上げた（+5.1 MB＝この記録）。
  ⚠ **`--update` は走らせていない**（全項目を書き戻すので、無関係な増加まで一緒に承認してしまう）。
  ⚠ **起動経路の SYNC は 1 バイトも増えていない**——束は最初に過去へ旅したときに初めて読む
  （実測: 素の起動で `hist-borders.js` も `cshapes.js` も要求 0 件）。増えたのは ASYNC の +26.4 kB
  （`js/time-borders.js` のコードぶん）だけ。
- `npm run check:docs` に **`histb-count`** を追加——`data/hist-borders.js` を実測し、
  この記録を名指す行が述べる件数（レコード数・変化日数）を 14 のソースに対して照合する（#R500 の形）。
