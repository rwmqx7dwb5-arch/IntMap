## R345 — **検査は散文ではなくコードを読む——ストリッパは1本、import は2本**

依頼はこうだった。「`tests/helpers/fn-cors.js` の `CORSFOR_RE` と、同じファイルでソース本文を読む
兄弟の正規表現に、**当てる前にコメントを外す**こと（ブロックもラインも。**文字列リテラルは壊さない**）。
**3本目の写しを書かず**、既にある `codeOnly()` を再利用するか切り出すこと。**両方向で証明する**こと
——ビルダがコメントで名指しされている fixture で契約がちょうど1本読めること、そして**本当に2本呼んで
いる関数では今も赤くなる**こと。そして同じ露出が他の正規表現にもあるか調べること。」

### 1. 何が起きていたか（#R339 の実測）

`supabase/functions/aviation-feed/index.ts` には実呼び出しが**1本**しかなかった——
`corsFor("x-intmap-channel")`。そのすぐ上に、なぜ共有ビルダをその場で拡張するのかを説明する
コメントがあり、そこに `corsFor()` という綴りが**もう1回**現れていた。

`CORSFOR_RE` の**引数なしの枝**がそのコメントに当たる。`onlyMatch()` は 2 件を見て
`corsFor(...) appears 2x — ambiguous` を投げ、`tests/r333-checks.test.mjs` の**5本**が、
**契約が一度も曖昧でなかったファイル**に対して赤くなった。#R339 は**自分のコメントを書き直して**
先へ進んだ。それはそのファイルを直すが、**次に丁寧な説明を書く人を待っているだけ**である。

⚠⚠⚠ **そして静かなほうの幽霊は throw しない。** `repoCorsContract()` は `literal`（明示的な
`Access-Control-Allow-Headers` 表）を `corsFor` より**先に**試す。共有ビルダへ移行するときに
**旧い表をコメントとして残す**のはごく普通の書き方で、その瞬間から、その関数は
**「コメントの中の表」で報告される**。何も落ちない。落ちないまま、**実呼び出しが足していた
追加ヘッダが消える**。

### 2. 直し方のほうを直した

このリポジトリは**同じ問題を8回目で既に解いていた**。`scripts/atlas-capability-audit.mjs` の
先頭に、`IntMapOS.exec()` を「その呼び出しを撤去した理由を書いた文」の中に見つけてしまう事故を
避けるための `codeOnly()` が**inline で**置いてある。**直し方が1つのファイルの中にあったから、
9回目が来た。**

⇒ **`scripts/code-only.mjs`（新規）** が唯一のストリッパになり、
`scripts/atlas-capability-audit.mjs` と `tests/helpers/fn-cors.js` の**両方が import する**。
`tests/r345-checks ⑩` が、どちらかが自分の定義を持ち直したら赤くなる。

⚠ **切り出しは「同じ heuristic の引っ越し」ではない。** 旧版は正規表現2本で、

```js
.replace(/\/\*[\s\S]*?\*\//g, ' ')
.split(/\r?\n/).map((l) => l.replace(/(^|[^:\\'"`])\/\/.*$/, '$1')).join('\n')
```

**引用符か `:` の直後の `//` しか守れない。** 依頼が名指しした「文字列リテラルを壊さない」は、
この形では満たせない。新版は 1 パスの走査器で、`'…'` / `"…"` / `` `…` ``（`${ }` の入れ子込み）と
**正規表現リテラル**（`/[/*]/` のような文字クラスは**ブロックコメントの開始ではない**）を
そのまま通し、コメントだけを外す。**行の構造も残る**——3行のブロックコメントは改行を3つ置いて
いくので、その前後の行が1行に繋がることがない（旧版は空白1個に潰していた）。

**実測（576 ファイル: `js/` `scripts/` `src/` `supabase/` `tests/`）: 163 ファイルで出力が違う。**
違いは**すべて旧版が壊していた側**だった——`/^image\/\//` や `/^https?:\/\//i` のような
正規表現リテラルの途中で切られていたもの、テンプレート文字列の中の GLSL / CSS のコメント。

既存の読み手が変わらないことは**出力の同一性**で押さえた:

| 測ったもの | 結果 |
|---|---|
| `node scripts/atlas-capability-audit.mjs --json` の before / after | **131,951 バイトが byte-for-byte 同一** |
| `--check` | 20/20 緑（前も後も） |

### 3. 他の正規表現の露出（依頼の3番）

| 読み口 | 同じ露出があるか | どうしたか |
|---|---|---|
| `CORSFOR_RE`（報告された件） | ある | `onlyMatch()` の中で `codeOnly(src)` を通す |
| `ACAH_RE`（ヘッダ許可表の走査） | **ある**。しかも `literal` が先に試されるので**静かに間違う** | 同じ1か所で同時に直る |
| `FRONT_RE`（`js/` が実際に送る `x-intmap-*`） | **ある**。**コメントアウトされた代入行**——「なぜ送るのをやめたか」を残した、いちばん出てきやすい散文——を「送っている」と数える。ヘッダ一覧は関数側の許可と突き合わされるので、**誰も行わない preflight のためにゲートが赤くなる** | 読み口で `codeOnly()` を通す。doc コメントの「散文での言及は数えない」は、**代入の綴りを持たない**散文についてしか真ではなかったので、そう書き直した |
| `index.ts` と隣の `index.gemini-backup.ts` の区別 | **無い**。これは正規表現ではなく**ファイルシステムの判断**（`readdirSync` ＋ `index.ts` だけを読む）で、どんなコメントでも動かせない | `⑤` が fixture で固定した。⚠ ただし**live なファイルの中にある2つ目の幽霊**（コメントとして残った表）は同じ形の露出で、それは上の `ACAH_RE` の行で閉じている |

### 4. 両方向で証明した（`tests/r345-checks.test.mjs`・10本）

fixture は `os.tmpdir()` に `mkdtemp` で作る使い捨てのチェックアウト（`supabase/functions/` と
同じ形。`_shared/relay-guard.js` は**本物をコピーする**ので base 集合は本番と同じ）。
⚠ 固定パスは使わない——共有の scratch 名は #R329 が別セッションの索引行を書き込んだ形。

| # | 何を主張するか |
|---|---|
| ① | #R339 の形（実呼び出し1本＋コメント1回）で契約が**ちょうど1本**読め、`x-intmap-channel` も base 4本も残る |
| ② | **本当に2本呼んでいる**関数では今も `ambiguous` で拒否する／コメントだけの言及は**契約ゼロ** |
| ③ | コメントとして残った表は、下の実呼び出しを**上書きしない**（静かなほうの幽霊） |
| ④ | ACAH は**本物が2つ**なら今も拒否・死んだ表の隣の生きた表は読める |
| ⑤ | `index.ts` と隣のバックアップの区別はファイルシステムの判断（コメントで動かない） |
| ⑥ | コメントアウトされた送信行は「送っている」に数えない／**生きた代入は今も見つかる** |
| ⑦ | コメントは消え、**文字列・テンプレート・正規表現リテラルは1文字も変わらない**・行数も変わらない |
| ⑧ | **置き換えた heuristic が実際に壊すことを記録に残す**（`'not // a comment'` は途中で切られ、`"opens /*" … "closes */"` を挟む `corsFor()` 呼び出しは**丸ごと消える**＝契約が `via:'unknown'` になる） |
| ⑨ | 出荷中の8本は**ストリッパを通しても同じに読める**（`content-type` / `authorization` が残り、`ai-proxy` の `x-intmap-turn`・`sv-cov` の `range` も残る） |
| ⑩ | ストリッパは**1本**——両方が import し、どちらも自分の定義を持たない |

⚠⚠ **緑を信じず壊して赤を見た。** `codeOnly` を2か所から外すと **10本中7本が赤**（①②③④⑤⑥⑩）。
⑦⑧⑨ は緑のまま——ストリッパ自身と**今日のリポジトリ**を測っているので、当然そうなる。

⚠⚠⚠ **同じ変異で `tests/r333-checks` は 9/9 緑のままだった。** これは失敗ではなく**測定**である
——今日の `index.ts` はどれもコメントでビルダを名指ししていないので、**r333 はこの欠陥を
捕まえられない**。捕まえるには、欠陥を**持ち込む** fixture が要る。それが ①〜⑥ である。

### 5. やっていないこと

`tests/r179` `r208` `r265` `r266` `r268` `r269` `r270` などが持つ `codeOnly` の**写しは触っていない**。

見送り、そう記録している）。**次に写しが必要になったら `scripts/code-only.mjs` を import する**、
というのが `docs/TESTING.md` と `docs/FILES.md` に書いた規則である。
