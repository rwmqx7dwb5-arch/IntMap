### Phase C ① — 埋め込みは実装したが、この鍵では 1 本も動かない

```
"error": "openai embeddings 403 (text-embedding-3-small):
          Project `proj_…` does not have access to model `text-embedding-3-small`"
```

⚠⚠⚠ **`GET /v1/models` を訊いたら、このプロジェクトに返るモデルは全部で 1 件で、そこに埋め込みは
無かった。** 推測で 2 つ 3 つ試すより速く、次の運用者にも「何が使えるか」が残る。

### Phase C ③ — 運用者の修正経路と、本番にだけあった食い違い

`admin.html` に News Events タブ（Review queue / All events / Operator log）。Merge / Split /
Reassign / 代表と分類と地点の上書き / Lock / Undo。

⚠⚠⚠ **migration が 400 で落ちて分かったこと**: リポジトリの baseline は
`public.is_admin()`（引数なし）を宣言しているが、**本番に在るのは `public.is_admin(uid uuid)` だけ**
である。本番の admin ポリシーはどれも `is_admin(auth.uid())` を呼んでおり、#R334 の migration が
本番に通ったのは、`news_cluster_decisions_admin` / `news_ingest_runs_admin` のどちらも
`is_admin` を呼ばず述語をインラインで書いていたからだった。`docs/MIGRATIONS.md` が言うとおり
**baseline は本番より後に書かれた再構成で、本番には記録されていない**。

⇒ 4 つの RPC すべてが
`exists (select 1 from public.profiles p where p.id = (select auth.uid()) and p.is_admin)`
を自分で確かめる。⚠ **引数なしの版を「足して直す」ことはしなかった**——共有の security primitive を
この作業のついでに増やす変更であり、`CLAUDE.md` §3.2 の範囲外である（利用者への報告に残した）。

⚠ **表を直接 UPDATE させない。** 1 回の merge は `news_event_articles` の付け替え・`merged_into`・
件数の再計算・監査の書き出しの 4 つに分かれるので、途中で失敗すると**どの表も嘘をつく**。
⇒ SECURITY DEFINER の関数 1 本。人が呼ぶ `news_event_merge` は admin を確かめてから
`news_event_merge_into` を呼び、**機械（`link` 段）は同じ関数を `actor := null` で呼ぶ**
——2 本の実装を持たない。⚠ そして機械は `manual_lock` を立てない（立てると、その Event は以後
どの取り込みでも更新できなくなる＝自分で自分を凍らせるパイプライン）。

⚠ 途中で 2 回、設計を実測が押し戻した:

- **RPC を Event 単位に畳んで返していた**（Event ごとに最も近いメンバー 1 本）。それだと
  `assignArticle` の推移の検算が**構造的に満たせなくなる**——10 人の Event に類似度を持つ
  メンバーが 1 人しか無ければ share は必ず 1/10 で、**embedding が正しく言い換えを見つけた
  ときほど落ちる**。⇒ 近傍そのものを返し、畳むのは呼び出し側。
- **`pairScore()` が embedding で通った対に 0 に近い点を付けていた**（語の量だけで採点していた
  から）。「最も強い候補」を選ぶ競争で、正しく見つけた言い換えが弱い語一致に必ず負ける。
  ⇒ その対だけ意味の近さを点に足す。**語で通った対の点は 1 ミリも変えない**（`assignment_score`
  は DB に保存され `clusterConfidence` の材料になる）。

### Phase D — 記事モードを 1 ビットも壊さずに、一覧を出来事にする

`js/news-events.js`（`IntMapLazy` の `newsEvents`。**起動経路には入らない**）。
`HOST.globalData` に**記事モードと同じ形の項目**を入れ、`_event` にだけ出来事固有の事実を足す
ので、既存の描画・ピン・無限スクロール・期間フィルタが分岐なしで動く。

- カードは `.news-item` に **3 つだけ**足す——カテゴリ・`Updated` の印・`N sources`。
- カテゴリ chips は `#news-cat-chips`。⚠ **0 件のカテゴリは出さない**（押せない chip は嘘）。
  ⚠ 一覧と地図に同時に効くのは規律ではなく**構造**で、述語は `passes()` 1 本しかなく、
  `computeFilteredNews()` がそれを呼び、ピンはその戻り値から作られる。
- 詳細は既存の `#news-reader-pane`。**独立画面を作らない**（§9）。
- ★は `saved_news_events`（Event の identity）。**記事の★は 1 バイトも触らない。**
  ⚠ 保存に失敗したら★を**元に戻す**（#R210/#R215 が二度払った形）。

⚠⚠⚠ **「媒体ごとの主張や数値が異なる場合、その相違を保持して表示できる」を、バイアス評価なしで
どう満たすか。** 出すのは**原文にそのまま書いてある数量**だけ——死者・負傷者・行方不明・金額・
割合。そして **相違と呼ぶのは、別々の `source_family` が別々の値を言ったときだけ**である。
同じ系列の速報 3 人 → 続報 5 人は**更新**であって相違ではない。IntMap は「どちらが正しいか」を
言わず、「両者はこう言っている」だけを言う。

⚠⚠⚠ **`LA()` は文字列ではなく配列を返す。** 9 言語ぶんを並べて書いた 37 か所は、`pick()` が
**5 つ目までしか位置引数を見ない**ので、zh / zh-hans / fr / ko は**英語のまま出荷される**ところ
だった（i18n ゲートがそれを名指しして赤くなった）。⇒ 呼び出しを 5 引数に切り詰め、29 語 × 4 言語を
`js/locales/ui.{zh,zh-hans,fr,ko}.js` の `inline` 表へ（**英語の原文が鍵**）。

### 検査で自分が踏んだこと

⚠⚠⚠ **`linkMinMatched` を測るつもりで書いた最初の fixture は、1 対も合致していなかった。**
門を外しても答えが変わらない＝**理由のない緑**である。⇒ 組み立てを変え、
「a1 と b1 は合致する」「a2 と b1 は合致しない」を**先に assert してから**門を測る。
そのうえで、割合の規則は満たされている（0.5 ≥ 0.34）ことも assert する——止めているのが
どちらの規則かが、検査の本文から読めるように。
