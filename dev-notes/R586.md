## R586 — **CI の門の 73% は 1 ステップだった——そしてその長さが、マージそのものを届かなくしていた**

〈#R585 の作業中に merge race に 3 回負け、ラウンド番号が R559 → R565 → R568 → R574 → R578 → R585 と
**6 回**動いた。利用者「auto-merge ってオンになってた方が便利ですか？」→「全部やってください」〉

### 1. ⚠⚠⚠ 便利さの問題ではなかった

最初に測ったのはリポジトリの設定で、そこに原因があった。

- `main` のルールセット「Protect main」は必須チェック 2 本（`Static checks` /
  `Browser smoke + internal QA`）を持ち、**`strict_required_status_checks_policy: true`**——
  「マージ前にブランチが最新であること」を要求していた。
- ⚠ **これは衝突が 1 つも無くても効く。** `main` が動いた瞬間に PR はマージ不能になり、
  rebase して CI をやり直しになる。
- ⚠ **そして GitHub の auto-merge はブランチを最新化してくれない。** 「マージ可能になるまで待つ」
  だけなので、strict が ON のままでは待ち続けて発火しない。

つまり **auto-merge を入れるだけでは何も解決しなかった**。効く順は ①strict を切る ②門を短くする
③auto-merge、で、③単独が消せるのは「CI 緑 → merge を打つまでの数十秒」だけだった。

⚠ **strict を切る代償は本物である**——古い `main` に対して緑だったブランチが、進んだ `main` に
入ると、個別には両方緑なのに **merge 後の `main` が赤になる**ことがある。このリポジトリは横断的な
不変条件が多く（能力数・Edge Function の本数・`js/` のファイル数・build stamp・遅延モジュール台帳）、
#R585 の作業中に **app-size で 3 回・capability-count で 2 回**実際に踏んだ。strict はそれを**着地前に**
止めていた。切ると**着地後に**気づくことになる。利用者の判断で切った。

### 2. ⚠⚠⚠ 門の 73% は 1 ステップだった

実測（job 102601448559・#R578 の run）:

| 秒 | ステップ |
|---|---|
| **558** | Source-level regression checks（`npm run test:checks`） |
| 88 | Production assets |
| 37 | Production build |
| 32 | Translation gate |
| 約 50 | 他すべての合計 |

その 558 秒の中身も特定した——**木を書き換えて `check:docs` を子プロセスで走らせる変異テスト**
（`r399` / `r403` / `r500`）が、ロックで直列化しながら**単独計測で約 400 秒**を占める。

⇒ ステップを `static` から出し、**Node 自身の `--test-shard=i/n` で 3 分割**した。

⚠ **「遅いファイルの一覧」を CI に書いていない。** それは
`.agents/rules/no-ad-hoc-hardcoding.md` §1 が最初に名指す埋め込み一覧で、ファイルが 1 本増えた日に
黙って古くなり、誰も教えてくれない。**glob が見つけた集合を Node が割る。**

⚠ **各シャードは別チェックアウトで走る**ので、変異テストの木ロックはランナーごとに閉じている。
2 つのシャードが 1 つの木を編集することは原理的に起きない（同じ木で並列にしていたら、それは
ロックが存在する理由そのものを壊す）。

### 3. ⚠⚠ 必須チェックの名前は matrix の脚にできない

脚の名前（`Regression 2/3`）にはシャード数が入っているので、**シャード数を変えた日に必須チェックが
黙って外れる**。`browser-gate`（#R203）が既にこの形を持っていたので同じにした——集約ジョブ
`Regression suite` を置き、ルールセットの必須チェックはそちらを指す。

### 4. ⚠⚠ 分割したスイートには、1 ステップには無い壊れ方がある

**シャードが 1 本消えても全部緑になる**——そのシャードが持っていたファイルは、ただ誰にも名指され
なくなるだけだから。`tests/r586-checks.test.mjs` はそこを測る:

1. シャードが **1..n を過不足なく**覆っていること
2. **`of` が全脚で一致**していること（`2/3` と `3/4` が混ざると、あるファイルは 2 回走り別のは 0 回）
3. シャードのステップが**ファイルを直接名指さず** npm スクリプトへ委譲していること（集合の正本は 1 つ）
4. 集約ゲートが **`always()` と success 判定の両方**を持つこと
   ——⚠ `always()` が無いとシャード失敗時にゲート自身が skip され、**skip した必須チェックは何も止めない**
5. 重いステップが `static` に**戻っていない**こと

変異 3 種（シャードを 1 本落とす／`of` を食い違わせる／`always()` を外す）で、それぞれ 2 本ずつ赤に
なることを確認した。
