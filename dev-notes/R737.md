## R737 — #R736 の教訓が、#R736 の修正に起きた

〈#R736 の production verification。デプロイ済みの本番で、直したはずの呼び出しを叩いた〉

```
dispatch({type:'flyTo', place:'Korean Peninsula'})
  → ok:true / 「Moved to: Korean Peninsula」 / カメラ -76.45, 37.09（バージニア州）
```

**同じ返答、同じ教会。** #R736 は雑音床を `placeExtent` の解決器（`_nomExtent`）にだけ置いた。
`flyTo` が実際に使ったのは**点の解決器** `geocode` → `_pickNominatim` で、そこには #R515 の
名前一致の床しか無い。自由文の Nominatim は**両方の端点に同じ 8 件の他人**を返す（実測・両 URL）。
「Peninsula Korean Baptist Church」は問い合わせの bigram をほぼ全部共有するので **0.63** で
名前の床を通り、importance 0.00005 を見る者は片方にしか居なかった。

⚠⚠⚠ **これは #R736 §2 がそれについて書かれた形そのものである**——
**1 つの関数に書いた規則は、その関数しか守らない**（#R429・#R488）。同じ回の中で 2 回踏んだ。

⇒ 規則を**尺度の隣に 1 つだけ**述べる。`_rankableFor(core, o)` は

1. 名前の一致が `NAME_AGREE_MIN` 未満なら 0（#R515 のまま）
2. **典拠自身が雑音床（`IMPORTANCE_FLOOR` = 0.05）に置いた候補は、名前が問い合わせを包含する
   ときだけ発言できる**（`_nameAgreement` が 1 を返すのは包含のときだけ。だから
   「Tokyo Station」→東京駅 のような importance の低い POI は今までどおり解決する）

を返し、**点の解決器と面の解決器が同じものに訊く**。

⚠ **検査は両方の扉を叩く。** 片方だけを叩く検査を書いたことが、この回が必要になった理由である。
`tests/r737-geocode-noise-floor-checks.test.mjs` は `geocode` と `placeExtent` の両方を、
`tests/fixtures/r736-nominatim.json`（実応答の写し）の上で走らせる。修正を外すと 3 本とも赤。

⚠ 数の由来: 同じ写しで実在の地物は **0.604 / 0.608**、他人 8 件は**全部 0.00005**。
失効条件は「Nominatim が `importance` の意味を変えるか、POI をこの床より上に並べ始めたとき」で、
再測定の相手はその写しである。
