## R783 — 取得・計算・説明を同じ条件のまま最後までつないだ（外部監査の P0〜P3 を 1 ラウンドで）

〈利用者から 3 件同時: ⑴ News の詳細の「Ask Atlas」は Atlas がニュースの内容を見ていない・自由入力欄が
無い・選択肢が消えない ⑵ 外部監査の報告書（`88c4cd82` 固定・P0〜P3）全部 ⑶ 前ラウンドの未了だった
画像・PDF の `attach.recall` の検証。⚠ 利用者の指示「勝手に範囲狭めるな全部やれ」〉

⚠⚠⚠ **この回は 13 の独立実装を並列で走らせ、触るファイルを重ねずに 1 つの木へ統合した。**
以下は主題ごとの**実測**で、順序は監査の優先度。

### 1. ⚠⚠⚠ P0 — 申告した能力が、未描画の経路では 1 つも効いていなかった

`supplierFor()` は**両方**の供給元について `where:true / cursor:true / limit:true` と申告する一方、
loader 経路の `loadedFetch()` は矩形で絞るだけだった。3 行（v=1,2,3）で実測:

| 指定 | loader 経路 | 描画経路 |
|---|---|---|
| `where v>=2` | `1,2,3`（条件は一度も適用されず） | `2,3` |
| `limit 1` | `1,2,3` / `next:null`（1 件のページについて「これで全部」） | `1` / `drawn@1` |
| `limit 1, cursor` | `1,2,3`（位置は読まれず） | `2` |
| `coverage.filteredBy` | **`"supplier"`** | — |

⚠ **3 つのうち最悪は 4 行目**——絞っていない答えに、絞ったという記録が付いていた。
⇒ 直したのは**道が 2 本あったこと**で、`if` を 3 つ足したのではない: `pageOf()` が条件・カーソル・
件数・`available` / `complete` / `next` の**唯一の実装**になり、両経路がそこを通る。
`filteredBy` は**実行した側の申告**から取る。
⚠ **カーソルは問いとデータに結び付いた**（`<layer>@<sig>@<offset>`）。一致しないものは
`query-or-data-changed` / `cursor-of-another-layer` / `cursor-not-recognised` / `past-the-end` で断る。
⚠ digest は同一性の証明ではなく「**認識できるものを断る**」ためのもの——本文にそう書いた。
⚠ **`canSample()` は表示状態を読まなくなった**（実質 `state.on` だった＝非表示が「能力が無い」に
なり、表示中は「数値サンプラーが在る」の証明にならなかった）。4 事実（能力／準備／利用可能／表示）を
分け、**未測定を `false` にしない**（`capable === null` は候補）。

### 2. ⚠⚠⚠ P0 — 面積按分が、凹形の画素を 100% と報告していた

1°×1° の画素に幅 0.2°・奥行き 0.4° の切り込み（四隅と中心はすべて区域内）:
旧実装 **1** ／ 球面の閉形式 **0.9200038992201667** ／ 修正後 **0.9200038992201675**。
格子規模（4°×4°・0.1° 画素・切り込み 40 本）で旧実装は **+701.66 km²**（区域の 0.44%）過大。

⇒ 検査点は増やしていない（任意の凹形に対して有限個の標本では包含を保証できない）。
**幾何的に証明できる問い**に置き換えた——区域の辺が画素矩形に触れ得るかを **360° の全周**について
厳密に判定し、触れ得ないときだけ中心 1 点で 1 か 0 を決める。
⚠ 副産物として**速くなった**: 穴なし 2000 頂点・6,400 画素で **852ms（旧 4,060ms）**、
穴ありで **2,765ms（旧 48,783ms）**——旧実装は内部画素ごとに O(n) の走査を 5 回していた。
⚠ 四隅の 4 回の点判定は**何も決めていなかった**ので削除し、`hasHole` の特例も不要になった。

### 3. P1 — 幾何の妥当性は 3 段だった（そして実データは本当に汚れていた）

`MultiPolygon` の**パート間**を誰も見ていなかった（単体で有効な正方形 2 つを重ねれば `valid:true`）。
⇒ 座標・環 → 1 パート内 → **パート間**の 3 段に分け、`parts-overlap` / `part-inside-part` /
`part-duplicates-part` を返す。⚠ 内部の点は**走査線で求める**（頂点は境界上なので判定できない
——外接した菱形が実測で無検出だった）。
⚠⚠⚠ **「既存の正常データを落第させていないか」は実測では逆だった**: `data/ecoregions_2017.geojson`
（635 MultiPolygon / 87,783 パート）の **126 件が本当にパート間の欠陥を持ち**、独立した sweep-line が
**568/568 を裏付けた**（交差面積が小さいパートの面積と完全一致＝同じ地面が二度入っている）。
⇒ 不変条件は件数ではなく**別の engine との一致**にした。追った 2 件の不一致は**閾値ではなく判定**を
直した。

### 3b. ⚠ 経度の枠を合わせる関数が、渡されたものの深さを決めつけていた

`alignTo` の `lonRange` は引数を「環の配列」と決めつけ、`boolOpR` / `unionR` / `bufferKmR` の 3 経路が
multi を渡していた ⇒ **1 周ずれた枠で書かれた 2 図形の boolean が常に空**。
⚠ 直したのは呼び手ごとの分岐ではなく**値に付けた規則**。実測 120 地物 × 720 回答のうち動いたのは
15 件で、union は面積が完全同一。値が動いた buffer の 1 件は**旧値が幾何的に不可能**だった
（周長 6,921km に 5km の縁で 63,867km²、上限は 34,603km²）。

### 4. P1 — 量の意味。単位は運ばれていたが、式を 1 つ通ると消えていた

実測: `abs(len)` / `round(len,2)` / `min` / `max` / `coalesce` / `number` がすべて `unit:null`。
`len % len` も `len / len` も `len * dist` も `null`。⚠ **`null` が 4 つの別の事実**（誰も述べていない／
無次元／量ではない／導けなかった）を同じ顔で運んでいた。
⇒ 規則を**関数の宣言そのもの**へ移し（`keeps` / `dimensionless` / `no-unit` / `changes`）、
状態を 6 つに分けた。`+`/`−`/比較/`%`/`keeps` は **1 つの結合規則**に統合（規則を演算子ではなく
「n 個が 1 つの量として扱われている」という事実に付けた）。
**量の意味**（種類・空間・時間・期間と許される集計）を表せるようにし、
⚠ **未申告は許可ではない**（`count` 以外は `undeclared` のままで `allowed` にならない）。
⚠ そして帯の宣言は **dataset の扉で落ちていた**（`add()` が帯を `{name,unit,nodata}` で作り直す）
——語彙は単位カーネルの持ち物なので**逐語で運ぶ**形にした。

### 5. P1 — 取得前の記述が、取得後の記述より薄かった

`mapRows()` が渡していたのは 5 欄（`ref`/`label`/`geometryType`/`count`/`samplable`）で、
監査が挙げた 5 主題のうち **4 つがゼロ**（時期・範囲・解像度・検索条件）。
⚠ しかも `toRaster` は幅と高さの無い呼びを断るので、**見せていない数を要求していた**。
⇒ `describe(ref)` が供給元に**訊いて** 24 slot を投影し、各 slot は
**stated / undeclared / notApplicable のどれか 1 つに必ず入る**（空欄が無い）。
一覧は `layers.sources()` ∪ `sources.list()` の**和集合**で、登録が 1 つ増えた日に自動で現れる。

### 6. P1 — 「宣言を足せば取れる」ではない。航空の上流を実測した

4 窓で叩いて: 窓は上流が**本当に実行する**（箱の外 0 件）／ID は ICAO 24bit hex で重複ゼロ／
しかし **980 格子タイルのうち 856 しか一度も訊かれていない**＝全件性は無い。
⇒ `complete` は**定数ではなく上流の文**（`lattice p/t`。`p===t` でも `null`——一度訊いた空 ≠ いま
保持する空）。結果 `completeness` は `partial` 固定で **`all` には到達できない**。
⚠ `where`/`cursor`/`fields` は**申告しない**＝名指しで拒否する。
⚠ 実測の副産物: `js/aviation-model.js` は worker からしか import されておらず、**メインスレッドに
`window.IntMapAviationModel` は存在しなかった**（#R341 の罠の後半）。
⚠ 束の 3 分岐は**表**になり、`acquireBundle()` は**必ず決着する**——旧分岐は callback を呼ばず、
`js/map-ui.js` の promise が**永久に pending** だった（拒否でもエラーでもなく、無言）。

### 7. P2 — Worker は数ではなくメモリで詰まる

`provide(name, fn)` がカーネルの関数そのものを Worker へ運ぶ扉になり（**自由名にしない**のが要点）、
`warp.geometry`（逆アフィンと areal のフットプリント箱）が別スレッドで走る。**実装は 1 本**で
主スレッドの腕も同じ関数を呼ぶ。⚠ 標本抽出と投影格子は**移していない**——規則の持ち主が別で、
移せば void 規則・端クランプ・sentinel 判定が 2 か所になる（`crs-not-in-worker` と述べて完走する）。
⚠ **上限は件数ではなくメモリ予算**（64 MiB。観測・失効条件・正本を本文に書いた）。予算は**在空中の
全部**に対する天井なので 4 並列は「1/4 のブロック」になる。**全単位は走る**——ブロック数が増えるだけ。
実測（37×29・1 行 592 B）: 予算 4,736 B → 4 ブロック・ピーク 4,736 B ／ 592 B → 29 ブロック。
⚠ **この実装中に見つけた欠陥**: `runBlocks` が `take` を await していなかったので、非同期の消費者では
29 ブロックが同時に在空し、**読者の中止が落ち、ピークが格子全体になっていた**。

### 8. P2 — 自前の読み手だけでは外部互換性を主張できない

足した出力は **COG** と **ベクタ GeoPackage**。⚠ **GeoParquet は入れていない**（部分実装を

⚠⚠⚠ **第三者は必要な証人だが十分な証人ではない**: 初版の COG は IFD 0 に nodata の tag を 2 回

### 10. §4.3 — 誤差は面と場所で桁が違う。測って申告した

（相対誤差・実測） 35°N の 1° 方形で EPSG:3857 の面積 **+53.14%**、60°N **+324%**、84°N **+12978%**。
UTM はゾーン 2 つ外で **+20624%**。⚠ **`areaScale` はその面自身の台に対する比**で、誰も測って
いなかった台の項がアプリの球面で赤道 +0.449% / 60°N −0.577% / 84°N −0.881%。
⚠ **`exact: true` は「その面の台に対して」の主張だった**（Mollweide の長さは 2.9〜113% 外れる）。
⚠ **長さの誤差の主項は投影ではなく辺の規則**（頂点間を平面の直線で結ぶ）で、Tissot の数値には
原理的に見えない。⚠ **球面の面積と球面の長さは同じ辺を別の曲線として読む**（60°N で 1,000km 辺の
三角形は 3.3%、5,000km 辺で 5.1% 食い違う）⇒ 辺規則は面ではなく**測る量ごと**に持たせた。
⇒ `certify()` が `bound` / `checked` / `within` / `blocked` / `verified` を返し、
`tolerance` を満たせないときは**数を出さず、満たせる面の一覧**を返す（上限ではなく経路）。

### 11. P3 — 異なるデータを組み合わせる 4 op

`spatialJoin` / `nearestJoin` / `timeJoin` / `convert`（24 → 28）。
⚠ **1 対多に既定を持たせない**（`cardinality` は必須——「区域 1 つに施設 40」は普通の場合）。
⚠ `first` は**索引の巡回順ではなく入力 1 の行順**。⚠ 時点は**半開**で裸の年はその年 1 年。
⚠ `convert` は**倍率を書かず**単位カーネルに訊き、換算前後の単位と変換をレシピの `resolved` に残す
（`params` とは別——`params` は再生の入力なので、解決値を混ぜると次回が列に訊かなくなる）。
実測: `nearestJoin` 2,000×20,000 が **2,780ms**（索引なし 24,266ms）、`timeJoin` 5,000×2,000 で
99,750 組・**527ms**・無駄な走査 0。

### 12. News の「Ask Atlas」— 主題は渡っていたが、**本文は誰も読んでいなかった**

⚠⚠⚠ 橋 `window._imReader` の生きている書き手は 1 つだけで、`body` を synthesis と gist から組む。
同じファイル自身の実測が「**43.5% は本文が 1 文字も無い**」と書いている ⇒ 大半の出来事で
モデルに届いていたのは **`OPEN NEWS ARTICLE "見出し"` の 1 行だけ**で、詳細ペインが見せている
各媒体の見出し・数字・一致と相違は **0 バイト**。利用者の「意味がない」は正しい読みだった。
⇒ `askReading()` が**押された瞬間に読む面そのものを読む**（面は id ではなく、それが着ている外皮の
親として同定するので次の読む面も名指し無しで読める）。読みは `open()` より**前**（Atlas に入ると
ペインが空になる）。自由入力欄を同じ群に置き、**チップでも自由入力でも起点が退く**
（判断は「どの操作をしたか」ではなく「到着が使われたか」）。
⚠ そして**切られた本文が黙って切られていた**（`maxBody` 2,600）。上限は #R413 の判断どおり残し、
**切ったことと全体の字数を Atlas に述べる**ようにした（#R320 の無言の打ち切り）。

### 13. ⚠⚠⚠ `attach.recall` は Atlas から**一度も実行できなかった**——#R773 の未了の正体

`run_capability{id:'attach.recall', args:{name:'…'}}` は dispatch に届く前に `needs_input` で返る。
能力表の 10 列目が `'text'` で、`hasTarget('text')` が読むのは `query/text/question/value/place/term`
——**この能力の唯一の引数 `name` がその一覧に無い**。⚠ `hasTarget` に `name` を足すのは誤りで
（`text` を的にする他の能力で意味が緩む）、直すのは**その 1 セル**。
同じ形がもう 1 件（`data.radiationNear` はスキーマが `lat`/`lon`、的の判定は `lng`）。
⇒ 検査は 2 件を名指しせず、**145 能力すべてを走らせて「必須と述べる引数を渡したのに `needs_input`
で返る能力が 0 件」**を構造として測る。
台帳側の欠陥も 3 件直した: 取り寄せの札（`… (attached earlier in this conversation)`）を `find` が
知らず**必ず失敗していた**／枠で落ちたテキスト添付を carry も declare も述べていなかった（10 件中
8 件だけ載っていた）／画像名を `log.length + i + 1` で作っていたので**同名衝突で古い画像が永久に
取り寄せ不能**だった。
