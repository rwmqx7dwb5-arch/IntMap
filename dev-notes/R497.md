## R497 — **行数は合っていた。名前が一つも入っていなかった**

#R495 は `volcanoes` を交差検索エンジンの表として登録し、その行をこう読んでいた——
`p.name` / `p.elev` / `p.type` / `p.last`。`data/volcanoes_gvp.json` のキーは**一文字**である:

```json
{"n":"West Eifel Volcanic Field","c":"Germany","t":"Volcanic field","e":600,"y":-8300,"v":210010}
```

`n` が名前、`c` が国、`t` が型、`e` が標高、`y` が最後の噴火年、`v` が GVP の火山番号。
読んでいた 4 つは**ファイルのどこにも無い**ので、全部 `undefined` だった。

**本番で実測（マージ当日）**: 「外洋から300km以上の火山」は **127 件**と答え、その 127 件は
**すべて名前が空で標高が null** だった。

### ⚠⚠ 件数が正しいことが、これを隠した

#R495 自身の規則②は「出典の無い列を出さない」である。**出典付きで中身が空の列**は、その規則を
内側から破る——値が「—」なのは見えるが、**行が数えられているのに名前が無い**のは見えない。
表の形（列がある・行がある・件数が出る）が通ることは、表が働いていることではない。

### だからこの検査は形ではなく値を見る

`tests/r497-checks.test.mjs` は同梱ファイルを実際に変換して:

- 名前のある行が **99% 超**、標高のある行が **95% 超**、国のある行が **95% 超**
- id が 1 つも重複しない（重複すれば結合が行を潰す）
- **Fuji が Japan にあり、3,000〜4,000 m で、138.73 / 35.36 にいる**（列が黙って入れ替わったら落ちる）
- そして `js/atlas-query.js` の**コードから**（コメントからではなく）`p.name` などが消えていること

### 併せて足した 2 列

行が持っていたのに誰も訊けなかったもの——`country`（GVP は**国名**を持ち、ISO コードは持たない）と
`lastEruptionYear`（負値＝紀元前）。カタログにも書いた: #R115 の規則どおり、**カタログが書いていない
列は planner にとって存在しない**。
