## R476 — **「Coastlines & shoresはデフォルトでオンにして」——既定オンは2か所で1つの編集で、門は片側にしかなかった**

依頼は1行。`cb-coast`（海岸線・湖岸線。`js/coast-line.js`、#R289）を既定でオンにする。

### 何を変えたか

「既定オン」は**2つの事実が同時に成り立つこと**で、どちらも他方を含意しない。

| 場所 | 何を言っているか |
|---|---|
| `index.html` の `<input …>` の `checked` | **箱が点いた状態で出荷される** |
| `js/data-layers.js` の `window.IntMapDefaultOn` | **アプリがその id を「既定オン」だと思っている** |

両方に `cb-coast` を足した。**そして片方だけだと、両方向とも無症状で壊れる**——これが今回の本体。

- **`checked` だけ**（id が無い）——`js/app-body.js` の boot dispatcher は「**すでに点いている箱**」に
  `change` を投げるので線は描かれる。ところが `IntMapBaseDisplay.matches()`（#R469）は**生の
  チェック状態**と `defOn()` を突き合わせるので食い違い、**起動 400 ms 後に「基本表示」が
  毎回「カスタム」へ降格する**。例外も警告も出ない。パネルが静かにモードを名乗らなくなるだけ。
- **id だけ**（`checked` が無い）——boot dispatcher は点いていない箱に何も投げないので
  **チェックも入らず線も出ない**（#R34 が記録した defect そのもの）。さらに悪いことに
  `js/session-tabs.js` の off-sweep がその id を既定オンとして読み、**復元のたびに能動的に外す**。

### なぜ誰も捕まえなかったか——門が片方向しか無かった

`tests/r225-checks` ⑤ は **リスト → markup** を歩いていた（「`IntMapDefaultOn` の各 id は本当に
`checked` で出荷されているか」）。**markup → リスト を歩くものは存在しなかった**ので、
`index.html` に `checked` を足しただけの編集は**検査の視野の外**だった。

⚠ しかも ⑤ のループは **7 個の id を手書きで持っていた**。#R309 が製品から4本の写しを消した、
その同じ形が門の中に残っていたわけで、8 個目を上のリストに足しても**このループは見なかった**。
⑤ は宣言をパースして**導出**するように直した。

新しい `tests/r476-checks.test.mjs`（`test:checks` に登録済み＝毎 push 走る）:

- **①** `cb-*` について **両方向**——`checked` で出荷される箱はすべて `IntMapDefaultOn` に在り、
  `IntMapDefaultOn` の id はすべて `checked` で出荷される。**両側とも導出**で、この検査は
  membership の写しを1つも持たない。
- **②** `cb-coast` が両側でオンであり、かつ **`IntMapBasicLayerRows` に留まっている**
  ——既定オンになったからといって「表示中のレイヤー」の chip やモバイル FAB の強調に
  数えられ始めてはならない（#R233/#R309。海岸線は地図の**見え方**であって上に載せた**データ**ではない）。
- **③** off-sweep の規則が無傷であること（下記）。
- **④** 文書が「既定は OFF」と言い続けていないこと。

### 届く範囲を、広げずに正直に書いた

**届くのは初回訪問者だけである。** 保存済みセッションには `cb-coast` が無く、
`js/session-tabs.js:143` の off-sweep は**保存に無い既定オン id を「読み手が消した」と読む**
（#R186/#R225）ので、既存利用者では毎回オフに戻る。届かせる手当ては `defv` の世代を上げて
1回だけ回復すること（#R189/#R190）で、**今回はしていない**——利用者の指示は
「どうでもいい。複雑なことはしなくていい」。

⚠ **その代わりに off-sweep を緩めてはならない。** 緩めれば「意図して消したレイヤーがリロードで
復活する」——#R186 が直した defect に戻る。③ がその規則の綴りを固定している。

`window._imCoastAuto`（#R289 の「風／気温を点けたとき1回だけ提案する」ラッチ）は**そのまま残した**。
初回訪問では `c.checked` がすでに true なので空振りするが、**#R476 以前の保存を持つ読み手にとっては
唯一の戻り道**である。ラッチであることが「既定」と「連動」を分ける（#R85）。
