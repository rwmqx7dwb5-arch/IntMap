## R577 — **波レイヤー——「Windy と同じ絵」を 3 つに分け、合っているものと合っていないものを別々に言う**

> 利用者「Windyと画素、RGBレベルで完全に同一なグラフィックに」「アニメーションのグラフィックも同一に」。

有義波高を色の場として塗り、その上に平均波向きの粒子を流す 1 レイヤーを足した。
**実装の正本は [`docs/MAP-LAYERS.md`](docs/MAP-LAYERS.md) §7.14**、契約は `Architecture.md` §7.3d。
ここにはラウンドの経緯と、**まだ合っていないもの**を残す。

### 新しく作ったもの

| ファイル | 仕事 |
|---|---|
| `js/waves-palette.js` | 波高→色。Windy の 1024 段 LUT を byte 単位で再現する |
| `js/waves-gl.js` | MapLibre の custom layer。ラスタ（bicubic + LUT）と粒子アニメーション |
| `js/waves.js` | 結線（レイヤー行・凡例・モデル切替・時刻軸）。**描かず、取りに行かない** |

データは既存の `.om` 経路そのままで、**新しい Edge Function も新しい配信元も無い**。
`js/wx-models.js` に `roles:['wave']` で 2 本を宣言した（実測 2026-09-09）:

- `ecmwf_wam025`（ECMWF WAM 0.25°）— 変数 4・有効時刻 85 段・1.43 MB/step
- `ncep_gfswave025`（NOAA GFS Wave 0.25°）— 変数 15・有効時刻 209 段・6.07 MB/step

⚠ **`roles` はここで初めて「既存レイヤーの代替ではないモデル」を締め出す役に立った**——波モデルは
風にも気温にも使える変数を 1 つも持たないので、気温のピッカーに並べば
**そのレイヤーを描けないモデル**を選択肢として見せることになる。

### ⚠⚠⚠ なぜ既存の SDK 経路を使えなかったか（実測・0.0.19 の出荷バンドル）

他の気象レイヤーは全部 SDK のタイルラスタライザを通る。**設定の漏れではなく、この絵はそこから出ない**:

- SDK の格子補間は**全経路 2×2 バイリニア**（ラスタ・等値線・矢羽根・地点読みのどれも）。
  `hermite` / `derivative` / `secondDerivative` を export しているが、**SDK 自身はどこからも呼んでいない**
  ——部品はあるが方針が無い。Windy は 4×4 バイキュービック（Catmull-Rom）で、
  **バイリニアは設定でバイキュービックにならない。**
- ラスタライザは**バンドル内の文字列から作る Blob URL Worker の中**にあるので、補間器は設定からも届かない。
- 色引きは**段の間を混ぜない最近傍のバケツ**。Windy は同じ 1024 段への線形フェッチ。

⇒ **ラスタだけ自前**にした。データの読み（`load()` の生の格子）は `js/wx-ecmwf.js` のままで、1 行も変えていない。

### 配色は「惜しいところで違う」実装が一番危なかった

sRGB で素直に線形補間すると、**平均 1.11/255**——目では通る。**最大は 11.52/255** ずれる
（3.5 m で Windy `rgb(152,44,103)` 対 線形 `rgb(144,48,100)`）。Windy は **YCbCr で補間し、
彩度長を両端の彩度長を結ぶ線へ再スケール**する（飽和した 2 色の中間が灰色寄りに垂れない）。
さらに最後の 1 バイトを決めたのが 2 つ:

- 標本点は `min + i·(max−min)/(steps−1)`。**`(i+0.5)/steps` ではない**
- 戻りは **×256 して四捨五入**。×255 でも floor でもない

4 つ揃えて **1024/1024 一致・最大差 0**。**どれも実測で決めたもので、理屈で選んだものは 1 つも無い。**
Windy 側の LUT の FNV-1a/32 = `96000495` を `tests/r577-checks.test.mjs ①` が固定しているので、
上流が配色を変えれば黙って離れるのではなく赤くなる（そのときの赤は「上流が変わった」であって
「壊した」ではない）。

⚠⚠ **リンギングは欠陥ではなく絵の一部。** Windy は赤チャンネル経路でだけ結果を 2×2 の min/max へ
追い込んでオーバーシュートを潰すが、**波が通る青チャンネル経路にその抑制は無い**。消すと別の絵になる。
海岸線は 4 近傍 alpha のバイリニアを **0.66 で二値化**——ぼかさない。Windy の海岸が締まって見えて、
同じデータの素朴なアルファ合成が霞むのはこの 1 つのしきい値の差だった。

### 「同一」と言えるもの・言えないもの

- **配色は byte 単位で同一**（上）。
- **算術は同一**（同じカーネル・同じ段ごとの [0,1] クランプ・同じ 0.66・同じ粒子定数）。
- ⚠ **値は同じ数ではない。** Windy は自前の 257×257 タイル（z3〜4 で頭打ち・以降アップサンプル）、
  こちらはモデルの native 0.25°。**実測の一致度は開洋上 10 箱の CIEDE2000 で中央値 ΔE00 = 1.1・最大 6.2**、
  残差は **2.0〜2.5 m のランプが最も急な区間**に集中していて、標本化の差で説明がつく。
  **スクリーンショットの差分は 0 にならないし、どんな実装でもできない**——Windy のタイルは配布されていない。

⚠⚠⚠ **Windy のタイル（`ims.windy.com`）は 1 バイトも使っていない。** 有効期限 48 時間の JWT が要り、
規約上も第三者利用はできない。**使ったのは配色の定義（12 個の数）だけ**で、値は Open-Meteo 経由の
ECMWF / NOAA（CC-BY-4.0 / NOAA-open）。出典 3 行を `js/reference-data.js` に足し、
**3 行目は「配色スケールであってデータ源ではない」と読める文言**にした——凡例にも
「配色は Windy の波スケールに準拠」と出るので、読者はどちらの経路からも同じことを知る。

### ⚠⚠ まだ合っていないもの（未解決・別途調査中）

**粒子の速さ。** Windy のタイルは R,G に方向ベクトルを持つが、**その物理量はバンドルのどこにも
書かれていない**——見えるのは「10 で正規化し 0.5 で床を張る」ことだけ。深海の位相速度
`c = gT/2π ≈ 1.56·T m/s` は 8 秒のうねりで 12.5 m/s、3.2 秒の風浪で 5 m/s と**ちょうどその範囲の両端**に
なるので、`wave_period` からそれを組んで暫定としている。**合っていないのは速さだけで、他は合っている。**
⚠ ここを「実測」と書かない——推定であることを `js/waves-gl.js` のヘッダにも書いてある。

### 実装上、他人が同じ穴に落ちるもの

- ⚠⚠⚠ **`wave_direction` を要求すると `wave_height` の数が返る。** 読み手は風の u/v と同じ
  「対の導出規則」を持っていて、どちらの名前で読んでも両方のファイルを読み
  `{values: 波高, directions: 波向き}` を返す。だから `wave_height` を**1 回**読み、向きは
  `.directions` から取る。気づかずに読んでいたら**波高の場を波向きとして描く**
  ——レンダラの不具合に見えて、そうではない欠陥。
- ⚠⚠ **復号された配列の行順は上流ファイルの性質**なので、宣言ではなく `sampler()`（SDK 自身の地点読み）に
  格子ノードを 11 点訊いて決め、使えないときだけ格子自身の宣言に落ちる（`state().orientation` が
  どちらだったかを言う）。**海の名前で当てる探り表は世界の 2 つ目の写し**で、新しい domain で最初に間違える。
- ⚠ **球（globe）では描かない。** 判定は投影の名前ではなく `globeness()`（MapLibre の `globe` は
  遷移ズームより上では実際にメルカトル）で、理由は `blocked` として凡例が印字する。
