### ① ドライブの特定は条件 1 つでは足りない

「USB メモリを自動判定する」を `DriveType=Removable` だけで書くと、外付け SSD も
カードリーダも同じ答えになる。**2 つの層に別々に訊いて交わりを取る**:

| 層 | 見るもの | このマシンでの実測 |
|---|---|---|
| `Get-Volume` | `DriveType` | `C:` Fixed / **`D:` Removable** |
| `Get-Disk` | `BusType`・`IsSystem`・`IsBoot` | 0: NVMe・System・Boot / **1: USB**（BUFFALO USB Flash Disk） |

交わりは **`D:` 1 台だけ**（115.43 GB・NTFS・**ラベル無し**）。
規程の「専用ラベルがまだ存在せず、書き込み可能なリムーバブル USB が 1 台だけなら設定してよい」に
そのまま当たったので、**ボリュームラベルを `INTMAP-BACKUP` にした**——次回からは「1 台だけだったから」
ではなく**名前で**当たる。合わせて、ルートに `.intmap-backup-id.json`（同期対象外の管理情報）を置いた。

### ② ⚠ USB には既に旧形式のフルコピーが載っていた

`D:\IntMap` が本日 **02:43** 更新で存在した。中身は working directory の**丸ごとのコピー**——
`node_modules`・`.git`・`.frame-cache`・`test-results`・`playwright-report` まで入っている。
**ドライブ全体で 31,816 項目**。

新しい規則は「**ルート**を IntMap バックアップとして使用する」「**古い IntMap ファイルを残さない**」なので、
これは畳んでルートへ移した。⚠ **削除を伴うので、実行前にユーザーに確認して承認を得ている**
（「今回は初回なのでバックアップまで進めてください」）。

**移した後の中身は追跡対象 609 ファイル・87.6 MB。** 31,816 → 609 になったのは、消したのではなく
**再現に要らないものを運ぶのをやめた**から:

- `node_modules` は `package-lock.json` から `npm ci` で戻る（**31,000 ファイルの大半がこれ**）
- `.git` は GitHub にある（バックアップの目的は「サイトを再び作れること」であって履歴の二重化ではない）
- `dist/` は `npm run build` の出力・`.frame-cache/` は第三者タイルの録画・`/x/` はラウンドの走り書き

基準は **`git ls-files`**（＋まだ commit していないがこの後追跡になるもの）。
「何を含めるか」を手で列挙すると必ず 1 つ忘れるので、**除外の定義は `.gitignore` に一本化**した。
⚠ Köppen の元 GeoTIFF は `.gitignore` にあり USB にも行かないが、アプリが出荷しているのは
**再投影済みの PNG（追跡対象）**なので、サイトの再現には要らない。

### ③ 「コピーが成功した」は「同じ物がある」ではない

`robocopy` の終了コードも `Copy-Item` の無例外も、**書いた側の主張**でしかない。
規程は同期後の**再帰比較**を要求している。実装した検証は 3 点:

1. **相対パス**の集合が一致する（USB 側の余りが 0・不足が 0）
2. **存在**する
3. **SHA-256 が一致する**（609 ファイルすべて。サンプリングしない）

実測（初回・USB 2.0 級の書き込み速度）:

```
PRUNE_SEC=491            旧 D:\IntMap の 31,816 項目を消すのに 8.2 分
COPIED=609 BYTES=91882916 COPY_SEC=483.1
VERIFY_SEC=22.2
HASHED=609 MISSING=0 EXTRA=0 MISMATCH=0
RESULT=OK
```

⚠ **検証は 22 秒**。同期の 3% しかかからないものを省いて「たぶん入った」で終わるのは、
安いから省いているのではなく**測っていないから**である。

### ④ ⚠ 1 回目は落ちた——`git ls-files` は非 ASCII のパスを引用符とオクタルで返す

剪定が終わってコピーに入った瞬間、`Test-Path : Illegal characters in path` で停止した。
止めたのは **1 ファイル**——`USGS.能登.pdf`。`git ls-files` は既定（`core.quotepath=true`）で
非 ASCII を含むパスを

```
"USGS.\350\203\275\347\231\273.pdf"
```

と**引用符ごと**返す。PowerShell はそれをそのままファイル名として扱うので、実在するファイルが
「存在しない」になる。⚠ **609 分の 1 でしか起きないが、起きるとバックアップは丸ごと止まる**——
そして 8.2 分の剪定はもう終わっているので、**USB は空のまま**になる。

`git -c core.quotepath=false ls-files` に変え、`[Console]::OutputEncoding` を UTF-8 にし、
**引用符で始まるパスが 1 本でも残っていたら投げる**検査を足した（規程 §11.7 の
「失敗したら原因を調べて自分で直し、再同期・再検証する」の 1 例）。再実行で `RESULT=OK`。

### ⑤ 台帳の日付は、成功したときだけ動く

`~/.claude/projects/C--Users-gyuuk-OneDrive-IntMap/usb-backup-state.json`（**リポジトリの外**）に
最後に**正常完了した**日付を持ち、同じ暦日の以後のセッションは USB 同期を行わない。

⚠ **順序が本体**。先に日付を書いて後から同期すると、**1 回の失敗が丸 1 日のスキップになる**——
その日はもう誰も試さない。だから書くのは検証が差分ゼロを返した**後**だけ。
**USB 未接続はエラーではない**（スキップして終わる。日付も更新しない）。
候補が複数あって一意に決まらない場合も同じで、**推測で選ばずスキップし、報告に書く**。
