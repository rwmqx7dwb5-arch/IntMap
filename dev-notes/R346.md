## R346 — **掃引は成功しているのに、その run は赤かった**

#R341 が入れた `.github/workflows/aviation-sweep.yml` は、5 分ごとに `?refresh=1` を叩いて共有スナップショットを前へ進める。着地直後に手で 1 回走らせたところ、**仕事は全部正しく終わっていた**:

```
--- slice 1: HTTP 200, 70170 bytes      x-intmap-save: ok   x-intmap-coverage: lattice 3/980
--- slice 2: HTTP 200, 70170 bytes      x-intmap-save: ok   x-intmap-count: 1405
##[error]Process completed with exit code 1.
```

原因はループの最後の 1 行:

```bash
[ "$i" = "1" ] && sleep 45
```

`i` が 2 のとき条件は偽で、`&&` 全体が **1** を返す。それがループ本体の最後のコマンドなので step の終了状態になり、GitHub は step を `bash -e` で走らせるため **exit 1** で落ちる。

⚠ **「成功を意味する赤」は、警報が無いより悪い。** 次に来る本物の失敗——provider が 429 を返す、関数が落ちる、スナップショットが書けない——が**まったく同じ顔をする**ので、この workflow の赤は最初から情報を持たない。#R304 が「deep tier が 14 夜赤いまま誰も見ていなかった」と記録したのと同じ形が、生まれた瞬間に起きていた。

⇒ `if [ "$i" = "1" ]; then sleep 45; fi`。**旧い形と新しい形の両方を実際に走らせて**、旧 `exit=1` / 新 `exit=0` を確かめた——1 行の修正でも、落ちる側と通る側の両方を測る。
