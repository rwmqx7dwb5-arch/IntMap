⇒ **「カメラが動かなかった」をこの回の欠陥として数えていない。** 途中まで「大陸名が全部誤って解決される」

`South America` も `Europe` も正しく返す）。⚠ 一方 §6 の広域地名は**アニメーションを介さない経路**で

## 2. ⚠⚠⚠ 日本語で頼むと、扉そのものに届いていなかった

3 問が**操作ゼロ**で終わった:

- 「東京から大阪までの鉄道ルートを引いて、所要時間と距離を教えて。」 — `find_capability` **8 回**・
  operations **0 件**・45 秒・`step_budget`
- 「世界の原子力発電所を地図に表示して、日本のものだけ強調して。」 — 同じ形・57 秒
- 「東京の今日の天気と、今後3日間の予報を教えて。地図にも出して。」 — `data.weather` に**一度も**届かず、
  気温レイヤーと降水予報レイヤーを地図に塗ったうえで「**数値を確認できませんでした**」

包んだ tool 呼び出しに、返っていた中身がそのまま残っていた:

```
"世界の原子力発電所を表示し、日本の原子力発電所だけを強調する"
  → layers.aircraftTrack, layers.allOff, layers.baseDisplay, layers.countryInfo,
    layers.isobars, layers.nightSide, layers.opacity, layers.planeAltitude
"nuclear power plants 原子力発電所 原発 世界 日本 強調"
  → map.clear, map.radiation, map.choropleth, map.clearAll, map.clearHighlights, map.compose, …
```

⚠ **前者は `layers.*` の辞書順の先頭 8 件、後者は `map.*` の辞書順の先頭**である。得点がどれも実質ゼロの
とき、`find_capability` は**登録順の先頭 N 件を「一致した候補」として返していた**。0 件を返すより悪い
——モデルはそれを候補だと信じ、言い換えて 8 回撃ち直し、1 ターンを使い切る。`find` は常に `ok:true` で
何かを返すので、`js/atlas-toolsurface.js` の「Nothing matched this wording … Rephrasing this search will
not find more.」は**そういうときにこそ出ない**。

原因は 5 つあり、どれも「日本語の語彙が足りない」ではなかった:

1. **df が「ブロック数」ではなく「能力数」を数えていた。** `js/atlas-catalog-text.js` は 145 能力を
   **60 ブロック**で説明し、最大のブロックは **33 能力**を一度に説明する。門のコメント自身が
   「4 **ブロック**を超える語は一致ではない」と書いているのに、コードは `docNorms()` の id を数えていた
   ——最大ブロック内のあらゆる語が df ≥ 33 で**常に 0 点**。そのブロックには `routing.route` の用例として
   **「東京から大阪への経路」が丸ごと書かれている**のに、一度も得点できなかった。
2. **ブロック内の語が、そのブロックが説明する 33 能力**全員**の証拠になっていた**（①だけ直すと同点 33 件が
   辞書順に並ぶ）⇒ 項目の開始から次の項目の開始までを、その能力について書かれた区間として帰属させる。
   区間は各能力**自身の綴り**から導出——手書きの一覧はない。
3. **ラテン語の語境界規則が、片方の照合にしか付いていなかった。** `hasTerm` は #R727 で「iss は missile の
   中には無い」と知っているのに、40 行下のエイリアス照合は素の `indexOf` だった。実測:
   **`nuclear` の中の `clear` で `map.clear` が 73 点で 1 位**（原発の問い）、**`duration` の中の `ratio` で
   `data.ratio` が 65 点で 1 位**（鉄道の問い）。
4. **日本語の自然文は固定 2 文字窓では当たらない**（長い文ほど窓が一般語になる）⇒ ブロックと共有する
   **連続部分文字列**の中にある窓だけを数える。資格は「run 全体」または「4 文字以上の断片」。
   ⚠ 床を 3 でなく 4 にしたのは実測——3 文字は「名詞＋助詞」（**「東京の」**）で、これが
   **天気の問いを `sim.earthquake` に送っていた**。`ありがとう` は 2 文字断片しか持たないので 0 件のまま
   （#R745 の退行を戻していない）。
5. **カテゴリのヒントが順序を決めていた。** `VERB_HINTS` はカテゴリ鍵なので同カテゴリ全員に同じ +8 を与え、
   同点は辞書順だった⇒ self（その能力自身を名指した証拠）と hint を分け、**self → total → id** で並べ、
   同じカテゴリ内で 1 つでも名指されたら残りのヒント専用行は候補にしない。

⚠ **それでも天気には届かなかった。** 得点器ではなく**カタログ本文**に穴があった——
`js/atlas-catalog-text.js` の全文に **「天気」が 0 件・「原子力」が 0 件**、`data.weather` の項目は
**`{"type":"weather","place":str};` という説明文ゼロの 1 行**だった。
⇒ 主題を en+jp で述べ、**「その能力は自分自身の主題の言葉で見つけられるか」を全能力について測る検査**を
`npm run check:capabilities` の中に置いた（[[intmap-catalogue-silence-is-a-denial]] の機械化）。

## 3. ⚠⚠⚠ ピンは数えて判定されていたので、成功が失敗として報告されていた

`research.situationMap` が**同じ主題に対して 1 ターンの中で ok と `not_rendered` を交互に**返していた。
返り値の実物:

```
{"ok":true, "status":"completed","code":"ok","rendered":true, …}
{"ok":false,"status":"partial","code":"not_rendered","rendered":true,"unverified":true,"error":"not_rendered", …}
```

Atlas は `ok:false / not_rendered` を読んで「描けなかった」と解し、topic を言い換えて撃ち直す:
令制国 1750 年で **7 回・9 分 16 秒**、1914 年のヨーロッパで **6 回・6 分 55 秒**、アイスランドの EEZ で
`research.analyze` **5 回・6 分 51 秒**。読者の吹き出しには**同じ報告が 3〜5 本積まれ**、最後に
`map.clear {what:"research-report pins"}` が**その回が置いたピンを全部消して**終わっていた（`objects: n=0`）。

原因は `js/atlas-capabilities.js` の第 3 の段（#R742 の「塗った当人の申告」）が**ピンの面だけ持っていな
かった**こと。申告が無い capability は**基数**（件数の増減）で判定され、`clearPois()` して同じピンを置き
直す実装では件数が動かないので、最後の行 `not_rendered` に落ちる。
⇒ `PAINTED_IDS` に `poi` の面を足し、ピンを置く 5 つの dispatch（`map.poi` / `research.mapReport` /
`research.situationMap` / `research.impact` / `research.events`）が**1 つの宣言**を通るようにした。
⚠ **名前を 1 つも持たないときは申告しない**——`PAINT_GOAL` は空配列を「この面は空であるべき」という
主張として読むので、名無しピンしか無いときに `poi:[]` を出すと逆のことを申告してしまう。


⇒ ⑴ 照合器を 1 本（`_bestRow(cat,q0)`）にして**表示側の扉と読み取り側の扉が同じ規則を使う**

`state(id).label` と registry 自身の規約から導く）⑶ **失敗の理由を 5 つに言い分ける**——存在しない／
存在するが点の値を公開しない／読めるがオフ／読めてオンだがその点が読み込まれていない（**先にそこへ
寄れば読める**と述べる）／サンプラが例外。⚠ **読者が既に済ませたことを「やれ」と言わない。**

## 8. ⚠⚠⚠ 打ち切られたターンは「上限に達した」と言い、答えを言わなかった

46 ターン中 **23** が読者に「このターンは作業の上限に達したため、上の回答は途中までの可能性があります
——上に書かれていないことは実行されていません」を出した。`js/atlas-console.js` の `_cutNote()` は
**1 本の文字列**で、`step_budget` / `call_budget` / `time_budget` / `repeated_calls` / `malformed_limit`
の 5 つが共有している。

**そのうち複数は、作業が成功していた。** 最悪の例:
「Show the top 10 countries by GDP per capita as a choropleth, and tell me which of them are NOT in the
top 10 by total GDP.」— 表は 2 つとも描かれ choropleth も塗られたのに、**読者が受け取った散文は
"I'm comparing the two rankings now." の 1 文だけ**。問われた「どれが総額 top10 に入っていないか」は
一度も述べられていない。

原因: 最後の 1 呼び出し（ツールは走ったが何も言わなかったターンのための段）が **`text` が空のときだけ**
走る。モデルが第 1 ステップで「これからやります」と 1 文書いていると `text` は空ではないので、
**その段は走らない**。⇒ 打ち切り（上の 5 つ）で終わったターンにも、**道具を渡さない最後の 1 呼び出し**を
与え、transcript にあるものだけから答えを書かせ、**答えきれていない部分を名指しさせる**。
⚠ **上限は 1 つも動かしていない**（`CONSTITUTION.md` §5・[[intmap-atlas-full-authority-no-new-limits]]）。

## 9. 読者の画面で見えていたもの（UI・グラフィック）

- **見出しが全部 2 回出ていた。** 実 DOM: `<h2>条約上の位置</h2><div class="atl-blk"><h2>条約上の位置</h2>…`。
  節は `heading` という**欄**を持つのに、書式指示（`js/atlas-console.js`）が散文に対して
  「各節は "## " の見出しで始めよ」と命じているので、モデルは**両方に書く**。⇒ レンダラの側で、
  節の最初のブロックが同じ見出しで始まっていれば 1 回にする（モデルが従ったかどうかに依存しない側で直す）。
- **1 文の平叙文が `<h4>` になっていた**（「国家間比較という次元では、…順位付けすることはできません。」）。
  `directAnswer` 全体が `**…**` で包まれると `js/atlas-markdown.js` の `RE_LEAD` が見出しにする。
  ⇒ **フィールド全体**を包む強調だけを外す。
- **略語で段落が割れていた。** 「It identifies Dujuan (JMA Typhoon No.⏎⏎25 / 2625) …」
  「to simplify U.⏎⏎S. Antarctic Program flights」。⇒ #R463 が dotted host と小数を「原子」として
  退避させている同じ仕組みに、**3 つの形**（点つき頭字語／母音を持たない短い大文字語＋句点／数字が続く
  句点）を足した。⚠ **本物の文境界は割れ続ける**ことを前後で測った（「…the Red Sea. The Nile…」は 2 文）。
- **本文に登場したが未配置**の行が、地名でないものを挙げていた（`Lake Baikal's`・`JMA Typhoon No`）。
  そして**日本語の国名を 1 つも解決できず**「ブルンジ, コンゴ民主共和国, エリトリア, エチオピア, ルワンダ,
  南スーダン…」を「特定できませんでした」と読者に述べていた。⇒ 所有格の接辞と略語の形を外し、
  **製品が既に持っている国名の呼び方**（`_imCldrRegion` × `IntMapLang.codes()`）から索引を導いて
  **12/12 を要求 0 件で解決**（表は 1 つも書いていない）。⚠ `Coeur d'Alene` / `N'Djamena` / `Xi'an` は
