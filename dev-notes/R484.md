## R484 — **当たり判定が予測していたのは、画面に無いピルだった**

#R480 の**本番検証**が見つけた。依頼された6項目のうちコンパスとの重なりは白だったが、その隣で
**1行目**が壊れていた。

### 実測（本番 → ローカルで同値を再現）

```
1310x900
  #map-search    656 – 1054
  .map-view-row  left 982.56
  重なり         71.44 px
  elementFromPoint(#ms-btn の中心) → btn-view-map
  msBtnClickable: false          ← 検索ボタンが押せない
```

無防備な帯は約 **1303〜1453px**。**1366 も 1440 も、その中**である。

### ⚠⚠⚠ 誤差は #R480 が作ったのではない。#R480 は誤差を可視にした

`js/mobile-ui.js` の判定はこうだった:

```js
const half=110, margin=14;   /* half = half of a comfortable ~220px centered pill */
const collide = ((mapCX + half + margin) > rightLeft) || …
```

`.map-search` は `width:min(380px,55vw)` ＋ padding 16 ＋ border 2 ＝ **398px**、半分は **199**。
**110 は 89px 足りない**——そしてそれは #R25 が書いた時からずっと足りなかった。

**見えなかった理由**: 右上スタックで最も広い行は `#map-tools-group`（290px）で、それは **y=50**。
検索バーは **y=10** にあり、両者の y 方向の重なりは 3px しかなかった。**x で重なる条件が揃っても、
y で重ならなければ何も起きない。**

**#R480 が変えたのはそこ**——317px の行を **y=10** に置いた。x の誤差は前からあり、y の隙間が消えた。

### ⚠⚠⚠ 「定数をやめて測る」を先に実装し、それが**より悪い**ことを実測した

自然な直しは `host.getBoundingClientRect()` である。**書いてみて捨てた。**

`ms-narrow` が付いている間、ピルの幅は**ウォッチャ自身が決めた値**なので、読み戻すと循環する。
つまり読めるのは**ウォッチャが切れている間だけ**＝値をキャッシュするしかない。ところが
**「ウォッチャが切れている間だけ更新されるキャッシュ」は、ウォッチャが入った後は二度と更新されない。**
早期に誤った値（stylesheet の max-width が効く前のピルはコンテナ全幅）を掴むと、それが永久に残る。

実測でそれが起きた: **1500x900 で衝突判定が両方 false なのに `ms-narrow` が外れない**。
古い half が ≈455 だったため。**もともと無事だった幅で、ピルが恒久的にずれる**——
直そうとした欠陥より悪い。

⇒ **数値はソースに書く。** そのかわり `tests/r484-checks` ② が
`css/intmap.css` の `.map-search` 規則から `width:min(<n>px` ・ `padding` ・ `border` を
**パースして (380+16+2)/2 = 199 を導出し**、`js/mobile-ui.js` の `const half=` と突き合わせる。
**#R25 が持っていなかったのはこれ**——定数そのものではなく、**定数が実物とずれたら落ちる門**である。

### 直したあとの実測

| 幅 | ms-narrow | 検索バー右端 | 1行目 左端 | 重なり | ボタン |
|---|---|---|---|---|---|
| 1600 | off | 1199 | 1274 | なし | 押せる |
| 1500 | off | 1149 | 1174 | なし | 押せる |
| 1440 | **on** | 958 | 1114 | なし | 押せる |
| 1366 | **on** | 921 | 1040 | なし | 押せる |
| 1310 | **on** | 893 | 984 | なし | 押せる |

⚠ **1600 と 1500 が off のままであることが、過剰発動していないことの証拠**である。
199 は上限なので、コンテナが狭くて `calc(100% - 330px)` が効く場面では**過大評価**になるが、
その向きの誤りは「gap 分岐が少し早く働く」だけで、そこは元から狭い場合のための分岐である。
