## 0. まず 5 件とも、自分で再現した

|---|---:|---|

| `rasterDiff` 10 **°C** − 283.15 **K** | **−273.15**（`ok:true`） | 0 |

⚠ **評価の書き方も正しかった。** 「`rasterDiff` が単位を null にしている」ことを欠陥として挙げず、
**「null にしても数は意味を持たない」**と書いてあった。そこが核心である。

## 1. ⚠⚠⚠ 単位は #R759 から運ばれていた。一度も読まれていなかった

`docs/GIS-CORE.md` §3.1 は単位が**残る**ことを述べていて、実際に残っていた——`unitStated`、
`unitStatedAt`、`unitFrom` まで揃っている。**この層が単位を読んだことは一度も無かった。**

```js
const unit = (A.band.unit != null && B.band.unit != null
  && String(A.band.unit) === String(B.band.unit)) ? A.band.unit : null;
```

綴りが一致すれば継承、違えば null。**そして引き算は生の数でやる。**

⚠ **札を外しても数は正しくならない。** 消えるのは誤りではなく**証拠**のほうで、これは
[[intmap-a-fix-that-removes-the-evidence]] が #R747 について記録した形そのものである
（あちらは冪等化が判定の証拠を消した。こちらは単位を消して「単位のことは何も言っていません」に
なった数が、区域統計にも凡例にも Atlas の回答にも注釈なしで流れていった）。

### 直したのは `rasterDiff` ではない

⚠ **1 つの op に検査を足すのは、規則を関数に付けること**（`.agents/rules/no-ad-hoc-hardcoding.md`
§3 の 2 問目）。**2 つの量が算術で組み合わされる**という事実に付けた:

**`js/gis-units.js`（新設・`units-1`）** — 答えるのは 1 問だけ。「この 2 つは足し引きできるか。
できるなら換算は何か」。`compare` の答えは 5 つで、そのうち 2 つが**拒否**である。

| 答え | 何が起きるか |
|---|---|
| `unstated` | 片方でも述べていなければ**何もしない** |
| `identical` | 綴りが同じ。表を引きもしない |
| `convertible` | 格子では **B を A の単位へ換算してから**引く／混ぜる |
| `incompatible` | 別の量。`unit-mismatch` |
| `unknown` | 綴りが違い、少なくとも片方が表に無い |

⚠ **沈黙を不一致にしなかった理由は計測である。** この app の格子の大半は単位を述べていない。
そこを拒んだら、**誰もしていない主張を理由に、在るデータを断る**ことになる。

⚠ **「わからない」を「同じ」にしなかった理由も同じ向きから来ている。** `NDVI` と `EVI` は
どちらもこの表に無いが、だからといって同じ量ではない。⇒ **拒む。** 表に原子を足すと
**拒否が答えに変わる**だけで、答えが別の答えに変わることはない——だから表は小さくてよい。

**表は SI の定義値の原子だけ**で、`mm/h`・`kg/m^2`・`µg/m³`・`W/m2`・`km/h` は**並べずに解析**する
（`m2`・`m²`・`m^2` は 1 つの式の 3 通りの書き方で、`m2` は `js/gis-crs.js` が使っている綴り）。
⚠ **年と月は原子に入れていない**——どちらも 1 つの長さを持たないので、係数になれない。

⚠ **°C と °F はオフセットを持つので、読みの換算と差の換算が別**（`convert(…, {difference:true})`）。
合成の中の `°C`（`°C/km` ＝ 気温減率）はオフセットを落とす。この区別は**このモジュールには
決められない**——渡された数が読みなのか 2 つの読みの差なのかは、呼び手だけが知っている。

### 呼び手は 4 つあり、式の中では換算しない

`rasterDiff` と `mosaic` は**この層が算術を選んでいる**ので、換算するか拒むかのどちらかをする。

`compute` と `rasterCalc` は**読者が書いた算術**なので、`+` と `−` は**同じ綴りだけ**を通し、
違えば `unit-mismatch` で**演算子と両方の綴りを名指して**拒む。⚠ 換算しない理由は
`js/gis-expr.js` の評価器が換算しないからで、`m` と名乗った答えを返せば**誰も述べていない主張**に
なる。読者は `a + b * 1000` と自分で書き、その主張はレシピに残って後から読める。

⚠ **リテラルは中立にした**（`t − 273.15` は拒まない）。厳密な次元解析はこれを拒むが、読者は
これを日常的に書き、返る数は意図どおりである。**これは計測ではなく判断**なので、
`js/gis-units.js` の頭に「後の読者が知ったうえで覆せるように」書いてある。

### ついでに #R759 が付けられなかった半分が付いた

`compute` の出力列は**これまで永久に単位を持てなかった**——`applyInherited` は列**名**で引くのに、
その列はその瞬間まで存在せず、派生記録は読者の宣言を拒む（`edit-would-contradict-recipe`）から
後から付けることもできない。⇒ **導けた単位は runner が述べる**（`renamed` と同じ形。
著者は op で、`unitStatedAt:'derived'`）。⚠ `×` と `÷` は**綴りを作らない**——`km·kg` は
誰も書いていない単位である。

## 2. ⚠⚠⚠ ひとつの多角形に、読み方が 2 つあった

`js/gis-geometry.js` の `pointInGeometry` は `alignTo` で環を問い合わせ点に合わせてから測る。
`js/gis-ops.js` の `ringAreaKm2` は**辺を書かれたまま**読む。だから 179°E→179°W の未分割の帯は

- 内外判定にとっては**幅 2° の帯**（180°,0.5° は内・0°,0.5° は外）
- 面積にとっては**経度差 358°**（4,426,211 km²）

**読者はどちらにも出会えた。** ⚠ `js/gis-crs.js` の `areaOn`（`measure` が CRS を名指したときの
平面路）は同じ環を `plane-seam-crossed` で**拒んでいる**——答えてしまっていたのは測地路だけだった。

### 註は正しかった。そして半分しか述べていなかった

`ringAreaKm2` の上には「⚠ Δλ IS THE EDGE AS WRITTEN, NOT THE SHORT WAY ROUND」という註があり、
**これは本当に正しい**: `IntMapGeodesy.diskFillPolys` は極の円盤を 89.9999° 線に沿って閉じる
**360° の辺**を持つ環として書くので、各辺を短い方へ正規化するとその辺が消え、面積は**補集合**に
なる（実測、89°N の 500 km buffer が 785,022 km² ではなく **509,280,824 km²**）。

同じ註はさらに「経度span > 180° の環はこの窓の外で、**その面積はここでは定義されない**」とも
書いていた。⚠ **そう書いてあるのに、何も拒んでいなかった。**
[[intmap-comment-contradicted-the-table-below-it]] と同じ形で、今回は註が自分の下のコードより
正しかった。

### 見分けるのは辺である（これは表現についての規則で、事例の特例ではない）

- **180° を超え 360° 未満**の辺 → 未分割の継ぎ目。その環だけを `unwrapRing` に通す
- **ちょうど 360°** の辺 → 全幅の帯が意図して書いた閉じ辺。触らない

⚠ **根拠は「この地図が読むどのデータにも半周より長い*辺*は無い」という表現の性質**で、
`js/gis-geometry.js` の `SEAM_STEP = 180` が同じことを同じ理由で述べている。失効条件も書いた
——180° より長く 360° でない実在の辺を書く上流を読むようになったら、辺は自分がどちらかを
述べられなくなり、答えは**上流の宣言**へ移る。

⚠ **巻き直しは 2 つ目を書かなかった。** `js/gis-geometry.js` の `unwrapRing` を呼ぶ——
`.agents/rules/no-ad-hoc-hardcoding.md` §2-3 の「同じ判断を 2 か所に持たせない」であり、
写しを置いた瞬間に内外判定と面積はまた別々の規則を持つ。④ がそれを測る
（このファイルに 2 つ目の 360° ループが生えていないこと）。

**実測（変更の前後）**

| | 前 | 後 |
|---|---:|---:|
| 継ぎ目の帯 179°E→179°W × 0°–1° | 4,426,211.1 | **24,727.4** |
| 同じ緯度の幅 2° の帯 | 24,727.4 | 24,727.4 |
| 継ぎ目の帯に継ぎ目の穴 | 13,167,666.9 | **172,949.0** |
| 極の円盤 500 km @89°N | 785,022.8 | **785,022.8** |
| 継ぎ目の円盤 500 km @179.8°E | 784,434.8 | **784,434.8** |

⚠ **期待値は測る対象の外から取った。** 極の円盤と赤道の円盤は同じ半径の円なので、
**互いが互いの参照になる**（[[intmap-co-designed-reader-cannot-falsify]]）。
さらに `crossesSeamUndivided` を `false` に潰すと ① と ② の 4 本が赤くなることを実測してから戻した
——**落ちない検査ではない**。

## 3. ⚠⚠⚠ 5 点プローブの根は `js/gis-sources.js` に無かった

#R763 は「窓の中央 1 点で全体を断じない」を直し、5 点に増やした。それでも、

- 北東端の 1 画素だけが値を持つ場は、**表示 OFF で `layer-not-visible`**（5 点全部が空振り）
- 同じ場を**表示 ON** にすると 100 画素を読んで値 42 を返す

**同じ範囲への同じ問い合わせが、表示状態で答えを変えていた。**

⚠ **点を 5 から 20 に増やすのは直っていない。** プローブは「**この供給元は答えるか**」を訊きたいのに
「**この 5 座標に値があるか**」を測っていた——[[intmap-proxy-predicate-freezes-the-wrong-diagnosis]]。

**根は `js/map-ui.js` の `sampleAt`** だった。訊いた登録が null を返すと**行を 1 つも push しない**
ので、「訊いたが値が無い」と「訊ける登録が無い」がこの扉で既に同じ沈黙に潰れていた。
⇒ **訊いた登録は必ず 1 行返す**（`asked:true`。値があるときだけ `value`、投げたら `failed`）。
行の組み立ても 1 か所にまとめた（以前は measure 経路と sampleAt 経路で 2 回組んでいた——
[[intmap-object-built-twice-and-hidden-class]]）。

プローブは「行が返ったか」だけを読む。行が返れば窓を全部読み、値がどこにも無ければ
**既にある** `layer-values-all-missing` で断る——「訊けなかった」ではなく「そこには無い」という
別の事実で、語彙は #R763 が既に作っていた。

⚠ **ついでに、同じ沈黙が 2 つの名前で呼ばれていた穴も塞いだ**: 表示 ON のときはプローブを通らない
ので、標本の扉を持たない行が ON では `layer-values-all-missing`・OFF では `layer-not-visible` に
なっていた。

## 4. ⚠⚠⚠ 書き手と読み手が一緒に作られていると、外の誰にも開けないことが分からない

`js/gis-export.js` は GDAL_METADATA (42112) に `role="unit"` と書く。**GDAL は `role="unittype"`**。
外部の GDAL 3.12.1 で読むと**単位が None になる**（画素値・CRS・配置・NoData・バンド名は 3 形式とも
一致していた——壊れていたのは単位だけ）。

⚠ **読み戻し側 `js/gis-geotiff.js` は `name=` で引いて `role=` を見ない。** だから
**IntMap で書いて IntMap で読む往復では永久に露見しない**
（[[intmap-co-designed-reader-cannot-falsify]]）。⇒ 回帰は**出たバイト**から IFD を自前で走査し、
`<Item>` の属性まで**測る対象の外に書いた独自パーサ**で読んで照合する。旧綴りに戻すと 3 本とも
赤くなることを実測した。読み手が `role` に依存していないこと（＝ #R774 以前のファイルと GDAL 製の
ファイルが開き続けること）も同じ本数で測っている。

⚠ GDAL はこのマシンに無いので**実行はしていない**。綴りが GDAL のものである根拠は定数の隣に
3 点（観測・失効条件・正本）で書いた。

## 5. 暦日と、終わりが始まりより前の期間

`asDate` は正規表現で形だけ見て `Date.parse` に渡していたので、`2026-02-30` が **2026-03-02** に、
平年の `2026-02-29` が **2026-03-01** に、`2026-04-31` が **2026-05-01** に繰り上がって**受理**された
（`2026-13-01` だけは拒めていた）。

⇒ **往復で確かめる**。述べられた年・月・日を `setUTCFullYear` で組み直し（`Date.UTC` は 100 未満の
年で 1900+y になる・#R602）、組み直した日が同じ年月日を述べるときだけ受ける。
⚠ **月ごとの日数表は書いていない**——書けばうるう年の特例を足すことになる。
判定は**暦日だけ**に効かせたので、時刻とゾーンは今までどおり瞬間にそのまま効く
（`2026-02-30T00:00+09:00` は拒み、`2026-03-01T00:00+09:00` は受けて UTC では 2/28 に落ちる）。
裸の年・BC・`YYYY-MM` は 1 つも変えていない。

`declareTime` の `constant` は正規化後に `start > end` なら `time-constant-reversed` で拒む
（`start === end` は長さ 0 の期間なので拒まない）。`interval` には**新しい方針を作らなかった**
——逆転した行を `readable` に数えず `reversed` に載せるだけにしたので、既存の「1 行も読めない宣言は
拒む」規則が全行逆転をそのまま `time-unreadable` で拒み、まだらは軸として残って件数が読者に届く。
⚠ 閾値も第二の政策も足していない。

## 6. 台帳

`ops-5→ops-6`（面積が継ぎ目で別の数を返す／`compute` が拒めるようになった／出力が単位を持つ）、
`raster-2→raster-3`（`diff` と `merge` が換算または拒否）、**`units-1` を新規記録**。
⚠ `js/gis-units.js` は `KERNEL_VERSION` を宣言する——**表を 1 行足せば、拒否だった呼び出しが
答えを返す**ので、保存したレシピの再生結果が変わりうる。

**起動費用は 1 バイトも動いていない。** `gis-core` は `js/lazy-modules.js` の動的 import の先なので、
新しいモジュールは**読者がデータと分析を開いたときにだけ**落ちてくる。その非同期チャンクの天井は
**369,076 → 377,285 バイト**（+8.2 kB）へ上げた——`check:perf` の許容幅（2,048 B）を超える実費なので、
⚠ **`--update` で全項目を書き換えず、その 1 行だけを実測値へ動かした**（他の項目を一緒に動かすと、
別の主題の増加がこの回の commit に紛れる）。⚠ **#R773 の着地に rebase したあと `dist.assets` も
18,444,509 → 18,545,075 バイトへ上げた**——増分の大半は #R773 のもので、その天井の許容幅
（92,222 B）をこの回の 8 kB が**越えさせた**。2 つの回の増加が 1 つの天井で合流する形なので、
**越えた側が上げる**（#R773 の branch では越えていなかった）。

## 7. 残した観測（直していないもの）

- **`js/gis-crs.js` の `AREA_UNITS`/`LENGTH_UNITS` は m と km の 2 つだけ**で、`measure` が
  **報告できる**単位の一覧である。「同じ量か」を訊く `js/gis-units.js` とは**別の問い**なので
  写しではないが、前者を後者から導けば読者は `measure` の答えを ha やマイルでも受け取れる。
  ⚠ 今回は触っていない（`crs-2` を動かす変更になる）。
- **`js/session-tabs.js` の `layers.data` は、この回で 2 種類の事実を分けて返すようにした**
  ——`sampleAt` が「訊いた登録」を全部返すようになったので、答えた行を `values`、
  訊いたが値の無かったレイヤーを `asked` に置いた。**読みの無い読みを Atlas に差し出さない**ため。
  ⚠ この形が Atlas の回答にとって最良かは本番で測っていない（表示を壊さないことだけ確かめた）。
- **外部評価の第 2 段階以降（描画から独立した取得・区域一括読み取り・分割実行・取得前カタログ）は
  この回では着手していない。** 第 1 段階の完了条件は
  「**意味を保証できない入力に対して、もっともらしい成功値を返さないこと**」で、それは満たした。
