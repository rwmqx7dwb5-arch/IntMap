# IntMap — 顧客区分ごとの提案書の骨子 (Proposal outlines)

> 相手から相談が来たとき、または運営者が承認した相手に提案するときの**骨組み**。中身は相手ごとに書くが、
> **章立てと「言ってよいこと」はここに従う**。数字は [`README.md`](README.md) の「5. 数字の出どころ」の正本から取る。
> 料金は [`pricing.md`](pricing.md) の文だけ。導入実績は無いので書かない（見本の地図は「見本」と書く）。
> ⚠ 提案を**こちらから送る**のは外部への発信なので、その都度運営者の確認を取る（`PRODUCT.md` §2.4）。

---

## 共通の章立て（どの区分も）

1. **相手の課題**（相手の言葉で 2〜3 行。こちらの推測で書かない——問い合わせの本文から引く）
2. **IntMap で何ができるか**（下の区分別の 3 点から、相手の課題に効くものだけ）
3. **具体的な形**（相手の題材で作った**実際の共有リンク／埋め込みコード**を 1〜3 本。画面写真を添える）
4. **導入の手順**（区分別の手順。相手側の作業が何分で済むかは**実測してから**書く）
5. **出典とライセンス**（各データの出典条件・クレジット行を消さないこと・ソフトウェアの `LICENSE`）
6. **費用**（[`pricing.md`](pricing.md) の文そのまま）
7. **できないこと**（正直に。稼働保証は無い・応答時間の約束は無い・専用の API は無い 等、該当するもの）
8. **次の一歩**（返信先・`contact.html`）

⚠ 3 の地図は、**実際に開いて目で確かめてから**貼る（歴史地図は `.agents/rules/historical-verification.md`：
年と場所を名指して何が描かれるかを確かめる）。

## A. 報道機関（記事への地図の埋め込み）

**相手が得るもの**
- 記事の日付・場所・レイヤーを固定した**動く地図**を、CMS に 1 行貼るだけで載せられる
- **出典の表示が枠の中に残る**（`js/embed-mode.js` が残す一覧に入っている）——記事側で出典を書き足す手間が減る
- 静止画にもできる（`interactive=0`）、読み込みは遅延（`loading="lazy"`）、ログインや広告は出ない

**手順（`for-newsrooms.html` と同じ 5 段）**: 地図を開く → 日付とレイヤー → 共有 → 埋め込み → 大きさを選んで貼る

**言ってよいこと / 言ってはいけないこと**
- ○ 埋め込みに料金は請求していない
- ○ 更新されるレイヤー（地震など）は読者が開いた時点のデータになる。ある時点を残すなら出典つきのスクリーンショット
- × 「ずっと同じ表示が保証される」「落ちない」——稼働保証は無い
- × 営利の媒体での利用について**ソフトウェアのライセンス**の判断をその場でしない（運営者に回す）

**見本に使う地図**: `for-newsrooms.html` に並ぶ見本（`scripts/org-pages.mjs` の `EXAMPLES`）

## B. 学校・教育委員会

**相手が得るもの**
- インストール不要・**生徒のアカウント不要**（生徒の個人情報を預からない）・広告なし
- 歴史（紀元前から現在）と現在のデータを 1 枚の地図で。授業案・授業用ツアー・問いつきの見本は `teachers.html`
- 日本の「地理総合」との対応は `js/showcase.js` の `CURRICULUM`（見本ごとに示している）
- **授業パック**＝授業ツアー（投影して進める）＋**印刷用ワークシート**（同じツアーの各段の地図・問い・解答欄を A4 に。
  生徒用と教員用、出典は紙にも焼き込む。授業モードのプリンタのボタン）。先生が自分で作ったツアー（ツアー作成）も同じ紙になる。
  提案書の「具体的な形」には、相手の単元のツアーのリンクと、そこから作った**実際のワークシートの PDF**（印刷画面の
  「PDF に保存」）を添える——作ったものを目で確かめてから（描けなかった段は紙に「撮れませんでした」と出る）

**情報担当向けの確認事項（`for-schools.html` の一覧と同じ）**
1. サイト本体と読み込み先の許可——読み込み先は**プライバシーポリシー §4 に全部ある**（`scripts/outbound-hosts.json` が正本）
2. WebGL が有効であること
3. アカウントは 13 歳以上（利用規約 第3条）。地図にはアカウント不要。Atlas はアカウントと 1 日の上限が要る

**言ってよいこと / 言ってはいけないこと**
- ○ 教育目的の利用はソフトウェアのライセンス上も無料（`LICENSE` §2）
- × 研修・訪問・教材の作成を約束する——運営者の確認なしに約束しない
- × 「〇〇校で使われています」——記録が無い

## C. 研究機関・NGO

**相手が得るもの**
- 手元のデータ（GeoJSON・KML・GPX・緯度経度の列がある CSV）を IntMap のレイヤーと並べて開ける（`js/geo-import.js`）
- **出典の一覧**（`sources.html`）と**計算の説明**（`science.html`）を引用の根拠として示せる
- 表示を共有リンク・埋め込みにして報告書・サイト・スライドで使える

**データを IntMap に載せたいという相談**
- 必要なもの: データ本体・ライセンス・帰属表示の書き方・更新の頻度
- 載せるのは**ライセンスが許し、出典・ライセンス・帰属表示がそろう場合だけ**。データの出自・権利・鮮度は
  `npm run check:datagov` の規則に乗せる（`docs/DATA-GOVERNANCE.md`）。出典ページ・利用規約・プライバシーも同時に更新する（`AGENTS.md` §3 の 4）
- 歴史のデータは `.agents/rules/historical-verification.md` に従って**主張を**確かめてから

**言ってよいこと / 言ってはいけないこと**
- ○ 非営利の研究での利用は無料（`LICENSE` §2）
- × 製品としての API がある——無い
- × 相手のデータの掲載をその場で約束する——上の確認を経てから

## D. 商用ライセンスの相談（`purpose = licence`）

`LICENSE` §6「商用ライセンスは著作権者に連絡」の窓口。**条件・価格は運営者だけが決める**。
エージェントは相談の内容（何を・どこで・どの規模で）を整理して運営者に渡すところまで。
