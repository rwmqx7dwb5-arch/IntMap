## 1. 何を測っているのか

「インターネットが落ちている」は 1 つの事実ではなく、**独立した複数の計器がそれぞれ別の角度から
見ている影**である。IntMap はその影を統一のモデルに正規化して 1 枚の地図に載せる。

| 観測の軸 | 何を見ているか | どこから来るか |
|---|---|---|
| 経路の可視性 (BGP) | その国／地方の prefix が世界の経路表から消えたか | IODA の `bgp` 信号 |
| 能動計測 | その国の /24 ブロックが ping に答えるか | IODA の `ping-slash24` 系 |
| ネットワーク望遠鏡 | 平常時に届くはずの背景トラフィックが止んだか | IODA の `merit-nt` |
| 利用者側のトラフィック | Google のサービスへの実トラフィックが落ちたか | IODA が中継する `gtr` |
| 実機の到達性 | 世界中の測定プローブが実際に切断されたか | RIPE Atlas |
| 経路の量 | その国で見えている ASN 数・prefix 数 | RIPEstat（国をクリックしたときだけ） |

⚠ **この表は説明であって、実装が持つ一覧ではない。** 信号の名前は応答の `datasource` として届き、
凡例の選択肢は**その応答から組み立てられる**（`js/net-health-live.js` の `signalsOf`）。
上流が計器を 1 つ足せばここに現れ、やめれば消える。**`js/net-health-live.js` は計器名を 1 つも書いていない**
——`tests/r565-checks.test.mjs` ⑦ がそれを測っている。

## 2. 使っている供給者（3 つ・すべて鍵なし・すべてブラウザ直取得）

正本は **`js/net-health-live.js` の `PROVIDERS`**。ここはその説明であって写しではない。

| id | ホスト | 鍵 | CORS 実測 | ライセンス・条件 |
|---|---|---|---|---|
| `ioda` | `api.ioda.inetintel.cc.gatech.edu` | 不要 | Origin を反射 | `Copyright (c) Georgia Tech Research Corporation`（応答自身が名乗る） |
| `ripeatlas` | `atlas.ripe.net` | 不要 | Origin を反射 | RIPE NCC のサービス規約 |
| `ripestat` | `stat.ripe.net` | 不要 | `*` | RIPE NCC のサービス規約（**再配布禁止**） |

### ⚠ なぜ「ブラウザが直接取りに行く」設計なのか

**性能の話ではなく、条件の話である。**
RIPE の規約は「RIPEstat のデータを再パッケージ・再配布してはならない」と明示している。
中継して当方のサーバーから配れば、それは再配布に触れる。**読者のブラウザが読み、当方は 1 バイトも
保存しない**なら触れない。IODA の `All Rights Reserved` に対しても同じ理屈が最も安全側に立つ。

だから:

- **新しい Edge Function は作っていない。** 中継を1つも追加していない（`#R266` の「不要な relay は
  1 つ余計に落ちるもの」）。
- **同梱データも増やしていない。** 州のポリゴンは既に持っている `data/admin1-world.json.gz`。
- **プライバシーポリシー §4 に 3 ホストを明記した**（`js/legal-text.js`）。§4 は「コードがどこから
  取得するか」についての事実なので、経路を足したら同じコミットで直す（`CONSTITUTION.md` §6）。

## 3. 採用しなかったもの（実測した結果として）

⚠ **「良さそうだが未検証」ではない。全部叩いて、落ちた理由を記録してある。**
同じ候補を次のラウンドがもう一度掘り出さないために書いている。

| 候補 | 実測した結果 | 採用するなら何が要るか |
|---|---|---|
| **Cloudflare Radar** | トークン必須。加えて**トークン無しで 200 を返す公開エンドポイント（`/client/v4/ips`）にも `access-control-allow-origin` が無い**＝ CORS ヘッダそのものが存在しない。preflight も未実装（400／405）。**トークンは認可を変えるだけで、無いヘッダを足さない**ので、鍵があってもブラウザからは到達できない | 中継用の Edge Function ＋ 利用者が発行した API トークン。データは **CC BY-NC 4.0** なので NC 条項の判断も要る |
| **OONI**（検閲・ブロッキング測定） | API は生きている（`/api/v1/aggregation` が 158 か国・`probe_cc` は ISO alpha-2）。ただし **CORS は `*.ooni.org` / `*.ooni.io` だけのホワイトリスト**で、本番オリジンは拒否される（Origin を振って確認済み） | 中継用の Edge Function。**CC BY-NC-SA 4.0**——NC に加えて **SA が伝播する**ので、これは実装ではなく方針の判断 |
| **Google Transparency Report** | 非公式 v3 API が本番オリジンから 200（219 か国・30 分刻み・遅延約 1 時間）。ただし**「障害イベント」のエンドポイントは無く**、系列から自分で推定するしかない。ライセンス表記も無い | **不要**——同じ系列は IODA が `gtr` 信号として中継しており、そちらには出典と条件がある |
| **Access Now #KeepItOn STOP** | 公開スプレッドシートの CSV が本番オリジンから 200（313 行・2009〜2025・`shutdown_type` と `actual_cause` を持つ**唯一の構造化された shutdown イベント集**） | 明示ライセンスが見つからない。最新が **2025-12-29 で約 8 か月古い**ので、そもそもライブ層ではなく歴史層 |
| **RIPE RIS Live**（生 BGP ストリーム） | 認証不要で接続できる。実測レートは**無フィルタで 2,420 msg/s・1.14 MB/s**、`path` で絞れば 6.45 msg/s | 無フィルタ購読はブラウザに流せない。特定の ASN／prefix を追う機能を作るときに、**そのときだけ**購読する形なら成立する |
| **Internet Society Pulse** | `/api/shutdowns` は 401、OPTIONS は 405（CORS 無し）。しかも出典は #KeepItOn ＝ 上の CSV の下流 | 鍵があってもブラウザ不可 |
| **NetBlocks** | `wp-json` は CORS 付きで開いているが、**最新記事が 2023-08-26 で 3 年以上停止**。国の構造化フィールドが無い | — |
| **bgp.tools** | `table.jsonl` は 200 だが CORS 無し。規約が `User-Agent` での自己識別を必須としており、**ブラウザの `fetch` は `User-Agent` を設定できない**＝原理的に規約を満たせない | — |
| **BGPView** | ⚠ **`bgpview.io` に A/AAAA レコードが無い（NXDOMAIN）。上流がホストごと消えている**（#R514 と同じ形） | 復活しない |
| **CAIDA BGPStream broker** | `api.bgpstream.caida.org` は NXDOMAIN。正しいホスト `broker.bgpstream.caida.org` は 200＋CORS だが、**MRT アーカイブファイルの目録**であって障害信号ではない | — |
| **BGPKIT** | `ACAO: *` で最もブラウザ親和的だが、**hijack / leak の検出結果は公開 API に無い** | — |
| ThousandEyes / Downdetector / outage.report / internetoutage.info | 403（Akamai）／`robots.txt` が `Disallow: /`・API 522／地理軸が無い／NXDOMAIN | — |

**BGP hijack と route leak の検出済みイベントは、現在この 3 供給者のどれからも鍵なしでは取れない。**
Cloudflare だけがそれを API で返しており、それには中継と鍵と NC の判断が要る——だから今回は
**「経路が見えなくなった」までは描き、「誰が乗っ取ったか」は描いていない**。

## 4. 範囲 → 地物の解決（何を拒むか）

| 範囲 | 何に結合するか | 実測 |
|---|---|---|
| 国 | `window.countryGeo`（Natural Earth。`ISO_A2_EH` → `ISO_A2` の梯子、`-99` は国コードではない） | IODA の国コードは ISO 3166-1 alpha-2 なので直結する |
| 地方 | `js/atlas-admin1.js` の `resolveMany()`（同梱の `data/admin1-world.json.gz`） | **1,999 件中 1,958 件＝97.9% が結合**（2026-09-09） |

⚠ **結合できなかった 41 件は「穴」ではない。** Anguilla の集落、Åland の自治体、
`[Invalid Region (54)]` のような欠番——**そもそも第一次行政区画ではないもの**である。
だから**最も近いポリゴンに寄せず、拒んで数える**。凡例が「アラート N 件／描画 M 件／配置できず K 件」
と出すのはそのため。

⚠ **IODA の region topology（`/v2/topo/region`）は使っていない**——gzip 14 MB・展開 36.8 MB で、
ブラウザに降ろす量ではない。同じ Natural Earth 10m 由来の索引を**もう持っている**。

## 5. ⚠ 打ち間違いと「平穏な地球」は、上流では同じ応答になる

**実測: `/v2/outages/alerts?entityType=nonsense` は HTTP 200・`error: null`・`data: []` を返す。**
これは障害が 1 件も無い世界の応答と 3 フィールドとも同一である。

`#R536`（段の条件を「解決器が存在するか」で分けたら本番で下の段が死んだ）と
`#R514`（上流の不在が計器では 5 通りの別名になった）と同じ形なので、対策も同じ形にした:

- **範囲は `/entities/query` がその範囲の実体を返したときにだけ使う。**
  実体が 0 件の `entityType` は存在しない。
- そのときレイヤーは `unsupported_scope` と言い、**測っていない「異常なし」を描かない。**
- 供給者ごとに「最後に何をしたか」（`ok` / `unreachable` / `unsupported_scope` / 件数）を持ち、
  **`report()` の答えに同梱する**。誰が測ったかを言わない障害の答えは、答えではない。

`tests/r565-checks.test.mjs` ① ② が、この 2 つの状態が**区別可能であること**を測っている
（片方でも欠けると赤くなることを変異試験で確認済み）。

## 6. Atlas から

制御面（`IntMapOS`）に 4 つ登録される:

| 命令 | 何をするか |
|---|---|
| `nethlth.toggle` / `netreach.toggle` | レイヤーの表示・非表示 |
| `nethlth.report` | **地図を描き替えずに**、ある場所（または全世界）について測定結果を返す |
| `nethlth.signals` | いま上流が公開している計器の一覧 |

⚠ **`report` が独立して存在するのは、レイヤーを ON にすることが答えではないから。**
「イランのインターネットは落ちているか」に対する答えは観測値であって、地図の状態変化ではない。

⚠ **「なぜ落ちたのか」はこのレイヤーが答えない。** 原因の分類（政府命令・ケーブル切断・停電など）を
API で返すのは Cloudflare だけで、それは §3 のとおり届かない。**原因は Atlas がウェブに訊く**
——これは `.agents/rules/no-ad-hoc-hardcoding.md` §2 の「判断が要るなら、判断できるものに訊く」
そのままで、原因の対応表をコードに埋め込むのは同じ規則が禁じている。

## 7. 費用

| 何 | 実測 |
|---|---|
| 世界全体の国別アラート 1 回 | 約 1.8 kB（gzip） |
| 地方まで含めた 1 回 | 約 14 kB（gzip） |
| RIPE Atlas プローブ（最大 500 点） | 1 リクエスト |
