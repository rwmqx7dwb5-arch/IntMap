## 8. UI/UX の構造

### 8.1 画面の骨格

- **地図上部の Measure ▾ / Share ▾ は同時に開かない。** 両方のトリガが `e.stopPropagation()` を
  呼ぶので相手の click-away に届かない——`window._closeMapMenus(except)`（`js/app-body.js`）が
  **集合を知る唯一の場所**で、各トリガは自分の名を渡してそれを呼ぶ。Layers は別機構
  （`window.IntMapLayerSidebar`・セッションに永続化）なのでこの排他には入らない。

- **最初の 1 枚（初回訪問）は地図が全面。** 保存されたセッションが「開いていた」と答えた側柱だけが起動時に開く
  （左は `js/app-body.js` の `_sessUI.left===true`、右のレイヤーパネルは `js/map-ui.js` の `ui.right===true`）。
  答えの無い初回訪問は**どちらも閉じて**起動し、読者が開いたときに開く——端末を問わない。既定タブ（Countries）は
  選ばれたままなので、左の開閉ボタンを押せば従来どおりそこに着く。起動が取らないもの: レイヤーパネルの
  サムネイル（`kick()` だけが門を開く、`docs/architecture/09-mobile.md` の該当項）と世界の地名辞典
  （`data/gazetteer-world.json.gz`。ニュースの地名解決が見出しを処理したとき・地名検索欄に手を伸ばしたとき・
  Atlas などの読み手が待つときに取る）。門は `tests/first-impression.spec.js`（1024×768・ストレージ空で
  起動し、両パネルが閉じ canvas が全幅・起動中に `preview_*.png` と世界の地名辞典を要求しない・開けば要求する）。
- **サイドバー（左）**：タブ（News / Companies / Countries / Atlas）、検索、ニュースフィード／
  企業ランキング／Atlas。
  ⚠⚠⚠ **左サイドバーには2つのレイアウトがあり、地図の中心の合わせ方が違う**（設定「Sidebar appearance」・
  `js/sidebar-style.js`）。**不透明**では `.operation-room` の flex 列なので **canvas 自体が狭まり**、
  中心は既に可視領域の中心にある——ここで補正すると**二重にずれる**。
  ⚠ `.operation-room` は**枠であってスクロールする箱ではない**（`overflow:clip`）。閉じた右のレイヤー欄は
  `translateX(102%)` で右の外に置かれており、`overflow:hidden` のままだとそれがスクロール可能な幅（1000px の窓で
  1,306px）になって、focus や `scrollIntoView` が殻ごと横にずらしていた。`tests/community-next.spec.js` が 1000px で測る。
  **フロスト2種**（`body.sidebar-glass`）では `.map-container{position:absolute;inset:0;width:100%}` で
  **canvas は全幅のまま**サイドバーが上に重なるので、camera padding の `left` に**可視幅**を書く。
  ⚠ 折り畳みは `width` を残して負マージンで外へ出すだけなので、幅ではなく**状態**を読む。
  ⚠ `bottom` は携帯シートの持ち物なので**書く前に読む**。⚠ **値が変わったときだけ書く**
  （レイヤートグル・テーマ変更・設定保存でカメラを動かさない）。
- **マップ上コントロール（右上）**：`.map-controls-top` は**縦一列**で、直下の子が1行ぶんになる。
  **1行目** `.map-view-row` に **Map/Sat** と **Flat/Globe/3D** の2つのピル（`.map-view-group`）が横並び。
  ⚠ **2つのピルのままである**——各ピルは `.view-btn.active` を1つだけ持つセグメント制御で、基図と投影法は
  互いに独立（既定は Satellite ＋ Globe の同時オン）。1つのピルに5個入れると選択チップが2つ並び
  「5個中2個選択」に読める。**2行目**が Grid／Measure／Share／Layers（`#map-tools-group`）。
  **3行目**は**コンパス単独**（`.compass-btn`・直下の子・丸型 42px・列の `align-items:flex-end` で右端）。
  中身は**細い一本の針**（北半分は赤 `#ff3b30`、南半分はテーマ色）と、北を指す小さな三角・薄い輪・軸受けだけ
  （目盛りと面取りの陰影は持たない）。**北の 2 つ以外はすべて `currentColor`**＝テーマ追従。同じ図形を携帯の `.m-compass-svg` が 38px で使う。
  回転するのは SVG 全体（`js/map-readout.js` が `rotate(-bearing)` を書く）＝**方位盤ごと回る**。
  ⚠ **どちらの SVG も `id` を持たない。** 同じ文書に2枚あるので、`<defs>` を足した瞬間に id が衝突する。
  1行目・2行目のピルは `.view-btn` の上下 5px＝**行の高さ 31px**（字は 12px のまま）。
  地名検索バー（`.map-search`）は**高さ 34px**で、角丸は**高さの半分**（18px）——半分でなくなると
  ピルではなく角丸長方形になる。
  ⚠ 右上スタックの高さを測る側（`js/mobile-ui.js` の地名検索バー配置）は**ピルではなく直下の子**を数える。
  コンパスの**右クリック**で方位・仰角・ズームを数値入力できる（デスクトップのみ）。傾き上限が
  「無制限」のときは仰角欄が 0〜360° を受け付け、180° 超は方位を反転した等価な視線に解決される。
- **画面下の2つの隅は1つの余白を共有する。** 座標・標高の常時表示（`.coord-readout`・左下）と
  Chronos（`.news-timeline`・右下）は、どちらも地図コンテナの隅から **6px**。
  ⚠ **数が2か所にある以上、片方だけ動かせる**ので、`tests/shell-css-surface-checks.test.mjs` ⑪ が**2つが等しいこと**を
  検査する（`tests/shell-map-input-checks.test.mjs` ⑥ と `tests/shell-css-surface-checks.test.mjs` ⑤ は左下の値そのものを錨にしている）。
  右パネルが開いているときの退避量（`--lsr-w` への加算）も、各要素**自身の**隅の余白に一致する。
  Chronos の字は**時計**（文字盤・4方位の目盛り・長短の針・軸受け）で、方位環と同じ作りをしている。
- **閉じた Chronos は年の軸を持つ（デスクトップ）。** ボタンの右に短いレール（`#ntl-peek`・
  `js/news-timeline.js` の `buildPeek`）——時計の床（`IntMapTime.min`）から「現在」まで、印は
  `IntMapHistScale.niceTicks`（目盛りと同じ導出）、位置は Year スライダーと同じ写像（`y2p`）、点は地図の
  いまの年。印を押すとその年へ（`IntMapTime.setYear`／「現在」は `setNow`）——パネルは開かない。
  **印と印の間も連続に動かせる**：レールのドラッグ（3 px 以上動いたらスクラブ。動かさない押下は印ならその年、
  印の外ならその位置）と、レール上のホイール（下・右で未来へ）。どれも Year スライダーと同じ 1 つの規則
  （`writeYearAtPos`）で時計を書き、書き込みは 1 フレーム 1 回にまとめる。
  隣の文字に重なる印は実際の描画幅で測って字だけを落とす（目盛りと当たり判定は残る）。
  ポップアップでもカードでもない。携帯では閉じた Chronos 自体が出ない（入口はシート頭の時計）。
- **ポップアップ類**：国情報カード（`country-info`）、国詳細（`country-popup`）、ピン／地名ポップアップ、
  凡例（ドラッグ可）。
- **共有パネルと埋め込み**（`js/map-ui.js` の `share`・`js/embed-mode.js`）：Share ▾ →「共有／リンクをコピー」で
  開くパネルは、最初は**リンクとコピー**（と端末の共有）だけを見せ、**題と一言・埋め込み・画像**は
  「その他のオプション」（`<details class="sh-more">`）に畳んである。埋め込みか画像のタブ、または題・一言を
  名指して開く呼び手（Atlas・`open({tab})`）には畳みが開いた状態で出る。以前の 3 タブ（リンク／埋め込み／画像）の
  中身はそのまま。Share ▾ →「地図のスクリーンショット」は**パネルを開かず**、画像タブと同じ絵
  （`js/map-recorder.js` の `postcard`・凡例と出典入り・既定の形）をその場で保存する（`IntMapShare.screenshot`）。どれも `IntMapBookmark.link()`（アドレスバーを書くのと同じ
  符号化器）を**1つの値として**読むので、別々の地図を述べることはない。タブの上に**題と一言**の欄があり
  （下の「リンクの題と一言」）、リンク・埋め込みコード・画像の 3 つが同じ文を運ぶ。**埋め込みは共有リンクに `?embed=1`
  を足しただけ**（`&interactive=0` で静止画）で、地図の状態の 2 つ目の符号化は無い。埋め込みタブは大きさ
  （`EMBED_SIZES` の 4 つ）とパン・ズームの可否を選び、`<iframe>` コードを**コピーのたびに現在の地図から**作り直す。
  プレビューはそのコードを本物の iframe で起動する（押したときだけ・パネルを閉じると破棄）。
  `<html data-embed>` は `index.html` の最初の script が query から立て、`src/main.js` はそのときだけ
  `js/embed-mode.js` を動的 import する（共有パネルは開いたときに取りに行く）——**通常の起動はこの module を読まない**。
  埋め込み表示は同ファイルの `EMBED_CSS` が**残すものの一覧**（地図・凡例 `.data-legend` / `.koppen-legend`・
  クレジット `#map-credit` と地図内の `.map-credit-view`・起動画面・`#im-embed-bar`）で決まり、それ以外は
  名指さずに隠れる。⚠ **クレジットは残す側にあり、削ってはならない**（埋め込みは「データを描く場所」である）。
  狭い枠でも省略記号で切らず折り返す。読み取り専用＝読者の（`isTrusted` の）click・右クリック・change・
  input・キーは地図内でアプリのハンドラに届かない（パン・ズーム・ダブルクリックのズームだけ通す。
  共有リンク復元の合成イベントは通す）。上端右の帯は時計の瞬間（ライブ／日付・紀元前は
  `IntMapHistScale.dateText`）と「IntMap で開く」。**「埋め込みか」の判定は
  `js/ui-device.js` の `embedded()` 1 つ**で、起動の入口がそれを訊いて埋め込みでは走らない: 両サイドバーを開く・
  アカウントとデータの起動（`bootSupabase`）・既定タブ・セッションの読み書き・ウィジェット板・
  デスクトップの Atlas 暖機（レイヤーパネルのサムネイルは、どの端末でもパネルが表示されたときにしか取らないので
  埋め込みの例外が要らない）。携帯シートの camera padding も 0（`js/mobile-ui.js` `sheetCovers`）。
  国の統計の取得（World Bank）は国の塗り分けが読むので残る。Atlas の `share` は作ったリンク／コードそのものを結果に載せる（`embed:true`・`size`・
  `width`/`height`・`interactive`、それに `title`/`note`——リンクを読む前に題を付ける）。
- **地図の絵葉書（画像タブ）**（`js/map-recorder.js` の `postcard` / `createPostcardTab`）：いまの地図を **PNG 1 枚**に
  合成する——地図（描画の tick の中で読む。タイムラプスのコマと同じ `captureCanvas`）・その瞬間（年として合わせた時計は年、
  それ以外は日付。ライブは「今日の日付」）・題と一言のカード・**地図上の凡例**・描いている典拠と `#map-credit` の
  **出典（必ず焼き込む・切らずに折り返す）**・IntMap の名前・リンク（共有リンクが 1 行に**丸ごと**入るときはそれ、
  入らないときはサイトのアドレス——切ったリンクは別の地図を開くので印字しない）。形は 3 つ
  （`POSTCARD_SIZES`: リンクカード 1200×630・正方形 1080×1080・縦長 1080×1350）。配置は純関数
  （`layoutFrame` の `caption` / `legends`・`layoutLegends`・`layoutCard`）。⚠ **凡例は種類ごとの写しを持たず、
  ページが組んだ DOM のカードをそのまま読む**（`rasterLegend`：各箱の背景色・グラデーション・枠線、ブラウザが置いた
  文字の行、描ける画像、ページと同じ切り抜き）。読者の**取っ手**（入力欄・スライダー・掴む／動かす／リサイズの
  カーソルを持つ要素・文字も見本も持たないボタン）だけを除く——行が `role="button"` の凡例（ケッペン）があるので
  「ボタンだから除く」ではない。取っ手について述べる文も取っ手に含める——札の中の操作部品が `aria-describedby` で
  指す説明（ケッペンの「クリックで強調…」）と、入力欄の名前以外に文字も見本も持たない行（「不透明度 100%」）。
  文言では判別しない。出典は**ソースが宣言する** `attribution` で、座標で置くソース（image / canvas）の宣言は
  MapLibre が落とすので `js/geo-engine.js` がソースとその直列化に持たせる（ケッペン＝Beck et al. 2023, CC BY 4.0）。凡例の列は 1 つの縮尺で右端に並べ、床（0.9）で入らないものは**落として数える**
  （パネルが件数を述べる）。プレビューは保存・共有されるファイルそのもので、形・題・地図が変わると作り直す。
  「共有…」は `navigator.share({ files, title, text, url })`（ファイルを渡せる端末だけ）、渡せない環境では
  「画像を保存してリンクをコピー」を 1 回の押下で行う。タブの module は遅延チャンク（タブを開いたときだけ読む）。
  Atlas `postcard`（`panel.postcard`）は同じタブを開いて作り、ファイル名・大きさ・題・凡例の件数・焼き込んだ出典を
  結果に載せる（共有シートは読者の押下でしか開けないので、送るのは読者）。`share` と `postcard` の結果が言い返す題と一言は
  **Atlas 自身が渡したものだけ**——読者が開いた他人のリンクの題は第三者の文なので、「ある」とだけ述べる。録画中のタイムラプスがあるときは作らない
  （`busy`）。
  **比較ウィンドウがスワイプ（あの頃といま、`Architecture.md` §7.4b）のとき、絵葉書は 2 つの瞬間のカード**
  （`thenNowCard`。`pair:false` でメイン地図だけ）：左にウィンドウの瞬間、右にメイン地図の瞬間（同じ視野）、各面の左上に
  その瞬間と、左はウィンドウが描く層の名前、中央下に題と**見ている場所の名前**（`js/place-dossier.js` の `viewPlaceName`
  ——地点カードと同じ Nominatim の逆ジオコードとキューを、地図の縮尺で訊く。名前が無い海などでは何も書かない）、
  帯に**2 つの地図の出典**（`comparePanes`。Chronos の比較画像と同じ読み）・語標・リンク。形は絵葉書と同じ 3 つ。
  画像タブはそれがどちらの絵かを述べ、スワイプでないときは「あの頃といま（スワイプ）」でスワイプを開く。
- **リンクの題と一言**（`js/map-state.js` の `title` / `note`・持ち主は `js/map-ui.js` の `share`）：共有リンクは
  状態に加えて**意味**を運べる。題（`TITLE_MAX` 字まで）と一言（`NOTE_MAX` 字まで）はプレーンテキストで、
  `captionText` が制御文字と双方向上書き文字を空白にし、**文字単位で**切る（書き手も読み手も同じ規則——手で作った
  リンクもそれ以上を持ち込めない）。URL では `s` の後ろ、最後に付く（それより前のリンクはバイト単位で不変）。
  `restore:'always'`（文字列は落ちる原因になりえないので、落ちた後の再読み込みでも残す）。リンクを開いた人には地図の
  上に控えめな帯 `#im-caption`（題・一言・閉じる）を出し、`document.title` を「題 — アプリの題」にする
  （言語の切り替えでアプリの題が書き直されても、`<title>` を見張って前に戻す）。帯の位置は**測って決める**：
  デスクトップは検索欄の下で、同じ行にある箱（地図の操作群・凡例・埋め込みの帯）を避けた最も広い区間の中央。
  それらの大きさの変化（凡例が出る・畳まれる）を ResizeObserver で見て置き直す。携帯は出典の小札の上
  （小札の高さを測る。シートが全開のときは隠れる）。**ページにも画像にも文字としてしか入らない**（`textContent`・
  `fillText`・入力欄は `.value`）。埋め込みは `EMBED_CSS` の残す一覧に `#im-caption` を持ち、閉じるボタンは出さない。
  ⚠ **共有リンク復元は箱に `__imRestored` を付けて `change` を配る**（`js/session-tabs.js` と同じ）——
  付けないと `js/layer-home.js` の層（EU・NATO・ウクライナ・米大統領選）が「読者が点けた」と読んで
  自分の範囲へ飛び、リンクの `v=` が失われる。
  ⚠ **復元が点けた行は時計を動かさない。** 戦争の行（`js/layer-time-decl.js` の `entry` を持つもの）は
  **読者が**点けたときだけ時計を記録の初日へ動かす。復元の印は `js/war-fronts.js` が `change` の瞬間に読んで
  使い切り、`js/war-layer.js` は時計が戦争の外ならその行を隠して時計が記録に入るのを待つ。
  **地図が自分で送り直す `change`**（`__syn` が立っている間の配信——`js/data-layers.js` の自己修復の off→on、
  `js/layer-time-kernel.js` の配達）も読者の操作ではないので、同じく時計を動かさない。描けずに待った再試行も
  元の要求の出自（復元か・地図自身か）を持ったまま走る。
  `js/layer-time-kernel.js` の門も復元のチェックを読者のものとして通さない。時刻は復元が述べる。
  ⚠ **新しい復元は古い復元の段取りを止める。** 各段（層 700/1800/3200 ms・時計 900 ms ほか）は世代を持ち、
  後から `IntMapBookmark.restore()` が呼ばれると前の復元の残りの段は何もしない（前のリンクの層を新しいリンクの
  時刻で点け直さない）。
  ⚠ **リンクは時刻を含めて完全に適用する。** `tt` は時計が live でないときだけ書かれるので、**`tt` の無いリンクは「今」**
  で、完全な復元は時計を今に戻す。アドレスが地図の状態（`v=`）で開いたとき、`js/session-tabs.js` の保存年はリンクに譲る
  （`IntMapBookmark.carriesState()`）。復元の段取り（約 3.5 s）の間に貼られたリンクは捨てず、終わったときに**その時点の
  アドレス**で復元する（最後の 1 本が勝つ）。状態を共有リンクに書くのはその状態が地図に出ている者だけ
  （気象の予報時刻は気象レイヤーが点いているときだけ）。
  ⚠⚠ **地図の状態には名前の付いた正本が 1 つある——`js/map-state.js` の `MapState`。** 視野（`v`）・共有レイヤー（`l`）・
  時刻（`tt`、旧形式 `ts`）・比較窓（`cmp` / `ct`）・基図（`sat`）・3D 地形（`t3`）・シミュレータ入力（`s`）・

  読むかは **レイヤーごとの宣言 `js/layers/<id>.js`** が述べ（`js/layer-manifest.js` がそこから一覧を導く）、`reorganizeLayerPanel()` はその並びで DOM を毎回並べ替えて
  分類する（`docs/MAP-LAYERS.md` §7.2）。行を作るのは今も各モジュールの `buildUI()`（ハンドラ・凡例を持つ側）で、
  基本表示の 10 行だけは manifest から `js/layer-rows.js` が書く（`src/main.js` が `js/i18n.js` の直後、
  レジストリを読む最初のモジュール `js/data-layers.js` より前に import する）。**一覧を知るために行を数えない**——
  タイル盤・共有リンク・お気に入り・セッション復元は manifest を読み、行からは状態（チェック）と、モジュールが
  組み立てた名前だけを読む。セッション復元は行の出現を `MutationObserver` で待つ（`whenBoxes`・時計を使わない）。
  **レイヤーの ON/OFF はどの経路でも箱の `change` 1つに行き着き、スタイルが受け取れる前に来たものは
  `js/layer-rows.js` の `holdUntilDrawable` が預かる**（document の capture リスナ。manifest が宣言する箱だけ・
  レンダラが在って `canDraw()` が偽のあいだだけ）。預かった箱には後で `change` を**1回だけ**、着いた順に、
  そのときのチェック状態で配る。配る時刻は `whenCanDraw()` の解決で、**MapLibre の `load` には結び付けない**。
  **アプリの起動処理（`js/app-body.js`）・共有リンク復元（`js/map-ui.js`）・セッション復元（`js/session-tabs.js`）も
  `load` ではなく `whenCanDraw()` を入口にする**——`load` は描画の内側で「その時点の全 source が読めた」ときにしか
  発火せず、忙しい地図では何分も来ない。起動処理の待ちは箱が生まれる前に登録されるので、預かったレイヤーより
  先に答えられる（待ちは登録順に解ける）。預かり中の一覧は `window.IntMapLayerHold.pending()`、
  配ったあとまだ要求が走っている箱は `window.IntMapLayerHold.inflight()`。
  配り直す `change` は**誰がその状態にしたか**も運ぶ——配るのは配る時点の状態なので、その状態を作った
  **最後に預かった変更**が `js/data-layers.js` の整合器自身の再発火（`cb.__syn`）なら、配る 1 回もそうとして
  出す（印が落ちると整合器はそれを利用者の操作と読み、利用者と争わないために自分の再発火の後半を取りやめる）。
  整合器（定期の点検と、ON にした 2.8 秒後の点検）は**預かり中の箱と描けない地図を判定しない**——
  そのあいだ「描かれていない」のは描く機会が無かったからで、失敗ではない。
  **配られた後、行が始めた要求（描画の待ち・取得・構築の梯子）がまだ終わっていない箱も判定しない**——
  `toggleLayer(id,on)` は各枝の最後の非同期の鎖を Promise として返し、行の `change` ハンドラがそれを
  `js/layer-rows.js` の `layerInflight`（箱ごとの取得中の登録。成功でも失敗でも settle で外れ、新しい要求が
  古い要求を置き換える）に渡す。2.8 秒後の点検は取得中なら `idle(id)` を待って settle 後に 1 回だけ見て、
  定期の点検は取得中の箱を数えない。遅い行の一覧はどこにも無い——行自身が要求を返す。
  登録は時計で終わらせないので、**要求の中の取得が自分の期限を持つ**（雨雲レーダー・火災・海底ケーブル・
  合計特殊出生率の取得は `js/fetch-deadline.js` で読み、秒数は `js/proxy-fetch.js` の `clockFor` が host ごとに
  答える。期限切れは取得できなかったとして各枝の既存の失敗の経路へ流れる）。
  詳細は `docs/MAP-LAYERS.md` §7.2。
- **レイヤーの「描けなかった」は状態として 1 か所が持つ——`js/layer-state.js`（`window.IntMapLayerState`）。**
  箱ごとに `loading` / `ok` / `failed`（答えが届き、それが「否」だった——状態・拒否・読めない本文・描画器の拒否）/
  `unobserved`（時間内に何も届かなかった＝`js/fetch-deadline.js` の `isUnobserved`。「確認できなかった」は
  「失敗した」ではない）/ `nodata`（データは在り、**時計の瞬間について述べるものが無い**——例: ライブ衛星の
  軌道要素はどれも元期の前後数日しか述べないので、時計が 1991 年なら描く衛星は 0。失敗ではないのでトーストせず、
  pill は灰色）と、理由（共有の読み手が投げる `reason`：`timeout`・`network`・`http`＋`status`・`parse`・
  `unsupported`・`worker`）・伝えた文・時刻を持つ。呼び手自身の中止（`aborted`）は状態にならない。
  入口は共有の経路: ⑴ `layerInflight` は追跡した要求を全部ここにも渡す（`inFlight(watch)`）——reject した要求は
  理由つきで**残る**（以前は `p.then(clear, clear)` で成功と同じく消えていた）⑵ 自分で失敗を捕まえて箱を外す行の
  腕は `report(箱, err, {told:true})` ⑶ どのモジュールも `window.IntMapLayerState.report(id, 'failed', {reason})`。
  出口は 3 つで同じ記録を読む: 行（`.lyr-state` の pill を名前の後ろに、en+jp。`js/map-ui.js` のタイル
  `.lst-tile[data-lid]` にも同じ pill——デスクトップのサイドバーと携帯のタイル表示ではタイルが唯一の顔。作り直された
  タイルには、失敗が在るあいだだけ動く観測器が付け直す）、読み上げ（状態に**入ったときに 1 回だけ**
  `js/notify.js` へ。行がすでにトーストした失敗は `told` で黙る）、Atlas（`snapshot()` / `get(id)` / `heals()`＝
  DOM を持たない素のデータ。`IntMapLayerAudit.states()` も同じもの）。**消えるのは箱の次の `change` だけ**
  （やり直し、または利用者が外した）。自己修復の直し（`IntMapLayerAudit.log()` に書く全件）も `healed(id, fix)` で
  ここに残る。
- **通知は 1 本——`js/notify.js`（`window.IntMapNotify`）。** 要素は `#ai-toast`（`.sat-toast`）1 つ、時計は
  4,600 ms 1 つ、live region は 1 つで中に 2 声（`role=status`/`aria-live=polite` と、`urgent` の呼び手だけが使う
  `role=alert`/`aria-live=assertive`）。どちらの声も最初の文より前から文書に在る。表示中に同じ文が来たら時計を
  延ばすだけで書き直さない（書き直しは 2 回目の読み上げ）。`aiToast`・`satToast`・`imToast`（→aiToast）・
  `_toast`（→imToast）・各 `toast`（→imToast、`js/navigation.js` だけは直に `urgent`）・`majorToast` は残して委譲する。
  `majorToast` だけは見た目が別で、シミュレータ自身の「速報」カードを画面上部に残し（その HUD は z-index 6300 で
  トースト層 3000 より上）、文だけを `visual:false` でこの region に渡す。
- **孤児の掃除（`_sweepOrphanLayers`）と表示状態の監査（`IntMapLayerAudit`）に周期実行は無い。** 不一致は
  スタイルの変化（MapLibre は描画の中で `styledata` を撃つ——idle でなくても）・箱や行の変化・タブの復帰の
  後にしか生まれないので、その事象で走る: `idle`・`styledata`（掃除は 2,500 ms、監査は 10,000 ms に 1 回へ束ねる
  ＝旧周期より頻繁にはならない）・`visibilitychange`・`#layer-dropdown` への**箱を含む**要素の挿入・監査は
  `whenCanDraw()` の最初の 1 回。監査の 2 回連続判定の 2 回目は、**1 回目に当たった箱があるときだけ** 10 秒後に
  1 回見直す（当たりが無ければタイマーも無い）。回数は `IntMapLayerAudit.runs()` が契機ごとに数える。
  ラベルの持ち上げは `js/label-occlusion.js` が `idle`・`styledata` で走らせるのでここでは繰り返さない。
- **箱がどの描画レイヤーを持つかは、宣言か因果で決まる——同じ数秒に現れたことでは決まらない。**
  `IntMapLayerAudit.owned(箱)` は ⑴ 表（`js/data-layers.js` の `STATIC` / `BASE`、`_registerLayerOpacity` が
  埋める `_imAuditReg`）が名指すもの、それが無ければ ⑵ **その箱の OFF の `change` を配送している最中に、
  その箱自身のハンドラが描かれていた状態から隠した・外したレイヤー**（`window._imLayerOwn`。すでに隠れていた層を
  共有の処理がもう一度隠しただけの書き込みは数えない。学習器は `js/layer-rows.js` の `ownershipLearner`）。エンジンの窓口
  `GE().layers.onVisibility` が表示を変える書き込み（add / remove / setVisible / setLayout の visibility）を
  同期的に知らせ、書き込みは**配送がまだ返っていない**（`eventPhase !== 0`）最も内側の箱の change に帰属する。
  時計の移動・描画可能になった瞬間・fetch の着地・Atlas の描画はその同期配送の中では走れないので、名前が何で
  あれ箱に帰属しない。ON 側は学ばない（共有の処理が箱の持ち物でない層を出す——`_applyBorders` は時計が
  旅しているあいだ時代の国境を出す）。別の箱に表が与えた層はこの箱のものにならない。箱は最初の OFF で
  学ぶので、それまで表の無い箱の `check()` は null（「判定するものが無い」）。
  OFF の箱で学んだ層がまだ描かれていれば監査が隠す（ON の非同期処理が OFF の後に着いた場合）。
  ⚠ Atlas の `layerCatalog()` はまだ `#layer-dropdown` を歩く。manifest 側の入口は `catalog()`。
  **Active layers** は `_refreshActiveLayers()` がオン中のレイヤーをチップで出し、常に**上部 sticky**の
  先頭要素にいる（固定高1行の横スクロール。空でも "(0)" で常時表示＝高さが動かない）。
  ⚠ `reorganizeLayerPanel()` は DOM を大量に並べ替えるので、タップ中に走ると行がずれて誤タップの原因になる。
- **重なり順の持ち主は1つ**——`js/ui-stack.js`（`window.IntMapStack`）。浮遊ウィンドウ同士の順と、
  「いま使っているパネル」の印の両方を、**document の capture リスナー 1 本**で決める。
  **ウィンドウの重なり順**は `order(el)`（`js/window-manager.js` の `bringToFront` はこれを呼ぶだけ）——触った順の
  **順位**を `calc(var(--z-window) + n)` としてインラインに書き、上限は `--z-shell-front` の 1 つ下
  （帯の端は `level()` で**スタイルシートから読む**。JS に 2200・2599・2650 は無い）。pointerdown が
  入った登録済みウィンドウは外側から順に並べ直すので、入れ子の内側が上に来る。
- **触ったパネルが最前面に来る**（`js/ui-stack.js` の `act` / `panelOf` / `front` / `back`）。pointerdown / wheel / focusin /
  keydown が当たった要素から**最初の positioned 祖先**を探し、さらに上に**重なり文脈を作る positioned
  祖先**（fixed/sticky、または z-index・transform・filter・opacity を持つ absolute/relative）があれば
  **その一番外側**へ移して、そこに `.im-front`（`z-index:var(--z-front) !important`＝2650・デスクトップ幅のみ）を付ける
  ——内側の要素の z-index は親の文脈から出られないので、印は帯の中で競う要素に付かなければ効かない
  （検索欄の中の結果一覧に付いて、凡例に押し負けていた）。地図と外殻（`NOT_PANEL`）で止まる。
  印は常に1つで、サイドバーを触ると外れる。
  ⚠ **これは「上げる」印であって、下げる手段ではない。** モーダル (`.modal-overlay` は 9999) の
  ように**この帯より上にいる層は、この機構の対象外**——`aboveBand()` が resolved z-index を `--z-front` と比べて
  除外する（綴りの一覧ではなく実測。後から足した重ね物も自動で入る）。除外しないと、設定の上に開いた
  規約ダイアログが 1 回のスクロールで 2650 へ**下げられ**、設定の背後に沈む。
  ⚠ **祖先の `overflow` に切られる形（検索欄の結果一覧が切られていた）は、重なり順では直らない。** `IntMapStack.clipOf(el)` が
  包含ブロックの鎖をたどって、要素の箱を切っている祖先と軸を返す（静的な祖先は absolute の箱を切らず、
  fixed の箱は transform／filter の祖先にしか切られない）。`tests/map-a11y-structure.spec.js` ⑤ が
  検索結果について、⑦ がウィンドウの順位を実ブラウザで訊く。
- **テキストに影を付けない**（`text-shadow:none` を徹底する）。

  絵文字に戻すこと・画像を消すことは**その列も同時に空にする**（片方だけ変えると画面どうしが食い違う）。
- **メニュー（`#acct-modal`）は `openAccountMenu()` が1度だけ組み、開くたびに塗り直す。**
  iOS の設定画面の形——身元の見出し（アイコン・メール・**どの方法でログインしているか**・admin）、
  次にラベル付きのカードが **AI 利用 / アイコン / セキュリティ / あなたのデータ / アカウント**、破壊的な2つが最後。

- **AI の残り回数はここと設定パネルの2か所に出る。** 数を決めるのは **`js/ai-core.js` の

- **どの方法でログインしているかはセッションが述べる**（`app_metadata.provider`）。

  ⚠ `HOST.user` は**2か所で組まれる**（`onAuthStateChange` の同期版と `refreshCurrentUser` の
  充実版）。両方が `_sessionProvider()` を呼ぶ——片方しか書かない欄は、遅い方が終わるまで（あるいは
  通信が死んでいれば永久に）**欠けたまま読まれる**。
- **「あなたのデータ」のカード**（account-data-center / my-places）は 3 行——**ライブラリ（マイプレイス）**（`js/my-places.js`
  のシート）・**IntMap が保持しているあなたのデータ**（`js/account-data.js` のシート）・**データのコピーを
  ダウンロード（JSON）**。どちらのモジュールも**押されたときに読み込む**（起動経路に無い）。
  目録のシートは DB の `account_data_inventory()` をそのまま描く——「あなたが作ったもの」「IntMap が利用について
  記録したもの」「保持していない種類」に分け、各行を開くと**何か・なぜ・いつまで**が出る。**表の名前を UI は
  1 つも持たない**（後で足された表は、外部キーと説明の 1 行ができた時点でここに出る。説明が無ければ表名のまま出て
  隠れない）。書き出しは `export_account_data()` の JSON をそのまま `intmap-account-<日付>.json` として渡す。
  マイプレイスのシートは「地図の中心を保存」（名前・コレクション・メモ）・コレクションごとの一覧（押すと地図に
  ピンとして出す）・行の中での名前変更・2 度押しの削除。**ピンのポップアップにも「保存」**があり、ピンの題と説明が
  場所の名前とメモになる（保存済みなら「マイプレイスに保存済み」）。地図に出した場所は**セッションのピンそのもの**
  （`HOST.addPin`）——ポップアップ・オブジェクト一覧・計測・削除が同じに効く。
  **同じシートの「この地図を保存」**（collection-workspace）は、いまの地図を共有リンクと同じ形（`MapState.hash()`）で
  名前・コレクション・メモつきに保存し、一覧では「地図」の印つきで場所と同じコレクションに並ぶ。押すと**共有リンクを
  貼ったときと同じ復元**（`IntMapBookmark.restore({shared:true})`）で開く。外から来た地図は codec に**書き直させてから**
  保存し開く（codec が書かない欄は残らない）。各コレクションの見出しと「すべて」に**「共有」**があり、開くと
  公開すると何が見えるか（場所の名前・メモ・位置と地図。アカウントやメールは見えない）を述べてから
  「閲覧専用リンクを作成」（`data-effect="outward"`）、公開中は「公開中」・リンク・「リンクをコピー」・
  2 度押しの「公開をやめる」。**公開リンク（`?collection=<token>`）を開いたページ**は `js/auth-ui.js` が
  `js/shared-collection.js` を読み込み、場所をピンで出して枠に収め、左下のカード（閲覧専用・題・場所と地図の一覧・
  「マイプレイスに追加」・「閉じる」）を出す。閉じるとアドレスから `collection` だけを外す。未ログインで
  「マイプレイスに追加」を押すとログインへ進み、戻ったあとに**同じタブで**頼まれた写しを 1 度だけ行う
  （ログインはクエリを持ち帰らないので、トークンは `sessionStorage` で待つ）。
  **このシートが「ライブラリ」**（map-document-unify）——保存した地図の行は**地図ドキュメント**（`js/map-doc.js`）として
  種類の札（地図／マイマップ／ツアー／Atlas の回答）を持ち、複数段のもの（ツアー・複数の回答のブリーフィング）は押すと
  **授業モードで再生**する（段を `js/tours.js` の `t` に詰めて `startTour('custom')`——自作ツアーと同じプレイヤー）。
  行の下の操作は意味のあるものだけ: 「ツアーとして再生」「ワークシートを印刷」（再生してから `js/tour-worksheet.js`）・
  「コレクション…」（行の中で別のコレクションへ移す。`window.prompt` は使わない）。**「この端末」の節**は
  アカウントに未保存のもの——このブラウザのマイマップ（`js/my-map.js`）・作成中のツアー（`js/tour-builder.js`）・
  このタブで Atlas が作ったツアー（`js/tour-player.js`）——を**それぞれの持ち主に訊いて**並べ（保存場所の鍵をシートは
  知らない）、「アカウントに保存」（上のコレクション欄に名前があればそこへ）。マイマップのパネル・ツアー作成・
  Atlas のノートとブリーフィングの「アカウントに保存」「地図として保存」は、ホストを持たない場所から
  `js/bus.js` の `intmap-open-library`（`{ doc }`）を出し、`js/auth-ui.js` がライブラリを開いてその文書を保存する。
  公開リンクのカードでも複数段の地図は再生され（授業モードがカードを隠し、終えると戻す）、「マイプレイスに追加」は段ごと写す。
- **確認と入力はシートの中で行う**（`_acctAsk()`）。`window.confirm` / `window.prompt` は使わない
  ——スタイルも翻訳も効かず、携帯では「127.0.0.1 says…」と**出自の名前**で出る。
- **パスキー**（ログイン画面のボタンと、セキュリティのカードの一覧・追加・削除）は SDK の関数と
  ブラウザの WebAuthn の**両方が在るときだけ**出る（`_passkeysAvailable()`）。失敗は `_pkFailure()` が
  SDK の返すエラーから3つに分ける——**取消**（出し直す）／**失敗**（通信・5xx。ボタンは残す）／
  **この origin では使えない**（relying party の拒否・エンドポイントが無い。そのセッションの間は
  パスキーの操作を**全部引っ込める**）。どれでも「メールアドレスとパスワードでログインできる」と述べて
  パスワード欄にカーソルを移す。一覧の取得失敗は「まだありません」ではなく失敗として述べる。
  プロジェクト側の RP 設定は `docs/SECURITY-ARCHITECTURE.md` §9。

### 8.1.3 IntMap のいま（状態ページ）と、失敗が名指すデータ元

読者の地図に効く事実のうち、**それまで CI の中か 1 行の pill の中にしか無かったもの**を 1 枚に集めたページ。
設定 ▸ **IntMap のいま**（`#btn-status-page`）・Atlas（`diagnose` の結果に同じ内容が文で入る／`module` が
`IntMapStatus` を名指しで開く）から開く。実装は `js/service-status.js`（**初めて使われたときに取りに行く**——
起動の経路には載らない）。開くための握りは起動済みの `js/layer-state.js` が持つ `window.IntMapStatus`
（`open` / `close` / `toggle` / `describe`）で、設定のボタンへの click はそこの document リスナー 1 本が受ける。

- **4 つの節。** ⑴ この端末——オンラインか、**この端末に IntMap の本体が保存されていてオフラインでも開けるか**
  （`sw.js` の `intmap-shell-<build>` が在るか）、保存量（`navigator.storage.estimate()`）。⑵ 地図のレイヤー——
  `IntMapLayerState` が「読み込めない／応答なし／この日時のデータなし」とした行と、その理由。⑶ データ元
  （毎晩の確認）——応答しなかった提供元ごとに、**いつから**・**最後に応答したのはいつか**、全件は開閉の中。
  ⑷ Atlas の品質評価——最後に評価された日時、または一度も測れていないこととその理由。
- **見出しは「いま本当である最も悪いこと」**（オフライン ＞ 描けないレイヤー ＞ 応答しないデータ元 ＞ すべて動いている）。
- **毎晩の確認は `data/service-status.json`。** `scripts/build-service-status.mjs` が `upstream-liveness` の最新の
  結果と `atlas-eval.yml` の実行記録から作り、`.github/workflows/tle-refresh.yml` の bot PR が 1 日 2 回運ぶ
  （運用側の読み方は [`docs/MONITORING.md`](../MONITORING.md) §1d・§1e）。出自はファイル自身が先頭で述べる。
- ⚠ **測っていないことは述べない。** 測定に載っていないホストは「動いている」とも書かず**触れない**。
  読めなかった記録・回線の無い晩・報告を残さなかった評価は、緑でも赤でもない**灰色の文**で「読めなかった」
  「何も測れていない」と言う（`.agents/rules/one-pass-or-a-reason.md` §5）。「いつから」は記録が観測した夜の
  時刻だけで、streak から言える以上を推して書かない。
- **レイヤーの失敗は、その要求が訊いたデータ元の夜の記録と結ばれる。** 共有の読み手（`js/fetch-deadline.js`・
  `js/proxy-fetch.js`）が投げるエラーに**要求の URL** を載せ、`js/layer-state.js` が記録に残す。失敗に入った瞬間に
  `upstreamRow(url)` を訊き、行の pill の文と Atlas が読む記録（`snapshot()` の `upstream`・`detail`）に
  「このデータ元は 10月2日 から応答していません（毎晩の確認・最後に応答 10月1日）」が足される。
  中継（`?u=https://…`）を通った要求は**運んでいる先**のホストで結ぶ。レイヤーとホストの対応表は無い。
  ⚠ **中継の梯子（`fetchViaProxy`）は投げずに `null` を返す**ので、失敗は呼び手の `note.failure` に書く
  ——`{ reason, status?, url }`（`url` は呼び手が訊いた上流）で、`classify()` がそのまま読む形。理由は
  状態コードがあればそれ（`http`）、全段が時間切れなら `timeout`、文書でない答えなら `parse`、
  訊ける段が 1 つも無ければ `unrelayable`、それ以外は `network`。人工衛星の行は、何も描けなかったときに
  これを受け取り、CelesTrak を名指す。
- **出典の一覧も同じ記録を読む**（アプリ内の出典ダイアログと `sources.html`）。出典のリンクのホスト、
  またはその下のホスト（`www.` を除いたサイトの下）が応答していなければ、その行の説明の下に同じ文が出る。
  ⚠ 登録ドメインを推測して広げない——`*.nasa.gov` の 1 つが落ちても NASA の出典すべてには付かない。
- 文は en + jp。データ元の名前は `scripts/outbound-hosts.json` の `what` / `whatJp`（夜の確認が訊く全行が両方を持つ）。
- **記録（時系列）。** ⑶ の節は**昨夜だけでなく測った全晩**を持つ——晩ごとの「測れた確認のうち応答した割合」の棒
  （全部応答＝緑・1 つでも応答しない＝橙。色を決める閾値は無い）、各データ元の帯（1 晩 1 マス）と
  「直近 N 晩の確認のうち M 晩で応答」。出典の一覧（アプリ内・`sources.html`）も、照合できる全行に同じ記録の
  文を出す（落ちた行だけでなく）。確かめられなかった晩・訊いていない晩は分母に入れない。
- **⑷ のセッション不要の半分。** ライブの評価が測れない夜も、記録した手順の再生と「問いの言葉が要る能力に届くか」
  （`atlasEval.offline`）は測られ、件数と「答えの評価ではない」が行に出る（[`15-ops-quality.md`](15-ops-quality.md) §15.6）。
- 携帯では `.modal-overlay` の規則どおり下からのシートになる。行は 44 px 以上。

### 8.1.5 「どこ＋いつ」——場所と時刻を 1 つの欄で

**読み方は `js/where-when.js` の 1 つ**で、検索欄（携帯のシートも同じ欄）・コマンドパレット・Atlas `time.whereWhen` がこれに訊く。
どれも初めて数字か「元年」を含む文が打たれたときに取る（起動の経路には無い）。

- **時刻は構文として読む。** 紀元の語（BC・AD・紀元前・西暦・v. Chr.…）と月名は登録簿の全言語について `Intl.DateTimeFormat`（CLDR）
  から、和暦の元号は ICU の japanese 暦（`ja-u-ca-japanese`、大化以降）を標本して読み戻す。手で書いた月名・元号の一覧は無い。
  書いてあるのは CLDR の `alt="variant"` の BCE / CE（`Intl` が出さない）と、場所と時刻のあいだの機能語（の・に・頃／in・at・circa…）だけ。
  読める形: 末尾の 3〜4 桁の年（今日より後は年ではない＝郵便番号）・紀元の語つきの年・月名つきの年と日・ISO（`1868-01`・天文年の `-0043-03-15`）・
  `n年m月d日`・和暦の `元号n年`（年に換算。1873 年より前の月日は太陰太陽暦で、変換器が無いので変換せず「年だけを使う」と述べる）。
  先頭の数字は年にしない（番地が先に来る）。元号として知らない漢字の語に付いた 1〜2 桁の年（「康熙5年」）は西暦と読まず、変換できないと述べる。
  日付は書かれたとおり、時計の数える暦（`Date` の先発グレゴリオ暦）で読む——ユリウス暦は換算しない。
- **場所は既存の読み手から。** 検索欄の `localFuzzyPlaces`、歴史都市名（`IntMapHistCities.records()`——各期間の全言語の名と今日の綴り）、
  Pleiades（`IntMapHistPlaces.records()`——題・形・ローマ字の各異形）。歴史都市の記録が自分の守備半径の中に地名辞書の行を持てば 1 行にまとめる。
  その年に記録が別の名を述べていれば行の副題に「この年の名: 江戸」と出す（`eraNameAt`）。
- **解釈が 1 つなら 1 回で、複数のときだけ選ばせる**（`.agents/rules/one-pass-or-a-reason.md`、Atlas と同じ規則）。行は「場所 · 時刻」で、
  打っているあいだから見える（携帯は打鍵ごとの候補、机上は検索ボタンのカード）。選んだ行は飛び（検索欄と同じ `gotoPlace`）、マスタークロックを合わせる（年は `setYear`・
  月はその 15 日・日はその日の正午 UTC）。時計が過去にあることが歴史地図の表示そのもの（国境・地方区分・都市名・Pleiades が追う）。
  場所の無い時刻（「1914」）は「1914 へ移動」の 1 行で時計だけを動かす（4 桁だけの文は地名としても引く）。
  検索欄の Enter: 場所の無い時刻は **その場で時計を合わせる**。場所があれば、名前そのものが打った場所である候補が 1 か所に決まるとき
  （端末の行と歴史の記録の行。1 つの都市の写しは記録の守備半径で 1 か所に数える＝`samePlace`）は **最初の Enter で飛んで時計を合わせ**、
  ネットワークに訊かない。決まらなければ 3 つのジオコーダーを待ち、それでも 1 か所ならそこへ、**複数ならカードを残して選ばせる**（時計も地図も動かさない）。
- Atlas `time.whereWhen`（`{query, pick?}`）は同じ `interpret` を通し、名前そのものの候補が 1 つ（または場所の無い時刻）なら適用し、
  複数なら番号つきで返して何も動かさない（`pick:n` で選ぶ）。

### 8.2 Panels タブ（ドック）

設定「凡例・ツール窓の表示」→「サイドバーのタブにまとめる」（既定オフ）。実装は `js/window-manager.js`。

- **入るのは「オンになっているもの」だけ。** 判定は所有者が書く**インライン `display`**
  （`js/data-layers.js` は凡例を `legend.style.display='flex'/'none'` で開閉する）。
  MutationObserver が `style` / `class` / `hidden` を**要素ごとに**見ており、**オフにすると地図へ戻る**。
- **ドック中はドラッグもリサイズもしない。** ⚠ **ドラッグ実装は2つある**——`js/window-manager.js` の
  `makeDraggable` と `js/data-layers.js` の `wireDrag`（凡例専用の委譲ドラッグ）。**両方**が
  `im-docked` クラスを見る。⋮⋮ のグリップは CSS で隠す（嘘をつく余地を残さない）。
- ⚠⚠⚠ **辺のリサイズは要素の listener、角のリサイズは document の capture。** `border-radius` は
  **当たり判定も切る**ので、丸い角の内側数 px では `elementFromPoint` が返すのは**下にあるもの**
  （地図の canvas）であり、要素に付けた listener には**原理的に届かない**。当たり幅 `M` を上げても
  足りない画素は要素の外にあるので直らない。だから角だけは document で受け、`getBoundingClientRect()`
  との**座標**で判定する。⚠ **角だけ**（辺まで document で取るとパネルの縁 9 px のクリックを全部奪う）、
  ⚠ **z 最上位の窓が勝つ**（`bringToFront` が保つ順序）、⚠ カーソルは `document.body` に書いて
  **角を出た瞬間に消す**（地図の上に残ったリサイズカーソルは、直した欠陥より悪い）。
- **剥がすのは幾何プロパティだけ。** `_flatten()` が `position/left/top/width/height/transform/
  z-index/margin/resize` などを `removeProperty` する。⚠ **`display` は剥がさない**
  （所有者が持っている開閉の状態を奪わない）。
- **`_undockOne` は `_dockOne` の厳密な逆。** 保存した文字列から**幾何だけ**戻す
  （全部戻すと、監視が再びドックへ入れる無限往復になる）。
- **列の中でスクロールする箱は作らない。** `*-scroll` / `*-body` / `*-list` に対して
  `max-height:none; overflow:visible` を宣言してある（`css/intmap.css`）。
- **ドック中は最小化で始めない。** 携帯の凡例自動折りたたみは「地図の上に浮いている凡例が地図を隠す」
  ために書かれたものなので、ドック中は走らせず、ドックする瞬間に開く。
- **携帯では列が画面の左右いっぱい。** `#docked-feed` がシートのパディングを打ち消す。
  シートの高さの所有者は `--sheet-h` ただ1つ。

### 8.3 パネルとウィンドウの作法

- **UI の状態はキャッシュせず、持ち主に訊く。** 各モジュールは `isOpen()` / `close()` を持ち、
  ツールカードは行に `mod:'IntMapX'` を1つ持って毎回呼ぶ。**出口を2つにしない**（既存の ✕ も同じ
  `close()` に付け替える）。
- **開いたことは「教えてもらう」。** 遅延チャンクのモジュールは押してから開くまでに秒かかるので、
  押した直後の同期も `setTimeout` も間に合わない。`OS.exec` が返す**到着の Promise** に繋ぐ。
- **動く障害物の位置は実測する。** サイドバーのように開閉するものを定数で避けない
  （`placeClear()` が覆っている物の矩形を測る）。
- **進捗バーは1種類。** `var(--prog-grad)` の塗り幅＝割合 ＋ ％表示。`busy()` / `set(f)` / `done()` の
  3状態だけ。⚠ 割合が出せないなら**上流を直す**（不確定モードを足さない）。
- **フォーム部品（`input` / `select` / `textarea`）の名前は、部品を作る場所が付ける。** 隣に語が
  書いてあるなら部品と結ぶ（`<label for>`、語と部品を包む `<label style="display:contents">`——
  行の flex 配置を変えない——、または `aria-labelledby`）。語が画面に無いなら、作る側が知っている意味
  から `aria-label` を付ける。レイヤー行の不透明度スライダと日付欄は「自分の語（翻訳キー付きの
  `aria-label`）＋行のレイヤー名 `#lyrname-<id>`」を `aria-labelledby` で**参照**するので、言語が
  変わっても画面の文字と同じ経路で名前が変わる。凡例の不透明度行（`.dl-op-row`）は3つの組み立て
  （`js/data-layers.js` `ensureLegendOpacity`・`js/weather.js` `opRow`・`js/waves.js` `opRow`）が
  同じ形で、％表示は名前に入れない（ドラッグのたびに名前が変わるため）。⚠ 包む `<label>` の中に
  `‹` ボタンがある日付行では、`<label>` はボタンを名指してしまう——その形では `aria-labelledby` を使う。
  Atlas の命名掃引（`_uiNameSweep()`）は名前の無いものを後から拾う補助であって、この規則の代わりでは
  ない。門は `tests/form-control-names.spec.js` ①（各レイヤー系統を1枚ずつ点けた状態で DOM の全部品。
  描画されている部品はブラウザの accessibility tree に訊き、されていない部品に当てる規則がその答えと
  一致することも同時に測る）と ③（ツールの入口——Layers の Tools 欄 `.lst-toolbody` のボタン全部と、
  携帯の tools sheet が名指す地図ツールバーの実ボタン——を**実体から見つけて1つずつ**押し、開いた物の
  部品を読んでから閉じる。シミュレーターを同時に2つ動かさない）。
- **キーボードのフォーカスは、全ての操作部品で 2 px のリングとして見える。** `css/intmap.css` の
  テーマ定義の直後にある `:where(…):focus-visible` の規則 1 つが `outline:2px solid var(--focus-ring)`
  を `!important` で書く——部品ごとの `outline:none` が基底の状態（`:focus` ではない）に書かれていて、
  特異度が (0,4,1) まであるため。`outline-offset` は `!important` にせず一覧も `:where()` なので、
  自前のリングを持つ部品（`.wgt-*`・`.rtp-*` など、どれも同じアクセント色）は後の規則の offset を保つ。
  `--focus-ring` はアクセント（`--primary-color`）で、カードに対して両テーマで 3:1 以上。
  ⚠ `:focus-visible` なので**マウスで押したボタン・select にはリングが出ない**。ただし文字を打つ欄は
  ブラウザがクリックでも `:focus-visible` とみなす——枠の無い欄を持つ検索ピル（`.search-bar`・
  `.map-search`）では欄はリングを描かず、ピルの `:focus-within` が 1 px の枠＋1 px の輪＝2 px の
  アクセントの縁を描く。門は `tests/ui-a11y-polish.spec.js` ①（1280 px・初回訪問の状態で Tab を
  45 回押し、到達した部品すべてのリングの太さと色を測る。母集合は Tab が届いたもの）。
- **アクセントには 2 つの役があり、トークンも 2 つある。** `--primary-color` は**文字としての**
  アクセント（文字・枠・リング・アイコン）、`--primary-fill` は**白い文字を載せる面としての**アクセント
  （ボタン・チップ・選択中のピル）。ライトは `#0069db` で、白いカードに 5.19:1・`--bg-color`
  （`#f5f5f7`）に 4.77:1・カードの上の `--input-bg`（`#f2f2f2`）に 4.64:1、その上に白文字でも
  5.19:1 なので、ライトの面はアクセントそのもの。ダークの文字は `#0a84ff`（`#1c1c1e` に 4.66:1）で、
  白文字の面はそれに黒を 15 % 混ぜたもの（`color-mix(in srgb, var(--primary-color) 85%, #000)`。既定で
  `#0970d9`、白文字 4.85:1）——暗いカードの上の文字（相対輝度 0.228 以上が要る）と白文字の面
  （0.183 以下が要る）は 1 つの値では両立しないため。混ぜて**導く**ので、利用者が選んだアクセントも
  面では同じ色相のまま暗くなる（選んだ色そのもののコントラストは保証しない）。
  ⚠ **アクセントで塗る背景は、CSS・JS のインライン style・index.html のどこでも `--primary-fill` を読む。**
  ダークの選択中セグメントは `#fff` 地に `#111`。門は `tests/ui-a11y-polish-checks.test.mjs` ③〜⑦
  （スタイルシートのトークンと規則から比を計算し、⑥ は `background` を文字用のトークンで塗る箇所を
  コード全体から探して 0 件であること、⑦ はアクセント文字が載る灰色の面を規則から見つけて全部測る）と
  `tests/ui-a11y-polish.spec.js` ①（画面上でアクセント色の文字を持つ要素すべてを、合成した背景に
  対して測る。ライトとダーク）。
- **モーダルは 1 つの契約に登録する——`js/dialog.js` の `window.IntMapDialog`。** 需要に応じて作る面は
  `open(root, opts)`、ページに居て持ち主が `style.display` や class で出し入れする面は `adopt(root, opts)`。
  登録された面は、パネルに `role="dialog"`・`aria-modal="true"`・名前（`labelledby`／`label`、無ければ
  面の最初の見出し）を持ち、**Escape は一番上の面だけを、持ち主の閉じる関数で閉じる**（設定の「変更を
  破棄しますか」はそのまま訊く）。Tab／Shift+Tab は一番上の面の中を巡り、閉じると開く前に
  フォーカスがあった所へ戻る（開く前に blur する持ち主のために、ダイアログの外で最後に focus を受けた
  要素を覚えている）。開閉は**観測**する——登録簿は要素そのものの style／class／hidden と親の子の
  出入りを見て、`display`／`visibility` で開いているかを判定する（画面外に待機する携帯のシートは
  持ち主の `isOpen` 述語）。⚠ **「モーダルが開いているか」は `IntMapDialog.anyOpen()` だけが答える。**
  サイドバーの Esc（`js/app-body.js`）とワークスペースの Esc（`js/workspace.js`）はこれに訊き、
  選択子の一覧を持たない。一文字のキーボードショートカット（`js/keyboard-shortcuts.js`）もモーダルの
  背後には届かない（「?」だけはヘルプを開閉する。設定で全部を切れる——下の「一文字のショートカットは切れる」）。登録している面: 設定・支援・規約・出典・投稿・
  画像の拡大・公開プロフィール・アバターの切り抜き・フィードバック・不具合報告・ショートカットのヘルプ・ウィジェットの
  追加・AI レポート・時系列・相関・企業の詳細・プレイグラウンドのカード・初回の案内・
  アカウント（ログイン・アカウント・確認）・携帯の 2 枚のシート。
- **押せるものはキーボードでも押せる。** クリックで動く `<div>`／`<span>`／`<td>`／`<img>`／`<li>` は、
  文字列で組むなら `role="button"`（または `option`／`switch`／`radio`…）と `tabindex="0"` を書き、
  コードで作るなら `IntMapDialog.makeActionable(el)` を通す。Enter／Space を押下に変えるのは
  `js/dialog.js` の委譲リスナー 1 つで、押下は `el.click()`——**クリックと同じ処理しか起きない**。
  `aria-sort` を述べる列見出しは、表の見出しのまま並べ替えの操作になる。レイヤー欄のタイルは両方の
  形とも `role="switch"` で、見た目の `.on` と `aria-checked` は `tileOn()` 1 か所が同時に書く。
  地名検索の結果は、欄から操作する listbox（`IntMapDialog.listbox`）——↓↑ で行を選び Enter で
  決める。欄に `aria-activedescendant` がある間、Enter は検索し直さない。行を選んでいないときの Enter は
  検索して先頭の候補へ飛ぶ（IME の変換確定の Enter は除く。規則は `12-fragile.md` の地名検索の節）。
  門は `check:static` の `keyboard-reach` 規則（`scripts/keyboard-reach.mjs`・台帳
  `tests/keyboard-reach-baseline.json`）と `tests/a11y-shared-dialog-checks.test.mjs`。
- **`prefers-reduced-motion: reduce` では、カメラは動くが飛ばない。** `js/geo-engine.js` の facade
  （`camera.flyTo`／`easeTo`／`fitBounds`／`zoomTo`／`zoomIn`／`zoomOut`）が `duration:0` を渡す——
  行き先も、動くかどうかも変えない（CONSTITUTION §3）。CSS は各節の transition を止める規則が節の
  隣にあり、終わらないアニメーション（事件点と検索ピンのパルス）とスクリーンショットの全画面の閃光は
  `css/intmap.css` 末尾の 1 ブロックが止める。同じブロックが**ページ全体の transition** を即時にし
  （`transition-duration:0.01ms`・`scroll-behavior:auto`。状態は変わり `transitionend` も来る）、
  各節のブロックが面を追いかける形をやめた。回転する読み込み表示は、作業が続いている唯一の印なので
  止めない。
- **`forced-colors: active`（Windows のハイコントラスト）では、色に頼るものを残さない。** 末尾の 1 ブロックが
  ページ全体の backdrop-filter を外し、塗りだけで示していた状態（`aria-pressed`／`aria-selected`／
  `aria-current`）に Highlight の輪郭を付ける。**`#map` だけは `forced-color-adjust:none`**——階級区分・凡例の
  色・マーカーの色相は情報そのものなので、OS の色で塗り潰さない。コンポーネント別のブロック（ウィジェット・
  Playground など）はそのまま隣にある。
- **地図にはテキスト代替がある——`js/map-narrator.js`。** 視覚的に隠した `#map-narration`（`role="status"`・
  `aria-live="polite"`・`aria-atomic`・`.im-sr-only`）に、中心の場所・表示中の日付（今日でないとき）・
  表示中のレイヤー・表示範囲の件数・選択中の地物を 1 段落で書く。**変化が落ち着いてから 1 回**（1.2 秒の
  デバウンス）、文が変わったときだけ。`#map` は `role="region"`・言語に合う `aria-label`・
  `aria-describedby="map-narration"`・`aria-keyshortcuts`。各節は**それを持つ読み手から**読む——
  レイヤー名は Active layers の帯（`_refreshActiveLayers` が書くチップ）、件数は `IntMapLayers.featuresIn`、
  場所は今日なら `HOST.countryGeo` と `window._imPipGeo`（名前は `HOST.cName`）、⚠ **時計が過去の年を指す間は
  現代の国を使わず** `IntMapTimeBorders.currentFC()`（その年の記録）が名づける。答えの無い節は書かない。
  外部への通信は足していない。
  **地物はキーボードでも選べる。** 地図にフォーカスがあるとき Alt+N／Alt+Shift+N（`e.code` で読むので
  macOS の Option+N も同じ）が、画面中央付近で描かれている地物を近い順に巡り、**レンダラ自身の click
  経路**（`GE().events.pressAt(point)`——MapLibre は `MapMouseEvent` を発火、Cesium は LEFT_CLICK と同じ
  `dispatch`）で押す。開くポップアップ・カード・所有権の判定はクリックとまったく同じで、新しい popup は無い。
  巡る対象は click 所有権の登録簿（`clickLayers({ownersOnly:true})`。背景の fallback は地物ではない）が答える。
  地図の上の `events.on('click')` だけで拾う物（航空機・衛星など）は登録簿に無いので巡回に入らない。
  視点は動かない。門は `tests/map-a11y-structure-checks.test.mjs` ③ と `tests/map-a11y-structure.spec.js` ①②。
- **「ここに何があるか」を声にできる——`js/map-reader.js`（読み上げモード）。** 地図にフォーカスがあるとき
  **Alt+R** が、地図の中心にあるもの——場所と行政区分の鎖・国・標高（水深）・現地時刻と日の出入り・**表示中の全
  レイヤーの値**（その地点に値が無いレイヤーは名前を挙げる）——を読み上げ、**Alt+Shift+R** が読み上げモードの
  オン・オフ（既定オフ・`localStorage` の `intmap_map_reading`・設定 ▸ キーボードショートカットに同じスイッチ・
  Atlas の `settings.mapReading`）。オンの間は、地図が動いて落ち着くたびに「約 12 km 北東へ移動」のあとに同じ段落を
  **1 回だけ**言う（書きかけの live 領域は読み上げを途中で切り直すので、完成してから）。⚠ **この層は何も集めず何も
  決めない**——記録は地点プロファイル（`js/place-dossier.js` の `placeProfile`、地点カードと Atlas の
  `research.placeProfile` と同じもの）が作り、`profileSpeech` がそれを文にし、答えられなかった節は**理由を言う**
  （沈黙は「そこには何も無い」と聞こえる）。⚠ **live 領域に書く者は narrator 1 つ**（`narratorApi.say` / `enrich`）。
  Alt は Alt+N と同じ理由で選んだ（1 文字ショートカットは修飾キーで戻り、レンダラは矢印と +/− だけを読む）。移動と
  拡大は既存のまま——矢印キーと +/−。モジュールは必要になったとき（キー・設定・Atlas・保存済みのスイッチ）にだけ取りに行く。
  門は `tests/keyboard-and-offline-checks.test.mjs` ④ と `tests/keyboard-and-offline.spec.js`。
- **一文字のショートカットは切れる（WCAG 2.1.4）。** 設定 ▸ キーボードショートカット ▸「1 文字のショートカット
  キー」（既定オン・`localStorage` の `intmap_kbd_single`・変えた瞬間に効く）。オフでは修飾キーの無い全ショート
  カット（「?」を含む）が何もしない。Escape はダイアログの登録簿のものなので対象外。
- **操作要素には名前がある。** 記号やアイコンだけの button は `aria-label`／`title` を、input／select／textarea は
  `<label>`・`aria-label`・placeholder のどれかを持つ。門は `check:static` の `control-names` 規則
  （`scripts/control-names.mjs`・台帳 `tests/control-names-baseline.json`。ファイルごとに両方向）。
  描画時の全数は `tests/form-control-names.spec.js` がブラウザの accessibility tree に訊く。
- **重なり順は名前のついた層で書く。** `css/intmap.css` の `:root` が層を 1 回だけ宣言する——
  `--z-inset` 0・`--z-marker` 100・`--z-map-overlay` 900・`--z-controls` 1000・`--z-dropdown` 1300・
  `--z-sheet` 1650・`--z-popup` 2000・`--z-window` 2200・`--z-menu` 2500・`--z-shell-front` 2600・
  `--z-front` 2650・`--z-toast` 3000・`--z-modal` 10000・`--z-overlay` 99990・`--z-system` 200000・
  `--z-max` 2147483647。スタイルシートの z-index は全部 `var(--z-…)` か `calc(var(--z-…) ± n)` を読み、
  **`js/` と `index.html` も同じ名前を読む**（style 文字列に `var(--z-…)` を書くか、実行時に組むなら
  `IntMapStack.z(name, step)`）。門は `check:static` の `z-layers` 規則（`scripts/z-layers.mjs`）——全宣言を
  解決した**順序列**を `tests/z-layers-baseline.json` と完全一致で照合し（描画順が動けば `--update` で書き
  直すまで落ちる）、`css/`・`js/`・`*.html` に残る数値リテラルの z-index をファイルごとに両方向で数え、
  **0 でないファイルは台帳の `why` に理由を 1 文持つ**（残りは `css/intmap.css` を読まない別文書の
  `admin.html`・`css/pages.css` の 2 本だけ）。さらに `js/` と `*.html` が
  読む層の名前（`var(--z-…)` と `IntMapStack.z('…')`）が `:root` にあることも確かめる——綴りを誤った層は
  ブラウザでは誤りにならず、宣言が捨てられて `auto` で描かれる。
- **セーフエリアも名前で読む。** `:root` の `--safe-top` / `--safe-right` / `--safe-bottom` / `--safe-left`
  （`env(safe-area-inset-*, 0px)`）だけが端末に訊き、`css/` と `js/` はそれを読む。門は `check:static` の
  `ui-owners` 規則（`scripts/ui-owners.mjs`・台帳 `tests/ui-owners-baseline.json`）。
- **携帯の地図の帰属表示のリンクは、見た目の大きさのまま指には 24 × 24 px 以上で当たる。**
  `#map-credit a::after` が文字の中心に `max(100%,24px)` 四方の透明な当たり判定を置き、ピルは
  `overflow:visible`（切り取られた箱は当たり判定も切り取られる。ピルの高さは 23 px）。門は
  `tests/ui-a11y-polish.spec.js` ②（375 px で各リンクの 24 × 24 の四隅と上下辺の中点を
  `elementFromPoint` に訊く）。
- **地図の地名検索の placeholder は、欄に収まる形を出す。** 欄の幅は `js/mobile-ui.js` の見張りが
  2 つのサイドバーの隙間から決める（1280 px の初回訪問で欄は 105 px）ので、同じファイルの次の
  見張りが欄の実幅と計算済みフォントで文を測り、`js/i18n.js` が書いた全文（`msPh`）が入らなければ
  短い形（「Search places」／「地名を検索」）にする。それでも入らなければ `text-overflow:ellipsis`。
  言語の切り替えは placeholder の書き換えとして `MutationObserver` が受け取り、測り直す。
  ⚠ Data & analysis（`js/gis-panel.js`）の引数欄は `paramControl` 1か所で作られ、**引数名の行**
  （`#gis-param-name-<n>`）がその下に作られる部品——型によって select / textarea / input / 単独の
  チェックボックス——の名前になる。

### 8.3b アイコン（線画・1 か所）

- **画面のアイコンはすべて `js/icons.js` の線画**である。24 単位のグリッド・線幅 1.75・丸い端と角・
  `currentColor`（文字と同じ色・テーマに追従）。1 つのアイコンは 1 本の path（点は長さ 0 の線を丸い端で描く）。
  塗りの図形は状態の点（`dot`）だけ。名前の一覧は `ICON_NAMES`。
- **入口は 4 つ**: `icon(name)`＝マークアップ（`IntMapSafe.markup` 製なので innerHTML にもテンプレートにも
  そのまま入る）／`iconNode(name)`＝`<svg>` 要素（`textContent` で書いていた所は `replaceChildren`）／
  静的マークアップの `<span data-icon="name"></span>`（読み込み時に `hydrateIcons()` が描く。index.html の
  ツールバー・Tools シート、admin.html）／`withIcons(text)`＝訳文の中の `{icon:name}`。
  地図のシンボル層は画素が要るので `iconImageData(name)` を `GE().scene.addImage` に渡す（ライブカメラの印）。
- **文字と絵は分ける。** ロケールの文字列は文字だけを持ち、絵は UI 側が描く。ボタンの名前をその絵で
  呼ぶ文（「▶ を押すと」の類）は、全言語が同じ `{icon:play}` を持ち `withIcons()` が描く。
  ⚠ 状態で絵が変わるもの（再生／一時停止、音あり／なし）は `iconNode()` で差し替える。
- **見た目の規則は 1 つ**: `css/intmap.css` の `.im-icon`（行の中の位置と縮まないこと）。大きさと線は
  `<svg>` の属性にあるので、intmap.css を読まない静的ページ（sources.html など）でも同じ大きさで描ける
  （静的ページは js/icons.js を STATIC_ASSETS から直接 import する）。
- **門**: `npm run check:static` の `icon-glyphs`（`scripts/icon-glyphs.mjs`）が、配信物の文字列・ページの
  文字・CSS の content に入った絵文字（Unicode の Extended_Pictographic）を拒む。文の一部として読む記号
  （©・文中の ↗ などの矢印）と出典が書いたデータ（`data/`）は理由つきで対象外。利用者が選ぶアバターの
  文字だけが宣言つきの例外（§8.1.2）。
- ⚠ ウィジェットのボード（`js/widget-core.js` の `WC.icon`）は同じ流儀の**別の写し**をまだ持っている
  （一部は同じ path）。1 か所に寄せるのは次の作業。

### 8.4 経路 (Directions)

正式な入口は **Layers ▸ Tools ▸ Directions／経路** の1つだけ（地図上に常設のボタンは無い）。
Atlas の自然言語も同じ経路計算を呼ぶ補助的な入口で、**両者は同じ状態を読み書きする**。

| ファイル | 役割 |
|---|---|
| `js/routing-store.js` | **状態の正本** `window.IntMapRouteStore`。出発地／経由地／目的地（確定した地点と未確定の文字列を分けて持つ）・交通手段・日時・回避条件・要求の状態・結果・選択中候補。DOM も地図も触らない |
| `js/routing-providers.js` | 各ルーターが**実際にできること**の表。UI はこの表が真を返す機能だけを出す |
| `js/routing-geocode.js` | 地点の**候補**検索と順位付け。確定はしない |
| `js/routing-cards.js` | 候補カード・手順・公共交通の区間・距離／時刻の書式。**Atlas とパネルが同じ関数を呼ぶ** |
| `js/routing-export.js` | GPX・GeoJSON・共有状態（**幾何は運ばない**） |
| `js/routing.js` | 実際の経路計算、地図への描画、`window.IntMapRouting` の公開契約 |
| `js/routing-ui.js` | パネル本体。**遅延取得**（`IntMapLazy.need('routeUi')`）。CSS は `css/intmap.css` の `.rtp-*` |
| `js/routing-ops.js` | 既存の経路についての分析（標高・国境・沿道・到着時刻・経路差・過去の路線網） |
| `js/routing-errors.js` | 失敗の分類 `window.IntMapRouteErrors`。15 コード。各コードは**文ではなく判断**を運ぶ（再試行してよいか・別 provider に投げてよいか・利用者が直せるか）。文は別に 9 言語で引く |
| `js/routing-time.js` | **どちらの「今」か** `window.IntMapRouteClock`。`planningNow()`＝Chronos（読者が見ている時刻・depart at / arrive by / 沿道天候）、`navNow()`＝壁時計（案内中）。**時計を増やしていない。既にある2つに名前を付けただけ** |
| `js/routing-traffic.js` | 交通情報つき provider のアダプタ `window.IntMapRouteTraffic`。`routing-relay` 経由でのみ通信し、**結果を一切保存しない**（provider の規約） |

**能力レジストリ (§3)** — `js/routing-providers.js` は 40 キーの語彙を宣言し、**どの provider も
全キーに答えなければ登録できない**（`assertComplete` が throw する）。キーが無いことは `false` と
読まれてしまうが、意味は「誰も訊いていない」なので、その2つを区別しないための仕組み。
UI・Atlas・要求組み立ての3つが**同じ表**を読むので、「押しても何も起きないボタン」が構造上作れない。
⚠ 語彙に入るのは**事実**だけ（yes/no か数）。**計算するもの**（どの provider がこの要求に答えるか、
それを選ぶと何を失うか）は関数のままで、語彙には入れない。
⚠ 各 provider は `evidence` を持つ——`'measured'`（実サーバに訊いた）か `'documented'`（提供元の
文書を読んだだけ）。`documented` の provider は `available()` が relay の答えを得るまで false なので、
**文書の力だけで利用者に何かを提示することは無い**。

**不変条件**

- **入力欄の文字を編集した瞬間、そこに確定していた座標は無効になる。** 未確定の文字列は
  ルーターに渡らない（`points()` が `null` を返す）。
- **経路計算は確定した地点が変わったときだけ走る。** 打鍵では走らない。同一条件の再送もしない。
- **古い応答は状態にならない。** ルーター側の requestId（描画の抑止）に加え、store 側の
  `settle(id,…)` が世代の合わない結果を拒否する。
- **パネルを閉じると地図の経路も消える。** ✕（と Esc）は `RT().clear()` / `clearAreas()` を通り、
  描いた経路と通過禁止範囲を地図から外す。**出発地・目的地・経由地は残る**ので、開き直せば同じ
  旅程がそのまま出て、1回の計算で戻る。パネルを開いたまま地図だけ綺麗にしたいときは
  「経路を消去」——こちらは閉じない。Atlas の「経路を消して」も同じ `IntMapRouting.clear()`。
- **候補を1つ選ぶと、そのカードが開いて詳細（手順／区間）を中に出す。** 候補一覧の下に別の
  ブロックを置かない。カードは `div[role=radio]` であって `<button>` ではない——中に入る手順は
  本物のボタンで、ボタンはボタンを含めない。押下の判定は**手順が先**で、次にカード。
- **時刻はその地点の現地時刻で書く。** `IntMapTimeZones.offsetAt(lng,lat)` から求めた実効オフセット
  で組み立てるので、東京→パリの旅程は出発が東京時間・到着がパリ時間になる。設定でタイムゾーンを
  明示している読み手はそれが優先される（アプリ全体を1つの時計で読むという選択だから）。
  出発時刻の入力欄自体は端末の時計で打つ `datetime-local` で、その旨を欄の横に書く。
- **どの地点欄からも現在地を1回で入れられる**（◎ ボタン）。許可を求めるのは**押した瞬間だけ**で、
  パネルを開いただけでは何も要求しない。拒否・タイムアウト・失敗はそれぞれ別の文で言う。
- **交通手段の切替はこのパネルにしかない。** Atlas の返答にはタブを置かない（同じ store を書く
  操作子を会話ログの中に二重に置かないため）。
- **入替は旅程全体を逆順にする**（`A → 1 → 2 → B` は `B → 2 → 1 → A`）。
- **地図の A / 1 / 2 / B は入力欄の番号と同じ規則から出る。** 経路線には見えない太いヒット領域が
  あり、線を押すと候補カードの選択が変わる（逆も同じ）。
- **できないことは表示しない。** ライブ交通を持つプロバイダーは1つも無いので、道路の所要時間は
  常に「標準所要時間・リアルタイム交通量は未反映」と書く。回避条件や通過禁止範囲が適用できな
  かった場合、代替経路が経由地のせいで取れなかった場合も、それぞれ別の文で言う。
- **公共交通の「リアルタイム」は上流が `realTime` を真にした区間だけ。** 一部だけなら「一部
  リアルタイム」で、遅延0は「定刻」と書く（「+0分」とは書かない）。
- **カメラは開いているパネルの実寸を避ける**（`IntMapRouting.setInsets()`）。

### 8.4b 案内 (Active Navigation)

経路を**引く**のが §8.4、引いた経路に沿って**連れて行く**のがこちら。計画の状態
（`IntMapRouteStore`）とは**別の store** を持つ——計画の状態は読者が入力したときに変わり、
案内の状態は誰も触らなくても毎秒変わるので、混ぜると経路パネルの購読者全員が走行中ずっと
1 Hz で再描画される。

**8 ファイルすべてが1つの async chunk**（`IntMapLazy.need('navigation')`）。一度も案内しない
セッションは 1 バイトも払わない。

| ファイル | 役割 | 純粋か |
|---|---|---|
| `js/navigation-store.js` | `window.IntMapNavStore`。10 状態の状態機械（`idle / acquiring_location / ready / enroute / offroute / rerouting / arriving / arrived / paused / error`）と**遷移表**。表に無い遷移は throw する。`rerouteGeneration` が古い再探索の返事を捨てる | ○ |
| `js/navigation-match.js` | `window.IntMapNavMatch`。GPS の受け入れ判定（古い・飛躍・順序違い）と平滑化（速度・**円形**の方位）、経路への射影（**頂点ではなく線分**へ。前回位置の窓＋一様格子で、毎 tick に全 polyline を歩かない） | ○ |
| `js/navigation-guidance.js` | `window.IntMapNavGuide`。残り距離・**手順の所要時間から積む**残り時間・次と次の次の操作・レーン・逸脱の投票・到着の投票・音声の段 | ○ |
| `js/navigation.js` | `window.IntMapNavigation`。ループだけ。`watchPosition` → 上の3つ → 地図。**再探索は `js/routing.js` の同じ扉を通る** | × |
| `js/navigation-camera.js` | 追従（進行方向を上・現在地を画面の下寄り）／北上／全体／手動パンで一時解除 | × |
| `js/navigation-voice.js` | 9 言語の音声。`off` / `alerts` / `guidance` | × |
| `js/navigation-sim.js` | 決定的な位置シミュレータ（`Math.random` を使わない）。逸脱・飛躍・精度劣化・停止・到着を注入できる | ほぼ○ |
| `js/navigation-ui.js` | 案内カード（上）と ETA バー（下）。`.nvg-*`。**案内中は経路パネルを隠す**（`body.nvg-on`） | × |

**不変条件**

- **位置が端末を出るのは経路を要求するときだけ。** 照合・進捗・案内・到着はすべて手元で計算する。
  `_sent()` が回数を数えており、検査がその数を見る。
- **案内は `IntMapTime`（歴史時計）を1回も読まない。** 地図を 1950 年にした読者も今日帰宅する。
- **交通情報を持たない所要時間に「渋滞考慮」と書かない。** 能力表が false のとき、UI は
  「交通状況未反映」と明示する。
- **provider が出さなかったレーンを推定しない。** `lanes` が null なら何も描かない。
- **地図には `IntMapGeoEngine` を通してのみ触る**（MapLibre / Cesium の両方で成立する）。

### 8.5 パンデミック・シミュレーター (Pandemic Simulator)

**Layers ▸ Tools の「パンデミック・シミュレーター」から 1 タップで起動する**（Playground ハブの
中のカードからも開ける）。押すと OS アクション `sim.pandemic`（`js/app-body.js`）を実行する
——**行・コマンドパレット・Atlas の 3 つが同じ 1 本のコマンドを押す**（地震シミュレーターの
`sim.seismic` と同じ形）。モジュールは遅延読み込みなので、押したときに取りに行く。
⚠ **行の正本は `js/map-ui.js` のツール一覧**である。この不変条件は「登録済みの `sim.*` コマンドを
数え上げて、そのすべてが行を持つか」を測る検査が守る（手で書いた一覧ではない）。
⚠ `js/data-layers.js` が `#layer-tools` に置くボタンのほうは**二重の扉になる**ので、置かれたままに
してある——帯ごと読者のパネルへ運ばれるようになったため（§8.6）、同じコマンドを 2 か所が差し出す。
**どちらを隠すかは宣言から計算する**: ボタンが `data-os-act` で、行が `data-act` で、自分が押す
コマンドを名乗り、重なったほうのボタンが隠れる。**id の対応表はどこにも書かない。**
行は走行中に点灯し、もう一度押すと閉じる——`js/playground.js` が `window.IntMapPandemic`
（`isOpen` / `close`）を**自分の扉の中から**公開する（描いただけで遅延モジュールが読まれてはならない）。

**Atlas から駆動できる。** 能力は 2 本で、`sim.pandemicRun`（走らせて**状態を返す**——世界の合計と、
国ごとの累計感染・死者・現感染者・到達日・国境段階）と `map.pandemicDay`（その日を地図へ描く）。
⚠ **計算と描画が別の能力なのは観測器の都合**である——描画を約束した能力が描かなかった回を、観測器は
`not_rendered` と判定する。開始地点は国コード・国名・地名・座標のいずれでもよく、**地名は同梱の
gazetteer で点に解決してから、その点を含む国を点内包判定で決める**（ジオコーダの第一候補をそのまま
国にしない）。どう決めたかは回答に出る。⚠ **指定されなかったパラメータは主張である**——`describePandemicParams`
が 1 つずつ出典（`caller` / `preset:<プリセット>.<欄>` / `preset-silent:…` ＝**上流が述べていない** /
`scenario:…` / `default`）を付けて返し、回答がそれを読者に述べる。範囲外の値は**丸めずに拒否**し、
拒否がその変数自身の範囲を持って返る。同じ種は同じ結果を再現する。

**世界は `js/pandemic-world.js`** ——どの行が人の住む場所か・人口・接続・誰が統治するか。
⚠ **パネルと Atlas は同じ世界を受け取る**（そうでなければ、Atlas が報告する数と読者が見る流行は
同じ名前の別物になる）。2 段階で、行は即座に・`ready` は 4 つの表が settle してから解決する
——移動行列は `createPandemicModel` で凍るので、**表が揃う前に始めた走行は種から再現できない**。

**数理は `js/pandemic-model.js`、地図と HUD は `js/playground.js`** で、この境界は動かさない
——`playground.js` は区画（S/SV/E/I/R/V/D）に対して算術をしてはならない。
⚠ **「地図の算術」も同じ側にある。** 何点描くか（`caseDotPlan`）・どの点が変わったか
（`dotSignature`）・スライダーが実際に持てる値はどれか（`snapToStep`）は `js/pandemic-model.js` の
**export された純関数**で、`playground.js` はそれを呼ぶだけ。疫学ではないが**数**であり、
DOM のクロージャの中にある数は検査が届かない（`scatterCases()` を外へ出したのと同じ理由）。

- **モデル**: 国ごとに 1 組の区画を持つ**確率的 SEIR メタ個体群**。潜伏と感染期はそれぞれ最大 2 段
  （指数分布 1 段だと滞在時間の裾が現実と合わない）。
- ⚠ **平均滞在日数は設定値そのものになる。** 1 日刻みのモデルで 1 つの段にいる日数は**幾何分布**
  （平均 `1/p`）なので、段あたりの日次確率は連続時間のハザード `1 − e^(−段数/T)` ではなく
  **`p = 段数 / T`**。**段数もその一部**で、1 日に 2 段は進めない以上、2 段では平均 2 日未満を表現
  できない——**2 日未満の期間は 1 段**にする（インフルエンザの潜伏 1 日）。指定した **R₀ もそのまま
  実現する**（`tests/hazard-pandemic-model-checks.test.mjs` ①② が 5 プリセットすべてを走らせて測る）。
- ⚠ **「n 人がそれぞれ確率 p で動く」は二項分布で引く**（BINV の逆関数法）。Poisson 近似は p が
  小さいときだけ正しく、`p` が 1 に近い遷移（潜伏 1 日＝ `p=1`）では**確実に起きることを 6 割の
  確率にしていた**。期待値が 30 人以上の遷移は期待値そのものを使う（大数の法則が済んでいる）ので、
  **小さな流行はひとりでに消えることがある**。
- **乱数は種を取る**（mulberry32）。同じ種・同じ設定なら**同じ流行**が再現する。詳細設定で種を
  指定できる。⚠ **再生速度（×1〜×8）は `setTimeout` の間隔だけを変える。** 疫学の確率に
  再生速度が入ってはならない（`tests/hazard-pandemic-model-checks.test.mjs` ② が engine の中に `speed` という語が
  無いことまで測る）。
- **人口は保存する。** `S+SV+E+I+R+V+D` は各国の初期人口に等しく、`invariant()` がそれを毎 step
  検査できる。国際的な再流入も**必ず現地の未感染者から取る**——⚠ **`S` と `SV` の両方から、
  比率どおりに**。国内の感染力はこの 2 つを同じ確率で引くので、輸入だけが `S` しか見ないと、
  **同じ人が隣人には感染し空港には感染しない**ことになる（接種が行き渡って `S` が尽きた国が、
  算術として輸入不能になる）。
- ⚠ **輸入は「人の移動」ではない。** 送り出し側の `E`/`I` は減らない。到着した感染者が現地で
  感染連鎖を始める**圧力**であって、だから消費するのは現地の未感染者で、だから両国の人口が保存する。
  **画面もコメントも「感染者が移住する」と説明してはならない。**
- ⚠ **国の時計は、病気が着いた日に始まらない。** 免疫の減衰と接種は**到達していない国でも毎日進む**
  （`stepUnreached`）。以前は 1 つの `if (!seeded) continue` が感染の算術と一緒にそれも飛ばしていて、
  **最初の旅行者が着いた日がその国の公衆衛生の開始日**になっていた。未到達国に配らない、という
  選択は `vaccinateUnreached` という**明示された政策**で、制御構造の副作用ではない。
- ⚠ **半端な人数の遷移は、期待値どおりの人数を動かす。** `draw(n,p)` は整数部を二項分布で引き、
  **端数 `frac` は `frac·p` をそのまま払う**。以前は端数のために「1 人まるごと」の Bernoulli を
  引いてから `min(n,k)` で切っていたので、**払い出しが端数ぶんに削られ、期待値が半分になっていた**
  （n=0.5・p=0.5 で 0.125。正しくは 0.25）。区画は 30 人を超える遷移から実数になるので、
  これは例外的な入力ではなく**この模型の通常の状態**である。
- ⚠ **ワクチンが守れなかった人は `S` に戻らない。** all-or-nothing のワクチンなので接種した人の
  一部しか `V` に入らないが、残りを `S` に戻すと**翌日また同じ人に接種抽選が回る**——効果 40% でも
  続ければ 40% を大きく超えて `V` が埋まる。守れなかった人は **`SV`（接種済み・非防御）** に入り、
  接種の対象からは外れ、**感染は `S` とまったく同じ確率で受ける**。HUD の「未感染」は `S+SV`。
- **累計感染は独立の台帳**（`cumInf`）。`R+D+I` は免疫が切れれば減るので、**累計感染率の分子には
  ならない**。HUD はこれを「延べ感染」と呼ぶ——再感染を含む**感染イベント**の数だから。
- **シナリオは 2 つ**。「未知の病原体」は誰も免疫を持たない世界、「現在の世界」はその病気が
  2026 年に実際に持っている**ワクチンと治療法**から始める。⚠ **免疫ゼロの世界を実在の病名で
  呼ばない**ためにこの区別がある。
- ⚠⚠⚠ **国ごとの「できること」は 4 つに分かれており、そのうち 3 つは実測値である**（`data/health.json`、
  `scripts/build-health.mjs`）。⚠ **どの指標を選ぶかは「取りやすさ」ではなく「その欄がモデルの中で何を動かすか」**
  で決めている:

  | 欄 | モデルの中で何を動かすか | 指標 | 件数 |
  |---|---|---|---|
  | `health` | 病院の逼迫倍率と基礎致死率（`overload` / `ifrEff`） | WHO UHC サービス被覆指数（SDG 3.8.1） | 195 |
  | `response` | 政府が入国規制を上げる速さ、ワクチン計画を回せるか | WHO IHR SPAR 能力 7「健康危機管理」 | 194 |
  | `delivery` | ワクチンが存在してから 1 日に届く未感染者の割合 | WHO/UNICEF DTP3 接種率 | 236 |
  | `connectivity` | `travel[i]` の最終フォールバックのみ | 1 人あたり GDP（従来どおり） | — |

  ⚠ **DTP3 が `delivery` にとって正しい問いなのは、当て推量ではない。**「すでに存在し、すでに予算が付き、
  すでに定期接種の予定に入っているワクチンを、この国の 1 歳児の何割が実際に 3 回受け取ったか」は、
  この欄が模している**ラストマイルそのもの**である。だから「定期接種が弱い高所得国」と「強い低所得国」が
  1 人あたり GDP では逆になっていた順序が、ここでは正しく出る。
  ⚠ **表に無い国は、能力が無い国ではない。** その国だけが従来の開発指標へ落ちる（`capacityFrom` が
  国ごとにどれが実測かを持ち、国インスペクタが `~` で印を付けて「1 人あたり GDP からの推定」と書く）。
  **落ちるのは国ごとであって、世界ごとではない。**
- ⚠⚠⚠ **麻疹の初期免疫は国ごとの実測値で、スライダーは「世界平均」の意味を保つ。** 以前は 1 つの数を
  全ての国・全ての年齢に当てていたので、**世界地図の上で南スーダンとポルトガルが同じ場所から始まっていた**。
  麻疹は 5 つのプリセットのうち唯一、現実の免疫が**実測された接種率そのもの**である病気なので、国別の値が
  存在する（WHO/UNICEF MCV1）。engine は観測を**形**として使い、その人口加重平均がスライダーの値に
  乗るよう同じ係数で伸縮する——スライダーはプリセットの世界値から始まるので、**既定の実行は従来と同じ世界平均を持ち、
  従来は無かった分布を持つ**。⚠ **上限 0.99 で切られた国は平均に寄与しなくなるので、実現する平均はスライダー以下**
  になる。平均をぴったり合わせる反復は**データが動かしていない国を動かす**ので、行わずに明示する。
  ⚠ **これは「現在の世界」シナリオでだけ効く**（「未知の病原体」は誰も免疫を持たない世界である）。
  ⚠ **小児の接種率を全人口の免疫として読んでいる**（このモデルは年齢構造を持たない）ことは画面が言う。
- ⚠ **COVID-19 の国別免疫は実測が存在せず、作らない。** ハイブリッド免疫は接種率ではなく、
  「この国の人口の何割がいま感染防御を持っているか」を公表している機関は無い。だから covid の 0.9 は
  従来どおり**明示された世界一律の仮定**のままで、`data/health.json` にその列は無い。
  用量数から国別の列を作れば MCV1 の列と同じ見た目になるが、それは観測ではない。
- ⚠ **「現在の世界」の初期免疫は観測値ではなく仮定である。** この engine の免疫は 1 区画しか
  無いので、COVID-19 の 0.9 は「世界の 90% が完全な感染防御を持つ」と読まれてしまう——WHO が
  そう推定したのではなく、**ハイブリッド免疫という定性的な事実の、この模型で表せる最も粗い形**
  である。麻疹の 0.84 も**子どもの MCV1 接種率**で、全年齢・全国に同じ割合を当てている。
  UI はこの 2 つを**「仮定した初期免疫」と名乗る**（実在するのはワクチンと治療法のほうだけ）。
- **疾患プリセットはデータ**（`PANDEMIC_PRESETS`）。伝播・重症度・免疫・ワクチン・治療を混ぜず、
  **重症度は指標名（IFR / CFR）を数と一緒に持つ**——SARS の 9.6% と Ebola の 50% は CFR で、
  分母が IFR と違う。`latentDays`（感染力を持つまで）は `incubationDays`（発症まで）とは別の欄で、
  インフルエンザと COVID-19 では前者のほうが短い。
  ⚠ **ただし指標名が分かれても、死亡の計算は分かれていない。** engine は値を `I` を離れる
  **すべての感染**に当てる（検出・報告・未診断を扱う観測モデルが無い）ので、CFR のプリセットでは
  分母が実際より小さい数を IFR として読んでいることになる。**根拠のない換算係数を掛けない**
  （それは由来を書けない定数になる）——**設定画面がそう明示し、読者が下げられる**ようにしてある。
- ⚠ **「終生免疫」は月数ではなく独立の欄**（`naturalImmunityLifelong`）。以前は
  `monthsToDays()` が「600 以上なら ∞」と読む**帯域内の番兵**で、1 つの変数が期間と分類を
  同時に運んでいた。Ebola の `naturalMonths: 120` は**実在する 10 年**なのにスライダーの上端で
  「∞」と表示され、**同じ上端を触ると番兵が書き込まれて本当に無限になった**——同じ画素・同じ
  表示で 2 つの異なる流行。0 か月（持続免疫なし）は 3 つ目の別の主張で、これとは衝突しない。
- **介入**は「対策なし／状況に応じて／強い対策」から選ぶ。国境は open→screening→restricted→closed
  の 4 段で、**静かな日が続けば戻る**（以前は閉じたら二度と開かなかった）。
- **変異株は生まれた国にしか無い。** 国ごとに株の占有率を持ち、置き換わりも免疫逃避もその国で
  進む。世界中の基本再生産数が同時に書き換わることはない。
- **国際伝播の行き先は分布から引く。** 国の組ごとに重み

  ```
  w_ij = 到達魅力_j × exp(−距離_ij / 3200km)  +  陸境の重み × adjacent_ij × 人口重み_j
  ```

  を作り、累積和の二分探索で行き先を決める。⚠ **航空の項には、これに加えて「実際にどこへ飛んでいるか」が
  入る**——`data/mobility.json`（`scripts/build-mobility.mjs` が OpenFlights から作る**国どうしの路線数**）を
  行ごとに正規化し、距離カーネルと **`ROUTE_MIX = 0.35`** で混ぜる。行の合計は混ぜる前と同じに保つので、
  陸境の項（`LAND_MIX`）の意味は動かない——**変わるのは航空の項の中の配分だけ**である。
  ⚠ **路線表は 2014 年 6 月で凍っている**（OpenFlights 自身が更新停止と明記）。それでも使うのは、
  **公開されていて現行の二国間の旅客行列が存在しないから**で、OAG・ICAO TFS・Sabre はいずれも商用。
  代替は「もっと良い二国間データ」ではなく「二国間の項が無い」だった。
  ⚠ **路線表の 0 は「誰も行き来しない」ではない**（乗り継ぎは路線表に写らない）。だから**置換ではなく混合**で、
  路線表に出発行の無い国は距離カーネルのまま——「2014 年の表に無い」は「どこへも飛ばない」ではない。
  ⚠ **買えたものと、買えなかったもの**（110 m の実世界・covid・種 1〜12 で実測）: オーストラリアの最有力の
  行き先が**ニュージーランド（12.0%）**になる（路線なしでは上位 6 件に入らずマレーシアが 1 位だった）・
  英国と日本の上位 6 件に**アメリカ**が入る・ポルトガル→ブラジルが 0.19%→1.07%。**フランス→セネガルは動かない**
  （0.18% のまま）——2014 年の表にその路線が少なく、この項が拾えなかった。
  ⚠ **代償も実測されている**: N 番目の国に到達する日の中央値が 60/81/100（10/50/100 番目）から **60/85/116** へ。
  実際の COVID-19 は 50/80/95 なので、**100 番目の点の超過が 5% から 22% に悪化する**。
  直行便の無い国が最後に残るからで、`TRAVEL_WHEN_INFECTED` を 70% 上げても 11 日しか戻らない
  （**路線表が変えるのは到達可能集合の「形」であって「速さ」ではなく、速さの定数は形を吸収しない**）。
  **到達魅力**は `data/mobility.json` の**実測の入国旅行者数**（World Bank `ST.INT.ARVL`・2019 年以前の最新年）を
  第一の段とし、無い国は `data/airports.json`（`scripts/build-airports.mjs`
  が OurAirports から作る**定期便のある空港の規模**）、**陸の隣接**は `data/country-facts.json` の
  `borders`（163 か国・無向 322 辺・対称）、**人口重み**は `countryStats` の人口。
  出国のしやすさ（人口あたりの空港規模）は**出発側**に入る——行き先ごとに変わらない量を重みに
  入れても正規化で消えるから。⚠ **どれも実際の航空路線でも旅客数でもない**（この計画には路線・便数・
  旅客数のデータ源が 1 つも無い）。空港は**インフラの規模**であって流量ではない。
  ⚠⚠ **実測の入国者数にも圧縮（`AIR_EXP`）を掛ける。** `AIR_EXP` のコメントは「座席や旅客を数える源が来たら
  失効する」と書いており、入国者数はまさにその源なので、最初の実装は線形にした。**実測すると誤りだった**——
  `attract_j` は「j に何人着くか」ではなく「i を出る人が j を選ぶ確率」であり、フランスの入国者の多くは
  **距離の項と陸境の項が既に運んでいる近隣からの短期反復旅行**なので、線形だと同じ流動を二重に数える。
  さらに**下端は観測ではなく報告の欠落**（World Bank はベナンを 1 人あたり 0.000 回、マラウイを 0.001 回とする。
  「ベナンからは誰も出国しない」は誰も観測していない）。圧縮つきなら較正への影響はほぼ無い（60/83/104）。
  ⚠⚠⚠ **同じ考えのもう半分は、実測したうえで採用しなかった。** `travel[i]`（その国の住民がどれだけ旅行するか）を
  World Bank の出国者数・搭乗者数から作ると、50/100 番目の日が **92/124**（線形なら 106/144）になり、
  **速さの定数では戻せなかった**。加えて **177 か国中 53% が `[TRAVEL_MIN, TRAVEL_MAX]` のどちらかに張り付いた**
  ——この上下限は**圧縮された代理比**のために選ばれた数で、実測の比は 0.000（ベナン）〜20.1（カタール）に広がる。
  この列を使えるようにするには**上下限の意味を考え直し、排出率を較正し直す**必要があり、それは行を 1 本
  変える仕事ではない。よって `data/mobility.json` は**モデルが実際に読む列だけ**を配る。
  UI はこれを
  そのまま名乗り、**読み込めなかったときは「人口と距離だけ」と名乗る**（`model.mobility.from`）。
- **国境を越えるのは人である。** 1 日の出国者は、その国の **E+I から**引く
  （国際的な越境の基準値は UN Tourism の年間国際観光客到着数 14 億 ÷ 世界人口 81 億
  ＝ **1 人 1 日あたり 4.7×10⁻⁴**。感染していることによる抑制と、国ごとの旅行しやすさ、
  読者の移動量スライダー、両国の国境状態が掛かる）。1 人が運ぶのは **1 感染**で、定着するかどうかは
  現地の力学が決める。⚠ **「有病率 0.04% 未満は 1 人も出国しない」という足切りも、
  「1 国 1 日 3 回の抽選」も無い**——どちらもシミュレータについての規則であって旅行についての
  規則ではなく、人口 1 億の国は 4 万人が感染するまで 1 人も出国しなかった。
- ⚠ **速さは COVID-19 の実際の国数曲線に合わせて較正してある**（10 か国 ≒ 50 日・50 か国 ≒ 80 日・
  100 か国 ≒ 95 日。実測 59 / 81 / 95 日）。**置き換えた側は 245 / 349 / 402 日**で、世界より
  5 倍近く遅かった——行き先が一様抽選で出国が有病率の足切りだった間は、実際の流行と比べられる
  ものが 1 つも無かったので、それが見えなかった。
- **走らせる上限は 3 年**。出生・死亡・加齢が無いモデルで「風土病として定着した」とは言えないため。
- ⚠ **すべての病気が同じ「よく混ざった集団」の式で広がる。** 接触・埋葬・輪状接種が決める
  エボラのような病気は、この式では実際より広く伝わる（年齢構造・入院・都市単位も持たない）。
  **持っていないものを持っているように名乗らない**のがここでの約束で、埋めるのは別の仕事。
- ⚠ **点の数は症例数に比例する——国ごとの上限は無い。** 以前は「世界で 4,800 点」という全体の
  刻みと「1 国 80 点」という上限が同時にあり、1 国が世界の症例の大半を持つと**両立しなくなった**
  （48 万人・1 点 100 人なら 4,800 点必要なのに 80 点しか描かず、HUD の「1 点 ≈ 100 人」が 60 倍
  外れる）。上限は全体の 4,800 点だけになり、点の置き場（国内の実在都市に散らしたもの）は
  必要な数まで**継ぎ足しで**増える。
- **点には安定した id がある**（国 × 上限 ＋ 枠）ので、1 日の変化は `{add,remove}` として
  `GeoJSONSource.updateData` へ送る（全件アップロードは engine 側のフォールバック。`js/geo-engine.js`）。
- **低ズームでは点の下に密度面（heatmap）を敷く。** 全球表示では 1 点が 1 画素より小さく、4,000 点が
  一様な滲みになって密度を伝えないため。⚠ **点と入れ替えるのではなく下に敷く**——入れ替えると
  HUD の「1 点 ≈ N 人」が、点の無い画面で真でなくなる。
- ⚠⚠⚠ **点は「人が住んでいるところ」に、住んでいる人数に比例して置く。** 以前は country ごとのアンカーに
  **均等に**配っていたので、カナダ・ロシア・オーストラリアでツンドラ・タイガ・砂漠に症例が散っていた
  ——アラートのアンカーとトロントのアンカーが同じ 1 票だったからである。均一混合の区画モデルでは症例は
  **人口に比例する**ので、アンカーも人口で重み付けする（`scatterCases` が最大剰余法で配分し、
  **割り当ての残っているアンカーを巡回して**出す——巡回順は契約の一部で、`buildDots()` が先頭 `kE` 点を
  「潜伏」に塗るため、都市ごとにまとめて出すと潜伏例が 1 都市に集まる）。
  ⚠ **重みが等しい／無いときは、置換前と 1 点も違わない**（最大剰余法＋巡回＝以前の丸投げ巡回）。
  これは検査が保持できる性質で、「重み付き関数を別に作らない」理由でもある。
  ⚠ **人口ラスタは IntMap に無い**（NASA GIBS の GPW は描画済み PNG で誰も画素を読み戻さず、WorldPop は
  ポリゴン単位で数十秒かかる遠隔 API）。あるのは `data/gazetteer-world.json.gz`——GeoNames の 148,630 地点、
  うち 139,056 が人口を持ち、既に同梱・遅延読み込み済みで、国コードで引ける。
  ⚠ **面ではなく点であり、画面がそう名乗る**（都市の地名辞典が知っているのは町の位置であって農村部の分布ではない。
  `js/shakemap.js` が同じ表の同じ限界を同じ理由で名乗っているのと同型）。
  ⚠ **`PPLX`（市の一部）の行は落とす**——GeoNames はそれに独立の人口を与えるので、残すと親の市と二重に数える。
  ⚠ **アンカーの上限は無く、必要も無い**。`n` 点に対して点を受け取れるアンカーは高々 `n` 個なので、
  **人口上位 `n` 件だけを見れば十分で、取りこぼしはゼロ**。固定上限は取りこぼす——実測で 160 件に切ると
  世界の地名辞典人口の 29.8%、フランスの 66.6% を落とす。
  ⚠ **国は地名辞典自身の ISO2 で決める**（Natural Earth の 10 m 輪郭に訊くと縁で食い違い、148,630 行すべてに
  点内判定を払うことになる）。ただし**実際に点を受け取るアンカーには輪郭の内外判定を行い**、外に落ちたものは飛ばす。
  ⚠ **地名辞典は「世界の確定」には入らない**（区画は 1 バイトも見ないので、種の再現性に関わらない）。
  5 MB の取得を待たせる理由が無いので開いた直後に走らせ、届いた時点で**配置のプールを捨てて置き直す**
  ——届く前に描かれた国が、残りの実行のあいだ重みなしのままになるのを避けるため。
- 地図の点は**赤＝感染性あり・橙＝感染済みで未感染性**で、HUD が両方の人数と**1 点が何人ぶんか**を
  明示する。点は実在の都市に置き、**ゆらぎを加えたあとも国の多角形の中にあるか検査する**
  （`scatterCases()`）。中に置けなければ、その国は点を描かない。
- ⚠ **この層は「いま病気の人」なので、累計死者がこの層に国を残すことはできない。** 以前は
  `E=0・I=0・D>0`（＝流行が終わった国）が点を 1 つ描き、しかも **赤（＝感染性あり）** になっていた
  ——凡例が定義している意味と正反対で、HUD の数とも矛盾していた。累計死者は生きている国の点を
  **暗くする**（そこでの流行がどれだけ致命的だったかは、まだ症例がある場所の性質だから）。
- ⚠ **1 日の差分の署名は、訊かれた組をすべて区別できなければならない。** `cls + sev×2` は
  できなかった——`sev` は 20 分の 1 刻みなので `sev×2` は 0, 0.1 … 2 を取り、
  **(感染性あり・死者なし) と (未感染性・半分暗い) がどちらも厳密に 1** だった。色が変わった点が
  「変わっていない」と判定され、差分が何も送らないまま古い色が残る。整数で詰めれば衝突しない
  （`dotSignature`）。
- ⚠ **走らせる前に「どの世界か」を確定する。** 国境表（`data/country-facts.json`）と空港表
  （`data/airports.json`）は取得が済む**まで発生国を選べない**——移動行列は `createPandemicModel()`
  の時点で凍るので、以前は**回線の速さがどの世界になるかを決めていた**（早く押せば人口と距離だけ、
  遅く押せば空港と国境つき。後から表が届いても行列は作り直されない）。種が「同じ種なら同じ流行」を
  約束できるのは、**同じ種が同じ世界を指すときだけ**である。⚠ **失敗しても閉じ込めない**——
  取得は「解決した／失敗した」のどちらかに**決着**すればよく、失敗は**表ごとに画面が名乗る**。
- ⚠ **設定の値・入力欄の値・engine が走らせる値は 1 つの数である。** スライダーの刻みが表せない
  精度を持つプリセットは、この 3 つを引き裂く（Ebola の R₀ 1.95 は engine で 1.95・入力欄で 2・
  ラベルで「1.9」だった）。`snapToStep()` が**入力欄が実際に持てる格子へ丸めて engine に書き戻す**
  ——**すべてのスライダーについて**、次に足されるものも含めて。プリセットの精度のほうを守るべき
  ときは**刻みを変える**（R₀ は 0.05）。

- ⚠ **人口が測られていない行は、そもそも区画ではない。** `countryGeo` は Natural Earth の admin-0
  で、10 m では 258 行あり、そのうち **9 行の人口はゼロ**（ビル・タウィール、クリッパートン島、
  スカーバラ礁、南パタゴニア氷原……）。以前は `(s && s.pop > 0) ? s.pop : 3e6` という既定値が
  **測られていない行に 300 万人を発明**し、その人たちが感染し、死に、国境を閉じていた。人口は
  その下のすべての量の**分母**なので、ここに正直な既定値は無い——`createPandemicModel()` は
  **人口の無い行を拒否し**、host が落とした件数を画面が言う。
- ⚠ **入国規制とロックダウンを決めるのは政府であって、地図の行ではない。** 以前はすべての行が
  自分で決めていたので、**南極大陸が国境を閉鎖したという速報**が出ていた——表示の誤りではなく、
  行が実際に規制段階を上げ、輸入のループがその通過率に従っていた。`policyActors()`
  （`js/pandemic-model.js` の純関数）が 2 つの事実からこれを導く:
  **① 別の行が Natural Earth の `SOVEREIGNT` で自分の宗主だと名乗っているなら、その政府に従う**
  （グリーンランド→デンマーク、プエルトリコ→アメリカ、マカオ→中国）。
  **② そうでなければ、`data/country-facts.json` に首都（政府の所在地）があるときだけ自分で決める。**
  台湾・コソボ・西サハラは首都を持ち、どの行にも統治されていないので自分で決める——「国連加盟国か」
  で判定していたら 3 件とも間違えていた。南極大陸・ビル・タウィール・スプラトリー諸島・
  主権基地領域には首都が無く、政策を行わない。
  ⚠ **表が読めなかったときは誰も降格しない**（この回より前と同じ挙動）。画面がそう名乗る。
  ⚠ **`totals()` の「入国規制中」「ロックダウン中」は政府の数**である。従属領が宗主の措置を
  持っていても、それは同じ 1 つの措置だから。従属領の側は `step()` の最後に宗主の状態を写す
  （国のループの中で写すと、答えが配列の順番で決まってしまう）。
- **報せ方は 2 つに分かれる**（`eventKind()`）。世界の規則を変える出来事
  （ワクチン・治療法・変異株の命名・緊急事態の閾値・終了）は**同時に 1 枚だけ**トーストで割り込み、
  各国政府の反応（入国規制・ロックダウン・再開）は**出来事の記録**（HUD の 🗒）に積む。
  ⚠ **以前は全部がトーストだった**ので、1 日に動く政府の数だけカードが縦に積み上がり、
  **地図に最も見るものがある瞬間に地図が最も隠れていた**（実測 12 枚）。宣言の無い種類は
  `routine` に落ちる——間違えたときの代償が非対称だから。
  ⚠ **語彙は閉じている**: `tests/hazard-pandemic-model-checks.test.mjs` ① が、engine が実際に
  `events.push` する種類がすべて `eventKind()` に宣言されていることを突き合わせる（宣言の無い種類は `null` を返すので、鍵の一覧を検査に手渡さずに測れる）。
- **政策は地図の上の状態として描く**（`pg-policy-ring` / `pg-policy-lock`）。入国規制の段階が
  リングの色（黄→橙→赤）、ロックダウンの強さが青い芯の濃さ。国ごとの塗り分けではなく
  **政府ごとに 1 つのバッジを Natural Earth の LABEL_X/Y に置く**——多角形をもう一度アップロード
  すれば 10 m のジオメトリを二重に持つことになるが、点なら約 200 件で費用が無い。症例の点より
  **下**に置く（症例が主題で、政策は文脈）。
- **時系列は engine が持つ**（`model.history()`）。1 日 1 レコードで、`newInf` / `newDead` は
  **台帳（`cumInf` / `D`）の差分**である——輸入・市中感染・再感染はすべて台帳を通るので、
  呼び出し側を足し合わせる書き方と違って経路を取りこぼせない。HUD の折れ線は
  `chartPoints()`（純関数）で描き、**各バケットの最大値**を取る（平均だと 1 日だけのピークが
  消える）。2 系列は**それぞれのピークで正規化**し、両方のピーク値を印字する。
- **国をタップすると、その国の数字が出る**（`model.report(i)`）。**Rₑ（実効再生産数）はここで
  engine が計算する**——β・季節・行動変容・ロックダウン・現地の変異株混合が要るので、UI 側で
  組み直せば同じ問いに 2 つの答えができる。`behaviourOf()` / `betaOf()` /
  `rEffOf()` は 1 か所にあり、`step()` と `report()` の両方がそこを通る。画面は
  **Rₑ = R₀ × 季節 × 行動変容とロックダウン × 未感染の割合**と内訳まで書く（Rₑ が R₀ を上回る
  ことは季節次第で実際に起きるので、第 3 の数が無いと読者はどちらかが誤りだと考えるしかない）。
- ⚠⚠⚠ **画面の数がどこから来たかは、ドロワーで読める**（📖「出典と仮定」）。以前は `sources` を「 · 」で
  つないだ **10 px の 1 行**が「詳細設定」の折り畳みの中にあるだけで、URL も日付も無く、
  **どの数の出典なのかも書かれていなかった**——「R₀ 1.95」を見た読者が 1.95 の出所を知る方法が無く、
  **仮定であるパラメータと測定であるパラメータが見分けられなかった**。しかも走り出した瞬間に消えていた
  （`renderRun()` が `hud` を作り直すため）。ドロワーは**設定画面と走行中の両方**から開き、3 群に分かれる:
  ① **疾患のパラメータ** — プリセットごとの出典。⚠ **出典は「どの欄の出典か」を名乗る**
  （`sources` の各要素は `{ for, name }` で、`for` は**そのプリセット自身のフィールド名**。散文ではなく鍵なので、
  欄の改名や削除で attribution が黙って迷子にならない。`js/pandemic-model.js` は言語を持たないので、
  鍵を 9 言語の語にするのは `js/playground.js`）。
  ⚠⚠ **出典が「無い」ことも出典情報である**——ドロワーは**プリセット自身のフィールドから**「名前の付いた出典が
  無いパラメータ」を数え上げて名指しする（COVID-19 の R₀ 3.2 と IFR 0.7% はこの表に出典を持たない）。
  手で書いた一覧ではないので、欄が増えれば自動的に現れる。
  ② **この実行が使う世界** — 6 つの表それぞれについて、ライセンスと**この実行で何が起きたか**
  （`dataState` の「読み込み済み／一部の国のみ／読み込めませんでした／読み込み中」）。
  ③ **測定ではなく仮定** — 路線数が旅客流動の代わりであること、点が人口の面ではなく都市に載ること、
  初期免疫が何であるか、重症度が検出モデル無しに全感染へ当たること。
  ⚠ **③ が要点である。** 出典だけを並べる一覧は、画面のすべての数に出典があると読ませてしまう。
- **1 本のランは分布からの 1 回の抽出である**（📊「この結果はどこまで偶然か」）。同じ世界・同じ
  設定・同じ発生国のまま**乱数だけ変えて** 10 / 25 / 50 回走らせ、死者・延べ感染・到達した国と
  地域・ピーク・ピーク日の**中央値と 10〜90 パーセンタイル**、および結末の内訳（封じ込め／
  流行しきって終息／期間上限でも継続中の 3 つで、これが `end` の全部）を出す。⚠ **main thread で
  時間分割する**——Worker には失敗したときの控えが要り、その控えが走るのは**最も余裕の無い端末**
  である。残り時間は**終わったランの実測**から出す。分位数は補間した
  順序統計量で（`sorted[Math.floor(p*n)]` は 10 本で p=0.10 と p=0.19 に同じ値を返し、p=1 に
  何も返さない）。

### 8.6 紹介ページ・授業ページ・見本の地図 (Landing & showcase)

アプリを開いたことのない人が着くページと、そこから開く見本の地図。**4 つの読み手が 1 つの宣言を読む**。

| 何 | どこ | 誰が書くか |
|---|---|---|
| 見本の宣言（視点・日付・レイヤー・ベースマップ・日英の題/説明/問い・`drawn`） | `js/showcase.js` `SHOWCASE` | 手で書く |
| 見本のリンクと画面写真 | `js/showcase.js` の生成領域 `CAPTURED`・`img/showcase/<id>.jpg`（とギャラリー用の `<id>-thumb.jpg`・480×252＝カードの縮小） | `scripts/showcase-capture.mjs` |
| ページの文（en + jp） | `scripts/landing-text.mjs` | 手で書く |
| `about.html` `teachers.html` `news-map.html` `embed-map.html` `developers.html`（データセットの表はビルドが埋める——01-overview §1.1）と `ja/` の同名、`sitemap.xml` `robots.txt` | リポジトリ直下 | `scripts/landing.mjs --write` |
| 見本ごとの共有ページ `s/<id>.html`・`ja/s/<id>.html` と、その og:image `img/showcase/<id>-card.jpg`（1200×630） | `s/`・`ja/s/`・`img/showcase/` | `scripts/landing.mjs --write`・`scripts/showcase-capture.mjs` |

- **リンクは手で書かない。** `scripts/showcase-capture.mjs` が**ビルドしたサイト**を Chromium で開き、
  投影・ベースマップのボタン、共有リンクが運ぶ全レイヤーのチェックと `change`、レンダラ契約のカメラ、
  Chronos（`IntMapTime`）で宣言どおりの状態を作り、アプリ自身の符号化（`IntMapBookmark.link()`＝
  §14 の `#v=` 形式）を読む。同じ瞬間に画面を撮る（実ネットワーク）。宣言に無い状態
  （`s=` や、基本表示の `d=`——昼夜は既定で点いているので、撮影は基本表示も自分の箱で消す）を符号化した
  リンクは書かない。`--serve dist` はこの実行の間だけ `scripts/serve.mjs` を立て、終わると止める。
- **ページは生成物。** 文・見本・事実（時計の床 `js/hist-scale.js` `FLOOR`、時代のスナップショット数
  `data/hist-eras.js`、国境の帯 `js/time-borders.js` `HB_MIN/HB_MAX/CS_MIN/CS_MAX`、レイヤー数
  `js/layer-manifest.js`、寄付リンク `js/supporter.js` `STRIPE_DONATE`）をそれぞれの持ち主から読む（サイトの住所は下の
  「絶対アドレス」）。**ページに数字を手で書かない。**
  言語は別 URL（`hreflang`）で、JS が無くても全文が読める。全ページに埋め込んだスクリプト（生成器の `PAGE_SCRIPT`）はテーマと、
  **日本語を選んだ読者**（アプリの設定または切替）だけを日本語版へ送る（保存された選択が無い訪問者は動かさない）。
- **紹介ページの冒頭（時空間の時計と三つの入口）**: 見出しの上のカテゴリ・見出し・信頼の一行は `scripts/brand-text.mjs` の
  `category`・`tagline`・`trust` を `scripts/landing.mjs` が直接読む（`landing-text.mjs` に写さない）。横の絵は
  `stripExamples()`——表示する見本のうち**日付を持ちレイヤーを持たない**もの（時計だけが絵を変える地図）を日付順に——の
  画面写真で、`HERO_EXAMPLE` の 1 枚だけが見え、他は `hidden`（遅延読み込みの絵は選ばれるまで取らない）。スライダーと年の
  ボタンも `hidden` で出し、紹介ページだけに置く 2 本目のスクリプト `STRIP_SCRIPT`（`PAGE_SCRIPT` と同じくハッシュで許可）が
  見せて 1 枚ずつ切り替える——スクリプトが無ければ 1 枚とそのリンクが残るだけ。その下の**三つの入口**（`ENTRANCES`）:
  「いまの世界」は時刻を持たない（＝現在の）地図に共有可能なライブ層を点けたリンクで、**アプリ自身の符号化器**
  （`js/map-state.js` `encode`）が書く（地震の層はリンクで運べないので、文はレイヤーから点けるよう述べる）。「どの年の
  世界も」は見本 1 件の撮影済みリンクと歴史地図の入口。「Atlas に訊く」は地図を開くだけ（Atlas パネルを開く URL は無い）。
  `--check` の `entranceProblems()` が、共有できない層・見本でないもの・時計に 2 枚未満を拒む。
- **共有ページ（SNS の素材）**: アプリの住所 `index.html#v=…` は状態を断片（`#`）に持つのでサーバへ届かず、
  どの見本も同じカードに展開される。Supabase Edge Function は text/html を返せないので要求時にも作れない。
  ⇒ 見本ごとに `<head>` がそのままカードになる静的ページを生成する（og:title/description/url/image・
  `twitter:card=summary_large_image`・自身への canonical・hreflang）。画像はアプリ自身が撮った 1200×630 で、
  `og:image:width/height` は**画像ファイルから読む**。人には meta refresh（JS 無し）と `location.replace`
  （履歴を残さない）とリンクの 3 つで、その見本の地図へ送る。絶対 URL は `index.html` の `og:url` 1 か所から。
- **SEO**: 各ページに title・description・canonical・hreflang（en/ja/x-default）・Open Graph・JSON-LD
  （紹介は `WebApplication`・価格 0、授業は `WebPage`）。`robots.txt` はホストの根でしか読まれない
  ので、`/IntMap/` 配下の今は効かない（ファイルにそう書いてある）。Search Console の確認ファイルは残す。
- **用途別のページ**: `news-map.html`（ニュースを地図で読む——News の出来事単位のピン・媒体ごとの記述・周りの
  レイヤーと時計・「Atlasに聞く」。背景の見本は主題が地球と人・経済の一般向け見本から導く）と `embed-map.html`
  （記事に地図を埋め込む——3 つの手順、**埋め込みタブが書くコードそのもの**＝`js/embed-mode.js` の
  `embedUrl`・`iframeCode`・`EMBED_SIZES` を英雄の見本の捕えたリンクに当てたもの、枠の題はアプリの文字列
  `embedFrameTitle`、何が見え何をしないか）。紹介ページの「こんな使い方も」から相互に結ぶ。
- **アプリ内の作例ギャラリー**（`js/showcase-gallery.js`）: 検索欄に何も打たずにカーソルを置くと、結果欄（携帯では
  欄が上げたシート）に作例と授業ツアーのカードが 1 列で並ぶ（写真・題・1 行）。最初の 1 文字で地名の候補に替わる。
  「すべて見る」・`data-im-gallery` の付いた操作・Atlas の `panel.gallery` で全体を開く（主題ごとの見出し
  ＝`TOPICS`、最後にツアー。`IntMapDialog` の契約）。カードは `SHOWCASE`（捕えたリンクと縮小がある見本）と
  `TOURS`（最初の見本の段の縮小）から導き、手で並べない。1 タップで見本は `openShowcase`（共有リンクの復元＋
  読み返し。Atlas の `panel.showcase` も同じ関数）、ツアーは `js/tour-player.js` の `startTour`。**自動では開かない**
  （初回のウェルカムカードは利用者の指示で撤去済み）。モジュールは最初にその欄へ触れたときに読む。
- **入口**: 設定 ▸ 情報とサポートの「IntMap について」（`#link-about`）。Atlas の `panel.about`
  （ページへのリンク）と `panel.showcase`（`id` で見本を開く——`js/showcase-gallery.js` の `openShowcase`：
  アドレスに捕えたリンクを置いて `IntMapBookmark.restore({shared:true})`＝読者がリンクを開いたのと同じ経路。日付と
  レイヤーが宣言どおりになったことを**読み返してから** completed を返す。`id` が無ければ一覧）と `panel.gallery`
  （作例ギャラリーを画面に出す。`section:"tours"` でツアーへ）。catalogue の一覧は `SHOWCASE` から作る（手で並べない）。
- **見せない見本**: 宣言に `withheld`（開くと写真どおりにならない、と実測した理由の文）がある見本は `SHOWCASE` に入らず、
  ページ・sitemap・Atlas・spec のどれにも出ない（宣言とリンクは残る）。生成器は自分の `s/` に残った古い共有ページを消す。
- **絶対アドレス**: 生成物は `scripts/site-url.mjs` の `SITE_TOKEN` を書き、ビルドの `siteUrlPlugin` が dist/ に写った
  .html/.xml/.txt のトークンを `site-origin.js` の値で埋める（`fillSiteToken`）。robots.txt の基底パスは `SITE_BASE_PATH`。
- **門**: `node scripts/landing.mjs --check`（`tests/landing-showcase-checks.test.mjs` が走らせる）——
  生成物が生成器と一致し、捕えたリンクが宣言（視点・投影・ベースマップ・レイヤー・日付）と一致し、
  宣言に無い状態を運ばない。`tests/landing-showcase.spec.js` が**全見本を開き**、日付・カメラ・
  レイヤーと `drawn`（その日付に地図が描く国名・行政区分）を地図に訊き、ページのリンク切れと
  モバイル幅の横スクロールが無いことを測る。

#### 8.6.1 授業ツアー (Classroom tours)

教員が登録なしで 1 コマを回すための「導かれた物語」。地図の状態を順に並べ、各段に**読み上げる文**（`say`）と
**生徒への問い**（`ask`）を付け、**授業モード**（全画面・大きな文字・余計な UI を隠す）で「次へ／前へ」と進む。

| 何 | どこ | 誰が書くか |
|---|---|---|
| ツアーの宣言（題・説明・学習指導要領の項目・段） | `js/tours.js` `TOURS` | 手で書く |
| 段のリンク（見本を名指す段は見本の `CAPTURED` をそのまま使う） | `js/tours.js` の生成領域 `CAPTURED_STEPS` | `scripts/showcase-capture.mjs` |
| 授業モード（パネル・キー・ピッカー・一時ツアー） | `js/tour-player.js` | 手で書く |
| 授業ページの「授業ツアー」の節 | `teachers.html`・`ja/teachers.html` | `scripts/landing.mjs --write` |
| 授業ページの「自分のツアーを作る」の節（`js/tour-builder.js` が実際にすることだけを述べる） | `teachers.html`・`ja/teachers.html` | `scripts/landing.mjs --write` |
| 全ページの足元の入口（紹介・授業・ニュース・埋め込み・年代から探す〔`history/`〕・報道/学校/研究/支援/相談）。**一覧は手で並べず**、`PAGES`・`ORG_NAV`・`HUB` から導く | 紹介系 8 ページと組織向け 10 ページ（`ja/` を含む） | `scripts/landing.mjs --write`・`scripts/org-pages.mjs --write` |

- **段は見本と同じ方法で作る。** 段は `example:`（見本の id）を名指すか、見本と同じ形の意図（`view`・`base`・
  `at`・`layers`・`drawn`）を持つ。リンクは手で書かず、`scripts/showcase-capture.mjs` がビルドしたアプリを
  その意図に置いて `IntMapBookmark.link()` を読む。`node scripts/landing.mjs --check` が見本と**同じ規則**
  （`linkProblems`）で、捕えたリンクが意図と一致し宣言外の状態を運ばないこと、見本を名指す段がその見本を
  **見せている**（`withheld` でない）ことを確かめる。
- **開き方は共有リンクの復元だけ。** 段を開くとアドレスが `?tour=<id>&step=<n>#v=…` になり、
  `IntMapBookmark.restore({shared:true})` が状態全体（カメラ・投影・ベースマップ・レイヤーのオンとオフ・時計・
  比較・シミュレータ）を適用する。2 つ目の復元器は無い。時計とレイヤーを**リンク自身の `tt` と `l`** に照らして
  読み返してから「開いた」とする（上限 6 秒——復元の最後の段 3.2 秒＋余裕。Atlas の `panel.showcase` と同じ読み）。
  アドレスバーは常に「いま映している段」へのリンク。
- **入口**: URL `?tour=<id>&step=<n>`（授業ページのリンクは断片に段のリンクを持つので、起動時の復元がそのまま
  地図を開く。断片の無い手打ちの URL はプレイヤーが復元する。知らない id はツアーの一覧を開く）／
  設定 ▸ 情報とサポートの「授業ツアー」（`#btn-tours`）／Atlas の `panel.tour`。プレイヤーは独立したチャンクで、
  `src/main.js` がこの 2 つの場合にだけ読む（通常の起動では取得しない）。
- **ガイド**: 初めて見る人向けの案内は専用の仕組みを持たず、このプレイヤーの `guide` ツアー（`?tour=guide`）。段は
  `js/showcase.js` の `guide: true` の作例から `js/tours.js` の `guideTour()` が導く（作例のタイトル・説明・問い・撮影済みリンクそのまま）。
  `TOURS` には入れない（授業ではないので教員ページ・一覧に出ない）。入口は `js/onboarding.js` の `_imStartDemo`
  （一度だけ・スマホでは出さない・主題レイヤーが既にオンなら出さない、の規則を持つ）。
- **授業モード**: `html[data-classroom]` の下で、地図・凡例（`.data-legend`・`.koppen-legend`）・出典表示
  （`#map-credit`・レンダラの credit）・アプリの通知（`#ai-toast`）・パネルだけを**残す一覧**で隠す（埋め込み表示と
  同じ作り。来年足されたパネルも自動で隠れる。出典表示は利用条件なので削らない）。キー: → / Space / Page Down で次、
  ← / Shift+Space / Page Up で前、Home / End、F で全画面、T で文を隠す、Esc で終了（プレゼン用リモコンが送るキー）。
  アプリ内から始めたツアーは、終えると始める前の地図へ戻る。
- **一時ツアー（Atlas）**: `panel.tour` の `addStep` が**今の地図**を `IntMapBookmark.link()` で段として記録する
  （語りと問いは Atlas が書く）。タブの `sessionStorage`（`intmap_tour_temp`）に置き、id `atlas` で再生する。
- **語りは地図についての主張**: 段の `drawn` が文の依拠する名前を持つ——`labels`（その日の国名）・`admin`（第1級区分）・
  `noAdminIn`（「この範囲に区分を描かない」という不在の主張）。`tests/classroom-tours-checks.test.mjs` が
  地図の描く記録（`data/cshapes.js`・`data/hist-admin1.js`・`data/hist-kuni.js`・`data/hist-admin-fill.js`）に訊く。
- **段が地図の外の操作を求めるとき**（共有リンクが運ばないレイヤーをオンにする、など）は、問いの中で
  アプリ自身のラベルで名指す（同じテストが locale と行の表示名に照らす）。
- **門**: `node scripts/landing.mjs --check`・`tests/classroom-tours-checks.test.mjs`。ブラウザでは
  `tests/landing-showcase.spec.js` が最初の見本を**それを通るツアーのアドレスから**開き、パネル・→ キーでの次の段
  （アドレスとカメラ）・Esc での終了を同じ起動の中で測る（新しい spec は作らない——テスト時間の総量には天井がある）。

#### 8.6.2 ツアー作成 (Tour builder)

教員が**自分の授業のツアー**を作り、リンク 1 本で配る。アカウントもサーバの表も無い。

- **入口**: ツアー一覧（`#btn-tours` のピッカー）の「自分のツアーを作る」／再生中の自作ツアー（`custom`）と
  Atlas の一時ツアー（`atlas`）のパネルの「このツアーを編集」（鉛筆）／Atlas の `panel.tourBuilder`。
  `js/tour-builder.js` は独立したチャンクで、これらが要求したときだけ読まれる。
- **段は地図そのもの**: 「いまの地図をステップに追加」は `MapState.hash()`（アドレスバーと共有リンクを書く codec）を
  そのまま段にする——カメラ・投影・ベースマップ・レイヤー・表示項目・時刻・比較・シミュレータ、共有リンクが運ぶもの全部。
  各段に題・話すこと・授業での問い（任意）。並べ替え（上へ／下へ）・削除・「いまの地図にする」（語りは残して地図を差し替え）・
  「この地図を表示」（共有リンクの復元で開く）。
- **保存はアドレスそのもの**: `?tour=custom&t=<ツアー>&step=<n>#<段 1 の地図>`。`t` は
  `{ v:1, n:題, s:[[断片, 題, 話すこと, 問い], …] }` の JSON を DEFLATE（`CompressionStream('deflate-raw')`）して
  base64url にしたもので、先頭 1 文字が書式（`z`＝圧縮、`j`＝圧縮できない環境向けの素の JSON）。codec は `js/tours.js`。
  プレイヤーは各段の断片を **地図の codec で書き直してから**使う（地図を名指さない断片は「リンクの無い段」になる）。
  書き手のブラウザでは下書きを `localStorage`（`intmap_tour_draft`）に保つ。
- **長さの上限は実測**: クエリはサーバへ送られる（断片は送られない）。本番（GitHub Pages）は path＋query が
  **8,192 バイトまで 200、8,193 バイトで 414**（二分探索で実測。`TOUR_REQUEST_LIMIT`）。パネルは使用量を常に示し、
  残りがこのツアーの 1 段あたりの平均より少なくなったら「あと 1 ステップ入らないかもしれません」と**先に**警告し、
  超えたツアーにはリンクを渡さない（コピー・共有を止める）。
- **再生は既存のプレイヤー**: `startTour('custom', n, { t })`。授業モード・キー・読み返しは宣言ツアーと同じもの
  （写しは無い）。プレビューも同じ経路で、終えると作成パネルに戻る（パネルは授業モードの「残す一覧」に無いので隠れる）。
- **共有**: 「リンクをコピー」（クリップボードが拒んだら選択済みの入力欄でリンクを渡す）・`navigator.share` がある端末では「共有」。
- **アカウントに保存**（map-document-unify）: 下書きを地図ドキュメント（`kind:'tour'`）にしてライブラリへ渡す（§8.1.2）。
  アカウントの行はリンクの長さの上限を受けないので、長いツアーもコレクションに入れて閲覧専用リンクで配れる。
  `t` の梱包は `js/link-codec.js`（ブリーフィングの `b` と同じ 1 つ。出力のバイト列は以前と同じ）で、読み手は
  `TOUR_INFLATED_MAX`（アカウントが 1 文書の段に許す 1 MiB の 2 倍）を超えて展開しない。
- **作成器で開くアドレス**: 同じアドレスに `&edit=1`（`js/tours.js` の `TOUR_EDIT_PARAM`）が付くと、プレイヤーは再生せず
  ツアーを `openBuilder({ load })`（「このツアーを編集」と同じ経路・同じ変換）に下書きとして渡し、クエリを消す（再読み込みで
  同じ下書きをもう一度渡さない）。地図は断片の段 1 で開いている。単元対応表（§8.6.5）の「この単元のツアーを作る」がこれを使う。
- **門**: `tests/tour-builder-checks.test.mjs`（codec の往復・断片の書き直し・`?tour=custom` の読み戻し・
  作成の各操作・再読み込み後の下書き・共有リンクの復号・上限の警告と拒否・Atlas の行と catalogue）。
#### 8.6.3 印刷用ワークシート (Classroom worksheet)

授業ツアーを**紙**にする。生徒が机で書き込むのは紙なので、各段の地図・問い・解答欄を A4 に並べる。

- **入口**: 授業モードのパネルのプリンタのボタン（宣言ツアー・自作ツアー・Atlas の一時ツアーのどれでも）／
  Atlas の `panel.tourWorksheet`（`id` を渡せばそのツアーを始めてから作る）。`js/tour-worksheet.js` は独立したチャンクで、
  押されたときだけ読まれる。
- **撮り方は既存の 2 つの部品**: 段は**プレイヤー自身**（`go(n)`——共有リンクの復元と読み返し）で開き、地図が描き終えたかは
  **タイムラプスがコマを撮る前に訊くのと同じ読み**（`js/time-lapse.js` の `mapDrawn`——時間の核が判定した・タイルが揃った・
  画面の境界の記録がその瞬間のもの）で待ち、絵は**地図の絵葉書**（`js/map-recorder.js` の `postcard`、リンクカードの
  1200×630——凡例と全出典を焼き込む）で撮る。合成器の写しは無い。撮り終えたら先生がいた段へ戻す。
- **描けなかった段は撮らない**: 隠れたタブ（絵葉書が `not-drawn`）と、`DRAW_WAIT_MS`（30 秒・推定）までに描き終えなかった段は、
  半分描けた絵を載せず、その場所に「撮れませんでした」と書き、結果がその段を名指す。
- **2 種類の紙**: 生徒用（題・宣言ツアーが述べる学習指導要領の項目〔`js/showcase.js` の `CURRICULUM`〕・組／番号／氏名・
  各段の題・地図の日付・地図・問い・解答欄 4 行）と教員用（加えて読み上げる文と、宣言ツアーなら各段を開く短いアドレス
  `index.html?tour=<id>&step=<n>`——プレイヤーはクエリだけで段を復元する）。足元に全段の出典を 1 回ずつ文字でも書く。
- **印刷はブラウザのもの**: プレビューの「印刷」が `window.print()`（紙または「PDF に保存」）。印刷用の CSS は
  `html[data-worksheet]` の間だけ効き、プレビュー以外を全部隠す（A4 縦・余白 12 mm）。紙は常に白地に黒。
  アップロードも保存も無い。授業モードの「残す一覧」に `#im-worksheet` があり、開いている間プレイヤーはキーを譲る。
- **門**: `tests/sales-next-checks.test.mjs` ①〜③（紙の模型を評価——項目・段・生徒用と教員用・段を開くアドレス・
  出典の重複なし・撮れなかった理由／絵葉書と描画の読みを借りていること／Atlas の行と catalogue）。

#### 8.6.5 単元対応表と学校向けの 1 枚 (Curriculum unit map & school handout)

教員の言葉（**単元**）から入る道と、学校の管理職・情報担当に回す 1 枚。どちらも `scripts/org-pages.mjs` が生成する組織向けページ
（`curriculum.html`・`school-handout.html` と `ja/`）で、上の帯（`ORG_NAV` の `{ bar: false }`）には出さず、全ページの足元・
学校向けページ・授業ページの「高等学校学習指導要領との対応」から辿る。

| 何 | どこ | 誰が書くか |
|---|---|---|
| 単元（一次資料からの引用）・訳・根拠の句・対応させる見本／状態／ツアー／クエスト・典拠（URL・閲覧日・sha256・ライセンス） | `data/curriculum-units.json` | 手で書く（一次資料の転記） |

#### 8.6.3 この日の歴史地図 (On this day)
暦の 1 日（`MM-DD`）について、地図が描く記録がその日に日付をつけている出来事を、記録の全年分まとめて読む。
**索引は 1 つ**で、読み手は 4 つ——アプリのカードとシート、Atlas、ビルドが書く静的ページとその絵、投稿の下書き。
⚠ この索引は**日付つき出来事の唯一の索引**でもある（`js/time-index.js` が記録の形・出典 `sourceOf`・日付の精度・切り口を持つ）。
暦の日の切り口（`onDay`）がこの節、**年の切り口**（`inYear`）が年鑑（§7.4b）、**時刻までの切り口**（`upTo`）が情報ダッシュボードの
「出来事」——地図の時計の瞬間までに始まった記録を新しい順に並べ、‹ › は時計そのものを 1 年動かす（手書きの表と独自の年の範囲は無い）。
索引は暦の日の記録（`days`）の横に、どちらの記録も述べない出来事を **Wikidata が述べるとおり**に持つ（`events`：項目 QID・日付を
述べた属性・精度・ユリウス暦の印・場所は項目か所在地の座標がある時だけ）。それは `scripts/fetch-world-events.mjs` が選んだ記事から
項目を引いて写しに書き（`scripts/time-index/wikidata-events.json`）、生成器は写しだけを読む。日付は P585（時点）と P580（開始）を
合わせて最も細かい精度の最も早い日、無ければ開通・初飛行・打ち上げ・発見・発表・成立の順。項目自身の終了より後の開始は日付に
しない。史実と矛盾する値は**値と理由を名指して**拒み（Wikidata が直せば「古い拒否」として報告される）、日付を述べない項目は落とす。
**Wikidata の出来事は暦の日のページには載せない**——ページが約束するのは地図が描く記録だから（年鑑と「出来事」には載る）。
| 何 | 正本 | 書き出し先 | 誰が書くか |
|---|---|---|---|
| 索引（`MM-DD` → 出来事） | `scripts/build-on-this-day.mjs` | `data/on-this-day.json`（追跡。`--check` で記録と照合） | 記録を直したら手で再生成（門 ① が古さを落とす） |
| 文言・見出しの規則・地図のリンク | `js/on-this-day.js`（`describe`・`headline`・`viewOf`/`stateFor`/`linkFor`） | アプリ・Atlas・静的ページ・下書きが同じ関数を読む | — |
| 静的ページ（日ごと、en と `ja/`）・暦・sitemap | `scripts/on-this-day-pages.mjs`（文は `scripts/on-this-day-text.mjs`） | ビルド時に `dist/on-this-day/<MM-DD>/`・`dist/ja/on-this-day/…`・`dist/sitemap-on-this-day.xml`（`sitemap-index.xml` が束ねる） | `vite.config.js` の `onThisDayPagesPlugin`（子プロセス） |
| リンクのカードの絵（1200×630 PNG） | `scripts/lib/map-card.mjs` | `dist/on-this-day/<MM-DD>/card.png`（言語共通） | 同上（子プロセスを最大 4 つに分けて描く） |
| 投稿の下書き | `scripts/on-this-day-pages.mjs --queue` | 標準出力（承認待ちの一覧。**投稿・送信・予約はしない**） | 人が読み、承認したものを人が投稿する |
- **国境の出来事は地図のコードが求める**。`scripts/history-pages.mjs` の `mapReader`（`js/time-borders.js` を Node で
  実体化したもの）に `changeDates()` の各日とその前日を訊き、地図が書く名前（`tagSame`）で比べる——前日に無く当日に
  ある政体は「地図に現れる」、逆は「地図から消える」、両日にあって描かれた面積が 1 km² 以上違えば「国境が変わる」。
  記録自身がその日にその政体の境（行の始まり、または前日の行の終わり）を持つものだけを載せる（名前の表は年単位なので、
  他国の国境の日に重なった改名は載せない）。CShapes の 1 月 1 日付けは `maybeYearOnly` の印を持ち、見出しにならない。
- **載せないもの**（索引の `skipped` が数える）: OpenHistoricalMap の記録（1689〜1885 年。日付に精度の欄が無く、
  2,480 の日付のうち 918 が 1 日——その日の主張にならない）、記録の継ぎ目（1886-01-01）、1689 年より前のシート。
- **戦争の出来事**は `data/wars.json` の行そのもの（完全な日付を持つもの）。地図のリンクはその戦争のレイヤーを点ける。
- **見出し**は `js/atlas-reasoning.js` `rankChanges`（変わった政体の数——歴史の重みの判断ではない）。その日に 1 月 1 日付け
  でない国境の出来事が無ければ、戦争の記録の最初の出来事。
- **地図のリンク**は日付（`tt`）・場所（政体の範囲を枠に収める `fitView`。歴史地図の入口ページの地域と同じ関数）・
  戦争のレイヤー（`l=dl-<戦争>`）・題（`title=`、出来事の文）を持つ。アプリでは共有リンクの復元で開き、時計とレイヤーを
  読み返してから「開いた」と言う（`js/showcase-gallery.js` `openLink`。作例と同じ開き方）。
- **アプリの入口**: 地名検索の欄に何も打たずに触れると、作例の帯の上に「この日の歴史地図 · 10月3日」のカード（今日の
  見出しを 1 タップで地図に、「すべて」で日ごとのシート。‹ › で前後の日へ）。今日の出来事が無ければ出さない。
  Atlas は `onThisDay`（`time.onThisDay`。`open:n` で n 番目を地図に、`show:true` でシート）。
- **計測**: 日のページと歴史地図の入口ページは匿名集計の入口（`entry` の `on-this-day`・`history`）。下書きのリンクは日の
  ページに utm を付け、そこから地図へ進んだ読者はそのページの utm で数えられる（ページだけを見た人は数えない）。
- **門**: `tests/marketing-next-checks.test.mjs`（索引が記録どおり・日と場所を名指した照合——1990-10-03、1945/1947/1948-08-15、
  1971-08-15——・名前がエポック内の問い順に依らない・リンクを地図の decoder で読み返す・ページと sitemap の整合・絵の形式と
  大きさ・下書きの tag と X の文字数・Atlas を索引で実行）。

  データセット（ライセンス未記載・再配布不可・サイトに無い）は節ごと出ない。出典表示が条件のものは同じページに出典とライセンスを書く。

- **オープンデータ**は国ごとに、提供されるデータセットの ID・ライセンス・条件・表示する出典と `api/v1/countries/<CODE>.json`

- **導線**: 紹介・授業・組織向けページのフッタ（`scripts/landing.mjs` `pageLinks`）と歴史地図のハブから一覧へ。

- **門**: `tests/country-pages-checks.test.mjs`（全コードにページ・一覧の順・地図のリンクを地図の decoder で読み返し、視点が国の枠を

- **年は規則で選ぶ**（`chooseYears`。手で並べた一覧は無い）。3 つの集合の和で、各ページはどれに選ばれたかを書く:
  ① historical-basemaps のシートの年（`data/hist-eras.js` の `snaps`）、② 日付を持つ記録（Cliopatria・OpenHistoricalMap・
  CShapes。最寄りのシートで補った輪郭は除く——その「変化」はシートの切り替わり）を、記録が始まる前のシートの年から CShapes の
  最終年まで毎年 7 月 1 日に読み、描き始めた名前と描かなくなった名前の和が、0 でない変化の上位 `TURN_SHARE`（5%）に入る年。
  答えを組む記録の組が変わる年（OpenHistoricalMap・CShapes の始まりなど）は**記録の継ぎ目**で、世界の変化として数えない、
  ③ 日付つき出来事の索引の Wikidata の出来事のうち、種類（`EVENT_KINDS`。索引の種類はすべてここで分類し、未分類の種類は
  ビルドを止める）が政体に関わるもの（地政・戦争・革命）の年。CShapes の最終年より後は地図が現在の国境を描くので選ばない。
- **ページが述べるのは地図が描くもの**。名前・記録・面積・絵は `scripts/history-pages.mjs` `mapReader`（地図の
  `js/time-borders.js` を実体化したもの）が 7 月 1 日に答える集まりから。名前の表は描かれる面積の順で、各行にその輪郭を描く記録と、
  記録が結ぶ Wikidata の項目。見出しは「名前」であって「国」ではない（シートは文化圏や「Antarctica」も描く）。
- **絵**は Equal Earth 図法・幅 1000 px の SVG。輪郭は表示のためだけにおよそ 1 px まで簡略化し（Douglas–Peucker）、1 px 未満の
  輪郭は絵から省く（データは触らない。ページにそう書く）。日付変更線をまたぐ環は両側に描いて図の縁で切る。陸地は今日の
  Natural Earth 1:110m を先に灰色で敷く（どの記録も政体を述べない陸地が海に見えないように）。シートの年でない年に最寄りの
  シートから補った輪郭は淡く塗り、図の註がそう言う。明暗は `prefers-color-scheme` で切り替わる。
- **変化**は前のページの年との比較で、日付を持つ記録の名前だけを数える（シートで補った名前は両方の年がシートの年のときだけ）。
  名前は書かれたとおりに比べるので、2 つの年で別の名前を持つ政体は両方の欄に出る（ページに書く）。
- **出来事**は索引の記録のうち、日付が名指す年がその年のもの（`js/time-index.js` `yearOf`。その年をまたぐ期間ではない）。
  国境の記録・戦争の記録はその日のページへ、Wikidata の出来事は項目へ結ぶ。
- **構造化データ**は `WebPage` の `mainEntity` に `Map`（`temporalCoverage` は ISO 8601 の年、`image` は絵、`url` は地図を開く
  リンク）と `BreadcrumbList`。リンクのカードの絵（`og:image`）はサイトの共通の絵。
- **地域ページ（世界）とは別の検索意図**: 地域ページ `history/world/<年>/` は「World map in 1914」＝**地図**、年ページは
  「The world in 1914: states, borders and changes」／「1914年の世界——国と国境、前の年からの変化」＝**その年の国の一覧と変化と
  出来事**。題・h1・description は重ならず（門が地域ページの題を生成器から読んで比べる）、canonical はそれぞれ自分自身。
- **導線**: 歴史地図のハブから一覧へ。各年は、同じ名前を並べる地域ページ（世界）があればそこへ「地図」として（シートの間の年には
  無い）、世界の地域ページは範囲の年のうち年ページのある年へ「国と変化」として結ぶ（年は `year-pages.mjs` `chooseYears` に訊く）。
- **計測**: `history/` の下なので匿名集計の入口は既存の `history`（新しい値・新しい開示は無い）。
- **門**: `tests/history-year-pages-checks.test.mjs`（規則をデータから導き直して年が一致すること・継ぎ目を数えないこと・
  紀元前 200 年／1000 年／1648 年／1815 年／1914 年／1945 年に描かれるべき名前と描かれてはならない名前・シートで補った名前を
  変化に数えないこと・出来事の年・絵と地図のリンクと構造化データ・hreflang・sitemap・リンク先の実在）。
#### 8.6.4 学ぶクエスト (Learn quests)
地図そのものを教材にする出題。IntMap が持つ実データから問題を作り、**答えは地図の上で出し、地図の上で示す**。
既存のクイズ（`js/analysis-edu.js` の国旗・首都・国クリック・シルエット・人口／面積対決）はそのまま残り、その
メニューから入れる。
| 何 | どこ |
|---|---|
| 出題エンジン（純関数。DOM・`window`・通信なし。Node でも読める） | `js/quest-engine.js` |
| パネル（遅延読み込み・`window` グローバルを足さない） | `js/quest-panel.js` |
| 今日のクエストの記録と連続日数（遅延読み込み） | `js/quest-daily.js` |
| その日の結果（アカウント側） | `public.quest_daily_results`（`supabase/migrations/20261008090000_quest_daily.sql`・pgTAP `30_quest_daily_test.sql`） |
| Atlas の能力 `learn.quest`・`learn.daily` | `js/atlas-cap-learn.js` |
| 検査 | `tests/learn-quests-checks.test.mjs`・`tests/watch-account-product-checks.test.mjs` |
- **種類はレジストリ**（`QUEST_KIND_IDS` などの一覧は全部そこから導く）。各種類は `{id, title{en,jp}, needs, generate(rng, data, n), score(q, a)}`。
  - **場所当て `where`** — `data/gazetteer-phone.json.gz`（GeoNames・CC BY 4.0）のうち、GeoNames 自身が `placeKinds` で
    settlement と呼ぶ行（市の一部・歴史上の地点・廃絶地は出さない）。都市名（出典の表記。日本語名が無ければ出典の英語名）と
    国名（ブラウザの `Intl.DisplayNames`）を出し、読者が地図をタップする。**難易度は人口の順位の分位**で、順位の対数で 3 段
    （境は順位 N^(1/3)・N^(2/3)。人口の閾値はどこにも書かない。都市人口はおおむね順位に反比例するので、順位の等分では
    30 万人の都市が「やさしい」に入る——初回の実測）。1 セットは前の 3 分の 1 が「やさしい」から順に上がるので、
    リンクに難易度の欄は要らない。採点は `js/geodesy.js` の `_distKm`（大円の線を引く式と同じ）。
  - **年代当て `when`** — `data/on-this-day.json` の出来事（国境の記録の変化日・戦争の記録）。文は `js/on-this-day.js` の
    `describe`（記録が自分について述べることだけ）、地図は同じファイルの `viewOf` の視点と、その日を主時計に置いたもの。
    **年を隠す**: 問題の間、`<body>` の class 1 つ（`im-quest-blind`）が、**地図の時刻を印字すると自分で述べる要素**
    （属性 `data-prints-map-time`）を `visibility:hidden` にする。属性は要素を作る側が付ける——Chronos `#news-timeline`・
    携帯の `#m-clock`・ニュースの一覧 `#live-news-feed`（index.html）、「この日の地図」の凡例（`js/layer-time-kernel.js`）、
    凡例の年の欄（`js/data-layers.js`）。パネルは印字する要素の一覧を持たない（日付を印字し始めたモジュールは属性を付ける）。
    **アドレスバーも止める**——`tt=` が答えを書くので、問題の間は `MapState.holdAddress('quest')` が書き手（`js/map-ui.js` の
    `save`）を待たせる。答えると外れ、時計とアドレスバーがその日を示す。
    出さないもの: **1 月 1 日付けの国境の出来事**（`maybeYearOnly`——記録が年しか述べていないかもしれず、「その日の地図」が
    記録の述べる日でないことがある。`js/on-this-day.js` が見出しにしないのと同じ理由）と、**文に 4 桁の数字を含む出来事**
    （「1949年休戦協定」のように年を印字する問題は読めば解ける）。範囲は索引の `span`（1886〜2019）。
- **採点の尺度は 1 つ**: 誤差 ÷ その問題で起こりうる最大の誤差を x として `round(1000^(1−x))`。完全な答えが 1000、
  最悪の答えがちょうど 1 点（スキップの 0 と区別がつく）。最大の誤差は場所当てなら地球の半周（`_HALF_CIRCUM`）、
  年代当てなら正解の年から索引の範囲の端まで。場所当てでは `max·exp(−d/L)`、L ≈ 2,897 km にあたる。
- **決定的**: 問題列は（種類・seed・n）とデータの関数（FNV-1a → mulberry32）。同じ 3 つなら全員が同じ問題を解く——
  **挑戦リンク** `?quest=<kind>.<seed>.<n>`（`?tour=` と同じ「ページのモード」の層。`src/main.js` が読み、地図の準備が
  できてから始める。読んだ query は消す）。データを作り直すと同じ seed でも問題は変わりうる（その版の問題になる）。
- **パネル**: 種類と問題数（5／10）を選ぶ → 各問を地図で答える → 場所当ては正解（緑）・タップ（赤）・その間の大円と距離、
  年代当ては記録の日付 → 合計・各問の結果・挑戦リンク（コピー・共有）。年代当ての各問から「この日の地図」（その日の
  共有リンク——戦争のレイヤーも点く）を開ける。自己ベストはこのブラウザの `localStorage`（`intmap_quest_best`、種類と
  問題数ごと）。閉じると主時計と視点を始める前に戻す。場所当ての問題が答えを待つ間は、**地図のタップはクエストだけのもの**——エンジンの
  `events.holdTaps('quest')`（`js/geo-engine.js`）が、`{ tapOwner: 'quest' }` で登録したクエストのクリック処理以外を走らせない
  （ニュースの点・火山・ピンの下を押しても開かない。`claimClick` は「このタップを取った」を後から言うだけで、訊かない処理には
  効かなかった）。移動・拡大・ホバーは止めない。答えるか閉じると放す。計測ツールを使っている間のタップは取らない。
- **入口**: クイズのメニューの「学ぶクエスト」2 項目、レイヤー ▸ ツール の「学ぶクエスト」（`tool.learnQuest`）、挑戦リンク、
  Atlas の `quest`（`learn.quest`: `start`・`link`・`state`・`close`）。Atlas の判定はパネル自身の状態（開いているか・
  種類・seed・何問目か）を呼んだ後に読む。
- **場所当ての間は、名前を書く基本表示を切る。** 地名・自然地名・施設名の 3 行は宣言自身が `names: true` と述べ
  （`js/layers/<id>.js`・`js/layer-manifest.js` の `nameItems()`）、パネルは**読者と同じスイッチ**（チェックボックス＋change）で
  それを切り、答えを示した時点で**自分が切った行だけ**を戻す（読者が元から切っていた行は切れたまま）。スタイルの層を
  隠すのではない——地名ラベルの処理はスイッチの状態どおりに描き直すので、層だけ隠しても戻ってくる。国境は残す。
- ⚠ アドレスバーは地図の状態（`tt` を含む）を書き続けるので、年代当ての間もブラウザのアドレス欄には日付が出る（画面内の表示は隠す）。
- **今日のクエスト**——暦の 1 日ごとに、各種類のセットが 1 つずつある（`js/quest-engine.js` の「THE DAY'S SET」）。
  - **seed が日付を述べる**: その日のセットは seed `d<YYYY>-<MM>-<DD>`（**読者の暦の日**＝端末の現地日付）と `DAILY_N`（5）問の
    ふつうの決定的なセット。サーバーも問題の一覧も要らず、その日付の人は全員が同じ問題を解く。挑戦リンクもふつうの挑戦リンク
    （`?quest=when.d2026-10-08.5`）。別の日に開いた他人のリンクは挑戦であって、その日のセットではない（判定は `isDailySet` 1 つ）。
  - **年代当ては「今日」から**: その日のセットの `when` は、索引がその暦の日（月-日）に日付をつける出来事を先に（seed の順で）出し、
    残りを索引全体から埋める。その日に出せる出来事が無ければ全部が索引全体から。日付の seed でない seed の問題列は変わらない
    （以前に作った挑戦リンクは同じ問題を出す）。
  - **最初に解き終えた結果がその日の記録**。もう一度解くのは練習で、記録しない（答えを知っているので）。記録は `js/quest-daily.js` が
    **このブラウザ**（`localStorage` の `intmap_quest_daily`。最大 3,660 日）に、ログイン中は**アカウント**（`public.quest_daily_results`）にも残す。
    ログイン前にこのブラウザで解いた日は、ログイン中に集計を読んだときにアカウントへ足す。同じ日・種類が既にあれば「記録済み」で、失敗ではない。
  - **連続日数**（`dailyStreak`）: いずれかの種類のその日のセットを解いた日の連続。今日がまだなら昨日から数える（朝のうちに「途切れた」と
    言わない）。最長も数える。読めなかったアカウントは「記録なし」ではなく、ブラウザの記録を示して読めなかったと述べる。
  - **見え方**: クエストのメニューの先頭に「今日のクエスト」——日付・連続日数（「今日解くと N 日目」）・最近 7 日の点・2 種類のボタン
    （解いた種類は今日の得点）・記録の置き場所。その日のセットの結果画面は「今日の記録に入りました／練習です」・保存先・**結果をコピー**
    （日付・種類・合計・連続日数・各問の得点・挑戦リンク。絵文字は使わない）。
  - **入口**: クエストのメニュー、アカウントのシートの「今日のクエスト」（連続日数を添える）、その日のセットの挑戦リンク、
    Atlas の `dailyQuest`（`learn.daily`: `state`（既定。今日の各種類・連続日数・最近 7 日。アカウントへの追記はしない）・`start`・`link`）。
#### 8.6.4 今週の地球 (This week on Earth)
地球の大きな自然現象を **ISO 週**（月曜 0 時 UTC から翌週の月曜まで）ごとにまとめた公開のダイジェストと、その過去の記録。
検索（「今週の地震」）とフィードの購読で読者が来て、各出来事から地図へ入る入口。**記録は 1 つ**で、読み手は 3 つ——ビルドが書く
静的ページとフィード、Atlas、投稿の下書き。
| 記録（ISO 週 → 地震と自然現象） | `scripts/build-weekly-earth.mjs` | `data/weekly-earth.json`（追跡。新しい週が先頭。`--check` で形式を照合） | 無人の定期更新（`scripts/data-refresh.mjs`・`tle-refresh.yml`。周期 `P7D`）が bot PR で週を足す |
| 週の計算・文言・見出しの規則・地図のリンク | `js/weekly-earth.js`（`weekOf`・`describe`・`headline`・`stateFor`/`linkFor`・`weekLink`） | builder・Atlas・静的ページ・フィード・下書きが同じ関数を読む | — |
| 静的ページ（週ごと、en と `ja/`）・一覧・Atom フィード・sitemap | `scripts/weekly-earth-pages.mjs`（文は `scripts/weekly-earth-text.mjs`） | ビルド時に `dist/weekly/<YYYY>-W<ww>/`・`dist/ja/weekly/…`・`dist/weekly/feed.xml`・`dist/ja/weekly/feed.xml`・`dist/sitemap-weekly.xml`（`sitemap-index.xml` が束ねる） | `vite.config.js` の `weeklyEarthPagesPlugin`（子プロセス） |
| 投稿の下書き | `scripts/weekly-earth-pages.mjs --queue [--week YYYY-Www]` | 標準出力（承認待ちの一覧。**投稿・送信・予約はしない**） | 人が読み、承認したものを人が投稿する |
- **上流は 2 つ、要求は 1 回ずつ**: USGS FDSN event service（M5.5 以上、公有）と NASA EONET v3（`status=all`、米国政府の著作物）。
  どちらの応答も `scripts/lib/upstream.mjs` で状態を確かめ、USGS 自身の `metadata.count` と特徴の数の一致、EONET の事象の形
  （id・題・分類・日付つきの観測）を確かめてから書く。失敗はファイルを書かずに投げる——**上流の失敗が短い記録になることはない**。
- **記録は蓄積する**: 既にある週はそのまま保つ（読者が保存したページは同じことを述べ続ける）。例外は**暫定の週**——週の終わりから
  7 日未満に取った週は `provisional` で、次の実行がもう一度訊いてから確定する（USGS はマグニチュードを審査に応じて改め、EONET は
  情報源の報告に応じて事象を足す）。初回だけ 52 週を埋め、以後は終わった週を先頭に足す。何も消さない。
- **載せないもの（`rule` としてファイルに書き、ページが述べる）**: M5.5 未満の地震。焼失面積が述べられていて 10,000 ha 未満の
  山火事（週ごとに**数える**——`fewer.wildfires`。面積が述べられていない火事は載せる）。輪郭（Polygon）だけで示される事象の
  **位置**（GDACS の洪水の輪郭は軸の順序が混在する——実測 180 件中 46 件が [緯度, 経度]——ので、一覧に載せて位置は示さない）。
- **地図のリンク**は場所（点の事象はズーム 5）・日（`tt`、UTC の日付）・題と、**出来事そのものを「受け取ったマイマップ」のピン**
  （`mm=`、`js/my-map-doc.js`。地震のレイヤー `bx-eq` は共有リンクが運べない生の配信なので、ピンで示す）。週のリンクは
  位置のある全項目をピンにして枠に収める。アプリでは共有リンクの復元で開き、時計を読み返してから「開いた」と言う。
- **見出し**は最大の地震（USGS のマグニチュード——数であって判断ではない）。地震の無い週は EONET が述べる風速の最も強い嵐。
- **入口**: 紹介ページ・組織向けページ・歴史地図の各ページの足元（`scripts/landing.mjs` `pageLinks`）、設定 ▸ 新着の下の
  「今週の地球」。Atlas は `weeklyEarth`（`time.weeklyEarth`。`week` で週を、`open:n` で n 番目を地図に、`show:true` で週全体を地図に）。
- **計測**: 週のページと一覧は匿名集計の入口（`entry` の `weekly`）。フィードは入口ではない。下書きのリンクは週のページに utm
  （`utm_campaign=weekly-earth`）を付ける。
- **門**: `tests/weekly-earth-checks.test.mjs`（ISO 週の境界と 53 週・上流の異常応答の拒否と、拒否した実行が書かないこと・床と
  数え上げ・Polygon を置かないこと・確定した週を書き換えないこと・記録が連続した ISO 週・ページとフィードと sitemap の整合・
  リンクを地図の decoder とマイマップの reader で読み返す・下書きの tag と X の文字数）。`npm run check:datagov` が出自と
  無人更新の安全（`refresh-safe`）を測る。
