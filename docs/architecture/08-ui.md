## 8. UI/UX の構造

### 8.1 画面の骨格

- **「何を見るか」は Layers、「何をするか」は Tools。** 地図上部の **Tools ▾**（「ツール」、トリガ `#btn-measure-menu`・中身 `#measure-dropdown`）と携帯の
  **Map tools シート**（`#tools-sheet`、FAB `#m-fab-tools`）は同じ 1 枚のパネルで、節は 4 つ: **測る・描く**（距離／面積・描画・半径・3D 体積。携帯は加えて
  グリッドとスクリーンショット）／**道具**（`SIM_TOOLS` の `group:'tool'` の行——経路・写真の撮影地点・マイマップ・学ぶクエスト・データスタジオ）／
  **シミュレーション**（残りの `sim.*` の行）／**分析**（`#layer-tools` の帯——比較ビュー・相関分析・地図データの読み込み・データと分析・プレイグラウンド）。
  組み立ては `js/map-ui.js` の `mountTools()` 1 つ（デスクトップは起動 1.5 秒後、携帯はシートを開くたびに。冪等）。行は `_toolRow()` が描き、押すと
  `IntMapOS.exec(id)`（コマンドパレット・右クリックメニュー・Atlas と同じ 1 本）で開き、点灯中にもう一度押すとモジュールの `close()` で閉じ、パネルは引っ込む。
  測る・描く節の 4 ボタンは実体をそのまま運んだもの（id もハンドラも同じ）。**Layers パネルには道具の行も分析の帯も無い**（残るのはプリセット `#lyr-presets`・
  「現在のレイヤー構成を保存」）。ただし Layers の検索は文字が入っている間だけ一致した道具の行を同じ `_toolRow()` でレイヤーの下に出す。地震・パンデミックの
  シミュレーターは行が唯一の扉。
- **地図上部の Tools ▾ / Share ▾ は同時に開かない**——`window._closeMapMenus(except)`（`js/app-body.js`）が集合を知る唯一の場所（両トリガが
  `e.stopPropagation()` を呼ぶため）。Layers は別機構（`window.IntMapLayerSidebar`・セッションに永続化）。
- **最初の 1 枚（初回訪問）は地図が全面。** 保存されたセッションが開いていたと答えた側柱だけが起動時に開く（左は `js/app-body.js` の `_sessUI.left===true`、右は
  `js/map-ui.js` の `ui.right===true`）。既定タブ（Countries）は選ばれたまま。起動が取らないもの: レイヤーパネルのサムネイル（`kick()` だけが門を開く。§9）と
  世界の地名辞典（`data/gazetteer-world.json.gz`。ニュースの地名解決・地名検索欄・Atlas などの読み手が待つときに取る）。門は `tests/first-impression.spec.js`
  （1024×768・ストレージ空で、両パネルが閉じ canvas が全幅・`preview_*.png` と地名辞典を要求しない・開けば要求する）。
- **サイドバー（左）**：タブ（News / Companies / Countries / Atlas）、検索、ニュースフィード／企業ランキング／Atlas。
  **2つのレイアウトがあり、地図の中心の合わせ方が違う**（設定「Sidebar appearance」・`js/sidebar-style.js`）。**不透明**では `.operation-room` の flex 列で
  canvas 自体が狭まる（補正すると二重にずれる）。`.operation-room` は枠であってスクロールする箱ではない（`overflow:clip`。閉じた右のレイヤー欄は
  `translateX(102%)` で外にあり、`overflow:hidden` だとスクロール可能な幅になる。`tests/community-next.spec.js` が 1000px で測る）。**フロスト2種**
  （`body.sidebar-glass`）では `.map-container{position:absolute;inset:0;width:100%}` で canvas は全幅のままなので、camera padding の `left` に可視幅を書く。
  折り畳みは負マージンなので幅ではなく状態を読む。`bottom` は携帯シートの持ち物なので書く前に読み、値が変わったときだけ書く。
- **マップ上コントロール（右上）**：`.map-controls-top` は縦一列で、直下の子が1行ぶん。**1行目** `.map-view-row` に **Map/Sat** と **Flat/Globe/3D** の2つの
  ピル（`.map-view-group`。各ピルは `.view-btn.active` を1つだけ持つセグメント制御で、基図と投影法は独立——既定は Satellite ＋ Globe）。**2行目**が
  Grid／Measure／Share／Layers（`#map-tools-group`）。**3行目**は**コンパス単独**（`.compass-btn`・丸型 42px・右端）——細い一本の針（北半分は赤 `#ff3b30`、
  南半分はテーマ色）と北を指す三角・薄い輪・軸受けだけで、北の 2 つ以外は `currentColor`。同じ図形を携帯の `.m-compass-svg` が 38px で使い、回転は SVG 全体
  （`js/map-readout.js` が `rotate(-bearing)`）。どちらの SVG も `id` を持たない（同じ文書に2枚ある）。ピルは `.view-btn` の上下 5px＝行の高さ 31px（字は 12px）。
  地名検索バー（`.map-search`）は高さ 34px、角丸は高さの半分（18px）。右上スタックの高さを測る側（`js/mobile-ui.js`）は直下の子を数える。コンパスの右クリックで
  方位・仰角・ズームを数値入力できる（デスクトップのみ。傾き上限が「無制限」なら仰角 0〜360°、180° 超は方位を反転した等価な視線に解決）。
- **画面下の2つの隅は1つの余白を共有する。** 座標・標高の常時表示（`.coord-readout`・左下）と Chronos（`.news-timeline`・右下）はどちらも隅から 6px で、
  `tests/shell-css-surface-checks.test.mjs` ⑪ が2つが等しいことを検査する（`tests/shell-map-input-checks.test.mjs` ⑥ と `tests/shell-css-surface-checks.test.mjs` ⑤ は
  左下の値そのもの）。右パネルが開いているときの退避量（`--lsr-w` への加算）も各要素自身の余白に一致する。Chronos の字は時計（文字盤・4方位の目盛り・長短の
  針・軸受け）。
- **閉じた Chronos は年の軸を持つ（デスクトップ）。** ボタンの右の短いレール（`#ntl-peek`・`js/news-timeline.js` の `buildPeek`）——時計の床（`IntMapTime.min`）から
  「現在」まで、印は `IntMapHistScale.niceTicks`、位置は Year スライダーと同じ写像（`y2p`）、点は地図のいまの年。印を押すとその年へ（`IntMapTime.setYear`／
  「現在」は `setNow`。パネルは開かない）。レールのドラッグ（3 px 以上でスクラブ）とホイール（下・右で未来へ）は Year スライダーと同じ規則（`writeYearAtPos`）で
  1 フレーム 1 回書く。重なる印は描画幅で測って字だけを落とす。携帯では閉じた Chronos は出ない（入口はシート頭の時計）。
- **ポップアップ類**：国情報カード（`country-info`）、国詳細（`country-popup`）、ピン／地名ポップアップ、凡例（ドラッグ可）。
- **共有パネルと埋め込み**（`js/map-ui.js` の `share`・`js/embed-mode.js`）：Share ▾ →「共有／リンクをコピー」のパネルは、最初はリンクとコピー（と端末の共有）だけで、
  題と一言・埋め込み・画像は「その他のオプション」（`<details class="sh-more">`）に畳む（タブや題を名指して開く呼び手——Atlas・`open({tab})`——には開いた状態）。
  Share ▾ →「地図のスクリーンショット」はパネルを開かず画像タブと同じ絵（`js/map-recorder.js` の `postcard`）をその場で保存する（`IntMapShare.screenshot`）。どれも
  `IntMapBookmark.link()`（アドレスバーと同じ符号化器）を1つの値として読む。**埋め込みは共有リンクに `?embed=1` を足しただけ**（`&interactive=0` で静止画）。
  埋め込みタブは大きさ（`EMBED_SIZES` の 4 つ）とパン・ズームの可否を選び、`<iframe>` コードをコピーのたびに現在の地図から作る。プレビューは本物の iframe
  （押したときだけ・閉じると破棄）。`<html data-embed>` は `index.html` の最初の script が query から立て、`src/main.js` はそのときだけ `js/embed-mode.js` を動的
  import する。埋め込み表示は `EMBED_CSS` が残すものの一覧（地図・凡例 `.data-legend` / `.koppen-legend`・クレジット `#map-credit` と `.map-credit-view`・起動画面・
  `#im-embed-bar`）で決まり、それ以外は隠れる。**クレジットは削ってはならない。** 狭い枠でも折り返す。読み取り専用＝読者の（`isTrusted` の）click・右クリック・
  change・input・キーは地図内でアプリのハンドラに届かない（パン・ズーム・ダブルクリックのズームと共有リンク復元の合成イベントは通す）。上端右の帯は時計の瞬間
  （紀元前は `IntMapHistScale.dateText`）と「IntMap で開く」。**「埋め込みか」の判定は `js/ui-device.js` の `embedded()` 1 つ**で、埋め込みでは両サイドバー・
  `bootSupabase`・既定タブ・セッションの読み書き・ウィジェット板・デスクトップの Atlas 暖機が走らない。携帯シートの camera padding も 0（`js/mobile-ui.js`
  `sheetCovers`）。国の統計の取得（World Bank）は残る。Atlas の `share` は作ったリンク／コード（`embed:true`・`size`・`width`/`height`・`interactive`・`title`/`note`）を
  結果に載せる。
- **地図の絵葉書（画像タブ）**（`js/map-recorder.js` の `postcard` / `createPostcardTab`）：いまの地図を PNG 1 枚に合成する——地図（`captureCanvas`）・その瞬間
  （年として合わせた時計は年、それ以外は日付）・題と一言・地図上の凡例・描いている典拠と `#map-credit` の**出典（必ず焼き込む・切らずに折り返す）**・IntMap の
  名前・リンク（1 行に丸ごと入るときだけ。入らないときはサイトのアドレス）。形は `POSTCARD_SIZES`（リンクカード 1200×630・正方形 1080×1080・縦長 1080×1350）。
  配置は純関数（`layoutFrame` の `caption` / `legends`・`layoutLegends`・`layoutCard`）。**凡例は種類ごとの写しを持たず、ページの DOM のカードをそのまま読む**
  （`rasterLegend`）。読者の取っ手（入力欄・スライダー・掴む／動かす／リサイズのカーソルを持つ要素・文字も見本も持たないボタン）と、取っ手について述べる文
  （`aria-describedby` の説明、入力欄の名前以外に何も持たない行）だけを除く（文言では判別しない）。出典はソースが宣言する `attribution` で、image / canvas の
  宣言は `js/geo-engine.js` がソースに持たせる（ケッペン＝Beck et al. 2023, CC BY 4.0）。凡例の列は 1 つの縮尺で右端に並べ、床（0.9）で入らないものは落として
  数える。プレビューは保存されるファイルそのもの。「共有…」は `navigator.share({ files, title, text, url })`、渡せない環境では「画像を保存してリンクをコピー」。
  Atlas `postcard`（`panel.postcard`）は同じタブで作り、ファイル名・大きさ・題・凡例の件数・出典を返す（共有シートは読者の押下でしか開けない）。`share` と
  `postcard` が言い返す題と一言は Atlas 自身が渡したものだけ（他人のリンクの題は「ある」とだけ述べる）。録画中は作らない（`busy`）。
  比較ウィンドウがスワイプ（§7.4b）のときは 2 つの瞬間のカード（`thenNowCard`。`pair:false` でメイン地図だけ）：左右にウィンドウとメイン地図の瞬間、左に
  ウィンドウが描く層の名前、中央下に題と見ている場所の名前（`js/place-dossier.js` の `viewPlaceName`）、帯に2 つの地図の出典（`comparePanes`）・語標・リンク。
- **引用タブ**（`js/map-cite.js` の `createCiteTab`・遅延チャンク）：① 図の下に入れる出典表記（`mapCredits`）、② 参考文献（APA 7・Chicago・SIST 02・BibTeX・RIS。
  発行日の無い地図として、地図の日付・閲覧日・開き直すリンク。精度は `clockReading`）、③ 歴史の国境が描かれているあいだはその国境の GeoJSON（全世界／
  表示範囲）と引用するデータ。GeoJSON は `js/border-extract.js` の `buildExtract` が `currentFC()` の形ごとに線のカードと同じ答え（`provenanceOf`＝`_provSide`）と、
  指紋が一致するときだけ `data/border-provenance-*.json` の事実を持たせる。**出すかどうかはページが決めない**: 形の行が入っているファイル（`side.bundle`）で
  `api/v1/catalog.json` の項目に結び、上流のライセンスを行ごとに当てる（`rowsFrom` より前に終わる行には当てない）。IntMap は営利なので、すべての上流が営利利用を
  許す形だけ輪郭つき、輪郭だけが非営利の記録に切られた形（`contributes:'outline'`）は `geometry:null`、行そのものが非営利の記録（CShapes 2.0）は件数と名前と
  入手先だけ。カタログが読めなければ何も出さない。Atlas `cite`（`panel.cite`）は同じタブを開いて結果を載せる。
- **リンクの題と一言**（`js/map-state.js` の `title` / `note`・持ち主は `js/map-ui.js` の `share`）：題（`TITLE_MAX` 字）と一言（`NOTE_MAX` 字）はプレーンテキストで、
  `captionText` が制御文字と双方向上書き文字を空白にし文字単位で切る。URL では `s` の後ろ、最後に付く。`restore:'always'`。開いた人には控えめな帯 `#im-caption`
  （題・一言・閉じる）を出し、`document.title` を「題 — アプリの題」にする（`<title>` を見張って戻す）。帯の位置は測って決める（デスクトップは検索欄の下で同じ行の
  箱を避けた最も広い区間の中央、ResizeObserver で置き直す。携帯は出典の小札の上、シート全開では隠れる）。文字としてしか入らない（`textContent`・`fillText`・
  `.value`）。埋め込みは `#im-caption` を残し閉じるボタンは出さない。
  **共有リンク復元は箱に `__imRestored` を付けて `change` を配る**（`js/session-tabs.js` と同じ。付けないと `js/layer-home.js` の層が飛んで `v=` が失われる）。
  **復元が点けた行は時計を動かさない**（戦争の行は読者が点けたときだけ記録の初日へ動かす。復元の印は `js/war-fronts.js` が `change` の瞬間に使い切り、
  `js/war-layer.js` は時計が戦争の外なら隠して待つ）。地図が自分で送り直す `change`（`__syn`——`js/data-layers.js` の自己修復の off→on、`js/layer-time-kernel.js` の
  配達）も同じで、待った再試行も元の出自を持つ。新しい復元は古い復元の段取り（層 700/1800/3200 ms・時計 900 ms ほか）を世代で止める。**リンクは時刻を含めて
  完全に適用する**（`tt` の無いリンクは「今」）。`v=` で開いたとき `js/session-tabs.js` の保存年はリンクに譲る（`IntMapBookmark.carriesState()`）。復元の段取り
  （約 3.5 s）の間に貼られたリンクは終わったときにその時点のアドレスで復元する。状態を書くのはその状態が地図に出ている者だけ。
  **地図の状態の正本は `js/map-state.js` の `MapState` 1 つ。** 視野（`v`）・共有レイヤー（`l`）・時刻（`tt`、旧形式 `ts`）・比較窓（`cmp` / `ct`）・基図（`sat`）・
  3D 地形（`t3`）・シミュレータ入力（`s`）・題と一言（`title` / `note`）・Atlas のブリーフィング（`b`、§2.1f）・読者の地図（`mm`、7.3g）・データスタジオの表
  （`ds`、7.3h）・セッションのレイヤー集合（URL なし）を `SCHEMA` が1回だけ宣言する（綴り・毎回か完全復元だけか・適用の時刻・セッションの鍵・持ち主）。
  値を決めるのは持ち主（`MapState.own(key, { read, apply })`）: 視野・基図・地形・共有レイヤー・シミュレータと時刻の配線・題と一言は `js/map-ui.js`（`js/chronos.js`
  自身は `js/map-state.js` を import しない）、比較窓は `js/compare.js`、ブリーフィングは `js/briefing-link.js`、読者の地図は `js/my-map.js`（値を持つ復元だけが
  取りに行く）、セッションのレイヤー集合は `js/session-tabs.js`。ストアは値を複製しない。**アドレスバー・共有リンク・埋め込み（`MapState.hash()` / `link()`）・
  セッション保存（`MapState.session()`＋タブ・サイドバー）・Atlas の `camera` / `time` 節（`viewOf` / `timeOf`）はすべてこの 1 つの写像。** 符号化／復号は純関数
  （`encode` / `decode`）で、無い欄は「無いこと」が述べる値（`tt` 無し＝今・`ct` 無し＝主の時計に従う・`l` 無し＝共有レイヤーなし）。復元は `MapState.restore()` の
  1 回の適用で世代を持ち、持ち主がまだ居ない欄は最新である間だけ登録時に渡す。持ち主は `MapState.changed(key)` で述べ、購読者（`MapState.on`）は `cause` で
  `restore` と `reader` を区別できる（時刻は Chronos の `source:'restore'` でも）。アドレスバーは購読者の 1 つ（視野 400 ms・他 300 ms 後）。URL の状態パラメータを
  `js/map-state.js` 以外で綴らない（手書きの `[#&]tt=` パーサや `'&l='` の連結は `tests/map-state-store-checks.test.mjs` ⑤ が赤にし、`location.hash` と
  `history.*State(` の直接の箇所はファイルごとに ratchet で数える）。共有パネルは右の Layers パネルが開いているとき `--lsr-w` を引いた地図の中央に置く。
  枠の設定: GitHub Pages は `X-Frame-Options` も CSP ヘッダも送らず、`<meta>` の CSP では `frame-ancestors` は無視される（`index.html` の注記・
  `docs/SECURITY-ARCHITECTURE.md` §6）。埋め込みはこの事実の上に成り立ち、新たに許したものは無い。
- **レイヤーパネル**：どのレイヤーが在るか・棚と位置・既定 ON・共有リンクに載るか・どの遅延モジュールを読むかは **`js/layers/<id>.js`** が述べ（`js/layer-manifest.js`
  が導く）、`reorganizeLayerPanel()` はその並びで DOM を並べ替える（`docs/MAP-LAYERS.md` §7.2）。行を作るのは各モジュールの `buildUI()` で、基本表示の 10 行だけは
  manifest から `js/layer-rows.js` が書く（`src/main.js` が `js/i18n.js` の直後、`js/data-layers.js` より前に import）。一覧を知るために行を数えない（タイル盤・共有リンク・
  お気に入り・セッション復元は manifest を読む）。セッション復元は行の出現を `MutationObserver` で待つ（`whenBoxes`）。
  **レイヤーの ON/OFF はどの経路でも箱の `change` 1つに行き着き、スタイルが受け取れる前に来たものは `js/layer-rows.js` の `holdUntilDrawable` が預かる**
  （document の capture リスナ。manifest が宣言する箱だけ・`canDraw()` が偽のあいだだけ）。預かった箱には後で `change` を1回だけ、着いた順に、そのときの状態で
  配る（配る時刻は `whenCanDraw()` の解決で、MapLibre の `load` には結び付けない）。起動処理（`js/app-body.js`）・共有リンク復元（`js/map-ui.js`）・セッション復元
  （`js/session-tabs.js`）も `whenCanDraw()` を入口にする（`load` は忙しい地図では何分も来ない）。一覧は `window.IntMapLayerHold.pending()`、配った後の要求は
  `window.IntMapLayerHold.inflight()`。配り直す `change` は最後に預かった変更が整合器自身の再発火（`cb.__syn`）ならそうとして出す。整合器（定期と ON の 2.8 秒後の
  点検）は預かり中の箱・描けない地図・要求が終わっていない箱を判定しない——`toggleLayer(id,on)` は各枝の最後の非同期の鎖を Promise で返し、`change` ハンドラが
  `js/layer-rows.js` の `layerInflight`（settle で外れ、新しい要求が置き換える）に渡す。2.8 秒後の点検は `idle(id)` を待って 1 回だけ見る。要求の中の取得は自分の
  期限を持つ（雨雲レーダー・火災・海底ケーブル・合計特殊出生率は `js/fetch-deadline.js`、秒数は `js/proxy-fetch.js` の `clockFor` が host ごとに）。§7.2。
- **レイヤーの「描けなかった」は `js/layer-state.js`（`window.IntMapLayerState`）が持つ。** 箱ごとに `loading` / `ok` / `failed`（答えが「否」だった）/ `unobserved`
  （時間内に何も届かなかった＝`js/fetch-deadline.js` の `isUnobserved`）/ `nodata`（時計の瞬間について述べるものが無い。トーストせず pill は灰色）と、理由
  （`timeout`・`network`・`http`＋`status`・`parse`・`unsupported`・`worker`）・文・時刻。呼び手自身の中止（`aborted`）は状態にならない。入口: ⑴ `layerInflight` が
  追跡した要求を渡す（`inFlight(watch)`。reject は理由つきで残る）⑵ 自分で失敗を捕まえる行は `report(箱, err, {told:true})` ⑶ `window.IntMapLayerState.report(id,
  'failed', {reason})`。出口 3 つ: 行（`.lyr-state` の pill、en+jp。`js/map-ui.js` のタイル `.lst-tile[data-lid]` にも同じ pill）、読み上げ（入ったときに 1 回だけ
  `js/notify.js` へ。`told` は黙る）、Atlas（`snapshot()` / `get(id)` / `heals()`。`IntMapLayerAudit.states()` も同じ）。消えるのは箱の次の `change` だけ。自己修復の
  直し（`IntMapLayerAudit.log()`）も `healed(id, fix)` で残る。

  `satToast`・`imToast`（→aiToast）・`_toast`（→imToast）・各 `toast`（→imToast、`js/navigation.js` だけは直に `urgent`）・`majorToast` は委譲する。`majorToast` は
  シミュレータの「速報」カード（HUD は z-index 6300、トースト層 3000）を残し、文だけを `visual:false` で渡す。
- **孤児の掃除（`_sweepOrphanLayers`）と表示状態の監査（`IntMapLayerAudit`）に周期実行は無い。** 事象で走る: `idle`・`styledata`（掃除は 2,500 ms、監査は

  オン中のレイヤーをチップで出し、常に上部 sticky の先頭（固定高1行の横スクロール。空でも "(0)"）。`reorganizeLayerPanel()` はタップ中に走ると誤タップの原因になる。

### 8.1.3 IntMap のいま（状態ページ）と、失敗が名指すデータ元

読者の地図に効く事実のうち、それまで CI の中か 1 行の pill の中にしか無かったものを 1 枚に集めたページ。設定 ▸ **IntMap のいま**（`#btn-status-page`）・
Atlas（`diagnose` の結果に同じ内容が文で入る／`module` が `IntMapStatus` を開く）から開く。実装は `js/service-status.js`（初めて使われたときに取得）で、握りは
`js/layer-state.js` の `window.IntMapStatus`（`open` / `close` / `toggle` / `describe`。設定のボタンへの click は document リスナー 1 本が受ける）。

- **4 つの節。** ⑴ この端末——オンラインか、IntMap の本体が保存されてオフラインでも開けるか（`sw.js` の `intmap-shell-<build>`）、保存量
  （`navigator.storage.estimate()`）。⑵ 地図のレイヤー——`IntMapLayerState` が「読み込めない／応答なし／この日時のデータなし」とした行と理由。⑶ データ元
  （毎晩の確認）——応答しなかった提供元ごとに、いつから・最後に応答したのはいつか。⑷ Atlas の品質評価——最後に評価された日時、または測れていないことと理由。
- **見出しは「いま本当である最も悪いこと」**（オフライン ＞ 描けないレイヤー ＞ 応答しないデータ元 ＞ すべて動いている）。
- **毎晩の確認は `data/service-status.json`。** `scripts/build-service-status.mjs` が `upstream-liveness` の最新の結果と `atlas-eval.yml` の実行記録から作り、
  `.github/workflows/tle-refresh.yml` の bot PR が 1 日 2 回運ぶ（[`docs/MONITORING.md`](../MONITORING.md) §1d・§1e）。出自はファイル自身が先頭で述べる。
- **測っていないことは述べない**（測定に載っていないホストには触れず、読めなかった記録・回線の無い晩・報告を残さなかった評価は灰色の文。
  `.agents/rules/one-pass-or-a-reason.md` §5）。「いつから」は記録が観測した夜の時刻だけ。
- **レイヤーの失敗は、その要求が訊いたデータ元の夜の記録と結ばれる。** 共有の読み手（`js/fetch-deadline.js`・`js/proxy-fetch.js`）がエラーに要求の URL を載せ、
  `js/layer-state.js` が失敗に入った瞬間に `upstreamRow(url)` を訊き、pill の文と Atlas の記録（`snapshot()` の `upstream`・`detail`）に「このデータ元は 10月2日 から
  応答していません（毎晩の確認・最後に応答 10月1日）」を足す。中継（`?u=https://…`）は運んでいる先のホストで結ぶ。レイヤーとホストの対応表は無い。中継の梯子
  （`fetchViaProxy`）は `null` を返すので、失敗は呼び手の `note.failure`（`{ reason, status?, url }`。理由は `http`・`timeout`・`parse`・`unrelayable`・`network`）に
  書き、`classify()` が読む。人工衛星の行は何も描けなかったときこれを受け取り CelesTrak を名指す。
- **出典の一覧も同じ記録を読む**（アプリ内の出典ダイアログと `sources.html`）。出典のリンクのホスト、またはその下のホストが応答していなければ同じ文が出る
  （登録ドメインを推測して広げない）。
- 文は en + jp。データ元の名前は `scripts/outbound-hosts.json` の `what` / `whatJp`。
- **記録（時系列）。** ⑶ の節は測った全晩を持つ——晩ごとの応答割合の棒（全部応答＝緑・1 つでも応答しない＝橙。閾値は無い）、各データ元の帯（1 晩 1 マス）と
  「直近 N 晩の確認のうち M 晩で応答」。出典の一覧も照合できる全行に同じ文を出す。確かめられなかった晩・訊いていない晩は分母に入れない。
- **⑷ のセッション不要の半分。** ライブの評価が測れない夜も、記録した手順の再生と能力に届くか（`atlasEval.offline`）は測られる
  （[`15-ops-quality.md`](15-ops-quality.md) §15.6）。
- 携帯では `.modal-overlay` の規則どおり下からのシートになる。行は 44 px 以上。

### 8.1.5 「どこ＋いつ」——場所と時刻を 1 つの欄で

**読み方は `js/where-when.js` の 1 つ**で、検索欄（携帯のシートも）・コマンドパレット・Atlas `time.whereWhen` が訊く。初めて数字か「元年」を含む文が打たれたときに取る。

- **時刻は構文として読む。** 紀元の語（BC・AD・紀元前・西暦・v. Chr.…）と月名は登録簿の全言語について `Intl.DateTimeFormat`（CLDR）から、和暦の元号は ICU の
  japanese 暦（`ja-u-ca-japanese`、大化以降）を標本して読み戻す（手で書いた月名・元号の一覧は無い。書いてあるのは CLDR の `alt="variant"` の BCE / CE と、場所と時刻の
  あいだの機能語だけ）。読める形: 末尾の 3〜4 桁の年（今日より後は郵便番号）・紀元の語つきの年・月名つきの年と日・ISO（`1868-01`・天文年の `-0043-03-15`）・
  `n年m月d日`・和暦の `元号n年`（1873 年より前の月日は太陰太陽暦なので変換せず「年だけを使う」と述べる）。先頭の数字は年にしない。知らない漢字の語に付いた
  1〜2 桁の年（「康熙5年」）は変換できないと述べる。日付は先発グレゴリオ暦で読む（ユリウス暦は換算しない）。
- **場所は既存の読み手から**——`localFuzzyPlaces`、歴史都市名（`IntMapHistCities.records()`）、Pleiades（`IntMapHistPlaces.records()`）。歴史都市の記録が守備半径の中に
  地名辞書の行を持てば 1 行にまとめ、その年の別名は副題「この年の名: 江戸」（`eraNameAt`）。
- **解釈が 1 つなら 1 回で、複数のときだけ選ばせる**（`.agents/rules/one-pass-or-a-reason.md`）。行は「場所 · 時刻」で打鍵ごとに出る。選んだ行は飛び（`gotoPlace`）、
  マスタークロックを合わせる（年は `setYear`・月はその 15 日・日はその日の正午 UTC）。場所の無い時刻（「1914」）は「1914 へ移動」の 1 行で時計だけ（4 桁だけの文は
  地名としても引く）。検索欄の Enter: 場所の無い時刻はその場で時計を合わせ、場所があって候補が 1 か所に決まるとき（`samePlace`）は最初の Enter でネットワークに訊かずに
  飛ぶ。決まらなければ 3 つのジオコーダーを待ち、複数ならカードを残して選ばせる。
- Atlas `time.whereWhen`（`{query, pick?}`）は同じ `interpret` を通し、1 つなら適用し、複数なら番号つきで返して何も動かさない（`pick:n`）。

### 8.2 Panels タブ（ドック）

設定「凡例・ツール窓の表示」→「サイドバーのタブにまとめる」（既定オフ）。実装は `js/window-manager.js`。

- **入るのは「オンになっているもの」だけ**（判定は所有者が書くインライン `display`。MutationObserver が `style` / `class` / `hidden` を要素ごとに見て、オフにすると
  地図へ戻る）。
- **ドック中はドラッグもリサイズもしない。** ドラッグ実装は `js/window-manager.js` の `makeDraggable` と `js/data-layers.js` の `wireDrag` の2つで、両方が `im-docked` を
  見る。⋮⋮ のグリップは CSS で隠す。
- **辺のリサイズは要素の listener、角のリサイズは document の capture**（`border-radius` は当たり判定も切るので、角の内側では `elementFromPoint` が下の canvas を返す）。
  角だけを `getBoundingClientRect()` との座標で判定し、z 最上位の窓が勝ち、カーソルは `document.body` に書いて角を出た瞬間に消す。
- **剥がすのは幾何プロパティだけ**（`_flatten()` が `position/left/top/width/height/transform/z-index/margin/resize` などを `removeProperty`。`display` は剥がさない）。
  `_undockOne` は `_dockOne` の厳密な逆（幾何だけ戻す）。
- **列の中でスクロールする箱は作らない**（`*-scroll` / `*-body` / `*-list` に `max-height:none; overflow:visible`）。ドック中は最小化で始めない（携帯の凡例自動
  折りたたみは走らせない）。携帯では列が画面の左右いっぱい（`#docked-feed`）。シートの高さの所有者は `--sheet-h` ただ1つ。

### 8.3 パネルとウィンドウの作法

- **UI の状態はキャッシュせず、持ち主に訊く**（各モジュールは `isOpen()` / `close()` を持ち、ツールカードは行に `mod:'IntMapX'` を1つ持つ。出口を2つにしない）。
- **開いたことは「教えてもらう」**（遅延チャンクは `OS.exec` が返す到着の Promise に繋ぐ）。
- **動く障害物の位置は実測する**（`placeClear()` が覆っている物の矩形を測る）。
- **進捗バーは1種類**（`var(--prog-grad)` の塗り幅＝割合 ＋ ％表示。`busy()` / `set(f)` / `done()` の3状態。割合が出せないなら上流を直す）。
- **フォーム部品（`input` / `select` / `textarea`）の名前は、部品を作る場所が付ける。** 隣に語があれば結び（`<label for>`、`<label style="display:contents">`、または
  `aria-labelledby`）、無ければ `aria-label`。レイヤー行の不透明度スライダと日付欄は「自分の語＋行のレイヤー名 `#lyrname-<id>`」を `aria-labelledby` で参照する。
  凡例の不透明度行（`.dl-op-row`）は3つの組み立て（`js/data-layers.js` `ensureLegendOpacity`・`js/weather.js` `opRow`・`js/waves.js` `opRow`）が同じ形で、％表示は名前に
  入れない。`‹` ボタンを含む日付行では `aria-labelledby` を使う。Atlas の命名掃引（`_uiNameSweep()`）は補助。Data & analysis（`js/gis-panel.js`）の引数欄は
  `paramControl` 1か所で作られ、引数名の行（`#gis-param-name-<n>`）が部品の名前になる。門は `tests/form-control-names.spec.js` ①（各レイヤー系統を点けた状態で全部品を
  accessibility tree に訊く）と ③（Tools ▾ の `#measure-dropdown .tlp-root` のボタン全部と携帯の tools sheet の実ボタンを1つずつ押す）。
- **キーボードのフォーカスは、全ての操作部品で 2 px のリングとして見える**（`css/intmap.css` のテーマ定義の直後の `:where(…):focus-visible` の規則 1 つが
  `outline:2px solid var(--focus-ring)` を `!important` で書く。`outline-offset` は `!important` にしない）。`--focus-ring` はアクセントで両テーマで 3:1 以上。マウスで押した
  ボタンにはリングが出ない。枠の無い欄を持つ検索ピル（`.search-bar`・`.map-search`）ではピルの `:focus-within` が 2 px の縁を描く。門は `tests/ui-a11y-polish.spec.js` ①

  5.19:1・`--bg-color` `#f5f5f7` に 4.77:1・`--input-bg` `#f2f2f2` に 4.64:1）で面もそのまま。ダークの文字は `#0a84ff`（`#1c1c1e` に 4.66:1）、面は

  `role="dialog"`・`aria-modal="true"`・名前を持ち、Escape は一番上の面だけを持ち主の閉じる関数で閉じ、Tab は面の中を巡り、閉じると元のフォーカスへ戻る。開閉は観測する

### 8.4 経路 (Directions)

正式な入口は **Tools ▾ ▸ 道具 ▸ Directions／経路** の1つだけ（携帯は Map tools シートの同じ行）。Layers の検索に「経路」「route」と打つと同じ行が一時的に出る。
Atlas の自然言語も同じ経路計算を呼び、**両者は同じ状態を読み書きする**。

| ファイル | 役割 |
|---|---|
| `js/routing-store.js` | **状態の正本** `window.IntMapRouteStore`。出発地／経由地／目的地（確定した地点と未確定の文字列を分けて持つ）・交通手段・日時・回避条件・要求の状態・結果・選択中候補。DOM も地図も触らない |
| `js/routing-providers.js` | 各ルーターが**実際にできること**の表。UI はこの表が真を返す機能だけを出す |
| `js/routing-geocode.js` | 地点の候補検索と順位付け（`suggest()`）。文字列を 1 地点にする唯一の扉 `resolve()`（Atlas・共有リンク・`IntMapRouting.geoNear`）——同じ出典・順位・一致規則に `namesakeOk` を足し、一致が無ければ `null` |
| `js/routing-cards.js` | 候補カード・手順・公共交通の区間・距離／時刻の書式。**Atlas とパネルが同じ関数を呼ぶ** |
| `js/routing-export.js` | GPX・GeoJSON・共有状態（**幾何は運ばない**） |
| `js/routing.js` | 実際の経路計算、地図への描画、`window.IntMapRouting` の公開契約 |
| `js/routing-ui.js` | パネル本体。**遅延取得**（`IntMapLazy.need('routeUi')`）。CSS は `css/intmap.css` の `.rtp-*` |
| `js/routing-ops.js` | 既存の経路についての分析（標高・国境・沿道・到着時刻・経路差・過去の路線網） |
| `js/routing-errors.js` | 失敗の分類 `window.IntMapRouteErrors`。15 コード。各コードは判断を運ぶ（再試行してよいか・別 provider に投げてよいか・利用者が直せるか）。文は別に 9 言語で引く |
| `js/routing-time.js` | **どちらの「今」か** `window.IntMapRouteClock`。`planningNow()`＝Chronos、`navNow()`＝壁時計（案内中）。既にある2つに名前を付けただけ |
| `js/routing-traffic.js` | 交通情報つき provider のアダプタ `window.IntMapRouteTraffic`。`routing-relay` 経由でのみ通信し、**結果を一切保存しない**（provider の規約） |

**能力レジストリ** — `js/routing-providers.js` は 40 キーの語彙を宣言し、どの provider も全キーに答えなければ登録できない（`assertComplete` が throw。キーが無いことと
`false` を区別するため）。UI・Atlas・要求組み立ての3つが同じ表を読む。語彙に入るのは事実（yes/no か数）だけで、計算するもの（どの provider が答えるか）は関数のまま。
各 provider は `evidence`（`'measured'` か `'documented'`）を持ち、`documented` の provider は `available()` が relay の答えを得るまで false。

**不変条件**

- **入力欄の文字を編集した瞬間、確定していた座標は無効になる**（未確定の文字列はルーターに渡らない。`points()` が `null`）。
- **経路計算は確定した地点が変わったときだけ走る**（打鍵では走らず、同一条件の再送もしない）。
- **古い応答は状態にならない**（ルーター側の requestId と store 側の `settle(id,…)` が世代の合わない結果を拒否する）。
- **パネルを閉じると地図の経路も消える**（✕ と Esc は `RT().clear()` / `clearAreas()`。出発地・目的地・経由地は残る）。「経路を消去」は閉じない。Atlas の「経路を消して」も
  同じ `IntMapRouting.clear()`。
- **候補を1つ選ぶとそのカードが開いて詳細を中に出す**（カードは `div[role=radio]`。中の手順は本物のボタンで、押下の判定は手順が先）。
- **時刻はその地点の現地時刻で書く**（`IntMapTimeZones.offsetAt(lng,lat)`。設定でタイムゾーンを明示している読み手はそれが優先）。出発時刻の欄は端末の時計で打つ
  `datetime-local` で、その旨を欄の横に書く。
- **どの地点欄からも現在地を1回で入れられる**（◎。許可を求めるのは押した瞬間だけ。拒否・タイムアウト・失敗は別の文）。
- **交通手段の切替はこのパネルにしかない**（Atlas の返答にはタブを置かない）。
- **入替は旅程全体を逆順にする**（`A → 1 → 2 → B` は `B → 2 → 1 → A`）。
- **地図の A / 1 / 2 / B は入力欄の番号と同じ規則から出る**（経路線の太いヒット領域を押すと候補の選択が変わり、逆も同じ）。
- **できないことは表示しない**（ライブ交通を持つプロバイダーは無いので「標準所要時間・リアルタイム交通量は未反映」。回避条件や通過禁止範囲が適用できなかった場合・
  代替経路が経由地のせいで取れなかった場合も別の文）。
- **公共交通の「リアルタイム」は上流が `realTime` を真にした区間だけ**（一部なら「一部リアルタイム」、遅延0は「定刻」）。
- **カメラは開いているパネルの実寸を避ける**（`IntMapRouting.setInsets()`）。

### 8.5 パンデミック・シミュレーター (Pandemic Simulator)

**Tools ▾ ▸ シミュレーションの「パンデミック・シミュレーター」から 1 タップで起動する**（Playground ハブのカードからも）。押すと OS アクション `sim.pandemic`
（`js/app-body.js`）を実行する——行・コマンドパレット・Atlas が同じ 1 本のコマンドを押す（地震の `sim.seismic` と同じ形）。モジュールは遅延読み込み。
行の正本は `js/map-ui.js` のツール一覧で、登録済みの `sim.*` コマンドを数え上げて全部が行を持つかを検査が測る。`#layer-tools` の帯にはシミュレーターのボタンを置かない
（帯のボタンが行と同じコマンドを押すなら、ボタンの `data-os-act` と行の `data-act` から重なったほうのボタンを隠す——`_placeLayerTools()`。id の対応表は書かない）。
行は走行中に点灯し、もう一度押すと閉じる（`js/playground.js` が `window.IntMapPandemic`——`isOpen` / `close`——を自分の扉の中から公開する）。

**Atlas から駆動できる。** 能力は `sim.pandemicRun`（走らせて状態を返す——世界の合計と、国ごとの累計感染・死者・現感染者・到達日・国境段階）と `map.pandemicDay`
（その日を地図へ描く）の 2 本（描画を約束した能力が描かなかった回を観測器は `not_rendered` と判定するので分ける）。開始地点は国コード・国名・地名・座標のいずれでもよく、
地名は同梱の gazetteer で点に解決してからその点を含む国を点内包判定で決め、どう決めたかは回答に出る。指定されなかったパラメータは主張である——
`describePandemicParams` が 1 つずつ出典（`caller` / `preset:<プリセット>.<欄>` / `preset-silent:…`＝上流が述べていない / `scenario:…` / `default`）を付けて返す。範囲外の
値は丸めずに拒否し、拒否がその変数の範囲を持って返る。同じ種は同じ結果を再現する。

**世界は `js/pandemic-world.js`**（どの行が人の住む場所か・人口・接続・誰が統治するか）で、パネルと Atlas は同じ世界を受け取る。2 段階で、行は即座に・`ready` は 4 つの表が
settle してから解決する（移動行列は `createPandemicModel` で凍るので、表が揃う前に始めた走行は種から再現できない）。**数理は `js/pandemic-model.js`、地図と HUD は
`js/playground.js`** で、`playground.js` は区画（S/SV/E/I/R/V/D）に対して算術をしない。地図の算術（何点描くか `caseDotPlan`・どの点が変わったか `dotSignature`・
スライダーが持てる値 `snapToStep`）も `js/pandemic-model.js` の export された純関数。

- **モデル**: 国ごとに 1 組の区画を持つ**確率的 SEIR メタ個体群**。潜伏と感染期はそれぞれ最大 2 段。
- **平均滞在日数は設定値そのものになる**（1 日刻みでは段の日数は幾何分布なので、段あたりの日次確率は **`p = 段数 / T`**。2 日未満の期間は 1 段）。指定した R₀ もそのまま
  実現する（`tests/hazard-pandemic-model-checks.test.mjs` ①② が 5 プリセットを走らせて測る）。
- **「n 人がそれぞれ確率 p で動く」は二項分布で引く**（BINV の逆関数法）。期待値が 30 人以上の遷移は期待値そのもの（小さな流行はひとりでに消えることがある）。半端な人数の
  遷移は `draw(n,p)` が整数部を二項分布で引き、端数 `frac` は `frac·p` をそのまま払う（期待値どおり）。
- **乱数は種を取る**（mulberry32）。同じ種・同じ設定なら同じ流行（詳細設定で種を指定できる）。再生速度（×1〜×8）は `setTimeout` の間隔だけを変える（engine の中に `speed`
  という語が無いことまで ② が測る）。
- **人口は保存する**（`S+SV+E+I+R+V+D` は各国の初期人口に等しく、`invariant()` が毎 step 検査できる）。国際的な再流入は現地の未感染者——`S` と `SV` の両方から比率どおり——
  から取る。輸入は人の移動ではなく現地で感染連鎖を始める圧力で、送り出し側の `E`/`I` は減らない（画面もコメントも「感染者が移住する」と説明しない）。
- **国の時計は病気が着いた日に始まらない**——免疫の減衰と接種は到達していない国でも毎日進む（`stepUnreached`）。未到達国に配らないのは明示された政策 `vaccinateUnreached`。
- **ワクチンが守れなかった人は `S` に戻らない**（all-or-nothing。守れなかった人は **`SV`**＝接種済み・非防御に入り、接種の対象から外れ、感染は `S` と同じ確率で受ける）。HUD の
  「未感染」は `S+SV`。
- **累計感染は独立の台帳**（`cumInf`）。HUD は「延べ感染」と呼ぶ（再感染を含む）。
- **シナリオは 2 つ**——「未知の病原体」（誰も免疫を持たない）と「現在の世界」（その病気が 2026 年に実際に持っているワクチンと治療法から始める）。免疫ゼロの世界を実在の
  病名で呼ばない。
- **国ごとの「できること」は 4 つで、3 つは実測値**（`data/health.json`、`scripts/build-health.mjs`）。指標は欄がモデルの中で何を動かすかで選ぶ:

  | 欄 | モデルの中で何を動かすか | 指標 | 件数 |
  |---|---|---|---|
  | `health` | 病院の逼迫倍率と基礎致死率（`overload` / `ifrEff`） | WHO UHC サービス被覆指数（SDG 3.8.1） | 195 |
  | `response` | 政府が入国規制を上げる速さ、ワクチン計画を回せるか | WHO IHR SPAR 能力 7「健康危機管理」 | 194 |
  | `delivery` | ワクチンが存在してから 1 日に届く未感染者の割合 | WHO/UNICEF DTP3 接種率 | 236 |
  | `connectivity` | `travel[i]` の最終フォールバックのみ | 1 人あたり GDP | — |

  DTP3 は既存の定期接種のラストマイルそのものなので `delivery` の問いに合う。表に無い国はその国だけ開発指標へ落ちる（`capacityFrom` が国ごとにどれが実測かを持ち、
  国インスペクタが `~` で「1 人あたり GDP からの推定」と書く）。
- **麻疹の初期免疫は国ごとの実測値（WHO/UNICEF MCV1）で、スライダーは「世界平均」の意味を保つ**——engine は観測を形として使い、人口加重平均がスライダーの値に乗るよう
  同じ係数で伸縮する（上限 0.99 で切られた国のぶん実現する平均はスライダー以下になり、反復で合わせない）。「現在の世界」シナリオでだけ効き、小児の接種率を全人口の免疫と
  して読んでいる（年齢構造を持たない）ことは画面が言う。**COVID-19 の国別免疫は実測が存在せず、作らない**（0.9 は明示された世界一律の仮定）。「現在の世界」の初期免疫
  （COVID-19 の 0.9、麻疹の 0.84）は観測値ではなく仮定で、UI は「仮定した初期免疫」と名乗る。
- **疾患プリセットはデータ**（`PANDEMIC_PRESETS`）。伝播・重症度・免疫・ワクチン・治療を混ぜず、重症度は指標名（IFR / CFR）を数と一緒に持つ（SARS の 9.6% と Ebola の
  50% は CFR）。`latentDays`（感染力を持つまで）は `incubationDays`（発症まで）とは別の欄。engine は重症度を `I` を離れるすべての感染に当てる（観測モデルが無い）ので、
  CFR のプリセットでは換算係数を掛けず、設定画面がそう明示し読者が下げられる。**「終生免疫」は独立の欄**（`naturalImmunityLifelong`。Ebola の `naturalMonths: 120` は
  実在する 10 年。0 か月は別の主張）。
- **介入**は「対策なし／状況に応じて／強い対策」。国境は open→screening→restricted→closed の 4 段で、静かな日が続けば戻る。
- **変異株は生まれた国にしか無い**（国ごとに株の占有率を持ち、置き換わりも免疫逃避もその国で進む）。
- **国際伝播の行き先は分布から引く。** 国の組ごとに重み

  ```
  w_ij = 到達魅力_j × exp(−距離_ij / 3200km)  +  陸境の重み × adjacent_ij × 人口重み_j
  ```

  を作り、累積和の二分探索で行き先を決める。航空の項には `data/mobility.json`（`scripts/build-mobility.mjs` が OpenFlights から作る国どうしの路線数）を行ごとに正規化し、
  距離カーネルと **`ROUTE_MIX = 0.35`** で混ぜる（行の合計は保つので陸境の項 `LAND_MIX` の意味は動かない）。路線表は 2014 年 6 月で凍っている（公開されていて現行の
  二国間の旅客行列は存在しない。OAG・ICAO TFS・Sabre は商用）。路線表の 0 は「誰も行き来しない」ではないので置換ではなく混合で、出発行の無い国は距離カーネルのまま。
  路線表を入れると N 番目の国に到達する日の中央値は 60/85/116（10/50/100 番目。実際の COVID-19 は 50/80/95）。**到達魅力**は `data/mobility.json` の実測の入国旅行者数
  （World Bank `ST.INT.ARVL`・2019 年以前の最新年）を第一の段に、圧縮（`AIR_EXP`）を掛けて使い（線形だと近隣の短期反復旅行を二重に数え、下端は報告の欠落）、無い国は
  `data/airports.json`（`scripts/build-airports.mjs` が OurAirports から作る定期便のある空港の規模）。**陸の隣接**は `data/country-facts.json` の `borders`（163 か国・
  無向 322 辺・対称）、**人口重み**は `countryStats` の人口。出国のしやすさは出発側に入る。どれも実際の航空路線でも旅客数でもない。`travel[i]` を World Bank の出国者数から
  作る案は採らなかった（速さの定数で戻せず、177 か国中 53% が `[TRAVEL_MIN, TRAVEL_MAX]` に張り付く）ので、`data/mobility.json` はモデルが読む列だけを配る。UI はこれを
  名乗り、読み込めなかったときは「人口と距離だけ」と名乗る（`model.mobility.from`）。
- **国境を越えるのは人である。** 1 日の出国者はその国の **E+I から**引く（基準値は UN Tourism の年間国際観光客到着数 14 億 ÷ 世界人口 81 億＝**1 人 1 日あたり 4.7×10⁻⁴**。
  感染による抑制・国ごとの旅行しやすさ・移動量スライダー・両国の国境状態が掛かる）。1 人が運ぶのは 1 感染。有病率の足切りや 1 国 1 日の抽選回数の上限は無い。
- **速さは COVID-19 の実際の国数曲線に合わせて較正してある**（10 か国 ≒ 50 日・50 か国 ≒ 80 日・100 か国 ≒ 95 日。実測 59 / 81 / 95 日）。
- **走らせる上限は 3 年**（出生・死亡・加齢が無いモデルで風土病の定着は言えない）。
- **すべての病気が同じ「よく混ざった集団」の式で広がる**（接触・埋葬・輪状接種が決めるエボラは実際より広く伝わる。年齢構造・入院・都市単位も持たない）。持っていない
  ものを持っているように名乗らない。
- **点の数は症例数に比例する——国ごとの上限は無い**（上限は全体の 4,800 点だけで、点の置き場は継ぎ足しで増える）。点には安定した id（国 × 上限 ＋ 枠）があり、1 日の変化は
  `{add,remove}` として `GeoJSONSource.updateData` へ送る（全件アップロードは `js/geo-engine.js` のフォールバック）。低ズームでは点の**下に**密度面（heatmap）を敷く
  （入れ替えると HUD の「1 点 ≈ N 人」が真でなくなる）。
- **点は「人が住んでいるところ」に、住んでいる人数に比例して置く**——`scatterCases` が最大剰余法で配分し、割り当ての残っているアンカーを巡回して出す（巡回順は契約の一部:
  `buildDots()` が先頭 `kE` 点を「潜伏」に塗る）。重みが等しい／無いときは巡回と同じ結果。人口ラスタは IntMap に無いので、アンカーは `data/gazetteer-world.json.gz`
  （GeoNames の 148,630 地点、うち 139,056 が人口を持つ）——面ではなく点であり画面がそう名乗る。`PPLX` の行は落とす。アンカーの上限は無い（`n` 点には人口上位 `n` 件で足りる）。
  国は地名辞典自身の ISO2 で決め、点を受け取るアンカーだけ輪郭の内外判定をする。地名辞典は世界の確定には入らず、開いた直後に取り、届いた時点で配置のプールを置き直す。
- 地図の点は**赤＝感染性あり・橙＝感染済みで未感染性**で、HUD が両方の人数と1 点が何人ぶんかを明示する。点は実在の都市に置き、ゆらぎの後も国の多角形の中にあるか検査する
  （`scatterCases()`。置けなければその国は点を描かない）。この層は「いま病気の人」なので累計死者は国を残さず、生きている国の点を暗くする。
- **1 日の差分の署名は訊かれた組をすべて区別できなければならない**（整数で詰める `dotSignature`）。
- **走らせる前に「どの世界か」を確定する。** 国境表（`data/country-facts.json`）と空港表（`data/airports.json`）は取得が決着するまで発生国を選べない（同じ種が同じ世界を指す
  ため）。失敗しても閉じ込めず、失敗は表ごとに画面が名乗る。
- **設定の値・入力欄の値・engine が走らせる値は 1 つの数である**（`snapToStep()` が入力欄の格子へ丸めて engine に書き戻す——すべてのスライダーについて。プリセットの精度を
  守るときは刻みを変える。R₀ は 0.05）。
- **人口が測られていない行は区画ではない**（`countryGeo` は Natural Earth admin-0、10 m で 258 行、うち 9 行の人口はゼロ。`createPandemicModel()` は人口の無い行を拒否し、
  host が落とした件数を画面が言う）。
- **入国規制とロックダウンを決めるのは政府**——`policyActors()`（純関数）が ① 別の行が Natural Earth の `SOVEREIGNT` で自分の宗主だと名乗るならその政府に従う
  （グリーンランド→デンマーク、プエルトリコ→アメリカ、マカオ→中国）② そうでなければ `data/country-facts.json` に首都があるときだけ自分で決める（台湾・コソボ・西サハラは
  決める。南極大陸・ビル・タウィール・スプラトリー諸島・主権基地領域は政策を行わない）。表が読めなかったときは誰も降格せず画面がそう名乗る。`totals()` の「入国規制中」
  「ロックダウン中」は政府の数で、従属領は `step()` の最後に宗主の状態を写す。
- **報せ方は 2 つ**（`eventKind()`）。世界の規則を変える出来事（ワクチン・治療法・変異株の命名・緊急事態の閾値・終了）は同時に 1 枚だけトーストで割り込み、各国政府の反応
  （入国規制・ロックダウン・再開）は出来事の記録（HUD の 🗒）に積む。宣言の無い種類は `routine`。① が engine が `events.push` する種類がすべて宣言されていることを
  突き合わせる。
- **政策は地図の上の状態として描く**（`pg-policy-ring` / `pg-policy-lock`。入国規制の段階がリングの色——黄→橙→赤、ロックダウンの強さが青い芯の濃さ）。政府ごとに 1 つの
  バッジを Natural Earth の LABEL_X/Y に置き、症例の点より下に置く。
- **時系列は engine が持つ**（`model.history()`。1 日 1 レコードで `newInf` / `newDead` は台帳 `cumInf` / `D` の差分）。HUD の折れ線は `chartPoints()`（純関数）で各バケットの
  最大値を取り、2 系列はそれぞれのピークで正規化し両方のピーク値を印字する。
- **国をタップするとその国の数字が出る**（`model.report(i)`。Rₑ は engine が計算——`behaviourOf()` / `betaOf()` / `rEffOf()` は 1 か所で `step()` と `report()` が通る）。
  画面は **Rₑ = R₀ × 季節 × 行動変容とロックダウン × 未感染の割合**と内訳まで書く。
- **画面の数がどこから来たかはドロワーで読める**（📖「出典と仮定」。設定画面と走行中の両方から開く）: ① 疾患のパラメータ——プリセットごとの出典で、`sources` の各要素は
  `{ for, name }`（`for` はプリセット自身のフィールド名。9 言語の語にするのは `js/playground.js`）。出典の無いパラメータもフィールドから数え上げて名指す（COVID-19 の R₀ 3.2 と
  IFR 0.7% はこの表に出典を持たない）。② この実行が使う世界——6 つの表のライセンスと `dataState`（読み込み済み／一部の国のみ／読み込めませんでした／読み込み中）。
  ③ **測定ではなく仮定**——路線数が旅客流動の代わりであること、点が都市に載ること、初期免疫が何か、重症度が検出モデル無しに全感染へ当たること（③ が要点）。
- **1 本のランは分布からの 1 回の抽出である**（📊「この結果はどこまで偶然か」）。同じ設定のまま乱数だけ変えて 10 / 25 / 50 回走らせ、死者・延べ感染・到達した国と地域・
  ピーク・ピーク日の中央値と 10〜90 パーセンタイル、結末の内訳（封じ込め／流行しきって終息／期間上限でも継続中＝`end` の全部）を出す。main thread で時間分割し（Worker の
  控えが最も余裕の無い端末で走るため）、残り時間は終わったランの実測から出す。分位数は補間した順序統計量。

### 8.6 紹介ページ・授業ページ・見本の地図 (Landing & showcase)

アプリを開いたことのない人が着くページと、そこから開く見本の地図。**4 つの読み手が 1 つの宣言を読む**。

| 何 | どこ | 誰が書くか |
|---|---|---|
| 見本の宣言（視点・日付・レイヤー・ベースマップ・日英の題/説明/問い・`drawn`） | `js/showcase.js` `SHOWCASE` | 手で書く |
| 見本のリンクと画面写真 | `js/showcase.js` の生成領域 `CAPTURED`・`img/showcase/<id>.jpg`（とギャラリー用の `<id>-thumb.jpg`・480×252） | `scripts/showcase-capture.mjs` |
| ページの文（en + jp） | `scripts/landing-text.mjs` | 手で書く |
| `about.html` `teachers.html` `news-map.html` `embed-map.html` `developers.html`（データセットの表はビルドが埋める——§1.1）と `ja/` の同名、`sitemap.xml` `robots.txt` | リポジトリ直下 | `scripts/landing.mjs --write` |
| 見本ごとの共有ページ `s/<id>.html`・`ja/s/<id>.html` と og:image `img/showcase/<id>-card.jpg`（1200×630） | `s/`・`ja/s/`・`img/showcase/` | `scripts/landing.mjs --write`・`scripts/showcase-capture.mjs` |

- **リンクは手で書かない。** `scripts/showcase-capture.mjs` がビルドしたサイトを Chromium で開き、投影・ベースマップのボタン、共有リンクが運ぶ全レイヤーのチェックと
  `change`、レンダラ契約のカメラ、Chronos で宣言どおりの状態を作り、アプリ自身の符号化（`IntMapBookmark.link()`＝`#v=` 形式）を読み、同じ瞬間に画面を撮る。宣言に無い状態
  （`s=` や基本表示の `d=`——撮影は基本表示も自分の箱で消す）を符号化したリンクは書かない。`--serve dist` はこの実行の間だけ `scripts/serve.mjs` を立てる。
- **ページは生成物。** 文・見本・事実（時計の床 `js/hist-scale.js` `FLOOR`、スナップショット数 `data/hist-eras.js`、国境の帯 `js/time-borders.js`
  `HB_MIN/HB_MAX/CS_MIN/CS_MAX`、レイヤー数 `js/layer-manifest.js`、寄付リンク `js/supporter.js` `STRIPE_DONATE`）をそれぞれの持ち主から読む。**ページに数字を手で書かない。**
  言語は別 URL（`hreflang`）で JS が無くても全文が読める。全ページの埋め込みスクリプト（`PAGE_SCRIPT`）はテーマと、日本語を選んだ読者だけを日本語版へ送る。
- **紹介ページの冒頭（時空間の時計と三つの入口）**: カテゴリ・見出し・信頼の一行は `scripts/brand-text.mjs` の `category`・`tagline`・`trust` を `scripts/landing.mjs` が直接読む。
  横の絵は `stripExamples()`（日付を持ちレイヤーを持たない見本を日付順に）の画面写真で、`HERO_EXAMPLE` の 1 枚だけが見え他は `hidden`。スライダーと年のボタンも `hidden` で出し、
  紹介ページだけの 2 本目のスクリプト `STRIP_SCRIPT`（ハッシュで許可）が見せて切り替える。**三つの入口**（`ENTRANCES`）: 「いまの世界」は現在の地図に共有可能なライブ層を
  点けたリンク（`js/map-state.js` `encode`。地震の層はリンクで運べないので、文はレイヤーから点けるよう述べる）、「どの年の世界も」は見本 1 件の撮影済みリンクと歴史地図の
  入口、「Atlas に訊く」は地図を開くだけ。`--check` の `entranceProblems()` が共有できない層・見本でないもの・時計に 2 枚未満を拒む。
- **共有ページ（SNS の素材）**: `index.html#v=…` は状態を断片に持つのでサーバへ届かず、Edge Function は text/html を返せない ⇒ 見本ごとに `<head>` がそのままカードになる静的
  ページを生成する（og:title/description/url/image・`twitter:card=summary_large_image`・canonical・hreflang。`og:image:width/height` は画像ファイルから読む）。人には meta
  refresh と `location.replace` とリンクの 3 つで地図へ送る。絶対 URL は `index.html` の `og:url` 1 か所から。
- **SEO**: 各ページに title・description・canonical・hreflang（en/ja/x-default）・Open Graph・JSON-LD（紹介は `WebApplication`・価格 0、授業は `WebPage`）。`robots.txt` は
  ホストの根でしか読まれないので `/IntMap/` 配下の今は効かない。Search Console の確認ファイルは残す。
- **用途別のページ**: `news-map.html`（ニュースを地図で読む）と `embed-map.html`（記事に地図を埋め込む——埋め込みタブが書くコードそのもの＝`js/embed-mode.js` の
  `embedUrl`・`iframeCode`・`EMBED_SIZES`、枠の題はアプリの文字列 `embedFrameTitle`）。紹介ページの「こんな使い方も」から相互に結ぶ。
- **アプリ内の作例ギャラリー**（`js/showcase-gallery.js`）: 検索欄に何も打たずにカーソルを置くと、結果欄（携帯ではシート）に作例と授業ツアーのカードが 1 列で並び、最初の
  1 文字で地名の候補に替わる。「すべて見る」・`data-im-gallery`・Atlas の `panel.gallery` で全体を開く（主題ごとの見出し＝`TOPICS`、最後にツアー）。カードは `SHOWCASE` と `TOURS`
  から導く。見本は `openShowcase`（共有リンクの復元＋読み返し）、ツアーは `js/tour-player.js` の `startTour`。自動では開かない。
- **入口**: 設定 ▸ 情報とサポートの「IntMap について」（`#link-about`）。Atlas の `panel.about`・`panel.showcase`（`id` で見本を開く——アドレスに捕えたリンクを置いて
  `IntMapBookmark.restore({shared:true})`、日付とレイヤーを読み返してから completed）・`panel.gallery`（`section:"tours"`）。catalogue の一覧は `SHOWCASE` から作る。
- **見せない見本**: `withheld`（開くと写真どおりにならないと実測した理由の文）がある見本は `SHOWCASE` に入らず、ページ・sitemap・Atlas・spec に出ない。生成器は古い共有ページを消す。
- **絶対アドレス**: 生成物は `scripts/site-url.mjs` の `SITE_TOKEN` を書き、ビルドの `siteUrlPlugin` が dist/ の .html/.xml/.txt を `site-origin.js` の値で埋める（`fillSiteToken`）。
  robots.txt の基底パスは `SITE_BASE_PATH`。
- **門**: `node scripts/landing.mjs --check`（`tests/landing-showcase-checks.test.mjs`）——生成物が生成器と一致し、捕えたリンクが宣言と一致し、宣言に無い状態を運ばない。
  `tests/landing-showcase.spec.js` が全見本を開き、日付・カメラ・レイヤーと `drawn` を地図に訊き、リンク切れとモバイル幅の横スクロールが無いことを測る。

#### 8.6.1 授業ツアー (Classroom tours)

教員が登録なしで 1 コマを回すための「導かれた物語」。地図の状態を順に並べ、各段に読み上げる文（`say`）と生徒への問い（`ask`）を付け、**授業モード**（全画面・大きな文字・
余計な UI を隠す）で「次へ／前へ」と進む。

| 何 | どこ | 誰が書くか |
|---|---|---|
| ツアーの宣言（題・説明・学習指導要領の項目・段） | `js/tours.js` `TOURS` | 手で書く |
| 段のリンク（見本を名指す段は見本の `CAPTURED` をそのまま） | `js/tours.js` の生成領域 `CAPTURED_STEPS` | `scripts/showcase-capture.mjs` |
| 授業モード（パネル・キー・ピッカー・一時ツアー） | `js/tour-player.js` | 手で書く |
| 授業ページの「授業ツアー」と「自分のツアーを作る」の節 | `teachers.html`・`ja/teachers.html` | `scripts/landing.mjs --write` |
| 全ページの足元の入口（紹介・授業・ニュース・埋め込み・年代から探す〔`history/`〕・報道/学校/研究/支援/相談）。`PAGES`・`ORG_NAV`・`HUB` から導く | 紹介系 8 ページと組織向け 10 ページ（`ja/` を含む） | `scripts/landing.mjs --write`・`scripts/org-pages.mjs --write` |

- **段は見本と同じ方法で作る**（`example:` か、見本と同じ形の意図 `view`・`base`・`at`・`layers`・`drawn`）。`node scripts/landing.mjs --check` が同じ規則（`linkProblems`）で、
  見本を名指す段がその見本を見せている（`withheld` でない）ことも確かめる。
- **開き方は共有リンクの復元だけ。** アドレスが `?tour=<id>&step=<n>#v=…` になり `IntMapBookmark.restore({shared:true})` が状態全体を適用し、時計とレイヤーをリンク自身の
  `tt` と `l` に照らして読み返してから開いたとする（上限 6 秒）。アドレスバーは常にいま映している段へのリンク。
- **入口**: URL `?tour=<id>&step=<n>`（知らない id は一覧を開く）／設定 ▸ 情報とサポートの「授業ツアー」（`#btn-tours`）／Atlas の `panel.tour`。プレイヤーは独立したチャンクで、
  `src/main.js` がこの 2 つの場合にだけ読む。
- **ガイド**: 初めて見る人向けの案内はこのプレイヤーの `guide` ツアー（`?tour=guide`）。段は `js/showcase.js` の `guide: true` の作例から `js/tours.js` の `guideTour()` が導く
  （`TOURS` には入れない）。入口は `js/onboarding.js` の `_imStartDemo`（一度だけ・スマホでは出さない・主題レイヤーが既にオンなら出さない）。
- **授業モード**: `html[data-classroom]` の下で、地図・凡例（`.data-legend`・`.koppen-legend`）・出典表示（`#map-credit`・レンダラの credit）・通知（`#ai-toast`）・パネルだけを
  残す一覧で隠す（出典表示は削らない）。キー: → / Space / Page Down で次、← / Shift+Space / Page Up で前、Home / End、F で全画面、T で文を隠す、Esc で終了。アプリ内から
  始めたツアーは終えると始める前の地図へ戻る。
- **一時ツアー（Atlas）**: `panel.tour` の `addStep` が今の地図を `IntMapBookmark.link()` で段として記録し、`sessionStorage`（`intmap_tour_temp`）に置き id `atlas` で再生する。
- **語りは地図についての主張**: 段の `drawn` が文の依拠する名前を持つ——`labels`（その日の国名）・`admin`（第1級区分）・`noAdminIn`（区分を描かないという主張）。
  `tests/classroom-tours-checks.test.mjs` が地図の描く記録（国名は 1886 年から `data/cshapes.js`・1689〜1885 年は `data/hist-borders.js`、区分は `data/hist-admin1.js`・
  `data/hist-kuni.js`・`data/hist-admin-fill.js`）に訊く。地図の外の操作を求める段は問いの中でアプリ自身のラベルで名指す。
- **門**: `node scripts/landing.mjs --check`・`tests/classroom-tours-checks.test.mjs`。`tests/landing-showcase.spec.js` が最初の見本をツアーのアドレスから開き、パネル・→ キー・
  Esc を同じ起動の中で測る。

#### 8.6.2 ツアー作成 (Tour builder)

教員が自分の授業のツアーを作り、リンク 1 本で配る。アカウントもサーバの表も無い。

- **入口**: ツアー一覧（`#btn-tours`）の「自分のツアーを作る」／再生中の自作ツアー（`custom`）と Atlas の一時ツアー（`atlas`）の「このツアーを編集」／Atlas の
  `panel.tourBuilder`。`js/tour-builder.js` は独立したチャンク。
- **段は地図そのもの**: 「いまの地図をステップに追加」は `MapState.hash()` をそのまま段にする。各段に題・話すこと・問い（任意）。並べ替え・削除・「いまの地図にする」・
  「この地図を表示」。
- **保存はアドレスそのもの**: `?tour=custom&t=<ツアー>&step=<n>#<段 1 の地図>`。`t` は `{ v:1, n:題, s:[[断片, 題, 話すこと, 問い], …] }` の JSON を DEFLATE
  （`CompressionStream('deflate-raw')`）して base64url にしたもので、先頭 1 文字が書式（`z`＝圧縮、`j`＝素の JSON）。codec は `js/tours.js`。プレイヤーは各段の断片を地図の
  codec で書き直してから使う。下書きは `localStorage`（`intmap_tour_draft`）。
- **長さの上限は実測**: クエリはサーバへ送られる。本番（GitHub Pages）は path＋query が **8,192 バイトまで 200、8,193 バイトで 414**（`TOUR_REQUEST_LIMIT`）。パネルは使用量を
  示し、残りが 1 段あたりの平均より少なくなったら「あと 1 ステップ入らないかもしれません」と先に警告し、超えたツアーにはリンクを渡さない。
- **再生は既存のプレイヤー**（`startTour('custom', n, { t })`）。プレビューも同じ経路で、終えると作成パネルに戻る。
- **共有**: 「リンクをコピー」（拒まれたら選択済みの入力欄）・`navigator.share` がある端末では「共有」。
- **アカウントに保存**: 下書きを地図ドキュメント（`kind:'tour'`）にしてライブラリへ渡す（§8.1.2。アカウントの行は長さの上限を受けない）。`t` の梱包は `js/link-codec.js`
  （ブリーフィングの `b` と同じ）で、読み手は `TOUR_INFLATED_MAX`（1 文書の段に許す 1 MiB の 2 倍）を超えて展開しない。
- **作成器で開くアドレス**: `&edit=1`（`js/tours.js` の `TOUR_EDIT_PARAM`）が付くと、プレイヤーは再生せず `openBuilder({ load })` に下書きとして渡し、クエリを消す。
  単元対応表（§8.6.5）の「この単元のツアーを作る」がこれを使う。
- **門**: `tests/tour-builder-checks.test.mjs`。

#### 8.6.3 この日の歴史地図 (On this day)

暦の 1 日（`MM-DD`）について、地図が描く記録がその日に日付をつけている出来事を記録の全年分まとめて読む。**索引は 1 つ**で、読み手は 4 つ——アプリのカードとシート、Atlas、
ビルドが書く静的ページとその絵、投稿の下書き。この索引は**日付つき出来事の唯一の索引**でもある（`js/time-index.js` が記録の形・出典 `sourceOf`・日付の精度・切り口を持つ）。
暦の日の切り口（`onDay`）がこの節、年の切り口（`inYear`）が年鑑（§7.4b）、時刻までの切り口（`upTo`）が情報ダッシュボードの「出来事」（時計の瞬間までに始まった記録を新しい
順に、‹ › は時計そのものを 1 年動かす）。索引は暦の日の記録（`days`）の横に、どちらの記録も述べない出来事を Wikidata が述べるとおりに持つ（`events`：QID・日付を述べた属性・
精度・ユリウス暦の印・座標があるときだけ場所）。`scripts/fetch-world-events.mjs` が選んだ記事から項目を引いて写し（`scripts/time-index/wikidata-events.json`）に書き、生成器は
写しだけを読む。日付は P585 と P580 の最も細かい精度の最も早い日、無ければ開通・初飛行・打ち上げ・発見・発表・成立の順。項目自身の終了より後の開始は日付にしない。史実と
矛盾する値は値と理由を名指して拒み、日付を述べない項目は落とす。**Wikidata の出来事は暦の日のページには載せない**（年鑑と「出来事」には載る）。

| 何 | 正本 | 書き出し先 | 誰が書くか |
|---|---|---|---|
| 索引（`MM-DD` → 出来事） | `scripts/build-on-this-day.mjs` | `data/on-this-day.json`（追跡。`--check` で記録と照合） | 記録を直したら手で再生成（門 ① が古さを落とす） |
| 文言・見出しの規則・地図のリンク | `js/on-this-day.js`（`describe`・`headline`・`viewOf`/`stateFor`/`linkFor`） | アプリ・Atlas・静的ページ・下書きが同じ関数を読む | — |
| 静的ページ（日ごと、en と `ja/`）・暦・sitemap | `scripts/on-this-day-pages.mjs`（文は `scripts/on-this-day-text.mjs`） | ビルド時に `dist/on-this-day/<MM-DD>/`・`dist/ja/on-this-day/…`・`dist/sitemap-on-this-day.xml` | `vite.config.js` の `onThisDayPagesPlugin`（子プロセス） |
| リンクのカードの絵（1200×630 PNG） | `scripts/lib/map-card.mjs` | `dist/on-this-day/<MM-DD>/card.png`（言語共通） | 同上（子プロセスを最大 4 つに分ける） |
| 投稿の下書き | `scripts/on-this-day-pages.mjs --queue` | 標準出力（**投稿・送信・予約はしない**） | 人が承認して投稿する |

- **国境の出来事は地図のコードが求める**（`scripts/history-pages.mjs` の `mapReader` に `changeDates()` の各日とその前日を訊き `tagSame` の名前で比べる——前日に無く当日にある
  政体は「現れる」、逆は「消える」、両日にあって面積が 1 km² 以上違えば「国境が変わる」）。記録自身がその日にその政体の境を持つものだけを載せる。CShapes の 1 月 1 日付けは
  `maybeYearOnly` の印を持ち、見出しにならない。
- **載せないもの**（索引の `skipped`）: OpenHistoricalMap の記録（日付に精度の欄が無く、2,480 の日付のうち 918 が 1 日）、記録の継ぎ目（1886-01-01）、1689 年より前のシート。
- **戦争の出来事**は `data/wars.json` の完全な日付を持つ行。地図のリンクはその戦争のレイヤーを点ける。
- **見出し**は `js/atlas-reasoning.js` `rankChanges`（変わった政体の数）。1 月 1 日付けでない国境の出来事が無ければ戦争の記録の最初の出来事。
- **地図のリンク**は日付（`tt`）・場所（政体の範囲を収める `fitView`）・戦争のレイヤー（`l=dl-<戦争>`）・題（`title=`）。アプリでは共有リンクの復元で開き、時計とレイヤーを
  読み返してから開いたと言う（`js/showcase-gallery.js` `openLink`）。
- **アプリの入口**: 地名検索の欄に何も打たずに触れると、作例の帯の上に「この日の歴史地図 · 10月3日」のカード（見出しを 1 タップで地図に、「すべて」で日ごとのシート、
  ‹ › で前後の日）。出来事が無ければ出さない。Atlas は `onThisDay`（`time.onThisDay`。`open:n`・`show:true`）。
- **計測**: 日のページと歴史地図の入口ページは匿名集計の入口（`entry` の `on-this-day`・`history`）。下書きのリンクは日のページに utm を付ける。
- **門**: `tests/marketing-next-checks.test.mjs`（1990-10-03、1945/1947/1948-08-15、1971-08-15 の照合ほか）。

#### 8.6.4 国別の入口ページ (Country pages)

検索から地図へ入る 3 つ目の軸——国。「<国名> 地図」「<国名> 人口 地図」「<国名> 歴史 地図」で探す人を、その国を開いた地図へ連れてくる。

| 何 | 正本 | 書き出し先 | 誰が書くか |
|---|---|---|---|
| 国の集合・名前（en/jp）・国ごとの行とその条件 | `scripts/public-api.mjs`（`countryUniverse`・`model().countryFile`） | — | — |
| 国別ページ（en と `ja/`）・一覧・sitemap | `scripts/country-pages.mjs`（文は `scripts/country-pages-text.mjs`） | ビルド時に `dist/countries/<code>/`・`dist/ja/countries/…`・`dist/sitemap-countries.xml` | `vite.config.js` の `countryPagesPlugin`（子プロセス。歴史地図と公開 API の後） |

- **国の集合**は公開 API と同じ Natural Earth admin-0（`ISO_A3_EH`、無ければ `ADM0_A3`）。全コードにページがある。
- **地図のリンク**は国の枠（`js/country-extent.js` `homeExtent`。遠い属領を含めず、日付変更線をまたぐ国は 180 を越える 1 区間）を `fitView` で収めた視点と、同じ視点に人口密度の
  1 km グリッド（`dl-popgrid`。共有リンクが運べるかをビルド時に確かめる）。
- **基本データ**は国の詳細カードと同じ 4 項目（首都・面積・通貨・言語）を `data/country-facts.json` から、カードと同じラベル（`js/locales/ui.*.js`）で。公開 API が提供する
  データセットの行だけ（提供されないものは節ごと出ない）。出典表示が条件のものは出典とライセンスを書く。
- **歴史地図**は `REGIONS` のうち枠が国の輪郭と重なる地域（`partKm2In` > 0、全球の枠は除く）。「その時代にその国があった」とは述べない。
- **出来事**は `data/on-this-day.json` の戦争記録のうち地点が国の輪郭の中にあるもの（名前で結ばない）。
- **オープンデータ**は国ごとに ID・ライセンス・条件・出典と `api/v1/countries/<CODE>.json` へのリンク。`api/v1/countries.json` の各国は `page` を持つ。
- **導線**: フッタ（`scripts/landing.mjs` `pageLinks`）と歴史地図のハブから一覧へ。**計測**: `entry` の `countries`。
- **門**: `tests/country-pages-checks.test.mjs`（ロシア・フィジーの視点など）。

|---|---|---|---|
| 年の選び方・年ページ（en と `ja/`）・世紀ごとの一覧・sitemap | `scripts/year-pages.mjs`（文は `scripts/year-pages-text.mjs`） | ビルド時に `dist/history/years/<年>/`・`dist/ja/history/years/…`・`dist/sitemap-years.xml` | `vite.config.js` の `yearPagesPlugin`（子プロセス。歴史地図の後） |
| 年の世界の絵（1 年 1 枚、両言語で共有） | `scripts/lib/world-svg.mjs` | `dist/history/years/<年>/world-map.svg` | 同上 |

- **年は規則で選ぶ**（`chooseYears`）。3 つの集合の和で、各ページはどれに選ばれたかを書く: ① historical-basemaps のシートの年（`data/hist-eras.js` の `snaps`）、② 日付を持つ記録
  （Cliopatria・OpenHistoricalMap・CShapes。最寄りのシートで補った輪郭は除く）を毎年 7 月 1 日に読み、描き始めた名前と描かなくなった名前の和が 0 でない変化の上位 `TURN_SHARE`
  （5%）に入る年（記録の継ぎ目は数えない）、③ 日付つき出来事の索引の Wikidata の出来事のうち種類（`EVENT_KINDS`。未分類の種類はビルドを止める）が政体に関わるもの（地政・戦争・
  革命）の年。CShapes の最終年より後は選ばない。
- **ページが述べるのは地図が描くもの**（`mapReader` が 7 月 1 日に答える集まり。名前の表は面積順で、各行に輪郭を描く記録と Wikidata の項目。見出しは「名前」であって「国」ではない）。
- **絵**は Equal Earth 図法・幅 1000 px の SVG（表示のためだけにおよそ 1 px まで Douglas–Peucker で簡略化し、1 px 未満の輪郭は省く——ページにそう書く。日付変更線をまたぐ環は
  両側に描いて縁で切る。陸地は Natural Earth 1:110m を灰色で敷く。シートから補った輪郭は淡く塗り註が言う。明暗は `prefers-color-scheme`）。
- **変化**は前のページの年との比較で、日付を持つ記録の名前だけを数え、名前は書かれたとおりに比べる。
- **出来事**は索引の記録のうち日付が名指す年がその年のもの（`js/time-index.js` `yearOf`）。
- **構造化データ**は `WebPage` の `mainEntity` に `Map`（`temporalCoverage` は ISO 8601 の年）と `BreadcrumbList`。`og:image` はその年自身のカード。
- **地域ページ（世界）とは別の検索意図**: `history/world/<年>/` は地図、年ページは「The world in 1914: states, borders and changes」／「1914年の世界——国と国境、前の年からの
  変化」。題・h1・description は重ならず（門が比べる）、canonical はそれぞれ自分自身。
- **導線**: 歴史地図のハブから一覧へ。各年は同じ名前を並べる地域ページ（世界）へ「地図」として、世界の地域ページは年ページのある年へ「国と変化」として結ぶ。
- **計測**: `history/` の下なので既存の `history`。
- **門**: `tests/history-year-pages-checks.test.mjs`（紀元前 200 年／1000 年／1648 年／1815 年／1914 年／1945 年に描かれるべき名前と描かれてはならない名前ほか）。

#### 8.6.4 入口ページのリンクのカードと共有 (Entry-page link cards & sharing)

入口ページを人に渡すための仕組み。リンクを貼ったときに出る絵をページごとに内容から描き、ページの終わりに読者が自分で共有するためのリンクを置く。

| 何 | 正本 | 書き出し先 | 誰が書くか |
|---|---|---|---|
| 年ページ・国別ページのカード（1200×630 PNG。1 ページ 1 枚、両言語で共有） | `scripts/lib/page-card.mjs`（ラスタ・メルカトルの枠・数字・PNG は `scripts/lib/map-card.mjs`、Equal Earth の環は `scripts/lib/world-svg.mjs`） | `dist/history/years/<年>/card.png`・`dist/countries/<code>/card.png` | `year-pages.mjs`・`country-pages.mjs` の `drawCards`（ワーカースレッド） |
| 共有のリンク（入口ページ全部） | 宛先は `scripts/lib/share-targets.mjs`、置くのは `scripts/history-pages.mjs` `shell`（文は `scripts/history-pages-text.mjs` `share`） | 各ページの `#share` | 各生成器（同じ `shell`） |
| 年ページの投稿の下書き（X・Bluesky・Threads、en / ja） | `scripts/year-pages.mjs --queue [--only <slug>,…]`（文は `scripts/year-pages-text.mjs` `post`） | 標準出力（**投稿・予約・送信はしない**） | 人 |

- **年のカード**はページの絵と同じ輪郭の集まり（`drawn`）を同じ図法・色で暗色の配色で描き、左上に年（`yearWords(y, 'en')`）、右下にワードマーク。
- **国のカード**はページの枠（`homeExtent`）を `map-card.mjs` `frameFor` で収め、周りの国（Natural Earth 1:10m）を陸としてその国を塗る。12 px に満たない国（バチカンなど）は
  印を付ける。国名は書かない。
- **カードはページが述べないことを述べない**（簡略化は表示だけ）。`og:image:alt` と `twitter:image:alt` はカードを持つページだけが書く（年は `mapAlt`、国は `cardAlt`）。一覧・
  地域ページ・今週の地球はサイトの共通の絵（この日の歴史地図は自分のカード——§8.6.3）。
- **共有のリンク**は X・Bluesky・Threads・Facebook・LINE・Reddit の共有画面を開く素の `<a href>`（スクリプトは無く、押されるまで何も通信しない）。アドレスに
  `utm_source=<サービス>&utm_medium=social&utm_campaign=share-page` を載せ、地図へ進んだ人は匿名集計の入口（`history`・`on-this-day`・`countries`・`weekly`）でそのサービスの名で
  数えられる。この一覧は読者が共有する先で、IntMap の持ち主が投稿する先（`on-this-day-pages.mjs` `CHANNELS`）とは別。
- **門**: `tests/marketing-growth-checks.test.mjs`。

#### 8.6.4 学ぶクエスト (Learn quests)

地図そのものを教材にする出題。実データから問題を作り、答えは地図の上で出し地図の上で示す。既存のクイズ（`js/analysis-edu.js` の国旗・首都・国クリック・シルエット・人口／
面積対決）はそのまま残り、そのメニューから入れる。

| 何 | どこ |
|---|---|
| 出題エンジン（純関数。DOM・`window`・通信なし。Node でも読める） | `js/quest-engine.js` |
| パネル（遅延読み込み・`window` グローバルを足さない） | `js/quest-panel.js` |
| 今日のクエストの記録と連続日数（遅延読み込み） | `js/quest-daily.js` |
| その日の結果（アカウント側） | `public.quest_daily_results`（`supabase/migrations/20261008090000_quest_daily.sql`・pgTAP `30_quest_daily_test.sql`） |
| Atlas の能力 `learn.quest`・`learn.daily` | `js/atlas-cap-learn.js` |
| 検査 | `tests/learn-quests-checks.test.mjs`・`tests/watch-account-product-checks.test.mjs` |

- **種類はレジストリ**（`QUEST_KIND_IDS` などはそこから導く）。各種類は `{id, title{en,jp}, needs, generate(rng, data, n), score(q, a)}`。
  - **場所当て `where`** — `data/gazetteer-phone.json.gz`（GeoNames・CC BY 4.0）のうち GeoNames 自身が `placeKinds` で settlement と呼ぶ行。都市名と国名（`Intl.DisplayNames`）を出し、
    読者が地図をタップする。難易度は人口の順位の分位で、順位の対数で 3 段（境は順位 N^(1/3)・N^(2/3)。人口の閾値は書かない）。1 セットは前の 3 分の 1 が「やさしい」から順に
    上がる。採点は `js/geodesy.js` の `_distKm`。
  - **年代当て `when`** — `data/on-this-day.json` の出来事。文は `js/on-this-day.js` の `describe`、地図は `viewOf` の視点とその日の主時計。問題の間 `<body>` の class
    `im-quest-blind` が、地図の時刻を印字すると自分で述べる要素（属性 `data-prints-map-time`。Chronos `#news-timeline`・携帯の `#m-clock`・`#live-news-feed`・`js/layer-time-kernel.js`
    の凡例・`js/data-layers.js` の年の欄。属性は要素を作る側が付ける）を `visibility:hidden` にし、`MapState.holdAddress('quest')` がアドレスバーの書き手（`js/map-ui.js` の `save`）を
    待たせる。出さないもの: 1 月 1 日付けの国境の出来事（`maybeYearOnly`）と文に 4 桁の数字を含む出来事。範囲は索引の `span`（1886〜2019）。
- **採点の尺度は 1 つ**: 誤差 ÷ 起こりうる最大の誤差を x として `round(1000^(1−x))`（完全が 1000、最悪がちょうど 1 点）。最大の誤差は場所当てなら地球の半周（`_HALF_CIRCUM`）、
  年代当てなら正解の年から索引の範囲の端まで。場所当てでは `max·exp(−d/L)`、L ≈ 2,897 km。
- **決定的**: 問題列は（種類・seed・n）とデータの関数（FNV-1a → mulberry32）。**挑戦リンク** `?quest=<kind>.<seed>.<n>`（`src/main.js` が読み、地図の準備ができてから始め、query を
  消す）。データを作り直すと同じ seed でも問題は変わりうる。
- **パネル**: 種類と問題数（5／10）→ 各問を地図で答える → 場所当ては正解（緑）・タップ（赤）・大円と距離、年代当ては記録の日付 → 合計・各問の結果・挑戦リンク。年代当ての
  各問から「この日の地図」を開ける。自己ベストは `localStorage`（`intmap_quest_best`）。閉じると主時計と視点を戻す。場所当ての間の地図のタップはクエストだけのもの——
  `events.holdTaps('quest')`（`js/geo-engine.js`）が `{ tapOwner: 'quest' }` で登録した処理以外を走らせない（移動・拡大・ホバーは止めない。計測ツール中のタップは取らない）。
- **入口**: クイズのメニューの「学ぶクエスト」2 項目、Tools の「学ぶクエスト」（`tool.learnQuest`）、挑戦リンク、Atlas の `quest`（`learn.quest`: `start`・`link`・`state`・`close`。
  判定はパネル自身の状態を呼んだ後に読む）。
- **場所当ての間は名前を書く基本表示を切る**（宣言が `names: true` と述べる 3 行——`js/layer-manifest.js` の `nameItems()`——を読者と同じスイッチで切り、答えを示した時点で自分が
  切った行だけを戻す。国境は残す）。アドレスバーは年代当ての間も日付を書き続ける（画面内の表示は隠す）。
- **今日のクエスト**——暦の 1 日ごとに各種類のセットが 1 つずつ（`js/quest-engine.js` の「THE DAY'S SET」）:
  - seed `d<YYYY>-<MM>-<DD>`（読者の暦の日）と `DAILY_N`（5）問のふつうの決定的なセット（挑戦リンク `?quest=when.d2026-10-08.5`）。判定は `isDailySet` 1 つ。
  - 年代当てはその暦の日（月-日）に日付をつける出来事を先に、残りを索引全体から埋める。日付の seed でない seed の問題列は変わらない。
  - 最初に解き終えた結果がその日の記録（2 回目は練習）。`js/quest-daily.js` がこのブラウザ（`localStorage` の `intmap_quest_daily`。最大 3,660 日）に、ログイン中はアカウント
    （`public.quest_daily_results`）にも残し、ログイン前に解いた日はログイン中に集計を読んだときに足す。同じ日・種類は「記録済み」。
  - 連続日数（`dailyStreak`）: いずれかの種類を解いた日の連続。今日がまだなら昨日から数え、最長も数える。読めなかったアカウントは読めなかったと述べる。
  - 見え方: メニューの先頭に「今日のクエスト」（日付・連続日数・最近 7 日の点・2 種類のボタン・記録の置き場所）。結果画面は「今日の記録に入りました／練習です」・保存先・
    結果をコピー（絵文字は使わない）。
  - 入口: クエストのメニュー、アカウントのシートの「今日のクエスト」、挑戦リンク、Atlas の `dailyQuest`（`learn.daily`: `state`（既定。アカウントへの追記はしない）・`start`・`link`）。

#### 8.6.4 今週の地球 (This week on Earth)

地球の大きな自然現象を **ISO 週**（月曜 0 時 UTC から翌週の月曜まで）ごとにまとめた公開のダイジェストと過去の記録。**記録は 1 つ**で、読み手は 3 つ——静的ページとフィード、
Atlas、投稿の下書き。

| 記録（ISO 週 → 地震と自然現象） | `scripts/build-weekly-earth.mjs` | `data/weekly-earth.json`（追跡。新しい週が先頭。`--check` で形式を照合） | 無人の定期更新（`scripts/data-refresh.mjs`・`tle-refresh.yml`。周期 `P7D`）が bot PR で週を足す |
|---|---|---|---|
| 週の計算・文言・見出しの規則・地図のリンク | `js/weekly-earth.js`（`weekOf`・`describe`・`headline`・`stateFor`/`linkFor`・`weekLink`） | builder・Atlas・静的ページ・フィード・下書きが同じ関数を読む | — |
| 静的ページ（週ごと、en と `ja/`）・一覧・Atom フィード・sitemap | `scripts/weekly-earth-pages.mjs`（文は `scripts/weekly-earth-text.mjs`） | ビルド時に `dist/weekly/<YYYY>-W<ww>/`・`dist/ja/weekly/…`・`dist/weekly/feed.xml`・`dist/ja/weekly/feed.xml`・`dist/sitemap-weekly.xml` | `vite.config.js` の `weeklyEarthPagesPlugin`（子プロセス） |
| 投稿の下書き | `scripts/weekly-earth-pages.mjs --queue [--week YYYY-Www]` | 標準出力（**投稿・送信・予約はしない**） | 人が承認して投稿する |

- **上流は 2 つ、要求は 1 回ずつ**: USGS FDSN event service（M5.5 以上、公有）と NASA EONET v3（`status=all`、米国政府の著作物）。`scripts/lib/upstream.mjs` で状態を確かめ、USGS の
  `metadata.count` と特徴の数の一致、EONET の事象の形を確かめてから書く。失敗はファイルを書かずに投げる。
- **記録は蓄積する**（既にある週は保つ。暫定の週＝週の終わりから 7 日未満に取った週は `provisional` で次の実行が確定する。初回だけ 52 週を埋める。何も消さない）。
- **載せないもの（`rule` としてファイルに書き、ページが述べる）**: M5.5 未満の地震、焼失面積が述べられていて 10,000 ha 未満の山火事（`fewer.wildfires` で数える）、輪郭（Polygon）だけで
  示される事象の位置（GDACS の洪水の輪郭は軸の順序が混在する）。
- **地図のリンク**は場所（点の事象はズーム 5）・日（`tt`）・題と、出来事そのものを受け取ったマイマップのピン（`mm=`、`js/my-map-doc.js`。地震のレイヤー `bx-eq` は共有リンクが
  運べない）。週のリンクは位置のある全項目をピンにして枠に収める。開いたら時計を読み返す。
- **見出し**は最大の地震（USGS のマグニチュード）。地震の無い週は EONET が述べる風速の最も強い嵐。
- **入口**: 紹介ページ・組織向けページ・歴史地図の足元（`scripts/landing.mjs` `pageLinks`）、設定 ▸ 新着の下の「今週の地球」。Atlas は `weeklyEarth`（`time.weeklyEarth`。`week`・
  `open:n`・`show:true`）。
- **計測**: 週のページと一覧は匿名集計の入口（`entry` の `weekly`）。下書きのリンクは `utm_campaign=weekly-earth`。
- **門**: `tests/weekly-earth-checks.test.mjs`。`npm run check:datagov` が出自と無人更新の安全（`refresh-safe`）を測る。
