## 10. 多言語対応の構造

### 10.1 答えは1つ — `npm run check:i18n`

利用者が読む文字列は複数の**形**で存在するので、`scripts/i18n-audit.mjs --gate`（＝`npm run check:i18n`。`npm test` に内包）が**全部の面を1つの表**に出す。

| 面 | 何を数えるか |
|---|---|
| keyed `ui` 表 | 421 キー × 9言語 |
| inline `L(…)` 表 | 6,000 行（位置引数を持たない言語が引く英語→訳の表） |
| `L(…)` の位置引数 | 7,336 サイト（最初の5言語） |
| 読み物ページ `js/locales/pages.*.js` | 463 |
| HTML の `data-i18n` キー | どの言語も宣言していないキーが 0 であること |
| `title` / `aria-label` / `placeholder` / `alt` | マークアップと `js/` の両方で、翻訳を通らないものが 0 であること |
| `<title>` / `<meta description>` | 読み物ページの文書そのものが訳されていること |
| **どの呼び出しも要求しない行** | locale 表に在って誰も引けない鍵が 0 であること（`scripts/i18n-dead-key-audit.mjs`） |

**形の監査**（いずれも現在 0。形が二度と現れないことを固定する）: `jp ? '…' : '…'` の2分岐三項（`scripts/i18n-two-branch-audit.mjs`）／`jp() ? … : …` のヘルパ三項と腕が配列／
オブジェクトの三項（`scripts/i18n-helper-ternary-audit.mjs`）／言語コードをキーにしたオブジェクト（`scripts/i18n-langmap-audit.mjs`）／言語→位置の表と `L()==='jp'?1:…` の index chain
（`scripts/i18n-positional-array-audit.mjs`）／方針が書くと決めている言語の位置引数を欠く call site と各言語の引数が英語と同一の call site（`scripts/i18n-positional-audit.mjs`。要求する
個数は `scripts/lang-policy.mjs` の `authoredLangs()` から導く——`pick()` が位置で解く 5 言語 en / jp / de / ru / es のうち方針がまだ書く最後の位置＋1、いまは **2**。`return all;` で 5 に戻る。
同一かの検査は狭めていない）／1つの英語キーが2つ以上の意味を運ぶ call site（`scripts/i18n-key-collision-audit.mjs`）。

- **門が 100% を要求するのは IntMap が新しく文を書く言語（en + jp）だけ。** 線は誰がその言葉を書いたかで引く——出典（Wikidata・OpenHistoricalMap・ライセンス名）が書いたラベルは出典が
  書いた全言語を運び、IntMap 自身が書く文だけが en+jp。方針の正本は `CONSTITUTION.md` §7、機械の正本は `scripts/lang-policy.mjs`（`return all;` の 1 行で 9 言語へ戻る）。
- **残る 7 言語は床で支えられている**（`CONSTITUTION.md` §0 の 3）。`tests/i18n-coverage-floor.json` が各言語・各面の現在の行数を持ち（数の正本）、門はそれを下回ることを拒む（新しい英語
  だけの文字列は通り、韓国語の 1 行を消すと落ちる）。位置引数の面の分母は 5 言語ぶんの組を実際に持つ call site（[`docs/TESTING.md`](../TESTING.md)）。床は上向きにも落ちる（訳を増やしたら
  `node scripts/i18n-audit.mjs --update-floor`）。比較は `scripts/i18n-floor.mjs` の純関数で、門と回帰検査が同じ 1 つを呼ぶ。
- **被覆は「英語と違う」で測る**（表には `=EN` 列がある）。
- **「行がある」は「その行が正しい」ではない。** `pick()` は en/ja/de/ru/es を位置引数で解決し、fr / ko / zh-Hant / zh-Hans は `inline[code][arguments[0]]`＝英語原文1つにつき1行でしか
  解決できない（位置の5言語は衝突しようがなく、inline の4言語は避けようがない）。判定は日本語の位置引数で行い、過大に拾うのでゲートは許可リスト（`BENIGN`。両方向に落ちる）に対して
  落ちる。直し方は外れ値の側に固有の英語キーを与えること（`arguments[0]` は英語の表示文字列でもある）。
- **どの呼び出しが翻訳呼び出しかはリポジトリ全体で1回だけ解決する**（`scripts/i18n-helpers.mjs`）。
- **属性の面の宇宙は読み手に届く属性が書かれる場所すべて**（`scripts/i18n-attr-audit.mjs`。同じタグ走査と同じ判定 `shapeOf()`）:

  | 形 | 例 | どう読むか |
  |---|---|---|
  | ① ディスク上のマークアップ | `index.html` · `admin.html` | タグ走査 |
  | ② 文字列が組み立てるマークアップ | `'<b title="Close">'`／`` `…${x}…` ``／`'<i title="'+…+'">'` | 定数部を1本に畳んでから同じタグ走査（`+` 連結を先に畳む） |
  | ③ 実行時の代入 | `el.title=…`／`el.setAttribute('aria-label',…)` | 値に翻訳呼び出しが届くか（手書きの `lang==='jp'? … :` 梯子は翻訳ではない） |

  この面が見ないもの（翻訳済みの前置きの後ろのフォールバック 2 件と属性バッグ `el(tag,{title:…})` 45 サイト）は当該ファイルの冒頭に名前で書いてある。
- **百分率はすべて `want ∩ have` なので、`want` に無い `have` の行は落ちる**——その向きは `scripts/i18n-dead-key-audit.mjs`（`check:i18n` の中で 0 を要求する）が見る。この検査だけは
  `shapeOf()` の宇宙を使わない（解決漏れが生きている行を消すことになる。`js/map-readout.js` の `const L=(...a)=>{ if(!_L) _L=window.IntMapLang.pick(…); return _L(...a); }` という遅延ラッパの
  10 サイトは全計器から見えない）。遅延ラッパは被覆の側でも危ない（その英語原文は `want` に入らず fr / ko / zh は英語に落ちる。実例は `js/auth-ui.js` の `_authL`）⇒ 読み手に見える文字列は
  計器が証明できる綴り（`window.IntMapLang.t(HOST.lang, …)` など）で書く（遅延ラッパは factory の規則——`tests/news-module-split-checks.test.mjs` #4——から来ているので消せない）。だから問いを
  「その鍵は出荷される木のどこかに書かれているか」にする（`js/lang-registry.js` は `pick()` の第0引数と `t()` の第1引数を無加工で添字にする。`fn.arr(tuple)` は `pick()` の適用）。
  「書かれている」は綴りと値の両方で見る（コーパスは生テキスト ∪ 出荷ファイルの全 string literal の値）。書かれずに到達しうる唯一の経路は組み立て（定数と変数を連結する call site
  107 を生成しうる文字列のパターンに変え、当たる鍵は保留として報告する）。staging 側（`scripts/i18n-apply-inline.mjs` が `scripts/i18n/r*.json` を合流し `scripts/i18n-append-inline.mjs` が
  locale に無い鍵を挿入する）にも同じ問いを掛ける。閉じ方は `node scripts/i18n-dead-key-codemod.mjs --write`（判定は監査の `classifier()` を import）。英語を書き換える変更は同じコミットで
  inline 表の旧行を消す。検査は AST で書く。
- **計器の視野の外の名前のついた穴**: 「隣接データスロットとして持たれた翻訳の組」が **143 件**（`js/reference-data.js` 143）。`scripts/i18n-audit.mjs` の `PAIR_CEILING` が増えたら落とし、減った
  のに天井が残っていても落とす（一覧は `node scripts/i18n-pair-audit.mjs --list`、直し方は `pickArgs()`）。無害である理由は 1 つ——`js/companies-ui.js` の `renderDashboard()` の本体の第1文が
  無条件に `renderCompanies()` を返すので、143 枚を描く本体も `dashFeatures` 代入も画面に出ない——で、ゲートはその委譲が今も本体の第1文であることを AST で確かめる（143 件が
  `js/reference-data.js` 以外へ移った場合も落ちる）。

**現在の状態: 9言語すべてが、上の全ての面で 100%。**

**OPEN GAP（百分率には数えず、印字してラチェットするもの）**:

- **隣り合ったデータ枠に置かれた翻訳** 143件（`js/reference-data.js` 143）。言語で添字されていないので、どの計器も 0 と数える形。`pickArgs()` へ変換していく。一覧は
  `node scripts/i18n-pair-audit.mjs --list`。世界の出来事アーカイブの手書きの表は日付つき出来事の索引（`js/time-index.js`）に置き換えて廃止した（名前と説明は Wikidata が書く全言語で運ぶ）。

**免除**（固有名詞のレコードと照合語リストで、アプリが書いた文ではないもの）1,379件。照合語リストは `js/newsgeo.js` の首都名・媒体名と `js/atlas-annotate.js` の単位の綴り
（`id|綴り;綴り;…`）。`@i18n-entity-data` で宣言し、座標・ISO コード・ティッカー・ドメインを持つ行であることを検証するので、免除の印で UI 散文を黙らせることはできない。

### 10.2 言語を1つ増やすコスト＝ファイル1本

`js/locales/ui.<code>.js` を置くだけでよい（登録簿の行も `src/main.js` の import 行もピッカーの項目も要らない）。

- `src/locale-boot.js` が `import.meta.glob('../js/locales/ui.*.js')`（lazy）でディレクトリを読む＝言語の集合はファイルの集合（`src/` に置くのは `scripts/static-checks.mjs` が `js/` を
  プレーンなスクリプトとして解析するため）。
- `js/lang-registry.js` の `derive(code)` が label（`Intl.DisplayNames`＝その言語自身の名前）・BCP-47 タグ・2文字 pill を code だけから作る。literal 行として残るのはファイル名では運べない事実を
  持つ言語だけ——最初の5言語（`L(…)` の引数順）と中文2行（スクリプト別 alias・1文字 pill・`normalise` の解決順。別名は字体タグ zh-Hant / zh-TW / zh-HK / zh-MO だけ）。
- 読み物2ページ（`sources.html` / `science.html`）はバンドラが無いので、`scripts/i18n-langs.mjs` が `js/locales/_langs.js`（`window.IntMapLangCodes` と `window.IntMapLangBeta`）を生成し
  `prebuild` で毎ビルド更新する（`tests/hazard-other-ui-chrome-checks.test.mjs`）。
- **(beta) 表記は測って付く**（inline テーブルの被覆率が 98% 未満なら beta。現在 `IntMapLangBeta` は空。明示 label の中文2行は常に優先）。
- 新言語の雛形は `node scripts/i18n-report.mjs --template <code>`、追加は `node scripts/i18n-new-language.mjs`。

### 10.3 読み込みと組み立て

- **locale は遅延読み込み。** eager なのは英語（全テーブルが `Object.create` で繋がるプロトタイプ）だけで、利用者の言語は独立チャンクとして取得し `js/app-body.js` の起動バリア
  （`then(go,go)`）で待つ。切り替えたときに取りに行くのはその言語のチャンクだけ（en の読者は `ui.en` のみ＝main の中・約 19 kB、jp は `ui.jp` 21,846 B、`inline` 表を持つ 4 言語は各 42〜45 万 B）。
- **起動時に英語以外の locale を読んだら `check:perf` が赤**（`scripts/perf-budget.mjs` が eager チャンクのモジュールから `js/locales/ui.<code>.js` を数え、フォールバック
  `IntMapLang.FALLBACK` 以外が 1 つでもあれば、またはフォールバックが無ければ落とす）。
- **locale の取得が失敗したら理由を読者に言う**（`IntMapLang.ensure()` は理由を `failure(code)` に残し、`onFail` の聞き手に 1 回知らせ、失敗をキャッシュしない。聞き手は `js/lang-switch.js`
  の 1 つで、`js/notify.js` の live region でその言語の言葉〔en / jp〕と理由を述べる。切替は適用する）。
- `js/i18n.js` はテーブルを差し替えず in-place マージする。表は英語にプロトタイプで鎖を繋ぐので欠けたキーはキー単位で英語に落ち、`js/i18n-late.js` が足すキーも全言語に届く。
  `i18n.ja === i18n.jp`。
- **言語変更は「待てるイベント」**（`js/lang-switch.js`。文字列が届く前に描き直さない）。
- **`ui.zh-hans.js` と `pages.zh-hans.js` は手で書かない**（`scripts/zh-hans.mjs` の生成物。繁体を直してから再生成する）。字体は OpenCC `tw→cn`、語彙は同スクリプトの `WORDS` 表
  （計算機・UI ／ 地図・科学 ／ 固有名詞 ／ 地名 ／ 社会・共同体）。字体が両方で同じ語は表に書かない限り台湾語のまま届く（`社群`→`社区`・`紐西蘭`→`新西蘭`・`金鑰`→`密鑰`・
  `義大利`→`意大利`）。網羅性の門は `tests/weather-models-checks.test.mjs ①`。左辺に置くのは文書の中で語義が1つしかない語だけ（`擷取`・`向量` は置かない）。OpenCC `twp` を pipeline の中で
  使わない（差分の一覧としてだけ）。
- **inline への追記は `scripts/i18n-append-inline.mjs`**（既存キーには触らない）。
- **地名ラベルも全言語対応**（`applyLabelLang` の `name:<lang>`。`Intl.DisplayNames` が生のまま返すコードを確認してから使う）。
- **地名ラベルの言語は設定「Place-name labels」（`imLabelLang`）の 4 択**——`ui`／`local`／`en`／**`ui+local`（設定言語の下に現地語を併記。既定）**。`ui+local` は `ui` と同じ式の下に瓦の `name` を
  1 行足したもの（同じ値に解決する瓦は 1 行）。`concat` + 改行であって `format` ではない（`format` は `js/cesium-style.js` が UNSUPPORTED と名指す演算子で、Cesium エンジン
  `js/cesium-layers.js` も同じ layout を読む）。書体は `placeFont()` のスタックのまま。検査は `tests/shell-map-labels-checks.test.mjs`（MapLibre 自身の評価器で測る）。
- **`name:ja` が在ることと、それが日本語名であることは別**（上流には意味を漢字に訳した値がある——`Barış`→`平和`、`Yüreğir`→`良癖`）。`js/place-labels.js` は記録した組（`name` と
  `name:ja` の両方が一致したときだけ）を拒み既存の鍵の並びに落とす（訂正はしない。上流が直せば失効する）。表の正本は `scripts/build-osm-ja-rejects.mjs`。鍵の並びを読む側
  （`js/map-ui.js` のポップアップ・`js/atlas-view-subject.js` の chip）は `window.IntMapOsmName(properties, keys)` に訊く。
- **出典の行が添えるライセンスは、表示言語で「既に述べたか」を判定し、表示言語で述べる**（`js/reference-data.js` の `useText`。行が `lic` を持ち説明文と名前がまだ述べていないときだけ末尾に
  ` — <ライセンス>`）。同一性は値で、言語ごとの名前は `js/locales/pages.<code>.js` の `licenceName[値]`。表示言語の名前・英語名・値のどれかが既に現れていれば「述べた」（末尾の版番号を除き
  名前の境界で止める——`CC BY` は `CC BY-NC-SA` の中では一致しない）。`licenceName` に載るのは出版者が名づけていない値だけ（`Public domain` など。`CC BY 4.0`・`ODbL 1.0`・
  `政府標準利用規約 2.0` は綴りのまま）。IntMap の言葉なので en + jp で書き、残り 7 言語では説明文が自国語で述べている 4 行に英語の末尾が重なる（凍結中の既知の穴）。検査は
  `tests/licence-stated-once-checks.test.mjs`。

### 10.4 言語が変わった瞬間に、画面のどこが塗り直されるか

§10.1 が測るのは訳が在るかで、その訳がいつ画面に届くかではない。

| 形 | 誰が塗るか | 言語が変わったとき |
|---|---|---|
| markup が `data-i18n` / `-ph` / `-title` / `-aria` / `-alt` を持つ | `updateI18n()`（`js/app-body.js`）が属性を頼りに一括で貼り直す | 自動 |
| JS が `textContent` / `innerHTML` / `<option>` / `aria-label` に書く | それを書いた関数だけ | **その関数が `intmap-lang` を聞いていなければ、塗り直されない** |

`updateI18n()` は最後に `window.dispatchEvent(new Event('intmap-lang'))` を投げ、2つ目の形はこれを聞く（例外は無い）。

- **「開いたときに塗る」は切替の代わりにならない**（言語の `<select>` は設定モーダルの中にあり、閉じずに開いたままにできる面——レイヤー欄・凡例・常設パネル——も同じ）。
- **塗り直しは「貼り替え」であって「再描画」ではないことがある**（確定前の状態を持つコントロール——衛星画像の API キー欄・時刻帯の絞り込みの文字——は文字だけを書き替える経路
  `IntMapNewsSources.relabel()`・`satRelabelKeyInputs()` を持ち、`intmap-lang` はそちらを呼ぶ）。
- **`aria-label` は最初に現れた言語で固まりやすい**（Atlas の命名掃引 `js/atlas-controls.js` `_uiNameSweep()` は `:not([aria-label])` にだけ名前を付け、書いた名前に `data-imname` の印を付け、
  言語が変わるとその印のものだけを取り返して掃き直す）。

ゲートは2本: `tests/news-settings-language-checks.test.mjs`（塗る側が全部聞いているかを綴りと実行の両方で）と `tests/r466.spec.js`（本物のブラウザで「設定を開き直しても1文字も変わらない
こと」）。
