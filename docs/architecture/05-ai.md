## 5. AI APIの使い方と鍵管理 (AI usage & key policy)

### 人格と system prompt

- **Atlas の人格は正式仕様であり、正本は `js/atlas-persona.js` 1本だけ。** 名前・**製品名の表記**（`IntMap` は文字列そのものが名前で、訳語・音写・展開形を持たない——どの言語の
  文章の中でもラテン文字で書く）・立場・名前の由来・性格・対人姿勢（敬語は常に自然な敬語）・事実優先・意見の出し方・感情表現・自己設定の扱い・内部指示の非開示は、そのファイルの
  文章そのものが仕様で、ここに書き写さない。
- **23 本すべての system prompt が `personaPrompt('<その呼び出しの役割>')` で始まり、各呼び出し側はタスク規則しか足さない**（`atlas-console` 8・`atlas-cap-research` 3・`news-ingest` 3・
  `app-body` 2・`atlas-geo-resolve` 2・`atlas-gloss` 1・`atlas-delegate` 1・`atlas-jobs` 1・`news-ui` 1・`refresh-news` 1）。本数と内訳の正本は `tests/r285-checks.test.mjs` の `EXPECTED_CALLS`（prompt を足したらまずあの
  表に足す）。モードは 2 つ——人の読む文章になる経路は全文、機械可読な JSON だけの経路（地域の輪郭・行政単位の解決・ニュースの地点解析・記事翻訳・地名検証）は
  `{mode:'internal'}` で身元・製品名の表記・事実規律・非開示だけ（記事翻訳は internal で走る）。サーバー側の2ファイル（`refresh-news`・`news-ingest`）は
  `supabase/functions/_shared/atlas-persona.js` の生成された写しを読む（`node scripts/sync-atlas-persona.mjs`・`npm run check:static` が差分を落とす）。

### 送信の見本（プリセット）

- **プリセット送信文の主語は「視界」であって「中心画素が落ちる国」ではない**（`js/atlas-examples.js` ＋ 測定は `js/atlas-view-subject.js`）。プールは 3 つで、**`V`（視界）が `P`（国）／
  `W`（世界）より必ず強い**（重みは 12–17 対 上限 10）。`V` の判定は視界そのものから測る: ① 視界に入る国（箱の 6×6 標本を国ポリゴンに当てる。`countryStats` の `bboxAll`——全領土の
  union——は ray-cast の足切りにだけ使う。2 か国なら国境、3 か国以上なら三国境）、② 陸と海の割合（内陸／海岸／外洋）、③ 名前のある水域（`window.SEA_LABELS` 120 行。うち 33 行は淡水
  なので海洋・海・湾・湖で問いを分ける。海峡は表に無いので「2 か国が水を挟んで向き合っている」という形で拾う）、④ タイルが名指す地名と山（`querySourceFeatures`。「集落が1つも
  無い」はタイルが答えたときだけ言う）、⑤ 戦略拠点 143 件の種別（`IntMapRefData.dashCards`。名前は差し込まず種別だけ）、⑥ 視界の縮尺（km）、⑦ 視界の中にアプリが実際に持って
  いるものの件数（`contentInView`——`IntMapLayers.featuresIn(id, box)` と海底ケーブルの陸揚げ点 `src-subcables-lp` を数える。取得はしない。「そのレイヤーの箱が入っている」は根拠に
  ならない。`null`＝数えられない、`0`＝ここには無い。数を刷るのは静的な目録——陸揚げ点・火山——だけで、動くもの——航空機・船舶・衛星・ニュース点——は在るかどうかだけ。単数形は
  別候補。全球の視界では数を主張しない）。
- **国のプール `P` の各候補は述語を持ち、成り立つものだけが候補になる**——① `countryStats` の中での順位（閾値ではなく順位）、② 利用者が今オンにしているレイヤー（数えられる層は `V` の
  ⑦に主語を譲る）、③ Chronos の位置、④ 国自身の外接矩形（`bbox`。±180 をまたぐ環は経度の主張を出さない。北極圏の主張は視界自身の北端も見る）、⑤ 言語の数と通貨、⑥ 2つの事実の組。
  選択は重み→鍵の順で決定的。
- **再描画の鍵は視界を名指す**（`exKey` → `VIEW.viewKey`。座標は視界自身の幅の 1/4000 に量子化）。
- **時計が過去を指し、地図が今日を描いていない間は、今日の世界のプール（`V`・`P`・`W`）を出さない。** 「地図が今日を描いているか」は描いている記録に訊く——
  `IntMapTimeBorders.modernAt(when, live)`（`js/compare.js` も同じ問いを自分の時計に訊く）。今日でなければ時代のプール `E`: 描かれている時代の国境（`currentFC()`）を同じ 6×6 標本で
  測ったもの（`featuresInView`）に門を置く——中心の政体・視界に入る政体の数・今日と名前が違うか消えた政体があるか（`_same:0`）・国境がこの形になった日（`changeAt`。日単位の記録の
  ときだけ）・視界の大半が海か。名前は時代ラベルの層が描く名前（`_same` なら `_modName`、それ以外は `_locName`→`NAME`）。年は `IntMapHistScale.yearText`。集まりが届く前は年だけで
  成り立つ 4 文（`tail:1`）だけ。地図をクリックしたときの予約枠は「この辺りでは{年}に何が起きていた？」。
- **未ログインの読者には、押す前に言う。** 行の先頭に「Atlas には無料アカウントが要る・1 日 N 回」（N は `supabase/functions/_shared/plans.js` の無料プランの `aiTurnsPerDay` を実行時に
  読む）。例文を押すと送らず、その問いを Atlas がどう扱うかのカード（地図の状態を読む → 道具で操作する → 結果を読んでから答えを書く、「図解（実際の回答の記録ではありません）」の
  静止の図、無料枠、「ログインしてこの質問をする」——問いを入力欄に置いてログイン画面を開く）。カードは回答を見せない（`scripts/atlas-eval/cassettes/` は全部 `kind:"scripted"`）。
  ログイン画面が閉じた時点で行を引き直す（`exKey` がログイン状態を持つ）。
- **地図をクリックしたときの 3 文も同じプールから選ぶ**（`pointExamples`。`askHere` が呼ぶ。選ぶ箱はクリックされた座標の周り）。3 枠のうち 1 枠は必ず汎用の 3 文に残す。常に真の
  6 文（首都・地域・最新・近隣比較・1990年以降・天気）は落穂拾い（`tail:1`）。候補の文はすべて第1引数がリテラルの `L()`（`scripts/i18n-report.mjs` はそれ以外を捨てる）。`{place}` は
  CLDR の国名なので ru / de / fr は名前を先頭に置く同格の形。

### 進行の見せ方

- **回答の置き場は設定で選ぶ**（設定 ▸ Atlas の回答: `tab`＝Atlas タブ〈既定〉／`float`＝地図の上に浮かせる。`intmap_settings.atlasDisplay`・Atlas からは `settings.atlasDisplay`）。`float` では `js/atlas-float.js` が**同じ `#atlas-panel`**（写しではない。会話・入力・能力は同じ）を地図左の透過したガラスのカードへ運ぶ。新しい吹き出しはふわっと現れ、しばらく触れないと透け、指を置くと戻る。カードの外は地図の操作を妨げない。Atlas タブを開けばパネルはタブへ戻り、離れれば地図へ戻る。`js/atlas-console.js` の open／close／toggle は先に `floatRoute()` に訊く。携帯（768px 以下）・ワークスペース・埋め込みではタブのまま（シートが地図を覆うので 2 枚目のカードを置く場所が無い）。
- **答えは道具の結果を集めたあと 1 度編集してから出す**（`js/atlas-turn-results.js` の `keep()` と `present()`）。同じ主題（`meta.subject`＝世界銀行の系列か表の欄）と同じ面（上位・下位・地図）の結果は後のもの（両方が年を言えば新しい年）が前のものを置き換え、本文が既に述べた順位表と地図の操作報告は 1 行に畳む（開けば全体が見え、出典は一覧に残る）。数値の結果は値と年と出典を `meta.provenance` に持ち、本文・表・地図・出典欄は同じデータから作られる。国の数え上げと順位は `isRankableCountry`（`js/atlas-metrics.js`）を通ったものだけ（世界銀行の地域・所得群の集計コードは入らない）。

- **回答中に何をしているかは、消えない一覧で見せる**（`js/atlas-progress.js`）。返答の泡の兄弟として `.atl-trace` を置き、実行器（`js/atlas-executor.js` の `on()`）の 10 段の
  ライフサイクルを購読して 1 操作 1 行を足す（済んだ行は残り、走っている行だけが輪を回す）。plan の段は `js/atlas-agent.js` の `onStep` から。行の言葉は category（レジストリ 4 列目）
  から、引数は `js/atlas-schemas.js` の引数 schema で宣言順で最初の enum を持たない文字列引数から（enum の引数は設定。名前を持たない操作の欄は空）。回答が着いたら見出しは終わり方と
  歩数（「回答しました · 3 ステップ」）になり、所要は残り、開き直せる。
- **進行を述べる場所はこの一覧 1 つだけ**（計画もその中）。一覧が見えている間は地図に何も出さず、見えないとき（サイドバーを閉じた・シートを下げた・ウィンドウを最小化した・流れて
  画面外・別の面が上）だけ地図に小さな表示を 1 つ出す（`js/atlas-live.js`。「Atlas · いまの語 · 手順 i/N」。押すと Atlas を開き一覧を見える位置へ送る。ターンが終わると約 2.6 秒で
  消える。デスクトップは地図の下中央、携帯 `IntMapDevice.COMPACT` は上端）。語は `liveWord()` を読むだけ。見えているかは実測する（矩形がビューポートにあり、祖先に透明・非表示が
  無く、見出しの中心と見えている部分の中心で `elementsFromPoint` が一覧自身を返す。ターンの間と直後だけ `everyTick` で 0.4 秒ごと）。
- **上限に達して終わったターンはそう名乗る**（`js/atlas-console.js` の `_cutNote`。Atlas が終わったと決めたのは `answered` だけで、`step_budget` / `call_budget` / `time_budget` /
  `repeated_calls` / `malformed_limit` は上限——`js/atlas-agent.js` の `CUT_STOPS` が名指す）。上限で切られたターンも、道具を渡さない最後の 1 呼び出しが transcript から答えを書き
  答えきれていない部分を名指す（`text` の有無によらない）。その事実はモデルには届かず（強制 final の指示は「上の結果が実際に起きたことだ、いま答えよ」だけ）、IntMap 自身が 1 行で
  述べる。`answered` では出さない。注記は泡の兄弟に置く。上限そのものは動かしていない（`CONSTITUTION.md` §5）。
- **いま何をしているかの 1 語**（Thinking / Reading the image / Verifying / Writing the answer、走っている操作の言葉）は一覧の見出しに出る（見出しがその 1 語で、開くと詳細な行）。語は
  ラベル自身を掃くシマー（`.atl-stage` の `background-clip:text` と透明な text-fill、帯は 2 秒、色はテーマごとの `--atl-shimmer-band`、`prefers-reduced-motion` では止めて text-fill を
  currentColor に戻す）。語を運ぶ span は使い回す。同じ行の反対の端にターンの合計時間（行が測るのは操作で、ターンの大半はその間の待ち）。`.atl-stage` は印でもある（取り消し走査と
  `markCancelled` が泡の中のこの綴りを見るので、中身が空の span を泡に残す）。`_atlCompose` が泡の `innerHTML` を書き換えるたびに `js/atlas-progress.js` の `live()` が印を戻し、
  `done()` がターンの終わりに外す。
- **Atlas の 1 手は考えているあいだから見える**（`js/atlas-live.js`。モデル呼び出しはストリームで届く）——① 推論の要約の最新の見出しを考え中の行の詳細へ、② 関数の名前が決まった
  瞬間に「次: …」を同じ行へ（行を開くのは実行器の `started` だけ）、③ 返答の JSON を届いた順に読み、先に生成される `turn` が `continuing` なら文を作業一覧の「途中の一言」行へ、そう
  でなければ回答の泡に下書きとして流す（キャレット付き）。下書きは答えではない（ループの答えが届くと `_atlCompose` が `__atlSay` で置き換える。再要求は `reset` で取り下げ、停止した
  ターンは下書きを未完と明示して残し、失敗したターンは残さない）。ループはストリームを知らない。体感の待ち時間は `window.IntMapAtlasDebug.latency()` が `firstVisible`・
  `firstThought`・`firstAnswer`・`firstCall`・`firstOp`・`firstDraw`（実行器の終端イベントの `produced`）・`answer`・`end` を ms で返す。
- **Atlas の計画は Atlas が宣言し、その状態は IntMap が観測する**（`js/atlas-plan.js`）。会話に 1 つの台帳（`makeAtlasPlan`）を `js/atlas-console.js` が持ち、`runTurn` に `opts.plan`
  として渡したときだけループは `plan` 道具を申告する（基本の道具の直後・昇格した道具より前の固定の位置）。`plan` の呼び出しは返答の中の呼び出し順にその場で台帳へ適用され（`goal`・
  `steps`・`current`）、同じ返答の後ろの呼び出しはその手順に属する。`plan` は footprint `pure` で実行器には届かない。手順の状態は観測——その手順で能力に届いた呼び出しの判定から
  導き、能力ごとに最後の試みが残り、手順は最も悪いもの（実行中 → 失敗 → 停止 → 入力待ち → 一部のみ → 観測できず → 完了）。呼び出しが無ければ「実行中」「操作なし」「未着手」。
  `unobserved` は決して完了にならない。手順に属するのはそのターンで `current` を述べたあとだけ。`plan` の結果が台帳の写しを返し、`_agentInput` が毎手の tail に `promptBlock()` を
  載せる。計画は最新のターンの作業一覧（`.atl-trace-plan`）の見出しの下に立ち（目標と「完了数/手順数」は畳んでも残る）、手順の行は一覧の行と同じ印を付ける。手順が描いたものは
  呼び出しの開始と判定の時点の `render.drawn` と `IntMapObjects` の指紋の差で見つけ、押すとその面・オブジェクト・カメラへ移る。`window.IntMapAtlasDebug.plan()` が同じ写しを返す。
  上限（`maxSteps`・`TURN_MAX_CALLS`）は読みも動かしもしない。

### 鍵・枠・台帳

- **地理空間分析の計画は `plan` の `geo` に構造で持つ**（`js/atlas-geoplan.js`）。対象地域（名前と bounds）・時点・必要データ（`source.kind` = layer/dataset/stac/ogc/overture/upload/none と `ref`・`completeness` = all/sample/any・解像度）・演算・実行環境（browser-gis/python/server/job）・成果物を Atlas が書き、後の呼び出しは変えた部分だけを述べる。IntMap が返すのは ⑴ 書かれていない項目（`gaps`。既定値で埋めない）、⑵ `geo.check:true` のとき `preflight` の観測——必要データごとに IntMap のレイヤー（`IntMapGis.atlas.describe`）と STAC/OGC カタログ（`remote` の `discover`）へ問い、`available`/`partial`/`unavailable`/`unknown` を分ける（答えなかったカタログは `unknown` であって `unavailable` ではない・カタログは全域被覆を証明できないので `completeness:"all"` は `unproven`・capability の無い環境 server/job は無いと述べる）。結果は `runnable` true/false/null としてモデルへ戻り、`promptBlock()` が以後の手に載せる。何も拒否せず、手数にも触れない。既存の plan・Capability 登録簿を再利用し、実行は従来どおり `gis`/`gisRemote`/`compute.run`。
- **鍵はサーバー（Edge Function）だけが持つ。** ブラウザは AI プロバイダに直接アクセスしない。モデル選択の UI も無い（利用者はモデルを選ばない）。
- **`ai-proxy`＝アカウント制AI。** `verify_jwt` に加えて関数内でもユーザーを検証し（未ログインは 401）、プラン別の1日上限を `consume_ai_turn` で原子的に消費する。上限は free 10 /
  plus 50 / pro 200 / unlimited 実質無制限。
- **消費の単位は「1 user turn」。** クライアントは `x-intmap-turn` ヘッダにターン鍵を載せ、その鍵の最初の 1 本だけが消費する。鍵は信用されない（行の主キーが `(user_id, turn_key)`、
  1 つの鍵が運べる回数 `TURN_MAX_CALLS` と寿命 `TURN_TTL_S` は Edge Function 側の定数）。上限超過は 429 `{error:"turn_calls"}`（1日上限の 429 `{error:"limit"}` とは別の文言）。
  プロバイダ失敗の払い戻しは `refund_ai_turn` が charge とターンの両方を解放する。決定論的な操作（`IntMapOS.execute()` だけで終わる依頼）は AI 枠を使わない。
- **プランで変わる値は 1 つの表**（`supabase/functions/_shared/plans.js` の `PLANS`——1 日の質問数 `aiTurnsPerDay`・用語解説数 `aiGlossPerDay`・購入できるか `offered`）。
  `ai-ledger.js` の `PLAN_LIMITS` と `ai-proxy` の `GLOSS_PLAN_LIMITS` はその列で、支援パネル（`js/supporter.js`）も同じ表を import する。import できないページの `AI_FREE_DAILY` は
  `tests/supporter-funnel-checks.test.mjs` が突き合わせる。全員が `free` で、購入できるプランは無い。
- **利用者の代わりに AI を呼ぶ経路は全部 1 つの台帳を通る**（`supabase/functions/_shared/ai-ledger.js`——`PLAN_LIMITS`・アカウントの解決 `profiles.plan` と `DEV_USER_IDS`・4 つの扉
  `consume_ai_turn` / `refund_ai_turn` / `settle_ai_turn` / `record_ai_usage`）。定期実行（cron）は消費しない。
- **枠のカウンタ（`ai_usage.count`・`ai_gloss_usage.count`）は負にならない——列の CHECK として**（負の値は上限を外し、表の所有者は grant に縛られない）。返金は課金した 1 回ぶんを
  超えず、課金した日の行へ戻る（`refund_ai_turn` がターン行を 1 文で消し、その行の `usage_date` を使う）。回数を増やすのは `profiles.plan` か `DEV_USER_IDS`。ターン鍵の無い依頼の返金
  （`refund_ai_usage`）だけは今日の行へ戻る（0 未満にはならない）。
- **費用も同じ台帳に載る。** `_shared/ai-usage.js` の `normalizeUsage` が 3 社共通の形 `{input, cached_read, cache_write, output}`（`input` はキャッシュ読み・書きを含まない）にし、1 リクエスト
  で読んだ全応答を足して `record_ai_usage` が `ai_usage`（アカウント×日）と生きている `ai_turns` 行に加える（`count` には触れない。開発者の呼び出しも記録される）。使用量を述べなかった
  応答は `unmetered_calls`。定期実行の費用は監視の所有者の行に載る。
- **用語グロスは「別の枠」で動く**（`public.ai_gloss_usage`。上限は free 60 / plus 300 / pro 1,000。両方向に独立）。どちらの枠で払うかは本文を読む前に `x-intmap-lane: gloss` で宣言し、
  本文を読んだ後に `task === "gloss"` と照合する（食い違えば払い戻して 400 `{error:"bad_lane"}`）。安いレーンは画像も web 検索も受け付けず prompt 上限は 8,000 文字。429 は
  `{error:"gloss_limit"}`。応答は `glossUsed`/`glossLimit` を名乗り、専用の写し（`aiGlossLeft()`）だけが読む（`used`/`limit` は返さない）。
- **クライアントが持っているのはサーバーの行の写し**（`js/ai-core.js` が `public.ai_usage` の当日行を写し、サーバーが送った数以外を書かない）。`ai-proxy` の 429 は 2 か所しか無く、どちらも
  `used` を載せて名乗る（`limit` / `turn_calls`）——名乗りの無い 429 はプラットフォーム側のレート制限なので写しを触らず「混雑しています（利用回数上限ではありません）」を出し、本文を
  `window._aiLast429` に残す。写しが「残り0」と言ったときは行を読み直す（`aiQuotaBlocked()`。`askAI` / `askAIEnvelope` / Atlas のターンが通る。同期の `aiGate()` は 1 回断ってから背景で
  読み直す）。規則の綴りは `aiOverQuota()` の 1 か所。

### 入力の上限とストリーム

- **入力の上限は本文を読む前に効かせる**: prompt は 24,000 文字、**system は 160,000 文字**（アプリ自身が組む操作カタログなので別枠）、画像は最大4枚・合計 12 MB。鍵・prompt・JWT は
  ログに出さない。Atlas のターンは prompt を使わず（protocol 2: `input` の item と `tools` の関数。§2.1）、上限は item ごと（`MAX_ITEM_CHARS` 96,000）と全体（`MAX_INPUT_CHARS` 480,000）
  ——クライアントの予算の 2 倍の柵。超えたら古い会話から落とし、`meta.inputTrimmed` で述べる。1 本の文字列の要求も受け、`meta.protocol` がどちらで答えたかを言う。
- **Atlas のターンはストリームで答えられる。** `stream: true`（protocol 2 の `atlas_turn` だけが送る）を受けると、`ai-proxy` は提供元にもストリームで頼み（OpenAI `stream`・Anthropic
  `stream`・Gemini `streamGenerateContent?alt=sse`）、`text/event-stream` で `open` → プレビュー（`think` / `text` / `call` / `search` / `reset`）→ `done` 1 つを返す。`done` の
  `{status, body}` はストリームなしの応答そのもので、ページ（`js/ai-core.js` の `aiReadStream`）はそれを Response に戻して従来の読み手に渡す。プロバイダの本文は 2 回読まれる
  （`supabase/functions/_shared/ai-stream.js`。届く間はプレビュー、届き切ったら非ストリームの本文へ畳み戻して既存の解析器へ）。`relay-guard.js` の `fetchBounded` は `onChunk` に渡すだけ。
  ストリームの中で提供元が述べた失敗（OpenAI `response.failed`・Anthropic `error`・Gemini の error chunk）は `classifyGemini` が分類し、終端の無いまま切れたストリームは
  `provider_unavailable`。台帳の順は同じ（消費は本文を読む前、精算は `done` の前、失敗は払い戻し）。読者が接続を閉じても提供元の呼び出しは最後まで走り記録と精算は行われる
  （`EdgeRuntime.waitUntil`）。推論の要約（OpenAI `reasoning.summary:"auto"`、Gemini `includeThoughts`）はストリームのときだけ頼み、400 の梯子の最初の段がそれだけを外す（isolate が
  覚える）。無言の間は 15 秒ごとに SSE のコメントで接続を保つ。
- **ストリームが `done` の前に切れたら、頼み直しは「再受信」である。** ページが要求ごとに再受信の鍵（`replayKey`）を付け、`ai-proxy` はその手の `{status, body}` を `done` の前に
  `public.ai_turn_answers`（鍵は (アカウント, ターン鍵, 再受信の鍵)）へ置く。切れたらページは同じターン鍵・同じ鍵を `x-intmap-replay` に載せて 1 回だけストリームなしで頼み直し、
  サーバーは ① 答えが置いてあればそれを返す（提供元を呼ばず、`consume_ai_turn` より前なので課金も `TURN_MAX_CALLS` も使わない。`charged:false`・`meta.replay {kind:"replayed"}`）
  ② 最初の要求がまだ走っていれば完了を待つ（走っている要求は SSE の心拍 `HEARTBEAT_MS` ごとにリースを更新し、リースは心拍 2 回分。死んだ要求は `abandoned`）③ 観測された失敗か
  `abandoned` のあとだけもう一度走らせる（`meta.replay {kind:"rerun", after, attempt}`。行ロック 1 つが走る 1 本を決める）。封筒の `streamReplay` はサーバーが述べた種類を運び、述べ
  なければ `unreported`。置いた答えは `TURN_TTL_S` で失効し、次の claim と 15 分ごとの pg_cron `ai-turn-answers-sweep` が消す（[`docs/DATABASE.md`](../DATABASE.md)）。台帳が答えなければ
  `meta.replay {kind:"unheld"}`。読者が押した停止は頼み直さない。

  （`supabase/functions/_shared/atlas-grade-schema.js` の `graderProviderFor`。開発者のモデル指定は効かない）。別 provider が無ければ 503 `no_independent_grader` で払い戻す。形
  （`ATLAS_GRADE_SCHEMA`）もサーバ所有。費用は 1 回 1 use・台帳に載る。
- **構造化出力は provider にも届く。** `responseSchema`（サーバ所有の `MAP_REPORT_SCHEMA` / `ANSWER_SCHEMA` / `GLOSS_SCHEMA` / `ATLAS_GRADE_SCHEMA`、クライアントが送る `PLAN_SCHEMA` /

  **`gpt-6.1-terra` → `gpt-6-luna` の順に 1 段ずつ**フォールバックする（403/404 の model_not_found のときだけ。開発者が名指ししたモデルは代替しない）。`meta.modelServed` が実際に答えた

- **モデルを選べるのは開発者アカウントだけ**（`DEV_USER_IDS`）。設定 → AI に provider と model の選択が出て、その口座の全ての AI 呼び出しに効き `user_prefs` で端末をまたぐ。選択肢は
  各プロバイダの目録（OpenAI `/v1/models`・Gemini ListModels の `generateContent` 対応分・Anthropic `/v1/models`）を `op:"models"` で取り寄せたもの（モデル名をリポジトリに書かない）。
  例外は取り下げ 1 つ（現行 `gpt-6-astra`。目録から除かれ、選んでいた口座の選択も次に設定を開いた時点でサーバー既定へ戻る——`js/ai-core.js`。proxy は渡された id をそのまま呼ぶ）。

- **既定モデルの表は 1 本**（`supabase/functions/_shared/ai-provider.js` の `PROVIDER_DEFAULT_MODEL`）。チャットのモデルを呼ぶ 4 本（`ai-proxy`・`news-ingest`・`refresh-news`・`who-don`）が

  プロジェクト全体の 1 日の天井 `<関数名>:global:day`（`public.relay_rate_buckets`・`relay_take`）から 1 単位を取り、DB が答えなければ送らない（fail-closed）② 天井（か受領証）を持たない
  呼び出しと提供元以外のホストを拒む ③ 期限は本文の最後のバイトまで・バイト上限（`fetchBounded`）④ 失敗は状態と長さだけを運ぶ（`providerFail`。提供元のエラー本文を運ばない）。

  `ai-proxy:newcomer:day` から、次に `ai-proxy:global:day` から取る（`_shared/ai-provider.js` の `shareCeiling`）。新規の取り分は全体の 1/3（3,000 のうち 1,000。
  `AI_PROXY_NEWCOMER_PER_DAY`）で、残り 2,000 は新規アカウントが届かない。尽きた新規アカウントは `provider_quota`（`meta.ceiling:"newcomer_day"`・503）と払い戻し。作成日が読めない
  アカウントは新規。誰の上限も下げていない。
- **障害耐性** — 400 はフォールバック階段（tool_choice 解除 → schema → json_object → JSON モード解除 → ツール解除）で降格する。Web 付き呼び出しは長めの期限を持ち、空応答は予算を
  増やして1回再試行する。
- **プロバイダの失敗は分類して 502/503 で返す**（`provider_rate_limit` / `provider_quota` / `provider_malformed` / `provider_empty` / `provider_blocked` / `provider_unavailable`）。
  `ai-proxy` が返す 429 は IntMap 自身の枠専用。上流のエラー本文は返さない（コード語だけ）。
- **Web 検索は本物のときだけそう言う。** `webMode:"required"` は検索を強制し、応答の検索呼び出しの件数から `webUsed` / `webSearches` を返す（クライアントは実際に検索した時だけ
  「ライブWeb検索」と表示する）。Anthropic 経路も同じ値を返す（回数は `server_tool_use`〔名前 `web_search`〕の数と `usage.server_tool_use.web_search_requests` の大きい方、引用は
  `web_search_result_location`）——`js/atlas-agent.js` の `externalContentSeen` が立つ。
  応答 meta の `web` は検索の結末を `{state:'not_run'|'failed'|'empty'|'ok', reason, searches, sources}` で述べ（timeout で検索を外して作り直した場合は `failed`・`timeout`）、
  `status:'complete'|'incomplete'` と `incompleteReason` はプロバイダの途中停止を本文と別に運ぶ。`js/atlas-cap-research.js` の注意書きはこの結末と回答が実際に引いた
  記録の由来から作り、ツール結果（`web`・`finish`・`retrieved`）として Atlas にも届く。
- **失敗の原因を変換しない。** `js/ai-core.js` が投げる Error は `code`・`status`・`retryable`（サーバの値を優先。無ければ 429・5xx・通信断だけ可）・安全な `meta` を持つ。
  再試行不可の 400 を「一時的に利用できない」と書かない。
- **数値の出典義務は宣言された種類から。** 構造化回答の `metric.kind` は `statistic`（`seriesId`・`period`・`unit` が必須）と `stated`（運賃・所要時間・観測日など。`unit` だけ必須）。
  宣言が無ければ statistic として扱う。同じターンで先に取得した Web ページは呼び出し前に証拠台帳へ登録され ID を持つ（`js/atlas-answer-pipeline.js`）。
- **鮮度の窓は「今」に結び付いた期間だけ。** `_analyzeFreshness` は質問中の期間を全部読み、直近・過去・今後・現在から・last・past・〜前 などで今に結ばれたものだけを証拠の窓にする
  （2 つあれば狭い方）。それ以外（移動時間など）は窓にせず、「質問が別のものを測っている期間」としてモデルに渡す。
- **ニュース地点解析AI** — `refresh-news` が同じ鍵・同じ `AI_PROVIDER` 規約でサーバー側実行する（利用者の枠は消費しない）。

### 委譲（delegation）——Atlas が仕事を子に渡し、結果だけを受け取る

Atlas は大きな依頼の**互いに独立な部分**を子のモデル（worker）に渡し、並行して調べさせ、返ってきた結果を自分で統合できる（能力 `research.delegate`）。委譲するか・何件にするか・何を返させるかは Atlas が決める。コードは決めない。

**変わらない部分（基盤 `js/atlas-delegate.js`）と、変わる部分（値として渡すもの）を分けてある。** 前者は 4 つの約束からなる。

| 約束 | 中身 |
|---|---|
| 仕事の契約 | 入力は `{id?, goal, returns?, inputs?:[{from}]}`、結果は `{state, code?, summary, findings[], gaps[], sources[], costUsd, calls, ms}`。`state` は done／partial／failed／refused／unobservable／cancelled の 6 つ。サーバが名指した拒否や誤りは観測された答え（refused・failed）。要求が戻らず、提供元が実行したか分からないものは `unobservable` と述べる（`.agents/rules/one-pass-or-a-reason.md` §5） |
| 実行者 | 契約を守るものなら何でもよい。今あるのは ai-proxy の背後にいるモデル（`makeWorkerExecutor`）だけ。返ってきた形が誤っていれば、何が誤りかを述べて**1 回だけ**直させる |
| 状態は実行者の外 | 追記だけの事象記録に置く。各事象は ID と、種類の付いた関係（`spawned_by`・`uses_output_of`・`same_as`）を持つ。木も DAG も、この記録の見方の 1 つにすぎない。作業場は結果の置き場、実費は記録の `effect.done` から読む。実行権（`task.lease`）も記録に残す |
| 依存はデータ | `inputs` が別の仕事を名指すと、その仕事が終わってから始まり、その結果を受け取る。`run(contracts)` は**一覧を丸ごと読んでから**始めるので、名指す先が一覧の後ろにあってもよい（待つ）。入力が自分に戻る輪は、全員を `input_cycle` で即座に終える（互いを待って止まらない）。一覧に無い名前は `input_unknown` のまま。永続するスケジューラは無く、後から足すなら同じ関係を読む |

同じ契約を 2 度始めると同じ仕事として扱い、`reused` と述べる。拒みもせず、再実行もしない。

**仕事には 2 種類ある（契約の `kind`）。** `worker`（既定）はモデルが調べる仕事。`capability` は、**読み取り専用の能力 1 つを、与えた引数でそのまま実行する**仕事で、モデルを挟まず費用もかからない（`{kind:'capability', capability, args}`）。同じ照会を複数の地点・項目に広げる（5 都市の天気、10 か国の数値）ときに、研究の仕事と並べて使う。どの能力を許すかは基盤ではなく、ページが渡す `classifyCapability` が決める——**能力表そのものから読む**（`risk` が読み取り専用・書き込み先なし・確認不要・`research.delegate` 自身でない、のときだけ `read`）。`read` でないものは `capability_not_read_only`、存在しないものは `capability_unknown` で**拒否**し（観測された答えで、実行しない）、結果は `delegated[].data` に能力自身の答え（`meta`）を運ぶ。実行は Atlas 自身の呼び出しと同じカーネルの経路（`source:'atlas-worker'`、確認を求めうる呼び出しにはならない）を通る。

**子が自分で呼び、自分で探す。** worker の契約に `tools`（親が許可する能力 id）があると、子は答えの代わりに `{"call":{"capability","args"}}` を返して、許可された読み取り能力を自分で呼び、結果を次の要求で読んでまた呼べる（同じカーネルの経路。各要求が子の 1 回で、最後の 1 回は必ず答えに使う）。`tools` に `find_capability` を入れると、子は `{"call":{"capability":"find_capability","args":{"query":…}}}` で**能力表を語で引ける**。検索は Atlas 自身の `find_capability` と同じもの（ページの `findCapabilities`＝`TOOLS.find`）で、見つかったもののうち `classifyCapability` が `read` と言うものだけが、次の要求からその子の許可に加わる。それ以外（地図や表示を変える・保存や送信をする・`research.delegate` 自身）は、走らせずに `capability_not_read_only` の理由つきで子に返す。直接呼んでも同じ理由で拒む。許可された能力の引数は、Atlas の `run_capability` が検査に使うのと同じ schema（`js/atlas-schemas.js`、`describeCapability`）で子に示す。`tools` の無い契約は、Web 検索で調べるだけの従来の worker のまま。

**上に載るもの（`js/atlas-orchestrate.js`）。** 実行者は種類ごとの経路を選ぶ**ルータ**で、その種類の経路を持たない場では `kind_unsupported` で拒否する。`integrate(results)` は複数の結果が**合わせて何を述べるか**を出す——所見と出典の重複除去（誰が見つけたか）、複数の子が扱った地点とその数値が食い違うか、誰も確かめられなかったこと、戻らなかった仕事とその状態、費用と所要時間。判断はせず、Atlas が読んで決める。道具結果には `integrated`（`coverage`・`duplicateFindings`・`placeOverlaps`・出典と引用した子・`gaps`・`unreturned`・`cost`）が `delegated` と並んで載る。`delegated` が運ぶ所見や出典の配列は繰り返さない。カードには、複数の子が見つけた所見の件数、数値が食い違う地点、戻らなかった仕事（`unobservable` は `failed` と別の語）、費用を 1 行ずつ出す。

**構造化事実の突き合わせ（`js/atlas-fact-merge.js`・`mergeFacts`）。** `integrate` の重複・食い違いは**文の綴り**を比べるので、「Port of Rotterdam」と「ロッテルダム港」が同じ実世界オブジェクトであることは解けず、値の食い違いも文に埋まっていれば見えない。子は所見に加えて `facts`（`{subject:{ref?,ids?,name?}, attribute, value, unit?, at?, source?, retrievedAt?, evidenceId?}`）を返してよく、`shapeOf`／結果が同じ形（`normalizeFact`）に整える——対象も属性も値も無いものは捨てる。`at` は値が**指す時点**で、読んだ時刻（`retrievedAt`）ではなく、無ければ補わない。ページの委譲（`research.delegate`）は `integrated.facts = { objects, counts, unresolved }` を返す。
- **対象の同一性**は、述べられた `ref`、他の事実と共有する外部 id（`wikidata`・`osm`・`geonames`）、注入された `resolve(subject)`（ページでは `makeFactResolver`＝セッション索引 `W.find` → 永続グラフ `findPersisted`。外部 id を先に、名前を後に訊く）の順で決まる。**名前の一覧も別名表もこのファイルに無い。**どれでも解決できない名前は `resolved:false` の別の対象のまま `unresolved` に挙がる（推測で束ねない）。resolver が投げても結果は落ちず `resolveFailed`。
- **属性 × 時点**の行ごとに `agree`（2 人以上が同じ値・単位）／`conflict`（値が違う。全観測が出典と `evidenceId` つきで返り、数値なら `relDiff` を**測って**返す。単位が違えば `unitMismatch`＝比較不能で、換算しない）／`single`（1 人だけ＝確認されていない）。年が違う値は別の行で、矛盾ではない。時点が述べられない値も別の行。`missingFrom` はその対象について何かを述べたがこの属性を述べなかった子。
- **判定ではない**: 矛盾は 2 つの真実（範囲の違い）でもありうる。Atlas が行を読んで決める。カードは矛盾の件数を 1 行出す。
- **接点（契約）。** `js/atlas-delegate.js` とは (a) 結果の `facts` 欄（`normalizeFacts` で 200 件まで）と (b) worker の返却形の説明だけで繋がる——永続ジョブ化・再開の記録が結果を保存するときは `facts` を結果の一部として運ぶこと。`js/atlas-evidence.js` とは `evidenceId` の**文字列**だけで繋がる（このファイルは Evidence を作らず読まない）。worker は URL（`source`）を返し、Evidence レコードの id はページ側がそれに付ける。テスト `tests/atlas-fact-merge-checks.test.mjs`。

**引数の参照。** 能力の仕事の引数は、文字列が `@<仕事の id>:<経路>` の形（経路は結果の `data` か `summary` から始まる、`.` 区切り）なら、その入力の結果の中身に置き換わる。空間分析の 1 歩目が作ったデータセットを 2 歩目へ渡す、は `"inputs":["@acq:data.gis.dataset"]`（`acq` は `inputs` にも書く）。名指せるのは `inputs` に宣言した仕事だけ（参照は依存で、依存は宣言する）。辿れない参照は、その仕事を走らせずに `input_ref_unresolved` で終える（推測した引数で走らせない）。`@@` で始まる文字列は `@` で始まる文字列そのもの。能力の仕事の結果は `data` を持ち、次の worker にも渡る。`data.gis` は読み取り専用の能力なので、この経路で子が GIS の演算を連鎖できる（モデルを挟まず、費用もかからない）。

**独立した検証。** worker の仕事に `verify:true` を付けると、結果が戻ったあと、**別の worker** がその所見を自分の出典で確かめる（`verifyContract`）。検証者は主張をそのまま繰り返して `verdict`（supported／unsupported／contradicted）を付け、`verifyOutcome` が元の主張と**本文の一致（`fold`）**で突き合わせる。繰り返されなかった主張と、戻らなかった検証者は `unchecked` で、支持されたとは扱わない（`integrated.verification` に件数と、検証者の状態＝拒否・不達を含む）。検証者も子の 1 体で、サーバの方式が認めるか拒む。

**失敗のあとの再試行。** worker は、サーバの上限（`delegationPolicy.childMaxCalls`）を渡されたとき、**観測された一過性の失敗**（`provider_unavailable`・5xx・時間切れ）のあとに、上限の範囲で**前と違う要求**をもう 1 度送る。Web 検索が時間切れだったなら Web なしで（結果は `partial`／`degraded` で、未検証と述べる）、それ以外は短く（所見 5 件以内）。拒否と、戻らなかった要求（`unobservable`）は再試行しない。上限を渡さない呼び出しは従来どおり（初回と、形の修復 1 回）。各要求は、**要求の中身（プロンプトと Web の方式）から作った鍵**を `x-intmap-replay` で運ぶので、同じ要求を別の実行者が重ねて送っても、先の答えが返るだけで 2 度は計算されない（修復・再試行・同じ id を使った別の `research.delegate` 呼び出しは別の鍵）。

**再開。** `snapshot()` は、結果と事象記録を平文の JSON で返し、`makeDelegation({resume})` に渡すと、同じ契約で `done`／`partial` に終わった仕事は**再実行も再課金もせず**記録から答える（`resumed`、費用は 0 として数え、元の費用は `task.resumed` に残る）。`research.delegate` は、仕事が 1 つ終わるたびに snapshot を端末の別の IndexedDB（`intmap-atlas-delegation`。書けなければそのページのあいだはメモリ。`js/atlas-delegate.js` `pageDelegationStore`）に書き、始めるときに**同じ仕事の一覧**（各契約の鍵＝`tools` の許可を含む、と `verify` を順に並べたもの、`delegationKey`）の記録を引いて `resume` に渡す。ページを閉じた・読み込み直した・ターンが切れたあとで同じ一覧を頼むと、終わっていた仕事は走らず（カードに「前回の実行の結果・再実行なし」、結果に `resumed`）、終わっていなかった仕事だけが走る。記録が答えるのはサーバがターンを生かしておく間（`TURN_TTL_S`）だけで、古い記録は読むときに消す（サーバ自身も同じ間しか同じ要求の答えを返さない）。一覧が違えば別の委譲（後の仕事の鍵は入力を id で名指すので、同じ一覧の中でだけ「同じ鍵＝同じ入力からの同じ仕事」が成り立つ）。`fresh:true` で全部を走らせ直す。ページを閉じているあいだに続きを走らせるものは、下の「永続ジョブ」（`research.delegate` とは別の入口。ページの委譲はページが実行者のまま）。

**走っているあいだ。** 委譲は事象記録を購読でき（`subscribe`）、作業の痕跡の行には仕事ごとの状態（待機・実行中・再試行・完了・拒否…）と、ここまでの費用が事象のたびに更新される（実行器の `progress` を能力まで通し、行の詳細欄に書く）。ターンを止めると（中止のシグナル）、走っている仕事はすべて取り消され、子のリクエストは中断される。子の `childMaxCalls`（サーバの方式）が分かっているときは、それがそのまま 1 つの子の要求回数の上限になり、**観測された一時的な失敗のあとだけ**同じ上限の範囲で 1 回やり直す（時間切れは Web 検索なしで、その旨を結果に述べる）。

**子は読むだけで、地図を書かない。** 描くのは Atlas で、子の結果（道具結果の `delegated`）から描く。子に許すタスクは `atlas_delegate` の 1 つだけで、Web 検索が付く。

**支払い方はサーバの設定で決まる**（`supabase/functions/ai-proxy/config.ts` `delegationPolicy`）。子の呼び出しは `x-intmap-parent-turn` で親のターンを名指す。

- `ATLAS_DELEGATION=independent`（既定）: 子は親の下に自分の枠を持つ（`consume_ai_child_turn`）。既定では子は最大 2 体、各 8 回まで（子が `tools` で許可された読み取り能力を自分で呼ぶとき、1 回の呼び出しが 1 手になる。最後の 1 回は必ず答えのために残す）（`ATLAS_DELEGATION_CHILDREN`・`ATLAS_DELEGATION_CHILD_CALLS`）。
- `=shared`: 子の呼び出しを親の `TURN_MAX_CALLS` に数える。
- `=off`: **停止スイッチ**。子の呼び出しはすべて `delegation_off` で拒否され、Atlas は子なしで答える。

**Atlas は方式を事前に知っている。** ai-proxy は Atlas のターンの応答に、毎回 `meta.delegationPolicy`（`{mode, maxChildren, childMaxCalls}`）を載せる。ページはそれを覚えてターンの文脈で Atlas に伝え、`research.delegate` は上限を超える件数を、費用を使う前に `too_many_tasks`（上限の数つき）で返す。`off` のときは `delegation_off` で返す。どの仕事をまとめるかは Atlas が決める。まだ方式が届いていない最初のターンでは、サーバが判断する。

**運用の記録。** 子の呼び出しと Atlas の親のターンは、成否・コード・使われたモデル・所要時間・トークン・費用を `ai_delegation_journal` に **30 日**残す（台帳 `ai_turns` は約 1 日で消え、失敗した子の行は払い戻しで消えるため、これが無いと失敗の記録が残らない。`log_ai_delegation`、service_role 専用・書けなくても要求は失敗させない）。管理画面の **Delegation** タブが `delegation_overview` で日別に読む（`docs/MONITORING.md`）。子のモデルは、`ATLAS_DELEGATION_MODEL`（**価格の分かるモデルだけ**。未知は理由つきで無視）で親と別の層にできる。未設定なら従来どおり。

**子の失敗は理由つきで残る。** サーバが述べた時間切れの有無と HTTP ステータスを、結果の `detail` で運ぶ。失敗した子の台帳の行は払い戻しで消えるので、記録に残るのはここだけになる。

どの方式でも、子が利用者の 1 日の回数を消費することはない。拒否はすべて 409 で名前付きで返る（429 は利用者の枠として読まれるため使わない）。

**1 つの質問（親と、それが開いた子の全体）の実費には上限がある**（`TURN_COST_CAP_USD`。環境変数 `AI_TURN_COST_CAP_USD` で変えられる）。

- **予約**: 提供元へ要求を送る前に見積もりを `reserve_ai_spend` で予約する。送る文字数をすべて未キャッシュのトークンとして数え、出力は可視枠の 2 倍として見積もるので、実際より多めになる。
- **精算**: 応答のあと、`settle_ai_spend` で実際に請求された額に置き換える。
- **台帳に届かないとき**: 予約せずに通し、`meta.spend:'unavailable'` とログに残す。この柵は 1 つの要求の費用を抑えるもので、同じ請求額にはプロジェクト全体の日次天井と子の回数枠という、失敗時に止まる柵がすでにある。ここで止めると、台帳が無いあいだ（migration より先に関数が配備されたときなど）はすべての質問が 500 になる。
- **途中で止まった予約**: 精算されなかった予約は、行の寿命まで残る。台帳は多く数える側に倒れる。
- **単価表**: `_shared/ai-provider.js` の `MODEL_PRICE_USD_PER_MTOK`。表に無いモデルは最も高い行の単価で数える（`priceOf` は `known:false` を返す）。
- **上限を超えたとき**: 409 `turn_cost`。
- **各応答の実費**: `meta.costUsd` に載る。

上限は Atlas の能力を縛る柵ではなく、請求額の柵である。値の根拠と失効条件は `config.ts` に書いてある。

**まだ無いもの（足すときもこの約束の上に足す）。**

- 調べた値の行は `data.table`（`js/atlas-table.js`）で dataset にして gis の段へ渡せる（worker の facts を自動で表にする経路は無い。Atlas が行を述べる）。
- サーバ側の実行者。いまは同じページの中で動き、タブを閉じると止まる（記録は端末に残り、同じ一覧を頼み直せば終わった仕事は走らない——上の「再開」）。
- 子の手数の実測。子が能力を呼び・探すとき、既定の 8 回で足りるかは本番でまだ測っていない。
- 結果の意味での統合。`integrate` は文字列の正規化で重複を除き、同じ地点で数値が違うことを**旗**にするだけで、同じ意味・別の表現を同一とは見ない。
- 委譲あり／なしの実測の蓄積（比較器は `scripts/atlas-delegation-bench.mjs`、本番で回した記録はまだ無い）。

### Skills——仕事の進め方を、必要なときだけ読む資料（`js/atlas-skills.js`・`js/atlas-skills-data.js`）

**Capability は「何ができるか」、Skill は「この種の仕事をどう進めるか」。** 産業立地の一次分析・衛星画像の変化検出・歴史的国境の比較・港湾物流リスクの比較のように、複数の能力を組み合わせる仕事には、どれから触れ、各結果が何を言えて何を言えないか、答えをどこで止めるかという**知識**が要る。それを能力表（能力ごとの引数と説明）や常時送る system prompt に混ぜず、必要なときだけ段階的に読む。

- **発見は `find_capability` と同じ入口。** 答えに `skills: [{id,title,summary,read}]` が付く（最大 2 件・名前と 1 行だけで本文は載せない）。要求と題・要約・キーワードが語を共有するものだけ（`MIN_SCORE`）。能力が 1 件も当たらなくても Skill が当たれば、その旨を note で述べる。能力の答えそのものは変えない。
- **読むのも同じ入口。** `find_capability {"query":"skill:<id>","section":"<節>","language":"en"|"jp"}`。**1 節だけ**返し（既定は先頭の節）、残りの節の題と文字数、本文が使う能力（`uses`）を添える。`read_result` が切られた結果を必要な範囲だけ読ませるのと同じ考え方で、1 節は 1,600 字以内（門が保つ）。読むだけで状態は変わらず、読まない turn は今までと同一。
- **Skill は固定手順の強制ではなく資料。** 順序も呼び出しも縛らず、結果は「資料であって手順ではない」と自分で言う。何を呼ぶかは Atlas が決める（`CONSTITUTION.md` §5）。
- **宣言は散文だけ、残りは導出。** `js/atlas-skills-data.js` に書くのは題・要約・キーワード・各節の本文（en + jp）。使う能力は本文の `id`／`id{arg,arg}`（バッククォート）から導く。門 `skills-consistent`（`npm run check:capabilities`）が、名指された能力がレジストリに実在し撤回されていないこと、引数がその schema にあること、英語と日本語が同じ能力を名指すこと、1 節が上限を超えないことを測る。
- **偽物を書かない。** 初期の 4 本は実在する能力とデータだけで書き、IntMap が持たないもの（地価・用途地域・運賃・バース混雑など）は「限界」の節で空白として名指す。
- 検査: `tests/atlas-skills-checks.test.mjs`（発見・段階読み・門が落ちること・tool surface の入口）。

## Atlas は結果を「実世界オブジェクト」で返し、辿れる——地震・出来事・施設・企業・火山・地点は 1 つの型

`js/atlas-geo-object.js` の `worldObject()` が型で、`geoObject()` を呼んで種別・`ref`・範囲・時刻・記事 id・証拠 id・出典・辺・値を足す（`provenance` はそのまま運ぶ）。**`ref` は
`type:id`** で、能力・カード・次の質問が対象を名指す 1 つの綴り。

- **返す側。** `research.impact`（中心の地震または場所、半径内の施設・都市・地震。各々が中心へ `within_impact_of` の辺）・`research.events`（各出来事＝`news_event`、構成記事の id つき）・
  `data.volcano`・`news.company`（企業と、それに触れる出来事＝辺 `mentions`）・`research.placeProfile` は、結果の `exec.worldObjects`（`subject`・`objects`・`totals`）に対象を載せ、
  セッションの索引へ入れる。アダプタは記録が述べたことだけを書く（`mapped === false` の擬似座標は採らない、火山の最終噴火は年のまま、施設は時刻を持たない）。
- **辿る側。** `research.object`（`worldObject`）は ref か名前から 1 件を返す（索引に無ければ読み込み済みニュース・火山カタログ・企業アトラス・USGS 週フィードへ落ちて同じアダプタで
  書く。無い名前は「無い」）。`research.related`（`worldRelated`）は結び付いた対象を返す。
- **関係の規則。** `linked`（辺、または共有する記事 id・証拠 id）、`near`（`km` 以内か相手の範囲の内側。既定 300 km）、`concurrent`（時刻の区間が `hours` 以内。既定 72 時間）。関連 =
  `linked`、または `near` かつ（`concurrent` またはどちらかが時刻を持たない）。時刻だけでは関連にしない。理由は結果に付け、上限は設けない（`limit` は呼び手のもの。総数は常に返す）。
- **UI。** 地点カードの「関連」が同じ索引・規則・描画（`relatedGroups`）を読む。索引は `js/atlas-world-objects.js` のモジュール単一インスタンスで、ページの寿命。

| 表 | 持つもの |
|---|---|
| `atlas_jobs` | ジョブ。状態は `queued` → `running` → `done`／`failed`／`cancelled`（中断。`stop_reason` は `user`／`kill_switch`／`cost_cap`）。費用の上限と使った額、**リース**（誰が今走らせているか）、取消の要求、結果 |
| `atlas_job_tasks` | 仕事ごとの契約・依存（`deps`）・状態・結果・費用 |
| `atlas_job_events` | 追記だけの記録。`amend`（利用者が走行中に変えた指示）もここ |
| `atlas_jobs_control` | 1 行。**停止スイッチ**（`enabled`）と上限（利用者あたり同時 2 件・全体 20 件・1 件 $1） |

**二重実行しない。** 走らせてよいのはリースを持つ者だけで、`atlas_job_claim` が `FOR UPDATE SKIP LOCKED` で 1 度に 1 人へ渡す。リースは更新されなければ切れ、次の claim が引き継ぐ。仕事は 1 度しか終われず（`atlas_job_task_finish` は 2 度目に `false`）、走行中に死んだ runner の仕事は待機に戻る。その runner が予約したまま決済しなかった費用は**使った額として数える**（多めに数える側へ倒す）。作成は `(user_id, idem_key)` で冪等——同じ鍵はいつも同じジョブで、2 度課金しない・2 度始めない。

**走らせ方。** `op:"create"`（利用者の JWT）が `planJob`（ページの委譲と同じ規則を先に 1 度適用）→ `atlas_job_create` → **新規のときだけ日次の AI 利用枠を 1 消費**（拒否なら作ったジョブを即取消）→ 最初のリースを背景で走らせる。続きは自分自身への `op:"tick"`（共有秘密 `ATLAS_JOBS_SECRET`・定数時間比較・未設定なら拒否）と、pg_cron の毎分の tick（リースの切れたジョブがあるときだけ）。1 回の起動は新しい仕事の波を 30 秒だけ始め、残りは次の起動へ。サーバが走らせるのは **worker（読み取りの子 AI）だけ**で、`capability` 型はページ側の道具レーンがサーバに無いため `kind_unsupported` で計画の段階で断る。プロバイダは OpenAI のみ（他は `provider_unsupported`）。

**会話は止まらない。** 利用者は走行中も普通に会話でき、ジョブは select（RLS で自分の行だけ）で読む。**途中の変更**は `atlas_job_amend(job, note, drop[])`——note は次の provider 要求の前（checkpoint）に runner が読み、worker への指示として契約より優先して渡る。`drop` は待機中の仕事を外す。**中止**は `atlas_job_cancel(job)`——未着手なら即、走行中なら次の checkpoint（**次の provider 要求の前**）で止まる。どちらも冪等で、所有者だけが操作できる。

**費用の柵（無人でサーバの鍵が使われる）。** ① 1 ジョブの上限（$1）を、**要求の前に予約・後に決済**（`atlas_job_reserve`／`settle`）。予約が上限を越えるなら要求を送らず `refused`／`cost_cap`。② 利用者の同時実行と全体の同時実行。③ プロジェクト全体の日次の要求数（`spendCeiling` `atlas-jobs`、`ATLAS_JOBS_GLOBAL_PER_DAY`）。④ **停止スイッチ**——表の `enabled=false` かシークレット `ATLAS_JOBS=off`。作成も claim も止まり、走行中のジョブは次の checkpoint で `cancelled`（`kill_switch`）。数値は利用者の 2026-11-20 の決定で、環境で動かせる。

**再試行は観測された失敗のあとだけ**（`one-pass-or-a-reason`）——プロバイダの 5xx／タイムアウトは 1 度（タイムアウトならウェブなしで、結果は `partial`）、形の誤りは理由を名指して 1 度。**Atlas の能力としての入口（利用者が頼める経路）と、ジョブを読む・変える・止めるページ側の窓口はまだ無い**——次の切り分け（窓口は能力と同時に入れる。呼び手のないモジュールを先に置かない）。

### 同一性・型付きの関係・時間・根拠（世界オブジェクトの知識グラフ層）

`worldObject` は `ref` のほかに次の欄を持つ。どれも出典が述べたときだけ入り、述べていなければ空のまま。

- **`ids`（外部識別子）。** `osm`（`node/123`・`way/…`・`relation/…`＝要素の種別を含む）・`wikidata`（`Q…`）・`geonames`・`company`・`dataset`（`<dataset id>:<feature id>`）。方式ごとに値を検査し、形の違うものは捨てる。
  出典自身の id は経路の途中で捨てない: `overpassPOIs` は `osm`、Wikidata の POI は `wd` を返し、`fromFacility`・`fromCity` はそれから `ref`（`facility:osm-way-4471`）を作る。ラベルの改名や座標の改善で `ref` は変わらない。
  id を持たない記録だけが名前＋位置（`slug`）に落ちる。GIS の地物は、データセットが名指した地物 id（`_fid`）があるときだけ識別子になり、行番号は識別子を名乗らない（`facts.idStable: false`）。
- **同一性。** `register()` は**同じ外部識別子を述べた 2 件**だけを 1 件にする（先に持っていた `ref` が残り、畳んだ側の `ref` は `aliases`。辺・`find` は別名から届く）。名前と座標が同じだけでは畳まない
  （港とそのターミナルは同じ場所にある）。2 つの id を持つ記録は、それぞれの id を持つ 2 件を 1 件にする橋になる。ある方式で**値が食い違う**ものは畳まず `conflicting_identity`、
  **型が違う**ものは `candidate_match` の辺で結ぶ。畳まなかった同名・近接（既定 0.5 km、見積り・呼び手が変えられる）は `identity().candidates`。`find` は `wikidata:Q123`・`osm:node/1` でも引ける。
- **型付きの関係。** `links` は `{rel, ref}` に加え、成立期間（`fromMs`/`toMs`）・`confidence`（high/medium/low）・`evidenceIds`・`source` を持てる。辺は述べた側に 1 件だけ保存し、逆向きの名前は
  `REL_INVERSE`（`part_of`↔`contains`、`operated_by`↔`operates`、`owned_by`↔`owns`、`mentions`↔`mentioned_in`…）で読む。`traverse()`／`related({rels, depth})` が名指した関係だけを何段でもたどり、各対象に
  たどった経路を付ける。この型付きの探索は近接を使わない（名指した関係は述べられた事実で、推測ではない）。`assertLink` は同じ関係・相手・期間なら 1 件、期間が違えば別の辺。
- **時間。** `validity`（`{fromMs, toMs}`）は対象が存在した期間（`time` は報じられた時刻）。`atMs` を渡すと、その時点で成立していない辺・対象は結果から外れる（「1990 年にこのターミナルを運営していたのは」）。
- **根拠のある値。** `claims`（`key`・`value`・`unit`・期間・`source`・`evidenceId`）は出典ごとの値を上書きせず並べて持つ。`claimConflicts()` は期間が重なり値が違うものを返し、単位が違うだけのものは
  「単位違い」として分ける。`facts` は 1 行表示用のスカラのまま。
- **企業。** `fromCompanyProfile()` は企業と各拠点（`operated_by`、開業・閉鎖年があればその期間）を書く。本社の精度が `city` なら座標は `resolved_place_centroid`（建物の位置ではない）。
- **Atlas。** `research.related` は `rels`・`depth`・`at`、`research.object` は `wikidata:Q…`／`osm:…` と、同一性（識別子・別名・畳まなかった候補・食い違い・出典間で値が違う項目）を返す。能力は増やしていない。

### Evidence Graph（数値の出自の系譜）

呼び出し中の Evidence Registry（`js/atlas-evidence.js`・1 呼び出し）は変えず、その外に**長期の系譜グラフ**（`js/evidence-graph.js`）を持つ。

- **節は 2 種類で混ぜない。** `source` は元の事実（データセット・Web 文書・アプリ保有の系列）で、IntMap は**どの版を読んだか**だけを記録する（版は追記のみ・分からなければ `unversioned`）。`derived` は IntMap/AI が作ったもの（`gis_op`・`answer_number`・`ai_inference`）で、入力ごとの**その時点の版**と計算 `{op, opVersion, params}` を持つ。id は内容アドレスで、同じ導出は同じ節。入力が節でなければ拒否。
- **問い。** `trace`（元データまで）・`impact`（これが何を養っているか）・`staleness`（鎖の先まで）・`wouldStale(source, 新しい版)`（更新の前に影響先を調べる）。
- **縦串。** `bindGis` が `IntMapData` の登録から取り込み/レイヤー読みを source、演算出力を `gis_op`（入力・`ops-N`・params）として記録する。`recordAnswer`（`runStructuredAnswer` が監査の後に 1 回呼ぶ）は、数値の claim を、引いた registry レコードの source 節へつなぐ。記録が述べる値と一致するなら `answer_number`、一致しなければ `ai_inference`、何も引かなければ節にせず `uncited` と数える。`graphRef` を持つ記録（GIS の結果を事実として渡したもの）は GIS 節へ直接つなぎ、数値が演算の鎖を通って元データに届く。
- **モデルは節を書かない。** 節はコードが持つ記録からだけ作られ、claim の `evidenceIds` が registry に無ければ辺を作らない（`unresolved`）。
- **永続化は未実装。** いまはページ寿命＋`snapshot()/restore()`。Supabase の表と RLS は別作業（dev-notes 2026-11-20-evidence-graph）。
- **更新の伝播。** `js/data-impact.js` が上流の版の変化（`diffObserved`）から再計算候補（`planRefresh`: 上流順・`rerun`＝GIS 演算の再実行 / `review`＝数値の読み直し・版が分からない元データは `unwatched`）を出し、`applyUpdates` が版を進めたうえで `staleness` と過不足なく一致することを確かめ、`executePlan` が runner（何を走らせるかは呼び出し側＝Atlas）で 1 回だけ上流順に再実行する（失敗の下流は blocked）。実データの経路は 企業工場拠点 → 格子 → 集計（産業集積）で `tests/data-impact-checks.test.mjs` が本物の GIS 演算で通す。

- **永続化（アカウントの写し）。** `evidence_graph_nodes`（1 節 1 行・`(user_id, id)`・本人だけ RLS・50 MiB の上限は名前付きで拒否）。**同意はノートの同期と同じ**——`js/atlas-notebook.js` が自分の同期の後に `syncEvidenceGraph`（`js/evidence-graph-sync.js`）を呼び、ノートのアカウント上のコピーを消すときに一緒に消す。`pending()` は**サーバが受けた分だけ** `ackPending` するので、送信に失敗しても失われない。`pull` は置換でなく `merge`（版の和集合・content-addressed な派生は同じ節）。
- **更新の影響の特定。** 出典が新しい版へ動いた瞬間に `putSource` が `impactReport`（触れた GIS 結果の dataset id・回答の数値とその値・ノート・段数・stale の理由）を作り、`onSourceChanged` へ配り `updates()` に残す。更新の**前**は `wouldStale`。
- **統合。** ニュース（`recordNews`・版は公開日。取得時刻は版にしない）と調査ノート（`recordNote`・ノートの `evidenceRefs` ＝そのターンの回答の数値の節の id）が節になり、ノートは根拠の節の上に立つ。`research.analyze` の `datasets` 引数は `datasetFacts`（行数と各数値列の最小・最大・埋まっている行数＝データセット自身が測った値）を `graphRef` 付きで回答へ渡す。
- **成果物の完成度と独立した根拠（`js/evidence-graph-deliver.js`）。** 操作が ok でも目的を達したとは限らない。`assessDataset`（各列が何行に値を持つか）・`assessSupport`（数値ごとの独立した出典の数——同じホストを 3 回引いても 1・`corroborated`／`single`／`model_only`）が**事実だけ**を出し、`makeTurnObserver` がそれを goal verifier（`js/atlas-goal-verify.js` の `observe`）へ「WHAT THE OUTPUTS ACTUALLY HOLD」として渡す。依頼を読み「20 都市のうち 8 都市分しか無い」を未達と判断するのは別モデルの verifier で、コードは依頼の語を 1 つも読まず、Atlas の判断も縛らない。観測が投げたら記録だけで走る。
### 永続の世界グラフ（Supabase・`world_graph_*`）

セッションの索引（上）はページの寿命で、出典が一度述べたこと（運営者・所有者の交代・取扱量）は再読み込みで消えていた。`supabase/migrations/20261119150000_world_graph.sql` の 3 表が、
**出典が述べたことだけ**を全員・全セッションに残す。

- **形はページの索引と同じ。** `world_graph_nodes` は `ref`（`facility:wd-Q104518607`）・type・位置と provenance・`ids`・存在期間、`world_graph_edges` は述べた側の型付きの辺と期間・確度・出典、
  `world_graph_claims` は値＋単位＋期間＋出典。読み口 `js/world-graph-store.js` が行を `geo.worldObject` で世界オブジェクトに戻して**同じ索引へ入れる**ので、たどる規則（`traverse`・`related`）は 1 つのまま。
- **結ぶのは識別子。** 運営者・所有者の企業は、IntMap の企業アトラスが同じ Wikidata id を持つなら `company:<atlas id>` に**なる**（`ids.company`）。能力はそのアトラスの拠点も同じ索引へ書き下ろす
  （`hydrateAtlasCompanies`）ので、「ターミナル → 運営企業 → その企業が運営する他の施設」が 1 回のたどりで出る。名前の一致では結ばない。
- **RPC。** `world_graph_subgraph(ref, rels, depth, at_ms)`（辺をどちらの向きにもたどる再帰 CTE。`at_ms` で成立していない辺・対象・値を外す）・`world_graph_find`（ref／識別子／完全一致の名前）・
  `world_graph_near`（大円距離）。SECURITY INVOKER・全員が読め、書くのは service_role だけ（migration の seed とサーバ側の取り込み）。
- **能力。** 新しい能力は足していない。`research.object` は session に無い ref・`wikidata:Q…`・名前をこのグラフへ訊き（`via: "graph"`・値は単位・期間・出典つき）、`research.related` は `rels`・`depth`・`at` を
  この永続グラフにも向け、近接の問いには近くの永続対象も加える。**データベースが答えなかったときは答えに明記する**（空のグラフと同じに見せない）。
- **縦串（実データ）。** `scripts/world-graph/build-lng.mjs` が Wikidata（CC0）から LNG ターミナル 68 件・運営／所有の企業 34 社・辺 49・取扱量 48 件を取り（P137／P127 の期間つき・P2957 は単位つき）、
  `data/world-graph-lng.json` と seed migration `20261119150100_world_graph_lng_seed.sql` を作る。取り込みは冪等。
- **港湾の面と継続取り込み。** 港湾（Wikidata 947 件が UN/LOCODE を持つ）を 2 つ目の領域として、**3 つの独立した典拠を識別子で結ぶ**: Wikidata（運営 P137・所有 P127 を期間つきで・P2957・鉄道線／道路への `connected_to`〔P81／P2789 のうち**対象が鉄道線か道路のもの**だけ〕・`part_of`・OSM relation P402）、
  UN/LOCODE（UNECE。名前・位置と**機能の旗**＝その地点に港・鉄道ターミナル・道路ターミナルがあること。地点についての述べであって特定の線への辺ではない）、Eurostat `mar_go_aa`（港ごと・年ごとの取扱貨物量〔千トン〕。Eurostat 自身の港コード `NL_0NLRTM` の中の LOCODE で結ぶ）。
  推測はしない: LOCODE でない Eurostat 港（Antwerp-Bruges `BE003`）は落とし、同じ LOCODE を持つ 2 つの Wikidata 項目は統合せず、港と鉄道の近さは辺にしない。実装は `supabase/functions/_shared/world-graph-ports.js`（Edge Function と node の検査が同じものを読む）。
  **継続取り込み**は `supabase/functions/world-graph-ingest`（毎週 pg_cron）が `world_graph_ingest_begin／apply／finish` で行う: 新規・改訂（同じ港・年の値の改訂は同じ行を更新）を書き、上流が述べなくなった辺・値・対象を退役し、**退役が行の 40% を超える実行は `refused`** にして何も消さない。実行は `world_graph_ingest_runs` に残り、`world_graph_freshness()` を `research.object` が答えの末尾に「最終確認・Eurostat の更新日」として出す（直近の更新が失敗していればそう言う）。
  経緯・実測・否定した見立ては `dev-notes/2026-11-20-world-graph-ports.md`。
- **識別と履歴。** 対象は不変の `uid` を持ち（`ref` や外部 id は更新で置き換わりうる）、どの外部 id をどの根拠（stated・元レコード・属性）で結んだかを `world_graph_id_history` が持つ。同一性の判定は `supabase/functions/_shared/world-graph-identity.js`: 安定 id → 振り直される id の履歴 → 元レコード → 属性（同種・同国・半径内＝**候補**どまり）の順で、**名前は証拠にしない**・安定 id が食い違えば別の対象・2 対象が当てはまれば選ばない。更新の差分（変わった属性・入れ替わった id・消えたもの）は `reconcile()` が返し、書かれた変更は trigger が `world_graph_changes` に残す。別の領域は `scripts/world-graph/lib/domain.mjs` の `linkByIdentifier` で、**一方が述べる識別子をもう一方が持つ対象へ**結ぶ（解けなければ引かない）。実データで行政区域 240・原子力発電所 638 を足し、国コードで `located_in`（発電所 631・LNG ターミナル 65）。`dev-notes/2026-11-20-world-graph-identity.md`。

### Atlas の答えが「構造」であるもの（`js/atlas-reasoning.js`）

PRODUCT.md §4 の 20 項目のうち 3 つは欄を持つ結果として返る。決めるのは `js/atlas-reasoning.js` の純関数で、能力は値を集めて描くだけ。拒むのは「空の欄を持つ答え」と「標本が支えない
言葉」だけ。

- **`research.scenario`（項目 12）** — `{model, place|lng+lat, baseline, assumptions[], impact?}` を受け、`sim.ashPlume` / `sim.radiation` / `sim.tsunami` / `sim.pandemicRun` のうち 1 つを
  そのシミュレータの能力として（`K.dispatch`）走らせ、`impact` があれば `research.impact` も走らせる。答えは必ず 4 欄——**前提**・**使用データ**・**考慮外**・**不確実性**。モデル・前提・
  対象・基準時点のどれかが空なら空の欄を全部名指して拒む。年だけの基準時点を日に変えない。`SCENARIO_MODELS` の引数語彙は各項目の schema と一致することを
  `tests/atlas-reasoning-checks.test.mjs` が測る。
- **`time.changes`（項目 8・9）** — `{from, to, place?, n?, maxDays?}`。両端を `readYear` で読み、政体の出現・消滅・面積変化、Maddison の変化、レイヤーの差を返し、期間内の出来事を影響する
  記録の数の順に並べる（国境の変化日＝出現・消滅 1・境界変化 ½、戦争＝期間内の日付つきの出来事の数）。1 月 1 日の変化日は「年だけの可能性」と印を付け、片端だけの値はゼロからの増加と
  読まない。直近 7 日にかかるときだけ `research.events` のライブのニュースを添える。調べる変化日の数には上限（既定 40・`maxDays`）があり、調べなかった数を書く。
- **`panel.correlate`（項目 10）** — パネルを開き（`x` / `y`）、パネルが描くのと同じ報告を返す: n（供給できた国数に対して）・欠損件数・Pearson r と Spearman ρ の 95% 区間・外れ値と 4 欄
  （確認できたこと／考えられる説明（未検証）／反証／限界）。n < 4 または区間が 0 に届くなら断定せず、区間の半幅が 0.2 以内なら「述べる」、それより広ければ「示唆される」。

### 文章をその時代の地図に（`time.textMap`・`js/atlas-text-map.js`）

読者が貼った・添付した文章（史料・紀行文・戦記・教材）の地名を、その文章が述べる時点の地図に置く能力。**文章を読むのは Atlas**
（2 本目の AI 呼び出しも抽出器も無い）で、コードは Atlas が読んだものを**文章と照合する**側を持つ。

- **照合の相手**——このメッセージ、以前のメッセージ（`_hist`）、会話のテキスト添付（`ATTACH_LOG`）。比較は NFKC・小文字化・空白をすべて除いた形
  （改行をまたいだ引用も同じ語）。文中に無い地名は `not_in_text` として**引きもせず描かない**。
- **時点**——`when` は文中の語句（`quote`）と Atlas の読み（`read`）。引用が文中に無ければ時計は動かない。引用を暦で読めれば
  （`js/where-when.js` の `parse`。漢数字と「とせ」は年・月・日を数える位置だけ数字に直す）暦の読みが正で、食い違う `read` は拒む。読めない
  引用（執政官による紀年など）は Atlas の読みを使い、凡例が「Atlas が〜と読みました」と述べる。文中の他の時点（`others`）と文の外から分かる年
  （`inferred`）はボタンになり、`inferred` は「推定・文中に記載なし」と書かれ**適用されない**。
- **地名**——`map.compose` に `era` を渡す。`era` があると解決の順は 台帳 → **歴史上の名前**（`js/where-when.js` の `placeAt`＝検索欄と同じ
  `histCandidates` の全名一致。歴史都市名と Pleiades）→ ジオコーダ → ウェブ確認。項目の `as` は文中の綴りが記録の形でないとき（ラテン語の格変化、
  旧仮名）の引く形で、凡例に「Atlas の同定」と出る。記録が同じ名前に 2 つの場所を持ち `country` が無ければ `ambiguous` として候補を返し、
  ジオコーダにも訊かない。凡例の各行は出所（歴史都市名・Pleiades・現代の地名辞典・ウェブで確認）を持つ。
- **入口**——Atlas に言葉で頼む（「この文章の地名を当時の地図に置いて」など。テキストは貼っても添付してもよい）。1 ターン・1 回の利用。

### 時をまたぐ道のり（`time.journey`・`js/journey-through-time.js`）

1 本の線を Atlas が選んだ複数の時点で訊く能力。線は地点（`places` / `points` / `from`+`to`+`via`）の間の大圏で、`asRoute:true` なら与えた点列そのもの。時点は `years`・`dates`・`now`
を渡された順に読み、無ければ時計の瞬間（年は 6 月 15 日の正午）。

- **測り方は経路パネルの「国境」と同じ 1 つ**（標本と点包含は `js/routing-ops.js` のモジュール直下の関数を export して import する）。各時点の多角形は `js/time-borders.js` の
  `collectionAt`、今日は `window.countryGeo`。名前は年鑑の `nameIn`（`js/year-book.js`）。
- **記録が描くものだけを言う**——同じ場所に 2 つの形があれば両方を名指して `overlap`、従属政体の上の realm は `within`、名前の無い形は `unnamed`。何も無い区間は今日の陸地の輪郭で
  海と記録の無い陸地に分け、輪郭が無ければ `outside`。読めなかった時点は `failed` に理由を持つ。
- **モデルに渡すもの**（`exec.journey`）——時点ごとの記録の出典・標本間隔・区間（政体と km）・政体ごとの合計・越境点・覆われない長さ、一部の時点でだけ通る政体。比較は記録が書く名前で
  行いそう述べる。
- **地図**——1 時点（`draw`、1 始まり）を区間ごとの `LineString` で Atlas の線の層（`_hlLines` / `paintLines`）に載せ、`meta.painted.lines` で宣言する（観測器 `paint`）。時計は動かさない。
- 経路パネルの「過去の路線網 ▸ その年の国境」は計算した経路を同じ関数に訊く（`renderRoutePanel`）。史実照合は `node scripts/journey-through-time.mjs --sites`。

### 持ち主が変わった土地（`time.territoryChange`・`js/territory-change.js`）

1 つの範囲で 2 つの時点を比べ、**政体が変わった土地を地図に描く**能力。範囲は `place`（地域名）・`bbox`・どちらも無ければ画面の範囲。時点は `from` と `to`（年・`YYYY-MM-DD`・
`now`）、`to` が無ければ時計の瞬間。年だけの時点はその年の 6 月 15 日に読み、読んだ日を結果の `instantsReadOn` に書く。

- **測り方**——範囲に 1 つの格子（既定は約 100 万セル。`stepKm` / `stepDeg` で変えられ、使った刻みは結果にある）を張り、各時点の記録（`js/time-borders.js` `collectionAt`、今日は
  `window.countryGeo`）がセルの中心に描く政体を、`js/routing-ops.js` `ptInPoly` と同じ偶奇規則で行ごとに求める（両者の一致は試験が出荷した記録で測る）。面積はセルの球面面積の和。
- **同一性**——両時点が CShapes の国家コード（`_gw`）を持てばそれで、無ければ Wikidata 項目（`_qid`・Natural Earth の `WIKIDATAID`）、それも無ければ記録が書く名前で比べる。
  同じコードで名前だけ違う土地は `renamed`（一覧のみ。`drawRenamed:true` で描く）。ただし括弧の中（`IntMapEraName.split` の gloss）が変わったもの——«Korean Empire» → «Korea (Japan)»・
  «Syria (France)» → «Syria»——は記録が保有者をそこに書いているので**移動として描き** `sameIdentifier` を付ける。識別子を共有しない組は `comparedByNameOnly`。
- ⚠ **記録の継ぎ目では名前は身元ではない**——セルの両側を**別の記録**が描き、共通の識別子が無く名前も違う組は `nameOnly`（一覧のみ。**合計に入れず**、
  既定で塗らない。`drawNameOnly:true` で描く）。結果の `seam` が継ぎ目であることを述べる。CShapes の国家コードと Wikidata 項目の対応は**データから導けない**
  （CShapes の行は名前とコードだけ、1886 年より前の OpenHistoricalMap と時代のシートは名前だけ、Wikidata に COW / Gleditsch–Ward コードのプロパティは無い——
  2026-11-16 確認）。この規則が無かった時、ヨーロッパ 1885 → 1887 は何も持ち主が変わっていない 1886 年の継ぎ目で 530 万 km² を「失って」いた。
- **同じ境界の 2 つの描き方は移動ではない**——同じ識別子の組（元の持ち主が後の時点でも描かれ、受け手が前の時点でも描かれる）で、両側を別の記録が描き、
  幅が 0.2° 未満（`RIBBON_DEG`。正本は `scripts/build-hist-clio.mjs` `SLIVER_W` の実測の谷）のかけらは `borderDrawing` に分け、合計に入れない。
  1 つの記録が 2 時点で境界を別の場所に描いたものは移動のまま。
- **記録が描くものだけを言う**——片方の時点だけが描く土地は `recordOnly`（記録の端であって移動ではない）。1 セルに 2 つの形があれば両方を名指して `overlap`。主張の重なりが**始まる**だけ、または複数の主張の 1 つが**終わる**だけの土地は
  持ち主の移動ではないので `overlaps` に（始まり・終わりとして）並べ、合計に入れない（判定は家族史と同じ `js/family-history.js` `claimChange`）。
- **費用を先に言う**——格子を張る前にセル数・秒（0.5〜0.9 µs／セルの実測）・MB の見積もり `estimate` を出す。`estimateOnly:true` なら見積もりだけを返し、何も張らず描かない（上限ではない）。
- **地図**——移動 1 件を 1 つの (Multi)Polygon（セルの境界をたどった輪郭）として Atlas の多角形の層（`_hlPolys` / `paintPolys`）に、受け取った政体の色で載せ、`meta.painted.polys` で
  宣言する（観測器 `paint`）。同じ問いの再描画は自分の多角形を置き換える。時計は動かさない。
- **モデルに渡すもの**（`exec.territoryChange`）——両時点の記録、範囲と刻み（度と km）、移動ごとの km²・元と新しい持ち主に占める割合・かけらの数・最大のかけらの位置と印、改名、
  片方だけが描く土地、合計。史実照合は `node scripts/territory-change.mjs --sites`、計測は `--bench`。

## Atlas の長期記憶は 3 層——作業記憶・調査記録・統合知識

| 層 | 何 | どこ |
|---|---|---|
| 作業記憶 | 進行中のターン | `js/atlas-state.js` |
| 調査記録 | 何を訊かれ何を答えたか（ログ。検索はするが知識としては読まない） | 調査ノート `js/atlas-notebook-store.js`（現在は利用者から非表示） |
| **統合知識** | 調査から取り出した**主張**。根拠・状態・場所・期間・世界オブジェクト ref を持ち、後の質問で必要分だけ読み込む | `js/atlas-knowledge-store.js`（規則）・`js/atlas-knowledge.js`（スイッチと端末ストア）・`js/atlas-cap-knowledge.js`（能力） |

**過去の回答を無条件に事実として保存しない**——規則はコード側にある:

- 書き込みは Atlas の明示呼び出し（`knowledge.remember`）だけ。ターンからの自動抽出はしない。
- `verified` は**再確認できる根拠**が要る: 証拠レジストリ（`canonicalizeUrl`）を通る URL か、名指しされた IntMap のデータセット／計算。無ければ拒否（`verified_needs_source`）。証拠 ID（`e3`）は 1 回の呼び出しの中でしか意味を持たないので**追跡用に残すだけ**で、URL とタイトルを保存する。
- `inferred` は根拠（`basis`）が必須。想起時も推論と明示し、`verified` に混ぜない。
- `stale`・`contested` は書く時に選べない。`supersedes`（旧主張が古い情報になる）と `contradicts`（双方が矛盾ありになり、並べて示す。勝者は IntMap が決めない）という**関係**から生じる。何も削除しない。`validTo` を過ぎた主張は想起時に「期間終了」と出る（保存は書き換えない）。
- 結び付け: 場所（名前＋座標）・期間（`validFrom`/`validTo`）・世界オブジェクト ref（`world_graph_nodes.ref` と同じ `type:id` 形）。想起は語・場所と半径・ref・日付で絞り、サイズ予算内の件数だけ返して残数を述べる。
- **既定オフ**。利用者が `knowledge.setting` で有効にするまで書き込みも読み出しも `KNOWLEDGE_OFF` で拒否。保存は**この端末（IndexedDB）だけ**で、アカウント同期はまだ無い（足すときは調査ノートの `sync` と同じ第 2 のスイッチを持たせる）。
