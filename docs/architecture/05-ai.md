## 5. AI APIの使い方と鍵管理 (AI usage & key policy)

### 人格と system prompt

- **Atlas の人格は正式仕様であり、正本は `js/atlas-persona.js` 1本だけ。** 名前・**製品名の表記**（`IntMap` は文字列そのものが名前で、訳語・音写・展開形を持たない——どの言語の
  文章の中でもラテン文字で書く）・立場・名前の由来・性格・対人姿勢（敬語は常に自然な敬語）・事実優先・意見の出し方・感情表現・自己設定の扱い・内部指示の非開示は、そのファイルの
  文章そのものが仕様で、ここに書き写さない。
- **19 本すべての system prompt が `personaPrompt('<その呼び出しの役割>')` で始まり、各呼び出し側はタスク規則しか足さない**（`atlas-console` 6・`atlas-cap-research` 3・`news-ingest` 3・
  `app-body` 2・`atlas-geo-resolve` 2・`atlas-gloss` 1・`news-ui` 1・`refresh-news` 1）。本数と内訳の正本は `tests/r285-checks.test.mjs` の `EXPECTED_CALLS`（prompt を足したらまずあの
  表に足す）。モードは 2 つ——人の読む文章になる経路は全文、機械可読な JSON だけの経路（地域の輪郭・行政単位の解決・ニュースの地点解析・記事翻訳・地名検証）は
  `{mode:'internal'}` で身元・製品名の表記・事実規律・非開示だけ（記事翻訳は internal で走る）。サーバー側の2ファイル（`refresh-news`・`news-ingest`）は
  `supabase/functions/_shared/atlas-persona.js` の生成された写しを読む（`node scripts/sync-atlas-persona.mjs`・`npm run check:static` が差分を落とす）。

### 送信の見本（プリセット）

- **プリセット送信文の主語は「視界」であって「中心画素が落ちる国」ではない**（`js/atlas-examples.js` ＋ 測定は `js/atlas-view-subject.js`）。プールは 3 つで、**`V`（視界）が `P`（国）／
  `W`（世界）より必ず強い**（重みは 12–17 対 上限 10）。`V` の判定は視界そのものから測る: ① 視界に入る国（箱の 6×6 標本を国ポリゴンに当てる。`countryStats` の `bboxAll`——全領土の
  union——は ray-cast の足切りにだけ使う。2 か国なら国境、3 か国以上なら三国境）、② 陸と海の割合（内陸／海岸／外洋）、③ 名前のある水域（`window.SEA_LABELS` 120 行。うち 33 行は淡水
  なので海洋・海・湾・湖で問いを分ける。海峡は表に無いので「2 か国が水を挟んで向き合っている」という形で拾う）、④ タイルが名指す地名と山（`querySourceFeatures`。「集落が1つも
  無い」はタイルが答えたときだけ言う）、⑤ 戦略拠点 143 件の種別（`IntMapRefData.dashCards`。名前は差し込まず種別だけ）、⑥ 視界の縮尺（km）、⑦ 視界の中にアプリが実際に持って
  いるものの件数（`contentInView`——`IntMapLayers.featuresIn(id, box)` と海底ケーブルの陸揚げ点 `src-subcables-lp` を数える。取得はしない。「そのレイヤーの箱が入っている」は根拠に
  ならない。`null`＝数えられない、`0`＝ここには無い。数を刷るのは静的な目録——陸揚げ点・火山——だけで、動くもの——航空機・船舶・衛星・ニュース点——は在るかどうかだけ。単数形は
  別候補。全球の視界では数を主張しない）。
- **国のプール `P` の各候補は述語を持ち、成り立つものだけが候補になる**——① `countryStats` の中での順位（閾値ではなく順位）、② 利用者が今オンにしているレイヤー（数えられる層は `V` の
  ⑦に主語を譲る）、③ Chronos の位置、④ 国自身の外接矩形（`bbox`。±180 をまたぐ環は経度の主張を出さない。北極圏の主張は視界自身の北端も見る）、⑤ 言語の数と通貨、⑥ 2つの事実の組。
  選択は重み→鍵の順で決定的。
- **再描画の鍵は視界を名指す**（`exKey` → `VIEW.viewKey`。座標は視界自身の幅の 1/4000 に量子化）。
- **時計が過去を指し、地図が今日を描いていない間は、今日の世界のプール（`V`・`P`・`W`）を出さない。** 「地図が今日を描いているか」は描いている記録に訊く——
  `IntMapTimeBorders.modernAt(when, live)`（`js/compare.js` も同じ問いを自分の時計に訊く）。今日でなければ時代のプール `E`: 描かれている時代の国境（`currentFC()`）を同じ 6×6 標本で
  測ったもの（`featuresInView`）に門を置く——中心の政体・視界に入る政体の数・今日と名前が違うか消えた政体があるか（`_same:0`）・国境がこの形になった日（`changeAt`。日単位の記録の
  ときだけ）・視界の大半が海か。名前は時代ラベルの層が描く名前（`_same` なら `_modName`、それ以外は `_locName`→`NAME`）。年は `IntMapHistScale.yearText`。集まりが届く前は年だけで
  成り立つ 4 文（`tail:1`）だけ。地図をクリックしたときの予約枠は「この辺りでは{年}に何が起きていた？」。
- **未ログインの読者には、押す前に言う。** 行の先頭に「Atlas には無料アカウントが要る・1 日 N 回」（N は `supabase/functions/_shared/plans.js` の無料プランの `aiTurnsPerDay` を実行時に
  読む）。例文を押すと送らず、その問いを Atlas がどう扱うかのカード（地図の状態を読む → 道具で操作する → 結果を読んでから答えを書く、「図解（実際の回答の記録ではありません）」の
  静止の図、無料枠、「ログインしてこの質問をする」——問いを入力欄に置いてログイン画面を開く）。カードは回答を見せない（`scripts/atlas-eval/cassettes/` は全部 `kind:"scripted"`）。
  ログイン画面が閉じた時点で行を引き直す（`exKey` がログイン状態を持つ）。
- **地図をクリックしたときの 3 文も同じプールから選ぶ**（`pointExamples`。`askHere` が呼ぶ。選ぶ箱はクリックされた座標の周り）。3 枠のうち 1 枠は必ず汎用の 3 文に残す。常に真の
  6 文（首都・地域・最新・近隣比較・1990年以降・天気）は落穂拾い（`tail:1`）。候補の文はすべて第1引数がリテラルの `L()`（`scripts/i18n-report.mjs` はそれ以外を捨てる）。`{place}` は
  CLDR の国名なので ru / de / fr は名前を先頭に置く同格の形。

### 進行の見せ方

- **回答中に何をしているかは、消えない一覧で見せる**（`js/atlas-progress.js`）。返答の泡の兄弟として `.atl-trace` を置き、実行器（`js/atlas-executor.js` の `on()`）の 10 段の
  ライフサイクルを購読して 1 操作 1 行を足す（済んだ行は残り、走っている行だけが輪を回す）。plan の段は `js/atlas-agent.js` の `onStep` から。行の言葉は category（レジストリ 4 列目）
  から、引数は `js/atlas-schemas.js` の引数 schema で宣言順で最初の enum を持たない文字列引数から（enum の引数は設定。名前を持たない操作の欄は空）。回答が着いたら見出しは終わり方と
  歩数（「回答しました · 3 ステップ」）になり、所要は残り、開き直せる。
- **進行を述べる場所はこの一覧 1 つだけ**（計画もその中）。一覧が見えている間は地図に何も出さず、見えないとき（サイドバーを閉じた・シートを下げた・ウィンドウを最小化した・流れて
  画面外・別の面が上）だけ地図に小さな表示を 1 つ出す（`js/atlas-live.js`。「Atlas · いまの語 · 手順 i/N」。押すと Atlas を開き一覧を見える位置へ送る。ターンが終わると約 2.6 秒で
  消える。デスクトップは地図の下中央、携帯 `IntMapDevice.COMPACT` は上端）。語は `liveWord()` を読むだけ。見えているかは実測する（矩形がビューポートにあり、祖先に透明・非表示が
  無く、見出しの中心と見えている部分の中心で `elementsFromPoint` が一覧自身を返す。ターンの間と直後だけ `everyTick` で 0.4 秒ごと）。
- **上限に達して終わったターンはそう名乗る**（`js/atlas-console.js` の `_cutNote`。Atlas が終わったと決めたのは `answered` だけで、`step_budget` / `call_budget` / `time_budget` /
  `repeated_calls` / `malformed_limit` は上限——`js/atlas-agent.js` の `CUT_STOPS` が名指す）。上限で切られたターンも、道具を渡さない最後の 1 呼び出しが transcript から答えを書き
  答えきれていない部分を名指す（`text` の有無によらない）。その事実はモデルには届かず（強制 final の指示は「上の結果が実際に起きたことだ、いま答えよ」だけ）、IntMap 自身が 1 行で
  述べる。`answered` では出さない。注記は泡の兄弟に置く。上限そのものは動かしていない（`CONSTITUTION.md` §5）。
- **いま何をしているかの 1 語**（Thinking / Reading the image / Verifying / Writing the answer、走っている操作の言葉）は一覧の見出しに出る（見出しがその 1 語で、開くと詳細な行）。語は
  ラベル自身を掃くシマー（`.atl-stage` の `background-clip:text` と透明な text-fill、帯は 2 秒、色はテーマごとの `--atl-shimmer-band`、`prefers-reduced-motion` では止めて text-fill を
  currentColor に戻す）。語を運ぶ span は使い回す。同じ行の反対の端にターンの合計時間（行が測るのは操作で、ターンの大半はその間の待ち）。`.atl-stage` は印でもある（取り消し走査と
  `markCancelled` が泡の中のこの綴りを見るので、中身が空の span を泡に残す）。`_atlCompose` が泡の `innerHTML` を書き換えるたびに `js/atlas-progress.js` の `live()` が印を戻し、
  `done()` がターンの終わりに外す。
- **Atlas の 1 手は考えているあいだから見える**（`js/atlas-live.js`。モデル呼び出しはストリームで届く）——① 推論の要約の最新の見出しを考え中の行の詳細へ、② 関数の名前が決まった
  瞬間に「次: …」を同じ行へ（行を開くのは実行器の `started` だけ）、③ 返答の JSON を届いた順に読み、先に生成される `turn` が `continuing` なら文を作業一覧の「途中の一言」行へ、そう
  でなければ回答の泡に下書きとして流す（キャレット付き）。下書きは答えではない（ループの答えが届くと `_atlCompose` が `__atlSay` で置き換える。再要求は `reset` で取り下げ、停止した
  ターンは下書きを未完と明示して残し、失敗したターンは残さない）。ループはストリームを知らない。体感の待ち時間は `window.IntMapAtlasDebug.latency()` が `firstVisible`・
  `firstThought`・`firstAnswer`・`firstCall`・`firstOp`・`firstDraw`（実行器の終端イベントの `produced`）・`answer`・`end` を ms で返す。
- **Atlas の計画は Atlas が宣言し、その状態は IntMap が観測する**（`js/atlas-plan.js`）。会話に 1 つの台帳（`makeAtlasPlan`）を `js/atlas-console.js` が持ち、`runTurn` に `opts.plan`
  として渡したときだけループは `plan` 道具を申告する（基本の道具の直後・昇格した道具より前の固定の位置）。`plan` の呼び出しは返答の中の呼び出し順にその場で台帳へ適用され（`goal`・
  `steps`・`current`）、同じ返答の後ろの呼び出しはその手順に属する。`plan` は footprint `pure` で実行器には届かない。手順の状態は観測——その手順で能力に届いた呼び出しの判定から
  導き、能力ごとに最後の試みが残り、手順は最も悪いもの（実行中 → 失敗 → 停止 → 入力待ち → 一部のみ → 観測できず → 完了）。呼び出しが無ければ「実行中」「操作なし」「未着手」。
  `unobserved` は決して完了にならない。手順に属するのはそのターンで `current` を述べたあとだけ。`plan` の結果が台帳の写しを返し、`_agentInput` が毎手の tail に `promptBlock()` を
  載せる。計画は最新のターンの作業一覧（`.atl-trace-plan`）の見出しの下に立ち（目標と「完了数/手順数」は畳んでも残る）、手順の行は一覧の行と同じ印を付ける。手順が描いたものは
  呼び出しの開始と判定の時点の `render.drawn` と `IntMapObjects` の指紋の差で見つけ、押すとその面・オブジェクト・カメラへ移る。`window.IntMapAtlasDebug.plan()` が同じ写しを返す。
  上限（`maxSteps`・`TURN_MAX_CALLS`）は読みも動かしもしない。

### 鍵・枠・台帳

- **鍵はサーバー（Edge Function）だけが持つ。** ブラウザは AI プロバイダに直接アクセスしない。モデル選択の UI も無い（利用者はモデルを選ばない）。
- **`ai-proxy`＝アカウント制AI。** `verify_jwt` に加えて関数内でもユーザーを検証し（未ログインは 401）、プラン別の1日上限を `consume_ai_turn` で原子的に消費する。上限は free 10 /
  plus 50 / pro 200 / unlimited 実質無制限。
- **消費の単位は「1 user turn」。** クライアントは `x-intmap-turn` ヘッダにターン鍵を載せ、その鍵の最初の 1 本だけが消費する。鍵は信用されない（行の主キーが `(user_id, turn_key)`、
  1 つの鍵が運べる回数 `TURN_MAX_CALLS` と寿命 `TURN_TTL_S` は Edge Function 側の定数）。上限超過は 429 `{error:"turn_calls"}`（1日上限の 429 `{error:"limit"}` とは別の文言）。
  プロバイダ失敗の払い戻しは `refund_ai_turn` が charge とターンの両方を解放する。決定論的な操作（`IntMapOS.execute()` だけで終わる依頼）は AI 枠を使わない。
- **プランで変わる値は 1 つの表**（`supabase/functions/_shared/plans.js` の `PLANS`——1 日の質問数 `aiTurnsPerDay`・用語解説数 `aiGlossPerDay`・購入できるか `offered`）。
  `ai-ledger.js` の `PLAN_LIMITS` と `ai-proxy` の `GLOSS_PLAN_LIMITS` はその列で、支援パネル（`js/supporter.js`）も同じ表を import する。import できないページの `AI_FREE_DAILY` は
  `tests/supporter-funnel-checks.test.mjs` が突き合わせる。全員が `free` で、購入できるプランは無い。
- **利用者の代わりに AI を呼ぶ経路は全部 1 つの台帳を通る**（`supabase/functions/_shared/ai-ledger.js`——`PLAN_LIMITS`・アカウントの解決 `profiles.plan` と `DEV_USER_IDS`・4 つの扉
  `consume_ai_turn` / `refund_ai_turn` / `settle_ai_turn` / `record_ai_usage`）。定期実行（cron）は消費しない。
- **枠のカウンタ（`ai_usage.count`・`ai_gloss_usage.count`）は負にならない——列の CHECK として**（負の値は上限を外し、表の所有者は grant に縛られない）。返金は課金した 1 回ぶんを
  超えず、課金した日の行へ戻る（`refund_ai_turn` がターン行を 1 文で消し、その行の `usage_date` を使う）。回数を増やすのは `profiles.plan` か `DEV_USER_IDS`。ターン鍵の無い依頼の返金
  （`refund_ai_usage`）だけは今日の行へ戻る（0 未満にはならない）。
- **費用も同じ台帳に載る。** `_shared/ai-usage.js` の `normalizeUsage` が 3 社共通の形 `{input, cached_read, cache_write, output}`（`input` はキャッシュ読み・書きを含まない）にし、1 リクエスト
  で読んだ全応答を足して `record_ai_usage` が `ai_usage`（アカウント×日）と生きている `ai_turns` 行に加える（`count` には触れない。開発者の呼び出しも記録される）。使用量を述べなかった
  応答は `unmetered_calls`。定期実行の費用は監視の所有者の行に載る。
- **用語グロスは「別の枠」で動く**（`public.ai_gloss_usage`。上限は free 60 / plus 300 / pro 1,000。両方向に独立）。どちらの枠で払うかは本文を読む前に `x-intmap-lane: gloss` で宣言し、
  本文を読んだ後に `task === "gloss"` と照合する（食い違えば払い戻して 400 `{error:"bad_lane"}`）。安いレーンは画像も web 検索も受け付けず prompt 上限は 8,000 文字。429 は
  `{error:"gloss_limit"}`。応答は `glossUsed`/`glossLimit` を名乗り、専用の写し（`aiGlossLeft()`）だけが読む（`used`/`limit` は返さない）。
- **クライアントが持っているのはサーバーの行の写し**（`js/ai-core.js` が `public.ai_usage` の当日行を写し、サーバーが送った数以外を書かない）。`ai-proxy` の 429 は 2 か所しか無く、どちらも
  `used` を載せて名乗る（`limit` / `turn_calls`）——名乗りの無い 429 はプラットフォーム側のレート制限なので写しを触らず「混雑しています（利用回数上限ではありません）」を出し、本文を
  `window._aiLast429` に残す。写しが「残り0」と言ったときは行を読み直す（`aiQuotaBlocked()`。`askAI` / `askAIEnvelope` / Atlas のターンが通る。同期の `aiGate()` は 1 回断ってから背景で
  読み直す）。規則の綴りは `aiOverQuota()` の 1 か所。

### 入力の上限とストリーム

- **入力の上限は本文を読む前に効かせる**: prompt は 24,000 文字、**system は 160,000 文字**（アプリ自身が組む操作カタログなので別枠）、画像は最大4枚・合計 12 MB。鍵・prompt・JWT は
  ログに出さない。Atlas のターンは prompt を使わず（protocol 2: `input` の item と `tools` の関数。§2.1）、上限は item ごと（`MAX_ITEM_CHARS` 96,000）と全体（`MAX_INPUT_CHARS` 480,000）
  ——クライアントの予算の 2 倍の柵。超えたら古い会話から落とし、`meta.inputTrimmed` で述べる。1 本の文字列の要求も受け、`meta.protocol` がどちらで答えたかを言う。
- **Atlas のターンはストリームで答えられる。** `stream: true`（protocol 2 の `atlas_turn` だけが送る）を受けると、`ai-proxy` は提供元にもストリームで頼み（OpenAI `stream`・Anthropic
  `stream`・Gemini `streamGenerateContent?alt=sse`）、`text/event-stream` で `open` → プレビュー（`think` / `text` / `call` / `search` / `reset`）→ `done` 1 つを返す。`done` の
  `{status, body}` はストリームなしの応答そのもので、ページ（`js/ai-core.js` の `aiReadStream`）はそれを Response に戻して従来の読み手に渡す。プロバイダの本文は 2 回読まれる
  （`supabase/functions/_shared/ai-stream.js`。届く間はプレビュー、届き切ったら非ストリームの本文へ畳み戻して既存の解析器へ）。`relay-guard.js` の `fetchBounded` は `onChunk` に渡すだけ。
  ストリームの中で提供元が述べた失敗（OpenAI `response.failed`・Anthropic `error`・Gemini の error chunk）は `classifyGemini` が分類し、終端の無いまま切れたストリームは
  `provider_unavailable`。台帳の順は同じ（消費は本文を読む前、精算は `done` の前、失敗は払い戻し）。読者が接続を閉じても提供元の呼び出しは最後まで走り記録と精算は行われる
  （`EdgeRuntime.waitUntil`）。推論の要約（OpenAI `reasoning.summary:"auto"`、Gemini `includeThoughts`）はストリームのときだけ頼み、400 の梯子の最初の段がそれだけを外す（isolate が
  覚える）。無言の間は 15 秒ごとに SSE のコメントで接続を保つ。
- **ストリームが `done` の前に切れたら、頼み直しは「再受信」である。** ページが要求ごとに再受信の鍵（`replayKey`）を付け、`ai-proxy` はその手の `{status, body}` を `done` の前に
  `public.ai_turn_answers`（鍵は (アカウント, ターン鍵, 再受信の鍵)）へ置く。切れたらページは同じターン鍵・同じ鍵を `x-intmap-replay` に載せて 1 回だけストリームなしで頼み直し、
  サーバーは ① 答えが置いてあればそれを返す（提供元を呼ばず、`consume_ai_turn` より前なので課金も `TURN_MAX_CALLS` も使わない。`charged:false`・`meta.replay {kind:"replayed"}`）
  ② 最初の要求がまだ走っていれば完了を待つ（走っている要求は SSE の心拍 `HEARTBEAT_MS` ごとにリースを更新し、リースは心拍 2 回分。死んだ要求は `abandoned`）③ 観測された失敗か
  `abandoned` のあとだけもう一度走らせる（`meta.replay {kind:"rerun", after, attempt}`。行ロック 1 つが走る 1 本を決める）。封筒の `streamReplay` はサーバーが述べた種類を運び、述べ
  なければ `unreported`。置いた答えは `TURN_TTL_S` で失効し、次の claim と 15 分ごとの pg_cron `ai-turn-answers-sweep` が消す（[`docs/DATABASE.md`](../DATABASE.md)）。台帳が答えなければ
  `meta.replay {kind:"unheld"}`。読者が押した停止は頼み直さない。

### タスク・モデル・提供元

- **責任分離** — クライアントはタスク種別と `webMode`（`off|auto|required`）を送り、`ai-proxy` がタスクごとに出力トークン上限・構造化出力・Web 方針を選ぶ。タスクは allowlist で、それ以外は
  400: `atlas_turn` / `atlas_plan` / `map_report` / `analysis` / `analysis_structured` / `free_text` / `json_extract` / `brief` / `geo_verify` / `geo_resolve` / `research_map` / `vision_read` /
  `gloss` / `atlas_grade`（正本は `supabase/functions/ai-proxy/tasks/`——1 タスク 1 ファイルで、出力上限・推論の強さ・構造化出力・サーバ所有の schema・レーン・プロトコル・採点の規則を
  述べ、`tasks/all.ts` の 1 行が登録する。`TASKS` はその一覧から導く）。出力上限は 500〜3,400 トークン（絶対上限 5,000）。OpenAI 経路の `reasoning.effort` は `atlas_turn` / `atlas_plan` /
  `analysis` / `analysis_structured` / `geo_resolve` / `research_map` / `vision_read` が medium、他は low。
- **`atlas_grade` は評価専用の独立採点**（`scripts/atlas-eval/grade.mjs`。0〜2 の 4 項目）。採点する provider はサーバが決め、Atlas に答えている provider（`AI_PROVIDER`）とは必ず別
  （`supabase/functions/_shared/atlas-grade-schema.js` の `graderProviderFor`。開発者のモデル指定は効かない）。別 provider が無ければ 503 `no_independent_grader` で払い戻す。形
  （`ATLAS_GRADE_SCHEMA`）もサーバ所有。費用は 1 回 1 use・台帳に載る。
- **構造化出力は provider にも届く。** `responseSchema`（サーバ所有の `MAP_REPORT_SCHEMA` / `ANSWER_SCHEMA` / `GLOSS_SCHEMA` / `ATLAS_GRADE_SCHEMA`、クライアントが送る `PLAN_SCHEMA` /
  `RESEARCH_MAP_SCHEMA` / `GEO_RESOLVE_SCHEMA`）は Gemini 方言（`type:'OBJECT'`）で、`strictJsonSchema()` が OpenAI の `json_schema` へ変換する（型名を小文字化、任意フィールドは
  `["string","null"]`、列挙も `null` へ広げる）。`meta.schemaAttached` が効いたかを言う。表現できない schema は梯子が `json_object` へ落とす。クライアント側の決定論的検証は残る。
- **プロバイダは `AI_PROVIDER`**（`anthropic` | `openai` | `gemini`。既定 anthropic）。OpenAI 経路のモデルは `AI_MODEL` シークレット（現行 `gpt-5.6-terra`）で、到達できない場合は
  **`gpt-5.6-sol` → `gpt-5.6-luna` の順に 1 段ずつ**フォールバックする（403/404 の model_not_found のときだけ。開発者が名指ししたモデルは代替しない）。`meta.modelServed` が実際に答えた
  モデル、`meta.model` は頼んだモデル。
- **モデルを選べるのは開発者アカウントだけ**（`DEV_USER_IDS`）。設定 → AI に provider と model の選択が出て、その口座の全ての AI 呼び出しに効き `user_prefs` で端末をまたぐ。選択肢は
  各プロバイダの目録（OpenAI `/v1/models`・Gemini ListModels の `generateContent` 対応分・Anthropic `/v1/models`）を `op:"models"` で取り寄せたもの（モデル名をリポジトリに書かない）。
  例外は取り下げ 1 つ（現行 `gpt-6-astra`。目録から除かれ、選んでいた口座の選択も次に設定を開いた時点でサーバー既定へ戻る——`js/ai-core.js`。proxy は渡された id をそのまま呼ぶ）。
  選んだモデルはフォールバックせず 403 をそのまま返す。無人の cron（ニュース取込み・WHO）は `AI_MODEL` のまま。
- **既定モデルの表は 1 本**（`supabase/functions/_shared/ai-provider.js` の `PROVIDER_DEFAULT_MODEL`）。チャットのモデルを呼ぶ 4 本（`ai-proxy`・`news-ingest`・`refresh-news`・`who-don`）が
  読み、優先順位は関数別の secret（`NEWS_GEO_MODEL` / `WHO_DON_MODEL` …）→ `AI_MODEL` → この表。無人の job は 403/404 のとき `FALLBACK_CHAIN` の最後の段へ 1 回だけ落ちる。
- **有料の提供元へは扉が 1 つだけ**（`_shared/ai-provider.js` の `providerFetch`。鍵を読む 5 本——上の 4 本と `atlas-embed`——は他の経路で要求を出さない）。① 送る前にその関数の
  プロジェクト全体の 1 日の天井 `<関数名>:global:day`（`public.relay_rate_buckets`・`relay_take`）から 1 単位を取り、DB が答えなければ送らない（fail-closed）② 天井（か受領証）を持たない
  呼び出しと提供元以外のホストを拒む ③ 期限は本文の最後のバイトまで・バイト上限（`fetchBounded`）④ 失敗は状態と長さだけを運ぶ（`providerFail`。提供元のエラー本文を運ばない）。
  1 日の数は各関数が定数の横に観測と失効条件を書いて持ち、`<関数名大文字>_GLOBAL_PER_DAY` で deploy なしに動かせる。定期実行の 2 本（`refresh-news`・`news-ingest`）の数は pg_cron の
  予定表から導く（1 日の回数 × 1 回が送りうる最大 × 2。`tests/edge-spend-and-models-checks.test.mjs`）。請求の柵であって Atlas の柵ではない。天井に当たった読者は払い戻され
  `provider_quota`（`meta.ceiling:"project_day"`・503）を受け取る。
- **`ai-proxy` の 1 日はアカウントの年齢で分けてある。** 作られて `NEWCOMER_AGE_DAYS`（7 日。`_shared/ai-ledger.js` の `cohortOf`、`auth.users.created_at`）未満のアカウントは、まず
  `ai-proxy:newcomer:day` から、次に `ai-proxy:global:day` から取る（`_shared/ai-provider.js` の `shareCeiling`）。新規の取り分は全体の 1/3（3,000 のうち 1,000。
  `AI_PROXY_NEWCOMER_PER_DAY`）で、残り 2,000 は新規アカウントが届かない。尽きた新規アカウントは `provider_quota`（`meta.ceiling:"newcomer_day"`・503）と払い戻し。作成日が読めない
  アカウントは新規。誰の上限も下げていない。
- **障害耐性** — 400 はフォールバック階段（tool_choice 解除 → schema → json_object → JSON モード解除 → ツール解除）で降格する。Web 付き呼び出しは長めの期限を持ち、空応答は予算を
  増やして1回再試行する。
- **プロバイダの失敗は分類して 502/503 で返す**（`provider_rate_limit` / `provider_quota` / `provider_malformed` / `provider_empty` / `provider_blocked` / `provider_unavailable`）。
  `ai-proxy` が返す 429 は IntMap 自身の枠専用。上流のエラー本文は返さない（コード語だけ）。
- **Web 検索は本物のときだけそう言う。** `webMode:"required"` は検索を強制し、応答の検索呼び出しの件数から `webUsed` / `webSearches` を返す（クライアントは実際に検索した時だけ
  「ライブWeb検索」と表示する）。Anthropic 経路も同じ値を返す（回数は `server_tool_use`〔名前 `web_search`〕の数と `usage.server_tool_use.web_search_requests` の大きい方、引用は
  `web_search_result_location`）——`js/atlas-agent.js` の `externalContentSeen` が立つ。
- **ニュース地点解析AI** — `refresh-news` が同じ鍵・同じ `AI_PROVIDER` 規約でサーバー側実行する（利用者の枠は消費しない）。

## Atlas は結果を「実世界オブジェクト」で返し、辿れる——地震・出来事・施設・企業・火山・地点は 1 つの型

`js/atlas-geo-object.js` の `worldObject()` が型で、`geoObject()` を呼んで種別・`ref`・範囲・時刻・記事 id・証拠 id・出典・辺・値を足す（`provenance` はそのまま運ぶ）。**`ref` は
`type:id`** で、能力・カード・次の質問が対象を名指す 1 つの綴り。

- **返す側。** `research.impact`（中心の地震または場所、半径内の施設・都市・地震。各々が中心へ `within_impact_of` の辺）・`research.events`（各出来事＝`news_event`、構成記事の id つき）・
  `data.volcano`・`news.company`（企業と、それに触れる出来事＝辺 `mentions`）・`research.placeProfile` は、結果の `exec.worldObjects`（`subject`・`objects`・`totals`）に対象を載せ、
  セッションの索引へ入れる。アダプタは記録が述べたことだけを書く（`mapped === false` の擬似座標は採らない、火山の最終噴火は年のまま、施設は時刻を持たない）。
- **辿る側。** `research.object`（`worldObject`）は ref か名前から 1 件を返す（索引に無ければ読み込み済みニュース・火山カタログ・企業アトラス・USGS 週フィードへ落ちて同じアダプタで
  書く。無い名前は「無い」）。`research.related`（`worldRelated`）は結び付いた対象を返す。
- **関係の規則。** `linked`（辺、または共有する記事 id・証拠 id）、`near`（`km` 以内か相手の範囲の内側。既定 300 km）、`concurrent`（時刻の区間が `hours` 以内。既定 72 時間）。関連 =
  `linked`、または `near` かつ（`concurrent` またはどちらかが時刻を持たない）。時刻だけでは関連にしない。理由は結果に付け、上限は設けない（`limit` は呼び手のもの。総数は常に返す）。
- **UI。** 地点カードの「関連」が同じ索引・規則・描画（`relatedGroups`）を読む。索引は `js/atlas-world-objects.js` のモジュール単一インスタンスで、ページの寿命。

### Atlas の答えが「構造」であるもの（`js/atlas-reasoning.js`）

PRODUCT.md §4 の 20 項目のうち 3 つは欄を持つ結果として返る。決めるのは `js/atlas-reasoning.js` の純関数で、能力は値を集めて描くだけ。拒むのは「空の欄を持つ答え」と「標本が支えない
言葉」だけ。

- **`research.scenario`（項目 12）** — `{model, place|lng+lat, baseline, assumptions[], impact?}` を受け、`sim.ashPlume` / `sim.radiation` / `sim.tsunami` / `sim.pandemicRun` のうち 1 つを
  そのシミュレータの能力として（`K.dispatch`）走らせ、`impact` があれば `research.impact` も走らせる。答えは必ず 4 欄——**前提**・**使用データ**・**考慮外**・**不確実性**。モデル・前提・
  対象・基準時点のどれかが空なら空の欄を全部名指して拒む。年だけの基準時点を日に変えない。`SCENARIO_MODELS` の引数語彙は各項目の schema と一致することを
  `tests/atlas-reasoning-checks.test.mjs` が測る。
- **`time.changes`（項目 8・9）** — `{from, to, place?, n?, maxDays?}`。両端を `readYear` で読み、政体の出現・消滅・面積変化、Maddison の変化、レイヤーの差を返し、期間内の出来事を影響する
  記録の数の順に並べる（国境の変化日＝出現・消滅 1・境界変化 ½、戦争＝期間内の日付つきの出来事の数）。1 月 1 日の変化日は「年だけの可能性」と印を付け、片端だけの値はゼロからの増加と
  読まない。直近 7 日にかかるときだけ `research.events` のライブのニュースを添える。調べる変化日の数には上限（既定 40・`maxDays`）があり、調べなかった数を書く。
- **`panel.correlate`（項目 10）** — パネルを開き（`x` / `y`）、パネルが描くのと同じ報告を返す: n（供給できた国数に対して）・欠損件数・Pearson r と Spearman ρ の 95% 区間・外れ値と 4 欄
  （確認できたこと／考えられる説明（未検証）／反証／限界）。n < 4 または区間が 0 に届くなら断定せず、区間の半幅が 0.2 以内なら「述べる」、それより広ければ「示唆される」。

### 時をまたぐ道のり（`time.journey`・`js/journey-through-time.js`）

1 本の線を Atlas が選んだ複数の時点で訊く能力。線は地点（`places` / `points` / `from`+`to`+`via`）の間の大圏で、`asRoute:true` なら与えた点列そのもの。時点は `years`・`dates`・`now`
を渡された順に読み、無ければ時計の瞬間（年は 6 月 15 日の正午）。

- **測り方は経路パネルの「国境」と同じ 1 つ**（標本と点包含は `js/routing-ops.js` のモジュール直下の関数を export して import する）。各時点の多角形は `js/time-borders.js` の
  `collectionAt`、今日は `window.countryGeo`。名前は年鑑の `nameIn`（`js/year-book.js`）。
- **記録が描くものだけを言う**——同じ場所に 2 つの形があれば両方を名指して `overlap`、従属政体の上の realm は `within`、名前の無い形は `unnamed`。何も無い区間は今日の陸地の輪郭で
  海と記録の無い陸地に分け、輪郭が無ければ `outside`。読めなかった時点は `failed` に理由を持つ。
- **モデルに渡すもの**（`exec.journey`）——時点ごとの記録の出典・標本間隔・区間（政体と km）・政体ごとの合計・越境点・覆われない長さ、一部の時点でだけ通る政体。比較は記録が書く名前で
  行いそう述べる。
- **地図**——1 時点（`draw`、1 始まり）を区間ごとの `LineString` で Atlas の線の層（`_hlLines` / `paintLines`）に載せ、`meta.painted.lines` で宣言する（観測器 `paint`）。時計は動かさない。
- 経路パネルの「過去の路線網 ▸ その年の国境」は計算した経路を同じ関数に訊く（`renderRoutePanel`）。史実照合は `node scripts/journey-through-time.mjs --sites`。
