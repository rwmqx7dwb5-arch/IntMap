# IntMap — Volcano Intelligence (火山の深さ)

> **火山について、この地図が何を知っていて、何を知らないか。** データ源・結合鍵・状態のはしご・
> 描くもの／描かないものの正本。
>
> - **正本**: このファイル。火山のデータ源・GVP 番号による結合・警戒レベルの段・火山灰域・
>   ハザード域・SO₂・周辺影響の扱いは、ここが唯一の記述。
> - **読む人**: 火山レイヤー、`js/volcano-intel.js`、`js/volcano-layers.js`、
>   `supabase/functions/volcano-feed`、`scripts/build-volcanoes.mjs` のどれかを触る人。
> - **更新条件**: データ源を足す・変える、段を足す、結合表を変えたとき。

## 1. なぜ作り直したか

依頼はこうだった——**「現在はGVPの完新世火山1,215座を全部入れてありますが、視覚上の主要分類は
『1950年以降』『1500年以降』『古い／不明』です。ここは恐ろしく深くできます。」**

3色は「深さについての設計判断」ではなかった。`data/volcanoes_gvp.json` は火山1件につき
**6項目（名前・国・型・標高・最終噴火年・地域）しか持っておらず、GVP 火山番号が入っていなかった**。
番号が無いということは**結合鍵が無い**ということで、噴火履歴も VEI もマグマ組成も周辺人口も
世界中のどのライブフィードも、上にどんな UI を載せても到達できない。3色は、
**そのファイルが知っていることのすべて**だった。

## 2. 何が実際に公表されているか（このラウンドで実測）

GVP の WFS（`webservices.volcano.si.edu`）は 6 つの feature type を出す。**4 つは使え、2 つは使えない。
そして「使えない」ほうも同じくらい重要な事実である。**

| feature type | 件数 | 使うもの |
|---|---:|---|
| `Smithsonian_VOTW_Holocene_Volcanoes` | 1,214 | 名前・型・地形区分・**主要岩石**・構造区分・時代・収録根拠・解説文・写真 |
| `Smithsonian_VOTW_Holocene_Eruptions` | 11,089 | **VEI**・開始／終了日・証拠方法・確認／不確実（＝噴火履歴） |
| `E3WebApp_HoloceneVolcanoes` | 1,214 | **半径 5 / 10 / 30 / 100 km の人口** |
| `E3WebApp_Eruptions1960` | 2,248 | 噴火一覧の部分集合——使わない |
| `Smithsonian_VOTW_Pleistocene_Volcanoes` | 1,452 | **観測機関が現在レベルを公表している座だけ**を取り出す（下の §2.1） |
| `E3WebApp_Emissions` | — | ⚠ **上流で壊れている**。`Invalid object name 'vrf.Emission'` を WFS 1.0.0/2.0.0 の両方・毎回返す。`DescribeFeatureType` には**今も宣言されている**ので、実際に呼ぶまで SO₂ の出典に見える |

⚠ **1,215 → 1,214。** 同梱ファイルは 1,215 件を持っていたが、上流のカタログは現在 1,214 件。
**件数はどこにもハードコードしない**——凡例も文書検査もテストも**ファイルから読む**。
6 か所に書いた数は、次にスミソニアンがカタログを改訂した瞬間に自分自身と食い違う数である。

⚠ **この表の件数は「上流が何件返すか」であって、同梱ファイルの大きさではない。**
噴火の行は 11,089 件すべてが降りてくるが、同梱されるのはそのうち §3 が述べる分だけ。
⚠ **この宣言は座数にしか適用されていなかった。** 同じラウンドで噴火の件数が 14 か所に書き写され、
そのすべてが上流の数だった（#R440）。今は噴火の側にも 3 つの門がある——
`tests/r353-checks ②`（ファイルの記載と実体）・`⑭`（コメントと出荷文字列に書かせない）・
`npm run check:docs` の `volcano-eruptions`（現行文書の数をファイルから引き直す）。

### 2.1 同梱カタログは「完新世だけ」ではない——観測機関が語っている座を足す

⚠⚠⚠ **§4 の段①は、この地図が描けない火山を名指すことがあった。**
`volcano/getMonitoredVolcanoes` は「USGS が監視している全 70 座」を返す（実測 2026-08-25）。
そのうち **5 座は完新世カタログに地物が無い**。4 座は **GVP が更新世カタログに置いている実在の火山**——
**Yellowstone**・**Long Valley**・**Coso Volcanic Field**・**Isanotski Peaks**——で、
最後に判明している噴火が完新世より前だから完新世の一覧には原理的に入らない。
残る 1 座 **Korovin** は GVP のどちらのカタログにも無い（下の §2.2）。

結果として、**USGS が毎回公表している警戒レベルを、この地図は取得してから捨てていた**。
`volcApplyStatus` はランクを**地物に書き込む**方式なので、地物が無ければ書き込む先が無い。
**専用の観測所を持つイエローストーンが、火山レイヤーに1点も出ていなかった。**

⚠ **除外一覧で塞がない**（`CONSTITUTION.md` §5）。
**観測機関が現在の警戒レベルを公表している火山は、火山地図に出るべきものである。**
そこで同梱カタログは **「GVP 完新世の全件」＋「観測機関が語っている座のうち完新世一覧に無いもの」** になった。
⚠ **後者は手で並べない。** `scripts/build-volcanoes.mjs` が**ビルド時に監視フィードを読み**、
完新世に無い番号を更新世カタログから引いて足す。GVP がどちらにも持っていない番号が出たら
**ビルドを止める**——黙って落とせば、このラウンドが見つけた状態（取得して捨てる）に戻るだけで、
しかも誰もそう言わない。

⚠ **更新世の feature type は完新世の 19 項目のうち 9 項目しか出さない。**
最終噴火年・岩石・構造区分・収録根拠・写真は無く、噴火一覧も人口レイヤーも完新世限定である。
**無い項目は推測せず null にする**（§6 と同じ規律）。カードの噴火記録タブは、
その座の**地質時代を見て**「完新世カタログに別の証拠で収録されている」ではなく
「完新世に入ってからの噴火の記録が無く、観測機関がレベルを公表しているのでこの地図にいる」と言う。

⚠ **件数と構成はファイルが持つ。** `data/volcanoes_gvp.json` は `holocene`（完新世の件数）を持ち、
凡例は `features.length` と `holocene` の**両方をファイルから読んで**構成を述べる。
レイヤー名から「完新世」の語が消えたのは #R353 が行の見出しから件数を消したのと同じ理由で、
**名前に書いた事実は自分を検査できない**。

### 2.2 USGS の番号は GVP の番号ではないことがある

`getMonitoredVolcanoes` の 70 行のうち **3 行は GVP 火山番号を持たない**（実測 2026-08-25）。

| 行 | 中身 | 扱い |
|---|---|---|
| «Alaskan Volcanoes» (AVO) | `vnum: null` | **火山ではない**——観測所全体の速報。`+null` は 0 なので、以前は**火山番号 0** という鍵が索引に入っていた |
| «Cascade Range» (CVO) | `vnum: null` | 同上 |
| «Korovin» (AVO, ak171) | `vnum: 311161` | GVP に 311161 は無い。Korovin は **GVP 311160「Atka Volcanic Complex」**の活動中の北側の火口で、GVP 自身の解説文がその名を書いている。AVO の速報の座標は 52°22′54″N 174°09′55″W ＝ GVP 311160 の点から **5.9 km** |

`js/volcano-intel.js` の `USGS_TO_GVP` が 3 つ目を結ぶ。**気象庁について `JMA_TO_GVP` がやっているのと
同じ形の結合表**で、機関自身の番号づけとスミソニアンの番号づけを突き合わせている。
⚠ **`scripts/build-volcanoes.mjs` はこの表を `js/volcano-intel.js` から読み出す**——
2 つ目の写しを持たせない（`AGENTS.md` §9）。

⚠ **AVO は Atka を 2 単位で監視している**（複合火山 ak17 と Korovin ak171）。地図の点は 1 つなので、
**同じ GVP 番号に落ちた行が複数あるときは、いちばん重いものを答えにする**（同着なら新しいほう）。
配列の並び順で決めていたら、GREEN の複合火山の陰に ORANGE の火口が隠れうる。

## 3. 同梱する2つのファイル

`scripts/build-volcanoes.mjs` が WFS から生成する。**実行時に上流へ行かない**——読者が火山を開く
たびにスミソニアンへ問い合わせるのは、相手にも読者にも失礼である。

| ファイル | いつ取りに行くか | 中身 |
|---|---|---|
| `data/volcanoes_gvp.json`（297 kB） | **レイヤーを ON にしたとき** | 地図が描く／絞り込むものだけ。`n` 名前・`c` 国・`t` 型・`e` 標高・`y` 最終噴火年・`r` 地域 ＋ **`v` GVP 番号（結合鍵）**・`k` 岩石索引・`s` 構造区分索引・`x` 記録上の最大 VEI・`q` 確認された噴火回数・`p` 半径30 km の人口。語彙（`rocks` / `settings`）と**構成（`holocene` ＝完新世の件数。§2.1）**はファイル自身が持つ |
| `data/volcano-detail.json.gz`（539 kB） | **最初に火山カードを開いたとき** | 11,043 件の噴火履歴（12項目の配列）・地質の概要・写真・4段階の人口・小地域・地形区分・時代・収録根拠 |

**火山を1つも開かない読者は後者を1バイトも払わない。1つ開いた読者は全部ぶんを1回だけ払う。**
gzip は**バイト列の先頭で判定**して `DecompressionStream` で解く（`js/gazetteer.js` と同じ理由・同じ注記）。

噴火1件の行は **12 項目**:
`[噴火番号, 開始年, 開始月, 開始日, 終了年, 終了月, 終了日, VEI, VEI修飾子, 確認1/不確実0, 証拠方法索引, 年の不確実性]`。
**月・日が 0 なのは GVP が 0 と書いたからで、1月1日に丸めない。**

## 4. 状態のはしご——現在の警戒レベル

**全世界の火山について現在の警戒レベルを述べるフィードは存在しない。** 在るふりをすると、
「地図が読める形で公表している機関が無い」が**1,150座の静かな火山**に化ける——気象警報レイヤーの
灰色斜線（[`MAP-LAYERS.md`](MAP-LAYERS.md) §7.1）が防いでいるのと同じ失敗である。
だから同じ三状態の作法を、**段に名前を付けて**適用する。

| 段 | 範囲 | 何を述べるか | 出典 | 経路 |
|---|---|---|---|---|
| ① | 米国（＋北マリアナ） | **航空カラーコード**（GREEN/YELLOW/ORANGE/RED）**と警戒レベル**（NORMAL/ADVISORY/WATCH/WARNING）、および直近1年の **VONA**。**監視対象の全体**を読むので、平常の火山も「平常と発表されている」として述べる（§7.6） | USGS HANS（`getElevatedVolcanoes` ＋ `getMonitoredVolcanoes`） | **直接**（ACAO あり） |
| ② | 日本 | **噴火警戒レベル 1–5**、レベル運用の無い火山では**発表された文言そのもの**（「入山危険」「周辺海域警戒」など） | 気象庁 `bosai/volcano/data/warning.json` | **直接**（ACAO あり） |
| ③ | 全世界 | 今週報告された火山の**活動状況**（"New Unrest" / "Ongoing Activity" …）と本文 | Smithsonian/USGS 週間火山活動報告 | **中継**（`volcano-feed?feed=weekly`） |
| ⓪ | 全世界 | **何も公表されていない**——言葉で述べる。静穏として描かない | — | — |

⚠⚠⚠ **①②③ は同じ量ではなく、1つの数に混ぜない。** 気象庁のレベル2と USGS の YELLOW/ADVISORY は
**別の機関の別の計器**である。カードは**機関自身の語彙**で、**機関名を付けて**印字する。
地図の色モードが縮約するのは**描画のための4段の重み** (`rank`) だけで、凡例がそう言う。

### 4.1 気象庁の発表単位は GVP の火山と一致しない

気象庁は**自分の単位**で発表する——「桜島」であって、それを含むカルデラ「姶良」ではない。
「樽前山」と「恵庭岳」は別々に発表されるが、GVP の項目は「Shikotsu」1つである。
だから `js/volcano-intel.js` の `JMA_TO_GVP` は**多対一を意図して**持ち、

- **カードは気象庁の単位名を示す**（気象庁がカルデラに警報を出した、とは決して言わない）
- **地図はそれを含む GVP の点を着色する**

表の右辺は、`data/volcanoes_gvp.json` の**国が Japan の 105 件**と突き合わせてある。
`tests/r353-checks.test.mjs` ④ が毎コミット再確認する——カタログ改訂で番号が消えたら、
**日本の警戒レベルが黙って地図から落ちるのではなく、ビルドが落ちる。**

## 5. 地図に描く3つのもの（`js/volcano-layers.js`）

### 5.1 火山灰域 — VAAC の advisory ではなく **SIGMET**

VAAC が出すのは整形テキストと画像である。**高度帯を持つポリゴンとしての灰の雲**は、その advisory を
受けて FIR が出す **SIGMET** に存在し、`aviationweather.gov` がそれを実座標の JSON で公表している。
実測（このラウンド）: 国際 SIGMET 127 本中 **8 本が火山灰** ——
Krakatau `SFC/FL090` 南西へ 5 kt `INTSF`、Ibu `SFC/FL070` 北東へ 10 kt。

- **描くのは航空当局が実際に発効させた区域**であって、火山のまわりの円ではない。
- ラベルは**発効させられたときの高度帯**（`SFC/FL090`）と移動方向・速度。
- ⚠ **SIGMET は有効時間中に差し替えられる。** レイヤーが見えている間 60 秒ごとに読み直し、
  **有効期限を過ぎたものは時計が落とす**（取得の失敗ではなく時計が判断する）。
- ⚠ **0 件は正常な答えである。** 応答の `read`（読んだ SIGMET の総数）が
  「世界のどこにも出ていない」と「フィードが答えなかった」を分ける。凡例が三状態を言葉で述べる。

### 5.2 ハザード域 — **データとして存在するものだけ**

火砕流・降灰・ラハールの想定区域は、**多くの火山で紙のハザードマップとしては存在し、
機械可読な GIS としてはごく僅かしか存在しない**。このラウンドで探索した結果、権威があり・鍵が要らず・
CORS を返す唯一のサービスは USGS 所有の `Volcano_Hazard_Zones` フィーチャサービスで、
**カリフォルニアの7火山地域・26 ポリゴン**（Ash / Lahars / Floods / Near-vent / Lava flows）である。

- **その7つは描く。**
- **他のすべての火山については、火山ごとに「公表されていない」とカードが述べる。**
  **推定の到達円は1つも描かない。**
  「ハザード域が描かれていない」が「ハザードが無い」と読まれてはならない。
- ⚠ USGS の区域名は**そのまま**示す。`Long Valley Volcanic Region` は USGS の作図単位であり、
  画面上でそれを GVP の火山名に書き換えると、**USGS が使っていない名前で USGS の地図を提示することになる。**
- ⚠ **1つの区域が複数の GVP 火山にかかることがある。** `Long Valley Volcanic Region` のポリゴンは
  カルデラ（GVP 323822 `Long Valley`）と `Mono-Inyo Craters`（323120）の**両方**を覆う。
  #R353 は前者がカタログに無かったので後者だけに結んでいたが、#R432 で前者も入った（§2.1）。
  片方だけに結ぶと、**もう片方のカードが「公表されていない」と言う**——USGS がまさにその名前で
  公表している区域について。だから `HAZ_TO_GVP` の値は**番号の配列**を取れる。

### 5.3 SO₂ — 衛星の全量

GVP 自身の SO₂ 放出量テーブルは**上流で壊れている**（§2）。実在する観測は衛星の全量で、
NASA GIBS が EPSG:3857 の WMS 経由で `Access-Control-Allow-Origin: *` 付きで配っている
（`js/layer-packs.js` が海氷で既に使っている扉と同じ）。
採るのは `OMPS_SO2_Upper_Troposphere_and_Stratosphere` ——**噴煙が現れる帯**であって、
境界層の工業由来のもやではない。日付はマスタークロック（`js/chronos.js`）に従う。

## 6. 「噴火様式」について——無い項目は無いと言う

**GVP のデータベースに「噴火様式」（ストロンボリ式・ブルカノ式・プリニー式…）という項目は存在しない。**
Bulletin の本文中にしかない。だからカードは、出典を示せない様式ラベルを印字しない。

代わりに、**記録が実際に持っているもの**から噴火の性格を組み立て、**どれが実測でどれが導出か**を述べる:

- その火山**自身の**噴火の **VEI 分布**（棒グラフ。件数はその火山のもので、世界の分布ではない）
- 記録上の**最大 VEI** とその年、**VEI 4 以上の回数 / VEI が付いている回数**
- **1500年以降の噴火間隔の中央値**
  ⚠ **観測時代だけから採る。** 先史時代の年代は放射性炭素とテフラ年代学で、分解能は世紀単位。
  混ぜた平均は**火山ではなく年代測定法についての数**になる。
- **主要岩石**（＝背後の SiO₂ 量が粘性を決め、溶岩流型か爆発型かに効く）と**火山型・地形区分**

## 7. 周辺への影響

| 何 | 出典 | 覆域 |
|---|---|---|
| **周辺人口** | GVP `E3WebApp_HoloceneVolcanoes` の半径 5 / 10 / 30 / 100 km | 完新世 1,214 中 1,178 座（更新世から足した座には人口の公表が無い・§2.1） |
| **空港** | OpenStreetMap `aeroway=aerodrome`（Overpass、半径150 km・3ミラーを競走） | 全世界（OSM の網羅度に従う） |
| **航空路** | 火山灰 SIGMET が名指しする **FIR**（§5.1） | SIGMET が出ている範囲 |
| **地震活動** | USGS 地震カタログ（半径50 km・直近30日） | 全世界（カタログの検知能力に従う） |
| **衛星熱異常** | 既存の熱異常レイヤー（`dl-thermal`）へカードから飛ぶ | 全世界 |

⚠ 空港と地震は**火山ごとに訊く**（背景で全火山を掃引しない）。
⚠ 「50 km 以内に地震なし」は**火山性地震が無い**という意味ではない——規模が小さく浅い地震は
全球カタログに載らないことがあり、カードがそう言う。

## 7.5 カードの「値」を9言語で言う——分類語は訳し、散文は訳さない

⚠⚠⚠ **ラベルが9言語で、値が英語だった。** 日本語で開いたカードは
「火山の型 **Stratovolcano**」「構造区分 **Subduction zone / Continental crust (> 25 km)**」
「収録の根拠 **Eruption Observed**」——左辺は全部日本語、右辺は全部英語だった。
`npm run check:i18n` は 100% を出しており、それは正しい——**あの門は表がどれだけ埋まっているかを
測る**のであって、上流の値が DOM に届くことは呼び出しではないので、**どの計器の分母にも入らない。**

### 訳すもの＝閉じた語彙

同梱データが実際に持っている値の数（このラウンドで実測）:

| 語彙 | 件数 | どこから |
|---|---:|---|
| 火山型 | 27 | `volcanoes_gvp.json` の `t` |
| 主要岩石 / 構造区分 | 10 / 10 | 同 `rocks` / `settings` |
| 地形区分 / 地質時代 / 収録の根拠 | 7 / 2 / 5 | `volcano-detail.json.gz` の `vocab` |
| 噴火の証拠方法 | 25 | 同 `vocab.evidence` |
| GVP 地域 / 小地域 | 19 / 116 | `r` / `sub` |
| USGS 航空カラーコード・警戒レベル・脅威度・観測所名 | 9 / 5 / 6 | HANS |
| 週間報告の状況語 | 7 | GVP 週報 |
| 気象庁の発表文言・変化 | 5 / 3 | `warning.json`（**鍵が日本語**） |

表は `js/volcano-intel.js` の `VOCAB`。形は **`LA(英語, 日本語, ドイツ語, ロシア語, スペイン語)`**
——`IntMapLang.pickArgs` に束縛された**呼び出し**なので i18n の計器から見え、残り4言語は
`js/locales/ui.{fr,ko,zh,zh-hans}.js` が英語文字列を鍵に持つ（他のすべての呼び出しと同じ）。
⚠ **翻訳ヘルパーを新設しない**（#R353 は arrow function のエイリアスで40件を落とした）。
⚠ **未知の値は原文にフォールバックする。** カタログの語彙は門で守れるが、ライブフィードの語彙は
守れない（USGS は明日、観測所を1つ増やせる）ので、そこでの正しい答えは**機関が言った言葉そのもの**。

⚠⚠⚠ **要求はデータから導出する。** `tests/r395-checks.test.mjs` ① は
`data/volcanoes_gvp.json` と `data/volcano-detail.json.gz` を読んで**カードが印字しうる値を数え上げ**、
それぞれに行があることを要求する。手で保つ表は「自分に何が足りないか」を言えない（#R335）ので、
**スミソニアンがカタログを改訂して28個目の火山型が現れたら、英語で出荷されるのではなくビルドが落ちる。**

### 国名は表に持たない

`Country` は文字列だが、読者の言語の国名は**プラットフォームが持っている**——`Intl.DisplayNames`
（`js/widget-core.js`・#R249「never a bundled table」）。だから表が持つのは **ISO 3166 コード**で、
名前は CLDR から来る。GVP 自身の複合はそのまま保つ:
国境上の火山は**両国を名乗り**、GVP が但し書きを付けている2件（`administered by` / `claimed by`）は
**その但し書きごと**示す——落とすと、GVP 自身が主張していない主権をこの地図が主張することになる。

### 訳さないもの＝機関が書いた散文

地質の概要（全1,218座で898,072字）・VONA の本文・週間報告の記述文・気象庁の文言は、
**語彙ではなく機関が書いた文章**である。**公表された言語のまま示し、その言語を読者の言語で述べる**
（`.volc-orig` の1行）。黙って出すと「翻訳漏れ」に見え、機械翻訳すると**観測機関の口に言葉を入れる**。
⚠ 気象庁の発表文言だけは定型句なので**訳したうえで原文を括弧で併記する**——
「レベル２（火口周辺規制）」はニュースで読者が聞く言葉であり、他の出典が引用する言葉でもある。

### 地図の側

火山灰 SIGMET のラベルの移動方向は `js/compass.js` の16方位（9言語）を通す。
ハザード域の5区分の名前は **`js/volcano-layers.js` の `HAZ_NAME` が唯一の正本**で、凡例・地図の
ポップアップ・カードの3つがそこを見る（以前は凡例だけが訳され、ポップアップは USGS の生値だった）。
⚠ **区域名（`Long Valley Volcanic Region`）は訳さない**——USGS の作図単位そのもの（§5.2）。

⚠ **カードは言語切替に追随する。** 値がレンダリング時に解決されるようになったので、
`IntMapLangSwitch.bind` で開いているカードを描き直す。

## 7.6 監視されている火山は「沈黙」ではない（#R395）

⚠⚠⚠ **①の段は、USGS が水準を公表している火山65座について「公表なし」と言っていた。**
`volcano/getElevatedVolcanoes` は**平常より上の火山だけ**を返す（実測5件）。それ以外の米国の火山は
⓪へ落ち、カードは「現在の警戒レベルを公表している観測機関がありません」と述べていた——
このファイルが真であらしめようとしている、まさにその一文である。

`volcano/getMonitoredVolcanoes` は**監視対象の全体**を同じ形で返す。同じ分の実測: **70件**、
うち **GREEN/NORMAL が65件**、そして elevated の5件は色・レベル・時刻まで**バイト単位で一致**する
（＝別の意見ではなく上位集合）。だから①は両方を読み、**elevated を先に**見る。

- **GREEN/NORMAL は「発表」である。** カードはそう述べる（日付は「その水準が最後に発表された日」）。
- 地図の `status` モードは rank 0 を**基底色とは別の色**で描く（#R353）ので、
  「機関が見て平常と言った」と「誰も公表していない」は**もともと別の色を持っていた**——
  このラウンドまで、前者に該当する火山がほとんど存在しなかっただけである。

⚠ **地殻変動（InSAR）は入れていない。** 探索の結果、COMET の火山変動ポータルは API ではなく
HTML を返し（CORS も無い）、機械可読で権威のある全球フィードは見つからなかった。
**無いものは無いと言う**（§6 と同じ規律）。

## 7.7 カタログを問いに絞る／噴火記録をマスタークロックに載せる（#R395）

**絞り込み**（凡例の中の独立したトグル・AND で合成）: `spoken`（現在の状況を公表している火山だけ）/
`elevated`（平常より上）/ `big`（VEI 4 以上を出したことがある）/ `recent`（1950年以降に噴火）。
すべて**同梱ファイルが既に持っている属性**なので、取得も推定も無い。
⚠ `spoken` は**不在の検査**（`['has','st']`）——`st` は誰も述べていない火山には**無い**。
⚠ **ハロー自身の条件は残る**（`['all', HALO_BASE, …読者の絞り込み]`）。輪は「今日、機関がこの火山に
ついて話している」という別の主張であって、読者の絞り込みがその意味を変えてはならない。

**時間軸**: `volcano.time` を入れると、地図は**マスタークロックの年に GVP が噴火中として記録している
火山だけ**を描く。索引はカードが使うのと**同じ同梱ファイル**（`data/volcano-detail.json.gz`）から作る。
⚠ **終了年が空欄の噴火を「終わっていない噴火」にしない**——GVP は「継続中」と「記録が無い」の
両方に空欄を使うので、空欄は**開始年だけ**を数える。そうしないと19世紀の噴火が以後の全年に塗られる。
⚠ **時計の下限は1850年**（`js/chronos.js`）。凡例がそう述べる——カードには記録上のすべての噴火が出る。

## 7.8 Atlas から問える（#R395）

`js/beta-overlays.js` は #R353 から `volcano.*` のカーネルコマンドを登録していたが、
**capability レジストリに火山の行が1つも無かった**——読者はボタンを押せるのに Atlas は押せない、
という「5つの一覧が食い違う」形（#R318）である。2本を足した:

| capability | legacy | 何をするか |
|---|---|---|
| `data.volcano` | `volcano` | **名前で**その火山のカードを開き、記録から答える（現在の水準と発表した機関・最終噴火・記録上の最大VEI・噴火回数） |
| `map.volcanoFilter` | `volcanoFilter` | 色モード・4つの絞り込み・時間軸を1つの操作で |

⚠ `data.layerValues` とは重複しない。あちらは「画面内に何個あるか」しか言えない——
火山の GeoJSON の properties は1文字の鍵なので、あちらの名前抽出器は何も見つけられない。
⚠ 追加は**3ファイル同時**（`js/atlas-capabilities.js` の表・`js/atlas-console.js` の dispatch・
`js/atlas-catalog-text.js` の SYS ブロック）。`scripts/atlas-capability-audit.mjs` の20問がそれを見る。

⚠ **色モードは4つ、点の大きさはどのモードでも「記録上の最大 VEI」。**
色（選んだ問い）と大きさ（爆発の規模）は**独立した2つのチャンネル**であって、1つではない。

⚠⚠⚠ **レイヤーは3つの描画を持ち、そのうち1つは黙って消えうる。** `volc2-halo`（活動中の火山に付く輪）・
`volc2-pt`（点）・`volc2-lbl`（ラベル）。MapLibre は `zoom` 式が paint プロパティの**最も外側**である
ことを要求し、**満たされていないときに throw せず、`ErrorEvent` を上げてそのレイヤーを飛ばす**。
`['*', 2.6, <zoom interpolate>]` と書いた輪は、**ローカルの検査が全部緑のまま本番から消えていた**
（本番のコンソールで発見）。だから半径のランプは**2つとも自分の top-level `interpolate`** であり、
`tests/r353.spec.js ②` は**レンダラに3つとも在ること**を訊く（ソースが何を意図したかではなく）。

⚠ **`js/volcano-intel.js` と `js/volcano-layers.js` は load-on-demand**（`js/lazy-modules.js`）。
火山をクリックするまで、あるいは3つのオーバーレイのどれかを ON にするまで**1バイトも取得しない**。
`tests/r353-checks.test.mjs` ⑨ が、遅延であることと eager 側に入っていないことの両方を主張する。
