# IntMap — Volcano Intelligence (火山の深さ)

> **火山について、この地図が何を知っていて、何を知らないか。** データ源・結合鍵・状態のはしご・
> 描くもの／描かないものの正本。
>
> - **正本**: このファイル。火山のデータ源・GVP 番号による結合・警戒レベルの段・火山灰域・
>   ハザード域・SO₂・周辺影響の扱いは、ここが唯一の記述。
> - **読む人**: 火山レイヤー、`js/volcano-intel.js`、`js/volcano-layers.js`、
>   `supabase/functions/volcano-feed`、`scripts/build-volcanoes.mjs` のどれかを触る人。
> - **更新条件**: データ源を足す・変える、段を足す、結合表を変えたとき。
> - **レイヤーの描画契約全般**は [`MAP-LAYERS.md`](MAP-LAYERS.md)、公開契約は
>   [`../Architecture.md`](../Architecture.md) §7。

## 1. なぜ作り直したか

依頼はこうだった——**「現在はGVPの完新世火山1,215座を全部入れてありますが、視覚上の主要分類は
『1950年以降』『1500年以降』『古い／不明』です。ここは恐ろしく深くできます。」**

3色は「深さについての設計判断」ではなかった。`data/volcanoes_gvp.json` は火山1件につき
**6項目（名前・国・型・標高・最終噴火年・地域）しか持っておらず、GVP 火山番号が入っていなかった**。
番号が無いということは**結合鍵が無い**ということで、噴火履歴も VEI もマグマ組成も周辺人口も
世界中のどのライブフィードも、上にどんな UI を載せても到達できない。3色は、
**そのファイルが知っていることのすべて**だった。

## 2. 何が実際に公表されているか（このラウンドで実測）

GVP の WFS（`webservices.volcano.si.edu`）は 6 つの feature type を出す。**4 つは使え、2 つは使えない。
そして「使えない」ほうも同じくらい重要な事実である。**

| feature type | 件数 | 使うもの |
|---|---:|---|
| `Smithsonian_VOTW_Holocene_Volcanoes` | 1,214 | 名前・型・地形区分・**主要岩石**・構造区分・時代・収録根拠・解説文・写真 |
| `Smithsonian_VOTW_Holocene_Eruptions` | 11,089 | **VEI**・開始／終了日・証拠方法・確認／不確実（＝噴火履歴） |
| `E3WebApp_HoloceneVolcanoes` | 1,214 | **半径 5 / 10 / 30 / 100 km の人口** |
| `E3WebApp_Eruptions1960` | 2,248 | 噴火一覧の部分集合——使わない |
| `Smithsonian_VOTW_Pleistocene_Volcanoes` | 1,452 | 対象外（このレイヤーは完新世） |
| `E3WebApp_Emissions` | — | ⚠ **上流で壊れている**。`Invalid object name 'vrf.Emission'` を WFS 1.0.0/2.0.0 の両方・毎回返す。`DescribeFeatureType` には**今も宣言されている**ので、実際に呼ぶまで SO₂ の出典に見える |

⚠ **1,215 → 1,214。** 同梱ファイルは 1,215 件を持っていたが、上流のカタログは現在 1,214 件。
**このラウンド以降、件数はどこにもハードコードしない**——凡例も文書検査もテストも**ファイルから読む**。
6 か所に書いた数は、次にスミソニアンがカタログを改訂した瞬間に自分自身と食い違う数である。

## 3. 同梱する2つのファイル

`scripts/build-volcanoes.mjs` が WFS から生成する。**実行時に上流へ行かない**——読者が火山を開く
たびにスミソニアンへ問い合わせるのは、相手にも読者にも失礼である。

| ファイル | いつ取りに行くか | 中身 |
|---|---|---|
| `data/volcanoes_gvp.json`（296 kB） | **レイヤーを ON にしたとき** | 地図が描く／絞り込むものだけ。`n` 名前・`c` 国・`t` 型・`e` 標高・`y` 最終噴火年・`r` 地域 ＋ **`v` GVP 番号（結合鍵）**・`k` 岩石索引・`s` 構造区分索引・`x` 記録上の最大 VEI・`q` 確認された噴火回数・`p` 半径30 km の人口。語彙（`rocks` / `settings`）はファイル自身が持つ |
| `data/volcano-detail.json.gz`（538 kB） | **最初に火山カードを開いたとき** | 全 11,089 件の噴火履歴（12項目の配列）・地質の概要・写真・4段階の人口・小地域・地形区分・時代・収録根拠 |

**火山を1つも開かない読者は後者を1バイトも払わない。1つ開いた読者は全部ぶんを1回だけ払う。**
gzip は**バイト列の先頭で判定**して `DecompressionStream` で解く（`js/gazetteer.js` と同じ理由・同じ注記）。

噴火1件の行は **12 項目**:
`[噴火番号, 開始年, 開始月, 開始日, 終了年, 終了月, 終了日, VEI, VEI修飾子, 確認1/不確実0, 証拠方法索引, 年の不確実性]`。
**月・日が 0 なのは GVP が 0 と書いたからで、1月1日に丸めない。**

## 4. 状態のはしご——現在の警戒レベル

**全世界の火山について現在の警戒レベルを述べるフィードは存在しない。** 在るふりをすると、
「地図が読める形で公表している機関が無い」が**1,150座の静かな火山**に化ける——気象警報レイヤーの
灰色斜線（[`MAP-LAYERS.md`](MAP-LAYERS.md) §7.1）が防いでいるのと同じ失敗である。
だから同じ三状態の作法を、**段に名前を付けて**適用する。

| 段 | 範囲 | 何を述べるか | 出典 | 経路 |
|---|---|---|---|---|
| ① | 米国（＋北マリアナ） | **航空カラーコード**（GREEN/YELLOW/ORANGE/RED）**と警戒レベル**（NORMAL/ADVISORY/WATCH/WARNING）、および直近1年の **VONA** | USGS HANS | **直接**（ACAO あり） |
| ② | 日本 | **噴火警戒レベル 1–5**、レベル運用の無い火山では**発表された文言そのもの**（「入山危険」「周辺海域警戒」など） | 気象庁 `bosai/volcano/data/warning.json` | **直接**（ACAO あり） |
| ③ | 全世界 | 今週報告された火山の**活動状況**（"New Unrest" / "Ongoing Activity" …）と本文 | Smithsonian/USGS 週間火山活動報告 | **中継**（`volcano-feed?feed=weekly`） |
| ⓪ | 全世界 | **何も公表されていない**——言葉で述べる。静穏として描かない | — | — |

⚠⚠⚠ **①②③ は同じ量ではなく、1つの数に混ぜない。** 気象庁のレベル2と USGS の YELLOW/ADVISORY は
**別の機関の別の計器**である。カードは**機関自身の語彙**で、**機関名を付けて**印字する。
地図の色モードが縮約するのは**描画のための4段の重み** (`rank`) だけで、凡例がそう言う。

### 4.1 気象庁の発表単位は GVP の火山と一致しない

気象庁は**自分の単位**で発表する——「桜島」であって、それを含むカルデラ「姶良」ではない。
「樽前山」と「恵庭岳」は別々に発表されるが、GVP の項目は「Shikotsu」1つである。
だから `js/volcano-intel.js` の `JMA_TO_GVP` は**多対一を意図して**持ち、

- **カードは気象庁の単位名を示す**（気象庁がカルデラに警報を出した、とは決して言わない）
- **地図はそれを含む GVP の点を着色する**

表の右辺は、`data/volcanoes_gvp.json` の**国が Japan の 105 件**と突き合わせてある。
`tests/r353-checks.test.mjs` ④ が毎コミット再確認する——カタログ改訂で番号が消えたら、
**日本の警戒レベルが黙って地図から落ちるのではなく、ビルドが落ちる。**

## 5. 地図に描く3つのもの（`js/volcano-layers.js`）

### 5.1 火山灰域 — VAAC の advisory ではなく **SIGMET**

VAAC が出すのは整形テキストと画像である。**高度帯を持つポリゴンとしての灰の雲**は、その advisory を
受けて FIR が出す **SIGMET** に存在し、`aviationweather.gov` がそれを実座標の JSON で公表している。
実測（このラウンド）: 国際 SIGMET 127 本中 **8 本が火山灰** ——
Krakatau `SFC/FL090` 南西へ 5 kt `INTSF`、Ibu `SFC/FL070` 北東へ 10 kt。

- **描くのは航空当局が実際に発効させた区域**であって、火山のまわりの円ではない。
- ラベルは**発効させられたときの高度帯**（`SFC/FL090`）と移動方向・速度。
- ⚠ **SIGMET は有効時間中に差し替えられる。** レイヤーが見えている間 60 秒ごとに読み直し、
  **有効期限を過ぎたものは時計が落とす**（取得の失敗ではなく時計が判断する）。
- ⚠ **0 件は正常な答えである。** 応答の `read`（読んだ SIGMET の総数）が
  「世界のどこにも出ていない」と「フィードが答えなかった」を分ける。凡例が三状態を言葉で述べる。

### 5.2 ハザード域 — **データとして存在するものだけ**

火砕流・降灰・ラハールの想定区域は、**多くの火山で紙のハザードマップとしては存在し、
機械可読な GIS としてはごく僅かしか存在しない**。このラウンドで探索した結果、権威があり・鍵が要らず・
CORS を返す唯一のサービスは USGS 所有の `Volcano_Hazard_Zones` フィーチャサービスで、
**カリフォルニアの7火山地域・26 ポリゴン**（Ash / Lahars / Floods / Near-vent / Lava flows）である。

- **その7つは描く。**
- **他の1,207座については、火山ごとに「公表されていない」とカードが述べる。**
  **推定の到達円は1つも描かない。**
  「1,200座にハザード域が描かれていない」が「1,200座にハザードが無い」と読まれてはならない。
- ⚠ USGS の区域名は**そのまま**示す。`Long Valley Volcanic Region` は USGS の作図単位であり、
  その完新世項目は GVP では `Mono-Inyo Craters` である。画面上で一方を他方に書き換えると、
  **USGS が使っていない名前で USGS の地図を提示することになる。**

### 5.3 SO₂ — 衛星の全量

GVP 自身の SO₂ 放出量テーブルは**上流で壊れている**（§2）。実在する観測は衛星の全量で、
NASA GIBS が EPSG:3857 の WMS 経由で `Access-Control-Allow-Origin: *` 付きで配っている
（`js/layer-packs.js` が海氷で既に使っている扉と同じ）。
採るのは `OMPS_SO2_Upper_Troposphere_and_Stratosphere` ——**噴煙が現れる帯**であって、
境界層の工業由来のもやではない。日付はマスタークロック（`js/chronos.js`）に従う。

## 6. 「噴火様式」について——無い項目は無いと言う

**GVP のデータベースに「噴火様式」（ストロンボリ式・ブルカノ式・プリニー式…）という項目は存在しない。**
Bulletin の本文中にしかない。だからカードは、出典を示せない様式ラベルを印字しない。

代わりに、**記録が実際に持っているもの**から噴火の性格を組み立て、**どれが実測でどれが導出か**を述べる:

- その火山**自身の**噴火の **VEI 分布**（棒グラフ。件数はその火山のもので、世界の分布ではない）
- 記録上の**最大 VEI** とその年、**VEI 4 以上の回数 / VEI が付いている回数**
- **1500年以降の噴火間隔の中央値**
  ⚠ **観測時代だけから採る。** 先史時代の年代は放射性炭素とテフラ年代学で、分解能は世紀単位。
  混ぜた平均は**火山ではなく年代測定法についての数**になる。
- **主要岩石**（＝背後の SiO₂ 量が粘性を決め、溶岩流型か爆発型かに効く）と**火山型・地形区分**

## 7. 周辺への影響

| 何 | 出典 | 覆域 |
|---|---|---|
| **周辺人口** | GVP `E3WebApp_HoloceneVolcanoes` の半径 5 / 10 / 30 / 100 km | 1,214 中 1,178 座 |
| **空港** | OpenStreetMap `aeroway=aerodrome`（Overpass、半径150 km・3ミラーを競走） | 全世界（OSM の網羅度に従う） |
| **航空路** | 火山灰 SIGMET が名指しする **FIR**（§5.1） | SIGMET が出ている範囲 |
| **地震活動** | USGS 地震カタログ（半径50 km・直近30日） | 全世界（カタログの検知能力に従う） |
| **衛星熱異常** | 既存の熱異常レイヤー（`dl-thermal`）へカードから飛ぶ | 全世界 |

⚠ 空港と地震は**火山ごとに訊く**（背景で全火山を掃引しない）。
⚠ 「50 km 以内に地震なし」は**火山性地震が無い**という意味ではない——規模が小さく浅い地震は
全球カタログに載らないことがあり、カードがそう言う。

## 8. 実装の場所

| ファイル | 役割 |
|---|---|
| `scripts/build-volcanoes.mjs` | GVP WFS → 同梱2ファイル。上流の壊れた feature type の見分け方もここ |
| `data/volcanoes_gvp.json` / `data/volcano-detail.json.gz` | 同梱データ（§3） |
| `js/beta-overlays.js`（volc2 の節） | **レイヤー本体**（eager）。4つの色モード・VEI による半径・活動中のハロー・凡例・Layers 欄の4行・`volcano.*` の5つのカーネルコマンド |
| `js/volcano-intel.js`（**遅延**・`IntMapVolcano`） | カタログの深さ・状態のはしご・気象庁の結合表・噴火の性格・地震／空港の問い合わせ・詳細カード |
| `js/volcano-layers.js`（**遅延**・`IntMapVolcanoLayers`） | 火山灰域・ハザード域・SO₂ の3レイヤーと凡例 |
| `supabase/functions/volcano-feed` | ACAO を返さない2本の中継＋サーバー側解析（§4③・§5.1） |
| `supabase/functions/_shared/volcano-parse.js` | その解析の正本。`node --test` から実応答で検査できるようにここに置いてある |
| `tests/r353-checks.test.mjs` | 同梱データ・2つの結合表・2つの解析器・遅延読み込み・中継の境界（12件） |
| `tests/r353.spec.js` | **毎プッシュの門**。ネットワークが1本も答えなくても真である2件 |
| `tests/r353-live.spec.js` | **夜間**。実際の上流に対する3件 |

⚠ **色モードは4つ、点の大きさはどのモードでも「記録上の最大 VEI」。**
色（選んだ問い）と大きさ（爆発の規模）は**独立した2つのチャンネル**であって、1つではない。

⚠⚠⚠ **レイヤーは3つの描画を持ち、そのうち1つは黙って消えうる。** `volc2-halo`（活動中の火山に付く輪）・
`volc2-pt`（点）・`volc2-lbl`（ラベル）。MapLibre は `zoom` 式が paint プロパティの**最も外側**である
ことを要求し、**満たされていないときに throw せず、`ErrorEvent` を上げてそのレイヤーを飛ばす**。
`['*', 2.6, <zoom interpolate>]` と書いた輪は、**ローカルの検査が全部緑のまま本番から消えていた**
（本番のコンソールで発見）。だから半径のランプは**2つとも自分の top-level `interpolate`** であり、
`tests/r353.spec.js ②` は**レンダラに3つとも在ること**を訊く（ソースが何を意図したかではなく）。

⚠ **`js/volcano-intel.js` と `js/volcano-layers.js` は load-on-demand**（`js/lazy-modules.js`）。
火山をクリックするまで、あるいは3つのオーバーレイのどれかを ON にするまで**1バイトも取得しない**。
`tests/r353-checks.test.mjs` ⑨ が、遅延であることと eager 側に入っていないことの両方を主張する。
