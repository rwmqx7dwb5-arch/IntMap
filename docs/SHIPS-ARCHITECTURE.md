## 1. なぜサーバーが読むのか

**#R510 まで、船舶レイヤーは BYOK だった。** 利用者ひとりずつが aisstream.io の無料キーを取得して
設定に貼り、キーが無ければ地図は「APIキーが必要です」と言って**何も描かなかった**。

これは #R341 が航空機で潰したのと同じ構造である:

- **上流負荷が利用者数に比例する**（ブラウザが1つずつ WebSocket を張る）
- **資格情報を取りに行った人にしか機能が存在しない**

⇒ `supabase/functions/ais-feed` が provider を代表して読み、全利用者へ**同じスナップショット**を配る。
**キーはこの関数の環境変数の中にしか無く、ブラウザには1バイトも渡らない。**

⚠ **BYOK の経路は取り上げていない**（`AGENTS.md` §3.1）。自分のキーを設定に入れている利用者は
**今までどおりブラウザから直接 aisstream.io を張る**——ライブの WebSocket はどんなスナップショットより
新しいし、そのキーはその人のもので、その人のブラウザにしか保存されない。
**変わったのは「キーが無いとき何が起きるか」だけ**である: プロンプトではなく、本物の船が出る。

## 2. 2つの provider は、代わりが利かない

| provider | 範囲 | 鍵 | ライセンス | 形 |
|---|---|---|---|---|
| **Digitraffic / Fintraffic** | バルト海・フィンランド海域 | **不要**（登録も不要） | CC BY 4.0 | HTTP × 2（位置・静的情報） |
| **aisstream.io** | **全球** | `AISSTREAM_API_KEY` | 利用規約に従う | WebSocket（firehose） |

**Digitraffic は「鍵が無い日でもレイヤーが空にならない」ためにある。** 実測（2026-08-31）:
位置 890 件・静的情報 854 件を2リクエストで返し、`access-control-allow-origin: *` を送る。
⚠ **gzip を受け入れない要求には 406**、`Digitraffic-User` ヘッダで名乗ることを求める——
どちらも文書化された要件であって推測ではない。
⚠ **喫水はデシメートル**で来る。AIS もカードもメートルなので 10 で割る。

⚠ **無料・鍵不要・全球の AIS は存在しない。** AISHub はデータを提供する人に配り
（adsb.lol の re-api と同じ形——[`AVIATION-ARCHITECTURE.md`](AVIATION-ARCHITECTURE.md) §4.5c）、
商用トラッカーは売っている。**他所の私的な端点を回り込んで取ることはしない。**

## 3. ⚠ WebSocket は「1回の呼び出しの中で」開いて閉じる

aisstream は WebSocket の firehose である。素朴な設計は「関数が裏でストリームを開きっぱなしにする」
だが、**それは本番で1バイトも集めない**——`EdgeRuntime.waitUntil` に渡した Promise は
**応答をまたいで生きない**（#R341 が航空機で実測し、そこに設計を賭けていた）。

⇒ `?refresh=1` の中で **開く → 数秒吸う → 閉じる**（既定 4 秒・`?ws=` で最大 20 秒）。
aisstream 自身の文書がキー1本あたり同時接続3本までと言っているので、
リフレッシュごとの短い読み取りは十分その内側にある。

### ⚠ 鍵が違うときの見え方は、繋がらないときと同じ

実測（本番と、わざと無効な鍵を入れた手元のマシン、どちらも同じ）:

```
open | sent | error | close:1006      ← フレームは1つも来ない
```

**エラーメッセージが無い**ので、外からは「aisstream が落ちている」と「この鍵を拒否している」が
区別できない。だから `x-intmap-note` が socket の顛末をそのまま出す——
`try:<form>:len<N>:<shape> | open:rs1 | sent | ... | end:<verdict>:frames<N>:pos<N>`。
⚠ **鍵の長さと形は出すが、鍵は出さない。** それが実際に問題を解いた事実だった
（保存されていた秘密は 79 文字で英数字以外を含み、aisstream が発行する形ではなかった＝値に別のものが
混ざっていた）。資格情報のダイジェストでは何も分からず、資格情報そのものは応答にもログにも
ヘッダにも出してはならない。

⚠ **秘密は trim する。** シェルやダッシュボードを通った値には、ついてきた空白がついてくる。
末尾に改行が1つ入った資格情報を持つハンドシェイクは**何も言われずに拒否**され、
それは「鍵が違う」と見分けがつかない。

### ⚠⚠⚠ 保存されている値は、資格情報そのものとは限らない（#R556）

#R510 は上の 79 文字を「aisstream が発行する形ではない＝**利用者にしか直せない**」と結論して
止まった。**その値は本物の鍵を内包していた。** 秘密は読めない（`supabase secrets list` は sha256
だけ）ので、関数自身に**値を 1 文字も出さずに形を報告させた**——長さ・文字クラス・候補の長さと形:

```
len 79 · alnum 73 / dash 2 / equals 1 / space 3
candidates: stored(79, other) · after-delimiter(40, hex)
```

⚠ **鍵を推測してはならない。値が実際に内包している候補を上流に訊く。**
候補は値から**構造だけで**導く: `stored` / `dequoted` / `after-delimiter` / `url-tail` /
`uuid` / `longest-alnum`。きれいな秘密なら最初の `stored` が当たり、他は一度も試されない。
受理された**形の名前**（鍵ではない）は共有スナップショットの `cf` に載るので、
冷えた isolate が壊れた候補を試し直して socket と時間を捨てることもない。

⚠ **受理を「フレームが来たか」で判定してはならない。** 拒否は即座に閉じられ、受理は数秒黙って
いることがある。判定は**上流が切ったかどうか**。実測:

```
try:stored:len79:other        | open | sent | error:Unexpected EOF | close   ← 拒否
try:after-delimiter:len40:hex | open | sent | （切られない）                ← 受理
```

⚠ **socket は同時に 1 本だけ。** 判定用と本読み用に 2 本開くと、キー1本あたり 3 接続の上限に
近づき、**4 本目は拒否と見分けのつかない無言**で落とされる——つまり自分の probe が、自分の
見つけた鍵を無言にする。判定と本読みは同じ socket が行い、次の候補は前が閉じるまで開かない。

### ⚠⚠⚠ aisstream のフレームはバイト列である（#R556）

**これが「船が出ない」の正体だった。** WebSocket の既定 `binaryType` は `blob` で、
`String(ev.data)` は文字列 `"[object Blob]"` になり、`JSON.parse` が投げ、`catch` が飲む。
本番実測: **15 秒で 1,224 フレームを受け取り、保持した船は 0**。
**船はずっと届いていて、ずっと捨てられていた。**

⇒ socket は `arraybuffer` を要求し、フレームは**文字列でもバイト列でも読める形で復号**する。
⚠ **ブラウザの BYOK 経路も同じ既定を持つ**ので、自分の鍵を入れた利用者も 1 隻も見ていなかった。
両方を同じ回で直した——**片方だけ直すと、説明と挙動がまた食い違う。**

## 4. 共有スナップショット

`ais` bucket（migration `20260831120000`）の `world.json`。
冷えた isolate はここから hydrate して即答できる。

⚠ **content-type は `application/json`、bucket の `allowed_mime_types` にも json が入っている。**
航空側の bucket は octet-stream しか許しておらず、#R504 の正直な `application/json` は
**415 で拒否され、書き込みだけが毎回黙って失敗した**（#R505）。この2つの事実は別ファイルに住むので、
`tests/r510` が migration と関数を突き合わせる。
⚠ **Storage は存在しない bucket への PUT に HTTP 400 + `NoSuchBucket` を返す**（404 ではない）。
404 だけを見る再試行は一度も発火しない。

⚠ **空の集合は共有スナップショットに書かない。** hydrate が届かない・provider が断る・鍵が無効、
のどれでも空になり得て、それを PUT すると**全利用者の海が同時に消え、上流障害と同じ顔をする**。

スナップショットには **provider 別の隻数 `p`** も入る。`x-intmap-coverage` は「設定されている
provider」ではなく**直近の更新で実際に答えた provider と隻数**（`digitraffic:891` の形）を言う——
鍵が拒否されている aisstream は 0 なので名乗らない。hydrate しただけの冷えた isolate も `p` から
同じことを言える。

### ⚠⚠⚠ 空の答えは 2 つの別々の事実である（#R556）

「この海に船がいない」と「ここは何も見えていない」は、**地図の上では同じ絵**になる。
#R510 はこれを**関数側で**直した（被覆は答えた provider だけを名乗る）が、ブラウザは 200 を
`if(r.ok)` で受けて**無言で空の海を描き続けていた**——トーストも注記もエラーも 0 件。

⇒ 応答は **`cov` ＝ いま保持している船の外接矩形**（`[w,s,e,n]`）を運ぶ。
⚠ **`cov` は保持している船から導く。** 地名も海域名も座標定数もコードに書かない
（[`../.agents/rules/no-ad-hoc-hardcoding.md`](../.agents/rules/no-ad-hoc-hardcoding.md)）——
provider が増えても減っても、鍵が通っても切れても、**自分で正しくなる**。
⚠ **`cov` は箱の答えではなく集合全体を describe する。** 0 隻を受け取った呼び出し側が知りたいのは
「いま探して見つからなかった範囲」ではなく「このリレーはどこまで見えるのか」だから。

ブラウザは 0 隻を受け取り、かつ視野が `cov` の外なら、理由を**1 度だけ**言う
（30 秒ごとのポーリングで催促にしない・`aisOutsideCoverage`・9 言語）。
⚠ **外接矩形は過大にしか外さない**ので、中の隙間は「被覆内で、たまたま空」と読まれる——
**実際に見えている海を「範囲外」と告げることは構造上できない。**
⚠ そして aisstream が答えているとき `cov` は世界なので、**この注記はひとりでに出なくなる。**

### ⚠ 温かい isolate も、TTL を過ぎたら自分で更新する

最初の版は「強制されたとき・何も持っていないとき・何も持たず古いとき」しか更新しなかった。
一度 build した isolate は**その寿命のあいだ同じバイト列を返し続け**、外から更新を頼むもの
（航空側の掃引のようなもの）も無い。本番で実測: 更新 1 回のあと `x-intmap-age-ms` が isolate の
寿命ぶん伸びていくだけ。**温かいサーバーで止まる「ライブ」**は、温かいサーバーの存在理由の逆である。
⇒ TTL（30 秒）を過ぎた呼び出しが**1 回分の更新（数秒）を待って**新しいバイト列を受け取る。
同時に来た呼び出しは `INFLIGHT` で 1 つの更新を共有する（aisstream は鍵 1 本あたり同時 3 接続まで
で、4 本目は**鍵が違うときと同じ顔で**断られる）。「古いものを返して裏で更新」は**応答の後に走る
仕事が無い**ので選べない（#R341）。

## 5. ブラウザ側

- 鍵がある → **従来どおり**ブラウザが直接 aisstream に繋ぐ（視野購読・`SHIPS_MIN_ZOOM` あり）。
- 鍵が無い → **30 秒ごとに `ais-feed` を1回 GET** し、`shipsData` に入れる。
  ⚠ **ズームの下限は無い。** 下限は「視野購読は全球を1つのブラウザに流せない」から在るもので、
  リレーは既に全球を持っている。
  ⚠ **しかし全球をそのまま運ばない。** 実測 1 隻あたり約 65 バイト（gzip 後）——バルト海だけの
  集合で 52 kB、全球なら数 MB を**30 秒ごとに携帯へ**運ぶことになる。だから `view` チャンネル
  （`?bbox=`）に**見ている範囲＋35% の余白**を訊き、**視野がその箱を出たときだけ訊き直す**
  （余白の内側のパンは何も要求しない。ズーム 2 未満は視野が世界なので世界を訊く）。
  ⚠ **パン時に `shipsData` を空にしない。** 従来の `moveend` ハンドラは視野購読のためのもので、その
  `else` 枝は `shipsData` を空にする——リレー経路でそれが走ると、**地図をドラッグするたびに世界が
  消える**。リレー経路はそのハンドラの**最初の 1 行**（箱を出たか見て訊き直す）だけを通る。
- 取得に失敗しても**画面は変わらない**（描かれている船は本物で、ただ古くなる）。
  ただし**何も描かれていない**利用者には理由を出す——空の海と届かないフィードは見分けがつかず、
  海についての主張なのは片方だけである。
- 凡例の出典行（`js/map-ui.js`）とカードの脚注は、鍵の有無で **aisstream.io だけ／aisstream.io と
  Digitraffic（CC BY 4.0）**を切り替える。Digitraffic を名指すのはライセンス上の義務。

**ワイヤ形式**は素の JSON の**配列**（キー名が payload になる規模なので）:
`a` が位置の行、`id` が識別の行、`t` はスナップショットの時刻、`p` が provider 別の隻数、
行の最後の数は**秒単位の age**。
⚠ **age を送るのであって時刻を送らない**のは、スナップショットの時計が読者の時計ではないから
（理由は**指示書** §22.2 ——`AVIATION-ARCHITECTURE.md` が同じものを引いている。
⚠ **リポジトリ外の文書の節番号**であって、航空の文書の §22.2 ではない。あちらは §9 までしか無い）。
