### 7.1 気象・災害警報

**「どこで／何が／どれほど危険か／情報は新鮮か」の4つに答える**（`js/world-packs.js`）。
**その機関が発令した単位で塗る。** 世界の事象フィード（GDACS）は**完全に撤廃されている**——
コードは1行も残っておらず、`tests/r273-checks.test.mjs` が**書かれていた構文**で不在を確認する。
撤廃したからこそ、**未対応国を「静かな国」に見せない**仕組みが要る（下の3状態）。

自前フィードは **13本**（下表の 12 か国 ＋ MeteoAlarm）で、MeteoAlarm が EUMETNET の残り 35 か国を運ぶ。
合計 **47 か国**。**その外側は WMO の CAP 登録簿（SWIC）**が運ぶ——下表の最終行。
さらに、**その機関の管轄がその機関の国境と一致しない**分（`ALSO`）が 8 か国・地域ある——下表の最終行の一つ上。
実測、対応 **148 か国・地域**（対応外 252 → 104）。

|---|---|---|

- **状態は3つで、見え方も3つ。**
  ⑴ **この地図がここについて何も述べていない**＝**灰色斜線**（`fill-pattern`・`wp-alert-hatch`。
  `washTier` = 0）。フィードが無い国と、フィードはあるが**まだ読めていない／読めなかった**国の両方。
  ⑵ **読んだうえで何も出ていない**＝**灰色**（国 1 枚のときは `QUIET_COL`／単位で描くときは `NONE_COL`）、
  ⑶ **発令中**＝その階級の色。
  ⚠⚠⚠ **斜線のタイルは<b>線だけ</b>で、下に灰色を敷かない。** タイルは `clearRect` から始まり、
  線が信号のすべてを運ぶ（かつては `fillRect` で灰色を敷いてから斜線を引いていたので、
  ⑴ が「灰色＋斜線」・⑵ が「灰色」になり、**斜線の国は静かな国の見え方を下に着ていた**）。
  2つの主張は**見た目として排他**でなければならない。
  ⚠⚠ **その線は<b>縁取りを持つ</b>**（`hatchCanvas()`：薄色の太い線を先に、濃い線をその上に）。
  単色の中間灰色は明るい基図では読めても、衛星画像とダークテーマではほとんど見えない。
  縁取りは線に付くだけなので**隙間は完全に透明のまま**——`tests/r293 ②` が被覆率を計算する。
  ⚠⚠ **凡例の見本はこのタイルそのもの**（`hatchSwatch()` が `toDataURL()` を読む）。
  「斜線塗がなんなのか分かるように、凡例に追加しろ」に対する行は**両モードの凡例に**あり、
  手書きの `repeating-linear-gradient` は**1つも残っていない**（かつては数値の違う2つがあった）。
  灰色（`NONE_COL` / `QUIET_COL`）は**白に少し近づけてある**——読み手の指定による。
  **「警報なし」と「データなし」は別**であり、**どちらの沈黙なのか**（未対応／順番待ち／取得不可）は
  タップした地点のカードが**言葉で**言う（見本は地図と同じ斜線）。
  パネルの `unread` は**0 に落ちなければならない数**である（実測、レイヤー投入から 80 秒で 29 → 3）。
  ⚠ この 3 状態は #R284 の 4 状態（未読＝何も描かない、`washTier` = −1）を**置き換えている**。
  −1 は「対応国まで斜線で塗るな」への答えだったが、読み手が同じ文の中で
  「まだ対応していない、**もしくはデータがまだ入っていない**ところは灰色斜線で」と指定した。
  #R284 が同時に入れた**冷たい輪番のバースト**（`COLD_CALLS`）があるので、斜線を着ている時間は
  1 分に満たない——「対応地域まで斜線で塗るな」は、**データが入った国は決して斜線にならない**という
  形で今も成り立っている。
- ⚠⚠⚠ **「発令なし」は<b>区分単位</b>で決まる。** 発令中は #R271 から発令単位で描いていたのに、
  発令なしは**国ぜんぶを覆う 1 枚の灰色**だった——警報の出た郡の隣にある静かな郡が、国の他の部分と
  区別できない。主張は単位ごとに真なので、塗りも単位ごとにする。
- ⚠⚠⚠ **「発表なし」の表現は<b>1つだけ</b>である。** 単位の灰色は**発令中の区域と同じコレクション・
  同じレイヤー**（`wp-alert` / `wp-alert-fill`）の中の、`norm` が 0 の地物であり、色は `NONE_COL` 1つ、
  不透明度は**そのレイヤーの不透明度**＝**利用者のスライダー**である。国も特別扱いしない。
  ⚠ かつては 2 つあった: 日本だけが `quietFeature()` を通って `wp-alert` に入り（`NONE_COL`・スライダーに従う）、
  それ以外は**別ソース `wp-alert-quiet-src` / 別レイヤー `wp-alert-quiet`** に入って
  `rgba(220,220,224,0.42)`・`fill-opacity` は **1 固定＝スライダーの対象外**だった。
  さらにその灰色は `wp-alert-fill` の**下**に置かれ、`UNITS` の**全単位**を（発令中の単位も含めて）
  出していたので、**発令中の区域の下にも灰色が敷かれていた**。2 つのソースは tolerance も違った
  （1.2 と 2.5）ので、同じ行政界が二通りに簡略化されて**縁が噛み合わなかった**。
  ⚠⚠ **発令が覆っている単位には灰色を出さない**（`warnMeeting` → `unitCovered` 相当の判定）
  ——単位の重心が、同じ国のどれかの発令ポリゴンの中に落ち、**その発令のほうが単位より大きい**とき。
  同一性では足りない: 自分でポリゴンを出す機関（DWD・NWS・MET Norway・CAP の `<polygon>`）の形は
  単位索引のオブジェクトではない。
  ⚠⚠⚠ **単位より<b>小さい</b>発令は、単位を捨てるのではなく単位に<b>穴</b>を開ける**
  （`warnMeeting` → `punchQuiet`）。重心が中に落ちるだけで単位を丸ごと捨てていたので、
  **その単位のうち何も出ていない部分が誰にも塗られなかった**。実測（z5・中欧・3,213 点）
  **73 点が「陸・フィードあり・何も発令なし・何も塗られていない」**。穴なので重ならない規則は
  そのまま。⚠ MapLibre は**巻き方**で外環と穴を区別する（`classifyRings`）ので、穴の巻きは
  外環と逆向きに揃える——揃えないと**塗られて**、二度塗りに戻る。
  ⚠ **単位からはみ出す発令は穴にできない**（外環と交差する内環は三角形分割が壊れる）ので、
  その単位は従来どおり捨てる。実測、はみ出した環の頂点内包率は **0.5〜0.6** に山があり
  ——MeteoAlarm のスイス・オーストリアの区域は NUTS-3 と**本当に重なっていない**——
  許容誤差では解けない。残差は z5 で **1.24%**（ほぼスイス）・z2 で **6.4%**（ほぼカナダ）。
  重なりが無くなったので、灰色と色は**1枚のレイヤー**に同居できる（配列順に描くので灰色が先）。
  ⚠ **単位はこの地図が既に持っているものだけ**——気象庁の市町村、Eurostat NUTS-3、CMA の行政区画、
  CWA の郷鎮市区、Natural Earth admin-1、**同梱の世界行政区画索引**、geoBoundaries ADM1。つまり
  **灰色に塗れる単位は、警報が出れば色を塗れたはずの単位**であり、それが灰色を「主張」にしている。
  ⚠⚠⚠ **世界の第1級行政区画は<b>1ファイルとして同梱している</b>**——`data/admin1-world.json.gz`、
  **247 か国・4,515 区分・2.38 MB（gzip）**、`scripts/build-admin1.mjs` が Natural Earth 10m を
  0.01°（≈1.1 km）で間引いて生成する。これが無かったとき、閉じた索引を持たない国は
  **geoBoundaries を1国ずつ**（0.3–2 MB × 同時2本）取りに行くしかなく、実測**95 か国が国全体の
  灰色1枚のまま**で、単位で描けていたのは 50 か国だけだった。ブラウザが払える世界 ADM1 は
  公開されていない——Natural Earth 50m は**9 か国**、同 10m は **40.7 MB**、geoBoundaries CGAZ は
  **360 MB**。だから**ビルド時に一度**間引いて配る。
  ⚠ **地図が読む索引であって、気象についての第2の意見ではない**（NUTS や国土数値情報と同じ扱い）。
  **何が発令されているか・その階級・その文言はすべて各国機関のもの**。
  ⚠ **区分の灰色は「視野」と「ズーム」で切る。** 単位の集合は貯まるので、貯まったものを全部
  publish すると視点を動かすたびにコレクションが育つ——実測、世界ズームで **6,101 区分・10.0 MB**。
  `QUIET_UNIT_Z`（= 3）未満では区分の境界線は 0.25 px で、国 1 枚と 500 枚は**同じ絵**になるため、
  国全体の灰色に戻す。持っていない国も同じく国全体の灰色（`washTier` = 1）で、パネルが
  **その差を数えて印字する**（`unitLine`）。
  ⚠ `washTier` が問うのは「**いま単位レイヤーがこの国を描いているか**」であって「形を持っているか」
  ではない（`quietSet`）——持っているが画面外の国を 2 にすると、**誰も塗らない**国ができる。
  ⚠⚠⚠ **「発令中の国」に国全体の灰色を敷いてはならない**（`drawnISO`。主張そのものが偽になる）。
  → **その国は「単位で」塗る。** ここは `washTier` の判定を変えるところではない——
  国1枚を取り下げるのは正しく、間違っていたのは**引き継ぐはずの単位レイヤーが動いていない**ことだった。
  `QUIET_UNIT_Z` は**区別が見えるか**についての床であって
  **地面が塗られるか**についての床ではないので、**発令中の国には床を適用しない**
  （`warnedISOs`）——世界ズームでもその国だけは単位で描き、発令のある単位には灰色を出さない。
  ⚠ かつては「何かを描いている国は wash しない」だけで、単位レイヤーがその国を描いていない窓
  （`QUIET_UNIT_Z` 未満・単位索引が届くまで）では**誰も塗らなかった**。実測——**同じカメラ・
  同じキャンバス・同じ標本格子で改修前後を通して**（z2・7,154 点・陸 3,404 点）
  **759 点＝22.3% → 217 点＝6.4%**〈中国 186→4・アメリカ 101→0・ブラジル 58→0〉。
  ⚠ **残差の 206 はカナダ**——ECCC は**自前の予報区ポリゴン**で発表し、この地図が持つのは
  州・準州 13 個なので、警報がその中に落ちるたびに州が消える（穴にできた分は戻り 386→206）。
  MeteoAlarm のスイス・オーストリアも同じ形である。
  ⚠ **視野の判定は publish 側と取得側で同じ箱を使う**（`paddedView`）——publish は半画面ぶん
  padding するのに取得は素の bounds を見ていたので、その差の帯にある国は
  「灰色として出されるが単位を取りに行かれない」状態になり得た。
  ⚠ geoBoundaries は**世界索引にも無かった国**にだけ、同時 2 本まで。
- ⚠⚠⚠ **対応国は<b>書き足す</b>のではなく<b>学習する</b>。** #R284 は NWS の UGC を読んで 8 か国・
  地域を手で書き足した。実測、同じ形が他にもある——フィンランドの機関は **Ahvenanmaa（オーランド、
  独自の ISO コードを持つ国）** に発令していて、そのポリゴンは既に描かれているのに、国の層は下で
  「未対応」の斜線を塗っていた。手書きの一覧は**増える日に嘘になる**（#R271）ので、
  `learnCoverage` が**描いた単位の重心**を `countryAt` に通し、自分のフィードを持たない国に落ちたら
  **その形を描いた機関がその国を担当している**と記録する。証拠はポリゴンそのもの。
  ⚠ **重心であって頂点ではない**（粗い輪郭が国境を数 km 越えても隣国を主張してはならない）。
  ⚠ **足すことしかしない**——自分のフィードを持つ国は決して割り当て直さない（「一国一ソース」）。
  ⚠ **保存しない**——いま地図にあるものから毎回導くので、発令をやめた機関は担当から外れる。
  実測、この仕組みだけでコソボとリヒテンシュタインが自動的に対応国になった。
- ⚠⚠⚠ **このレイヤーの重さは「1つのコレクションを何回貼り直すか」で決まる。** 実測（本番・対照つき・
  z4 で欧州・60 秒）: **レイヤー無し 36.5 fps / 警報オン 3.4 fps**、主スレッド遮断は 19.5 s に対し
  **49.0 s**。78 秒で `wp-alert` に **62 回**（最大 3,792 地物）貼り直していた。原因は4つあり、
  4つとも「絵は変わっていないのにやり直している」形をしている——
  ① **機関の発表一覧を全地物の文字列プロパティに入れていた**（`items:JSON.stringify(rows)`）。
     スタイルは一度も読まないのに、毎回シリアライズしてワーカーへ複製していた。→ `ROWS`（`rid` で
     引く手前側の表）へ。カードと国別凡例が読むものは同じ。
  ② **MeteoAlarm のバッチが来るたびに35か国ぜんぶを組み直していた**。→ 国ごとに組んだ結果を持ち、
     鍵（索引の顔ぶれ・その国の取得時刻・表示言語）が変わった国だけ組み直す。WMO 側も同じ。
  ③ **貼り直しの合流窓が 160 ms** で、1フレーム内の2件しか合流しない。→ `PUBLISH_MS`（貼り直しは
     多くても窓に1回・末尾）。国の薄塗り（`paintCountries`）も同じ窓に乗る。`force` は即時。
  ④ **`learnCoverage` の `countryAt` が国境の全リングを歩いていた**（CPU プロファイル実測、
     `ptInRing ← countryAt ← learnCoverage ← publishNow` で **5,562 ms**／50 秒）。国ごとの
     **バウンディングボックス**で弾き、さらに「フィードを持たない国」だけを試す。答えは変わらない。
  ⚠ 加えて、**略号ラベルの層に下限ズームが無かった**。`text-allow-overlap:false` は再タイルのたびに
  4千件の衝突判定を走らせるが、世界ズームではそのどれも読めない。→ z2.5 未満は色と輪郭が答える。
- ⚠⚠ **簡略化は<b>1つ</b>。** `wp-alert` の `tolerance` は MapLibre の既定 **0.375**（ズームごとに
  約 0.05 px の誤差）。#R297 はここを 1.2、灰色の別ソースを 2.5 に上げていたが、その別ソースが
  無くなり、単位を二度（灰色で一度・色で一度）貼ることも無くなったので、節約する相手のほうが消えた。
- ⚠⚠ **境界線の解像度は2段。** Eurostat NUTS の**床は 20M** のまま（欧州全体が画面に入るズームでは
  20M と 10M は同じ絵で、細かくすると再タイルの費用だけが増える）。`UNIT_HIRES_Z`（= 4）を越えると
  **03M**（LEVL_3・6.77 MB ＋ **LEVL_2・3.97 MB**）を取りに行き、索引を**併合**して、`mkey` が変わるので
  描かれている警報が細かい形で置き直される。
  実測サイズ: LEVL_3 = 20M 1.68 / 10M 2.58 / 03M 6.77 / 01M 28.18 MB、LEVL_2 = 20M 0.69 / 10M 1.21 / 03M 3.97 MB。
  ⚠⚠⚠ **細かい段は<b>両方の階級</b>を取る。** MeteoAlarm はイタリアだけ**州（NUTS-2）**で発表するので、
  LEVL_3 しか昇格させないと**イタリアだけ 20M に固定**される。それが実際に起こしていたのは
  **ローマ中心部が何も塗られない**という穴で、本番実測 **12.95 km × 9.48 km・格子 323 点で `wp-alert-fill`
  が 0 件**（z9 と z11 で同一＝タイル簡略化ではない）。原因は**上流の一般化**である——Lazio の内側リング
  （バチカン市国）が 20M で **0.44 km² → 73.93 km²（168 倍）**に膨らみ、歴史地区を飲み込んでいる。
  IntMap は改変していない（リングの座標が Eurostat のファイルと 9 桁一致）。**03M では 1.66 km²** に戻り、
  ローマ中心は穴の外になる。⚠ 同じ穴は 20M の LEVL_3 にもあるが、そちらは 03M が届いた時点で**自然に治る**
  ——だから症状がイタリアの形をしていた。⚠ 公開コレクション 3,384 地物・穴 94 本のうち、
  **中に何も入っていない穴はこの 1 本だけ**（他は全部、中に別の単位が入っている正当な穴）。
  ⚠⚠⚠ **日本も同じ2段にする。** 全国1ファイルの `s0001` は**1,894 市町村で 33,394 頂点＝1区域あたり
  17.6 点**しかない（実測: 千代田区 **7 点**・足立区 11・青梅市 16）。地図側の `tolerance` を下げても
  元データに無い形は戻らない。同じ配布元の **`s0010`（都道府県ごとに1ファイル）** は同じ 2021 年版・
  同じ JIS キーで、東京の共通 60 コードが **561 → 6,132 頂点（10.9 倍）**（千代田区 7→41・足立区 11→125・
  小笠原村 17→773）。全国分は 8–12 MB になるので床にはできない。
  → **`UNIT_HIRES_Z` を越え、かつ画面に入っている都道府県だけ**を `s0010` へ昇格させる（同時2本・
  `bndJSON` でキャッシュ）。⚠ **警報が出ている県だけを昇格させてはならない**——同じ境界の2つの版は
  簡略化の分だけ食い違うので、細かい県と粗い県の境に隙間が出る。**視野が触れる県は全部**昇格させれば
  その継ぎ目は画面の外になる。⚠ **昇格したら警報も置き直す**（`jpShape` が同じ索引を読む）。
  片方だけ差し替えると、細かい「発表なし」と粗い「発令中」が隣り合って #R298 が消した欠陥に戻る。
  ⚠⚠⚠ **昇格は「細かくする」だけでなく「足す」。** 全国版 `s0001` は**8市町村を丸ごと欠いている**
  （実測: 利島村・青ヶ島村・日吉津村・上島町・姫島村・座間味村・粟国村・渡名喜村。**日吉津村は離島で
  はなく米子市に囲まれた村**）。県別 `s0010` にはすべて入っているのに、合流が「床に無いキーは捨てる」
  と書いてあったため、この8つは**警報も「発表なし」の灰色も付かない穴**だった（灰色はこの索引そのもの
  から出る）。→ **床に無い行は、届いた解像度のまま索引に足す。** 実測 1,894 → **1,902** 単位。
- ⚠⚠⚠ **形の索引（②）はセッションを越えて残す。** MeteoAlarm の区域は**全部が EMMA_ID を持ち、
  1つもポリゴンを持たない**（実測、10か国 850 区域）。だから35か国は名前で置くしかなく、その名前を
  知っている索引は**同じ機関が WMO に出している形**だけ——そしてそれは毎回空から積み直していた。
  → Cache Storage（`intmap-swicgeo-v1`・7日）に**名前と形だけ**を保存し、次の訪問では読む前に適用し、
  新しく読めた形と**併合**する（増えるだけ）。⚠ 発令内容は決してキャッシュしない。
  ⚠⚠⚠ **「まだ足りないから3分後にもう一度訊く」は、HTTP キャッシュを外さないと訊けない。**
  登録簿が持っているのは**その機関がいま出している区域だけ**なので、この応答は「この分に学べる形」で
  あり、`max-age` の長さがそのまま**索引が育てない時間**になる。⑴ 取得は `{cache:'no-store'}`、
  ⑵ relay の窓は**再取得の間隔より短く**（`stale-while-revalidate` が上流を守るので、窓を縮めても
  上流への回数は増えない）。形の 7 日の保存はクライアント側の Cache Storage が担う。
- ⚠⚠ **国をクリックすると、その国の凡例がパネルに出る。** 地点のカードは「ここで何が出ているか」を
  答え続け、パネルは**その国の機関自身の階級・単位・発令中の区域・置けなかった数**を出す（`countryPanel`）。
  パネルは今どちらを出しているかを覚える（`panelISO`）——覚えないと、次に届いたバッチの publish が
  1秒後に世界の一覧へ戻してしまう（＝押しても何も起きないのと同じ）。カードを閉じると世界へ戻る。
- ⚠ **更新間隔。** tick は **10 秒**（`TICK_MS`）、輪番の再読み込み下限は **15 秒**（`MIN_AGE_MS`＝
  relay のエッジキャッシュ **15 秒**に対する下限）、冷たい輪番のバーストは 10 枠。実測、レイヤー投入から
  **45 秒で 35/35 か国・93/93 加盟**を読み終えており、そのあと増えるのは**読み込みではなく形**である。
  ⚠ **パネルが印字する間隔は `TICK_MS` から作る。** 書き写した数字（「30秒ごと」）が実装（20 秒）と
  食い違っていた実例がある。
- ⚠⚠ **表示・非表示は<b>1つの呼び出し</b>で決める。** 可視性は 3 つの別々のリストに対して 4 か所で
  設定されていて、そのどれもがスタイルが層を受け付けない瞬間に走りうる——実測、`wp-alert-fill` と
  国の 2 枚が `visibility:none` のまま、その隣の輪郭と文字だけが見えている状態になった（＝警報が
  塗り無しの細い線だけで描かれる）。`applyAlertVis()` が一族まとめて設定し、`idle` と 30 秒の tick が
  **再主張する**（起動直後に `js/map-ui.js` の保存レイヤー再適用が一度これを消すため）。
- ⚠⚠ **国全体の灰色・斜線は、発令単位の塗りの<b>下</b>に置く。** 実測、`wp-alert-fill` が style index 34、
  `wp-alert-choro` が 39——どちらも `before` を指定しておらず、薄塗りの側が後から着地するため、
  **発令中の区域の上に 42% の灰色が乗っていた**。`ensureChoro()` は `wp-alert-fill` を **名前で**
  `before` に指定する（順序が非同期の着地順に依存してはならない）。
- ⚠ **国は「発令単位で描く」か「薄塗り」かのどちらかで、両方はしない。** 置けなかった区域のために
  描画済みの国まで薄塗りすると、日本を市町村で描いたとき **1,490 のうち 11 置けないだけで全土が着色**される。
  置けなかった数は**言葉で**印字する（`placedLine`）。
- **配色は2モードで、既定は各機関の公式配色**（`localStorage['im.alertPal']`）。
  ① **各国公式** … 気象庁 `#f2e700`/`#ff2800`/`#aa00aa`/`#0c000c`（**気象庁自身のページの
  `.contents-levelNN` から読み出した値**）、中国気象局の四色予警信号、その他は CAP の黄／橙／赤。
  ② **IntMap 換算** … 読み手が指定した5色——**灰（発令なし）・黄（注意）・赤（警戒)・紫（危険）・
  黒（緊急）**。値は IntMap 自身のもの（iOS 系統色）で気象庁の表の写しではないが、**並びは同じ**
  になる。パネルは「IntMap 独自の換算であり、同じ段でも国どうしの危険度が等しいという意味ではない」
  と明示する。⚠ 色の**名前**は `tests/r293 ①` が色相と明度を計算して検査する（定数を信じない）。
  地物は `colA`（公式）と `colN`（換算）の**両方**を持つので、切替は**再取得ではなく塗り替え**。
- ⚠⚠⚠ **災害名は読み手の言語で書く。** 実測、1つの画面に「Thunderstormwarning」（墺）・「ORAGE」
  （象牙海岸）・「STARKES GEWITTER」（独）・「Mye regn」（諾）・「Baixa Umidade」（伯）・「降雨」（台）・
  「大风蓝色」（中）・「大雨」（日）・「ارتفاع درجات الحرارة」が同時に並んでいた——8言語3文字体系で、
  どれも読み手の言語とは限らない。`HAZ`（25 の災害 × 各機関が実際に書く語のパターン）が分類し、
  `L()` が設定言語で名前を出す。⚠ **勝つのは「一番早く一致した」パターンであって表の先頭ではない**——
  先頭語が災害で残りは限定だから（「Strong Wind and Large Waves」は wind、「雷雨大风」は thunderstorm、
  「rain-flood」は rain）。同着は表の順で決め、それが「VENT DE SABLE」を砂嵐に入れる。
  ⚠ **機関の言葉は捨てず、並べる。** 地物は `hzr`（機関自身の表記）を持ち、タップしたカードが
  「訳語（原語）」の形で両方出す。表に無い語は**訳さずそのまま**出す（プレースホルダに潰すほうが失う）。
  ⚠ **階級は災害名ではない**——本文が「Yellow Warning」だけの行は災害を名乗っていないので名前に使わない。
  ⚠ **表に無い語は測れる。** 実測（MeteoAlarm 35 機関 ＋ WMO 登録簿の全加盟機関、同じ分）: 異なる
  event 文字列 **163** のうち分類できなかったのは **7**。うち 2 つは仕様どおり（「Yellow Warning」＝階級だけ、
  「Other dangers」＝災害を名乗っていない）で、残る 5 つ——**Red Flag Warning**（NWS の林野火災）・
  **Meteorological risk of geological disaster**（CMA の土砂災害）・**Strong convection**（CMA の雷）・
  **rissaga**（バレアレスの気象津波）・**Small Craft Advisory**（NWS の海上）——を表に足した。
  ⚠ 言語を切り替えると `relabel()` が**取得し直さずに描き直す**（`hzr` が地物にあるので再取得は要らない）。
  ⚠⚠ **災害名の英語は、その災害だけの鍵でなければならない。** 6言語目以降（fr / ko / 中文）の索引は
  **英語の文字列で引く**ので、他の呼び出し箇所が同じ英語を別の意味で使っていると、そちらの訳が出る。
  実測: 雹を `L('Hail',…)` と書いたところ、`js/time-borders.js` に `LA('Hail','ハーイル',…)`
  ——サウジアラビアの**都市** حائل——が既にあり、4つの表はその都市で埋まっていた
  （fr《Haïl》/ ko《하일》/ 中文《哈伊勒》）。**欠落も未翻訳も無いまま、地図が都市名を災害として
  印字する**ところだった。同じ理由で `Wind` / `Fog` / `Snow` / `Heavy rain` / `Thunderstorm` も
  他の呼び出しに使われていたので、災害側は `Strong wind` / `Dense fog` / `Heavy snow` /
  `Heavy rainfall` / `Thunderstorms` という**自分の鍵**を持つ。`tests/r277 ⑩` が
  「1つの英語の鍵が2つの意味を持たないこと」を検査する。
- **種別は地図の上に文字で出る。** 区域は災害名を持ち、同じ区域に複数出ていれば `+N`。
  z5 未満は短縮形、以上は正式名。⚠ **`text-field` に `['step',['zoom'],['get',…]]` は書けない**
  （style 時に落ちてページごと死ぬ）ので **2レイヤーの `minzoom`/`maxzoom`** で表す。
  ⚠ 短縮形は**頭字語ではない**——階級語を落として災害語を残す（頭字語にすると読み手に鍵が無い）。
- **塗りは薄い。** 既定の不透明度は **0.38**（他レイヤーと同じ `_registerLayerOpacity` の**共通スライダー**が
  動かす。専用のボタンは作らない）。階級は**輪郭線**が持つので、塗りを透かしても答えは残る。
- **更新は 10 秒**（`TICK_MS`）＋タブ復帰で即時。**フィードの鮮度は4段階**——
  Fresh（≤6h）／ Delayed（≤48h）／ Stale ／ Error。⚠ これは**フィードについての語**であって、
  発表が無い機関は「静か」であって「故障」ではない、とパネルが自分で書く。
- ⚠⚠ **多国フィードは「初回読み込みの待ち行列」ではなく「輪番」である。** MeteoAlarm は1リクエスト
  6か国（relay の上限）× 2本／tick、対象は**最後に読んだ時刻が古い順**（未読が先）。35 か国を約 90 秒で
  一周する。**「まだ持っていない国」だけを候補にすると、届いた瞬間に候補から外れて二度と更新されない**
  ——実測、修正前は8分間・80回の更新で MeteoAlarm へのリクエストは**3本**で、以後は**ゼロ**だった。
  `maAt` / `swicAt` が国ごとの取得時刻を持ち、パネルの `maOldestS` / `swic.oldestS` が
  「最後に読んだのが一番古い国の年齢」を印字する（**増え続けたらそれが凍結**である）。
- ⚠⚠ **一周は「エッジキャッシュの寿命」に合わせる。** relay のキャッシュは **15 秒**なので、
  それより速く同じ国を聞いても**同じバイトが返るだけ**で上流は新しくならない。床が下がれば一周も
  速くできる: tick **10 秒** × **1リクエスト6か国 × 3本**。
- ⚠⚠ **定常の速さと「最初の1分」の速さは別物である。** 3本は正しい**定常**の速さで、正しくない
  **出だし**の速さだった——実測、レイヤーを入れて 45 秒の時点で MeteoAlarm 30/35・WMO 登録簿 78/93 で、
  世界の4分の1がまだ白いまま読み手が見ていた。まだ一度も読んでいない国はキャッシュを消費しない
  （キャッシュされたものが無い）ので、**未読が残っている間だけ 6 枠**（`COLD_CALLS`）で走り、
  一周したら 3 枠に戻る。実測、45 秒で **35/35・93/93**、未読は **26 → 1**。
  バーストは国の数で上限が決まるので、**1セッションに1回しか起きない**。
- ⚠⚠ **`busy` はラッチではなく<b>数</b>である。** 全バッチを1つの `Promise.all` に入れて1つの真偽値で
  守ると、**一番遅い国が次の tick を決める**——実測、3本にしたのに最古が 108 秒まで伸び、2本のときより
  悪化した（10 MB の上流取得が 30 秒を超えると次の tick が丸ごと空振りする）。`maBusy` / `swicBusy` は
  **飛んでいるバッチの数**で、遅い1本は3枠のうち1枠を占めるだけ。`maPend` / `swicPend` が
  「いま飛んでいる国」を持ち、二重取得を防ぐ。⚠ `maAt` は**完了時にだけ**書く（先に書くと停止が隠れる）。
- ⚠ **WMO 登録簿は「誰かに何か出ているか」を先に1回で聞く。** `?swicscan=1` は GeoServer の
  `propertyName` から**幾何列を外した**同じ問い合わせ（実測 1.53 MB・1.5 秒で全世界 4,427 区域）で、
  形を落とさずに「どの加盟国に何件あるか」を答える。形を取りに行くのはそこに出ている国だけなので、
  93 か国が**最初の tick で読み終わる**。⚠ `propertyName` に `wkb_geometry` を書き忘れると
  GeoServer は**全地物を `geometry: null` で返す**（実測、韓国 37 区域が形なしで「取得成功」した）。
- **パネルは「危険以上の警報が出ている国」から始まり、そこは1国1行である。** 〈色・国・災害（最悪順、
  入り切らない分は `+N`）・階級・区域数〉。**上限は16か国**（超過分は「+N か国」）、**1行の災害名は3つ**まで。
  ⚠ **国 × 災害で並べると1国が何行も占める**——実測、14行のうち**5行が中国**、
  4行がイタリア、2行が豪で、残りの世界は「+59」だった。⚠ **行に印字する階級はその行の階級**である
  （旧実装は国全体の最悪値を1つの災害名の横に出し、CMA の**黄色**に「Red (I)」と書いていた）。
  ⚠⚠ **一覧は IntMap 換算で `HOT_MIN`（= 3 ＝ `NORM_NAME(3)` の「危険」）以上の国だけ**を出す。
  しきい値は**1か所（`HOT_MIN`）にだけ書く**——見出し・空のときの1行・絞り込みが別々の数を言わないため。
  ⚠ **見出しは絞り込みを名乗る**（「危険以上の警報が出ている国」）。一覧でないものを「いま発表されている
  警報」と呼ぶのは、この層が何度も払ってきた「偽の見出し」である。
  ⚠ **空のときの文は「どこにも何も出ていない」ではない**——下位の階級は出ていて地図に描かれうるので、
  「いま『危険』以上に達している国はありません」と、**答えた問いのほうを言う**。
  取得先の一覧（`Source status`）とその下の `Diagnostics`（置けなかった区域）は畳んである。
  数字は**全ソースで「区域数」に統一**する。
- **押した地点の警報は別のカードに出る**（`.country-panel` ではなく `.country-popup`＝アプリ共通の詳細カード）。
  当たり判定は**描かれている地物の幾何**（`ptInGeom` / `alertsAt`）なので、答えは「日本なら市町村、ドイツなら郡、
  その他はその機関が描いたポリゴン」。⚠ **凡例は上書きしない**——タップで「いま世界で何が起きているか」が
  消えるのが旧実装で、国全体の一覧はカードのボタンから開く。同じ答えは `__wpAlerts.at(lng,lat)` でも取れる。
- `drawnISO` は**実際にソースに載った地物から毎回作り直す**（`publish()`）。「自分の単位を描いている国」は
  表ではなく**測定**である。⚠ **手書きの対象一覧を作らない**——その一覧に国が増える日に嘘になる。
- 名前の突き合わせは**両側に同じ正規化**（`_norm`：アクセント畳み・記号除去・単位語の除去）を通し、
  `_alias()` が `|` `/`・括弧つきの別綴り・**先頭の行政語**（`Prov.` / `Région de` / `Landkreis` …）を外した形・
  **`A; B; C` の各要素**を索引に入れる。`lookupUnit()` は完全一致 → 語の接頭辞・接尾辞（4文字以上）→
  **索引側の接頭辞**（＝索引の鍵が問い合わせで始まる。「Antwerp」→「Prov. Antwerpen」、
  「Viseu」→「Viseu Dão Lafões」）の順に試し、⚠ **索引側は一意に決まるときだけ**採用する
  （二つに当たる語幹はコイン投げであり、違う区域に警報を描くのは描かないより悪い）。
  ⚠ **片側だけの正規化はコイン投げ**になる。

**発令区域の形を、5段のはしごで探す**

実測、MeteoAlarm の35か国で公表 1,127 区域のうち**置けたのは 754**——373 区域が地図から静かに落ちていた
（オーストリア 86／スロバキア 59 全部／ベルギー 9 全部／クロアチア 13 全部／スペイン 64／モルドバ 42 全部）。
原因は1つで、**MeteoAlarm の CAP はそれらにポリゴンを持たず**（`<geocode>` は `EMMA_ID` だけ）、
区域名が**その機関自身の呼び名**で Eurostat NUTS の名前ではないこと——「Rijeka region」「Wien Brigittenau」
「Meseta cacereña」「Košice okolie」。

| 段 | 形の出どころ | 効く国（実測） |
|---|---|---|
| ① | CAP 自身の `<polygon>` | 英国・オランダ |
| ② | **同じ機関が WMO 登録簿に出している形**（relay `?swicgeo=<mid>`） | 墺・斯・西・波・塞・波黒・克・希・斯洛 … |
| ③ | Eurostat NUTS 2/3（＋ **その機関が英語名で呼ぶ NUTS-2 の別名表** `MA_ALIAS`） | 伊・仏・独・洪 … |
| ④ | **geoBoundaries gbOpen ADM1 → ADM2**（今日の天気に左右されない行政界） | 葡（distrito）・モルドバ（raion）・立陶宛 … |
| ⑤ | 国境そのもの（**区域名が国名のときだけ**） | 塞浦路斯 |

はしごの効き目は**数えられる**。実測、MeteoAlarm の35か国で **965 / 1,127**。
⚠⚠ **② は「いま発令中の区域の形」しか返さないので、その機関が静かな日には空になる。** 実測（同じ分）:
墺 112・波 126・西 86・斯 54 の形が返る一方、**葡 0・モルドバ 0・洪 0・伊 0・白 0**——だから
モルドバは **0 / 42**、ポルトガルは **1 / 18** しか置けていなかった（＝機関が発表しているのに国が真っ白）。
→ ②の索引は**セッション中ためる**（後から来た形は**併合**であって置き換えではない）、
空で返った機関は**一定時間後に聞き直す**、そして④が**天気に依存しない行政界**を持つ。
実測（同じビルド・同じ手順）: **2,737 / 2,923 → 2,877 / 2,961**（欠落 186 → 84）。
モルドバ 0→32 / 42、ポルトガル 1→17 / 18、リトアニア 7→10 / 11、伊 18→19 / 20。
残りは国ごとに「置けた数／公表数」を**言葉で**印字する（丸めない）。
⚠ ④ は **`media.githubusercontent.com/media/…` から読む**。`raw.githubusercontent.com` は
Git-LFS の**ポインタ**（実測 131 バイト・`version https://git-lfs…`）を返し、`github.com/…/raw/…` は
CORS ヘッダを返さない。media ホストだけが実体を `Access-Control-Allow-Origin: *` で返す
（実測、ポルトガル 595 KB・373 ms）。**ADM2 が無い国は 404**（実測、モルドバ・モンテネグロ）で、それは
握り潰さずフォールバックとして扱う。⚠ ④ は **④ より上が答えられなかった区域にだけ**効かせる——実測、
希と白は既存の段のほうが良い（希 10/16 対 3/16）。出典・ライセンスは `js/reference-data.js`・
`js/legal.js`・sources ページに記載（CC BY 4.0）。
⚠ **② は「第2の警報ソース」ではない**——`?swicgeo=` が返すのは **区域名と形だけ**（event も severity も
時刻も入っていない）。何が発令されているかは今もその国のフィードが答えるので、**一国一ソース**は保たれる。
⚠ **② は有効期限で絞らない。** 警報は期限切れになるが、その警報を描いた郡は期限切れにならない。
⚠ 座標は小数4桁（約 11 m）に丸める——実測、オーストリアの生データは 1.5 MB、要約後 1.07 MB。

**出典の言葉で読む**

- ⚠ **気象庁のコード表は気象庁のものを置く。** `JMA_CODE` は気象庁自身の警報ページが持つオブジェクトから
  取った「コード → 要素 ＋ **レベル**（20/30/40/50）」で、**階級はレベルだけ**から決める
  （コードの数値範囲から決めてはならない）。⚠ 指定河川洪水予報の表は混ぜない（コードが衝突する）。
  検証は出典自身の言葉で行う（`headlineText` の文言と要素名が一致するか）。
- ⚠ **現在の状態は「官署ごと・速報種別ごとの最新1件」。** `r8` は**種別ごとに1行**を持つ現況スナップショット
  であって履歴ではない（実測: 287行 / 58官署 / **1組につきちょうど1行**）。`dataTypeCode` は災害の系統で、
  1官署が **VPWW55 大雨系・56 土砂系・57 高潮・58 風・59 波浪・61 雷/濃霧/乾燥** をそれぞれ独立に出す。
  各行はその系統について、その官署の**全 class20 を「発表なし」まで含めて**列挙する。
  だから**種別を鍵に含めずに「官署ごとの最新1件」にすると、系統1つを残して残り4つを捨てる**。
  ⚠ **古い行を捨ててはならない。** 再発表されていない系統は「その系統は変わっていない」という意味である
  （実測: 14日より古い41行のうち**発表中の項目を持つものは0**）。
  最新が 72 時間より古ければ **throw** する——これは「このフィードが生きているか」の判定であって、
  「全系統が新しいか」ではない。
  ⚠⚠⚠ **同じ速報の中では `class20Items` が `class10Items` に勝つ。** 1つの速報は一次細分区域
  (`class10Items`) と市町村 (`class20Items`) を**両方**載せている。区域の行をその中の全市町村へ配ると、
  **同じ速報が「発表警報・注意報はなし」と書いている市町村まで塗る**——実測、青森 020010 津軽は 19 市町村
  のうち **14 が「なし」**、名瀬 460040 奄美地方は 13 のうち 7 が「なし」で、**合わせて 21 市町村が
  何も発令されていないのに塗られ**、宮古郡多良間村は2階級高く塗られていた。
  → **区域の行が埋めるのは、その速報自身が名前を挙げていない市町村だけ**（「区域の注意報でその町が
  空白に見える」のを防ぐという元の意図はそのまま残る）。
  ⚠ 気象庁自身のマップも区域と市町村を混ぜない——**class10 は z4–7、class20 は z8–11 の別レイヤー**で、
  一方を他方へ配ることはしない。実測、この規則にしたあと気象庁の表示と**塗りすぎ0・塗り漏れ0・
  階級違い0**で一致する。
- ⚠⚠⚠ **同じ「形」を12本のローダ全部に当てた結果**（「機関が名指していない範囲を塗る」）:
  - **カナダ (ECCC)** — `status_en:"ended"` を**印字するだけでフィルタしていなかった**。実測
    **159件中35件が解除済み**（マニトバ州インターレイクの14自治体が連続）。→ 落とす。
    他のローダは既に落としている（HKO の `CANCEL`・INMET の `encerrado`・relay の CAP `msgType:cancel`）。
  - **中国 (CMA)** — `alertid` が自分の区・県にも `slice(0,4)+'00'` の地級市にも当たらないとき、
    **省まで繰り上げて省全体を塗っていた**。実測 `500157 重慶市両江新区` → **重慶市 82,400 km² 全域**
    （名指された範囲の約69倍）。省直轄県級行政区（`429004`・`469001`・`659001`）も同じ経路に落ちる。
    → **省の段を廃止**し、置けないものは `UNPL` に数える。⚠ 地級市の段は残す（DataV の
    `100000_full_city` は477単位で**県を1つも含まない**ので、県級の発表には元から形が無い。
    実測 941件の内訳＝区146・市794・省1）。
  - **米国 (NWS)** — 実測 **281件中201件 (71.5%) が `geometry:null`**（UGC 区域コードで発表され、
    形はクライアント側が持つ）。黙って捨てたうえで `PLACED.USA=[80,80]`＝「全部置けた」と印字していた。
    → **分母に数え `UNPL` に立てる**。⚠ これは描けるようにする変更ではない（UGC の区域索引が要る）。
    「発表なし」ではなく「置けなかった」と言うようにしただけ。
  - **香港 (HKO)** — 地物を1つも作らないローダなのに `PLACED.HKG=[1,1]` だった。→ `[0,1]`。
  - **ヨーロッパ (NUTS)** — 警報は 03M へ昇格するのに `UNITS[iso]` が 20M のままで、34か国で
    **警報＝細かい形／隣の「発表なし」＝粗い形**という縁の食い違いが残っていた（#R298 が消した欠陥の
    ヨーロッパ側）。→ 昇格時に単位も作り直す。日本側の規則（「昇格したら警報も置き直す」）の裏返し。
  - **オーストラリア (BoM)** は変えていない。1件の警報を `a.states` の全州へ配るので、実測
    1つの川の1区間の洪水警報が **NSW（80.1万 km²）と VIC（22.7万 km²）の全面**を塗るが、BoM は
    州より細かい単位で発表しておらず、この地図もオーストラリアの州より細かい境界を持っていない。
    ＝**機関自身の単位**であって、上書きしている細かい主張が存在しない。
- ⚠ **全フィードが自分の時計を持つ。** `seenAt(feed, iso)` が**そのペイロードの一番新しい時刻**を記録し、
  パネルが機関ごとに年齢を印字する。**年齢は常に印字する。**
  ⚠ **有効期間は発表時刻ではない**——CAP の `onset`/`expires` は有効期間なので、`seenAt` は未来を拒否し、
  リレーの `fetchedAt` を使う。
- ⚠ **上流の「悪い日」より短い制限時間は、生きたフィードをランダムに落とす。** 上流の期限は 45 秒＋1回の
  リトライ。投げっぱなしのローダには**自前の in-flight ガード**を持たせる（`Promise.all` する側の
  `busy` は自分しか守らない）。
- ⚠ ライブ取得は全て `cache:'no-store'`（付けないと定期タイマがキャッシュを読み直す）。
- ⚠ **遅いフィードを `Promise.all` に入れない。** 公開される地物は「待ち合わせた分＋各ローダが着地させた分」を
  1か所（`publish()`）で組み立てるので、遅いフィードが早いフィードを白紙にできない。
- タップは `grouped()` の3段（admin-1 → sub → 市区町村）。同じ災害の組合せを持つ市区町村は1行にまとめる
  （**markup にも予算がある**）。
- ⚠⚠⚠ **CORS が開いていることと、「本番のオリジンから読める」ことは別である。** 中国の行政区画
  （DataV.GeoAtlas）は `Access-Control-Allow-Origin: *` を返し、**同時に hotlink を防いでいる**——
  実測、同じ秒・同じ URL で `Referer: http://127.0.0.1:4277/` は **200 / 569 KB**、
  `Referer: https://rwmqx7dwb5-arch.github.io/IntMap/` は **403**。ローカルのプレビューでは
  見えないので、中国が 127.0.0.1 では 223 区画描かれ、本番では `PLACED.CHN = [0, 1217]` になった。
  → **relay 経由で読む**（relay は Referer を送らない）。`?cngeo=` は境界データなので**1日**のエッジキャッシュ。
- ⚠ **公開フィードが見つからない国は、灰色斜線で「データなし」と言う。** 空の地図に「平穏」を含意させない。
- **「対応国をどこまで増やせるか」は測れる。** 実測（同じ分）: WMO の加盟表に ISO コードを持つ加盟機関は
  **198**、そのうち WMO 自身が「CAP 実装 Completed」と記録しているのは **139**——この地図はその全部を
  読んでいる（自前フィードの国を含めて **140**）。残りは **Development 37 ／ Not started 20** で、
  **登録簿の全球スキャンに1件も現れない**（実測、スキャンに出た 37 機関はすべて Completed）。
  つまり **「CAP を出しているのに読んでいない加盟機関」は 0 である。**
  ⚠ 加盟表の外を足すには、その機関が**機械可読で、発令単位ごとに**出していなければならない。
  実測（12機関を叩いた結果）: 印 IMD **401**（IP 制限）／土 MGM **500**（Not allowed）／墨 **500**／
  南ア **404**／泰・尼・越・智・亜・以 **404 または 403**／新 SGP はデータ無し。
  唯一答えたのは **馬 MET Malaysia**（`api.data.gov.my/weather/warning` · 200 · JSON）だが、
  中身は**散文**で（「over the waters of Pahang • Terengganu • Northern Sarawak」）、
  `<area>` も geocode もポリゴンも無い——**出典が分けていないものを地図が分けてはいけない**ので、
  これを区域に切り出すのは実装ではなく捏造になる。よって**足していない**。
- ⚠⚠ **MeteoAlarm の「緑」は警報ではない。** CAP の `parameter[awareness_level]` が `1; green; Minor` の行は
  「注意の必要なし」で、**発表中の警報ではない**。実測、イタリアの 474 件のうち **201 件が緑**、ベルギーは
  フィード全体（10 区域）が緑だった——`severity` だけを読むと緑が `Minor`/`Moderate` として警報の色になる。
  ⚠ **災害名の文字列で代用してはならない**：イタリアは event に色名を書くが、オーストリアは書かない
  （`Thunderstormwarning` 796 件、すべて awareness 2）。階級は **2/3/4 → CAP の 1/2/3**、緑は**落として数える**
  （relay が `green` を返し、黙って消さない）。

### 7.2 レイヤー欄の分類

**レイヤー欄は右サイドバー（タイル）ひとつだけ。** `Layers` ボタンは `IntMapLayerSidebar.toggle()` しか
呼ばない。携帯では同じタイル盤が「Map & layers」シートに載る。**「どちらのレイヤー欄を使うか」という
設定は無い。**

⚠ **`#layer-dropdown` という要素は残っていて、それは UI ではなくレジストリである。**
このアプリのレイヤーの**チェックボックスは全部この要素の中にいる**——右サイドバーのタイルは
`rowsFromDropdown()` がこの要素を歩いて組み立てるし、レイヤープリセット・Atlas のレイヤーカタログ・
不具合報告・共有リンクも同じ要素を数える。だから要素は残り、**常時 `display:none`**（表示させる
`.show` クラスは存在しない）。**新しいレイヤーの行はこれまでどおりここに追加する。**

`js/data-layers.js` の `GROUPS` が **18 の棚に 136 行**を配る。`GROUPS` に無い行は末尾の
**「Others」**と**「ベータ」**へ自動的に掃かれる（ベータは削除ではなく1段下の棚）。

- ⚠ **1つの id は1つのグループにしか書けない。** `order.push` は要素を**移動**させるので、2箇所に書くと
  最後のグループにしか出ない。`tests/r271-checks.test.mjs` が全 id の一意性を検査する。
- ⚠ **全グループキーは9言語すべてに見出しを持つ**こと（同テストが検査する）。
- ⚠ **行が0のグループはキーを残す**（保存済みセッションや共有リンクが名指しできる。描画はされない）。
- ⚠ **`lyrGrpOthers` のキーは変えない。** `js/map-ui.js`（タイルのベータ判定）と `js/layer-dropdown.js`
  （携帯での折りたたみ）が名指しで使っているので、改名すると携帯でベータ節が畳まれなくなる。
- **基本表示カテゴリ**（地名・国境・**海岸線**・州県境・道路・鉄道・グリッド・国情報）に**昼夜の表示**
  （`dl-nightside`）が入る。これは「地球のどちら側に太陽があるか」という常設のビュー切替であって
  レイヤーではないので、`_refreshActiveLayers()` の `skip`、`window._imActiveLayerCount`、
  `js/widgets.js` の `FEAT_IDS`（ルーレット）のいずれにも入れない。
  ⚠ 常設スイッチへ移した行は `placed` にも入れること（入れないと掃き出しでベータにも現れて二重になる）。
- **海岸線・湖岸線**（`cb-coast` → `js/coast-line.js`）は**国境線と全く同じ手法**で描く：
  同じ `ofm` ベクタソース・同じ `BORDER_COLOR`・同じ `BORDER_WIDTH`／`BORDER_CASING`・同じ「黒縁を線の下に」の対。
  違うのは `source-layer` だけ（`boundary` → `water`）で、**海のポリゴンの輪が海岸線、湖のポリゴンの輪が湖岸線**
  ——1つの幾何なので1レイヤーが両方に答える。`swimming_pool` は除く。
  ⚠ **タイルの継ぎ目は出ない**（実タイル復号：切断は extent 4096 に対し −64 / +4160 ＝バッファ内で、
  タイル境界に乗る線分は 0。MapLibre のステンシルがバッファを捨てる）。
  ⚠ **既定は OFF、<b>風レイヤーか気温レイヤー</b>を点けたとき1回だけ提案する**
  （`window._imCoastAuto` のラッチ）。ラッチであることが「既定」と「連動」を分ける——消した読み手を
  次の点灯で覆さない。⚠ **気温だけで、他の 8 つのラスタには広げない**——理屈は同じでも、
  指示が名指ししたのは気温である。
- **行 id の接頭辞**は `rowFor()` が知っている必要がある（世界データ層 `wp-dl-`、施設層 `fac-dl-` など）。
- **分類の規則は1つ——レイヤーは、それが測っている主題に属する**（作った計器でも、対象の場所でも、
  出てきた表でもない）。
- ⚠ **過去の指示で beta へ降格されたものを、勝手に昇格させない**（「beta」は品質の判断、分類は主題の判断）。

### 7.5 地図の初期化・基図・投影

- **初期化**：`map = new maplibregl.Map(...)`。`renderWorldCopies` は投影／自由パンに応じて切り替える。
  基盤は CARTO / Esri のラスタ ＋ OpenFreeMap のベクタ（`ofm`）。
- **基盤切替**：`btn-view-map/sat` と `applyTheme()` ＋ `_reassertBase()`（スタイルロード競合に強い
  ポーリング再適用）。⚠ `applyTheme` は `styledata` を同期で発火しうるので**再入禁止フラグ**を持つ。
- **投影**：Flat (mercator) / Globe。3D 地形は terrarium DEM（複数ホストで並列取得。携帯は maxzoom 13）。
- **タイルの密度はバイトで言う**：`maxTileCacheSize` は 512² のタイルを前提に決める（256² 前提の枚数を
  そのまま使うとメモリが4倍になる）。
- **衛星タイルは `imapsat://` プロトコル**（`js/sat-proto.js`）。@2x の綴じ合わせは「無い画像」に払わない
  ——z10 近傍ごとに `have`（実画像が見えた最深）と `stop`（次の段が灰色だと**観測された**最深）を
  **別々に**持ち、止めてよいのは `stop` だけ。記録は**訊かれたタイル**に対して行う（祖先に対してではない）。
  観測は `window.IntMapSatProto.depth/wouldStitch/hiDPI`。
- **粗い地球全体の衛星ベース**：`js/world-base.js` が同梱の正距円筒画像から `imapworld://` で低ズーム
  衛星タイルを**ネットワーク無しで**生成し、`layer-sat` の下に敷く。
- **極冠 (±85.0511°〜±90°)**：Mercator にそこのタイルは存在しないので、`layer-polar-cap`
  （スタイル配列の先頭に宣言された `background`）が**どのベースマップでも**敷かれる。
- **背後の星空・太陽・月**：`js/space-sky.js`。ダークテーマ ＋ globe ＋ 自前の空を持たないエンジンのときだけ、
  `#map` の**下**の `#space-canvas` に実カタログの星（`data/stars.bin`）と実位置の太陽・月を描く。
  月は満ち欠けを描く（照射率・明縁の位置角・明暗境界楕円・地球照）。太陽は周縁減光した円盤＋光冠＋コロナ。
  数値は `window.IntMapEphemeris` から来る（テクスチャではない）。
- **大気の縁**：`js/limb-layer.js`。`js/theme-sky.js` の `_sunElevAtCentre()` は
  ⑴ 衛星写真でなければ `null`（標準マップに大気は出さない）、⑵ **昼夜表示がオフなら 90°**
  （`_aimSun()` がカメラ中心の真上へ向けた光の読み戻し）、⑶ それ以外は実際の太陽高度を返す。
  ⚠ **「モードをオフ」は「その量が不明」ではない**——`null` を返すとアプリ自身の大気がそもそも点かない。

### 7.6 ラベル

- **地名ラベル**：`ensurePlaceLabels()` が `ofm` の `place` レイヤから `ofm-country` / `ofm-city` /
  `ofm-other` を生成する（冪等）。`cb-names`（既定 ON）で表示。
  ⚠ **市区町村より下の階層は `ofm-other`**：`village` / `suburb` / `hamlet` に加えて
  `borough` / `quarter` / **`neighbourhood`** / `isolated_dwelling` / `farm`。
  綴りは **`neighbourhood`**（OpenMapTiles のスキーマ値。US 綴りは1件もマッチしない）。
  クラスを3段に分け、`['step',['zoom'],1, 13,2, 14,3]` で開く。⚠ **段は整数**
  （`['zoom']` はフィルタ内では整数ズームでしか再評価されない）。
- **地方行政区分ラベル**：同じ `place` レイヤの `state` / `province` クラスから `ofm-admin1`。
  ここでの `rank` は**面積で世界規模にそろった順序**なので、ズームの階段は国別ではなく rank 別。
  ⚠ **色は「その区分を描いている線の色」**＝`js/border-style.js` の `ADMIN1_COLOR` を**そのモジュールから
  読む**ので、破線とラベルが食い違わない。⚠ ハローは**両基図で暗色**にする（コントラストはハローの仕事）。
  ⚠ **クリック／ホバーの一覧に入っている**（地図の上では都市名と見分けがつかないので、答えないラベルは
  壊れた機能である）。4つの一覧（レイヤー別クリック・カーソル・厳密ヒット・パディング付きタップ）は
  `PLACE_LBL` / `ALL_LBL` から**導出**するので、片方だけ更新できない。
- **ポップアップは名前を2つ出す**：「現地名（地図がそう描いた名前）」。`showPopup(…,{title})` は
  **見出しだけ**を差し替え、`name`（コピー・Wikipedia 照会・AI ブリーフ・境界検索が使う識別子）は
  タイルの `name` のまま。2つ目の名前は `applyLabelLang()` が `text-field` を組むのと**同じ**
  `OSM_NAME_KEYS(lang)`（`window.IntMapOsmNameKeys`）から求めるので、言語一覧は1つしかない。
- **細かい地名ラベルの範囲ハイライト**：`IntMapOutline.fetchPolygon` は Nominatim を**2段**で引く。
  ① クリック地点の ±0.06°・`bounded=1` ＝結果をその近傍に**限定**、② 見つからなければ ±8° の viewbox
  （ヒントであって限定ではない）。⚠ 順序が本体（±8° は再ランクするだけなので、細かい地名は同名の有名地に
  枠を奪われる）。⚠ ポリゴンが存在しない place ノードには**何も描かない**（点に長方形を被せない）。
- **水域・地形ラベルと河川**：`geo-sea` / `ofm-water` / `ofm-water2` / `ofm-river` / `ofm-peak` は
  クリックでポップアップ（面が無いので「この地域だけ」「移動」は出さない）。
  **`ofm-river` だけは、その河川を線でハイライトする**。選び方は `js/river-course.js`：
  **名前の集合**（`name`・`name:xx`・`name_xx`・`int_name`・`alt_name` を正規化）を作り、
  **共有する名前で推移的に**タイル内の `waterway` 区間を繋ぐ。⚠ **1つの名前で比較してはいけない**
  （河川は国境ごとに改名され、`name:en` だけが共通という形が普通）。
  そのうえで `course()` が OSM に実流路を訊く（Nominatim →（駄目なら）Overpass）。
  ⚠ **タイルのハイライトを先に描き、それを取り上げない**（取得は後から届き、届かないこともある）。
  ⚠ `course()` が受け取るのは「押された区間」ではなく**閉包そのもの**（全名前・範囲・代表点）。
  ⚠ 門は「クリックからの 40 km」ではなく「**すでに一致しているタイル区間のどれかからの 40 km**」。
- **ポイント地物はタイル直描画／ラベル線地物は初見ピン留め。** 見えているアンカーを「改善」目的で動かさない。
- **ラベルのサイズ**：全レイヤーが `window.IntMapLabelScale`（`js/label-scale.js`）から取る。
  地名以外は必ず地名の基準の 0.88 倍以下。
- **施設・店舗名**：同じ `ofm` の `poi` レイヤから `ofm-poi`（テキスト）＋ `ofm-poi-dot`（点）。z14 〜、
  `rank` の窓をズームで開き、`symbol-sort-key` で衝突順も同じ順序にする。`cb-poi`（既定 OFF）。
- ⚠ **閉じる × は U+00D7 ひとつに統一する。** 実測 `measureText` 16px で **U+2715 は Inter・Noto Sans JP・
  system-ui・sans-serif・Arial の全部で 13.07px**（＝どれも持たず記号フォント落ち）、**U+00D7 は
  10.59/16.00/10.95/16.00/9.34**（＝Inter が持っている）。定義は `window.IntMapClearGlyph()` ただ1つで、
  `tests/r273-checks.test.mjs` が js/ と css/ の**全ファイル**を掃く。位置は**それが属する入力欄の矩形**から
  決める（`top:50%` は位置指定の祖先に解決されるため、包み箱と入力欄の高さが違うとずれる）。

### 7.7 レイヤー個別の注意

- **年降水量**（`dl-annprecip` / `js/precip-annual.js`）— **平年値**は CHELSA V2.1 bio12（30秒角 ≒ 1 km、
  1981–2010）をメルカトルに再投影したもの、**年別**は GPCC Full Data Monthly V2022（DWD、0.5°、
  陸上の雨量計解析）の 1981–2020 を1枚に縦積みしたもの。**色は16段の帯**（連続ランプではない——
  色から範囲へ正確に戻せる）。数値の読み出しは絵を読まず `data/precip-mm.png`（8bit の log(mm)）を読む。
  ⚠ **格子と帯と色は `data/precip-mm.json` / `data/precip-year.json` から読む**（JS 側に写さない）。
  ⚠ 海の上で雨量計解析は何も言わないので、陸だけを塗る。
- **GIBS ラスタ** — 各プロダクトの**実配信期間**は `data/gibs-range.json`（範囲外 404・範囲内 200 を
  二分探索して実測したもの）。⚠ NDVI はローリング窓、土壌水分は配信終了済みのものがある——
  「今日−2日」を既定にすると**何も描かない**日ができる。⚠ 2層同時に切り替えるときは、
  フラグではなく**飛んでいる Promise を共有**する（2つ目が「まだ着かない答え」を `null` として受けない）。
- **宇宙基地・地上局**（`js/osm-facilities.js`）— 同梱スナップショット `data/osm-space.json`（14,965件）と
  ライブ Overpass を **id で合成**する（ライブがスナップショットを上書きすると、ズームで件数が減る）。
  外交公館も同じ形。⚠ 疎な集合は「視野内 Overpass」では答えが出ないので、全球スナップショットを同梱する。
- **宗教・言語のポップアップ**は棒グラフ＋**データの年**を出す。
  ⚠ **出典が分けていないものを地図が分けてはいけない**（自由文の括弧を採るのは限定された語のときだけ）。
  ⚠ **出典が分けているものを地図がまとめてはいけない**（旧ユーゴの4標準は別々の分類）。
- **GDP 成長率は発散配色**（0 ＝ 白・負 ＝ 赤・正 ＝ 青・0 について対称）。
- **データセンター層**は表示範囲の集計を**レイヤー自身の凡例**に出す（浮くポップアップにしない）——
  「この点は何か」は浮き、「表示範囲に何があるか」はレイヤーの答えである。
- **貿易フロー**の矢印は軸（`wp-trade-arc`）・頭（`wp-trade-tip`）・相手国名を**一式**で切り替える。
  軸は頭の base で終わる（`trimEnd` / `line-cap:'butt'` / `icon-anchor:'top'`）。
  ⚠ 切る長さは**画素**なので**レンダラの投影に訊く**（`GE().coords.project`）。メルカトルのメートルは
  画面中心でしか合わない。`moveend` で作り直す。

### 7.8 地形と水

`js/terrain-water.js`。

- **DEM の穴は「地面が無い」ではなく「キャッシュに無い」かもしれない。** 判定の閾値は**物理**で置く
  （−12,000 m ＝ チャレンジャー海淵の下・符号化の最小の上）。穴に当たったら終わりにせず
  **ピラミッドを1段降りる**。残った穴は**数えて印字**する。
- **basin の拡張は DEM タイルのブロック単位**（`growBasin`）。LRU に丸ごと収まる大きさで読み、
  `null` は1回だけ再試行する。⚠ セルの密度で温めると、広い basin ではタイルの大半が未要求のまま残り、
  未取得タイルの矩形の辺で水が止まる。
- **新しい水源を置いても、既にある水はリセットされない。** 作業矩形の外を押したときは
  `padsToReach()` → `extendToPoint()` が**盆地を広げて**そこに届く（`sim.grow` は水深をそのまま運ぶ）。
  予算 `basinMaxCells()` を超えるときだけ `rebuildAround`（＝リセット）に落ちる。
  Atlas の `addSource()` も同じ経路を通る。
- **リセットは1本の関数**（`resetTerrainNow()`）。⚠ **「この関数を通れ」という注記が2本あったら、
  通らない道を無くす番**である（`editDirty()` を呼ばない経路を作らない）。
- **ツールは4つ**——盛る・削る・堤防・ダム・**水源**。一行の帯に出るのは短い語で、`modeName()` が正式名を持つ（キャプション・Atlas・検査が同じ関数を読むので、二つがずれない）。
- **`cont` / `rate` は水源自身の属性**（最後に置いた水源だけを太らせない）。継続の水源は緑＋輪、
  1回きりは青い点。
- ⚠⚠⚠ **1回きりと継続の差は「水が出続けるか否か」だけである。** どちらも**流量を持つ蛇口**で、
  `feedTaps(dt)` が**両方**に `rate × dt` を注ぐ。違うのは `cap`（＝出し切る総量）が有限か `Infinity` かの
  1点で、`owed(x) = cap − m3` が 0 になったら止まる。`m3` は**これまでに出した量**（両方とも）。
  ⚠ 旧実装は1回きりを `pool()` で**最初から静止した湖**として置いていたので、置いた瞬間に
  `simMoving()` が偽 → `canPour()` が偽 → **▶ が無効・↺ を押しても再生できない**という状態になっていた。
  ▶ は「まだ出し切っていない水源がある**か**、水がまだ動いている」ときに有効。
- ⚠⚠⚠ **その差は「量」と「速さ」の2つの数で、m³/s の箱は<b>1つ</b>である。** 旧実装は
  「1クリックの水量 m³」「注水量 m³/s」「流量 m³/s」の**3つ**を並べていて、後ろ2つは**同じ量**だった——
  `placeSource` が `rate:(flowM3s!=null?flowM3s:pourRate)`、`srcRate` が `pourRate` に落ちる、つまり
  1つの数に2つの操作子があった。いまは `pourRate` **1本**（`setRate()` が唯一の書き手で、置いてある
  水源すべての `rate` も同時に動かす。Atlas の `setFlow()` も同じ関数を通る）と、1回きりだけが持つ
  `srcM3`（総量）。⚠ **パネルが割り算を自分でする**——「1クリックで合計 X m³ を、毎秒 Y m³ の速さで
  出します（シミュレーション時間で約 Z）」を2つの箱の下に印字するので、2つの数が**何をするのか**が
  読める。継続では総量の箱ごと消え、「止めるまで出し続けます」と書く。
  ⚠ この文の鍵は**静的な文字列**でなければならない（`L('One click pours '+n+…)` は英語の引数を自分で
  組み立ててしまい、6言語目以降の索引は**英語の文字列で引く**ので永久に一致しない）。`{v}`/`{r}`/`{t}`
  を後から差し替える。
- **水は届くまでに時間がかかる**（`js/water-dynamics.js`）——浅水方程式の局所慣性形＋q 中心化、
  マニング n。閉じた形の答えで検証してある（等流水深・静水で max|q|＝0・質量保存）。
  ⚠ **予算は実時間の上限で持つ**（格子が育つとステップの値段が変わるので、ステップ数は予算にならない）。
- **パネルは1本の列。** `.tw-body` は `scrollbar-gutter:stable`、スクロールバーの幅は `_squareColumn()` が
  **実測**して `.tw-head` / `.tw-foot` の `padding-right` にインラインで書く
  （⚠ **インラインの padding にスタイルシートは勝てない**）。
  ⚠ **寸法は1か所の宣言**（`TW_FS`/`TW_FS_S`/`TW_FS_H`/`TW_ROW`/`TW_CTL`/`TW_IN`/`TW_PAD`/`TW_GAP`/`TW_INSET`）で、
  **端末クラスで2組**ある——デスクトップは**他の凡例と同じ寸法**（本文 11 px・行 30 px・操作 28 px）、
  携帯は指の寸法（12 px・44 px・36 px）。⚠ 44 px は iOS のグループ化リストの行高で、**デスクトップの
  凡例の列では他のどの行の3倍近く**になる（実測、警報凡例は本文 10.5 px・行 13〜16 px）。
- **ツール選択は上部に<b>一行で</b>ピン留めされる。** `.tw-tools` は `.tw-body` の**兄弟**（`.tw-foot` と
  同じ作り）で、head → tools → body → foot の順。⚠ **`position:sticky` はスクローラの中では効かない**
  ——ピン留めは CSS ではなく **DOM の親子関係**である（不均衡な `</div>` 1個でピン留めが黙って失われる）。
  スクロールバー幅は `.tw-head` / `.tw-tools` / `.tw-foot` の3枚に配る。
  ⚠ **ピン留めするのは「切替」だけで、設定は流れる。** 実測、`.tw-tools` は 591.7 px のパネルのうち
  **131.7 px**（「ツール」見出し 17.7 ＋ 2×2 の選択 58 ＋「着色」チェック 31.3）を占めていた——
  ピン留めする要素は正しかったが、**3行あった**。いまは `grid-template-columns:repeat(4,1fr)` の
  **1行 46.7 px**で、着色チェックは本文（「表示」）へ移した。
  ⚠ 4つの**正式名**は 306 px に入らない（実測）ので、帯には短い語を出し、正式名は `title` と、
  そのツールが開くパラメータ欄の見出し（`modeName()`＝**唯一の宣言**）に出る。
- **計算解像度は読み手が選ぶ**（`RES_D=[384,512,768,1024]`・既定 **512**・`im.twRes` に保存）。
  解像度の変更は `build({keep:true})` で**同じ作業矩形のまま**作り直す。セル寸法と格子数はパネルが印字する。
- ⚠⚠⚠ **標高のレベルは「作業矩形」から選ぶ。カメラからではない。** 作業矩形は `MAXKM`（60 km／携帯 26 km）で
  切られるので、切る**前**の視野で `_demZoomForSpan` を呼ぶと格子より粗い DEM を読むことになる——実測、
  カメラ z6 で矩形 47.2 km・セル 92 m のところ **DEM は z10（124 m 標本）**で、**格子より粗い地面**を
  読んでいた。矩形から選べば z13（15.5 m）。`viewKm`（視野）と `spanKm`（矩形）は別の名前を持つ。
- ⚠ **ツールを開くことは「地図を動かせ」という要求ではない。** `open({lng,lat})` はその点が**画面外のときだけ**
  カメラを動かし、**ズームは変えない**。旧実装は `zoom: max(現在,11)` で飛んでいたので、z6 で開くと z11 に
  なった（`js/map-ui.js` のツール行は**カメラの中心そのもの**を渡す）。矩形は `build({center})` で直接狙う。
- **↺ 再生**は時計・水・各水源の供給量を 0 に戻し、**同じ地形と同じ水源のまま** t=0 から流す。
  `m3` は「これまでに出した量」なので**両方の種類とも 0 に戻す**——それが再生そのものである。
  ⚠ `editDirty()` を通すこと。⚠ **⏭（静止まで進める）も蛇口に注ぎ続ける**（`settle({onStep:feedTaps})`）——
  注がない静止状態は「置いた水の一部の静止状態」でしかない。
- パネルは他の浮遊ウィンドウと同じ帯にいる（`registerWindow`）。開く位置は `placeClear()` が
  **地図を覆っているものの矩形を実測**して決める（サイドバーは開閉するので定数にできない）。
  読者が動かした後は動かさない。

⚠ **津波シミュレーターにボタンは無い。** 地震シミュレーターが震源（規模と深さ）を持ってから渡す

⚠ **どの行も `mod` にモジュール名を持ち、そのモジュールは `isOpen` と `close` を答えられる**
（行のハイライトと2度押しでの解除がそれを読む）。

**地震波（`js/seismic.js` ほか）**

- **初動の等時線は、破壊速度 Vr ≤ 波速 V であるかぎり厳密に震央中心の円である。**
  `t(x) = min_k( off_k/Vr + dist(k,x)/V )` の括弧が常に ≥ 0 だからで、これは改善できる近似ではなく物理。
  だが有限の破壊が持つ境界は**2つ**あり、もう一方は円ではない:

  ```
  T_first(x) = min over k ( off_k/Vr + dist(k,x)/V )    ← 円（定理）
  T_last (x) = MAX over k ( off_k/Vr + dist(k,x)/V )    ← 断層の形が出る
  ```

  その間が「いま揺れている」**帯**で、`T_last − T_first` は継続時間そのもの。破壊が向かった側では
  狭く（＝指向性）、背後では広い。⚠ **後端に枝刈りを掛けてはいけない**——最大値に勝てないとして
  捨てられる点こそが、最小値を決める点である。⚠ 点震源では両境界が一致するので**帯は描かれない**
  （長さが無ければ到達時刻は広がらない）。
- **場址項は周波数の関数**（`js/seismic-site.js`）。上位 30 m を Vs30、その下を CRUST1.0 の実層構造と
  した速度柱から `A(f)` を積分する。⚠ 高周波の極限は 1/4 波長を 30 m で1点評価した従来値と厳密に一致し、
  変わるのは**その下の周波数だけ**＝盆地効果。⚠ 速度反転は作らない（Vs30 を下回らないようクランプ）。
- **破壊は1枚のすべる矩形ではない**（`js/seismic-subfault.js`）。k⁻² すべり／**総モーメント厳密保存**／
  破壊時刻 |r−r_hypo|/Vr／ライズタイムは公表式。位相は断層形状を種にした決定的生成なので、
  **同じ断層なら常に同じすべり分布**になる。
- **その土地の分類は測って決める**（`js/earth-structure.js`）。同梱の CRUST1.0 / Slab2 / PB2002 から
  interface / intraslab / active-crustal / stable-continental を判定し、**区分ごとに公表された
  パラメータ一式**を返す。⚠ 幾何減衰の折れ点は**その土地の Moho 深さ**に比例させる。
  ⚠ **出典が確認できない係数は書かない**（出典のない閾値はファイル冒頭に明記してある）。
- ⚠ **地域限定の補正に依存しない。** 検証は観測から作る（`scripts/build-seismic-observations.mjs` /
  `scripts/seismic-validate.mjs` の `--baseline` で A/B）。
- これらのファイルは**純粋な算術**（DOM・レンダラ・fetch・アプリ状態を参照しない）なので、
  Node から直接検証できる。

**津波・水（`js/tsunami.js` / `js/water-dynamics.js`）**

- 浅水方程式の局所慣性形＋q 中心化、マニング n。**閉じた形の答えで検証する**
  （等流水深との比・静水で max|q| ＝ 厳密に 0・質量保存）。
- ⚠ **「このモデルは X を扱いません」と自分で書いてある機能は、いつか X を要求される。**
  到達時間を隣に表示しているなら、到達時間はそのモデルが答えるべき量である。
- ⚠ **2つ目の時計を作らない**（フッタと詳細が別々の到達時刻を出さない）。

### 7.10 気象モデル（ECMWF IFS）・風・レーダー

**気象の数値はすべて 1 つのモデルから来る。** `window.IntMapECMWF`（`js/wx-ecmwf.js`）が
Open-Meteo の spatial アーカイブ（**ECMWF IFS HRES・O1280 縮約ガウス格子・約 9 km**）を持つ。
色面（ラスタ）・粒子・カーソル下の地点値・共有リンクの4つが**同じ変数・同じ初期時刻・同じ有効時刻**を読む。

- **`.om` ファイルの場所は自分で組み立てる。**
  `<base>/<初期 YYYY>/<MM>/<DD>/<HH>00Z/<有効 YYYY-MM-DD>T<HH>00.om`。
  ⚠ **SDK に `latest.json` を渡してはならない。** `normalizeUrl` は `time=` を無視して
  `valid_times[0]` に解決し、キャッシュ鍵（`DATA_RELEVANT_PARAMS` は `['variable']` のみ）も
  時刻を含まない。**ファイル名に有効時刻が入っていることが、予報時刻が実在する唯一の理由**。
- **予報時刻は全部使う**（実測 145 ステップ＝3日は毎時、6日目まで3時間毎）。既定は「今」に最も近い段。
  **モデル初期時刻（run）と有効時刻の両方を印字する。**
  モデルランが更新されたら、**同じ添字ではなく同じ壁時計の瞬間**へ移す。
- ⚠⚠⚠ **予報時刻は<b>そのレイヤーのもの</b>で、アプリ共通の時計へは流れない。**
  各レイヤーの凡例が自分の時刻選択 UI を持つ（`window.IntMapWxPlayer.timeUI` —— **1つの宣言**を
  風の凡例と ECMWF の凡例が共有する。1つの軸の2つの見え方であって、2つの時計ではない）。
  ⚠ **選択肢は `<select>` で、`IntMapECMWF.times()` が公開している有効時刻だけ**が並ぶ。
  添字を動かす range 入力は**連続に見える**ので、「データのない時間を選べない」は
  コントロールについての主張として成り立たない。
  ⚠ **`window.IntMapTime` との結線は<b>両方向とも無い</b>。** 予報を1時間動かすことが、
  ニュース・歴史的国境・昼夜境界・国別統計を同じ時刻へ引きずっていた（`_pushClock`）し、
  逆にアプリ側の時刻移動が読み手の選んだ時刻を上書きしていた（`_followClock` の購読）。
  `_followClock` は**名前として残して公開**してある——「その時刻の天気」を明示的に求める操作
  （Atlas）は購読ではなく呼び出しである。
  ⚠ **`data-legend-ec-time`（「ECMWF 予報時刻」）という<b>勝手に開く箱</b>は今も無い。**
  各レイヤーの凡例の `.ecl-when` は「**この絵がいつのものか**」の**読み**であって、
  他所のコントロールを開くボタンではない。
  ⚠ Chronos（`js/news-timeline.js`）の **「予報」タブ**はモデルの軸を**直接**動かす第2の見え方として
  残っている——アプリ共通の瞬間には触れない。
- **凡例は「1レイヤー1枚」で、レンダラ自身の配色表から作る**（`IntMapECMWF.legend(variable)`）。
  箱の `<h4>` は**そのレイヤー自身の名前**（`data-legend-ec-<id>`）、中身はそのレイヤーの帯・目盛・
  **不透明度**・データ源・モデル・時刻選択・「いつの絵か」だけ。
  ⚠ **不透明度は凡例にある。** #R16 の絶対規則——「レイヤー欄にスライダー・日付・フィルタを置かない。
  そのレイヤーの**凡例**にだけ置く」——を `css/intmap.css` が `.layer-dropdown .ec-op{display:none}` で
  強制しており、ECMWF の行は凡例側を持っていなかった。実測、`#lyrrow-ec-temp` の `<input class="ec-op">`
  は**レイヤーを入れても `display:none`** で、9 レイヤーすべての透明度に読み手は到達できなかった。
  他のレイヤーと同じ `.dl-op-row` の形で凡例に入る。
  目盛は 5 点・単位つきで、気温は `imUnitTemp`、風は風速単位の選択に従う。
  **凡例の最大値が LUT と食い違うことは構造上起きない。**
  ⚠ **家族名の箱に全部を積んではならない。** 実測（1280×800・ECMWF 3 レイヤー）: `ECMWF weather` と
  題した 1 枚に 3 つの帯が縦に積まれて 354 px あり、**どのレイヤーの帯かはどこにも書かれていなかった**。
  さらに幅の狭い画面では `ensureLegendMinimize` が floating な凡例を自動的に畳むので、
  箱の中身が全部消えて**「ECMWF 気象」という2語だけ**が残る＝「凡例名が ECMWF 気象・凡例が無い」。
  ⚠ 並べるのは既存のタイラー（`js/data-layers.js` の `tileLegends`）で、**id の接頭辞**
  `data-legend-ec-` で拾う（1つの要素を名指しすると、次にレイヤーが増えた日に古くなる）。
- ⚠⚠⚠ **気温は<b>1つのレイヤー</b>で、切り替わるのは<b>ソースだけ</b>。** 「気温」（`ec-temp`）は
  ECMWF IFS の予報**だけ**を答える。
  ⚠ 以前は**2つの行**があった（ここと `js/data-layers.js` の GIBS ラスタ）。ひとつの量に 2 つの
  スイッチ・2 つの凡例・2 つの日付操作・**2 つの配色**があり、`dl-temp` は削除された（保存済み
  セッションは `js/session-tabs.js` の `RETIRED` 表で `dl-ec-temp` に翻訳される）。
  ⚠ **MERRA-2 再解析（第2のデータ源）は撤去した。** 凡例の `Source` プルダウン・月の時計・
  `js/wx-reanalysis.js`（`imwxre://`）は、それだけを養っていたので一緒に消えている。
- ⚠⚠⚠ **時刻を変えても地図は空にならない。** 新しい時刻は**空いているスロット**に不透明度 0 で組まれ、
  古いスロットは新しいほうが**実際に出てから**外れる（#R284）。⚠ その「出てから」の合図は
  **そのソース自身の `sourcedata` ＋ `e.tile` ＋ `isSourceLoaded`** である
  （**タイルが1枚でも届いたとき**。`isSourceLoaded` だけでは「まだ1枚も頼まれていないソース」でも真になる）。
  ⚠⚠ **どのスロットを建てるかは「いま表に出ていないほう」で決め、露出は世代トークンで守る。**
  スロットの添字を建てた瞬間に反転させると、タイルを待っているあいだその添字は**表に出ているほう**を
  指す——連続してステップすると可視スロットを消してから不透明度 0 の新スロットを作ることになり、
  さらに 1 回目の露出処理が「自分の old」＝**もっと新しい時刻**を消す。落とすのは
  「**いま表に出たスロット以外**」で、追い越された露出処理は**何も出さず何も消さない**。
  ⚠ 同じ規則が風の色面と ECMWF のラスタ・等圧線・矢印の両方に要る（片方だけ直すと隣で同じ穴が開く）。`once('idle')` は
  「**いま持っているタイルについて**描くものが無い」という意味なので、まだ1枚も返ってきていない
  ソースでは**即座に**成立し、古いスロットが外れて読み手は残りのダウンロードのあいだ基図を見る。
  2.5 秒の予備タイマーも同じ側に倒れていた。予備は**12 秒**で、届かないソースが2枚のスロットを
  抱えたままにならないためだけにある——それまでは**古い絵が出たまま**、というのが要求そのもの。
  実測、6 段の時刻ジャンプを 250 ms 刻みで 40 回標本化して、**どちらのスロットも見えない瞬間は 0**。
- **時刻の操作盤のアイコンは<b>描く</b>。** 最初へ（棒＋三角）／1つ戻る（**二重**三角）／再生（**単一**三角）／
  一時停止（2本の棒）／1つ進む（**二重**三角）、そして「現在」は**言葉**。
  ⚠ **再生と「次へ」が同じ字だったことがある**（`⏮ ◀ ▶ ▶ ⦿`）。絵文字・Miscellaneous Technical の字は
  10.5 px で読み手の OS 任せに描かれるので、形の違いを**自分で**持つ SVG にする。
  ⚠ 風の凡例の操作盤と ECMWF の箱の操作盤は**同じ宣言**（`IC`）を読む——1つの時計の2つの見え方である。
- **風の配色は windy.com 自身の表**（`WIND_ANCHORS`・**27 停留点・0〜104 m/s**・全域 α=1）。
  ⚠ **粒子の濃さ**は速度で決まる（静穏 0.34 〜 最大 0.68 の α に、寿命の三角包絡が掛かる）。
  Canvas2D の代替経路も**同じ比**で描く——上限を下げたら最上位のバケットが到達不能にならないよう、
  バケットの除数も一緒に下げる。
  かつては Windy の**区切り値だけ**を借りて色を書き起こした「相当品」で、実測すると 2 m/s から
  乖離し始め **25 m/s で 133/255**（こちらは赤、Windy は青紫）、45 m/s 以上ではこちらが白に
  飽和する一方 Windy はカーキ→灰だった。⚠ **正本は宣言表ではなく<b>塗る関数</b>**——
  `W.colors.wind.defaultColorGradient` は 20 停留点だが `RGBA(v)`（0〜104 m/s を 2,048 段に
  前計算した表）は**その線形補間と一致しない**（実測 32.25 m/s で 20/255）。#R288 が気温で見つけた
  形がそのまま再現した。→ `RGBA` を 0.1 m/s 刻みで 1,041 点標本化し、線形補間でそれを再現する
  最小の停留点集合に落とすと **27 点・最大チャネル誤差 3/255**。104 m/s より上は Windy と同じく灰。
  SDK 既定の風配色は最初の 7 m/s で α を 0→1 に上げるため静穏域が「穴」になるが、
  この表は**全域不透明**（Windy 自身がそうである）。プロトコルは**この表で**登録する。
- **気温の配色も同じ形で、参照は<b>測ったもの</b>**（`TEMP_ANCHORS`・23 停留点・°C）。
  読み手が渡した参照画像は windy.com の既定の気温オーバーレイで、その配色表は Windy 自身の
  「Customize color scale」に出る値である。目視ではなく実測した——`W.colors.temp.defaultColorGradient`
  が 13 停留点（ケルビン）、`_precomputedGradient.RGBA(k)` が実際に塗られる色。203–320 K を 0.05 K
  刻みで標本化し、**線形補間でそれを再現する最小の停留点集合**に落とすと 23 点で
  **最大チャネル誤差 3/255**。0.00–0.85 °C に停留点が 4 つ集まっているのは雑音ではなく、
  Windy が氷点の等温線を「1 度未満で青から緑へ」と強調しているためで、そのうち 1 つ（0.40）を
  落とすと誤差は 3 → 7 に上がる。⚠ SDK の家族名 `temperature` に登録するので、`temperature_2m`・
  `surface_temperature`・土壌温度が**同じ表**を読む（`dew_point` は別家族なので触らない）。
  刻みは **0.05 °C**（2,341 段）——最も急な 0.35→0.75 °C 区間で青が 0.4 度に 92 単位動くため。
- ⚠⚠⚠ **SDK の配色表は<b>補間しない</b>ので、17 色の表は 17 本の帯になる。** 出荷されているコードで
  `rgba` は `colors[floor((v−min)/step)]`、`breakpoint` は `colors[binarySearch(breakpoints, v)]`——
  どちらも最近傍の抽選である。一方 `legend()` が作る CSS `linear-gradient` は**補間される**ので、
  **凡例だけが滑らかで地図が階段**という、色と名前が食い違う状態になっていた。
  → `rampFrom(WIND_ANCHORS, 0.1)` が**同じ色**を 0.1 m/s 刻みへ**再標本化**する（1,041 段）。
  節の値はそのまま自分の色に着地するので「色はそのまま」は近似ではなく厳密、あいだは sRGB で線形。
  **データは一切変わらない**（同じファイル・同じ 9 km 標本・同じ風速）。変わったのは色の分解能だけ。
  実測: 隣り合う段の最大チャネル差 **4/255**、大西洋上の走査線で拾った 51 画素のうち **46 画素**が
  17 色の表では作れない色だった。⚠ 601 段の帯を CSS に書くと 24 kB になるので、`legend()` は
  **描画用の停止点だけ**を 64 以下に間引く（`stops` は完全なまま）。
  ⚠⚠ **画面の1画素は「点の風速」ではなく「その画素が覆う空気」の色である。** ラスタは texel から
  `raster-resampling: linear` で描かれ、`valueNow()` は格子を**点**で内挿する——この2つは別の問い。
  17 本の帯だったころは両方が同じ帯に落ちて**同じ色**になっていたが、0.1 m/s では 1〜8 段ずれる。
  実測（z3・150°E 20°N・上に載る層を消して 81 画素）: **78 画素が表の項と厳密に一致**する一方、
  **点の値の項と一致したのは 78 中 20（26%）**、**1画素以内のどれかの風速の項と一致したのは 78/78**。
  → 検証は「色は厳密・速度は画素の覆う範囲」で行う（`tests/helpers/wind-ramp.js`）。
- ⚠⚠ **気象の面は昼夜シェーディングより上に置く。** `im-night-shade` は装飾、気象はデータ。
  実測（z3・150°E 20°N・夜側）：LUT が要求する `rgb(40,130,180)` に対し実際の画素は `rgb(15,43,64)`＝**0.36 倍**。
  `IntMapECMWF.before()` が夜側スタックの直後を返し、`lift()` が**毎 idle** で位置を再主張する
  （`js/night-side.js` は自分の層をタイマーで貼り直すため）。
- ⚠⚠ **断られたレイヤーは、断られたままにしない。** `addField`／`addLayer` はスタイルが層を受け付けられ
  ない間は false を返すので、**1回呼んで終わりにすると「粒子は出るが色がつかない」になる**
  （実測、梯子なしでは 150 秒待っても付かない／梯子ありで 6.9 秒）。約 16 秒のポーリング＋次の `idle`、着いたら止める。
  時刻変更時の再構築は**先に層を消す**ので同じ梯子が要る。
- ⚠⚠ **読み手は1つ、だから待ち行列も1つ。** SDK の `ensureData` は毎回 `setToOmFile` で**共有リーダを
  張り替える**ので、違うファイルの読み込みが時間的に重なると互いを壊す（同じ state 同士は
  `state.dataPromise` が重複排除するので安全）。`IntMapECMWF` が始める読み込みは全部1本の鎖に並ぶ。
- ⚠⚠ **レイヤーが手放してよいのは自分のフレームだけ**（`release(variable)`）。無条件の `release()` は、
  別の変数の読み込みが飛んでいる最中だとそれを黙って無効にし、地点値が理由もなく空欄になる。
  ⚠ `js/map-ui.js` は起動後 700 / 1,800 / 3,200 ms に保存済みレイヤー集合を再適用するので、
  これは稀な競合ではなく**通常の起動で起きる**。
  ⚠⚠⚠ **「時刻を変えたときの `release()` は無条件で正しい」——これは誤りだった。**
  正しかったのは、その行が `setIndex` の中で**同期に**走っていたあいだだけ。`COALESCE_MS` ぶん
  遅らせた瞬間、それは**140 ms 後の未来**に着地するようになり、その窓の中で始まった読み込みを
  （`release()` が `loadingKey` も消すので）黙って無効にする。**同じ欠陥の時間軸版**である。
  実測（#R287）: 起動後の最初の1歩は必ず負ける（冷えた場は 7〜9 秒、窓は 140 ms）——`valueNow` が
  null を返し、1.5 秒後の再試行は 25.27 °C を返した。暖まった場は窓の内側で解決するので影響を受けない。
  ⚠⚠⚠ **(#R288) そして `fireTime()` は<b>古いフレームすら捨てない</b>。** 窓を外しても、
  **より新しい要求に追い越された読み込み**は同じように null を返していた——ハンドラが
  **自分の復号したフレームではなくモジュール変数 `held` を返していた**からで、
  実測（本番ビルド）読み込み開始 50 ms 後に `release()` を呼ぶと **8.3 秒かけてデータは届いた
  うえで結果は null**。→ ⑴ `load()` は**自分のフレームを返す**（どれが「今のもの」かは単調な
  `seq` が決め、`release()` もそれを進める）、⑵ 古いフレームは**新しいものが着いたら置き換わる**
  ——捨てると地点値が空欄になり、同じ時刻をもう一度復号することになる。
- ⚠⚠⚠ **読むのは<b>読み手が見ている緯度帯</b>であって惑星ぜんぶではない。**
  実測、全球 1 フレームは **6,599,680 標本・274 レンジ要求・17.96 MB・7.8〜8.4 秒**で、粒子が
  1 つも動き出す前にそれを待っていた——「重すぎる」の実体はこれで、描画ではない（レンダラ自身は
  粒子 1,980 個で 2.65 ms／フレーム）。ECMWF の領域は**縮約ガウス格子**なので、SDK の
  `getCoveringRanges` は**緯度でしか**絞れない（経度は 1 本の平坦な添字）。25°–46°N の帯なら
  **935,400 標本・25 要求・1.64 MB**——**同じ 9 km 間隔・同じ数値・同じ色**で、落とすのは画面に
  無い部分だけ。⚠ 帯は**全経度**を含むので、東西のパンでは読み直さない。
  ⚠⚠⚠ **「1枚も持っていない」と「地球を持っている」を同じ値で表してはならない。** `heldBand()` は
  どちらにも `null` を返し、`bandCovers(null, …)` は「地球は全部を覆う」＝真なので、
  **フレームを1枚も持っていない起動直後に narrow 化が飛ばされていた**——そして起動時の視野は地球なので
  `bandFor` も `null`＝**全球 13,199,360 標本**。つまり「最初の読みは画面の緯度帯」という経路は、
  書かれてはいたが**初回に一度も通っていなかった**。持っていないことは `false` で言う。
  ⚠⚠ **色が出るまで、絵に要らない読み込みを始めない。** 読み手は1本しかいないので、
  ⑴ 次の時刻の先読み（**別のファイル**を指すので読み手を張り替える）⑵ 視野全体へ広げる2本目の帯
  ⑶ カーソル下の数値の暖機 の3本は、**色のスロットが実際に表に出てから**走らせる
  （12 秒の予備タイマーで諦めた場合も必ず走る＝永久に走らない経路を作らない）。
  粒子のための最初の読み込みは**遅らせない**——遅らせれば粒子が遅くなる。
  ⚠ 帯は**待ち時間（レイテンシ）律速**になるので、SDK 自身の `prefetchVariable`
  （`prefetchConcurrency: 1000`）で先に温めてから読む。実測、
  **全球 8,436 ms ／ 帯のみ 2,829 ms ／ 帯＋先読み 1,254 ms**。
  ⚠ 保持しているフレームは**要求された帯を含んでいれば**再利用する。帯 `null` は全球を意味し、
  全球はすべてを含む——だから任意地点を要求する呼び出し（`valueAt`）は今までどおり全球を得る。
  ⚠⚠⚠ **手元に残すのは「変数ごとに1枚」ではなく「予算に入るだけ」。** `keepFrame` は同じ変数の
  **別の時刻**まで捨てていたので、「1時間進めて戻す」が必ず再ダウンロードになっていた。置き換えるのは
  **同じ鍵で、新しい帯が古い帯を覆うもの**だけにし、あとは `FRAME_SAMPLES`（24e6）の LRU に任せる。
  帯なら **7〜21 時刻**が残る＝再生で通った時刻の往復は**通信ゼロ**。
  ⚠⚠⚠ **追い越された読み込みは、順番が回った時点で捨てる。** `serial()` の待ち行列に入ったまま
  「もう自分は古い」を確かめていなかったので、スライダーを 20 コマ引きずると **20 回とも最後まで
  通信してから**捨てられていた。世代を見て**1バイトも読まずに**戻る（20 → **1**）。
  ⚠ 戻り値を falsy にしてはならない——`js/weather.js` はそれを「取得失敗」と読んで 900/2,000/4,000 ms の
  再試行に入り、使い切るとトーストを出す。その変数のフレームを1枚返せば、`sampler()` が正しく判断する。
  ⚠⚠⚠ **視野いっぱいへ広げるのは「段」で行う。** `widen()` は時刻を変えるたび `band()`（世界ズームでは
  `null`＝**地球 13,199,360 標本 ≈ 18 MB**）を読み直していた。→ **静止 900 ms ごとに1段**、時刻が動けば
  段はやり直し。⚠ **段は幅ではなく標本数で切る**——縮約ガウス格子では行の点数 ∝ cos φ なので、
  「半幅を2倍」は世界ズームで地球の **86.6%** を掴み、段を挟むと合計が**増える**。目標の 60% を超える段は
  目標そのものにする。⚠ **広い読みを省略はしない**——読み手がその視野に留まれば最後は必ず `band()` に着く。
  ⚠⚠ **粗い領域へ落として速くしない。** `ecmwf_ifs025`（0.25°・標本 1/6.4）は実在するが `valid_times` が
  **3時間刻み（49本）**で、既定の `ecmwf_ifs`（**1時間刻み・109本**）と軸が違う。使えば読み手が選んだ
  時刻がずれる——それは「品質を保ったまま速く」ではない。
  ⚠ `lift()` が呼ぶ `_layerIds()` は `getStyle()`（スタイル全体のシリアライズ）なので、**メモ化して
  `styledata` で捨てる**。以前は idle ごとに最低2回（move を挟むと最大12〜18回）走っていた。
- ⚠⚠⚠ **予報時刻は「ジェスチャに1回」動く。** `<input type="range">` は**ドラッグの1画素ごと**に
  `input` を発火し、その一つひとつが層の作り直しと 26 MB の場の読み込みを1本ずつ待ち行列に積んでいた
  ——**読み手が指を止めた時刻は行列の最後**で、手前には誰も見ない9枚が並ぶ。それが
  「未来や過去に変えたときの読み込みが異常に遅い」の正体である（作業が遅いのではなく、
  **既に用済みの絵のための作業**だった）。→ 軸のイベントは2つ:
  `index`（**即時**・時刻の文字と目盛だけ）と `time`（軸が `COALESCE_MS` 静止してから1回・**取得を伴う**）。
  実測、12 段のドラッグで `index` 12 回・`time` **1 回**。
  ⚠ ボタンと `step()` は `{now:true}` で**即時**に撃つ（クリックは掃引ではない）。
  ⚠ `index` は**箱を作り直さない**——作り直すと、指がつまんでいる `<input>` 自体が差し替わる。
- ⚠⚠⚠ **時刻を変えたときに粒子を消してはならない。** 旧実装は `time` の先頭で
  `renderer.setField(null)` を呼んでいたので、**ドラッグの1画素ごとにアニメーションが消えて戻っていた**
  ＝報告された「点滅」。粒子が読む場は**それが作られた時のフレームを閉じ込めたクロージャ**なので、
  新しい時刻が着地するまで**古い時刻のまま正しく動き続ける**のが正しい。
  実測、12 段のドラッグ中に採った 22 フレームすべてで描画継続（最小 1,513 セグメント）。
- ⚠⚠ **ラスタも「消してから足す」をしない。** 各 ECMWF レイヤーは**2つのスロット**を交互に使い、
  新しい時刻を不透明度 0 で隣に組み立ててから、地図が落ち着いた時点で古いほうを落とす
  （アニメーション風の色面が以前からやっていることと同じ）。
- **隣接フレームの先読みは「時刻変更時」だけ。** 1 フレームの暖機は画面のフレームと同じ範囲読み込み
  （実測 410 リクエスト・約 27 MB）を要求するので、再生器に触っていない読者には課さない。
- ⚠⚠⚠ **暖機は「読まれる範囲」を暖める。** `prefetchVariable(v, null)` は**変数まるごと＝全球**を
  暖める。画面のフレームも全球だったあいだはそれで正しかった（#R288）が、#R288 以降その場は
  **視野の緯度帯**（93.5 万標本 対 660 万）なので、3 変数ぶんの全球暖機は **約 80 MB を、1.6 MB
  で足りるステップの前に**並べることになる。本番実測（風＋気温・z4.5）: 新しい時刻の場が
  **39 秒たっても来ない**。→ 暖機は `load()` と**同じ bounds** で作った state の `ranges` を使う。
  実測 **1,364 ms / 742 ms**。`null`（全球）は世界ズームとラスタタイルのための正しい既定として残る。
  ⚠ 「もう暖めた」の印は**ファイル＋帯**で持つ（帯の暖機が、していない全球を「済み」に見せない）。
- ⚠⚠⚠ **暖機は、暖めている当のものの<b>前に並んではならない</b>。** このモジュールの読み込みは
  **1 本の列**を通る（SDK のリーダーが 1 つだから）。隣の時刻の先読みと、カーソルの読み取り欄が
  欲しい帯が、**粒子が飛んでいる場の前に**並んでいた。同一セッションの A/B、1 ステップから新しい
  時刻の場が手に入るまで: z4.5・風だけ **711/447 → 396/515 ms**、**z4.5・風＋気温ラスタ
  30 秒たっても来ない → 1,073/1,737 ms**、世界ズーム 13.6/18.5 → 11.6/14.3 s（回線律速・差なし）。
  → 暖機は軸が**止まってから** 2.5 秒で走り、さらにステップが来たら**予定を置き換える**。
- ⚠⚠⚠ **1 本の列であることと、FIFO であることは別の決定である。** 上の「前に並ばない」は
  **開始のタイミング**を遅らせただけで、いざ並んだあとの**順番**は先着順のままだった。この列を通る
  読み込みは 2 種類ある——**読み手が待っているもの**と、このモジュールが自分で始めるもの
  （視野へ広げる段・次の時刻の暖機）。世界ズームでは後者が**両方とも地球**を要求するので、
  時刻の1ステップは毎回 18 MB の後ろに並んでいた。実測（起動時の視野・軸を1段ずつ）:
  **7,050 / 7,942 / 8,270 ms**、既に手元にある時刻は **45 ms**——待っていたのは通信ではなく**列**。
  → **同じ「1度に1本」のまま、レーンを2本にする**（`serial(fn, bg)`・`qHi` / `qLo`）。
  読み手の読み込みが先、モジュール自身の読み込みは後。⚠ **走り始めたものは取り消せない**
  （SDK のリーダーに中断が無い）ので、もう半分は「背景の読み込みを小さくする」ことである。
  改修後 **1,501 / 684 / 1,665 ms**（同じ手順）。
- ⚠⚠⚠ **暖める帯は「次のステップが実際に読む帯」である。** #R290 追記2 は規則としては正しく
  （「画面のフレームと同じ範囲」）、それを `band()` と綴った——`band()` は `bandFor` であり、
  **緯度幅 120° を超える視野では `null`＝地球**を返す。つまり**このアプリが開く視野では、暖機は
  毎回地球を暖めていた**。次の時刻はフレームを1枚も持たないので `bandCovers` は必ず偽であり、
  そのステップが読むのは常に `nearBand()`。暖めるのはそれ。
- ⚠⚠ **暖めるのは「軸の進行方向」の隣**（`_stepDir`）。「次の時刻」を `index()+1` と綴っていたので、
  **軸を戻している読み手は毎回冷たい読み込みを払っていた**。方向は軸自身から測り、既定は +1
  （再生ボタンは前へ進む）。
- ⚠⚠ **「静止」には<b>到着</b>も入る。** 段の待ち時間は**読み込みを要求した瞬間**から測っていたので、
  2.4 秒かかる読み込みは**答えが返った時点で既に 1.5 秒静止していた**＝読み手が絵を見る前に
  次の段が走り出す。フレームが**着地した時点**でも時計を打ち直す。
  ⚠ さらに、**段が地球そのものになる場合だけ待ち時間を長くする**（`BIG_STILL_MS` = 2,500 ms 対
  `STILL_MS` = 900 ms）——1 秒ごとに軸を送る読み手は地球の読み込みを始めさせず、止まった読み手は
  1.6 秒遅れで同じ絵に着く。
- ⚠⚠⚠ **保持するフレームの上限は<b>個数ではなく標本数</b>で、地点値は<b>全球を要求しない</b>。**
  実測、**世界ズームの風のフレームは 13,199,360 標本**（u と v の 2 本。`bandFor` は緯度幅 120° を
  超えると「地球全部」と答える）。16 M の予算では 2 本目の全球級フレームが来ると 19.8 M で溢れ、
  **風と読み取り欄が互いの場を追い出していた**（風は次のステップで `sampler()` が null＝粒子が止まる）。
  → 予算は **24 M**、そして `bandNear` が地点値用の帯（画面の緯度を中心 ±30°・約 220 万標本）を返す
  ——`bandFor` は「この絵が何を覆うか」に答える関数で、地点値は絵ではない。
  ⚠ `.om` を開く操作は `Content-Length` が示すほど高くない——実測 `setToOmFile` は 260 ms / 1,019 ms で、
  Range 無しの 200（ファイル全体の宣言長）は**本体を読まずに捨てられている**。
- **不透明度は1回だけ掛ける。** 面の α は配色表（風速の意味を持つ）、スライダーはただ1つの倍率で既定 1.0。
- **粒子は WebGL・1フレーム1描画呼び出し**（`js/wx-wind.js`）。移動量・寿命・残像はすべて**実経過時間**基準
  （`dt` 秒／`exp(-dt/τ)`）なので、60 Hz と 144 Hz で同じ絵になる。WebGL が無ければ**束ねた Canvas2D**。
  粒子はネイティブ格子を直接サンプルする（実測 14,000 回 2.2 ms）——低解像度の地点格子は存在しない。
- ⚠⚠⚠ **同じ大きさへの `resize()` は<b>何もしない</b>。** `js/weather.js` は地図の `moveend`——
  **すべてのパン・ズームの終わり**——から `resize()` を呼び、それが無条件に走っていた。
  `canvas.width` への代入は**同じ値でも canvas を消す**し、`makeTargets()` は残像用の
  フレームバッファを2枚とも作り直し、`cleared = true` が streak を捨てる。つまり**読み手が地図から
  指を離すたびにアニメーションが全消しされて組み直されていた**——1フレームの空白と、0.75 秒かけて
  戻る残像。これが報告された「点滅」である。実測、修正後は**5 回のパンで canvas 再生成 0 回**、
  ビューポートを実際に変えると**ちょうど 1 回**。
- ⚠⚠ **粒子数の調速機には<b>ヒステリシス</b>がある。** 閾値は 9 ms / 4.5 ms を 30 フレームごとに
  判定していたので、そのあたりに座る機械は 18% 減らし、次の窓で 12% 戻し、永久に振動する
  ——毎秒2回脈打つ密度も「点滅」である。判定は**2回続けて同じ**でなければ動かず、不感帯は広く
  （11 ms / 5.5 ms）、刻みは小さい（0.90 / 0.08）。
- ⚠⚠ **時刻を変えたら、前の時刻の粒子は<b>そこで終わる</b>。** 新しい時刻が届くまで古い場で動かし
  続けるのは正しい（上）——だが**届いた瞬間に終わらせる**のも同じくらい正しい。終わらせないと、
  新しい時刻の色の上を前の時刻の軌跡が流れる。`opt.step` のときだけ `renderer.reseed()`
  （粒子を撒き直し、残像テクスチャを落とす）。最初の読み込みでは撃たない——残す前の時刻が無い。
- **地点値**：ECMWF ラスタが出ていれば `valueNow(variable, lat, lng)`＝**タイルを描いたのと同じ配列**。
  NASA GIBS のラスタ（`temp`/`sst` など）は地点値サービスを持たないので、**データセット名と表示中の日付**を
  出して止まる。⚠ **別のデータセットの現在値を代わりに出してはならない。**
- **レーダー**：RainViewer の `radar.past`（実測 13 コマ・10 分間隔・直近2時間）を**ループできる**。
  コマ時刻と経過（「13:30 · −11 分 · 13/13」）を出す。タイルは差し替え（`setSourceTiles`）なので
  コマ送りは点滅せずクロスフェードする。⚠ 無料枠の配色番号は**2種類しか返らない**
  （0/2/3/6/7/8 と 1/4/5/9 でバイト一致）ので、`RV_SCHEME` が実際に得られる方を名指しする。
- **雲（赤外）**：RainViewer の衛星 IR は**廃止済み**（`satellite.infrared` は実測 0 コマ）。
  NASA GIBS の静止衛星 clean-IR（**Himawari + GOES-East + GOES-West**、10 分間隔）に置き換えた。
  ⚠ **Meteosat は GIBS に無い**ので、およそ西経 20°〜東経 75°（欧州・アフリカ）は範囲外。
  凡例が**その旨を文字で書く**（空白を「雲が無い」と読ませない）。
- **地点天気ポップアップ**は `window.IntMapWx`（`js/wx-source.js`）経由。突風・海面更正気圧・
  **データの有効時刻**（ブラウザ時刻ではない）・**実際のモデル名**を出す。
  ⚠ Open-Meteo の `models=` 無指定は **Best match**（GFS ではない）。⟳ は `ttl:0` で
  **両方の**梯子（Open-Meteo と MET Norway）のキャッシュを無効化する。
- ⚠ **Open-Meteo への直接 fetch は残っていない。** すべて `IntMapWx.guardedJSON`（キャッシュ・
  重複排除・日次 429 のサーキットブレーカ）を通る。`IntMapWx.isOpenMeteo(url)` が**ホストで**判定する
  （部分文字列ではない）ので、`sims.js` / `atlas-console.js` の共有ローダも自動的に通る。
- **共有リンク**は選択中のレイヤー（`dl-*`）に加えて **ECMWF の有効時刻（瞬間）と各層の不透明度**を運ぶ
  （`IntMapShareState.register('weatherEC')`）。⚠ 添字ではなく**瞬間**——開いた人のモデルランは別かもしれない。
