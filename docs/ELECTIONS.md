# IntMap — 国政選挙レイヤー (National elections)

> **この文書が正本なのは**「選挙レイヤーがどう組み立てられているか」——データの契約、パックの作り方、
> 出典とライセンス、どの選挙が入っていて何が入っていないか、そして**なぜ入っていないか**。
> レイヤーの見た目と操作は [`MAP-LAYERS.md`](MAP-LAYERS.md)、ファイルの所在は [`FILES.md`](FILES.md)。
>
> ⚠ **米大統領選レイヤー（`dl-uselect`）はこれとは別のレイヤーである。** 1789年からの60回を、
> 州が誰に選挙人票を与えたかで塗る——選挙区も議席も一般投票も無い（1824年以前）記録で、ここの契約では
> 表現できない。2つは政治カテゴリに並んで存在する。

---

## 1. 何を答えるレイヤーか

**塗り分けは「その選挙区で当選したのはどの政党か」であって、「誰が政権を取ったか」ではない。**
この違いは飾りではない——ここに入っている制度のほとんどで、その2つは別の問いである。

- 日本の衆議院 465 議席は、小選挙区 289 と比例代表 176 の合計
- ドイツの議席は**第2票（比例）**が決め、小選挙区で1位でも議席を得ないことがある
- オーストラリアは優先順位付投票なので、第1選好で1位の候補が当選するとは限らない

したがって**地図は選挙区を、凡例のバーは議会全体を**表し、凡例がそのことを9言語で明記する。
`districtSeats + listSeats = seatsTotal` は検査が毎回確かめる（合わなければビルドが落ちる）。

⚠ **結果が記録されていない選挙区には色を付けない**（灰色にもしない——灰色はどこかの政党の色である）。
⚠ **議席の配分が記録されていない選挙では、バーは得票率になり、見出しがそう名乗る**（ロシア）。
議席として持っていない数を議席のふりをさせない。

## 2. データの契約

正本は [`../scripts/lib/elections-schema.mjs`](../scripts/lib/elections-schema.mjs)。**散文ではなく実行される
検査**であり、`npm run check:elections`（`npm test` と CI に登録済み）が committed なバイト列に対して走る。

```
data/elections/index.json        すべての polity・選挙・政党（小さい。起動時ではなく初回トグル時に読む）
data/elections/<era>.geo.json    境界の版ごとに1つ。同じ版で戦われた選挙が共有する
data/elections/<id>.res.json     選挙ごとに1つ
```

⚠ **「境界の版」は「選挙」ではない。** 日本の 289 小選挙区は 2022 年に引き直され（10増10減）、その前の
区割りは 1996 年からのもの。英国は 2024 年に 650 区すべてを引き直した。米国は 10 年ごとに、しかも近年は
その途中でも引き直している。**間違った版の上に結果を載せることは「少し古い」ではなく、別の土地に議席を
渡すことである。** だから `geo` は選挙の属性で、2つの選挙が1つのファイルを共有するのは、実際に同じ地図の
上で戦われたときだけ。

検査が保証すること（すべて committed なバイト列だけから）:

1. 選挙区ポリゴンと結果が**両方向**で対応する
   ——結果の無い選挙区は地図に**穴**を開け、穴は「ここでは誰も勝たなかった」と読める。それは嘘である
2. 議席の算術（**地図が描ける議席＋描けない議席＝総定数**）。⚠ 「描けない議席」は普通は比例代表だが、
   常にそうではない——フランスの 18 は在外選挙区と海外準県の**小選挙区**、香港の 70 は職能別選挙区と
   選挙委員会。だから選挙は `listName` で自分の言葉で名乗れる（凡例に「比例」と書くのが嘘になる国がある）
3. 参照されている政党がすべて政党表にあり、色を持つ
4. 各選挙が `src`（出典表記）と `lic`（ライセンス）を持つ
5. `index.json` が名指ししていないファイルが `data/elections/` に落ちていない
6. **名前テーブルの言語キーが、このアプリが実際に持つ言語であること**（正本は `js/locales/_langs.js`）。
   ⚠ このアプリの日本語は `jp`、繁体字は `zh` である。`ja` / `zh-Hant` は別名として受理されるが、
   **どちらでもない綴りは「誰にも読まれない訳」**なので落とす（このラウンドが実際にやった間違い）

⚠ **この検査は意図的にオフラインである。** #R243 の `scripts/build-us-elections.mjs --check` は
「全部取り直して差分を見る」形で書かれ、その結果**どのゲートにも配線されないまま 18 ラウンド**が過ぎた
（`package.json` にも `.github/workflows/` にも 1 件も出てこない）。**走らせる余裕が無いゲートはゲートでは
ない。**

## 3. パックの作り方

1 つの polity につき 1 つのファイルを `scripts/elections/` に置く。**パックの一覧はどこにも書かれていない**
——そのディレクトリの中身が一覧である（手で並べた一覧は次に足されたものを黙って落とす。
[`../.agents/rules/no-ad-hoc-hardcoding.md`](../.agents/rules/no-ad-hoc-hardcoding.md) §2.4）。

```js
export const about = '一行の説明';
export async function build(ctx) {           // ctx.get(url, {json|text}) — キャッシュ付き
  return { polities, parties, elections, geo: {…}, res: {…} };
}
```

書いている途中は 1 パックだけを走らせて検証する（`index.json` の読み書きが競合しないように）:

```bash
node scripts/elections/_selftest.mjs jp        # 1パックをビルドして契約に照らす
node scripts/build-elections.mjs --only jp     # index.json への統合まで
node scripts/build-elections.mjs --check       # ゲート（オフライン）
```

上流の形式を読むヘルパは [`../scripts/lib/elections-geo.mjs`](../scripts/lib/elections-geo.mjs) にある
——ZIP、Shapefile（SHP＋DBF）、Web Mercator からの再投影、Douglas–Peucker の簡略化、ポリゴンの結合。
**ブラウザに届く依存は 1 つも足していない**（このヘルパは Node の zlib と算術だけ）。この回で足した 2 つは
どちらも **devDependency** で、ビルド時にしか動かない: `xlsx`（総務省が BIFF8 でしか出していない回の表）と
`pdfjs-dist`（同じく PDF でしか出していない候補者別得票。⚠ その PDF は埋め込みテキストを持っており、
`pdftotext` が日本語を落とすだけである）。

## 4. polity という語について

⚠ **このレイヤーは主権・国家性・承認・どこかへの帰属について、いかなる主張もしない。** データの契約には
それを表現する語彙が無い——polity が持つのは名前と地図上の枠と選挙の一覧だけである。香港と台湾が日本や
ドイツと並ぶのは、日本が並ぶのと同じ理由（選挙が行われ、結果が記録されている）であって、それ以上の意味は
無い。UI の語は「国・地域」相当の中立な表現を 9 言語すべてで用いる。

**中国本土についてはこのレイヤーに何も無い。** 実測（2026-09-09）: `npc.gov.cn` / `stats.gov.cn` /
`gov.cn` のいずれにも、地図に描ける競争的な全国選挙の機械可読データは 1 件も無い。全国人民代表大会は
間接選挙で、公表されるのは党派別の内訳だけである。**無いものを描かない。**

## 5. 出典とライセンス

⚠ **ここに入っているライセンスのいくつかは、出典表記を「再配布してよい条件」そのものにしている**
（CC BY 4.0、dl-de/by-2.0、Open Parliament Licence、data.gov.hk の利用条款）。したがって各選挙は自分の
`src` を持ち、レイヤーは**選択されている選挙の** `src` を地図の帰属表示に出す——レイヤー共通の定数に
すると、英国のデータをドイツの出典で表示することになる。

収録されている選挙の一覧と、その出典・ライセンス・入手経路は `data/elections/index.json` が持つ
（`src` と `lic`）。**この文書に写しを作らない**——写しは必ず片方が古くなる。一覧を読むには:

```bash
node -e "const i=require('./data/elections/index.json');for(const e of i.elections)console.log(e.id.padEnd(20),e.date,'|',e.src,'|',e.lic)"
```

## 6. 採らなかったもの（実測 2026-09-09）

| 候補 | なぜ採らなかったか |
|---|---|
| **GADM** | 「学術・非商用のみ。再配布および商用利用は事前許可なしには認めない」。IntMap は public なので検討の余地が無い |
| **AEC（豪州選管）自身の空間データ** | 著作権ページが CC BY 4.0 を謳いながら「AEC の地図」を明示的に適用除外し、別途の空間データ利用許諾が非移転で改変再配布を制限している。同じ区割りを **ABS（豪州統計局）が CC BY 4.0** で出しているのでそちらを使う |
| **CLEA / GRED**（選挙区の地理と結果を横断的に持つ唯一のデータセット） | Cloudflare の bot 判定で**全 URL が 403**。curl でもヘッドレス Chrome でも 1 バイトも取れない |
| **Global Elections Database** | HTTPS が無く（証明書エラー）、メールアドレスの入力を要求し、「第三者への譲渡・複製・配布を禁ずる」と明記 |
| **Manifesto Project** | 「提供データの再配布は書面による許諾がある場合を除き禁止」 |
| **IDEA（投票率）** | 「書面による許諾なしに複製・改変・配布してはならない」 |
| **IPU Parline** | CC BY-**NC**-SA。NC 条項があるので public な製品に同梱しない |
| **CHES**（政党の政治的位置） | ライセンスが**一切明示されていない**（LICENSE ファイル無し・引用要求のみ）。同梱せず、必要ならリンクと引用で扱う |
| **OpenStreetMap / Overpass** | 選挙区のタグ付けがどの国でも母集合にならない。実測: 英国 599/650、ドイツ 1/299、韓国 9/254 |
| **Wikidata** | 選挙区アイテムは 144,319 件あるが geoshape を持つのは 3.2%。得票は英国 2024 年総選挙で 99 件（候補者は 4,515 人）——**結果データとしては使えない**。政党の色と同一性には使える |
| **Natural Earth** | 選挙区データを持たない（リポジトリ全文検索で 0 件） |

## 7. 収録の広さ（2026-09-10 の実測）

12 の polity・**134 の選挙**・81 の境界の版・935 の政党。⚠ **この数を手で数え直さない**——
`npm run check:elections` が毎回印字する。

| polity | 選挙 | 範囲 | 境界の版 |
|---|---|---|---|
| 米国 | 下院・上院 62 | 1976–2024 | 37（下院は議会ごと・上院は改選年ごと） |
| ドイツ | 連邦議会 21 | 1949–2025 | 13（**1980 年より前の 8 回は結果だけ**——輪郭が公開されていない） |
| 日本 | 衆議院 7・参議院 7 | 2007–2026 | 6 |
| 欧州議会 | 10 | 1979–2024 | 8（加盟国そのものが「区」） |
| オーストラリア | 下院 8 | 2004–2025 | 8 |
| 英国 | 庶民院 5 | 2010–2024 | 2 |
| フランス | 国民議会 4 | 2012–2024 | 1 |
| カナダ | 庶民院 3 | 2015–2021 | 1 |
| 韓国 | 国会 2 | 2020・2024 | 2 |
| 台湾 | 立法院 2 | 2020・2024 | 2 |
| ロシア | 国家院 2 | 2016・2021 | 1 |
| 香港 | 立法会 1 | 2025 | 1 |

⚠ **ドイツの 1949–1976 は地図が空になる**（結果はある）。凡例がその理由を 9 言語で言い、地図は前の選挙の
絵を残さずに空にする。**「境界が無い」と「誰も勝たなかった」を混同させない。**

⚠ **ロシアの色は「その区で連邦比例名簿票の首位だった政党」**であって、その議席を取った議員ではない。
中央選挙管理委員会は小選挙区の候補者結果を区ごとの HTML ページでしか出しておらず、機械可読な記録が
存在しない。凡例のバーも議席ではなく**得票率**で、そう名乗る。

## 8. 既知の限界

- **収録の深さは国ごとにまったく違う。** 選挙区の**過去の**境界を公開している当局はごく少ない。境界が
  取れない回は**入れていない**——古い結果を新しい地図に載せることは、別の土地に議席を渡すことだから
- **上流が壊れている国がある。** ロシアの中央選挙管理委員会（`cikrf.ru`）は DNS は解決するが TCP 接続が
  できない（実測 21.6 秒でタイムアウト）。CI からも同じである前提で、パイプラインに置いていない
- **日本の衆議院の候補者別得票は、総務省が PDF でしか公開していない**（第44〜51回。第48回だけ .xls）。
  ⚠ **ただしその PDF は埋め込みテキストを持っており、機械可読である**——`pdftotext` は日本語を落とすが、
  ToUnicode CMap を読む抽出器（`pdfjs-dist`）なら取れる。**抽出器の失敗を PDF の性質と読み違えない。**
  ⚠ **第24回参議院選（2016）の候補者一覧だけは本当に取れない**——その PDF は全 10 頁がスキャン画像で
  テキストが 0 件（実測）。区の色は当選人数表から付いており、欠けているのは候補者名と得票だけ
