# IntMap — 国政選挙レイヤー (National elections)

> **この文書が正本なのは**「選挙レイヤーがどう組み立てられているか」——データの契約、パックの作り方、
> 出典とライセンス、どの選挙が入っていて何が入っていないか、そして**なぜ入っていないか**。
> レイヤーの見た目と操作は [`MAP-LAYERS.md`](MAP-LAYERS.md)、ファイルの所在は [`FILES.md`](FILES.md)。
>
> ⚠ **米大統領選レイヤー（`dl-uselect`）はこれとは別のレイヤーである。** 1789年からの60回を、
> 州が誰に選挙人票を与えたかで塗る——選挙区も議席も一般投票も無い（1824年以前）記録で、ここの契約では
> 表現できない。2つは政治カテゴリに並んで存在する。

---

## 1. 何を答えるレイヤーか

**塗り分けは「その選挙区で当選したのはどの政党か」であって、「誰が政権を取ったか」ではない。**
この違いは飾りではない——ここに入っている制度のほとんどで、その2つは別の問いである。

- 日本の衆議院 465 議席は、小選挙区 289 と比例代表 176 の合計
- ドイツの議席は**第2票（比例）**が決め、小選挙区で1位でも議席を得ないことがある
- オーストラリアは優先順位付投票なので、第1選好で1位の候補が当選するとは限らない

したがって**地図は選挙区を、凡例のバーは議会全体を**表し、凡例がそのことを9言語で明記する。
`districtSeats + listSeats = seatsTotal` は検査が毎回確かめる（合わなければビルドが落ちる）。

⚠ **結果が記録されていない選挙区には色を付けない**（灰色にもしない——灰色はどこかの政党の色である）。
⚠ **議席の配分が記録されていない選挙では、バーは得票率になり、見出しがそう名乗る**（ロシア）。
議席として持っていない数を議席のふりをさせない。

## 2. データの契約

正本は [`../scripts/lib/elections-schema.mjs`](../scripts/lib/elections-schema.mjs)。**散文ではなく実行される
検査**であり、`npm run check:elections`（`npm test` と CI に登録済み）が committed なバイト列に対して走る。

```
data/elections/index.json        すべての polity・選挙・政党（小さい。起動時ではなく初回トグル時に読む）
data/elections/<era>.geo.json    境界の版ごとに1つ。同じ版で戦われた選挙が共有する
data/elections/<id>.res.json     選挙ごとに1つ
```

⚠ **「境界の版」は「選挙」ではない。** 日本の 289 小選挙区は 2022 年に引き直され（10増10減）、その前の
区割りは 1996 年からのもの。英国は 2024 年に 650 区すべてを引き直した。米国は 10 年ごとに、しかも近年は
その途中でも引き直している。**間違った版の上に結果を載せることは「少し古い」ではなく、別の土地に議席を
渡すことである。** だから `geo` は選挙の属性で、2つの選挙が1つのファイルを共有するのは、実際に同じ地図の
上で戦われたときだけ。

検査が保証すること（すべて committed なバイト列だけから）:

1. 選挙区ポリゴンと結果が**両方向**で対応する
   ——結果の無い選挙区は地図に**穴**を開け、穴は「ここでは誰も勝たなかった」と読める。それは嘘である
2. 議席の算術（**地図が描ける議席＋描けない議席＝総定数**）。⚠ 「描けない議席」は普通は比例代表だが、
   常にそうではない——フランスの 18 は在外選挙区と海外準県の**小選挙区**、香港の 70 は職能別選挙区と
   選挙委員会。だから選挙は `listName` で自分の言葉で名乗れる（凡例に「比例」と書くのが嘘になる国がある）
3. 参照されている政党がすべて政党表にあり、色を持つ
4. 各選挙が `src`（出典表記）と `lic`（ライセンス）を持つ
5. `index.json` が名指ししていないファイルが `data/elections/` に落ちていない
6. **名前テーブルの言語キーが、このアプリが実際に持つ言語であること**（正本は `js/locales/_langs.js`）。
   ⚠ このアプリの日本語は `jp`、繁体字は `zh` である。`ja` / `zh-Hant` は別名として受理されるが、
   **どちらでもない綴りは「誰にも読まれない訳」**なので落とす（このラウンドが実際にやった間違い）

⚠ **この検査は意図的にオフラインである。** #R243 の `scripts/build-us-elections.mjs --check` は
「全部取り直して差分を見る」形で書かれ、その結果**どのゲートにも配線されないまま 18 ラウンド**が過ぎた
（`package.json` にも `.github/workflows/` にも 1 件も出てこない）。**走らせる余裕が無いゲートはゲートでは
ない。**

## 3. パックの作り方

1 つの polity につき 1 つのファイルを `scripts/elections/` に置く。**パックの一覧はどこにも書かれていない**
——そのディレクトリの中身が一覧である（手で並べた一覧は次に足されたものを黙って落とす。
[`../.agents/rules/no-ad-hoc-hardcoding.md`](../.agents/rules/no-ad-hoc-hardcoding.md) §2.4）。

```js
export const about = '一行の説明';
export async function build(ctx) {           // ctx.get(url, {json|text}) — キャッシュ付き
  return { polities, parties, elections, geo: {…}, res: {…} };
}
```

書いている途中は 1 パックだけを走らせて検証する（`index.json` の読み書きが競合しないように）:

```bash
node scripts/elections/_selftest.mjs jp        # 1パックをビルドして契約に照らす
node scripts/build-elections.mjs --only jp     # index.json への統合まで
node scripts/build-elections.mjs --check       # ゲート（オフライン）
```

上流の形式を読むヘルパは [`../scripts/lib/elections-geo.mjs`](../scripts/lib/elections-geo.mjs) にある
——ZIP、Shapefile（SHP＋DBF）、Web Mercator からの再投影、Douglas–Peucker の簡略化、ポリゴンの結合。
**ブラウザに届く依存は 1 つも足していない**（このヘルパは Node の zlib と算術だけ）。この回で足した 2 つは
どちらも **devDependency** で、ビルド時にしか動かない: `xlsx`（総務省が BIFF8 でしか出していない回の表）と
`pdfjs-dist`（同じく PDF でしか出していない候補者別得票。⚠ その PDF は埋め込みテキストを持っており、
`pdftotext` が日本語を落とすだけである）。

## 4. polity という語について

⚠ **このレイヤーは主権・国家性・承認・どこかへの帰属について、いかなる主張もしない。** データの契約には
それを表現する語彙が無い——polity が持つのは名前と地図上の枠と選挙の一覧だけである。香港と台湾が日本や
ドイツと並ぶのは、日本が並ぶのと同じ理由（選挙が行われ、結果が記録されている）であって、それ以上の意味は
無い。UI の語は「国・地域」相当の中立な表現を 9 言語すべてで用いる。

**中国本土についてはこのレイヤーに何も無い。** 実測（2026-09-09）: `npc.gov.cn` / `stats.gov.cn` /
`gov.cn` のいずれにも、地図に描ける競争的な全国選挙の機械可読データは 1 件も無い。全国人民代表大会は
間接選挙で、公表されるのは党派別の内訳だけである。**無いものを描かない。**

## 5. 出典とライセンス

⚠ **ここに入っているライセンスのいくつかは、出典表記を「再配布してよい条件」そのものにしている**
（CC BY 4.0、dl-de/by-2.0、Open Parliament Licence、data.gov.hk の利用条款）。したがって各選挙は自分の
`src` を持ち、レイヤーは**選択されている選挙の** `src` を地図の帰属表示に出す——レイヤー共通の定数に
すると、英国のデータをドイツの出典で表示することになる。

収録されている選挙の一覧と、その出典・ライセンス・入手経路は `data/elections/index.json` が持つ
（`src` と `lic`）。**この文書に写しを作らない**——写しは必ず片方が古くなる。一覧を読むには:

```bash
node -e "const i=require('./data/elections/index.json');for(const e of i.elections)console.log(e.id.padEnd(20),e.date,'|',e.src,'|',e.lic)"
```

## 8. 既知の限界

- **収録の深さは国ごとにまったく違う。** 選挙区の**過去の**境界を公開している当局はごく少ない。境界が
  取れない回は**入れていない**——古い結果を新しい地図に載せることは、別の土地に議席を渡すことだから
- **上流が壊れている国がある。** ロシアの中央選挙管理委員会（`cikrf.ru`）は DNS は解決するが TCP 接続が
  できない（実測 21.6 秒でタイムアウト。2026-10-03 に再測定して同じ）。CI からも同じである前提で、
  パイプラインに置いていない。**2026 年の国家院選挙はそのために入っていない**——§9 の「更新不能」
- **日本の衆議院の候補者別得票は、総務省が PDF でしか公開していない**（第44〜51回。第48回だけ .xls）。
  ⚠ **ただしその PDF は埋め込みテキストを持っており、機械可読である**——`pdftotext` は日本語を落とすが、
  ToUnicode CMap を読む抽出器（`pdfjs-dist`）なら取れる。**抽出器の失敗を PDF の性質と読み違えない。**
  ⚠ **第24回参議院選（2016）の候補者一覧だけは本当に取れない**——その PDF は全 10 頁がスキャン画像で
  テキストが 0 件（実測）。区の色は当選人数表から付いており、欠けているのは候補者名と得票だけ

## 9. 生きたデータとして — 受領証・週次の確認・上流の生死（companies-elections-live）

⚠ 実測（2026-10-03）: このレイヤーは 2026-09-10 に一度だけ書かれ、**誰も組み直していなかった**。
バイトには「いつ・誰から取ったか」が無く、記録が世界に遅れていることを誰も見られなかった
——米国下院は 2018 年で止まり、カナダの第 45 回総選挙（2025-04-28）とロシアの 2026 年国家院選挙が
無い。理由はどれも**パックのコメントにだけ**書かれていた。

**選挙の行**は `fetchedAt`（結果を上流から取った日）・`fetchedFrom`（`build`＝ビルドが書いた／
`commit`＝この欄より前の行で、結果ファイルを最後に変えたコミットの日——導出であることを名乗る）・
`up`（上流の名前）を持つ。**polity** は `pack` と `refresh` を持つ。契約は
[`../scripts/lib/elections-schema.mjs`](../scripts/lib/elections-schema.mjs)、純粋な部分は
[`../scripts/lib/elections-live.mjs`](../scripts/lib/elections-live.mjs)。

**宣言** — [`../scripts/elections/upstreams.json`](../scripts/elections/upstreams.json)。パックごとに
上流の名前・夜間に訊く probe・**各議院の選挙間隔の法定上限**（`maxGapMonths` と条文の根拠）。
`--check` が両方向に照合する（全パックに宣言がある・宣言は全部パックである・記録にある議院は全部
上限を持つ）。JSON なのは、依存を入れずに走る夜間の生死確認がそのまま読めるようにするため。

**週次の確認** — [`../.github/workflows/elections-refresh.yml`](../.github/workflows/elections-refresh.yml)
（毎週水曜）:

1. `node scripts/build-elections.mjs --watch` — 各議院について、記録の最新の選挙と
   **法が次の選挙を要求した日**（最新＋`maxGapMonths`）を出し、`watch()` を持つパック（ca・ru・us）に
   キャッシュ無しで「記録より新しい選挙はあるか・無いならなぜか」を訊く。結果が polity の `refresh`:
   `current`／`overdue`（法の期限を過ぎ、理由は未確認）／`blocked`（新しい選挙があり、取り込めない
   理由が確認された）／`importable`（妨げが消えた）。⚠ **見られなかった watch は「何も無い」ではない**
   ——前の記録を残し、`checkedAt` を進めず、警告を出す。
2. `importable` のパックだけを組み直す。
3. `--check` を通ったバイトを bot の PR にし、`land-bot-pr` で着地させる。

**凡例**は選んだ polity の `blocked`／`overdue` を「**更新不能**」として、理由と**最終確認日**を
添えて出す。選挙ごとに「取得日／記録日」と上流名も出す。2026-10-03 の確認で `blocked` だったもの:

| polity | 議院 | 欠けているもの | 理由（確認したこと） |
|---|---|---|---|
| ca | 庶民院 | 第 45 回総選挙（2025-04-28） | open.canada.ca に OGL の公式結果が無い（55 データセットを確認）。elections.ca の写しは商用再配布を禁じる |
| ru | 国家院 | 2026 年の選挙 | 集計者は投票所別の結果を 2026-10-02 に公開したが、**小選挙区の列（`oik`）が無い**。投票所と選挙区の対応を出す唯一の機関 cikrf.ru には接続できない |
| us | 下院 | 2020・2022・2024 | MEDSL の 1976–2024 は Dataverse のゲストブック 458 の奥で、ファイル API が 400 を返す（版 15・2026-03-09） |

⚠ **法定上限は早い選挙を捕まえない**（解散・前倒し）。カナダ 2025 とロシア 2026 は上限の内側だった
——捕まえたのはパック自身の `watch()`。上限は、`watch()` を持たないパックの最後の網。

**上流の生死** — [`../scripts/upstream-liveness.mjs`](../scripts/upstream-liveness.mjs) が夜ごとに
`upstreams.json` の probe も訊く（識別子は `elections/<pack>: <host>`。同じホストを訊く 3 パックは
3 本の連続記録）。**2 夜続けて落ちたら赤**の規則はブラウザの上流と同じ。2026-10-03 の初回実測:
25 本中 alive 23・refused 1（Statistics Canada の 2013 年区割り、どの UA でも 403）・dead 1（cikrf.ru）。
どちらも初めから落ちているので赤にはならず、毎晩の要約に載る。

## 10. 地図が述べていること — 境界の版と選挙の年（historical-verification）

`--check` は形式だけでなく**主張**も訊く。地図が読者に述べているのは「その日、この土地がこの選挙で
投票した」で、それを**別の記録**——CShapes 2.0（`data/cshapes.js`、1886–2019 の各日の国家の輪郭）
——に訊く（[`../scripts/lib/elections-claims.mjs`](../scripts/lib/elections-claims.mjs)）。各選挙区の
内部を標本化し、投票日に各標本がどの国にあったかを**幾何で**引く（国名どうしを綴りで結ばない）。

- **拒むもの**: 投票日に**2 つの国にまたがっていた**選挙区（自分の国の国境から `BORDER_KM` 以内の
  標本と、海を隔てた飛び地の標本は除いて、他国の標本が `FOREIGN_SHARE_MAX` を超える）。
- **実測で見つかったもの（2026-10-03）**: 欧州議会 1979・1984・1989 年が**統一後のドイツ**を描いていた
  ——東ドイツは 1990-10-03 まで加盟しておらず、その 3 回に投票していない。パックのコメントは
  「認められた時代錯誤」と書いていたが、読者には何も言っていなかった。いまは
  [`../scripts/elections/eu.mjs`](../scripts/elections/eu.mjs) が統一前を**西独の 10 州**（GISCO NUTS-1。
  ベルリンは描かない——西ベルリンの議員は 1994 年まで直接選挙でなかった）で描き、1994 年は
  別の版（`eu-ms-1994`）になった。
- **拒まないもの（列挙する）**: 選挙区が**丸ごと**別の単位にあるもの。CShapes はグアドループや
  レユニオンを独自の単位として持ち、どこの属領かを持たないので、フランスの海外選挙区を
  「フランスの外」と誤読する。これは `--enumerate` の出力に「別の CShapes 単位」として出し、人が読む。
- **国名の現地語形は引き継ぐ**: GISCO は 2026-09-25 の再公開で `CNTR_NAME` を英語名にした。
  このレイヤーが出荷していた現地語形（「Österreich」など）は、**国コードで**前の版（コミット済みの束）から
  引き継ぎ、行の `nativeFrom`（引き継ぎ元のファイル・その版のコミット日・その版が何から読んだか）が出所を言う。
  上流が今も述べている独語・仏語名（`NAME_GERM`／`NAME_FREN`）はそのまま足す。前の版を読むのは
  `build-elections.mjs` が渡す `ctx.previous(file)`（HEAD のバイト）で、組み直し中の作業ツリーではない。
- **訊かないもの**: CShapes の最終日（2019-12-31）より後の選挙（2026-10-03 時点で 26 回）。
  **「訊けなかった」は「正しい」ではない**——`--check` が件数を印字する。

人が読むための列挙（historical-verification §2.1）:

```bash
node scripts/build-elections.mjs --enumerate --year 1979 --in 5,47,16,55
```

その年に**効力を持っていた議会**（その年末までの最新の選挙）・境界の版・取得日・上流・領域の判定・
箱の中の選挙区と勝者を出す。⚠ 経度の範囲は**円周上の弧**として比べる: アラスカの選挙区は +170° から
−130° に及び、素朴な最小・最大では地球一周になってドイツの箱に入っていた。選挙区の経度を最短の弧で
持ち、西端が東端より東にある箱（±180° をまたぐ箱）も同じ規則で読む。

## 11. 時間で流す — 勝者の入れ替わり

凡例の ▶ が、選んだ**議院**の選挙を順に再生する（上院と下院を混ぜない）。各回はその回の境界の版で
描かれ、**前回と同じ版で戦われたときだけ**、勝者が変わった選挙区を黄色の太線で囲み、件数を出す。
区割りが変わった回は「比較しない」と言う——別の土地どうしを比べて「入れ替わった」と言わない。
どちらかの回に勝者の記録が無い選挙区は「入れ替わり」に数えない（欠けは出来事ではない）。
コントロールに手を触れると止まる。`window.IntMapElections` の `play()`／`stop()`／`swing()`／
`freshness()`／`latest()` が同じものを外から呼べ、Atlas には `layers.electionPlay`・`layers.electionSwing`・
`layers.electionFreshness` として登録してある（`js/atlas-cap-layers.js`）。
